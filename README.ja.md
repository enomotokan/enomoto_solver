# ENOMOTO-Solver

[English README](README.md)

ENOMOTO-Solver は，Python のモデリングインターフェースと Rust のコアからなる，線型最適化問題(LP)・混合整数線型最適化問題(MIP)求解用のソルバーです．

**対応環境**：次の OS で，CPython 3.9 以降に対応しています(3.9・3.13・3.14 でテスト済み)．wheel は abi3(Python の安定 ABI)なので，各 OS で 1 つの wheel がすべての対応バージョンに入ります．

| OS | アーキテクチャ |
|---|---|
| Windows | x86_64 |
| Linux(glibc 2.28 以降，manylinux_2_28) | x86_64，aarch64 |
| macOS | x86_64(Intel)，arm64(Apple シリコン) |

LP の解法には**傾き・切片双対二段解法**を実装しています．これは，双対単体法のフェーズ1の一つである人工上下限法(双対問題に対する大M法)の M を，数値として固定せず記号的に扱う方法です．

- **局面A(傾き問題)**：計算なしに双対実行可能となる全スラック基底から出発し，無限の上下限を ±1 に，右辺を 0 に置き換えた問題を解きます．その最適値から，元の問題が有限な最適値を持ちうるかが分かります．
- **局面B(切片問題)**：局面Aの最終基底から，傾きを固定して得られる問題を通常の双対単体法で解きます．
- **後処理**：人工の境界に残った変数があれば，最適性を保ったまま主比検定で有限な境界へ移します．

これにより，**数値の M を選ばずに，双対単体法だけで**，LP が有限な最適値を持つか，非有界か，実行不可能かを判別し，有限な最適値を持つ場合は最適基底解を返します．

このほか，次も実装しています．

- **近接内点法 + クロスオーバー**：近接内点法(IP-PMM，Mehrotra の予測子・修正子法)で内点の最適解を求め，クロスオーバー(主・双対の押し出しと基底の選択)で最適基底解に直します．仕上げは単体法で行います．
- **二つの解法の並列実行**：`threads` を 2 以上にすると(既定は，使える CPU の数 + 1 の半分．HiGHS と同じ)，LP(整数最適化では warm start できない緩和問題)を，傾き・切片双対二段解法(1 スレッド)と近接内点法 + クロスオーバー(残りのスレッド)で同時に解き，先に結論を出した側を採ります(もう一方は打ち切ります)．
- **混合整数線型最適化(MIP)**：分枝切除法(制約伝播，切除平面，主ヒューリスティクス，対称性の処理など)で解きます．緩和問題はすべて傾き・切片双対二段解法で解き(ノードでは親の最適基底から warm start)，根の緩和問題に有限な最適値がないときは，切片問題の変数を整数に制限した問題で実行不可能か非有界かを判別します(`distinguish_infeasible_unbounded=True` のとき)．ソルバーに複数のスレッドを与える(`threads` を 2 以上にする)と，分枝限定法を並列化します．根の処理の後は，未処理のノードを共有して木の探索を複数のスレッドで分け合います(根の緩和問題は二段解法と近接内点法 + クロスオーバーで同時に解きます)．

## インストール

PyPI からインストールできます(上の「対応環境」なら，ビルド済みの wheel が入るので Rust などは不要です)．

```sh
pip install enomoto-solver
```

### ソースからビルドする場合

開発やベンチマークの実行には，リポジトリを取得してビルドします．次のものが必要です．

- Python 3.9 以降
- Rust のツールチェーン(`rustc`，`cargo`)
- [maturin](https://www.maturin.rs/) 1.5 以降(拡張モジュールのビルドに使用)
- ベンチマークを実行する場合のみ：[highspy](https://pypi.org/project/highspy/) と C コンパイラ(Netlib のデータの展開に使用)

```sh
git clone https://github.com/enomotokan/enomoto_solver.git
cd enomoto_solver
python -m venv .venv
# Windows: .venv\Scripts\activate   /   Linux・macOS: source .venv/bin/activate
pip install maturin
maturin develop --release
```

必ず `--release` を付けてビルドしてください．デバッグビルドは何倍も遅くなります．

## 使い方

### 問題の定義と求解

```python
import math
from enomoto_solver import Model, Variable

M = Model()
x = Variable(float, 0, 10)          # 連続変数 0 <= x <= 10
y = Variable(float, 0, math.inf)    # 上下限は無限でもよい
M.set_objective(x + 2 * y, sense="maximize")
M.add_constraint(x + y <= 10)
M.add_constraint(x - y >= -4)

sol = M.solve()
print(sol.status, sol.objective)    # optimal 17.0
print(x.value, y.value)             # 3.0 7.0
```

- `Variable(型, 下限, 上限)` は，最後に作った `Model` に変数を作ります(`model=...` で明示することもできます)．型は `float`(連続)か `int`(整数)です．上下限には `±math.inf` を使えます(整数変数でもかまいません)．自由変数は `Variable(float, -math.inf, math.inf)` です．
- 線型式は `+`，`-`，スカラー倍，数値での割り算で，制約は `<=`，`>=`，`==` で書きます．目的関数と制約は線型式に限ります．変数どうしの積(`x * y`)，べき乗(`x ** 2`)，式での割り算(`1 / x`)のように二次以上になる式を作ると，線型でないことを示す `TypeError` になります．
- `set_objective(f, sense="minimize" | "maximize")` で目的関数を設定します(既定は最小化)．
- `solve()` の引数(すべて省略可)：

  | 引数 | 意味 |
  |---|---|
  | `threads` | 使うスレッドの数(既定は，使える CPU の数 + 1 の半分．HiGHS と同じ．`enomoto_solver.default_threads()`)．2 以上なら LP を二段解法と内点法 + クロスオーバーで同時に解き，整数最適化では木の探索も分け合います．詳しくは下の「スレッド数(`threads`)」． |
  | `root_solver` | LP の解法(既定 `"auto"`．下の「LP の解法の選択」)． |
  | `distinguish_infeasible_unbounded` | 有限な最適値がないとき，実行不可能か非有界かを区別するか(既定 `False`．下の「結果の状態と，実行不可能・非有界な問題」)． |
  | `time_limit`，`mip_rel_gap`，`node_limit` | 整数最適化の打ち切り条件(秒，相対ギャップ(既定 0)，ノード数)． |
  | `log` | ログを出すか(既定 `True`．下の「ログ」)． |

- `solve()` は常に `Solution` を返し，実行不可能・非有界・求解失敗でも例外は送出しません．結果は `Solution.status` で判断します．`status` が `"optimal"` のとき(整数最適化で打ち切ったときは，暫定解があれば)だけ `objective` に値が入り，各変数の値を `.value` で読めます．それ以外では `objective` は `None` で，`.value` を読むと `RuntimeError` になります．

### 結果の状態と，実行不可能・非有界な問題

`solve()` は次の属性を持つ `Solution` を返します．`status` は `"optimal"`，`"infeasible"`，`"unbounded"`，`"infeasible_or_unbounded"`，`"not_solved"` のいずれかです(整数変数を含むモデルでは，さらに `"time_limit"`，`"node_limit"` があります)．

| 属性 | 意味 |
|---|---|
| `status` | 結果の状態(上のいずれか)． |
| `objective` | 解の目的値(元の向きで，定数項を含みます)．`"optimal"` のとき，および整数最適化で打ち切ったときに暫定解があれば値が入ります．それ以外は `None`． |
| `node_limit_hit` | 整数最適化でノード数の上限(`node_limit`)により打ち切ったか．LP では常に `False`． |
| `best_bound` | 整数最適化で証明済みの最適値の限界(最小化なら下界，最大化なら上界)．最適値はこの値と `objective` の間にあります．実行不可能なら `inf`(最大化なら `-inf`)．LP では `None`． |
| `mip_gap` | 整数最適化の相対ギャップ \|`objective` − `best_bound`\| / max(\|`objective`\|, 1)．`mip_rel_gap` 以下になると `"optimal"` で終わります．暫定解がなければ `inf`．LP では `None`． |
| `nodes` | 整数最適化で処理した分枝限定法のノード数(全スレッドの合計)．LP では `None`． |

既定では，有限な最適値がないと分かった時点(局面Aの終了時)で止まり，`"infeasible_or_unbounded"` を返します．`distinguish_infeasible_unbounded=True` を渡すと局面Bまで進み，両者を区別します．

### 線型最適化（LP）

```python
M = Model()
z = Variable(float, -math.inf, math.inf)
M.set_objective(z)                  # z を最小化
M.add_constraint(z <= 5)

sol = M.solve(distinguish_infeasible_unbounded=True)
print(sol.status)                   # unbounded
```

整数変数を含むモデルでも同じです．根の緩和問題で局面Aが有限な最適値がないと示したとき，既定では `"infeasible_or_unbounded"` を返します．`distinguish_infeasible_unbounded=True` なら，切片問題(局面Bの問題)の変数を整数に制限した問題を分枝限定法で解き，実行可能解があれば `"unbounded"`，実行不可能なら `"infeasible"` を返します(切片問題の実行可能解 x⁰ と局面Aの傾き x¹ から，x⁰ + M x¹ が目的値をいくらでも下げる整数解になるためです)．

### LP の解法の選択

`solve(root_solver=...)` で LP の解法を選べます(整数変数を含まないモデルにだけ効きます．整数最適化の緩和問題は，常に傾き・切片双対二段解法を warm start で使って解きます．整数変数を含むモデルに `"auto"` 以外を指定すると `UserWarning` を出し，指定を無視して解きます)．

| `root_solver` | 解法 |
|---|---|
| `"auto"`(既定．`None` も同じ) | `threads` が 2 以上なら，傾き・切片双対二段解法(1 スレッド)と近接内点法 + クロスオーバー(残りのスレッド)を並列に実行し，先に結論を出した側を採ります．`threads=1` なら二段解法だけで解きます． |
| `"simplex"` | 傾き・切片双対二段解法だけ． |
| `"ipm_crossover"` | 近接内点法 + クロスオーバーだけ．内点法が収束しなければ二段解法で解き直します． |
| `"interior"` | プリソルブも独立した近接内点法(IP-PMM)．基底解ではなく，検証用です． |

どの解法を使っても，実行不可能・非有界の判定は二段解法が行います．`"auto"` で内点法 + クロスオーバー側が採られるのは，単体法で最適性を確かめた基底解が得られたときだけです．

### 混合整数線型最適化（MIP）

```python
M = Model()
items = [(Variable(int, 0, 1), value, weight) for value, weight in [(60, 10), (100, 20), (120, 30)]]
M.set_objective(sum(v * value for v, value, _ in items), sense="maximize")
M.add_constraint(sum(v * weight for v, _, weight in items) <= 50)
sol = M.solve(time_limit=60)
print(sol.objective, [round(v.value) for v, _, _ in items])   # 220.0 [0, 1, 1]
print(sol.best_bound, sol.mip_gap, sol.nodes)                 # 220.0 0.0 0
```

整数変数を含むモデルは，傾き・切片双対二段解法で緩和問題を解く分枝切除法で解きます．

- **プリソルブと制約伝播**：平行な行の統合，probing，活動量に基づく境界の締め付け，衝突解析と双対証明．
- **切除平面**：CMIR(Gomory 相当の tableau 行を含む)，lifted flow cover，{0, 1/2}-Chvátal–Gomory(zerohalf)．
- **主ヒューリスティクス**：丸め，fix-and-propagate，Feasibility Pump，Feasibility Jump，潜り込み，内点法の解からの丸め，サブ MIP による改善(RINS，RENS，DINS，Crossover など)．
- **探索**：擬似コストによる信頼性分岐，plunge(子ノードへの潜り込みと warm start)，再スタート，対称性の検出と対称性を崩す不等式(orbitope を含む)．

#### 探索の並列化

`threads` が k ≥ 2 のとき，探索は次のように並列に動きます．

- **warm start できない緩和問題**：根の LP と再スタート後の根の LP は，始める基底がないので，二段解法(1 スレッド)と近接内点法 + クロスオーバー(k − 1 スレッド)で同時に解きます．ノードの緩和問題は，親の最適基底から warm start する二段解法で解きます(数反復で終わるので，内点法を同時に走らせても勝ち目がなく，手間だけが増えるためです)．ヒューリスティクスの中で解くサブ MIP(RINS など)は小さいことが多いので，基底のない求解も二段解法だけで解きます．木の探索が k 本のスレッドを使い始めた後は，同時実行をしません．
- **根**：根の切除平面とヒューリスティクスは，根を解いたスレッド(主スレッド)が行います．
- **木の探索**：主スレッドに未処理のノードが 2 つできた時点で，根の処理を終えた木の写しから残りの k − 1 本のスレッドを始めます(根で解き終わる問題では，追加のスレッドを作りません)．各スレッドは自分の待ち行列のノードを処理します．待ち行列が空になったスレッドがあれば，ほかのスレッドが下界の小さいノードを共有の待ち行列を通して渡します．全てのスレッドが待っていて，共有の待ち行列も空になったら探索を終えます．
- **ヒューリスティクス専用のスレッド**：k ≥ 4 のとき，⌊k/4⌋ 本のスレッドが木の探索を離れて改善ヒューリスティクス(適応的な大近傍探索)を回し続けることがあります．大近傍探索が 1 秒あたりに閉じる木の量が，木の探索の 1 スレッドが閉じる量以上と見込まれる間だけこの役に就きます(木の進み具合は未処理のノードの重み 2^−深さ で，大近傍探索の寄与は暫定解の改善で刈れる木の重みの指数移動平均で測ります)．そうでなくなるか，20 回続けて暫定解を改善できなければ木の探索に戻ります．最適性の証明より良い暫定解を優先するときは環境変数 `ENOMOTO_MIP_FOCUS=primal` を，使わないときは `ENOMOTO_MIP_NO_HEUR_ROLE=1` を指定します．
- **スレッド間で共有する情報**：暫定解(最良の目的値は全スレッドの枝刈りに使います)，大域的な境界の締め付け，擬似費用の観測(16 ノードごとに合算)，双対証明と衝突(64 ノードごとに取り込み)．
- ノードを処理する順序がスレッドの進み具合で変わるため，k ≥ 2 では実行ごとにノード数や求解時間が変わることがあります(求まる最適値は変わりません)．

打ち切り条件は `time_limit`(秒)，`mip_rel_gap`(相対ギャップ，既定 0)，`node_limit`(ノード数)で指定します．上限で止まったときは `status` が `"time_limit"` か `"node_limit"` になり，暫定解があれば `objective` と各変数の `.value` を読めます．`Solution` の `best_bound`(証明済みの限界)，`mip_gap`(相対ギャップ)，`nodes`(処理したノード数)にも結果が入ります．

相対ギャップは，暫定解(探索中に見つかった実行可能解のうち目的値が最も良いもの)の目的値と証明済みの限界の差を

  相対ギャップ = |暫定解の目的値 − 証明済みの限界| / max(|暫定解の目的値|, 1)

で測ったものです(分母は，目的値が 0 に近いときに比が極端に大きくならないよう 1 未満なら 1 にします)．最適値は証明済みの限界と暫定解の目的値の間にあります．探索中は，限界が「暫定解の目的値 − max(`mip_rel_gap` × max(|暫定解の目的値|, 1), 10⁻⁹ × max(|暫定解の目的値|, 1))」に届いたノードを枝刈りするので(目的関数の整数変数の係数がすべて共通の刻みの倍数で，目的関数に連続変数がないときは，刻み 1 つ分良くできないノードを枝刈りします)，未処理のノードがなくなったとき，相対ギャップは `mip_rel_gap` 以下(既定の `mip_rel_gap=0` なら 10⁻⁹ 以下)です．このとき `"optimal"` として終わります．したがって既定では，`"optimal"` は LP 緩和の許容誤差の範囲で最適性を証明したという意味です．保証を緩めて早く止めたいときは `mip_rel_gap=1e-4` などを指定してください．

返す解は報告の前に研磨します．整数変数はちょうどの整数に丸め，連続変数があれば，整数変数をその値に固定した元の問題の LP を解き直し，その解が元の解より制約を破らず目的値も悪くならなければそれに取り替えます．`objective` は返す値から誤差補償つきの和で計算し直すので，返す解の目的値と丸め誤差の範囲で一致します(`benchmarks/` の MIPLIB 2017 の問題では，参照の最適値との相対誤差は 10⁻¹⁵ 以下)．

### スレッド数(`threads`)

`solve(threads=...)` で使うスレッドの数を指定します．省略すると，HiGHS と同じく(このプロセスが使える CPU の数 + 1) / 2 にします(`enomoto_solver.default_threads()`．論理コアが 4 なら 2，8 なら 4)．このプロセスが使える CPU の数(`enomoto_solver.max_threads()`)を超える値は，そこで頭打ちにします．プリソルブなどの並列区間も含め，求解全体をこの数のスレッドで動かします．

| `threads` | LP(`root_solver="auto"`) | MIP |
|---|---|---|
| 1 | 傾き・切片双対二段解法だけで解きます． | 緩和問題も木の探索も 1 スレッドで解きます． |
| k ≥ 2 | 二段解法(1 スレッド)と近接内点法 + クロスオーバー(k − 1 スレッド)で同時に解き，先に結論を出した側を採ります． | warm start できない緩和問題(根など)を左と同じように同時に解き，根の処理の後は k 本のスレッドで木を分け合って探索します(上の「探索の並列化」)． |

同時実行では，始める前にスレッドを二段解法用(1 本)と内点法 + クロスオーバー用(残り)の別々のプールに分けるので，二つの解法が互いのスレッドを奪い合うことはありません．二段解法が先に解ければその基底解をそのまま使い，内点法 + クロスオーバーが先なら，クロスオーバーの仕上げ(二段解法の主ループ)で得た最適基底をそのまま使います．負けた側は打ち切り，その終了は待ちません．

```python
import enomoto_solver
sol = M.solve(threads=enomoto_solver.max_threads())   # 使える CPU をすべて使う
```

### ログ

`solve()` は既定で，最初に作者・ライセンス・連絡先の案内と問題の大きさを，求解中は要点を，最後に結果を標準出力に出します．求解中の要点は次のとおりです．

- LP：プリソルブ後の大きさ，使う解法，並列実行ではどちらの解法が先に結論を出したか．
- MIP：プリソルブ後の大きさ，根の LP の値，根の切除平面による値の変化，再スタート，探索の経過(経過時間，処理したノード数，未処理のノード数，証明済みの限界，暫定解の目的値，相対ギャップ．5 秒ごと)．

上の「混合整数線型最適化（MIP）」の例では次のように出ます．

```text
ENOMOTO-Solver 0.1.0 (MIT License)
Author: Kan Enomoto (https://enomoto-math-labo.com/en)
For optimization consulting requests and bug reports, contact enomotokan@gmail.com

Problem: 3 variables (3 integer), 1 constraints, 3 nonzeros, maximize; threads 1
Presolve: 1 rows, 3 columns -> 1 rows, 3 columns (0.00s)
Root LP: objective 2.2000000000e2 (0.00s)
     time      nodes      open        best bound         incumbent       gap
     0.0s          0         0     2.200000000e2     2.200000000e2     0.00%
Result: optimal, objective 220, best bound 220, gap 0.00%, nodes 0 (0.00s)
```

探索の経過の各列の意味は次のとおりです．

| 列 | 意味 |
|---|---|
| `time` | 求解を始めてからの経過時間． |
| `nodes` | 処理した(緩和問題を解いた)ノードの数(全スレッドの合計)． |
| `open` | 未処理のノードの数．分枝で作られて待ち行列に入ったまま，まだ緩和問題を解いていない部分問題の数です(全スレッドの合計)．0 になれば探索は終わりです． |
| `best bound` | 証明済みの限界(最小化なら最適値の下界，最大化なら上界)． |
| `incumbent` | 暫定解(見つかった実行可能解のうち目的値が最も良いもの)の目的値．まだなければ `-`． |
| `gap` | 相対ギャップ(上の「混合整数線型最適化（MIP）」)を百分率で表したもの． |

`solve(log=False)` なら案内もログも出しません．

## ベンチマーク結果

### 線型最適化

HiGHS 1.15.1，CLP 1.17.11，SoPlex 8.1.0 と 207 問の LP で比較しました(2026年9月29〜30日に計測)．各欄は「解けた問題数 / 求解時間のずらした幾何平均(秒)」です(10 秒ずらし．解けなかった問題は制限時間の 600 秒として計算)．太字は各行で最良の値です．

| 問題集合 | ENOMOTO | HiGHS | CLP | SoPlex |
|---|---|---|---|---|
| Netlib，有限の最適解あり(93問) | 93 / **0.152** | 93 / 0.166 | 93 / 0.164 | 92 / 0.741 |
| Kennington(16問) | 16 / **0.964** | 16 / 1.68 | 16 / 1.16 | 16 / 5.76 |
| Mittelmann LPopt(40問) | 12 / **377** | 11 / 405 | **18** / 393 | 7 / 503 |
| Netlib 実行不可能(29問) | 29 / **0.00597** | 29 / 0.0154 | 29 / 0.0743 | 28 / 1.53 |
| 実行不可能な問題の双対，非有界(29問) | 29 / 0.0588 | 29 / 0.335 | 28 / 2.01 | 29 / **0.0332** |
| 全体(207問) | 179 / **10.6** | 178 / 11.0 | **184** / 11.3 | 172 / 13.4 |

207問全体の幾何平均は，ENOMOTO 0.084 秒，HiGHS 0.183 秒，CLP 0.100 秒，SoPlex 0.146 秒です．ENOMOTO は誤った答えを1つも返しませんでした．局面Aで有限の最適解がないと検出した非有界な27問では，非有界か実行不可能かの区別に要した追加の時間は求解時間の2%程度でした．

- 計算機：AMD Ryzen 7 5700U のノート PC(8コア16スレッド，メモリ 16 GB)，WSL2 の Ubuntu 22.04(メモリ上限 12 GB)．ENOMOTO と HiGHS は16スレッド，CLP と SoPlex は逐次．時間制限とスレッド数以外はすべて既定の設定です．
- 時間は求解の呼び出しのみ(MPS ファイルの読み込みとモデルの構築は含まず，プリソルブとポストソルブは含む)で，3回の中央値です(300 秒以上かかった場合は1回)．1回ごとに新しいプロセスで解いています．
- Mittelmann は，plato.asu.edu から取得できる公開 44 問から，この計算機のメモリに載らない最大の4問(thk_48，L2CTA3D，dlr2，Dual2_5000)を除いた40問です．
- 全体の表，問題ごとの時間，生データは [benchmarks/paper/summary.md](benchmarks/paper/summary.md)，`per_problem.csv`，`results.json` にあります．再現の手順(Linux)は [scripts/paper_bench/README.md](scripts/paper_bench/README.md) を参照してください．

### Netlib での HiGHS との手軽な比較

Netlib の LP データには再配布を明示的に認めるライセンスがないため，このリポジトリには含めていません([docs/netlib-data.md](docs/netlib-data.md))．最初に一度だけ取得・展開します．

```sh
python scripts/setup_netlib_data.py          # ネットワーク接続と C コンパイラが必要
```

そのうえで HiGHS と比較します(`pip install highspy`)．

```sh
python -m enomoto_solver.benchmark_highs --max-vars 100000 --out netlib_results.csv
```

各問題は別々のサブプロセスで解きます．計測する時間は求解の呼び出しのみで(MPS ファイルの読み込みとモデルの構築は含まない)，どちらのソルバーもプリソルブとポストソルブを含みます．
