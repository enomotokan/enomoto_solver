# Netlib LP テストデータの扱い方

このリポジトリのベンチマーク(`python -m enomoto_solver.benchmark_highs`)は
Netlib LP テスト問題集(`https://www.netlib.org/lp/data/`)を使う。
このドキュメントは、そのデータを**リポジトリには含めず**、
**環境構築時に一度だけ取得してローカルにキャッシュする**という設計に
した理由と、具体的な使い方を説明する。

## なぜ `data/` にコミットしないのか

Netlib LP テスト問題集には、明確なライセンス表記(MIT/BSD/CC0 のような
再配布許可を明示した文書)が付いていない。Netlib 全体としては
米国政府職員の成果物由来のものが多く実質パブリックドメインに近いが、
LP テスト問題は 1980〜90年代に外部の研究者・企業(Bob Fourer, Chevron 等)
から提供されたものが中心で、当時の慣行として明示的なライセンス文言が
存在しない。長年にわたり学術・産業界で自由に再配布されてきた実績はあるが、
「無条件に再配布してよい」と確認できる一次情報は見つからなかった。

実際、有力なLPソルバの一つである HiGHS も、自身のリポジトリに Netlib の
`.mps` ファイルを同梱しておらず、テスト実行時に外部から取得する方式を
採っている。このリポジトリもそれに倣い、**Netlib のデータそのものは
git 管理下に置かない**方針とする。

## 設計: 「取得は1回だけ、通常のベンチマーク実行はネットワーク不要」

- `scripts/setup_netlib_data.py` — 環境構築時に1回だけ実行する。
  netlib.org からデータ一式を取得し、Netlib 自身の展開ツール `emps.c` を
  ビルドして展開し、`--cache-dir`(デフォルト: `<repo>/.netlib_cache`、
  `.gitignore` 済みでコミットされない)にキャッシュする。
- `python -m enomoto_solver.benchmark_highs` — 通常のベンチマーク実行。
  このスクリプトは **netlib.org に一切アクセスしない**。上記キャッシュを
  読むだけで、キャッシュが無ければ「先に setup_netlib_data.py を実行せよ」
  という明確なエラーで止まる(問題ごとに黙ってダウンロードを試みたりしない)。
- `scripts/netlib_fetch.py` — 上記2つが共有する取得・キャッシュ処理の実体。
  標準ライブラリのみに依存しており、この crate のビルド成果物
  (`_core` / `highspy`)を必要としない。`setup_netlib_data.py` が
  ビルド前の環境でも単独で動くのはこのため。

## 使い方

新しい環境(コンテナ、CI イメージ、開発機)でベンチマークを初めて実行する
前に、一度だけ:

```sh
python scripts/setup_netlib_data.py
```

を実行する(netlib.org へのネットワークアクセスと、`emps.c` をビルドする
ための C コンパイラ — `gcc` など — が必要)。以降は:

```sh
python -m enomoto_solver.benchmark_highs
```

がキャッシュのみを参照して動作し、netlib.org への都度アクセスは発生しない。
`--cache-dir` はコンテナ・イメージのレイヤーやボリュームとして永続化して
再利用してよい(git 管理下に置かないだけで、環境側でのキャッシュ保持は
自由)。
