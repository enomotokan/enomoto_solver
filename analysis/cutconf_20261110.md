# PAPER1: cut-based の衝突解析 (試作 `ENOMOTO_MIP_CUTCONF`) (2026-11-10)

bench に使う環境変数: `ENOMOTO_MIP_CUTCONF=1` (試作。既定では使わない)。比べる相手は既定 (cand1108zd、環境変数なし)。
計測は 4 スレッド (`ENOMOTO_MIP_THREADS=4`)、種は `ENOMOTO_T_MIP_SEED`。

## 結論

- cut-based の衝突解析を試作 `ENOMOTO_MIP_CUTCONF` (既定では使わない) として `src/mip/cutconf.rs` に入れた。伝播の理由を行として持つ
  (元の行は記録の理由から、双対証明・目的関数・カットのプールの伝播は行を覚えて)、理由の行との線形結合と、0-1・整数の列での MIR の
  縮約で 1-UIP まで遡り、得た線形の制約を証明のプール (別の分類) に入れて伝播に使う。
- 効き目は見えない: 58 問 (60 秒、種 1・2、116 対) で SGM 18.58 → 18.50 (-0.4%、95% 区間 [-4.8%, +4.1%])、解けた数 82 → 82。
  一般整数列を含む制約を捨てる形 (`b`) は +1.3% ([-2.1%, +5.1%])、82 → 79。効きそうな問題 (120 秒) でも揃った改善はない
  (timtab1 は少し良く、mas74 は下界が 2 回とも低い、noswot は揺れが大きく向きが定まらない)。
- 作った制約はよく使われる (58 問の cc の全部の回で 35.5 万本、刈ったノード 12.3 万、締めた境界 1561 万) が、解く時間は変わらない。
- 誤答: 最初の版に MIR の右辺の符号の誤りがあり timtab1 で最適解を切った (直した)。直した後は、デバッグ解の検査・検査の形
  `ENOMOTO_MIP_CUTCONF_CHECK`・制約ごとの fuzz (500 問)・最適値の fuzz (fuzz_tiny 400、mip_fuzz_vs_highs 300、fuzz_cutconf 600) で誤りなし、
  58 問の 348 回で暫定解と下界の矛盾なし。
- 既定にする価値は今はない (害も小さいが、効き目が見えない)。47 問 (600 秒) は、58 問で効き目が見えなかったので計っていない。

## 文献と本文で確かめたこと

- Mexi, Serrano, Berthold, Gleixner, Nordström 2025「Cut-based Conflict Analysis in Mixed Integer Programming」(INFORMS JoC、
  arXiv 2410.15110v2)。最初はこの環境から本文に届かず要旨だけで作り、後で (親のセッションがネットワークを許可した後に) arXiv の
  HTML 版の本文と SCIP の GitHub のソース (`src/scip/conflict_resolution.c`・`set.c`、master) を読んで確かめた。

本文・ソースで確かめたこと (事実):
- 縮約 (4.2 節、命題 2): 0-1 の理由の行で、今の状態で効いている (non-relaxable な) 列を補にしてから MIR をかける (cMIR-CA)。
  補にすれば weakening は要らず、CG (RoundingSat の division) や以前の MIR より強い (5 節)。ENOMOTO の縮約 (各列を、その時点の値に
  近い大域的な境界で補にして MIR) は 0-1 列についてはこれと同じ形。
- 連続列 (6 節、命題 4): 0-1 と連続の混合では、理由の行に入っている局所的に締まった連続列を、その連続列を伝播した行と結合して
  消してから縮約する (理由の行だけ・衝突の行だけでは、縮約しても破れなくなることがある)。ENOMOTO は**入れていない** (連続列は MIR の
  式のまま扱う)。60 秒の選別では、連続列の段で失敗したのは timtab1 で 6 回、noswot で 0 回と少なかった。
- 一般整数 (7 節): いつも結合を試す。大域的でない境界の一般整数列が効く場合、縮約なしでも 72% は破れたまま残り、残りに cMIR を
  試すが成功は約 3%。ENOMOTO も同じ (結合を試し、だめなら MIR の縮約、だめなら止める)。
- 失敗したらグラフ式に戻る (8.1 節、呼び出しの約 19%)。性能の比べ (8.3 節) は cut-based を「足す」形で、毎回の矛盾からグラフ式と
  cut-based の両方の衝突を作る。ENOMOTO の `cc` (`1`) と同じ。
- 長さと年齢 (8.3 節): SCIP は密な衝突を捨て、しばらく伝播しない衝突を年齢で消し、cut-based の衝突にも同じ上限を使う。長さの上限を
  外すと 4〜5% 遅くなる (ノードは 2% 減る)。ソースでは長さの上限は `conflict/maxvarsfracres` = 0.20 x (連続でない列の数)、長すぎると
  今の状態で大域的な境界にある (relaxable な) 列を消して縮め (`weakenConflictRow`)、それでも長ければ止める。係数の比の上限
  `conflict/maxcoefquot` = 1e6。FUIP は 1 段 (`conflict/resfuiplevels` = 1)。
- 結果 (表 2、MIPLIB 2017 の 794 問): 解けた数 636 → 644、時間 0.95 倍、影響のあった問題で 0.92 倍、1000 秒以上の問題で 0.85 倍、
  ノードは両方解けた問題で 0.95 倍。
- SCIP の master の既定では cut-based (generalized resolution) は**使わない** (`conflict/usegenres` = FALSE)。

確かめた後の ENOMOTO との違い: (1) 長さの上限が HiGHS 式 (0.3 x 整数列数 + 100) で緩く、relaxable な列を消さない (mas74 で 150 列中 86 の
長い行)。(2) 年齢で消さない (証明のプールの古い順の追い出しだけ)。(3) 連続列を伝播した行で消す縮約 (命題 4) がない。
(1) を形 `w` として入れて 58 問で計った (下の (b2))。(2)・(3) は入れていない。

## 実装したもの

新しいファイル `src/mip/cutconf.rs` (解析の本体) と、既存のファイルへの小さな差分:

- `src/mip/domain.rs`: 変更の記録を読む `trail_entry` だけ足した。
- `src/mip/solver.rs`: `add_conflicts_multi` の頭で試作の解析を呼ぶ (`add_cutconf`)。双対証明のプール・目的関数・カットのプールの
  伝播で境界を締めたとき、その行を「理由の行」として記録の位置ごとに覚える (`cutconf::note_range`、試作のときだけ)。
  得た制約は証明のプールに入れる (分類を別にして、双対証明を追い出さない。`S` で同じ分類)。統計を `MIP: cutconf ...` に出す。

解析の手順 (`cutconf::analyze`):

1. 始めの衝突の制約 `C: sum c_j x_j <= b` は、伝播で矛盾した行 (`ConflictSrc::Row`) か、破れている証明 (双対証明・Farkas の証明・
   目的関数の行・カットのプールの行)。係数の最大を 1 に正規化する。
2. 今の境界の状態 (記録の位置 `pos` より前の変更 + 残した変更) で、`C` の最小活動量を大域的な境界より上げている変更を集める。
   その最も深い段の変更が 1 つなら止める (1-UIP)。
3. その段の、まだ残していない最も新しい変更 `k` (列 `x_p`) を選ぶ。理由が元の行なら、その行を `<=` の向きにした `R`、理由が
   外から来た変更 (双対証明・目的関数・カットのプールの伝播) で行を覚えていればその行を `R` にする。どちらでもない (分枝の決定・
   被約費用の固定・対称性の固定など) なら「残す」(その境界は以後も状態に入れたまま、置き換えない)。
4. `C' = C + λR` (`λ = -c_p / ρ_p > 0`) を作り、位置 `k` の時点の状態でまだ破れていれば (余裕 < -1e-6) 採る。
   破れなくなるときは、`x_p` が整数なら `R` を縮約する: 各列を大域的な境界のうち `k` の時点の値に近い方で補にし、`|ρ_p|` で割って
   MIR で丸めた `R'` (`x_p` の係数は ±1) で結合し直す。それでも破れなければ止める (それまでの `C` を返す)。
5. 小さすぎる係数 (正規化の後 1e-9 未満) は大域的な境界で弱めて消す。正規化する。2 に戻る。
6. 1 段以上進んだら、大域的に固定された列を右辺に移し、今の境界で破れていて長さが HiGHS 式の衝突の上限以下なら返す。

妥当性: 使うのは元の行・双対証明などのプールの行 (どれも妥当、目的の行・打ち切り値による大域的な固定は暫定解より良い解について
妥当) の非負結合と、大域的な境界での補と MIR だけなので、記録の読み違いがあっても得た制約は妥当 (破れているかの判定だけが変わる)。

## 誤答の検査

### 見つけて直した誤り (2026-11-10)

- 最初の版で timtab1 (種 1、120 秒) が「最適 823035」(最適値は 764772、既定は 764772) を返した。デバッグ解 (前処理の後の問題を
  HiGHS で解いた最適解、`ENOMOTO_MIP_DEBUG_SOL`) で解くと、cutconf の制約がデバッグ解を切る知らせが数十回出た (行の矛盾からの
  長さ 5〜9 の制約も)。
- 原因: 縮約 (`reduce`) で MIR の式を補の変数から元の列に戻すとき、下限 `l` で補にした列 (`y = x - l`) の右辺を `+ f l` とすべき所を
  `- f l` にしていた (上限で補にした列は正しかった)。下限が 0 の列では効かないので、0-1 列だけの問題では出ず、下限が 0 でない
  一般整数列のある timtab1 で出た。直した後、timtab1 の種 1・2 (120 秒) は 764772 で、デバッグ解の知らせは 0。
- 直す前の版で、最終の最適値だけを見る fuzz (`fuzz_cutconf.py` 300 問、下限が 0 でない列を入れた後) はこの誤りを捉えなかった
  (誤りの版にわざと戻して確かめた: bad 0)。最適値の比べは弱いので、次の制約ごとの検査を足した。

### 制約ごとの検査

- デバッグ解の段ごとの検査 (`ENOMOTO_MIP_DEBUG_SOL` のとき): 始めの制約・理由の行 (そのまま・縮約の後)・結合の後の制約が
  デバッグ解を切ったら、どの段かを出す。目的の証明・打ち切り値による大域的な固定を使うので、デバッグ解が打ち切り値より良いとき
  だけ確かめる (双対証明の CMIR と同じ条件)。
- 検査の形 `ENOMOTO_MIP_CUTCONF_CHECK` (診断用): どの実行可能解にも妥当な材料だけを使う (問題の境界 (大域的な締め付けを使わない)、
  元の行だけ (覚えた外の行を使わない)、伝播の矛盾の行からだけ始める)。得た制約はどの実行可能解も切ってはならないので、
  暫定解によらずデバッグ解でいつも確かめられる。対称性の処理はデバッグ解を外しうるので `ENOMOTO_MIP_NO_SYMMETRY=1` と合わせる。
- `fuzz_check.py`: 乱数の 0-1 混合の問題 (多次元ナップサック・固定費用・一般整数 (下限が 0 でないことも)・被覆・等式・クリーク) を
  MPS に書き、ENOMOTO の前処理の後の問題を書き出して HiGHS で最適解を求め、検査の形で解く。

## 次の一手

- 制約の数を絞る: 今は衝突ごとに 1 本入れる。SCIP のように使われない衝突を年齢で捨てる・長さの上限を列数の割合で決める・
  グラフ式の衝突 (リテラル) で足りるとき (0-1 列だけの節になるとき) は入れない、などで伝播の手間を減らす。
- 論文の連続列の縮約 (命題 4、連続列を伝播した行で消す) を入れる。今の 0-1 の問題の
