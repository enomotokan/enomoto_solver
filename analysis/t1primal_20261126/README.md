# T1PRIMAL: 1 スレッドの解探し (2026-11-26〜27、親の依頼、gap240 の型 1)

gap240_20261126 の型 1 (1 スレッドの解探し、効き 0.972) の試作。ENOMOTO_MIP_T1PRIMAL=1 で入る (既定は切)。
計測の版は e110c4660 の .so (ALNS 既定化 cd676b114 より前)。次の計測は 82071c738 以降で行う。

## 1. 作り (src/mip/t1primal.rs)

- 4 スレッドの FJ スレッドが回す FJ + Local-MIP の組 (fj_lmip_mix) を、再開できる形 (Mix) に写し、1 スレッドでは別スレッド
  「t1primal」に置いて、主スレッドが時間の切れ端 (Slice) を渡したときだけ回す (主スレッドはその間待つので、使うのは 1 コア)。
- 入れる所: 根 (T1MIX の後、根が閉じていないとき) と、木の新しい潜り (plunge_depth == 0) の頭。
  条件は mip_threads()==1・submip でない・再スタートの前・proof_only でない・FJ スレッドがない。
- 手間の取り分 s = 0.25·σ(logit h + logit f + logit g)。新しい閾値は入れていない。
  - h = (当たり+1)/(切れ端+2) (当たりの率、ラプラス)
  - f = (今 − 最後の改善)/今 (改善が止まっている割合)
  - g = 根の下界からの相対ギャップ (暫定解なしは 0.5)
  - 0.25 は 4 スレッドの heur_role の取り分 (ENOMOTO_T_MIP_HEUR_ROLE_FRAC) と同じ。
- 預金 = s·今 − 使った時間 が切れ端の最小 (FJ_MIX_SLICE、0.2 秒) を超えたら、min(預金, 残り時間の半分) を回す。
- 返った解は新しい順に試し、ラベルは「T1PRIMAL」。
- ALNS (FVbj) とは別勘定 (ALNS の frac には触れない)。予算をまとめるかは両方の P の結果が出てから相談する。

確かめ: fuzz.sh (ファザー 7 つを 1 スレッド・T1PRIMAL=1・切れ端 0.002 秒で回す) で不良 0、cargo test 425 通過 (fuzz.out)。

## 3. P (1 スレッド、60 秒、種 1〜3、58 問、summ_P.txt)

比 1.006 [0.997, 1.014]、解けた数 116 → 116、食い違い 0。全種 1.25 倍超の遅れ: markshare_4_0 [1.54, 1.37, 1.37]。

原因 (logs/diag_markshare_4_0_tp・_def、diag_qiu_tp・_def):
- markshare_4_0 は暫定解 1・下界 0 で g = 1.0 のまま。logit g = +∞ が当たり 0/16 (h 0.06) を押し流し、取り分が 0.25 に張り付く。

- 暫定解なしのときは f = 1 (logit +∞) で、h がいくら下がっても 0.25 のまま (bnatt400 の損も同じ所から)。

直し方の案 (次の版): f と g も h と同じ数 (切れ端の数 n) でラプラスにならし (x̃ = (x·n+1)/(n+2))、外れが続けば
h の下がりが f・g の上がりと打ち消し合って取り分が下がるようにする。暫定解なしの g は 1 にそろえる。

## 8. 3 版目・4 版目

### 3 版目の作り (bb391996c)

- 取り分を σ(logit h + (logit f + logit g)/2) に変えた (h = 当たりの率、f = 前の改善からの経過の割合、g = ギャップの割合。
  f と g はどちらも「要る」側の量なので平均し、h と同じ重みにする)。f・g は adapt.rs の laplace(·, n)、logit・sigmoid も共通の関数に付け替え。

  30n20b8 の長い潜りで止まるので、時の刻みを深さ > 0 の任意の節に変えた。

## 9. 5 版目 (P の遅れの切り分けと直し、674c7ebc5)

### 切り分け (logs/diag10、種 1、60 秒、4 版目)

P で遅れた 3 問 (markshare_4_0 1.15・mik-250-20-75-4 1.10・mzzv42z 1.08) は、どれもノード数・目的値が既定と同じ
(240417・3287・237 ノード)。遅れは T1PRIMAL が回した時間そのもの。

| 問題 | 既定 (秒) | 4 版目 (秒) | 回した回数 / 当たり | 回した秒 | 取り分の推移 |
|---|---:|---:|---|---:|---|
| markshare_4_0 | 9.0 | 9.7 | 4 / 0 | 0.8 | 0.062 → 0.078 → 0.087 → 0.092 |
| mik-250-20-75-4 | 7.4 | 7.8 | 1 / 0 | 0.2 | 0.062 |
| mzzv42z | 53.6 | 56.9 | 1 / 1 (根) + 再スタートの後 10 / 0 | 0.44 + 3.27 | 再スタートの後 0.062 → 0.114 |

- 外れが続くと取り分が上がる: 3・4 版目の σ(logit h + (logit f + logit g)/2) は、当たりなしで logit h = −log(n+1)、
  要る側が 1 のまま (markshare_4_0 は暫定解 1 がすでに最適で下界 0 なので g = 1、暫定解なしなら f = g = 1) だと
  (logit f + logit g)/2 = +log(n+1) となり、打ち消し合って σ → 1/2。それに laplace(1, n) → 1 が掛かり、取り分は 0.125 へ上がる。
  「短い問題で早いうちから取り分が大きい」のはこれ。
- 再スタートの後のやり直し (4 版目で足した部分): mzzv42z は根で T1PRIMAL が -5090 を当てた後に再スタート。後の solver では前処理で
  開始解が落ち (`the start solution is not feasible in the presolved problem; dropped`)、暫定解は打ち切り値にしか残らない。
  T1PRIMAL は「暫定解なし」(f = g = 1) と見て、回数も 0 から数え直し、当たりなしで 10 回 (3.3 秒) 回していた。mzzv42z の損のほぼ全部。
- ノード数は 3 問とも変わらないので、木への影響はない。

### 直し (新しい閾値なし)

1. 取り分 s = 0.25 × h × (f + g)/2 (当たる見込み × 要る度合い)。n = 0 で 0.0625 (3・4 版目の初めと同じ)。外れが続けば h とともに
   1/(n+2) で下がる。
2. 再スタートのとき、回した回数・当たった回数を次の solver に引き継ぐ (t1primal.rs の `CARRY`)。
3. 暫定解がなければ打ち切り値を暫定解の目的値として f・g を測る (`Solver::gap_frac_at(z)` を切り出した。`gap_frac()` の動きは同じなので
   FVbj の ubg は変わらない)。

種 1 の試し (logs/diag11): markshare_4_0 は回した秒 0.8 → 0.4、mzzv42z は 3.7 → 1.2 秒 (解き終わり 56.9 → 54.8 秒、既定 53.6 秒)。
