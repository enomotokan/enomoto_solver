# PDLP の解を中心化してから内点法に渡す案 (課題 PDLG、2026-11-11)

PDLP (restarted PDHG、`src/interior_point/pdlp.rs`) で荒い解を求め、近接内点法 (IP-PMM、`src/interior_point/boxed.rs` の
`solve_box_lp_warm`) を その解から始めるとき、先に解を中心化すれば滑らかにつながるのでは、という利用者の案を実装・計測した。
計測の台本と結果は `benchmarks/crossover/pdlg/`。

## 結論 (短く)

- **仮説 (最初の数反復が中心性で詰まる) は当たっていた**。`ENOMOTO_T_XO_PDLP=2` (PDLP の解を初期点にも、θ = 1e-2 で底上げ) の初期点は
  相補積の 最小/平均 が 1e-4〜3e-2、最大/平均 が 1e2〜1e3 (既定の Mehrotra 型の初期点は 0.6 と 2 程度) で、pilot.we・pilot87・dfl001・ship12l では
  最初の 2 反復の歩幅が 0.001〜0.1。
- 案 A (相補積を [μ/κ, κμ] に寄せる、κ = 10) で最初の歩幅は 0.3〜0.8 に戻るが、**内点法の反復の合計はほとんど減らない**。
- **効いたのは中心化より正則化の初期値 (案 C)**。PDLP の点から始めても ρ・δ の初期値が既定の 1e-4 のままでは、近接項が点を PDLP の点
  (近接中心) へ引き戻して進まない。1e-8 から始めると perold 130 → 77 反復、dfl001 61 → 40、osa-30 80 → 37、pilot.we は二段解法への差し戻しが消えた。
- それでも **109 問 (Netlib 93 + Kennington 16) の時間では基準より 1.31 倍遅い** (PDLP 500 反復の手間が小さな問題では内点法と同じくらい)。
  分解の重さ・問題の大きさで PDLP を使う問題を絞っても 1.00〜1.03 倍で、改善にはならない。**既定にしない**。
- 内点法が「最適」で終わらなかったときだけ PDLP から解き直す形 (`ENOMOTO_T_XO_IPM_RETRY_PDLP=500`、`_ANY=1`) は、109 問で二段解法への
  差し戻し 1 → 0 問、幾何平均 1.04 倍 (害も揺れの範囲を少し超える程度)。差し戻しの代わりの安全網としては使えるが、109 問では得がない。
- 先行研究: Rothberg "Hybridizing PDHG and Interior-Point Methods" (arXiv:2603.03150、2026-03) がほぼ同じ形 (PDHG 1e-4 → 中心化 → 内点法) を
  試し、内点法の反復は冷えた初期点の 0.51 倍 (1e-6 からなら 0.30 倍) に減るが 12〜19% は温め始めた内点法が最初の点から動けずに失敗し、
  Mittelmann 43 問の時間では冷えた初期点の内点法が総合で勝つ。中心化は尺度をそろえた後の問題で、1 回の変更を 1e-4 までに抑え、
  最初の歩幅が小さければ下限を 10 倍にしてやり直す。結論の向きは今回と同じ。

## 1. 試験用の切り替え (既定はすべて無効)

| 環境変数 | 働き |
|---|---|
| `ENOMOTO_T_PDLP_WARM_CENTER=κ` | 案 A。初期点の相補積 `s z` を [μ/κ, κμ] に寄せる。小さすぎる積は小さい側 (境界に張り付いた側) を持ち上げ、大きすぎる積も小さい側 (θ で底上げした 0 に近いはずの側) を下げる。`ENOMOTO_T_PDLP_WARM_CENTER_HI=0` で大きすぎる積はそのまま |
| `ENOMOTO_T_PDLP_WARM_MU=μ` / `_MU_MODE=1` | 中心化の目標 μ (大きさをそろえた後の単位)。未指定なら相補積の平均 (`_MU_MODE=1` で幾何平均) |
| `ENOMOTO_T_PDLP_WARM_CSTEPS=k` | 案 B。最初の k 反復を σ = 1・μ 固定の純粋な中心化の Newton 歩にする (残差の右辺は 0) |
| `ENOMOTO_T_PDLP_WARM_REG0=r` | 案 C (既存)。PDLP の点から始める内点法の ρ・δ の初期値 |
| `ENOMOTO_T_XO_PDLP_GATE=R` | 振り分け。KKT 系の分解の演算量の見積もり / nnz(A) が R 未満なら PDLP を使わない。見積もりで作った KKT 系は内点法がそのまま使う (記号分解を 2 回しない、`prebuild_kkt_flops`) |
| `ENOMOTO_T_XO_PDLP_MIN_NNZ=k` | 振り分け。nnz(A) が k 未満なら PDLP を使わない (問題の大きさの下限) |
| `ENOMOTO_T_XO_IPM_RETRY_PDLP=k` | 内点法が受理できない点で終わったら、PDLP を k 反復回した解から ρ・δ = `ENOMOTO_T_XO_IPM_RETRY_PDLP_REG0` (既定 1e-8) で解き直す。`_ANY=1` で受理できる未収束の点 (クロスオーバーが諦めることがある) でも解き直す |

あわせて、PDLP の経路の内点法にも同時実行の二段解法と共有する下界 (`lower_bound`・`bound_gap`) を渡すようにした (それまでは PDLP の経路だけ
渡しておらず、競争で早めに止められなかった)。

## 2. 現状の測定 (案 2 の反復ごとの歩幅と中心性)

`ENOMOTO_DEBUG_IPM=1` の反復ごとの `alpha_p・alpha_d・min(sz)/mu・max(sz)/mu` を 11 問で集めた (台本 `/tmp` の trace.py、1 回ずつ)。
最初の 2 反復の小さい方の歩幅と、0 反復目の相補積の比:

| 問題 | 既定: 歩幅 / min/μ / max/μ | 案 2 (PDLP 500 反復): 歩幅 / min/μ / max/μ |
|---|---|---|
| perold | 0.63 / 0.6 / 3 | 0.10 / 3e-2 / 80 |
| greenbeb | 0.62 / 0.6 / 2 | 0.11 / 8e-3 / 400 |
| pilot.we | 0.68 / 0.6 / 3 | 0.000 / 4e-5 / 500 |
| ship12l | 0.89 / 0.7 / 1 | 0.004 / 2e-2 / 4 |
| pilot87 | 0.74 / 0.6 / 2 | 0.01 / 2e-3 / 300 |
| dfl001 | 0.60 / 0.3 / 200 | 0.000 / 1e-4 / 1000 |
| osa-30 | 0.77 / 0.6 / 10 | 0.01 / 2e-2 / 40 |

PDLP の点は境界に張り付いた成分 (積 θ² 程度) と離れた成分 (積が大きい) が混じり、最初の数反復は中心性を取り戻すだけで終わる。

109 問すべて正解 (誤答・矛盾 0)。速くなったのは greenbea 0.36・beaconfd 0.38・pilot.we 0.47・pilot.ja 0.50・perold 0.68・greenbeb 0.73・dfl001 0.78 倍など、

pds・ken (多品種流) は反復がほとんど減らない (pds-20 86 → 84、ken-18 35 → 34)。

### 振り分け (利用者の指摘: 問題の大きさの下限)

上の p2+C(1e-8) の結果を、PDLP を使う問題を条件で絞ったとして数え直した (対象外の問題は基準と同じ時間とみなす。
KKT 系の記号分解は内点法と共有するので振り分け自体の手間はほぼない)。

| 条件 | 対象の問題数 | 対象の中の比 | 109 問全体の比 |
|---|---|---|---|
| なし | 109 | 1.31 | 1.307 |
| nnz(A) ≥ 1 万 | 37 | 1.21 | 1.065 |
| nnz(A) ≥ 10 万 | 8 | 1.31 | 1.020 |
| 演算量 / nnz(A) ≥ 100 | 30 | 1.10 | 1.027 |
| 演算量 / nnz(A) ≥ 200 | 26 | 1.06 | 1.014 |
| nnz(A) ≥ 5 万 かつ 演算量 / nnz(A) ≥ 200 | 7 | 1.07 | 1.004 |

大きさの下限だけでは、大きいが分解の軽い問題 (osa-60 nnz 61 万で 1.53 倍、osa-14 1.91 倍、fit2d 1.52 倍) を拾って損をする。
分解の重さ (演算量 / nnz(A)) のほうが目安として合うが、109 問ではどの条件でも基準を下回らない。109 問は小さい問題ばかりで、
PDLP の並列化 (行 2,048 本ごとに rayon) も 2 スレッドでほとんど効いていないので、判断は Mittelmann 級の大きな問題で行うべき。

## 5. 失敗したときだけ PDLP から解き直す (`benchmarks/crossover/pdlg/run_109_retry.sh`、3 案を交互に 3 回)

| 案 | 幾何平均 (秒) | 基準との比 | 二段解法へ戻した数 | 退行 |
|---|---|---|---|---|
| base | 0.04979 | 1.000 | 1 | — |
| R500 (受理できない点だけ) | 0.05067 | 1.018 | 1 | なし |
| R500any (未収束の点すべて) | 0.05176 | 1.040 | 0 | なし |

pilot.we は内点法が未収束のまま残差で受理され、クロスオーバーが「収束していない点からの頂点は主実行不能 371 本」で諦めて二段解法へ
戻っていた。R500any は PDLP 500 反復の点から 82 反復で収束し差し戻しが消える (0.21 → 0.20 秒)。ただし未収束で受理されても
クロスオーバーが成功する問題 (perold など) でも解き直すので少し遅くなる。
