# 木を閉じる力の調べ (treeclose2、親の依頼 2026-11-17)

題: csched008・sct2 で HiGHS は開いたノードを数十〜1400 に保って閉じるが、当方は数千〜1.8 万に増え続ける (treeclose の記録 9.55〜9.58 節)。
調べる 2 点: (1) 衝突解析の強さ、(2) 対称性。既定の動きは変えない (診断・試作は環境変数で)。

## 1. 計測 (`run.py`、打ち切り値つき・600 秒・4 スレッド・種 1、`res.jsonl`・`logs/`)

HiGHS 1.15.1 は源 (PyPI の sdist) に数え上げの計装を入れて scratchpad に別にビルドしたもの (ベンチマークの highspy は変えない)。
計装は主の MIP (サブ MIP を除く) の衝突解析の回数・作った衝突 (conflict cut と reconvergence cut) の数と長さ・衝突のプールの伝播で
刈った数と締めた境界・軌道の固定の数を数え、`cleanupSolve` で `ENOSTATS` の行に出す。

| 回 | 結果 | 節点 |
|---|---|---|
| HiGHS sct2 | **356 秒で最適** | 21928 |
| HiGHS sct2 対称性なし (`mip_detect_symmetry=false`) | **541 秒で最適** | 34263 |
| HiGHS csched008 | **190 秒で証明** (打ち切り値の下に解なし) | 12329 |
| 当方 sct2 既定 | 時間切れ | 98628 |
| 当方 sct2 対称性なし (`ENOMOTO_MIP_NO_SYMMETRY`) | 時間切れ | 118412 |
| 当方 sct2 衝突を長く持つ (`ours_cut_keep`) | 時間切れ | 99979 |
| 当方 csched008 既定 | 時間切れ | 93247 |
| 当方 csched008 衝突を長く持つ | 時間切れ | 100283 |

### 衝突解析の数 (当方は主のスレッド)

| | HiGHS sct2 | 当方 sct2 | HiGHS csched008 | 当方 csched008 |
|---|---|---|---|---|

- 衝突の長さとその上限 (HiGHS は `10 長さ > 1000 + 3 整数列数` で捨てる) は同じ桁で、差の元ではない。
- **プールの持ち方**: 当方は役に立たずに 1000 回調べられた衝突を消すので、終わりのプールは 800 本前後 (追加の約 9 割が消える)。
  HiGHS は 1 万本 (`mip_pool_soft_limit`) を超えたときだけ年齢で消す。当方で年齢で消さず枠 1 万にした回 (`ours_cut_keep`、
  既存の調整用変数 `ENOMOTO_T_MIP_LIT_CONFLICT_AGE`・`_POOL`) は、sct2・csched008 とも閉じず、刈ったノードも増えない。**決め手ではない**。

### 対称性

- HiGHS の生成元 28 個は、根で 2 回再スタートして整数列を 24%・6.4% 減らした後のモデルで見つけたもの。当方は縮める前のモデルで 82 個
  (19 個を軌道の固定に、残りは完全な orbitope 19 個)。
- HiGHS は対称性を切っても sct2 を閉じる (356 → 541 秒)。当方は対称性を切っても閉じない。**対称性は閉じる・閉じないの差の元ではない**。
  csched008 は両方とも対称性なし。

## 2. 当方の衝突解析が止まる理由 (診断 `ENOMOTO_MIP_CONFLICT_LEV_DIAG`、既定では動かない)

[`Domain::analyze_multi_bumps`] (HiGHS 式の衝突解析) に診断を足した: 深さごとに 1-UIP まで解けたか・解けずに残った変更の理由と、
解析 1 回ごとの止まり方。数は全スレッドの合計。下は 180 秒の回 (同じ条件)。

| | sct2 | csched008 |
|---|---|---|
| 解析 | 11816 | 11612 |
| 作った衝突 (解析 1 回あたり) | 61829 (5.2) | 16881 (**1.45**) |
| 遡った深さ (解析 1 回あたり) | 88755 (7.5) | 41445 (3.6) |
| 最初の深さで解けず衝突 1 本で終わった解析 | 2179 (18%) | **4442 (38%)** |
| 5 段の規則で止まった解析 | 8159 | 7107 |
| 深さのうち 1-UIP まで解けなかった | 6089 / 88755 (7%) | 6971 / 41445 (17%) |
| 解けずに残った変更の理由 | 双対証明 128671・局所の被約費用 63216・目的関数 8051・orbitope 4313・決定 2285 | **双対証明 656483**・決定 5315・リテラルの衝突 2979 |

- 当方の解析は**問題の行による変更しか遡れない** (`explain_change` は理由が行でない変更に `None` を返し、深さの中で遡る相手から外す)。
  双対証明・リテラルの衝突・目的関数の伝播・局所の被約費用で変わった境界は、決定と同じく葉として残る。
- csched008 では、1-UIP まで解けなかった深さに双対証明の変更が平均 94 個残る。解析の 38% は最初の深さで何も遡れずに衝突 1 本で終わる。
- HiGHS は `HighsDomain::ConflictSet::explainBoundChange` で、問題の行に加えてカットのプール (双対証明もここに入る)・衝突のプール・
  目的関数の伝播による変更も遡る。
- 主のスレッドだけの数 (`MIP: conflict analysis (HiGHS style)`) で 1 回あたり 1.6〜1.7 本なのは、主のスレッドの解析の回数に
  解析の時間の上限で休んだ呼び出しなども入るため (全スレッドの診断の数の方が HiGHS の数と比べやすい)。

## 見立てと次の案

- 差の元の候補: **双対証明による境界の変更を衝突解析で遡れないこと** (csched008 で特に大きい)。sct2 は 1 回あたり 5.2 本で HiGHS の
  6.5 本に近く、残る差は局所の被約費用・双対証明。
- 試作案 (既定は変えない): 双対証明で締めた変更に証明の番号を残し (番号は使い回さない。証明がプールから消えていれば遡らない = 今と同じ)、
  [`Domain::analyze_multi_bumps`] の `explain_change` が証明の行でも説明できるようにする。

## 3. 試作 `ENOMOTO_MIP_CONFLICT_PROOF_EXPLAIN` (b4cd4d270、既定では使わない) の確かめ

双対証明で締めた変更に証明の通し番号を、カットのプールの伝播で締めた変更に写しの表 (番号の変わらないカットの写し) の番号を残し、
[`Domain::analyze_multi_bumps`] の `explain_change` でその行から遡る (HiGHS の `explainBoundChange` がカットのプールの行を遡るのと同じ)。
引けなければ (証明が捨てられた・番号が付け直された) 従来どおり葉。cargo test --release --lib 419 通過。

| 回 (打ち切り値つき・600 秒・4 スレッド・種 1) | 結果 | 最後の下界 | 節点 | 解析 1 回あたりの衝突 (全スレッド) | 最初の深さで止まった解析 |
|---|---|---|---|---|---|
| csched008 既定 | 時間切れ | 172 | 93247 | 1.45 (180 秒の回) | 38% |
| csched008 試作 | 時間切れ | 172 | 68132 | 1.64 | 26% |
| sct2 既定 | 時間切れ | −231.0636 | 98628 | 5.2 (180 秒の回) | 18% |
| sct2 試作 | 時間切れ | −231.0636 | 77160 | 5.9 | 11% |

- 双対証明・カットのプールの変更は解けずに残らなくなった (残りはリテラルの衝突・局所の被約費用・目的関数・決定) が、**どちらも閉じず、
  節点は 2〜3 割減る** (説明のための証明・カットの写しと解析の手間)。
- csched008 の解析 1 回あたりの衝突は 1.45 → 1.64 本で、HiGHS の 7.5 本には遠い。最初の深さで止まる解析 (分枝の直後に LP が実行不能に
  なり、遡る変更がない) は HiGHS でも衝突 1 本で終わる形。
- sct2 は既定でも 1 回あたり 5.2 本で HiGHS の 6.5 本に近いのに閉じない。**衝突の数は sct2 の閉じない差の元ではない**と見る。

## まとめ (2026-11-17)

- 調べた 4 つ (衝突を長く持つ・対称性を切る・双対証明を遡る・カットのプールを遡る) は、どれも csched008・sct2 を閉じない。
  HiGHS は対称性を切っても sct2 を閉じる。
- 衝突解析の作りの違い (遡れる理由の種類) は事実としてあるが、HiGHS と同じにしても閉じないので、木を閉じる力の差の元ではない。
- 試作 `ENOMOTO_MIP_CONFLICT_PROOF_EXPLAIN` は採らない (試作のまま残す)。対の台本は作らない。
- 残る候補 (推測): HiGHS の csched008 の解析 1 回あたり 7.5 本の内訳 (reconvergence が 28644 本と多い) と当方の差、ノードの LP の下界の
  動き方 (sct2 は深さ 250 でも LP 値が打ち切り値まで 0.05 縮まない、9.56 節)。

## 4. 候補 (1)・(2) (親の依頼 2026-11-17 午後、1 スレッド・打ち切り値つき・600 秒・種 1)

擬似費用・子の下界)、`ENOSTATS2` (reconvergence の UIP の理由・解析で遡った変更の理由)。当方は既存の `ENOMOTO_MIP_TREE_LOG` の
`ENODE`・`EBR` の行の後ろに `plb=` (取り出したときの下界)・`src=` (dive / queue / shared)・`t=`・`n=`、`EBR` に `pcd=`・`pcu=` を足した。
