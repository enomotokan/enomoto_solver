# 4 スレッドで nra の統計をスレッド間で共有する試作 `ENOMOTO_MIP_NRA_SHARE` (2026-11-26、親の依頼)

analysis/par4_20261126/README.md の候補 4。c2c の 4 スレッドの nra の害 (neos-631710 1.78 倍・neos-911970 1.66 倍) について、
各スレッドが自分の木だけで数える統計 (φ・f、ĝ) を全スレッドの合計で数える形にした。既定ではオフ。

## 0. まとめ

- **食い違いは大きい**。同じ時刻でもスレッドごとの f (外す割合) が 0.01〜0.99 に割れる (1 節)。
- **共有で f はそろう**。neos-911970 の同じ時刻のスレッド間の f の幅は、平均 0.29 → 0.12。
- **それでも害は共有では消えない**。neos-911970 の害を消すのは nra の `p` (φ の補正) で、共有を足しても良くならない。
  neos-631710 の遅れは nra の統計とは関係がない (2 節)。
- 1 スレッドの道筋は変わらない (プールがないので読まない)。cargo test は共有ありで 424 通過。
- **P の計測はしていない**。3 問で共有の得が見えず (r0k23p の上では 9 回のずらし幾何平均 53.9 → 54.4)、採る理由がないため。

## 1. 診断: 4 スレッドの nra の統計のスレッドごとの食い違い

`diag.sh` (c2c、4 スレッド・種 1、`ENOMOTO_MIP_NRA_TRACE=500`・ログつき) → `diag_summ.py`。
各求解 (再スタートで区切る) の終わりの、スレッドごとの閉じた葉 [実行不能/下界] と、そこから計算した φ・f。最後の列は全スレッドの合計から計算した値。

| 問題 | 求解 | スレッドごと (φ / f) | 合計の φ / f |
|---|---|---|---|
| neos-631710 | 最後 | t0 0/0 (0.50 / 0.54)、t1 1/0 (0.67 / 0.95)、t2 4/0 (0.83 / 1.00)、t3 2/0 (0.75 / 0.99) | 7/0: 0.89 / 1.00 |
| neos-911970 | 最後 | t0 238/213 (0.53 / 0.65)、t1 227/210 (0.52 / 0.62)、t2 498/175 (0.74 / 0.99)、t3 410/173 (0.70 / 0.97) | 0.64 / 0.93 |
| rococoC10-001000 | 2 回目 | t1 (0.35 / 0.09)、t2 (0.31 / 0.04)、t3 (0.55 / 0.73) | 0.43 / 0.26 |
| rococoC10-001000 | 最後 | φ 0.19〜0.32 / f 0.01〜0.06 | 0.26 / 0.02 |

- `NRA_TRACE` の 4 行ずつの組で見た、同じ時刻のスレッド間の f の幅: neos-911970 は平均 0.29・最大 0.69、rococoC10-001000 は平均 0.42・最大 0.87。
- neos-631710 は、葉がほとんどないうちに f ≈ 1 に張りつく。ラプラスの補正 (1, 1) でも、実行不能の葉 1〜4 枚で φ > 0.49 になる。
  合計で数えても 7/0 で f 1.00 なので、共有では変わらない見込み。
- neos-911970 の最後の求解は、合計でも φ 0.64・f 0.93 (外す側)。共有しても外す側にいる見込み (par4 の見立てと同じ)。

## 2. 試作 `ENOMOTO_MIP_NRA_SHARE` (src/mip/solver.rs `nra_share_on`・`nra_leaf_counts`・`nra_gain_sums`・`pc_gain_add`)

- 木を分け合うプール (`WorkPool`) に、閉じた葉の数の加算器 `nra_sh_leaves` [実行不能, 下界] と、プールのラウンドの伸びの加算器 `nra_sh_gain` [和, 回] を置く。
- `nra_leaf` と `pc_gain` の更新で、自分の数に加えて加算器にも足す。プールがない間 (木を分け合う前) の分は取っておき、後の合計に足す。
- φ (`nra_share`) と、`p`・`g` の ĝ を、全スレッドの合計から計算する。
- プールがなければ (1 スレッド) 今のまま。再スタートの後はプールが新しく作られるので、合計も数え直し (今のスレッドごとの数と同じ)。
- 新しい閾値はない。
- 共有の効き (neos-911970、c2c + 共有、種 1、`logs_neos-911970_c2cs_s1.err`): `NRA_TRACE` の φ は同じ時刻で全スレッドが 0.474〜0.487 にそろい、
  f の幅は平均 0.12・最大 0.27 になった (共有なしは 0.29・0.69)。残る幅は、加算器を読む時刻の違いの分。

## 3. 比べ (4 スレッド、種 1〜3、300 秒、1 本ずつ順に。`run.py` → `res3.jsonl`)

設定:
- c2c: analysis/combo2_20261125/cfg.py の C2C (nra は `r0k23`)。
- c2cs: c2c + 共有。
- c2cp: c2c の nra を `r0k23p` にしたもの (親の追加: nra の採用候補)。
- c2cps: c2cp + 共有。

秒 (種 1 / 2 / 3、太字は幾何平均)、答えは 45 回ともそれぞれの問題の最適値。

| 問題 | 既定 | c2c | c2cs | c2cp | c2cps |
|---|---|---|---|---|---|
| neos-631710 | 28.1 / 32.4 / 32.6 (**31.0**) | 47.4 / 50.6 / 47.7 (**48.5**) | 43.8 / 49.6 / 51.5 (**48.2**) | 51.2 / 53.1 / 44.9 (**49.6**) | 53.7 / 53.7 / 49.6 (**52.3**) |
| neos-911970 | 13.6 / 15.5 / 10.2 (**12.9**) | 29.1 / 20.1 / 16.9 (**21.5**) | 22.5 / 15.5 / 19.6 (**19.0**) | 13.9 / 13.6 / 9.7 (**12.2**) | 11.8 / 19.5 / 12.8 (**14.3**) |
| rococoC10-001000 | 194.9 / 184.2 / 175.4 (**184.6**) | 120.5 / 175.8 / 208.2 (**164.0**) | 136.4 / 206.4 / 152.1 (**162.4**) | 152.0 / 195.1 / 217.0 (**186.0**) | 156.9 / 234.8 / 121.9 (**165.0**) |

9 回のずらし幾何平均 (ずらし 10 秒): 既定 46.8、c2c 58.6、c2cs 56.3、c2cp 53.9、c2cps 54.4。

- **neos-911970**: 害を消すのは `p` (c2cp 12.2、既定 12.9)。共有だけ (c2cs 19.0) は少し縮むが残る。`p` と共有を組み合わせても (14.3)、`p` だけより良くならない。
  共有は f をそろえるが、合計の φ 自体が外す側 (1 節の 0.64) にあるので、自己強化の循環を止める `p` が要る。
- **neos-631710**: 4 形とも 48〜52 秒で、既定 (31 秒) との差は nra の統計では動かない。
  ノード数は 51〜6269 と大きく動くが、時間は変わらない。害の元は nra の外し方の判定ではなく、ほかの部品と見られる (未切り分け)。
- **rococoC10-001000**: 共有の有無の差は種ごとの揺れの中 (162〜186)。

## 4. 確かめ

- 1 スレッド (`res1t.jsonl`、種 1、300 秒): 共有の有無で道筋は同じ。
  - neos-631710 は 4 形とも 1300 ノード。neos-911970 は c2cp・c2cps とも 7727 ノード。
  - c2c・c2cs の neos-911970 はどちらも 300 秒で時間切れ。そこまでに処理したノード数 (113685・113018) は速さで変わるので比べられない
    (1 スレッドではプールがなく、共有のコードは読まれない)。
- cargo test (`ENOMOTO_MIP_NRA_SHARE=1`): 424 通過・0 失敗。
- 試作をつけないときは、加算器に足すだけで読まないので、既定・c2c の道筋は変わらない (共有を読むのは `nra_share_on` のときだけ)。
