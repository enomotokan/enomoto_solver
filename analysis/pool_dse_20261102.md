## 1. 仕組み

- 渡す側 (`snap_of` → `SnapNode::of_with_basis`): ノードに保存した親の LP の DSE 重み (`OpenNode::dse`、`dse_snapshot` の (変数番号, 重み)) から、
  列 (j < n) と元の行 (n + i、i < m) の基底変数の分だけを `SnapNode::dse` に付ける。カットの行の分はスレッドごとに違うので捨てる。
  元の行の番号は行の追加・削除 (カットの行だけ) で変わらないので、番号はそのまま使える。
- 受け取る側 (`open_from_pool`): 基底と一緒に `OpenNode::dse` に入れる。`restore_node_basis` で基底を置いた後
  (`POOL_BASIS_FIX` なら `fix_pool_basis` で直して置いた後。今までは直した経路では重みを当てはめていなかった) に `set_dse_vars` で当てはめ、
  `restored_dse` → `WARM_DSE_ONCE` で最初の LP が引き継ぐ。直しで外した列の重みは捨て、重みのない基底変数 (直しで残った・入った列、
  カットの行のスラック) は 1。値 `n` (`ENOMOTO_MIP_POOL_DSE=n`) なら重みのない基底変数を `NaN` にし、求解の始めにその行だけ BTRAN で厳密な値を埋める
  (`DseState::fill_missing`。既存の仕組み)。
- 主が従を始めるときの `TreeSnapshot` の nodes (依頼の (2)) は、既定 (racing でない) では空 (`make_snapshot(.., with_nodes = false)`) で、
  従は根の LP の後に共有の待ち行列からノードを取る。racing (`ENOMOTO_MIP_TREE_RACING`) のときのノードは基底も渡していない (`basis: None`) ので、
  重みだけを渡しても使えない。今回は (1) の共有の待ち行列だけに付けた。
- 診断: `ENOMOTO_MIP_NB_DIAG` (か `ENOMOTO_PROF_TREE_PAR`) で、スレッドごとに
  `POOL_DSE: tid t sent ノード 重み (KB) received 受け取ったノード applied 当てはめた回 basic with weight 重みのあった基底変数 without なかった数` を出す。

### 渡すデータの大きさ

1 ノードあたり (u32 + f32) × 基底の数のうち列と元の行の分。今回の 8 問で 1 ノード 40 (eil33-2)〜2600 (mc11) 個、つまり 0.3〜20 KB。
1 問 60 秒の合計は mc11 1.9 MB (94 ノード)、roll3000 1.8 MB、neos5 12 MB (22324 ノード、1 ノード 70 個 = 0.55 KB)。
重みの切り出しは `snap_of` (錠の外) で、錠の中では `Vec` を動かすだけなので、共有の待ち行列の錠の時間はほぼ変わらない。
基底の状態 (列 + 元の行、1 バイト × (n + m)) に対して 4〜8 倍の大きさだが、ノード数の多い neos5 でも合計は小さい。

当てはめた基底変数のうち重みがあったのは neos5 63/137、misc07 211/570、noswot 171/509、neos-911970 107/540、swath1 495/615、eil33-2 32/60、
roll3000 1588/2145、mc11 1916/3625 (both、受け取った 1 ノードの平均)。重みのない分はほとんどがカットの行のスラック。

### 読み

- **pool の 1 LP の反復 (fix → both)**: 大きい問題で重みが効く。roll3000 2678 → 1804 (−33%)、mc11 2889 → 1805 (−38%)、neos-911970 938 → 712 (−24%)、
  swath1 486 → 264 (−46%)、noswot 73 → 56。小さい問題 (neos5 50 → 53、eil33-2 44 → 45、misc07 65 → 81) は変わらないか少し増える
  (重みのない基底変数 (カットの行のスラック) が半分以上で、1 にした分が不正確)。
- `bothn` (重みのない分を厳密な値で埋める) は 1 回だけだが pool の反復は both よりさらに少し少ない (misc07 81 → 59、swath1 264 → 192 など)。
  埋める BTRAN の分の時間を差し引いて得かは 1 回では言えないので、bench17 は `=1` にする。
- **dse 単独は効かない**: 受け取った基底は直さないと全件特異 (NB_DIAG の tree_pool の n_noeff = n) で、warm start を捨てて全スラック基底から
  解くので重みは使われない。時間の差はノード数の振れ (neos-911970 の 51.4 秒の回は pool の LP が 534 回に増えた探索の順の違い)。
- 時間は 1 問 2 回で振れが大きい (mc11 base 16.8 / 37.7、misc07 both 29.0 / 9.9) が、8 問の SGM は both が最も小さい (base 33.67 → both 31.72、−6%。
  fix 単独は 37.15 で今回は base より遅い。analysis/singular_fix_b_20261102.md の 58 問 1 回では fix −1.5%)。
  noswot・roll3000・mc11 で both が base・fix より速く、eil33-2 (57.3、1 回時間切れ)・misc07・neos-911970 で base より遅い。
- 既定にはしない。bench17 で `POOL_BASIS_FIX=1 POOL_DSE=1` を 58 問・Mittelmann で確かめる。
