## 1. 数える (事実)

### 1.1 ログの拾い方

`parse.py` は、主の根の最初のカットのループについて、ラウンドごとに本数・候補の数・LP の反復・目的値を拾う。上限に当たったラウンドは
`LP status IterationLimit|TimeLimit, removed the cuts` の行と、その前の進みの判定の行 (`stopped by the progress check at iter I (cap C)`) から
上限・反復・出発からの伸びを拾う。終わり方は `cap_stop` (`ENOMOTO_MIP_CUT_LP_CAP_STOP=flat` で止まった)・`fail_return` (2 回目の失敗で関数から戻った)・
`time_cap` (根のカットの時間の上限)・`other` (停滞などの普通の止まり方)。既存のログには上限に当たったラウンドの本数が出ないので、
診断の行 (`CUTLPCAP cap ... cuts ...`) を足した (`ENOMOTO_MIP_CUTLPCAP_LOG`)。

### 1.2 既定の今の上限と止め方 (コードで確かめた)

- 反復の上限 `lim` = max(0.1 x 根の LP の反復, 1000, 5 x このループで最適まで解けたカットの LP の最大の反復)
  (`ENOMOTO_T_MIP_CUT_LP_WORK=0.1`・`..._PREV=5`)。
- `ENOMOTO_MIP_CUT_LP_CAP_ROBUST=p`: `lim` を過ぎても、0.25 x lim 反復の窓ごとに目的値の伸びを見て、窓の伸びが出発からの伸びの 1% 未満に
  なったら止める (安全網は 10 x lim)。
- 止まったら、そのラウンドのカットを全部外して解き直す。下界がまだ根の LP の値から動いていなければ (`CUT_LP_CAP_STOP=flat`) ループを止める。
  動いていれば失敗 1 回と数え、2 回目で関数から戻る。

## 2. 原因を分ける

### 2.1 HiGHS v1.15.1 のやり方 (ソースで確かめた)

- カットの LP の反復の上限: `HighsMipSolverData::evaluateRootNode` で、根の分離の間は
  `setIterationLimit(std::max(10000, int(10 * avgrootlpiters)))` (`avgrootlpiters` はこれまでの LP の平均の反復)。ENOMOTO の既定 (0.1 x 根の LP、最低 1000)
  より 100 倍大きく、最低も 10 倍。
- 上限に当たったとき (`HighsLpRelaxation::run` の `kIterationLimit`): サブ MIP でなければ、同じ LP を内点法 (IPX、反復の上限 200、
  単体法の反復の上限は止まった時点の数) で解き直して基底を作る。カットを全部外すことはしない。解けなければ状態が最適でなくなり、
  根の分離のループ (`while (getLp().scaledOptimal(status) && ...)`) を抜ける。
- 1 ラウンドの本数: 上限はない。`HighsCutPool::separate` は、点数 (違反 / (非零の数 x ノルム)) が最良の点数の `minScoreFactor` 倍
  (動的に調整) 以上のものを点数の順に見て、すでに採ったものとの平行度が 0.1 を超えるものを捨てる。平行度の閾値が厳しく
  (ENOMOTO の既定は 0.3)、似たカットをまとめて入れにくい。

- 1 ラウンドの本数の上限は既定 50 本 (`ENOMOTO_T_MIP_ROOT_MAX_CUTS`) だが、**implied bound カットは選択を通さずに全部入る** (`forced`、
  `separation.rs` の implied bound の分離。pg のために入れたもの)。istanbul・lectsched・kumeu・widden の数百〜1440 本はほとんどがこれ (推測: 本数の差から。
  ログに分離器ごとの内訳は出していない)。HiGHS も implied bound カットをプールに入れるが、`HighsCutPool::separate` の点数と平行度 0.1 の選択を通る。
- 一方 cod105・satellites2-40・neos-960392・neos-1354092 は数本〜15 本で当たる。本数ではなく、LP が退化して上限 (最低 1000) の中で目的値が進まない。

### 2.3 分け方 (推測を含む)

- **上限が小さすぎる**: 当たった回はすべて上限が最低値 1000 (根の LP の 0.1 倍が 1000 より小さい) か、その近く。HiGHS の最低 10000 の 1/10。
  出発からの伸びが正の問題 (widden・istanbul・neos-1354092・thor50dday・mzzv11 など) は、上限を広げれば (前の HO4_CUT0・CUT0_RETRY が示したように) 解き切れる見込みがある。
- **カットが多すぎる**: implied bound カットを全部入れる問題 (istanbul・lectsched・kumeu・widden) と、並行の試作 (MODKVB の physiciansched6-2 の 296 本、HNFSUBST の mzzv11)。
- **LP が退化して進まない**: 伸びがちょうど 0 の問題 (cod105・kumeu・satellites2-40・neos-960392、既定の physiciansched6-2 の 7 ラウンド目)。neos-960392 は根の LP の値が
  すでに最適値で損はない。他は HiGHS の根が高いので、カットを入れて LP を解き切れば上がるはずだが、比の判定 (退化) の直しは小さくない (puriri_cutlp の記録)。

## 3. 試作 `ENOMOTO_MIP_CUTLPCAP` (既定では使わない、`src/mip/separation.rs`)

主の根のカットのループ (サブ MIP でも裏のカットの写しでもない) だけ。値は文字の並び。

- `a`: カットの LP が上限 (反復・時間・進みの判定) に当たったら、全部外す前に、そのラウンドのカットを効き目 (選んだときの `efficacy`) の
  大きい順に半分だけ残し、加える前の状態 (`save_state`) から同じ上限で解き直す。最適になるか `ENOMOTO_T_MIP_CUTLPCAP_AMIN` 本 (既定 5) 未満に
  なるまで繰り返す。最適になればそのラウンドを成功として続け、以後の 1 ラウンドの本数の上限を残した本数にする。最適にならなければ既定と同じに外す。
- `n`: 1 ラウンドに入れる本数 (選択を通らないカットも含む) を、0 ラウンド目は `ENOMOTO_T_MIP_CUTLPCAP_N0` 本 (既定 100)、以後は前に最適まで
  解けたラウンドの本数の `ENOMOTO_T_MIP_CUTLPCAP_NMULT` 倍 (既定 2) と N0 の大きい方までに、効き目の順に絞る。
- `c`: 反復の上限を `ENOMOTO_T_MIP_CUTLPCAP_CMULT` (既定 1) x max(根の LP の反復, 前処理の LP の反復, 今の LP の行の数) より小さくしない。
- `l` (または `ENOMOTO_MIP_CUTLPCAP_LOG`): ラウンドごとに上限と本数を出す (診断)。
