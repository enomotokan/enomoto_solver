# 試作 `ENOMOTO_MIP_GEN_LAZY` (余裕のある一般の不等式の行を LP から外し、破られたら戻す。2026-11-17、GENLAZY)

CLQ_LAZY (treeclose 9.80〜9.82 節、クリーク型の行だけ) を一般の行に広げた試作。既定では使わない。作りの説明は `src/mip/genlazy.rs` の頭。

## 切り替え

| 環境変数 | 意味 |
|---|---|
| `ENOMOTO_MIP_GEN_LAZY` | `1`・`all` で使う。`clq,one,vb,knap,int,mix,cont` のコンマ区切りで外す行の種類を選ぶ |
| `ENOMOTO_T_MIP_GEN_LAZY_THETA` | 余裕の判定のしきい値 θ (既定 0.5): 正規化した活動 a = (c·x − 最小活動)/(b − 最小活動) が θ 以下の行を外す (最小活動が無限なら a = 1/(1 + 余裕/‖c‖₂)) |
| `ENOMOTO_MIP_GEN_LAZY_MODE=score` | 点数の判定 (利用者の指示): カットの質 `cut_quality` と同じ点数 (効き目 + 0.1×目的との平行度 + 0.1×整数台、効き目は (c·x − b)/‖c‖ で満たされていれば負) が τ 未満の行を外す |
| `ENOMOTO_T_MIP_GEN_LAZY_TAU` | 点数の判定のしきい値 τ (既定 0) |
| `ENOMOTO_T_MIP_GEN_LAZY_AGE` | A > 0 なら、戻した行がノードの LP 解で A 回を超えて張り付かなければ外し直す (既定 0 = しない) |
| `ENOMOTO_MIP_GEN_LAZY_SB=1` | 強分岐の子の LP 解が破った外した行を、分枝の選びの後に戻してノードを解き直す |
| `ENOMOTO_MIP_GEN_LAZY_BACK=cut` | 戻すときカットの行として加える (CLQ_LAZY と同じ)。既定は元の行の境界を戻す |
| `ENOMOTO_T_MIP_GEN_LAZY_VIOL` | 破りの判定 c·x > b + tol·max(1,|b|) の tol (既定 1e-7) |
| `ENOMOTO_MIP_DIAG_GENLAZY` | 診断: 木に入るときの種類ごとの片側の行の数・スラックが基底の数・非零・外した数と、正規化した活動・点数の分布を `GENLAZY {...}` の 1 行で出し、終わりに `GEN_LAZY stats` を出す。`stop` なら外さない |

- 外すのは片側だけの不等式で、スラックが基底にある行だけ (両側の行・等式は外さない)。
- TREECLOSE の `ENOMOTO_MIP_DIAG_ROWTYPES` (`analysis/rowtypes_20261117/`) と役割を分けた: あちらは行の種類ごとの量・相対の余裕のおおまかな分布・
  大域の境界の下で冗長な行 (GREDUNDANT の見込み)、こちらは「木に入る時点で LP から外せるか」(正規化した活動・点数の細かい分布と外した行・戻した行) に絞る。

## 正しさ (`fuzz_*.txt`、`fuzz.sh`)

  M は (問題, 種) ごとの秒・時間切れの下界も出す)。**この台本のコミット以降でビルドして回す** (`maturin develop --release`)。ソルバーは同時に 1 つ。

  同じ (問題, 種) の 7 設定は同じ分担で続けて解く。
- P: 58 問 × 種 1〜3 × 7 設定、4 スレッド・60 秒 (1218 回)、12 分担 (各約 0.84 時間): `python run.py P K` (K = 0〜11)。
- M: mzzv11・neos-933966・supportcase33・neos-3216931-puriri・neos-1456979・neos-3627168-kasai・irp × 種 1・2 × 7 設定、600 秒 (98 回)、
  14 分担 (各約 1.2 時間): `python run.py M K` (K = 0〜13)。

## mzzv11 の切り分け (`local_D.out`・`local_E.out`・`local_F.out`、手元 300 秒・4 スレッド・種 1)

| 形 | 外した行 | 結果 |
|---|---|---|
| def (2 回) | — | 時間切れ (下界 −21806・−21942) |
| GEN_LAZY を入れて外さない (診断 stop、τ −100・−1000・−3) | 0 | 4 回とも時間切れ |
| 作り直しだけ (`ENOMOTO_MIP_GEN_LAZY_TOUCH`、選んだ行の境界を同じ値で設定し直す) 1 行分・148 行分 | 0 | 2 回とも時間切れ (ノード 619・277 と少ない) |
| 点数 τ −1 | **1 行 (非零 2)** | **281.9 秒で最適** |
| 点数 τ −0.3 | 148 行 (非零 0.5%) | 256.0 秒で最適 |
| θ 0.1・0.5・1.0、点数 τ 0・−0.1 | 3199〜5320 行 (44〜78%) | 162〜224 秒で最適 |

- **1 行外すだけで効く**。対の比べ (600 秒、2 種) でも外す形は 14 回とも def (時間切れ・533 秒) より速い。外さない形・標準形の作り直しだけでは
  効かないので、効き目は「LP に空の行 (両側とも無限の境界の行) がある」こと自体から来る。LP が軽くなる効き目ではない。
- 空の行があると変わる所 (`has_free_rows` が真): 基底の修復で空の行のスラックを基底に入れる (`repair_basis`)、受け渡しの基底の直し
  (`fix_pool_basis`) で空の行を外す、双対・Farkas・tableau の重み・被約費用で空の行を 0 にする、標準形で空の行 (0 = 0) にする。
  どれが mzzv11 の道筋を変えるかは未特定 (外した 1 行は直接は何も変えないはずの行で、戻しも 0 回)。TREECLOSE の puriri の現象 (外す形で 1 本のスレッドの
  LP だけが重くなる) と同じ所に根がある可能性がある。次の一手は、空の行のある LP で上の 4 つを 1 つずつ元に戻して mzzv11 が時間切れに戻るかを見ること。

### 空の行の扱いを 1 つずつ戻す切り分け (`local_G.out`・`local_H.out`、診断 `ENOMOTO_MIP_FREEROW_OFF`・`ENOMOTO_MIP_FIXROW`、手元 300 秒・種 1)

基準は「点数 τ −1 で 1 行外す」(sm1、281.9 秒で最適)。

| 形 | 結果 |
|---|---|
| sm1 + `r` (基底の修復で空の行のスラックを基底に入れない) | 288.6 秒で最適 |
| sm1 + `d` (双対・Farkas・tableau・被約費用で 0 にしない) | 257.4 秒で最適 |
| sm1 + `p` (受け渡しの基底の直しで空の行を特別に扱わない) | 257.9 秒で最適 |
| sm1 + `s` (標準形で空の行にせず、係数を残してスラックを自由変数に) | **時間切れ** (下界 −21912) |
| 行を外さず、中身のない固定の行 (0 = 0、スラック [0, 0] の基底変数) を LP の末尾に足す (`ENOMOTO_MIP_FIXROW`) | **時間切れ** (下界 −21898) |

- `r`・`d`・`p` (後から入った直し・双対の 0 扱い) は効き目に関係しない。効くのは標準形で「その行の係数が消え、スラックが [0, 0] に固定された基底変数になる」形。
- ただし固定された基底変数を 1 本足すだけ (FIXROW) では効かず、行の係数を残して行を無効にする形 (`s`) でも効かない。**その行の係数が行列から消え、
  かつその位置に固定の基底変数が残る**組み合わせでだけ効く。行列の形 (LU の軸の選び・同点の崩し) を通した道筋の違いと見るのが自然で、
  「既定の経路の処理の弱点」として取り出せる直しの形は見つからなかった。mzzv11 の def が 4/4 で遅く外す形が 22/22 で速いのは偶然とは考えにくいが、
  1 問の道筋の性質で、他の問題に広がる直しにはならない見込み (P・M の対の比べでも外す形は全体で中立)。
- FIXROW の確かめ: fuzz 600 問 (前処理なし 300・既定 300、4 スレッド) で食い違い 0。
