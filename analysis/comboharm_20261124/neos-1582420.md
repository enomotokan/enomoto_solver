# neos-1582420 の combo の害 (2026-11-25、親の依頼)

combo の計測 (analysis/combo_20261124) で 1 スレッドが 2.2 倍 (既定 43.0 秒・443 ノード → combo 107.9 秒・7660 ノード)。4 スレッドは 25.5 → 31.2 秒。
この機械で 1 スレッド・種 1・600 秒、3 本並べて回した (`res_neos-1582420.jsonl`・`_rep2`・`_ks`・`_m`・`_ksm`)。答えはどの回も 91 (最適)。

## 0. まとめ

- **原因の部品: heur (`ENOMOTO_MIP_HEUR_ADAPT=1`) の中の FP の第 3 段 (`FP_STAGE3`)。**
- **仕組み**: HEUR_ADAPT は FP の第 3 段 (FP が解を出さなければ、丸めの点の周りを孫 MIP で探す) を常に有効にし、上限 (500 ノード・残りの 0.1 倍で 10 秒まで) に
  f_g を掛ける。f_g は暫定解がなければ 1。外側の根から出したサブ MIP (被約費用・LP face など) には暫定解がないので、その中の FP の第 3 段が
  削られずに回り、サブ MIP の時間とノードを食う。neos-1582420 では
  - 根の被約費用のサブ MIP の解が 98 → 103 に悪くなり、
  - 続く LP face のサブ MIP が **ノード 0 のまま時間切れ** (8.7 秒、解なし) になる。既定はここで 24 ノードで 92 を出し、393 列を固定して根で再スタートし、443 ノードで閉じる。
  - これを逃すと、根の下界 89.274 → 89.057、木は 2021 ノード (+heur)。ほかの部品 (sbpb・bfrt・nra) と重なって combo では 6000〜7600 ノード。
- **直し (試作、既定オフ)**: `ENOMOTO_MIP_HEUR_ADAPT=1m` — FP の第 3 段を、外側の根から出したサブ MIP の中では回さない
  (src/mip/heuristics.rs、`heur_adapt_flag('m')`)。新しい閾値はない。`FP_STAGE3` を単独で指定したときは今までどおり。
  - +heur(`1m`) 443 ノード (既定と同じ道筋)、**combo(heur を `1m`) 314 ノード・45.9 秒**、combo+k+s+m 314 ノード・43.6 秒 (既定 42〜47 秒・443)。

## 3. ログで見た分かれ目 (既定と +heur)

- 根のカットのループ (24 ラウンド、下界 89.0574) までは同じ。最初の解 202 の名札が `[tree]` → `[feasibility jump]` になるのは FJSYNC_LABEL で、道筋は変えない。
- 根の被約費用のヒューリスティクス (1719 の潜む境界、固定率 0.51): サブ MIP が 既定 56 ノード・98、+heur 57 ノード・**103**。
  +heur ではサブ MIP の中で解き直しの行 (`CUTMIX clique edges`) が余分に出る (孫 MIP)。
- LP face (1719 / 2407 列を固定): 既定は 24 ノードで **92** を出し、`early restart: 393 newly fixed integer columns after LP face` → 再スタートの後 443 ノードで閉じる。
  +heur は `sub-MIP: 688 free columns, status TimeLimit, nodes 0, objective None, 8.69s` で解なし。続く RENS が 102 → 2-opt で 101。再スタートなしで木へ。
- `1m` のログ: 被約費用 98、LP face 92・393 列固定の再スタート、と既定と同じ道筋 (443 ノード、45.9 秒)。
