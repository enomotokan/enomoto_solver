# beasleyC3 (1 スレッド) の combo の害 (2026-11-25、親の依頼)

combo の計測 (analysis/combo_20261124) では 1 スレッドで既定 40.0 秒 → combo 74.5 秒 (どちらも最適 754)。4 スレッドは 13.7 → 12.1 秒で害はない。
計測はこの機械 (4 コア)、1 スレッド・600 秒。並べた本数は 1〜2 本。部品の短い名前は README.md の表と同じ。

## まとめ

- **原因の部品: nra** (`ENOMOTO_MIP_NODEROWS_ADAPT=t`)。
- **仕組み**: 葉が下界で閉じる木 (φ ≈ 0.05〜0.24) で f ≈ 0 になり、nra は「行を外す」側をほとんど使わず、
  プールの選び直しのラウンド (`pool_select_round`、1 回で最大 100 本) を回す側に寄る。`t` の比 g_sel / g_tree は 0.09 と低いが、
  ρ = σ(ln 0.09) ≈ 0.08 なので 2400 ノードで約 270 回まわる。ラウンドの得 (下界の伸び) はほぼ 0 (G_sel 7 に対し G_tree 1878)。
  ラウンドのある木では、ノードの LP の行が 2217 → 2741、LP 1 回の反復が 60 → 83、解き直しの LP が +370 回に増え、
  ノードの数は 2780 → 2387 と 14% 減るが、1 ノードの手間が 15 → 25 ms になって全体で遅くなる。
- **揺れではない**: 種 1〜4 のどれでも +nra・combo は既定より遅く、combo から nra を抜くと既定並みに戻る。
- **直し**: 試した 2 つ (`w`・`e`、下) はどちらも効かず、ソースから戻した。まだ見当がない。

- 外すだけにすると悪い。下界で閉じる木では行を外すのが害、という nodespeed 8 節の見立てと合う (nra の f ≈ 0 はこの点では正しく働いている)。

## 4. 試した直し (どちらも効かず、ソースから戻した)

### `w`: ラウンドで戻した行が LP に残る分の手間を、ラウンドの手間に数える

- 考え: `t` はラウンドの解き直しの手間しか W_sel に数えない。戻した行はその後もノードの LP に残って毎ノードの LP を重くするので、
  その分は普通のノードの手間 W_tree に入り、比を高く見積もる。普通のノードの手間を「今の LP の行のうちラウンドが加えて残っている行の割合」で分け、
  その分を W_sel に移す (新しい閾値なし)。
- 結果 (`res_beasleyC3_tw.jsonl`、+nra を `tw` に): 種 1〜4 で 127.8 / 4524・43.8 / 2085・51.9 / 1971・37.9 / 1806。
  - ログ (`logs_beasleyC3_nratw_t1.err`): 比は 0.0085 まで下がり、ラウンドは 270 → 101 回に減った。
  - それでも LP の平均の行は 2704、反復は 94.7 / LP で、重いままだった。
  - 100 回でも、1 回あたり最大 100 本の行が戻って残る (f ≈ 0 なので外されない) ので、回数を減らすだけでは足りない。

### `e`: ラウンドの解き直しで目的値が伸びなければ、戻した行を外す (POOL_SEL の `e` と同じ処理)

- 伸びなかったノードとその子では、nra のラウンドを回さない。
- 結果 (`res_beasleyC3_te.jsonl`): 種 1〜4 で 347.1 / 4049・41.9 / 1596・185.9 / 2529・147.3 / 2418。
- はっきり悪い。1 ノードの手間が 86 ms (種 1) になった。戻しては外す行の出し入れが増えると見る (未確認)。

### 残る見当 (未実装)

- 下界で閉じる木 (f が小さい) で、ラウンドの回数ではなく、ラウンドで戻す本数 (今は 1 回最大 100 本、`ENOMOTO_T_MIP_HCM_NODE_MAX_CUTS`)
  を効き目に合わせて絞る形。
- ρ = σ(a ln 比) の a = 1 では、比が 1/11 でも 8% 回る。比 < 1 (ノードより効きが悪い) のときに回す理由はないので、
  比 < 1 なら回さない (σ の代わりに比較) 形も考えられる。ただし、ラウンドは後のノードを強くする効き目 (今の比では数えていない) を持ちうる。
  mik-250・roll3000 など nra の得が出た問題で、その得がラウンドの側から来ているかを先に確かめる必要がある。
