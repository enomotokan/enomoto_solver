# 裏のカットがまだ下界を上げていれば根のヒューリスティクスの後に待つ試作 (`ENOMOTO_MIP_BG_CUTS_WAIT`、2026-10-30)

- 機械: 4 CPU。ソルバーは同時に 1 つだけ動かした。HiGHS (highspy) は 1.15.1。
- 土台: ブランチ `ccr-1beed81b-ex0uhq` の `62c27da5` に、この試作 (`b0b1a7cb`) を足したもの。既定は変えていない。
- 計測: `ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_THREADS=4`、60 秒・4 スレッド。台本とログは `analysis/bgcuts_wait_20261030/`
  (`run.sh 問題 名前 [環境変数 ...]` で 1 回、`batch1.sh` (mc11)・`batch2.sh` (副作用) が今回の並び、`summary.py` が下の表を作る)。
- 発端: `analysis/mc11_h1_20261030.md` の「直し方の案 1」。裏のカット (background cuts) は根のヒューリスティクスが終わると止められるので、
  サブ MIP が早く終わる設定 (`ENOMOTO_MIP_SUBMIP_HIGHS=s`) では mc11 の裏のカットが上がっている途中で止まり、根の下界が落ちて解けなくなる。
- `cargo test --release --lib` は 329 件通過 (この環境では pyo3 の `extension-module` のためにそのままではリンクできないので、
  `CARGO_TARGET_DIR=target/test-py RUSTFLAGS="-C link-arg=-lpython3.13"` を付けて回した)。

## 1. 実装 (`src/mip/solver.rs` の `bg_cuts_wait_on`・`BgCuts::wait_progress`)

- 裏のカットのループ (`separation.rs` の `root_cut_loop`、`CUT_JOB` のあるとき) が、各ラウンドの LP が解けた後の目的値 (offset 込み) を
  `CutJob::prog` に積む。
- 主は根のヒューリスティクスと並列のサブ MIP (`join_submips(0)`) が終わった後、`bg.finish()` (止めの合図) の前に、次のどれかまで 5 ミリ秒ごとに見て待つ:
  - `done`: 裏のスレッドが自分で終わった (裏のカットのループの停滞判定・ラウンドの上限)
  - `stalled`: 直近 `ENOMOTO_T_MIP_BG_CUTS_WAIT_WIN` ラウンド (既定 5) の上がり幅が相対 `ENOMOTO_T_MIP_BG_CUTS_WAIT_EPS` (既定 1e-4) 以下
    (ラウンドが窓より少なければ閾値をラウンド数の割合に縮める。ラウンドが 2 つ未満なら待たない)
  - `cutoff`: 目的値が暫定解に届いた
  - `cap`: 待ちが上限に達した。上限は min(残り時間 × `ENOMOTO_T_MIP_BG_CUTS_WAIT_FRAC` (既定 0.1), 主の根のカットのループの時間 ×
    `ENOMOTO_T_MIP_BG_CUTS_WAIT_MULT` (既定 5、0 以下なら使わない))
- 待った後は既定と同じ流れ (`finish` → 根の LP を解き直し → 裏の LP の目的値が上なら置き換え、置き換えた LP が下がれば戻す)。
  裏のカットの LP 解・下界の扱いは変えていない。待つ間、主のスレッドは何もしない (裏のカットは `threads - 1` 本)。
- ログ: `MIP: background cuts: waited 3.93s for progress (cap 5.69s, done), 51 rounds, obj Some(11666.01) (6.84s)`。
- 再スタートの後の根でも裏のカットが回れば同じく待つ (h80x6320d は 1 回の求解で 3 回、計 6〜8 秒待った)。

## 2. 結論

事実:

1. **mc11 + `SUBMIP_HIGHS=s`: 既定は 3 回とも時間切れ (根の下界 11375〜11434)、試作は 3 回とも解けた (38.6・40.6・45.4 秒)**。
   根のヒューリスティクスは 2.3〜2.9 秒で終わり、試作は 3.6〜3.9 秒待って裏のカットが自分で止まる (`done`、51 ラウンド) まで続け、
   根の下界は既定の設定 (`s` なし) と同じ 11666 になった。待ちの上限 (4.7〜5.7 秒) には当たっていない。
2. mc11 (`s` なし): 既定の設定では根のヒューリスティクス (7.9〜9.2 秒) の前に裏のカットが自分で終わっているので、試作は待たない
   (待ち 0.00 秒・`done`)。時間は既定 47.3・53.1・17.1 秒、試作 43.4・41.5・43.9 秒で、差は木の揺れ (既定の 17.1 秒の回は裏のカットが
   52 ラウンド・11683 に届いた回)。
3. 副作用 (2 回ずつ): 待ちが 0 の問題 (neos-911970・noswot) は試作でも何も変わらない (時間の差は揺れ)。待った問題は:
   - h80x6320d: 毎回上限 (4.0〜4.3 秒、再スタート後の分も入れて計 6.7〜7.5 秒) まで待ち、裏のカットは 14 → 18 ラウンド (6344.5 → 6347.3)
     になるが、置き換えた後の根の下界はほぼ同じ (6355.5〜6357.8)。結果は既定 時間切れ・49.9 秒、試作 59.3・59.4 秒 (2 回とも解けたが時間ぎりぎり)。
   - physiciansched6-2: 1.3 秒 (`done`)・3.7 秒 (`cap`) 待ち、2 回目は裏のカットが 49324 (最適値) に届いた。どちらも 60 秒では解けない
     (既定も同じ)。
   - roll3000: 1.8・2.6 秒待って `stalled` で止め、裏のカットは 54〜55 → 70 ラウンド (12621〜12629 → 12650)。根の下界は 12649 → 12651 と
     わずか。結果は既定 53.9 秒・時間切れ、試作 時間切れ・53.8 秒 (揺れの範囲)。

推測:

- 狙いの「サブ MIP が早く終わったために裏のカットが途中で止められる」形はこの試作で直る。既定の設定で根のヒューリスティクスが短い問題
  (運でサブ MIP が早く終わった回を含む) にも同じ利得がありうる。
- 損は「待っても置き換え後の下界がほとんど上がらない」問題 (h80x6320d・roll3000) で、待った秒数 (2〜8 秒) がそのまま遅れになる。
  裏のカットの目的値は上がっていても、置き換え前の主の LP (前景のカット + ヒューリスティクスで足したカット) との差が小さいときに起きる。
  主の LP の値との差 (例: 裏の目的値が主の根の LP の値をまだ超えていない、または超えた分が小さいなら待たない) を判定に足すと減らせる見込み。
- 待ちの上限は h80x6320d では毎回当たった。上限 (残り時間の 1 割・主のカットのループの 5 倍) は mc11 には十分で、ほかの問題での損を
  抑えるなら `ENOMOTO_T_MIP_BG_CUTS_WAIT_FRAC=0.05` などに縮めるのも 58 問で比べるとよい。

## 4. 58 問で測るべき設定

1. `ENOMOTO_MIP_BG_CUTS_WAIT=1` (既定に足す形): 既定の設定での利得 (運でサブ MIP が早く終わった回) と損 (h80x6320d のような待ちの上限に当たる問題)。
2. `ENOMOTO_MIP_BG_CUTS_WAIT=1 ENOMOTO_MIP_SUBMIP_HIGHS=1` (h1 と組む形): mc11 の悪化が消えて h1 の利得 (physiciansched6-2・mzzv42z など) が残るか。
3. 損が目立つなら `ENOMOTO_T_MIP_BG_CUTS_WAIT_FRAC=0.05` (待ちの上限を半分) を 1. と並べる。
