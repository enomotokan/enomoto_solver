# polish の費用摂動の統一 (5b99c58) の判定

内容: 主ループと同じ摂動済み費用 (スラック列は真の費用) を polish_with_true_bounds でも使う (`dual_active_costs`)。
`ENOMOTO_POLISH_PERTURB_SLACK=1` で旧動作。

- 実装担当の計測: Netlib93 / Mittelmann 11 問のすべてで経路不変 (status・目的関数値のビット・polish/引き継ぎの反復数が一致)。
  cont1 は polish 開始時の双対実行不能列が 3 → 0 になるが、cleanup 後の基底が既に主実行可能で polish は 0 反復のため結果不変。
  摂動除去後の双対実行不能 788 列・引き継ぎ 1,819 反復は変わらず、原因は主ループの摂動量 (摂動費用での最適値 0.01493 vs 真 0.00878)。
- 依頼者側の確認: Netlib93 を base 066660a と比べ status・目的関数値のビットが 93 問すべて一致。
- 判定: 経路を変えない不整合の修正として**採用** (速度の基準は対象外)。
- 次の候補: cont1 レポート策5 の後半 (摂動量を真の費用の尺度に比例させる) が 788 列を減らす本命。全問の経路が変わるので A/B で判定が必要。
