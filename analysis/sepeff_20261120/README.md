# カットの種類ごとの効き目と手間、根の停滞と双対退化 (P2-INF、2026-11-20〜21)

親の依頼 (利用者の承認済み) は 2 つ。

- (sepeff)「その求解の中で種類ごとの効き目を測り、効き目に応じて手間を配る」の材料集め 2 段。
  - 1 段目: 根のカットのラウンドで、種類ごとに次を記録する診断を足す (環境変数)。
    - (a) 決定的な手間 (ticks)
    - (b) 作った数・入れた数
    - (c) ラウンドの後の LP で効いている (双対が 0 でない) 数
    - (d) 下界の伸び
  - 2 段目: P 58 問・M 186 問を根だけで回し、種類ごとの手間あたりの伸びの分布を見る。
    zero-half が「効く問題」(seymour) と「手間だけの問題」(nw04・misc07・eil33-2・graph20-20-1rand) を分けられるかを見る。
- (退化) 根の停滞は双対退化から来るという仮説を確かめる。
  - (1) 停滞した時点の退化の度合いを測る (MPSEP の mpsep_width の数え方)。
  - (2) 最適面の中の別の頂点で分離する試作を、MPSEP の部品で (a) 向きを決まった押し方に、(b) 時点を最後の停滞の 1 回に変えて作る。
    MPSEP の oqmgs と比べ、見込みが薄ければ打ち切る。

既定は変えていない (どれも環境変数、新しい閾値なし)。`cargo test --release` は通る。

## 0. 道具

- 診断は `ENOMOTO_MIP_SEPSTAT=1` と `ENOMOTO_MIP_LOG` で出る。
  - 根の `SEPLEARN ... root` の行に、出どころ (rows_cmir・zerohalf・clique・implbd・path_highs・path・tableau・pool・mcf・modk) ごとの値が出る。
    rows の cmir・lcover・ecover・flowcover は分けて出す。
  - 値は `cands` (作った数)、`chosen` (入れた数)、`act1` (入れた直後の LP で |双対| > 1e-9 の数)、`gain`、`ticks` (手間)。
    `gain` は LP 値の伸びを |双対|・違反で割り振った近似。
  - ticks を数えていなかった zero-half・clique・implbd には、診断だけの手間 (`crate::ticks::diag_add`) を数える。
    重み `ENOMOTO_T_TICKS_W_DIAG` (既定 2)。診断だけの手間は `ticks::total()` と期限には入れない。
- 根のループを抜けた時点の行は `SEPEFF face ... width w nonbasic nb nfrac ...`。
  - w は mpsep_width と同じ数え方で、固定でない非基底のうち被約費用・双対が 0 のもの (最適面の次元の目安)。
  - nb は固定でない非基底の数、nfrac は分数の整数列の数。
- 試作 `ENOMOTO_MIP_FACECUT=1` (separation.rs `facecut_probe`、solver.rs の根のループの直後で 1 回だけ)。
  - 写しの LP で、被約費用が 0 でない非基底の列と双対が 0 でない行を今の値に固定する (最適面に留まる)。
  - 分数の列を近い整数の側へ押す向きと、逆の向きの 2 つの目的で `solve_primal` を解く (反復の上限は根の LP の反復の数)。
  - 動いた頂点 x' で分離し、`select_cuts` で 50 本まで選んで足す。足した後に LP を解き直し、伸びと手間を `SEPEFF facecut` の行に出す。
  - `=x` は比べで、頂点を動かさず今の頂点 x* でもう 1 回分離して足すだけ。
- `run_root.py`: P・M (重なりを除いて 203 問) を根だけ、1 スレッド、種 1、決定的な設定で回す。300 秒、4 本並べる。
  - 設定は `NODE_LIMIT=1`、`TIMEDEP=b`、`DET1T=onil`、`NO_ZEROHALF=0`。
  - `SEPEFF_OUT` が結果の名前、`SEPEFF_ENV` が足す環境変数、`SEPEFF_PROBS` が問題の絞り込み。
  - 結果の対応: root.jsonl が既定 (FACECUT なし)、face.jsonl が FACECUT=1 の全問、face_x.jsonl が比べ x (対象)、nompsep.jsonl が MPSEP=0 と FACECUT=1 (対象)。
- 集計: summ.py → summ.txt (種類ごと)、summ_face.py → summ_face.txt (退化)、cmp_face.py → cmp_face.txt (FACECUT・x・MPSEP)。
- 対象 (targets.txt、50 問) は 2 群。
  - 停滞する P 29 問 (analysis/disj_20261119.md の jobs_SBF P)。
  - A ≥ 3% の M 21 問 (同 8 節。A は 1 列の離接で上がる余地)。

## 1. 種類ごとの効き目の分布 (summ.txt)

値の定め方:

- share: 根のカットの伸びのうちその種類の取り分。
- tshare: 手間の割合。
- rel = share / tshare (1 より大きいと手間の割に効く)。
- eff = gain / |LP0| / (ticks / 1e9)。

分布は 10 / 25 / 50 / 75 / 90%、手間が 1e6 以上の問題を数える。

| 種類 | 問題 | 伸び > 0 | share 中央 / 90% | tshare 中央 / 90% | rel (伸び > 0) 25 / 50 / 75% |
|---|---|---|---|---|---|
| tableau | 181 | 144 | 0.20 / 1.00 | 0.42 / 0.80 | 0.32 / 1.08 / 1.79 |
| path_highs | 182 | 119 | 0.015 / 0.49 | 0.20 / 0.62 | 0.08 / 0.53 / 1.12 |
| path | 89 | 62 | 0.009 / 0.29 | 0.20 / 0.53 | 0.02 / 0.25 / 0.91 |
| rows_cmir | 180 | 94 | 0 / 0.56 | 0.068 / 0.18 | 0.58 / 3.37 / 8.51 |
| zerohalf | 132 | 67 | 0 / 0.33 | 0.022 / 0.35 | 0.14 / 1.52 / 5.32 |
| clique | 66 | 30 | 0 / 0.54 | 0.0006 / 0.0075 | 0.10 / 19.3 / 75.7 |
| implbd | 76 | 17 | 0 / 0.010 | 0.0034 / 0.019 | 0.003 / 7.1 / 38.6 |
| mcf | 18 | 9 | 0 / 0.23 | 0.025 / 0.14 | 0.21 / 7.2 / 67.7 |
| flowcover | 76 | 7 | 0 / 0 | 0.0087 / 0.036 | ほぼ 0 |

- 手間の大半は tableau (中央 42%) と path_highs・path (中央 20%) で、どちらも rel は 1 前後かそれ以下。
- rows_cmir・clique・implbd・mcf は手間が小さく、効く問題では rel が大きい。
- 経路集約 (path_highs・path) の rel が中央 0.25〜0.53 と低い。手間を配り直して得をしやすいのはここ。
- flowcover は 76 問で回り、伸びたのは 7 問だけ (rel ほぼ 0)。
- 種類の分けが取れないのが 16 問 (supportcase42・rail01・cod105 など。根のループに入らないか、時間で切れる)。

### zero-half は「効く」と「手間だけ」を分けられるか

| 問題 | 狙い | 候補 | 入れた | 直後に効いた (act1) | share | tshare | rel |
|---|---|---|---|---|---|---|---|
| seymour | 効く | 2266 | 286 | 180 | 0.76 | 0.16 | 4.73 |
| misc07 | 手間だけ | 944 | 128 | 16 | 0.31 | 0.022 | 14.1 |
| nw04 | 手間だけ | 262 | 17 | 6 | 0.004 | 0.021 | 0.19 |
| eil33-2 | 手間だけ | 128 | 0 | 0 | 0 | 0.013 | 0 |
| graph20-20-1rand | 手間だけ | 125 | 12 | 0 | 0 | 0.072 | 0 |

- 5 問のうち 4 問は分かれる。
  - seymour は入れたうちの 63% が直後に効き、伸びの 76% を取る。
  - nw04・eil33-2・graph20-20-1rand は伸びが 0 か 0.4%。
- misc07 は根では zero-half が効いている (伸びの 31%、手間 2%)。
  「手間だけ」は通しの解き (analysis/cutmix_20261111.md) で遅くなった結果なので、遅れは根の伸びではなく木の側 (行が増えてノードが重い) から来るとみる。
  根の効き目だけで配っても、misc07 の遅れは防げない。
- zero-half の rel は問題によって 0〜318 に散る (seymour1 318、sp97ar 65、blp-ic98 42、…、0 の問題 50 余り)。
  intsmall のような問題の形の特徴よりも、その求解の中で測った値のほうが分けやすい。

### 注意

- gain は |双対|・違反での割り振りで、ラウンドの中で種類が重なると割り振りが近似になる。
- zero-half の診断の手間は、nw04 で秒の割合に比べて約 7 倍少なく数える (重み 2 の決め方は大まか)。
  zero-half の rel は大きめに出る側にずれる。
- 根の伸びが木の速さにつながるとは限らない (misc07)。

## 2. 「比べて配る」の試作の案

- 材料は 1 段目の診断と同じ、出どころごとの累積の伸びと手間 (SEPSTAT の値)。求解の中で根の各ラウンドの後に足し込む。
- 配り方 (新しい閾値なし):
  - 根の 1 ラウンドの手間の枠は今の既定のまま (分離の期限・行の上限)。
  - 枠を種類ごとの「これまでの伸びの取り分」に比例して配る。
  - 1 ラウンド目は今と同じ配り方で測る (測りの回)。
  - 伸びが 0 の種類にも、伸びが 0 でない種類の中で一番小さい取り分を残す (0 にしたまま測れなくなるのを避ける)。
    これは決まった比で、新しい閾値ではない。
- 手間を絞れる所 (今の上限をそのまま比で縮める):
  - 経路集約 (path_highs・path): 始点の数。
  - tableau: 使う行の数。
  - zero-half: 見る行・候補の数。
  - flowcover: 回すか。
- まず試すなら、手間の 6 割を使い rel が 1 以下の tableau・経路集約と、rel が散る zero-half の 3 つに限る。
  M・P の根だけで「同じ手間で根の下界がどれだけ伸びるか」を見て、そのあと通しの解きで速さを測る。
- 4 節の結果から、ラウンドを止める判断 (停滞) も同じ材料で比べる候補になる。
  停滞で止めた直後にもう 1 回分離すると、8 問で残りギャップの 1% 超が伸びる。

## 3. 停滞と双対退化 (summ_face.txt)

根のループを抜けた時点の値 (face.jsonl、193 問)。25 / 50 / 75%。

| 群 | w (被約費用 0 の非基底) | r = w / 非基底 | 分数の整数列の割合 |
|---|---|---|---|
| 停滞 (113) | 27 / 398 / 2560 | 0.005 / **0.55** / 0.95 | 0.03 / 0.078 / 0.28 |
| 停滞でない (80) | 9 / 125 / 2180 | 0.005 / **0.07** / 0.45 | 0.04 / 0.12 / 0.36 |
| A 小 < 0.1% (43) | 119 / 1000 / 2320 | 0.58 / **0.88** / 0.98 | 0.04 / 0.13 / 0.36 |
| A 大 ≥ 3% (24) | 22 / 292 / 854 | 0.002 / **0.015** / 0.24 | 0.035 / 0.099 / 0.27 |

- 停滞した問題は停滞でない問題より退化が大きい (r の中央 0.55 / 0.07)。停滞と双対退化はつながる。
- ただし退化は A (1 列の離接で上がる余地) と**逆向き**。
  - A の小さい (伸びる余地のない) 問題は最適面がとても広い (r 中央 0.88)。
  - A の大きい問題はほとんど退化していない (r 中央 0.015)。
- 「退化で同じ頂点しか見えないので停滞する。別の頂点で分離すれば伸びる」が成り立つには、退化して、かつ伸びる余地のある問題が要る。
  その組み合わせは少ない。
- 退化の大きい問題で停滞するのは、伸びる余地がない (最適面全体で切れるカットが今の種類では見つからない) からとみる。

## 4. FACECUT と比べ x と MPSEP (cmp_face.txt、対象 50 問)

- 閉じた割合 c = (根のループの後の LP 値 − 最初の LP 値) / (参照値 − 最初の LP 値)。
- MPSEP の効き = c(既定 oqmgs) − c(MPSEP=0)。
- FACECUT・x の伸びは、根のループの後の残りギャップに対する割合。

| | 10 / 25 / 50 / 75 / 90% | 平均 | > 0.1% の問題 | > 1% |
|---|---|---|---|---|
| MPSEP oqmgs の効き | 0 / 0 / 0 / 0 / 0 | 0.05% | 2 | 1 |
| FACECUT (MPSEP 既定の上) | 0 / 0 / 0 / 0.018% / 0.35% | 0.18% | 9 | 2 |
| FACECUT (MPSEP=0 の上) | 0 / 0 / 0 / 0.035% / 0.35% | 0.18% | 9 | 2 |
| 比べ x (今の頂点でもう 1 回) | 0 / 0.002% / **0.057%** / 0.38% / 2.3% | **1.27%** | **19** | **8** |

- 手間 (1e9 ticks) の中央 / 平均は、FACECUT が 0.027 / 0.30、x が 0.075 / 0.39。
- MPSEP oqmgs は対象 50 問のうち 47 問で根の値をまったく変えない (MPSEP=0 と閉じた割合が同じ)。
  - 変えたのは cmflsp50-24-8-8 (+4.2%)、supportcase26 (+0.8%)、icir97_tension (−2.6%) だけ。
  - 門 (面の幅 ≥ max(20, 0.5・行)) が、A の大きい (退化の小さい) 問題では開かない (3 節と同じ形)。
- FACECUT は 50 問中 38 問で伸びが 0。
  - 多くは最適面の中で頂点が動かないか (w が小さい)、動いた頂点で x* を切らないカットしか出ない。
  - 伸びた問題 (neos-662469 3.5%、neos-1582420 2.3%、blp-ic98 0.47%、air05 0.35%、mzzv11 0.34%) でも、x の伸び (3.7%・2.3%・0.77%・0.33%・1.44%) と同じか下。
  - 伸びのもとは「別の頂点」ではなく「もう 1 回分離した」ことにある。
- MPSEP=0 の上でも FACECUT の伸びは同じ。MPSEP と重なる分はない (どちらもほぼ働いていない)。
- 比べ x は、停滞で止めた直後にもう 1 回分離するだけで 19 問が 0.1% 超、8 問が 1% 超伸びる。
  - 大きいのは binkar10_1 20.2%、nu25-pr12 17.7%、neos-1456979 4.0%、neos-3083819-nubu 3.9%、neos-662469 3.7%。
  - 手間は根のループに比べて小さい。
  - ただし x は `select_cuts` の 50 本を、ループの絞り (平行・効き目の足切り) なしに足している。
    根の伸びが通しの速さになるかは測っていない。
- 全 203 問 (face.jsonl) で FACECUT が 1% 超伸びたのは 12 問。
  - 多くはラウンドの上限 (round_limit) や時間で止まった問題で、x と同じく「もう 1 回」の分。
  - 例: nexp-150-20-8-5 14%、milo-v12-6-r2-40-1 5.1%、n3div36 4.3%。nursesched-sprint02 の 50% は整数の目的の丸めで 1 単位上がっただけ。

**見立て: FACECUT (最適面の中の別の頂点で分離) は MPSEP より良くなる見込みが薄い。(2) は打ち切りを提案する。**

- 退化の大きい問題には伸びる余地がなく、伸びる余地のある問題は退化していない。
- 分かったこと: 停滞で止めた後にも、今の頂点のもう 1 回で伸びる問題がある (8 問で 1% 超)。
  止める判断を種類ごとの手間あたりの伸びで比べる「比べて配る」の側で扱うのがよい (2 節)。

## 5. 誤答の確かめ

- `scripts/mip_fuzz_vs_highs.py` は 60 種で誤答 0 (FACECUT=1)。
  小さな問題は nfrac = 0 で FACECUT が回らないことが多い。
- `scripts/mip_fuzz_symmetric.py` (対称の割り当て問題で、根のカットが停滞して FACECUT がカットを足す) も誤答 0。
  - 倍率 2 で 1500 種、倍率 3 で 500 種 (fuzz_sym2.txt・fuzz_sym3.txt、`ENOMOTO_MIP_REL_GAP=1e-9`・1 スレッド)。
- 試作は分離の関数をそのまま使い、足すのは妥当なカットだけ。最適面の写しの固定は LP の写しの中で戻す。
