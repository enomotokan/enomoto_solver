# physiciansched6-2 で ENOMOTO が実行可能解を見つけられない件 (2026-10-20)

機械は 4 CPU (`nproc` = 4、専用コンテナ)。基準は develop `bc89ad1`、試作はブランチ `inv/physiciansched6-2-20261020`
(試作は環境変数で有効にし、既定は変えていない)。**計測はすべて 4 スレッド** (ENOMOTO は `ENOMOTO_MIP_THREADS=4`・
`m.solve(None, False, T, None, None, 4, log=True)`、HiGHS 1.15.1 は `threads=4`)。時間上限は断りがなければ 60 秒
(一部 120・300 秒)。前の調査の 1 スレッドの数値 (`eno120.log`・`highs120.log`・`highs_nopre.log`) は参考として残す。
ログ・スクリプトは `analysis/physiciansched6-2_20261020/` (`eno_run.py <mps> <秒>`、`highs_run.py <mps> <秒> [option=値 ...]`、
`highs_presolved_dump.py` (HiGHS の前処理後の問題を MPS に)、`highs_rule_sweep.py` (`presolve_rule_off` を 1 ビットずつ)、
`screen.sh` (試作が各問題で何をするか)、`cmp.sh` / `summ.py` (基準と試作の比較))。

## 1. 結論

事実 (4 スレッドで確かめた):

1. **ENOMOTO がこの問題で解を出せる手段は Feasibility Jump (FJ) だけで、FJ は前処理後の問題の形に敏感**。
   HiGHS の前処理後の問題 (8861 行 × 4608 列) を ENOMOTO に解かせると、FJ が毎回 0.2 秒以内に解を見つけ (種を変えた
   5 回すべて)、最初の解 50927 (8.1 秒)、120 秒で 49625 (最適 49324、ギャップ 1.8%)。同じ問題で FJ を切ると
   (`ENOMOTO_MIP_DEBUG_NO_FJ`) 60 秒で解なし (LP 系のヒューリスティクス・サブ MIP は全部失敗)。ENOMOTO 自身の前処理後
   (15892 × 9577) では FJ は違反 24〜33 行で止まる (手間の上限を 16 倍にしても 23 行)。
2. **HiGHS は FJ ではなく根のサブ MIP (`L`) で最初の解を見つける**: 前処理 → 根の LP 47410.76 (4.5 秒) → カットで 49324
   (= 最適値、9.9 秒) → `L` 49324 (12.7 秒) → 1 ノードで終了。HiGHS の前処理を切ると ENOMOTO と同じく解なし
   (前の調査、1 スレッド 140 秒)。つまり HiGHS では「前処理 + カットで根の下界が最適値に届き、LP 解が整数に近いので
   サブ MIP が当たる」。
3. **前処理の差のうち、LP を強めているのは HiGHS の Probing** (`presolve_rule_off` で切ると前処理後の LP 47410.76 →
   46620.13 = ENOMOTO の 46619.25 とほぼ同じ)。HiGHS のログでは probing は「4775 probing evaluations: 96 deleted rows,
   755 deleted columns, **1783 lifted nonzeros**」で、後者がクリーク行の拡張 (集合詰め込み行にすべての文字と衝突する文字を
   加える)。ENOMOTO にはこれがない。同じ形の拡張を入れると (`ENOMOTO_MIP_CLIQUE_EXTEND`) 根の LP は 46619.25 → **48583.1**
   (HiGHS の 47410.76 より高い。最適解は拡張後も実行可能)。
4. ENOMOTO の前処理が残している形 (どれも HiGHS は消している):
   - `x ≤ y` と `x ≥ y` の向きの逆の不等式の組が、前処理の **後** の `merge_parallel_rows` で初めて等式 `x = y` になるので、
     前処理の二項等式の代入に届かない: 0-1 列どうしの `x - y = 0` が 3482 本・`x + y = 1` が 46 本残る (前処理後の等式
     3798 本、HiGHS は 283 本)。
   - 目的の費用が `y ≥ Σ (罰則の列)` の形の連続列 (その行だけに出る) にあり、罰則の列 (430 本) が費用のない 2 行の列として
     残る。不等式の列シングルトン (`ineqsingleton`) が MIP の前処理では無効 (`int_mask().is_none()` のときだけ)。
   - プロービングで見つかる同値な 0-1 列 (`x_k = x_j`・`x_k = 1 - x_j`) を代入しない (HiGHS は 755 列消す)。

推測 (確かめきれていない):

- 3 の拡張・4 の 3 つを全部入れると ENOMOTO の前処理後は 11896 行 × 5991 列・根の LP 48583.1 になるが、FJ はまだ違反
  18〜21 行で止まり解は出ない (60 秒 2 回、120・300 秒も解なし)。HiGHS の前処理後との差は 0-1 列の数 (5435 対 4185) と
  2 変数の ±1 の不等式 (4190 本対 562 本) で、FJ の成否はこれらの積み重ねで決まっているように見える (HiGHS の前処理を
  ENOMOTO の前処理後にかけても FJ は 3 回中 1 回しか通らない。単独で FJ を通す規則はない、§2.4)。
- 根の下界は HiGHS (同じ前処理後の問題で 49324) に届かない: HiGHS の前処理後の問題でも ENOMOTO のカットは 47410.8 →
  48513.3 まで。カットのループは LP の時間上限で打ち切られることがある (「cut round 1: LP status TimeLimit, removed the
  cuts」)。HiGHS 流に「根の下界が最適値付近 → サブ MIP」で解を出すには、カットの強さも要る。

### 2.2 HiGHS の前処理の規則を 1 つずつ切る (`highs_rule_sweep.py`、`highs_rule_sweep.log`)

LP を 46620 から 47411 に上げているのは Probing だけ (他の規則を切ると LP がかえって上がるものがあるのは、前処理後の LP が
双対の縮約などで元の LP 緩和と同じでないため)。

### 2.3 HiGHS の前処理後の問題で FJ が通る規則 (`fj_*`、各 3〜4 回)

元の問題に HiGHS の前処理 (規則を 1 つ切る) → ENOMOTO (FJ の違反の最小・解の有無):
既定はすべて解あり。Free col substitution を切ると 3 回とも解なし (違反 10〜17)。Probing を切ると 3 回中 1 回、
Parallel・Sparsify を切ると 4 回中 3 回、Aggregator・Enumeration を切っても解あり。

### 2.4 ENOMOTO の前処理後の問題に HiGHS の前処理をかける (`fj_on_eno_pre_ruleonly.log`)

ENOMOTO の前処理後 (MR 試作あり、12119 × 6003) に HiGHS の前処理を「全部」かけると 9143 × 5363 で FJ は 3 回中 1 回。
規則を 1 つだけ有効にした場合はどれも解なし (Free col substitution だけが違反を 21〜25 → 8〜11 に減らす)。

### 2.5 ENOMOTO の前処理後の形 (`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED` で書き出して数えた)

- 連続列 560 本: 費用なし・2 行 450 本、3 行 92 本。費用のある列は 3 本だけ (`y62277 ≥ 7608` (117 列の等式)、
  `y62280` (`-y62280 + Σ 434 罰則列 ≤ 0`、この行だけ)、`y110727 ≥ 1012.5`)。HiGHS の前処理後は連続列 423 本の
  ほとんどが「1 行・費用つき・有界 [0, 100〜600]」の罰則列。
- 等式 3798 本のうち 3482 本が 0-1 列どうしの `x - y = 0`、46 本が `x + y = 1` (`ENOMOTO_MIP_NO_ROW_MERGE` で書き出すと
  これらは等式にならず、向きの逆の不等式の組として残る → `merge_parallel_rows` が作っている)。
- 整数行 (試作 `all` の後、HiGHS の前処理後と比べて): 2 変数の ±1 の不等式 4190 本 (HiGHS 562 本)、5〜10 列の ±1 の
  不等式 683 本 (HiGHS 1264 本)、0-1 列 5435 本 (HiGHS 4185 本)。
- FJ が最後まで破っている行 (`ENOMOTO_MIP_FJ_DEBUG=2`) はほとんどが整数列だけの行 (2 変数の `≤ 1`・3 変数・長い等式)。

## 4. 既定にする候補か

- `ENOMOTO_MIP_MERGE_REPRESOLVE`・`ENOMOTO_MIP_PROBE_EQUIV` は軽く、働く問題では前処理を小さくし LP を締める
  (timtab1・beavma・noswot)。既定の候補だが、40 問の全体の計測 (親) で確かめる必要がある。二つは同じ `x = y` を
  拾うことが多い (physiciansched6-2 では EQUIV だけで 3854 組、MR の後は 8 組)。
- `ENOMOTO_MIP_CLIQUE_EXTEND` は physiciansched 系で根の LP を大きく上げるが、40 問ではほぼ働かない。行を長くするので
  LP が重くなる恐れ (physiciansched3-3 で 243590 非零を足した) があり、副作用は 40 問より広い問題で見る必要がある。
- `ENOMOTO_MIP_INEQ_SINGLETON` は 40 問に当たらず副作用は未確認。整数列を等式化しない形にしてあるが、MIP で固定
  (双対の固定) を使うことの影響 (対称性・後処理) は試験だけでは分からない。
- どれも担当の問題で解を見つけるには至っていない。

## 5. 確かでない点・次の手

- FJ を通す前処理の形 (2 変数の ±1 の行を減らす・0-1 列をさらに減らす) は特定できていない。HiGHS の前処理後の形に
  近づける次の候補は、2 変数の衝突行を大きなクリークにまとめて元の行を消す (HiGHS のクリークの統合。今の CE は
  拡張できた行しか消さない)、支配される列 (Dominated col 3 本)、Enumeration (157 列固定)。
- カットの強さ: HiGHS の前処理後の問題でも ENOMOTO のカットは 48513 (HiGHS 49324)。HiGHS 流に根でサブ MIP を当てるには
  根の下界を上げる必要がある。
- 根で失敗するヒューリスティクスの時間 (FP 30 秒・ダイビング 3 種で 45 秒) は今回は絞っていない (木に入っても 1 ノード
  4 秒で、木で解が出る見込みも薄い)。
- `ENOMOTO_MIP_CLIQUE_EXTEND_FIX` は評価していない。
- 前の調査の注意: 作業ディレクトリに `struct.py` を置くと highspy の import が壊れる。
