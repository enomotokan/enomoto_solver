# 最大公約数で丸めた右辺と活動値の範囲を合わせた等式・強制の判定 (試作 `ENOMOTO_MIP_GCDFORCE`) (2026-11-07)

bench に使う環境変数: 既定 (`def`) はなし。試作は `ENOMOTO_MIP_GCDFORCE=1` (丸めの直後に等式・強制・冗長・実行不能を処理し、変わった行があれば前処理をかけ直す)。
診断は `ENOMOTO_MIP_DEBUG_GCDCOUNT=1` (数えてログに出すだけ、`=stop` なら前処理の最後の問題を数えた後にプロセスを終える)。
どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_MIP_LOG=1`・`ENOMOTO_T_MIP_SEED=1`。試作は既定では使わない。

## 結論

- **見落としは無い** (事実、203 問): 58 問 (`analysis/cbcimpl_20261029/probs.py`) と Mittelmann 186 問 (`analysis/mitt600_20261103/shards2.json`、
  重複を除いて 203 問。前処理が 300 秒で終わらない 4 問を除く) で、整数列だけ・係数が整数の不等式のうち、**最大公約数で丸めて初めて**
  (a) 値が 1 つに決まる・(b) 冗長・(c) 実行不能・(d) 強制 になる行は、前処理の各呼び出しの丸めの直前 (計 308 回、不等式 187 万本) でも、
  前処理の最後の問題 (不等式 107 万本) でも **0 本**。等式で右辺が g の倍数でない行も 0 本。
- **理屈でも起きない** (事実、§2): 片側の行 `Σ a_j x_j <= u` を g で丸めた右辺が最小の活動値 `mn` と一致する (強制) なら `u − mn < g <= |a_j|` なので、
  前処理の伝播 (整数列の上下限を丸める `round_int_bounds`) だけで各列が `x_j < lo_j + 1` となり、丸めより前に固定される。丸めで実行不能
  (`floor(u/g)·g < mn`) になるのは `u < mn` のときだけ (mn は g の倍数) で、これは丸める前から実行不能。両側が行の場合は
  `merge_parallel_rows` が等式・実行不能を見つける。冗長は丸めで増えない (丸めは幅を狭めるだけ)。親のセッションの例
  (x, y >= 1、2x + 2y <= 5) は伝播が `x <= 1.5 → 1` で固定する。
- 丸める前から判定が出る行 (= 今でも拾えるはず) は (b) 冗長だけで、前処理の最後の問題に 58 問で 86 本 (2 問)、Mittelmann で 13526 本 (31 問)。
  これは最後の前処理の後のプロービング・LP による固定が締めた上下限で冗長になった行 (前処理はかけ直さない) と推測。丸めの直前で冗長なのは
  supportcase33 の 25 本だけ。
- 暗黙の整数列 (`MipProblem::implied_integers`、主側と双対側) も整数列として数えても、丸めで初めて判定が出る行は 0 本 (§1。印が増えるのは 22 問、
  不等式 +10585 本)。双対側の暗黙の整数は最適解でだけ整数なので、問題を変える判定 (GCDFORCE) には使わない。
- 試作 `ENOMOTO_MIP_GCDFORCE` は入れたが、203 問では supportcase33 (冗長 25 本を消してかけ直す) のほかは何も変えない。HNFPRE と組んでも等式は増えない
  (等式にする行が 0 本)。当たる問題が無いので、58 問の比べ・HNFPRE との組み合わせの比べは回していない (問題が変わらないので結果は既定と同じ)。
- 誤答の検査 (事実): GCDFORCE で `fuzz_tiny.py 400 0` は 11/400 (既定は 13/400 で、11 件はすべて既定の 13 件に含まれる既知の件)、
  `mip_fuzz_vs_highs.py 300` 0 件、丸めに当たる形の乱数の問題 `fuzz_gcd.py 1000 0` 0 件 (1000 問中 GCDFORCE が判定を出したのは実行不能 1 問、
  既定もその問題を前処理の後の段で実行不能と示す)。`cargo test --release --lib` 371 件通る。
- 次の一手 (推測): この方向 (丸めと活動値の範囲) からは等式は増えない。HNFPRE の対象を増やすなら、(1) 最後のプロービング・LP による固定の後に
  冗長になった行を消す軽いかけ直し (冗長 13526 本、31 問。行が減るだけで等式は増えない)、(2) 片側の行の丸めた右辺と上下限から決まる
  **列の上下限** は伝播と同じなので、等式を増やすには「2 本の行の和・差で g が大きくなる」形 (Chvátal–Gomory の集約) が要る。

## 2. なぜ起きないか (事実、式の確かめ)

片側の行 `Σ a_j x_j <= u` (a_j は g の倍数の整数、x_j は整数で上下限 [l_j, u_j] は整数) の最小の活動値を `mn = Σ min(a_j l_j, a_j u_j)` とする (g の倍数)。

- 丸めで強制 (`g·floor(u/g) = mn`) ⇔ `mn <= u < mn + g`。伝播は列 j について `|a_j|·(x_j を mn の端から動かす量) <= u − mn < g <= |a_j|` を出すので、
  動かせる量は 1 未満で、整数の丸めで 0 になる (列は端に固定)。丸めの前に `run_extended_mip` の伝播 (`round_int_bounds`) が固定する。
- 丸めで実行不能 (`g·floor(u/g) < mn`) ⇔ `u < mn` (mn は g の倍数なので)。丸める前から実行不能。
- 丸めで値が 1 つ (強制でない) は片側の行では起きない (交わりは `[mn, floor(u/g)·g]` で、1 点なら端)。両側が行 (`l <= Σ <= u`) の場合、前処理は
  ≤ と ≥ の 2 本で持ち、どちらも丸めた後に `merge_parallel_rows` が 1 本にまとめ、両側が一致すれば等式・交わらなければ実行不能にする
  (乱数の問題で確かめた: `fuzz_gcd.py` の seed 494 は既定でも前処理で実行不能)。
- 冗長は丸めで増えない (丸めは幅を狭めるだけ)。

例外になりうるのは伝播が回らない場合 (伝播の回数の上限・行が長すぎて伝播しない・上下限が無限の列) だが、203 問の数え上げでは 0 本。

## 3. 作ったもの

`src/mip/gcdforce.rs` (新しいファイル) と `src/mip/mod.rs` の 3 か所 (小さな差分):

- `count` (診断 `ENOMOTO_MIP_DEBUG_GCDCOUNT`): `presolve_mip_depth` の `normalize_integer_rows` の直前 (前処理の呼び出しごと、サブ MIP を除く) と、
  `solve_problem_inner` の前処理の最後の問題 (`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED` と同じ所) で数える。
- `apply` (試作 `ENOMOTO_MIP_GCDFORCE`): `normalize_integer_rows` の直後に、値が 1 つに決まる行を等式に (右辺は交わりの点)、冗長な行を消し、
  実行不能なら `Presolved::Infeasible` を返す。変わった行があれば、行をまとめた後のかけ直し (`MERGE_REPRESOLVE`) と同じ所で前処理をかけ直す (1 回だけ)。
  算術は f64 (係数 < 1e9、活動値の絶対値 > 1e15 の行は使わない。整数の倍数の判定が f64 の丸めで狂わない範囲)。

## 5. 文献

- 係数の最大公約数で割って右辺を丸めるのは Chvátal–Gomory の丸め (Chvátal 1973、Gomory 1958) の 1 行の特別な場合。前処理での使い方と、
  活動値による強制・冗長の判定は Savelsbergh (1994) "Preprocessing and probing techniques for MIP"、Achterberg, Bixby, Gu, Rothberg, Weninger (2020)
  "Presolve reductions in mixed integer programming"。
