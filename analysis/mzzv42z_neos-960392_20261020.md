# mzzv42z・neos-960392 が HiGHS に負ける原因の切り分け (2026-10-20)

環境: 4 CPU の専用のクラウドのコンテナ (`nproc` = 4、ソルバーは同時に 1 本だけ)、基準はコミット develop bc89ad1
(このブランチ `inv/mzzv42z_neos960392-20261020` の試作は既定では無効なので、既定の動作は bc89ad1 と同じ)、HiGHS 1.15.1。
**計測はすべて 4 スレッド** (`ENOMOTO_MIP_THREADS=4`、`m.solve(None, False, T, None, None, 4, log=True)`、HiGHS `threads=4`)、
時間上限 60 秒 (双対側だけの計測は 120 秒)。ENOMOTO は `ENOMOTO_MIP_LOG=1` を付けた。
ログは `analysis/mzzv/t4/` (計測の並びは `analysis/mzzv/t4/q*.txt`、台本 `analysis/mzzv/runq.sh`・`run_eno.py`・`run_highs.py`)。
前の調査の 1 スレッドのログは `analysis/mzzv/t1/` (参考)。

## 結論

| 問題 | 主因 | 根拠 (4 スレッド) |
|---|---|---|
| neos-960392 | **主側だけ**: 根の RENS・RINS が LP 解 (と暫定解) に合う列を全部固定するので近傍が狭すぎ、広げても既定のサブ MIP の時間 (残りの 7%、最大 6 秒) では解けない | 根の LP = 最適値 -238。最適解を与えると 0 ノード・18 秒で終了。固定率上限 + サブ MIP 20 秒で -226 → -236 (2 回とも) |
| mzzv42z | **双対側 (根のカット) と主側の両方**。前処理は主因ではない | HiGHS も前処理なしで根のカット後 -20829 (7.8 秒)・50 秒・1 ノードで解ける。ENOMOTO は最適解を与えても 120 秒で下界 -20944 (ギャップ 2%) |
| mzzv42z の揺れ | 根の RINS が「FJ・locks の弱い暫定解」から 9 割を固定した小さいサブ MIP を 1 回解くだけで、出発点の暫定解が並列の locks のサブ MIP (3 秒上限) が間に合うかで変わる | 既定 3 回: -16840 / -8598 / -14892 |

## 1. neos-960392 (最小化、最適値 -238、4744 行 × 59376 列、全て 0-1)

| | HiGHS (2 回) | ENOMOTO 既定 |
|---|---|---|
| 前処理後 | 3169 行 × 56041 列 (2〜5 秒) | 4229 行 × 58529 列 (6.2 秒) |
| 根の LP | -238 (4.2 / 6.9 秒) | -238 (前処理の後 2.3 秒) |
| カット後の根 | -238 | -238 (7 本、9.2 秒) |
| 最初の解 | 0 (trivial zero、2.2 / 4.5 秒) | 0 (FJ、5.3 秒) |
| 暫定解の推移 | 15.4 / 22.7 秒に根のサブ MIP (`L`) で -238 | 11.2 秒に根の RINS で -226、以後変わらず |
| ノード / 時間上限の時点の下界 | 1 ノードで最適 (15.4 / 22.7 秒) | 234 ノード、-238 (60 秒、暫定解 -226) |

### 事実

- **双対側は何もしなくてよい**: `ENOMOTO_MIP_START_FILE=analysis/mzzv/sol_neos-960392.txt` (HiGHS の最適解) を与えると、
  前処理後でも実行可能として受理され、根のカットの後 0 ノード・18.1 秒で最適 (`t4/eno_neos_start.log`)。
- 既定の根のヒューリスティクスの内訳 (`t4/eno_neos_log1.log`):
  - RENS (暫定解 0 があるので旧来の全部固定): LP 解で整数値の列を全部固定し 294 列しか残らず、サブ MIP は 0 ノードで実行不能。
  - locks (18640 列)・clique (192 列) のサブ MIP も実行不能。
  - RINS (暫定解 0 と LP 解が一致する列を全部固定): 692 列のサブ MIP の最適値が -226。以後 -226 のまま。
- 既存の切り替えで試したもの (各 1 回、60 秒):

| 設定 | 根の RENS のサブ MIP | 結果 |
|---|---|---|
| `ENOMOTO_MIP_RENS_PROP` | 58529 個の固定が全部伝播で通り 265 列、実行不能 | -226 |
| `ENOMOTO_MIP_RENS_DIVE` | 固定率 0.60 (23332 列)、**3.0 秒で時間切れ・0 ノード** | -226 |
| `ENOMOTO_MIP_FIX_CAP` | 固定率 0.86 (8391 列)、**3.0 秒で時間切れ・0 ノード**。RINS (固定率 0.62) も時間切れ | 0 (悪化) |
| RENS_DIVE + サブ MIP 時間 0.3・最大 20 秒 | 23322 列のサブ MIP の中で暫定解が見つからず 12.9 秒で時間切れ | -226 |
| 同 + `ENOMOTO_MIP_SUBMIP_RENS` (入れ子の RENS) | | -226 |
| 同 + `ENOMOTO_MIP_SUBMIP_CUTS` | | -226 |
| **FIX_CAP + サブ MIP 時間 0.3・最大 20 秒** (2 回) | 8391 列のサブ MIP が自分の根の FP で 1.8 秒に -236、164 ノードで時間切れ | **-236 / -236** |

  サブ MIP の時間は `ENOMOTO_T_MIP_SUBMIP_TIME_FRAC=0.3 ENOMOTO_T_MIP_SUBMIP_TIME_MAX=20` (既定 0.07・6 秒)。
- 1 ノードが重い理由: 根の強分枝 (124 LP、25638 反復) に 18.2 秒かかっている (`sb_secs 18.19`)。58529 列の LP。HiGHS は根で終わるので強分枝をしない。

### 推測

- HiGHS の根の RENS は固定率の目標 (初期 0.6 前後) で止め、サブ MIP にノード上限だけを課す (時間は短くない) ので、8000〜20000 列が残る
  サブ MIP を解き切れる。ENOMOTO は「全部固定 → 狭すぎて実行不能・-226 止まり」か「広げる → 時間切れ」の両極端になっている。
- 残りの -236 → -238 は、サブ MIP 自体の強さ (1 スレッドのサブ MIP が 13 秒で 164 ノード、HiGHS のサブ MIP は 2 秒) の差と見られる (未確認)。

## 2. mzzv42z (最小化、最適値 -20540、10460 行 × 11717 列)

| | HiGHS (前処理あり) | HiGHS `presolve=off` | ENOMOTO 既定 (3 回) |
|---|---|---|---|
| 前処理後 | 6139 行 × 6980 列 (18 秒) | 10460 × 11717 | 10460 行 × 10693 列 (3.7 秒、行は 1 本も減らない) |
| 根の LP | -21414.2 (19.6 秒) | -21623.0 (2.5 秒) | -21623.0 |
| カット後の根 | -20737.7 (25.4 秒、373 本) → 再スタート 2 回で -20671.8 | -20829.2 (7.8 秒、469 本) → -20750.2 | -21488.6 / -21401.1 / -21488.6 (27〜34 本、7.3〜11.5 秒) |
| 最初の解 | 0 (FJ、19.0 秒) | 0 (trivial zero) | -1400 (FJ、3.4〜4.7 秒) |
| 最適解 -20540 | 25.4 秒、根のサブ MIP (`L`) | 21.0 秒、根のサブ MIP (`L`) | 見つからず |
| 終了 / 時間上限の時点 | 53.0 秒・1 ノードで最適 | 50.0 秒・1 ノードで最適 | 60 秒、596 / 266 / 239 ノード、下界 -21273 / -21267 / -21414、暫定解 -16840 / -8598 / -14892 |

### 事実

- **前処理は主因ではない**: HiGHS は前処理なしでも根のカットで -20829 まで上げ、21 秒に -20540、50 秒・1 ノードで終わる
  (`t4/highsopt_mzzv_nopre.log`)。HiGHS の前処理の内訳 (`log_dev_level=1`、`t4/highsopt_mzzv_dev.log`) は probing
  (行 1373・列 2276 を削除、係数の持ち上げ 19706)、列挙前処理 (列 1076 固定)、支配列 126 固定など。
- **双対側の大きさ** (主側を除いた測定、120 秒):
  - `ENOMOTO_MIP_START_FILE=analysis/mzzv/sol_mzzv42z.txt` (HiGHS の最適解、受理された): 下界 -20944 (ギャップ 2.0%)、697 ノード。
    根のカット -21519、再スタートで新たに固定できた列は 5 本 (HiGHS は 14.6%・4.3% の列を落として再スタート)。
  - `ENOMOTO_MIP_CUTOFF=-20539.5`: 下界 -20957 (ギャップ 2.4%)。打ち切り値で再スタートが起き、その後の木の RINS・proximity で
    暫定解 -20460 まで届いた。
  - HiGHS は同じ時点で 1 ノード目の強分枝で -20543 にして終わる。ENOMOTO の根の下界は HiGHS より 600〜700 弱く、被約費用による固定も効かない。
- **根のカット**:
  - 既定はカットのループの時間上限 (全体の 10% = 6 秒) で 2 ラウンドで止まる。1 ラウンドの分離が 2.6 秒で、その大半は
    面の頂点からの分離 (`ENOMOTO_MIP_FACE_SEP` 既定 `int2`: LP を複製して面の LP を解く) と見られる
    (`ENOMOTO_MIP_DEBUG_SEP` で分離器の合計は 1 ラウンド 0.65 秒、`ENOMOTO_MIP_FACE_SEP=off` で 1 ラウンド 0.3 秒)。
  - 行からの MIR (`SEP rows`) の候補は毎ラウンド 0 本。候補は tableau (Gomory) が約 1100〜1500 本、zerohalf が 100 本。
  - ラウンドを増やしても下界は伸びが鈍い (各 1 回):

| 設定 | ラウンド | カット後の根 | 暫定解 (60 秒) |
|---|---|---|---|
| 既定 | 2 | -21488.6 | -16840 / -8598 / -14892 |
| `ENOMOTO_T_MIP_CUT_TIME_FRAC=0.4` | 8 (25 秒) | -21298.6 | -18272 |
| 同 + `ENOMOTO_MIP_CUTSEL_HIGHS` | 8 (26 秒) | -21236.5 | -16120 |
| 同 + `ENOMOTO_MIP_CUT_ADAPT_MAX` | 8 | -21298.6 | -18272 |
| `ENOMOTO_MIP_FACE_SEP=off` | 8 (7 秒) | -21268.8 | -15990 |
| `FACE_SEP=off` + `CUT_TIME_FRAC=0.4` | 7 (LP の時間切れで停止) | -21276.6 | -10800 |

    HiGHS (前処理なし) は最初のカットの段で -20829。ENOMOTO はどの設定でも -21240〜-21300 で止まる。
- **主側**: 根の RENS (旧来の全部固定) は 718〜750 列が残り実行不能。根の RINS は 9 割を固定 (874〜977 列) した
  サブ MIP の最適値を返すだけで、その値は出発点の暫定解で決まる:
  - 1・3 回目: 並列の locks のサブ MIP (3 秒上限) が -8424 を出し、RINS はそこから -14892。
  - 2 回目: 根のカットが 11.5 秒かかり (他は 7.3 秒)、locks のサブ MIP は解 0 で時間切れ。RINS は FJ の -1400 から出発して -8598。
  - 木の中の RINS が 1 回当たると改善する (1 回目 -16840、48 秒) が、木は根の下界が弱く 300〜600 ノードしか進まない。
  これが揺れの原因 (手元 16 スレッドの -16926 / -9108 も同じ形と推測)。

### 推測

- 双対側の差はカットの種類の差が大きい: HiGHS は前処理なしでも最初の分離で 4953 本の候補 (469 本を LP に入れる) から -20829 まで
  上げる。ENOMOTO は行の集約からの MIR が 1 本も出ず、Gomory と zerohalf だけで、50 本ずつ入れても伸びが小さい。
  どの族が効いているかは HiGHS の計測用パッチ (scripts/highs_instrument.md) で分離器ごとの効きを見ないと確定しない (未実施)。
- 主側は、下の試作 (広い近傍のサブ MIP) で -20190 まで届くので、残りの差の多くは双対側 (被約費用固定・再スタートが効かない) にある。

## 3. 試作: `ENOMOTO_MIP_ROOT_WIDE_SUBMIP` (既定では使わない)

- 内容: 根のヒューリスティクスの最後 (既定の RINS の後) で、暫定解と根の LP の差が `ENOMOTO_T_MIP_WIDE_SUBMIP_GAP` (既定 0.5%) を
  超えていれば、固定を目標の固定率 ([`target_fix_rate`]、初期 0.6) で止めた広い近傍 (`ENOMOTO_MIP_FIX_CAP` と同じ固定) で、
  サブ MIP の時間を残りの `ENOMOTO_T_MIP_WIDE_SUBMIP_FRAC` (0.3)、最大 `ENOMOTO_T_MIP_WIDE_SUBMIP_MAX` (20 秒) にして
  RENS と RINS をもう 1 回ずつ解く。既定の RENS・RINS はそのまま (前に FIX_CAP を全体に入れたら noswot・10teams が悪化した
  (analysis/mip_primal_weakness_20261016.md) ので、置き換えずに追加にした)。

## 4. 既定にする候補か

- 主側の試作は候補になりうるが、そのままでは早い: 解ける問題で根に数秒を足す (rout +4 秒)。根の時間を使う条件を
  「既定の RENS が 0 ノードで実行不能 (近傍が狭すぎた) または RINS のサブ MIP が 0 ノードで最適 (近傍の中に改善がない)」に
  絞ると、rout のような「根の RENS が普通に働く問題」を外せる見込み (未確認)。40 問の全体の計測は親に任せる。
- mzzv42z の双対側 (カット) は別の作業: 行の集約からの MIR が出ない理由と、面の頂点の分離の時間 (1 ラウンド 2.2 秒) を見直す。
  `ENOMOTO_MIP_FACE_SEP=off` は分離を 8 倍速くするが、この問題では下界がほとんど変わらない (-21269)。

## 5. 失敗した試み・確かでない点

- RENS_DIVE・RENS_PROP・SUBMIP_RENS・SUBMIP_CUTS は neos-960392 で効果なし (全て -226)。カットの選択 (CUTSEL_HIGHS・ADAPT_MAX・
  時間 0.4) は mzzv42z の根の下界を -21489 → -21240〜-21300 にするだけで、HiGHS の -20829 には遠い。
- neos-960392 の -236 → -238 の差 (サブ MIP の強さ) は未確認。
- 副作用の 8 問は 2 回 (neos-1456979・qiu は 1 回) で、10teams・noswot は揺れの方が大きい。
- 試作の目標の固定率は既定の記録 (`rens_succ`・`rens_infeas`) を使うので、既定の RENS・RINS の結果で変わる
  (neos-960392 の RINS (wide) は 0.82 になり狭い)。
- 診断用の `ENOMOTO_MIP_START_FILE` (コミット e9615bf) は両問題で受理され、正しく動いた。
