bench に使う環境変数: `ENOMOTO_MIP_SYMPRE=probe` (疎な自己同型の探りだけ、本命)、`ENOMOTO_MIP_SYMPRE=1` (= `pre`、次数 0・1 の除去 + 探り)、

検出に渡したグラフと生成元の書き出しは `ENOMOTO_MIP_DEBUG_DUMP_SYMGRAPH=ファイル`。**どれも既定では使わない (既定の動きは変えていない)**。

生データ: `analysis/sassy_20261110/` (`survey.md` = ソフトウェアの調査、`detect*.jsonl` = 検出だけの数え、`bench_eff.jsonl` = 6 問の MIP、

## 結論 (先に)

1. **既定にはしない** (このセッションの指示は「試作は既定では使わない」。別のセッション (親) から「4 問で効き目・58 問で害なし・誤答 0 なら既定に
   してよい」という基準も届いたが、下のとおり **MIP の時間での効き目が見えない** ので、その基準でも既定にはならない)。
2. **見落とし (事実)**: 今の ENOMOTO の検出 (後戻りなしの貪欲な 1 本の道) は、生成元のある 45 問のうち 10 問で、軌道が色の細分化の上界
   (軌道の上界) より小さい。そのうち neos-827175・physiciansched6-2 では、自前の後戻りの探索 (refcheck.py) で ENOMOTO が見落とした
   自己同型を実際に見つけた (確かめつき)。ほかの 8 問は「上界との差はあるが、節点の上限で決められない対が残る」(本当の見落としかは未確定)。
3. **探り (sassy の (3)) は見落としを拾う (事実)**: 深い探索の前に全ての色の組で浅い個別化・細分化の疎な置換を集めると、
   neos-827175 (生成元 66→121、軌道の列 17,353→31,598 = 上界)、uccase12 (20→34、18,095→33,841 = 上界)、physiciansched6-2 (194→198 列)、
   neos-873061 (76→244)、satellites2-60-fs (1,386→1,492)、academictimetablesmall など。検出の時間はほぼ同じ (最大の増え 0.6 秒)。
4. **MIP の時間には効かない (事実、種 2 回)**: 見落としの多い 6 問で既定・probe・pre の時間・解はほぼ同じ (neos-827175 は 3 設定とも 5〜10 秒で
   最適、揺れの内)。58 問 (60 秒・4 スレッド・種 1・2) で既定 対 probe は **SGM -0.5% [95% 区間 -5.3%, +4.5%]、解けた 86 → 85**、
   最適値の食い違い 0 / 116 対。害は見えないが、効き目もない。
5. **次数 0・1 の除去 (sassy の (1)) は勧めない (事実)**: neos-873061 でだけ効き (軌道 76→792 列・検出 3.1→2.0 秒) 、satellites2-60-fs では
   部分木の入れ替えで生成元が 146→925 個に増え検出が 1.0→3.8 秒、academictimetablesmall では核の検出の生成元が減る (原因は未解明)。
6. **誤答の検査**: 全ての設定で確かめを通らない生成元は 0 (検出の比べで書き出した全部の生成元を、別に書いた確かめで取り直した)。
   fuzz (自作の対称な MIP の fuzz を含む) も全部 bad 0。`cargo test --release --lib` 400 件通過 (sympre の単体テスト 2 件を含む)。
7. **外部ライブラリ**: 配れるのは nauty/Traces (Apache-2.0) と dejavu/sassy (MIT)。入れるなら dejavu 2.1 (sassy 込み、ヘッダーだけ、MIT) が
   第一候補で、手間は 2〜4 日 (推測)。ただし上の 4. のとおり、生成元を増やしても今の対称性の扱い (orbital fixing・lex-leader・オービトープ) では
   MIP の時間が縮まらないので、**今すぐ入れる価値は低い** (判断は利用者に任せる。結び付けは入れていない)。

## 3. 試作 `ENOMOTO_MIP_SYMPRE` (src/mip/sympre.rs)

- **(1) 次数 0・1 の除去 (`d1`)**: 行と列の二部グラフで、次数 1 以下の頂点を回ごとにまとめて外し (木の葉から中心へ)、外した部分木の形
  (ハッシュ) を残った頂点の色に書き込む。核 (残ったグラフ) を今の検出にかけ、核の生成元を元の問題に戻す (核の行は色と写した中身で対応、
  外した頂点は親の像の子のうち同じ形の同じ順位に写す)。同じ親の下の同じ形の部分木と、核の同じ行に付いた部分木の入れ替えも生成元に足す。
  元から次数 0 の列は外さない (`ENOMOTO_MIP_SYM_SKIP_FIXED` と合わせる)。双子 (呼び出し側が扱う) どうしの入れ替えは足さない。
- **(3) 疎な自己同型の探り (`probe`)**: 今の検出 (`symmetry.rs` の `detect_inner`) の中、深い探索の前に、全ての色の組で、組の先頭の列 a と
  各列 b を 1 回だけ個別化して細分化し、色が変わった列だけを対応させた置換 (`shortcut_perm`) を確かめて生成元にする。a の側の細分化は組ごとに
  1 回。組の全部が a の軌道に入れば、その組は片付く (深い探索も組の中の対を試さない)。探りは残りの時間・手間の
  `ENOMOTO_T_MIP_SYMPRE_PROBE_FRAC` (既定 0.5) 倍で止め、**使った分は深い探索の上限に足す** (初めの形では探りが上限を先に使い、cod105・
  mushroom-best で軌道が減り、chromaticindex512-7・1024-7 で生成元が 0 になった。直した後は 3 問とも既定と同じ)。
- どの生成元も元の (検出に渡す) 問題で確かめてから使う。`symmetry.rs` の差分は関数の公開範囲と探りの呼び出しだけ。
- sassy の (2) (次数 2 の道) と (4) (商グラフ) は入れていない。

## 5. 誤答の検査

## 6. 外部ライブラリを使う価値 (推測を含む)

- 入れるなら dejavu 2.1 (sassy 込み、MIT、ヘッダーだけ): vendoring + `cc` クレートで `extern "C"` の shim。係数を色に写し、辺を中間頂点で
  符号化する変換が要る (SCIP の `build_dejavu_graph.cpp` と同じ)。手間 2〜4 日 (推測)。C++14 のコンパイラが wheel の CI に要る。
- nauty (`nauty-Traces-sys`) は FFI の手間が最小 (1〜2 日、推測) だが、sassy なしでは大きな MIP のグラフで遅い。
- **価値**: 今回、探りで軌道を上界まで広げても MIP の時間は縮まなかった (neos-827175・uccase12 は軌道の列が倍)。完全な群を求めても、
  今の対称性の扱いがそれを使い切れないなら効き目は小さい (推測)。外部ライブラリより先に、増えた軌道で orbital fixing・オービトープの数が
  どう変わったかを調べる方がよい。

## 8. 軌道が倍になっても速くならない理由 (neos-827175・uccase12、2026-11-11)

既定と probe を 60 秒・4 スレッド・種 1・2 で解き、対称性のログを拾った (`analysis/sassy_20261110/why/`、事実)。

| | neos-827175 既定 | neos-827175 probe | uccase12 既定 | uccase12 probe |
|---|---|---|---|---|
| 生成元 / 軌道の列 | 66 / 17,353 | 121 / 31,598 | 20 / 18,095 | 34 / 33,841 |
| オービトープ | 1 個 (175x67) | 1 個 (175x122) | 5 個 (168x6・2・2・3・12) | 12 個 (168x6・2・2・3・14・3・5・2・2・2・3・2) |
| orbital fixing に使う生成元 | 0 / 66 | 0 / 121 | 0 / 20 | 0 / 34 |
| lex-leader の行 | 0 | 0 | 0 | 0 |
| オービトープの固定 (種 1) | 0 | 0 | 11 | 0 |
| 結果 (種 1 / 種 2) | 最適 4.4 / 6.8 秒、ノード 0 / 0 | 最適 6.9 / 6.8 秒、ノード 0 / 0 | 時間切れ、ノード 35 / 45 | 時間切れ、ノード 41 / 45 |
| 下界 (時間切れの時) | — | — | 11507.371 / 11507.370 | 11507.372 / 11507.372 |

- **neos-827175 は根で解ける** (どの回もノード 0、根の下界 = 最適値 112.00152)。対称性の扱いは分枝の木で効くもので、木がないので
  軌道がいくつあっても効かない。時間は根の LP・カット・ヒューリスティクス (初めの解は 2.6〜3.2 秒) で決まり、差は揺れ (既定どうしで 4.4 と 6.8 秒)。
  生成元は全部 175 行のオービトープ 1 個にまとまり (列が 67 → 122 本に広がる)、orbital fixing にも lex-leader の行にも回らない。
- **uccase12 は 60 秒で 35〜45 ノードしか進まない**。1 ノードの LP が重く (前処理の後 8.9 万行)、木が浅いので対称性で刈る余地がない。
  probe でオービトープが 5 → 12 個に増えたが固定は 0 (既定の種 1 で 11)。再スタートの後は生成元が 0 個に落ちる (`orbital fixing after the restart keeps 0 of 0`)。
  時間切れの下界と解は 4 回とも 1e-5 の内でそろっていて、差を作っているのは LP の手間。
- どちらも、見つけた生成元はオービトープに吸われ orbital fixing に使われていない (`orbital fixing with 0 of N generators`)。
  オービトープの列が増えても、木が無い・浅い問題では固定が起きない。
- **推測**: 軌道を広げて効くのは「分枝の木が大きく、対称な解の取り違えでノードが増えている」問題で、今回の見落としの多い問題はそうではなかった。
  探り・外部ライブラリの価値を測るなら、ノード数の多い対称な問題 (例: 生成元があり 60 秒で数千ノード以上の問題) を選んで比べる必要がある。

## 7. 次の一手

1. (済み、8 節) neos-827175 は根で解け、uccase12 は木が浅く LP が重いので、対称性の扱いが効く場面がない。次は、ノード数の多い対称な問題で probe の効きを測る。
2. academictimetablesmall で `d1` の核の検出の生成元が減る原因 (核の色の書き込み・上限の割り当て) を調べる。直せないなら (1) は捨てる。
3. dejavu との比べ (完全な群) をするなら、ビルドしたプログラムの実行の許可が要る。
