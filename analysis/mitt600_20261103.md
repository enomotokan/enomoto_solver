# Mittelmann 186 問を 600 秒で HiGHS と比べる (2026-11-04)

- ENOMOTO は今の既定 (canddet + p、環境変数なし、ビルドはブランチ ccr-1beed81b-ex0uhq の d2a78f98 前後 (52195348 を含む))、HiGHS は highspy 1.15.1。
  4 スレッド・600 秒・1 回ずつ。ソルバーは同時に 1 つ、問題ごとに順を入れ替え。50 の並列セッション (4 CPU・メモリ約 15 GB の機械、
  cgroup の上限 ≈ 13.6 GB) で分担 (`mitt600_20261103/shards.json`、`run600.py`)。最大 RSS は 1 秒ごとの VmRSS。
- 集計は `mitt600_20261103/cmp600.py` → `cmp600.txt`。解けた = 最適か実行不能を示して 605 秒以内。SGM はずらし 10 秒、解けなかった回・crash は 600 秒。
  勝ち負けは解けた方の勝ち、両方解けたら (t+10) の比 0.9 未満・1/0.9 超、両方解けなければギャップが半分未満の方。

## 結果

| | ENOMOTO | HiGHS |
|---|---|---|
| 解けた数 (186 問) | **67** | **86** |
| SGM (秒) | **220.3** | 232.5 (ENOMOTO / HiGHS = 0.948) |
| 片方以上が解いた 91 問の SGM | 73.3 | 82.6 |
| 勝ち | 55 | 57 (互角 74) |
| 両方解けた 62 問の勝ち | 33 | 20 (互角 9) |
| メモリ不足で落ちた (returncode −9、13.3〜13.6 GB) | **6** | 0 |
| 最大 RSS が 5 GB を超えた問題 | 26 | 0 |
| 食い違い (両方最適で目的値が違う・状態が違う) | 0 | |

- 60 秒の比べ (`highs_mitt_20261103.md`) は解けた数 50 対 35、SGM 42.70 対 48.42 で ENOMOTO が大きく勝っていた。600 秒では
  **解けた数で逆転 (67 対 86)** する。SGM は ENOMOTO がわずかに良い (速く解ける問題で勝つ) が、60〜600 秒の範囲で HiGHS が 51 問を
  足すのに対し ENOMOTO は 17 問しか足さない。
- **片方だけ解けた 29 問: ENOMOTO だけ 6 (comp07-2idx・fhnw-binpack4-48・gen-ip054・mas74・wachplan・(uccase9 は両方解けず))、HiGHS だけ 23**。
  HiGHS だけの 23 問のうち、ENOMOTO の最後のギャップが 1% 未満なのが 8 問 (sct2 1.7e-4・unitcal_7 7.7e-4・mushroom-best 3.0e-3・
  neos-3627168-kasai 4.4e-3・neos-933966 9.4e-3・mzzv11 9.8e-3・csched008 1.7e-2 (1.7%)・tbfp-network 2.0e-2)。暫定解は良いが
  **下界を閉じられない** (木の効率・下界の上がり方)。uccase12 はメモリ不足で落ちた。
- **メモリ不足 6 問** (ENOMOTO だけ): app1-2・chromaticindex1024-7・neos-4763324-toguru・radiationm40-10-02・supportcase18・uccase12。
  ほかに uccase9 (13.3 GB)・CMS750_4 (12.6 GB)・chromaticindex512-7 (12.2 GB) が上限の手前。最大 RSS の比 (ENOMOTO / HiGHS) の中央値は 3.9。
  HiGHS は 186 問とも 5 GB 未満。
- 時間の上限の超過: ENOMOTO が 605 秒を超えて返った回はない。HiGHS は chromaticindex1024-7 (613.8)・chromaticindex512-7 (629.2)・germanrr (667.2)。

## 考え

- Mittelmann 先生の計測は時間の上限が長い (未確認) ので、**今の形で依頼すると「解けた数で HiGHS に負ける」結果になる見込み**。
  60 秒の強さ (根・ヒューリスティクス・速く解ける問題) は 600 秒でも SGM と両方解けた問題の勝ち (33 対 20) に残るが、
  長く木を回す問題で負ける。
- 直す順: (1) **メモリ** (6 問が落ちる。uccase12_mem1〜3 の試作 siblu1r・mem2p を bench22 で測っている。開いたノードの持ち物に
  上限を置く `MEM2` の `b` も要る)、(2) **木を閉じる力** (ギャップ 1% 未満で止まる 8 問、ノードあたりの効率・下界)。
