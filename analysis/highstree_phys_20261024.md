# physiciansched6-2: HiGHS の探索を辿って ENOMOTO と突き合わせる (依頼 highstree-phys、2026-10-24)

- 機械: 4 CPU (`nproc` = 4)。ソルバーは同時に 1 つだけ (ビルドは計測の合間)。
- 土台: `inv/submip-20261024` の `62ef950`。作業ブランチ `inv/highstree-phys-20261024`。
- HiGHS: GitHub `ERGO-Code/HiGHS` タグ `v1.15.1` を源からビルドし、計測の出力を足した (`highstree_phys_20261024/highs_trace.patch`)。
  既定のまま (ログの表示は「Thread count 2 … Using 1 max workers. Parallel search off」= 逐次の探索)、時間の上限 600 秒。
- ENOMOTO: 60 秒・4 スレッド (`run_cfg.sh`、`ENOMOTO_MIP_LOG=1`)。サブ MIP の書き出しは `ENOMOTO_MIP_SUBMIP_DUMP`、その近傍の最適値は
  HiGHS (highspy 1.15.1、1 スレッド、`highs_sub.py`) で求めた。
- 計測の行の目的値 (`TR ...` の `obj`・`lpobj`・`lb`) は HiGHS の前処理後の空間の値で、目的の定数項を含まない。外側の最初の前処理では
  定数 36109.5 (13214.5 ↔ 49324)。本文の値は元の空間に直した。

## 1. 結論

事実:

1. **HiGHS は 2 回とも木に入らず根 (1 ノード) で最適**。暫定解は 1 つだけで、出どころは根の RENS のサブ MIP (`L`)。RINS は一度も回らない
   (RINS は暫定解があるときだけ、HiGHS は FJ も解なし)。

   | 回 | 前処理後 | 根の下界の推移 (カットのラウンド) | 49324 の出どころ | 時間 |
   |---|---|---|---|---|
   | 種 0 (`h_s0`) | 8861 行 × 4608 列 | 47410.8 (5.1 秒) → 48107 → 48678 → 49033 → 49124 → **49324 (5 ラウンド目、9.8 秒)**、13 ラウンドで止める (LP 9351 行) | RENS: 固定率 0.600・戻り 0・自由な整数列 1814 / 4599。サブ MIP は前処理で 1162 × 1235、根の LP が既に 49324 で、カットの 1・2 ラウンド目の後の乱択丸め (`R`) が 49325.5 → 49324 | 14.1 秒 |
   | 種 1 (`h_s1`) | 8861 × 4604 | 47280.8 → 48151 → 48863 → … → 49311 → **49324 (8 ラウンド目、13.4 秒)**、11 ラウンド | RENS: 固定率 0.600 は前処理で実行不能 (0.09 秒) → 達した率の半分 0.302 (自由な整数列 3199、前処理で 3049 × 2427) でやり直し、5 ノード・1.76 秒。中で FJ (`J`) の解の後に、サブ MIP の中の RINS の潜り (`H`) が 49324 | 18.1 秒 |

   - 最適の証明は根の下界が 49324 に着くこと (カットだけで着く) なので、**木の形は 1 ノード** (分枝なし)。
2. **反実仮想 (外側の根のカットのラウンドを切る、`HIGHS_TRACE_MAXSEPA`、計測用に足した)**: カットがなくても HiGHS は解ける。
   - `MAXSEPA=0` (`h_sepa0_s0`、変化のあとの 1 ラウンドだけ、下界 47666): 根の RENS が固定率 0.600 (自由 1814) → 0.327 (3054) と
     サブ MIP が実行不能で、**0.163 (自由な整数列 3795、前処理で 5143 × 3396) が 3.10 秒・2 ノードで 49324** (14.4 秒)。その後は
     再スタート・木 104 ノード (深さ最大 58、葉 27: 下界で 16・定義域の矛盾 13・LP 実行不能 2) で 32.9 秒に証明。
   - `MAXSEPA=2` (下界 49033): RENS 0.33 で 49824 (9.3 秒) → 再スタート後の RENS 0.12 で 49424 → 0.307 で 49324 (24.7 秒、1 ノード)。
   - つまり HiGHS の主側の要は **「根の RENS が LP を解き直しながら固定し、サブ MIP が解を出さなければ固定率を半分にしてやり直す」こと
     と、その近傍のサブ MIP を数秒で解くこと** で、カットは下界 (証明) と近傍の質を上げる。
3. **ENOMOTO (既定・`SUBMIP_HIGHS=-t`) の根**:
   - 前処理後 10690 行 × 6003 列 (HiGHS 8861 × 4608)。根の LP 48583.1 (6〜7 秒)。
   - **根のカットのループは前景で 0 ラウンド**: 時間の上限は「開始から全体の 1 割」(`ENOMOTO_T_MIP_CUT_TIME_FRAC` 0.1 × 60 = 6 秒、
     `separation.rs` の `cap_base = self.cpu0`) で、根の LP の終わり (6〜7 秒) で既に超えている。背景のカットが根のヒューリスティクスの間に
     3 ラウンド・48 本で 48583 → 48587.4。以後の下界はこれ (HiGHS の根は 49324)。
   - 暫定解は先に Local-MIP から (50625〜51125、6〜8 秒)。根のヒューリスティクスはカットのない LP (48583) で回る。
   - 書き出した根のサブ MIP を HiGHS で解いた近傍の最適値 (`logs/sub_highs.txt`):

     | 近傍 | 既定 (`def_dump`、打ち切り 50725) | `-t` (`hnt_dump`、打ち切り 50826) |
     |---|---|---|
     | RENS (LP で整数値の列を全部固定、自由な整数列 1782) | 実行不能 | 実行不能 |
     | locks (1886) | 実行不能 | 実行不能 |
     | clique (441) | 実行不能 | 実行不能 |
     | RINS (Local-MIP の暫定解と一致する列を固定、2477 / 2342) | **49424** (ENOMOTO は 3.3 秒・0 ノードで時間切れ) | **49724** (ENOMOTO は 1.0 秒で 49724) |

     **ENOMOTO の根で作る近傍には、どれも 49324 が入っていない**。RINS の近傍の最適は出発点の暫定解で決まり (前の調べの d1_3 も 49424)、
     60 秒で 49424・49724 止まりなのはこれで説明がつく。
4. **ENOMOTO にダイビング式 RENS + やり直しを入れた試作 `ENOMOTO_MIP_RENS_HIGHS`** (外側の根で暫定解があっても、目標 0.6 から、解が出なければ
   達した率の半分で 4 回まで。既存の「暫定解なしの RENS」の形を使う):
   - 乱数の順 (既定) では、1 段目 (固定率 0.1) で LP が実行不能になって固定率 0.00 に戻る。0.29 まで進んだ近傍 (自由 3887) も HiGHS で実行不能。
   - **固定の順を HiGHS と同じ lock の積の順 (既存 `ENOMOTO_MIP_DIVE_LOCK_ORDER`) にすると、戻りなしで 0.51 → 0.26 → 0.13 と進み、
     0.13 の近傍 (自由な整数列 4740) に 49324 が入っている** (HiGHS で 12.5〜13.0 秒・1 ノード。2 回の回で同じ近傍が出る)。0.51 は
     実行不能、0.26 は 49824。
   - しかし **ENOMOTO はその近傍を解けない**: 実際の回では 10.2〜10.9 秒 (`SUBMIP_HIGHS=1` なら 40.3 秒) で 0 ノードの時間切れ。
     書き出して 1 スレッド・60 秒で解き直しても解なし (サブ MIP の形 48789、`SUBMIP_HIGHS=1` 49184、それ + `CUT_AGG` 49228、
     通常の求解 48957)。
5. **同じ近傍 (`rhl_c13`) で HiGHS と ENOMOTO を比べると、差は根のカット**:
   - HiGHS: 前処理 10690 × 111827 → 5678 × 3612。カットのラウンドで下界が 48884 → … → **49324 (7 ラウンド目、6.7 秒)**、LP 6270 行。
     その後の RENS が 0.6・0.36 で実行不能、0.18 (自由 2808) のサブ MIP の中の潜り (`H`) で 49324 (13.1 秒、1 ノード)。
   - ENOMOTO (`SUBMIP_HIGHS=1`、サブ MIP の形): 前処理後 7454 × 4563 (通常の求解の表示)。根の LP 48784 → カット 25 ラウンド
     (毎ラウンド 50 本、カットの非零の平均 2〜3) で 49184 (25 秒)。`CUT_AGG` でも 49228。
   - 外側でも同じ: 根のカットを前景で回す (`ENOMOTO_T_MIP_CUT_TIME_FRAC=0.4` + `CUT_AGG`) と 43 秒かかって 48987 (HiGHS は 11 秒で 49324)。
6. **60 秒・4 スレッドの確かめ** (形 A = `ENOMOTO_MIP_RENS_HIGHS=1 ENOMOTO_MIP_DIVE_LOCK_ORDER=1 ENOMOTO_MIP_SUBMIP_HIGHS=-t`):

   | 形 | 回 | 暫定解 |
   |---|---|---|
   | A | 2 | 51029・49724 |
   | `-t` だけ (`submip_20261024` の (b)) | 2 | 49724・49424 |
   | `RENS_HIGHS` だけ・+`LOCK_ORDER`・+`SUBMIP_HIGHS=1`・A+カットの時間 0.4 (各 1 回、診断の回) | 1 | 50825・50425・50525・49424 |

   手当ては近傍を作るところまでは効く (49324 を含む近傍が毎回できる) が、60 秒の結果は良くならない (解ける近傍にならない)。
7. 目的値の不一致 (HiGHS の最適値と違う「最適」) は出ていない (ENOMOTO は今回どの回も `time_limit`。HiGHS の 4 回はどれも 49324)。

推測:

- **道の分かれ目は「根で作る近傍」**: HiGHS は根の LP (カットで 49324 まで締めたもの、またはカットなしでも) から lock の順に LP を解き直し
  ながら固定し、固定率を半分にしながら近傍を広げて、49324 を含みかつ数秒で解ける近傍に着く。ENOMOTO の根は (i) 全部固定の RENS・
  locks・clique が実行不能で、(ii) RINS は Local-MIP の暫定解に縛られた近傍 (49424・49724) しか作らない。試作でこの (i) を HiGHS の形に
  すると 49324 を含む近傍はできるので、分かれ目の 1 段目はここ。
- その先で効いているのは **根のカットの強さ・速さ** (同じ近傍で HiGHS は 7 ラウンド・6.7 秒で 49324、ENOMOTO は 25 ラウンド・25 秒で
  49184)。HiGHS の近傍のサブ MIP が速いのは、根の下界がサブ MIP の最適値に着き、LP 解の丸め・潜りがすぐ当たるため (種 0 ではサブ MIP の
  根の LP が既に最適値)。外側でも、HiGHS は同じカットで根の下界を 49324 にして RENS の 1 回目 (0.6) で当てる。ENOMOTO のカットは 1 本
  あたりの非零が 2〜3 の短いもの (clique・含意とみる) が大半で、HiGHS が上げる分 (集約・MIR とみる) が出ていない (カットの種類は今回は
  数えていない)。
- 既定の根のカットの時間の上限 (開始から 1 割) は、この問題では前処理と根の LP で使い切られて前景のカットを 0 ラウンドにしている。ただし
  上限を外しても ENOMOTO のカットは遅く弱い (43 秒で 48987) ので、上限だけ直しても届かない。

## 4. 追加の依頼: 根のカットの強さと速さ (2026-10-24 午後)

- physiciansched6-2 の根の下界 48857 は、ENOMOTO の前処理の形での ENOMOTO の分離の限界に近い (選び方を 3 通り変えても同じ値で止まる)。
  HiGHS との残りの差は 6.1 の前処理 (探りの代入と持ち上げ) が大きく、選択・プールの回し方では埋まらない。
- pool の形は physiciansched6-2 よりも他の問題 (h80x6320d・mzzv42z・neos-960392) で効くので、別に 40 問で測る値打ちがある (既定にする判断は
  まだしない)。

## 7. HiGHS の探りの代入と持ち上げ、ENOMOTO の探りが HiGHS の探りを止める理由 (追加の依頼、2026-10-24 夜)

依頼: HiGHS の探りの代入 (750 列) と係数の持ち上げ (1942 個) のどちらが効くかを分け、効く方を ENOMOTO の探りに足す。ENOMOTO の探りの後で HiGHS の
探りが 0 列・539 個しか働かない理由を 1 段見る。

事実:

1. HiGHS の探りの中身 (ソース `HPresolve::finaliseProbing`・`applyConflictGraphSubstitutions`、`HighsCliqueTable::addImplications` の被覆の判定):
   「持ち上げ」は clique の行に新しい 2 値の列を足すもの (clique の延長)。「代入」は含意からのもの (y = a + b·x) と clique の表の同値
   (v1–v2 と ¬v1–¬v2 の両方が clique にあれば v1 + v2 = 1) の 2 種類。計測版に `HIGHS_TRACE_NOLIFT`・`HIGHS_TRACE_NOSUBST=impl|clique|all` と
   代入の数の出力を足し、元の問題で 1 つずつ止めた (60 秒、`logs/ps_*`):

   | 形 | 前処理後の 2 値の列 | 根の LP | 60 秒 |
   |---|---|---|---|
   | そのまま (clique の同値の代入 732、含意からの代入 0) | 4185 | 47410.8 | 12 秒で最適 49324 |
   | 含意からの代入なし | 4185 | 47410.8 | 11.3 秒で最適 (代入が 0 本なので同じ) |
   | **clique の同値の代入なし** | 4967 | 46623.2 | 49325・下界 48144 |
   | **持ち上げ (clique の延長) なし** | 4233 | 46619 | 解なし |
   | 両方なし | 5243 | 46619 | 解なし |

   **clique の同値の代入と持ち上げは両方とも要る** (どちらか一方では LP が 46620 前後のまま、カットも効かない)。

2. ENOMOTO の探りの前後の書き出し (clique の延長の前、`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED`、探りあり A・なし B) を列名で突き合わせると
   (`prediff.py`、`logs/prediff.txt`)、**行は全く同じで、違いは A で 2 値の列 180 本が 0 に固定されていることと、z (C62277) の下限 7308 → 7607.99999209
   の 2 つだけ**。B に 1 つずつ入れて HiGHS にかけると (`premod.py`、`logs/pm_*`):

   | 形 | HiGHS の探り | 前処理後の 2 値 | 根のカット (10 ラウンド) |
   |---|---|---|---|
   | B (探りなし) | 4108 回、750 列を消す、1942 個の持ち上げ | 4223 | 11663 → 13214.5 (= 49324) |
   | **B + 180 本の固定** | **1001 回、0 列、503 個** | 4940 | 10412 → 10414 (動かない) |
   | B + z の下限 (7607.99999209 / 7608) | 4108 回、750 列 | 4223 | 13167 (ほぼ同じ) |

   - 180 本の固定は全部 0 で、HiGHS の最適解 (49324) とも全部一致する (固定は正しい)。
   - **理由は HiGHS の探りの手間の予算**: HiGHS の探りは、列が消えるかクリークが増えた評価で予算 (`probingContingent`・`splayContingent`) を増やし、
     何も起きない評価が続くと減らす (`numFail`)。元の問題ではこの 180 本の固定が HiGHS 自身の探りの最初の方の「成果」として予算を延ばしていたが、
     ENOMOTO が先に固定してあると最初の評価が空振り続きになり、1001 回で予算が尽きて、後ろにある 732〜750 組の同値に届かない。つまり ENOMOTO の形が
     代入を消しているのではなく、HiGHS の打ち切りの規則による (ENOMOTO の形に HiGHS をかける比べは、探りについては公平でない)。
3. ENOMOTO 側の対応する部品は既にある: 含意つきの同値の代入 `ENOMOTO_MIP_PROBE_EQUIV2` (この問題で 1084 組、前処理後 9872 × 4981) と clique の延長 (既定)。
   E2 の後の書き出しを HiGHS にかけると、延長の前は LP 46623 で弱く (HiGHS の探りはまた 1001 回で打ち切られ、持ち上げ 195 個)、延長の後は LP 48583.1 →
   10 ラウンドで 49157 (HiGHS 自身の前処理の後は 49324)。新しい切り替えは足していない (効く方の代入は既存の `PROBE_EQUIV2`、持ち上げは既定の clique の延長)。
4. **確かめ: E2 + プールの選び直し (e2pool)** = `ENOMOTO_MIP_PROBE_EQUIV2=1 ENOMOTO_MIP_ROOT_CUT_HIGHS=1 ENOMOTO_T_MIP_ROOT_CUT_HIGHS_MAX_CUTS=1000
   ENOMOTO_MIP_CUTSEL_HIGHS=1 ENOMOTO_MIP_CUTSEL_HIGHS_POOL=1 ENOMOTO_T_MIP_ROOT_POOL_ROUNDS=1000 ENOMOTO_T_MIP_ROOT_CUT_AGE=10`
   (`batch_e2pool.sh`、60 秒・4 スレッド、`logs/sum_rch.txt`):

   | 問題 | def | pool (§6) | **e2pool** |
   |---|---|---|---|
   | physiciansched6-2 (4 回) | (50925・51029・49424・50825) | 50427・50227・49324・49424 | 49624・49624・49624・49724 |
   | 最初の根のカットの終わり / 最後の根 | 48587 | 48857 (25 秒) / 49024 | **49240.7 (46 秒)** / **49257〜49274** |
   | mzzv42z | −20420・−20480 | −20540・−20540 | −20470・−20500 |
   | timtab1 | 772421・764772 | 764772・781836 | 774885・781836 |

   | app1-1 | 21.3・21.3 秒 | 14.6・18.9 秒 | 14.0・14.1 秒 |
   | qiu | 47.7・44.0 秒 | 43.0・59.9 秒 | 37.7・40.3 秒 |
   | h80x6320d | 時間切れ・58.0 秒 | 26.2・25.8 秒 | 30.7・26.9 秒 |
   | nw04 | 8.2・9.9 秒 | 11.2・11.2 秒 | 10.0・10.2 秒 |

   - physiciansched6-2 の根の下界は今までで最も高い (最初の根で 49241、最終 49274、最適値まで 50)。ただし根のカットに 46 秒かかり、暫定解は
     49624〜49724 で pool より悪い (根の後のヒューリスティクスの時間が残らない)。証明は 0 回。

推測:

- HiGHS の形で根のカットが効くのは「clique の同値の代入 (約 730 組) + clique の延長 (約 1900 個)」の後の形で、ENOMOTO の E2 (1084 組) + clique の延長
  (3644 行に 10857 非零) は同じ種類の手順だが、延長の量と選び方が違い、tableau のカットの効きは HiGHS の形に届かない (HiGHS をかけても 49157 対 49324)。
  延長の量 (ENOMOTO は HiGHS の約 5 倍の非零を足す) が LP を退化させているとみる (確かめていない)。
- 次の 1 段は、ENOMOTO の clique の延長を HiGHS の量 (`HighsCliqueTable` の延長の選び方) に寄せた形で、E2 の後の根のカットを比べること。

## 9. 根で試して選ぶ形 `ENOMOTO_MIP_CUTSEL_PROBE` (追加の依頼、2026-10-25)

依頼: 計測 15 (`origin/inv/heur-ls-20261023` の `analysis/heur_ls_20261023/bench15_results.md`) で POOL の得 (roll3000・h80x6320d・binkar10_1・physiciansched6-2) と
損 (noswot・neos-960392・hypothyroid-k1・dcmulti) がどちらも本物だったので、問題の特性で決め打ちせず、根で試して選ぶ形を作る。

### 9.1 入れた切り替え (既定では使わない、`separation.rs`)

- `ENOMOTO_MIP_CUTSEL_PROBE=1|rate`: 外側の最初の根 (再スタートの前) の 0 ラウンド目で、既定の選び方 (`select_cuts`、50 本) と POOL の選び方 (HiGHS の点数・1000 本・平行度 0.1、
  2 ラウンド目からプールで違反しているカットも候補) のそれぞれで `ENOMOTO_T_MIP_CUTSEL_PROBE_ROUNDS` (3) ラウンド、分離 → 選択 → LP を温かい基底から解く、を
  回す (`Solver::probe_cut_mode`)。下界の伸び (`1`) または時間あたりの伸び (`rate`) の大きい方を選び、終わったら足した行を外して LP の状態 (基底・LU) と HiGHS の

## 10. 比べの副作用を消す (追加の依頼、2026-10-25)

依頼: 比べの分離の乱数・分離器の状態を保存・復元して noswot の副作用を消す。比べにかかった根の時間を `ENOMOTO_MIP_LOG` に出し、既定を選んだ問題で既定と同じ経路に
戻っているか (根の下界・最初の分枝まで) を noswot・hypothyroid-k1・neos-960392 で既定と突き合わせる。9 問・4 回 (既定と PROBE) で確かめる。

### 10.1 副作用の元と直したこと

- noswot の既定と PROBE (§9 の形) のログを突き合わせると、根のカットの 0 ラウンド目は同じで、**1 ラウンド目の候補が 120 → 118 本にずれていた**
  (プールも 455 → 484 本)。プールへの追加は本体のループの中だけなので、ずれは比べの分離が書き換えた分離器の状態から来る。
- 直したこと (`separation.rs`):
  1. 比べ (`probe_cut_mode`) の前後で、乱数 `rng`・tableau の記憶 `tab_memo`/`tab_memo_mode`/`tab_memo_stats`・tableau の予算の数え `tab_calls`/`tab_tries`・
     面の頂点の時間の勘定 `face_secs`/`face_used`/`face_off_loop`・並列の分離の CPU 時間 `sep_par_cpu`・`last_cut_lp_secs`・LP の反復の累計 (`set_total_iterations`) と、
     HiGHS の点数の状態 `cutsel_best`/`cutsel_factor` を保存して戻す。
  2. 比べを 0 ラウンド目の選択の直前から、**0 ラウンド目の始め (時間の上限の判定の前)** に移し、比べ自身が分離する。既定を選んだら、最低ラウンド数を元に戻し、
     **時間の上限の起点を比べにかかった時間だけ後ろにずらす**。これで既定を選んだときの時間の上限の判定は比べがないときと同じになる (以前は、hypothyroid-k1 で
     比べの 8 秒が根のカットの上限に数えられて 2 ラウンドが 1 ラウンドに減り、neos-960392 では既定なら 0 ラウンドのところを 1 ラウンド回していた)。
  3. ログに比べの合計時間と終わった時刻を出す: `MIP: cut selection probe (6 rounds): default … gain … (…s), pool … gain … (…s) -> default (rule rate, probe 10.55s in total, 11.81s)`。
