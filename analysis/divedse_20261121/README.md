# 潜りの LP で DSE の重みを毎歩作り直す手間 (P2-INF、2026-11-21)

analysis/biglp_20261121/ の直し案 1 の続き。
sing44 (4 スレッド) では、再スタートの後の根の潜り 2 本に 337 秒かかっていた。
gdb の標本は、どれも潜りの各歩の LP の `DseState::from_basis` の中にあった。
作り直しを手間の見積りで省く試作 `ENOMOTO_MIP_DSE_COST` (既定オフ) を入れて、既定と比べた。

## 0. 結論

**判断の材料**

- **作り直していた枝**:
  - 潜りの LP は、まず尺度を揃えた別の LP (LPSCALE の双子) で解く。元の尺度で確かめて通らなければ、本体の LP で仕上げ直す (mip_lp.rs:1822)。
  - その直前に `dse_cache` を空にするので、重みが渡らない。そのため `ENOMOTO_MIP_DSE_INIT` (既定 `umr`) の `u` の枝で、4.8 万行ぶんの単位 BTRAN を毎歩行っていた (§1)。
- **試作の効き目が出るのは、行が多くて 1 回の求解が短い LP (大きな問題の潜り) だけ。**
  - sing44 (4 スレッド): 根の潜り 1 本の時間は、既定 152〜198 秒 (種 1) に対し、試作は 24〜30 秒 (種 2)。
    - ただし 4 スレッドでは潜りの前から道が分かれる。どちらの設定でも、解が先に見つかって根の潜りを飛ばす種が多い (§3)。
  - rail01 (1 スレッド・決定的): 根の潜り 3 本の合計が 125.8 → 107.3 秒 (vector length が 58.4 → 40.3 秒)。根の下界は同じ。
- **P の 58 問では差がない、または少し遅い。**
  - 根だけ: 根の時間の比の幾何平均は 0.983。根の潜りがほぼ回らず、下界・解は全問同じ。
  - 木まで (1 スレッド・決定的・120 秒): 両方解けた 45 問で時間の比は 1.032、食い違いは 0。
    - 節の数が同じ 21 問では 1.013 (計り方の揺れの範囲)。
    - 節の数が変わった 13 問では 1.064 (timtab1 が 41 → 76 秒、rout が 19 → 14 秒)。
    - 単位重みから始めると選ばれる最適の基底が変わり、木の道が変わる。その揺れが目立つ。
- **誤答の確かめ**: fuzz 7 本は誤答 0。cargo test は既定・`DSE_COST=1` とも 419 件通過 (§5)。

**扱い**

- 大きな問題の潜りには効くが、P では木の道が揺れるぶん少し損に出た。
- このまま既定にするほどの材料はない。P・M の通しの計測の台本と分担表は作っていない (§6)。
- スイッチは既定オフのまま残す。

## 1. 枝の特定 (sing44、行番号つきのビルド)

- ビルド: `CARGO_TARGET_DIR=target/dbgline CARGO_PROFILE_RELEASE_DEBUG=line-tables-only maturin build --release`。
- 道のり: `follow.py` で既定の道をなぞった (`follow.out`・`logs/sing44_dive.log`)。
  - 再スタートが 129 秒。
  - fractional diving が 231.6 秒、vector length が 134.8 秒。
  - 木に入らずに時間の上限で止まった (下界 8118412・解 8131615)。
- 潜りの最中に gdb の標本を 11 回取った (`logs/sing44_dive_gdb_*.txt`)。そのうち 6 回が LP の中だった。
  - 5 回は `solve_tw` の仕上げ (mip_lp.rs:1822) → `solve_inner0` (:2957) → `solve_slope_intercept_dual_from_basis` の `u` の枝 → `DseState::from_basis` → `from_basis_sparse` の中にいた。
  - 1 回は双子の求解 (:1765) の中だった。
- 仕上げでは、重みを渡さずに解き直す。そのため、毎歩、行の数ぶんの単位 BTRAN を行う。1 歩あたり約 1 秒だった。

## 2. 試作 `ENOMOTO_MIP_DSE_COST=1` (既定オフ)

- **判定**: `u` の枝 (重みを作り直す枝) に入る前に、2 つの手間を比べる。
  - 作り直しの手間 = 1 行あたりの手間 × 行の数。
  - その求解の見込みの手間 = その LP の前の求解の反復の数 × 1 反復あたりの手間。
  - 作り直しの手間のほうが大きければ、作り直さずに単位重みで始める。
  - 理由: 正確な重みで減らせる手間は、求解全体の手間を超えない。
- **見積りの材料**:
  - 1 行あたりの手間 (`DSE_INIT_TICKS_PER_ROW`、src/simplex.rs): `from_basis_sparse` で LU の手間の差 × 重み / 行の数として測る。
    - この差は DseTickGuard が戻すので、決定的な手間には入らない。
  - 1 反復あたりの手間と前の反復の数 (`TwoStageLp` の `dc_last_it`・`dc_ticks`・`dc_iters`、src/simplex/mip_lp.rs): その LP の求解ごとに、手間と反復の差を貯める。
- **材料がないとき**: どちらかの見積りがまだなければ、今までどおり作り直す (そこで 1 行あたりの手間を測る)。
- **新しい閾値は置いていない。**
- **数え** (src/mip/solver.rs): 終わりに `MIP: DSE_COST skipped … built … built-without-estimate …` を出す。主スレッドのぶんだけで、`ENOMOTO_MIP_LOG` のとき。
- **双子の重みを引き継ぐ案は採らなかった。**
  - 双子は行も列も尺度を変えている。DSE の重み ‖e_iᵀB⁻¹‖² は行の尺度の 2 乗で変わり、列の尺度は B⁻¹ の行の各成分に別々に効く。
  - そのため、尺度を戻す正確な換算がない。近似で引き継ぐと、単位重みとの違いが見積りにくい。
