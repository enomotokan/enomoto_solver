# fuzz_tiny の食い違いはいつからか (2026-11-03)

**結論 (先に)**:

- 「当時 (2026-10-22) の既定では 300 問で 0」という前提は読み違い。`fuzz_summary.txt` の `== default  bad 0 of 300` は
  **別の生成器 `scripts/mip_fuzz_vs_highs.py`** の結果 (`analysis/equiv2_bug_20261022.md` §5 の 4 つ目の項目)。同じファイルの
  `== new` (fuzz_tiny、当時の既定) は **14/300** で、seed 61・81・139・148・159・195・201・210 と、今と同じ値で食い違っていた。
- 今の先頭 (6b614f69) の 13/400 は、2026-10-22 の e7a64375 (幅の小さい列の固定の最終版) から **seed も値も全く同じ**
  (e7a64375・e364c132・6b614f69 の 3 つで 400 問の出力が一致)。**この間に入った食い違いはない** (退行ではない)。
- seed ごとの始まり:
  - **seed 81**: 最初の版 5c40603b (2026-09-05) から今と同じ −37.53 (HiGHS −30.36)。入ったコミットはない。
  - **seed 195**: 2 つ目のコミット 5987f1db (2026-09-05「前処理や並列化などにより高速化」) から食い違う
    (そのときは「実行不能」、12a5d64a で −9.61、93045869 (10-09) 以降 −14.02)。
  - **seed 61**: 最初の版から 12a5d64a (09-25) までは −35.54 (こちらが良い) で食い違い、93045869 (10-09)〜4fee445b (10-22) は
    HiGHS と一致、**53d41e12 (10-22「係数の強化で、許容誤差の範囲で冗長な行は縮めない」) から −25.36** で食い違う。
- **戻せる環境変数**: seed 61 だけは戻せる。
  - 53d41e12 の時点では `ENOMOTO_MIP_COEF_TIGHTEN_TINY=1` で消える。
  - 今の先頭では `ENOMOTO_MIP_COEF_TIGHTEN_TINY=1 ENOMOTO_MIP_NO_TINY_WIDTH_FIX=1 ENOMOTO_MIP_PROBE_EQUIV2=0` の **3 つとも**
    戻して初めて消える (2 つだけだと −17.8 になる。PROBE_EQUIV2 を既定にした 19f6e814 (10-26) による)。
  - ただし 3 つ戻すと 400 問の食い違いは 13 → **109** に増える。seed 81・195 は戻せない (初めからの差)。戻すことは勧めない。
- 食い違いの中身: どれも許容誤差の境目 (右辺 `1 − 2e-9` の行・幅 1e-9 の列) の差。HiGHS の許容誤差を 1e-10 に締める (前処理なし)
  と HiGHS 自身の値も変わり、13 件のうち 4 件 (139・159・201・246) は ENOMOTO と一致、残り 9 件は 3 者とも違う (§4)。
  どの seed でも ENOMOTO の値 ≤ 1e-10 の HiGHS の値なので、「厳密に実行可能な解より悪い値を最適と返す」誤りは**この 13 件では
  起きていない**。

## 1. 手順

- `fuzz_tiny.py` は最初の 10 件しか出さないので、全部の seed を出す写し `fuzz_tiny_all.py` を使った (生成・判定は同じ。
  2026-10-06 より前の版は `mip_rel_gap` を受け付けないので外して既定の打ち切りで解く、実行不能を例外で返す版は `infeasible` とみなす)。
  判定は fuzz_tiny と同じ (状態が同じで、最適なら `|ENOMOTO − HiGHS| ≤ 1e-6 (1 + |HiGHS|)`)。HiGHS は 1.15.1、`mip_rel_gap=1e-9`。
- コミットごとに `git worktree` で出し、`CARGO_TARGET_DIR` を共有してビルドし (`bt.sh`)、wheel を展開して `PYTHONPATH` で読む。
  二分探索は first-parent の列で (`bis.sh`、環境変数つきは `bis_env.sh`)。生成器・判定・`scripts/mip_fuzz_vs_highs.py` は
  今の先頭のものを使い、ソルバーだけを替えた。
- 生データ: `analysis/fuzz_tiny_when_20261103/seeds/<コミット>[_TN].seeds` (食い違った seed の全部と `bad n of 400`)、
  `HEAD_*.seeds` (今の先頭で環境変数を変えたもの、先頭行に環境変数)。`_TN` は
  `ENOMOTO_MIP_COEF_TIGHTEN_TINY=1 ENOMOTO_MIP_NO_TINY_WIDTH_FIX=1`。

## 4. 食い違いの中身 (今の先頭)

`fuzz_tiny_cls.py 0 400` (`cls_6b614f69.txt`): こちらが悪い 5 件 (61・159・195・210・362) は全部 HiGHS の解の整数列を丸めた点が
行を 2e-9 破る。こちらが良い 8 件 (81・139・148・201・246・260・324・350)。

HiGHS を許容誤差 1e-10 (`primal_feasibility_tolerance`・`mip_feasibility_tolerance`、前処理なし) で解いた値 (`tight_tol.txt`、`tight.py`):

  1e-9〜2e-9 破る (`cls_6b614f69.txt` の `ours ... viol`) ので、ENOMOTO は「厳密」と「1e-6」の間の扱いをしている (列の幅 1e-9 の
  緩め・整数の行の丸め 1e-9 など、手順ごとに許容誤差が違う)。どこが混ざるかは追っていない。
- seed 139・201・246 (HiGHS 0、ENOMOTO −1e-6) は HiGHS (1e-6) が幅 1e-9 の列の寄与を落とした差で、ENOMOTO の方が正確。

## 5. 残り

- 食い違いを 0 にするには、許容誤差の扱いを HiGHS (1e-6) に揃えるか (整数の行の丸め・係数の強化の冗長判定・幅の小さい列の固定)、
  判定を緩める (fuzz_tiny の判定 1e-6 相対は、許容誤差の内の破れで目的値が O(1) 動く問題には厳しすぎる) かのどちらか。
  どちらにするかは決めていない。
- seed 81・148・260・324・350 (ENOMOTO が HiGHS (1e-6) より良い) は ENOMOTO の点が 2e-9 破るだけで HiGHS の許容誤差の内のはず
  なのに HiGHS が見つけない理由は調べていない (HiGHS の前処理が幅 1e-9 の列を固定するためと推測)。
