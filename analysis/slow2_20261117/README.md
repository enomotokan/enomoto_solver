# SLOW2: HiGHS より全種で遅い mzzv42z・unitcal_7 の原因 (2026-11-17)

課題 (利用者の依頼): 0.1.9 の既定は Mittelmann 48 問で HiGHS 1.15.1 より SGM −42% 速いが、mzzv42z (2.09 倍) と unitcal_7 (1.48 倍) は
全種で遅い (analysis/vshighs_20261117/summ_M.txt)。原因を特定し、改善案を出す。

- 機械: 4 CPU のクラウドのコンテナ。ソルバーは同時に 1 つ。4 スレッド・600 秒・種 1 (一部 2)。HiGHS 1.15.1 (highspy、mip_rel_gap 0)。
- 台本:
  - `one.sh <問題> <ours|highs> <種> <秒> <名前> [K=V ...]`: 1 回解き、ログを `logs/<問題>_<名前>_s<種>.log` に (各行の頭に起動からの経過秒。置いてあるのは gzip したもの)。
  - `root.py <問題> <札> [K=V ...]`: 根だけ (node_limit 1) → `root.jsonl`・`logs/root_<問題>_<札>.log`。
  - `pre.py <問題,...> <札> [K=V ...]`: 前処理だけ (`ENOMOTO_MIP_DEBUG_PRETIME=stop`) → `pre.jsonl`・`logs/pre_*.log`。
  - `batch1.sh`〜`batch5.sh`: この調べで回した並び。
  - 対の比べ: `cfg.py` (def・wst)・`plan.py`・`run.py`・`summ.py` (vshighs_20261117 の写し)。

## 結論 (先に)

1. **mzzv42z の差の大半は解 (主側) と手順の空回り** (事実、種 1): 当方 130.3 秒・HiGHS 63.5 秒。HiGHS は根のカットの直後のサブ MIP が
   29.6 秒で最適解 −20540 を出し、再スタート 2 回で 1 ノードで閉じる。当方は −20540 を 129 秒 (木の中) に見つけ、その 1.5 秒後に閉じる。
   その前に、結果を捨てる前処理のかけ直しのプロービング 10.7 秒・カットの選び方の試し 14 秒・再スタート後の HNFPRE のかけ直し 11.6 秒・
   木の根の強分枝 10.8 秒を使っている。
2. **unitcal_7 の差は根の下界 (カットの質) と根の解** (事実、種 1): 当方 301.6 秒・HiGHS 206.9 秒。根の下界は当方 1.9574e7・HiGHS 1.9608e7
   (最適 1.96356e7 までの残りが 2.2 倍)。ラウンド数 (100)・第 2 段階・zerohalf・1 ラウンドの本数 2000 では埋まらず、HiGHS 流のカット管理で
   1.9583e7 まで。根の解も当方 69 秒で 1.9776e7 (1%)、HiGHS 27 秒で 1.9641e7 (0.03%)。
3. **試作 wst** (`ENOMOTO_MIP_PRR_PRECHECK=1` + `ENOMOTO_T_MIP_HNFPRE_REPRE_MIN=10`、既定は変えない): mzzv42z 種 1 130.2 → 103.9 秒、
   種 2 147.4 → 123.7 秒。unitcal_7 は働かない (307 秒、ゆれの中)。対の比べ (P・M) で害を確かめる。
4. 既存の `ENOMOTO_MIP_CLQPRB` は mzzv42z に強く効く (種 1 69.8 秒、wst と組んで 69.5 秒、`1dgr` + wst で種 2 89.6 秒) が、
   puriri の解を失う害で不採用の経緯がある (analysis/prbimp_20261113.md)。ここでは扱わない。

## 3. 試作 wst (既定は変えない)

- `ENOMOTO_MIP_PRR_PRECHECK=1`: プロービングの後の前処理のかけ直し ([`represolve_after_probe`]) は、最後に行が 10% (`ENOMOTO_T_MIP_PRR_MIN_ROW_FRAC`) 減って
  いなければ結果を捨てる。かけ直しの中の前処理がプロービングに入る前の時点で 10% 減っていなければ、そこで返す (中のプロービングとさらに内側の
  かけ直しを省く)。中のプロービングで行が 10% を越えて減る問題では結果が変わりうる。mzzv42z: 前処理 25.1 → 13.9 秒。
- `ENOMOTO_T_MIP_HNFPRE_REPRE_MIN=10`: HNFPRE (整数の等式の Hermite 標準形、既定 `bounds`) が締めた列が 10 本より少なければ、前処理を
  (プロービングごと) かけ直さず、締めた境界だけ置く。mzzv42z の再スタート: HNFPRE の 11.6 秒 → 0 秒。

### 7.1 選び方の切り替え (根だけ、unitcal_7、`root.jsonl`)

- 全体の回では、カットの選び方の試しが毎回 pool (HiGHS の点数の選び方) を選ぶ (`MIN_REL` は効かない)。600 秒の回: `MIN_REL=0.1`・200 本で
  種 1 263.6 秒・種 2 236.4 秒 (既定 301.6・220.1 秒、ゆれの中)、mzzv42z 種 1 125.9 秒。
- pool の選び方でも経路のカットは 1 ラウンド 20〜40 本。implied bound は「必ず入れる」扱い (効き目 1e-4 でも、0 ラウンド目に 2323 本。HiGHS は点数で
  選び 278 本) で、当方は 0 ラウンド目に HiGHS より高く (前処理後の空間で 1.9512 対 1.9468) 出てから伸びが止まり、HiGHS が 3 ラウンド目で追い越す。
- `ENOMOTO_MIP_IMPLBD_SELECT=1` (既存、implied bound も選択に通す): 序盤の道筋は HiGHS に近づく (0〜4 ラウンド目 当方 1.94684・1.94873・1.95076・
  1.95170・1.95269、HiGHS 1.94682・1.94995・1.95242・1.95382・1.95479) が、ループが早く止まり根は 1.95660e7。
  + `MIN_REL=0.1`・200 本・`CUT_ROUNDS=60`・第 2 段階で 30 ラウンド 1.95782e7 (HiGHS は 11 ラウンド目で 1.95903、30 ラウンド目で 1.96047)。
- → 選び方とループの長さで差の 1/4〜1/2 は埋まるが、2 ラウンド目以降の 1 ラウンドの伸びが HiGHS の 6〜8 割にとどまる。同じ点での候補の強さは
  0 ラウンド目では同じだったので、残りは「同じ点を与えたときの 2 ラウンド目以降の経路のカットの強さ」か「LP の点の選ばれ方 (退化した面のどの頂点か)」の

## 9. 同じ点での分離の比べと試作 `ENOMOTO_MIP_VB_IMPL` (unitcal_7、親の指示 (2)、既定は変えない)
