# 再スタートで持ち込むカットの扱いの試作の確かめ (2026-10-28)

`ENOMOTO_MIP_RESTART_CUTS_FIX` (inv/restart-cuts-fix-20261027、a66e7b3) の効果を、4 スレッド・60 秒の機械 (Linux、4 コア) で
確かめ、既定にする候補を決める材料を作った。計測はすべて 1 本ずつ (同時に回さない)。

- ENOMOTO: `ENOMOTO_MIP_THREADS=4 python scripts/run_miplib_benchmark.py --worker-ours <mps> --time-limit 60 --threads 4` を
  `analysis/restart_cuts_fix_20261028/run.py` から呼ぶ。
- 結果・集計の道具・ログの抜き出しは `analysis/restart_cuts_fix_20261028/` に置いた (下の各節に対応するファイルを書く)。

## まとめ

- 4 スレッドで readd の経路を通るのは、負けている 21 問のうち **exp-1-500-5-5 と p200x1188c だけ** (ほかの 19 問は再スタートが
  ないか、もともと問題の行の経路)。試作の修正 1・2 はこの 2 問 (と readd・プールの経路を通る問題) にしか効かない。
- **p200x1188c で修正 3 が遅くなりうる理由**: カットを問題の行にすると、再スタートの前処理がその行の列を消せなくなる。
  readd のときは前処理で 1388 -> 266 行・非零 854 になるところ、問題の行で持ち込むと 1460 -> 947 行・非零 8846 (10 倍) に
  とどまり、その後の根の LP・分離・2 回目以降の再スタートがすべて大きい問題の上で回る (ログつきの 1 回は 4 回の再スタートで
  8.0 秒)。4 スレッドの計測では、修正 3 は既定より速かった (中央値 8.8 -> 3.9 秒) が、それは「捨てていた 61 本が残る」効果が
  上の損より大きかったため。
- **代わりの試作 `ENOMOTO_MIP_RESTART_CUTS_SUBST`** (前処理で消された列を含むカットを捨てずに、後処理の代入を通して写す) で、
  p200x1188c の 61 本は 61 本とも残り (以前は 0 本)、前処理も 1388 -> 266 行のまま。修正 3 は要らなくなる。
- **既定にする候補: 修正 1・2 + SUBST (修正 3 なし)**
  (`ENOMOTO_MIP_RESTART_CUTS_FIX=1 ENOMOTO_T_MIP_RESTART_CUTS_ROWS_FRAC=2 ENOMOTO_MIP_RESTART_CUTS_SUBST=1`)。
  - exp-1-500-5-5: 中央値 17.9 -> 8.8 秒 (7 回)。p200x1188c: 8.8 -> 3.6 秒 (7 回、試した組み合わせで最速)。
  - MIPLIB 40 問 (各 2 回): 解けた数 26 / 26 -> 26 / 26、SGM 21.88 / 21.01 -> 21.00 / 20.54 秒、目的値の不一致 0。
  - 手元 (16 スレッド) の負けている 21 問でも確かめてから採否を決めるのがよい (下の「残っていること」)。
- `ENOMOTO_MIP_RESTART_HCM_KEEP` (HiGHS 流のカット管理を再スタートの後も使う) は、exp-1-500-5-5 の 2 回目以降の再スタートも
  readd の経路にするが、時間は変わらず (8.8 -> 8.3 秒)、p200x1188c では遅くなった (3.6 -> 4.5 秒) ので候補にしない。

## 3. p200x1188c で修正 3 が遅くなりうる理由と、代入で写す試作

### 修正 3 で何が重くなるか

試作あり (修正 3 が働く) と SUBST (修正 3 なし、readd のまま代入で写す) のログつきの 1 回 (`log_excerpts/p200x1188c_{fix,subst}_diag_0.txt`):

| | 修正 3 (問題の行) | SUBST (readd + 代入で写す) | 既定 (readd、全部捨てる) |
|---|---|---|---|
| 1 回目の再スタート | 固定 384 列、72 本 | 固定 766 列、61 本 | 固定 766 列、61 本 |
| 再スタートの前処理 | 1460 -> **947** 行、自由な列 1992 -> 1448、非零 12922 -> **8846**、後処理 39 手 | 1388 -> **266** 行、1610 -> 419 列、非零 4752 -> **854**、47 手 | 同じ (1388 -> 266 行) |
| 持ち込んだカット | 問題の行 72 本 | カットの行 61 本 (写せたのは 61/61、以前の写し方では 0/61) | 0 本 (全部捨てる) |
| 再スタート後の根の LP の始め | 13961 | 13408 | 5679 |
| その後 | 再スタート 4 回 (前処理後 947 / 399 / 382 / 277 行) | 再スタート 3 回 (266 / 267 / 207 行) | 再スタートなし、木 401 ノード |
| 時間 | 8.0 秒 | 4.0 秒 | 8.5 秒 |

- 持ち込むカットは平均 113 非零 (72 本で 8170 非零。うち固定された列の項 2124) と密で、問題の行にすると、前処理はその行に
  出てくる列を代入で消せず、行も消せない。そのため前処理後の問題が readd のときの 3.6 倍の行・10 倍の非零になり、根の LP・
  分離・プロービングのすべてが大きい問題の上で回る。さらに次の再スタートもその問題から始まる (2 回目 1011 -> 399 行、
  readd なら 325 -> 267 行)。
- 一方で、捨てていた 61 本が残るので根の下界は上がる (13961 vs 5679)。4 スレッドの計測では下界の得が勝ったが、
  再スタートの時刻・固定の数は揺れるので (384 列か 766 列か)、行が増える損が大きい回もある。手元の 16 スレッドで遅いのは
  この損と考えられる (この機械では 16 スレッドを再現できないので確かめていない)。

### 試作: `ENOMOTO_MIP_RESTART_CUTS_SUBST` (カット 1 本ごとに後処理の代入を通して写す)

依頼にあった「カット 1 本ごとに問題の行かカットの行かを選ぶ」(前処理で置き換えられる列を含むカットだけ問題の行にする) は、
どの列が置き換えられるかが前処理をかけるまで分からず、問題の行にすればその列は置き換えられなくなる (上の損がそのまま残る)。
そこで、前処理をかけた後で、置き換えられた列を含むカットにも置き換えの式を代入して写すことにした (`src/mip/mod.rs` の
`map_restart_cut_subst`)。

- 前処理は列の番号を保ち、尺度 `x = d x'` を掛け、消した列の値を後処理の手順 (`PostsolveStep`) で決める。カットに `d` を
  掛けた後、手順をログの順に当てる (後処理は逆順に当てるので、前の手順の式に出てくる列は後の手順で決まる):
  - 代入 (`Sub`、`x_var = (rhs - Σ t_k x_k) / coeff`): 線形なのでそのまま代入する。
  - 平行列の併合 (`x_kept + s x_var` を `kept` に持つ): 消した列の係数が残した列の係数の `s` 倍のときだけ残した列に移す。
    それ以外 (と強制列) はカットを捨てる (式が線形でない)。
  - 最後に前処理後の問題で固定された列を右辺に移す。
- 写したカットは、前処理後の任意の実行可能解 x' について「元のカットを後処理で戻した解で評価したもの」と一致するので、
  元のカットが成り立つ限り成り立つ。診断 (`ENOMOTO_MIP_DEBUG_RESTART_CUT_USE`) では再スタート前の暫定解でこの一致を確かめて
  いて、p200x1188c・exp-1-500-5-5・neos-911970 の差は最大 6.7e-16、破れ 0。
- p200x1188c: 61/61 本が残る (以前の写し方 0/61)、再スタート後の根の LP 13408、前処理は 1388 -> 266 行のまま。
  exp-1-500-5-5: 356/358 本 (以前 344/358)。
- `ENOMOTO_MIP_RESTART_CUTS_SUBST` 単独ではなく、修正 1 (readd の印を渡す) と合わせて使う ((d))。修正 1 がないと、写した
  カットはプールに入るだけになる。

### 試作: `ENOMOTO_MIP_RESTART_HCM_KEEP`

1 節の exp-1-500-5-5 の 2 回目以降を readd にするため、前の求解が自動で選んだ HiGHS 流のカット管理 (`hcm_auto`) を新しい
求解の最初から使う。exp-1-500-5-5 は 4 回とも readd になり、再スタート後の問題は 550 -> 515 -> 456 -> 428 行と小さいまま
(試作ありでは 893 -> 845 行) だが、時間は (d) と変わらず、p200x1188c では 3.6 -> 4.5 秒と遅くなった (再スタート後の木の
カット管理も HiGHS 流になり、ノードが 1 -> 23)。候補にしない。

## 既定にする候補と根拠

候補: **`ENOMOTO_MIP_RESTART_CUTS_FIX` の修正 1・2 と `ENOMOTO_MIP_RESTART_CUTS_SUBST` を既定にし、修正 3 は使わない**
(`ENOMOTO_T_MIP_RESTART_CUTS_ROWS_FRAC` を外す)。

- 修正 1 は、前の求解が readd と決めたカットが新しい求解でプールに入るだけになる不具合を直すもので、exp-1-500-5-5 の
  根の LP が毎回 2.8e4 から作り直していたのを止める (4 スレッドで 17.9 -> 8.8 秒、手元 16 スレッドで 11.0 / 14.2 -> 5.5 / 6.8 秒)。
- 修正 3 は、前処理が列を置き換えるとカットが捨てられる問題を「カットを問題の行にして前処理に置き換えさせない」ことで避けて
  いたが、その分前処理が効かなくなる (p200x1188c で 947 行 vs 266 行)。SUBST は前処理を効かせたまま 61 本を全部写すので、
  p200x1188c は 4 スレッドで (c) 3.9 -> (d) 3.6 秒、揺れも小さい。readd の経路にとどまるので、カットは木の中で年齢で外せる。
- MIPLIB 40 問で悪くならない (26 / 26 問、SGM 21.88 / 21.01 -> 21.00 / 20.54、不一致 0)。readd・プールの経路を通らない問題では
  動作が変わらない (修正 1・2・SUBST はどれも、カットを問題の行にしない経路でしか働かない)。

### 残っていること (手元で決める前に)

- 手元 (16 スレッド) の負けている 21 問で (d) を 2 回測り、`benchmarks/loss21_earlyrc_20261027.jsonl` と比べる。
