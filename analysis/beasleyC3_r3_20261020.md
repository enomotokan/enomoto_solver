## 0. 要約

### 確かめた事実

1. **今の develop (TREE_SEP 入り) では、解けるかどうかは根の下界 (背景のカットの後) でほぼ決まる。** 全 58 回 (打ち切り値を
   与えた 4 回を除く) を背景のカットの後の根の下界で並べると、**744 以上の回はすべて解けた (14.8〜45.6 秒)**。742.6 未満の回は
   時間切れ・50 秒前後が集中する (表は §2)。根の下界は回ごとに 730.0〜748.9 と揺れる (HiGHS は 733.05)。
2. **根の下界の揺れは、時刻に依る 2 つの選択から来る。** 同じ選択の組なら根 (前景・背景のカットの後の値) は毎回同じになる。
   - (a) **対称性の検出の時間の上限 0.3 秒** (`ENOMOTO_T_MIP_SYM_TIME`)。beasleyC3 は全部で 773 個の生成元 (22 軌道 795 列、
     18 個の 1 行オービトープ + lex-leader 397 行) を 0.64 秒で見つけるが、0.3 秒では 190〜490 個 (1 軌道 191〜490 列、同じ数の
     lex-leader 行) で打ち切られる。数が回ごとに違い、それだけで根のカットの経過が変わる (既定の def_2 と def_4 は同じ 357 個で、
     前景のカットの 25 ラウンドが 1 本違わず一致した)。
   - (b) **根の LP の同時実行** (二段解法と内点法 + クロスオーバーの先に終わった方を採る、`TwoStageLp::solve_race`)。退化した LP で
     頂点が違う。対称性を全部見つけた (773 個) 上では、内点法側の頂点なら前景 720.16 → 背景 746.3〜746.6、二段解法側なら
     718.84 → 741.96 (毎回同じ値)。
   - 全部の対称性の上での結果: **内点法側 16 回中 16 回解けた (14.8〜30.3 秒)、二段解法側 14 回中 7 回 (34.9〜52.3 秒、残りは時間切れ)**。
     ほかに 714.58 → 744.20 の経路 (3 回、すべて解けた) と、p5s の下での 717.09 → 743.32 (1 回、解けた)。
3. **主側: 754 を見つけるのが遅い。** 根のヒューリスティクスの後の暫定解は 768〜787 (RENS・RINS・LP face のサブ MIP、根の LP は前景の
   カットの後の 706〜724)。756 以下を最初に見つけるのは 9.5〜58.7 秒 (木のヒューリスティクス: 他のスレッドの RINS・DINS・
   乱択丸め・木のノードの整数解)。HiGHS は根のサブ MIP (「L」) で 1.7〜1.8 秒に 756 を、木のノード (「T」) で 23.8〜24.2 秒に 754 を見つける。
   解けた回の時間は 754 を見つけた時刻 + 1.5〜23 秒。
4. **双対側は打ち切り値があれば足りる。** `ENOMOTO_MIP_CUTOFF=754.5` を与えると 4 回とも 15.6〜25.2 秒で解ける (根の下界 741.96 の
   回も 25.2 秒)。HiGHS は 26.1・26.5 秒・378 ノード (前の調査では打ち切り値を与えて 28.5 秒)。
5. 解けた回と解けない回で、前処理後の大きさ (1153 行・1704 列・3408 非零、HiGHS も同じ) と根の LP (237.99) は同じ。違うのは
   根のカットの後の下界と、754 を見つけた時刻。ノード数は解けた回 586〜2610、時間切れの回 1410〜2857 (時間に比例)。

### 推測

- 根の下界が高いと、木のヒューリスティクス (RINS・DINS・乱択丸めは木の LP 解を使う) が早く 754 に届き、届いた後の証明も短い。
  低い根 (741.96) では 754 の発見が 24〜59 秒 (届かない回もある)、届いた後の証明は 4〜23 秒。根の下界が主側の速さに効く
  仕組みそのものは確かめていない。
- 内点法側の頂点が良いのは beasleyC3 のこの対称性の組での偶然と見る (対称性の検出が途中で切れた既定の回では、内点法側の回も
  740.8〜745.4 とばらつく)。どちらの頂点が良いかを先に知る方法は見つけていない。

## 3. 試したこと

### 3.1 対称性の検出の上限の延長 (試作 `ENOMOTO_T_MIP_SYM_TIME_EXT`、既定では使わない)

`src/mip/symmetry.rs` の `detect`: 上限 `time_cap` (0.3 秒) に達した時点で、生成元が `ENOMOTO_T_MIP_SYM_EXT_MIN_GENS` (100) 個以上、
試した組の `ENOMOTO_T_MIP_SYM_EXT_RATE` (0.5) 以上で見つかっていれば、上限を `ENOMOTO_T_MIP_SYM_TIME_EXT` 秒に延ばす。延ばすときは
1 回の `search` の中の上限も延長後の値にする (0.3 秒をまたいだ探索が打ち切られて、772 / 773 個と回ごとに変わった)。

- beasleyC3 では毎回 773 個 (0.59〜0.68 秒) になり、対称性の側の揺れはなくなる。**しかし解けるかどうかは根の LP の頂点で決まり、
  ext・ext2・p5sext を合わせて 8/14** (既定 5/6・p5s 3/4 より良いとは言えない)。ext2 の 4 回はたまたま全部二段解法側で 1/4。
  既定にする候補ではない。
- 40 問で検出の結果が変わる問題 (`runs/bc3r3/symscan_def.txt` / `symscan_ext2.txt`): 10teams (168 → 394 個)・binkar10_1 (419 → 786)・
  graph20-20-1rand (137 → 256)・beasleyC3。最初の版 (生成元の数の下限なし) では 30n20b8・nw04・blp-ar98・h80x6320d も延びた。
- 最初の版の副作用 (4 スレッド・60 秒、各 2 回、既定 → 試作): nw04 11.4・10.4 → **26.0・25.7 秒**、h80x6320d 34.4・38.5 → **40.4・48.0 秒**、
  10teams 8.8・9.4 → 9.2・10.9 秒、binkar10_1 11.2・9.7 → 9.3・9.4 秒、30n20b8 (解なし)・blp-ar98・graph20-20-1rand は両方時間切れで
  下界・暫定解は揺れの範囲。nw04・h80x6320d は最後の版 (下限 100 個) では延びない (検出の行で確かめた。60 秒の計測はしていない)。

### 3.2 根の LP を内点法 + クロスオーバーの頂点にする (診断用 `ENOMOTO_MIP_ROOT_LP_IPM`、既定では使わない)

`src/simplex/mip_lp.rs` の `solve_race`: 二段解法が先に最適で終わっても内点法側の結果を待って採る。

- ext と組むと beasleyC3 の根が毎回同じ (前景 720.16・背景 746.3〜746.6) になり、**6/6 (17.6〜28.5 秒)**、p5s と組んで 2/2 (15.8・38.2 秒。
  2 回目は p5s の前処理の下で別の経路 717.09 → 743.32)。
- 副作用 (各 2 回、既定 → ext + ROOT_LP_IPM): **misc07 8.9・9.7 → 15.8・17.8 秒、binkar10_1 10.1・10.2 → 13.4・13.8 秒**、rout 8.9・10.5 →
  9.0・9.8 秒、neos-911970 21.6・38.6 → 22.6・24.7 秒。どちらの頂点が良いかは問題しだいで、既定にする理由はない。

### 3.3 主側 (根で 756 以下を見つける) — どれも決め手にならなかった

- `ENOMOTO_MIP_BG_CUTS_REHEUR=rins` (既存): 背景のカットの後の LP 解で RINS をもう一度。4 回中 3 回で暫定解が良くなるが
  762〜774 どまり (1.2〜2.0 秒)。4/4 解けたが 21.8〜54.5 秒。
- `ENOMOTO_MIP_BG_CUTS_REHEUR=rens` (試作、`src/mip/solver.rs` の背景のカットを置き換えた後): RENS も回す。758・763・765 (根の
  RENS の 771〜780 よりは良い) だが 756 には届かず、3 回中 2 回 (38.2・45.4 秒)。
- `ENOMOTO_MIP_RENS_DIVE=1 ENOMOTO_MIP_RINS_DIVE=1` (既存の HiGHS 流の潜り式): 根の暫定解 773〜780、3/3 解けたが 19.6〜45.6 秒。
- `ENOMOTO_MIP_BG_CUTS=heavy` (既存、背景のカットの停滞の判定を緩める): 二段解法側の頂点の根は 741.96 → 742.27・742.39 とほぼ
  上がらない。4/4 だが 24.8〜40.4 秒。
- HiGHS の 756 (根の「L」) がどのサブ MIP (RENS / RINS) から出るかは調べていない (scripts/highs_instrument.md の計測用パッチは当てていない)。

## 4. 結論と次の手

- 解けない主因 (4 スレッド、上の表):
  1. 根の下界 (背景のカットの後) が時刻に依る経路で 730〜749 に揺れ、低い回 (742 前後) は 754 の発見・証明とも遅い。揺れの源は
     対称性の検出の 0.3 秒の上限 (773 個中 190〜490 個) と根の LP の同時実行の頂点。全部の対称性の上で内点法側 16/16、二段解法側 7/14。
  2. 主側: 根のヒューリスティクスが 768〜787 しか出さず、756 以下は木のヒューリスティクス頼み (9.5〜58.7 秒)。HiGHS は 1.7 秒に 756。
     打ち切り値 754.5 を与えれば 4/4 が 15.6〜25.2 秒で解ける。
- 試作は既定の候補にしない。`ENOMOTO_T_MIP_SYM_TIME_EXT=1` は対称性の側の揺れを消すだけで、beasleyC3 の解ける割合は上がらない。
- 次の手:
  - 根で 756 以下を見つける力 (主側) を HiGHS と比べる。HiGHS の計測用パッチで「L」の 756 を出したサブ MIP の固定 (RENS か RINS か、
    固定率、ノード数) を取り、ENOMOTO の RENS (771〜780、自由な列 988〜1028) と比べる。
  - 根の頂点が良くない回を救う方向として、背景のカットが停滞した後に根の LP の頂点を変えてカットを続ける (別の頂点のカットを
    混ぜる) 案。試していない。
  - 時刻に依る選択 (対称性の上限・根の LP の同時実行・LP probing の打ち切り) を、作業量に依る上限にして再現できるようにすると、
    この種の調査がしやすい (beasleyC3 が解けるようになるわけではない)。
