# 前処理でまとめた行の向きをそろえる試作 `ENOMOTO_MIP_ROWNORM` (2026-11-06)

bench に使う環境変数: `ENOMOTO_MIP_ROWNORM=1` (試作、既定では使わない)。比べのために `ENOMOTO_MIP_HO3_SYMNORM=0` (既定の SYMNORM を止める) も使う。
すべて 4 スレッド (`ENOMOTO_MIP_THREADS=4`)、`ENOMOTO_MIP_LOG=1`。生データは `analysis/rownorm_20261106/`。

背景: `analysis/highs_only_20261105/G3.md` (fastxgemm-n2r6s0t2 の対称性の見落とし) と `analysis/symlp_default_20261106.md`
(検出に渡す写しだけ向きをそろえる `ENOMOTO_MIP_HO3_SYMNORM` を既定にした)。ここでは前処理の側で向きをそろえる。

## 1. まとめた行の向きはどう決まっているか (事実: コードを読んだもの)

- 整数最適化の前処理 (`presolve_mip_depth`、src/mip/mod.rs) は、元の行を `build_a_g_from_ranged_rows` で等式 (A) と `<=` の行 (G) に分ける。
  `>= l` の行は `-a x <= -l` (−1 倍) として G に入る。幅つきの行 `l <= a x <= u` も `-a x <= -l` と `a x <= u` の 2 本になる。
- 前処理 (`run_extended_mip`) の後、行は「等式 (pre.a の順)、次に `<=` の行 (pre.real_rows の順)」に並べ直され、
  `merge_parallel_rows` (src/mip/mod.rs) で係数が定数倍の行をまとめる。
  - 組の鍵は「行の最初の非零 (列の番号の最も小さい列) の係数で割った係数の並び」なので、鍵は行の向きによらない。
  - **残る行は、組の中で行の並びの先に来た行そのまま** (係数は書き換えず、左右辺だけをその行の倍率に合わせて戻す)。
    つまり向きは「先に来た行の向き」で、元が `<=` の行なら `a x` の向き、`>=` の行なら `-a x` の向きになる。
    列の順は鍵の正規化 (最初の非零で割る) にしか使われず、向きを決めるのは**行の順**。
- fastxgemm-n2r6s0t2 では `merged 1536 parallel rows (0 new equations)` (ログ)。G3.md の `-2 <= -a-b-c+d <= 2` 1151 本と
  `-2 <= -a+b+c+d <= 2` 385 本の合計 1536 と一致する。どちらの形になるかは、元の問題で `<= 2` と `>= -2` のどちらが先に書かれているか
  (と前処理の後の並び) で決まる (推測: MPS の行の並びを 1 本ずつ突き合わせてはいない)。
- 等式 (右辺 0 を含む) は向きをいじる所がなく、元の行の向きのまま。

## 2. 試作 `ENOMOTO_MIP_ROWNORM` (既定では使わない)

- 場所: `presolve_mip_depth` で前処理の結果の `MipProblem` を作った直後 (行をまとめた後、LP による固定・プロービング・かけ直しの前)。
  関数は `normalize_row_signs` (src/mip/mod.rs)。かけ直しの前処理もここを通るので、前処理が返す問題の行はそろっている
  (前処理が何も減らさず `None` を返すときは元の問題のまま)。再スタートの前処理も同じ関数を通る。
- 規則: 行ごとに (下限, 上限, 係数を小さい順に並べた列) と (−上限, −下限, −係数を並べた列) を辞書式に比べ、後の方が小さければ行を −1 倍する
  (SYMNORM と同じ規則、列の順・行の順によらない)。片側の `<=` の行 (下限 −inf) は動かない (−inf < −上限)。前処理の後に `>=` だけの行はない。
  - SYMNORM との違い: **−0.0 を 0.0 にそろえてから比べる**。SYMNORM は `f64::total_cmp` で比べるので、右辺 0 の等式は
    (0, 0) と (−0.0, −0.0) の比べで必ず「後の方が小さい」となり、係数によらず全部向き直される (向きはそろわない。事実: コードから)。
    fastxgemm では右辺 0 の等式が 144 本あり (下の 3 節の数から導いた)、ROWNORM はそのうち 72 本を係数で向き直す。
- 列の向き (列方向の表現 `cols`) も直す。2 回かけても変わらない (単体テスト `normalize_row_signs_is_orientation_independent`)。
- 後処理: 整数最適化の結果 (`MipResult`) は列の値・目的値・下界だけで、行の双対値は返さない。後処理の手順 (`PostsolveStep`) は列の値だけを
  戻し、行の活動値は元の問題で x から数える。行の −1 倍は実行可能な集合を変えないので、**後処理に足す手順はない** (事実: コードから)。
- 気を付けた所: LP による固定 (`lp_probe`) は根の基底を行の指紋 (`rows_fingerprint`) つきで渡す。向きを LP による固定の後にそろえると
  指紋が合わず行の状態が捨てられるので、LP による固定の前にそろえる。

## 3. fastxgemm-n2r6s0t2 での効き目

### 3.1 対称性の検出 (事実: ログ)

| 設定 | 前処理で向き直した行 | 検出の写しで SYMNORM が向き直した行 | 生成元 | 軌道 | 覆う列 | 検出の手間 (work) |
|---|---|---|---|---|---|---|
| 既定 (SYMNORM あり) | — | 529 / 4462 | 4 | 32 | 784 (全列) | 25246436 |
| SYMNORM=0 (G3.md の既定の前) | — | — | 1 | 120 | 360 | (G3.md) |
| ROWNORM (SYMNORM あり) | 457 / 4462 | 144 | 4 | 32 | 784 | 25246436 |
| **ROWNORM だけ (SYMNORM=0)** | 457 / 4462 | — | **4** | **32** | **784** | 25246436 |

- **ROWNORM だけで SYMNORM と同じ生成元 4 個・軌道 32 個 (全 784 列) が見つかる**。検出の手間の数 (work・search・verify) も 3 つの設定で同じ
  (検出から見て同じ形の問題になっている)。
- ROWNORM の後に SYMNORM が向き直す 144 本は右辺 0 の等式 (2 節の −0.0 の扱いの違い。ROWNORM が 0.0 にそろえた右辺を SYMNORM がすべて −0.0 にする)。
  全部そろって向き直されるので検出の結果は変わらない。
- 529 = 385 (幅つきの行) + 144 (右辺 0 の等式)、457 = 385 + 72 (右辺 0 の等式のうち係数で向き直したもの)。385 本は G3.md の
  `-2 <= -a+b+c+d <= 2` の本数と一致する (並べた係数が [−1, 1, 1, 1] の形を [−1, −1, −1, 1] の形にそろえた)。(導いた数。行を 1 本ずつは見ていない)
