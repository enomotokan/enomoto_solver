**不具合 (直した): qiu の s1wd 4 スレッドが 3 種とも `not_solved` を返した。**

- 目的値 -132.873136947 と下界の差は 1.5e-7〜3e-6 で、実際は解けている。
- 原因: STRICT=1 + WARM では、木の求解の終わり (`finish`) で返す解を研磨し、目的値が 3e-6 上がる。
  - 共有の最良値は研磨の前の値のまま残る。
  - そのため最後の守り (共有の最良値が返す解より良ければ最適と言わない、solver.rs) が働き、`NotSolved` になった。
  - STRICT=2 は木の中で研磨してから共有するので起きない。1 スレッドは共有の最良値がないので起きない。
- 直し: 研磨で上げた幅 `warm_raise` を引いて比べる (既定ではこの幅は 0 で、動きは変わらない)。
- 直した後に同じ機械で qiu の def_t4・s1wd_t4 を流し直した (`shards_qiufix.json`・`res_wd_qiufix.jsonl`)。
  - s1wd_t4: 19.68・17.62・15.05 秒、すべて最適。
  - 既定: 14.90・12.84・14.80 秒。
- qiu のこの 6 行を差し替えた集計は `summ_wd_fixed.txt`。
