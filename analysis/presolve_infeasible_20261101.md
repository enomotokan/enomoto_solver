## 1. 結論

1. **原因は伝播の「強制行」の規則の論理の誤り** (`src/presolve/propagate.rs` の `propagate_split`、等式の `propagate_equalities` も同じ形)。
   行 `a x <= b` の最小活動度 `L` が `b - PROPAGATE_EPS <= L` (1e-9) なら、全項を最小活動度側の端に固定して行を消していた。
   `L = b` (または `L > b` で許容誤差内の違反) なら正しいが、`L < b` で余裕 `δ = b - L` (≤ 1e-9) が残る行は強制行ではない:
   各項 j は端から `δ/|a_j|` まで動ける。端に固定すると実行可能な点を切り、係数 |a_j| が小さいと動かした量 `δ/|a_j|` が
   `PROPAGATE_EPS` を大きく越える。それが別の行にたまり、その行の実行不能の判定の許容誤差 (1e-9) を越えた。
2. h80x6320d の再スタート 2 の問題での道筋 (2 節): カットの行 `Σ_{9 本} x - 384 y <= 2e-9` (y は 0 に固定) で x の上限が 2e-9 になり、
   `-0.1 x_4048 + y_10368 <= 0`・`-0.1666 x_4054 + y_10374 <= 0` の最小活動度が -2e-10・-3.3e-10 (右辺 0 まで余裕あり) になる。
   これを強制行として x_4048・x_4054 を **上限 2e-9 に固定** し (HiGHS の解は 0)、次のパスでカットの行の最小活動度が 4e-9 > 2e-9 + 1e-9 となって実行不能とした。
   打ち切り値・目的関数の行・整数の丸め・双対による固定は関係しない (前処理の最初のラウンドの最初の伝播で起きている)。
3. **直し方**: 強制行とみなすのを、余裕 δ が丸め誤差の大きさ `FORCING_SLACK_REL * (1 + max(Σ|項|, |b|))` (1e-12、`src/params.rs`) 以下のときに限る
   (`forcing_reaches`)。余裕の残る行は境界の強化 (候補は正確) に任せる。この例では y の上限が 2e-10 → 整数の丸めで 0 になり、x の下限は 0 のまま。
   `ENOMOTO_T_FORCING_SLACK_REL=0` で従来の判定に戻せる (比べるためだけ)。LP の前処理 (同じ `propagate_split`・`propagate_equalities`) にも効く。
4. 確かめ (3・4 節):
   - 単体テスト 3 件を足した (不等式の伝播・等式の伝播・`run_extended_mip` の全体、同じ形を小さく組み立てたもの)。修正前の判定では 3 件とも失敗し、
     修正後は通る。`cargo test --release --lib` は 333 件 (330 + 3) 通過。
   - 再現の問題は 6382.09905 で最適 (35 秒、修正前は 0.03 秒で infeasible)。
   - h80x6320d を def・ns250s・n50・t10 で 3 回ずつ (12 回) 解き、全部 6382.09905。再スタート 2 に入った 8 回は、前処理が実行不能とせず、
     木を探して最適を示している。
   - 58 問 1 回 (修正後 def・修正前 old を交互に): **最適値の食い違い 0** (既知の最適値 `scripts/miplib2017-v31.solu` と相対 1e-4 で比べ、
     時間切れの暫定解が既知の最適値より良い問題もない)。SGM は def 13.46・old 13.59 (57 問、graph20-20-1rand は両方時間切れ)、解けた数 41・42。
     **元の問題の前処理の結果は 58 問すべてで修正前と同じ** (`MIP: presolve: rows` の最初の行が一致)。違いが出るのは再スタート後の前処理だけで、
     時間の差は h80x6320d (下) を除いて揺れの範囲 (bench8 の def の時間と比べて)。
   - 乱数の小さな問題で HiGHS と突き合わせ: LP 400 問 (`lp_fuzz_vs_highs.py`)・MIP 200 問 (`mip_fuzz_vs_highs.py`、`ENOMOTO_MIP_REL_GAP=1e-9`)・
     固定費のフロー 150 問 (`mip_fuzz_fixed_charge.py`) で、食い違い 0。
5. **過去の計測の誤った最適値** (5 節): bench7・bench8 (`halve_submip_20261030/`) の「最適」520 行には食い違いがない。
   ただし `restart_letters_20261031/res.jsonl` の h80x6320d に、試作の P_ch (6 回中 4 回)・P_cht (6 回中 3 回) が 6386.09905 を最適として返した回が
   7 回ある (22〜25 秒の速い回が全部それ)。`restart_letters_20261031.md` の「最適値の食い違い・crash はない」と、h80x6320d の P_ch・P_cht の時間 (22〜25 秒の回) は誤り。
6. **def の h80x6320d の速い回 (約 25 秒) は、この誤りによる近道だった** (3 節)。再スタート 2 に入る回は、修正前は再スタート 2 の解き直しが
   誤った実行不能で即座に終わり (暫定解がたまたま最適なので結果は正しい) 約 25 秒、修正後はそこで最適を示す木の探索が要り 41〜47 秒。
   再スタート 2 に入らない回は修正の前後とも 37〜47 秒。したがって h80x6320d の def の時間は、修正後は 25〜33 秒 (bench8) ではなく 40〜47 秒程度になる。
   これまでの記録の「h80x6320d の得」(`submip_nodes_20261101.md`・`diag_gain_20261031.md` など) の一部はこの近道に乗っていた可能性がある。

## 2. 原因の突き止め方

一時的な診断のビルド (コミットしていない) で、HiGHS の解 (6382.099) を前処理の各段の後の境界・行に代入し、どこで切られるかを見た。

1. 実行不能を返す 9 か所に印を入れた: 外側のラウンドの最初の伝播 (`propagate::propagate_split` が `infeasible`) だった (ラウンド 0)。
2. 伝播の入口では HiGHS の解は境界・行をすべて満たす (違反 0)。伝播の中で、HiGHS の解を切る境界の更新と強制行の固定を出した:

   ```
   forcing row cuts col 4054 x=0 -> 2e-9 pass=1 b=0 fsi=-3.33e-10 row=[(4054, -0.1666), (10374, 1.0)]
   forcing row cuts col 4048 x=0 -> 2e-9 pass=1 b=0 fsi=-2.0e-10  row=[(4048, -0.1), (10368, 1.0)]
   infeasible row pass=2 min_act=4e-9 b=2e-9 row=[(4041,1),(4043,1),(4048,1),(4051,1),(4054,1),(4082,1),(4084,1),(4090,1),(4097,1),(7555,-384)]
   ```

   行 `R365` (`Σx - 384 y_7555 <= 2e-9`) は引き継いだカット (右辺を 2e-9 緩めたもの)、y_7555 は 0 に固定。x は連続 [0, 384]、y は 0-1。
   パス 1 で R365 が x の上限を 2e-9 に締め、`R1110`・`R1104` (`-a x + y <= 0`) の最小活動度が -2e-10・-3.3e-10 となって強制行の判定 (≥ -1e-9) を通り、
   x を上限 2e-9 (負の係数なので最小活動度側は上限) に固定した。パス 2 で R365 の最小活動度 2 × 2e-9 = 4e-9 が右辺 2e-9 を 2e-9 越え、
   許容誤差 `1e-9 * (1 + max(Σ|項|, |b|))` ≈ 1e-9 を越えて実行不能。
3. 打ち切り値 6386.0990436 は再現に要らない (`check.py` は打ち切り値を渡さずに解いて infeasible だった)。
   `ENOMOTO_DBG_SKIP` の段を外しても同じだったのは、どの段より前の伝播で起きているため。
