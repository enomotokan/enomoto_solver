# 前処理の LP による固定 (lp_probe) をクリークの拡張の後へ移す試作 (`ENOMOTO_MIP_LP_PROBE_AFTER_EXT`)

日付: 2026-11-02。生データ・ログ・台本は `analysis/lp_probe_after_ext_20261102/` (表は `tables.md`)。

## 結論

- **既定は変えない。** 移す並べ方 (`=1`) は 58 問 2 回で SGM +9.4%、解けた数 87 → 80 と負けた。既定と同じ条件のときだけ基底を渡す値 `s` でも +2.7%、解けた数は 86。
- ねらいの「根の LP が短くなる・root_probe の特異で捨てる LP が減る」は**その通りになった**。
  - root_probe の特異で捨てる LP: 1 回あたり 8/12 → 0/57 (`s` なら 0/10)。
  - root_probe の反復: 33564 → 766。
  - 根の LP: neos-827175 8287 → 1 反復、neos-960392 7447 → 1、mzzv42z 6877 → 1、physiciansched6-2 6074 → 547。
- それでも全体の時間は縮まらない。理由は二つ。
  1. 根の頂点が変わる (同じ LP 最適値でも別の頂点になる)。分枝の木・カット・ヒューリスティクスの行き先が変わり、問題ごとに大きく振れる。今回の 58 問では負けの方が多かった (drayage-25-23 9 → 60 秒、mc11 35 → 60 秒、neos-960392 28 → 38〜60 秒、physiciansched6-2 26 → 60 秒など)。
  2. 根の LP が重い問題でも、その時間は並行の FJ と重なっていて、全体の時間をあまり決めていない (ns1116954、下記)。
- LP による固定は、新しい並べ方でも**増えなかった**。58 問で固定が出るのは最大 3 列で、拡張の後ではむしろ減った (下表)。このため (b) 前処理のかけ直し (値 `r`) は実装だけして、58 問では計らなかった。

## 何をしたか

### 試作 (`src/mip/mod.rs`、`src/mip/solver.rs`)

`ENOMOTO_MIP_LP_PROBE_AFTER_EXT` を立てたときだけ、次のように並べ方を変える。立てなければ今まで通り。

- **前処理の中:** `presolve_mip_depth` の中では `lp_probe` を飛ばす。
  - `quick_probe_fixings` と `FEAS_FJ_EARLY` は `lp_probe_secs.is_some()` の条件のまま、元の場所で動く。
- **拡張の後:** `solve_problem_inner` の中で、`extend_clique_rows` の後・対称性の行を足す前に `lp_probe` を呼ぶ。
  - 早い解があるとき (`early_sol`) は、既定と同じく呼ばない。
  - 実行不能なら、ROOT_* と START_SOL などを消して Infeasible を返す。
- **基底の受け渡し:** 基底 (列・行) は今まで通り `ROOT_BASIS`・`ROOT_BASIS_ROWS`・`ROOT_DSE` で根へ渡す。
  - 拡張の後の行で作るので、行の指紋と行の数が根の行と合う (ログ「行も」)。既定では拡張で行が書き換わるので、ほとんど「列だけ」になる。
  - 根 (root_probe) では、非基底の列・行が上限と下限のどちらにあるかも `set_basis_nb` で渡す。
    - 解から推し量る今までのやり方 (値 `k`) では、推し量りが外れて (NB_DIAG の sum_opp が 0 でない) 根の LP が長く残った。例: neos-827175 で 748 反復、neos-960392 で 2665 反復。
    - 置き場所を渡すと 1 反復になる。
- **値の文字:**
  - `k`: 置き場所を渡さず、推し量りのまま。
  - `s`: 基底を渡すのは既定と同じ条件 (固定が出た・根の LP が遅い) のときだけ。
  - `r`: 固定が出たら前処理をかけ直し (postsolve をつなぐ)、もう一度拡張して、固定なしの LP で基底を作り直す。
- **固定の扱い (a):** 固定が出ても、境界を固定するだけにする。前処理はかけ直さない。
- **NB_DIAG:** `ENOMOTO_MIP_BASIS_NB` の場所に `p` (root_probe) を足した (`src/simplex/mip_lp.rs` の説明も直した)。

`cargo test --release --lib`: 333 件成功・失敗 0 (18 件は ignored)。

- 条件: 4 スレッド・60 秒、`scripts/run_miplib_benchmark.py --worker-ours` で 1 問ずつ順に解いた (同時に動かすソルバーは一つ)。
- wheel: a7531eb7f のころのソースに試作を足して作った。base と各設定は同じ wheel で計った。計測の途中の rebase で入った他の変更 (pooldse・bgret など) は、wheel に入っていない。

ns1116954 で FJ_EARLY=0 の場合:

- 前処理の LP は重くなる (3225 反復・14.1 秒 → 4085 反復・13.7〜14.7 秒)。拡張で行と非零が増えるため。
- 根の LP は 3892 反復・11.7 秒 → 1 反復になる。
- それでも全体は速くならない。既定では根の LP の 12 秒が並行の FJ と重なっていて、解は FJ が見つけている。根の LP を縮めても、その分の時間は浮かない。
- 推し量りの `k` (extk_nofj) でも 35.5・35.1・35.6 秒。

FJ_EARLY が有効な ns1116954 は、早い解が見つかるので、どちらの並べ方でも LP による固定は走らない。

## 58 問 (2 回ずつ、analysis/cbcimpl_20261029/probs.py)

SGM はずらし 10 秒。解けなかった回は 60 秒として数えた。

| 設定 | 解けた (116 回中) | SGM | base との比 |
|---|---|---|---|
| base | 87 | 17.13 秒 | – |
| ext (=1) | 80 | 19.70 秒 | +9.4% |
| exts (=s) | 86 | 17.87 秒 | +2.7% |

NB_DIAG の合計 (1 回あたり):

| 設定 | root_probe の LP / 特異で捨てた LP / 反復 | restart の LP / 特異で捨てた LP |
|---|---|---|
| base | 12 / 8 / 33564 | 35〜36 / 31〜32 |
| ext | 57 / 0 / 766 | 34〜37 / 29〜32 |
| exts | 9〜10 / 0 / 555 | 35 / 31 |

restart の特異は変わらない。restart の基底はこの試作では扱っていない。

### ext (=1) の問題ごとの動き (2 回とも同じ向き)

- **負け:** 安い根の LP にも基底を渡すと、根の頂点が変わる。
  - drayage-25-23 9 → 60 秒、mc11 35 → 60 秒、swath1 27 → 42 秒、roll3000 38 → 57 秒。
  - neos-960392 28 → 38〜60 秒、physiciansched6-2 26 → 60 秒。
  - nw04 11 → 49 秒、noswot 10 → 33 秒、misc07 11 → 22 秒、qiu 25 → 37 秒。
- **勝ち:** nu25-pr12 4.1 → 1.4 秒、drayage-100-23 3.6 → 2.3 秒、exp-1-500-5-5 6.8 → 4.7 秒、neos-827175 5.6 → 3.6 秒、p200x1188c 4.3 → 2.9 秒など。

### exts (=s)

- 安い根の問題の負け (drayage-25-23・mc11・swath1 など) は消えた。基底を渡すのが既定と同じ問題だけになるため。
- 残った負けは neos-960392 (上限・39.6 秒) と physiciansched6-2 (上限×2)。どちらも根の LP が重い問題で、行まで合う基底を置き場所込みで渡すと根の LP は 1〜547 反復に縮む。それでも、そこから先の探索が既定より遅い (対象の 3 回でも同じ)。
- neos-827175 の勝ち (5.6 → 3.8 秒) は残った。
- noswot は基底を渡していない (ログ「なし」、固定 0、前処理の LP も同じ 81 反復) のに、ext と同じく負けた (10・9 → 37・27 秒)。lp_probe を呼ぶ場所が変わったことのほかの影響 (前処理の残りの段との順序など) と見られるが、原因はまだ調べていない。
- h80x6320d (45 → 34 秒) と neos-911970 (26 → 17 秒) は基底を渡していないのに速い。拡張の後の行で前処理の LP を解いた違いが、ほかに伝わっただけの揺れと見る。1 回の差では判断しない。

## 判断

- 根の LP を短くする仕掛け自体 (行まで合う基底と、置き場所の受け渡し) は動く。ただ、全体の時間への効き方は「根の頂点が変わる」揺れに負ける。既定にはしない。
- 根の LP が重い問題で根の時間を浮かせたいなら、別の方向を試すべきだと考える。今回の結果から候補を挙げる。
  - 頂点を変えないよう、根の LP の結果 (最適な基底) そのものを、既定の頂点に近いものに寄せる。
  - 並行の FJ と重なっていない問題に限る。
- 拡張の後でも LP による固定は増えないので、固定の数を増やす目的でこの並べ方を採る理由はない。
