# SEPLEARN: 分離器ごとの効き目の計測と、効き目で配分を変える試作 (2026-11-08)

bench に使う環境変数: `ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_THREADS=4 ENOMOTO_T_MIP_SEED=s` (s = 1, 2) に、設定ごとに
stat = `ENOMOTO_MIP_SEPSTAT=1` (計測だけ)、nozh = `ENOMOTO_MIP_NO_ZEROHALF=1`、sl = `ENOMOTO_MIP_SEPLEARN=1`。
名指しの 11 問は 150 秒、58 問 (`analysis/cbcimpl_20261029/probs.py`) は 60 秒。計測のスクリプトは `seplearn_20261108/bench.py`、表は `summ.py`。

## 結論 (先に)

- **計測 (`ENOMOTO_MIP_SEPSTAT`) はできた**: 分離器ごと・根と木に分けて、候補・LP に入れた本数・下界の伸びへの寄与 (|双対値| x 違反で按分)・
  3 LP 後の生き残り・時間を出す。58 問で根の伸びの最大は tableau (Gomory) 21 問・元の行 (CMIR・flow cover・cover) 18 問・HiGHS 版の経路集約 10 問、
  木では tableau 22 問・元の行 8 問。zerohalf が根の伸びの 20% 以上を出すのは 10teams・eil33-2・misc07・neos-860300・neos5 (表は下)。
- **学習の試作 (`ENOMOTO_MIP_SEPLEARN`) は既定に勝たない**: 58 問 (4 スレッド・60 秒、種 1・2) で v1 は SGM +4.5% (95% 区間 [-1.8%, +11.0%])・
  解けた数 85 → 81、問題ごとに遅い 16・速い 5 (p = 0.027)。根で飛ばさない控えめな v2 も +3.2% ([-3.2%, +10.9%])・85 → 82。既定では使わない。
- **zerohalf の害は局所の効き目では見えない**: zerohalf を外すと速い問題 (neos-860300・n2seq36q・wachplan・physiciansched6-2・ns1830653) のうち、
  学習で zerohalf を止めたのは physiciansched6-2 だけ (根の伸びの 0%)。neos-860300 では zerohalf が根の伸びの 22〜67%・ノードの伸びの約半分を出し、
  「効く」と測れるのに外した方が 2 倍速い (13・17 秒 対 32・30 秒)。n2seq36q でも zerohalf の伸びは 0% だが候補が少なく学習が止めても速くならない。
  害の元は伸びでなく、道の変化か LP の重さ (neos-860300 の zerohalf の候補は 1 本約 480 非零) と見られる (推測)。
- **zerohalf が効く問題では学習は既定のまま**: enlight_hard・hypothyroid-k1・mzzv42z・comp07-2idx で zerohalf を止めず、時間は既定と同じ程度 (表)。
  つまり「両方の良い方に寄る」のは physiciansched6-2 だけで、害の側の 4 問では既定のまま。
- **ノードの配分は変わる**: kasai ではノードで元の行・implbd・経路集約を 7000〜9800 回飛ばし (元の行のノードの時間 8.2 → 0.05 秒)、csched008 ではノードの
  zerohalf を 401 回飛ばした。150 秒の下界・解はどちらも既定と同程度かやや悪い (kasai は下界 984262・983459 → 982724・983089)。
  kasai で HiGHS が使っているノードの経路集約は、ENOMOTO ではノードで動いていない (始点 0) ので、配分の学習の対象にもならない。
- 誤答の検査: `fuzz_tiny.py 400 0` は SEPLEARN でも既定でも同じ 13 問 (前からの不一致、seed も同じ)、`mip_fuzz_vs_highs.py 300` は不一致 0。cargo test は下。
- 次の一手 (推測): 報酬を「下界の伸び」から「LP の反復・行の非零の増え (費用) を引いた伸び」か、短い先読み (ノードの数への効き) に変える。
  序盤の観測で切らない (misc07 は根の最初の 3 ラウンドで zerohalf の伸びが 0 と出て切り、根の下界が弱くなってノードが 3 倍)。
  ノードの経路集約 (kasai) のように、既定で止めている分離器を学習の候補に入れる。

## 2. 計測の仕組み (`ENOMOTO_MIP_SEPSTAT`、既定では使わない)

- `src/mip/seplearn.rs`。分離器 (sepprof の `SRC_*`。MODKVB・MUSHAGG は新しい `SRC_MODK` に分けた) ごとに、根とノードに分けて
  呼び出し・候補・LP に入った本数・伸びへの寄与・生き残り・分離の時間・仕事を数える。根のループの終わり (`SEPLEARN root ...`) と、
  木の探索のスレッドの終わり (`SEPLEARN tree tN ...`) に stderr へ出す。
- 伸びへの寄与: カットを加えてから次の LP を解いたときの目的値の伸び Δ を、加えたカット i の |y_i| x (加える前の点での違反 v_i) で按分する
  (一次の近似 Δ ≈ Σ y_i v_i)。打ち切り・実行不能なら Δ = 打ち切り値 - 加える前の値を違反で按分。根はラウンドの LP、ノードは解き直しの LP。
- 生き残り: 加えてから 3 回あとの LP (同じスレッドの LP の通し番号) で LP にあり |y| > 1e-9 の割合。
- 時間は separate() の段階の時計 (sepprof::lap) を分離器に対応させて数える (元の行の時間には CMIR・flow cover・cover がまとめて入る。分けていない)。
- 計測だけでは判断を変えない (sync_cut_age・row_duals を読むだけ)。

## 1. 調べ (文献・他のソルバー)

注: arxiv.org などに届かなかったので、論文の数値は抄録・二次要約による。ソルバーは GitHub の現行のソースを読んだ。

- **SCIP** (Achterberg 2007、sepa.c): 分離器ごとに priority・freq・maxbounddist・delay・expbackoff (SCIP 5.0 から、深さ/freq が 4 の冪のときだけ呼ぶ)。
  delay の分離器は他がカットを見つけなかったラウンドだけ呼ぶ。打ち切りは主に `maxstallroundsroot` = 10。`SCIPsepaGetNCutsApplied` などの統計は表示だけで、
  呼ぶかの判断には使わない (効き目によるオンラインの適応はない)。SCIP 8 でカット選択がプラグインになり既定は hybrid、SCIP 9 で ensemble (Turner) と
  dynamic を足したが既定ではない (Bestuzheva ほか 2021、Bolusani ほか 2024)。
- **CBC** (CbcModel・CbcCutGenerator): howOften の負の値 (-98 = 伸びている間、-99 = 根だけ、-100 = 止める)、`switchOffIfLessThan` (根の最初のパスで本数が少なければ止める)、
  根の終わりに「本数の 0.2 x 平均」より少ない生成器を √ 比で間引く (k + 1e6)、0 本は SCANCUTS (1000 ノード) ごとに様子見。serialCuts (ENOMOTO の SEP_ADAPTIVE が移植済み)。
  どれも本数と伸びで見て、分離器ごとの伸びへの寄与は見ない。
- **HiGHS** (HighsSeparation.cpp): 含意 → クリーク → tableau・path・mod-k → プールを固定の順で毎ラウンド全部呼ぶ。伸びが前のラウンドまでの 1.01 倍を超える間繰り返す。
  根は平滑化した進み・停滞 3 回・2√(log2 木の大きさ) ラウンドで止める。分離器ごとの適応はない (numCutsFound は数えるだけ)。
- **Turner, Koch, Serrano, Winkler 2023** (OJMO、Adaptive cut selection): SCIP のカット選択の重み (efficacy・dcd・isp・obp) を問題ごとに GCNN で予測。固定の規則はどれも外す問題の族が
  あることを示し、問題ごとの適応は大きく効くが 1 つの関数で表すのは難しいと結論。
- **Berthold, Francobaldi, Hendel 2022** (Learning to use local cuts): Xpress で局所カットを使うかを回帰森で問題ごとに決める (完全な予言で平均約 11% 速いのが上限)。
- **Tang, Agrawal, Faenza 2020**・**Paulus ほか 2022** (先読み: 1 本足したときの下界の伸びを expert に模倣)・**Huang ほか 2022** (カットの順位、生産計画で 12% 速い)・
  **Wang ほか 2023** (HEM、本数の比率と順序を RL で学ぶ): どれもカット 1 本ずつの選択を事前の学習で決める。
- **Li, Ouyang, Paulus, Wu 2023** (L2Sep、NeurIPS): どの分離器を使うかの構成を学び、求解の途中でも切り替える。SCIP 既定より合成問題で最大 72%、実問題で最大 37% 短い。
  分離器単位の配分にいちばん近いが、事前の学習が要る。
- **Chmiela, Gleixner, Lichocki, Pokutta 2023**: LNS・潜りのヒューリスティクスを bandit で配分 (難しい問題で約 4% 速い)。分離器に当てはめた bandit の研究は見つからなかった (未確認)。
- **Deza, Khalil 2023** (サーベイ)、**Balcan ほか 2021/2022** (カット選択の標本複雑度、未精査)。

示唆 (推測): 報酬は「採ったカットの |双対値| x 違反で下界の伸びを按分」、生き残りを遅れて届く補助の報酬に、費用は時刻でなく決定的な仕事 (非零の数・反復) で割る。
分離器は 10 前後なので ε-greedy か割引の UCB で足り、効かない分離器も止め切らずに指数的に間引いて試し直す (SCIP の expbackoff・CBC の SCANCUTS)。根と木は別の統計にする。


## 3. 学習の試作 (`ENOMOTO_MIP_SEPLEARN`、既定では使わない)

- 分離器ごとに 1 回の呼び出しの伸び・仕事 (決定的: 候補の非零の数 + 5 x LP に入れたカットの非零の数)・生き残りの指数移動平均 (α = 0.3) を根とノードで別に持つ。
  得点 = 0.5 x 伸び (最良で 1) + 0.3 x 伸び/仕事 (最良で 1) + 0.2 x 生き残り (最初の形の 伸び/仕事 だけだと、安い元の行が伸びの 7 割を出す zerohalf より上になった。enlight_hard のノード)。
- (a) 呼ぶか: 3 回の観測の後、得点 < 0.1 か「仕事の割合 > 3 x 得点の割合 + 0.05」なら飛ばす。飛ばす長さは 2 から倍々 (最大 16)、飛ばし終えたら 1 回試す (決定的な ε-greedy)。
  (b) 候補の上限: 得点 < 0.5 の分離器に、得点の割合 x 2 x 1 ラウンドの本数の上限 (最低 20) まで効き目の順に残す。
  (c) 時間の上限: 時刻は決定性を壊すので使わず、(a) の仕事の割合で代える (`=t` で時間を使う形もあるが試していない)。
- 根で学んだ値を木の探索の写し (`TreeSnapshot::sepl`) に引き継ぎ、スレッドごとにノードの観測で更新する。tableau 行 (Gomory) とプールは計測だけ (`g` で tableau にも上限)。
- v2 = `ENOMOTO_T_MIP_SEPLEARN_ROOT_SKIP=0` (根では飛ばさない) + `ENOMOTO_T_MIP_SEPLEARN_NODE_WARM=10` (ノードは引き継がず自分の観測 10 回まで飛ばさない)。
- 調整用の値: `ENOMOTO_T_MIP_SEPLEARN_{ALPHA,WARM,SKIP,WORKF,MAXSKIP,CAPMULT,CAPMIN,NOCAP,LPW,SURV_K}`。
