## 2. 試作 `ENOMOTO_MIP_ROOTPAR_PH=r` (既定オフ): カット前の LP 解の RENS をカットのループの前に並列のサブ MIP として出す

- 中身 (src/mip/solver.rs、`rootpar_ph`): heur の段で暫定解がないときに回す「RENS (LP before cuts)」(カット前の LP 解 x_root0 の RENS) を、
  2 スレッド以上の外側の根では、カットのループの前に並列のサブ MIP として出す (カットのループの CPU 2.12 本の空きで解かせる)。受け取りは今までどおり
  heur の段の待ち。出したときは heur の段では回さない。1 スレッドの動きは変えない (`mip_threads() > 1`)。`check_default` 6 問一致。
- 根の時間 (`res_diag4_r.jsonl`、37 問・4 スレッド・種 1、木に入る時刻): 和 425.2 → 509.9 秒、ずらした (1 秒) 幾何平均の比 **1.072 (悪い)**。
  大きく遅れたのは dano3_3 46.5 → 99.8・supportcase26 15.1 → 35.9・swath1 13.5 → 18.6・h80x6320d 18.7 → 23.7。速くなったのは mc11 6.4 → 5.2・
  mzzv42z 39.4 → 38.0・supportcase7 95.3 → 92.5 だけ。
- 30n20b8 種 1 では、早い RENS が 18 秒かかり、後の根の被約費用・LP face のサブ MIP と取り合って、木に入る時刻は 32.8 → 33.5 秒。
- 見立て: 既定では暫定解がある問題では「RENS (LP before cuts)」を回さない (多くの問題で FJ が暫定解を出している) ので、早く出すと仕事が増える。
  さらにカットのループの並列の分離 (表の行・経路集約) と CPU を取り合う。**採らない** (既定オフのまま残す)。
