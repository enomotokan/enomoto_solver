## 2. 試作 `ENOMOTO_MIP_ROOTPAR_PH=r` (既定オフ): カット前の LP 解の RENS をカットのループの前に並列のサブ MIP として出す

- 中身 (src/mip/solver.rs、`rootpar_ph`): heur の段で暫定解がないときに回す「RENS (LP before cuts)」(カット前の LP 解 x_root0 の RENS) を、
  2 スレッド以上の外側の根では、カットのループの前に並列のサブ MIP として出す (カットのループの CPU 2.12 本の空きで解かせる)。受け取りは今までどおり
  heur の段の待ち。出したときは heur の段では回さない。1 スレッドの動きは変えない (`mip_threads() > 1`)。`check_default` 6 問一致。
- 根の時間 (`res_diag4_r.jsonl`、37 問・4 スレッド・種 1、木に入る時刻): 和 425.2 → 509.9 秒、ずらした (1 秒) 幾何平均の比 **1.072 (悪い)**。
  大きく遅れたのは dano3_3 46.5 → 99.8・supportcase26 15.1 → 35.9・swath1 13.5 → 18.6・h80x6320d 18.7 → 23.7。速くなったのは mc11 6.4 → 5.2・
  mzzv42z 39.4 → 38.0・supportcase7 95.3 → 92.5 だけ。
- 30n20b8 種 1 では、早い RENS が 18 秒かかり、後の根の被約費用・LP face のサブ MIP と取り合って、木に入る時刻は 32.8 → 33.5 秒。
- 見立て: 既定では暫定解がある問題では「RENS (LP before cuts)」を回さない (多くの問題で FJ が暫定解を出している) ので、早く出すと仕事が増える。
  さらにカットのループの並列の分離 (表の行・経路集約) と CPU を取り合う。**採らない** (既定オフのまま残す)。

## 4. 研磨 (dano3_3 の重い LP) の切り分け (2026-11-26、親の依頼)

- カットの段の診断で、dano3_3 の根のカットのラウンド 1 が 17 秒かかっていた。中身は OBJPROBE の乱択丸めの解を受け取る所の重い LP。
- **重いのは乱択丸めではなく、暫定解を受け取るときの研磨** (`POLISH_STRICT=2` + `POLISH_WARM=d`、2026-11-25 に既定化):
  dano3_3 4 スレッド種 1 で、乱択丸めの 2 回目が既定 21.9 秒、`POLISH_STRICT=0` で 0.83 秒 (得た暫定解は 576.4163814249816 と ...785 でほぼ同じ)。
  丸めの中の連続部の LP (反復の上限 1000) と `resolve_continuous` (`INC_LP_CAP` の上限が FJ_P3 の既定で効く) は軽く、`NO_INC_LP` でも 22 秒のまま。
  この 20 秒でカットのループの時間の上限 (12 秒) を越え、ラウンド 1 から最少回数で止まっていた。
- OBJPROBE の乱択丸め (`objprobe_scan.py`・`res_objprobe4.jsonl`、37 問・4 スレッド・種 1): 351 回、解を見つけた 21 回はどれも暫定解を良くした。
  重いのは dano3_3 (17.6 秒、最初の暫定解) と supportcase7 (3 回・計 4.0 秒、なし) だけで、ほかは 1 回 0.05 秒未満。乱択丸めそのものは要る。
- 研磨を切った形の根の時間 (`res_diag4_nopolish.jsonl`): 37 問の木に入る時刻の和 425.2 → 399.0 秒。dano3_3 46.5 → 24.8、swath1 13.5 → 9.1、supportcase7 95.3 → 90.6。
- **27a8f25eb (研磨の LP を手間の期限で止めない直し) の前から**: 1 つ前の版 09cc2ad0e (別の worktree・venv) でも乱択丸めの 2 回目が 20.4 秒。
  OBJPROBE の乱択丸めは手間の期限の中で呼ばれていないので、直しの前後で変わらない。
- **なぜ 20 秒**: dano3_3 は整数が 69 列だけで、整数を固定した LP はほぼ元の LP のまま重い。整数を固定した LP (`dano_fixed.mps` を作って比べた) を
  HiGHS 1 スレッドで冷えた始動から: 前処理あり 13.6 秒・なし 29.0 秒 (32780・60006 反復)。当方 1 スレッドの冷えた始動 58.7 秒。
  木の中の研磨は B&B の基底から温めて約 20 秒 (5〜6 万反復)。研磨 (`polish_in_problem_warm`) は B&B の LP とは別に TwoStageLp を一から作り、
  カットの行の分の基底を捨てて直すので、基底の多くが崩れる (親・利用者の指摘)。
