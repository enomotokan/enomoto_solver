# momentum1 の根の LP が解けない・壊れる原因と直し (2026-11-06)

bench に使う環境変数: base = `ENOMOTO_MIP_ROOTLP_SCALE_RESCUE=0` (直す前の既定と同じ)、fix = `ENOMOTO_MIP_ROOTLP_SCALE=1`
(安全網 `ENOMOTO_MIP_ROOTLP_SCALE_RESCUE` は既定で入る)。どちらも `ENOMOTO_MIP_THREADS=4` (`--threads 4`)、調べの回は `ENOMOTO_MIP_LOG=1`。
新しいつまみ `ENOMOTO_T_MIP_ROOTLP_SCALE_MIN_M` (既定 10000)・`ENOMOTO_T_MIP_ROOTLP_SCALE_MIN_RANGE` (既定 1e4)・
`ENOMOTO_T_MIP_ROOTLP_RESCUE_MIN_RANGE` (既定 1e4) は既定値のまま。

生データは `analysis/momentum1_rootlp_20261106/` (`lp/` 書き出した根の LP、`lp_runs.jsonl` 単独の求解、`logs/`、`long.jsonl`・`sim.jsonl`・
`bench58.jsonl`)。走らせ方は `run1.py` (1 問)・`lp_set.py` (書き出した LP を HiGHS と LP の経路で)・`bench58.py`・`queue.sh`。

## 結論 (短く)

- **原因 (事実)**: MIP の根の LP (`TwoStageLp`) は行と列の尺度を調整しない。momentum1 の根の LP は係数の幅 7.9e9 (1.3e-9〜10) で、
  尺度なしの二段解法は基底なしでも 114 秒で終わらない。尺度を調整した写しで解くと 0.7 秒 (2369 反復)。LP の経路が 0.3〜0.5 秒で解けるのは
  LP の経路が尺度を調整するから (LP の前処理は要らない)。HiGHS も尺度を切ると 0.38 → 3.1 秒になり、目的値もずれる。
- **既定の MIP で競争も働かない理由 (事実)**: 前処理の LP による固定の最初の LP (3.3〜3.8 秒) が 1 秒を超えるので、その基底 (列だけ) が根の LP に
  渡される。基底があると根の LP は warm start で二段解法だけになり (`TwoStageLp::solve` の競争は基底のない求解だけ)、内点法との競争もなく
  600 秒回り続ける。combb の `ENOMOTO_SIMPLEX_SCALE` は基底のない求解だけに効くので、根の LP は尺度なしのまま (前向きの Harris で 14.6 秒)。
- **クリーク行の拡張 (事実)**: 拡張で行は 24303 → 20438、非零は 62369 → 84798。係数の幅は変わらない。拡張なしの根の LP は尺度なしでも 2.4 秒だが、
  根の下界は 79203 (拡張ありは 96247)。拡張した行が尺度の悪い LP を二段解法にとって難しくする (推測: 密な行が加わって基底の条件が悪くなる)。
- **直し**: (1) 試作 `ENOMOTO_MIP_ROOTLP_SCALE=1` (既定では使わない): 根の LP (最初・再スタートの後) と前処理の LP による固定の最初の LP を、
  基底があっても尺度を調整した写しで解く (基底は写しに渡す)。(2) 安全網 (**既定で入れた**、`ENOMOTO_MIP_ROOTLP_SCALE_RESCUE=0` で戻せる):
  根の LP が `Error`・`IterationLimit` で終わったら、内点法 + クロスオーバーの前に、尺度を調整した写しを基底なしの二段解法で解いて解き直す。

- **効き目と害 (事実)**: momentum1 (600 秒) は base が根の LP で時間切れ (下界も解もなし) → fix は根の LP 0.68 秒・ギャップ 81.7%。
  satellites2-40 は根の LP 80 → 0.19 秒 (300 秒の結果は同じ)。58 問 ×2 回では尺度の調整も安全網も一度も働かず (条件に当たる問題がない)、
  解けた数・時間の差は揺れ (6 節)。

## 1. 根の LP を書き出して単独で解く

`ENOMOTO_MIP_ROOTLP_SIMPLEX_DIAG=<prefix>` で最初の主の根の LP (前処理・LP による固定・クリーク行の拡張の後、カットの前) を書き出し
(`lp/mom_root.mps.gz`、20438 行 × 5174 列、非零 84798)、同じ診断で二段解法だけ (基底なし、1 スレッド) で解いた。書き出した LP は
`lp_set.py` で HiGHS (1 スレッド) と ENOMOTO の LP の経路 (`Model.solve`、LP の前処理と尺度の調整つき) で解いた (`lp_runs.jsonl`)。
目的値は定数 -0.5714 を除いた値 (MIP の値は 96246.84036)。

| 解き方 | 結果 | 秒 | 反復 |

| 同 + 尺度の調整 + 他の組み合わせ (combb など) | 最適 | 0.63〜0.66 | 2,369 |

- 事実: 尺度の調整だけで、前処理なしの MIP の根の LP が 0.7 秒で解ける。LP の前処理は要らない。LP の経路が速いのは尺度の調整のため。
- 事実: 尺度なしの HiGHS も 8 倍遅くなり、目的値が 0.39 (相対 4e-6) ずれる。この LP は尺度を調整しないと数値的に扱いにくい。
- 事実: 前向きの Harris は尺度なしでも 114 秒超 → 17.8 秒に縮める (比の判定が悪条件の基底へ入るのを防ぐ。`puriri_cutlp_20261106.md` と同じ向き) が、
  尺度の調整 (0.7 秒) には遠い。
- 事実 (`lpstats.txt`): 係数 1.3e-9〜9.98 (幅 7.9e9)、1e-4 未満の係数 3552 個。幅 0 < 幅 < 1e-6 の行は 0 本 (prr の問題にある 19 本は既定の
  問題にはない)、幅 < 1e-6 の列 233 本、固定列 2119 本。クリーク行の拡張は係数の幅を変えず、行を減らして非零を 22429 増やす。

## 2. 既定の MIP で根の LP が 600 秒終わらない理由

`logs/a_def_momentum1_0.log` (120 秒)・`analysis/combb_600_20261106/logs/momentum1_def_r*_600.log.gz` (600 秒):

1. 前処理の LP による固定 (`lp_probe`) の最初の LP (クリーク行の拡張の前の 24303 行) は、基底なしなので二段解法と内点法の競争で解かれ、
   二段解法が 3.3〜4.0 秒で勝つ (尺度なし、5656 反復)。
2. 最初の LP が 1 秒以上 (作業量 `ENOMOTO_T_MIP_PRESOLVE_WORK_LP_BASIS` 以上) なので、その基底 (列の状態だけ) を根の LP に渡す
   (`basis passed true`、`root LP basis from the presolve LP probing: used (columns only)`)。
3. 根の LP (クリーク行の拡張の後の 20438 行) は基底があるので `TwoStageLp::solve` の競争 (基底のない求解だけ) に入らず、尺度なしの二段解法だけで
   解かれる。基底なしでも 114 秒で終わらない LP なので、600 秒で 15 万反復回って時間切れ (`main 1 lps 154374 iters 594.82s`)。
   `ENOMOTO_T_MIP_LP_PROBE_BASIS_SECS=1e9` で基底を止めようとしたが、渡すかどうかは作業量でも判定するので基底は渡り、結果も同じだった。
4. combb (`ENOMOTO_SIMPLEX_SCALE` を含む) でも、尺度の調整は基底のない求解だけなので、最初の LP は 0.54 秒になるが基底が渡り
   (作業量の判定で)、根の LP は尺度なし + 前向きの Harris で 14.6 秒 (23,344 反復)。

## 3. prr (`ENOMOTO_MIP_PROBE_REPRESOLVE=1`) の `Error`

`logs/c_prr_momentum1_0.log` (安全網あり、60 秒): 根の LP は 20.5 秒・44,999 反復で `Error` (`prr_harm_20261106.md` 1 節と同じ)。
安全網が尺度を調整した写しを基底なしで解き (2668 反復 0.53 秒、元の尺度で warm start 193 反復)、`Optimal` (根の下界 96248.94) で続く。
直す前は内点法 + クロスオーバーの解き直しも `Error` で `not_solved` だった。

## 4. momentum1 (4 スレッド・600 秒、1 回ずつ、`long.jsonl`・`logs/long_*`)

| | base (直す前の既定) | fix (`ENOMOTO_MIP_ROOTLP_SCALE=1`) |
|---|---|---|
| 根の LP | 594 秒で時間切れ (15 万反復級) | **0.68 秒** (写し 2,364 反復 + 元の尺度で 5 反復) |
| 根のカットの後の下界 | なし | 96265.53 |
| 暫定解 | なし | 527462.86 (130 秒、vbounds (loose) のサブ MIP) |
| 結果 | 時間切れ、下界・解なし | 時間切れ、ギャップ 81.7%、107 ノード |

- 参考: combb の 600 秒 (`combb_600_20261106.md`) はギャップ 72.2% (根の LP 14.6 秒)、HiGHS は解なし。
- 事実 (fix のログ): 根の LP の後も遅い。根のカットのループは 4 秒で終わるが、根のヒューリスティクスの終わりが 283 秒: 内点の丸め 21 秒、
  feasibility pump 39 秒、潜り 3 種で 54 秒、並列のサブ MIP (RENS 94 秒で実行不能、根の被約費用 239 秒で 500 ノード打ち切り)。
  木のノードの LP は 1 回平均 5,125 反復 (102 回)。
- 推測: これらの LP (サブ MIP・潜り・ノード) もすべて尺度なしの `TwoStageLp` で、根の LP と同じく遅い。根の LP だけ尺度を調整しても
  MIP 全体は遅いままで、MIP の LP を尺度を調整した形で持つ (行と列の尺度を `TwoStageLp` の中に閉じ込める) 直しが次の手。今回は手を付けていない。

## 5. 似た問題 (4 スレッド・300 秒、1 回ずつ、`sim.jsonl`・`logs/sim_*`)

| 問題 | base 根の LP | fix 根の LP | base 結果 (解 / 下界) | fix 結果 (解 / 下界) |

| supportcase42 | 0.13 秒 (1 反復) | 0.09 秒 (1 反復) | 時間切れ 8.0 / 7.344 | 同じ |

| dano3_3 | 0.02 秒 (1) | 0.03 秒 (1) | 最適 120.8 秒 | 最適 107.7 秒 |
| satellites2-40 | 80.2 秒 (56209) | **0.19 秒 (2)** | 時間切れ 5 / -30 | 時間切れ 5 / -30 |

  fix でも何も変わらない。安全網 (`re-solved with the scaled`) はどの問題でも働いていない。
- 事実 (satellites2-40): base は LP 探りの最初の LP が 30 秒の上限で止まり、根の LP を基底なしで 80 秒かけて解く。fix は最初の LP を尺度を
  調整した写しで 7.0 秒 (10632 反復) で解き、根の LP はその基底から 2 反復。ただし 300 秒の結果 (解 5・下界 -30) は同じ。
- 事実 (uccase12): fix の最初の LP は写しが反復の上限 (20213 反復 1.6 秒) で止まり、尺度なしで続けて 7.4 秒 (base 7.8 秒)。根の LP は写しで 391 反復。
- 事実 (rail01): 尺度の調整は働いていない (係数の幅が小さい) のに fix が遅い。base は LP 探りの最初の LP が 30.00 秒の上限で止まり、
  fix は 29.10 秒で解き終わったので、その基底 (列だけ。行が変わったので行の状態は使わない) が根の LP に渡り、根の LP が 29.6 → 116.4 秒になった。
  推測: 時間の揺れによる差で、直しのせいではない。ただし「列だけの基底を渡すと根の LP が遅くなる」ことは momentum1 と同じ向きで、
  列だけの基底を渡す判定は別に見直す価値がある。
- 事実 (opm2-z10-s4): 根の LP は同じ (行 1 万未満)。解の差 (-27523 / -31681) はその後の揺れ。
