# 木の従を根の LP の最適面の上の別の頂点へ移す試作 (2026-10-22)

- 機械: 4 CPU の容器。ソルバーは同時に 1 つだけ。4 スレッド・60 秒 (一部 120 秒)、`ENOMOTO_MIP_TREE_DIAG=1`。
- 土台: `inv/diverse-vertex-20261022` の 013a1b4 (develop + 写しの基底の受け渡し、analysis/bound_inf_20261021.md §6・§7)。
  試作は 7e0cccc。スクリプト・ログは `analysis/diverse_vertex_20261022/` (`run_cfg.sh`・`summarize.py`・`batch{1,2,3}.sh`・`logs/`)。
- 背景: 写しの基底 (SNAP_BASIS) は 40 + 16 問で 2 回とも不採用。§7 の見立ては「従が主と同じ頂点から始めるので、
  (a) 根の被約費用による大域的な固定の違い (互いに教え合う) と (b) 根の LP 解の多様性が失われる」。

## 1. 結論

- **既定にする候補ではない** (60 秒の結果で既定より良いと言えない: 軽い 4 問 × 4 回で解けた数は既定 13/16、`dual` 12/16、
  `rand,lex,dual` 12/16。揺れの範囲)。試作は環境変数の下に残す (既定は不変)。
- **主の側 (頂点) を動かしても双対解はほとんど変わらない**。最適面の上で d を最適化すると従ごとに主と 100〜1000 列違う頂点に
  着くが、被約費用は主と同じままのことが多く (10teams・neos-911970・noswot で違い 0)、根の被約費用の固定の数も主と同じで、
  主・従が受け取る大域的な境界は 0。§7 の (a) は双対の側の多様性で、主の側を動かしても戻らない。
- **双対の側を動かす `dual` は (a) を戻す**: 非基底の変数の境界を乱数の幅で緩めて解き、戻して解き直すと、従の被約費用が主と
  数十〜数千列違い、受け取る大域的な境界は基底なしの解き直し (修正なし) と同じ程度に戻る (10teams 110〜670、neos-911970 53〜75。
  写しの基底では 0)。かかるのは軽い問題で 0.00〜0.06 秒、physiciansched6-2 で 1.1 秒、mzzv42z で 2〜4 秒 (基底なしの解き直しは
  13〜24 秒)。uccase12 では 5 秒の上限で打ち切り (元に戻す)。
- 基底なしの解き直し (修正なし) では、**従 3 本は互いに同じ頂点に着く** (同じ反復数・同じ距離。決定的)。修正なしの「多様性」は
  主と従の 2 通りだけだった。
- 下界はすべての回で最適値以下 (§4)。`cargo test --release --lib` (analysis/bound_inf_20261021.md §4 の組み方): 308 passed, 0 failed, 18 ignored。

## 2. 試作 (`ENOMOTO_MIP_TREE_DIVERSE_VERTEX=<rand|frac|far|none>[,lex][,dual]`、`src/mip/solver.rs`)

木の従 (写しの基底から根の LP を解いた直後、主と同じ頂点 x0・目的値 z*) で行う。指定すると写しには常に基底を持たせる。

- 主の側 (`Solver::diverse_vertex`): 従ごとの目的関数 d (種はスレッド番号と写しの番号)
  - `rand`: 整数列に [-1, 1] の乱数。`frac`: 分数値の整数列を乱数の向き (±1) へ、ほかは ±0.05 の乱数。
    `far`: 主の頂点で下限の列は上へ、上限の列は下へ、間は乱数の向き。
  - 最適面に制限する版 (既定): 被約費用が 0 でない非基底の列を今の値に固定し (相補性から最適面では動かない)、`c x <= z* + tol`
    の行を足して d を最小化、行と固定を外して c で解き直す。
  - `lex`: 制限せず、費用 `c + ε d` (ε = 1e-4 × max|c|、`ENOMOTO_T_MIP_DIVERSE_EPS`) で解いてから c で解き直す。
  - この LP は双対単体法しかない (`solve_primal` も双対単体法) ので、「目的値の変わらない主単体法のピボット」で c に戻すことは
    できない。最適面に制限する版では c に戻す双対単体法が重く、mzzv42z では 4.4 万反復・31 秒で時間切れ (元に戻した)。
    `lex` は c に戻すのが 1〜900 反復で済むので、以後は `lex` で比べた。
- 双対の側 (`dual`、`Solver::diverse_dual`): 非基底の変数・行の (有限の) 境界を幅 `ENOMOTO_T_MIP_DIVERSE_DELTA` (既定 1e-5) ×
  乱数 × (1 + |境界|) だけ緩めて解き (費用は同じなので今の基底は双対実行可能。双対単体法が退化した基底変数を出し、双対解が
  双対の最適面の上の乱数で決まる点へ動く)、境界を戻して解き直す (多くは 1 反復)。境界にある基底変数を締める版 (`tight`) は
  10teams・beasleyC3 で実行不能になり使えなかった。等式の右辺をずらすのも従属な等式で実行不能になるので既定では行わない
  (`eqshift`)。
- どの段も時間 (`ENOMOTO_T_MIP_DIVERSE_SECS`、既定 5 秒、残り時間の 2 割まで)・反復の上限があり、解けなければ元の状態に戻して
  解き直す。最後は必ず c で最適 (目的値は z* と 1e-6 相対で一致を確かめる)。
- 診断 (`ENOMOTO_MIP_TREE_DIAG`): 写しに主の LP 解・被約費用を入れ、従の根の行に「主の頂点と値の違う整数列・被約費用の違う整数列」、
  `diverse vertex`・`diverse dual`・`diverse DvMode` の行 (反復・秒・距離・双対の違い)、終わりに `tid k end: root reduced-cost
  tightenings N (candidates M), global bounds taken from other threads K` を出す。`set_row_bounds_many` を `MipLp` に足した。

## 5. 副作用・注意

- 最適面に制限する版は c に戻す双対単体法が重い問題で爆発する (mzzv42z 31 秒)。主単体法があれば「目的値の変わらないピボット」で
  安く戻せるはずだが、今の LP には主単体法がない。
- 上限 (5 秒) で打ち切った回はその時間が丸ごと損 (physiciansched6-2 の lex、uccase12 の dual、mzzv42z の dual 単独)。
- `dual` は全非基底の境界を緩めるので、大きい LP では退化した基底変数を出すピボットが多い (mzzv42z 8000〜11000 反復、uccase12
  1.4 万反復超)。緩める割合 (`ENOMOTO_T_MIP_DIVERSE_DUAL_FRAC`) を下げる余地はある (試していない)。
- 従 3 本の dual の双対解は互いに似る (緩めた LP の最適解が同じ近傍に集まる)。

## 6. 既定にする候補か

- 候補ではない。60 秒の軽い 4 問では解けた数が既定と同程度以下で、重い 3 問は 60 秒ではそもそも木にほとんど入らない。
- 残すとすれば `dual` だけを、根の LP が重い問題 (写しの基底を渡す問題) に限って、反復上限を問題の大きさに合わせて使う形。
  ただし重い問題で効果を測るには 60 秒では足りず (木に入らない)、120 秒以上・再スタートの扱いを含めた計測が要る。
- (a) の「互いに教え合う」効果は `dual` で数の上では戻るが、解ける数に表れないので、§7 の不採用の主因が (a) だという見立ては
  この計測からは支持されない (揺れが大きく、4 回ずつでは差を言えない)。
