## 1. 待ちの内訳 (事実)

決めてから再スタートまでに通る所 (solver.rs、根の終わり):
1. 根のヒューリスティクスの残り: 早めの再スタートが決まると `heur!` は残りを飛ばす (`skipped (early restart)`)。決めたヒューリスティクス自体
   (tbfp-network の clique 44 秒など) は決める前の時間。
2. 並列のサブ MIP の受け取り `join_submips(0)`: 既定は全部の終わりを待つ。tbfp-network は根の被約費用のサブ MIP・RENS (時間の上限が残り時間)
   を 190 秒待つ。`LOSE6_1_STOP` (既存) は 0.5 秒待ってから `SubmipCtl::abort` で止める。
3. 裏のカット (`BgCuts`): `BG_CUTS_DETERM` の待ち `wait_determ` (安全網は残りの 0.3 倍) の後、`finish` で止めの合図 (`job.stop`) を出して
   スレッドを join する。止めの合図はラウンドの始めでしか見ないので、回っているラウンド (tbfp-network は 1 ラウンド 10〜25 秒) の終わりまで待つ。
   `LOSE6_1_STOP=w` は待ちの上限を 2 秒にするが、この join の待ちは残る (tbfp-network の es の回で 25 秒)。
4. 置き換えた LP を解き直した後、裏のカットが手間の上限で終わったなら (`bg_end == "work"`)、主のカットのループとして続ける
   (`BG_CUTS_DETERM` の `c`、既定で使う)。tbfp-network の es の回で 59 秒、thor50dday の既定で 126 秒。再スタートの後の根でまたループを回すので、
   この続きは再スタートの前には要らない。

ログ (HILOSS の es の回、tbfp-network): 決定 163.1 秒 → サブ MIP を止めて受け取る 164.9 秒 → 裏のカットの待ち 2 秒 → join 26.7 秒 (191.8 秒)
→ 主のカットのループの続き 59 秒 → 再スタート 250.9 秒。

## 2. 試作 `ENOMOTO_MIP_ERWAIT` (src/mip/solver.rs・separation.rs、既定の経路は変えない)

値は文字の並び。外側の求解の早めの再スタート (`early_restart`) が決まった根でだけ働く。
- `s`: 走っている並列のサブ MIP に止めの合図を送る (`LOSE6_1_STOP` と同じ `abort_submips_after_grace`、0.5 秒待ってから)。止めたサブ MIP は
  時間切れとしてその時点の解を返し、主は受け取る (解は捨てない)。
- `b`: 裏のカットの待ちを 0 にし、`CutJob::halt` を立てる。裏のカットのスレッドは `cancel::with_halt` の中で回っているので、LP の反復
  (`slope_intercept_dual` の `halted()`) と zerohalf の分離がその場で止まる。止まった LP は最適でないので、ループは `st != Optimal` の道で
  そのラウンドのカットを外して抜け、結果 (`job.out`) を書かない。主は行を置き換えない (書かれていれば片側の行をカットプールに入れるだけ)。
  裏のカットが合図の前に自分で終わっていれば今まで通り置き換える。
- `k` (`b` と使う): 先に `ENOMOTO_T_MIP_ERWAIT_BGWAIT` 秒 (2) まで今まで通り待つ。まだ回っていれば止め、裏のカットのスレッドがラウンドごとに
  取っておいた最後の最適な LP のカットの行と基底 (`CutJob::last_ok`、`record_round` の直前で写す) で置き換える (LP は 1 反復ほどで解ける)。
- `c`: 4 の主のカットのループの続き (と試作 `MC11FIX2` の続き) を回さない。

正しさ: 裏のカットのラウンドの記録 (`record_round`、`bg_proved` の材料) は LP が最適になったラウンドの後だけなので、止めた LP の値で
下界を言うことはない。置き換えるカットの行は妥当な不等式で、置き換えた LP は主が解き直し、元より下がれば元に戻す既存の道を通る。
サブ MIP の止め方は既存の `abort` (時間切れの扱い) と同じ。

診断 `ENOMOTO_MIP_ERWAIT_DIAG=1`: `MIP: ERWAIT_DIAG: <区切り> +<決めてからの秒>s (<通しの秒>s)` を、サブ MIP の受け取りの後・裏のカットの前・
裏のカットの join の後・置き換え (と続き) の後・再スタートで出す。

## 6. 2 組目 (def 対 ewk) と判断

`cmp58_def_ewk.txt` (`cmp58.py def ewk "resk58_sh*.jsonl"`、4 分担、1 組目と同じ分け方。def も回し直したもの)。

- SGM 16.05 → 15.56 秒 (−3.1%)、対の比 95% 区間 [−7.2%, +1.2%]。揺れの大きい 12 問を除くと −1.6% [−4.7%, +0.7%]。

- 揃って遅い問題: なし。問題ごと 5% 超: 速い 10・遅い 5。根の下界・初めの解の時刻・時間切れのギャップのずれは 0 と区別できない。
- 矛盾 0、両方最適で値が違う 0、最大 RSS def 1920・ewk 1879 MB。
- h80x6320d は 3 回とも速い (56.4/52.2/時間切れ → 32.3/34.4/50.5 秒)。
- mc11 は揺れが大きい: 2 組の def 6 回は 48.4・36.0・14.8・時間切れ・32.8・16.8 秒、ewk は時間切れ・48.2・時間切れ (分担) と 59.3・37.2・15.7 秒 (手元)。
  手元の ewk 3 回は早めの再スタートが起きていない。`k` があっても早めの再スタートの回は裏のカットを 2 秒で止めるので、少し損をしている可能性は残る (推測)。
- 費用: `k` は裏のカットのスレッドがラウンドごとにカットの行と基底を写す (`ERWAIT` に `b` と `k` があるときだけ)。58 問で目立つ時間・メモリの増えはない。

判断 (取り込みの基準と照らす):
1. 区間の上限 +1.2% ≤ +5% — 満たす。
2. 解けた回 128 → 130 — 満たす。
3. 揃って遅い問題なし — 満たす (1 組目の 10teams は ERWAIT が働かない揺れ)。
4. 誤答 0 (fuzz_tiny 400・mip_fuzz_vs_highs 300)・矛盾 0・cargo test 通過 — 満たす。
5. 時間・メモリの余分な費用は小さい — 満たす。

→ `ENOMOTO_MIP_ERWAIT=sbkc` を次の束 (cand) の候補にする。600 秒でも tbfp-network (既定は時間切れ ×2) を解き、h80x6320d を約 1.5 倍速くする。
残る課題 (推測): mc11 のように裏のカットが長く効き続ける問題では、2 秒で止めると再スタートの固定が減る。待ちの上限を時間でなく
「裏のカットの伸びが続いているか」で決める形 (`wait_determ` を 1 ラウンドの重さで切る) にすれば、tbfp-network の 1 ラウンド 25 秒と
mc11・p200x1188c の速いラウンドを分けられる見込み。
