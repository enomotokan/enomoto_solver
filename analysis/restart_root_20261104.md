`res58.jsonl`・`run58.log` は 58 問の結果、`one.sh`・`run58.py`・`summ_log.py`・`summ_root.py`・`summ58.py` は回し方と集計)。

## 1. HiGHS の再スタート (v1.15.1 のソースを読んだ事実)

`highs/mip/HighsMipSolverData.cpp` (`performRestart`・`evaluateRootNode`)、`HighsCutPool.cpp`、`HighsNodeQueue.cpp`、`HighsMipSolver.cpp`:

1. **下界は持ち越す。** `performRestart` は `lower_bound` を目的の定数項の付け替えだけで残し、`evaluateRootNode` は
   `updateLowerBound(max(LP の値, lower_bound))` とする。**HiGHS のログの再スタートの後の下界は、再スタートの前の木の下界 (全体の下界) で、
   再スタートの後の根の LP の値ではない。** kasai の「970736 → 984177」は HiGHS の木の下界 (232 ノードと 1710 ノード) の比べで、
   再スタートの後の根が強くなった証拠ではない (tree_close1 の 7 章の書き方は誤解を招く)。HiGHS の再スタートの後の根の LP の本当の値は
   ログに出ない (計装した HiGHS を自前でビルドしたが、この環境では実行の許可が得られず測れていない)。
2. **カット**: 再スタートの時点の LP の行 (`getLp().getLp()`) を丸ごと前処理の模型にする (LP にあるカットは全て問題の行として前処理に
   かかる。`appendCutsToModel`)。カットのプールも持ち越し、再スタートの後の根の LP を解く前に**プールの全てのカット**を LP に加え
   (`separateLpCutsAfterRestart`)、解いてから効いていない行を外す (`removeObsoleteRows`)。衝突のプール・擬似費用 (`pscostinit`) も持ち越す。
3. **根のカットのループ**: 最初の根だけ回数の上限 `2 sqrt(maxTreeSizeLog2)` があり、再スタートの後は上限なし。止めるのは、進み (方向の
   内積の平滑値) が 1% 未満かつ下界の伸びが 0.1% 以下のラウンドが 3 回続いたとき、カットが 0 本のとき、固定が 10% を超えた (再スタート) とき。
4. **未処理のノードからの大域的な固定** (`HighsNodeQueue::pruneInfeasibleNodes`、木が待ち行列に戻るたび): 全ての未処理のノードで締まって
   いる列の境界を大域的な境界にする (ノードの境界の変更は伝播によるものも含む)。ENOMOTO にはこれに当たる処理が見当たらない (5 章の `f`)。

## 2. ENOMOTO の再スタート (既定の経路)

- `Solver::maybe_restart` は、既定ではカットを**問題の行**にする経路 (`cuts_as_rows`): 今の LP のカットの行のうち活動量が上限・下限に
  あるもの (効いているもの) だけを行にし、**カットのプールは持ち越さない** (`RESTART_CUTS` を渡すのはプールの経路と readd の経路だけ)。
- 根の再スタートでは今の LP = 根の終わりの LP なので、効いている行を全部残すと再スタートの後の根の LP は再スタートの前の根の終わりの値と
  同じになる (58 問の再スタートした問題は全てそう。h80x6320d: 6355.32 → 6355.32)。
- **木の中の再スタート (`TREE1_RESTART`) では、今の LP は最後に解いたノードの LP。** 効いているかをそのノードの LP の解で判定し、
  ノードで効いていない根のカットや年齢で外れた根のカットを落とす。そのため**再スタートの後の根の LP が再スタートの前の根の終わりより下がる**
  (表 3.1・3.2 の `t`。kasai 965982 → 965001、972264 → 969844。tree_close1 の trp600 でも 966866 → 965012)。
- 返す下界は `max(再スタートの後の求解の下界, この求解の根の下界)` で、**再スタートの時点の木の下界は捨てる。** 再スタートの後の求解が
  木を作り直して元の高さに戻る前に時間が切れると、木の中の再スタートの前より低い下界を返す。

## 5. 試作 `ENOMOTO_MIP_RESTART_ROOT_CUTS=文字` (既定では使わない、`src/mip/solver.rs`)

- `r`: 根の終わり (木に入る直前、`maybe_restart` の前) の LP で効いているカットの行を控え (`Solver::root_end_cuts`、`tight_cut_rows`)、
  木の中の再スタートで、今の LP で効いている行に無いものを問題の行として足す (readd の経路ならプールに渡すカットに足す)。
- `p`: カットを問題の行にする経路でも、カットのプールを新しい求解のプールに渡す (固定された列は代入して右辺に移す)。
- `l`: 木の中の再スタート (rebase の後は `ENOMOTO_MIP_TREE_RESTART` にまとめられた HiGHS 式の判定。`TREE1_RESTART=1` はその `force` の別名) を決めた時点 (従を止める前) の全体の下界 (`global_lower_bound` と潜りの子の下界の小さい方) を、
  再スタートの後の求解が返す下界の下限にする (HiGHS の `lower_bound` の持ち越しに当たる。返す値だけで、刈りには使わない)。
- `f`: 1 スレッドの木の中の再スタートで、未処理のノード (手元の待ち行列と潜りの子) の分枝の境界が全てのノードで大域的な境界より締まっている
  整数列は、その中で最も緩い境界まで大域的な境界を締める (`Solver::tighten_by_open_nodes`、HiGHS の `pruneInfeasibleNodes` の弱い形。
  ENOMOTO のノードは分枝の変更だけを持ち、伝播による境界は持たない)。kasai・swath3 の 1 スレッドの再スタートでは締まる列が **0 本**
  (2065〜5441 ノード)。4 スレッドでは従の手元のノードが合流のときに失われるので使えない。
- `1` は `r`・`p`・`l` (`f` は入れない)。

## 6. まとめ

- 差の原因 (事実):
  1. HiGHS のログの再スタートの後の下界は持ち越した木の下界で、根の LP の値ではない。「HiGHS は再スタートの後の根が 984177 まで上がる」は
     ログの読み違い。HiGHS の再スタートの後の根の本当の値は測れていない。
  2. ENOMOTO の木の中の再スタートは、最後のノードの LP で効いているカットしか持ち込まないので、再スタートの後の根の LP が前の根の終わりより
     下がる (kasai 965982 → 965001・972264 → 969844)。根の再スタートではこの損はない。
  3. ENOMOTO は再スタートの時点の木の下界を返す下界に残さない (HiGHS は残す)。
  4. HiGHS は再スタートでカットのプールと LP のカットを全部持ち込み、再スタートの後のカットのループに回数の上限がない。
- 推測: 木の中の再スタートの後の HiGHS の伸びの速さは、根の強さより、固定の多さ (swath3 で二値 1351 → 41、前処理で行・列が減る) と
  木の強さによる。kasai では HiGHS も ENOMOTO も新たな固定はほぼ 0 で、根を少し上げても木の下界 (約 1.2 万上) には届かない。
- 試作の効き目: `r` で再スタートの後の根が上がる (kasai の最後の根 972850 → 975770、swath3 +0.84)、`l` で木の中の再スタートの後に
  返す下界が下がらない (kasai 600 秒 986426 → 987010)。解けるまでの時間 (swath3 395.9 → 465.7 秒) と 58 問 (43 → 44 解けた、
  SGM 16.43 → 16.78 秒) は揺れの範囲。`f` は 0 本で効かない。既定は変えない。
- 次: 木の中の再スタートを使うなら `r` と `l` は入れるのが筋 (損の理由がない: `r` は根の LP を失わない、`l` は正しい下界を返す)。
  セッション 1 の木の中の再スタートのまとめに合わせて決める。固定の多さの差 (HiGHS の木の中の大域的な固定の源: 衝突・伝播を含む
  ノードの境界) は分けて調べていない。
- テスト: `cargo test --release --lib` は 338 通過・0 失敗・18 ignore (`cargo_test.log`、rebase の前)。rebase の後は 339 通過・0 失敗・18 ignore。
- 計測のビルドは b6299242 + この記録の変更 (rebase の前)。rebase で入ったセッション 1 の木の中の再スタートのまとめ (`ENOMOTO_MIP_TREE_RESTART`) などは計測に入っていない。
