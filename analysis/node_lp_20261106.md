## 足したもの (既定の動きは変えない)

- 診断 `ENOMOTO_MIP_NODELP_DIAG=1`: ノードの LP 1 回ごとに、双対単体法の中で [warm start か, 出発の主実行不能の行の数, warm start で費用を
  ずらした列の数 (出発の基底の双対実行不能), 再分解の回数, DSE 重みの種類 (単位・引き継ぎ・厳密), 段階 A から始めたか, 段階 A の反復, 費用の摂動] を
  記録し (`slope_intercept_dual.rs` の `NODELP_REC`)、木の側 (`solver.rs`) でスレッドごと・種類ごと (潜りの子・兄弟・自分の待ち行列・共有の待ち行列・
  同じノードでの解き直し) に、回数・反復・秒・LP の行・カットの行と合わせて足し、終わりに `MIP: nodelp tid <t> <種類>: ...` を出す。
- 診断 `ENOMOTO_MIP_NODELP_DUMP=<dir>`: 主 (tid 0) のノードの最初の LP を `ENOMOTO_T_MIP_NODELP_DUMP_EVERY` (既定 50) 回に 1 回、
  `ENOMOTO_T_MIP_NODELP_DUMP_MAX` (既定 30) 個まで、解く前の LP・出発の基底・直近の解・DSE 重みを `dump_lp` の形式で書き出し、
  木の中での結果を `<dir>/index.txt` に足す。解き直しは `cut_lp_debug` テスト (ENOMOTO) と `highs_warm.py` (HiGHS、同じ基底から)。
- HiGHS 1.15.1 の計装 (`highs_nodelp.patch`、`HIGHS_NODELP=1` で `evaluateNode` の LP 1 回ごとに `NLP` の行: 深さ・反復・LP の行・元の行・秒・状態・
  サブ MIP か・ヒューリスティクスの潜りか・境界の固定の後の解き直しか (`rec`)・待ち行列や兄弟から基底を戻した直後か (`restored`))。
  `git clone --depth 1 --branch v1.15.1 https://github.com/ERGO-Code/HiGHS`、`git apply highs_nodelp.patch`、
  `cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DFAST_BUILD=ON .. && ninja highs-bin`。`run_highs.sh <問題> <秒>` (threads=4・mip_rel_gap=0)。
