bench に使う環境変数: `ENOMOTO_MIP_THREADS=4` (全部の回)、計数の回は `ENOMOTO_MIP_NODELP_DIAG=1`、書き出しの回は
`ENOMOTO_MIP_NODELP_DUMP=<dir>`・`ENOMOTO_T_MIP_NODELP_DUMP_EVERY=100` (traininstance6 は 200)、試作の回は `ENOMOTO_MIP_NODELP_PERTURB=<値>`、
比べの回は `ENOMOTO_MIP_BASIS_NB=t`・`ENOMOTO_MIP_CHILD_HIGHS=1`・`ENOMOTO_MIP_PROBE_REPRESOLVE=1`。

生データ: `analysis/node_lp_20261106/` (台本・ログ・書き出した LP の一覧 `dumps/<問題>/index.txt`。LP 本体 (.mps/.bas) は大きいので置いていない。
同じ環境変数で同じものが出る)。

## 1. 足したもの (既定の動きは変えない)

- 診断 `ENOMOTO_MIP_NODELP_DIAG=1`: ノードの LP 1 回ごとに、双対単体法の中で [warm start か, 出発の主実行不能の行の数, warm start で費用を
  ずらした列の数 (出発の基底の双対実行不能), 再分解の回数, DSE 重みの種類 (単位・引き継ぎ・厳密), 段階 A から始めたか, 段階 A の反復, 費用の摂動] を
  記録し (`slope_intercept_dual.rs` の `NODELP_REC`)、木の側 (`solver.rs`) でスレッドごと・種類ごと (潜りの子 `dive`・潜りの途中で兄弟へ戻った
  ノード `sibling`・自分の待ち行列 `queue`・共有の待ち行列 `pool`・同じノードでの解き直し `resolve`) に、回数・反復・秒・LP の行・カットの行と
  合わせて足し、終わりに `MIP: nodelp tid <t> <種類>: ...` を出す (最初の回 `dump` の計数では兄弟は `dive` に入っている)。
- 診断 `ENOMOTO_MIP_NODELP_DUMP=<dir>`: 主 (tid 0) のノードの最初の LP を `ENOMOTO_T_MIP_NODELP_DUMP_EVERY` (既定 50) 回に 1 回、
  `ENOMOTO_T_MIP_NODELP_DUMP_MAX` (既定 30) 個まで、解く前の LP・出発の基底・直近の解・DSE 重みを `dump_lp` の形式で書き出し、
  木の中での結果を `<dir>/index.txt` に足す。解き直しは `cut_lp_debug` テスト (ENOMOTO、`cmp_dumps.py`) と `highs_warm.py` (HiGHS、同じ基底から、
  非基底の置き場所は直近の解から。1 スレッド・前処理なし・双対単体法)。
- HiGHS 1.15.1 の計装 (`highs_nodelp.patch`、`HIGHS_NODELP=1` で `HighsSearch::evaluateNode` の LP 1 回ごとに `NLP` の行: 深さ・反復・LP の行・
  元の行・秒・状態・サブ MIP か・ヒューリスティクスの潜りか (`heur`)・被約費用などで境界が変わった後の同じノードの解き直しか (`rec`)・
  待ち行列や兄弟から基底を戻した直後か (`restored`))。`git clone --depth 1 --branch v1.15.1 https://github.com/ERGO-Code/HiGHS`、
  `git apply highs_nodelp.patch`、`cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DFAST_BUILD=ON .. && ninja highs-bin`。
  `run_highs.sh <問題> <秒>` (threads=4・mip_rel_gap=0)、要約 `nlp_summ.py`・`highs_restored.py`。
- 試作 `ENOMOTO_MIP_NODELP_PERTURB=<文字>` (既定では使わない): 木のノードの LP (同じノードでの解き直しを含む。強分枝・ヒューリスティクスの LP は
  含めない) を解くあいだだけ、`p` = 費用の摂動 (既存の `ENOMOTO_NODE_PERTURB` と同じ処理・同じ判定: 構造列の費用の絶対値の種類 x 4 <= 列の数)、
  `P` = 判定なしで摂動、`h` = 前向きの Harris (`ENOMOTO_SIMPLEX_HARRIS2=t` と同じ)、`g` = このスレッドのノードの LP の平均の反復が
  `ENOMOTO_T_MIP_NODELP_HEAVY` (既定 100) 以上のときだけ。スレッド局所の印 (`NODE_PERTURB_SCOPE`・`Harris2Scope`) で置き、解き終わったら戻す。

### 2.3 兄弟・待ち行列のノードの出発の点 (コードで確かめたこと)

- ノードの基底を戻す既定の `TwoStageLp::set_basis` は、基底に入る列の集合だけを使う。非基底の列を下限・上限のどちらに置くかは warm start
  (`warm_start_basis`) が被約費用の符号で決め、被約費用がほぼ 0 (|d| <= 1e-7 (1 + |c|)) の列だけ「直前に解いた LP の解 x からの推し量り」(`nb_hint`) に従う。
  兄弟・待ち行列のノードでは直前の LP は別のノード (潜りの深い葉など) なので、双対退化の強い問題 (0-1 の分割・被覆) では被約費用 0 の列の
  置き場所が保存した基底と食い違い、出発の主実行不能が増える (推測。兄弟 69 行・待ち行列 500 行という数と合う)。
  HiGHS は保存した基底の非基底の向き (`nonbasicMove`) もそのまま戻す。
- 保存した置き場所を使う既存の試作 `ENOMOTO_MIP_BASIS_NB=t` (analysis/basis_nb_20261102.md) は 12 問で揺れの範囲だった。今回の重い問題で計数を見る (4 節)。
- 潜りの子の向き: ENOMOTO は「擬似費用 x 端数の小さい側」(目的値の伸びの見込みの小さい側)、HiGHS は「(1 + 推論の平均) / 擬似費用の大きい側」
  (`ENOMOTO_MIP_CHILD_HIGHS` で同じにできる)。
