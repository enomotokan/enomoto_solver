利用者の問い: 「INTSING と列の支配のように、判定を同時にできる (順番で結果が変わる) 前処理は他にあるか。判定の並列実行もできるのでは」。

(`solve_portfolio`・`solve_problem_inner`・`presolve_mip_depth`・`probe`・`dominated_binary_fixings`)。

## まとめ (結論を先に)

- **順番で結果が変わる組は多い (事実)**。縮約の本体の段はどれも「境界・費用・行」のどれかを読み、どれかを書き換える。8 組を 3 章に挙げた。

- **並べる意味があるとすれば「速さ」より「結果が順番によらないこと」(推測)**: 同じ写しで判定して決まった順に当てると、スレッドの数・行列の並びに

  試作 `ENOMOTO_MIP_ORDINV`)。ただし 1 ラウンドに当てられる縮小が減り、ラウンドが増える。
- **勧め (推測)**: 縮約の本体の PaPILO 化は手間 (各段を「提案」と「当て」に分け、錠を付ける。2〜3 週の規模) に対して速さの得が 0.15% 以下なので、
  やらない。順番の問題は、効いている組 (INTSING → 列の支配など) ごとに「どちらを先にするか」を計測で決める方が安い (3 章の表の「勧める順」)。

  どちらも PaPILO の方式ではなく段の中の並列化の話 (4.3 節)。

## 2. 「順番で結果が変わる」とは

段 A が書き換えるもの (境界・費用・係数・行の有無) を段 B が判定に使うなら、A → B と B → A で結果が違いうる。違い方は 3 つ:

1. **両方当てられるが量が違う** (例: 境界の締め → 係数の強化。締めた後の方が強化が大きい)。順番は「どちらを先にすると縮小が多いか」の問題で、
   どちらの順でも正しい。不動点まで回せば差は小さくなるが、当方は回数に上限がある (ラウンド・かけ直しの回数)。
2. **片方を当てると他方が成り立たなくなる** (例: 支配の組 y_j ≻ y_k と y_k ≻ y_j が両方成り立つ同じ列の組。片方ずつなら正しいが、同じ写しの判定を
   両方当てると両方 0 になり最適解を失う)。同じ写しで並べて判定する形では、衝突を見つけて片方を捨てる必要がある (PaPILO の錠)。
3. **書き換えが判定の前提を壊す** (例: 列の代入が行の係数を変え、別の段がその行の古い係数で判定した結果を当てると誤る)。これも錠で防ぐ。

当方の逐次の流れでは 2・3 は起きない (各段が最新の問題で判定する。`dominated_binary_fixings` は「固定した列を含む組は使わない」で 1 段の中の 2 も防いでいる)。
1 は起きていて、順番は経験的に決めてある (HiGHS の順にならったものが多い。「集約は singleton/doubleton の後」「平行な列は集約の直後」など)。

## 4. PaPILO の方式を当方に入れる場合の見通し

### 4.1 PaPILO の方式 (要点、論文と公開の説明による理解)

各ラウンドで、前処理器 (presolver) を同じ問題の写しに対して並べて走らせ、それぞれが縮小の「取引」(transaction: 境界の変更・列の代入・行の削除など) の
列を作る。取引は、読んだ・書く行と列に「錠」を付ける。全部の前処理器が終わったら、決まった順 (前処理器の順、その中は作った順) に取引を当て、
このラウンドで既に書き換わった行・列に錠のかかった取引は捨てる (次のラウンドで最新の問題から作り直される)。前処理器は手間で fast・medium・
exhaustive に分け、安いものから回す。結果はスレッドの数によらない。

### 4.2 当方の縮約の本体に入れる場合

- **並べられる段 (推測)**: 5.4 双対の固定・5.5 スラック列・5.7 行シングルトン・2 項等式・列シングルトン・5.8 集約 (候補の判定まで)・5.9 平行な列・
  5.10 重複行は、どれも「今の行列と境界を読んで縮小の候補を出す」部分と「当てる」部分に分けられる。5.1 伝播は行ごとに独立に締めを出せる (PaPILO も
  伝播は 1 つの前処理器)。
- **手間 (推測)**: 大きい。今の各段は行列 (`FaerCsr`) と分離形式の G (`cur_real_rows`) をその場で書き換え、後処理の手順を積む。並べるには
  (1) 各段を「提案」(取引の列を返す) と「当て」に分ける、(2) 取引ごとに錠 (読んだ行・列、書く行・列) を付ける、(3) 当てる側で錠を確かめる、
  (4) 後処理の手順の順を当てた順にそろえる、が要る。集約・2 項等式は他の行の係数を書き換えるので錠が広い。8 段 + 伝播で 2〜3 週の規模と見る。
- **得の上限 (事実)**: 5 章の通り縮約の本体は全体の 0.15% (58 問)。11-07 の Mittelmann 186 問 (600 秒) でも縮約の本体とかけ直しは前処理の 2% 弱
  (25.7 + 4.3 秒 / 1446 秒)、全体 76389 秒の 0.04%。最大は snp-02-004-104 の 12.5 秒 (600 秒中) で、これは 1 問の縮約の本体が長い特別な例。
- 結論: 速さのためには入れない。決定性・順番によらないことのためなら意味はあるが、当方の縮約の本体は既に 1 本で決定的なので、得は「行列の並びに
  よらない」だけで、それは `ORDINV` の鍵の方が安い。
