## 1. 試作の中身

### 1.1 HiGHS の扱い (ソースで確かめた事実、v1.11.0 の `highs/mip/`)

- 変数上下限は `HighsImplications` の `vubs`/`vlbs` (列ごと、相手は 0-1 列だけ、`w ≤ coef·z + constant`)。入るのはプロービングの含意
  (`z = v ⇒ w ≤ b` から `addVUB(w, z, b - ub, ub)` など、一般整数列も含む) で、この版では 2 項の行から直接は入れていない。
- `HighsTransformedLp` の構築: 連続列はいつも最良の VUB/VLB (`getBestVub`: LP での余裕が小さいもの。余裕が 0-1 列を緩めたときの距離より
  大きいものは捨てる `kSkipBadVbds`) を持つ。**整数列は「LP 値が単純な上下限の真ん中 (両側に feastol より離れる) で、LP 値が整数
  (`|round(x) - x| < feastol`)」のときだけ VUB/VLB を探し**、変数上下限の余裕が単純な上下限の余裕より大きければ捨てる。
- `transform` (置き換え): 整数列は「幅 ≤ 1.5、または変数上下限の余裕が 0 でない (`boundDist != 0`)、または単純な上下限に乗っている」なら
  単純な上下限。そうでなければ (= 変数上下限がちょうど効いている) VUB か VLB で置き換える。向きは余裕の小さい方、同点なら
  **係数が正なら VUB、負なら VLB** (余りの項 `s` が係数負で残る向き。連続列の同点は逆で、係数が正なら VLB = 余りを捨てる向き)。
  置き換えた後で余りの係数が正なら捨てる (`remove`)。
- 余り `s = d z + e - w` は元の整数列の番号のまま「整数」として扱い、上限は `ub - lb` (コメントに「変数上下限がきつい (cleanupVub で
  最大値 ≤ ub にしてある) ことを仮定」とある)。`untransform` で `s` を元の式に戻す。

### 1.2 ENOMOTO の試作 (`src/mip/cuts.rs`・`separation.rs`)

- `VarBounds` に `ivub`/`ivlb` (一般整数列の変数上下限) を足した (既存の `vub`/`vlb` は連続列のもので、heur_scip の vbounds や flow cover も
  使うので分けた)。`VarBounds::add_int_vbs` が集める:
  - 2 項の行 `row_lo ≤ a w + b z ≤ row_up` (w は整数で幅 > 1.5、z は 0-1 列): 行の両側を見て `w ≤ (rhs - b z)/a` (a > 0、`≤` 側) などを作る
    (係数の符号・等式はこれで全部扱える)。
  - `ENOMOTO_MIP_INTVUB_IMPL` ならプロービングの含意 `p.implied_bounds` (`z = v ⇒ w ≤ b`) も HiGHS と同じ式で入れる (下の 4)。
  - **z = 0 と z = 1 での値をそれぞれ整数に丸め (上限は切り捨て、下限は切り上げ)、w の境界で切り詰める**。w が整数・z が 0/1 なので
    丸めても妥当で、余り `s = d z + e - w` も整数になる (HiGHS は丸めない。含意から入る値は整数なので困らない)。z の値によらない
    (d = 0) ものは捨て、同じ z が 2 回出れば両方の値で強い方をとる。
  - 整数かどうかはカットに使う `cut_int` (暗黙の整数列を含む)、境界は大域的な境界。表は最初の分離で 1 回作る (既存の `vbounds` と同じ)。
- `substitute_finish` (整数列の置き換え) の前に、整数列ごとに `int_vb_choice` で置き換えるかを決め、z の係数を足し込んでから単純な上下限の
  処理をする。余りの項は「整数、LP 値は変数上下限の余裕、上限は `max(e, d + e) - l` (VUB) / `u - min(e, d + e)` (VLB)」。
  - `=1`: HiGHS と同じ条件と向き (上の 1.1)。
  - `=2`: LP 値が整数でなくてもよく、変数上下限の余裕が単純な上下限の余裕より feastol 以上小さければ置き換える (向きは `=1` と同じ)。
  - `=3`: まず「余りを捨てる向き」(係数が正なら VLB、負なら VUB) で、余裕が単純な上下限の余裕以下のものがあれば LP 値によらず使う。
    なければ `=2` と同じ。連続列の同点の扱い (既定) と同じ考え。
- `unsubstitute`: 補変数にした余り (`s' = yu - s`。CMIR の向きの反転・lifted cover が作る) を戻せるようにした (`c s' = c yu - c s`)。
  連続列の余りは補変数にしないので既定には関係しない。
- 置き換えは `substitute` を通る全部 (CMIR・extended cover・lifted cover、元の行・集約行・tableau 行・経路集約) に効く (HiGHS も
  `transform` を CMIR と lifted cover で共有する)。
- 診断: `ENOMOTO_MIP_INTVUB_LOG` (集めた数)、`ENOMOTO_MIP_DEBUG_SEP` と一緒なら置き換えの判定の結果の数、`ENOMOTO_MIP_INTVUB_DUMP=N`
  (変数上下限のある列を含む元の行を N 本、置き換え後の項と CMIR の結果を表示)、`ENOMOTO_MIP_INTVUB_DUMP_TAB` (tableau の集約行も)。

## 3. mushroom-best

### 3.1 再スタートの後の模型の根だけ (`root/`)

模型は `ENOMOTO_MIP_DEBUG_DUMP_RESTART` で書き出した再スタート 1 回目の模型 (9197 行 × 8468 列、持ち越したカットを含む。4.5 MB なので
置いていない。書き出し方は `highs_only_20261105/G1/mushroom/README.md` と同じ、20 秒・4 スレッド)。ENOMOTO は 1 スレッド・根だけ
(ノード上限 1、打ち切り値 = 最適値)、HiGHS は `cutloop_stop_20261106/B/mushroom/hcutpool.py` (4 スレッド、ノード上限 1、`objective_bound` = 最適値)。

| 設定 | 根の LP → カットの後 | カット (足した / LP に残る) | 置き換えの判定 (呼び出し / 置き換えた / LP 値が小数で見送り) |
|---|---|---|---|
| def | 0.0158432 → 0.0158479 | 7 / 6 | - |
| iv1 | 0.0158432 → 0.0158460 | 5 / 3 | 580 万 / 435 万 / 139 万 |
| iv2 | 0.0158432 → 0.0158488 | 7 / 6 | 820 万 / 820 万 / - |
| iv3 | 0.0158432 → 0.0158476 | 8 / 6 | 739 万 / 739 万 / - |
| HiGHS | 0.0158432 → **0.0305207** | プール 9573、LP に 44 本 (0-1 列が主の式: `B8I1`・`B16`・`B13I3`…、平均非零 19.6) | - |

(HiGHS の前の記録 `cutloop_stop_20261106/B.md` では別の書き出しで 0.01585 → 0.02695、プール 10050・LP 38 本。)

事実:
- **試作でも根は動かない**。置き換えは数百万回起きているのに、元の行の分離 (`SEP rows`) と経路集約 (`SEP path`) の候補は既定と同じく 0 本、
  tableau の候補だけ (49〜64 本) から 1 ラウンド 1〜2 本。
- 模型の形 (`hpre.py`・`G1/mushroom/insp.py`): w は 113 列 (幅 [-10, 10] の一般整数列)、z は 113 列の 0-1 列、`w ≤ 10 z`・`-w ≤ 10 z`
  (`|w| ≤ 10 z`) の 2 項の行 226 本。データの行 8660 本はどれも **x0 (幅 [-100, 100] の一般整数列で、変数上下限を持たない) と、係数 -310 の
  列 (大部分は固定済み)** を含む `Σ ±w + x0 - 310 e ≤ -0.001`。HiGHS の前処理の後も同じ形 (x0 は [0, 200]、8127 行すべてに入る)。
- LP の点 (`ENOMOTO_MIP_INTVUB_DUMP`): 大半の w は 0 (z も 0)、0 でない w は 0.429・0.571・-2.571・-0.857 など小数。x0 = 0.429。
  - iv1 (HiGHS の条件): 小数の w は置き換えない (LP 値が整数でない)。w = 0 の列は VUB も VLB もちょうど効いていて、同点の規則
    (係数が正なら VUB) で余り s (係数 -1) が残る向きになり、z の係数 10・余り -1 の式になる。CMIR は作れない。
  - iv3 (余りを捨てる向き): 全部の w が z に置き換わり `-y0 - 10 Σ z ≤ -101` (y0 = 100 - x0、LP 値 99.571) の形になるが、x0 の項
    (変数上下限を持たず幅 200) が残るので MIR で強いカットにならない (CMIR は作れない)。
  - tableau の集約行は、行の論理変数 (データの行の余り、上限なしの整数) が 100〜150 個並び、z の項はほとんど出てこない。
- HiGHS のプールの z だけの式 (`Σ_{S} z ≥ 1`、|S| = 7・11・18 など) の z の集合を、x0 の符号が逆の 2 本のデータの行の和 (x0 と共通の w が
  消える) の w の集合と突き合わせた (`pairs.py`、6 本) が、一致する組は 1 つもなかった。出所は分からない。

推測:
- 1 本の行で z の式のカットを出すには x0 が消えていなければならず、要るのは「置き換え」より「x0 を消す集約」(x0 は整数列なので、
  連続列だけを消す経路集約 (ENOMOTO・HiGHS とも) では消えない)。HiGHS がどこで z の式を作っているかは、この調べでは突き止めていない。
