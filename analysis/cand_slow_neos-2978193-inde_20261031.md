# 既定にする候補 cand で neos-2978193-inde が遅くなる理由 (2026-10-31)

`analysis/halve_submip_20261030.md` の bench7 で、cand (`ENOMOTO_MIP_SUBMIP_HIGHS=-s ENOMOTO_MIP_SUBMIP_PC_INHERIT=1 ENOMOTO_T_MIP_SUBMIP_RELIABLE=0
ENOMOTO_MIP_BG_CUTS_WAIT=1 ENOMOTO_MIP_SUBMIP_HIGHS_TRIM=r ENOMOTO_T_MIP_RESTART_FIRST_FAC=0.01 ENOMOTO_MIP_BG_CUTS_PROOF_STOP=1`) が
neos-2978193-inde で def 33.1 秒 → 50.2 秒と遅かった (bench6 でも hs_pi0_bgw で def だけ解けた) 理由を調べた。

- 機械: 4 CPU。4 スレッド・60 秒、`ENOMOTO_MIP_LOG=1`、ソルバーは同時に 1 つだけ。問題ごとに設定の順を回で逆にした。
- ビルド: 計測 1〜3 (切り分け) は `6bfcc89d` そのもの。計測 4 以降は `6bfcc89d` に下の試作 (既定では使わない) を足したもの
  (def・cand の動きは `6bfcc89d` と同じ)。設定は全部環境変数で明示した (def は環境変数なし = `6bfcc89d` の既定。
  同時に別のセッションが cand を既定にする変更 `f50a7f4` を push したが、計測には取り込んでいない)。
- 台本・ログは `cand_slow_neos-2978193-inde_20261031/`:
  - `run.py 設定,... 問題,... 回数 [最初の回]`: 1 回ずつ解いて `問題_設定_回.log` に書く。`cand-X` は cand から部品 X を外す、`def+X` は def に X だけ足す、
    `cand-hs<x>` は `ENOMOTO_MIP_SUBMIP_HIGHS=-s<x>` (hs から文字 x を抜く)。試作の設定は `DIAG_EXTRA_CFGS` で渡す (`run1.out`〜`run6.out` が出力)。
  - `summ.py [問題] [設定,...]`: 全体の秒・最初の根の長さ (再スタートの時刻)・早めの再スタートの有無・最初の根のサブ MIP の秒・木の秒。`summ.txt` に全部。
  - `subroot.py`: 最初の根の RENS・RENS (more nodes)・RINS のサブ MIP 1 本ごとの秒とノード。`stat.py`: 1 回ごとの時間の配分 (`stat.txt`)。
- 表の数字は秒。T は時間切れ (60 として平均)。最適値の食い違い・crash はない。
- `cargo test --release --lib` (`CARGO_TARGET_DIR=target/test-py RUSTFLAGS="-C link-arg=-lpython3.13"`): 330 passed (`f50a7f4` 以降の変更に rebase した後も同じ)。
- 注意: rebase した先 (`f50a7f4`) では cand が既定になっている。この記録の def は `6bfcc89d` の既定 (cand の前) を指す。

## 1. 結論

1. **遅さは毎回ではない**。neos-2978193-inde は cand 20 回で平均 41.7 (中央値 37.9、32.2〜60.0)、def 8 回で平均 38.8 (中央値 38.8、31.7〜44.1)。
   木の秒が回ごとに大きく揺れ (cand 16〜41 秒)、bench7 の 50.2 秒は cand の揺れの上の側に当たる (cand は 20 回中 4 回 55 秒以上)。
2. 揺れを除いた差は **最初の根 (1 回目の再スタートまで) の長さ** に出る: cand 平均 8.4 秒、def 3.2 秒。木の秒は同じ (cand 27.0、def 27.1)。
3. 仕組み: どの回も最適値 -2.38806 は最初の根で見つかり、後は木の証明だけ。最初の根の終わり方が 2 通りある (「くじ」)。
   - 乱択丸め (と内点の丸め) が良い解 (-2.361・-2.388) を出すと、被約費用で整数列 8/64 本が固定され **早めの再スタート** に入り、最初の根は 2 秒で終わる。
   - 出せないと、根のヒューリスティクスが続き、並列の RENS のサブ MIP が最適解を出す。しかし並列のサブ MIP の結果を受け取る `join_submips(0)`
     の後には早めの再スタートの判定がないので、整数列 8 本が固定されていても **RENS のやり直し (more nodes) と RINS (各 50 ノード) を逐次に回す**。
   - そのサブ MIP 1 本が、def では 1.6〜1.7 秒、cand では 3.5〜3.7 秒 (hs の形)。くじに外れた回の最初の根は def 6.8・7.3 秒、cand 9〜17 秒になる。
   - くじに当たる割合は設定によらない (def と def+X の 26 回中 15 回、cand と cand-X の 62 回中 28 回。乱択丸めは根のサブ MIP より前で、設定の文字は効かない)。
4. サブ MIP 1 本を重くするのは hs の文字 `h` (サブ MIP の中でも RENS を回す) が主で、`c` (根のカットを親と同じだけ回す) が一部。
   擬似コストの引き継ぎ・強分枝なし (RELIABLE=0)・BG_CUTS_WAIT・TRIM=r・FIRST_FAC・PROOF_STOP は関係しない (2 節)。
   binkar10_1・dcmulti で `diag_hsletters_20261031.md` が見た仕組み (1 本が重い) と同じ。
5. 手当ての試作 **`ENOMOTO_MIP_EARLY_RESTART_JOIN`** (既定では使わない、3 節): 並列のサブ MIP の結果を受け取って暫定解が良くなったときも、
   早めの再スタートの判定をする。neos-2978193-inde は cand 41.7 (中央値 37.9) → **cand_erj 35.9 (中央値 33.0、12 回)**、最初の根 8.4 → 3.7 秒 (def 3.2)。
   得の問題 (h80x6320d・qiu・mc11・physiciansched6-2・binkar10_1) は 3 回ずつで損がない (h80x6320d は 1 回で働いて 21.8 秒)。
6. n5-3・neos-1582420 の遅さは別の形で、試作は働かない (どの回も判定に当たらない)。こちらは再スタートの前の根のサブ MIP が def の 2〜3 倍
   (n5-3: 根のサブ MIP の秒の和 def 10〜16 → cand 49〜54、根のヒューリスティクス 14〜16 → 38〜42 秒) で、早めの再スタートの起きない問題 (4 節)。

## 3. 手当ての試作 `ENOMOTO_MIP_EARLY_RESTART_JOIN` (既定では使わない)

`src/mip/solver.rs` の根のヒューリスティクスで、並列のサブ MIP を受け取る `join_submips(0)` と `poll_find_thread()` の後に、
暫定解がその前より良くなっていて早めの再スタートの判定 (`proto_restart_ok`、`ENOMOTO_T_MIP_EARLY_RESTART_FRAC` 0.025) が通れば、
`early_restart` を立てて残りの根のヒューリスティクス (RENS のやり直し・RINS など) を飛ばす。逐次のヒューリスティクスの後の判定と同じ扱い。
ログは `MIP: early restart: 8 newly fixed integer columns after the parallel sub-MIPs (9.31s)`。

| def_erj | 6 | 37.1 | 35.6 | 3.5 | 3 / 3 | 25.5 |

- cand_erj の 60.0 秒の 1 回は木が 47 秒・5432 ノード (全スレッド) の揺れ (最初の根は 4.5 秒)。
