# 根の LP の頂点の選び方に頑健なカットの試作 (2026-11-24)

依頼 (親、利用者の方針「根で使っても強いカットが得られる頑健な設計にしたい」): 根の LP が退化して最適面が広いとき、どの頂点に落ちたかで
カットの強さが変わり、根で閉じるかが決まってしまう (nw04)。これを頂点の選び方に頑健にする試作を作り、既定・試作で根の下界と根で閉じるかを比べる。
既定オフ、新しい恣意的な閾値は作らない。

台本:
- `one.py 問題 名札 [ENV=値 ...]`: 1 回解く (既定 1 スレッド・種 1・60 秒、`CR_TH`・`CR_SEED`・`CR_TL`)。ログ `logs/<問題>_<名札>_th<T>_s<S>.log.gz`、行 `res.jsonl`。
- `batch.sh 名札 問題 [ENV=値 ...]`: 出発の頂点を `ENOMOTO_MIP_MPSEP_START=0..8` (0 は既定の頂点、1〜8 は最適面の上の別の最適基底へ移ってから根のカットを始める、
  analysis/mpsep_20261106.md の計測用) の 9 通りで回す。カット選択の比べの同点を時間の揺れで決めないよう `ENOMOTO_MIP_CUTSEL_PROBE_TIE_FEWER=1` を付ける (2 節)。
- `scip_one.py 問題 名札 [名=値 ...]`: SCIP 10.0 (pyscipopt 6.3.0) で 1 回解く。行 `scip.jsonl`。


## 結論 (短く)

- **nw04 の「頂点の違い」は、点ではなく基底の違い (事実)**: 出発の頂点を `MPSEP_START=1..8` でずらすと、動く列は 0 本で、基底が 12〜13 本違うだけ。
  単体表 (Gomory) のカットは基底の行から作るので、同じ点でも基底でカットが変わる。HCoW の `LU_EXTEND=r` の悪い道 (luxroot 6 節) も、周 2 で同じ最適面の別の頂点に落ちる形。
- **既定の当たり外れには、カット選択の比べの同点も効いている (事実)**: 比べ (`CUTSEL_PROBE`) で既定と POOL の伸びが同じとき、1 ラウンドの時間の揺れで
  どちらかが決まる (analysis/parint2_20261113.md で既知)。出発の頂点 2 では既定 (3 本ずつ) が選ばれ、根で閉じずに 1 ノード。`TIE_FEWER=1` で除くと 9 通りとも根で閉じるが、
  根のカットのラウンドは 5〜14、時間は 19〜53 秒と揺れる。
- **候補 2 の試作 `ENOMOTO_MIP_CUTVERT=q` (分数の度合いが増える頂点へ移る) は nw04 で効かない (事実)**: 今の点がほぼいつも分数の度合いの局所最大で動けない。
  まれに動いた 2 通りは既定より悪い (根で閉じず 1 ノード)。`LU_EXTEND=r` の悪い道も立て直せない (既定 16842.3、`q` 16808.2、どちらも 1 ノード)。
  親の指摘どおり、nw04 では閉じた頂点の分数の列 3 本・止まった頂点 23 本で、分数の多さは物差しにならない。
- **参考の `ENOMOTO_MIP_CUTROBUST=g` (候補を 1 本ずつ LP に足して伸びを測り、伸び 0 を捨てる) も nw04 では働かない (事実)**: 点が 1 つに決まるので、
  どの候補も最適面を丸ごと切り、伸びは全部正。測る時間だけ延びる (時間の中央値 25.3 → 33.0 秒)。`m`・`a` (面の頂点で効き目を測る) も、面の頂点が今の点と同じか近く、何もしない。
- **既存の試作**: `FACE_BASIS` は悪い (9 通り中 2 通りで 1 ノード、1 通りは時間切れ)。`MPSEP=oqmgs` は最適面が狭い判定で 1 ラウンドも働かず既定と同じ。
- **一番大きい発見: nw04 の clique 分離の漏れ (事実)**: HiGHS の LP 緩和の頂点 (前処理なし) で、分数の列 6 本のうちに元の行に含まれない clique が 3 つ破れ
  (Σx = 1.33〜1.67)、odd-cycle も破れる (重みの和 0.33 の奇閉路)。SCIP 10 は nw04 の根で clique のカットを 262 本・Gomory を 14 本 LP に入れる (統計 `logs/scip_nw04_stat_p0.stat`)。
  こちらは clique の候補が 0 本。長い集合分割の行 (2000 文字超) を衝突グラフに入れないため、nw04 では行の衝突の 100% (81.6 億組) が落ちる (analysis/clqprb_20261112.md 13 節)。
  頂点に依らない強化として、長い行の clique を行の形のまま持つ試作 `ENOMOTO_MIP_CLQROW` を作った (4 節)。
- **ただし `CLQROW` はどの形も悪い (事実)**: nw04 は既定 9 通りとも 0 ノードに対し、`=1` は 5 通り中 4 通り、`=2` (clique を別枠で足す) は 9 通り中 5 通りで根で閉じず 1 ノード。
  eil33-2 は既定 44.3 秒で解けるのが `=1`・`=2` とも時間切れ (根の下界 870.5 → 821.0・819.0)。air03 は根の LP で解けて差なし。
  clique のカットは 0 周目でも下界を上げず (nw04 は 16669.1 のまま)、LP の頂点をずらして、次の周の単体表のカットを弱くする (nw04 の周 1 の伸び: 既定 +105.9、`=2` +15.6)。
  SCIP の 262 本は、被約費用の固定と再スタート (根で 3 回) で問題を 87482 → 11119 列に縮めながら入れたもので、こちらの根のループにそのまま足しても効かない。
- **広い 14 問 (1 スレッド・種 1・60 秒、出発の頂点 2 通り)**: `q`・`g` とも、根の下界の揺れが縮む問題 (`g`: neos859080 1・1.53 → 2・2、gt2) と広がる問題
  (`q`: supportcase26) が混ざり、時間も問題で上下する。はっきりした改善はない (3 節)。
- 既定オフ。`cargo test` と MIP の fuzz 7 本は 5 節。

## 2. 試作の中身 (どれも既定オフ)

- `ENOMOTO_MIP_CUTVERT=q` (`src/mip/separation.rs` の `cutvert_move`、`src/simplex/mip_lp.rs` の `optface_move` の `q`): 根のカットのループの各ラウンドで、LP が双対退化している
  (被約費用 0 の非基底がある) とき、分離の前に、双対退化の非基底を入れる軸の入れ替えで整数列の分数の度合い Σ min(f, 1 − f) を増やす。候補は全部比べ、増やす入れ替えが
  なくなったら止まる (局所最大。ピボット数の上限は作らない)。時間の上限は `MPSEP` の 1 回の移動と同じ (根の LP の秒 × 0.25 を 0.01〜0.1 秒に。analysis/mpsep_20261106.md で
  入れ替えの手間から決めた値)、入れ替えの安全網は既存の `ENOMOTO_T_MIP_OPTFACE_PIVOTS` (1000)。
- `ENOMOTO_MIP_CUTROBUST=m|a|g` (`cutrobust_rescore`・`cutrobust_gain`): `m`・`a` は面の頂点の分離 (`FACE_SEP` 既定 `int2`) が解いた頂点でも候補の効き目を測り、
  面の全点で破れる候補だけ残す (`m`) か効き目を平均にする (`a`)。`g` は双対退化のラウンドで候補を 1 本ずつ LP の写しに足して解き、伸び 0 の候補を捨てる
  (伸び正の候補があるときだけ。カット 1 本を足した LP の値は頂点・基底によらない)。測るのは効き目の順に、面の LP と同じ時間の上限まで。
- `ENOMOTO_MIP_CLQROW=1|2` (`src/mip/clique.rs`): 衝突グラフの行の上限 (2000 文字・2 万辺) で辺にしなかった行のうち、行全体が clique のものを行の形で持ち
  (文字ごとの行の番号)、clique カットの分離だけで「同じ行の 2 文字は隣接」とみなす。上限は既存 (始点 500・値 0 の文字の足し込み 200)。`=2` は clique の候補を別に選んで足す
  (同じ本数の上限、ほぼ平行 (0.99) は除く)。

## 4. 退化した根の頂点の選び方: SCIP・HiGHS (依頼の候補 3)

- SCIP 10.0 (pyscipopt 6.3.0) の既定: `lp/solutionpolishing = 3` (auto、SoPlex の解の磨き)、`lp/lexdualalgo = False` (辞書式の双対単体法は実装があるが既定で使わない。
  `lexdualrootonly`・`lexdualmaxrounds 2`・`lexdualstalling`)。nw04 を permutation の種 0〜2 × {既定・磨きなし・辞書式} で解くと、9 回とも根で閉じる (ノード 1、62〜91 秒、`scip.jsonl`)。
  磨きも辞書式も nw04 の根を左右しない。
- SCIP が nw04 の根で LP に入れたカット (`logs/scip_nw04_stat_p0.stat`): clique 262 本・Gomory 14 本 (gomorymi 12・strongcg 2)・cmir 0。被約費用の固定と再スタート 3 回で
  87482 列 → 46143 → 22098 → 18445 → 11119 列に縮めながら回す。
- HiGHS 1.15.1: 最適面の中の頂点を選ぶ設定 (磨き・辞書式) はない (`random_seed` だけ)。
- clique・odd-cycle の破れ (`clique_check.py`、HiGHS の LP 緩和の頂点、前処理なし): nw04 は分数の列 6 本 (1/3 が 4 本・2/3 が 2 本)、衝突の辺 12 本、元の行に含まれない
  破れる clique 3 つ (Σx = 1.33〜1.67)、重みの和 0.33 の奇閉路 (破れる odd-cycle)。

## 6. 見立て (推測)

- nw04 の当たり外れは「同じ点の基底の違いで単体表のカットが変わる」ことから来ていて、点を選ぶ候補 2 では触れない。分数の多さも、カット 1 本の伸びも、頂点の良し悪しの物差しにならなかった。
- 頂点に依らない強化として clique は理屈は合うが、こちらの根のループでは下界を上げずに頂点をずらす害が勝つ。SCIP 並みに効かせるには、被約費用の固定で問題を縮める再スタートと組む必要がありそう。
- 次に試すなら: 同じ点の別の基底の Gomory を「伸びの見積もり (双対の 1 歩の伸び min d_j/π_j)」で選ぶ形 (親の案)。ただし基底ごとに単体表の行が要り、多点分離 (利用者が避けたい形) に近い。
