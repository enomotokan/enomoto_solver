## 1. qap15: 双対単体法では (HiGHS でも) 600 s で届かない。CLP は Idiot crash + 主単体法で 26 s

### 1.1 問題の形

6,330 行 × 22,275 列、94,950 非零、**全行が等式**、右辺は 6,300 行が 0・30 行が 1、係数は +1 (88,650) と −1 (6,300) だけ、
全列 `[0, ∞)`、費用の非零 15,750 (値は 22 種、2〜120)。QAP (nug15) の Adams–Johnson 型線形化。
**等式行の階数は 5,698 で 632 行 (10%) が一次従属** (`A_eq A_eq^T` の固有値、`fa_rank.py`、`fa_qap15_rank.log`)。
前処理: ENOMOTO (`PRESOLVE_SIZE`) も HiGHS も CLP も縮約 0。ENOMOTO の `ENOMOTO_REDEQ_MODE=0` (階数判定あり) は
**190 s かけて 144 行しか落とせない** (`fa_qap15_redeq0.log`、`redundancy.rs` の DM ブロック分割が従属行を見逃す件は
`analysis/nug08_irish_20260926_013500.md` §2.3 と同じ)。HiGHS の従属等式探索 (`HPresolve::removeDependentEquations`、
`HFactor` で `[A_eq^T; b^T]` を分解) は時間上限 (`max(1, 0.01·time_limit)` s) で 0.45 s で打ち切られ、こちらも 0 行。

### 1.4 CLP の解き方 (`fa_qap15_clp.log`、`clp qap15.mps -log 2 -either -solve`、合計 36 s、うち求解 25.8 s)

`ClpSolve::automatic` (`ClpSolve.cpp:1578-1700`): 行 6,330 > 200・列 22,275 > 2,000・列 > 2 × 行 なので `tryIt = 3`、
係数が ±1 だけ (`plusMinus`) なので Sprint ではなく **Idiot** (`doIdiot < 0 && plusMinus`、`:1822`)、右辺の最大/最小 = 1 で
`nPasses = max(100, 10 + 列/1000)` = 100 (`:1625-1650`、実際は 77 パスで収束) → `method = usePrimal`。

1. **Idiot crash 1.3 s** (`Idiot::solve2`、`IdiSolve.cpp`): `min c'x + λ'(Ax−b) + (1/2μ)‖Ax−b‖²` を箱制約つきの座標降下
   (1 パス 105 反復) で解き、λ を更新しつつ μ を 0.1 → 1.9e-7 に 77 段階で下げる (Forrest の "idiot crash"、
   Galabova–Hall 2020 の解析対象はまさに QAP の線形化)。77 パス目で目的 1041.396 (最適 1040.994)・実行不能の和 8e-5、
   境界から離れた列 17,677、**4,598 列を 0 に固定**。
2. **crossOver (`Idiot::crossOver(3)`)**: 固定列を除いた 17,677 列の問題で `primal(1)` の値パス (values pass: Idiot の解を初期値に、
   境界から離れた列を superbasic として基底化): **17,677 反復、20 s**。続けて費用摂動つき主単体法 3,537 反復 (3 s)、
   合計 21,214 反復で最適。
3. 元問題 (全 22,275 列) に戻して双対単体法 0 反復で最適を確認。

つまり qap15 は「近似解 (Idiot) を 1.3 s で得て、主単体法で 2.1 万反復の crossover」が効く問題で、双対単体法で解く限り
HiGHS でも 600 s を超える。(論文の CLP 475 s は同じ経路でも版・ビルド差で Idiot のパス数などが違ったものとみられる。)

### 1.6 追加計測 (qap15、同じコア)

**HiGHS の他の解法** (`fa_qap15_highs_primal2.log`、`fa_qap15_highs_ipm2.log`):

| 解法 | 結果 |
|---|---|
| HiGHS 主単体法 (`simplex_strategy=4`、全スラック基底から) | 540 s で打ち切り (第 1 段階 ~1.2 万反復 / 70 s、第 2 段階 107,725 反復で目的 1056.98、最適 1040.99 に未達)。**主単体法でも全スラック基底からでは解けない** |
| **HiGHS IPX (内点法 + crossover)** | **11.8 s で最適** (内点法 ~8 s、crossover 2.85 s・2,557 更新。crash 基底から落とした列 846、基底の最小特異値 1.4e-6) |
| CLP Idiot + 主単体法 (§1.4) | 26 s (Idiot 1.3 s + 主 2.1 万反復) |

qap15 は「近似解 (内点法か Idiot) から基底を作る」経路なら 10〜30 s、単体法だけでは双対・主とも 600 s 超、という問題。

**ENOMOTO の双対単体法の切り分け** (計装版、150 s で打ち切り、同じ反復数で比較。`fa_qap15_{dsework,dserefresh,pert10,pert01,slack9,harris6,harris5}.log`):

| 設定 | 2 万反復の双対目的 | 6 万反復 | 10 万反復 | 備考 |
|---|---:|---:|---:|---|
| 既定 | 332 | 455 | 509 | DSE 重みの相対誤差: 97.5% が 1% 未満、100% 超は 0.5% (`dse_rel_err`) → **重みの精度は問題ではない** |
| `ENOMOTO_DSE_REFRESH_ON_REFACTOR=1` (再分解ごとに厳密な重み) | 380 | 458 | – (1 反復 2.3 ms に増) | 同上 |
| 費用摂動 ×10 | 345 | 455 | 498 | 効かない |
| 費用摂動 ×0.1 | 390 | 497 | 539 | わずかに良い |
| スラック摂動 1e-9 (§3 S1) | 332 | 455 | 509 | 等式行のスラックは固定で摂動対象外 → 経路同一 |
| **Harris 窓 `HARRIS_RATIO_TOL` 1e-7 → 1e-6** | 383 | **505** | **553** | 窓を広げるほど良い |
| **Harris 窓 1e-5** | **443** | **525** | – | 同上 (HiGHS は 6.6 万反復で 876) |
| (参考) HiGHS 双対 | 678 (1.6 万) | 876 (6.6 万) | 973 (12 万) | |

DSE 重み・摂動量ではなく、**比率テストで「ほぼ同点の候補のうちどれを入れるか」が反復あたりの進みを左右している**
(qap15 は費用の値が 22 種しかなく、摂動後の `d_j` と `|alpha_j|` (係数 ±1) の比が大量に同点になる)。ENOMOTO のパス 2
(`slope_intercept_dual.rs:4507-4530`) は `k_star` から**後ろ向きだけ** (比が `k_star` 以下の候補) に `HARRIS_RATIO_TOL = 1e-7` の窓を取り
|alpha| 最大を選ぶ。HiGHS (`HEkkDualRow::chooseFinal`) と CLP は前向きの Harris (`theta_max = min_j (d_j + tol_d)/|alpha_j|` まで比が
大きい候補も許し、その中で |alpha| 最大) で、許容誤差 (`dual_feasibility_tolerance` 1e-7) の分だけ双対実行不能を許す代わりに
大きなピボットと大きな双対ステップを取る。nug08/irish では前向き窓で選択が変わる反復は 0.1〜0.6% (nug08 報告 §4.4) だったが、
qap15 では窓の幅だけで 6 万反復時点の目的が 455 → 525 と変わる。→ 対処案 **Q5** (前向き Harris 窓 + 費用シフト) を追加 (§1.5b)。
ただし窓 1e-5 でも HiGHS の半分以下なので、qap15 を 600 s 内に収めるのは Q1/Q1' の経路で、Q5 は双対単体法全般の改善。

  残る差は 1 反復 (ours ~0.7 ms vs HiGHS 0.28 ms): tau が密 (m の 5〜10%) になる 2 割の反復が FTRAN の 58% (`O(m)` の

  行ごとの密度予測で最初から全走査) と前処理の行数差 (87K vs 78K: HiGHS の dominated row / doubleton 連鎖) が残っている。
  本調査では新しい原因は見つけていない。
- stormG2_1000 (79 vs 71): 1.12 倍で揺れの範囲に近い (この機械 73 s)。`analysis/stormG2_1000_*` の残項目のみ。扱わない。

## 6. 優先順位 (全体)

1. **Q1' (内点法 + crossover) または Q1 (Idiot crash + 主単体法)**: qap15 打ち切り → 数十 s (HiGHS IPX 11.8 s、CLP 26 s)。
   131 問の幾何平均で −2% 級の単独効果。適用条件で他問題不変。どちらも大きな実装。Q1' は既存の内点法を使えるが Q4 の修正が前提。
2. **C0: cont1 の序盤 4 万反復で基底が密になる原因の切り分け** (HiGHS は同じ段階を 0.4 ms/反復 = 16 s で通過、ENOMOTO は ~250 s)。
   計測 (入る列・出る行の種類と同点数の記録) が先。直せれば cont1 −150〜200 s で HiGHS 並み。
3. **Q5: 前向き Harris 窓 + 費用シフト** (qap15 で窓の幅だけで反復あたりの進み +15%、退化問題全般)。全問題の経路が変わるので Netlib A/B。
4. **S1: スラック費用の微小摂動** (square41 −41% の実測 1 回。全問題の経路が変わる。perold 型の crash の双対実行不能の対策が要る。
   ゲート付きなら Netlib 不変)。
5. **C1/N2 (Q2): DSE → Devex の切替** (HiGHS は cont1 で 1.6 万反復目に切り替えて tau の FTRAN を省く。密な問題の 1 反復 −25%、
   反復数の増加と相殺の可能性。発火条件で他問題不変)。
6. **Q3/N1: 従属等式の除去を LU で** (nug08 −6%、qap15 632 行。時間上限付きで他問題の手間を抑える)。
7. C2/N3: 再分解の列方向の値 (cont1・nug08 の再分解 11〜14% のうち −30〜40%、ビット一致)。
8. S2/S3: square41 の許容誤差・PRICE。
9. Q4: 内点法の誤 infeasible (正しさ、Q1' の前提)。
