# GAP4 のメモリの候補 (rocn) と tableau の試作 (t) を新しい既定と比べる (2026-11-11)

bench に使う環境変数: `ENOMOTO_MIP_GAP4=rocn` (r: 再スタート前の古い `Solver` の LP・プール・待ち行列を捨てる、o: 木のスレッドの `orig` の写しから含意を除く、
c: 密なカットを伝播に入れない、n: 共有の待ち行列のノードに基底・DSE を付けない)、`ENOMOTO_MIP_GAP4=t` (LP の元の行が 2 万以上の問題でだけ tableau の行を
HiGHS の選び方で選ぶ。新しく足した試作)。どれも既定では使わない。既定は cand1108zd + DRCR (`ENOMOTO_MIP_FOLD=ri`)。
wheel はメモリの回が c37086fe、58 問・600 秒の追加の回が 10d17fbe (どちらも既定の動きは同じ。`t` を足しただけ)。4 スレッド、ソルバーは同時に 1 つ。
生データは `analysis/gap4_rootstuck_mem_20261109/` (`runs.jsonl` の `m11*`、`res58_m11.jsonl`・`cmp58_m11.txt`、`checks/m11_*`)。親のセッションの依頼による計測。

## 結論 (先に)

- 58 問 (60 秒・種 1・2): `rocn` は SGM 17.66 → 17.68 (+0.1%、95% 区間 −2.3%〜+2.3%)、解けた 82 → 84、最大 RSS の和 −8.1%。`t` は +0.5% (−3.2%〜+4.6%)、
  82 → 83、RSS +0.9% (58 問に 2 万行以上の問題はほとんどない)。どちらも揃った差・矛盾なし。
- メモリの問題 (600 秒・種 1): `rocn` で uccase12 3497 → 2670 MB (−24%)、fiball 3936 → 2013 MB (−49%、最適 557 → 445 秒)、widden 3508 → 3407 (−3%、下界 15700 → 21124)、
  neos-957323 は新しい既定で 19 秒で最適になりメモリの問題ではなくなった (531 → 507)。**tbfp-network は 2 種とも悪い**: RSS 2446・3308 → 2260・2308 だが、
  既定 (種 1 時間切れ 24.163、種 2 最適 586 秒) に対し `rocn` は 2 種とも 25.889 で時間切れ (木に入るのが 412〜424 → 551〜553 秒)。切り分け (種 1、1 回ずつ):
  `c` だけは最適 564 秒 (害なし)、`ron` は 508 秒で木に入り 25.889。遅れは r・o・n の側か、根の並列のサブ MIP の揺れ (被約費用のサブ MIP 216 → 370 秒) で、どれかまでは分けていない。
- `t` は新しい既定の neos-873061 では効かない (600 秒の下界 既定 104.72・104.42 対 `t` 104.42・104.09)。前の既定では根のヒューリスティクスの後の「2 回目のカットのループ」
  (104 秒) で `TAB_HIGHS_RULES` の軽いラウンドが下界を 109.5〜111.4 まで上げていたが、新しい既定ではこのループが 0 秒で、根の時間の大半 (300〜470 秒) が根のヒューリスティクス。
  `t` で 1 回目のループのラウンドは 6 → 9・12 に増えるが下界は同じ。また新しい既定では前処理の LP の基底が根に渡らず (`root LP basis from the presolve LP probing: none`)、
  根の LP が 11136 反復・14 秒の回と 43926 反復・170〜180 秒の回に分かれる (種で揺れる)。
- 誤答の検査: `fuzz_tiny.py 400 0` は既定・`rocn`・`t` とも bad 0 (strict 13 は既知)、`mip_fuzz_vs_highs.py 300` は 3 つとも bad 0、
  58 問の全回で両方最適の目的値の食い違い・下界と解の矛盾 0 件、`cargo test --release --lib` (3b4206af) 400 通過・0 失敗。

## 次 (推測を含む)

- `rocn` を既定にするなら tbfp-network の遅れを先に分ける (r・o・n を 1 つずつ、2 種)。`c` 単独は害が見えず、`o`・`r` は解き方を変えない作りなので、`n` (ノードの基底を渡さない) が
  一番疑わしい (前の記録でも widden で主のスレッドのノードの LP が 1.6 倍重い兆し)。`roc` (n なし) だけなら uccase12・fiball の開いたノードの持ち物は減らないので、
  `n` の代わりに基底は残して DSE だけ外す形 (既存の `ENOMOTO_MIP_POOL_DSE=0`) と比べる。
- `t` は新しい既定では効き目がないので候補から外す。neos-873061 は根のヒューリスティクス (300〜470 秒) と根の LP の揺れ (前処理の LP の基底を渡さない) の方が先。
