# globalaudit: 大域的に分かった情報を捨てている・局所に留めている箇所の洗い出し (2026-11-24、親の依頼)

親の依頼 (利用者の問い「改良というより元が抜けていただけでは。ほかに似た抜けはないか」): 大域的に (木全体で、または打ち切り値より良い解に対して)
成り立つと分かった情報を、捨てているか局所に留めているか、ほかの場所 (再スタートの前処理・ほかのスレッド・木の全ノード・再スタートの判定の数え)
に渡していない箇所を、コードを読んで洗い出し、抜けの疑いの強いものは診断で量を数えた。**直す試作は作っていない。既定の振る舞いは変えていない。**
根で目的の伝播の固定が大域的な境界に入らない件 (analysis/objprobehull_20261124 の付記) は別の子の担当なので、表に載せるだけにした。

- コードの読みは自分 (1・5) と、読むだけの手伝い 3 本 (3 再スタート、4・7 スレッド・サブ MIP、2・6 衝突・含意) で行った。手伝いの結論は
  主なものを自分でもコードで確かめた (行番号は 473742b4c + 診断の差分の時点。手伝いの読んだ時点とは solver.rs が数十行ずれうる)。
- 診断: `ENOMOTO_MIP_DIAG_GLOBALAUDIT=1` (既定では働かない。数えて `ENOMOTO_MIP_LOG` の出力に出すだけ。写しの伝播の手間は時計・手間の期限から差し引く)。
  1. `MIP: GLOBALAUDIT root:` 根のノード (深さ 0) を分枝する時点で、定義域が大域的な境界より締まっている整数列を、最後にその境界を変えた記録の理由ごとに数える
     (src/mip/solver.rs の `globalaudit_root`)。深さ 0 の変更はどれも (打ち切り値より良い解について) 大域的に成り立つが、子には分枝だけが渡り、
     次に根へ戻る (`reset_to_root`) と巻き戻されるので、木では捨てることになる。あわせて、その固定を足すと再スタートの判定 (`restart_expected`) が変わるかを出す。
  2. `MIP: GLOBALAUDIT reset:` `reset_to_root` (src/mip/domain.rs:543) が保留中の大域的な締め付け (`pending_global`) を置いた後に伝播の待ち行列を捨てる
     (domain.rs:564) ので、その締め付けから行を通して締まるはずの境界は大域的な境界にもノードにも入らない。写しで伝播して、締まる整数列の境界を数える (全スレッドの合計)。
  3. `MIP: GLOBALAUDIT conflicts:` リテラルの衝突のうち、大域的に成り立つリテラルを除いて長さ 1 のもの (= 大域的な固定) の数 (全スレッドの合計)。
- 計測: `python analysis/globalaudit_20261124/run.py 60 4 1` (4 スレッド) と `... 60 1 1` (1 スレッド)、種 1・60 秒、P (analysis/cbcimpl_20261029/probs.py) の 18 問。
  結果は res_t4.jsonl・res_t1.jsonl、表は `python analysis/globalaudit_20261124/tab.py res_t4.jsonl`。
- 診断を足した後の `cargo test --release --lib` (リンクの指定は以前の記録と同じ `CARGO_TARGET_DIR=... RUSTFLAGS="-C link-arg=-L/usr/local/lib -C link-arg=-lpython3.13" LD_LIBRARY_PATH=/usr/local/lib`): 424 通過・失敗 0。

## 1. まとめ (先に)

- **根のノードの深さ 0 の局所の変更 (表の A1)** が一番はっきりした抜け。深さ 0 で出た固定 (行の伝播・ノードの被約費用の固定・強分枝の片側の固定) は
  大域的な境界に入らず、子にも渡らず、最初に根へ戻ったときに巻き戻される。`commit_root` を呼ぶのは solve の始め (solver.rs:5446) と試作 RCLOOP だけ。
  qnet1 は 4 スレッドで 418 本 (うち固定 415、L 324・R 88・S 4)、1 スレッドで 329 本 (固定 320)。再スタートの判定にも入らず、4 スレッドの qnet1・dcmulti・
  eil33-2 では「この固定を数えれば再スタートの閾値を越える」(ただし 4 回目以降は再スタートの上限で判定は偽)。
- **`reset_to_root` で捨てる伝播 (A2)**: 大域的な締め付け (主に暫定解が良くなったときの根の被約費用の固定) を置いた後の行の伝播を捨てる。
  qnet1 (4 スレッド) で 137 本、blend2 で 88 本 (1 スレッドで 34 本)、fiber で 54 本の整数列の固定が、大域的な境界にもノードの定義域にも入らない。
  (fixmore.rs:1-7 のコメントに「大域的な範囲では伝播しない」と書かれ、試作 FIXMORE (既定外、保留) がこれを直す形だった。)
- **長さ 1 の衝突 (C1)**: 大域的な固定なのに衝突のプールに入れるだけ。数は小さいが常に出る (noswot 4 スレッドで 214 本、neos5 で 334 本、eil33-2 で 14〜20 本)。
  直すのは小さい (`add_lit_conflict` で長さ 1 なら `tighten_global`)。
- fiber の 106 本 (目的の伝播だけで出る固定) は、根の定義域に J (目的の伝播) の記録が 1 本も無いことから、**局所に留まっているのではなく、既定では根の定義域で
  一度も計算されていない** (ノードの目的の伝播 `ENOMOTO_MIP_OBJ_PROP` が既定オフ、solver.rs:22548。大域的な目的の伝播 `HO2_GOBJ`・`TREEFIX p` も試作で既定オフ)。
  担当の子への参考。
- そのほか、再スタートで衝突のプール・含意・LP に入っていないカットのプール・打ち切り値 (前処理) を捨てる、サブ MIP の情報 (途中の解・no-good) を返さない、
  主スレッドの木の中のカットをほかのスレッドに渡さない、など (表)。多くは以前の試作で一部を試しているか (TREEFIX・FIXMORE・TC l・B3)、効きが未計測。

### 3.3 読み

- A1 (締めが 1 本以上) は 18 問中 4 スレッドで 7 問、1 スレッドで 5 問 (固定があるのは 4 スレッド 6 問・1 スレッド 4 問)。大きいのは qnet1 (根の 3〜4 回目の再スタートの後の根で 320〜415 本の固定、多くは L = 根のノードの LP の被約費用)
  と blend2 (4 スレッドで R 62 本)。eil33-2 は S (強分枝の片側) 14〜15 本で、両方のスレッド数で「数えれば再スタートの閾値を越える」。
  多くの問題 (misc07・mas76・rout・noswot・neos5) では 0 本、timtab1 はカットプールの伝播の締め 2 本 (固定なし) だけ。
- A2 は 4 スレッドで fiber 54・qnet1 137・blend2 88 (+ 連続 36) 本、1 スレッドで fiber 2・blend2 34 本。eil33-2 は締め付けを 1593〜6556 本置いても伝播の帰結は 0。
  スレッド数で大きく変わるのは、暫定解が見つかる時点・回数が変わるため (推測)。
- C1 は多くの問題で毎回出るが、全体の衝突の 1% 前後 (noswot 214/47860、neos5 334/53443、eil33-2 14/1136)。
- どの抜けも、木の大きい問題 (mas76・noswot・neos5・timtab1) では量が小さいか 0 で、効くとしても根で固定の多い問題 (qnet1・blend2・fiber・eil33-2) に限られそう (推測)。
  これらはもともと速く解ける問題が多いので、時間の差は大きくないかもしれない (未計測)。
