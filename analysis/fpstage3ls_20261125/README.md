# FP の第 3 段を FJ・Local-MIP で解く試作 (2026-11-25、親の依頼・利用者の案)

利用者の問い: 「実行可能ポンプの第 3 段のサブ MIP を分枝限定で解くのは重すぎないか。FJ・Local-MIP で解くべきでは」。

## 0. まとめ

- 試作 `ENOMOTO_MIP_FP_STAGE3_LS` (既定オフ) を作った。
  - FP の第 3 段 (src/mip/heuristics.rs `fp_stage3`) を、LP 解にいちばん近かった丸めの点 r を出発点にした FJ2・Local-MIP で解く。
  - `a` (や `1`): FJ2・Local-MIP だけで解く。
  - `b`: まず FJ2・Local-MIP。解がなければ残りの上限で今のサブ MIP。
- 確かめに使った 16 問 (1 スレッド・種 1〜3) では、速さは 3 つの組とも基準 (`HEUR_ADAPT=1m`) と同じ程度。
  - 害の出た 3 問 (swath3・neos-1582420・app1-1) は、幾何平均 40.5 → 37.0 秒 (a)・38.2 秒 (b)。
  - 解けた数は 3 つの組のどれでも同じ。
- 第 3 段が回った回では、局所探索が速く解を出す。
  - CMS750_4: 3 種とも 0.07〜0.28 秒で解。サブ MIP は 3 種のうち 2 種で、約 7 秒かかる。
  - markshare_4_0・misc07: 0.07 秒以内に解。
  - pk1: 3 種のうち 2 種で解。
- 失敗した回は app1-1 の 1 回と pk1 の 1 回。
  - 局所探索は上限 (手間) まで回って解なし。b ではその後のサブ MIP も解なし。
- 案 b の「Local-MIP のやり直しで止める」は、どの回でも上限より先に来なかった。
  - b は「a + 失敗したらサブ MIP」と同じで、失敗した回の分だけ重い。
  - 今回の 16 問では、b のサブ MIP が解を出した回はない。
- **勧め: a。** 第 3 段のサブ MIP (分枝限定) が要る場面は、今回の問題では見つからなかった。
- 確かめ: fuzz 7 本 (`fuzz.sh`、`FP_STAGE3_LS=b`・`HEUR_ADAPT=1m`・`LMIP_SCORE_TICKS=1`) は誤答 0、cargo test は 424 通過・0 失敗。
  既定の道筋は 6 問とも基準と一致 (`check_default.out`)。

## 1. 作り

### 探索の形

前処理の早めの FJ/Local-MIP (src/mip/mod.rs `feas_fj_lmip_early`) の 1 本の形をそのまま使う (`feas_fj_lmip_early_from`)。

- FJ2 を 1 回と Local-MIP の 1 切れを交互に回す。
- 違いは出発点だけ。FJ2 は毎回 r から始め (`fj2_search_from`)、Local-MIP も r から始める (`set_start`)。Local-MIP の中のやり直しも r に戻る。
- 1 本の形でも、探索は呼んだスレッドとは別のスレッドで回る (既存の robust FJ と同じ)。そのため、探索の手間は主のスレッドの手間に入らない。

### 予算

- 第 3 段のサブ MIP と同じ秒の上限を使う: f_g × min(残りの 0.1 倍, 10 秒)。
- `ENOMOTO_MIP_TICKS` の `f` (既定) なら、早めの探索と同じく手間で数える。時間は 10 倍の安全網と求解の期限で抑える。
- 新しい閾値は作らない。
- b のサブ MIP は、局所探索に使った秒を引いた残りの上限で回す (ノードは 500 のまま)。
- b の止め方は Local-MIP 自身のやり直しの判断に合わせた (改善のない手数 `ENOMOTO_T_MIP_LOCALMIP_RESTART`)。これを「出発点の周りで行き詰まった」印とみなす。

### 目的: 元の目的にした (r からの距離にはしない)

- サブ MIP の目的「r からの 0-1 列の距離」は、分枝限定を r の周りに留めるための目的。局所探索は出発点 r から動くので、もう r の周りにいる。
- FJ・Local-MIP は、解を見つけるまでは違反の量だけを見る。目的は、解を見つけた後に磨く方向にしか効かない。
  - 見つけた解はそのまま暫定解の候補なので、元の目的で磨くほうが得。
- 暫定解があれば、サブ MIP と同じく「目的値が暫定解より良い」行を足す。

### 表示

`ENOMOTO_MIP_FP_STAGE3_LS_DEBUG=1` (または verbose) で、次の行を出す。

- `FP stage 3 LS: cap …, 秒, 自由な連続列の数, until restart, accepted`
- 早めの探索の `early FJ/Local-MIP (1 thread): FJ … (… in ticks), Local-MIP …` の行

## 3. CMS750_4 で第 3 段が効く理由 (連続の列)

- CMS750_4 には自由な連続列が 3002 本ある。
- 当方の FP は、丸めの点で整数列を全部固定すると連続列の LP が実行不能になり、179 回とも解を出さない。
- 第 3 段は整数列を r の周りで動かしながら、連続列も同時に動かせる。これが効く理由。
  - サブ MIP は連続列を LP で持つ。
  - FJ2・Local-MIP も連続列を手 (jump・tight move) で動かす。
- FJ2・Local-MIP は連続の列を含むこの問題でも、r から始めれば 3 種とも 0.3 秒以内に解を出した (FJ2 が見つけた: Local-MIP 0.00〜0.11 秒)。
  - サブ MIP は 3 種のうち 2 種で、約 7 秒かかる。
- 根の始めの FJ (出発点は各列の下限) が出す解は 767〜775。r から始めると 319〜603 になる。
  - r (LP 解に近い丸め) から始めることが質に効いている。
- 最終の値 (200 秒) は、adm が 335・513・339、lsa が 387・311・424。後の探索の揺れが大きく、第 3 段の差は残らない。
