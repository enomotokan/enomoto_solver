## 3. 問題ごとの差の正体 (事実)

- **kasai: Sparsify**。等式 `−x0 − x462 + x463 = −402.5` を `x0 + x462 ≤ 4500` から引くと `x463 ≤ 4097.5` (1 列の行 → 境界) になり、
  行が消える (フィルイン 1 列を許す疎化)。HiGHS で Sparsify を切ると 1652 行で ENOMOTO の既定とまったく同じ大きさ。既存の `SPARSIFY_LATE`
  (HiGHS 1.15.1 の選び方の写し) で 1190 行 (HiGHS 1206)。根の LP は変わらない (954341)。
- **rococoC10: 整数列の Aggregator**。既存の `TREE2_INTAGG` で 577×2443 (HiGHS 576×2442)。58 問の害 (h80x6320d・nubu) は tree_close2 で既知。
- **neos-1445765**: 既定 (2026-11-04 からの `TREE2_FORCEQ`) で HiGHS とほぼ同じ (1001×2146 対 999×2133)。差はもうない。
- **neos859080: 双対の議論による行の等式化**。0-1 列 `y_b` (費用 0) が詰め込みの行 `y_a + y_b ≤ 1` と、`y_b` を増やしても破れない行
  `x_k ≤ 10 y_b` にしか出ない。どの最適解でも `y_b` を `y_a + y_b = 1` になるまで上げてよいので、行を等式にでき、2 項等式の消去が
  `y_b = 1 − y_a` を代入して 0-1 列 40 本が消える (HiGHS の前処理後の行がちょうど `x + 10 y_a ≤ 10` の形)。HiGHS の規則の切り替えでは
  切れない基本の縮約。ENOMOTO には同じ縮約がない (整数最適化の前処理は双対の議論の縮約を多く外している) → 試作 `DUALEQ` (4 章)。
  ただし neos859080 は今の既定で 1.6 秒・1629 ノードで実行不能を証明する (hiloss の 75 秒は旧い回) ので、`DUALEQ` (1.8 秒) の効き目はない。
- **net12: Enumeration**。根の LP の差 (68.4 対 128.3) は既存の `HO3_ENUM` で埋まる (128.29。highs_only G3 と同じ)。行の差 (14021 対 12728) は
  `prr0` (プロービングの後のかけ直しを使う) で 12783 になる。
- **puriri: Probing・Sparsify・Enumeration**。`spl` 5289、`prr0` 5262、`enum` 5194、全部で 4968 (HiGHS 3731)。根の LP は変わらない
  (根の LP の差は GAP4 の `q` で埋まる、analysis/gap4_rootstuck_mem_20261109.md §6.2)。
- **mzzv11・mzzv42z: Probing (+ かけ直し) と Aggregator**。ENOMOTO の最初の前処理の本体は何も減らさない (二項等式も列シングルトンもない
  全整数の問題、presolve_gap_20261022 と同じ)。プロービングの後のかけ直しは mzzv11 で 9499 → 9053 行 (4.7%) と減るが、「行が 10% 減らなければ
  捨てる」判定 (`ENOMOTO_T_MIP_PRR_MIN_ROW_FRAC`、drayage-25-23 の害の手当て、analysis/prr_harm_20261106.md) で捨てられ、根の LP は
  クリーク行の拡張で 127 行消えただけの 9372 行で解く。既存の試作を全部入れて 7463 行 (HiGHS 5723)。残りは HiGHS のプロービング
  (クリーク表を使う伝播と 4 回の繰り返し、mzzpre_20261024 §結論 1〜2) で、試作の組で届かない。
- **physiciansched6-2**: 根の LP の前では既定で 8621×4981 (HiGHS 8861×4608) と行はもう少ない。hiloss の 15889 行は最初の前処理の後の数。

## 4. 試作 `ENOMOTO_MIP_DUALEQ` (src/mip/mod.rs の `dual_row_equalities`)

- 規則: 列 j を目的の悪くならない向き (費用 ≤ 0 なら増やす、≥ 0 なら減らす) に動かすと破れうる行 (錠) がちょうど 1 本 r なら、どの最適解からも
  x_j をその向きに r が等号になるまで動かせば、目的は悪くならずほかの行は緩む向きにしか動かない。条件: (1) r が等号になる前に x_j の境界に
  当たらない (r から導かれる x_j の境界が x_j の境界の内側)、(2) x_j が整数列なら r のほかの列がすべて整数列で、係数と右辺が a_rj の整数倍、
  (3) 1 回で複数の組を選ぶときは、選んだ列はほかの選んだ行に出ない (動かす順によらず等号が保たれる)、(4) 1 行にしか出ない列は除く
  (列シングルトンの縮約に任せる)、(5) 等式にすると r のほかの列の双対の固定 (その向きに錠がなく目的も悪くならない列) を壊すなら選ばない。
  最適解の集合を狭めるだけ (実行可能な点は変えない) なので後処理は要らない。
- かける場所: **前処理の最後** (プロービング・同値の代入の後、`SPARSIFY_LATE` と同じ所)。等式にした行があれば前処理をもう一度かける
  (2 項等式の消去が整数列どうしの `y_b = 1 − y_a` を代入する)。再スタートの前処理・サブ MIP ではかけない。
- 経緯 (事実): 最初は前処理の前 (元の行) にかけた (`=early` として残す)。neos8 で 5591×1128 → 6503×1660 に**大きくなった**: 等式で
  プロービングが境界を 4 本締め、「境界を締めると同値な 0-1 列 (602 組) を代入せずに返る」既知の癖 (`probe_equiv_fix`) に当たる。gt2・flugpl も
  列が増えた: 元の行で錠を数えると、前処理で冗長として消える行 (gt2 の `25 x_180 + … ≥ 0`) も錠に数え、等式にした行の費用 0 の列 8 本の
  双対の固定を失う。前処理の最後にかける形にしてから、58 問で既定より大きくなる問題はない。
- 58 問で前処理が変わる問題 (`epre.jsonl` の deq4): neos-960392 1808 → 1647 行、beavma 327×352 → 317×342 (根の LP 170489 → 172198)、
  physiciansched6-2 8621 → 8611、flugpl 15×15 → 13×14、binkar10_1 822 → 821、ns1116954 (既定の回が 300 秒で根に届かず比べられない)。
- 誤答の検査 (`checks/`): `mip_fuzz_vs_highs.py 1800 0` (DUALEQ が働いた 246 問) bad 0、`fuzz_tiny.py 400 0` bad 0 (strict 13 は既知、
  前処理の最後の DUALEQ は働かない)。前処理の前にかけた版でも `mip_fuzz_vs_highs.py 300` (77 問で働く)・`1500 1000`・`fuzz_tiny.py 400 0` bad 0。
  `cargo test --release --lib` 400 通過・0 失敗 (libpython を `-C link-arg=-lpython3.13` で明示して別の target で)。
