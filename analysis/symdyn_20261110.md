  オービトープ (動的な orbitopal fixing) とは群が直積に分かれるので併用。lex-leader の行 (`NO_SYM_OF`) とは使わない。

- **効き目 (事実)**: 58 問 (60 秒・4 スレッド・種 1・2) で `refl` は SGM 16.44 → 16.12 (−1.9%、95% 区間 [−7.0%, +2.7%])、解けた

  (`refl` 26.8・18.1 → 14.7・10.7 秒)、neos5 もほぼ速い。47 問の対称性のある 13 問 (600 秒) で `refl` +3.0% [−17.1%, +31.9%]
  (cod105 が 2 回とも時間切れに悪化)、`reflo` +4.1% [−8.7%, +23.4%] (cod105 は既定並みに戻る)。
- **害 (事実)**: 生成元ごとの比べだけ (`dyn`/`refl`) は推移的な群で orbital fixing より弱い (cod105: 197.6・206.0 → 時間切れ・

  MIPLIB のこの 2 つの集合には max-cut・グラフ分割の形がなく、効き目を見る問題がない。

## 1. 実装 (`src/mip/symdyn.rs`、既存のファイルへの差分は小さく)

### (a) 動的な辞書式の縮小 `ENOMOTO_MIP_SYMDYN` (van Doornmalen・Hojny「A Unified Framework for Symmetry Handling」2022/2024、SCIP 9 の lexred)

- 各ノードで、根からそのノードまでの分枝の並び (`OpenNode::changes`、親の対称性の固定 `sym` の印を除く) の、列が最初に
  分枝された順 σ を辞書式の比べの順にする ([`symdyn::branch_order`])。子の順は親の順を延ばすだけ (両方の子が同じ列を足す)。
- 生成元 γ ごとに `σ(x) ≥_lex σ(γ(x))` (`γ(x)_v = x_{g(v)}`) を伝播する ([`DynSym::prop_one`]): 先頭から、両辺が同じ値に
  固定されている位置を飛ばし、最初に差が出うる位置 v で `x_v ≥ γ(x)_v` になるよう両方の列の境界を締める。締めて等しく固定
  されたら次の位置へ進む。等号が 1 つの値 c でしか成り立たないときは、等号を仮に置いて後ろの位置を境界だけで見て
  (`peek_equal_feasible`)、破れるなら等号を除く (整数列なら `x_v ≥ c + 1`、像の側 `≤ c − 1`。SCIP の lexred の peek と同じ考え)。
  真に大きいと決まった位置で止まる。締めたら行の伝播を回し、変わらなくなるまで繰り返す (最大 20 回)。
- 0-1 以外の整数列・連続列にもそのまま使える (連続列は等号を除く締めはしない)。
- 締めは「外から来た変更」(理由 tag 3、オービトープ・orbital fixing と同じ) として定義域に置くので、衝突解析はこれを文字として
  残し、学習した衝突は大域的に成り立つ。親の締めは子に渡さず、子で数え直す (順が延びるだけなので同じ締めが再び出る)。
- 生成元の出どころと使い分け:
  - 既定の orbital fixing (HiGHS 流、`SYM_OF_GENS`) の生成元をそのまま使い、**orbital fixing の代わりに**呼ぶ
    (`Solver::orbital_fixing_checked` の頭で分ける)。同じ群に、違う規則の代表を残す 2 つの処理を重ねると、両方に切られて
    最適解が全部消えることがあるので、両方は使わない。
  - オービトープ (動的な orbitopal fixing) とは混ぜる: orbital fixing の生成元は、もともとオービトープの列 (と、オービトープの
    生成元が動かす列) を動かさないものだけなので、群は直積に分かれ、成分ごとに別の処理を使ってよい (van Doornmalen・Hojny の
    枠組みの、直積の成分ごとの組み合わせ。論文本文は届かず未確認、SCIP 9 も成分ごとに orbitopal reduction と lexred を
    使い分ける)。
  - `ENOMOTO_MIP_NO_ORBITOPE=1` と合わせる (`dynall`) と、全ての生成元を辞書式の縮小で扱う。
  - lex-leader の行 (`ENOMOTO_MIP_NO_SYM_OF`) とは混ぜない (行は列の番号の順の代表を残す)。このときは `SYM_OF_GENS` が
    置かれないので試作は何もしない。
- サブ MIP では使わない。木の並列の従には `TreeSnapshot` の `of_gens`・`refl_gens` で渡し、従も同じ順の規則で数える。
  再スタートの後は orbital fixing と同じく生成元を確かめ直したもの (`sym_of_reverify`、反転は `symdyn::reverify`) を使う。

### (a'') 軌道の比べ `ENOMOTO_MIP_SYMDYN=o` (47 問の cod105 を見て足した)

- 生成元ごとの比べ `x ≥_lex γ(x)` は、生成元の数しか比べない。cod105 (推移的な群、生成元 11 個) では既定の orbital fixing が
  分枝 x_v = 0 の子で v の軌道全体 (1454 本) を 0 に固定して 14 ノードで解けるのに、`refl` (生成元ごとの比べだけ) は
  8653 ノードで時間切れになった (事実)。
- そこで、順の位置 i ごとに、先頭 v_1..v_{i-1} を動かさない部分群 H_i (既存の `OrbitalGens::schreier_stabilizer` を順に重ねて
  求める。軌道 4096・生成元 64 で打ち切れば部分群) での v_i の軌道 O_i について `x_{v_i} ≥ x_u` (u ∈ O_i) を締める
  (`DynSym::orbits_for`、先頭の並びごとに固定群と軌道を控える)。H_i の元 γ は先頭の位置を動かさないので、`x ≥_lex γ(x)` は
  位置 v_i の比べを含み、同じ「順で辞書式に最大の代表」の規則の一部になる (生成元ごとの比べ・反転と混ぜてよい。証明は自前で、
  論文の orbital reduction と同じものかは未確認)。推移的な群で v_1 を 0 に分けると軌道の全ての列が 0 になる。
- 2 本目のビルド: 計測の途中で入れたので、計測に使っていた版 (661a44ca) に `symdyn.rs` だけを載せて組み直した
  (既定・`dyn`・`refl` の動きは同じ)。`reflo` (`SYMREFL=1` + `SYMDYN=o`) の回はこのビルド。

### (b) 反転の対称性 `ENOMOTO_MIP_SYMREFL` (Hojny「Detecting and Handling Reflection Symmetries in Mixed-Integer (Nonlinear) Programming」2024)

- 検出 ([`detect_reflections`]): 有限の境界を持ち固定されていない列 j ごとに反転した列 x̄_j (同じ境界・整数性、費用 −c_j) を
  足し、各行を中心 ((lo + up)/2) からのずれで書いて x_j に係数 a、x̄_j に −a を置き、区間を中心の分だけずらした行と、その
  −1 倍の行の両方を置いた写し Q を作る。x_j と x̄_j は右辺が他と重ならない 2 列の行で結ぶ。Q の列の置換は組を組に写し、
  x_j → x̄_k は「x_j を x_k の反転に写す」と読める (論文の「各変数に x と −x の 2 頂点を置き、間に辺を張るグラフ」と同じ考え。
  検索の抜粋で確認、細部は未確認)。既存の検出 ([`symmetry::detect`]、色の細分化と探索) で Q の生成元を求める。
- 確かめ ([`verify_signed`]): 見つけた符号つきの置換 T (`(Tx)_v = r_v ? (lo_v + up_v − x_{g(v)}) : x_{g(v)}`) を元の問題で直接
  確かめる (動かす位置で境界・整数性が同じ、反転する位置で境界が有限、`c_v s_v = c_{g(v)}`、各行に T を代入した行が −1 倍を
  許して同じ区間で問題にある)。通らなければ逆元を試す。反転を 1 つも含まない生成元は捨てる (置換は既存の検出が持つ)。
- 扱い: (a) の辞書式の縮小に、`γ(x)_v = lo_v + up_v − x_{g(v)}` として足す (`SYMREFL` は `SYMDYN` も入れる)。0-1 列 v を自分の
  反転に写す生成元なら、v を最初に分枝したノードで `x_v ≥ 1 − x_v` から `x_v = 1` が出て、0 の側の子が刈られる (lex-leader と
  同じ考えで 1 本を 1 に固定するのに当たる。根では順が空なので何もしない)。
- オービトープの列を動かす反転の生成元は捨てる (直積の条件)。再スタートで境界が片側だけ締まると反転は崩れるので確かめ直す
  (乱数の max-cut では再スタートで全て落ちることがある)。サブ MIP・再スタート後の探し直し (HO6) では検出しない。
- 上限: 非零 200 万 (`ENOMOTO_T_MIP_SYMREFL_MAX_NNZ`)、検出の時間 1 秒 (`ENOMOTO_T_MIP_SYMREFL_TIME`)。

### 既存のファイルへの差分

## 6. 既定にする価値と次の一手

- 既定にはしない。(a) は生成元ごとの比べだけだと推移的な群で orbital fixing より弱く (cod105)、軌道の比べを足すと小さな群の
  問題 (qiu・neos5) で締めが増えて遅い。どちらの版も 58 問・47 問で既定より速いと言える差がない。(b) は MIPLIB のこの 2 集合に
  効く問題がない (反転があるのは supportcase33 だけで、その列は分枝されない)。
- 次の一手 (推測):
  1. orbital fixing (既定) と動的な辞書式の縮小を同じ「分枝の順で辞書式に最大」の規則で併用できるかを詰める。分枝で 0 にした
     列の軌道を 0 にする部分は同じ規則に収まる (自前の議論) が、伝播で固定された列の軌道を固定する部分は収まるか未確認。
     収まれば、orbital fixing を残したまま生成元ごとの比べを足せる (SCIP 9 は lexred と orbital reduction を併用する。論文本文は
     未確認)。
  2. 軌道の比べ (`SYMDYN=o`) を、軌道が大きい (推移的に近い) 群だけに使う (cod105 型だけ拾い、qiu 型を避ける)。
  3. 反転は max-cut・グラフ分割・符号の対称な割り当ての集合 (Hojny 2024 の試験集合) で確かめる。MIPLIB の 2 集合では評価できない。
  4. 反転の検出の写し (列 2 倍・行 2 倍) は重いので、置換の検出の結果で色を分けてから反転だけを探すなどで手間を減らす。
- 文献: van Doornmalen・Hojny「A Unified Framework for Symmetry Handling」(arXiv 2211.01295、2022/2024)、Hojny「Detecting and
  Handling Reflection Symmetries in Mixed-Integer (Nonlinear) Programming」(arXiv 2405.08379、2024、Math. Prog. Comp. 2026)。
  この環境から arxiv.org に届かず本文は読めていない。内容は検索の抜粋と SCIP の文書 (`prop_symmetry.c`: lexred・orbitopal
  reduction・orbital reduction の 3 つの動的な方法) で確かめた範囲で、peek の細部・直積の組み合わせの条件・反転の検出グラフの
  細部・論文の orbital reduction の定義は未確認。

## 7. 論文の本文で確かめたこと (2026-11-10 夕、arxiv.org に curl で届くようになった後)

van Doornmalen・Hojny (arXiv 2211.01295):
- 4.1 節の LexRed は、先頭から `x_t ≥ γ(x)_t` を伝播して等しく決まる間は進み、止まった位置で等号を仮に置いて矛盾を見る 2 段の
  算法 (命題 17: その制約について完全、O(n))。**この試作の `prop_one`・`peek_equal_feasible` と同じ** (事実)。
- 例 11 (分枝の順の構造): 根は空、子は初めて分枝した列を順の末尾に足す。一般整数を 2 度目に分枝しても順は変えない。**この試作の
  `branch_order` と同じ** (事実)。
- 補題 6・24・25: 0-1 列の orbital fixing (1 に分枝した列の集合を保つ部分群 ∆_bin の軌道で、0 に分枝した列の軌道を 0 にする) の
  固定は、分枝の順の `σ(x) ≥_lex σ(γ(x))` から出る。よって **orbital fixing と LexRed は併用してよい** (事実: 論文の主張)。
  ENOMOTO の既定の orbital fixing の部分群 (1 にした 0-1 列と分枝した一般整数列を動かさない元。Schreier を使うときも同じ部分群の
  元) は論文の ∆β に含まれ、「軌道のどれかの列が固定されたら全て同じ値」は補題 24 (軌道の列の定義域の共通部分) に当たる
  (自前の照合。補題 24 は対称性によらない締め (被約費用の固定など) が対称に扱われる前提を置いていて、その前提を ENOMOTO が満たすかは
  orbital fixing を既定にしたときと同じ扱い)。
- 補題 23 (orbital reduction): 分枝した列 x_i について、∆β の軌道の列 j に `x_i ≥ x_j`。**`SYMDYN=o` (順の先頭を点ごとに固定する部分群)
  は ∆β の部分群なので、この補題の弱い版に当たる** (事実: 部分群の軌道は ∆β の軌道に含まれる)。論文は ∆β の代わりに、
  ノードの境界で `σ(x) ≤ σ(γ(x))` が成り立つ生成元で張る部分群を使う。
- 5.1 節: **群を直積の成分に分け、成分ごとに扱いを選ぶ**。オービトープの成分は (a) 1 行なら `x_1 ≥ … ≥ x_ℓ` の行、(b) 2 列 (置換 1 個) なら
  LexRed、(c) パッキング・分割の行が 3 行以上ならパッキングのオービトープの静的な伝播、(d) それ以外は動的な orbitopal reduction。
  オービトープでない成分は LexRed と orbital reduction を併用。リスタートは止めて比べている。計算結果では、オービトープでない成分に
  orbital reduction と LexRed を併用すると orbital reduction だけより 6.6% 速い (1437〜1441 行目付近)。
- 3 本目のビルドで **`ENOMOTO_MIP_SYMDYN=f` (既定の orbital fixing を残し、その後に LexRed を足す) を入れた** (`fo` で軌道の比べも)。
  orbital fixing の代わりに使う `=1` は、論文の設定から orbital reduction を外したものに当たり、cod105 で弱かったのはそのため。

Hojny (arXiv 2405.08379):
- 反転の中心は列の境界の中点 ξ_i で、符号つきの置換は「−i への写し」と中心のまわりの反転・平行移動で表す。検出グラフは列ごとに
  x と −x の頂点を持ち、境界は中心からの相対で色を付ける (中心の違う列どうしの対称性も見つかる)。**この試作は境界が同じ列どうし
  だけを写すので、論文の検出の部分集合** (事実)。
- 扱い: 6.5 節で LexRed を符号つきの置換に広げる (この試作と同じ)。全部を反転する γ* には `Σ x_i ≥ Σ ξ_i` (max-cut で使える) も
  あるが、辞書式の方法とは併用できない (e_1 が反例) と書かれている。
- 7.3 節・表 1: SCIP で前処理の後に検出して、**MIPLIB 2017 の 1055 問のうち反転があるのは 60 問だけ** (置換の対称性は 504 問)。
  その 60 問で反転を扱うと解けた数は 14 → 17 に増えるが、平均の時間は対称性を扱わない場合より 4.7% 遅い。反転が効くのは max-cut
  (119 問)・充填・SAT 2002 (819 問のうち 282 問)。**この試作の 105 問で 1 問 (supportcase33) という結果と合う** (推測: 集合が違うので
  比率は直接比べられない)。

## 8. 群の成分への分解と、成分ごとの扱い (親のセッションからの追加の依頼)

診断 `ENOMOTO_MIP_SYMCOMP_DIAG` (`symdyn::component_diag`): 生成元を、動かす列の集まりで union-find にまとめた成分ごとに、
オービトープに使った生成元・orbital fixing に回した生成元・どちらにも使わず捨てた生成元の数と形 (orbitope = 全てオービトープ、
cyclic1 = 生成元 1 個 (巡回群) でオービトープでない、of = 全て orbital fixing、mixed = 混ざる・捨てたものあり) を数える。
58 問・47 問と neos859080・neos-2746589-doon・10teams の 90 問 (`symscan2.jsonl`、検出の直後で止める):

- 生成元のある 46 問、成分の計: orbitope 243、of 65、cyclic1 43、mixed 1 (事実)。
- **今の ENOMOTO はほとんど成分ごとに 1 つの扱いになっている** (事実): オービトープの判定は生成元ごとだが、orbital fixing に回す生成元を
  「オービトープの列を動かさないもの」に限るので、45 問は全ての成分が「オービトープだけ」か「orbital fixing だけ」。
  例外は sct2 の 1 成分 (2087 列・生成元 108: オービトープ 82・orbital fixing 22・捨てた 4)。この成分では同じ成分に 2 つの扱いを
  使っているが、orbital fixing の生成元はオービトープの列を動かさないので、オービトープの列とそれ以外の列で群が分かれる
  部分だけを使っている (捨てた 4 個が両方をつなぐ)。
- 成分が複数ある問題は 19 問 (rococoC10-001000 は生成元 1 個の成分が 41、sp150x300d は 92 成分 (orbitope 84・of 8)、neos8 は 54 成分)。
  オービトープでない成分を持つ問題は 18 問。
- 論文の扱いとの違い (事実): 2 列のオービトープ (置換 1 個) を、論文は LexRed、ENOMOTO は orbitopal fixing で扱う (mzzv42z の 2 成分、
  neos859080 の 80x2)。1 行のオービトープを論文は行で、ENOMOTO は双子のオービトープとして固定で扱う。オービトープでない成分は、

## 9. 反転を前処理の前に検出する価値 (親のセッションからの追加の依頼)

診断 `ENOMOTO_MIP_SYMREFL_PRE_DIAG`: `solve_problem_inner` の前処理の直前 (読み込んだまま) の問題に `detect_reflections` を掛けて数える
(求解は変えない)。同じ 90 問で (`symscan2.jsonl`):

| 問題 | 前処理の前 (生成元 / 反転する列) | 前処理の後 (今の場所) |
|---|---|---|
| traininstance6 | 1 / 5 列 (0.08 秒) | 0 |
| supportcase33 | 0 | 6 (反転する位置 計 18) |
| ほかの 88 問 | 0 | 0 |

- **前処理の前に見つかるのは 90 問中 1 問で、もともと少ない** (事実)。前処理で消えたのは traininstance6 の 1 個だけで、逆に
  supportcase33 は前処理の後にだけ現れる (前処理が境界や行を揃えた結果、対称になった。推測)。
- traininstance6 で崩れた原因: 前処理の後に「有限の境界を持ち固定されていない列」が 10218 列中 1181 列しかない (前処理の前は
  これより多い) ので、前処理が境界を外す (含意から自由な列にする) か列を固定・消去したことで反転の対象から外れたと見られる
  (推測。どの前処理かは下で調べる)。
- 論文 (Hojny 2024) も前処理の後で検出していて (SCIP の既定)、MIPLIB 2017 で 60/1055 問。
- **前に回す価値は今は小さい** (推測): 90 問で得られるのは traininstance6 の 1 個 (5 列) だけ。「前処理の前に反転を崩す行を足し、
  木では前処理の後に確かめ直したものだけを使う」形の試作は、max-cut・グラフ分割のような集合で反転が前処理の前にだけ見える
  問題が多いと分かってからでよい。
