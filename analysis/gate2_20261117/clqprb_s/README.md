# gate2 候補 2: CLQPRB を成果の比のシグモイドで入り切りする (`ENOMOTO_MIP_CLQPRB=1dgrs`、2026-11-17)

依頼: analysis/gate2_20261117/BRIEF.md の候補 2。プロービングの含意を後の伝播に使う形 (`CLQPRB`、analysis/clqprb_20261112.md・
analysis/prbimp_20261113.md) は mzzv11 を解けるようにするが puriri で解を失い、不採用・保留だった。問題の特徴の連続関数で入り切りする形に作り直す。

## 1. 分ける特徴 (記録からの数え。事実 + しきい値は結果を見て選んだもの)

`1dgr` (既定の形でプロービングし、何か得たら含意を使う形でやり直し、含意の形が既定の形より多く得なければ既定の結果に戻す) で
含意の形が残るのは、prbimp の P の 58 問・M の 48 問のうち 6 問だけ (`analysis/prbimp_20261113/pscreen.jsonl`、種 1)。
残りの問題は前処理が既定と同じで、`r` の時点で timtab1・widden・neos-860300 の害は消えている。

成果 = 固定 + 締め付け + 同値な組 (最初のプロービング)。比 ρ = 含意の形の成果 / 既定の形の成果。

| 問題 | 既定の形 (固定・締め付け・同値) | 含意の形 | ρ | 記録での結果 (含意の形) |
|---|---|---|---|---|
| neos8 | 0・0・602 | 0・0・2431 | 4.0 | P で 0.6 倍 (効き) |
| mzzv11 | 336・113・59 | 1520・317・(同値は不明) | ≥ 3.6 | 6 回とも解ける (既定は 6 回とも時間切れ) |
| mzzv42z | 355・104・100 | 926・455・(不明) | ≥ 2.5 | 計測で向きが逆 (0.62〜1.18)。slow2 では今の既定に対し強く効く |
| peg-solitaire-a3 | 0・6・0 | 0・6・(>0) | > 1 (不明) | 差なし (両方とも解なし) |
| **neos-3216931-puriri** | 304・40・16 | 354・171・113 | **1.77** | **6 回とも 81380 前後の解を失う** |
| 30n20b8 | 3283・0・0 | 3577・0・0 | 1.09 | 60 秒では両方時間切れ |

- puriri の害の仕組み (prbimp §1): 含意で増えた固定・締め付けで、ほぼ唯一の解の出どころ (根の後の locks の sub-MIP) の固定率が上がり実行不能になる。
  「含意の形が既定の形をわずかに上回るだけ」の問題で害が出て、大きく上回る問題 (mzzv11・neos8・mzzv42z) で効く、と読める。
- ただし分けられるのは実質 6 点で、puriri (1.77) と mzzv42z (≥ 2.5) の間に置くしきい値は楽観的。別の種・別の計測で確かめる前提。

## 2. 試作 `s` (src/mip/mod.rs の `probe`、`g`・`r` の続き)

- 戻すかを σ(k (ln ρ − ln ρ0)) で決め、0.5 未満なら既定の形の結果に戻す (`ENOMOTO_T_MIP_CLQPRB_S_RHO` = ρ0、既定 2、`ENOMOTO_T_MIP_CLQPRB_S_K` = k、既定 8)。
  今は 0.5 で切るので ρ ≥ ρ0 で使う形と同じ (k は強さを連続に変える後の拡張のための形)。`r` は ρ0 = 1 (ρ > 1 で使う) に当たる。
- 既定は変えない。`ENOMOTO_MIP_CLQPRB=1dgrs` で使う。

## 5. 漏れの修正 (2026-11-18、M 分担 6・7 の害の調べから)

M 分担 6・7 (種 3・4) で clqs だけ時間切れ: snp-02-004-104 (2 種とも)・supportcase40 (種 4、種 3 は 494.7 → 597.2)・net12・tbfp-network。親の依頼で調べた。

- **漏れ (事実)**: 前処理のかけ直し (プロービングの後の `depth` > 0) で含意を引き継ぐ処理 (`presolve_mip_depth` の `keep_impl`) が `clqprb_on()` だけで入っていて、
  `g` で判定が入らない問題・`r`/`s` で既定の形に戻した問題でも働いていた。既定と前処理の結果が変わるのは、前処理のかけ直しのある問題
  (`pscreen_def.jsonl` と `pscreen.jsonl` の見比べ: blend2 の根の LP 6.916 → 7.044、neos-4722843-widden 13920×4459 → 14217×4648。再スタートの後のかけ直しでも同じ)。
- **修正**: `keep_impl` を、含意の形に切り替えた求解 (`CLQPRB_STICKY`) で、戻していない (`CLQPRB_REVERTED` でない) ときだけにした (`g` を使わない形は以前のまま)。
  修正後 (`pscreen_fix.jsonl`): blend2・widden は既定と同じ前処理。mzzv11・neos8 は含意の形のまま (5496×6488・4457×560)。
  cargo test 419 通過、fuzz_tiny 400・mip_fuzz_vs_highs 300・fuzz_slack 1000 で誤答 0。
- **4 問の読み (事実 + 解釈)**: supportcase40・net12・tbfp-network は、同じ種なら根の下界と最初の解 (時刻・値) が def と clqs で完全に同じ
  (`res_M_s6・s7.jsonl` の `root_bound`・`first_solution_*`)。プロービングで何も得ない (supportcase40 は判定も入らない) ので、違いは木の中の 4 スレッドのゆれ。
  どれも def が 600 秒近く (494.7〜588.7 秒) で解けている境目の問題。snp-02-004-104 は `g` の判定が入るが ρ = 1.0 で戻り、修正前でも前処理は 1 回で
  かけ直しがない。**同じ設定・同じ種 3 でも根の下界・最初の解が大きく変わる** (90 秒で 2 回ずつ、`res_R0〜R3_s0.jsonl`: def の根の下界 5.6049e8・5.8678e8)。
  satellites2-60-fs・snp は def どうしでも前処理の列の数が時間でゆれる (33980・33969)。害の仕組みは見つからず、ゆれの大きい問題と読む。
- **計測への影響**: M 分担 6・7 と P 分担 0 (と P 分担 1 の最初の 5 行) は修正前のビルド。漏れで変わるのは前処理のかけ直しのある問題で、`g` で何も得ない問題も含む。
