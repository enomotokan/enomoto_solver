## 結論

**作り直しは見送り (計測の依頼はしない)。** 今の既定の上では、特徴で入り切りする前提の「効く群」がなく、記録にある害の仕組みも起きない。

1. 古い記録 (b58.jsonl、0.1.9 より前) でも、静的な特徴 (根の 0 ラウンド目の候補数 / 余裕 0 の行の数、連立の大きさ) は害と効き目を分けない
   (害の physiciansched6-2 0.127、効く misc07 0.73、600 秒で効く comp21-2idx 0.052・mushroom-best 0.025)。2 回とも揃って動いたのは
   physiciansched6-2 (遅い) と h80x6320d・misc07 (速い) だけで、残りは試作の候補が 0〜18 本の問題の揺れ。
2. 今の既定の上の当て直し (事実、下の表): 試作のどのログにも「カットの LP が上限に当たった」行がない (physiciansched6-2 の 0 ラウンド目も
   281 本・2076 反復で最適)。害の仕組み (0 ラウンド目の LP が反復の上限 → ループが止まる) は、その後の既定 (CUTLPCAP=ac など) で消えている。
   そのため試作 `ENOMOTO_MIP_MODKVB_CAPDROP` (上限に当たったら MODKVB のカットだけ外して解き直す、src/mip/separation.rs) は一度も働かない。
3. 効き目も消えた: h80x6320d は差なし、misc07 は根の下界 1425 → 1527 と上がるのに 2 回とも遅い (2.1 → 4.0 秒・2.4 → 3.5 秒。
   カットのプールの非零 1591 → 49626 と密な行が入り、ノード 6447 → 9693)。mc11 は 2 回とも遅い (26.2 → 39.4・16.8 → 28.1 秒)、swath1 も 2 回とも遅い。
4. 残る効き目の見込みは 600 秒の comp21-2idx・mzzv42z・mushroom-best (古い記録、上限なしの形) だけで、それらと害の問題を分ける特徴は見つからない。

## 残したもの

- `ENOMOTO_MIP_MODKVB_CAPDROP` (既定では使わない、MODKVB と組のときだけ) はコードに残した。今の既定では働かないので cargo test・fuzz・計測はしていない。
- 気づき (推測): misc07 では試作が根の下界を大きく上げても、密なカットでノードの LP が重くなって遅い。MODKVB を見直すなら、特徴での入り切りより
  集約行の長さ (非零) の上限を問題の大きさの連続関数にする方が先。
