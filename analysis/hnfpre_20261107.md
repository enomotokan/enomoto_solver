# 整数列だけの等式の Hermite 標準形による前処理 (試作 `ENOMOTO_MIP_HNFPRE`) (2026-11-07)

bench に使う環境変数: 既定 (`def`) はなし。試作は `ENOMOTO_MIP_HNFPRE=1` (`hnf`、実行不能・固定・合同式の上下限の丸め + 分枝と伝播の丸め)。
ほかに `=count` (数えてログに出すだけ、問題は変えない)・`=bounds` (根の上下限だけ)、`ENOMOTO_MIP_HNFPRE_QUIET=1` (ログを出さない)、
`ENOMOTO_T_MIP_HNFPRE_WORK` (手間の上限、既定 3e8。数え上げは 3e9)。どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_MIP_LOG=1`・`ENOMOTO_T_MIP_SEED=回`。
試作は既定では使わない。

## 結論

- **当たるのは少数だが、当たれば大きい** (事実): 前処理の後に整数列だけの等式の格子から何か (実行不能・固定・合同式) が出るのは、58 問で 2 問、
  Mittelmann 186 問で 15 問、MIPLIB 2017 の実行不能の 45 問で 8 問。60 秒・2 回の比べで、
  - 実行不能の証明: **neos-952987 は既定が 60 秒で終わらない → 0.14・0.19 秒**、neos-3218348-suir 10.9・9.0 → 0.91・0.94 秒、
    enlight11 17.9・11.4 → 0.01 秒、enlight9 2.6・2.0 → 0.01 秒、maritime-jg3d9 55.1・59.7 → 41.8・42.4 秒 (固定 3 本)。
  - 最適化: enlight_hard 2.7・2.5 → 0.01 秒 (0-1 列 100 本が法 2 の合同式で全部固定され、前処理で解ける)、neos-3083819-nubu 7.6・7.4 → 5.9・6.0 秒 (固定 10 本)。
  - 合同式が上下限を詰めない (分枝・伝播の丸めにだけ使う) 問題 (brazil3・mzzv11・rococo・traininstance など) は 60 秒では両方とも時間切れで、差は見えない。
- **neos859080 はこの型ではない** (事実): 整数列だけの等式は 39 本 (0〜10 の整数列 80 本の ±1 の和が 0) で、格子は階数 39・列 80、
  合同式・固定・実行不能のどれも出ない。この問題の実行不能は上下限と 0-1 列の組み合わせから来るもので、格子だけでは見えない。
- **market split 型 (markshare) には、この試作 (1 列ごとの合同式) は当たらない** (事実): MIPLIB の markshare は等式に連続のスラック列が入り、
  前処理の後には等式が残らない。スラックを除いた実行可能性問題でも、0-1 列の格子からは 1 列ごとの合同式は出ない。
  一方、AHL (2000) の「x = x_d + Q λ (Q は LLL で簡約した核の基底) と書き直して λ で分枝する」を Python で作って ENOMOTO に渡すと
  (§6)、スラックを除いた markshare_5_0 (5 行・40 列) は **元の形が 120 秒・1100 万ノードで終わらない → 16.2 秒・3 万ノード**、
  markshare1 (6 行・50 列) は 120 秒で終わらない → 58.4 秒で実行不能を示した (どちらも約 12 秒は両方の形に共通の初めの FJ)。
- 害 (58 問、60 秒・4 スレッド・種 1・2、事実): SGM 15.39 → 15.24 (−0.9%、95% 区間 [−4.1%, +2.8%]、p=0.64)、解けた回 87 → 85。
  既定だけ解けた 2 回 (physiciansched6-2・timtab1 の種 2) は格子から何も出ない (問題が変わらない) 問題なので、回ごとの揺れ。
  58 問で問題が変わるのは flugpl・neos-3083819-nubu の 2 問だけで、ほかの問題の手間は解析の数ミリ秒。
- 誤答の検査: `fuzz_tiny.py 400 0` は既定と同じ 13/400 (既知の件、同じ seed)、`mip_fuzz_vs_highs.py 300` 0 件、合同式の出る乱数の問題
  (`fuzz_hnf.py 1000 0`) 0 件。`cargo test --release --lib` は §7。
- 次の一手 (推測): (1) 実行不能の判定と固定・上下限が詰まる合同式 (`=bounds` 相当) は手間がほぼ 0 (8div を除き 0.06 秒以下) で、検査で誤りも
  出ないので、既定に入れる候補。入れる前に、手間の上限 (8div-n59k10 は 3e8 で 1.6 秒使って諦める) を時間でも抑えること、Mittelmann の 600 秒で
  当たる問題 (maritime 型・atlanta-ip) を見ること。(2) 分枝の丸めだけの合同式 (brazil3・rococo・traininstance など) は 60 秒で差が見えないので
  後回し。(3) market split 型には AHL の書き直し (列を λ に置き換える前処理) が要る。列の番号を保つ今の前処理の枠の外なので、
  「等式の成分がすべて 0-1/整数列で、核の次元が小さい (n − m ≤ 50 程度)」問題に限って、書き直した問題を別に解く形で試すのがよい。

## 1. 作ったもの (事実)

`src/mip/hnf.rs`。前処理 (`presolve_mip`、`ENOMOTO_MIP_SPARSIFY_LATE` の後) の結果の問題に対して:

1. 等式 (`row_lo == row_up`) のうち、固定されていない列がすべて整数列 (尺度の掛かっていない列) のものを集める。固定された列 (連続列も) は定数として右辺へ移す。
   係数と右辺は連分数で分母 1000 以下の有理数にし (相対 1e-9 の誤差まで)、行ごとの分母の最小公倍数 (1e6 まで) を掛けて整数にする。できなければその行は使わない。
2. 列を共有する等式の連結成分ごとに、`[A; I]` に単模な列の操作をかけて `A U = [H 0]` (H は下三角) にする。行は「活きた候補の列の少ない順」に選び、
   行の中では絶対値の最小 (同じなら非零の少ない) 列で他の列を割った余り (最も近い整数の商) にする (Euclid の互除法)。値は i128 で持ち、
   積・和は溢れを検査し、絶対値が 2^96 を越えたらその成分は諦める。手間 (列の操作で触った非零の数の合計) が上限を越えても諦める。
3. `H y = b` を選んだ行の順に前から解く。軸で割り切れない・軸のない行の残りが 0 でなければ **実行不能**。解ければ `x0 = U y` と核の基底 (U の残りの列) N から、
   列 j について N の j 行の gcd g を取り、g = 0 なら **固定** `x_j = x0_j`、g > 1 なら **合同式** `x_j ≡ x0_j (mod g)`。
4. 使い方: 実行不能ならそこで終わる。固定と合同式で上下限を詰め (下限は合同式に合う最小の値まで上げ、上限は最大の値まで下げる)、詰まれば前処理をかけ直して
   (尺度が掛かっていなければ) もう一度解析する (最大 4 回)。`=1` では、合同式が残れば解く直前の最終の問題 (クリーク行・対称性の行の追加、
   前処理のかけ直しの後) で解析をやり直して表を作り、`Domain::tighten_lower/upper/global` (伝播・強分枝の固定) と分枝の子の上下限
   (`x ≤ floor(v)` → 合同式に合う最大の値、`x ≥ ceil(v)` → 最小の値) の丸めに使う。
5. 単体テスト 4 本 (`mip::hnf::tests`: gcd の実行不能、2 行の有理数の解だけの実行不能、合同式と固定、丸め、有理数への変換)。

試作の範囲の外 (しなかったこと): 列の置き換え `x = x0 + N λ` で問題を書き直すこと (列の番号を保つ前処理の枠に入らない)、2 列以上の組み合わせの合同式
(例えば neos859080 の行は「和が偶数」を言うが、1 列の合同式にはならない)、連続列の暗黙の整数性の検出。

## 3. neos859080 (事実)

## 6. market split と置き換え x = x_d + Q λ (AHL 2000 の見積もり) (事実)

`ahl.py`、`ahl.jsonl`。market split の実行可能性問題 (0-1 の x、`A x = d`、目的 0) を 2 つの形で作り、ENOMOTO (既定) に 4 スレッド・120 秒で解かせた:

- 元の形 (`orig`)。
- AHL (2000) の書き直し (`ahl`): 埋め込み `[[I, 0], [0, N1], [N2 A, -N2 d]]` (N1 = 1000、N2 = 100000) の基底を LLL (fpylll) で簡約し、
  最後の m 成分が 0 の n − m 本を核の基底 Q、N1 の成分が ±N1 のものから `A x_d = d` の x_d を取る。変数は整数 λ (上下限なし)、行は `0 ≤ x_d + Q λ ≤ 1`。
  LLL は 0.004 秒以下、Q の要素の絶対値は全部 2 以下。

### 9.1 既定の誤答: 稠密 LU が構造的に特異な基底を受け入れていた (修正、既定に入れた)

- 見つけ方: §9.2 の書き直しを乱数の問題 (`fuzz_lat.py`) で確かめていて誤答が出た。書き直した問題を MPS に書き出す
  (`ENOMOTO_MIP_HNFPRE_LAT_DUMP`) と、**既定の ENOMOTO がその 8 列の MIP (`wrong_q4.mps`) を 2・4 スレッドで解くと最適値 15.2 を返す**
  (HiGHS と 1 スレッドの ENOMOTO は −37.4)。`wrong_q732.mps` (13 列) も同じ型 (−203.5、正しくは −213.7)。
- 切り分け: 前処理の後の問題には最適解が入っている (`ENOMOTO_MIP_DEBUG_SOL`)。根の LP が、前処理の LP のプロービングの「列だけの基底」
  (行が変わったので行の状態は捨てる) から解き始めて、誤った「最適」(129.6、正しい LP の最適値は 77、どちらも定数 −114.4 を足す前) を返す。
  `ENOMOTO_MIP_PROBE_BASIS_DIAG=wcf` で、基底あり 15.2・基底なし −37.4・作り直し −37.4。出発の点の主実行不能の和が 3e17。
- 原因: その基底 (7 行) は、行 3〜6 の 4 行に非零を持つ列が 3 本しかなく**構造的に特異**。7×7 で非零が 22 個なので稠密 LU
  (`factorize_dense_faer`) に回り、そこは U の対角が**厳密な 0** のときだけ特異とする。消去の打ち消しで残った 6.7e-17 を軸に取り、基底解が
  1e17 になって、その後の単体法が誤った「最適」を返した。疎な Markowitz 分解はこの行列を特異と判定する (単体テストで確かめた)。
- 修正 (`src/simplex/lu.rs`): 稠密 LU で、対角の絶対値が元の列の最大の絶対値の `ENOMOTO_T_LU_DENSE_SING_TOL` (既定 1e-11) 倍以下なら特異とする
  (部分ピボットは残りの列の最大を選ぶので、それがそこまで小さければ列は数値的に従属)。特異なら呼び手の修復 (スラックに差し替え) に回る。
  単体テスト `simplex::lu::hnf_singular_tests::structurally_singular_basis_is_rejected` (稠密・疎の両方の経路)。`=0` で以前の判定。
- 確かめ: `wrong_q4.mps` は 2・4 スレッド × 種 1〜3 の 6 回すべて −37.4、`wrong_q732.mps` −213.7。`fuzz_lat.py 1000 0` (書き直しあり) は
  修正なしで 1 件 (seed 4)・修正ありで 0 件。害は §9.4。

  列だけの基底を渡す経路 (`analysis/probe_basis_20261106.md` の「列だけの基底は 11/11 問で特異」) では起こりうる。

### 9.2 書き直し x = Uᵀν をソルバーに入れた (試作 `ENOMOTO_MIP_HNFPRE_LAT`、既定では使わない)

`src/mip/hnflat.rs`。外側の求解 (`solve_problem` の入口) で、元の問題の整数列 x (n_I 本) を `x = Uᵀ ν` と置き換えた問題を解き、解を戻す。
- U は埋め込み `[e_j | N A_eq e_j]` (A_eq は等式の行の整数列の係数、N = 1e4) の行を LLL (δ = 0.99、Gram–Schmidt は f64、行の操作は i128 の整数で
  溢れを検査) で簡約した基底の前半。先頭の n_I − 階数 本は A_eq の核になる (AHL 2000 の向き)。U は単模なので問題は同値。
- ν の上下限は ν = U⁻ᵀ x と x の箱から出す (U⁻¹ は f64 の Gauss–Jordan で求めて丸め、U U⁻¹ = I を整数で確かめる)。元の整数列の上下限は行になる。
  連続列はそのまま。戻した解が元の問題で実行可能でなければ、書き直さずに残りの時間で解き直す (安全網、検査では一度も通らなかった)。
- 使う条件: 整数列 2〜120 本 (`ENOMOTO_T_MIP_HNFPRE_LAT_MAXN`)・すべて上下限が有限、整数列の係数が整数で 3 列以上・最大 2 以上の等式がある、
  固定されていない連続列を 2 本以上含む等式がない (pk1 で悪くなったので足した。手元の問題に合わせた条件)。
- 条件に合う問題 (245 問のうち MPS が 3MB 以下のもの、`lat_candidates.txt`): markshare_4_0・markshare_5_0・markshare1・markshare2・pk1 の 5 問
  (pk1 は最後の条件で外れる)。58 問には無いので 58 問の動きは変わらない。

(結果は §9.3)
