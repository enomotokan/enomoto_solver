# 「カット (根の下界が弱い)」型の負けの原因 (2026-11-23、利用者の依頼「全部やって」)

analysis/losses_20261123 の 6.3 節で「カット (根の下界)」型とした 13 問のうち、istanbul-no-cutoff・net12・ns1830653・mcsched・swath1 と
mzzv11・seymour1・tbfp-network の根の下界を、当方・SCIP・HiGHS で同じ条件 (1 スレッド・ノード 1 (根だけ)・600 秒・種の既定) で取り直し、
差の出どころを前処理とカットに分けた。ビルドはブランチの先頭 (b5908a4ff、pip install -e .)。

## 台本

- `ours_root.py 問題 [名札] [ENV=値 ...]`: 当方の根 (ENOMOTO_MIP_LOG・ENOMOTO_MIP_SEPSTAT)。`OURS_MPS=パス` で別の MPS (相手の前処理後の問題) を解く。→ `ours.jsonl`・`logs/ours_*.log.gz`
- `scip_root.py 問題 [切る分離器,... | allsep | -] [設定=値 ...]`: SCIP 10.0.2 (pyscipopt 6.3.0) の根。ログの表の行 (時刻・カット数・ラウンド・下界) を拾う。→ `scip.jsonl`・`logs/scip_*.log`・`.stat`
- `highs_root.py 問題 [名札] [オプション=値 ...]`: HiGHS 1.15.1 の根 (mip_max_nodes 1)。`WRITE_PRESOLVED=1` で前処理後の問題を `presolved/` に書く。→ `highs.jsonl`
- `scip_presolved.py 問題`: SCIP の前処理後 (変換後) の問題を `presolved_scip/` に書く。
- `survey.sh 問題 ...`: 上の 3 者と hpre (HiGHS の前処理後の問題を当方に解かせる) を 1 本ずつ順に回す。`tab.py` → `tab.md` (表)。
- 前処理後の MPS (presolved/・presolved_scip/) は大きいのでコミットしない (作り直せる)。

## 1. 根の下界の 3 者比べ (tab.md)

losses 6.3 節の「SCIP 204」「HiGHS 214」などは相手の **最終の下界 (解けたなら最適値)** で、根の下界ではなかった。根どうしで比べると:

| 問題 | 当方 根の LP → カット後 | SCIP 根の LP → カット後 | HiGHS 最初の LP → カット後 | 当方 (HiGHS の前処理後) | 見立て |
|---|---|---|---|---|---|
| net12 | 68.40 → 79.48 | 68.40 → 82.28 (強分枝の後 83.44) | **128.31** → 130.33 | 128.31 → 129.99 | HiGHS の前処理 (enumeration) |
| istanbul-no-cutoff | 55.14 → 71.00 | **66.83** → **132.29** | 6.33 → 74.44 | 60.72 → 75.95 | SCIP の前処理 (probing と linear の繰り返し) + cmir |
| ns1830653 | 6583 → 10721.5 | 7083 → 11633.4 | 6797.3 → 11622 | 6797.3 → 11622 | HiGHS の前処理 (probing) + その形でのカット |
| mcsched | 193775 → 193787 | → 193830 (193839) | 193775 → 193795 | → 193788 | 根の差はない (最終の 211913 は木) |
| swath1 | 334.50 → 340.58 | 334.50 → 340.86 | → 340.86 | → 340.87 | 根の差はない |
| mzzv11 | −22535.3 → −21855.9 | −22945.2 → −21861.9 | −22419.4 → −21838.2 | → −21838.3 | 根の差はない (HiGHS の 1 ノードは根の後の解探し) |
| seymour1 | 404.35 → 405.88 | → 406.65 (406.94) | → 405.69 | → 405.69 | 根の差は小さい (SCIP +0.8) |

(SCIP の「根の LP」の列は表の最初の LP の行。tbfp-network は計測中。)

- 根の下界の差が大きいのは net12・istanbul-no-cutoff・ns1830653 の 3 問で、どれも **前処理** から始まる。mcsched・swath1・mzzv11・seymour1 は根の差がほとんどなく、
  「カット」型ではない (木か解探しの差)。

## 2. net12: HiGHS の enumeration 前処理

- HiGHS の前処理後の問題を当方に解かせると根の LP 128.31・カットの後 129.99 (HiGHS 130.33 と同じ)。差は前処理。
- `presolve_rule_off` で規則を 1 つずつ切ると、根の LP を 68 → 128 にするのは **kPresolveRuleEnumeration (ビット 16)** だけ (ほかは 128 のまま。
  Probing を切ると 128.29)。HPresolve::enumerateSolutions: 8 列以下の純 0-1 の行 (最大 400 行、重なり 50% 超を除く、空振り 6 回続けばやめる) の割り当てを
  伝播つきで全部書き出し、全部の解で共通の境界・クリーク・2 列の一致 (x = y)・相補 (x = 1 − y) を入れる。net12 では、詰め込みの行の 2 列を相補で置き換えた行
  (例 R0633: a + b + c + d ≤ 1 → a + c ≤ y) が LP を締める。
- 当方にも同じ前処理の試作 `ENOMOTO_MIP_ENUM_PRESOLVE` (既定オフ、`enumerate_rows`) がある。そのままでは 30 行で空振りの上限 (6 回) に当たり、
  見つける組は probing と同じ 35 組で根の LP は 68.40 のまま。**行の数・空振りの上限を外す** (`ENOMOTO_T_MIP_ENUM_ROWS=100000 ENOMOTO_T_MIP_ENUM_FAILS=100000`) と
  953 行・0.05 秒で 154 組・6 固定、**根の LP 128.29・カットの後 129.72** (HiGHS 並み)。
- HiGHS が同じ上限で止まらないのは、行の並べ方 (列のクリークの含意の数の積で並べる) と、クリークを足しただけでも「空振りでない」と数えるためと見る
  (当方は固定・締め付け・組だけを数える)。

## 3. istanbul-no-cutoff: SCIP の前処理 (probing と linear の繰り返し) と cmir

- 整数列は 30 本だけ (連続 5252 本)。SCIP の根は 66.83 → 132.29 (53 ラウンド)。
- SCIP の分離器を切る (allsep・aggregation・cmir・flowcover・impliedbounds・mixing・gomory): cmir を切ると 88.3、aggregation 全体で 78.1、ほかは 115〜140。
  効くのは **cmir** (6730 本)。
- SCIP の前処理を切る (presolving/maxrounds=0) と根の LP 51.11・カットの後 79.21 (当方 71.0 に近い)。前処理器を 1 つずつ切ると (カットは切って根の LP だけ)、
  効くのは **probing** (切ると 68.07 → 52.63)。linear を切ると 63.24。SCIP は probing (14294 本の境界の変更) と linear の前処理 (係数の締め 47989・左右辺 21087) を
  13 周交互に回し、締めた連続列の境界で係数を締め、その係数でまた probing が締める。
- SCIP の前処理後の問題を当方に解かせると根の LP 66.83・**カットの後 100.10**。前処理で 71 → 100、同じ問題でのカットの差で 100 → 132。
- 当方は probing で 904 本の境界を締めるが、固定が 0 本なので「プロービングの後の前処理のかけ直し」を飛ばす (`ENOMOTO_T_MIP_PRR_MIN_FIXED` 1)。
  `ENOMOTO_T_MIP_PRR_MIN_FIXED=0 ENOMOTO_T_MIP_PRR_MIN_ROW_FRAC=0 ENOMOTO_T_MIP_PROBE_REPRESOLVE_MAX=20` で 11 周 (係数の締め 3772・5268・5137・… と減っていく) 回すと
  根の LP 60.94・カットの後 84.22 (71.0 から)。SCIP の 66.83 には届かない (締めた境界の数が SCIP の半分ほど)。

## 4. ns1830653: HiGHS の probing と、その形でのカット

- HiGHS の前処理後の問題を当方に解かせると根の LP 6797.3・カットの後 11622 (HiGHS と同じ)。規則を切ると、根の LP を 6583 → 6797 にするのは **Probing (ビット 15)**
  だけ (整数列 53 本を消す)。
- 当方の probing も、含意を使うやり直し (CLQPRB) で 79 本固定する (既定の probing は 46 本) が、得の比 1.891 が閾値 `ENOMOTO_T_MIP_CLQPRB_S_RHO` (2.0) に届かず、
  やり直しの結果を捨てている。閾値を 1.0 にすると根の LP 6797.3 (HiGHS と同じ) になるが、カットの後は 10883.7 (HiGHS の前処理後なら 11622)。
  当方の前処理後の形では rows_cmir の候補が 0 本 (HiGHS の前処理後では 40 本・得 650) で、残りの差はこの形の違い (調べ中)。

## 途中のまとめ

- 「カット」型の 13 問のうち、ここで見た 8 問で根の下界の差がはっきりあるのは 3 問で、3 問とも差の始まりは前処理 (net12: 列挙、istanbul: probing と
  係数の締めの繰り返し、ns1830653: 含意を使う probing)。分離器そのものの差は istanbul の cmir (同じ問題で 100 対 132) と ns1830653 の rows_cmir に残る。
- 計測の注意: survey.sh の計測と、上の切り分けの 1 本ずつの計測は一部重なって回した (どれも 1 スレッド、根の下界は時間にほとんどよらない。当方の根のカットの
  時間の上限 60 秒に当たる net12 の 12 ラウンド目だけは時間による)。
