# bnatt400: 1 スレッドで解が出ない原因の切り分けと試作 (2026-11-23、親の依頼)

親の依頼 (利用者の「全部やって」の一部): analysis/losses_20261123 の 6.4 節で、bnatt400 は根の下界が SCIP と並ぶ (0 対 0、最適値 1) のに、
当方 1 スレッドは時間切れ (最初の解 558 秒)、4 スレッドは 239 秒、SCIP (1 スレッド) は 147 秒だった。何が解を出すかを調べ、直しの試作を作る。

- 台本: `one.sh 問題 種 秒 スレッド 札 [K=V ...]` (heur1t_20261123 の写し、当方を `ENOMOTO_MIP_LOG=1` で 1 回解き、`res_one.jsonl` に 1 行)。
  `scipab.py` (presym_20261123 の写しに、部品の群をまとめて切る `HEUR=off`・`SEP=off`・`PRESOL=off` を足した)、`scipabl.sh 秒 名前 パラメータ...`
  (SCIP を 1 回解き、`scipabl.txt` に結果・最初の解 (ノード・秒・出した部品)・runs の数を 1 行)。ログは logs/ (コミットしない)。
- 当方はブランチ d096fdf94 + 下の試作 (`pip install -e .`)、SCIP 10.0.2 (pyscipopt 6.3.0、1 スレッド、randomseedshift = 種)。
- 先行の調べ: analysis/p2inf_20261119 の 4.2〜4.17・5 節 (衝突の中身・分枝の得点を詳しく追い、衝突の重みの RAMP・LIT_EXPLAIN=sig を既定にした)、
  analysis/presym_20261123 の 7〜9 節 (SCIP-VB: 衝突解析を切る・分枝の衝突の重みを 0 にすると SCIP も解けない)。

## 1. 何が解を出すか (事実)

| 回 | 結果 | 最初の解 |
|---|---|---|
| 当方 4 スレッド 種 1 (400 秒) | 291.6 秒で最適、全スレッドで 21455 ノード | 289.6 秒、別スレッドの木 (そのスレッドの 4741 ノード目) のノードの LP が整数 |
| 当方 1 スレッド 種 1 (600 秒) | 時間切れ (暫定解 1)・12170 ノード | 594.6 秒、木 (12113 ノード目) |
| 当方 1 スレッド 種 2・3 (600 秒) | 時間切れ・解なし (12750・13300 ノード) | なし |
| SCIP 1 スレッド 種 1〜4 (300 秒) | 141.7 秒・時間切れ・164.5 秒・277.3 秒 | 467・6325・2342・6303 ノード目 (27.4・248.3・89.2・169.4 秒)、4 回とも木の LP (relaxation) |

- 根のヒューリスティクス (丸め・RENS・locks・FP・ダイビング・robust FJ・Local-MIP・局所探索・repair) は 4 スレッドでも 1 つも解を出さない
  (10.9 秒、`after root heuristics: incumbent None`)。当方・SCIP とも、解は**木のノードの LP が整数になって出る**。
- 当方の 1 スレッドと 4 スレッドの差は、ノードあたりの効率ではなく処理量: 4 スレッドの最初の解は全スレッドの約 2.1 万ノード目、1 スレッドは
  1.2 万ノード目 (種 1) か 1.2〜1.3 万ノードで解なし (種 2・3)。並列の解探し (Local-MIP・サブ MIP) が出したのではない。
- SCIP との差は 2 つ:
  1. 最初の解までのノード数: SCIP は 467〜6325 (種で大きく揺れる、4 種の中央値約 4300)、当方は 1.2 万〜2 万超。
  2. ノードの速さ: SCIP は LP 1 本 275 反復・1 反復約 90 µs (双対単体法 1.1 万反復/秒)、当方は 356 反復・約 250 µs (4000 反復/秒)、ノードの LP 1 本
     88 ms (LP の時間が全体の 95%)。LP の行は SCIP 約 4500・当方約 5400 で 2 割多いだけなので、差の大半は LP の 1 反復の速さ
     (p2inf 4.2 節の 193 µs/反復、ftran 36% と同じ型)。
- 種 1 で解が出た後も、1 スレッドでは「目的値 0 の解がない」証明が残りの時間で終わらない (`GAP1=ur` 種 1: 364 秒に解、600 秒で下界 0 のまま)。
  4 スレッドは解が出て 0.6 秒で証明できた (ほかのスレッドの木が進んでいた)。SCIP も解の後の証明に 100 秒前後かかる。

## 2. SCIP の部品を 1 つずつ切る (1 スレッド・種 1・300 秒、scipabl.txt、事実)

| 切ったもの | 結果 | 最初の解 (ノード・秒) |
|---|---|---|
| なし (既定) | 141.7 秒で最適・4098 ノード (再スタート 1 回) | 467・25.6 |
| 衝突解析 (`conflict/enable=False`) | 時間切れ・解なし・13613 | – |
| ヒューリスティクス全部 (`HEUR=off`) | 時間切れ・12010 | 8709・223.4 |
| 分離全部 (`SEP=off`) | 137.8 秒で最適・12347 | 9257・104.9 |
| 前処理 (`PRESOL=off`) | 時間切れ・解なし・10211 | – |
| 分枝を推論だけ (`branching/inference/priority=100000`) | 時間切れ・解なし・10797 | – |
| 分枝を擬似費用だけ (`branching/pscost/priority=100000`) | 時間切れ・14105 | 8091・239.4 |
| ノード選択を深さ優先 (`nodeselection/dfs/stdpriority=1000000`) | 189.9 秒で最適・6871 | 1655・37.7 |
| 対称性 (`misc/usesymmetry=0`) | 147.5 秒で最適・4098 (既定と同じ道) | 467・27.4 |
| rapidlearning (`separating/rapidlearning/freq=-1`) | 295.5 秒で最適・12163 | 11087・277.4 |

- 解はどの回も木の LP (relaxation)。ヒューリスティクスを切って遅れたのは、ヒューリスティクスが解を出すからではなく道が変わったため
  (既定でもヒューリスティクスは解を出していない)。種 1〜4 の既定だけで 467〜6325 ノードと揺れるので、1 回ずつの比べは揺れの中にあるものが多い。
- 揺れを超えて効くのは衝突解析 (切ると解なし) で、presym 7 節・p2inf 4.3 節と同じ。分枝を推論だけ・擬似費用だけにしても解なし (衝突の得点を使う
  relpscost の混合が要る)。rapidlearning は既定で木の中で 96 回呼ばれ、境界の締め 30327・衝突の制約 465 本を出す (切ると 11087 ノードまで解なし、
  種 1 のみ)。ノード選択は深さ優先でも解ける (p2inf 4.7 節と同じ)。
- 当方の 1 スレッドの HEUR1T (`fl`・`fndl`、heur1t_20261123) は、木の中の大近傍探索を暫定解があるときだけ回すので、この問題では動かない
  (種 1 で 12065・12012 ノード・解なし、既定と同じ木)。

## 3. 当方の分枝の得点に衝突がどう入っているか (事実)

- 分枝の得点は SCIP の relpscost と同じ形 (`pseudocost.rs` の `hybrid`): `dynw × (1e-4 s(推論) + 1e-4 s(打ち切り) + w × s(衝突)) + s(擬似費用) / dynw`。
  bnatt400 は擬似費用の利得が最後まで 0 で、分枝 2389 回中 2388 回が双対退化で強分枝なし。点数は衝突と推論の項で決まる。
- 衝突の重み w は既定の RAMP (p2inf 5 節): ノード 200 の窓で「作った衝突 / ノード」1.47 を見て 0 → 0.1 (SCIP の conflictweight は 0.01、推論の 1e-4 との比は
  当方 1000 倍・SCIP 100 倍で、どちらも衝突の項が支配する)。
- 衝突の得点の付け方は、RAMP の既定 (`ENOMOTO_MIP_CONFLICT_WEIGHT_RAMP_HCS` 既定オン) で HiGHS 式: 1 回の解析で説明に使った境界の変更すべての列を、
  1.02 倍ずつ増える重みで上げる (解析 1 回あたり約 156 列)。SCIP の VSIDS は、できた衝突のリテラルの列を 1/0.98 倍ずつ増える重みで上げる
  (減衰は同じ、上げる列の選び方が違う)。当方は既定で、できた衝突のリテラルでは上げない。
- 量 (1 スレッド 600 秒、種 1): 当方は解析 6334 回で衝突 13947 本 (1 回 2.2 本、平均 24.9 リテラル)、12170 ノード。SCIP (種 1) は伝播の衝突の解析
  2314 回で 12789 本 (1 回 5.5 本)、4098 ノード。解析の回数 / ノードはほぼ同じ (当方 0.52、SCIP 0.56)、1 回でできる衝突の数は SCIP が 2.5 倍。

## 4. 試作 (どれも既定では使わない) と結果 (1 スレッド・600 秒・種 1〜3)

- 新しい試作 `ENOMOTO_MIP_CONFSCORE_LITS` (src/mip/solver.rs の `add_conflicts_multi`、閾値なし): HiGHS 式の付け方のときも、SCIP の VSIDS と同じく
  できた衝突のリテラルの列の衝突スコアを上げる。`a` = HiGHS 式に足す、`o` = リテラルだけ (HiGHS 式の変更では上げない)。
- 既存の試作の子の選び方: `ENOMOTO_MIP_GAP1=ur` (`r` = HiGHS の kRootSol、両側の推論の平均に根の LP 解からの距離の重みを掛けて大きい側へ潜る。
  SCIP の childsel `h` (推論と根の LP 値の混合) に近い)、`ENOMOTO_MIP_CHILD_HIGHS=1` (HiGHS の kHybridInferenceCost)。

| 形 | 種 1 | 種 2 | 種 3 |
|---|---|---|---|
| 既定 | 解 594.6 秒 (12113 ノード目)・時間切れ | 解なし (12750) | 解なし (13300) |
| `CONFSCORE_LITS=a` | 解なし (13074) | 解なし (12701) | 解なし (13355) |
| `CONFSCORE_LITS=o` | 解なし (11410) | 解なし (13644) | 解なし (12286) |
| `GAP1=ur` | **解 365.9 秒** (8133 ノード目)・時間切れ | 解なし (12521) | **解 536.8 秒**・時間切れ |
| `CHILD_HIGHS=1` | 解なし (12587) | 解なし (12947) | 解なし (12823) |

- 衝突の得点の付け方を SCIP 寄りにする (`a`・`o`) は効かない。p2inf 4.16 節で HiGHS 式 (HC) が bnatt400 に要ると分かっていたのとも合う。
- 子の選び方 `GAP1=ur` は 3 種中 2 種で解が出た (既定は 1 種)。ただし 3 種では揺れと区別できず、解が出ても 1 スレッドでは証明まで届かない。
- cargo test (試作を足した版、`cargo_test.txt`): 421 通過・0 失敗。この環境では `cargo test --release --lib` が libpython のリンクで
  失敗するので、`RUSTFLAGS="-L/usr/local/lib -lpython3.13"` を付けて別の target で回した。fuzz は回していない (試作は既定では動かない)。

## 5. 読みと次 (判断の案)

- bnatt400 の 1 スレッドの負けは「1 スレッドで解探しが回らない」型ではない。当方・SCIP とも解は木のノードの LP から出て、根・木の中の
  ヒューリスティクスは解を出さない。1 スレッドと 4 スレッドの差は木の処理量 (4 本並べてノードが約 2 倍) で、HEUR1T の型 (heur1t_20261123) の直しは当たらない。
- SCIP との差は (1) ノードの速さ (LP 1 反復が約 2.8 倍遅い)、(2) 最初の解までのノード数 (SCIP の中央値約 4300、当方は 1.2 万超) の積。(2) は衝突の
  得点の付け方を SCIP の VSIDS に寄せても縮まない。SCIP では衝突解析 (と rapidlearning) が効くが、p2inf で衝突の中身・量・重みを追っても届かなかった。
- 次の候補 (どれも重い): (a) ノードの LP の 1 反復の速さ (bnatt400 は 5400 行・ftran が重い。LP の担当の課題)、(b) 1 回の解析で作る衝突の数を SCIP
  (5.5 本) に近づける、(c) SCIP の rapidlearning に当たる「LP なしの短い探索で衝突・固定を学ぶ」部品、(d) `GAP1=ur` を種を増やして確かめる
  (P・M の計測は親がほかの試作とまとめて回す)。
