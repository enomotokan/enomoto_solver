# DUALEQ2: binkar10_1 の害の仕組みと、DUALEQ の入れ直し (2026-11-13)

課題: DUALEQ (`ENOMOTO_MIP_DUALEQ`、双対の議論で不等式行を等式にする。src/mip/mod.rs の前処理の最後) は束 cand1113 にあったが、
binkar10_1 が 4 種そろって 1.45 倍になったので cand1114 で外した (analysis/cand1114_20261113/README.md)。記録 (cand1113 の loo.md) の見立ては
「1 列を消すだけで根の切除平面の打ち切り (mpsep gate) が 13 周目まで遅れ、ノードが増える」。この見立てを確かめ、カットのループの打ち切り側で直せるかを試す。

ビルド: ブランチ ccr-1beed81b-ex0uhq (このセッションのコミット)。機械は 4 コア、ソルバーは同時に 1 つ (4 スレッド)。
`c14` = cand1114 (analysis/cand1114_20261113/cfg.py)、`c14d` = c14 + `ENOMOTO_MIP_DUALEQ=1`。

## 結論

1. **害の元はカットのループの打ち切りではない。カットのループの側では直せない。**
   - c14 を停滞で止めずに 25 周回しても (`ENOMOTO_T_MIP_CUT_STALL=100`) 6.2〜6.5 秒 (ノード 1.8〜1.9k、種 1〜4)。c14d を 6 周で止めても
     (`ENOMOTO_T_MIP_CUT_ROUNDS=6`) 7.7〜8.3 秒 (3.7〜4.1k) のまま (c14 5.9〜7.0 秒・2.2〜2.4k、c14d 9.9〜12.1 秒・4.0〜4.3k)。
   - mpsep gate は分離の多点 (MPSEP) の門で、ループの打ち切りではない。どちらの回も mpsep は 0 周 (門を見る周がずれるだけ)。
2. **DUALEQ がしているのは 1 行だけ**: R804 `C792 + C2147 ≥ 1` (C792 は連続 [0,1]、C2147 は 2 値。費用はどちらも約 1e6 の罰金) を等式にし、
   かけ直しが `C792 = 1 − C2147` を代入する。費用 1e6 が打ち消し合い、C2147 の費用は −8.32、約 1e6 が目的の定数項 (offset) に移る。
   LP の緩和は同じ (LP でも R804 は等号で効く)。
3. **等式の問題そのものが木で重い (cand1114 に固有でもない)**: 前処理の後の問題を等式にする前 (`_pre`) と後 (`_eq`) で MPS に書き出し
   (`ENOMOTO_MIP_DEBUG_DUMP_DUALEQ`、定数項は書き出されないのでどちらも内部の目的値は 1.005e6)、DUALEQ なしで解いた:

   | 設定 | `_pre` (秒・ノード) | `_eq` (秒・ノード) |
   |---|---|---|
   | c14 種 1〜4 | 7.0・6.9・6.3・6.2 秒 / 2.2〜2.5k | 10.5・10.5・10.3・11.2 秒 / 3.8〜4.6k |
   | def 種 1・2 | 6.1・7.0 秒 / 1.4k・1.6k | 8.0・8.3 秒 / 2.6k・2.4k |
   | c14 − RCSTRONG 種 1・2 | 6.4・6.5 秒 / 2.3k・2.5k | 13.4・9.9 秒 / 5.0k・3.9k |

   目的値の大きさ (offset) を同じにしても、等式にしただけで木のノードが 1.6〜2 倍になる。def では再スタートのかけ直しで `_eq` のほうが
   大きく縮む (行 853 → 730、`_pre` は 848 → 828) が、それでもノードが多い。木の中のどの部品が効いているかまでは分けていない
   (種 1 の c14d では、最適解 6742.2 が根で見つからず (根の被約費用のサブ MIP が 6765.3 止まり) 木の 3.1 秒で見つかる。c14 は根で 1.5 秒。
   ほかの種では c14 も木で見つけるので、主因は証明の側 (ノードの数))。
4. **別件 (周回数の違いの本当の理由)**: 根のカットのループの停滞の判定 (SCIP 式、相対変化 ≤ 1e-4) は offset を除いた内部の目的値で測る。
   binkar10_1 の c14 は内部の値が 1.005e6 (offset −9.986e5) なので、1 周に 0.1% 伸びても相対変化 4e-6〜1.4e-5 で毎回停滞と数えられ 6 周で止まる。
   c14d は費用 1e6 が打ち消されて内部の値が 5.2e3 になり、25 周の上限まで回る。判定が前処理の定数項の置き方で変わるのは筋が悪いが、
   binkar10_1 の時間には効いていない (1. の表)。直すなら別の課題 (目的の尺度に `|obj + offset|` を使う、など)。
5. **代わりの直し (試作) `ENOMOTO_T_MIP_DUALEQ_MINRED` = f (既定 0 = 見ない)**: DUALEQ のかけ直しで減った行の割合と固定でない列の割合の大きい方が
   f 未満なら、等式の問題を使わない。binkar10_1 は 0.0012 (822 行のうち 1 行)、ほかに縮む問題は neos-960392 0.043・beavma 0.031・
   flugpl 0.133・neos859080 0.25。f = 0.01 で binkar10_1 だけが外れる。58 問 (P の組) を前処理だけ回して見ると、f = 0.01 で前処理が
   cand1114 と変わるのは **beavma・flugpl・neos-960392 の 3 問だけ** (ほかの 55 問は等式が 0 行か、2 列の行がなくかけ直さないか、門で使わない)。
   よって 58 問の比べはこの 3 問 (と binkar10_1 の確かめ) を種を増やして測ればよい (下の 6 節)。
