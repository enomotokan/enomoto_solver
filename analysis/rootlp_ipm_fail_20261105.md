# MIP の根の LP で内点法 + クロスオーバーが頂点を返さない・遅い例の原因と試作 (2026-11-05)

bench に使う環境変数: 既定 (base) はなし。試作 (trial) は
`ENOMOTO_T_XO_CLEANUP_HINT=3 ENOMOTO_XO_IPM_RETRY_PC=3 ENOMOTO_XO_NO_BOUND_STOP_ZERO_COST=1 ENOMOTO_IPM_KKT_AUG_RATIO=4`。
(`ENOMOTO_T_XO_CLEANUP_HINT=3` は LP 単独にも効く既存の調整値。MIP の根の LP だけに絞った同じ働きの版 `ENOMOTO_XO_MIP_CLEANUP_HINT=1` も入れた (5 節))。
診断: `ENOMOTO_MIP_ROOTLP_BOTH_DIAG=1` に `ENOMOTO_MIP_ROOTLP_IPM_ONLY=1` (内点法 + クロスオーバーだけを解く)・`ENOMOTO_MIP_ROOTLP_DUMP=ファイル`
(根の LP を MPS に書き出す)。ログは `ENOMOTO_DEBUG_CROSSOVER=1 ENOMOTO_DEBUG_IPM=1 ENOMOTO_DEBUG_EXT_ITERS=1`。

## 目的

`analysis/rootlp_both_diff_20261105.md` で、根の LP (前処理・LP プロービングの後、カットの前、基底なし) を内点法 + クロスオーバーで解くと、
最適な頂点を返さない (momentum1・satellites2-40・cryptanalysiskb128n5obj16・opm2-z10-s4・sorrell3・physiciansched6-2・graph20-20-1rand・mas74)、
あるいはクロスオーバーが大半を占めて遅い (chromaticindex512-7・cryptanalysiskb128n5obj14・neos-933966) 例があった。並列 2 セッションのうちの 1 として、
どこで失敗しているかを特定し、試作を入れて測る (二段解法側の失敗はセッション 2)。

## 結論 (短く)

- **大半の原因は内点法ではなく、クロスオーバーの最後の単体法の仕上げ** だった。押し出しで作った基底は主・双対ともほぼ実行可能 (crypt14/16・
  chromaticindex512-7 は主・双対の実行不能 0、physiciansched6-2 は双対実行不能 64、neos-933966 は 398) なのに、仕上げに渡すのが **基底だけ** で、
  非基底の列をどちらの境界に置くかを被約費用の符号で決め直すため、費用 0 の列・双対退化した列が反対の境界に飛び、**主実行不能な基底変数
  1.7 万〜3.3 万本** から双対単体法を回していた (crypt16: 27,670 反復・91 秒)。graph20-20-1rand は同じ理由の主実行不能 1,721 本から、特異な基底の
  作り直しを繰り返して 60 秒で頂点なし。既存の `ENOMOTO_T_XO_CLEANUP_HINT=3` (仕上げにも非基底の向きを渡す) で、これらは **仕上げ 0 反復**。
- 残りの原因は 4 つ: (1) 目的が 0 の LP では二段解法と共有する下界で内点法が 4 反復目に止まり (主残差が許容の 728 倍)、悪い点から仕上げる
  (crypt16 の競争)、(2) mas74 は上限 6.4e6 の列があり、尺度をそろえない内点法が収束しない、(3) sorrell3 は構造列 1,024 本・行 52,801 で、正規方程式の
  分解が 1 反復 15 秒 (拡大系なら 1/50 の演算量)、(4) momentum1 は内点法が停滞し (HiGHS の IPX も「imprecise」)、仕上げの単体法も数値的に破綻、
  opm2-z10-s4 は仕上げの主単体法が最適な面の上で 2 万反復停滞 (未解決)。
- 試作一式で、内点法 + クロスオーバーだけで解いたとき **11 問中 9 問が最適な頂点** (既定は 5 問)。時間 (既定 → 試作):
  physiciansched6-2 294 秒 (頂点なし) → 1.5 秒、neos-933966 35.0 → 0.94、chromaticindex512-7 62.6 → 3.0、crypt14 80.0 → 7.3、crypt16 99.0 → 8.2、
  satellites2-40 264 (頂点なし) → 75、sorrell3 269 (頂点なし) → 42、mas74 頂点なし → 0.05、graph20-20-1rand 0.44 → 0.32。momentum1・opm2-z10-s4 は頂点なしのまま。
- 二段解法と同時に解く形 (競争) では、試作で 11 問中 7 問 (satellites2-40・crypt14/16・physiciansched6-2・chromaticindex512-7・neos-933966・sorrell3)
  で **内点法側が二段解法より先に最適な頂点を出す** (既定では 7 問とも負けるか頂点なし)。目的値はすべて二段解法と一致。
- 58 問 (60 秒、1 回) の MIP 全体: SGM は負けている 21 問 15.02 → 14.63 秒 (解けた数 19 → 18)、MIPLIB 40 問 18.51 → 19.40 秒 (26 → 26)。差の出た 8 問を
  さらに 2 回ずつ回すと、noswot・qnet1・mc11 は試作が 3 回中 2〜3 回遅いが、noswot・qnet1 は既定・試作ともすべての根の LP の競争で二段解法が勝って
  いて内点法の頂点は使われない (根の LP の結果は同じ)。58 問の根の LP は 0.1 秒未満が大半で、試作の効く場面がほぼない。**58 問では効き目も害も
  揺れの範囲を出ない** (6 節)。効くのは根の LP が数秒〜数十秒の大きい問題 (7 節)。

## 2. 問題ごとの原因

### 2.1 仕上げで非基底の向きが捨てられる (physiciansched6-2・crypt14/16・chromaticindex512-7・neos-933966・satellites2-40・graph20-20-1rand)

事実:
- 押し出し (主の押し出しは飛ばされ、基底の選択 + Megiddo 式の押し出し) までは速い (crypt16 4.4 秒、chromaticindex512-7 2.4 秒、physiciansched6-2 0.3 秒)。
  押し出しの後の基底は主実行可能で、双対実行不能も 0〜398 本 (`CROSSOVER basis quality`)。
- 仕上げ (`solve_slope_intercept_dual_from_basis`) の warm start は `ENOMOTO_DEBUG_EXT_ITERS` で
  「cost shifts 12148, hint agree 0 differ 0 unknown 0, **primal infeasible basics 32584**」(crypt16)。仕上げに渡るのは基底だけで、非基底の列の向き
  (下限・上限) の希望 (`set_warm_nb`) は既定では頂点の修復にしか渡さない (`ENOMOTO_T_XO_CLEANUP_HINT` のビット 1)。
- `ENOMOTO_T_XO_CLEANUP_HINT=3` (仕上げにも渡す) では「hint agree 48950 differ 0, primal infeasible basics 0」、仕上げの主ループ 0 反復。
- graph20-20-1rand の競争 (`--both`): 内点法 0.15 秒、押し出しの後の基底は主・双対とも実行可能だが、仕上げの warm start が主実行不能 1,721 本、
  双対単体法が「refactorize returned None (singular basis)」を数十回繰り返して 61.9 秒で `None`。内点法だけ (IPM_ONLY) で解いたときは同じ問題でも
  仕上げが速かった (0.44 秒) ので、点のわずかな違いで分かれる。向きを渡すと競争でも 0.41 秒で頂点。
- satellites2-40 は既定では仕上げが 200 秒を超えて期限。向きを渡すと仕上げの主ループ 0 反復 (双対実行不能 221 本は polish が直す) で 64.7 秒 (内点法 54.7 秒)。

原因 (事実から): 非基底の列を被約費用の符号で置き直すと、費用 0 の問題 (crypt14/16 は目的が 0) や双対退化した列 (被約費用がほぼ 0) で、
押し出しが置いた境界と反対の境界に移り、`x_B` が大きく変わって主実行不能になる。そこからの双対単体法は二段解法を一から解くのと同程度かそれ以上。
過去の記録 (`docs/improvement_history.md` の「頂点の修復に非基底の上下限の向きを渡す」) では、LP 単独 (irish-electricity) で仕上げが 34.3 → 57.1 秒と
遅くなったのでビット 2 は既定から外していた。

### 2.2 目的が 0 の LP で、共有の下界で内点法が早く止まる (cryptanalysiskb128n5obj16 の競争)

事実: 向きを渡しても、競争 (`--both`) では crypt16 が 92.8 秒 (二段解法 53 秒に負ける)。内点法は **4 反復で `Optimal`**、相対残差 (主, 双対, ギャップ) /
許容 = (728, 63, 7.0e7)、押し出しの後の基底は主実行不能 16,419 本、仕上げ 2.5 万反復。内点法だけで解いたときは 13 反復で主残差は許容以内。
`ENOMOTO_T_XO_BOUND_PRES=1` (共有の下界で止めるときに要る主残差を許容の 1e4 倍から 1 倍に) なら 9.7 秒。

原因: 内点法は「主目的値と二段解法の共有の下界の相対差 ≤ 1e-6、かつ主残差 ≤ 許容の 1e4 倍」で止まる (`boxed.rs` の external lower bound)。
目的が 0 の LP では目的値も下界も 0 で差が常に 0 なので、主残差が許容の 1e4 倍に入った反復で止まる。(止めの行は `ENOMOTO_DEBUG_IPM` を
付けずに測ったのでログにないが、4 反復で `Optimal` になる経路はこれしかない。)

### 2.3 mas74: 大きな上限の列で内点法が収束しない

事実: 13 行・151 列、上限 6.355e6 の列が 1 本 (`|h|max=6.355e6`)。双対化した内点法 (55 反復) も元の問題の内点法 (172 反復) も、相補性 μ が 1e-60 まで
下がっても主残差 6.24e-7・ギャップ 0.245 (目的値 0.195 に対して) が動かず、最後は残差が発散 (NaN) して不受理。`ENOMOTO_T_XO_IPM_PC=2` / `3`
(内点法の前に行・列を幾何平均でそろえる) では 3〜5 ミリ秒で収束し最適な頂点 (目的値 10482.80、二段解法と一致)。HiGHS の IPX は 16 反復。
推測: そろえない内点法は大きな境界の列のスラックと乗数の積が丸めで崩れ、境界の残差がギャップに効いたまま縮まない。

### 2.4 sorrell3: 正規方程式が重い (構造列が少なく行が多い)

事実: 52,801 行・1,024 列 (標準形の内点法の問題は 53,825 列)。稠密な列の判定のしきい値は平均の非零数 (スラック 52,801 本を含めて数える) の 10 倍 = 401 で、
構造列 1,024 本のうち 823 本だけが稠密扱い (Woodbury)、残り 201 本で正規方程式の因子が 1,680 万非零・1.8e10 flops、1 反復の分解 15 秒、
15 反復で 300 秒の期限。拡大系なら因子 400 万非零・3.5e8 flops (1/52)。HiGHS の IPX は 46 反復 14 秒。
もう 1 つの事実: 根の LP の内点法と同時に、169,162 行の問題の拡大系の記号分解が 60 秒余り走ってから 0 反復で終わっている (ログで交互に出る)。
推測: LP プロービングの最初の LP の競争で二段解法が勝った後、内点法側が取り消しを見ない記号分解の中にいて、根の LP の計算と CPU を取り合っている
(未確認。既定の MIP でも起きているなら、二段解法が勝った後に最大 60 秒ほど 3 スレッドが無駄に回る)。

### 2.5 momentum1: 内点法の停滞と仕上げの破綻 (未解決)

事実: 内点法 (元の問題、正規方程式) は 55 反復ほどで主・双対残差が 1e-9・1e-12 まで下がるが、ギャップ (内部の尺度で 1.88e-5、許容の 1e3 倍) で
停滞し、双対の歩幅 1e-4 前後・Newton 方向が非有限で正則化を上げ直す反復が 200 反復まで続く。最良点は受理の範囲 (主 0.14・双対 2.9e-6・ギャップ 1e3 倍)
なのでクロスオーバーに進むが、頂点の主実行不能 580 本が上限 (行の 1/50 = 408) を超えて諦める (`ENOMOTO_T_XO_UNCONVERGED_GIVEUP`)。
諦めずに仕上げると 80 秒で破綻 (`None`)。`ENOMOTO_T_XO_IPM_PC=3` でも内点法は 199 反復で収束せず (ギャップ 2.7 倍)、向きを渡した仕上げも
主単体法が「broke down」でやり直しになって 98 秒で頂点なし。HiGHS の IPX も「imprecise」(ギャップ 6.4e-6) だが、クロスオーバー 1,348 反復で 2.1 秒。
推測: 双対の最適解集合が非有界に近い (仕上げ前の双対実行不能の最大 4.9e6) か、主の内点がほとんどない問題で、内点法の双対側が収束しない。
内点法そのものの扱い (最適面の外への発散を抑える・IPX のように内点法を早めに切ってクロスオーバーで直す) が要る。

### 2.6 opm2-z10-s4: 仕上げの主単体法が最適な面の上で停滞 (未解決)

事実: 双対化した内点法 13.5 秒 (35 反復、収束)、押し出し 17 秒 + 双対の Megiddo 式押し出し 14.6 秒。基底は主実行可能・双対実行不能 1,593 本 (最大 5.7e3)。
向きを渡しても warm start で主実行不能 7,455 本 (希望と反対の側に置いた列 151 本と費用のずらし 1,583 本のため)、双対単体法 583 反復で
**目的値 -46921.5078404 (二段解法の最適値と一致) に達する** が、ずらしを外すと双対実行不能 1,584 列、主単体法に引き継いで 20,400 反復の間
目的値が変わらず (「obj unchanged for 50 iters」) 破綻 → 費用を全部ずらして解き直し → 同じ → 300 秒の期限。HiGHS の IPX は 10.3 秒 (クロスオーバー 12,487 反復)。
推測: 双対実行不能の列は最適な面の中の退化した方向で、主単体法が退化の停滞を抜けられない。MIP の根の LP では双対の記録が要るので、
頂点を内点法の双対の下界で確かめて仕上げを省く近道 (`ENOMOTO_T_XO_ACCEPT_GAP`) が使われない (`duals_requested()` のとき飛ばす)。
次の手: 主単体法の退化対策、または MIP でも下界で確かめた頂点を採り、双対は別に作る。

## 5. MIP の根の LP だけに絞る版

`ENOMOTO_T_XO_CLEANUP_HINT=3` は LP 単独 (`root_solver="ipm_crossover"`・auto の競争) の仕上げにも効き、過去に irish-electricity で遅くなった。
MIP の中で仕上げまで走るクロスオーバーは根の LP の競争と解き直し (`solve_ipm_rescue`) だけで (`TwoStageLp::interior_point` は押し出しまで)、どちらも双対の記録を要求する (`request_duals(true)`) ので、
`ENOMOTO_XO_MIP_CLEANUP_HINT=1` は「双対の記録が要求されているときだけ仕上げに向きを渡す」とした。MIP の中では `CLEANUP_HINT=3` と同じ働き
(58 問の計測は `CLEANUP_HINT=3` で取った)。既定にするならこちら。

## 6. 58 問 (MIP 全体、60 秒)

`bench58.jsonl` (`bench58.txt`)。1 回目は 58 問すべて、差の出た 8 問は 2 回ずつ追加。

差の出た 8 問 (3 回の時間、秒。60 は時間切れ):

| p200x1188c | 7.2 / 3.4 / 3.4 | 3.5 / 3.5 / 3.4 | 4.6 | 3.5 |

読み方:
- 事実: noswot・qnet1 を `ENOMOTO_DEBUG_RACE=1` で回すと、既定・試作ともすべての根の LP の競争 (2 回ずつ) で二段解法が勝つ。根の LP の診断 (`both58.jsonl`、
  2 回ずつ) でも勝ちは二段解法。内点法側の頂点は試作で変わる (noswot の二段解法の頂点との違い 34 → 54 列) が、使われない。
- 推測: noswot・qnet1 の差は根の LP の結果を通したものではなく、並列の MIP の揺れ (noswot は既定だけでも 9〜28 秒) か、内点法側の手間の違い
  による時間のずれの連鎖。mc11 は根の LP の競争で内点法が勝つことがあり (既定 1/2 回、試作 2/2 回)、点は同じで基底が少し違う (二段解法の
  基底との違い 48/38 → 49/39) ので、経路が変わりうる。3 回では向きは言えない。
- 58 問の根の LP は大半が 0.1 秒未満で、二段解法が先に終わる。試作の効く「仕上げが長い」場面がほとんどないので、58 問では効き目も害も揺れを
  出ないと見る。既定にするかどうかは、根の LP が数秒以上の問題 (Mittelmann) での MIP 全体の計測で決めるのがよい (7 節)。

## 7. Mittelmann の 6 問 (MIP 全体、60 秒、1 回)

`mitt_mip.jsonl`。根の LP の競争で試作の内点法側が勝つようになった問題のうち 6 問。60 秒ではどれも解けないので、時間切れの時点の状態を比べる。

| 問題 | 既定: 暫定解 / 下界 | 試作: 暫定解 / 下界 |
|---|---|---|
| neos-933966 | 41290 / 318 (根の下界) | **5375** / 318 |
| chromaticindex512-7 | 4 / 下界なし (根の LP が終わらない) | 4 / **3** (根の下界) |
| satellites2-40 | 79 / 下界なし | **46** / **-30** (根の下界) |
| cryptanalysiskb128n5obj14 | なし / なし | なし / なし |
| cryptanalysiskb128n5obj16 | なし / なし | なし / なし |
| sorrell3 | -11 / なし | -11 / なし |

- 事実: chromaticindex512-7・satellites2-40 は既定では 60 秒の間に根の LP (二段解法 59〜83 秒) が終わらず下界がないが、試作では内点法側が
  3 秒・76 秒 (競争の診断の値) で頂点を出して根の下界まで進む (satellites2-40 は 62.9 秒で止まった)。neos-933966 は根の LP が 0.94 秒になり、
  時間切れの時点の暫定解が良い。crypt14/16・sorrell3 は前処理と LP プロービングが重く、どちらも根の LP の後まで進まない (根の LP の手前の
  LP プロービングの最初の LP の競争にも同じ試作が効くはずだが、60 秒では差が出ない)。
- 既定にするかは、時間の上限を長くした Mittelmann の計測 (根の下界の後のカット・分岐まで) で決めるのがよい。
