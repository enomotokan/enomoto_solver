# RENS のやり直しを本当にノード上限まで進んだときだけにする試作の確かめ (2026-11-01)

背景: 根の RENS のサブ MIP がノード上限 (`NodeLimit`) で返ると、ノード上限を 4 倍にしたやり直し `RENS (more nodes)` が走る
(`src/mip/solver.rs` の根のヒューリスティクスの終わり、別スレッドの RENS は `take_submip` が `rens_node_limited` を立てる)。
停滞 (`ENOMOTO_T_MIP_SUBMIP_STALL`)・成果連動の打ち切り (`submip_outcome_stop`) で止まったときも状態は `NodeLimit` なので、やり直しても
同じノード数・同じ解で止まる空回りになる (`analysis/cand_slow_n5-3_20261031.md`、58 問で深さ 1 のやり直し 12 本・39.7 秒で成果 0 本、
`analysis/submip_where_20261101.md`)。試作 `ENOMOTO_MIP_RENS_MORE_NODES_REAL` (既定では使わない) はやり直しを、RENS のサブ MIP の
ノード数が上限に届いたときだけにする。この記録はそれを今の既定 (`analysis/cand_default_20261031.md`) の上で確かめたもの。

- 機械: 4 CPU。4 スレッド・60 秒、`ENOMOTO_MIP_LOG=1`、ソルバーは同時に 1 つだけ。HiGHS (highspy) は 1.15.1。
- ビルド: ブランチ `ccr-1beed81b-ex0uhq` の `92b80fd` + 下の 1 節の変更 (計測の後に別のセッションの `99fa509` (`ENOMOTO_MIP_SUBMIP_NOSOL_STOP`、
  既定では使わない) の上に rebase した。計測のビルドにはそれは入っていないが、既定の振る舞いは同じ)。
- 設定 (`run.py` の `CFGS`): def = 環境変数なし (今の既定)、real = `ENOMOTO_MIP_RENS_MORE_NODES_REAL=1`、
  real_s0 = real + `ENOMOTO_MIP_RENS_MORE_NODES_SUB=0`、real_s2 = real + `ENOMOTO_T_MIP_RENS_MORE_NODES_SUB_MULT=2`。
- 台本・ログは `rens_more_real_20261101/`:
  - `run.py 設定,... 問題,... 回数 [回の始め] [ログのディレクトリ] [K=V ...]`: `<ディレクトリ>/<問題>_<設定>_<回>.log`。問題・回ごとに設定の順を逆にする。
  - `summ.py [ディレクトリ]`: 回ごとの秒・目的値・外側の根のやり直し (結果/秒)・省いた行の数 (`summ.txt`)。`table.py`: 時間の表 (`table.txt`)。
  - `retries.py ディレクトリ [glob]`: `ENOMOTO_MIP_SUBMIP_VERBOSE` の SMT 行から、やり直し 1 本ずつと、同じ親の直前の RENS が上限まで進んだか (`full`)。
    `tom.py`: 深さ 2 のやり直しの解が外側まで届いたか。
  - `logs/`: 本計測。`logs_olddef/`: binkar10_1 を旧既定 (`analysis/cand_default_20261031/olddef.env`) で。
    `logs_nostop/`: binkar10_1 を旧既定 + 打ち切りなし (`ENOMOTO_MIP_NO_SUBMIP_OUTCOME_STOP=1 ENOMOTO_T_MIP_SUBMIP_STALL=0`) で。
    `logs_v/`: `ENOMOTO_MIP_SUBMIP_VERBOSE=1` で 5 問 × 4 設定 × 1 回 (深さ 2 を見る)。
- `cargo test --release --lib` は 330 件通過 (`CARGO_TARGET_DIR=target/test-py RUSTFLAGS="-C link-arg=-lpython3.13"`、rebase の後)。

## 0. 結論

1. **real は既定の上でも空回りだけを消す。** 11 問 + 1 問 × 3 回で、def の外側のやり直しは 36 回中 17 本・89.7 秒、**解を見つけたものは 0 本**
   (blp-ar98 で 1 本 20 秒、n5-3 で 9〜10 秒、ran14x18-disj-8 で 6〜7 秒)。real で残ったやり直しは 2 本 (neos-1582420、どちらも RENS が本当に 500 ノードに届いたもの、解なし)。
   省いたことで解を失った回はない (def のやり直しが 1 本も解を出していないので、失いようがない)。
2. 時間: n5-3 は def 60.0 (時間切れ) / 47.0 / 60.0 → real 47.9 / 41.9 / 40.0 秒。h80x6320d 37.8 → 32.0 秒、physiciansched6-2 は def の 2 回の時間切れが
   real でなくなったが、これは Local-MIP の揺れ (やり直しはどちらでも 0 本)。neos-1582420 は real の 2 回が遅い (45.9・51.5 秒) が、
   これは RENS が 500 ノードまで進んで解なしになる回で、real でも def でもやり直しは走る (def の 3 回はたまたま RENS が 107〜159 ノードで実行不能と分かる回)。
   ほかは揺れの中。
3. **binkar10_1 のやり直しは、やり直しが要る形では残る。** ただし今の既定では、binkar10_1 の RENS は 48〜79 ノードで打ち切られて 6763.3 (旧既定でも 7038.1) を返し、
   やり直しは同じノードで止まって何も見つけない (def でも 0 本)。real はそれを省き、7.4 → 6.7 秒。打ち切りを外して RENS を 500 ノードまで進ませると
   (`logs_nostop/`)、real でもやり直し 3 本が def と同じに走り、同じ解 (6763.3・6742.2・6751.0) を見つける。やり直しを作った理由 (500 ノードで 7182) は、
   今は停滞・成果連動の打ち切りの方が先に来るので起きていない。
4. **深さ 2 (サブ MIP の中の RENS) のやり直し**: 58 問のログ (`submip_where_20261101/logs`) で、深さ 2 のやり直しは 36 本・35.7 秒、親を良くしたのは 8 本。
   そのうち **6 本は本当に 500 ノードに届いたもの** (ran14x18-disj-8 の 5 本・blp-ar98 の 1 本)、2 本は停滞で止まったもの (mas74、外側の解に届いたが 0.03 秒後に
   別の解で上書き)。上限に届いた 6 本は 6 本とも親を良くし、届かない 30 本は 2 本だけ。real は届いた側を残す。
5. 深さ 2 以上でやり直さない形 (real_s0)・深さ 2 以上で倍率 2 の形 (real_s2) は、試した 4 問 × 3 回で real と差が見えない
   (ran14x18-disj-8 の深さ 2 のやり直しは 1 本 3〜5 秒で、外側に届くのは 1 回に 1 本ほど)。real_s2 はやり直しの秒を約 3 割減らす (verbose の 1 回で 18.4 → 12.6 秒、成果は同じ 5 本)。
6. **58 問で確かめる形の提案 (1 つ)**: 今の既定 + `ENOMOTO_MIP_RENS_MORE_NODES_REAL=1`。深さ 2 の扱い (real_s0・real_s2) は、この形の結果を見てからでよい。

## 1. 変更 (どれも既定の振る舞いは変えない)

- `ENOMOTO_MIP_RENS_MORE_NODES_REAL` は前の記録 (`cand_slow_n5-3_20261031.md` の 4 節) のまま。判定は、主のスレッドで解いた RENS は
  `submip_full_nodes` (結果のノード数 ≥ 倍率を掛けた後のノード上限)、別スレッドの RENS は出したときの上限 (`rens_spawn_node_limit`) と比べる。
  コードを読み直し、比べる上限が `ENOMOTO_T_MIP_SUBMIP_NODES_MULT`・`submip_node_mult` を掛けた後の値であることを確かめた。
- ログ (`ENOMOTO_MIP_LOG=1` のとき): REAL でやり直しを省いた RENS について `RENS (more nodes) skipped: ...` を出す
  (`heuristics.rs` の `log_rens_retry_skip`、`solver.rs` の `take_submip`)。差が 0.5% 以下でもともとやり直さない場合にも出るので、
  行の数 (real 36 回で 27 行) は def のやり直しの本数 (17 本) より多い。
- `ENOMOTO_MIP_RENS_MORE_NODES_SUB=0` (試作): サブ MIP の中 (深さ 2 以上) ではやり直さない。
- `ENOMOTO_T_MIP_RENS_MORE_NODES_SUB_MULT` (試作): サブ MIP の中のやり直しのノード上限の倍率 (既定は外側と同じ `ENOMOTO_T_MIP_RENS_MORE_NODES_MULT` = 4)。

## 5. 58 問で確かめる形
