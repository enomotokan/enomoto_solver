# bgx_check1: 裏のカットの写しに列の値を渡すと写しのラウンドが 0 になる回の原因 (physiciansched6-2、2026-11-02)

- 発端: analysis/flbgx_default_20261102.md の確かめで、`ENOMOTO_MIP_BG_CUTS_BASIS_X=lpw` (既定、commit 89e721bb) の 2 形とも、写しが
  15〜32 秒の間に止めの合図の時点でラウンドの記録が 0 (`rounds so far []`、待ち 0.00 秒・理由 `done`、終わりに `2 rounds, obj 48957 not above`)。
  `=0` は同じ間に 2 ラウンド (48857 → 49007)。
- 土台: d8c8b723 に、表示と試作 (下の 3 節、既定では働かない) を足したビルド。4 スレッド・60 秒、ソルバーは同時に 1 つ、
  `ENOMOTO_MIP_LOG=1`・`ENOMOTO_MIP_BG_CUTS_LOG=1` (写しの求解のログ。表示だけ)。時刻は MIP の時計 (外側の前処理の後に 0)。結果の秒は呼び出しから。
- 台本・ログは `bgx_check1_20261102/`: `run.py 設定,... 回数 [初めの回]` (`logs/<設定>_<回>.log`・`res.jsonl`。追加の設定は環境変数
  `BGX_EXTRA_CFGS` に JSON で)、`summ.py [設定,...]` (1 回ごとの表、全部は `summ_all.md`)、`hog.sh` (CPU を空回しで埋める。効かなかった、2 節)。

## 1. 結論

1. **原因は、写しのカットの LP の 1 回の時間の上限 (1.0 秒) に当たって 2 ラウンド続けてカットを全部外し、失敗 2 回で写しのループが抜けること**。
   写しの `time_limit` は主の残り時間 (約 45 秒) なので、上限 `max(0.02 × time_limit, 1.0)` (`src/mip/separation.rs` の根のカットのループ) は最低値の
   1.0 秒になる (主は 60 秒の 2% = 1.2 秒)。写しのカットの LP は 1 回 1000〜1400 反復で、この機械で 0.6〜0.8 秒。前回の確かめの機械は主の LP が
   約 1.5 倍遅く (主の 4 ラウンド目 1184 反復が約 0.9 秒)、写しの LP が 1.0 秒前後になって上限に当たる。
   - 写しの上限を 0.6 秒にして遅い機械を真似る (`ENOMOTO_T_MIP_BG_CUTS_LP_CAP_SECS=0.6`、診断) と、列の値を渡す形は **6 回とも**
     0・1 ラウンド目の LP が上限に当たって外され (`LP status TimeLimit, removed the cuts`、外した後の解き直しは 1 反復)、写しが 2〜3 秒で自分で終わる。
     主から見ると `waited 0.00s (done)・0 rounds・rounds so far []`、終わりに `2 rounds, obj ... not above`。**前回の記録と同じ形**。
   - ラウンドの記録 (`prog`) は LP が最適に解けたラウンドだけに入り、`2 rounds` (`bg_cut_rounds`) はラウンドの始めで数えるので、外したラウンドも数える。
2. **列の値を渡すと何が変わるか**: 渡す形は写しが主と同じ頂点から始まり、最初のカットの LP が 1121〜1402 反復 (この機械で 0.6〜0.8 秒)。
   渡さない形は写しの根の LP (1545〜11030 反復) で別の頂点に着き、0 ラウンド目の LP が 870〜932 反復と少し軽いので、遅い機械の真似でも
   1〜2 ラウンドは通ってから同じ失敗で終わる (前回の `=0` の 48857 → 49007 の 2 ラウンドと同じ形)。上限に当たるのは**どちらの形も同じ**で、
   渡す形は最初の LP が少し重いぶん 0 ラウンド目から当たる。カットが全部弾かれる・分離のカットが主のプールと重なる、という形は見られない
   (写しの 0 ラウンド目の候補 1424 本から 50 本を採り、LP を足すところまでは進んでいる)。
3. **今の機械の速さでは 0 ラウンドの回は出ない**: 既定 6/6 で最適 (23.7〜41.3 秒)、写しの 1 ラウンド目は 14.7〜15.0 秒、2 ラウンド目で 49324。
   `=0` は 1/6 (写しの根の LP が 11030 反復・5.8〜6.2 秒で、止めの合図 (16〜20 秒) までに 0〜1 ラウンド。phys6_20261101.md の群 A と同じ)。
   前回の確かめとの違いは機械の速さで、主が時間の上限で 5 ラウンド (48957) で止まる道もその遅さから来ている。
4. **試作 `ENOMOTO_MIP_BG_CUTS_LP_CAP=m`** (写しでは 1 回の LP の上限を主の根の LP の時間の m 倍より短くしない。physiciansched6-2 では m=1 で
   約 2.3 秒) で、遅い機械の真似は **1/6 → 5/6** (解けない 1 回は暫定解が出ない群 C で写しとは関係ない)。普通の速さでは 6/6 のまま
   (SGM(+1) 26.6 → 26.6)。
5. 判断: 写しの 1 回の LP の上限が速さに敏感な作りで、列の値を渡す形はその上限に 0 ラウンド目から当たりやすい。列の値を渡す既定は保ったまま、
   `ENOMOTO_MIP_BG_CUTS_LP_CAP=1` を 58 問で確かめて既定にする候補とする (下の 4 節の注意)。

### 2.1 前回の道の再現の試み (補い)

- 主の根のカットのループを時間の上限で早く止める (`ENOMOTO_T_MIP_CUT_TIME_FRAC=0.05`、4 ラウンド・280 本・48857) と、普通の速さでは写しのラウンドは
  0 にならない。ただし列の値を渡す形は写しの下界の上がり方が遅く (48907 → 48957 → 48957 → 49007 → 49224 → 49274)、渡さない形は 4 ラウンドで
  49324 (48857 → 49007 → 49274 → 49324)。解けた数は def_c4 1/3 (解けない 2 回は、1 ラウンドで止めの合図 = 待ちの判定の `stalled`、と群 C)、
  x0_c4 3/3。3 回ずつなので揺れと区別できない。主が早く止まる道 (遅い機械) では、列の値を渡す利点が小さくなるかもしれない。
- `ENOMOTO_T_MIP_CUT_TIME_FRAC=0.065` + 上限 0.6 秒 (def_c5_s06・x0_c5_s06、2 回ずつ): 主は 4〜5 ラウンド (48857〜48957)。列の値を渡す形は 2 回とも
  0・1 ラウンド目が失敗して写しのラウンド 0 (前回の記録と同じ)、渡さない形は 2 ラウンド (48957 → 49057) の後に 2 回失敗。4 回とも時間切れ。
- CPU を 2 本の空回しで埋める形 (`hog.sh 2`、def_ld2・x0_ld2 3 回ずつ) は主のループが 1 割ほどしか遅くならず、前回の遅さを真似られなかった
  (def_ld2 3/3、x0_ld2 0/3)。

## 3. 試作 (既定の経路は変えない)

- `src/mip/separation.rs` (根のカットのループの 1 回の LP の上限): 裏のカットの写し (`job.is_some()`) では
  - `ENOMOTO_MIP_BG_CUTS_LP_CAP` = m (試作、既定では使わない): 上限を主の根の LP (カットの前) の時間の m 倍より短くしない。
  - `ENOMOTO_T_MIP_BG_CUTS_LP_CAP_SECS` = s (診断、既定 0 で使わない): 上限を s 秒にする (遅い機械の真似)。m と同時なら大きいほう。
  - 主の根の LP の時間は `src/mip/solver.rs` の `BG_ROOT_LP_SECS` (写しのスレッドを起こすときに入れる) で渡す。
  - 表示: 写しの 0・1 ラウンド目の上限 (`background cut LP time cap`)、LP を外したときのカットの LP・解き直しの反復と時間。
- 4 節の注意から、上限の上に枠 (例えば写しの残り時間の 5%) を付けるのも候補。今回の 6 回は枠なしで測った (physiciansched6-2 では
  写しの LP は 1 秒を超えないので、枠の有無は効かないと見られる)。

## 4. 注意・次

- 写しの LP は止めの合図を見ない。上限を伸ばすと、主の止めの合図の後に写しの LP の終わりを待つ時間が最大でその上限まで延びる
  (`BgCuts::finish` の join)。根の LP が重い問題 (uccase12 など) で m × 根の LP の時間が大きくなりすぎないか、58 問と Mittelmann で確かめる。
  並列のもう 1 つの調査 (58 問・Mittelmann の写しのラウンドが 0 になる回) で、同じ `LP status TimeLimit, removed the cuts` が写しに出ているかを
  `ENOMOTO_MIP_BG_CUTS_LOG=1` で見ると、この原因の広がりが分かる。
- 写しの失敗の数え方: 写しでは 1 回の LP の失敗で止める理由は薄い (主は根のヒューリスティクスを回していて、写しは止めの合図まで回れる)。
  `ENOMOTO_MIP_CUT_LP_HALVE` (時間の上限に当たったら本数を半分にして続ける) を写しだけ既定にする形も候補。
- 主の 1 回の LP の上限 (1.2 秒) も遅い機械では主のカットの LP (0.9 秒前後) に近い。今回の主のループに失敗は出ていない。
