# hypothyroid-k1: HiGHS が根で解き終わる理由と、打ち切り値つきの根のプロービングの試作 (2026-10-20)

ブランチ `inv/hypothyroid-sb-20261020`。計測は 4 コアのコンテナ (nproc 4)、両ソルバー 4 スレッド・60 秒、
HiGHS 1.15.1 (`mip_rel_gap=0`)、ENOMOTO は `m.solve(None, False, 60, None, None, 4, log=True)`。

## 結論

- 差は強分岐の速さではない。**HiGHS は木に入らない (1 ノード、強分岐 0 回) で根で最適性を証明している**。
- 下界が根で閉じる仕組み: HiGHS は根の分離の 1 回目 (`HighsSeparation::separationRound` の先頭で呼ぶ
  `HighsImplications::separateImpliedBounds`) で、まだ試していない分数値の 0-1 列を全てプロービングする。このときの
  定義域の伝播には、暫定解の打ち切り値を使う目的関数の伝播が入る。hypothyroid-k1 では、ランダム丸めの暫定解 -2692
  (打ち切り -2693) を持った状態で 2153 列を試し、**968 列を固定**する (6.8 秒)。それで LP が **-2902.85 -> -2851.08** に
  なり、目的関数は整数なので下界は -2851 になる。その直後に RENS が -2851 を見つけて終わる。
  (HiGHS 1.15.1 をソースからビルドし、ログを出す行を足して確かめた。下の「HiGHS の内訳」。)
- ENOMOTO のプロービングは前処理のときだけで、打ち切り値なし・予算つき (432 / 2595 列、固定 0)。根で暫定解 -2851 を
  見つけた後に打ち切り値を使ったプロービングをしないので、下界は -2880 前後で止まる。その下界のまま強分岐に入り、
  最初のノードで約 28 秒 (子の LP 36〜86 本・約 9000 反復) を使っていた。
- 試作 `ENOMOTO_MIP_ROOT_OBJ_PROBE=1` + `ENOMOTO_MIP_ROOT_OBJ_PROBE_IMPL=1`: hypothyroid-k1 が **3 回とも 60 秒以内に
  最適** (38〜40 秒。既定は 2 回とも時間切れで、下界は -2880〜-2882)。
- さらに LP のカットの行も伝播に入れると (`ENOMOTO_MIP_ROOT_OBJ_PROBE_CUTS=1`)、1 回目の根で 351 列を試して 63 列を固定し、
  両側の矛盾で最適性を証明する (2.3 秒)。**hypothyroid-k1 は 23.6〜26.9 秒で最適、0 ノード** (4 回)。HiGHS は 13〜17 秒。

presolve を切ると (`presolve=off`)、60 秒で下界 -2865・暫定解 -2554 になり解けない。このときは根のランダム丸めが
暫定解を見つけないので、プロービング (2401 列) が打ち切り値なしで走って固定は 0。目的の列だけを手で代入して消した
問題では、presolve を切っても 15 秒で解ける。HiGHS 側で効いているのは「打ち切り値があるときのプロービング」。
root reduced cost heuristic (`mip_heuristic_run_root_reduced_cost=false`)・対称性・RENS・ヒューリスティクスの量の設定は、
どれを変えても結果は同じ。

### ENOMOTO (既定、`ENOMOTO_MIP_LOG=1`)

| 項目 | 1 回目の根 | 再スタート後の根 |
|---|---|---|
| 前処理後 | 5190 行、2596 列 (目的の整数列が残る) | 5253 行、2592 列 |
| 根の LP | 3067 反復、4.46 秒 (約 1.45 ms / 反復) | 2996 反復、5.59 秒 |
| カット後 | -2902.85 -> -2888.35 (10.9 秒) | -2882.43 -> -2880.69 (9.5 秒) |
| 暫定解 | RENS で -2851 (14.9 秒) | 引き継ぎ |
| プロービング | 前処理で 432 / 2595 列、固定 0 (打ち切り値なし) | 272 / 2591 列、固定 0 |

(a) LP の 1 反復の速さ: 根の LP は ENOMOTO 1.45 ms・HiGHS 1.7 ms と同程度。強分岐の子の LP は 1 反復約 3 ms
(9318 反復 / 27.7 秒) で遅めだが、HiGHS はそもそも強分岐をしない。

(b) 根のカットの後の下界: ENOMOTO -2888 (1 回目)・-2880.7 (再スタート後)、HiGHS -2851 (プロービングの固定による)。
木に入るまで ENOMOTO は約 25 秒 (15.5 秒 + 再スタート後の 9.8 秒)、HiGHS は木に入らない。

(c) 強分岐: ENOMOTO の最初のノードは強分岐の子の LP 36 本・9318 反復・27.7 秒 (別の回では 86 本・8835 反復・27.2 秒)。
ノードの LP がまだないので `avg_node_iters` は既定の 1000、子の LP の反復上限は `4 * 1000 * 21` を 500 に切り詰めた値、
予算は `0.125 * node_iters + 25000` 反復。1 反復約 3 ms なので、予算を使い切ると 75 秒かかる。
HiGHS の予算は `100000 + (LP の反復 - ヒューリスティクス - 強分岐) / 2` 反復で、子の LP の反復上限は
`max(10000, 10 * 根の平均反復)`。むしろ HiGHS の方が多い。だから、強分岐を絞っても下界 -2880 から -2851 までは
閉じない (60 秒では無理)。

(d) 再スタート: `ENOMOTO_MIP_NO_RESTART=1` では、既定は 60 秒で下界 -2882・4 ノード。試作を入れても同じ (-2882)。
試作で列が固定されるのは再スタート後の根だけ (1 回目の根では 2429 列を試して固定 0)。再スタートでカットが行になり、
定義域の伝播に入るため。HiGHS はカットプールのカットも伝播するので、1 回目の根から固定が出る。

## 試作

`src/mip/solver.rs` の `root_obj_probe` (根の被約費用による固定の後・再スタートの判定の前に呼ぶ)。既定は変えない。

- `ENOMOTO_MIP_ROOT_OBJ_PROBE=1`: 暫定解 (打ち切り値) があるとき、根の LP 解で分数値の 0-1 列 x_j ごとに
  x_j = 0 と x_j = 1 を試す。行の伝播と目的関数の伝播 (`propagate_objective` の本体を環境変数なしで、衝突は足さずに呼ぶ)
  をかけ、矛盾した側があれば逆の値に大域的に固定する。固定はすぐ定義域に入れるので、後の列の試しにも効く。両側とも
  矛盾したら、暫定解が最適 (根の LP が打ち切りで終わる)。
  - `ENOMOTO_T_MIP_ROOT_OBJ_PROBE_TIME_FRAC` (既定 0.2): 時間上限に対する割合の上限
  - `ENOMOTO_T_MIP_ROOT_OBJ_PROBE_GIVEUP` (既定 200): 最初のこの数の列で固定が 1 つもなければやめる
- `ENOMOTO_MIP_ROOT_OBJ_PROBE_IMPL=1`: 矛盾しなかった側で固定された 0-1 列を含意 (`x_j = v => x_c = w`) として
  定義域に足し (`Domain::add_implications`、対偶も伝播する)、後の列の試しに使う。HiGHS がプロービングの含意をクリーク表に
  入れるのに当たる。打ち切り値を使って得た含意なので、打ち切り値より良い解でだけ成り立つ (大域的な固定と同じ扱い)。

- `ENOMOTO_MIP_ROOT_OBJ_PROBE_REDCOST=1`: 根の LP の被約費用の行 `z + Σ d_j (x_j - b_j) <= U` も伝播する。b_j は LP 解で
  列がいた境界。双対の実行可能性から、LP の行 (カットを含む) を満たす全ての x で `z(x) >= z + Σ d_j (x_j - b_j)` が
  成り立つ。被約費用による固定は列 1 本ずつだが、この行は試しで動いた列の分を足し合わせる。
- `ENOMOTO_MIP_ROOT_OBJ_PROBE_CUTS=1`: LP に入っているカットの行も (行ごとに 1 回) 伝播する。定義域の伝播は元の行だけ
  なので、これまでは再スタートでカットが行になるまで効かなかった。
- どちらかの列で両側が矛盾したら、自分の暫定解を最適として根で終える (打ち切り値がほかのスレッドの解から来ているときは
  除く)。

プロービング自体は小さい問題では 0.01 秒未満で、固定もない。noswot は 3 回とも遅め (+20〜40%)。固定が 0 でも、
学んだ含意 (16 本) は定義域に残って木の伝播を変えるので、そのせいの可能性がある (qiu の 48.5 秒は 1 回だけで、
ほかの 2 回は既定と同じ)。直すなら、固定が出なかったときは含意を捨てる (一時的な含意の表に分けて、終わったら外す)。

既定にする前に、固定が出なかったら含意を捨てる形にしてから、40 問で各 2 回以上測る必要がある。

## 次の手

1. (`CUTS` で済み) 残りの差は、暫定解 -2851 が見つかる (RENS、約 15 秒) までの時間と、1 回目の根の LP・カット
   (約 11 秒)。HiGHS は打ち切り -2693 (ランダム丸めの解) で足りているので、こちらも根の最初の暫定解ができた時点で
   試せば早くなる見込み。
2. 目的関数の伝播をクリークの分割つきにする (HiGHS の `HighsObjectiveFunction::setupCliquePartition`)。HiGHS は
   打ち切り -2693 でも 968 列を固定するが、こちらは打ち切り -2852 で 35〜67 列だけ。
3. 固定が出なかったときは学んだ含意を捨てる (noswot の副作用の候補)。
4. 時間の上限: 2400 列で約 5 秒。列や非零が多い問題での手間を、ほかの問題でも測ってから既定の候補にする。
5. 強分岐の子の LP の 1 反復 (約 3 ms) が根の LP (1.45 ms) の約 2 倍。状態の保存と復元 (`save_state`/`restore_state`) の
   因子分解のやり直しが効いているかを別に調べる。
