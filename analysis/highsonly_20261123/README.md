# highsonly: 負け問題のうち「HiGHS だけが解ける」5 問の原因 (2026-11-23)

対象 (analysis/losses_20261123/README.md 6 節): sct2・satellites2-40・satellites2-60-fs・neos-873061・csched008。
HiGHS は 1 スレッドでも 258〜356 秒で解き、当方と SCIP は時間切れ。

- 計測: `python analysis/highsonly_20261123/run.py 名札 種類 問題[,..] [スレッド] [上限秒] [追加]` (種類 ours/highs/scip、
  `ENOMOTO_*` を外して種 1。追加は当方なら `K=V;K=V` の環境変数、HiGHS ならオプション)。結果は `res.jsonl`、ログは `logs/<名札>_<問題>.log.gz`。
- 計測は 1 本ずつ (他の計測と並べない)。ただし最初の HiGHS の切り分け (h1_nolns) の間に、LP の短い試し (47・73・12・4.6 秒)、根の LP の書き出し、
  試作 1 の 150 秒の試しとビルドが重なった (誤り)。h1_nolns の秒はその分ずれている可能性がある。

## 2. HiGHS の部品を切る (1 スレッド、900 秒)

| 問題 | 既定 | RINS・RENS 切り (h1_nolns) | 再スタート切り (h1_nores) |
|---|---|---|---|
| sct2 | 317 秒 | 768 秒 | 時間切れ (-230.989 / -231.028) |
| satellites2-40 | 356 秒 | 472 秒 | 時間切れ (21 / -29) |
| satellites2-60-fs | 295 秒 | 363 秒 | 時間切れ (-16 / -29) |
| neos-873061 | 337 秒 | 894 秒 | 時間切れ (113.668 / 113.398) |
| csched008 | 258 秒 | 225 秒 | 時間切れ (175 / 172) |

事実: **再スタートを切ると 5 問すべてが 900 秒で解けない**。RINS・RENS は速さに効くだけ (切っても 5 問とも解く)。
HiGHS が解き切る道筋は、どの問題でも「根 (や木の中) で多くの列を固定 → 再スタートで小さくした問題を解く」。

## 3. 問題ごとの差

### satellites2-40・satellites2-60-fs

- HiGHS (h1 のログ): J 42 (5.6 秒) の後、根のカットに 212 秒かけ、「40.2% inactive integer columns」で再スタート
  (8459 行 x 11853 列)。286 秒で 21、296 秒で -19 (最適)。固定は被約費用ではなく**解析的中心での固定** (費用 0 の LP の内点法の中心で境界にある
  列を大域に固定。analysis/highs_only_20261105/G4.md 2 節、satellites2-60-fs で 11955 列)。
- 当方 (既定): 根のカットのループが長い (satellites2-40 で round 5〜7 の LP が 15658・51576・13282 反復、最低 8 回まわすので 60 秒の上限を越えて
  125 秒目まで)。最初の解は 126 秒の trivial 80。restart check の新しい固定は 0 本 (satellites2-60-fs で 110 本、閾値 343) で再スタートしない。
- 1 スレッドの解の出方の試作 (親の依頼) は**どれも既定と同じ** (600 秒):

  | 設定 | satellites2-40 | satellites2-60-fs |
  |---|---|---|
  | 既定 (o1b) | 80 (126 秒 trivial) / -29、再スタート 0 | 80 (65 秒) → 21 (81 秒 locks) / -29、0 |
  | `HEUR1T=fl` | 80 (131 秒) → 79 (148 秒 RINS) / -29、0 | 80 → 21 / -29、0 |
  | `HEUR1T=fndl` | 80 / -29、0 | 80 → 21 / -29、0 |
  | `ROBUST=pqf` | 80 / -29、0 | 80 → 21 / -29、0 |

  理由 (事実): ROBUST の `f` (FJ のやり直し) は「暫定解がなければ」で、直前の trivial が 80 を出すので飛ぶ (ログに FJ が一度も出ない)。
  HEUR1T の `f` もサブ MIP の中で暫定解がないときの話で同じ。根のヒューリスティクスは 125 秒目からしか始まらない。
  HiGHS との差は早い FJ の解 (42 と 80) より、根での固定 → 再スタートの方が大きい (5 節の試作で確かめた)。

### neos-873061

- HiGHS は根の LP を LP 前処理つきで解く (evaluateRootNode)。当方は根の LP 自体が遅い (43812 反復)。当方の LP の経路
  (`solve_lp_dual_with`、強い前処理) なら同じ LP を 5.2 秒で解くが、その解から MIP の基底に戻せない (試作 1、4 節)。
- HiGHS も再スタートを切ると時間切れ (113.668 / 113.398、195 ノード)。

### sct2

- HiGHS は L (RENS) のサブ MIP で早く改善する。RINS・RENS を切ると 317 → 768 秒、再スタートを切ると時間切れ。
  木の進め方の差は treeclose の記録 (sct2 は HiGHS が再スタート・対称性なしでも閉じる、木の差) と同じ。今回は試作なし。

### csched008

- 当方の 1 スレッドは解なしで時間切れ (171)。HiGHS は木の中の再スタートが決め手 (treeclose の記録と同じ。再スタート切りで 175 / 172 の時間切れ)。
  今回は試作なし。

## 4. 試作 1: `ENOMOTO_MIP_ROOTLP_PRESOLVE` (既定では使わない、neos-873061 向け)

根の LP (種類 3・4、warm 基底なし) を LP の経路 (`crate::simplex::solve_lp_dual_with`、前処理つき) で解き、そこから MIP の LP の基底を作る
(`src/mip/solver.rs` の `rootlp_presolve_solve`、`src/simplex/mip_lp.rs` の `solve_from_point`・`solve_from_primal_dual`)。

- 値 `1` (点だけ): 境界の内側の列・スラックを基底にして修復し、解き直す。効き目なし: 点が退化していて (境界の内側の列 184、スラック 0、行 93292)、
  解き直しは既定と同じ 43812 反復。
- **値 `d` (主双対の点からクロスオーバー)**: 双対の問題 (行の `p`・`q`、列の境界の `zl`・`zu`) も LP の経路で解いて元の行の双対 `π` を得て、
  `(x, π)` をクロスオーバー (`XoOptions::given_point`) に与えて最適基底を作り、採る (`adopt_ipm_vertex`)。経過 (neos-873061、1 スレッド):

  | 回 | 双対の LP | クロスオーバー | 根の LP 全体 | 中身 |
  |---|---|---|---|---|
  | o1_rlpd | 137 秒 | 97 秒 | 238 秒 | 双対の問題を全部の変数で解いた |
  | o1_rlpd2 | 0.78 秒 | 95 秒 | 100 秒 | 主の最適解との相補性で、`x` で等号でない行・境界にない列の双対を外した |
  | rlpd_sgnp (130 秒) | 0.87 秒 | 期限切れ | - | クロスオーバーに渡す双対の向きの取り違え (内点法の符号にしていた) を直した: D 以外の双対実行不能 174882 → 0、D は 93542 列 |
  | rlpd_fill4 (130 秒) | 0.86 秒 | **0.24 秒** | **5.5 秒** | 基底の足りない列をスラックより先に被約費用の小さい列で埋めた (`ENOMOTO_T_XO_FILL_BY_S=4`): 基底は B 184・D 91323・スラック 1785、双対実行不能 4、仕上げ 2 ピボット |

  クロスオーバーが遅かった理由 (事実、`ENOMOTO_DEBUG_CROSSOVER`): 点の境界の内側の列は 152〜184 本しかなく、双対の押し出しは飛ばされ
  (Megiddo 式の押し出しのときは射影の押し出しをしない)、基底の残り 93108〜93140 本をスラックで埋めていた。スラックを基底に入れると
  その行の双対が 0 に固定され、双対実行不能が 2224〜3202 本残って仕上げの単体法に 95 秒以上かかった。
  埋め方は `XoOptions::fill_by_s` (足りない数の 4 倍まで試す) にして、この試作のときだけ使う (既定の経路は 0 のまま)。

- 結果 (600 秒、`o1_rlpd3`): 根の LP は 101 秒 → **6.4 秒** (主の LP の経路 4.3 秒・双対 0.85 秒・クロスオーバー 0.23 秒、その後の反復 0)。
  ただし最後は 121.63 / 106.43 (10 ノード) で既定 (121.50 / 104.96、13 ノード) と変わらない。根のカットのループが 87 秒 (13 ラウンド、
  下界 95.91 → 106.35)、根のヒューリスティクスが 148 秒まで、木は 156 秒から 10 ノードだけ。HiGHS は 7645 ノード・337 秒で解くので、
  残る差はノードの LP (とカットの LP) の重さ。根の LP だけでは決め手にならない。

## 5. 試作 2: `ENOMOTO_MIP_HO4_ACFIX=d` (既定では使わない、satellites2 向け)

`src/mip/heur_ipm.rs` の `Solver::acfix_dual`。根の内点法の丸め (`interior_rounding`) の初めに、費用 0 の根の LP (カット込み) を内点法で解き
(丸めと同じ秒数の壁時計の期限、丸めの手間の予算の外)、その双対 `y` で境界に張り付く整数列を固定する。

- 正しさ: どの `y` でも、LP の実行可能な点は `Σ_j d_j (x_j - 境界) = -L(y)` (`d = -A^T y`、`L` は費用 0 のラグランジュ下界、各項は 0 以上) を
  満たすので、`d_j > 0` の整数列は `x_j - 下限 <= -L / d_j`、これが 1 未満なら下限に固定してよい (上限側も同じ、1 以上なら幅を締める)。
  費用 0・上界 0 の被約費用の固定と同じ形で、LP を解かずに正しい (浮動小数の余裕つき)。LP の境界が大域の境界を含むときだけ使い、固定は LP の
  境界から測る。カットは整数解を切らないので整数解でも正しい。
- G4 の `HO4_ACFIX` (中心の点の値で固定) は確かめなしでは qnet1・nu25-pr12 で誤った最適値、LP で確かめると satellites2 では間に合わなかった。
  その確かめの置き換え。双対の向き (内点法は `c + A^T y`) によらないよう、両方の符号で作って `-L` の小さい方を使う。
- 経過: 最初の版は向きの取り違えで `-L` 2840 (固定 0)、2 つ目は satellites2-40 で費用 0 の内点法が丸めの手間の上限 (`DET1T` の `i`) で 14 反復で
  止まり `-L` 383〜845 (固定 0)。予算の外に出して直した。

結果 (1 スレッド、600 秒、`o1_acd4`):

| 問題 | 既定 (o1b) | `HO4_ACFIX=d` |
|---|---|---|
| satellites2-40 | 80 / -29、再スタート 0 | `-L` 1.7e-9 で **12244 列を固定** → 再スタート 1 (木 181 秒)、**-14** / -29、1123 ノード |
| satellites2-60-fs | 21 / -29、再スタート 0 | `-L` 1.0e-8 で **12226 列を固定** (HiGHS 11955) → 再スタート 1、**-19 (最適値)** / -29、3434 ノード |

- 費用 0 の内点法は 3.4〜9.7 秒。どちらもまだ下界が -29 のまま (HiGHS は再スタートの後の木で 296 秒から下界を上げて閉じる)。残る差は
  再スタートの後の木 (下界の上げ方) と、根のカットのループの長さ (再スタートは 123〜181 秒目、HiGHS は 212 秒目なので同じくらい)。
- qnet1・nu25-pr12 (300 秒): 正しい最適値 (16029.69・53905)。ただしどちらも LP の境界が大域の境界より狭い列があり、この試作は使われなかった
  (固定 0)。
- P・M の計測は親の方針で後回し (他の調査の試作とまとめて回す)。

## 6. ACFIX=d の後の木で下界が上がらない理由 (satellites2、HiGHS との比べ)

satellites2-60-fs (1 スレッド、600 秒):

| | 当方 `ACFIX=d` (o1_acd4) | HiGHS (h1) |
|---|---|---|
| 再スタートの後の問題 | 7915 行 x 11554 列 | 4911 行 x 8917 列 |
| 木 | 3434 ノード、下界 -29 のまま、暫定解 -19 (最適値) | 約 140 ノードで閉じる (71 ノードで探索済み 81%、241 秒で -28.3、291 秒で -21.9) |
| 強分枝 | 分枝 2060 回のうち 2001 回は「双対退化」で強分枝なし (sb LP 262 回・4.7 万反復) | 強分枝 96319 反復 |
| 木の進め方 | DFSBB の潜り込み (平均の深さ 36) | - |

事実: 当方は双対退化の強いノード (`dual_degeneracy` が 0.8 以上か比 2 以上、根以外) で強分枝をしない。satellites2 の LP は強く退化しているので、
ほぼすべてのノードが擬似費用だけで分枝され、下界の上がる分枝を選べていない。

既存の設定で確かめた (`ENOMOTO_MIP_SB_NO_DEGEN_SKIP`: 退化でも強分枝する、`ENOMOTO_MIP_SB_BUDGET_HIGHS`: 強分枝の予算を HiGHS と同じ
100000 + 0.5 x ノードの LP の反復にする):

| 回 | 問題 | 設定 (`ACFIX=d` に足す) | 結果 |
|---|---|---|---|
| o1_acd_sb | satellites2-60-fs | NO_DEGEN_SKIP + SB_BUDGET_HIGHS | **最適 -19、500 秒、1031 ノード** (退化での省略 0、sb LP 1488 回・33 万反復、343 秒で下界 -25) |
| o1_acd_nd | satellites2-60-fs | NO_DEGEN_SKIP だけ | 時間切れ -19 / -29、2045 ノード (sb LP 642 回・13 万反復。予算に当たって擬似費用に戻る) |
| o1_acd_sb | satellites2-40 | NO_DEGEN_SKIP + SB_BUDGET_HIGHS | 時間切れ 62 / -29、974 ノード (再スタートが 154 秒目と遅く、暫定解も悪い) |

- satellites2-60-fs は 1 スレッドで初めて解けた (既定は 21 / -29 の時間切れ、HiGHS 295 秒)。根での固定 (ACFIX=d) と、木での強分枝 (退化でも
  省かず、予算も HiGHS 並み) の両方が要る。
- satellites2-40 はまだ届かない。残る差は根の長さ (カットのループが 125 秒目まで、再スタートは 154 秒目。HiGHS は 212 秒目なので根の長さは
  同じくらいだが、HiGHS は J 42 を 5.6 秒で持っている) と、再スタートの後の問題の大きさ (前処理の差)。
- 2 つの既存の設定は既定では使わない。既定にするかは P・M の計測で決める (親の方針で後回し)。
