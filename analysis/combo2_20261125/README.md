# 組み直した組み合わせ (combo2) の計測 (2026-11-25、親の依頼・利用者の承認)

前回の combo (analysis/combo_20261124) の最終の集計と害の切り分け (同 README 10.4 節・analysis/comboharm_20261124) を受けて、組み合わせを組み直す。
- nra・enum・heur は直しを入れた形にする。
- sbpb は外す (c2a)、SB_ADAPT の適応形にする (c2b)、常に使う (c2c) の 3 通りにする。
  c2c は親の追加の依頼 (利用者の問いを受けて)。

計測は 2 段。
- 第 1 段 (この記録): P (58 問 × 種 1〜3 × 60 秒、1・4 スレッド) で c2a・c2b・c2c を比べる。
- 第 2 段: 第 1 段の結果から、1 つを MIPLIB 240 問 (1・4 スレッド、600 秒) に回す。前回の combo と同じ台本を使う。

既定は変えない。どの設定も既定に足す試作の環境変数で、新しい閾値は作らない。

## 7. 害の分け方と採用の判定 (利用者の方針、2026-11-25、親経由)

利用者の方針は「道筋が変わったことによる害は、本質的な害とは見なさない」。これを受けて、最終の集計と第 2 段の判断では害の問題を 2 つに分ける。

- **(1) 道筋の害**: 正しい推論・工夫 (伝播・固定・強分枝の子の伝播など) で木や根の道筋が変わり、結果として遅くなったもの。
  - 1 ノードあたりの手間は増えず、ノードの数 (木の大きさ) や、根で解が見つかるかどうかが変わる。
- **(2) 仕組みの害**: 手間そのものが増えるもの。
  - 例: LP が重くなる、時間・手間の数え違い、判定の食い合い (nra と再スタートの判定 K)、空回り (得のない列挙・満額の孫 MIP)。

判定のしかた:
- 採用の目安の「全種 1.25 倍超の遅れ」は、(2) と未分類の問題だけで判定する。
- (1) は表の別の欄 (「同 (道筋、目安に数えない)」) に残すだけにする。
- 比の全体値 (区間の上端) と解けた数は、今までどおり全部の問題で出す。

分け方は `kind.json` に書き、summ.py が読む。キーは cause.json と同じ。**載っていない問題は (2) として数える** (分かるまでは厳しい側)。
