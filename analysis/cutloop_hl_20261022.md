# 根のカットのループで下界が HiGHS ほど伸びない原因の切り分け (2026-10-22)

- 機械: 4 CPU (`nproc` = 4、専用コンテナ)。ソルバーは同時に 1 つだけ動かした (ビルドは計測の合間)。
- コミット: ブランチ `inv/cutloop-hl-20261022` (develop `b16fcd1` から)。highspy 1.15.1。HiGHS 1.15.1 をソースからビルドし、
  `scripts/highs_instrument.patch` に、根のラウンドごとの記録と LP のカットの行の書き出しを足した
  (`cutloop_hl_20261022/highs_instrument_cutloop.patch` = 当てた後の差分全体)。
- 「1 スレッド・根だけ」は ENOMOTO `ENOMOTO_MIP_THREADS=1`・`NODE_LIMIT=1`・`ENOMOTO_MIP_NO_BG_CUTS=1` (`run_eno.sh`)、HiGHS `threads=1`
  (`run_highs.sh`)。「4 スレッド・60 秒」は ENOMOTO `ENOMOTO_MIP_THREADS=4` で木まで。
- 台本・ログは `analysis/cutloop_hl_20261022/` (§7、ログは `logs.tar.gz`)。HiGHS の書き出し (`dumps/`、64 MB) はコミットしていない (台本で作り直せる)。

## 1. 結論

事実:

1. **roll3000 の差の主因は選択の質の閾値** (`select_cuts_hybrid` の「質が最良の 0.5 倍未満は採らない」)。同じ LP の点 (HiGHS の
   ラウンド k の後の LP をそのまま ENOMOTO に入れたもの、前処理なし) から 1 ラウンド回すと:
   - k = 3: HiGHS が次のラウンドで入れた 25 本のうち 22 本はこの点で破れる。それだけを候補にして ENOMOTO の選択に通すと 9 本しか
     採らず 11342.6 → **11349.3**。閾値なし (`ENOMOTO_T_CUTSEL_MIN_REL=0`) なら 22 本全部を採り **11647.9 = HiGHS と同じ**。
     k = 6 も同じ (既定 9/17 本で 11804.7、閾値なしで 11892.6 = HiGHS)。
   - 落ちたカットを 1 本ずつ highspy で LP に足すと、単独で **+193 (効き目 0.103、非零 29)・+100 (0.127、48)・+30 (0.107、11)**。採った
     9 本は効き目 0.2〜0.35 の 2〜4 非零 (x_i − x_j <= 0 の形など) で、単独では +0〜+2。退化した LP で目的値を動かさない疎なカットが質の
     基準 (最良) になり、効き目は小さいが目的値を大きく動かす密なカットが閾値で落ちる。roll3000 の目的は列 1 本だけ (目的との平行度は
     すべて 0) で、質 (効き目 + 0.1 × 目的との平行度 + 0.1 × 整数の割合) では区別できない。
2. **カットを作る側 (分離) の差は、同じ点でなら小さい**:
   - HiGHS の tableau 分離の 1 回目の集約行 346 本を ENOMOTO の CMIR に通すと、HiGHS がカットを作った 143 本すべてで同じ効き目の
     カットができる (平均 0.0596 / 0.0595。`highs_cut_dump` のテスト)。
   - ただし同じ点で HiGHS が次のラウンドで入れたカットのうち、ENOMOTO の候補に同じものがあるのは半分程度 (k = 3: 14/25、6: 9/19、
     10: 3/8、20: 3/9)。どの行を集約するか (経路・tableau の行の選び方) の違いは残る (§3)。
3. 根の下界の分解 (roll3000、前処理なし、1 スレッド、25 ラウンド目):

   | | 下界 |
   |---|---|
   | ENOMOTO 既定 | 11827 |
   | ENOMOTO + HiGHS がそのラウンドまでに LP に入れたカットを候補に混ぜる (`INJECT_ROUND=prog`、選択は既定) | 12105 (40 ラウンドで 12390) |
   | HiGHS (前処理なし) | 12352 (43 ラウンドで 12494) |
   | HiGHS の最後の LP のカット 320 本を全部 ENOMOTO の根の LP に入れる | 12494 (その後 ENOMOTO のループで 12540) |

   HiGHS の分離器を 1 つずつ止めると、tableau だけで 12456、tableau なしで 12229 (前処理なし)。ENOMOTO は tableau のカットを止めても
   下界が変わらない (11836、既定 11827)。tableau のカットは作れているが、選択で落ちている (上の 1)。
4. **前処理ありの roll3000 では、ラウンドの上限 (25) も効く**。ENOMOTO 1 スレッドは 25 ラウンドで 12279〜12360 (止まらずまだ伸びている)、
   50 ラウンドで 12448〜12533。HiGHS は 39 ラウンド (1.9 秒) で 12619。1 ラウンドの時間は ENOMOTO 約 0.095 秒 (分離 0.084・LP 0.011)、
   HiGHS 約 0.033 秒 (分離 0.015・LP 0.018)。**分離が HiGHS の 5 倍遅い** (LP は ENOMOTO の方が速い)。
5. neos-911970 は別の仕組み。HiGHS の LP の点から始めれば ENOMOTO の 1 ラウンドは HiGHS と同等以上 (k = 15: 49.999、HiGHS 49.964)。
   HiGHS も 47.26 で 2 ラウンド止まるが、そこから抜ける。ENOMOTO は自分の頂点で 47.26 から動かない (19〜24 ラウンド)。閾値の試作は
   最初のループでは効かない (47.26 のまま)。前回の in-out 分離 (中心寄りの点で分離すると 52.0) と合う: 退化した最適面のどの頂点で
   分離するかの問題。
6. mzzv42z は「LP の大きさ・1 ラウンドの重さ」と時間の上限。ENOMOTO の根の LP は 10661 行 (HiGHS の前処理後 6282 行)、1 ラウンド
   0.6〜1.0 秒 (分離 0.3・LP 0.3〜0.5)、HiGHS は 0.24 秒 (分離 0.05・LP 0.07)。根のカットの時間の上限 (60 秒の 10%) で 5〜8 ラウンドで止まる
   (HiGHS 16 ラウンド)。上限を 50% にすると 25 ラウンドで −20795、再スタートの後 −20748 (HiGHS の根 −20738)。1 ラウンドの伸びも
   HiGHS より小さい (4 ラウンド目 −20926、HiGHS −20800) が、前処理の差 (presolve_gap_20261022.md) と分けていない。
7. 試作 `ENOMOTO_MIP_CUTSEL_FEEDBACK=main` (前のラウンドの伸びが |目的値| の 1e-3 未満なら閾値を半分に、0.05 まで。伸びれば 0.5 に戻す。
   裏のカットのループでは使わない) は roll3000 の根を 12268〜12323 → 12367〜12405、physiciansched6-2 (代入あり) を 49091 → 49322 に上げる。
   副作用は mik-250 が +0.5〜1 秒。60 秒の結果が良くなった問題はまだない (§5)。裏のループでも使う `=1` は misc07 が 2 倍遅いので不採用。

推測:

- 「効き目の大きいカットが目的値を動かさない」は退化した LP (roll3000、neos-911970 の 47.26 の面) で起きやすい。HiGHS の選択は
  閾値の係数を、採れる数が少ないとき (5% 以下) に下げ続けて元に戻さないので、ラウンドが進むとほとんどの破れたカットを採る
  (`HighsCutPool::separate`)。ENOMOTO は毎ラウンド「そのラウンドの最良の 0.5 倍」に戻る。
- physiciansched6-2 は今回は掘っていない (§5 で試作の効き目だけ見た)。

## 5. 試作 `ENOMOTO_MIP_CUTSEL_FEEDBACK`

- `src/mip/separation.rs` の `root_cut_loop`。既定の選択 (`select_cuts_hybrid`) の質の閾値を、前のラウンドの目的値の伸び
  g = Δ目的値 / max(1, |目的値|) で変える: g < `ENOMOTO_T_CUTSEL_FB_TAU` (1e-3) なら閾値を半分に (`ENOMOTO_T_CUTSEL_FB_FLOOR` = 0.05 まで)、
  それ以上なら `ENOMOTO_T_CUTSEL_MIN_REL` (0.5) に戻す。固定費用型の緩めた選択 (`fc_relax`)・第 2 段階・`CUTSEL_HIGHS` の方が優先
  (mc11・beasleyC3・h80x6320d の最初のループは変わらない)。
- `=1`: 裏のカットのループ (根のヒューリスティクスの間に別スレッドで回すもの) でも使う (fb)。`=main`: 裏のループでは使わない (fbm)。
- 1 スレッド・根だけ: roll3000 (前処理あり) の 25 ラウンド目 12279〜12361 → 12422 (50 ラウンド: 12533 → 12559)、前処理なし 11827 → 12069。

## 6. 確かでない点・しなかったこと

- 分離が HiGHS の 5 倍遅い理由 (roll3000: 分離 0.084 秒 / ラウンド、`separate()` の中の合計は 0.03〜0.05 秒で、残りは面の頂点の分離の
  準備などとみるが分けていない)。
- 同じ点で HiGHS が入れたカットの半分が ENOMOTO の候補にない理由 (経路集約の始点・tableau の行の選び方)。HiGHS のカットを全部候補に
  混ぜても (prog) 25 ラウンド目で HiGHS に 250 届かないので、これも効いているはず。
- neos-911970 の退化した面 (§1 の 5)、mzzv42z の LP の大きさは試作していない。physiciansched6-2 は根の数字だけ。
- 前処理ありの問題に HiGHS のカットを入れる実験はしていない (列の対応が要る)。§3・§4 はすべて前処理なし。
- ENOMOTO は 1 スレッドでも根の経過が回ごとに違う (roll3000 の 25 ラウンド目 12279〜12361)。
- `cargo test --release --lib`: 既定・`ENOMOTO_MIP_CUTSEL_FEEDBACK=main` とも 310 件通過 (18 件は無視の印)。

## 7. ファイル

  `ENOMOTO_MIP_INJECT_CAND=ファイル`、`ENOMOTO_MIP_INJECT_ONLY`、`ENOMOTO_MIP_DEBUG_CAND_DUMP=ファイル`。前処理なし (`ENOMOTO_MIP_NO_PRESOLVE`) で使う。
