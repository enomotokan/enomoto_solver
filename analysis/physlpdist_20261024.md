  その求解の問題 (ENOMOTO の前処理後、111827 列、自由な整数列 5443) を `<接頭辞>0.mps`、カットの後の LP 解を `_x.txt`、
  カットの前の LP 解を `_x0.txt` に書く。
- 書き出した 3 つ (どれも `ENOMOTO_MIP_CUT_AGG=1 ENOMOTO_T_MIP_CUT_EXTEND_MAX=0.5`):

  | 名前 | LP の値 (カットの後) | 最適値 49324 との差 | 回 |
  |---|---|---|---|
  | `a1_0` | 48757.3 | 567 (1.15%) | 60 秒 (`agg50_1`) |
  | `a2_0` | 48940.7 | 383 (0.78%) | 60 秒・再スタートなし (`agg50nr_1`) |
  | `b1_0` | 49247.4 | 77 (0.16%) | 150 秒・再スタートなし (`agg150nr_1`) |

- 比べた相手 (HiGHS 1.15.1、4 スレッド。台本は `analysis/physlpdist_20261024/`):

  - **LP 解に最も近い最適解**: 目的値 ≤ 49324 の整数解のうち、自由な整数列の L1 距離 Σ|x_j − x̄_j| が最小のもの (`dist.py`)。
  - **反転の最小数**: LP で整数値 (0 か 1) の列のうち、実行可能解 (目的値の上限つき・なし) にするために値を変えなければならない列の最小数 (`flips.py`)。

## 1. 結論

事実:

1. **LP 解は分数の列が多く、しかも本当に分数 (0.1〜0.9) の値が大半**。目的値が最適値に近づいても大きくは減らない。

   | | `a1_0` (48757) | `a2_0` (48941) | `b1_0` (49247) | カットの前 (48583) |
   |---|---|---|---|---|
   | 分数の列 (自由な整数列 5443 のうち) | 1808 (33%) | 1827 (34%) | 1539 (28%) | 1782 (33%) |
   | そのうち値が 0.1〜0.9 | 1508 | 1413 | 1146 | 1543 |
   | LP で 1 の列 / 0 の列 | 673 / 2962 | 715 / 2901 | 878 / 3026 | 553 / 3108 |
   | 分数の列の、最も近い整数までの距離の和 | 468.5 | 430.7 | 358.7 | 553.7 |

   最適解で 1 の列は 1555 本。

2. **LP 解に最も近い最適解でも、L1 距離は 490〜710**。

   | | `a1_0` | `a2_0` | `b1_0` |
   |---|---|---|---|
   | HiGHS の最適解 1 つとの L1 | 1445.6 | 1335.2 | 1293.0 |
   | 　その最適解と違う「LP で整数値の列」 | 592 | 526 | 619 |
   | **最も近い最適解との L1** | 710.3 (下限 697.1、300 秒で打ち切り) | **627.3** (最適) | **489.5** (最適) |
   | 　内訳: 分数の列の分 / 整数値の列の分 | 659.3 / 51 | 599.3 / 28 | 474.5 / 15 |
   | 　分数の列を四捨五入した値が最適解と合う割合 | 0.686 | 0.494 | 0.745 |

   - 最適解は多数ある (HiGHS の 1 つは LP の整数値の列と 600 本前後違うが、最も近いものは 15〜51 本しか違わない)。
   - 最も近い最適解でも、分数の列の 25〜50% は四捨五入と逆の値を取る。四捨五入だけで決まる距離 (1 の表の最後の行) の上に、
     116〜190 の余分な距離がある。

3. **RENS (LP で整数値の列を全部固定) が実行不能になる理由が特定できた**: LP の整数値の列のうち、少数を反転しないとどんな実行可能解も作れない。

   | | `a1_0` | `b1_0` |
   |---|---|---|
   | 実行可能解 (目的値の上限なし) に要る最小の反転 | 11 (解 50624.5) | **1** (解 49724) |
   | 目的値 ≤ 51029 (FJ の暫定解) | 11 | 1 |
   | 目的値 ≤ 49324 (最適) | 20 | **1** |

   - `b1_0` で反転が要る 1 本は `c89965` (LP では 0、最適解では 1)。行は
     `x1 + x2 + x3 + x4 + x5 + 5 z ≤ 5` と `x1 + x2 + x3 + x4 + x5 + z ≥ 1`、つまり **「5 本の x がどれも 0 のときに限り z = 1」** という
     指示の列。LP は x を 0.25 × 4 (和 1) にして z = 0 で両方の行を満たすので、z は整数値に見えるが、それは分数の x が支えている値。
     最適解では x がすべて 0 で z = 1。z = 0 に固定すると x のどれかが 1 でなければならず、近傍に解がなくなる。
   - `a1_0` で反転が要る 20 本には、同じ形の指示の列 (`c89963`・`c89985`・`c90447` など列の非零 2) のほか、係数 100〜500 の
     ナップサック型の行や「13 以上を覆う」行に入る普通の列 (`c11542`・`c52943`・`c86629` など) がある。LP が弱いほど、整数値の列の並びが
     組として最適解と食い違う。

4. **固定する列の選び方を変えた RENS の近傍** (`rensvar.py`、HiGHS で 60 秒まで):

   | 固定する列 | `a1_0` | `a2_0` | `b1_0` |
   |---|---|---|---|
   | LP で整数値の列を全部 (旧来の RENS) | 3635 本、実行不能 (0.1 秒) | 3616 本、実行不能 (0.2 秒) | 3904 本、実行不能 (0.4 秒) |
   | そのうち、分数の列と同じ行に入らない列だけ | 546 本、実行不能 (1.4 秒) | 626 本、実行不能 (1.2 秒) | **912 本、49324 (最適)・1 ノード・6.8 秒** |

   LP で整数値の列のうち、分数の列と同じ行に入るものは 2990〜3089 本 (どれも目的の係数 0)。

推測:

- 「目的値が最適値に近ければ LP 解の近くに解がある」が成り立たないのは、この問題の LP の最適な面が大きく (根の LP face で固定できるのは
  5443 列中 129 列)、LP 解がその面の、整数点から組合せの意味で遠い頂点にあるため。とくに「すべて 0 のときに限り 1」の指示の列は、LP では
  分数の x の和が 1 あれば 0 で済むので、LP の整数値がそのまま誤りになる。丸め・ダイビング・RENS は LP の整数値を正しいものとして
  使うので、この型の列があると外れる。
- HiGHS が根のサブ MIP で解を出せるのは、暫定解との一致で近傍を作り (RINS)、強い前処理とカットで近傍の LP を整数に近づけるためで、
  LP 解の整数値そのものに頼っていないとみる (`physprimal_20261024.md` の書き出し 3 つは、どれも RINS の近傍に解があった)。
- 手当ての候補 (試していない): (a) RENS で、LP の整数値の列のうち分数の列と同じ行に入るものは固定しない (`b1_0` なら近傍に最適解。
  ただし LP が弱い `a1_0`・`a2_0` では足りない)、(b) 指示の列 (`Σx + K z ≤ K`・`Σx + z ≥ 1` の組) を見つけ、z を x の側から決める
  (z を固定の対象から外す・ダイビングで z を最後に決める)、(c) この型の組に対する強いカット (`x_i + z ≤ 1` を各 i に。LP で
  x = 0.25 × 4・z = 0 を切らないので弱さの本体ではないが、z の値を x と結びつける)。

## 2. 台本・ログ (`analysis/physlpdist_20261024/`)

- `run_cfg.sh`・`eno_run.py`・`sumlog.py`: `physprimal_20261024` と同じ。
- `dist.py <接頭辞k> [最適値] [秒]`: LP 解の形、HiGHS の最適解との差、LP 解に最も近い最適解 (`ONLY=x` でカットの後の解だけ)。結果 `logs/dist_*.txt`。
- `flips.py <接頭辞k> <目的値の上限 or ''> [秒]`: LP で整数値の列の反転の最小数と、反転した列。結果 `logs/flips.txt`。
- `colctx.py <接頭辞k> <列名> [解]`: 列が入る行と、その行の各列の LP 値・解の値。
- `rensvar.py <接頭辞k> [秒]`: 固定の選び方を変えた RENS の近傍を HiGHS で解く。結果 `logs/rensvar.txt`。
- `dumpgz/`: `b1_0` の問題・LP 解 (カットの前後)・HiGHS の最適解・最も近い最適解・反転 1 本の解と、`a1_0` の問題・LP 解 (gzip)。
  ほかの書き出し (`dump/`、1 つ 8MB) はコミットしていない (上の回の環境変数に `ENOMOTO_MIP_DEBUG_DUMP_ROOT_X` を足して作り直せる)。
- `cargo test --release --lib`: 313 件通過・18 件無視。
