## 1. 試作 (既定では使わない。既定の経路と `=r`・`=rw`・`=q` は変えない)

- 重みの育ち具合 (`src/simplex/slope_intercept_dual.rs`): 双対単体法が DSE 重みを初期化してからの反復の数 (仕上げの反復を含む) を求解をまたいで数える。
  - 初期化のときの値: warm start の単位重み 0、全スラック基底 (warm start でない) の単位重みは厳密な値なので `u64::MAX` (育ちきった扱い)、
    厳密な値 (`DSE_EXACT_ONCE`・`ENOMOTO_DSE_EXACT_INIT`・主ループの中の計算し直し 5 か所) も `u64::MAX`、`=rw` の BTRAN を途中でやめた単位重みは 0、
    引き継いだ重みは呼び出し側が一緒に渡す値 (`WARM_DSE_AGE`)。
  - 求解の終わりに「初期化のときの値 + この求解の反復」を `LAST_DSE_AGE` に残す (最後の重み `LAST_DSE` と、打ち切りの続きの状態 `LAST_STOP_STATE` の両方)。
- `TwoStageLp` (`src/simplex/mip_lp.rs`): `dse_cache` と並べて `dse_age` を持つ (求解の後に `LAST_DSE_AGE`、warm start で `WARM_DSE_AGE` に渡す、
  状態の保存・戻しで一緒に動く、外から当てはめた重み (`set_dse_vars`・`adopt_lu_snapshot`) は分からないので 0、行の追加・削除で重みを引き継ぐときはそのまま)。
  `dse_age()` (重みがなければ `None`) と `recompute_dse_exact(stop)` (手元の同じ基底の LU キャッシュから行ごとの BTRAN で厳密な重みを計算して
  次の求解に引き継ぐ重みにする。32 行ごとに `stop` を見てやめる。LU がなければ何もしない) を足した (`MipLp` にも既定の実装つきで足した)。
- `ENOMOTO_MIP_BG_CUTS_DSE=g` (`src/mip/solver.rs`): 写しの根の LP が最適で終わった時点で、重みがない、または育ち具合が
  `α × 行数 m` 未満 (α = `ENOMOTO_T_MIP_BG_CUTS_DSE_GROW`、既定 1) なら、最初のカットの LP の前に `recompute_dse_exact` をかける
  (列の値を渡したかによらない)。止める条件は写しの LP の期限・取り消し・主の止めの合図 (`CutJob::stop`) で、`=rw` と同じく 32 行ごとに見る。
  カットの LP の外 (根の LP と最初のカットの LP の間) で計算するので、`=x` のようにカットの LP 1 回の上限に食い込まない。
  表示: `[snapshot] DSE weights not grown after the root LP (N iters; age A < α x m rows); exact weights recomputed (s)` / `... stopped by ...` /
  `DSE weights grown after the root LP ...; kept`。

### 数え方の確かめ (`check/debug_ext_iters.txt`、`ENOMOTO_DEBUG_EXT_ITERS=1`)

- 写しの根の LP は、主の基底を置いて **warm start の単位重みから始まる** (`DSE weights: unit (warm_started=true, passed=none, ...)`)。主の重みは渡らないので
  (渡すのは `=1`)、根の LP が 1 反復で終わると年齢 1。最初のカットの LP は `inherited (… rows, 0 unknown, age exact)` で、計算し直した重みを引き継ぐ
  (足したカットの行の重みは今までどおり 1)。
- 引き継ぎの数え方: 同じログの主のスレッドの LP は `inherited (4102 rows, …, age 2)`・`age 3`・…・`age 371` と 1 回ごとに反復の分だけ増える。
  mc11 の主の重みは年齢 4218 (行数 2654 の 1.6 倍) で育っているのに、写しは 1。**写しの重みが育っていないことは数え方で正しく見えている**。

ひととおり育つ) として 1 のままにした。

## 3. 結論

1. **`=g` は数え方としては正しく「写しの重みが育っていない」を捉えるが、写しではそれが全部の問題で真なので、条件として何も選ばない**。実際には
   「写しで常に厳密な重み」(= `=r` を根の LP の後に移した形) になり、bench16 の `=r` の害がそのまま出た。
2. **mc11 は 3/3 で時間切れ** (`w1` 3/3 最適 35〜60 秒、def 3/3、`w1_rw` 3/3): 写しのカットの LP の反復の並びが最初から変わり (`w1` 229・172・167…、
   `w1_g` 151・126・145…)、32・33 ラウンド目が反復の上限 (それまでの最大の 5 倍) に当たって外され (4725・4276 反復)、写しは 34 ラウンド・下界 11558
   (`w1` は 51 ラウンド・11666) で終わる。3 回とも同じ並び (決定的)。
3. **roll3000 は 3/3 で時間切れ** (def 2/3、`w1` 2/3、`w1_rw` 1/3): 写しが 18 ラウンド・12478.6 で止まる (ほかは 69〜70 ラウンド・12650.4)。外した LP はなく、
   ループの止め方 (進み具合) で早く止まる。これも 3 回とも同じ。
4. 列の値を渡す問題では `=g` は `=rw` とほぼ同じ: neos-960392 (2/2 で `rw` と同じ並び 1086・381・365・170・365・730、6 ラウンド・失敗 0。`w1` は 2 ラウンド)、
   neos-933966 (7〜8 ラウンド・失敗 0)、comp07-2idx (`rw` と同じ並び、8 ラウンド、写し 6)、physiciansched6-2 (**2/2 最適** 33.7・34.4 秒、`w1_rw` 2/2、`w1` 1/2、
   def 0/2)。厳密な重みの計算は 0.17 秒 (neos-960392)〜1.9 秒 (comp07-2idx)〜5〜6 秒 (atlanta-ip)。
5. atlanta-ip はどの設定でも写しが結果を返さない (主の止めの合図の方が先、この機械が遅いため)。`=g`・`=rw` は根で 5〜6 秒使う分、止めの合図の時点で
   回せたラウンドが少ない (`w1` 5・8 本、`w1_g` 0・5 本、`w1_rw` 1・6 本)。
6. **時間の上限は守られた**: neos-4763324-toguru 60.3 秒 (BTRAN 106772 行を 6.3 秒で止めの合図でやめる、待ち 0.01 秒)、uccase12 60.3 秒 (88598 行を 29.5 秒で
   やめる、待ち 0.16 秒)、neos-4722843-widden 60.2〜60.3 秒 (9.6〜12.7 秒でやめる)。ただし toguru・uccase12 では `=rw` はかからない問題なのに `=g` は
   写しのラウンドを 0 にする (`w1` は toguru 1 本、uccase12 5 本・6 ラウンド)。
7. 判断: **`=g` は採らない (bench に出さない)**。害の理由は「重みが育っているのに計算し直す」ことではなく (mc11・roll3000 の写しも育っていない)、
   **厳密な重みに変えると着く頂点・カットの道が変わること**で、その影響は道に敏感な問題 (mc11・roll3000) で大きく、カットの LP が軽い問題 (100〜200 反復) では
   単位重みでも困っていない。つまり「重みが育っていない」は「価格付けが悪くて困る」の必要条件でしかなく、困るかどうかはカットの LP の重さで決まる。
   その困る側は `LP_WORK=1` (反復の上限) で既に失敗 0 になっている (neos-960392・neos-933966・comp07-2idx は `w1` で失敗 0)。
8. 次の候補 (試していない): 条件を重みの年齢ではなく「最初のカットの LP が重い」側で決める形、たとえば写しのカットの LP が上限の一部 (例: 反復の上限の半分) を
   単位重みで使い切ったときだけ厳密な重みで解き直す。道が変わるのは困った問題だけになる。または写しにも主の重み (年齢 4218 のように育っている) を
   年齢と一緒に渡し、年齢で判断する形 (`=1` は主の重みのずれで半端だった、bgdse の 2 節)。
