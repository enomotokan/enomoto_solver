# timtab1 の調査 (根のカット・木・主側の切り分け、2026-10-20)

- 環境: 専用コンテナ 4 CPU (`nproc` = 4)。develop 0542795 から分けたブランチ `inv/timtab1-20261020`、HiGHS 1.15.1 (highspy、
  `mip_rel_gap=0`、`threads=4`)。ENOMOTO は `m.solve(None, False, T, None, None, 4, log=True)` + `ENOMOTO_MIP_THREADS=4`。
  ソルバーは同時に 1 つだけ動かした。
- timtab1: 171 行 397 列 (2 値 64、一般整数 107、連続 226)、最小化、最適値 764772。行はすべて等式
  `±x_i ± x_j ... - 60 p = 定数` (周期 60 の時刻表、x は [0, 59] などの連続、p は 0〜5 の整数)。

### 打ち切り値に最適値を与えた比較 (双対側だけ。ENOMOTO `ENOMOTO_MIP_CUTOFF=764773`、HiGHS `objective_bound=764773`)

→ **主因は双対側** (根のカットの下界と木の下界の伸び)。HiGHS が 47 秒・5.5k ノードで達する 695k に、ENOMOTO は 300 秒・11 万ノードかかる。
主側 (暫定解) も遅いが、打ち切り値を与えても証明できないので先に双対側を見た。

### 既定の根のカットのループ (`ENOMOTO_MIP_LOG=1`)

- 毎ラウンド候補 2400〜3600 本 (ほとんど元の行の CMIR と経路集約) から 3〜27 本しか採らない (既定の選択 `select_cuts_hybrid`、
  質が最良の 50% 未満は採らない)。カットは非零 2〜4 の短いもの。
- 下界は 25 ラウンド目まで毎ラウンド伸びており (例: ラウンド 23→24 で 492576 → 495790)、**ラウンドの上限 25 で止まる**。
  停滞の判定に届かないので、`ENOMOTO_MIP_CUT_PHASE2` (停滞したら HiGHS のスコアの選択に切り替える第 2 段階) や
  `ENOMOTO_MIP_HIGHS_CUTMGMT` を付けても、多くの実行で第 2 段階に入らない (HCM の 60 秒 4 回のうち根の下界が上がったのは 1 回)。
- 上限に当たったところで第 2 段階に入れると (下の試作)、32〜40 ラウンド目で 598k〜607k (2.9〜3.8 秒) まで上がる。HiGHS の 569k〜610k と同じ。

### 木の側の観察 (打ち切り値つき、60 秒)

- 主の木のスレッドのノードの LP は平均 1408 行・116 反復 (HiGHS は分枝を含めて 1 ノード約 57 反復)。基底の復元 3077 回のうち
  1531 回は基底の大きさが合わず、ノードの LP の反復 73.7 万のうち 65.1 万が「復元の後の最初の LP」。
- 強分岐: 分枝の選択 2332 回 (主スレッド、30 秒) で強分岐の LP 1294 本 (1.6 万反復、全反復の約 2.5%。HiGHS は約 10%)。
  双対退化で強分岐を止めた回数は 0 (診断用に数を出すようにした)。
- 対称性: 前処理で消えた (固定された) 196 列どうしの入れ替えを「対称性」として 194 生成元・lex-leader 行 170 本・1x25 の
  オービトープを作っている。`ENOMOTO_MIP_NO_SYMMETRY=1` でも下界は変わらない (120 秒 674527 vs 既定 675030) ので害はない
  (行は固定列だけなので無意味)。

## 推測

- timtab1 の差の大部分は双対側。根では既定の選択が 1 ラウンドに数本しか採らず、25 ラウンドの上限で下界がまだ伸びている
  ところで止まる (HiGHS は同じ段階で 100k 上)。第 2 段階 (HiGHS のスコア) が停滞したときにしか入らない作りなので、伸び続ける
  問題では使われない。上限で第 2 段階に入れると根は HiGHS に並ぶ。
- それだけでは木の伸びは HiGHS の半分程度 (60 秒で 673k〜690k)。HCM (取り出したノードでのプール + 新しい分離のラウンド、
  年齢によるカットの外し、潜りの上限 100、基底の保護なし) を合わせると、ノードの LP が軽く (946 行・68 反復) なり下界の伸びが
  HiGHS に近づき、150 秒以内に証明できる。HiGHS (71 秒) との残りの差は、主側 (最適解を見つけるのが HiGHS は 51 秒、こちらは
  50〜100 秒、根のサブ MIP の解が HiGHS の 804458 に対しこちらは 929196) と、HiGHS の 16.6 秒の再スタート (下界 630k → 658k)
  にあると見ている (こちらは再スタートしない。未確認)。
- HCM は既知のとおり mik-250・rout・qnet1・neos-860300 などを遅くする (40 問では既定にしなかった) ので、既定にするなら
  timtab1 のような問題 (伸び続けて上限で止まる・一般整数の等式) に絞る判定が要る。`CUT_PHASE2_AT_CAP` 単独は根を上げるが
  10teams・qnet1 で遅くなる (10teams は既定でも 9.9〜37 秒と揺れる)。
- 前処理の大きさの差 (201 列 vs HiGHS 361 列) の影響は調べていない (`ENOMOTO_DISABLE_AGGREGATOR` では前処理後の大きさが
  変わらず、列を消しているのは別の縮約)。

## 試作 (既定は変えない)

- `ENOMOTO_MIP_CUT_PHASE2_AT_CAP` (separation.rs `root_cut_loop`): 根のカットのループの第 1 段階がラウンドの上限に当たって
  止まるとき、停滞していなくても第 2 段階 (HiGHS のスコアの選択、`ENOMOTO_T_MIP_CUT_PHASE2_ROUNDS` ラウンド・第 1 段階の
  時間の `ENOMOTO_T_MIP_CUT_PHASE2_TIME_MULT` 倍まで) へ進む。`ENOMOTO_MIP_CUT_PHASE2` がなくても働く (停滞で止まる場合は既定のまま)。
  サブ MIP では使わない。
- 診断: 終了時のログ (`ENOMOTO_MIP_LOG`) に分枝の選択の回数・双対退化で強分岐をしなかった回数を出す。
  `ENOMOTO_MIP_SB_NO_DEGEN_SKIP` で双対退化による強分岐の停止を外す (timtab1 では 0 回なので効果は測っていない)。

計測にそのまま渡す組:

- 推奨 (timtab1 を解く): `ENOMOTO_MIP_HIGHS_CUTMGMT=1 ENOMOTO_MIP_CUT_PHASE2_AT_CAP=1`
- 根だけ: `ENOMOTO_MIP_CUT_PHASE2_AT_CAP=1`
