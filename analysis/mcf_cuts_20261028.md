# 多品種フロー (MCF) の cut-set カットの試作 (2026-10-28)

SCIP の `sepa_mcf.c` (Achterberg & Raack, "The MCF-separator: detecting and exploiting multi-commodity flow structures
in MIPs", 2010) に当たる分離を `src/mip/mcf.rs` に移植し、`ENOMOTO_MIP_SEPA_MCF` で入り切りできる試作として入れた。
**既定は変えない** (環境変数を付けなければ分離のコードは一切通らない)。

結論:

- 検出は 71 問中 27 問で網が見つかり (根まで届かなかった dano3mip を除く 70 問中)、23 問で集約からカットの候補が出た。
- 品種が複数ある網・VUB 型でない網 (fiber・ta2-UUE・germany50-UUM・beavma・khb05250・neos-4387871-tavua) では根の下界がはっきり上がる。
  ta2-UUE は 120 秒で解けなかったのが 4 回とも 70〜77 秒で解け、tavua は最後のギャップ 38% -> 28%、fiber は根のギャップの 56〜60% を閉じる。
- 固定費用ネットワーク型 (`fixed_charge_network`、VUB の行が大半の 1 品種の網: mc11・mc7・n3700 系・beasleyC3・h80x6320d など) では、
  1 節点の cut-set は経路集約と flow cover のカットとほぼ同じで、採られるのはラウンドあたり 1 本程度。根の下界は揺れの範囲で上下し、
  h80x6320d は再スタートの経路が変わって遅くなる (52 -> 110 秒、1 回は時間切れ)。
- そこで `ENOMOTO_MIP_SEPA_MCF=auto` (固定費用ネットワーク型でない問題でだけ使う) を足した。今回の 24 問 x 2 回に当てはめると
  解けた回 11 -> 13、時間のずらし幾何平均 74.66 -> 73.03 秒 (全部で使う `1` は 12 回・75.34 秒)。
- 既定にするには、MCF の網がない問題で何も変わらないことは確かだが (検出だけ、数 ms)、網のある問題での揺れ (ta1-UUM の
  カット選択の比べの判定が変わる、neos-1171737 の暫定解が悪い回がある) をもっと多くの問題・回数で確かめる必要がある。今回は保留。

## 1. 実装

### 1.1 検出 (`mcf::extract`、根で最初に分離するときに 1 回だけ、元の行から)

SCIP の `mcfnetworkExtract` の順に移植した。

1. 流量保存の候補 (`extractFlowRows`): 係数の絶対値が全部同じ行 (長さが列の 1 割以下)。点数は SCIP と同じ (拡大縮小が要らない +1000、
   正負の係数が両方 +500、列の型がそろう、長さ、等式 +50)。
2. 品種 (`extractFlow`): 点数の順に、まだ使っていない行から品種を始め、新しく入った列を後ろから見て、その列を含む行のうち品種に合う
   (同じ品種で同じ符号の列が 2 度入らない、ほかの品種の列を含まない) 最良の行を足していく。等式だけの品種は向きを反転できる。
   節点 3 未満・最大の品種の半分未満の品種は消す。
3. 容量の候補 (`extractCapacityRows`): 流量の列を含む残りの行。点数は SCIP と同じ。品種ごとの流量の列の数の点数の和で、向きあり
   (1 品種 1 列) か向きなし (反対向きの 2 列が容量を共有) かを多数決で決める。
4. 弧 (`extractCapacities`): 点数の順に、流量の列の 1/3 以上がまだ弧に割り当てられていない行を弧にする。
5. 節点 (`extractNodes`): 品種の違う流量保存の行どうしで、容量の行を通じた弧の重なりの点数 (`getNodeSimilarityScore`) が最良の行を同じ節点にする。
6. 後始末 (`cleanupNetwork`)、弧の始点・終点の多数決 (`identifySourcesTargets`。食い違いが弧の数の 2% を超えたら網を使わない)、
   容量の行のない流量の列から容量なしの弧 (`findUncapacitatedArcs`、ここでは節点の組ごとに数える簡単な形)、連結成分ごとに網
   (節点・弧が 3 以上、大きい順に 4 つまで)。

SCIP との違い:

- SCIP は LP の双対値を点数の同点の決め手と、等式の向きの決め手に使う。ここでは使わない (検出は分離の前に 1 回だけ、元の行から)。
  等式の向きは右辺 < 0 なら右辺側、左辺 > 0 なら左辺側、それ以外は右辺側 (SCIP の双対値がないときと同じ)。
- 容量の行を両側で使える (等式) とき、SCIP は右辺側を使う。ここでは流量の係数が正になる側を使う (`c x - sum f = 0` を右辺側で
  使うと流量が打ち消されない)。
- SCIP の `getNodeSimilarityScore` には「重なる弧が 2 本以上なら +1000」があるが、直後の代入で上書きされて効いていない。同じにした。
- 食い違いの上限は `ENOMOTO_T_MIP_MCF_MAX_INCONS` (0.02、SCIP と同じ) で変えられる。

### 1.2 分離 (`mcf::aggregations` → `separation.rs` で CMIR に通す)

SCIP の `generateClusterCuts` の集約の部分を移植した。節点の集合 S について:

- S の需要 `sum_{v in S} (-d_v^k)` が負の品種 (向きなしなら 0 でない品種) を選ぶ。
- T = V \ S から S に入る弧 (向きなしなら S と T をまたぐ弧) の容量の行を重み `arccapacityscale` で足す。余裕が最大係数の 0.1 倍を
  超える行は使わない (端点が不明な弧は余裕 0 の行だけ)。
- その品種の S (需要の向きが逆なら T) の流量保存の行を、容量の行の流量の係数の大きさ x 行の倍率で足す (余裕のある行は使わない)。
- 重みの最大 / 最小が 1e6 を超える集約は使わない。

できた行 `flow(S -> T) - c x(T -> S) <= -d_S` を、経路集約と同じく行の活動量の列 (スラック) を含めた形で
`cuts::generate_cuts` (CMIR・lifted flow cover・extended cover) に通し、`finish_cut` で仕上げる。スラックを含めて足すので、
検出が外れていてもできる行はいつでも妥当で、外れはカットの強さにしか効かない。

S の選び方は SCIP と同じ: 1 節点ずつ (向きありなら S = {v} と T = {v} の両方)、続いて弧の重み `余裕 x 倍率 - |双対値| / 倍率`
(容量なしの弧は無限大、需要のある節点どうしは後回し) の大きい順に節点を縮めた `ENOMOTO_T_MIP_MCF_CLUSTERS` (5) 個の塊の部分集合
(S と T がそれぞれつながっているものだけ、1 節点の S・T は除く)。集約は `ENOMOTO_T_MIP_MCF_MAX_AGGS` (400) 本まで、
候補は 1 ラウンド `ENOMOTO_T_MIP_MCF_MAX_CUTS` (200) 本まで。

移植していないもの: SCIP の flowcutset (容量の行を外すと違反が増えるなら外して作り直す)、knapsack cover の分離、
delta の候補を容量の係数から作ること (`generate_cuts` が自分で delta を選ぶ)、aggressive の effort level。

### 1.3 切り替え

| 環境変数 | 意味 |
|---|---|
| `ENOMOTO_MIP_SEPA_MCF=1` (`root`) | 根の分離で使う (サブ MIP では使わない) |
| `ENOMOTO_MIP_SEPA_MCF=nodes` | ノードの分離 (`light`) でも使う |
| `ENOMOTO_MIP_SEPA_MCF=auto` (`auto-nodes`) | 固定費用ネットワーク型 (`fixed_charge_network`) でない問題でだけ使う |
| `ENOMOTO_MIP_MCF_NO_SINGLE` | 1 節点の cut-set を使わない (塊の部分集合だけ) |
| `ENOMOTO_MIP_DEBUG_MCF` (または `ENOMOTO_MIP_LOG`) | 検出の結果 (`MCF detect: ...`) とラウンドごとの集約・候補の数 (`MCF sep: ...`) を出す |
| `ENOMOTO_T_MIP_MCF_CLUSTERS` / `_MAX_AGGS` / `_MAX_CUTS` / `_MAX_INCONS` | 5 / 400 / 200 / 0.02 |

`ENOMOTO_MIP_DEBUG_SEPPROF` の集計に分離器 `mcf` (候補と採った本数) と段階 `mcf` (時間) を足した。

### 4.3 下界が下がる問題の中身

- mc11 (根だけ、`ENOMOTO_MIP_DEBUG_SEPPROF`): どちらも根のループが上限の 25 ラウンドまで回り、毎ラウンド 50 本を入れて下界はまだ伸びている。
  MCF の候補はラウンドあたり 79 本出るが採られるのは 1 本で、1 節点の cut-set の CMIR は経路集約 (path_highs 22 本・path 12 本) の
  カットとほぼ同じ。下界の差は入る順の違いによる軌跡の揺れ (MCF の時間はラウンドあたり 12 ms、根のループ 1.14 -> 1.42 秒)。
- h80x6320d: 再スタートの後は MCF の候補がラウンドあたり 0.4 本しか出ず、遅くなるのは再スタートの経路 (固定される列の数) が変わるため。
- ta1-UUM: MCF の候補は最後の選択でほぼ採られない (0.0 本 / ラウンド) が、カット選択の比べ (`ENOMOTO_MIP_CUTSEL_PROBE`) の判定が
  既定 (`default`) から `pool` に変わり (比べが早く止まる)、その後の根の下界が 4.16e6 -> 3.93〜4.05e6 になる。カットそのものではなく
  比べの判定への波及。
- beasleyC3: 根の下界は下がるが、木の探索の下界は 2 回とも上がる (最後のギャップ 1.79% -> 0.85%)。

## 5. この先

- `auto` を既定の候補にするなら、MCF の網があり固定費用ネットワーク型でない問題をもっと集めて (MIPLIB のネットワーク設計・
  品種の多い問題、例えば dfn-gwin・nobel-eu・germany50 系、今回取れなかったもの) 回数を増やして確かめる。網のない問題は
  検出 (数 ms) 以外は何も変わらない。
- SCIP の flowcutset (容量の行を外す) と、容量の係数から delta を選ぶことは移植していない。fiber・ta2-UUE のように効く問題で試す価値がある。
- 食い違いで落ちる dano3 系・cvs16 系・neos-911970 は、前処理の後の形で検出しているため。前処理の前の行で検出すれば拾える可能性がある。
