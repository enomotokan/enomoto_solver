## 結論 (先に)

- satellites2-60-fs の HiGHS の根の固定 (整数列の 40.3%) は、**伝播 (行・含意・目的関数の行) ではなく、LP の双対の選び方の差**から来る。
  - 事実: ENOMOTO の根の終わりの大域的な範囲から、行・含意 (衝突グラフ 124 万辺)・打ち切り値つきの目的関数の行で伝播した閉包を取っても、
    固定は 1 本も増えない (`d`、917 → 917)。
  - 事実: カットなしの LP 緩和の被約費用で数えると、単体法の頂点の双対では 88〜198 本 (0.3〜0.6%)、内点法 (クロスオーバーなし) の双対では
    10924〜10995 本 (32%) が固定できる (`rcfix_lag.py`)。内点法の双対の被約費用は 81〜1.6e5 で、その列は x = 0。単体法の頂点では同じ列の
    被約費用が 0 (双対退化)。LP の実行可能領域全体で 0 になる 0-1 列とみられる (推測)。
  - HiGHS は根で費用 0 の LP の解析的中心を求め、そこで境界にある整数列を固定する (`finishAnalyticCenterComputation`。以前の記録
    analysis/highs_only_20261105/G4.md で 11955 列)。同じ考えの以前の試作 `HO4_ACFIX` は、確かめなしでは誤答 (qnet1・nu25-pr12)、
    確かめ入りでは satellites2 で確かめの LP が間に合わず固定 0 だった。
- 試作 `u`: 既定の根のヒューリスティクス interior rounding (`Solver::interior_rounding`) が**もともと解いている**費用つきの内点法の点の双対 y から、
  ラグランジュ下界 L(y) と被約費用 c − Aᵀy を作り、被約費用による固定の表に足す。L(y) はどの y でも LP の下界なので、確かめの LP は要らない。
  余分な手間は O(非零) の 1 回だけ。
  - satellites2 (600 秒・種 1): 新しい固定 176 → **13165 本 (38%)**、再スタートで自由な列 34539 → 12841 (HiGHS 12408)、木に入るのが
    163 → 82 秒。ただし解けない (下界 −29 のまま、再スタートの後のカットのループが −29 から動かない。HiGHS は再スタートの後のカットで −25)。

## 1. HiGHS の根の固定の仕組み (HiGHS 1.15.1 のソースで確かめた事実)

- 大域的な範囲を変えるたびに (`HighsDomain::changeBound`)、0-1 列が固定されるとクリーク表の含意と変数の含意を当て (`cliquetable.addImplications`・
  `implications.applyImplications`)、`propagate` で行・カットのプール・衝突のプール・目的関数の行 (クリーク分割つきの `ObjectivePropagation`) を
  伝播する。
- 被約費用による固定: 根のカットの各ラウンドの LP の被約費用を「打ち切り値ごとの潜んだ境界」(`HighsRedcostFixing::addRootRedcost`、lurking bounds)
  として持ち、暫定解が良くなるたびに (`propagateRootRedcost`) まとめて当てて伝播する。
- 暫定解が良くなると、目的関数の行からクリークを取り出してクリーク表に足す (`extractObjCliques`)。
- 再スタートの判定 `percentageInactiveIntegers` は、固定された整数列とクリーク表の代入を数える。
- 根の解析的中心 (`finishAnalyticCenterComputation`) で境界にある整数列を固定する (satellites2 の主な出どころ、G4.md)。

## 2. ENOMOTO の同じ段 (事実)

- 根の被約費用による固定 (`Solver::root_redcost_fixing`) は列 1 本ずつ大域的な境界を締めるだけで、大域的な範囲では伝播しない
  (伝播はノードごとにやり直す)。再スタートの判定 (`maybe_restart`) は締めた後の固定の数を数える。
- 試作 `HO2_GOBJ` (目的関数の行の大域的な伝播)・`TREE4_RCUNION` (根のカットの各ラウンドの被約費用)・`IPMRC` (根の LP の同時実行の内点法の双対) が
  すでにある。IPMRC は根の LP の同時実行で内点法が走ったときだけ効き、根の LP をプロービングの基底から温め直す satellites2 では一度も効いていない
  (ipmrc_20261111 の `res_s0.jsonl`、`winner: warm`)。
