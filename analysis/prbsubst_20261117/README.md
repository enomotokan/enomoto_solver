# プロービングでの代入 (HiGHS の probing substitutions) の調べ (2026-11-17)

## 1. HiGHS の規則 (1.15.1 の源を読んだ)

- `HighsImplications::runProbing(col)`: 0-1 列 x を 1 と 0 に固定して伝播し (`computeImplications`、大域の定義域・クリークの表を使う)、
  両側の含意 (列ごとの境界の変化) を列の番号の順に突き合わせる。列 y が x = 0 で a に、x = 1 で b に固定され (a ≠ b、差が許容より大きい)、
  y がまだ代入も固定もされていなければ、代入 `y = a + (b − a) x` を記録する (`substitutions`)。そうでなければ両側の弱い方で y の境界を締める。
- y の種類は問わない (0-1・一般の整数・連続)。代入は前処理 (`HPresolve`) が `substitute(substcol, staycol, offset, scale)` で当てる。
- これとは別に、クリークの表が 0-1 列どうしの同値 (`cliquetable.getSubstitution`) を持ち、プロービングの前に確かめる。

当方: 0-1 列どうしの同値 (x_k = x_j か 1 − x_j) だけを集め、等式の行として足して前処理をかけ直す (`probe` の `equiv`)。
0-1 列以外の y の代入はない。

## 2. sat_rens での数え上げ (診断 `ENOMOTO_MIP_DEBUG_PROBE_SUBST`、振る舞いは変えない、`sat_rens_diag.txt`)

プロービングの後の定義域で、各 0-1 列の両側を伝播し、両側で違う値に固定される列を種類別に数えた (4 スレッド、既定と試作 `ENOMOTO_AGG_DUALFREE_INEQ`)。

| 形 | 0-1 | 一般の整数 | 連続 | 当方の同値な組 |
|---|---|---|---|---|
| 既定 (1 回目のプロービングの後) | 119 | 0 | 0 | 154 |
| 既定 (かけ直しの後のプロービング) | 0 | 0 | 0 | 0 |
| 試作 (1 回目) | 119 | 0 | 0 | 154 |

- sat_rens では 0-1 列以外の代入の候補が 0 本。0-1 列どうしの候補は既存の同値の検出が拾っている (154 組 ≥ 119)。
  → **HiGHS の probing の代入を移しても sat_rens は変わらない見込み**。差は代入ではなく固定の数にある
  (HiGHS の最初のプロービングは 1435 列を消す、当方の 1 回目は固定 299)。
- HiGHS の伝播はクリークの表を使う (`computeImplications` は大域の定義域の伝播でクリークも当てる)。当方の試作 `ENOMOTO_MIP_PRB_TABLE=ab` では固定 499。

## 3. HiGHS のプロービングの内訳 (ログ出力のみのパッチ `highs_prblog.patch`、利用者の許可を得て sat_rens で 2 回、`prblog_sat_rens.txt`)

- 10 回のプロービングで、含意による代入 0 本 (0-1・一般の整数・連続のどれも 0)、クリークの表による代入 計約 340 本、固定 計約 4800 本 (すべて 0-1 列)。
- 1 本ごとに見ると、0-1 列を 1 にすると矛盾して 0 に固定し、その伝播で 0-1 列が 41 本 (多いときは 61 本) 固定される形が繰り返す。
  最初の 1 本 (列 10521) は自分は固定されず、両側で同じ値になる 0-1 列 420 本を固定する。
- → 差は代入ではなく固定。

## 4. 差はプロービングではなく、その前の集約 (`rulecut.py` → `rulecut.txt`)

- HiGHS でプロービングだけ止めて前処理した問題 (5629 行・11013 列、0-1 列 10940) を当方で解くと、当方のプロービングがよく効く:
  前処理の後 1684 行・1907 列、根の LP 1.24、同値な組 13295、40 秒以内に最適 5 (元の sat_rens では根 −29・同値 154・時間切れ)。
- HiGHS の規則を 1 つずつ (プロービングと一緒に) 止めて書き出し、当方で解くと、効くのは**集約 (規則 12) だけ**
  (集約を止めたときだけ 8370 行・12041 列 → 当方で根 −29・同値 121・時間切れ。他の 16 規則は止めても最適 5)。
- 当方のプロービングに渡る問題 (`ENOMOTO_MIP_DEBUG_DUMP_PROBE`、試作 `ENOMOTO_AGG_DUALFREE_INEQ` あり) を HiGHS の前処理 (プロービングなし) に
  通すと当方で最適 (根 3.24、同値 12124)、集約も止めると時間切れ (根 −27)。この問題での HiGHS の集約の記録 (`highs_agglog.patch`): 763 回、
  0-1 列 × 等式 672、連続列 × 等式 91 (時刻の列、行は大きい M の行を等式にしたもの、行の長さ 4・列の長さ 3)。

## 5. 当方の集約が落とす理由 (診断 `ENOMOTO_DEBUG_AGG_REASONS`、振る舞いは変えない) と試作 `ENOMOTO_AGG_PIVOT_COL`

- 同じ問題で当方の集約 v2 は、連続列 90 本を「ピボット行なし」(ピボットの比の判定) で落としていた。当方は係数と**行の**最大係数の比
  (1e-2) だけを見る。時刻の列の係数 1 に対して大きい M の行の係数は 2e5 で、比が足りない。
- HiGHS 1.15.1 の `aggregator` は、行と列の短い方の最大係数で比を見て、だめならもう一方 (列の最大係数) で見る。時刻の列は列の係数が ±1 なので通る。
- 試作 `ENOMOTO_AGG_PIVOT_COL` (既定では使わない): 行の比で落ちても、列 j の係数の最大との比で通れば認める (規則を読んで自前で書いた)。

| sat_rens (4 スレッド) | 前処理の後 | 根の LP | 同値な組 | 結果 |
|---|---|---|---|---|
| 既定 | 7895 行・10970 列 | −29 | 154 | 時間切れ (120 秒、解 6) |
| `PIVOT_COL` だけ | 7895 行・10970 列 | −29 | 154 | 時間切れ (時刻の列が等式に出ないので効かない) |
| `PIVOT_COL` + `AGG_DUALFREE_INEQ` | 1793 行・2045 列 | 1.24 | 12606 | **最適 5、40 秒** |
| HiGHS 1.15.1 (参考) | 1444 行・1686 列 | 5 | | 最適 5、6.6 秒 |

- 2 つの試作の組み合わせで、sat_rens の差 (調べ C の P3) の本体が埋まる: 時刻の列を大きい M の行で代入して消すと、0-1 列だけの等式の行が
  残り、プロービングが同値な組 (1 万 2 千) と固定を見つける。
