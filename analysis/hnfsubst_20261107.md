# HNFPRE の合同式で列を置き換える前処理 (試作 `ENOMOTO_MIP_HNFSUBST`) (2026-11-07)

bench に使う環境変数: 既定 (`def`) はなし。試作は `ENOMOTO_MIP_HNFSUBST=1` (`sub`、HNFPRE の `bounds` (実行不能・固定・上下限の丸め) をしてから
合同式の出た一般整数列を x_j = r_j + g_j y_j に置き換え、置き換えた列を含む整数行を最大公約数で割る)。`=raw` は行を割らない (60 秒のふるいの 1 回目)。
比べに HNFPRE の試作 `ENOMOTO_MIP_HNFPRE=1` (`hnf`、分枝・伝播の丸め)。ほかに `ENOMOTO_T_MIP_HNFSUBST_MAXMOD` (置き換える法の上限、既定 1000)、
`ENOMOTO_MIP_HNFSUBST_QUIET=1` (1 行のログを出さない)。どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_MIP_LOG=1`・`ENOMOTO_T_MIP_SEED=回`・
`ENOMOTO_MIP_HNFPRE_QUIET=1`・`ENOMOTO_MIP_DEBUG_SEPPROF=1` (根のカットの分離器ごとの数、診断で解き方は変えない)。試作は既定では使わない。

## 結論

## 1. 作ったもの (事実)

`src/mip/hnfsubst.rs` と `src/mip/mod.rs` の `hnf_subst`。

- **場所**: `hnf_presolve` (HNFPRE、前処理の後の整数列だけの等式の Hermite 標準形) の直後、クリーク行の拡張・前処理の LP による固定 (クリーク行の拡張の後)・
  対称性の検出の前。選んだ理由:
  - 合同式は前処理の後の問題の格子から出るので、前処理の後でないと分からない。HNFPRE は上下限が詰まれば前処理をかけ直して解析し直す (最大 4 回) ので、
    その不動点の後に置く。
  - クリーク行の拡張は 0-1 列だけを見るので、置き換え (一般整数列だけ) の前でも後でも同じ。対称性の検出は置き換えた後の問題で探す (検出した対称性・
    オービトープ・対称性の行は置き換えた後の列の上の話になり、写し直しが要らない)。
  - 置き換えの後に前処理をかけ直すことはしていない (前処理は列の尺度 d を新しく掛けることがあり、置き換えと尺度の順の約束が増える)。割った行の丸めや
    上下限の伝播を前処理に使わせる余地は残っている (§6)。
- **置き換え**: HNFPRE の解析 (`hnf::analyze`) をもう一度かけ、合同式 x_j ≡ r_j (mod g_j) が出た列のうち、整数列 (尺度の掛かっていない列)・固定されていない・
  0-1 列でない・1 < g_j ≤ 1000 のものを x_j = r_j + g_j y_j (y_j は整数) にする。r_j は下限が有限なら下限以上で合同式に合う最小の値 (下限は HNFPRE が
  合同式に合うよう詰めてあるので r_j = 下限、y の下限は 0)、上限だけ有限なら上限以下の最大の値、両方無限なら [0, g) の代表。
  行の係数 a → a g、行の下限・上限から a r を引く、費用 c → c g・目的の定数に c r を足す、y の上下限は ceil((l - r)/g)・floor((u - r)/g)。
  プロービングの含意 (`implied_bounds`) の相手が置き換えた列なら値を y に直して丸める。値は 2^52 未満の整数だけ扱い (超えたら置き換えない)、
  置き換えで係数の絶対値が 1e9 を越える列は置き換えない。
- **行を割る**: 置き換えた列を含む行のうち、列がすべて整数列 (尺度なし) で係数が整数のものを係数の最大公約数で割り、下限を切り上げ・上限を切り下げる
  (等式で右辺が割り切れなければ割らない)。例: flugpl の `2 x1 + 3 x2 = 12` 型の行は置き換えると `6 y1 + 6 y2 = 6` で、割ると `y1 + y2 = 1`。
- **列の番号を保つ前処理の約束 (事実、コードを読んで確かめた)**: 前処理の結果は (問題, 後処理の手順 `PostsolveStep` の並び, 列の尺度 `scaling.d`) で、
  元の空間の解は「手順を逆順に適用してから x = d x'」で戻す。尺度の形 x = d x' は定数のずれ r を表せないので使えない。代わりに
  **自己参照の代入** `PostsolveStep::Sub { var: j, terms: [(j, -g)], rhs: r, coeff: 1 }` (値 = (r - (-g) x_j)/1 = r + g y_j。`Substitution::value` は
  書き込みの前に読む) を手順の最後に足す。逆順に戻すので置き換えが最初に戻り、それから前処理の手順が戻る。新しい手順の種類は要らなかった。
- **整合 (事実、コードを読んで確かめた)**:
  - 再スタートのカットの写し (`map_restart_cut_subst`): 手順を前から辿って代入するので、自己参照の代入では a x_j → a r + a g y_j になり正しい。
    尺度だけで写す経路 (`ENOMOTO_MIP_NO_RESTART_CUTS_SUBST`) は置き換えがあれば使わずカットを捨てる。
  - 再スタート: 再スタートの後の求解は解いている (y の) 問題を元の問題として `solve_problem` を呼ぶので、その中の前処理・HNF・置き換えは y の空間で閉じる
    (y の格子でさらに合同式が出れば重ねて置き換える)。暫定解・カットプールも y の空間のまま渡る。
  - 暫定解の写し (元の空間 → 前処理の後の空間): x/d の後に y = (x - r)/g (`hnfsubst::forward`)。前処理の中の早めの FJ の解 (`FEAS_FJ_SOL`) も写す。
  - pseudocost の写し (`ENOMOTO_MIP_RESTART_PC`): y の 1 刻みは x の g 刻みなので尺度に g を掛けて渡す。
  - 根の基底 (前処理の LP による固定の最後の LP): 列の状態はそのまま使える (有限の上下限は合同式に合わせてあるので、x が下限 ⇔ y が下限)。行は並びが
    同じで係数・右辺が変わるだけなので、行の指紋が置き換えの前の行と合っていたら置き換えの後の行の指紋に付け替える。最初の版は基底を捨てていて、
    snp-02-004-104 の根の LP が基底なしで 6 秒を越えた (既定は基底から 626 反復・0.66 秒) ので直した。DSE の重み・行の中身の写しは捨てる。
  - カットの共有 (`ENOMOTO_MIP_BISECT_SHARE_CUTS`、既定では使わない) は尺度 d で元の空間に戻すので、置き換えたときは尺度を渡さない (共有しない)。
  - サブ MIP は解いている (y の) 問題から作るので触らない。HNFPRE=1 と一緒に使うと、分枝の丸めの表は置き換えの後の問題で作り直される (`hnf_register_final`)。
  - 安全網: 後処理した解が元の問題で実行不能なら前処理なしで解き直す既存の仕組みがある。計測のログでこれが働いた回はない (§4)。
- 単体テスト `mip::hnfsubst::tests::subst_roundtrip` (置き換え・行の割り算・後処理・暫定解の写し)。

## 2. 置き換えが起きる問題 (事実)

HNFPRE の記録の「合同式が出る」問題のうち一般整数列のもの 17 問 (`run.py` の `HITS`)。置き換えた列の数 (60 秒のふるいの `sub` のログ、`screen60b.jsonl` の `subst`):

## 3. 根の下界・カット (事実)

60 秒・4 スレッド・種 1 (`screen60.jsonl`・`screen60b.jsonl`) と、600 秒の回の根 (`long600.jsonl`)。「根」は根のカットの終わりの LP 値 (`cut loop done`)、
括弧は最初のカットのループの最後のラウンドの値 (クリークのカットの予備の手 (clique fallback) を使った回だけ違う)。表は `root_table.txt` (`rootsumm.py`)。
閉じたギャップは (根 - 根の LP) / (最良の値 - 根の LP)、最良の値はこの計測で見つかった最良の暫定解 (flugpl 1201500、mzzv11 -21718)。

| 問題 | 根の LP | def の根 | hnf の根 | sub (行を割らない `raw`) の根 | sub の根 |
|---|---|---|---|---|---|
| flugpl | 1167875.2 | 1172948.3 (閉じた 15%、145 ノード) | 同じ (29 ノード) | 1201500 (100%、0 ノード) | 1201500 (100%、0 ノード) |
| mzzv11 (60 秒) | -22841.1 | -22183.5 (59%) | 同じ | -22108.8 (65%) | -22125.8 (64%) |
| mzzv11 (600 秒、種 1・2) | -22841.1 | -21984.5・-21984.5 (76%) | 同じ | - | **-22841.1・-22841.1 (0%)** (下の注) |
| rococoB10-011000 (60 秒) | 8350.2 | 10364.1 | 同じ | 13625.0 | 13650.8 (10063.9、予備の手を使った) |
| rococoB10-011000 (600 秒、種 1・2) | 8350.2 | 10364.1・10364.1 | 10364.1・10322.8 | - | 10219.8・10236.5 |
| rococoC10-001000 (60 秒・600 秒 × 2) | 7515.3 | 9007.2 | 同じ | 8953.7 | 8968.3・8963.5・8953.8 |
| traininstance2・6、brazil3、piperout-08・27、snp、rocI、radiationm18・40、kumeu、lectsched、8div | | | どれも同じ値 (根の LP のまま、または同じカットの値) | | |

- flugpl (と flugplinf) は置き換えで根のカットが最適値まで閉じる (6 ラウンド)。分離器ごとの 1 ラウンドあたりの候補/採用は def `tableau 14.3/2.0`
  (12 ラウンド)、sub `rows 4.3/0.5 path_highs 8.0/0.0 path 2.7/0.0 tableau 14.5/1.3`。推測: 置き換えの後は tableau 行の整数列の係数が 10 の刻みを
  知っているので、同じ数の Gomory カットでも強い (どのカットが閉じたかは調べていない)。
- rococoB10 の 60 秒の回の 13650 は、置き換えの効き目ではなく予備の手 (クリークのカット 100 本を足した LP の伸びが閾値を越えると、もう一度
  カットのループを回す) の結果。予備の手の前の値は 10063.9 で既定 (10364.1) より低い。600 秒の 2 回は予備の手が働かず 10220・10237 (既定より 1.4% 低い)。
  sub では行の CMIR (`rows`) が 1 ラウンドに 26 本の候補・14 本の採用を出す (def は 0 本) が、下界は上がらない。
- **mzzv11 の 600 秒の回は、置き換えた方だけ根のカットが 0 本** (2 回とも): 最初のラウンドのカットを入れた LP が反復の上限 1000 を越え、進み具合の
  判定 (窓の伸び 0.37) で止められて「カットを外して根のカットを終える」(`ENOMOTO_MIP_CUT_LP_CAP_STOP`)。既定は同じ判定を 1764 反復で通る。60 秒の回では
  sub も 1395 反復で通る (根のカットの時間の上限が 4.7 秒 対 58.6 秒で、選ぶカットが違う)。推測: 置き換えで係数が g 倍 (mzzv11 は最大 23) になり、
  尺度を調整しない根の LP が少し解きにくくなって、カットの LP が上限のすぐ外に落ちた。
- カットの数と種類 (1 ラウンドあたりの候補/採用): traininstance6 は sub で行の CMIR (`rows`) 1.4/0.8 → 9.5/1.5、tableau 4.6/1.2 → 43.7/1.5、`path_highs`
  0.8/0.2 → 10.0/0.0 と候補は増えるが、根の下界は 0 のまま (根の LP 0 の問題で、カットは下界を動かせない)。
