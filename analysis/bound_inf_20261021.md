# 時間切れの返り値の `best_bound` が -inf になる (2026-10-21)

- 機械: 4 CPU (`nproc` = 4、専用コンテナ)。ソルバーは同時に 1 つだけ動かした (修正版の計測の後に `cargo test`)。
- コミット: 土台は develop `99be060` (§1〜5)、§6 は develop `577c999` (§1〜5 の修正をマージした後) の上。修正はブランチ `inv/bound-inf-20261021`。
- 計測はすべて 4 スレッド・時間上限 60 秒 (`ENOMOTO_MIP_THREADS=4 ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_TREE_DIAG=1`、
  `m.solve(None, False, 60, None, None, 4, log=True)`)。スクリプトは `analysis/bound_inf_20261021/`:
  `run_cfg.sh <問題> <秒> <名前> [環境変数...]` (`run_one.py` を呼び、ログは `logs/<問題>_<名前>_<回>.log`)。
- physiciansched6-2 の 5 回目の調査 (`analysis/physiciansched_r5_20261021.md`) で、根の下界が分かっているのに返り値の
  `best_bound` が -inf になる回があった (既定の mzzv42z、`E2C` と `tab`+`LP_RESUME`+`ROWS_DSE_EXACT` の physiciansched6-2)。

## 1. 結論

- **再現**: develop の mzzv42z (既定、4 スレッド・60 秒) は 3 回とも `best_bound` = -inf (暫定解 -13168・-13908・-20360、
  ノード 4・3・0。根の下界 -20762・-20798・-20753 は分かっている)。
- **原因は 2 経路** (どちらも「分かっている下界を捨てて -inf で上書きする」):
  - **(A) 木の従のスレッドが写しの根の LP で時間切れになり、下界 -inf を返す** (`solver.rs` の根の LP の `LpStatus::TimeLimit`
    → `finish(TimeLimit, -inf)`)。主は `join_workers` で従の下界の最小を取る (`finish` の `best_bound.min(wlb)`) ので、
    自分の待ち行列の下界 (-20762) があっても -inf になる。mzzv42z の 1・2 回目: 従は 37 秒・46 秒に始まり、写しの根の LP
    (10843 行、主の根の LP は 7880 反復・3.4 秒だが従 3 本は基底なしで同時に解く) が 60 秒までに終わらず、3 本とも
    `worker ended: status TimeLimit objective None bound -inf nodes 0`。従は共有の待ち行列からノードを取る前なので
    探索し残した部分木はなく、本来は主の下界を下げない (+inf) べき。
  - **(B) 再スタート後の求解が暫定解なしで終わると、`mod.rs` の `solve_problem_inner` が「前処理の目的値の定数のずれが
    分からない」として下界を -inf にし、`maybe_restart` がそれをそのまま返す** (`r.best_bound.min(objective)`)。
    mzzv42z の 3 回目: 35.5 秒に再スタート 1 (暫定解 -20360 は再スタート後の前処理で実行不能になり捨てられる) → 再スタート後は
    暫定解なしのまま時間切れ (根の下界 -20753 は分かっている) → -inf。暫定解のない physiciansched6-2 (`E2C`) も同じ経路
    (再スタートの有無によらず、暫定解なしの時間切れはすべてこの経路で -inf になっていた)。
    ただし前処理 (`presolve_mip`) は代入で生じた目的値の定数を `offset` に入れている (後処理は縮約後の点についてアフィン) ので、
    ずれは暫定解があるときの計測でも ~0 で、前処理後の問題の下界はそのまま元の問題の下界として使える。
- **修正** (`src/mip/solver.rs`、`src/mip/mod.rs`):
  1. 従のスレッドが根の LP で時間切れ・失敗で終わるときの下界は +inf (`root_fail_bound`。主・ほかの求解は従来どおり -inf だが
     次の 2 で抑える)。
  2. 求解ごとに根の LP の値 (カットのループの後はその値) を `root_lb` に持ち、`finish` は時間切れなどの終わり方では下界を
     `max(root_lb)` で抑える (そして暫定解の値で上から抑える)。`maybe_restart` も再スタート後の結果の下界を再スタート前の
     `root_lb` で抑える。
  3. `solve_problem_inner` は暫定解がなくても前処理後の問題の下界をそのまま返す (-inf にしない)。暫定解があるときに測る
     ずれが 1e-9 (相対) を超えたら `ENOMOTO_MIP_LOG` で知らせる。
- **確認**: §3 (修正版の計測)。`cargo test --release --lib` は §4。

## 5. 残る課題 (§1〜4 の時点)

- mzzv42z (4 スレッド) では木の従のスレッド 3 本が写しの根の LP を 60 秒までに解き終えず、木に一度も加わらない
  (従は 37〜46 秒に始まり、10843 行の根の LP を基底なしで 3 本同時に解く。主の根の LP は 7880 反復・3.4 秒)。写しに根の基底を
  持たせて従に渡せば、従の準備が数秒で済むはず (`TreeSnapshot` は行・境界・擬似費用は持つが基底は持たない)。→ §6 で修正。
- 従の下界 +inf・`root_lb` の抑えは「分かっている下界を捨てない」ための修正で、下界そのものを良くはしない。

## 6. 写しに基底と DSE 重みを持たせ、従の根の LP を warm start する (develop 577c999 の上、コミット 635d42a)

- 修正: `make_snapshot` が主の今の LP の基底 (`lp.basis()`: 列と、元の行 + 写しのカットの行) と DSE 重み (`dse_snapshot`) を
  `TreeSnapshot` に入れる。写しから解く求解 (従・二分探索の求解) は根の LP の前に `set_basis` + `set_dse_vars` し、
  `WARM_DSE_ONCE` で重みを引き継いで解く (行の数が合わないときは従来どおり基底なし)。主が木の中にいるときの基底は最後に解いた
  ノードの最適基底だが、根の LP (大域的な境界) に対して双対実行可能なので双対単体法の warm start になる。
