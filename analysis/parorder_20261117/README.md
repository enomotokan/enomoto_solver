# 並列の木の探索の順の試作 (2026-11-17、treeclose 9.78 節)

既定の動きは変えず、環境変数 `ENOMOTO_MIP_PARORD` に含む文字で試作を入れる (src/mip/solver.rs の `parord`)。どれも 4 スレッド向け。

| 文字 | 中身 |
|---|---|
| `a` | 作業者 0 だけが大域の下界最小のノードを取る (HiGHS の分け方)。共有の待ち行列の最小が自分の最小より小さければ共有から取り、ほかのスレッドの下界がもっと小さければそのスレッドに「出せ」の合図を立てる。合図を見たスレッドは 32 ノードおきの同期で自分の最良のノードを共有に出す |
| `e` | (`a` と併せて) 作業者 0 以外は推定値だけで選ぶ (`pop_hgs(u64::MAX)`) |
| `c` | 番号の一番大きいスレッドを、暫定解がない間ヒューリスティクス役 (Local-MIP。止めていれば FJ) に回し、解が出たら木に戻す |
| `g` | (`c` と併せて) 相対の間隙が `ENOMOTO_T_MIP_PARORD_C_GAP` (既定 0.05) を超える間も役に回す (既存の役の ALNS を使う) |

ほかの調整: `ENOMOTO_T_MIP_PARORD_C_SECS` (役の 1 回の上限秒、既定 0 = なし)、`ENOMOTO_T_MIP_PARORD_C_FJ_EFFORT`・`_FJ_SECS`。
`ENOMOTO_MIP_LOG=1` か `ENOMOTO_PROF_TREE_PAR=1` で、終わりに `PARORD:` の行をスレッドごとに出す。

比べ先の `p3` は既存の試作 `ENOMOTO_MIP_POOL3_BEST=0.05` (pool_bound3_20261104.md。0.05 秒おきに全体の最小の下界のノードを必ず処理する)。

既定との時間の比 (幾何平均、+1 秒ずらし、12 対): a 1.024、ae 1.089、**cg 0.909**、**p3 0.931**。種の間のぶれ (kasai の def 168〜182、p3 125〜274) が大きく、12 対では差と言えない。

- `a`: 作業者 0 は共有から多く取る (mas76 で 677、neos5 で 1031 ノード)。ほかが出すノードは少ない (多くて 37)。kasai では 1.2〜1.4 倍遅いが、**csched008 を種 1・2 とも 380〜398 秒で解いた** (既定は 2 種とも 600 秒で時間切れ、最良 173 = 最適値)。下界を上げる働き手が 1 つ決まっていることが、最後に下界を閉じるところで効いたと見る。
- `ae`: `a` より悪い。ほかのスレッドが推定値だけで潜ると、下界の低いノードが残りやすい。
- `cg`: 役に入るのはほとんど `g` (間隙 5% 超え) の方で、時間は 0.3〜6 秒 (csched008 だけ 18〜69 秒)。`c` (暫定解なし) で役に入ったのは kasai の 2 回だけで、Local-MIP 1 回で最初の解を出してすぐ木に戻った。対象の問題の多くは 1 秒以内に最初の解が出るので、`c` だけではほぼ動かない (parprof の見立てどおり)。
- `p3`: 小さい問題で速めだが timtab1 種 1 で 2 倍、kasai 種 2 で 1.6 倍遅い。58 問で少し悪かった前の結果 (pool_bound3_20261104.md) と同じく、ぶれが大きい。

`RUSTFLAGS="-C link-arg=-L/usr/local/lib -C link-arg=-lpython3.13" LD_LIBRARY_PATH=/usr/local/lib` を付けた。
