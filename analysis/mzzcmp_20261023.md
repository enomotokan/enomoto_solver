# mzzv42z: HiGHS と一つずつ比べる (2026-10-23)

環境: 4 CPU のクラウドのコンテナ (`nproc` = 4)。ソルバーは同時に 1 本。土台は claude/enomoto-solver-heuristic-survey-xjlnol の 9acab4b。
4 スレッド・60 秒 (一部 150 秒)。HiGHS 1.15.1 (highspy、threads=4・mip_rel_gap=0、ログつき)。最適値 -20540。
台本は `analysis/mzzcmp_20261023/`:
- `run_cfg.sh <問題|MPS> <秒> <名前> [環境変数...]` (ENOMOTO 1 回)、`run_highs.sh <問題|MPS> <秒> <名前> [キー=値...]` (HiGHS 1 回)
- `highs_presolved.py <mps> <出力>` (HiGHS の前処理後の問題を MPS に書く。目的の定数項 0。容量のため MPS は置いていない。
  batch3・batch5 の `mps/mzzv42z_hpre.mps` はこれで作り直す)
- `summarize.py logs/*.log` (ENOMOTO のログの要約)、`batch1.sh`〜`batch9.sh` (計測の並び)
- ログ `logs/<問題>_<名前>_<n>.log` (HiGHS は名前の頭に `h`)、`logs/mzzv42z_hpresolve_rules*.log` (HiGHS の前処理の規則ごとの記録)

略号: GR = `ENOMOTO_MIP_GR_RESTART=1`、ff = `ENOMOTO_MIP_GR_RESTART=ff` (この調査の手当て)、mixoc = `ENOMOTO_MIP_FJ_LMIP_MIX=1 ENOMOTO_MIP_SYM_ORIG_CUT=1`、
cut = `ENOMOTO_MIP_CUTOFF=-20539.5` (HiGHS は `objective_bound=-20539.5`)、hpre = HiGHS の前処理後の問題。

## 結論

1. **この機械では HiGHS も 60 秒では証明しない** (事実): 60 秒 2 回とも -20540・下界 -20674、0 ノード。150 秒にすると **77.0 秒・1 ノードで証明**。
   前処理が 28〜29 秒 (基準の 50.1 秒の機械より約 1.5 倍遅い)。打ち切り値を与えても 60 秒では同じ (-20674)。
2. **差の出どころは 3 つ** (事実、切り分けは 3 章):
   - (a) **前処理** (主側と根の下界): HiGHS の前処理後の問題を ENOMOTO に解かせると、60 秒の値が既定の -20290 / -20300 から
     -20500 / -20430 (GR で -20540) に、根の下界が -20741〜-20769 から -20724〜-20738 に良くなる。根の RENS が崩れなくなる
     (hpre の 7 回すべてで固定率 0.80〜0.81、サブ MIP が 3〜8 秒で -15712〜-20540。-20540 は 2 回。元の問題の 60 秒の 12 回 (既定・ff・mixoc・mixoc+ff・GR・ff+EQUIV_FIX) では 9 回が固定率 0.29〜0.54 に崩れた)。HiGHS の前処理で根の LP を強くしているのは Enumeration presolve と probing
     (どちらか一方で根の LP -21623 → -21424。ENOMOTO は -21534)。
   - (b) **最適解を得た後の再スタートの連鎖** (証明): HiGHS は暫定解 -20540 の後に 2〜4 回再スタートし、そのたびの根のカットで
     下界を上げ (-20811 → -20683 → -20640 → -20637)、最後は根の強分枝 (17742〜11202 反復) と衝突 (275〜441) で 1 ノードで閉じる。
     ENOMOTO は 2 回目の再スタートの閾値 (全部の整数列 11717 本の 2.5% = 293 列) に届かず (新たに固定 10〜304 列)、1 回で止まる。
   - (c) **木の根の強分枝が狭い** (証明): hpre + 打ち切り値で ENOMOTO の木の根は強分枝 48 LP (6353 反復) で分枝に進み、
     80 ノード進めても下界 -20733 のまま。強分枝の候補の上限を外すと (調整値) 230 LP・64772 反復・35 秒かけても根を閉じない
     (下界 -20688)。HiGHS は同じ所から 17742 反復で閉じる。
3. **ENOMOTO の時間の使い方** (事実): 前処理 + probing 4.5 秒 (問題はほぼ減らない: 列 11717 → 10693、行は減らない)、根の LP 3.3 秒、
   根のカット 7 秒 (-21534 → -20834〜-20914)、根のヒューリスティクス 6〜20 秒 (RENS が崩れると 0 ノードのサブ MIP が 16 秒時間切れ)、
   再スタートは 21〜34 秒。再スタート後は根の LP の解き直しに 6〜9 秒 (11000〜16000 反復)。木はほぼ 0〜3 ノード。
4. **手当て: `ENOMOTO_MIP_GR_RESTART=ff`** (GR に加えて、2 回目以降の再スタートの割合の分母を根の始めに自由だった整数列の数に
   する = 既存の `ENOMOTO_MIP_RESTART_FRAC_FREE` を一般整数のある問題で働かせる。HiGHS の `percentageInactiveIntegers` に近い)。
   打ち切り値つきでは 2 回目の再スタートが起き、60 秒の下界が GR だけの -20709 から -20657 (`RESTART_FRAC_FREE` で)・-20713 (ff) に。
   打ち切り値なしでは: 既定 -20290 / -20300 → ff -20000 / -20210、mixoc -19320 / -20040 → mixoc+ff **-20480 / -20480**。
   2 回目の再スタートが起きたのは 4 回中 1 回 (1 回目の再スタートが 30 秒前後と遅いと効く時間が残らない)。**60 秒での証明はどの設定も 0 回**。
5. **既定にする候補か: まだ候補にしない**。ff の効果は「1 回目の再スタートが早いとき 2 回目が起きて下界が上がる」ことで、
   60 秒の値の差は回ごとの揺れ (根の RENS が崩れるか) より小さい。副作用 (1 回ずつ): neos-911970 は 30.1 → 27.1 秒 (mixoc 49.4 → 33.3 秒)、
   roll3000 は ff で再スタートが 1 回増え、値 12890 → 12902 (mixoc 12905 → 13168)、physiciansched6-2 は同じ。
   誤った最適値 (HiGHS と違う「最適」) は 0 回。

- 前処理の probing を止めた HiGHS は、前処理 2 秒・根のカット後 -20811 (ENOMOTO と同じくらい) からでも、15.4 秒の `L` で -20540 を得た後
  4 回の再スタートで 58.7 秒で証明した (既定の HiGHS 77 秒より速い)。**証明を決めているのは前処理の重さではなく、最適解を得た後の
  再スタートの連鎖と根の強分枝**。
- HiGHS の前処理の中身 (`mzzv42z_hpresolve_rules*.log`): 1 段目で支配列 41・係数の強化 37・Enumeration presolve で 280 列固定と 11 置換・
  probing で 591 行・1000 列削除と 13388 非零の持ち上げ。probing を止めても Enumeration と支配列で根の LP は -21424 になる。
- ENOMOTO の前処理は mzzv42z では何も減らさない (`presolve: rows 10460 -> 10460`)。probing は 355 列固定・同値な組 100 を見つけるが、
  境界を締めた回は同値な組を代入しない (`probe_equiv_fix`)。`ENOMOTO_MIP_PROBE_EQUIV_FIX=1` で代入すると根の LP -21534 → -21489。
- 試作 (この調査で書いて戻したもの、計測のログは残す):
  - HiGHS の Enumeration presolve と同じ考えの列の組の全数検査 (0-1 だけで 8 列以下の行の値の組を全部伝播で調べる): 全部の行を
    調べると 169 列を固定・同値な組 155 を見つけるが、**根の LP は変わらない** (-21533.8 のまま。`enumf_1`・`enumfeqfix_1`)。
    HiGHS の上限 (何も出ない行が 6 本続いたら止める) では 6 行で止まり 0 列 (`enum_1`)。
  - 被約費用による固定を根のカットのループの各 LP の被約費用でも行う (HiGHS の `addRootRedcost` と同じ): hpre + 打ち切り値で
    再スタートの時の固定 235 → 238 列とほぼ同じ (`rm_*`・`grrm_1`・`cutgrrm_1`)。HiGHS の 15% (約 1060 列) の出どころではない
    (HiGHS の割合はクリーク表の代入も数える: `percentageInactiveIntegers`)。

## 5. 残る差と次の手 (推測を含む)

- (推測) 60 秒での証明に一番効くのは「最適解を早く得ること」と「得た後の再スタートの連鎖」。前者は前処理の差 (HiGHS の前処理後の
  問題では ENOMOTO の RENS も崩れない) で、ENOMOTO の前処理が mzzv42z で何も減らさないこと (支配列・Enumeration・probing の
  代入) が根の LP の差 (-21534 対 -21424) と RENS の近傍の差になっている。HiGHS の前処理の規則を 1 つずつ ENOMOTO の前処理後に
  当てて根の LP がどれで上がるかを測るのが次の一手 (今回の全数検査は固定を出すが LP を上げなかった)。
- 木の根の強分枝: HiGHS が 1 ノードで閉じる所を ENOMOTO は閉じない。強分枝の LP の速さ (1.5 倍) と、子の打ち切りからの固定の後の
  解き直し (HiGHS は衝突 275〜441 本を使う) の差と推測。未検証。
