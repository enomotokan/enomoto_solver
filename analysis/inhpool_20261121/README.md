# 引き継ぎの鎖を共有の待ち行列でも共有する直し (`ENOMOTO_MIP_INHPOOL`) の 4 スレッドの時間への影響 (2026-11-21、親の依頼)

analysis/biglp_20261121 の 8 節で既定に入れた直し (n3div36 の 4 スレッドの RSS 5553 → 1347 MB) について、4 スレッドで 1 回ずつ見えた遅れ
(neos5 35 → 43 秒、noswot 19 → 27 秒、unitcal_7 215 → 242 秒) が揺れかどうかを、P の広い計測で確かめる。

- 設定 (cfg.py): def = 既定、old = `ENOMOTO_MIP_INHPOOL=0`。どれも 4 スレッド・60 秒。
- 分担表 (plan.py → shards_P.json): MIPLIB の 58 問 × 種 1〜3 × {old, def} = 348 回を 6 分担 (見積りは 1 分担 0.47 時間)。
- 回し方 (リポジトリの根から、分担 K = 0〜5): `cd analysis/inhpool_20261121 && python run.py P K` → res_P_sK.jsonl (途中から再開できる)。
  ビルドは直しの入った wheel (a781007d4 以降、`build.sh`)。
- 集計: `python ci.py 60 old def res_P_s*.jsonl` (ずらし幾何平均の比の 95% 区間、解けた数、全回で 1.25 倍超の遅れ)。

## 結果

### P (6 分担そろい、ci_P.txt)

- `python ci.py 60 old def res_P_s*.jsonl`: def/old のずらし幾何平均の比 1.023 (95% [0.998, 1.049])、解けた old 138 / def 139。
- 全種で 1.25 倍超の遅れ: noswot (素の比 1.83・6.63・1.41、ずらした比 1.35・3.52・1.22)。種 2 は 8.1→53.6 秒 (ノード 21794→113211)。
- 1 回だけの大きな遅れ: 10teams 種 3 (15.4→58.6 秒)、10teams 種 1 (6.4→10.5 秒)、pk1 種 3 (18.8→28.6 秒)。physiciansched6-2 は全種ではない。
- 区間の上端 +4.9% と解けた数は基準内。noswot が「全種 1.25 倍超」の基準にかかるので、種を増やした再計測で運か INHPOOL によるものかを確かめる。

### noswot・10teams の切り分け (rep.py → res_rep.jsonl、106111489 の build.sh の wheel、0.1.10)

P で noswot が全種 1.25 倍超・10teams が 1 回大きく遅れたので、同じ問題を種を増やして 2 回ずつ回した (4 スレッド・60 秒)。
同じ (種, 回) の old と def を続けて回し、2 回目は順を入れ替えた。1 スレッドも old_t1・def_t1 で種 1〜4 を 1 回ずつ。
比は def/old の 1 秒ずらしの幾何平均、区間は組ごとの対数比の平均 ± 2 標準誤差 (おおよその 95%)。

| 問題 | スレッド | 組 | def/old | おおよその 95% | def が遅い組 | 解けた old / def |
|---|---|---|---|---|---|---|
| noswot | 4 | 種 1〜10 × 2 回 = 20 | 0.836 | [0.62, 1.12] | 7 | 20 / 20 |
| 10teams | 4 | 種 1〜16 × 2 回 = 32 | 0.987 | [0.71, 1.37] | 15 | 32 / 32 |
| noswot | 1 | 種 1〜4 | 1.003 | [0.96, 1.05] | 2 | 4 / 4 |
| 10teams | 1 | 種 1〜4 | 1.000 | — | 1 | 1 / 1 (残り 3 は両方時間切れ) |

- **系統的な遅れではなく、4 スレッドの揺れ** と判断する。
  - 同じ設定・同じ種の 2 回の間でも、時間の差は大きい。
    - noswot の old: 種 3 は 4.7 / 33.1 秒、種 2 は 54.1 / 28.2 秒。
    - 10teams の old: 種 14 は 40.9 / 20.8 秒、種 3 は 48.7 / 12.5 秒。
  - 1 回目と 2 回目の比 (中央値): noswot は old 1.48・def 1.31 倍、10teams (種 1〜6) は old 1.45・def 2.12 倍。
  - P で見えた noswot 種 2 の 8.1 → 53.6 秒は、この揺れの幅に入る。今回の old 種 2 は 54.1 秒と 28.2 秒だった。
  - ノード数も時間と一緒に動く。たとえば noswot 種 2 は old 155763 / def 60911 ノードで、遅いときは探索の道筋が変わって木が大きくなっている。
- **10teams も種 1〜6 では def/old が 1.55 [0.95, 2.52] と遅く見えたが、偏りだった**。
  - 種 7〜16 では old のほうが遅い組が多かった。種 14 は old 40.9・20.8 秒、def はどちらも根で 2.9 秒。
  - 32 組を合わせると 0.99。
- **1 スレッドでは old と def のノード数が同じ**。
  - noswot は 4 種とも同数 (23695・50301・32518・18237)。10teams も 8490 と 8491 のように、ほぼ同数。時間の差は 5% 以内。
  - INHPOOL が変えるのは共有の待ち行列に出すノードの持ち方だけで、定義域は同じ。1 スレッドでは探索がほぼ変わらない。
  - 4 スレッドの差は、スレッドの間のノードのやり取りの順と時刻の揺れが探索の道筋を変えた結果で、鎖の持ち方そのものによる遅れの兆しはない。
- 系統的な遅れが見えないので、ログ (鎖の長さ・被約費用の固定の数) での原因の見立てはしていない。
