# cmir の集約の選び方 (AGGRSEL、2026-11-22、利用者の依頼)

**閉じた (2026-11-22、利用者の判断)。** `ENOMOTO_MIP_AGGRSEL` は既定オフのまま残す。

背景は treegap_20261121 の候補 4。SCIP の根の伸びのほぼ全部は aggregation/cmir から来ていて、当方の根との差 (unitcal_7・neos-911970・neos-1582420) は
cmir を切った SCIP と同じ程度だった。そこで、集約の選び方 (出発行・消す列・相手の行・集約の長さ) のどこが差を生むかを調べた。

## 0. 結論

**根の差の元は、集約の選び方 (経路の選び方) ではない。** ラウンドの数を揃えて比べると、元は問題によって次の 3 つに分かれる (§2)。

- **ラウンドの数 (neos-911970・p200x1188c・beasleyC3)**
  - 25 ラウンド目の比べ (当方 / SCIP): neos-911970 46.86 / 47.26、p200x1188c 13041 / 11260 (当方が上)、beasleyC3 719 / 732。ほぼ同じか当方が上。
  - SCIP は根を 100〜131 ラウンド回して 52.22・15078・754 まで上げる。当方は 22〜85 ラウンドで止まる。
  - 根を長く回すと全体の時間は遅くなる (rootstop_20261121)。
- **1 行の cmir の強さ (neos-1582420)**
  - SCIP は集約なし (maxaggrsroot=0) でも、25 ラウンドで 89.87 に届く。その中で cmir を切ると 88.44 に落ちる。当方は 89.06。
  - 集約ではなく、cmir の作り方 (δ の探し方・補数の取り方・変数上界の置き換え) の差。
- **集約の外の差 (unitcal_7)**
  - SCIP は aggregation を切っても 1.95884e7 で、当方の 1.95659e7 より上。差は集約の外にある。
  - 既存の記録 (slow2_20261117 §9): プロービングの含意の変数上界 (`ENOMOTO_MIP_VB_IMPL`) で差の約 8 割が埋まる。ただし M で +10% のため不採用。
- **集約が効いているのは mc11 の早いラウンドだけ**
  - 5 ラウンド目は当方 8710 / SCIP 10425、25 ラウンド目は 11070 / 11247。
  - 当方の path_highs は 1 ラウンド目に経路をまったく伸ばせない。連続列の LP 値が全部、境界か変数上界に張り付いているため (§1)。

**試作 `ENOMOTO_MIP_AGGRSEL` (既定オフ) は勧めない。**

- 中身: path_highs で、消す連続列の相手の行を、乱数でなく SCIP の行の点数 (|双対値| × 分数の活動量 / ノルム) で選ぶ。
- 根では下がった: mc11 11523 → 11021、p200x1188c 13325 → 13034、unitcal_7 1.95659e7 → 1.95571e7、beasleyC3 だけ 720.1 → 724.7。
- 通し (5 問・種 1〜3・4 スレッド・60 秒) は 1.174 倍 (95% [1.085, 1.270]) と悪い。
- P の分担表は作らない。
- 確かめ: fuzz 7 本 bad 0。cargo test は既定・試作とも 419 通る、失敗 0。

**当方で直すなら (推測を含む)**

- neos-1582420 の 1 行の cmir の差を、SCIP の `SCIPcutGenerationHeuristicCMIR` (cuts.c) と並べて調べる。最も具体的な候補。
- 当方の cmir は rows_cmir と generate_cuts で、δ の候補・補数・変数上界の置き換えの規則が SCIP と違う。

## 1. 当方の経路集約の中 (根だけ、1 スレッド、再スタートなし)

- `ENOMOTO_MIP_GAP4_PATHDIAG` に 2 つを足した。
  - 消す列がなくて止まった回のうち、集約行に境界から離れた連続列がそもそもない回 (`nocol_nocont`)。
  - 境界から離れた連続列の数 (`cont_off_bound`)。
- 1 ラウンド目 (最初) と最後のラウンドの値:

## 2. SCIP (10.0、pyscipopt 6.3.0) の根だけ

- 1 スレッド・limits/nodes=1・再スタートなし (presolving/maxrestarts=0) で回した。

## 3. SCIP の sepa_aggregation.c (v10.0.0) と当方の path_highs の違い (ソースから)

| 項目 | SCIP | 当方 (path_highs = HiGHS の移植) |
|---|---|---|
| 出発行 | 分数の活動量 / ノルムが 0 でない行を、その大きい順に。すき間は問わない。向きは活動量が近い側と、その反対 (trynegscaling) | LP で効いている行を、番号の順に全部。向きは両方 |
| 止め方 | 続けて 100 回 (根の早いラウンドは最大 2 倍) カットが出なければ止める。1 ラウンドのカットは 500 本まで | 全部の始点を試す |
| 消す列 | まず、その列だけが境界から離れている等式がある列 (good)。次に、境界からの距離 (近い変数上界・下界を含む) が最大の 99% 以内の列 | 境界からの距離が最大の列。連続列が 1 つだけの等式は先に代入する |
| 相手の行 | 点数 (双対値 × 分数の活動量 + 密度・すき間の小さな項) が最大の行。すき間のある行も使い、側を選ぶ | 効いている行の中から、乱数の位置から最初に使えるもの |
| 長さ | 根で 6 段、集約行の非零は 0.2 × 列 + 100 まで | 6 段 |
| 作るカット | 各段で flow cover・knapsack cover・cmir を作り、効き目の高いものを 1 本 | cmir・flow cover の候補から最良を 1 本 (`keep_best`) |
| カットが出たら | 伸ばさない。使った行の点数を、カットとの平行度に応じて下げる | 伸ばさない |
| 打ち切り値 | 暫定解があれば、目的の行 (打ち切り値) からも始める | なし |

試作では「相手の行」を SCIP の点数で選ぶ形にした (§0)。経路の選び方では、根の差が埋まらないことを確かめた。

## 4. 置き場所

- `scip_root.py`: SCIP の根だけを回す (設定は VARS、問題は環境変数 `AGGRSEL_PROBS` で絞れる)。

- `cfg.py`: 当方の設定 def・as。
- `run.py`・`ci.py`・`shards_L.json`: 通しの計測。結果は `res_L_s0.jsonl`、出力は `run_L.out`。
- `fuzz.sh`・`fuzz_as.out`: 誤答の確かめと cargo test。
- コード (src/mip/separation.rs):
  - `aggrsel()` と `path_aggregation_highs` の `rscore`: 試作。
  - PATHDIAG の `nocol_nocont`・`cont_off_bound`: 診断で足したもの。
