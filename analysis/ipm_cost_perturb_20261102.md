# 内点法の段階だけ費用を微小にずらす案 (内点法向けの退化対策) の当たりつけ (2026-11-02)

## 案

内点法 + クロスオーバー (`root_solver="ipm_crossover"`) で、内点法だけを費用を微小にずらした問題で解く。双対退化
(主の最適解が複数ある) を崩して主の最適解を 1 つの頂点にし、内点法の終点を頂点に近づけて、クロスオーバーの押し出し
(超基底の数) を減らすのがねらい。クロスオーバー (検出・押し出し・頂点の判定・仕上げ) は元の費用のまま。

試験用の `ENOMOTO_T_IPM_COST_PERTURB=δ` (既定 0 でしない。`src/simplex/crossover.rs` `solve_ipm_crossover_with`)。
ずらし幅は `δ (|c_j| + ‖c‖∞) (0.5 + 0.5 r_j)`、向きは下限だけの列 +・上限だけの列 −・箱型は乱数・自由列はずらさない。
ずらしたときは同時実行の二段解法の下界 (`ENOMOTO_T_XO_BOUND_GAP`) を使わない (元の費用の下界と比べられない)。

## 分かったこと

1. **仕組みは働くが、δ が内点法の精度より十分大きいときだけ。** δ = 1e-8 (内点法の停止基準と同じ桁) では超基底は減らない
   (6,630 → 7,598)。1e-6 で約半分、1e-4 で 1/3 に減り、cycle・greenbea・pilotnov などではほぼ頂点に着く (1e-4 で 1〜19 本)。
2. **頂点の受理 (`ENOMOTO_T_XO_ACCEPT_GAP=1e-8`) が崩れる。** 内点法の y は、ずらした費用に対する双対解なので、元の費用では
   δ の大きさの双対実行不能が残り、下界 `L(y)` が弱まる。dfl001 (δ = 1e-8) では頂点の目的値は最適値に一致する
   (1.123514504667e7) のに、ギャップは 4.7e-10 → 3.9e-6 になって受理されない。y_B (基底の双対) も双対実行不能で −∞。
   受理されない問題では仕上げの単体法が走り、その手間が押し出しの節約を大きく上回る (dfl001 +1.0〜6.4 秒、pilot87 +2.2 秒)。
   δ が大きいと、ずらした問題の頂点が元の問題の最適頂点でなくなる (dfl001 δ = 1e-6 で頂点の目的値 1.123514916e7)。
3. **そもそも節約できる時間が小さい。** δ = 0 で 91 問の合計 8.44 秒のうち内点法が 6.68 秒 (79%)。押し出し・基底の選択・判定を
   合わせたクロスオーバーは 1.8 秒程度で、超基底の最も多い dfl001 (843 本) でも 0.11 秒。超基底の Megiddo 式の押し出しは、
   すでに乱数の摂動つきの安い処理になっている。
4. 内点法の反復数はほぼ変わらない (合計 2,396 → 2,368〜2,532)。greenbea だけ 175 → 49 反復と大きく減った (δ = 1e-6)。
5. **別の問題 (要調査)**: pilotnov は δ = 1e-8 で、主実行可能で双対実行不能が 3 本 (最大 5.5e-3) しかない基底からの仕上げに
   77 秒かかる (2 回とも同じ。δ = 0 では受理されて 0.11 秒)。仕上げの単体法に、良い基底からでも長引く経路がある。

## 判定

不採用 (既定は 0 のまま。試験用の環境変数として残す)。受理判定を保ったまま効かせるには、元の費用に対する双対実行可能な y が
別に要り、内点法をもう一度解く手間がかかる。退化で押し出しが重かった Mittelmann の fome13・qap15 はこの環境では確かめて
いないが、両者とも今は頂点の受理で仕上げを省く経路で解けている (`docs/crossover.md` 第 37・60・61 回)。費用をずらすと、
その経路から外れる点は同じ。
