# 過去の試作の洗い直し: 一部の問題だけに入れると効くもの (2026-11-18)

依頼は `BRIEF.md`。新しい計測はせず、コードも変えていない。使ったのは手元の analysis/ の res*.jsonl (2275 個) と、問題の特徴として
`analysis/binheur_20261111/kinds.json` (87 問の列・行の数、0-1・一般整数・連続の数、行の型) と `analysis/gate2_20261117/tab/feat.jsonl`
(既定の根だけの解: 根の間隙・根の LP の反復・tableau の集約の非零) だけ。MIPLIB の公開の表はこのコンテナから取れなかった (名前が引けない)。

## 方法 (台本はこのディレクトリ)

- `load.py`: analysis/ の下の res*.jsonl を全部読み、(ディレクトリ, 問題, 設定, 種) → 時間 にまとめる。時間切れ・解けない回は上限 (tl) で数える。
  crash は除く。同じディレクトリの 1 スレッドの記録 (`_t1` の名前・`threads=1`) は別の組 (`#t1`) に分けた。上限が 60 秒でない回は
  問題の名前に `@秒` を付けて別の問題として数える (P の 60 秒と M の 600 秒を混ぜない。下の「訂正」)。中間の pickle は `/tmp/remine_20261118/`。
- `scan.py` → `scan.txt`: ディレクトリの基準 (def・base・k・c14・c18 など。robust_20261114 の pgq・spgq は base2) と、同じ問題・同じ種の対が
  2 種以上ある問題が 8 問以上の試作 291 件 (問題 40 問以上は 208 件) について:
  - 全体: 対の比 (t+1)/(t_def+1) の幾何平均 (shift 1 秒)。
  - 安定して速い/遅い: 全種で 0.8 倍未満 / 1.25 倍超。**揺れの大きい問題 (BRIEF の一覧) は 3 種以上そろった時だけ数える。**
  - ρ: 種の組ごとの、問題の比の順位の Spearman 相関の平均。
  - 見かけ: 種の平均で速い問題だけに入れた時 (選ぶ種と評価する種が同じ。甘い)。
  - **問題で選ぶ CV**: 種を 1 つ抜き、残りの種の平均で速い問題だけに入れ、抜いた種で評価 (cutcoef_20261118/summ.py と同じ方法)。区間は問題の bootstrap 95%。
- `stump.py` → `stump.txt`: 特徴 1 つの境目 (if) の CV。抜いた種以外で「特徴 × 境目 × 向き」を総当たりで選び (入れない・全部に入れるも候補)、
  抜いた種で評価する。種ごとに選ばれた境目 (`種ごと`) がそろうかで、境目の安定さを見る。特徴は log10 列数・log10 行数・行/列・0-1 の割合・
  一般整数の数・連続の割合・分割/詰め込み/被覆/ナップサック型の行の割合・根の間隙・log10 根の LP の反復・LP の非零・集約の非零/列。
- `xexp.py A B`: 同じ環境変数を別の日に測った 2 つの記録があるとき、A で選んだ境目を B で評価する (実験をまたいだ検証)。
- `detail.py 'dir:cfg|特徴|向き|境目'`: 境目で選ばれる問題と種ごとの比 (`detail_examples.txt`)。

## 全体の結論

- **選び過ぎの見かけの得は大きい。** 問題 40 問以上の 208 件で、見かけの得 (速い問題だけに入れる) の中央値は −2.8%、種を分けた CV の中央値は +0.4% (得なし)。
  問題で選んで CV が「無条件 (害なら入れない) より 2% 以上良い」のは 205 件中 15 件、特徴 1 つの if で 2% 以上は 3 件だけ。
- 得の大半は 1〜2 問 (多くは揺れの大きい問題: 10teams・neos-911970・noswot・mc11) が作っている。揺れの大きい問題を 3 種そろえる条件にすると、
  多くの候補の「安定して速い」は 0〜1 問になる。
- それでも残るのは、2 つの別の計測で同じ問題が速い TAB_HIGHS_RULES と、境目が種をまたいでそろう CLQ_LAZY・LUCLOCK=g の 3 系統。
  どれも得は 1〜3% の程度で、条件付きにしても大きな伸びは見込めない。

## 上位 5 件: 条件付きの形と短い計測の案

計測はどれも 4 スレッド・60 秒 (P の問題)、同じ問題・種の組は同じ分担で続けて解く (robust_20261114 の記録どおり、機械の差は試作より大きい)。

### 1. TAB_HIGHS_RULES を根の LP の重い問題だけ (TAB_HIGHS_SIG の計測へ渡す)

- 事実: 2 つの別の計測 (11-09 の hr・11-12 の tab) で、速い問題 (qnet1・neos-860300・eil33-2・neos17・neos-827175・hypothyroid-k1) と
  遅い問題 (nw04・sp150x300d・roll3000・mik-250-20-75-4・mas76・binkar10_1・neos-960392) がほぼ同じ。
  遅い側は根の LP の反復が少ない問題が多い (nw04 456・pk1 941・mas76 1462・sp150x300d 2571・neos-960392 2755)。速い側は 6000〜15000。
  例外は roll3000 (3 万反復で遅い、一般整数 492) と hypothyroid-k1 (1900 で速い)。
- 形: 根の最初の LP の反復 (または根の LP の時間) が閾値を超えるときだけ HiGHS の選び方。roll3000 を外すなら一般整数の数 (> 170 で入れない) を足す。
  境目の近く (2000〜6000 反復) に問題が多いので、連続の形にするならここ。
- 計測: TAB_HIGHS_SIG の計測の結果を、上の速い・遅い 13 問で読み直すのが先 (重複して実装しない)。そこで遅い側が残るなら、
  13 問 × 種 1〜4 × {def, TAB_HIGHS_RULES, 反復 > 5000 の if} を 1 分担 (約 1 時間)。
