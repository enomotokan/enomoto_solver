# 整数の平行列の併合 (`ENOMOTO_PRESOLVE_PARALLEL_INT`) の確かめ直し (2026-11-13)

2026-10-28 に不採用にした `ENOMOTO_PRESOLVE_PARALLEL_INT` (`src/presolve/parallelcols.rs`、整数列どうしで比 ±1・境界が整数なら併合) を、
束 cand1114 (`analysis/cand1114_20261113/cfg.py`) に単独で足した形 (以下 PINT) で測り直した。10-28 の計測は `SYM_TWINS` との組だけで、
理由の主だった nw04 の 3 倍の悪化は「根のカットの経路の当たり外れ」と分かっていた (`analysis/parint_20261028.md`)。
台本は `parint2_20261113/` (`cfg.py`・`run.py`・`plan.py`・`summ.py`・`fuzz.sh`・`diag.py`)。4 コアの機械 1 台、ソルバーは同時に 1 つ (4 スレッド・60 秒)。

- seed 1746 は **HiGHS 側の誤り**: HiGHS 1.15.1 は Optimal -7.7083 を返すが、我々の解 -8 (x = [2, 2, 0, 1, 1, 2, 0, 0, 0, 0, 2]) は全ての行と
  境界・整数性を満たし、目的値も -8。PARALLEL_INT の有無によらず同じ解を返す。
- seed 1586 の panic (`cannot convert float seconds to Duration: value is either too big or NaN`) は 10-28 の版だけで、今の版では出ない (後で直っている)。

  (`Substitution::apply`) は z の値を `[var_lb, var_ub]` に切り詰めて分けるだけで、z が許容誤差の内で整数からずれても分けた値が許容誤差の内に収まる
  (整数の比 ±1 の併合では、z の任意の整数値が整数の組に分けられる)。**許容差の範囲と判断し、直しは入れない。**

  fuzz_dupcols 2000・fuzz_slack (slackcol、`SLACK_COL` 付き) 2000 で不一致は fuzz_dupcols の seed 1746 (上の HiGHS 側) だけ。
  `cargo test --release --lib` は既定・PINT とも 415 件通過・0 失敗・19 無視。

## 3. nw04 が遅くなる仕組み (`diag.py`、ログは `nw04/`)

1 スレッド・`ENOMOTO_MIP_LOG=1` で c14 と PINT を種 1〜4 並べた (P の計測と並行に回したので時間は膨らんでいる)。遅れは 2 つの別のもの。

| 回 (1 スレッド) | 前処理 | カット選びの比べ (1 ラウンドの時間 default / pool → 選択) | 根のカットの終わり | 計 |
|---|---|---|---|---|
| c14 種 1 | 6.35 | 0.83 / 0.74 → pool | 16862 (6 本) | 18.9 |
| c14 種 2 | 6.29 | 0.70 / 0.69 → pool | 16862 | 18.2 |
| c14 種 3 | 6.07 | 0.70 / 0.68 → pool | 16862 | 17.6 |
| c14 種 4 | 6.37 | 0.80 / 0.71 → pool | 16862 | 18.7 |
| PINT 種 1 | 8.74 | 0.71 / 0.74 → **default** | 16852.37 (10 本) | 30.5 |
| PINT 種 2 | 8.47 | 0.69 / 0.68 → pool | 16862 | 20.6 |
| PINT 種 3 | 8.08 | 0.68 / 0.73 → **default** | 16852.37 | 28.7 |
| PINT 種 4 | 7.95 | 0.68 / 0.69 → **default** | 16852.37 | 28.5 |

(a) **根のカット選びの比べが同点で、1 ラウンドの時間の揺れで決まる (+8 秒)**。`ENOMOTO_MIP_CUTSEL_PROBE` (既定 `rate`) は根で既定の選び方と
  POOL の選び方を 1 ラウンドずつ試し、伸び / 時間の大きいほうを選ぶ。nw04 では 1 ラウンド目の伸びが両方同じ (c14 343.33、PINT 364.33) で、
  0.7 秒前後の時間の 0.01〜0.09 秒の差で決まる。c14 は 4 種とも pool を選び、1 ラウンド 1 本ずつで 16862 (最適値) に届き根で終わる。
  PINT は種 1・3・4 で default (1 ラウンド 2〜4 本) を選び、16852.37 で止まる。その後は根のヒューリスティクス (内点の丸め 2.5 秒の失敗、
  縮約費用の部分 MIP 3.8 秒で 16862) と LP の探り (GAP1 u) で最適を示すので、+8 秒。種 2 は pool を選んで差は前処理の分だけ。
  - 10-28 の記録 (併合で LP の頂点が変わりカットの経路が変わる) は今も当てはまる: `ENOMOTO_MIP_CUTSEL_PROBE=0` (常に既定の選び方) では
    c14 は 16862 に届き (14.8 秒)、PINT は 16852.37 で止まる (25.7 秒)。ただし今の cand1114 では POOL を選べば PINT も 16862 に届くので、
    分かれ目は「同点の比べを時間の揺れで決めていること」。
  - `ENOMOTO_MIP_LOSE6_2_TIE=1` (同点なら 2 ラウンドずつ比べ直す既存の試作) では PINT も pool を選び 21.7 秒 (c14 19.1 秒)。
(b) **前処理のプロービングが +2 秒 (毎回)**。プロービングは 16 本ごとに手間の上限を見る。c14 は 32 本で上限を越えるが、PINT は列が減って
  1 本あたりの手間が少し小さく (3650 万 → 3440 万)、32 本の時点でわずかに上限の下にあり 48 本試す (含意 273 万 → 386 万、6.1 秒 対 3.8 秒)。
  どちらも固定 0 で効きはない。16 本の刻みの当たり外れで、併合そのものの費用ではない。
- 対称性: c14 の対称性 (双子の入れ替え 27 本の生成元、lex-leader の行 0、orbital fixing) は nw04 では効いていない。c14 に `ENOMOTO_MIP_NO_SYMMETRY=1` を
  付けても遅くならない (種 1 で 16.7 秒)。併合で対称性の扱いの効きを失っているのではない。

### 試作 `ENOMOTO_MIP_CUTSEL_PROBE_TIE_FEWER` (既定では使わない、`src/mip/separation.rs`)

比べたラウンドでの伸びが同じ (差が許容誤差以内) なら、`rate` の代わりに、そのラウンドまでに足したカットが少ない側を選ぶ (本数が同じなら今まで通り)。
比べの費用は増えない (`LOSE6_2_TIE` と違い比べ直さない)。`probe_cut_mode` がラウンドごとの本数の累計を残すようにした。

- 同点の比べはほかの問題でも起きる (lose6_2_20261103.md の physiciansched6-2)。TIE_FEWER の 58 問での得失は未測。
