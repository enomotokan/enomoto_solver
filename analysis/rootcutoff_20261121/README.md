# ROOTCUTOFF: 根で打ち切り値 (暫定解の値) を使う (2026-11-21〜22、親の依頼、利用者の依頼「根で打ち切り値を使う」)

背景は analysis/treegap_20261121/README.md の 31〜32 行と 5 節の案 2・3。そこでは次のように見えていた。
- SCIP は打ち切り値で根の下界が上がる (swath1 340.86 → 342.51、misc07 1601.6 → 1663.1)。根で被約費用の固定と再スタートをする (neos-911970 は 4 回、neos-1582420 は列 10100 → 1197)。
- 当方は `ENOMOTO_MIP_CUTOFF` を渡しても根の下界が変わらない。

追加の依頼 (利用者の案) で、目的関数の行 `c x ≤ U` から集約したカットが固定を増やすかも見た (5 節)。

台本と記録:

- `diag.py`: ログから根ごと (再スタートの回ごと) の経過を拾う。
- `scip_root.py`: SCIP 10.0.2 の根だけ (`limits/nodes=1`) を回し、`scip_root.jsonl` に足す。

- ログは gzip 済み。`logs/v1_r_gated/` は 3 節の直し前 (r が RSTCRIT に止められていた版) のもの。

ビルドは 1732a09b9 の前後 (試作は 036f9fcba・03658c0c3、診断は c12c053d1 以降)。この機械は 4 コアで、ソルバーは 1 本ずつ回した。

## 結論 (先に)

- **RCLOOP (f・r) は閉じた (2026-11-22、利用者の判断)。** 既定では使わないまま、コードに残す。続きの 3 件は 7 節以降。

- **差は「固定の数」でも「再スタートの条件」でもなく、再スタートの後 (と 1 回目) の根のカットの強さにある問題が多い。**
  - swath1: 打ち切り値つきだと、当方も根で整数列の 65% (1409 / 2172) を被約費用で固定して再スタートする。前処理後の自由な 0-1 列は 681 で、SCIP の 576 と同じくらい。
    それでも再スタート後のカットのループは 5 ラウンドで止まり、340.58 から動かない。SCIP は 2 回目の run の根で 342.51 まで上げる。
    SCIP の根だけ (1 run) は打ち切り値つきでも 340.86 で、SCIP の上がりは全部 2 回目の run から来ている。
  - misc07: 当方の根の LP はカットの後で 1425、SCIP は 1601〜1677 (種しだい) で、根の LP がそもそも弱い。打ち切り値 2810 では被約費用の固定は 0 本。
    SCIP の根だけでも、打ち切り値なし 1676.9、ありで 1671.1 と、打ち切り値は効いていない。treegap の 1601.6 → 1663.1 は種の揺れと見る (種 1 の基準が 1676.9)。
  - neos-911970: SCIP の根だけで、打ち切り値なし 52.25、ありで 54.67 と、1 回の根の中で +2.4 上がる (被約費用の伝播を切ると消える)。
    当方は各ラウンドで固定しても (2 節の試作 f、ラウンド 13〜15 で 75 本)、カットのループの LP は 46.86 のまま変わらない。
  - neos-1582420: SCIP の根だけでは打ち切り値は効かない (89.73 対 89.80)。SCIP は 3 回再スタートして 90.16 / 1197 列。
    当方は打ち切り値つきだと再スタートが 1 回で止まる (2 回目の判定で新たな固定 49 本 < 閾値 93 本)。打ち切り値なしの方が多く (2 回)、89.27。
- **試作 `ENOMOTO_MIP_RCLOOP` (既定では使わない) は採らない。** 12 問 × 種 1・2 で def と比べた (打ち切り値なし、300 秒、ずらした幾何平均の def 比)。
  - `r` (2 回目以降の再スタートを、前の再スタートが根の下界を上げたかで決める): 1 スレッド 1.081、4 スレッド 1.012。
  - `fr` (r + 各ラウンドの被約費用の固定): 1 スレッド 1.130、4 スレッド 1.059。
  - swath1 は速くなる (1 スレッド 41・56 → 36・28 秒)。neos-1582420・h80x6320d・roll3000 は遅くなる。
  - 打ち切り値つき (最適値を渡す) の 1 回だけを見ると、`fr` で swath1 の根が 340.58 → 341.81、neos-911970 が 92 → 21 秒。打ち切り値を早く持てる場面では効く余地がある。
- **目的関数の行からのカット (利用者の案) は、今の分離の仕組みでは 1 本も出ない。**
  - 11 問、打ち切り値つき/なしの全部で、目的関数の行 1 本からのカット (c1) も、連続列を消しながら集約したカット (c2) も 0 本だった (5 節)。
  - LP 解では c x = z_LP < U で目的の行に余裕があるため、違反するカットが作られない。
  - 目的の行の伝播 (a) と被約費用 (b) を超える固定も 0。
  - 目的の行の余裕を 0 とみなした点で作ると、数本 (0〜6 本) は出るが、固定も LP の値も 1 つも変わらない (5.2 節)。
    効く余地が見えないので、RCLOOP と組み合わせた試作は作っていない。

## 1. 診断: 根ごとの固定と再スタート (1 スレッド、種 1)

`diag.py` の出力をまとめた。LP はカットのループの前 → 後の値、「固定」は早めの被約費用の記録 (カットのループの後) で新たに固定された整数列。
「判定」は再スタートの判定の (新たな固定 / 閾値)。

  分母を自由な整数列にする形は rstden_20261113 で測って不採用 (+1.3%)。
- neos-911970 は再スタートしても列を落とさない (RESTART_DROP_FIXED が出ない)。SCIP は 517 列まで落とす。

## 2. 試作 `ENOMOTO_MIP_RCLOOP` (既定では使わない)

- `f` (または `=1`): 外側の主の根のカットのループの各ラウンドで、最適に解けた LP の被約費用と打ち切り値で大域的に固定する
  (`Solver::rcloop_round`: `store_root_redcost` + `root_redcost_fixing`)。続けて定義域で伝播して大域的な境界にし (`commit_root`)、LP の列の境界に入れて解き直す。
  伝播が矛盾したら、根の下界を打ち切り値にして閉じる。固定はそのまま再スタートの判定に入る。
- `r`: 2 回目以降の再スタートの判定で、新たな固定が 1 本以上あり、この根の下界が前の再スタートを決めたときの根の下界より上がっていれば、
  固定の数の閾値 (`ENOMOTO_T_MIP_RESTART_FAC`) と縮みの条件 (`ENOMOTO_MIP_RSTCRIT`) を見ずに再スタートする。新しい閾値は置かない。
  回数の上限 (`ENOMOTO_T_MIP_MAX_RESTARTS` 4) は既存のまま。
  - 最初の版は RSTCRIT の見送りが残っていて、`r` が再スタートと判定しても起きなかった (`res_v1_r_gated.jsonl`・`logs/v1_r_gated/`)。03658c0c3 で直した。

## 4. どこを直すと SCIP に近づくか (事実からの推測、優先順)

1. **再スタート後の根のカットのループ (swath1)**: 固定も前処理後の大きさも SCIP と同じなのに、当方は 5 ラウンドで止まって 340.58。SCIP の 2 回目の run は 342.5。
   `fr` で 3 回目の根が 25 ラウンド回ると 341.62 まで上がったので、止め方 (stall の判定) が早すぎる可能性がある。
   再スタート後の根の止まり方 (`cutstop`) と、ラウンドごとの伸びを SCIP の 2 回目の run と並べるのが次の診断。
2. **neos-911970 の 1 回の根の中の +2.4**: SCIP は被約費用の伝播で上がるが、当方は同じことをしても (f) 上がらない。
   SCIP が redcost で締めるのは整数列だけでないこと (DomReds 1284 本、連続列も含む) と、締まった境界の上の cmir の差を見る要がある。
   当方の `store_root_redcost` は整数列だけを記録する (`ENOMOTO_MIP_RCSTRONG` の暗黙の整数を除く)。
3. 再スタートで列を落とさない (neos-911970) のは別件。前処理が固定した列を消していないので、RESTART_DROP_FIXED の条件から見る。
4. misc07 は根のカットの強さ (1425 対 1601〜1677) で、打ち切り値とは関係しない。treegap の対称性 (ORBPP) の方が効く。

## 5. 目的関数の行から集約したカット (利用者の案、診断 `ENOMOTO_MIP_DIAG_OBJAGG`)

src/mip/objagg.rs。外側の主の根の、カットのループの後 (早めの被約費用の記録の前) で、打ち切り値が有限なら 1 行を出す。解き方は変えない。
どれも「元の行 + LP のカットの行」の問題を大域的な境界から伝播し、固定された整数列の数を数える。

- `base`: 足すものなし。
- `a`: 目的関数の行 `c x ≤ U − 定数項` を足す (SCIP の pseudoobj に当たる)。
- `b`: 根の被約費用 (`root_redcost`) による締めを入れる。
- `ab`: `a` と `b` の両方。
- `c1`: `ab` に、目的関数の行 1 本だけから `generate_cuts` (cmir・被覆・flow cover) で作ったカットを足す。
- `c2`: `ab` に、目的関数の行から連続列を消しながら LP の行を足していった各段 (分離の経路の集約と同じ選び方、最大 6 段) から作ったカットを足す。

あわせて、根の LP に c1・c2 のカットを足した LP の値を出す。分離の空間は「列 + LP の行の余裕 + 目的の行の余裕」で、カットは構造変数の式に戻してから足す。

なお、今のカット生成は目的関数の行を材料にしていない (分離の経路の集約の始点・相手は LP の行だけ)。目的の行を使うのは FJ・Local-MIP・前処理の伝播 (`prechain` の `b`、`tpre`) と、目的の伝播 (`ENOMOTO_MIP_HO2_GOBJ`、既定では使わない) だけ。

| neos-911970 | 打ち切り値 根 2 | 765 | 75 | 78 | 146 | 148 | 148 | 148 | 0 / 0 |

(base の数は、伝播し直した問題で固定されている整数列の全部 (前から固定の列を含む)。打ち切り値なしの回は暫定解の値で同じ形になり、どれも c1・c2 = ab。ログは `logs/*_d_*`。)

- **c1・c2 のカットは全部の回で 0 本。** 根の LP 解では c x = z_LP < U で目的の行に余裕 (U − z_LP、swath1 で 38.5) があり、cmir・被覆の分離は LP 解で違反するカットしか返さないため。
  LP の値も変わらない (c1・c2 とも根の LP と同じ)。
- 固定を作るのは `b` (被約費用) で、`a` (目的の行の伝播) が足すのは neos-911970 の 3〜6 本、swath1 の 1 本だけ。

### 5.2 目的の行の余裕を 0 とみなした点で作る (`=t`、打ち切り値つき)

カットの妥当性は点によらないので、目的の行の余裕の値を 0 (c x = U) にした点で `generate_cuts` を呼んだ (11 問、種 1、上限 30 秒、`logs/*_dt_cut_*`)。

- カットが出たのは数本だけ: c1 は misc07・p200x1188c で 1 本。c2 は neos-911970 で 5〜6 本、neos5 で 5 本、mas76 で 1 本。ほかは 0 本。
- **固定が増えた回は 0。** どの回も c1 = c2 = ab (例: neos-911970 根 0 で ab 78 → c2 78、根 2 で 148 → 148。swath1 1491 → 1491。h80x6320d 5219 → 5219。p200x1188c 759 → 759)。
- 根の LP の値もどの回も変わらない (出たカットは根の LP 解で違反していない)。

### 5.3 判断

- 目的の行から 1 本・集約したカットは、伝播 (固定) も根の LP の値も強くしない。固定はほぼ全部が被約費用から来て、目的の行の伝播はそれに 0〜6 本を足すだけだった。
  分かれ目は、目的の行が LP 解で効いていないこと。被約費用による固定は、LP の双対 (= 目的の行と LP の行の最良の組み合わせ) をもう使っている。
  目的の行に LP の行を足して作るカットは、その組み合わせの丸めの分しか違わず、今回の 11 問では列の範囲を締めるところまで届かなかった。
- 効く余地が見えないので、本筋の試作 (RCLOOP) と組み合わせた試作は作っていない。
- 診断 `ENOMOTO_MIP_DIAG_OBJAGG` はコードに残す (解き方は変えない)。

## 7. 続き 1: 再スタート後の根のカットのループの止め方 (swath1)

止め理由は診断 `ENOMOTO_MIP_CUTSTOP_LOG=1` で出した (swath1、1 スレッド、種 1)。

| 回 | 根 0 | 根 1 (再スタート後) | 根 2 以降 |
|---|---|---|---|
| 既定 | stall、11 ラウンド、334.50 → 340.57 | **stall、5 ラウンド**、340.57 → 340.58 | |
| 打ち切り値つき | stall、11、同 | stall、5、同 | |
| 打ち切り値 + RCLOOP fr | stall、10 | stall、6 | 根 2: round_limit 25 ラウンド、340.58 → 341.62。根 3: stall 9、→ 341.81 |
| `ENOMOTO_T_MIP_CUT_STALL=30` (確かめ) | stall、21、→ 340.59 | round_limit 25、340.59 → **342.90** | (通しで 26.6 秒・775 ノード。既定は 43.7 秒・4557) |
| `ENOMOTO_T_MIP_CUT_STALL=100` | round_limit 25、→ 340.97 | round_limit 25、→ 342.93 | 根 2: → 343.05 |

- 止めているのは停滞の数え (`separation.rs` の `stall`)。1 ラウンドの伸びが相対 1e-4 以下で小数の列の数が減らないラウンドは +2 と数え、10 (`ENOMOTO_T_MIP_CUT_STALL`) で止める。
  つまり平らなラウンドが 5 回続くと止まる。再スタートの前と後で同じ規則で、再スタート後の根は最初から伸びが小さい (相対 2e-5) ので、5 ラウンドで止まる。
- 上限を 30 にすると、再スタート後の根は 2 ラウンド目から伸び続け、25 ラウンドで 342.90 になる (SCIP 342.51)。停滞はしばらく平らな後に伸びる形で、5 回で切ると伸びる前に止まる。
- 試作 `ENOMOTO_MIP_RSTLOOP=n` (既定では使わない、新しい閾値なし): 再スタートの後の根では、前の根のループが回したラウンド数に届くまで停滞で止めない。

## 8. 続き 2: SCIP の redcost・rootredcost が何をしているか (neos-911970)

SCIP 10.0.2 のソース (prop_redcost.c・prop_rootredcost.c、github の scipopt/scip) で確かめた。

- `propagating/redcost` (各ノードの LP の後、根ではカットのラウンドの間にも走る):
  - 連続列は既定で対象外 (`propagating/redcost/continuous` = FALSE)。
  - 0-1 列は、根 (深さ 0) では「その列の最良の根の被約費用」(`SCIPvarGetBestRootRedcost` と、そのときの根の LP の値) で、
    `根の LP の値 + |被約費用| > 打ち切り値` なら固定する。最良の根の被約費用は、根の LP を解くたびに列ごとに一番強いものを残す。
  - 一般整数列は、今の LP の被約費用で `新しい上限 = (打ち切り値 − LP の値) / 被約費用 + 下限` (と逆向き) と締める。
- `propagating/rootredcost`: 最良の根の被約費用で全部の列 (連続列も、`onlybinary` = FALSE) を締める。neos-911970 では DomReds 0。
- 当方との違い:
  - 当方の `store_root_redcost` は整数列 (一般整数も) を入れ、一般整数は境界を締める。ここは SCIP と同じ。
  - 連続列は試作 `ENOMOTO_MIP_RCSTRONG_KROOT` (最初の 1 回だけ) でしか締めない。ただし SCIP の redcost も既定では連続列を締めない。
    1 節の SCIP の切り分けでも、redcost の連続列を切って (`continuous=FALSE`、既定と同じ) 54.67 のまま。neos-911970 の +2.4 は連続列から来ていない。
  - 列ごとの最良の根の被約費用に当たるものは、試作 `ENOMOTO_MIP_TREE4_RCUNION` (カットの各ラウンドの LP の被約費用を残し、固定のたびに全部使う) がある。
- 試作の組 `k` (既定では使わない既存の 2 つ: `ENOMOTO_MIP_TREE4_RCUNION=1` + `ENOMOTO_MIP_RCSTRONG_KROOT=1`) で比べた (新しいコードはない):
  - 根だけ: p200x1188c 13531.8 → **14020.6**、exp-1-500-5-5 65780.5 → 65887.0、neos-1582420 89.274 → 89.236、ほかは同じ (neos-911970 46.86 のまま)。
  - 通し (4 スレッド): def 比 **1.072**。10teams 種 3 15.9 → 37.0 秒、neos-911970 種 3 8.6 → 15.6、neos5 種 2 33.5 → 50.3 で遅い。p200x1188c は 3.4・3.7・4.9 → 2.6・3.1・6.3 と入り混じる。
  - 採らない。
- neos-911970 の SCIP の 1 回の根の中の +2.4 の元は、まだ分かっていない。連続列でも、列ごとの最良の被約費用でもない (k でも 46.86 のまま)。
  SCIP の DomReds (redcost 1284、pseudoobj 635) は木を含む数で、根だけの数ではない。次に見るなら、SCIP を根だけ・打ち切り値つきで走らせた統計の
  Propagators の表 (根の DomReds) と、ラウンドごとの LP の値を当方と並べること。

## 9. 続き 3: 再スタートで列を落とさない件 (neos-911970)

- 既定の `ENOMOTO_MIP_RESTART_DROP_FIXED` (2026-11-20 に既定) は、渡すものに対称性の表か pseudocost・含意があると使わない (`mod.rs` の `restart_drop_fixed`)。
  落とすと列の番号が詰まり、それらの表を写せないため。
  - neos-911970 の 1 回目の再スタートは「not used (symmetry tables)」(オービトープ・生成元がある)。2 回目以降 (木の中の再スタート) は「pseudocosts carried」。
  - 対称性を切っても (`ENOMOTO_MIP_NO_SYMMETRY=1`)、木の中の再スタートは pseudocost を持ち越すので落ちない。種 2 で 1 回落ちただけ。
- 再スタート後の前処理は、固定された列を行から消す (非零 4851 → 4334) が、列の番号は保つ。自由な列の数 (813) は同じ。
  固定された列は LP・伝播では定数で、落とさないことが効くのは手間だけ。根の下界の差の元ではない。
- 対称性を切った 1 スレッドで、落とす (=1) と落とさない (=0) を比べた: 種 1 は 76.5 秒・12437 ノードと 73.8 秒・12437 ノードで、落ちる回がなく同じ道筋。
  種 2 は 75.7 秒 (1 回落ちる)・12451 ノードと 119.8 秒・22221 ノードだが、道筋ごと変わっているので落とした効果とは言えない。
- SCIP との差は落とすかどうかではなく、固定の数にある。SCIP は 4 run で 517 列 (0-1 489)、当方は打ち切り値つきで 3 回再スタートして自由な整数列 698。
- 試作は作っていない。対称性の表と pseudocost を詰めた番号へ写す形は手間が大きい。nw04 のように列の大部分が固定される大きな問題でなければ効きが見込めない
  (neos-911970 は 888 列)。
