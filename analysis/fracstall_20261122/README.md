# FRACSTALL: 根のカットのループの停滞の判定に LP 解の整数度を使う (2026-11-22、利用者の案)

今の判定 (src/mip/separation.rs): 下界の相対の伸び ≤ 1e-4 かつ分数の整数列の本数 nfrac が (0.9 − 0.1·stall)·前の回の本数 以上なら停滞と数え、
本数が減っていなければ +2、減っていれば +1、10 で止める (第 1 段階では第 2 段階へ)。伸びた回で 0 に戻す。

## 0. 結論 (途中)

- 試作 `ENOMOTO_MIP_CUT_STALL_FRAC=s` は、1 スレッドの 10 問 (種 1) で根が既定から変わったのが 5 問。その 5 問を種 1〜3 で比べると
  s/def の幾何平均 0.877 (15 組)。neos-1582420 は 3 種とも速く (0.89・0.96・0.95、ノード 410〜443 → 256)、neos-911970 も速い側
  (0.71・0.57・1.04)。swath1 (1.37・0.44・1.13)・mik-250-20-75-4 (0.51・1.06・1.37)・h80x6320d (1.12・0.65・1.03) は種で向きが変わる。
  5 問は「種 1 で根が変わった」で選んでいるので甘い側。1 スレッドの時間はこの機械で大きく揺れる (swath1 の def 29〜62 秒)。
- `c` (本数と F の両方) は根が変わったのが 2 問 (swath1・neos-1582420) で、どちらも遅い (1.33・1.25)。進めない。
- **P の分担表を作った** (`wide/`、def と sf = `s`、58 問 × 種 1〜3、4 スレッド・60 秒、6 分担・各 0.47 時間)。
- F の推移そのものが「続ければ得 / 止めれば得」を分けるかは、この 10 問では言えない (根が変わる問題が少なく、変わった問題の得・損も種で揺れる)。

## 1. 試作 `ENOMOTO_MIP_CUT_STALL_FRAC` (既定では使わない)

- F = Σ_{j ∈ 整数列} min(x_j − ⌊x_j⌋, ⌈x_j⌉ − x_j) (LP 解の整数列の、最も近い整数からの距離の総和)。比べる相手はこのループでのこれまでの最小 F (Fmin)。
- `s`: 本数の条件を F の条件 F ≥ (0.9 − 0.1·stall)·Fmin に置き換える。+2 は F が Fmin を更新しないとき、+1 は更新したとき。係数・10 はそのまま (新しい閾値なし)。
- `c`: 本数の条件と F の条件の両方が停滞のときだけ数える。+2 は本数も F も減らないとき。
- サブ MIP では使わない (既定のまま)。
- 診断: `ENOMOTO_MIP_CUTSTOP_LOG=1` で各ラウンド `CUTFRAC round k obj … nfrac … F … Fmin … stall …` を出す。
- 近い既存の試作 `ENOMOTO_MIP_FRACCUT` の `c` (analysis/fraccut_20261118) は「直前の回から F が 10% 以上減ったら停滞と数えない」(新しい閾値 0.1) で、
  根が変わる問題が少なく、得・損の向きもそろわなかった。
