## 1. 今の fallback の判定と却下の理由 (事実、ソースとログで確かめた)

- 既定 (`clique_cuts_mode` = `fallback`) は、根のカットのループをクリークなしで回し終えた LP で 1 回だけ、破れるクリークカット (最大 100 本)
  だけを入れて解き直し (`clique_fallback_trial`)、伸び g_c がループ全体の伸び g_d の 0.5 倍を超え、かつ 1e-4 × |目的値| を超えるときだけ、
  クリークカットを加えてループをもう一度回す。g_d = 0 のときは分数の列の数が 0.9 倍以下に減れば使う。ノードでは使わない。
  裏のカットのスレッド (別のスレッドの求解) は判定をしないので、使うと決めた問題でもクリークカットを使わない。
- 根だけの回 (ノード上限 1、種 1、`root2.jsonl` の def):

| 問題 | fallback の行 | 却下の理由 |
|---|---|---|
| rococoC10-001000 | 90 本、LP 8874.96 → 9095.84 (g_c 2.5e-2, g_d 1.5e-1)、分数の列 237 → 346 | g_c / g_d = 0.16 < 0.5 |
| neos-1456979 | 7 本、LP 154 → 154 (g_c 0)、分数の列 166 → 165 | 伸び 0 |
| hypothyroid-k1 | 100 本、g_c 4.6e-5 (g_d 7.0e-3) | 伸び 0 に近い |
| 30n20b8 | 51 本、g_c 7.3e-4 (g_d 1.2e-1)、分数の列 212 → 237 | g_c / g_d が小さい |
| net12 | 56 本、g_c 3.1e-3 (g_d 1.5e-1) | g_c / g_d が小さい |
| neos859080 | 破れるクリークカットなし | (根では使いようがない) |
| drayage-25-23 / -100-23 | 使う (伸び 2.8e-3 / 分数の列 94 → 84) | |

- neos-1456979 は、常用 (`ENOMOTO_MIP_CLIQUE_CUTS=1`) で毎ラウンド入れても始めの 3 ラウンドは 154 のままで、4 ラウンド目から
  154.3 → 155.4 → 157.2 → 160 と伸び、22 ラウンドで 164.8 (HILOSS の `logs2/neos-1456979.cq.log.gz`)。ループの終わりで 1 回だけ
  試す判定では、この「続けて入れると効く」伸びが見えない。
- hypothyroid-k1 は常用でも根の下界の推移がクリークなしとほぼ同じで (始めの 6 ラウンドは同じ値)、分離が遅くなる (1 ラウンド 1.1 → 2.5 秒)
  だけ。常用 (`1`) での 97 → 220 秒の害は、ノードでもクリークの分離をすることと根の遅れによるもの (推測。ノードを分けた計測はしていない)。
- 分数の列の数で却下する規則は今の fallback にはない (分数の列が減れば使う規則が g_d = 0 のときだけある)。HILOSS の「分数の列が増える」は
  ログに出る値で、却下の理由は g_c / g_d の割合。

## 2. 試作

`ENOMOTO_MIP_CLIQUE_CUTS=probe` (`Solver::clique_probe`、`src/mip/separation.rs`): 根 (外側の最初の求解、サブ MIP・裏のカットでない) の
カットのループの 0 ラウンド目の始め (カットの選び方の比べ `CUTSEL_PROBE` の後) で、クリークカット**なし**と**あり**のそれぞれで
k = `ENOMOTO_T_MIP_CLIQUE_PROBE_ROUNDS` (5) ラウンド回す (`probe_cut_mode` の形、毎ラウンド分離し直す。目的値が動かないラウンドでも止めない)。
伸び g0・g1 と時間 t0・t1 から、

- g1 − g0 > `..._GAIN` (1e-4) × max(1, |目的値|) かつ g1 / max(t1, tmin) ≥ `..._RATE` (1.0) × g0 / max(t0, tmin) (tmin = `..._TMIN` 0.5 秒) なら使う。
- どちらの伸びも 0 なら、終わりの分数の列の数が `..._FRAC` (0.9) 倍以下に減るときも使う (drayage-100-23 の今の規則と同じ考え)。
- 勝った側の終わりの状態 (足したカット・LP の状態) からループを続ける (比べのラウンドはラウンドの数・時間の上限の勘定に入る)。負けた側のカットは
  プールに入れる。比べの時間は全体の `..._TIME_FRAC` (0.05) 倍まで。再スタートの後は最初の判定を引き継ぐ。ノードでは使わない (fallback と同じ)。
- 時間の下限 tmin を置いたのは、rococoC10 で比べが 0.1 秒と短く (なし 0.10 秒で 15.6%、あり 0.11 秒で 17.0%)、0.01 秒の差で却下したため (v1)。
  v1 は k = 3 で、目的値が動かないラウンドで止めていたため neos-1456979 を 2 ラウンドで判定していた。

`probe_s` (v3): `probe` の余分を減らす形。(1) 始めの LP 解で破れるクリークカットがなければ比べない。(2) 「あり」の側を先に回し、選ばれた
クリークカットが 0 本ならその状態から使わずに続ける (「なし」の側は同じ道筋なので回さない)。
