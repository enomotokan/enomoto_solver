# 平行列の併合先の選び直しと、費用 0 のスラック列の消去 (2026-10-28)

swath1 で、費用 0 で 1 行 (行 0、6724 項の等式) にしか現れない [0, 1] の連続列 54 本が前処理の後に残り、対称性の検出がそれを
双子として扱っていた (`analysis/parint_20261028.md`)。なぜ前処理で消えないかを調べ、2 つの試作を入れた。どちらも既定では使わない。
4 コアの機械で計測した。

## 原因

1. **`parallelcols` の不具合**: 平行列の群の中で、先頭の列だけを併合先として試していた。swath1 では 54 本と同じ群に列 0 (行 0 の係数
   +1、比 -1116.57、費用 1、上限 535290) が入り、群の先頭になる。費用の比が合わないので、ほかの列はどれも列 0 に併合できず、互いに
   同じ費用 0 の 54 本どうしは比べられないまま残った (`ENOMOTO_DEBUG_PARALLELCOLS_COL=163` で確かめた)。
2. **スラック列を消す縮約がない**: `colsingleton` は等式 1 本につき 1 列だけ代入で消し、等式は範囲制約 (0 <= ... <= 1116.57) になる。
   範囲制約の中の費用 0 のスラック列は両向きにロックされるので `dualfix` では固定できず、上限が有限なので `forcingcol` の対象でもない
   (`forcingcol` は整数最適化では使わない)。
3. 同じ行の 0-1 列 28 本 (費用 0、1 行だけ) は、単独では消せない (残りの項の和が 0 か a のどちらかでなければならず区間にならない)。

## 試作 1: `ENOMOTO_PRESOLVE_PARALLEL_ALL_KEPT` (併合先の選び直し)

群の先頭の列に併合できない列があれば、残りの列から併合先を選び直して続ける (群ごとに `ENOMOTO_T_PRESOLVE_PARALLEL_KEPT_TRIES`
回、既定 64)。フラグなしでは以前と同じ動き。
- 64 問で併合が増えるのは swath1 (60 -> 113 列)、physiciansched6-2 (+22)、mik-250-20-75-4 (+4) だけ (`slackcol_20261028/pcscan.py`)。
- 4 スレッド・60 秒・交互に各 3 回 (`ab_allkept_4t.jsonl`): mik-250-20-75-4 9.8〜12.9 -> **6.3〜7.1 秒**、swath1 23.4 / 23.4 / 39.4 ->
  26.5〜29.0 秒 (揺れの範囲)、physiciansched6-2 はどちらも 3 回中 1〜2 回時間切れ (RENS の当たり外れ)。不一致 0。

## 試作 2: `ENOMOTO_PRESOLVE_SLACK_COL` (費用 0 のスラック列の消去、`presolve/slackcol.rs`)

費用 0・上下限が有限の連続列が、等式行に現れず、`G` の 1 行 (範囲制約なら符号を反転した 2 行) にだけ現れるなら、列を消して
行をその項の値域 `[mn, mx]` だけ緩める (`r <= U - mn`、`r >= L - mx`)。後処理 (`SlackCol::apply`) は元の行が許す区間と上下限の
共通部分に置く。`forcingcol` の直後に置き、LP の前処理でも働く。
- swath1 では 1 ラウンド目で 54 本を消し、0-1 列 28 本が 1x28 の完全オービトープになる。`ALL_KEPT` と組むと先に 54 本を 1 本に併合し、
  その 1 本を消す (どちらも前処理後の自由な列 6289)。
- 64 問で効くのは swath1 (54 列) と timtab1 (1 列) だけ (`slackcol_20261028/slscan.py`)。
- 正しさ: 費用 0 のスラック列を不等式・範囲制約・等式の行に 1 行あたり 1〜4 本入れた乱数問題 (`slackcol_20261028/fuzz_slack.py`、
  約 4 割で消去が働く) 2000 問 x 3 設定、LP・MIP・固定費・対称性の乱数問題で不一致 0。`cargo test --release --lib` 324 件通過。
- 4 スレッド・各 3 回 (`ab_slack_4t.jsonl`): swath1 既定 23.3〜35.7、SLACK 26.4〜29.3、SLACK + ALL_KEPT 23.3〜31.4 秒。timtab1 は
  どれも時間切れ (終わりのギャップ 0.025〜0.097 で差なし)。不一致 0。

## 双子の検出 (`ENOMOTO_MIP_SYM_TWINS`) の 3 回目の計測

整数列の双子は併合した列が組の列の上限まで締まるときだけ併合する修正の後、双子のある 8 問・4 スレッド・各 3 回
(`parint_20261028/ab_twins_4t_r3_intcap.jsonl`): SGM 22.26 -> 25.15 秒。swath1 は 25.5〜35.5 -> 25.8〜27.7 秒で悪化がなくなり、
差のほとんどは nw04 (12〜14 -> 31〜32 秒、根のカットの経路の当たり外れ) による。

## 40 問・負けている 21 問での確認と既定化 (`ab_allkept_58_4t.jsonl`)

MIPLIB 40 問と負けている 21 問 (重なりを除いて 58 問)、4 スレッド・60 秒・既定と交互に各 2 回:

| 組 | 回 | 既定 SGM (解けた数) | ALL_KEPT SGM (解けた数) |
|---|---|---|---|
| 40 問 | 1 回目 | 19.53 (26) | 20.84 (25) |
| 40 問 | 2 回目 | 21.66 (25) | 20.10 (26) |
| 21 問 | 1 回目 | 19.39 (18) | 21.51 (17) |
| 21 問 | 2 回目 | 20.92 (19) | 19.17 (19) |

- 回ごとに勝ち負けが入れ替わり、全体の差は揺れの範囲。MIPLIB の最適値との不一致 0。
- 前処理が変わる 3 問: mik-250-20-75-4 11.3 / 11.2 -> 6.3 / 6.3 秒、swath1 31.5 / 21.9 -> 25.8 / 28.5 秒、physiciansched6-2 21.3 / 60.3 ->
  60.0 / 35.0 秒 (どちらも 1 回時間切れ、RENS の当たり外れ)。ほかの 55 問は前処理が同じで、差は揺れ (neos-911970 +43.8 秒など)。
- 不具合の修正で、悪くなる問題がないので既定にした (`ENOMOTO_PRESOLVE_PARALLEL_NO_ALL_KEPT` で以前の形)。

## まとめ

- `parallelcols` の併合先の選び直しは不具合の修正で、効く問題は少ないが mik-250-20-75-4 ははっきり速い。40 問・21 問で確かめて既定にした。
- スラック列の消去は正しく働くが、ベンチマークで効く問題が swath1・timtab1 だけで、時間は変わらない。
- `PARALLEL_INT` は乱数問題 2000 問中 1 問で、目的値が最適値より 2.8e-6 低く出た (等式の行の残差 4.8e-7、LP の許容誤差の範囲)。
