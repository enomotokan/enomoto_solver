# rootrestart: HiGHS 型の根の再スタートと縮小 (2026-11-26〜27、親の依頼、gap240 の型 5)

- 対象: neos-873061・uccase12・satellites2-40・satellites2-60-fs。従として csched008・sct2。
- HiGHS はこれらで根の再スタートを繰り返し、問題を縮めている。
  - neos-873061: 6 回で 4558 列。
  - uccase12: 21〜25 回で 39970 → 11594 列。
- 当方はほとんど縮まない。この差を調べ、試作 `ENOMOTO_MIP_ROOTRESTART2` を作る。

## 1. HiGHS 1.15.1 の根の再スタート (ソースで確かめた。`HighsMipSolverData::evaluateRootNode`)

- **数えるもの**: `percentageInactiveIntegers` = (大域で固定された整数列 + クリークの代入) ÷ (前処理の後に自由だった整数列)。
  - 分母は再スタートのたびに数え直す。
  - 固定の原因 (伝播・被約費用・解析的中心・対称性) は区別しない。
- **判定は 3 か所**:

| 場所 | 閾値 | 動き |
|---|---|---|
| (a) 根の LP と丸め系のヒューリスティクスの後 (分離の前) | 10% | 再スタート |
| (b) 分離のラウンドの頭 | 10% | ループを抜けて (c) へ |
| (c) 根の最後 | 2.5%。初回だけは 1 本でも固定があれば | 再スタート |

  - 回数の上限はない。(c) で再スタートすると、分離のラウンドの上限をそれまでのラウンド数に縮める。
- **再スタートの中身**: その時点の LP をそのまま新しい問題にして (`presolvedModel = getLp()`)、前処理をかけ直す。
  - LP に入っているカットは、行として前処理に入る。前処理の後に行列から外してカットプールに戻し、再開した根で LP に入れ直す (`separateLpCutsAfterRestart`)。
    - LP に入っていなかったプールのカットは失われる。根でしたカットの仕事は、LP に入っていた分だけ引き継がれる。
  - 引き継ぐもの: 擬似費用・クリーク表・含意・暫定解・基底。
  - 捨てるもの: 衝突・被約費用の情報。
- **解析的中心による固定**: 根の初めに、費用 0 の LP 緩和を IPM で解く (別のタスク、200 反復、カットなし)。最適なら、範囲の端 (許容誤差 feastol·min(幅, 1)) にある列 (連続列も) をその端に固定する。
- **閾値が根の最後だけ小さい理由** (利用者の問いへの見立て、親の考え方):
  - 根の途中で再スタートしなければ、次の段はカットのラウンドの続きで、その間にも固定は増える。
  - 根の最後で再スタートしなければ、次の段は木全体になり、縮まない問題のままノードの数だけ手間がかかる。
  - 10% と 2.5% の差は、この「次の段の重さ」の違いを固定値で表したもの。

## 2. 当方の根の再スタート (既定)

- 判定は根の最後の `maybe_restart` だけ。
  - 条件は「新たな固定 ≥ fac × 全部の整数列」。fac は初回 1%、2 回目以降 2.5%。分母に、根の始めに固定済みの列も入る。
  - さらに RSTCRIT n (新たに固定した列の非零が 5% 未満なら見送る) がある。回数の上限は 4。
  - gap240 の記録の「閾値 16」は net12 の 0.01 × 1603 で、定数ではない。
- 早い再スタート (根のヒューリスティクスの途中) は、残りのヒューリスティクスを飛ばすだけ。判定は上と同じ。
- カットの引き継ぎ: 根の最後の LP で効いている (活動量が境界にある) カットだけを、問題の行として持ち込む。
  - 効いていないカットとプールのカットは捨てる。
  - 再スタートの後の根の LP は、効いているカットの分の下界を保つ。
- 木の中の再スタート (`TREEEFF=rpsh`、K・R ガード) は `maybe_restart` を `force_restart` で呼び、固定の閾値は見ない。
  - 固定の数え方と回数の上限 4 は根と同じ。
  - nra は K ガードの「効いているカット」の数え方を変えるだけ。
- 過去: hso (ACFIX=d + SB_NO_DEGEN_SKIP + SB_BUDGET_HIGHS) は P で外れた (4 スレッド 1.025、解けた数 141 → 137)。記録の上の害の元は強分枝の 2 部品の費用 (ノードは減るが時間が増える型) で、ACFIX=d の害の記録はない (protoscreen_20261124)。

## 3. 診断 (`ENOMOTO_MIP_RR_DIAG=<最適値>`、`diag.sh`、1 スレッド・種 1・600 秒、ログは logs/ でコミットしない)

- 「HiGHS の割合」: 新たな固定 ÷ 根の始めに自由だった整数列。

| csched008 | 既定 (ACFIX は 0 本) | 1 | 0 | 0% | 被約費用の列が 0 | 0 | 解なし、下界 171 |

- **neos-873061**: 最適値で打ち切っても、根の LP の被約費用で固定できるのは 1 本。
  - HiGHS が 88% を固定できたのは、カットで根の下界を 112.99 (ギャップ 0.74%) まで上げてからの被約費用。当方の根の下界は 104.74 (ギャップ 8%) で、固定が起きない。
  - 差の大元は、根の下界 (カット) と根の LP の速さ (当方 109〜119 秒、HiGHS 約 9 秒)。再スタートの条件では埋まらない (rootbound_20261126 の領分)。
- **uccase12**: 当方も根で 2 回再スタートする。
  - 3 回目は新たな固定が 3 本で、どの閾値でも止まる。最適値で打ち切っても 98 本。
  - HiGHS の 21 回は、ほぼ最適の暫定解 (20 秒で 11507.405、ギャップ 3e-6) の被約費用を、再スタートのたびに取り直して固定を重ねたもの。
- **satellites2**: 固定の元は、解析的中心 (当方は ACFIX=d の双対の形) で 38%。被約費用は最適値でも 1% 未満。
  - ACFIX=d で 1 回再スタートすると、暫定解が 79 → −14、21 → −17 に良くなる (最適 −19)。
  - HiGHS の 42.6% と同じ型。
- **sct2・csched008**: 根の再スタートは HiGHS とほぼ同じ (sct2 は根 1 + 木 2 回)。差は木の中にある (gap240 の候補 6)。
- まとめ:
  - 閾値の形 (1%・2.5%、分母) が理由で再スタートを逃している問題は、この 6 問にはない。
  - 縮まない原因は「固定が起きないこと」で、satellites は解析的中心による固定、neos-873061 は根の下界。

## 4. 試作 `ENOMOTO_MIP_ROOTRESTART2` (既定オフ) の判定の式

親の考え方 (1 節) で、固定値の閾値の代わりに次の比べにする。新しい閾値は置かない。

- 再スタートする ⇔ σ(ln(W·s / C)) ≥ 1/2 ⇔ W·s ≥ C
  - **s (縮む割合)**:
    - 根の最後では、新たに固定した列の非零 ÷ 根の始めに自由だった列の非零 (`restart_shrink`、RSTCRIT と同じ量)。
    - 根の途中では、(新たな固定 + 今の被約費用で固定できる本数) ÷ 根の始めに自由だった整数列。
  - **W (次の段の手間の見込み、秒)**:
    - 根の最後 (`e`): 期限までの残り。解けない木は残りの時間を全部使う。
    - 根の途中 (`m`): 残りのラウンドの見込み (ここまでの 1 ラウンドの平均の秒 × 残りのラウンドの数)。
  - **C (再スタートの手間、秒)**:
    - 2 回目以降は、前の再スタートで実際にかかった秒 (決めてから次の根の LP が解けるまで: 前処理のかけ直し + 根の LP)。
    - 初回は、ここまでの外側の経過秒 (前処理 + 根の LP + カット) で見積もる。
- 文字:
  - `e`: 根の最後。木の中の再スタート (force) は今のまま。
  - `m`: 根のカットのラウンドの頭。
  - `a`: 解析的中心の固定。`ENOMOTO_MIP_HO4_ACFIX=d` と同じで、根の内点法の丸めの初めに、費用 0 の内点法の双対で固定する。
- 干渉: 木の中の再スタートの判定 K・R と nra は、`force_restart` の道でこの判定を通らないので変わらない。回数の上限 4 は共有する。

## 5. 6 問の比べ (`cmp6.sh`、1 スレッド・種 1・600 秒、結果は cmp6.jsonl、ログは logs/ でコミットしない)

- 設定: def (既定) と eam (`ENOMOTO_MIP_ROOTRESTART2=eam`)。ビルドは 53b2ade2e。
- eam2: 初回の再スタートの手間 C の見積もりを直したビルド (f6aa85659 の前、その時点の取り込みを含む) で、見積もりの行が出た 3 問をもう一度。
- 再スタートの回数はログの行から数えた (早い再スタートと ROOTRESTART2 の行を両方数えるので、satellites2-60-fs の eam・eam2 の 2 は実際は 1 回)。

| 問題 | def: 再スタート / 暫定解 / 下界 | eam | eam2 |
|---|---|---|---|
| satellites2-60-fs | 0 / 21 / −29 | 1 / **−19** (最適) | 1 / **−17** |
| satellites2-40 | 0 / 79 / −29 | 0 (σ 0.497 で見送り) / 79 | 1 / 80 |
| uccase12 | 根 2 + 木 1 / 11507.405 / 11507.3726 | 根 3 + 木 1 / 11507.405 / 同じ | 根 2 / 11507.406 / 11507.3690 |
| sct2 | 根 1 + 木 1 / −230.989 / −231.047 | 根 2 + 木 1 / −230.981 / 同じ | — |
| csched008 | 0 / なし / 171 | 0 / なし / 171 | — |
| neos-873061 | 0 / 121.50 / 104.96 | 0 / 121.50 / 104.96 | — |

- **見積もりの直し**: eam の satellites2-40 は ACFIX で 12243 本 (s = 0.456) 固定したのに、初回の手間 C を外側の経過秒 189.5 秒 (うち根の RINS が約 174 秒) で見積もり、W·s = 187 < C で見送った。
  - 再スタートで実際にかかる秒 (前処理のかけ直し + 根の LP) は、satellites2-60-fs の実測で 21.8 秒。
  - そこで初回の C を「前処理の秒 (外側の経過秒 − ソルバーの経過秒) + 根の LP の秒」にした。eam2 では 20.4 秒の見積もり (実測は 13.4 秒) で再スタートする。
  - uccase12 の初回の見積もりも 24.1 → 7.3 秒 (実測 3.8 秒) と実測に近づいた。
- **satellites2**: 再スタートすれば 60-fs は 21 → −19・−17 と大きく良くなる (ACFIX=d の診断の −17 と同じ型)。
  - 40 は eam2 で再スタートしたが、80 のまま (ACFIX=d の診断 `acd` では −14)。ログを比べた (logs/satellites2-40_ceam2.log と _acd.log):
    - 縮んだ問題はほぼ同じ (行 12551 と 12426、自由な列 15137 と 14988)。再スタートの判定と固定 (12241 本と 12243 本) は同じ働きをしている。
    - どちらも再スタートの後は暫定解なしで木に入る (TRSTAT の ub inf。見立て: ACFIX の双対の固定が 80・79 の解を切るため。確かめていない)。そこからは実行可能解を探す木になる。
    - acd は木の丸めで 181 ノード目に 64、695 ノード目に −14 を出した。eam2 は 517 ノードで 1 つも出なかった。
    - 木の差: ノードの LP の反復 985 と 597 (1 本あたり)、ダイブ 67 本と 176 本、ダイブの底の深さ 63.7 と 50.9。eam2 の方がノードが重く、ダイブが少ない。
    - 差の元は再スタートの後の木の道筋 (根の最後に再スタートしたので残したカットが 12 本、acd は根のヒューリスティクスの途中の早い再スタートで 35 本。ビルドも違う) で、再スタートの判定ではない。種 1 本では良し悪しを言えず、P で見る。
- **2 回目以降の判定**: 実測の C が小さい問題 (uccase12 は 3〜4 秒、sct2 は 0.2 秒) では、縮む割合が 0.3% (sct2 の 4 本) でも再スタートする。σ は 0.80〜0.98。
  - 固定が 0 に近いと (satellites2 の 2 回目、s = 0.0000) σ ≈ 0 で止まる。
  - sct2 の暫定解の差 (−230.989 → −230.981) は 1 本の種の道筋の違いの範囲。
- **根の途中の判定 (`m`)**: 6 問とも `ROOTRESTART2 cut round` の行は出なかった。行は本数が 1 本以上のときだけ出るので、どのラウンドの頭でも、新たな固定 + 被約費用で固定できる本数が 0 だった (固定は根の LP とヒューリスティクスの後にまとまって起きる)。
- **K・nra との干渉**: sct2 と uccase12 の木の中の再スタート (TREE restart) は def と同じく起きる (force の道は判定を通らない)。上限 4 回の共有で、uccase12 の eam は根 3 + 木 1 = 4 回で止まる。
- neos-873061・csched008 は変わらない (固定が起きない。3 節)。
