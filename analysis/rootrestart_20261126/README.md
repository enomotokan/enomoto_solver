# rootrestart: HiGHS 型の根の再スタートと縮小 (2026-11-26〜27、親の依頼、gap240 の型 5)

- 対象: neos-873061・uccase12・satellites2-40・satellites2-60-fs。従として csched008・sct2。
- HiGHS はこれらで根の再スタートを繰り返し、問題を縮めている。
  - neos-873061: 6 回で 4558 列。
  - uccase12: 21〜25 回で 39970 → 11594 列。
- 当方はほとんど縮まない。この差を調べ、試作 `ENOMOTO_MIP_ROOTRESTART2` を作る。

## 1. HiGHS 1.15.1 の根の再スタート (ソースで確かめた。`HighsMipSolverData::evaluateRootNode`)

- **数えるもの**: `percentageInactiveIntegers` = (大域で固定された整数列 + クリークの代入) ÷ (前処理の後に自由だった整数列)。
  - 分母は再スタートのたびに数え直す。
  - 固定の原因 (伝播・被約費用・解析的中心・対称性) は区別しない。
- **判定は 3 か所**:

| 場所 | 閾値 | 動き |
|---|---|---|
| (a) 根の LP と丸め系のヒューリスティクスの後 (分離の前) | 10% | 再スタート |
| (b) 分離のラウンドの頭 | 10% | ループを抜けて (c) へ |
| (c) 根の最後 | 2.5%。初回だけは 1 本でも固定があれば | 再スタート |

  - 回数の上限はない。(c) で再スタートすると、分離のラウンドの上限をそれまでのラウンド数に縮める。
- **再スタートの中身**: その時点の LP をそのまま新しい問題にして (`presolvedModel = getLp()`)、前処理をかけ直す。
  - LP に入っているカットは、行として前処理に入る。前処理の後に行列から外してカットプールに戻し、再開した根で LP に入れ直す (`separateLpCutsAfterRestart`)。
    - LP に入っていなかったプールのカットは失われる。根でしたカットの仕事は、LP に入っていた分だけ引き継がれる。
  - 引き継ぐもの: 擬似費用・クリーク表・含意・暫定解・基底。
  - 捨てるもの: 衝突・被約費用の情報。
- **解析的中心による固定**: 根の初めに、費用 0 の LP 緩和を IPM で解く (別のタスク、200 反復、カットなし)。最適なら、範囲の端 (許容誤差 feastol·min(幅, 1)) にある列 (連続列も) をその端に固定する。
- **閾値が根の最後だけ小さい理由** (利用者の問いへの見立て、親の考え方):
  - 根の途中で再スタートしなければ、次の段はカットのラウンドの続きで、その間にも固定は増える。
  - 根の最後で再スタートしなければ、次の段は木全体になり、縮まない問題のままノードの数だけ手間がかかる。
  - 10% と 2.5% の差は、この「次の段の重さ」の違いを固定値で表したもの。

## 2. 当方の根の再スタート (既定)

- 判定は根の最後の `maybe_restart` だけ。
  - 条件は「新たな固定 ≥ fac × 全部の整数列」。fac は初回 1%、2 回目以降 2.5%。分母に、根の始めに固定済みの列も入る。
  - さらに RSTCRIT n (新たに固定した列の非零が 5% 未満なら見送る) がある。回数の上限は 4。
  - gap240 の記録の「閾値 16」は net12 の 0.01 × 1603 で、定数ではない。
- 早い再スタート (根のヒューリスティクスの途中) は、残りのヒューリスティクスを飛ばすだけ。判定は上と同じ。
- カットの引き継ぎ: 根の最後の LP で効いている (活動量が境界にある) カットだけを、問題の行として持ち込む。
  - 効いていないカットとプールのカットは捨てる。
  - 再スタートの後の根の LP は、効いているカットの分の下界を保つ。
- 木の中の再スタート (`TREEEFF=rpsh`、K・R ガード) は `maybe_restart` を `force_restart` で呼び、固定の閾値は見ない。
  - 固定の数え方と回数の上限 4 は根と同じ。
  - nra は K ガードの「効いているカット」の数え方を変えるだけ。
- 過去: hso (ACFIX=d + SB_NO_DEGEN_SKIP + SB_BUDGET_HIGHS) は P で外れた (4 スレッド 1.025、解けた数 141 → 137)。記録の上の害の元は強分枝の 2 部品の費用 (ノードは減るが時間が増える型) で、ACFIX=d の害の記録はない (protoscreen_20261124)。

## 4. 試作 `ENOMOTO_MIP_ROOTRESTART2` (既定オフ) の判定の式

親の考え方 (1 節) で、固定値の閾値の代わりに次の比べにする。新しい閾値は置かない。

- 再スタートする ⇔ σ(ln(W·s / C)) ≥ 1/2 ⇔ W·s ≥ C
  - **s (縮む割合)**:
    - 根の最後では、新たに固定した列の非零 ÷ 根の始めに自由だった列の非零 (`restart_shrink`、RSTCRIT と同じ量)。
    - 根の途中では、(新たな固定 + 今の被約費用で固定できる本数) ÷ 根の始めに自由だった整数列。
  - **W (次の段の手間の見込み、秒)**:
    - 根の最後 (`e`): 期限までの残り。解けない木は残りの時間を全部使う。
    - 根の途中 (`m`): 残りのラウンドの見込み (ここまでの 1 ラウンドの平均の秒 × 残りのラウンドの数)。
  - **C (再スタートの手間、秒)**:
    - 2 回目以降は、前の再スタートで実際にかかった秒 (決めてから次の根の LP が解けるまで: 前処理のかけ直し + 根の LP)。
    - 初回は、ここまでの外側の経過秒 (前処理 + 根の LP + カット) で見積もる。
- 文字:
  - `e`: 根の最後。木の中の再スタート (force) は今のまま。
  - `m`: 根のカットのラウンドの頭。
  - `a`: 解析的中心の固定。`ENOMOTO_MIP_HO4_ACFIX=d` と同じで、根の内点法の丸めの初めに、費用 0 の内点法の双対で固定する。
- 干渉: 木の中の再スタートの判定 K・R と nra は、`force_restart` の道でこの判定を通らないので変わらない。回数の上限 4 は共有する。

## 8. 根の最後の W を木の手間の見込みにする (利用者の選択: 作ってから P を 1 回)

- 式 (`rr2_tree_work`): 根のカットのループが下界を伸ばした速さのまま、残りのギャップを閉じる秒。新しい閾値はない。
  - W = t · G / Δ。期限までの残りを上限にする。
    - t: カットのループの秒。
    - Δ: 今の根の下界 − カットの前の根の LP の値。
    - G: 暫定解 − 今の根の下界。
  - 暫定解がない、Δ ≤ 0、t が測れないときは、期限までの残り (前と同じ)。G ≤ 0 なら 0。
  - ログ: `MIP: ROOTRESTART2 tree work: …`。
- C は 7 節の直し (前処理のかけ直し + 根の LP + 今の根のカットのループ) のまま。
- 確かめ (1 スレッド・種 1、ビルドは 025d9c607 = LU_REFAC_BAL=k の先端の後。ログは logs/W_*):

| 問題 | 時間 | `none` (ノード・秒、下の注) | eam (ノード・秒) | 判定 |
|---|---|---|---|---|
| p0201 | 60 | 21・0.77 | 21・0.83 | W 0.28 秒 × 0.66% < C 0.25 秒、σ 0.007 で見送り |

## 10. 再スタートの閾値を緩める形 `RSTLOOSE` (利用者の方針: 「再スタートの閾値はなるべく緩めに持つ」)

### 10.1 再スタートで何が引き継がれるか (既定の棚卸し)

| もの | 既定 | 備考 |
|---|---|---|
| 暫定解 | 引き継ぐ | RESTART_SOL |
| LP で効いている (tight な) カット | 問題の行になる | cuts_as_rows の道筋 |
| 効いていない LP のカット・プールのカット | 捨てる | `RESTART_ROOT_CUTS p` か木の再スタートの持ち越しのときだけ残る |
| 基底 | 引き継ぐ (RESTART_BASIS=1) | 行が 9 割以上合うときだけ使う (TREE3_RBASIS) |
| 擬似費用 | 木の再スタート + TREEEFF p のときだけ | 根の再スタートでは観測がほぼ 0 |
| 含意 (conflict_edges) | PRBWORK の skip のときだけ | |
| 双対の証明・衝突 | 引き継がない | |
| 解のプール | 引き継がない | |

- 擬似費用か含意を引き継ぐと、固定された変数を落とす処理 (RESTART_DROP_FIXED) は止まる (`restart_drop_fixed` が RESTART_PC と conflict_edges を見る)。

### 10.2 実装 (既定オフ、`ENOMOTO_MIP_RSTLOOSE`、文字の集合。`1` は `t` と同じ)

- `t`: 再スタートの閾値を全部、今ある中で一番緩い 0.01 にそろえる (`ENOMOTO_T_MIP_RESTART_FIRST_FAC` の値)。対象は RESTART_FAC 0.025 (4 か所)、EARLY_RESTART_FRAC 0.025 (2 か所)、木の再スタートの TREE_RESTART_FRAC 0.05 / INC2 の 0.1。`rst_fac` で包む。
- `p`: 根の再スタートでも、効いていないカットをプールごと持ち越す (`RESTART_ROOT_CUTS p` と同じ道筋)。
- `c`: 擬似費用に観測があれば根の再スタートでも引き継ぐ。
- `i`: 含意 (conflict_edges) を引き継ぎ、探査 (probing) はそれに足していく。
- 部分 MIP (submip) では p・c・i は効かない。単体テスト `rstloose_one_means_t` を足した。cargo test 428 passed、check_default は 6 問とも一致。
