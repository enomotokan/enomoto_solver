# 集約行ごとに 0.5 倍以上から最大 3 本残す (GENTOP3、2026-11-21、利用者の案)

試作 `ENOMOTO_MIP_GEN_TOP3` (src/mip/separation.rs の `keep_best`、既定オフ) を作り、8 問で既定と比べた。

**試作の中身**

- 今の `keep_best` は、集約行 1 本の向き 1 つから作った候補のうち最良 1 本だけを残す。試作では次のように変える。
  - その中で最良の質 (`cut_quality`) の `ENOMOTO_T_CUTSEL_MIN_REL` (既定 0.5) 倍以上のものを選ぶ。0.5 倍は全体の選択 `select_cuts_hybrid` の質の下限と同じ値。
  - その中から、良い順に最大 `ENOMOTO_T_MIP_GEN_TOP3_N` (既定 3、利用者の指定) 本を残す。
- 平行度と本数は全体の選択に任せる。
- 効く範囲は GEN_TYPE と同じで、`keep_best` を使う所すべて。
- `ENOMOTO_MIP_GEN_TYPE` より優先する。
- `ENOMOTO_MIP_GEN_TOP3_LOG` をつけると、`keep_best` に 2 本以上の候補が来た回に `GENTOP3 候補の数 0.5倍以上の数` を出す (診断)。

## 0. 結論

**t3 (LIFTED_COVER なし) は 0.979 倍 (95% [0.926, 1.034]) で、少し良いが区間は 1 をまたぐ。**

- 8 問・種 1〜3・4 スレッド・60 秒で測った。
- 根では p200x1188c と mc11 しか変わらない (gentype の gt とほぼ同じ形)。
- 他の 6 問の根は既定と同じ。
- 解けた数は 24 / 24。全回で 1.25 倍超遅れた問題はない。
- P 58 問の分担表 `shards_P.json` を作った (6 本、1 本 0.47 時間、計 2.8 時間)。回すかどうかは判断を待つ。

**t3lc (LIFTED_COVER あり) は勧めない。**

- 既定に対して 1.048 倍 (95% [0.942, 1.165])、lc に対して 1.022 倍 (95% [0.974, 1.073])。
- p200x1188c は根で最適値に届く (残り 0%)。
- 一方で exp-1-500-5-5・nw04・qiu・timtab1 は lc と同じく遅い。

**3 本まで残せる形でも、実際にはほぼ 2 本しか残らない (§1)。**

- `keep_best` に 2 本以上の候補が来る回は、ほぼ必ず 2 本で、2 本とも最良の 0.5 倍以上。
- 3 本以上が来るのは LIFTED_COVER ありの mc11 (15%)・beasleyC3 (9%)・p200x1188c (4%) くらい。
- そのため t3 は「候補を全部残す」とほぼ同じで、種類ごとに最良を残す gentype の gt とも結果がほぼ同じ。

**確かめ:**

- fuzz 7 本は、t3・t3lc とも bad 0。
- cargo test は、既定・t3・t3lc とも 419 通る、失敗 0、無視 19。

## 4. 置き場所と回し方

- `cfg.py`: 設定 def・lc・t3・t3lc・diag・diaglc。
- 根だけの計測:
  - `root.py`: 根だけを回す (1 スレッド、ログは logs/、コミットしない)。
  - `rootsum.py`: 集計して `root_table.md` を作る。
  - `diag.py`: 診断を集計して `diag.md` を作る。
- 通しの計測: `run.py`・`ci.py`・`shards_L.json` で回し、結果は `res_L_s0.jsonl`・`run_L.out`。
- 広い計測:
  - `plan.py` で分担表を作る (gentype_20261121 の写し)。
  - `shards_P.json` は作成済み (`python plan.py P 6 t3`): P 58 問 × 種 1〜3 × {def, t3}、60 秒、6 本、1 本 0.47 時間。
  - 回し方は `python run.py P K` (K = 0〜5)、集計は `python ci.py 60 def t3 res_P_s*.jsonl`。
- 誤答の確かめ: `fuzz.sh [lc]` で回し、結果は `fuzz_t3.out`・`fuzz_t3lc.out`。
