# set_basis が捨てている非基底の置き場所の損の上限 (2026-11-02)

試作 (analysis/basis_nb_20261102.md、`ENOMOTO_MIP_BASIS_NB`) の前に、`set_basis` が保存した `Basis` の Upper / Lower を捨て、
解き始めの置き場所を `nb_hint()` (直前に解いた点 `self.x` から推し量る) で決めていることで、今どれだけ損をしているかの上限を測った。

- 土台: b41f5735 (診断を足したコミット。親は 35affb08)。既定の設定 (試作の切り替えは付けない)。
- 58 問 (analysis/cbcimpl_20261029/probs.py)、4 スレッド・60 秒、1 回ずつ、ソルバーは同時に 1 つ。
- 台本・ログ: analysis/basis_nb_diag_20261102/ (`run.py` が解いて `logs/<問題>.log` に NB_DIAG の行を書き、`table.py` が `tables.md` を作る)。

## 1. 数え方 (`ENOMOTO_MIP_NB_DIAG`、振る舞いは変えない)

src/simplex/nb_diag.rs。`set_basis` の呼び出し元が場所の印 (`nb_diag::tag`) を付け、`set_basis` が渡された `Basis` から
標準形の列ごとの「保存した側」(列: Lower → -1、Upper → +1、Zero・Basic → 0。行: σ と Upper / Lower からスラックの下限 -1 / 上限 +1) を覚える。
その直後の求解 1 回で次を数える。

| 名前 | 意味 |
|---|---|
| 比べた列・行 (`cmp`) | 保存した側が ±1 で、求解のときも非基底 (修復の後) で、固定 (下限 = 上限) でない列・行 |
| 食い違い (`mis` = `opp` + `unk`) | そのうち `nb_hint()` が保存した側と違う数。`opp`: 反対の側、`unk`: 0 (前の解でどちらの境界にもない = 前の LP で基底だった列など) |
| 実際に置いた側の食い違い (`eff`) | 双対単体法の warm start の初期化 (`warm_start_basis`) が実際に置いた側が保存した側と違う数。被約費用の符号がはっきりした列は希望によらず符号の側に置かれるので、`mis` より小さい |
| 保存した側に置けた (`fix`) | `eff` のうち、保存した側を希望として渡せばその側に置かれた数 (真の費用での被約費用がその側で許容誤差 `ENOMOTO_T_WARM_NB_TOL` 以内。今の希望の判定と同じ条件)。**置き場所を渡す試作で変わりうるのはこの列だけ** |
| 特異で捨てた LP (`n_noeff`) | 比べたが `warm_start_basis` の数え上げまで来なかった LP。渡した基底の LU 分解が特異で、warm start をやめて crash (全スラック基底) から解いたもの (drayage-100-23・misc07 で一時ログを入れて確かめた。ほかの早期の戻りは起きていない) |

LP は `mis > 0` かどうか、`fix > 0` かどうかで分け、反復数と時間 (`solve_once` の経過時間) を足す。場所:

| 場所 | 呼び出し元 |
|---|---|
| tree_sibling | 潜りの兄弟ノード (`restore_node_basis`、`tp_kind` 0) |
| tree_queue | 自分の待ち行列から取ったノード (`tp_kind` 1) |
| tree_pool | 共有の待ち行列から取ったノード (`tp_kind` 2) |
| submip_root | サブ MIP の根の初めの基底 (`SUBMIP_BASIS`、列の状態だけ) |
| bg_copy | 裏のカットの写しの根 (`BG_ROOT_BASIS`) |
| bg_return | 主が裏のカットを受け取ったときの基底 (`bg.job.basis`) |
| restart | 再スタートの後の根 (`RESTART_BASIS`) |
| root_probe | 前処理の LP による固定の基底からの根 (`ROOT_BASIS`) |
| slack_retry | 根のカットのループで LP が誤り・反復上限のときの全論理変数基底からの解き直し |
| no_set_basis | `set_basis` の後でない求解 (前の解からそのまま。比べる相手なし。全体の時間の分母) |

`main` / `sub` はそのスレッドがサブ MIP (`params.submip`) を解いているか。時間はスレッドの和 (58 問で main の LP の時間の和 2060 秒、経過時間の和 1397 秒)。

読み方:

- **食い違いはほぼ常にある** (木で 83〜99%) が、大半は「不明」(`nb_hint` が 0: 前の LP で基底だった列が保存した基底では非基底) で、
  被約費用の符号で保存した側に置き直される。実際に置いた側が違うのは 1 LP あたり 2〜4 列、保存した側を渡して変わるのは **1 列以下** (0.6〜1.0)。
- 置けた列のある LP は反復が多い (木の tree_queue で 30 対 10、tree_sibling で 21 対 9) が、この比べには「遠いノードほど食い違いも反復も多い」
  交絡が入っている。損の上限は「置けた列のある LP の時間」: 木で 67.3 + 97.5 + 4.4 = **169 秒 (main の LP 時間 2060 秒の 8.2%)**。
  反復の差 (置けた列ありの平均 − 食い違いなしの平均) の分だけ減るとしても sibling 38 秒 + queue 65 秒 ≈ **100 秒 (4.9%)** が上限の目安。
- 裏のカットの写し (bg_copy) は LP 数は少ないが、置けた列のある LP は 1 回平均 556 反復 (食い違いのない写しは 1 反復)。置き場所を渡せば
  ほぼ 1 反復になる見込みの典型 (analysis/phys6_20261101.md の 1 節と同じ形)。
- **置き場所より大きい損: 渡した基底が特異で丸ごと捨てられている**。共有の待ち行列のノードの 36%、再スタートの後の根の 89%、
  前処理の LP の基底からの根の 69%、サブ MIP の根の 82% で、warm start をやめて全スラック基底から解いている。

## 4. どこを直すと得が大きそうか

1. **特異で捨てている基底 (置き場所より先)**: 前処理の LP の基底からの根 (ns1116954 で 12 秒、mzzv42z・neos-960392・physiciansched6-2・
   neos-827175 で 1〜2.5 秒)、再スタートの後の根 (mzzv42z で 8 秒)、共有の待ち行列のノード (36%。neos5・misc07・noswot・neos-911970 など)。
   列の状態だけ (行は空) の基底を `set_basis` の修復 (`repair_basis`) が論理変数で埋めた結果が特異になっているとみられる。修復で特異な列を
   論理変数に入れ替える (LU の特異な列を外す) か、特異なら今の基底のまま解く、の方が置き場所を渡すより効きが大きい見込み。
2. **裏のカットの写し (bg_copy)**: 置けた列のある写しは 1 回平均 556 反復、ない写しは 1 反復。neos-960392 (7.2 秒)、physiciansched6-2。
   試作 `ENOMOTO_MIP_BASIS_NB` の場所 `b` (か `ENOMOTO_MIP_BG_CUTS_BASIS_X=lpw`) の効く所。
3. **木のノードの復元 (t)**: 上限は main の LP 時間の約 5〜8% (58 問の和で 100〜169 秒)。効く見込みがあるのは timtab1・supportcase26・
   bppc4-08・graph20-20-1rand・noswot・neos5・roll3000。1 LP あたりで保存した側に置き直せる列は 1 列以下なので、反復の差の大半は
   「遠いノードの基底」から来ていて、置き場所を渡しても減らない分が多いと考える。試作では置けた列のある LP の反復が食い違いのない
   LP (tree_queue で 10 反復) の水準まで下がるかを見るとよい。
4. サブ MIP の根 (s): 合計 5.2 秒しかなく、82% は特異で捨てているので、置き場所を渡しても得はほぼない (特異の手当てが先)。
