# 根のサブ MIP による解探しの差 (SCIP-RENS、2026-11-20)

親の依頼: neos-1171448 (SCIP は根のカット 11 巡の後の LP 点の RENS で −309) と 10teams (SCIP は lpface で最適 924) の差を突き止め、
同じ型の問題 (根の下界は最適なのに解が出ない) にも効く形で試作する。既定は変えない。

  (`lfscan.jsonl`。書き途中なのでコミットせず、終わったものを `lfscan_done.jsonl` に写してコミットする)。

## 1. 10teams: SCIP の lpface の決め手 (事実)

- SCIP (種 1) の最初で最後の解は lpface (5 ノード目・深さ 4)。lpface は既定で `minpathlen = 5` なので根では回らず、下界の変わらない道が
  深さ 4 に届いたノードで回る。lpface を切ると種 1 は 4.8 → 24.2 秒・805 ノード (種 2・3 は lpface が回らず変わらない)。
- `heuristics/lpface/minpathlen = 0` (根でも回す) にすると種 1〜3 とも **根 1 ノード** で最適 (4.0・4.7・6.1 秒)。
  この形で、LP の行 (カット) を使わない・目的を元のままにする、のどちらも 1 ノードのまま。根のカットを切る (根の LP 917 < 最適 924) と解けない。
- heur_lpface.c (v10.0.2) を読むと、サブ SCIP は (1) 被約費用が 0 でない列を LP 解の値 (大域の境界の上にあるもの) に固定、
  (2) LP の行を写す、(3) **目的値 = 今の下界 の等式を足す**、(4) 目的は 0 (`subscipobjective = z`)、前処理・分離は fast、ノード上限 5000 まで。
- 当方の LP face (`src/mip/heur_scip.rs` の `lp_face`) は (1) は同じ (10teams で 1600 列中 535 列を固定) だが、(3) の行がない。
  250 ノードで解なし (scipslow 2 節)。しかも直前の「根の被約費用」のサブ MIP が同じ固定 (自由な列 1065) で 4 秒空振りしている。

## 2. 試作 `ENOMOTO_MIP_LPFACE=<文字の並び>` (既定では使わない)

- `c`: LP face のサブ MIP に目的値の行 c·x ≤ z̄ を足し、打ち切り値を z̄ のすぐ上 (目的値の刻みがあれば刻みの半分、なければ相対 1e-6) にする。
  z̄ は今の LP の値を目的値の刻みに切り上げたもの (刻みがなければ LP の値)。z̄ は根の下界なので、見つかる解は最適。
  面の固定が少ない (固定率 < 0.3) 問題では今と同じく回らない。
- `z`: さらにサブ MIP の目的を 0 にする (SCIP の既定の形)。
- `f`: 根で LP face を「根の被約費用」のサブ MIP より先に回す (`src/mip/solver.rs` の根のヒューリスティクスの並び)。
- 正しさ: 解は元の問題で確かめてから暫定解にする (`try_incumbent`)。目的値の行と打ち切り値は、サブ MIP が探す範囲を狭めるだけ。

## 3. neos-1171448 (事実)

- 根の LP は最初から −309 (= 最適値)、双対は完全に退化していて、被約費用が 0 でない整数列がない (LP face は「0 of 2457 fixed」で回らない)。
- SCIP の RENS はカット 11 巡の後の LP 点 (4 秒、暫定解 −217) で 10000 反復のサブ SCIP を回し −309。ただし SCIP 自身も揺れが大きい
  (`logs/neos-1171448_sciph.jsonl`、120 秒): 既定 11.1・10.0・35.4 秒、RENS なし 43.3・71.5・**8.7** 秒、根のカットなし 24.7・**3.4**・時間切れ (種 1〜3)。
  最適面が広く、どの頂点に RENS を当てるかの運の要素が強い。
- 当方 (`c`、1 スレッド): 種 1 は 215.6 秒 (根の SUBFIX の RENS で −307、木の crossover で −309)、種 4 は 60.1 秒。LP face は回らないので既定と同じ計算。
- 判断: 1 問向け・運向けの対策になりやすいので、ここでは手を入れない (heur4 2 節の `HEUR4` の結論とも同じ)。

## 8. M の途中で遅くなった問題の切り分け

### comp07-2idx (種で割れる揺れ)

- 親の計測: 種 1 は def 時間切れ (暫定解 46)・lfc 50.0 秒、種 2 は def 38.7・lfc 323.2 秒。
- 手元で種 2 (4 スレッド) を解き直すと def 118.3 秒・lfc 400 秒で時間切れ (暫定解 23)。def だけでも 38.7 → 118.3 秒と揺れる。
- ログ (`logs/comp07-2idx_*_s2_t4.log.gz`): 2 回は LP face より前に分かれている。def は Local-MIP が 18 秒で 6 (最適) を見つけ、
  根の早い段階の被約費用で 8308 列を固定。lfc は 8 秒で 55 までで、固定は 38 列。差は Local-MIP の揺れで、試作の手が入る前に決まっている。

### neos-1582420 (z̄ が最適値に届かず、LP face の解を消す)

- 親の計測: 種 1 は 25.3 → 52.1 秒、種 2 は 35.1 → 45.1 秒。根の下界 89.3、z̄ = 90、最適 91。
- 1 スレッド (揺れなし、`logs/neos-1582420_*_t1.log.gz`): def 57.8・55.7・56.9 秒、lfc 63.4・62.8・52.4 秒 (種 1〜3)。
  - def: 目的値の行のない LP face が 15 秒で 92 を見つけ、そのまま再スタートに入る。
  - lfc: 行 c·x ≤ 90 のサブ MIP は解なし (2.6 秒)。92 は 8 秒遅れて RINS が見つける。種 3 だけは別の道で速い。
- 4 スレッド (`logs/neos-1582420_*_s1_t4.log.gz`、19.8 → 24.5 秒): RENS が先に 92 を出すので再スタートまでは同じ。
  分かれるのは再スタートの後で、差の大きさは揺れが広げている。
- 原因: z̄ が最適値に届かない (根の下界と最適値の間に刻みが 1 つ以上ある) 問題では、目的値の行が LP face の普段の働き
  (面の上で良い解を探す) を消す。行のサブ MIP の解なしは「面の上に z̄ 以下の解はない」という情報で、その後の探しには使えない。
