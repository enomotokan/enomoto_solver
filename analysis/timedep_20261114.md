# timedep: 経過時間で分かれ道や量を決めている所の洗い出しと、揺れへの効き方の確かめ (2026-11-14)

- 発端: 同じ問題・同じ設定でも結果 (時間・ノード数・解けるか) が回ごと・機械ごとに大きく揺れる (58 問で 10teams 1.47/4.57 倍、
  noswot 0.37/0.19 倍など。前処理が同一の A/A でも)。揺れの元のうち「経過時間 (壁時計・CPU 時間) を見て処理の分かれ道や量を
  決めている所」を、手間の量 (LP の反復・ラウンド数・ノード数・非零の演算など) に置き換える候補を選ぶ。
- 先例: 裏のカットの止め方 `ENOMOTO_MIP_BG_CUTS_DETERM` (既定 `c`、solver.rs:4131) と LP 1 回の上限 `BG_CUTS_LP_WORK` (既定 `1`、
  separation.rs:1625-1628) は既定化済み (analysis/bg_determ_20261102.md・bg_lp_work_20261102.md・canddet_default_20261102.md)。
  CUTSEL_PROBE の同点 (analysis/parint2_20261113.md、試作 `ENOMOTO_MIP_CUTSEL_PROBE_TIE_FEWER`) は別のセッションで 58 問を計測中なので重ねない。
- この記録では試作は作らない (コードは変えていない)。版は fc875d5f。
- 台本・ログは `timedep_20261114/`: `run1.py` (1 回解いてログ)、`batch.sh`・`batch2.sh` (A/A の並び)、`summ.py` (ログから分かれ道を拾って並べる)、
  `firstdiff.py` (2 つのログの最初の分かれ目)、

## 1. 洗い出し (コードの読み)

範囲: src/mip/ 全部と、src/ の LP・前処理 (simplex・interior_point・presolve・solver.rs・cancel.rs ほか)。grep の当たり
(`Instant|elapsed|_SECS|TIME_FRAC|time_limit|deadline|remaining|secs|cpu_time|now()`) は約 1800 行。うち約 3/4 は表示・統計だけ
(ログの秒、prof、TRSTAT などの診断)。前処理 (presolve)・グラフ・二段解法の本体の LU の作り直し (合成クロック `synth_tick`/`build_tick`)・
KKT の並べ方 (演算量の見積もり) には時間で決める所は無い。

測り方の注意: 根のカットのループの上限 (C1・C2) は **そのスレッドの CPU 時間** (`cap_clock()`、mod.rs:267-289) で、ほかはほぼ壁時計。
CPU 時間は同じ CPU を他の処理と分け合っても伸びないが、機械そのものが遅ければ伸びる。

## 2. A/A で、どの分かれ道が実際に揺れているかを確かめた

### 2.1 やり方

- 機械: 4 CPU、ソルバーは同時に 1 つ (ほかの計測と重ねない)。束 cand1114、種 1、60 秒、`ENOMOTO_MIP_LOG=1` (表示だけ)。
  1 スレッドは `taskset -c 0`、4 スレッドは `taskset -c 0-3`。
- 設定の札 (ログ `timedep_20261114/logs/<問題>_t<スレッド>_<札><回>.log`):
  - `n`: 普通。3 回。
  - `s`: 遅い機械の真似。ソルバーと同じ CPU に同じ数の空回し (`yes`) を載せ、壁時計で約半分の速さにする。2 回。
    **スレッドの CPU 時間はほぼ伸びない**ので、壁時計で決める分かれ道だけが動く (CPU 時間で決める C1・C2 は動きにくい)。
  - `v`: `ENOMOTO_MIP_MPSEP=oqmgsv` (既定 `oqmgs` と動きは同じで、MPSEP の移動の 1 行を出す)。1 スレッド 3 回。
  - `m`: `v` + `ENOMOTO_T_MIP_MPSEP_MOVE_SECS=100` (C9 の移動を時間でなく入れ替えの回数 1000 だけで止める)。1 スレッド 3 回。
  - `r`: 4 スレッドで `ENOMOTO_MIP_MC11FIX1_RACE=s`・`ENOMOTO_T_MIP_MC11FIX1_RACE_SIZE=1e12` (根の LP の同時実行をやめ単体法だけ、E1 を消す)
    + `ENOMOTO_T_MIP_MPSEP_MOVE_SECS=100`。3 回。
- 分かれ目の探し方: `firstdiff.py A.log B.log` が、秒の表示を消した 2 つのログの最初に違う行を出す。`summ.py` が回ごとに分かれ道の印
  (根の LP の勝ち手・カット選び・根のカットのラウンド数と値・暫定解の出どころ・サブ MIP の時間切れの数・木の再スタートのガード) を並べる。

### 2.3 分かれ目 (最初に違う行) とその元

事実:

1. **1 スレッドでも揺れる**。10teams は 7.0〜50.6 秒、noswot は 30.5 秒〜時間切れ、mc11 は 34.9 秒〜時間切れ。
   physiciansched6-2 と nw04 は 1 スレッドの普通の 3 回がほぼ同じ道 (physiciansched6-2 は秒の表示を除き最後まで同じ。nw04 はカット選びが 1 回目だけ default)。
2. **C9 (MPSEP の最適面の上の移動、上限 0.25×根の LP の秒を 0.01〜0.1 秒に挟む)**: 10teams・noswot の 1 スレッドで、最初の分かれ目は
   どれも MPSEP を使ったラウンドの直後 (10teams は 3 ラウンド目、noswot は 4 ラウンド目。同じラウンドの LP の反復とカットの数が違う)。
   既定の動き (`v`) では、10teams の移動 32 回がすべて「時間で止まった」(noswot は 22 回のうち 12 回)。
   **`m` (回数だけで止める) では 10teams の 1 スレッドの 3 回が最後まで同じ道** (4824 ノード、違うのは LP の秒の表示だけ)。
3. **C2 (カットのループの第 2 段階の上限、第 1 段階の CPU 時間の 4 倍)**: mc11 の 1 スレッドは、第 1 段階が 25 ラウンドで 0.90 秒、
   第 2 段階は CPU 時間 約 3.1〜3.2 秒で止まり (終わりの表示なし)、そこまでのラウンド数が 64 (35.3 秒で解ける) と 73 (時間切れ)、
   62 (34.9 秒) に分かれた。`m` でも 60 ラウンド目で止まるかどうかで分かれる。**CPU 時間で測っても回ごとに 1 割ほど揺れ、それでラウンド数が変わる。**
4. **木の中 (noswot の 1 スレッド、`m`)**: C9 を消した後の分かれ目は、(a) 木の中の再スタートをしたかどうか (B7、TREEEFF `r` のガード。
   `TREE restart ... at node 2100` が一方にだけある) と、(b) 木の大近傍探索のサブ MIP が `NodeLimit, nodes 1000, 0.26s` か
   `TimeLimit, nodes 735, 0.30s` か (B1、1 回の上限の下限 0.3 秒)。
5. **E1 (根の LP の同時実行の先着)**: 4 スレッドの 10teams・noswot・mc11 では、普通の 3 回の最初の分かれ目が
   `Root LP: the two-phase method / interior-point method + crossover finished first`。勝ち手は前処理の LP プロービングと根の 2 か所で
   それぞれ揺れる。mc11 では根で単体法が勝った 2 回 (n1・s2) が根のカット 25 ラウンド・下界 11024.5 で 55.3 秒・時間切れ、
   内点法が勝った 3 回 (n2・n3・s1) が 64〜65 ラウンド・11565〜11567 で 25.8・31.6・55.7 秒。
6. **E2 か E4・E5 (同時実行の中の内点法・クロスオーバー)**: physiciansched6-2 の 4 スレッドは、2 回とも内点法が勝つが、前処理の
   LP プロービングの根の LP の反復が 5696 と 5888 で違う (内点法をどの反復で止めてクロスオーバーに渡したか、押し出しの締切)。
7. **FJ / Local-MIP のスレッドの解の届く時期 (A3・D1・D2)**: 4 スレッドで E1 と C9 を消した `r` でも揺れは残り (10teams 8.7〜33.4 秒、
   mc11 33.6 秒〜時間切れ)、最初の分かれ目は Local-MIP の解が主のカットのループの何ラウンド目に届くか (mc11 は 8 ラウンド目の前に
   `Local-MIP solution accepted false` が入るかどうか) と、Local-MIP が見つける解の値そのもの (10teams は 976 と 958。Local-MIP は 0.2 秒ずつの
   時間の区切りで回る)。
8. **遅い機械の真似 (`s`) で変わる分かれ道** (壁時計のもの):
   - **C7 (カット選びの比べの予算、壁時計 0.05×残り)**: physiciansched6-2 は普通の機械では比べが 1.6〜1.9 秒 (予算 2.7 秒) で終わって
     pool を選び、根の下界 49324 (36 秒で解ける)。遅い機械の真似では 3.0〜3.1 秒で予算 (2.3 秒) に当たり、**0 ラウンドで打ち切られて default** に
     なり、根の下界 47633.7 で 1 スレッドは 2 回とも時間切れ、4 スレッドも 1 回は時間切れ。nw04 も `s` では 4 回とも予算で打ち切られ pool。
   - **D5 (根の局所探索、壁時計 0.05×TL = 3 秒)**: 10teams の 1 スレッドは局所探索がどの回も 2.86〜2.98 秒まで回る (時間で止まっている)。
     普通の機械では 924・940 を見つけ、遅い機械の真似では 2 回とも 956 で、どちらも時間切れ。
   - **E1**: 遅い機械の真似でも勝ち手は回ごとに揺れる (どちらが速いかは、両方の進みが同じように遅くなるので変わりにくい)。
9. 時間の上限の割合の基準も壁時計: physiciansched6-2 の C1 (根のカットのループの上限、CPU 時間) の上限は、普通の機械 5.40 秒・
   遅い機械 4.67 秒で、求解の始めの残り時間 (前処理に使った壁時計の秒を引いた値) から計算されている。C7 の予算も 2.7 秒と 2.3 秒。

見立て:

- 1 スレッドの揺れの先頭は C9。次に C2、その先 (木の中) は B1・B7 と、根の局所探索 D5。C9 は 1 回の移動が 0.01〜0.1 秒しかないため、
  機械が同じでも当たり方が毎回違う。手数に替えるのは易しい (既に入れ替えの回数の上限 1000 がある。`m` は時間を外しただけ)。
- 4 スレッドの揺れの先頭は E1。その後は FJ / Local-MIP のスレッドとの受け渡しの時期と、Local-MIP の時間の区切り。並列の受け渡しの時期は
  手間に置き換えても残る (受け取るラウンドを決めるには、主が待つ形にする必要がある)。
- 遅い機械 (または混んだ機械) で効くのは C7 (比べの予算) と D5、それに割合の基準が壁時計の残り時間であること (B19 と同じ性質)。
  58 問の機械ごとの差 (例: 10teams 1.47/4.57 倍) には、これらが効いているはず。
- `m` は 1 スレッドの 10teams を決定的にしたが、速さは良くも悪くもない (45 秒。既定の回は 7〜60 秒)。手間に替えることは揺れを消すだけで、
  速さは別に確かめる必要がある。
