# mc11 で HiGHS 風のサブ MIP (h1) が遅くなる原因 (2026-10-30)

- 機械: 4 CPU。ソルバーは同時に 1 つだけ動かした。HiGHS (highspy) は 1.15.1。
- 土台: ブランチ `ccr-1beed81b-ex0uhq` の `9b4957cb` (ソースは変えていない)。
- 計測: `ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_THREADS=4`、60 秒・4 スレッド、mc11 (最適値 11689)。
- 台本とログは `analysis/mc11_h1_20261030/` (`run.sh 名前 [SUBMIP_HIGHS の値] [環境変数 ...]` で 1 回、`batch1.sh`・`batch2.sh` が
  今回の並び、`summary.py` がログから下の表を作る。全部の回の表は `logs/summary.md`)。
- 発端: `analysis/halve_submip_20261030.md` で h1 (`ENOMOTO_MIP_SUBMIP_HIGHS=1`) にすると mc11 が 2 回とも時間切れになった。

## 1. 結論

事実:

1. **原因の部分は `s` (サブ MIP の擬似費用の信頼の観測を 0 にする = サブ MIP で強分岐をしない)**。`s` だけで h1 と同じく
   3 回とも時間切れ (11740・11689・11699)、`-s` (s を除く全部) は 3 回とも解ける (13.8・31.8・26.2 秒)。ほかの 1 文字だけの形
   (`p c g t i h f`) はどれも既定並みに解ける (24.6〜40.9 秒)。
2. **仕組み: 根のヒューリスティクスが早く終わる → 裏のカット (background cuts) が途中で止められる → 根の下界が弱い → 木が閉じない**。
   - 根のヒューリスティクスの長さは、並列に回す `root reduced cost` のサブ MIP (自由な列 2272) の終わりでほぼ決まる
     (並列のサブ MIP は `join_submips(0)` で待つ)。このサブ MIP は暫定解を改めない (13276 など) のに、既定では強分岐で 3.1〜3.5 秒かかる。
     `s` では同じ 104 ノードが 0.65 秒、h1 (`c` で根のカットが増える分も入る) は 50 ノードで 1.4 秒。
   - 裏のカットは「根のヒューリスティクスの間だけ」続け、終わったら止めて根の LP のカットを置き換える (`solver.rs` の `bg_cuts.finish()`)。
     既定では根のヒューリスティクスが 6.8〜8.6 秒まで続き、裏のカットは 53〜58 ラウンドで停滞の近く (`BG_CUTS_LOG`: 45 ラウンドで 11682.8、
     51 ラウンドで 11683.8) まで進み、根の下界は 11668〜11684。h1 では 2.9〜3.4 秒で終わり 28〜29 ラウンド (1 ラウンドで 20 ほど
     上がっている途中) で止められて 11578〜11590、`s` だけでは 2.1〜2.4 秒・16〜18 ラウンドで 11375〜11417。
   - 根の下界と最適値 11689 の差は、既定 5〜21、h1 99〜112、`s` だけ 272〜314。木のノードは既定 142〜1620 に対し、h1・`s` は 60 秒で
     2254〜3668 ノード進んでも閉じない (時間切れの回の暫定解は 11689〜11740、最適値まで届いても証明できない)。
3. **裏のカットを止めると (`ENOMOTO_MIP_NO_BG_CUTS=1`) 既定も h1 も 2 回とも時間切れ** (既定 11718・11743、h1 11719・11729。根の下界は
   どちらも 11003.7〜11097.6)。つまり mc11 は裏のカットの下界が解けるかどうかの決め手で、h1 の差はサブ MIP の解の質ではなく、
   裏のカットに与える時間の差で起きる。
4. 根のサブ MIP の解の質は h1 のほうがむしろ良い (根の RENS は h1 で 17 ノードの最適 12063・0.2 秒、既定はノード上限で 12104 と
   その後の `RENS (more nodes)` 1.4 秒)。h1 は根の暫定解 12063 → 木の RINS 11948〜11998 (8 秒台) と早く進むが、最適値の証明が遅れる。

推測:

- 裏のカットの長さが「根のヒューリスティクスの長さ」に縛られているのが本当の弱点で、`s` はそれを表に出しただけ。サブ MIP を速くする
  変更 (h1 の `s`、`-c` の形も 15 ラウンド・11371 で時間切れ) は、mc11 のように根のカットが長く効き続ける問題で同じ形の悪化を起こしうる。

## 2. 直し方の案

1. **(本命) 裏のカットの終わりを根のヒューリスティクスから切り離す**: 根のヒューリスティクスが終わった時点で裏のカットがまだ
   上がっている (例: 直近 5 ラウンドの上がり幅が相対 1e-4 超) なら、停滞するか待ちの上限 (例: 残り時間の 10% か、主の根のカットの
   ループの時間の k 倍) まで `finish` を待つ。待つ間は主のスレッドで木の RINS 相当や丸めを回してもよい。mc11 では h1 の 2.9 秒 →
   6〜8 秒で既定並みの下界 (11668〜11684) に届く見込み。既定の側でも、運でサブ MIP が早く終わった回に下界が弱くなるのを防げる。
2. `s` を HiGHS と同じく打ち切り値が無限のサブ MIP だけにする (`ENOMOTO_MIP_SUBMIP_NO_SB` と同じ範囲) か、根の `root reduced cost`
   の並列のサブ MIP だけ外す。mc11 は直るが、根の長さを強分岐で間接に決めることになるので 1. より筋が悪い。h1 の利得
   (physiciansched6-2・mzzv42z など、主に `c`・`h`) との兼ね合いは 58 問で確かめる必要がある。
3. 根のヒューリスティクスの最低時間を裏のカットのためにとる (例: 主の根のカットのループの時間の 5 倍まで次のヒューリスティクスを続ける)。
   1. の簡易版。
