## まとめ

- **出どころ (事実)**: HiGHS の z の式のカットは **mod-k 分離器 (`HighsModkSeparator`)** から出る。mod-k を止めると根の下界は 0.015844 で ENOMOTO と
  同じ (他の分離器・含意・クリークを止めても 0.0275〜0.0311)。mod-k が見つける行の組は「**x0 の係数の符号が逆のデータの行 2 本** (+ LP 値が
  0 でない w を消す w-z の 2 項の行 0〜10 本)」で、その集約行 (x0 と共通の w が消える) を `generateCut` に渡し、w を変数上下限
  (`|w| ≤ 10 z`、前処理で w' = w + 10 にずらした `w' ≤ 10 z + 10`・`w' ≥ -10 z + 10`) で z に置き換え、**lifted mixed-integer cover** が
  `Σ_S z ≥ 1` (S は 2 本の行の w の対称差) を作る。mod-k の剰余の式そのもの (CG カット) ではなく、mod-k は「LP 値が 0 でない整数列 (x0、
  小数の w) が全部消える行の組」を見つける道具として使われている。
- **試作 (事実)**: `ENOMOTO_MIP_MUSHAGG` (根だけ): LP で等号の元の行のうち、変数上下限を持たない一般整数列 (LP 値が上下限の内側) の係数が
  逆符号の 2 本を足してその列を消し、変数上下限による「0-1 列の cover」(`vb_cover_cut`: 全部の z = 0 なら w が縛られて行が満たせない →
  `Σ z ≥ 1`) を作る。再スタートの後の模型の根の下界は **0.01585 → 0.03163** (HiGHS 0.03052)。

## 1. HiGHS のカットの出どころ

### 1.1 計装 (事実)

- HiGHS v1.15.1 (github の ERGO-Code/HiGHS のタグ、highspy 1.15.1 と同じ版) に既存の `scripts/highs_instrument.patch` と、この調べの印付けを
  当ててビルドした highs-bin (`mushroom_cuts_20261106/highs_tag.patch` は両方を含む差分。当て方の元は `tag.py`・`tag2.py`)。
  - `HIGHS_POOL_TAG=ファイル`: カットプールに入る全てのカットに `P` 行 (submip か・プール・行番号・出どころ・方法・衝突か・右辺・係数 | 集約した LP の行と重み)、
    LP に入れるときに `L` 行。出どころは分離のラウンドの中で印を付ける (`tab`・`path`・`modk` は `HighsSeparation` の 3 つの分離器、`impl` は
    `separateImpliedBounds`、`clq` は `separateCliques`、`cf-search`・`cf-heur` は双対の証明からの衝突 (`generateConflict`))。方法は
    `tryGenerateCut` で 1 = CMIR、2 = lifted knapsack cover、3 = lifted mixed-integer cover、4 = lifted mixed-binary cover。集約の行は
    `HighsLpAggregator::addRow` で記録 (LP のカットの行は中身ごと)。
  - `HIGHS_GC_TRACE_MODK=ファイル`: mod-k の分離のときだけ `generateCut` の途中 (既存の計装の `IN`・`XF`・`BT`・`TR`・`PP`・`TG`・`UT`・`PO`) を書く。

    (ノード上限 1 の 10 秒の解法で再スタートの表示なし)。前処理の後の模型 (8456 行 × 304 列) にカットは入っていない。プールの全ての行は上の印のどれか

  `highs_only_20261105/G1/mushroom/README.md`)。HiGHS は 4 スレッド・ノード上限 1・`objective_bound = 0.0553338` (`highs/root.opt`)。

### 1.4 z の式が出るときの集約の詳細 (事実、`highs/zcut_blocks.txt.gz`)

3 本を追った (行番号・列番号は HiGHS の前処理の後の模型。LP の論理変数の番号は 304 + 行番号)。

1. プール 2963 (ラウンド 10、LP の値 0.02160 → `Σ_{10 本} z ≥ 1`):
   - 集約: データの行 5992 (`x0 + Σ w ≤ 309`) と 6941 (`-x0 - Σ w ≤ -311`) を重み 0.4 ずつ (mod 5 の重み 2/5)。**x0 と共通の w が消え**、
     対称差の w 10 本 (係数 ±0.4) と 2 本の行の論理変数が残る (右辺 0 の等式の形)。
   - 置き換え (`BT`): w 10 本は LP 値 w' = 10 (w = 0) で VUB・VLB がちょうど効く (余裕 0) ので、係数が正なら VUB (型 2)、負なら VLB (型 3) で
     `w' = 10 z + 10 - s` / `w' = -10 z + 10 + s` に置き換え。z の係数 4 (0.4 × 10)、余り s の係数 -0.4 (上限 20)、右辺 248。
   - 前処理で係数を 1/8 に (z 0.5、s -0.05、右辺 31)、一般整数を含むので lifted mixed-integer cover (`COVER 1 kind 1`)。CMIR (delta 0.125) は
     効き目がそれを超えず使わない (`USE lifted`)。余りは補変数にされ、元に戻すと `-0.1 Σ z ≤ -0.1` → `Σ z ≥ 1`。
2. プール 9408 (ラウンド 2、`Σ_{16 本} z ≥ 1`): データの行 4734・5988 と w-z の行 8145 (`w25' - 10 z138 ≤ 10`)・8237 (`-w26' - 10 z139 ≤ -10`) を
   重み 0.4 ずつ。w25・w26 は LP 値が 0 でない (z138 = 0.17、z139 = 0.03) ので mod-k の連立が w-z の行で消し、z138・z139 の項 (係数 4) が残る。
   ほかは 1. と同じ (w 14 本を変数上下限で置き換え、lifted MI cover)。
3. プール 13641 (ラウンド 9、`Σ_{9 本} z ≥ 1`): データの行 3739・1056 と w-z の行 8238・8144 (z137・z140)。同じ形。

意味 (事実から読めること): 2 本のデータの行の和は「対称差の w の符号付きの和 ≤ -2」(右辺 309 + (-311))。w = 0 なら満たせないので、
対称差の w のどれかは 0 でなく、`|w| ≤ 10 z` からその z は 1。これが `Σ_S z ≥ 1`。

- `intvub_20261106/pairs.py` で一致しなかった理由は調べ直していない (今回の印付けでは 2963 の z の集合と 2 本の行の w の対称差が一致する)。

### 1.5 HiGHS の mod-k の手順 (ソース `HighsModkSeparator.cpp`、事実)

- LP で等号の行 (`≤` 側か `≥` 側) を、`HighsTransformedLp::transform` で単純な上下限・変数上下限に置き換えた空間に移し、**値が 0 でない
  (feastol より大きい) 整数列の係数**と右辺を整数に倍率をかけた連立を作る (連続列が値を持つ行は使わない)。
- GF(k) の消去 (`HighsGFkSolve`) で、k = 2, 3, 5, 7 の順に「全ての列の係数が k で割り切れ、右辺が割り切れない」行の組を探す (前の k でカットが
  出れば次の k は試さない)。見つかった組の重み `(w (k-1) mod k)/k` と `w/k` の 2 通りの集約行を `generateCut` (`onlyInitialCMIRScale`) に渡す。
- mushroom では x0 (値 0.429) と小数の w だけが値を持ち、x0 は全てのデータの行に係数 ±1 で入るので、「x0 の符号が逆の 2 本 (+ 小数の w を消す w-z の行)」が
  解になる。

## 2. 試作 `ENOMOTO_MIP_MUSHAGG` (`src/mip/separation.rs` の `mush_agg_cuts`、`src/mip/cuts.rs` の `vb_cover_cut`)

- mod-k の連立は解かず、消す列ごとに逆符号の行の組を直接作る (mushroom で HiGHS が見つける組と同じ形):
  - 消す列: 整数 (幅 > 1.5)、LP 値が大域的な上下限から feastol より内側、一般整数列の変数上下限を持たない。LP で等号の元の行に逆符号で出る
    数の多い順に `ENOMOTO_T_MIP_MUSHAGG_COLS` (既定 4) 本。
  - 行の組: 係数が正の行・負の行それぞれ `ENOMOTO_T_MIP_MUSHAGG_ROWS` (既定 200) 本までの組のうち、足した行の非零の概算 (共通の列を引く) が
    小さい順に `ENOMOTO_T_MIP_MUSHAGG_PAIRS` (既定 3000) 組。集約は `row_p/|a_pj| + row_q/|a_qj|` (列 j は消える)。
  - 組ごとに `vb_cover_cut` (`cover`、既定の試作) と、一般整数列の変数上下限の置き換えを強制した `generate_cuts` (`gen`、モードは
    `ENOMOTO_MIP_MUSHAGG_IV`、既定 2) を作り、組ごとに最良の 1 本を候補にする (`keep_best`)。根だけ (ノードの分離・サブ MIP では使わない)。
  - 一般整数列の変数上下限の表 (`VarBounds::add_int_vbs`、試作 `ENOMOTO_MIP_INTVUB` のもの) を試作のときも作る。置き換えは `with_intvub_mode`
    の中だけ (CMIR など既存の分離には効かない)。
- `vb_cover_cut(base ≤ rhs)`: 各項に「縛る条件 (リテラル)」を選ぶ。一般整数列 w は係数が正なら VLB `w ≥ d z + e` (z = 0 で w ≥ e)、負なら VUB
  (z = 0 で w ≤ e)、0-1 列 x は係数が負ならリテラル x、正なら 1 - x。全部のリテラルが 0 のときの最小の活動量 (縛った値 + ほかは大域的な上下限)
  が右辺を超えれば `Σ リテラル ≥ 1` が全ての整数解で成り立つ。上がりの小さいリテラルから外して短くする。同じ列が x と 1 - x の両方で出たら作らない。
  LP 解で違反するものだけ。HiGHS の lifted mixed-integer cover がこの模型で作るものと同じ形 (持ち上げはしない)。
