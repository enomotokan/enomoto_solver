## 文献と SCIP の実装

- Turner・Berthold・Besançon・Koch (2023)「Branching via Cutting Plane Selection: Improving Hybrid Branching」(arXiv 2306.06050)。
  本文はこの環境から読めていない (未確認)。要旨: 列 x_j での分枝の split は、x_j が基底の tableau 行から作る GMI カットの split と同じ。
  GMI カットの質の履歴を hybrid branching の点数に足すと、影響を受けた MIPLIB 2017 の問題で時間 −4%・ノード −8%。
- SCIP の実装 (GitHub の scipopt/scip master の `sepa_gomory.c`・`branch_relpscost.c` を読んだ、事実):
  - `sepa_gomory.c`: 1 回の分離で tableau 行ごとに作ったカットの効き目を持ち、カットを作った行 (`colindsproducedcut >= 0`) の最大で割った
    値を、効き目が十分な (`SCIPisEfficacious`) 行の基底の列に `SCIPsetVarLastGMIScore`・`SCIPincVarGMISumScore` で記録する
    (カットが採られたかに関わらない)。
  - `branch_relpscost.c` の `calcScore`: `dyn * (conflict + conflength + inference + cutoff + gmiavgeffweight * 平均 + gmilasteffweight * 最後) + pscost / dyn`。
    既定の重みは `gmiavgeffweight` = 0、`gmilasteffweight` = 1e-5 (推論・打ち切りは 1e-4)。点数は強分枝の前の候補の並べと、
    強分枝の後の選択の両方に使う。

## 実装 (`src/mip/brcut.rs`、既存のファイルの差分は小さい)

- 状態はプロセスで 1 つ (`RwLock`): 列ごとの (正規化した効き目の和, 回数, 最後の値)。外側の求解の始め (`solver::solve`、サブ MIP 以外) で空にする。
  根の分離・木の各スレッドのノードの分離・分枝で共有する (再スタートの前処理は列の番号を保つので、履歴を引き継ぐ)。
- `separation.rs` の tableau 行の分離 (逐次・並列の両方の経路): 行ごとに、その行から作った候補 (`generate_cuts` の CMIR/GMI 形、
  正負の 2 向き、`keep_best` の後。選択で採られたかに関わらない) の効き目の最大を、行の基底の列と一緒に集め、分離の 1 回の終わりに
  `brcut::record` で記録する。正規化はその回の行の最大で割る。既定 (SCIP と同じ) では効き目 0 の行は記録しない (`z` で 0 として記録)。
  ENOMOTO の tableau 行のカットは GMI に限らない (集約行からの CMIR・flow cover) が、split は同じ基底の列なので同じに扱う。
- `pseudocost.rs` の `hybrid` (擬似費用・推論・打ち切りの点数): `brcut` の旗 (外側の求解でだけ立てる) があれば、
  `dyn * (... + WAVG * 平均 + WLAST * 最後の値)` を足す。この点数は強分枝の前の候補の並べ (`select_branch_inner` の `score_of`) と、
  強分枝の実測値による点数 (`hybrid_score_with_gains`) の両方に入る。
- 診断: `ENOMOTO_MIP_BRCUT_LOG=1` で、記録の回数が 2 の冪のときに `BRCUT rounds ... rows ... cols ...` を stderr に出す。
  roll3000 では 256 回 (根と木のノード)・1 万行・532 列を記録した。
