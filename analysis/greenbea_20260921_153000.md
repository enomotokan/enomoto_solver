# greenbea M側巻き戻しフリップ(`m_enter_via_flip`)のタイブレーク改変 プロトタイプ検証(自己改善ループ 反復#11, runtime 段) -- 結論: **本反復では見送り推奨**。同スコア内の優先順位変更だけで届くのは M 側巻き戻し 10,205 回のうち最大 2,098 回(20.6%)で、実装した 4 変種はすべて greenbea の経路を壊し(168,620 反復のバイアウト、または特異基底)BIG_M 誤答(-72465273.017, 相対誤差 1.2e-3)に落ちる。他 13 問題では exact 同点が存在せず(タイクラスは常に 1 = 自分自身)、経路・反復数・目的値がビット同一の no-op

対象: NETLIB `greenbea`(2392 行 x 5405 列, 30,877 非零)。HiGHS 1.x(`highspy`)、4 コア。
基点: `main` = e5f8188。前回分析: `analysis/greenbea_20260921_140700.md`(反復#9、主因 = M 側スラッシングの特定)、`analysis/greenbea_20260921_150000.md`(反復#10、再分解単価)。
全数値はこのセッションでこのコンテナ上で実測。worktree を 2 本(`base` = e5f8188 そのまま、`proto` = e5f8188 + 診断 + タイブレーク変種、いずれも `CARGO_TARGET_DIR` を分離)使い、`PYTHONPATH=<worktree>/python` で `_core` を切り替え、各実行で `_core.__file__` を stderr に出して取り違えがないことを確認した(§8)。**リポジトリ本体のソースは変更していない**(本ファイルの追加のみ)。推定で埋めた箇所はそう明記する。

## 0. 結論(要約)

1. **`m_enter_via_flip`(BFRT が列を M 側へ戻すフリップ)の発生箇所**は `src/simplex/extended_dual.rs:2836-2852` のフリップ確定ループ(`for cand in &sorted[..best_idx]`)で、フリップされる列 = 昇順 `(ratio, j)` に並べた候補の `best_idx` 未満の接頭辞。`best_idx` は BFRT pass 1(`:2647-2665`、累積容量 `cum` が `w_r` に到達する `k_star`)と Harris pass 2(`:2738-2752`、`k_star` から後方 1e-7 幅の窓で最大 |alpha|)で決まる。**M 側へ戻すフリップは `w_r.slope != 0`(退出行の実行不能量が M スケール)の反復でしか起きない**(`bfrt_reached`, `:759-768`: `w_r.slope == 0` なら M 幅の候補で必ず walk が止まり、その候補は進入列になるかフリップ対象外)。実測: `iters_wr_slope=18,527`(27,654 反復の 67%)、うち M 側戻しが起きた反復は 1,433(5.2%)で 1 反復平均 7.1 本を戻す。
2. **タイブレークで触れる範囲は小さい**: M 側戻し 10,205 回のうち、ratio が**厳密に同点**で「M 側へ戻さない未フリップ候補」が存在するのは 2,098 回(20.6%、うち M 側から降ろす候補が同点にあるのは 1,571 回)。Harris 幅(1e-7)まで広げても 2,125 回(20.8%)。残り 79% は ratio が真に異なる(より小さい)候補として先にフリップされているので、優先順位づけでは動かない。同点は全部 `ratio == 0`(双対退化: `hat_c = max(sigma*d_j, 0) = 0`)で、タイクラスの平均サイズは 84 本(`tie_class_sum=858,467 / 10,205`)。
3. **実装した 4 変種(§3)はすべて greenbea で正答性を失う**。変種1(`(ratio, lands_on_M, j)` 順)・変種2(同、`w_r.slope != 0` の反復のみ)は 168,620 反復 = `max_iters` まで走って(`bland_mode=true`, `infeas_check` 再分解 23,649 / 14,774 回)BIG_M 古典経路に落ち **目的値 -72465273.0169(HiGHS -72555248.1298、相対誤差 1.2e-3)**、変種3・4(M 側から降ろす < 有限幅 < M 側へ戻す の 3 段)は 4.4 s で特異基底 → BIG_M → 同じ誤答。変種1では `exact_alt_any=0`(設計通り同点の巻き戻しは消えた)にもかかわらず `m_enter_via_flip` は 19,350 に**増え**、M 側の解消は進んだのに(`remaining_m_side=7`)実行不能行が消えない。
4. **他 13 問題では変種1は完全な no-op**(greenbeb / pilot4 / pilot87 / pilotnov / pilot.ja / pilot / 25fv47 / degen3 / fit1p / cycle / d2q06c / perold / maros / stair: 反復数・`m_enter_via_flip`・目的値がビット同一、§5)。診断で確認した 5 問題(greenbeb, degen3, d2q06c, fit1p, cycle)は `tie_class_sum == m_flips`(全 M 側戻しのタイクラスが自分自身のみ)、`m_flip_ratio0 = 0`、`exact_alt_any = 0` — **exact 同点の M 側戻しは greenbea にしか存在しない**。したがって「同点内の優先順位変更」は他問題に影響を与えない代わりに greenbea 以外に利益もなく、greenbea では経路を壊す。**見送り推奨**。
5. 副産物として M 側巻き戻しの機序が数値で裏付いた(§2): (a) M 側戻しが起きた反復では実行不能行プールが平均 **+4.56 行**増え(それ以外の反復は -0.29 行)、`pool delta ≈ 0.19 + 0.61 x (M側戻し本数)`。プール最大増 +410 の反復 6650 は **`w_r.slope = 1.67e-7`(snap 閾値 1e-7 をわずかに超えた雑音 slope)**を M スケールの実行不能とみなし、ratio ~1.1e15-1.6e15(|alpha| ~1e-15 級)の M フラグ列 22 本を M 側へフリップしたもの。反復 6696 は `w_r.slope=33.2` を埋めるために ratio=0 同点クラス(598 L / 8 X / 215 f)から 756 本を一度にフリップし、うち 547 本が M 側戻し。(b) M 側戻しの 92%(9,407 / 10,205)は iter 6,000-12,000 に集中し、前回分析のプール跳ね上がり(286 → 975)と一致。(c) コードの前提「M フラグ列は BFRT フリップで M 側に戻らない(`prop:no-return`)」(`extended_dual.rs:1970-1975` のコメント)は `w_r.slope != 0` の反復では成り立たない — 実装は制限なしの `delta_of`(全一側無限列を M 追跡)なので、この命題の前提(S 制限)を満たしていない。
6. 3 分類は前回と同じ **(b) 反復数**が主因(本ソルバ 27,654 vs HiGHS 2,524、11x; 1 反復 360 us vs ≤ 88 us が副因)。改善候補は §6: タイブレークでは届かないので、(1) `w_r.slope` の雑音判定(比較時許容)、(2) ratio=0 同点クラスに対する M 幅フリップの扱い(HiGHS 型双対フェーズ1 or 幅制限)、(3) BIG_M フォールバックの安全策、の順。いずれも 93 問題全数検証が必須。

## 3. プロトタイプ(`proto` worktree、`ENOMOTO_BFRT_M_TIEBREAK=<0..4>` でゲート、0 = baseline とビット同一)

### 3.1 差分の要点(`src/simplex/extended_dual.rs`)

```rust
// struct Cand (L1411): フィールド追加
struct Cand { j: usize, hat_alpha: f64, ratio: f64, m_land: u8 }

// impl Ord for Cand (L1434-1438): ratio と j の「間」にだけ入れる = 厳密同点の順序のみ変わる
self.ratio.total_cmp(&other.ratio)
    .then_with(|| self.m_land.cmp(&other.m_land))
    .then_with(|| self.j.cmp(&other.j))

// 主ループ前(L2196 付近): 判定クロージャ
let lands_on_m = |j, nb_status| j < n_orig && delta[j].is_flagged() && match nb_status[j] {
    Some(NbStatus::Lower) => delta[j].has_upper(),   // 今 Lower(有限側) → Upper(M 側)に着地
    Some(NbStatus::Upper) => delta[j].has_lower(),
    None => false };
let on_m_now = |j, nb_status| ...;  // 今 M 側にいる(フリップで降りる)

// 候補生成(L2486): キー付け
let m_land = match bfrt_m_tiebreak {
    1 | 2 if bfrt_m_tiebreak == 1 || w_r.slope != 0.0 => if lands_on_m(j, &nb_status) { 1 } else { 0 },
    3 | 4 if bfrt_m_tiebreak == 3 || w_r.slope != 0.0 =>
        if lands_on_m(j, &nb_status) { 2 } else if on_m_now(j, &nb_status) { 0 } else { 1 },
    _ => 0 };
candidates.push(Cand { j, hat_alpha, ratio: hat_c / hat_alpha.abs(), m_land });
// polish 側(L3900)は m_land: 0 固定(ソートは独自の sort_by なので無関係)
```

`bland_mode` の `candidates.sort()` も同じ `Ord` を使うので両経路で一貫。候補の除外・新しい閾値・禁止ルールは一切なく、`ratio` が厳密同点のときの順序だけを変える(依頼の「タイブレークの変更のみ」の条件を満たす)。診断コード(`ENOMOTO_DEBUG_M_TIES`、`prof_phases::MT_*` 13 本、`full_sorted` の全候補ソート)は計測専用で、キー付けとは独立。差分全体は 152 行(うちタイブレーク本体は約 25 行)。

### 3.3 変種1で不一致になった機序(推定を含む)

`ENOMOTO_DEBUG_M_TIES` の数値だけから確定できるのは「同点の巻き戻しは 0 になったが、巻き戻し総数は減っていない」ことまで。§2.3 の iter 6663 型(同点クラス内に M 側から降ろせる候補がない)では順序を変えても L でしか容量が埋まらず、変えたのは「どの L を戻すか」だけになる。どの L を戻すかが変われば `x_B` の M 係数分布が変わり、以後の `w_r.slope`・DSE 重み・LU の経路がすべて変わる。この問題では基底が悪条件(反復#9 §1.3: FT 更新 5 反復で残差 1e-4 超え、再分解 241 回)なので、異なるピボット系列が特異基底(変種3・4)や `infeas_check` ループ(変種1・2)に入りやすい。「タイブレークがサイクリングを引き起こした」というより「greenbea では経路をどう変えても正答経路が 1 本しかない」に近い(反復#9 §4 の感度スイープと整合)。

## 6. 改善候補(優先順、効果見積もりとリスク)

タイブレーク(同点内の優先順位)では上限 20.6% x 主ループ 93% で理論上限でも 19%、実際には経路を壊す。M 側戻しを本当に減らすには「同点でない候補」に踏み込む必要があり、それは依頼の範囲(タイブレークのみ)外なので以下は提示のみ。

1. **`w_r.slope` の雑音判定を比較時許容に**(効果: 反復 6650 型のプール +410 を止める。上限は小さいが確実): `row_deviation`(`:1096-1130`)/ `bfrt_reached`(`:759-768`)で |slope| < 1e-7 級を slope=0 として扱う。snap は格納値 `x_b_slope` を書き換える(`:651-668`)が、`w_r` は `hat_l - x_bi` の減算で作られ、`hat_l.slope`(0 または ±1)と `x_b_slope`(snap 済み)の差に丸め誤差が乗るとすり抜ける。反復#9 §6-4 と同じ方向。リスク: 中(経路が変わる、93 問題必須)。
2. **ratio=0 同点クラスに対する M 幅フリップの扱い**(効果: 6k-12k 区間の 9,407 回の巻き戻しが対象、上限 = 反復数の大半): 選択肢は (a) HiGHS 型双対フェーズ1(人工上下限 ±1 の箱で `crash` 後の双対不能量を先に消し、M 側列を M 追跡でなく通常反復で扱う; `docs/highs_dual_simplex.tex` L130-148)、(b) `w_r.slope > 0` の反復で M 幅フリップ 1 本あたりの容量を「M 側から降ろす」候補に限定し、「M 側へ戻す」候補は進入列としてのみ許す(= 前回候補 2 の後半。候補から外すのではなく `k_star` で止める)。(b) は本反復で禁止したい「候補除外」に近いが、`w_r.slope == 0` の反復で既に起きている挙動(M 幅候補で walk が止まる)を `w_r.slope > 0` にも広げる形なので、退化・infeasible 誘発の性質は既存経路と同質。効果見積もり: 上限 70-85%(反復#9 と同じ)。リスク: 高(拡張双対コア、93 問題の経路が変わる)。
3. **BIG_M フォールバックの安全策**(正答性、前回候補 1 と同じ、`src/simplex.rs:3042-3070`): 本反復の 4 変種すべてと baseline の `pilot` がこの経路を踏んでいる。変種1-4 は誤答、`pilot` は正答なので、「BIG_M クランプが最終解に残っているか」で `optimal` を返すか判定する必要がある。リスク: 低。
4. 1 反復の定数(dse_update 14.6%、refactor 22.7%、反復#10 で -2.8% 実装済み)は本反復の対象外。

## 7. 想定との食い違い(そのまま報告)

- 依頼文の前提「M 側へ戻すフリップと、戻さない同等/より良いフリップが両方候補にある場合」は greenbea でも M 側戻しの 20.6% にしか当てはまらず、他 13 問題では 0 件。「同等」を厳密同点でなく Harris 幅(1e-7)にしても 20.8%。
- 「タイブレークの変更は低リスク」という期待に反し、greenbea では同点順序だけの変更で正答経路を失った(4 変種すべて)。他問題で無害なのは「変更が効く同点が存在しない」からで、安全性の証拠ではない。
- 反復#9 の `m_enter_via_flip` 20 倍増(511 → 10,205)の内訳は「同点で誤って戻している」ではなく「`w_r.slope` が大きい(最大 9.8e3)反復で slope 容量を埋めるために ratio が真に小さい/ゼロの M フラグ列を大量に戻している」。前者なら優先順位で直るが、後者は容量の埋め方(候補の幅の定義)の問題。
- コード内の前提 `prop:no-return`(`:1970-1975`)は実測と矛盾している(M 側戻し 10,205 回)。命題は S 制限版の設計に対するもので、現行の非制限 `delta_of` では成り立たない。コメントの修正が要る(本反復では触っていない)。
