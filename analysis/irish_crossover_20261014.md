# irish-electricity (Mittelmann) の内点法 + クロスオーバーの破綻 (2026-10-14)

`root_solver="ipm_crossover"`、4 コア / 15 GB、develop `8e95f64`。`ENOMOTO_DEBUG_CROSSOVER=1 ENOMOTO_DEBUG_EXT_ITERS=1
ENOMOTO_DEBUG_PROGRESS=1` と、今回足した `ENOMOTO_DEBUG_PRIMAL_TRACE=1` (主単体法の引き継ぎの毎反復の比率テスト) で調べた。

2546254.5633、相対 9.5e-9 ずれ) になるので、閾値は緩めない。

## 2. 破綻: 主単体法の引き継ぎが発散する

修復した基底を仕上げの開始点にすると (下の対策 A)、双対単体法は 0 反復 (主実行可能) で、真の費用での双対実行不能 4,942 列を
主単体法の引き継ぎ (`run_phase2_incremental`) が直す。ここで目的値が発散した:

```
PROGRESS primal iter=1000 obj=2.5392793788e6 dual_infeas=4569
PROGRESS primal iter=2000 obj=1.3771980669e21 dual_infeas=10322
DEBUG_EXT: primal refactorization singular; replaced 1 basis columns by slacks   (以後 7 回)
PROGRESS primal iter=3000 obj=3.1694636425e34 ...   (以後 1 反復 70 ms で止まらない)
```

最初の崩れ (反復 1809):

```
PTRACE it=1808 theta=9.820e-9 alpha1=5.894e-7 piv=9.980e-1 viol_after=7.706e-7 delta=5.88e-7
PTRACE it=1809 theta=9.488e-3 alpha1=-1.671e-1 piv=1.033e-6 amax=3.571e2 viol_after=2.793e-2
```

- ある基底変数が EXPAND の緩め幅 δ (5.9e-7) を超えて上下限の外 (7.7e-7) にあった (差分更新した x_B の誤差)。
- その行の `relaxed = (境界 ± δ − x) / rate` が負になり、パス 1 の `alpha1` が負 (−0.167) になった。
- パス 2 の候補 (`exact <= alpha1`) はその行だけで、ピボット 1.03e-6 (max|alpha| = 357 の 3e-9 倍。相対の下限 1e-5 を
  下回るが、ほかに候補が無いので選ばれる)。
- ステップは最小ステップ `EXPAND_TAU / |pivot|` = 9.5e-3 になり、他の基底変数を 2.8e-2 外し、基底は特異に近くなった。
  以後、外れた変数がさらに外れ、再分解の特異 → スラックへの差し替えを繰り返して発散する。

ソースの注記 (`ENOMOTO_T_PRIMAL_REL_PIVOT`、`try_refactorize_repair`) にあるとおり、irish-electricity の仕上げの引き継ぎで
目的値が 5e25 に発散したことが以前もあり、同じ型とみられる (相対ピボットの下限はほかに候補があるときしか効かない)。

## 3. 対策

**B. 比率テストで、すでに外れている基底変数は今の値を境界とみなす** (`ENOMOTO_T_PRIMAL_SHIFT_INFEAS`、既定 1、
`src/simplex.rs` `run_phase2_incremental`): `exact < 0` の行は `exact = 0`、`relaxed = δ / |rate|` にする。`alpha1` は負に
ならず、外れた行は小さなピボットでもステップを止めず (その変数はさらに高々 δ しか外れない)、通常の行が出る行に選ばれる。

**A. 修復した基底を仕上げの開始点にする** (`ENOMOTO_T_XO_REPAIR_REUSE`、既定 1、`src/simplex/crossover.rs`): ギャップで
受理しなかった修復の最終基底と非基底の位置を返し、仕上げはその基底から始める。非基底の位置の希望 ±2 を新設し
(`warm_start_basis`)、被約費用の符号によらず希望の側に置く (費用をずらす) ので、主実行可能のまま始まる。

| 版 | 合計 (秒) | 仕上げ | 目的値 |
|---|---|---|---|
| 基準 | 55.9 / 56.0 (1 スレッド) | 二段解法 10,552 + 主 1,261 | 2546254.56333589 |
| A のみ | 発散 (900 秒で打ち切り) | 主 3,000 反復以降 目的値 3e34 | ― |
| A + B | 48.6 / 48.9 (1 スレッド) | 主 7,478 反復 (11 秒) | 2546254.5633103745 (HiGHS と相対 1e-11) |
| 修復なし (`ENOMOTO_T_XO_REPAIR=0`) | 41.4 | 二段解法 10,552 + 主 1,261 | 2546254.56333589 |

## 4. 残る問題 (根本はクロスオーバーの基底の質)

- 内点法の解は強く退化していて (上下限の間 45,868 < m = 72,029)、双対の押し出しは `|D| < 0.7 m` で省かれ、残り 26,161 行を
  スラックで埋める。この基底は双対実行不能 5,558 で、どの経路でも 7,000〜12,000 ピボットの仕上げが要る (HiGHS は 13)。
  双対の押し出しは 1 歩で階数を 1 しか増やせないので、2.6 万歩はこの実装では重い (cre-b で 1 歩 2 ms)。
- 修復は irish では割に合わない (修復 15.6 秒 + 仕上げ 11 秒 > 修復なしの仕上げ 20 秒)。修復の要否 (主実行不能の数が少なくても、
  ずらす費用の列が多い: 5,670) の判定は別途の比較が要る。
- `run_phase` (非差分版の主単体法、第 2 段階) の比率テストにも同じ構造 (外れた基底変数で `alpha1` が負になりうる) がある。
  既定の引き継ぎは差分版なので今回は触っていない。
