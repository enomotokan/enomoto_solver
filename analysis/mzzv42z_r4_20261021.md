**このマシンは前回 (r3) より遅い**: HiGHS の前処理が 17〜18 秒 → 24 秒、HiGHS は 2 回とも 60 秒で終わらない (前回は 51 秒前後で最適)。

## 結論

1. **残りの差は主側・時間の使い方・双対側の 3 つ。60 秒の暫定解の悪い回を決めているのは主側 (根の RENS の崩れ)** (事実):
   - 既定 4 回: -20380 / -19800 / -20290 / -18472 (最適 -20540)、**下界は 4 回とも -inf** と報告される。
   - 4 回中 2 回で根の RENS (暫定解が FJ の質の悪い解だけのときのダイビング式、目標の固定率 0.8) が 2 段目の LP の実行不能で 1 段戻り、
     固定率 0.37 (6800 列が自由) のサブ MIP が 18 秒 0 ノードのまま時間切れ。その回の根の後の暫定解は locks (-13096・-13204) からの
     RINS の -19334・-18472。崩れない回 (固定率 0.80) は 8〜9 秒で -20280・-20290。
   - 崩れるかどうかは根のカットの強さでは決まらない (根 -20914 で崩れる回 (E1)、-20920 で崩れない回 (K3))。根のカットを延ばす
     (`ENOMOTO_MIP_CUT_EXTEND`) と根は上がるが 2 回とも崩れ、-15628・-15128 と悪くなった。
2. **時間の使い方: 再スタートの後が空回りし、木では従 3 本が 1 ノードも処理しない** (事実):
   - 4 回中 3 回は根の後に再スタート (新たに固定 3〜330 列。def2 は 3 列で再スタート)。前の暫定解は打ち切り値の固定で外れて捨てられ、
     暫定解なしとして Feasibility Pump・カット前の LP の RENS に 5〜16 秒、カットを行にした根の LP の解き直しに 6.5〜19.3 秒
     (13760〜28717 反復) を使い、60 秒までに木に入らないか 0〜2 ノード。暫定解のないまま終わるので下界は -inf と報告される。
   - 4 スレッドの木では、従が写しから LP を作って根の LP (10800 行) を**基底なしで最初から**解く。木に入ってから 20 秒、従 3 本は
     0 ノードのまま根の LP の途中で時間切れになり `finish(TimeLimit, -inf)` を返し、主の下界 (= 報告する下界) が -inf になる
     (`ENOMOTO_MIP_TREE_DIAG` で確認: `worker ended: status TimeLimit objective None bound -inf nodes 0` が 3 本)。
     **再スタートしない回でも下界が -inf になるのはこのため** (def4・EN2・E1・E2・TD1)。
3. **双対側: 根の下界は HiGHS より 60〜140 弱い** (事実): HiGHS は前処理 (24 秒) で 6139 行 × 6980 列に減らし、根の LP が -21414
   (ENOMOTO は 10460 行 × 10693 列で -21534)。カット後 -20738、2 回の再スタートの後 -20672、60 秒で下界 -20670・暫定解 -20540
   (根のカットの直後のサブ MIP (`L`) で見つける、32 秒)。ENOMOTO は背景のカットの後 -20736〜-20826、再スタート後の根 -20727〜-20855。
   この差の中身 (HiGHS の前処理のどの縮小が効くか) は調べていない (推測: 前処理の差が大きい)。
4. **試作 F (= GR + TB)**: mzzv42z の 60 秒の暫定解は 5 回で -20430〜-20520 (-20500 / -20430 / -20470 / -20520 / -20500)、
   下界は 5 回とも有限 (-20719〜-20778)。崩れた RENS の回も背景のカットの後の RINS で -20400 台に戻り、再スタート後は参照解との
   RINS で -20470〜-20520 が出て、再スタート後 11〜14 秒で木に入る。**それでも 60 秒で最適までは閉じない** (-20540 に届く回はない。
   下界との差 180〜250 が残る。このマシンでは HiGHS も 60 秒で閉じない)。
5. **副作用** (一般整数のある 10 問を F で 2 回ずつ、TB を一般整数のない 7 問で 2 回ずつ): 誤った最適値 0。GR は qnet1 の 2 回目以降の
   再スタートで参照解を失って倍の時間 (10.5 秒) になっていたのを直した (修正後 3.3〜5.9 秒、既定 5.1〜5.4 秒)。mik-250 は F で
   8.4 / 9.0 秒 (既定 7.4 / 7.9)。TB は neos-911970 が 45 / 54 → 23 / 30 秒、beasleyC3 は 4 回ずつで既定 27〜37 秒、TB 29〜51 秒と時間切れ 1 回
   (揺れの大きい問題)、10teams・misc07 は 1〜2 秒遅い。
6. **既定にする候補か**: TB の「従が根の LP で時間切れなら下界を +inf」の部分は報告の誤りの修正 (従はまだノードを持たない) なので
   切り出して既定にしてよい候補。TB の基底の受け渡しと GR は、mzzv42z を良くするが 60 秒で解けるところまでは届かず、副作用の計測が
   2 回ずつしかないので、40 問・16 問の対の計測 (親) で決めるのがよい。GR の `=readd` は mik-250 の根を弱める (-53829 → -53948) ので候補にしない。

## 3. 再スタートの空回り (事実)

- 初回の再スタートは「新たに固定された整数列が 1 本でもあれば」(HiGHS と同じ規則、`ENOMOTO_T_MIP_RESTART_FIRST_FAC` 0)。
  HiGHS は前処理後の問題の 14.6% が固定されて再スタート、ENOMOTO の def2 は 3 列 (0.03%) で再スタートして根の LP の解き直しに 8.6 秒使う。
- 前の暫定解は打ち切り値 (暫定解より刻み 1 つ良いこと) で固定された列で外れるので、再スタート後の問題では必ず実行不能になり捨てられる
  (`the start solution is not feasible in the presolved problem; dropped`)。再スタート後は暫定解なしとして Feasibility Pump (5〜16 秒) と
  カット前の LP の RENS (実行不能) を回す。
- 再スタート後の根の LP が重いのは、効いているカット (500 本余り、平均 50〜90 非零) を問題の行にして前処理にかけ、基底なしで解くため
  (13760〜28717 反復)。カットを行にせず根の LP の前にカットの行として足す (`ENOMOTO_MIP_RESTART_CUTS_READD`) と 7066〜8255 反復・
  1.8〜2.6 秒。ただしその場合、再スタート後の根の LP は再スタート前より弱い (-20743 → -20945 など。代入で消えた列を含むカット
  46〜78 本を捨てる。前処理で値が決まっただけの列を右辺に移して残す試作 `RESTART_CUTS_SUBST` も書いたが、残せたのは 13〜17 本で根の
  LP は変わらなかったので外した)。根のカットのループ 3 秒ほどで -20745〜-20872 まで戻る。

## 4. 試作 GR: `ENOMOTO_MIP_GR_RESTART=1` (既定では使わない)

内容 (`src/mip/mod.rs` の `gr_restart_for`・`gr_restart_readd_for`・`restart_ref_for`、`src/mip/solver.rs` の 5 か所): 一般整数のある問題
(`implbd_genint_for` が真。一般整数が固定されていない列の 1% 以上、既定の P3 と同じ条件) だけで、
1. `ENOMOTO_MIP_RESTART_REF` (r3 の試作): 再スタート前の暫定解を参照解に残し、再スタート後の根の RINS の相手にする。暫定解なし扱いに
   しない (Pump・カット前の LP の RENS を回さない)。打ち切り値に届かない解を暫定解にしない。暫定解がなくても下界を報告する。
   **この調査で 1 つ直した**: 再スタート後の求解が暫定解なしでさらに再スタートするとき、参照解を次に渡す (`maybe_restart`。
   渡さないと qnet1 (3〜4 回再スタート) の 3 回目の求解が暫定解なしで局所探索を 2.7〜2.9 秒ずつ回し、5 秒 → 10.5 秒になっていた)。
2. `ENOMOTO_MIP_BG_CUTS_REHEUR=rins`: 背景のカットで根の LP を置き換えた後、その LP 解で丸めと RINS をもう一度回す。
3. (`=readd` のときだけ) `ENOMOTO_MIP_RESTART_CUTS_READD`: 効いているカットを問題の行にせず、再スタート後の根の LP の前にカットの行として足す。

## 6. 試作 TB: `ENOMOTO_MIP_TREE_ROOT_BASIS=1` (既定では使わない)

内容 (`src/mip/solver.rs`): (1) 木の写し (`TreeSnapshot`) に写しを作ったときの主の LP の基底 (`root_basis`) を持たせ、木を分け合う従は
根の LP をその基底から解き始める。(2) 木を分け合う従が根の LP の途中で時間切れになったら下界を +inf で返す (従はまだ共有の待ち行列から
ノードを取っていないので、主の下界に混ぜない)。

- mzzv42z: 既定 (TD1) は木に入ってから 21 秒で従 3 本が 0 ノード・下界 -inf。F では従が 6〜9 ノードを処理し (`worker nodes 6`〜`9`)、
  下界は 5 回とも有限。ノード数は GR=readd の 18〜44 に対し F は 1〜22 で、ノードが増えたとは言えない (再スタート後の木に入る時刻が遅い)。
- (2) は報告の直し。(1) を使わなくても、(2) だけで「再スタートしない回の下界 -inf」は直るはず (未計測。(2) だけを分ける環境変数は作っていない)。

## 7. うまくいかなかった試み

- `ENOMOTO_MIP_CUT_EXTEND=1` (develop にある): 根のカットが 16〜20 秒まで延び、根は -20761〜-20919 になるが、RENS の崩れは防げず
  (E1・E2 は崩れて -15628・-15128)、ほかのヒューリスティクスの時間が減る。
- `ENOMOTO_MIP_NO_RESTART=1` (+ `CUT_EXTEND`): EN1・EN2 は -19010・-20340。
- `RESTART_CUTS_SUBST` (書いて外した): 4 章の最後。

`cargo test --release --lib`: 308 件通過 (18 件は無視の印) (pyo3 のため `RUSTFLAGS="-L /usr/lib/x86_64-linux-gnu -l python3.13"`)。

## 8. 確かでない点

- RENS の 2 段目の LP がなぜ実行不能になるか (根の LP 解のどの列の組が近傍を壊すか) は見ていない。HiGHS の RENS (`L`、カットの直後) は
  同じ問題で 1 回で -20540 を出す。HiGHS は強い前処理 (列が 35% 少ない) の後の問題で RENS をするので、近傍の形が違う。
- 1 ラウンド目の LP の反復が 1500 か 4400 かに分かれる理由 (同じ根の LP 値・同じ候補数 1439 でも分かれる) は見ていない。
- 60 秒で最適まで閉じるには、HiGHS 並みの根の下界 (-20670 前後) と -20540 を 30 秒台に出すことの両方が要る。前者は前処理 (HiGHS は
  列を 4737 本減らす、ENOMOTO は 1024 本) の差が大きいと推測しているが、どの縮小が効いているかは調べていない。
- RESTART_REF の下界の報告は「前処理は目的値を定数だけずらす」ことを前提にしている (r3 から)。2 回目以降の再スタートで参照解を
  渡すようにしたので、参照解 (前の前の問題の暫定解) から求めたずれを使う回が増える。
- 副作用は 2 回ずつ (beasleyC3 は 4 回)。
