# roll3000 を HiGHS は解けて ENOMOTO は解けない理由の調査 (2026-10-19)

対象: MIPLIB 2017 の roll3000 (2295 行、1166 列、整数 738 (0-1 は 246、残りは [0, 2] の整数)、目的関数は自由な連続変数 1 本、
最適値 12890)。16 スレッドの計測で HiGHS は最適、ENOMOTO は時間切れ。

- 環境: Linux x86_64、**4 コア**。develop の最新 (7e9f192) を `cargo build --release --lib`、highspy 1.15.1
- このコンテナではスレッド数は使える CPU の数 (4) で頭打ちになる (`mip::max_threads`) ので、16 スレッドそのものは再現できない。
  ただし以下のとおり差は 4 スレッドでも同じ形で出ており、スレッド数の問題ではない
- HiGHS の MIP はこの版では木を並列に探索しない (ログに「Thread count 4 (of 4 threads). Using 1 max workers. Parallel search off」)。
  16 スレッドでも 4 スレッドでも HiGHS の探索は逐次で、時間もほぼ同じになる

## 結果 (4 スレッド)

| | 根の LP | 根のカット後 | 最初の解 | 結果 |
|---|---:|---:|---|---|
| HiGHS (60 秒以内) | 11097.9 | 12619.2 (5.0 秒) | 13357 (5.0 秒、根のサブ MIP「L」)、13009 (13.6 秒) | 最適 12890、50.7 秒、616 ノード |
| ENOMOTO 既定 (120 秒) | 11097.1 | 11802.6 (4.9 秒) | 13511 (11.0 秒) | 時間切れ、上界 13226、下界 12406、9301 ノード |

最新の develop (cf46224 の根のカットの上限を広げる変更を含む 778d027) でも同じ: 根のカット後 11581.8 (17 ラウンド、
3.9 秒で停滞)、120 秒で上界 13049・下界 12338・5706 ノードの時間切れ。

根の下界で閉じたギャップの割合 ((根 - 根の LP) / (最適値 - 根の LP)) は HiGHS 85%、ENOMOTO 39%。ENOMOTO の木は 120 秒で
下界を 11853 → 12406 にしか上げられず、HiGHS の根の値にも届かない。主な原因は根の下界、次に最初の解の遅さと木の効率。

## 原因 1: 根の切除平面が弱い (最大の差)

`ENOMOTO_MIP_LOG=1` の根のカットのループ:

```
cut round 0: 50 cuts (of 1752 ...), cut rows mean nnz 4, obj 11242.4
...
cut round 10: 11 cuts, obj 11722.3
cut round 11:  7 cuts, obj 11723.4
cut round 12:  8 cuts, obj 11723.9
cut round 13: 24 cuts, obj 11780.2     <- まだ上がっている
cut round 14:  5 cuts, obj 11780.8     <- ここで停滞と判定して止まる
```

- 毎ラウンド 1700〜2100 本の候補があるのに、既定の選択 (`select_cuts`) で採るのは 5〜50 本、採ったカットの平均の非零は 4〜18。
- 停滞の判定 (SCIP 型: 相対変化 1e-4 以下で分数の列が減らなければ 2 回分と数え、10 で止める) が、上がり下がりのあるこの問題では
  まだ伸びている途中で止める (ラウンド 10〜12 の小さな伸びで止まり、ラウンド 13 では 56 上がっている)。
- 根のカットの時間の上限 (`ENOMOTO_T_MIP_CUT_TIME_FRAC` = 時間上限の 0.1、60 秒なら 6 秒) も、選択を変えたときは効いてくる。

設定を変えた根の下界 (1 スレッド、ノード 1 で止める。時間で打ち切るので ±100 程度は揺れる):

| 設定 | 根のカット後 | ラウンド | 時間 |
|---|---:|---:|---:|
| 既定 | 11632〜11803 | 14〜15 | 4〜6 秒 |
| `ENOMOTO_T_MIP_ROOT_MAX_CUTS=300` | 11754 | | 5.1 秒 |
| `ENOMOTO_MIP_HIGHS_CUTMGMT=1` | 11885 | 22 | 6.3 秒 (時間の上限) |
| `ENOMOTO_MIP_CUT_PHASE2=1` | 12017 | 22 | 6.1 秒 (時間の上限) |
| `ENOMOTO_MIP_CUTSEL_HIGHS=1` | 11996 | | 6.2 秒 (時間の上限) |
| `ENOMOTO_MIP_CUTSEL_HIGHS=1 ENOMOTO_T_MIP_ROOT_MAX_CUTS=300` | 12133 | 21 | 6.2 秒 (時間の上限、まだ伸びている) |
| 上 + `ENOMOTO_T_MIP_CUT_TIME_FRAC=0.5 ENOMOTO_T_MIP_CUT_ROUNDS=200` | 12462 | 89 | 26.2 秒 |
| HiGHS (前処理あり) | 12619 | | 5.0 秒 |
| HiGHS (`presolve=off`) | 12468 | | 5.4 秒 |

- HiGHS 型の選択 (`select_cuts_highs`) なら止まらずに伸び続けるが、HiGHS が 5 秒で出す値に 26 秒かかる (1 ラウンドあたりの
  伸びが小さい)。
- HiGHS の前処理を切ると HiGHS の根は 12468 で、ENOMOTO の長く回した値 (12462) とほぼ同じ。差の約 150 は HiGHS の前処理
  (HiGHS: 1473 行・996 列、ENOMOTO: 1617 行・878 列) による。
- 分離の種類ごとの寄与 (HiGHS 型の選択、40 ラウンド): zerohalf を切る・経路集約を切る・flow cover を切る・経路集約を従来/HiGHS
  移植の片方だけにする・clique・0-1 間の implied bound・lifted cover・`ENOMOTO_MIP_TAB_HIGHS_RULES` のどれでも 40 ラウンド後の
  値は 12310〜12445 の範囲。特定の種類の分離が欠けているのではなく、選択と停滞判定、1 ラウンドの効き目の差。

## 原因 2: 最初の解が遅く悪い

- HiGHS は根のカットの途中のサブ MIP (「L」) で 5.0 秒に 13357、再スタート後の根で 13009 を出し、木に入る前の上界が最適値の 1% 以内。
- ENOMOTO の根のサブ MIP (根の被約費用・LP の面・RENS・RENS (カット前の LP)・locks・clique) は、時間切れの 1 つを除いて全て
  0〜1 ノードで実行不能。最初の解は根の係数の潜り (8.8 秒、15450) か、木に入ってから (11.0 秒、13511)。
- 上界が悪い間は被約費用による固定も効かず、木で刈れない。

## 原因 3: 木の下界の伸びが遅い

根を強めた設定 (`ENOMOTO_MIP_CUTSEL_HIGHS=1 ENOMOTO_T_MIP_ROOT_MAX_CUTS=300 ENOMOTO_T_MIP_CUT_TIME_FRAC=0.3`、4 スレッド・120 秒):

```
Root cuts: 11097.1 -> 12233.4 (5.3 秒)、再スタート後 12452.6 -> 12488.8
   14.5s      1 nodes  bound 12500.7  incumbent 13210
   61.2s   3345 nodes  bound 12557.9  incumbent 12890   <- 最適値は約 60 秒で出る
  105.1s   5849 nodes  bound 12639.5  incumbent 12890   <- 時間切れ (ギャップ 1.94%)
```

- 既定 (上界 13226、下界 12406) よりずっと良く、最適値も見つかるが、60 秒でも 120 秒でも最適性は示せない
  (`ENOMOTO_MIP_CUT_PHASE2=1` でも同様: 12899、下界 12521)。
- HiGHS は根 12622 から 616 ノード (逐次) で閉じ、LP の反復の 65% (174487 のうち 113848) が強分岐。ENOMOTO は 4 スレッドで
  5849 ノード処理しても下界は 140 しか上がらない。根の差 (残りのギャップ 390 対 268) に加え、ノードあたりの効き目
  (分岐変数の選択・強分岐の量) にも差がある。

## その他 (表示のみ)

- 4 スレッドの木の最初の数秒で、ログの best bound が 12181.9 (12.6 秒、5 ノード) → 11897.6 (14.7 秒) と下がる。全体の下界
  (`global_lower_bound`: 自分の待ち行列・処理中のノード・共有の待ち行列・各スレッドの `ThreadSlot::lb` の最小) から、
  どこかのノードが一時的に抜けている。原因はまだ確かめていない。刈り込みはノードごとの下界で行うので結果には影響しないと
  考えられるが、`global_lower_bound` は証明の段階の判定 (`solver.rs` 3853 行付近) やトリガの閾値にも使われている。

## 次にやること (案)

1. 根のカットの停滞判定と選択: 既定の選択で停滞したら HiGHS 型の選択に切り替える第 2 段階 (`ENOMOTO_MIP_CUT_PHASE2`) は
   roll3000 で 11.8k → 12.0k、`select_cuts_highs` を最初から使い上限 300 本にすると 12.1k (どちらも 6 秒の時間の上限で止まる)。
   40 問・93 問での評価が必要 (過去に `ENOMOTO_MIP_CUT_PHASE2` は misc07・neos5・10teams などで遅くなり不採用)。
2. HiGHS の前処理との差 (約 150): HiGHS の前処理後の行・列の数との違い (ENOMOTO は列が少なく行が多い) から、効いている
   簡約を特定する。
3. 根のサブ MIP がすべて 0 ノードで実行不能になる理由 (固定が強すぎるのか、正しく実行不能なのか) を、HiGHS の RENS
   (この問題で 13357 を出す) の固定と比べて確かめる。
4. 木: 強分岐の量 (HiGHS は LP 反復の 65%) と、根を強めたときの木のノード数を HiGHS と比べる。
