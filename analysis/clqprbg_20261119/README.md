# CLQPRB の `g` の 2 周目の手間 (mzzv42z の前処理の倍増の続き、2026-11-19)

親の依頼: mzzv42z の前処理の倍増 (プロービング 4.8 → 14.4 秒、analysis/presolve_par_20261119) を調べる。P2-SCIP-P の記録
(analysis/scipslow_20261119 の 2 節) では neos8 で CLQPRB の `g` (既定の形のプロービングの後に、含意の形でやり直す) の 2 周目が丸ごと余分になり、
mzzv11・mzzv42z も同じ型。`ENOMOTO_MIP_CLQPRB` = 既定 (`1dgrs`)・`1dgr`・`1dr`・`1drs` を 4 問 (neos8・mzzv42z・mzzv11・puriri) で並べ、
「1 周目で含意の形が残る問題では 2 周目を省く」のような一般の理屈の立つ直しが作れるかを見る。コードは変えていない。

- 台本 `run.py` (`pre` = 根の前で止めて前処理の秒、`full` = 600 秒で最後まで)。1 スレッド・種 1 (`TH=4` で 4 スレッド)。
- ビルド: `pre` (1 スレッド) と neos8・mzzv42z・mzzv11 の `full` は 7b3418ada。`pre` (4 スレッド、`res_pre_t4.jsonl`) と puriri の `full` は
  13e443a1a (qiu・cs2・sw2 を既定から外した後。前処理の道は同じ)。

## まとめ (結論を先に)

- **判定の 1 周目の手間 (事実)**: 既定の形のプロービング (同値探しの巡を含む) は、1 スレッドで neos8 2.2 秒・mzzv42z 5.6 秒・mzzv11 4.4 秒・
  puriri 0.9 秒、4 スレッドで 1.6・6.1・2.1・0.6 秒。含意の形が残る 3 問では、この 1 周目は ρ の計算にしか使われない。
- **3 問とも判定をしなくても (`1dr`) 解き方は同じ (事実)**: 1 スレッドの 600 秒の回でノードの数・目的値が既定と同じ (neos8 0・mzzv42z 811・
  mzzv11 1425 ノード)。全体の秒は neos8 6.3 → 4.2 秒、mzzv42z 92.8 → 90.6 秒、mzzv11 198.9 → 192.8 秒 (同じ木なので差は前処理の差と時刻の揺れ)。
- **判定の結果を変えずに 1 周目を省く形は作れない (理屈)**: ρ = (含意の形の成果) / (既定の形の成果) は両方を数えないと決まらない。順番を入れ替えて
  含意の形を先にしても、ρ ≥ 2 を確かめるには既定の形を最後まで回す必要がある (既定の形の成果が含意の形の半分以下であることは、途中で打ち切っては
  分からない)。「1 周目で含意の形が残ったら 2 周目を省く」は、同じ求解の後のプロービング (かけ直し・再スタート) では既に `CLQPRB_STICKY` で
  そうなっている。余分なのは最初の呼び出しの 1 回だけ。
- **一般の理屈の立つ直しの候補は 2 つ (推測)**:
  1. **同値探しの巡の手間の数え方を、本体のプロービングと同じにする**。既定の形の 1 周目の中の同値探しの巡 (`PROBE_CLIQUE=equiv`) は、mzzv42z で
     1 スレッド 3.4 秒・4 スレッド 5.1 秒かかり、結果は「使わない」(見つけた組が候補の 5% に届かない) で捨てられている。手間の上限は本体の上限 (20 × 非零数 + 10 万) と 0.5 秒相当
     (`ENOMOTO_T_MIP_PRESOLVE_WORK_EQUIV2` = 5e7) の小さい方だが、巡が数えるのは行の走査 (`debug_work`、含意の隣の走査を含む) だけ。本体の
     プロービングの手間 `pwork` は 行の走査 × 2.5 + 活動量の更新 (`act_work`) × 5 + 境界の変更 (`chg_count`) × 68 + 増えた含意 × 190 で数える。mzzv42z の既定の形の本体では work 74 万に対し pwork 8.5 億 (約 1000 倍) で、巡は手間の上限に届かず、
     時間の安全網 (0.5 秒 × 10 = 5 秒) か候補の終わりまで走る (4 スレッドの 5.13 秒はこの安全網)。直すと結果 (同値な組) が変わりうるので計測が要る。
  2. **2 つの形を同時に回す (2 スレッド以上)**。前処理の打ち切りは手間で数える (`ENOMOTO_MIP_PRESOLVE_WORK` が既定) ので、それぞれの形の結果は
     スレッドの数によらない。既定の形と含意の形を別のスレッドで同時に回し、終わってから今と同じ ρ の判定をすれば、結果を変えずに短い方の時間を省ける
     (4 スレッドで neos8 1.6 秒・mzzv42z 4.3 秒・mzzv11 2.1 秒・puriri 0.6 秒が上限)。1 スレッドでは得がない。`probe` は thread_local の状態
     (`PROBE_EQUIV`・`PROBE_GAIN`・`CLQPRB_*`・`PREPAR_THREADS` など) を多く使うので、写して渡す手間がある。
- 勧め: 1 を先に (理屈がはっきりしていて、1 スレッドでも効く。mzzv42z の 1 周目 5.6 秒のうち 3.4 秒)。結果が変わるので P・M で対の計測をする。
  2 は 1 の後に残る分 (本体のプロービングの秒) が大きい問題が多ければ。

## 2. 600 秒の回 (1 スレッド、種 1)

| 問題 | 既定 | 1dgr | 1dr | 1drs | ノード (4 形とも) |
|---|---|---|---|---|---|
| neos8 | 6.3 | 6.3 | 4.2 | 4.0 | 0 |
| mzzv42z | 92.8 | 91.8 | 90.6 | 94.6 | 811 |
| mzzv11 | 198.9 | 197.5 | 192.8 | 206.2 | 1425 |
| neos-3216931-puriri | 時間切れ (解 81380、下界 59460、320 ノード) | 時間切れ (解なし、下界 60550、10 ノード) | 同左 | 同左 | — |

- 3 問とも 4 形で同じ木 (ノード・目的値が同じ)。含意の形が残る問題では、1 周目は時間だけの差。mzzv42z・mzzv11 の 1drs (判定なしで同じ形) が
  既定より 2〜7 秒遅いのは、同じ木の時刻の揺れ (1 スレッドでも根のヒューリスティクスなどの時間の上限で揺れる)。
- puriri (ビルド 13e443a1a): 既定 (`g` で既定の形に戻る) だけが解 81380 を持つ。含意の形のまま進む 1dgr・1dr・1drs は 600 秒で解なし
  (gate2 の 4 スレッドの結果と同じ。`1drs` は `g` がないので ρ の判定をせず、含意の形のまま)。`g` の判定が要る理由はこの 1 問で、1 スレッドでも再現した。
