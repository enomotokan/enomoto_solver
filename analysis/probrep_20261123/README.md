### `ENOMOTO_MIP_PRBWORK` (analysis/probework_20261120、既定では使わない) の中身

- プロービングが固定・締め付け・同値な組を 1 つも得ないまま「何も見つからない間の上限」(`ENOMOTO_T_MIP_PRESOLVE_WORK_PROBE0` か時間の安全網) で
  **打ち切られた**ら印を付け、その求解の**再スタートの後**のプロービングを回さず、再スタートの問題に前の含意を渡す。後の回が何か得れば印を消す。
- 列が変わっていても省く (再スタートの後は固定が増えて列が狭まっている)。根拠は「上限で打ち切られた = 候補が多く何も見つからない問題」。
  irp・n2seq36q・nursesched-sprint02 の 3 問だけで働き、得が小さいので利用者の判断で計測せずに閉じた (同 6 節)。

## 2. 試作 `ENOMOTO_MIP_PROBREP` (src/mip/mod.rs の `probe`・`ProbRepSnap`、既定では使わない)

- プロービングが成果 0 (固定・締め付け・同値な組がどれも 0) なら、その回に渡した問題の列の状態 (列の数・目的係数・境界・整数の印) と、
  その回の含意 (`conflict_edges`)・含意による境界 (`implied_bounds`) を控える。成果があれば控えを消す。最初の求解の始めに消す。サブ MIP は対象外。
- 次のプロービングの入口で、列の状態が控えと全く同じなら回さず、控えの含意・含意による境界をそのまま入れて成果 0 として返す。
- 根拠: 列が同じで行だけが変わっている (冗長な行の削除・平行な行の併合・等式による疎化、再スタートでは加えたカットの行) なら、
  問題は前の回の問題と同じかそれを狭めたもので、前の回の含意はそのまま成り立つ。閾値は無い (判定は列の状態が同じかの真偽だけ)。
- **再スタートの後**: 再スタートの問題は前の求解の前処理の後の問題 (列はそのまま、境界は大域の境界) にカットの行を足したもの。
  新たな固定が 0 で再スタートの前処理でも列が 1 本も消えず境界も変わらなければ、列の状態が控えと同じになり、ここでも省く。
  新たな固定があれば列が変わるので回す (neos-860300・irp・mzzv42z の再スタートの後は回す)。
- **PRBWORK との関係**: 別の判定。PRBWORK は「打ち切られた」ことを根拠に列が変わっても再スタートの後を省き、PROBREP は「列が同じ」ことを根拠に
  前処理の中でも再スタートの後でも省く。両方つければどちらかが当てはまれば省く。PROBREP は列が変わった回を省かないので、neos-860300 の再スタートの後の
  固定を失わない。
- 値 `f` は確かめ用 (成果があっても控える。省く道を fuzz で通すため)。
- 1 版目 (コミット 1b0b62a73) は列の状態を列の数・境界・整数の印だけで比べていた。0-1 だけの問題では境界・整数の印が全部同じなので、
  再スタートの前処理で別の列が同じ数だけ残ると列の対応が違うのに同じに見えうる。2 版目で目的係数も比べるようにした (1 版目の計測では
  省いた回はどれも列が 1 本も消えていない回で、対応は同じ)。
- **前提が崩れる点** (`supportcase18`): 再スタートの後は行 (カット) が増えるので、既定ではプロービングの含意が 323680 → 387920 → 482890 → 570180 本と増える。
  固定・締め付けは 0 のままだが、PROBREP は前の回の含意 (323680 本) を使い回すので、増える分の含意を失う。「行だけの変化はプロービングの結果を変えない」は
  固定・締め付けについては成り立つが含意の数については成り立たない。前処理の中の行の書き直し (冗長な行の削除・疎化) では含意の数は同じだった
  (nursesched-sprint02 の 1829712 本)。
