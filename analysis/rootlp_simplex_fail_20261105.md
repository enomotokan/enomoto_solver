# 根の LP で二段解法 (単体法) が時間切れ・`Error`・遅くなる例の調査 (2026-11-05)

bench に使う環境変数: `ENOMOTO_SIMPLEX_SCALE=1` (試作、既定では使わない。基底のない求解を、行と列の尺度を調整した写しで解き、
その最適基底から元の LP を warm start する)。調べるとき用: `ENOMOTO_MIP_ROOTLP_SIMPLEX_DIAG=<prefix>` (根の LP を書き出して二段解法だけで解く)、
`ENOMOTO_SIMPLEX_PIVLOG=1`、`ENOMOTO_DEBUG_PROGRESS=1`、`ENOMOTO_PROF_PHASES_EXT=1`。

並列 2 セッションのうちの 2 (二段解法側)。背景は `analysis/rootlp_both_diff_20261105.md` (根の LP を二段解法と内点法 + クロスオーバーで
両方最後まで解いた計測)。生データは `analysis/rootlp_simplex_fail_20261105/`。

## 結論 (短く)

- **uccase12 (時間切れ) の原因は尺度の調整をしていないこと** (事実)。根の LP の係数は 9e-5〜420。HiGHS も尺度の調整を切る
  (`simplex_scale_strategy=0`) と 120 秒・60,551 反復で時間切れになり、こちら (141 秒・61,665 反復で時間切れ) と同じ振る舞いになる。
  調整ありの HiGHS は 2.1 秒・32,311 反復。こちらも 7,000 反復目から入る列の FTRAN の結果の密度が 0.06% → 7〜22% に跳ね上がり、
  1 反復が約 30 倍遅くなる (LU の非零は 2〜3 倍にしかならない。基底の逆行列そのものが密な基底へ入っていく)。
  試作 `ENOMOTO_SIMPLEX_SCALE` で **141 秒 (時間切れ) → 4.9 秒で最適** (32,517 反復、元の LP の warm start は 1 反復)。
- 尺度の調整は行の多い遅い例の一部にも効く: uccase9 24.6 → 11.5 秒、snp-02-004-104 17.4 → 9.9 秒、sing44 27.4 → 20.6 秒。
  sing326 (17.4 → 19.5)・thor50dday (60.7 → 61.0)・neos-873061 (107.7 → 101.9) はほぼ変わらない。
- **rail01・neos-873061 (時間切れ) は二段解法の欠陥ではなく、双対単体法に重い問題** (事実): HiGHS の双対単体法も rail01 は 129.6 秒・
  126,110 反復、neos-873061 は 87.8 秒・38,157 反復かかり、こちらと 1 反復の時間 (約 1.0 ms・2.4 ms) も反復数もほぼ同じ。
  内点法 + クロスオーバー (32.5 秒・12.1 秒) が勝つのが正しい。
- **supportcase42 (`Error`) は数値の破綻** (事実): 511 反復目に再分解直後の x_B の照合 (`xb_consistency_bailout`、ずれ 0.13) で
  解き直しになり、解き直し (safe_pivot・摂動の掛け直し) では LU が特異になって巻き戻すことが 30 回、最後に「確定しない軸が 50 回連続」で
  `Error`。試した軸 3,408 回のうち 560 回 (16%) が照合 (PRICE と FTRAN の軸の値) で捨てられ、そのたびに再分解する (再分解 468 回、
  時間の 82%)。HiGHS は **尺度の調整なしなら 1.1 秒・1,298 反復**、ありなら 87 秒・51,753 反復で解く。こちらの比の判定まわりの試作
  (`GROW_TA`・`HARRIS_WIDE`・`TINY_SKIP`、照合の解き直しを止める `ENOMOTO_T_XB_CONSISTENCY_TOL=0`) はどれも解けなかった。
- 遅い例 (sing326・sing44・thor50dday・uccase9) は反復数は HiGHS と同程度 (0.9〜1.3 倍) で、**1 反復が HiGHS (尺度あり) の 1.5〜2.5 倍**。
  HiGHS (尺度なし) とはほぼ同じ (0.9〜1.6 倍)。FTRAN が 1 反復の 33〜43% (入る列・DSE・BFRT の 3 本)。
- MIP 全体 (58 問・60 秒・1 回): SGM は既定 14.02 / 18.79 秒に対し SCALE 14.71 / 19.23 秒 (負けている 21 問 / MIPLIB 40 問)、解けた数 20→18 / 26→26。
  変わったのは上限近くの 3 問と根の LP の軽い小さい問題の経路の揺れで、58 問には得がない。大きい LP に限って使う形 (`ENOMOTO_T_SIMPLEX_SCALE_MIN_M`) が候補。

## 2. 問題ごと

### uccase12 (時間切れ → SCALE で 4.9 秒)

- 事実: 全スラック基底では実行不能な行 359 行。1000 反復で 3.8 万行になり、HiGHS (4.0 万〜4.3 万行) と同じ程度。行の数そのものは原因ではない。
- 事実 (`ENOMOTO_DEBUG_PROGRESS`、`logs/prog/uccase12.log`): 0〜7,000 反復は 0.06 ms/反復、7,000 反復目から入る列の FTRAN の結果の密度 (`col_aq`) が
  0.0006 → 0.017 (7,000) → 0.07〜0.22 (8,000〜24,000) に跳ね上がり、2 ms/反復になる。LU の非零は 8.9 万 → 15〜30 万 (行の 2〜3 倍) で、
  分解し直しも普通に起きる (主に drift・clock)。`ENOMOTO_PROF_PHASES_EXT_WORK` の 1 反復の非零: rho 216、alpha 6,756、tau 9,946 (行の 8〜11%)。
- 事実: HiGHS は尺度の調整ありで 2.1 秒 (64 µs/反復)、なしで 120 秒・60,551 反復で時間切れ (1,982 µs/反復、こちらの 2,285 と同じ程度)。
- 原因 (推測をほぼ含まない): 尺度の調整をしない LP では DSE の価格付けと比の判定が選ぶ軸の経路が変わり、逆行列の密な基底に入る。
  係数の幅は 9e-5〜420 (6.5 桁)。HiGHS で同じことが起きるので、二段解法の実装の誤りではない。
- SCALE: 写しを 4.84 秒・32,516 反復で解き、元の LP は warm start の 1 反復 (0.09 秒)。目的値は HiGHS と一致 (11468.4898 + 定数 38.8016)。

### supportcase42 (`Error`)

- 事実 (`ENOMOTO_DEBUG_EXT_ITERS`、`logs/sc42dbg/supportcase42.log`): 全スラック基底の実行不能な行は 2 行 (HiGHS も 2 行)。1000 反復で 9,735 行、
  入る列の FTRAN の結果の密度 0.70 (2000 反復で 0.83)、LU の非零 44 万 (行列の非零 43.6 万と同じ程度)。
  1. 511 反復目: 再分解直後の x_B (FTRAN) と `rho^T (b - N x_N)` (BTRAN) のずれ 0.13 (許容 1e-6) → `broken-basis` として
     摂動を掛け直し safe_pivot で最初から解き直し (`solve_slope_intercept_dual_retrying`)。
  2. 解き直し: 再分解が特異 (`refactorize returned None`) → 直前の軸の巻き戻し、を 30 回 (巻き戻す軸の |alpha_r| は 1e-9 前後)。
     軸の試し分解で特異と分かって捨てた軸 (`singular-pivot probe rejected`、|alpha_r| 1e-9〜8e-8) も 6 回。
  3. 2,896 反復目に「確定しない軸が 50 回連続」(`ENOMOTO_T_DISCARD_CYCLE_LIMIT`) → 解き直しの印を立てて `None`。解き直しは使い切っているので `Error`。
- 事実 (`ENOMOTO_SIMPLEX_PIVLOG`、`piv_base.jsonl`): 試した軸 3,408 回のうち 560 回 (16%) を捨てた (照合の不一致・特異)。|alpha_r| < 1e-7 の軸は 88 回で、
  うち 78 回は FT 更新が 10 回未満 (分解し直した直後) のとき。1e-12 未満の軸も 3 回。
- 事実: 時間の 82% が再分解 (468 回、1 回 約 50 ms。理由は照合の不一致 239・特異の検査 210)。1 反復 9.5 ms。
- 事実: HiGHS は尺度の調整なしで 1.1 秒・1,298 反復 (同じく 8,559 行まで実行不能が増え、和は 1e9 まで暴れるが通り抜ける。分解し直しは 50〜200 反復ごと)、
  尺度の調整ありで 87 秒・51,753 反復。
- 試したこと (どれも解けない、`piv_*.jsonl`・`sc42_*.jsonl`):

  | 設定 | 結果 | 秒 | 試した軸 | 捨てた軸 | |alpha_r|<1e-7 |

  | 既定 | Error | 29.0 | 3,408 | 560 | 88 |

  | `ENOMOTO_SIMPLEX_HARRIS_WIDE=1` (窓の軸が小さいとき後ろ向きの窓を広げる) | Error (既定と同じ経路) | 31.4 | 3,408 | 560 | 88 |
  | `ENOMOTO_SIMPLEX_TINY_SKIP=1` (|alpha| < 1e-7 の候補に Harris の比の緩め) | Error | 118.2 | 8,306 | 1,899 | 35 |
  | `ENOMOTO_T_XB_CONSISTENCY_TOL=0` (1. の解き直しを止める) | Error | 102.5 | 6,416 | 1,856 | 182 |

  `HARRIS_WIDE` が 1 回も効かないのは、小さい軸が比の最も小さい候補 (退化の比 0 付近) で、手前に候補がないため (事実)。
  `TINY_SKIP` は小さい軸を 1/2.5 に減らすが、照合で捨てる軸の割合が 23% に増える。
- 原因 (推測): 基底が数値的に悪く (逆行列が密で条件数が大きい)、PRICE の行と FTRAN の列の値が合わない軸が多い。こちらは不一致のたびに捨てて分解し直し、
  特異の検査でも試し分解をするので、1 反復が HiGHS の 10 倍以上になり、さらに捨てる軸が続いて止まる。HiGHS (尺度なし) が 1,298 反復で通り抜ける
  違いは、比の判定 (Harris の 2 パスで |alpha| の大きい軸を選ぶ・緩めた比で小さい軸を除く) と、不一致のときの扱い (分解し直して続ける。解き直しはしない)
  にあると見ている (確かめていない)。

### rail01・neos-873061 (時間切れ)

- 事実: HiGHS の双対単体法でも rail01 は 129.6 秒・126,110 反復、neos-873061 は 87.8 秒・38,157 反復。こちらは rail01 が 114 秒で 107,841 反復
  (1 反復 1,058 µs、HiGHS 1,027)、neos-873061 は 107.7 秒・43,812 反復で最適 (2,457 µs、HiGHS 2,302)。数値の問題 (捨てた軸・特異) はない。
- 原因: 双対単体法に重い問題 (反復の多い問題、列が多く price・chuzc1・dual の更新も重い)。内点法 + クロスオーバーが勝つのが正しく、二段解法の改善の対象ではない。
  `rootlp_both_diff` で neos-873061 が時間切れだったのは、同時に走る内点法とメモリの帯域を取り合って遅くなり、MIP の期限 (150 秒) の中の残り時間に間に合わなかったため (推測)。
- SCALE はどちらも変わらない (係数の幅は rail01 が 1〜157、neos-873061 が 0.007〜1 で狭い)。

### 遅い例 (sing326・sing44・thor50dday・uccase9・snp-02-004-104)

- 事実: 反復数は HiGHS (尺度あり) の 0.9〜1.3 倍で、1 反復が HiGHS の 1.6〜2.5 倍 (snp-02-004-104 だけはこちらが速い)。
  HiGHS (尺度なし) との比は 0.9〜1.6 倍に縮む。退化・数値の問題は見えない (捨てた軸・特異の再分解なし、再分解はほぼ clock)。
- SCALE: uccase9 は反復 22,056 → 15,984 (HiGHS 16,974) で 1 反復も 1,115 → 718 µs、sing44 は 816 → 615 µs、snp-02-004-104 は 247 → 147 µs。
  sing326・thor50dday は変わらない。尺度を調整しても 1 反復は HiGHS の 1.4〜2.1 倍で、残りの差は FTRAN・BTRAN の実装 (超疎の解き方・
  密度の予測) と価格付け (thor50dday・neos-873061 は price と chuzc1 が HiGHS より重い、推測) にある。過去の記録 (`analysis/simplex_loop_20260924_113533.md`、
  `docs/lu_comparison_enomoto_vs_highs.md`) と同じ傾向で、今回は手を入れていない。

## 3. 試作 `ENOMOTO_SIMPLEX_SCALE` の中身

- `src/simplex/mip_lp.rs` の `TwoStageLp::solve_once`: 基底がなく、行の数が `ENOMOTO_T_SIMPLEX_SCALE_MIN_M` (既定 0) 以上なら `solve_scaled`。
  MIP では根の LP (同時実行の二段解法側を含む)、LP プロービングの最初の LP、サブ MIP・再スタートの根など、基底のない求解すべてに効く。
- 尺度 (`scale_factors`): 行と列を交互に `1 / sqrt(min |a| · max |a|)` で 4 回 (`ENOMOTO_T_SIMPLEX_SCALE_PASSES`)、最後に列の最大の絶対値を 1 に。
  2 の冪に丸め、2^-20〜2^20 に収める。費用は調整しない (HiGHS の既定と同じ)。
- 写し: 係数 `r_i a_ij s_j`、行の境界 `× r_i`、列の境界 `/ s_j`、費用 `× s_j`。目的値は変わらない (打ち切り値はそのまま使える)。
  写しを基底なしで解き、最適なら基底 (標準形の列番号。尺度によらない) と `x = s · x'` (非基底列の置き場所の手がかり) を元の LP に置いて warm start で解き直す。
  9 問とも元の LP は 1 反復 (0.05〜0.09 秒) で最適。
- 写しが時間・反復の上限で止まればそのまま返す。実行不能・非有界・`Error` などは元の LP を基底なしで解き直す (証明の射線・双対を元の尺度で得るため。
  supportcase42 はこれで時間を倍に使う)。
- DSE の重みは元の LP に持ち込まない (単位から)。

## 8. supportcase42 の仕上げが重い理由と、軽くする試み (2026-11-06)

7 節で「仕上げの主単体法が重い」と書いたのは誤り。`HARRIS2=r` の supportcase42 (二段解法だけ、30.6 秒) の内訳 (`ENOMOTO_DEBUG_EXT_ITERS`・`ENOMOTO_PROF_PHASES_EXT`、
ログは scratchpad の `pol*.log`、要点をここに写す):

| 段 | 反復 | 秒 | 1 反復 |
|---|---:|---:|---:|
| 1 回目 (511 反復目で x_B の照合により解き直し) | 511 | 約 1.5 (推定) | - |
| 解き直しの主ループ (段階 B) | 12,618 | 18.1 | 1.43 ms |
| 仕上げの双対単体法 (`polish_with_true_bounds`、真の境界) | 9,557 | 約 11 (残りから推定) | 約 1.2 ms |
| 主単体法への引き継ぎ (`run_phase2_incremental`) | 2 | 0.045 | - |

- 事実: 重いのは主単体法ではなく、仕上げの **双対単体法** (真の境界で解き直す段)。線形代数 (`BasisKernel` の FTRAN・BTRAN・FT 更新・再分解) は
  主ループと共有していて、1 反復は主ループ (1.43 ms) とほぼ同じ。**重いのは反復の数 (9,557)**。
- 事実: 主ループの終わりで目的値は 6.8988 (真の費用、主ループの x_B)、仕上げの終わりで 7.3435 (最適)。仕上げの始めに真の境界で主実行不能な行は
  **4,720 行、最大の外れ 2.3e9、和 2.5e9** (新しい診断 `polish_start_primal_infeasible_rows`)。
- 事実: 主ループは 6,617 行を「丸め誤差の範囲の外れ」(`noise_feasible`、作業 #5 M1: 逸脱² ≤ (C eps ‖b‖)² · w_r) として以後の chuzr から外して終わっている。
  選んだ行の DSE 重みの最大は sqrt で 1.8e64 (基底は数値的にほぼ特異)。仕上げはこの印を持ち込まないので、外していた行の (壊れた) 外れがすべて現れる。
- 原因: 主ループが数値的に壊れた基底の上で、外れを雑音として無視して「最適」で抜け、仕上げがその基底から立て直している。立て直しの反復が 9,557。

試したこと (どれも `HARRIS2=r` と一緒、二段解法だけ):

| 設定 | 結果 | 秒 | 主ループ | 仕上げ |
|---|---|---:|---:|---:|
| 仕上げは今のまま (重みなしの最大の外れ) | 最適 | 30.6 | 12,618 | 9,557 |
| `ENOMOTO_SIMPLEX_POLISH_DSE=1` (仕上げの行の選び方を DSE の規則に、引き継いだ重み) | 時間切れ | 121.2 | - | 18,017 で終わらず |
| `ENOMOTO_SIMPLEX_POLISH_DSE=2` (同じ、重みを 1 から始める) | 時間切れ | 120.7 | - | 22,529 で終わらず |
| `ENOMOTO_T_NOISE_C=0` (主ループで外れを雑音として外さない) | 最適 | 109.2 | 66,022 | 2 |

- 壊れた基底からの立て直しは、重みなしの最大の外れ (今の規則) がいちばん速い。DSE の規則は壊れた重み (1e64) でも 1 から育てた重みでも倍以上の反復になる。
- 雑音として外す仕組みは、主ループを早く終わらせて仕上げに任せる方が全体では速い (30.6 対 109.2 秒)。仕上げは重いが、主ループで続けるよりは軽い。
- 結論: 仕上げを軽くするには、仕上げの規則より、主ループが壊れた基底に入らないようにする方が効く (推測)。候補: 小さい軸を選ばない比の判定 (`HARRIS2` を
  安全モードの前から使う・Td の扱い)、外れを雑音として外す行が増えたら (例: 行の 10%) 分解し直して DSE 重みを作り直す、HiGHS (尺度の調整なしで
  1,298 反復) のように不一致のときに解き直さない。
- 新しい試作 `ENOMOTO_SIMPLEX_POLISH_DSE` (既定では使わない) は残すが、効かない。
