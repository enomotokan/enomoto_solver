## 2. 無駄と高速化の機会 (効果の大きい順)

各項目: 場所 / 何が無駄か / 直し方 / 見込み (試作で測れたものは実測) / 正しさへの危険 / 結果が変わるか。

### 2.1 双対の押し出しを省けば速い問題がある (cre-b: 10.8 秒 → 3.3 秒)

- **場所**: `src/simplex/crossover.rs:780-897` (双対の押し出しのループ)、`:932-965` (基底の選択)、`:1054` (仕上げ)。
- **無駄**: 双対の押し出しは 1 歩で `D` の階数を 1 しか増やせない (比率テストでブロックした 1 列 + `|s_j| <= tol` の
  同点だけ)。必要な歩数は `m - rank(A_D)` にほぼ等しく (cre-b: m=5110、開始時 |D|=765 → 4381 歩。ken-13:
  10959 − 8095 → 3454 歩。ken-18 は約 19 万歩で 190 秒)、1 歩が KKT の三角求解 1 回 + `O(n)` の走査 4〜5 本 +
  `O(k·dim)` の Schur 補正なので、歩数 × (0.3〜4 ms) になる。一方、同じ「階数を m まで埋める」仕事は仕上げの
  有界双対単体法 (スラック列で埋めた基底から) でもできる。
- **実測** (試作 `ENOMOTO_X_XO_DUAL_MAX_STEPS=0` = 双対の押し出しを飛ばす):

  | 問題 | 基準 | 押し出しなし | 1000 歩で打ち切り |
  |---|---|---|---|
  | cre-b | 10.75 (双対 8.1、仕上げ 0.01) | **3.32** (仕上げ 0.68) | 4.54 |
  | ken-13 | 14.76 (双対 10.0、仕上げ 3.2) | 17.48 (仕上げ 16.0) | 18.21 |
  | degen3 | 1.53 (双対 1.03) | **0.65** (仕上げ 0.23) | ― |
  | 80bau3b | 1.20 (双対 0.47) | **0.67** (仕上げ 0.04) | ― |
  | greenbea | 1.86 (双対 0.62) | **1.40** (仕上げ 0.25) | ― |
  | osa-60 | 25.5 (双対 13.8) | **13.4** (仕上げ 3.0) | ― |
  | pds-10 | 20.2 (双対 10.3、仕上げ 3.2) | **9.1** (仕上げ 3.7) | ― |
  | d2q06c | 3.8 (双対 0.3、仕上げ 2.4) | 10.4 (仕上げ 9.4) | ― |

  9 問中 7 問で押し出しを全部省く方が速い (cre-b 3.2 倍、pds-10 2.2 倍、osa-60 1.9 倍)。ken-13 と d2q06c では
  スラック列で埋めた基底の双対実行不能 (ken-13 で 2828 列) を単体法が直すのに 16 秒 / 9 秒かかり逆効果。つまり「押し出しか単体法か」は問題依存で、`m - |D|` (残りの階数) と `n` から
  見積もって切り替える必要がある。
- **直し方**: (1) 開始時に残りの階数 `m - rank` が大きい (例: `|D| < 0.5 m` または 残り × 1 歩の見込み時間が
  仕上げの見込みを超える) なら押し出しを飛ばす。(2) 押し出しの途中でも、歩数の累計時間が内点法の時間を超えたら
  打ち切る (ken-18 の 190 秒を上限で切る)。(3) 本質的な解決は 1 歩で複数の列を入れる変種 (§3.1)。
- **見込み**: cre-b/cre-d で 3 倍、ken-18 で押し出しの 190 秒が消える (ただし仕上げがどれだけ増えるかは要計測)。
- **危険**: 正しさは変わらない (仕上げが最適性を保証する)。結果 (基底) は変わる。目的値は同じ。

### 2.2 pds-20 の仕上げ 62 秒 (旧ビルド 486 秒) は射影の数値破綻 (inf) が原因

- **場所**: `src/simplex/crossover.rs:594-602` (主の押し出しの向き `v`)、`:812-820` (双対の `v_y`)、
  `src/interior_point/kkt.rs:329-360` (`AugKkt::factor`/`solve_in_place`)。
- **何が起きているか** (`ENOMOTO_DEBUG_CROSSOVER=1`): 主の押し出しの 218 歩目で `|v|=inf`。`inf > 1e-6·inf` は
  偽なので零空間の検査を通り、`theta=0` で歩を進め (`pstep theta=0 |v|=inf`)、その後 `|B| = 9567 > m = 8928` の
  まま押し出しが終わる。双対の押し出しは 1 歩目で `|v_y|=inf` → "no direction" で 0 歩。基底の選択は `B` から
  4988 列しか取れず (B が大きく階数落ち)、スラック 3940 列で埋めた基底は主実行不能 3165 (最大 3.7e8)、双対実行
  不能 16814 で、仕上げの単体法が 62 秒かかる。pds-10 でも同じ inf が出る (`primal push: non-finite direction`)。
- **無限ループ**: さらに悪いことに、`|B| > m` のまま「向きが無い」(`‖Av‖ > 1e-6‖v‖`) と判定したときの分岐
  (`:619-629`) は `need_factor = true; continue` で、`round > max_primal = 10n + 10` (pds-20 で 895,310 回)
  までループする。1 回ごとに `BorderedKkt::factor` (記号分解を含む全再分解、`|B|` は変わらないので同じ系) を
  やり直すだけで、何も進まない。試作で分解の加算順が変わった (`ENOMOTO_X_FACTOR_SEQ=1`) だけで pds-20 は
  この分岐に入り、15 分で 18,803 回再分解したところで止めた (`|Av|` は 0.2〜6 と射影になっておらず、
  `AugKkt` の分解が壊れている)。旧ビルドの 486 秒もこの型 (再分解を繰り返した後に何らかの理由で抜けた) と
  考えられる。pds-10 でも `non-finite direction` が出る。
- **直し方**: (0) 「向きが無い」分岐で `|B| > m` のときはループを抜ける (再分解しても同じ系なので無意味)。
  少なくとも同じ `|B|` で 2 回続けて向きが無ければ終える。(1) `v`/`v_y` が有限でなければ向きとみなさない (今は inf が検査をすり抜ける)。(2) 非有限なら ε を
  上げて (1e-12 → 1e-8) 分解し直す。ただし ε を上げると `‖A v‖ <= 1e-6 ‖v‖` の検査を通らなくなるので、`|B| > m`
  で向きが無いときは `need_factor=true; continue` で回り続けず (`:623-628`。試作で `max_primal = 10n` 回まで
  再分解を繰り返して 20 分以上止まらなかった)、押し出しを終えて基底の選択に任せる。(3) inf の発生源の特定
  (AugKkt の動的正則化は `|pivot| <= 1e-13` を ±1e-9 に置き換えるが、`[I A_B^T; A_B -εI]` で `|B| > m` の
  退化した列が多いとき `S` (Schur 補行列) の `dense_solve` が 1e-300 未満のピボットを飛ばして λ が発散する可能性
  がある: `:318-360`)。
- **見込み**: pds-20 は仕上げが 62 秒 → 数秒 (pds-10 並み) になれば 85 秒 → 25 秒程度。pds-20 で退行した
  「停止の許容誤差 1e-6」案 (docs/crossover.md) も、この破綻が直れば再評価の価値がある。
- **危険**: 失敗経路だけの変更。結果は変わる (pds-10/20 で基底が変わる)。

### 2.3 内点法の停滞検出が効かず 200 反復まで回る (greenbea: 内点法 1.0 秒のうち 0.75 秒が無駄)

- **場所**: `src/interior_point/boxed.rs:428-450` (停滞の判定)、`:412-426` (最良の反復点)。
- **無駄**: greenbea は 45 反復目で `dres=8.46e-8, gap=3.85e-4` に張り付き、以後 155 反復は同じ点を往復する
  (`pres` だけ 4e-13 ↔ 4e-12 で揺れる)。停滞の判定 `res.primal >= prev_p·0.999999 && res.dual >= prev_d·...`
  は主残差が 1 回でも「改善」すると `stall = 0` に戻るので、揺れている限り永久に発火しない。pilot 系・
  greenbea・dfl001 の 200 反復はこの型。
- **直し方**: 最良の反復点 (`best`) の `worst` が K 反復 (8〜10) 改善しなければ (正則化が下限に達した後に限る)
  打ち切る。試作 `ENOMOTO_X_IPM_NOIMPROVE=10` (正則化が下限に達した後、`worst` が 10 % 以上改善しない反復が
  10 回続いたら打ち切り): greenbea 内点法 1.00 → 0.29 秒 (43 反復で打ち切り、総時間 1.86 → 1.10 秒)、
  dfl001 3.9 → 2.4 秒 (28 反復で打ち切り。偽の Infeasible のまま単体法で解き直し)。収束する pilot87、d2q06c、
  80bau3b、pilot では発火せず反復数・時間とも同じ。
- **危険**: 打ち切った点で `worst <= 1e4` ならクロスオーバーへ、そうでなければ単体法へ解き直す経路は既存のまま。
  収束する問題では発火しない (正則化が下限に達した後、`worst` が 10 % 以上改善しない反復が K 回続くことは
  収束中にはまず無い) が、閾値は 93+16 問で確認が要る。結果は未収束の問題だけ変わる。

### 2.4 疎 Cholesky の並列分解が逆効果 (cre-b 内点法 2.2 → 1.5 秒、pds-10 4.2 → 3.0 秒)

- **場所**: `src/params.rs:1156` (`KKT_PARALLELISM = Rayon(0)`)、`src/interior_point/kkt.rs:296,343-350`
  (`AugKkt`)、`:570,639-642` (`NormalKkt`)。
- **無駄**: faer の超節点分解は節点内の密な行列積を rayon で分けるが、この大きさ (nnz(L) 0.3〜1M、超節点は
  小さい) では分割の手間が計算を上回る。試作 `ENOMOTO_X_FACTOR_SEQ=1` (分解だけ `Parallelism::None`):

  | 問題 | 内点法 factor | 内点法合計 | クロスオーバーの数値分解 | 総時間 |
  |---|---|---|---|---|
  | cre-b | 1.29 → 0.58 | 2.18 → 1.48 | 0.36 → 0.41 | 10.75 → 10.96 (双対の押し出しのばらつき) |
  | pds-10 | 3.01 → 1.73 | 4.22 → 2.99 | 1.48 → 0.78 | 20.15 → 16.07 |
  | pds-20 | 14.1 → 11.8 | 17.4 → 15.3 | (主の押し出しが §2.2 の無限ループに入り計測できず) | ― |

  反復数・目的値は同じ (cre-b 54 反復、23129639.88683238 vs ...375: 最終桁のみ)。
- **直し方**: 分解は `Parallelism::None` を既定にする (または nnz(L) か最大超節点の大きさで切り替える)。
  本当に並列化したいなら消去木の部分木ごとの並列 (faer にはない) が要る。三角求解は `ENOMOTO_X_SOLVE_SEQ=1` で
  差が無かった (simplicial では faer が並列度を無視し、超節点でも 1 本の右辺では効かない)。
- **危険**: なし。結果はビット一致ではない (密な積の加算順が変わり最終桁が動く) が反復数は変わらない。

### 2.5 再分解のたびに AMD + 記号分解をやり直す (双対の押し出しの 15〜25 %)

- **場所**: `src/simplex/crossover.rs:177-215` (`BorderedKkt::factor` → `AugKkt::new`)、`kkt.rs:266-316`。
- **無駄**: 再分解は `should_refactor` (`:220-223`) が「縁の手間の累計 > 1 回の分解時間」で起こすので、cre-b で
  291 回、ken-13 で 146 回、pds-10 で 218 回。毎回 `rows` の Vec<Vec> を作り直し、CSR を組み、三つ組をソート
  (`try_new_from_indices`)、AMD、記号分解、`l_values`/作業領域の確保をする。記号分解の時間は cre-b 1.63 秒、
  ken-13 2.14 秒、pds-10 1.68 秒、osa-60 1.10 秒で、数値分解 (0.3〜1.5 秒) より重い。しかも分解時間が
  大きいほど `should_refactor` は縁を長く引きずるので、縁の補正 (`O(k·dim)`) も増える。
- **直し方**: (a) 列集合は押し出しの中で単調に変わる (主: 減る、双対: 増える) ので、AMD は「今の列集合」でなく
  「このエポックで入りうる列」の上位集合に対して 1 回取り、以後は順序を固定して記号分解だけやり直す (記号分解は
  AMD より軽い)。(b) 双対の押し出しは `A_D` に列を足すだけなので、正規方程式形 `εI + A_D A_D^T` (m×m) の
  パターンを全列の `A A^T` で 1 回だけ記号分解し、数値分解だけを繰り返す (docs は「全列で 1 回」を試して
  cre-b で遅かったとするが、それは拡大系で `BIG` 対角を残した版。正規方程式は寸法が `m` で、内点法の
  `NormalKkt` と同じ組み立て (`dest` の事前計算) が使える)。(c) 少なくとも `rows`/三つ組/作業領域の確保は
  使い回す (`:191-196`、`kkt.rs:270-297`)。
- **見込み**: 記号分解が消えれば cre-b で −1.5 秒、ken-13 で −2 秒 (双対の押し出しの 15〜20 %)。再分解が
  安くなると `should_refactor` の均衡点が動き、縁の補正時間も減る (合わせて 25 % 程度)。
- **危険**: 順序を固定する (a) は fill-in がやや増える。結果は (a)(c) ならビット一致、(b) は変わる。

### 2.6 双対の押し出しの 1 歩に `O(n)` の走査が 5〜6 本 (osa-60 で押し出しの 70 %)

- **場所**: `crossover.rs:821` (`at_y`: 全列の `A^T v_y`)、`:824` (noise: 活性列の走査)、`:838-856` (比率
  テスト: 全列)、`:870-872` (`s -= θ w`: 全列)、`:891` (`update_active`: 全列)、`:895` (`n_active` の数え直し:
  全列)、`:765` (`dual_correct` の `border_cols.contains(&j)`: 全列 × k の線形探索)。
- **無駄**: n=242,410 の osa-60 では 1 歩あたり約 6 本の全列走査 (計 ~1.5M 要素) を 2475 歩 → 1 歩 3.8 ms、
  合計 9.4 秒 (押し出し 13.8 秒の 70 %)。cre-b でも 3.1 秒 / 8.1 秒。`at_y` の並列化の仕方を変えても (逐次 /
  塊で並列: 試作 `ENOMOTO_X_MV_MODE=2`) 差は無く、rayon の手間ではなく走査そのものの量。
- **直し方**: (1) `w = A^T v_y` と比率テストは非活性・非基底の列だけ要る。活性列の `w_j` (noise) は
  `A_D^T v_y` の誤差評価で、縁の列だけ見れば十分 (分解に入っている列は `ε` の精度で 0)。候補列の添字配列を
  持ち、活性になった列を抜いていく。(2) `s` の更新は候補列だけでよい (活性列の `s` は理論上不変、`s_tgt` で
  追跡済み)。(3) `n_active` は増分で数える。(4) `update_active` は `s` が変わった列 (候補列) だけ見る。
  (5) `border_cols.contains` は `bool` 配列にする。
- **見込み**: osa-60 で −5〜7 秒、cre-b で −1.5〜2 秒、ken-13 で −2 秒。歩数が減らなくても 1 歩が半分になる。
- **危険**: なし (同じ値を部分集合で計算するだけ)。ビット一致 (走査順が同じなら)。

### 2.7 主の押し出しの補正 `primal_correct` が全 nnz の残差を逐次で計算 (osa-60 で 4.8 秒)

- **場所**: `crossover.rs:537-555` (`b - A x` を全列で逐次に計算 → `solve_general`)、`:674-682` (ずれの判定
  `θ‖Av‖ > 1e-9` で毎歩補正)、`:685` (`detect` の全列走査)。
- **無駄**: osa-60 (nnz=614k、n=242k) の主の押し出し 494 歩のうち 377 歩で補正。1 回の補正が残差の計算 (逐次

  pds-10 (1.1 秒)、cre-b (0.17 秒) でも同じ比率。
- **直し方**: 残差 `r = b - A x` を増分で保つ (1 歩で変わるのは `x += θ v` の `v` の非零列と、境界に置いた
  1 列: `r -= θ A v` は `Av` を既に `:610-618` で計算している)。補正後は `A δ` の分だけ更新する。`detect`
  は `v_j != 0` の列と新たに境界に当たった列だけ見ればよい。
- **見込み**: osa-60 で −4 秒、pds-10 で −1 秒。
- **危険**: 残差の増分更新は丸め誤差が溜まるので、再分解のときだけ一から計算し直す。ビット一致ではない。

### 2.8 仕上げに渡す基底の質 (d2q06c、pilot87、ken-13、pds-10 の仕上げ 3〜11 秒)

### 2.9 結果が実行ごとに変わる (仕上げの時間が 0.9〜11 秒でばらつく原因)

- **場所**: `src/interior_point/boxed.rs:54-56` (`dot`: `par_iter().sum()`)、`:511-517` (`sz_aff` の並列 `sum`)、
  `:395` (`gx`)。
- **何が起きているか**: rayon の `sum()` は分割の仕方が実行ごとに変わるので加算順が変わり、`cx`, `by`, `hz`,
  `mu`, `sigma` の最終桁が実行ごとに動く。56 反復の内点法を経ると `y` の下位桁が変わり、`detect` の境界判定
  (絶対 1e-8) と押し出しの経路が変わる。pilot87 で同じ 56 反復・同じ目的値でも、仕上げに渡す基底の質が
  主実行不能 512 / 464 / 110 / 112、双対実行不能 1674 / 517 / 273 / 152 とばらつき、仕上げが 0.9〜11.2 秒
  (総時間 4.9〜15.8 秒)。d2q06c の仕上げも 2.4〜4.3 秒。`benchmarks/crossover/ab` の 3 回の中央値でも
  pilot87・d2q06c 級のばらつきは吸収できず、A/B 比較 (Gondzio 等) の判定を揺らす。
- **直し方**: 内点法の総和を決定的にする: 固定長の塊 (例 4096) ごとの部分和を逐次に足す (`par_chunks(4096)` の
  `map(sum).collect()` → 逐次 `sum`)、または `with_min_len` でなく `par_chunks` を使う。クロスオーバー側は
  要素ごとの並列 (`at_y`) で決定的。
- **見込み**: 速度そのものは変わらないが、仕上げの時間のばらつき (最大 10 秒) が消え、§2.8 の対策の評価が
  できるようになる。
- **危険**: なし。結果は (決定的になるという意味で) 変わる。

### 2.10 内点法の Newton 求解の周辺: 行列ベクトル積と rayon の手間が三角求解の 3〜30 倍

- **場所**: `src/sparse.rs:1461-1483` (`csr_mat_vec_into` は `min_len` なしの並列、`csr_mat_t_vec_into` は
  逐次)、`kkt.rs:709-754` (`NormalKkt::solve_in_place`: 並列ループ 3 本 + 行列ベクトル積 2 本)、
  `:799-838` (`solve_refined`: 反復改良の残差 `K·x` を毎回計算)、`boxed.rs:647-672` (`newton`)。
- **無駄**: §1.2 のとおり greenbea で solve 0.42 秒のうち faer の三角求解は 0.06 秒、osa-60 で 1.73 秒のうち
  0.05 秒。差は (a) `A^T y` の逐次計算 (osa-60: nnz 614k を 1 反復に 4〜6 回: 残差 1 回、求解の中 1 回、改良
  の残差 1〜3 回)、(b) 反復改良の第 1 回の残差計算は常に行う (`:810-826`) が、改良が要ったのは pilot87 0 回、
  pds-10 2 回、cre-b 11 回 / 120 求解。(c) 小さな問題では rayon の並列ループ (1 反復 20 本以上。

- **直し方**: (a) `csr_mat_t_vec_into` を列方向 (CSC) で並列化するか、`NormalKkt` が持つ `col_ent` (CSC) を

  のときだけ行う、または前回の改良が不要だったら 1 反復飛ばす。(c) `n + p < 2〜4 万` なら rayon を使わない
  逐次版に切り替える (`PAR_MIN_LEN` を使う `with_min_len` では join の手間は消えない)。
- **見込み**: osa-60 の内点法 3.6 → 2.5 秒程度、greenbea/80bau3b で 0.1〜0.2 秒 (内点法の 20〜30 %)。
- **危険**: (a)(c) はビット一致 (加算順を揃えれば)。(b) は反復改良を省いた分だけ数値が変わる。

### 2.11 `NormalKkt::factor` の組み立てと Woodbury が逐次

- **場所**: `kkt.rs:616-632` (正規方程式の値の足し込み: 列ごとに逐次)、`:650-702` (Woodbury の `W = M_s^{-1} U`

- **無駄**: osa-60 は三つ組 1.19M を毎反復逐次に足す (factor 0.33 秒のうち大半。nnz(L) は 32k しかない)。
  稠密列を持つ問題 (fit2p) では `k` 本の三角求解を 1 本ずつ行う。
- **直し方**: 足し込みは行 (= CSC の列) ごとに分けて並列化する (各列 `c` の `dest` の範囲は
  `symbolic_base` の列ごとに連続なので、`dest` を列で分割すれば書き込みが衝突しない)。Woodbury の `W` は
  faer の多列右辺 (`solve_in_place_with_conj` は `k` 列の `MatMut` を受ける) で 1 回に解く。
- **見込み**: osa-60 で factor 0.33 → 0.1 秒。fit2p で `W` の求解が 2〜3 倍速い。
- **危険**: なし。足し込みの順序を列順のままにすればビット一致。

### 2.12 縁取り (BorderedKkt) の細かな無駄

- **場所**: `crossover.rs:226-250` (`add_border`)、`:253-270` (`border_correct`)、`:304-314` (`solve_base`)。
- **無駄**: (a) 縁 1 本ごとに三角求解 1 回。1 歩で複数列が入る (cre-b は平均 2.3 列/歩) のに多列右辺で
  まとめない。(b) `border_correct` は毎歩 `S` を平らにコピーし (`k²`)、`dense_solve` で LU を一から取り

## 3. 個別の検討事項

### 3.1 (a) 双対の押し出しに Kennington で数千歩かかる理由と代替案

**理由**: §2.1 のとおり歩数 ≈ `m - rank(A_D)` (開始時)。cre-b 4345 → 4381 歩、ken-13 2864 → 3454 歩、
osa-60 2199 → 2475 歩、pds-10 197 → 2234 歩 (pds-10 は `|D| = 3930 < m = 4127` でも `A_D` の階数が低く、
終盤 (`|v_y|` が 1e-6 近く) まで雑音の向きで列を足し続けた)。ken-18 (m ≈ 10 万) が 19 万歩になるのも同じ。
参照実装 (Julia) も 1 歩 1 列で、論文の問題 (PDLP の解) では `|D|` が最初から `m` に近いことを前提にしている。
内点法の解は退化面の内点なので `|s_j| <= 1e-8` の列は多いが、Kennington のネットワーク系では `B` が `m` の
70〜80 % しかなく、残りをすべて押し出しで埋めている。

**1 歩の費用** (cre-b、1.85 ms/歩): 縁の求解 0.37 + Schur 補正 0.16 + `A^T v_y` 0.31 + 比率テスト・更新 0.26
+ update_active 0.14 + 再分解の償却 0.6。

**代替案の比較**:

1. *ブロック (複数列) 版*: 比率テストで `θ` の小さい順に `r` 列を取り、同時に `D` に入れる。`y` は `θ_1` だけ
   動かすので 2 列目以降は `s_j ≠ 0` のまま `D` に入る (`s_tgt` の仕組みは既にそれを許している: `:742-747`)。
   これは「基底に入りうる列」を増やすだけで、基底の双対実行可能性は仕上げに任せることになる。1 歩が `r` 倍
   安くなる代わりに基底の質が落ちる (ken-13 で見た通り仕上げが伸びる危険)。`r` を 2〜4 に抑えて試す価値はある。
2. *より良い初期 D*: `update_active` の `|s_j| <= 1e-8` は内点法の精度 (相対 1e-8 × ‖c‖) と同じ桁で、退化した
   列を取りこぼしている可能性がある。`tol` を `max(1e-8, 1e-6·‖c‖∞)` 程度にし、入れた列は `s_tgt` に記録
   (既にそうなっている) すれば初期 `|D|` が増える。安全で安い。実測は未 (閾値を `prm::TOL_BOUND` で変えると
   `detect` も変わるので別の定数にする)。
3. *単体法へ早く切り替える*: cre-b で 10.8 → 3.3 秒 (§2.1)。ken-13 では逆効果。判定は「残りの階数 × 1 歩の
   見込み時間」と「仕上げの見込み (残りの階数 × 単体法の 1 ピボットの見込み)」の比較で、1 ピボットの見込みは
   内点法の `nnz(L)` と `m` から粗く出せる。少なくとも押し出しの累計時間が内点法の時間の数倍を超えたら
   打ち切る上限は入れるべき (ken-18 の 190 秒)。
4. *1 歩を安くする*: §2.5、§2.6、§2.12 の合計で 1 歩が半分以下になる見込み (cre-b 8.1 → 3〜4 秒)。

推奨は 4 + 3 (上限) をまず入れ、1 と 2 は A/B で測る。

### 3.2 (b) pds-20 の仕上げ 486 秒 / 62 秒

§2.2 のとおり、押し出しの射影が inf になって主の押し出しが `|B| > m` のまま終わり、双対の押し出しが 0 歩で
終わる失敗経路。`inf` が零空間の検査 (`:619`、`inf > 1e-6·inf` は偽) と `vn <= 1e-9` (`:818`) をすり抜ける。
試作で「非有限なら ε を 1e4 倍して分解し直す」だけを入れると、ε=1e-8 では `‖Av‖ <= 1e-6‖v‖` を満たせず
`:623-628` の `need_factor=true; continue` で `max_primal = 10n` 回まで再分解を繰り返す (20 分で打ち切った)。
直すなら (1) 非有限は「向き無し」として押し出しを終える、(2) `|B| > m` で向きが無いときはループを抜ける、
(3) inf の発生源 (Schur 補行列の特異性か LDLᵀ の動的正則化か) を `ENOMOTO_DEBUG_CROSSOVER` で `S` の対角と
`n_regularized` を出して特定する、の順。仕上げ 62 秒そのものは、主実行不能 3165 (最大 3.7e8)・双対実行不能
16814 の基底 (B から 4988 列 + スラック 3940 列) を双対単体法が直す時間で、基底が普通なら pds-10 並み (数秒)。

### 3.3 (c) BorderedKkt の 1 歩の費用

§2.5 (再分解の方針と記号分解)、§2.12 (Schur 更新・密解・確保)。補足:

- `should_refactor` (`:220-223`) は「縁の累計時間 > 直近の分解時間」で、古典的な 2 倍近似 (再分解の最適周期
  は `√(2·factor/border_per_step)` 歩で、累計比較は最適の 2 倍以内)。分解時間に記号分解が入っているので周期が
  長めに出る。記号分解を省けば周期は短くなり、縁の補正時間の合計は減る。
- `max_border` (`:159-161`) は `512 MB / (8·dim)` を 64 で頭打ち。cre-b (dim 15k) で 64 本は 7.7 MB しか
  使わないので、上限 64 は時間の方針が先に発火する限り効いていない (`borders` は最大 35 程度)。
- `add_border` の縁の求解 (`:234`) と `solve_general` (`:294`) はともに 1 本の右辺。`AugKkt::solve_in_place`
  の作業領域は 1 列分 (`solve_in_place_req(1)`、`kkt.rs:297`)。多列にするなら `req(k)` で取り直す。
- `AugKkt::factor` (`kkt.rs:336`) は毎回 `symbolic_base.clone()` (col_ptr と row_idx の複製) と
  `new_from_order_and_values` (値の並べ替え) をする。nnz 規模の手間だが、再分解 291 回で効く。

### 3.4 (d) 内点法の 1 反復の手間と分解

- 分解: §2.4 (並列を切ると 1.7〜2 倍速い)。順序付けは faer の AMD のみで、pds (多品種流) のような格子状の
  構造では nested dissection の方が fill-in が数倍少ないのが通例 (pds-20 nnz(L)=3.4M)。faer には ND が無い
  ので、入れるなら外部 (METIS のバインディングか純 Rust の実装) が要る。超節点か simplicial かは faer が
  `flops/nnz(L) > 40` で自動選択し、Netlib の小さな問題は simplicial (greenbea、80bau3b、ken-13、osa-60)。
- 求解: §2.10。faer の三角求解は simplicial では並列度を無視し (`cholesky.rs:1249` `let _ = parallelism`)、
  超節点でも 1 列の右辺では `matmul` の分割が効かないので、`KKT_PARALLELISM` は求解には無意味。
- 行列ベクトル積: `csr_mat_t_vec_into` (`sparse.rs:1469-1483`) は逐次。1 反復に残差 1 回 + 求解 1〜2 回 +
  改良 1〜4 回。osa-60 で合計 0.8 秒。
- 反復改良: `REFINE_STEPS = 3` で、残差の検査 (K·x) は必ず 1 回行う。改良が要った回数は pilot87 0/113、
  pds-10 2/133、cre-b 11/120、greenbea 150/551、d2q06c 68/217。検査の省略条件 (§2.10 (b)) で改良が要らない
  問題では検査の分 (greenbea 0.09 秒、osa-60 0.61 秒) が消える。
- 確保: `best` の保存 (`x`, `y`, `rc` を `clone`/`vec!`: `boxed.rs:418-425`) は改善した反復ごと。Gondzio
  (既定無効) は `saved_rhs`/`saved` を毎回 `clone`。`rc` の組み立て (`:630-636`) は逐次。
- 停止判定の norm 群 (`:391-401`): `dot` 5 本、`norm_inf` 6 本、`gx` の filter が全部 rayon。小さな問題では
  1 反復 0.1〜0.3 ms (greenbea 200 反復で 0.01 秒、osa-60 で 0.13 秒)。

### 3.5 (e) 受け渡し

§2.13。加えて: `detect` (`:486-510`) の閾値 `TOL_BOUND = 1e-8` は絶対値で、内点法の解の精度は相対 1e-8 × 大きさ
(osa-60 の `|h|max = 2e-3`、pds の `|b|` は 1 に正規化) なので、境界の大きさによっては内点法の解の方が粗く、
`detect` が境界の列を取りこぼして `B` が `m` より大きく (pilot87 2597 > 1877、pds-20 9883 > 8928) なり、
主の押し出しの歩数 (pilot87 392 歩 1.8 秒、osa-60 494 歩 7 秒) が増える。`detect` の閾値を内点法の停止
許容 (`bnd_p` 相当) に合わせると主の押し出しが短くなる見込み (未計測)。
