# HNFPRE の合同式をカットの分離器に教える (試作 `ENOMOTO_MIP_HNFCUT`) (2026-11-07)

bench に使う環境変数: 既定 (`def`) はなし。`hnf` = `ENOMOTO_MIP_HNFPRE=1` (前の試作、`analysis/hnfpre_20261107.md`)。試作は `ENOMOTO_MIP_HNFCUT=1`
(`hcut`、= `abc`。`HNFPRE` がなければ `HNFPRE=1` と同じ前処理・丸めもする)、文字ごとに `=a` (`hcut_a`、CMIR)・`=b` (`hcut_b`、zerohalf と SNFMODK)・
`=c` (`hcut_c`、tableau 行)。どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_MIP_LOG=1`・`ENOMOTO_T_MIP_SEED=回`。試作は既定では使わない。

機械: 4 CPU、ソルバーの計測は同時に 1 つ (`run.py` を順に)。wheel は計測ごとに作り直した (根の比べの前に同点の扱いを直したもの、根の LP 点の診断と 600 秒・58 問はそれに診断のログを足しただけのもの)。

## 結論

- **効くのは `b` (zerohalf・SNFMODK を合同式の列を `z` に写した空間で作る) で、当たる問題は少ない** (事実): HNFPRE の合同式の出る 16 問のうち、
  根の下界が変わるのは 3 問 (flugpl・rococoB10-011000・rococoC10-001000)。600 秒・2 回で
  - rococoB10-011000: 下界 11340・11502 (既定) → **14591・14419** (`HNFCUT=b`)、ギャップ 49.0・45.3% → 26.6・32.1%。根のカットの後の値 10364 → 13869。
  - rococoC10-001000: 下界 10536・10480 → **10701・10667**、ギャップ 8.8・9.3% → 6.8・7.7% (根のカットの後は 9007 → 8875 と下がるが、ノードが 1.4〜1.6 倍進む)。
  - flugpl (`a`・`c`): 根で閉じたギャップ 15% → 100%、根で解ける (0.12 → 0.04 秒。もともと速い)。
- **`a` (CMIR)・`c` (tableau 行) は効かないか害** (事実): rococo の 600 秒で `HNFCUT=ac` は 2 問とも既定以下 (B10 11046・11170、C10 10358・10391)、ノードも 2〜3 割減る。
  `abc` では rococoB10 の `b` の効き目が消える (下界 11465・11335 = 既定と同じ)。推測: 置き換えた CMIR (根で 2254 本が元の CMIR に勝ち、効き目の合計 31.3 対 0.3)
  が選びの上位を取って zerohalf の写したカットを押し出す。
- **効かない問題が多い理由** (事実): 根の LP 点で合同式の列の値を数えると、13 問のうち 11 問は合同式の列がほとんど合同式に合う値 (多くは HNFPRE が詰めた上下限)
  にあり、`z` の空間でも整数なので丸めに効かない。効いた 3 問は合同式に合わない値の列が多い (flugpl 4/4、rococoB10 82/90、rococoC10 69/95)。
- 害 (58 問、60 秒・2 回、`HNFCUT=1`): 見えない (SGM 16.64 → 16.42 (−1.3%、区間 [−3.9%, +1.0%])、解けた 86 → 86)。58 問で合同式が残るのは flugpl だけなので、ほぼ HNFPRE の解析の手間の比べ。
- 誤答の検査: 合同式に合う整数点を全部並べる単体テスト (CMIR 5301 本・zerohalf 2637 本) と、合同式のカットが効く乱数の問題 `fuzz_cut.py` 2000 問 (うち 1565 問で
  合同式のカットが出た) で 0 件。既存の `fuzz_tiny.py 400 0` は既定と同じ 13/400 (既知の件)、`mip_fuzz_vs_highs.py 300`・`fuzz_hnf.py 1000` は 0 件。
  `cargo test --release --lib` 369 通る。
- 次の一手 (推測): (1) 既定の文字を `b` だけにする (`a`・`c` は外す) か、`a`・`c` は置き換えた方を候補に足すだけにして選びは既定に任せる。(2) `b` が効く理由
  (rococo の法は 46〜128、法 2 の連立で偶数の法の列が消える) を確かめ、別のセッションの `ENOMOTO_MIP_MODKVB` の連立 (`modkvb_cuts`) にも写しを入れる。
  (3) 行の活動量 (論理変数) の合同式 (行の整数の列が全部合同式の列なら、行の活動量も gcd の法で決まる) を足す。(4) 当たる問題が少ないので、既定に入れる前に
  合同式の出る問題を Mittelmann・MIPLIB の collection からもっと探す (合同式に合わない LP 値の列があることが条件)。

## 1. 作ったもの (事実)

- `src/mip/hnfcut.rs` (新しい部品) と、`cuts.rs`・`separation.rs`・`mod.rs` への小さな差分、`hnf.rs` の 1 行 (`HNFCUT` だけでも `HNFPRE=1` と同じにする)。
- 表: HNFPRE の最終の表 ([`hnf::table_for`]、`Domain::cong`) を、`Solver::separate` の間だけスレッドごとの置き場 (`hnfcut::Guard`) に置く。
  並列の分離 (tableau 行・`sep_parallel_parts`・`gen_cuts_parallel`) のスレッドにも写しを置く。サブ MIP は表がない (指紋が違う) ので何もしない。
- `a` (CMIR): `generate_cuts` の中で、境界の置き換え (`substitute`) の後、単純な上下限で置き換えた整数列で合同式 `x = r + g z` のある項を
  `z` の項にする (`v = l + y` なら `y = g (z - lz) + (r + g lz - l)`、`v = u - y` なら `y = g (uz - z) + (u - r - g uz)`、`lz = ⌈(l - r)/g⌉`・
  `uz = ⌊(u - r)/g⌋`)。係数は `a g`、右辺から定数を引く。δ の選び・補変数の向きの反転・MIR の丸めはそのまま (`Term` の `Sub::Cong`)、
  戻しは `c (z - lz) = (c/g) x - c (r/g + lz)`。置き換えた空間と元の空間の両方で CMIR を作り、効き目 (LP 点の違反 / ノルム) が
  相対 1e-3 より大きく勝つときだけ置き換えた方を残す (最初は 1e-9 の差で選んでいたが、brazil3 で効き目がほぼ同点の「勝ち」が 3988 本出たので直した)。
  lifted cover・flow cover・extended cover は元のまま (置き換えない)。
- `b` (mod-k): zerohalf (`zerohalf_cuts`、逐次と並列の両方) と別のセッションの `ENOMOTO_MIP_SNFMODK` の CG カットを、合同式の列を `z` に写した
  行 (係数 `a g`、行の上下限から `a r` を引く)・上下限 (`lz..uz`)・LP 値 (`(x - r)/g`) で呼び、カットの係数を `c/g`、右辺に `c r / g` を足して戻す
  (`hnfcut::map_rows`)。法 2 の連立で `g` が偶数の列が消える (行の奇偶が変わる) のが効くはず (推測)。`ENOMOTO_MIP_MODKVB` は `generate_cuts` を
  通るので `a` の置き換えがかかる (MODKVB の連立そのものは写していない)。
- `c` (tableau 行): 単体表の行の CMIR (GMI に当たる) の区間だけ `a` と同じ置き換えを使う (`a` と `c` は区間で切り分ける)。
- 数え上げ: 根のカットの後に `MIP: root HNFCUT stats: ...` (根の最初の LP 点での合同式の列の値の内訳、合同式の項を含む CMIR の行、置き換えた方が勝った数と
  効き目の合計、置き換えた方だけ作れた数、mod-k の呼び出しと写したカットの数)。
- 整数の算術: 表の値 (i64) を f64 にして使う。上下限の絶対値が 1e12 を越える列は写さない。

## 6. 続き: `b` が効く理由・MODKVB への写し・行の活動量の合同式 (`l`)・当たる問題の探索

### 6.1 作ったもの (事実)

- `l` (`ENOMOTO_MIP_HNFCUT` の文字、`1` には含めない): 行の活動量の合同式。整数の行 `s = Σ a_j x_j` で合同式の列を含むものは
  `s ≡ Σ_{合同式} a_j r_j + Σ_{固定} a_j x_j (mod G)`、`G = gcd(合同式の列の a_j g_j, ほかの整数列の a_j)`。
  - `a`・`c`: 分離の回ごとに LP の行 (元の行とカットの行) の合同式を表に足し (`hnfcut::extend_logicals`)、CMIR の論理変数の項も `s = r + G t` に置き換える。
  - `b`: 写した行で合同式の列を含む整数の行の上下限を、写した係数の gcd の倍数に丸めてから zerohalf・SNFMODK に渡す。
- MODKVB への写し (`b` と `ENOMOTO_MIP_MODKVB` の両方のとき): `modkvb_cuts` に、合同式の列を `z` に写した変数・LP の行 (論理変数は `s − shift`)・
  変数上下限 (相手が合同式の列なら `d x_y + e = d g z + (e + d r)`、合同式の列自身の整数の変数上下限は捨てる) を渡し、カットを戻す
  (`hnfcut::map_cutvars`・`MappedVars::unmap`)。写した空間の `generate_cuts` には `a` の置き換えを重ねない。
- 診断 `ENOMOTO_MIP_HNFCUT_BPAR=even` / `odd`: `b` で法が偶数 / 奇数の列だけ写す。
- 直し: `Sub::Cong` に上側の基準 `uz` も持たせ、補変数の側 (`uz − z`) を直接戻すようにした。前は下限が −∞ の列 (論理変数で起きる) で
  補変数の側を選ぶと右辺が NaN になり、そのカットは `finish_cut` で捨てられていた (誤りではなく取りこぼし。構造変数では下限が −∞ の合同式の列で起きる)。
- 根の最初の LP 点の内訳を、その場でログに出す (`HNFCUT: first LP point: ...`)。
