# 既定にする候補 cand で n5-3 が遅くなる理由 (2026-10-31)

`analysis/halve_submip_20261030.md` の bench6・bench7 で、cand (`analysis/halve_submip_20261030/run.py` の `CFGS["cand"]`) は全体では速いが、
n5-3 が def 26.8 秒 → cand 54.9 秒と遅い (bench6 でも hs_pi0_bgw で def だけ解けた)。その仕組みを調べ、手当てを試作した。

- 機械: 4 CPU。4 スレッド・60 秒、`ENOMOTO_MIP_LOG=1`、ソルバーは同時に 1 つだけ (例外は下の「計測の注意」)。HiGHS (highspy) は 1.15.1。
- コード: `6bfcc89d` (計測の 1〜3 節)、`6bfcc89d` + 下の試作 (4 節。試作は環境変数で入れるだけで、ほかの設定の動きは変えない)。
  別のセッションが cand を既定にする変更を進めているので、比べる設定はどれも環境変数で明示し、ビルドは計測の途中で取り込み直していない。
  def は環境変数なし = `6bfcc89d` の既定。
- 台本・ログは `cand_slow_n5-3_20261031/`:
  - `run.py 設定,... 問題,... 回数 [回の始め]`: ログを `logs/問題_設定_回.log` に書く。問題・回ごとに設定の順を逆にする。
    設定は cand から部品を 1 つ外す `cand-x`、def に部品を 1 つ足す `def+x`、試作の `cand+real` など (`CFGS`)。
  - `summ.py [問題,...] [設定,...]`: 回ごとの時間・再スタート・根のヒューリスティクスの終わりの時刻と暫定解・木の開始・根のサブ MIP の時間の和 (`summ.txt`)。
  - `table.py`: 問題 × 設定の時間の表 (`table.txt`)。
  - `verbose/`: `ENOMOTO_MIP_SUBMIP_VERBOSE=1 ENOMOTO_MIP_DEBUG_SUBMIP_STOP=1` でサブ MIP の中も出したログ (cand・def・cand+real+dc 各 1 回)。
- 計測の注意: verbose の 1 回を def+pi・def+r0・def+bgw の計測と同時に走らせてしまったので、その 4 本は `discarded/` に移し、全部 1 本ずつ測り直した。

## 1. 結論

1. **遅さは安定している**: n5-3 は def 31.9 / 34.0 / 32.1 秒、cand は 3 回とも時間切れ (この機械は bench7 の機械より遅い)。再スタートはどちらも起きない。
2. **原因は hs (`ENOMOTO_MIP_SUBMIP_HIGHS=-s`) のサブ MIP が 1 本ずつ重いこと**。`c`・`h`・`t` のどれか 1 文字を抜くだけで def 並みに戻る。
   ほかの部品 (擬似コストの引き継ぎ・RELIABLE=0・BG_CUTS_WAIT・TRIM=r・FIRST_FAC・PROOF_STOP、文字の p・g・i・f) は抜いても戻らない。
   TRIM=r は再スタートのない n5-3 では何もしない。
3. 仕組み: 根 (8 秒でカットのループが終わる) の後の根のヒューリスティクスが、def 6〜8 秒に対し cand 28〜35 秒かかる。
   サブ MIP の木はどれも 50 ノードほど (成果連動の打ち切り) で軽く、時間の大部分は **深さ 1 のサブ MIP の中の根**: 25 ラウンドのカット (`c`)、
   中の RENS (深さ 2、`h`。その中でも 25 ラウンドのカット)、そして **その RENS の「more nodes」のやり直し**。
   `t` はサブ MIP の時間を残り全部 (既定は残りの 7%・最大 6 秒) にするので、中のカットの時間の上限 (サブ MIP の時間の 5 割) と入れ子の RENS の時間 (3 割) も大きくなる。
4. **RENS のやり直しの空回り**: 根の RENS のサブ MIP が停滞・成果連動の打ち切りで止まっても状態は `NodeLimit` で返るので、
   ノード上限を 4 倍にしたやり直しが走る。止まり方は上限によらないので、やり直しは同じノード数で同じ解を返す
   (外側の根で 55 → 55 ノード・10.8 秒、深さ 1 のサブ MIP の中で 189 → 189 ノード・3.3 秒)。def でも外側で 2.7 秒の空回りがある。
5. 手当ての試作 `ENOMOTO_MIP_RENS_MORE_NODES_REAL` (やり直しを、RENS が本当にノード上限まで進んだときだけにする):
   - n5-3 は cand 時間切れ×3 → **42〜46 秒** (def は 32〜34 秒にはまだ届かない)。def に足しても 32 → 25〜30 秒。
   - 得の問題の得は残る (h80x6320d 23〜25 秒、qiu 22〜24 秒、binkar10_1 6 秒)。挙動が変わるのはやり直しが空回りする場合だけなので、
     physiciansched6-2 (やり直しが起きない) では何も変えない。
6. n5-3 を def 並みに戻すには、さらに深さ 2 で `c` を抜く (`ENOMOTO_MIP_SUBMIP_HIGHS_DEEP=-c`、試作) と、`t` の時間を 8 秒までにする
   (既存の `ENOMOTO_T_MIP_SUBMIP_HIGHS_TIME_MAX=8`) のを重ねる形 (cand+real+dc+tm8) で 33〜38 秒になる。ただし qiu・h80x6320d の遅い回が増える気配があり (4 回中 qiu 2 回・h80x6320d 1 回)、
   回数が足りないので勧めない。
7. どれも既定にしない (試作だけ)。次は cand + `ENOMOTO_MIP_RENS_MORE_NODES_REAL` を 58 問・Mittelmann で確かめるのがよい。

## 2. 部品の切り分け (n5-3、秒、T は時間切れ)

cand から 1 つ外す (各 2 回。cand-x の x は部品、cand-hx は `ENOMOTO_MIP_SUBMIP_HIGHS=-sx`、cand-hs は `SUBMIP_HIGHS` を外す):

|---|---|---|---|---|---|---|---|
| 31.9 / 34.0 / 32.1 | T / T / T | T / 56.8 | T / T | T / 52.7 | 48.9 / 57.3 | T / 58.0 | 55.7 / 52.4 |

| cand-hs | cand-hp | cand-hc | cand-hg | cand-ht | cand-hi | cand-hh | cand-hf |
|---|---|---|---|---|---|---|---|
| **27.2 / 26.8** | T / 58.8 | **32.4 / 32.6** | 52.8 / 47.5 | **36.2 / 35.8** | 54.8 / 45.1 | **33.6 / 31.9** | 54.1 / 52.0 |

def に 1 つ足す (各 1 回):

| def+pi | def+r0 | def+bgw | def+trim | def+ff | def+ps | def+hs |
|---|---|---|---|---|---|---|
| 32.1 | **20.0** | 34.5 | 29.1 | 32.8 | 29.7 | **T** |

- hs だけで時間切れになり (def+hs)、hs を外すと def より速い (cand-hs 27 秒)。cand-hs の速さは RELIABLE=0 から来る (def+r0 20 秒:
  サブ MIP で強分枝しないと、根のサブ MIP の時間の和が def 9〜14 秒 → 2.2 秒)。
- hs の中では `c`・`h`・`t` の 3 文字がそろって初めて遅い (1 文字抜けば戻る)。`analysis/diag_hsletters_20261031.md` の binkar10_1・dcmulti と同じ文字。

## 3. 仕組み (ログ)

`summ.py` (回 0。根ヒューは根のヒューリスティクスの終わりの時刻、サブ MIP は木の前の根のサブ MIP の時間の和):

外側の根の直列のサブ MIP (回 0):

| | def | cand |
|---|---|---|
| 並列の RENS / root reduced cost | 2.7 / 2.6 秒 | 12.9 / 9.7 秒 |
| RENS (more nodes) | 51 → 51 ノード、2.75 秒、none | 55 → 55 ノード、10.8 秒、none |

- cand は根のサブ MIP で def より良い暫定解 (8260 vs 8984) を出すが、最適値 8105 はどちらも木で見つかる。木の時間 (def 12 秒) はほぼ同じなので、
  根のヒューリスティクスに使った分 (26 秒) がそのまま遅れになる。
- 深さ 1 のサブ MIP 1 本の中 (`verbose/n5-3_cand_v.log`、直列の RINS 9.4 秒): 自分の根のカット 25 ラウンド 1.9 秒 →
  中の RENS (深さ 2) 3.6 秒 (そのカット 25 ラウンド 2.1 秒 + 木 189 ノード、停滞で停止) → **中の RENS (more nodes) 3.3 秒 (同じ 189 ノード・同じ解)** →
  自分の木 54 ノード 0.6 秒 (成果連動で停止)。並列の root reduced cost (10.3 秒) も同じ形 (中の RENS 3.5 秒 + やり直し 4.0 秒)。
- `t` があると深さ 1 のサブ MIP の時間の上限が残り全部 (約 50 秒) になり、`c` の根のカットの上限 (その 5 割) も、入れ子の RENS の時間 (その 3 割) も大きい。
  `t` を抜くと上限が残りの 7%・最大 6 秒になり、全部が縮む。

## 4. 手当ての試作 (既定では使わない)

- `ENOMOTO_MIP_RENS_MORE_NODES_REAL` (`src/mip/solver.rs` `rens_more_nodes_real`、`heuristics.rs` `solve_submip_problem`・`rens_old`):
  RENS (more nodes) のやり直しの判定 (`rens_node_limited`) を、RENS のサブ MIP のノード数がノード上限に届いたときだけ立てる。
  主のスレッドで解いたサブ MIP は `submip_full_nodes` (結果のノード数 ≥ 上限)、別スレッドに出した根の RENS は出したときの上限 (`rens_spawn_node_limit`) と比べる。
  外側の根でも、サブ MIP の中の根でも効く。
- `ENOMOTO_MIP_SUBMIP_HIGHS_DEEP` (`heuristics.rs` `hs_drop`): 深さ 2 以上のサブ MIP で使う `SUBMIP_HIGHS` の文字 (書き方は `_RESTART` と同じ。`-c` で `c` だけ抜く)。
- 既存の調整値 `ENOMOTO_T_MIP_SUBMIP_HIGHS_TIME_MAX` (`t` の時間の上限) も試した。

## 5. 判断と次

- cand の n5-3 の損は「`c`・`h`・`t` でサブ MIP 1 本が重い」×「停滞で止まった RENS をノード上限 4 倍で同じように解き直す空回り」。
  後者は形の問題 (やり直しても結果が変わらない) なので、`ENOMOTO_MIP_RENS_MORE_NODES_REAL` は cand にも def にも足してよい候補。
  n5-3 の損の約 6 割 (時間切れ → 44 秒) を消し、得は残る。
- 残り (cand+real 44 秒 vs def 33 秒) は直列の RINS (1 本 4〜12 秒、解を良くしない) と、深さ 1・2 のサブ MIP の 25 ラウンドのカット。
  消すには `DEEP=-c`・`TIME_MAX` が効くが、得の問題を削る気配がある。
- 次: cand + `ENOMOTO_MIP_RENS_MORE_NODES_REAL` を 58 問 × 2 回と Mittelmann で確かめる。残りは、根のサブ MIP が良い暫定解を出した後の
  直列の RINS を軽くする形 (暫定解が根の RINS の近傍より良くなっていれば `t` の時間を使わない、など) を試す。
