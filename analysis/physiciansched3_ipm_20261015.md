# physiciansched3-3 の内点法の歩幅が小さいまま進まない件 (2026-10-15)

develop `d58ef73` (9d7a07d を含む)。計測は 4 CPU・15 GB の機械 (`RAYON_NUM_THREADS=4`、`threads=4`)。この問題は双対化した
内点法 (`solve_ipm_crossover_dualized`) を通る。双対 LP は 24,150 行 × 130,154 列 (下限側 43,612・上限側 86,065・自由 477 列、
境界はすべて 0)、非零 53.6 万。

## 1. 結論

- 原因は **双対 LP の尺度** (行列と費用がそろっていない) で、Mehrotra 型の初期点 (全成分を同じ量だけ持ち上げる) が解から遠く、
  内点法が境界の近くを長く這う。正確な Newton 方向は行・列の縮尺で変わらないので、効いているのは尺度に依存する部分
  (初期点の一律の持ち上げ、正則化 ρI・δI) で、正則化を変えても反復は減らない (§3) ので初期点が主。
- **対策 (採用)**: 双対化した問題の内点法の前だけ、行・列を幾何平均でそろえてから平衡化する
  (`ENOMOTO_T_XO_DUALIZE_IPM_PC`、既定 3。0 で従来)。双対化しない問題の既定 (`ENOMOTO_T_XO_IPM_PC=0`) は変えない
  (全問題でそろえる案は第 41・45・48〜50 回で degen3・greenbea・ken-13・ns1688926 などが遅くなり不採用)。
- physiciansched3-3 (`ipm_crossover`): 内点法 96 → 55 反復、内点法 87 → 44 秒、合計 98.8 → 56.8 秒 (目的値は同じ
  2432694.766158786)。HiGHS の IPX は同じ双対 LP (前処理・クロスオーバーなし) で 70 反復 41 秒、元の問題で 59 反復。

## 2. 調べたこと

### 2.1 再現の道具

- `ENOMOTO_DEBUG_IPM_DUMP=ファイル`: `solve_box_lp_warm` に渡す問題 (A, b, c, l, u) を書き出す。
- `ENOMOTO_IPM_REPLAY=ファイル` で `cargo test --release --lib ipm_dump_replay -- --ignored --nocapture`
  (PyO3 の `extension-module` のため `RUSTFLAGS="-C link-arg=-lpython3.13"` が要る): 内点法だけを再生する。元の経路と反復・残差が
  完全に一致する (96 反復)。前処理・双対化を飛ばして 1 回 70 秒で試せる。
- `ENOMOTO_DEBUG_IPM=2`: 反復ごとに相補積 `s z / μ` の分布 (下限側・上限側)、修正子の後の点の相補積 / 目標の分布、歩幅を
  止めている成分 (主・双対) の `s, z, ds, dz, ds_aff, dz_aff`、方向を実行可能性の部分 (r_s = 0) と相補性の部分
  (r_x = r_y = r_z = 0) に分けたときのそれぞれの歩幅を出す (追加の求解をするので診断専用)。
  通常の `ENOMOTO_DEBUG_IPM=1` の行に予測子・修正子の Newton 系の相対残差 (`solve_rel`・`corr_rel`) を足した。

### 2.2 中心から外れているのではない

`min(sz)/μ` 1e-3〜1e-2・`max(sz)/μ` 50〜400 は **ごく少数の成分** (各反復で数個〜十数個) の値で、13 万本の 99.9% 以上は
[0.5, 2)μ に入っている。歩幅を止めている成分も `s z / μ ≈ 1` のよく中心化された成分で、反復ごとに別の成分 (主は双対 LP の
`t_j` 列 = 元の列の被約費用、双対は `y_i` 列) が止めている。止めている成分では修正子の方向が予測子の 5〜15 倍
(例: 31 反復目 `ds_aff = -1.69`、`ds = -15.6`)。

方向の分解では、遅い区間 (10〜56 反復) で実行可能性の部分だけでも歩幅 (主 0.2〜0.3、双対 ~0.1)、相補性の部分も 0.03〜0.2
で、どちらか一方のせいではない。残差と μ の比は最初の反復より小さく (近傍の条件は満たしている)、μ が残差より先に下がって
いるのでもない (`ENOMOTO_T_IPM_INFEAS_GUARD` は発動しない)。Newton 系の相対残差は 60 反復目まで 1e-14 程度で、分解の精度の
問題でもない。

### 2.3 経路: 序盤に解から遠い領域へ進み、境界の近くを這って戻る

内部の単位で最適値 -247.6 に対し、主目的値は 0 反復目 -189 → 5 反復目 +3094 と大きく行き過ぎ、μ は 0〜6 反復で 27 → 0.26 に
下がる。その後 10〜56 反復は歩幅 0.05〜0.3 で目的値を少しずつ戻す。IPX も同じ双対 LP で同じ形 (主目的値が最適値の 58 倍まで
行き過ぎ、12〜39 反復で主残差が 1 反復 15% ずつしか減らない) なので、這う区間そのものはこの LP の性質。差は這う区間を
抜ける速さで、主目的値の最適値からの相対誤差で比べると:

| 区間 | IPX | 従来 | 尺度をそろえた後 |
|---|---|---|---|
| 開始 → 主目的値が 0 を切る | 39 | 45 | 約 20 |
| → 誤差 10% | 6 | 19 | |
| → 誤差 1% | 7 | 6 | |
| → 誤差 0.1% | 6 | 8 | |
| → 停止 (+ 高精度化) | 12 | 11 + 7 | |
| 合計 | 70 | 96 | 55 |

## 4. 終盤の分解の失敗 (未対策)

従来の経路の 96 反復のうち 5 反復 (尺度をそろえた後も 3〜4 反復) は「分解に失敗して正則化を上げ、同じ点で解き直す」反復で、
それぞれ分解 1 回 (約 0.45 秒) を捨てている。正規方程式は対角をそろえておらず (成分 3e-9〜1.5e13)、動的正則化の閾値
(`ENOMOTO_T_NORMAL_PIVOT_EPS` = 1e-14) が絶対値なので、桁落ちしたピボットが置き換えられず、後の更新で非有限になる
(faer の LLᵀ は正則化が有効なら非有限のピボットでしか失敗しない)。閾値を絶対値で大きくすると序盤が壊れる (1e-2 で 13 反復目に
破綻)。対角をそろえる既存の試験用 `ENOMOTO_T_NORMAL_DIAG_SCALE=1` でも失敗は残る。相対的な閾値 (対角の元の値に比例) の
置き換えが候補だが、全問題の終盤の振る舞いが変わるので今回は見送り。

## 5. 計測 (4 CPU、`threads=4`、`ENOMOTO_T_XO_DUALIZE_IPM_PC` 3 = 新 / 0 = 従来)

双対化するのは前処理後に行数 5 万以上・行数が構造列数の 3.5 倍以上・列の平均非零 100 以下の問題だけ (Netlib・Kennington は
該当しない)。目的値・状態はすべて従来と一致。

| 問題 | 経路 | 内点法の反復 (従来 → 新) | 内点法の時間 | 合計 |
|---|---|---|---|---|
| physiciansched3-3 | `ipm_crossover` | 96 → 55 | 87.0 → 44.0 秒 | 98.8 → 56.8 秒 |
| physiciansched3-3 | `auto` | 91 → 55 | 87.8 → 53.3 秒 | **100.2 → 64.8 秒** |
| supportcase10 | `ipm_crossover` / `auto` | 29 → 29 | 同じ | 10.8 → 10.7 / 11.5 → 12.1 秒 |
| ex10 | `ipm_crossover` / `auto` | 12 → 12 | 同じ | 49.2 → 50.4 / 52.5 → 53.3 秒 |
| neos | `ipm_crossover` (3 回) | 125 → 106 | 19.1 → 20.4 秒 | 22.2・22.8・22.1 → 23.8・23.5・23.7 秒 |
| neos | `auto` | | | 25.9 → 26.5 秒 |
| neos-5251015 | `auto` | 4 → 4 | 12.4 → 12.2 秒 | 164.9 → 165.6 秒 |

- supportcase10・ex10 は双対 LP の行列の非零がすべて ±1 で、縮尺がすべて 1 (書き出して確かめた) なので経路は変わらない
  (時間の差は揺れ)。
- neos は反復が減るが、終盤 (60〜100 反復目) の Newton 系の反復改良が上限の 3 回まで回るようになり (1 回の求解あたりの改良
  0.82 → 1.69 回)、求解の時間が 9.1 → 11.3 秒に増えて合計で 1〜1.7 秒 (5〜7%) 遅い。改良の打ち切り (`REFINE_TOL` = 1e-13、
  相対残差 1e-10〜1e-12 でも続ける) は全問題に効くので今回は変えない。幾何平均だけ (`=2`) でも同じ (105 反復、求解 12.1 秒)。
- 16 スレッドの機械では未計測 (この機械は 4 CPU)。cont1・rmine15 (双対化しても 600 秒で解けない) は未計測。

## 6. 残り

- 分解の失敗 (§4) の相対的な閾値。
- neos の終盤の反復改良の回数 (`REFINE_TOL` を相対残差 1e-10 程度に緩める案は全問題の比較が要る)。
- IPX の初期点 (`ENOMOTO_T_IPM_INIT_IPX`) は尺度をそろえない問題で 96 → 84 反復だが、そろえた後は差がない (57 → 54〜59)。
  全問題の初期点を変えるので既定にはしない (Linf_520c の `ENOMOTO_T_IPM_INIT_LOCAL` と同じく比較が要る)。
