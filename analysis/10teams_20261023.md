# 10teams: HiGHS (1.6〜2.5 秒) と ENOMOTO (10〜60 秒) の差 (2026-10-23, 依頼 I)

土台: inv/heur-ls-20261023 (4361e05)。作業ブランチ inv/10teams-20261023。4 スレッド・60 秒、同じ機械 (4 コア)。
ログ: `analysis/heur_ls_20261023/logs/10teams_*.log`・`app1-1_*.log`、HiGHS は `analysis/10teams_20261023/highs.log`。

## まとめ

- **遅いのは解。下界ではない。** ENOMOTO の下界は全 6 回で 0.42〜0.54 秒 (根のカットのラウンド 0) に 924 (最適値) に届く。
- 924 の解は根の「root reduced cost」(RRC) か「LP face」のサブ MIP が見つける (取れた回は 248 ノード、2.6〜3.2 秒)。サブ MIP の時間の上限は残りの 7% (約 3.7 秒) で、ぎりぎり。外れると木で見つけるまで 25〜60 秒かかる。
- 加えて、根のカットのループが、下界が 924 で動かないのに 12〜15 ラウンド (6〜8 秒) 回っていた。分数の列の数が上下するので、SCIP 式の停滞判定が停滞と数えない。
- 手当て `ENOMOTO_MIP_CUT_INTOBJ_STALL=1` (既定では使わない): 目的値が整数刻みの問題で、目的値が一度上がった後にまったく動かないラウンドが 3 回続いたら (`ENOMOTO_T_MIP_CUT_INTOBJ_STALL`、既定 3)、分数の列の数に関係なくカットのループを止める。
- 効果 (3 回ずつ): 既定 10.1・60 (936 で時間切れ)・38.4 秒 → **5.4・10.9・5.4 秒**。mixoc 10.3・25.6・26.9 秒 → **5.5・5.3・5.4 秒**。6 回中 5 回は根で解けた (ノード 0)。
- 56 問中、この切り替えが働くのは 10teams と app1-1 の 2 問だけ。app1-1 は既定 20.2・12.7 → 10.7・10.6 秒、mixoc 15.2・11.9 → 12.4・12.2 秒 (2 回ずつ)。目的値の不一致はなし。
- 既定にする候補。働く問題が少なく、働いた 2 問では悪くならない。

## 1. HiGHS は 2.5 秒で何をしているか (事実)

HiGHS 1.15.1、4 スレッド・60 秒 (このマシンで 2.47 秒。依頼文の 1.6 秒は別の機械)。

| 項目 | HiGHS |
|---|---|
| 前処理後 | 210 行・1600 列 (全部 0-1)・9600 非零。「目的関数は刻み 1 の整数」と判定 |
| 根の LP | 917 (0.1 秒) |
| カットの後の下界 | 924 (カット 195 本、LP に 25 本) |
| 最初の解 | 924、出どころ L (サブ MIP)、2.5 秒。サブ MIP は根で 3 回・1.75 秒 |
| ノード数 | 1 |

ENOMOTO も前処理後は 210 行・1600 列で同じ大きさ。根の LP 917 も同じ。

## 2. ENOMOTO の 924 の時刻と下界の時刻 (事実、各 3 回)

| 設定 | 回 | 下界 924 | カットのループの終わり | 924 の時刻 | 924 の出どころ | 終わり |
|---|---|---|---|---|---|---|
| 既定 | 1 | 0.47 秒 | 6.22 秒 | 9.03 秒 | 根の RRC サブ MIP (248 ノード、2.7 秒) | 最適 10.1 秒 |
| 既定 | 2 | 0.49 秒 | 6.76 秒 | (見つからず、936) | RRC・LP face とも時間切れ (109・92 ノード、3.7 秒) | 時間切れ 60 秒 |
| 既定 | 3 | 0.54 秒 | 6.49 秒 | 37.77 秒 | 木 (サブ MIP は時間切れ) | 最適 38.4 秒 |
| mixoc | 1 | 0.53 秒 | 6.49 秒 | 9.72 秒 | 根の RRC サブ MIP | 最適 10.3 秒 |
| mixoc | 2 | 0.54 秒 | 7.87 秒 | 24.91 秒 | 木 (他スレッド) | 最適 25.6 秒 |
| mixoc | 3 | 0.52 秒 | 7.68 秒 | 約 26.2 秒 | 再スタート (11.73 秒) 後の木 | 最適 26.9 秒 |

- 最初の解は既定が FJ の 964 (2.2〜3.2 秒)、mixoc が Local-MIP の 1026〜1042 (0.5〜1.2 秒)。mixoc の Local-MIP は 948〜956 まで下げるが 924 には届かない。
- カットのループはラウンド 0 (0.5 秒) で 917 → 924 にした後、12〜15 ラウンド 924.000 のまま回る。「50 cuts did not move the objective」でカットの本数を増やす分岐 (widen) に入り、停滞の数え方も分数の列の数が減ったラウンドで 0 に戻る。

### サブ MIP が外れる理由 (事実と推測)

- 事実: 根の RRC のサブ MIP (1065 列が自由) を書き出し (`ENOMOTO_MIP_SUBMIP_DUMP`)、単独で 1 スレッドで解くと、ENOMOTO 1.1〜6.1 秒、HiGHS 0.15〜4.7 秒 (4 個)。どれも 924 を含む。カットの組み合わせ (行数 380〜417) で難しさが変わる。
- 事実: 時間の上限 0.07 × 残り (60 秒の問題で約 3.7 秒) に対し、取れた回は 2.6〜3.2 秒、外れた回は 80〜300 ノードで 3.6〜3.7 秒。
- 事実: RRC と LP face は多くの回で同じ固定 (535 列) になり、同じサブ MIP を 2 本並べて解いている (どちらも 248 ノードで同じ結果)。違う結果になる回もある (stall3 の 5 回目: RRC は時間切れ、LP face が 924)。
- 推測: カットのループを早く止めると、(a) サブ MIP が 4〜5 秒早く始まり残り時間が長いので上限が少し延びる、(b) LP に入るカットが少なく密でない時点の LP 解でサブ MIP を作るので、サブ MIP が易しくなる回が多い。下の試しで 11 回中 10 回が根の RRC/LP face で取れた (既定・mixoc は 6 回中 2 回)。

## 3. 試した手当て (各 2〜5 回、既定に足したもの)

| 試し | 時間 (秒) | 根のサブ MIP で 924 |
|---|---|---|
| (なし、既定) | 10.1・60 (936)・38.4 | 1/3 |
| `ENOMOTO_MIP_SUBMIP_CUTS=1` (サブ MIP にカットの行) | 28.2・10.1 | 1/2 (1 回は RRC が始まらず) |
| `ENOMOTO_T_MIP_SUBMIP_TIME_FRAC=0.15` | 8.5・9.3 | 2/2 |
| `ENOMOTO_MIP_NO_LPFACE=1 ENOMOTO_T_MIP_RRC_TIME_FRAC=0.14` | 9.9・9.6・9.1 | 3/3 |
| `ENOMOTO_T_MIP_CUT_STALL=3` (全問題で停滞 3 回、手当ての元) | 6.1・5.1・5.9・5.1・6.3 | 5/5 |
| **`ENOMOTO_MIP_CUT_INTOBJ_STALL=1`** (手当て) | **5.4・10.9・5.4** | 2/3 (残り 1 回も木で 10.2 秒) |
| `ENOMOTO_MIP_CUT_INTOBJ_STALL=1 ENOMOTO_MIP_OBJ_STEP_SKIP_FIXED=1` | 5.7・18.2・15.0 | 1/3 |

- サブ MIP の時間を延ばすのも効くが、根で待つ時間が延びるので全問題に影響する。カットのループの停滞を 3 回にするのが一番効くが、全問題では強すぎるので、整数刻みの目的値で下界がまったく動かない場合だけに絞った。

## 4. 手当て: `ENOMOTO_MIP_CUT_INTOBJ_STALL=1` (src/mip/separation.rs の root_cut_loop)

- 条件: (1) 目的値が整数刻み、(2) 外側の求解 (サブ MIP でない)、(3) 目的値が最初の LP から上がっている、(4) 前のラウンドから目的値の相対変化が 1e-9 以下。満たすラウンドが `ENOMOTO_T_MIP_CUT_INTOBJ_STALL` (既定 3) 回続いたら止める。満たさないラウンドで 0 に戻す。
- (3) は neos-1456979 (最初の 4 ラウンドは下界が動かず、続けると上がる) を止めないため。
- 整数刻みの判定は、新しい `MipProblem::objective_step_bounds` で、今の定義域で整数値に固定された連続列を整数列と同じに扱う。
  - 事実: 10teams は費用のある連続列 225 本 (定義域で 0 か 1 に固定) があり、これまでの `objective_step` (= `obj_step`) は None。HiGHS は前処理で消して「刻み 1」と判定する。
  - 同じ判定を `obj_step` (刈り込みの上限など) にも使う `ENOMOTO_MIP_OBJ_STEP_SKIP_FIXED=1` も入れたが、10teams では効果がなく (上の表)、既定にする候補ではない。

### 効果 (3 回ずつ、同じ機械)

| 設定 | 切り替えなし | `ENOMOTO_MIP_CUT_INTOBJ_STALL=1` |
|---|---|---|
| 既定 | 10.1・60.1 (936)・38.4 | **5.4・10.9・5.4** |
| mixoc | 10.3・25.6・26.9 | **5.5・5.3・5.4** |

- カットのループの終わり: 6.2〜7.9 秒 → 1.75〜2.37 秒。924 の時刻: 4.3〜4.7 秒 (5 回、根の RRC)、1 回は木で 10.2 秒。
- 6 回とも切り替えが働いた (ログの「integral objective, LP bound unchanged for 3 rounds; stop」)。
- 参考: 最初の作り (整数刻みの判定に `obj_step` を使い、10teams では None なので働かなかった) の 6 回は `analysis/10teams_20261023/*_nofire.log`。実質は切り替えなしと同じで、既定 18.4・9.3・11.8 秒、mixoc 12.8・15.8・55.5 秒。切り替えなしの揺れの大きさの参考になる。

### ほかの問題 (事実)

- `analysis/10teams_20261023/fire_scan.sh` で 55 問 (MPS のキャッシュ全部) を根のカットのループの終わりまで動かした。働いたのは 10teams と app1-1 だけ (`fire_scan.txt`)。
- app1-1 (2 回ずつ): 既定 20.2・12.7 → 10.7・10.6 秒、mixoc 15.2・11.9 → 12.4・12.2 秒。根の下界は −3 で同じ。
- 目的値の不一致: なし (10teams はすべて 924、app1-1 はすべて −3)。
- `cargo test --release --lib`: 313 通過。

## 既定にするか (推測)

- 候補。働くのは 56 問中 2 問で、どちらも速くなるか同じ。根の下界を下げる回は見ていない。
- 心配: 目的値が整数刻みで、ラウンドの途中で下界がしばらく平らになってから上がる問題では、カットのループを早く止めて根の下界が下がる可能性がある。40 問 + 16 問では該当がなかった。

## 残り

- RRC と LP face が同じ固定のサブ MIP を 2 本並べる無駄 (片方を別の固定や延長に回せる)。
- 根のサブ MIP の時間の上限がぎりぎりの問題で、外れたときに延長して試す仕組み。
