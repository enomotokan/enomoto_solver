## 3. trento1 の根: ダイブ式 RENS が悪い解を受け入れて既定の RENS を飛ばす

1 スレッドの根で、今の版は SUBFIX のダイブ式 RENS が打ち切りのサブ MIP から 4.96e9 (下界 5.18e6 の約 1000 倍、間隙 0.999) を出し、
これが「解を出した」とされて既定の RENS (LP で整数値の列を全部固定) を回さない。0.1.9 では、根の被約費用のサブ MIP が
たまたま先に 4.47e9 を出してダイブの解が受け入れられず、「SUBFIX RENS found nothing」で既定の RENS に進み 6.59e7 を出していた
(根の LP の解の違い: 今は前処理の LP probing の基底から 32 反復、0.1.9 は 12217 反復)。

- 案 rg (cargo test --release --lib 409 通過・0 失敗): 試作 `ENOMOTO_MIP_RENS_BIGGAP=g` (src/mip/heuristics.rs の `rens`、既定は使わない)。ダイブが解を出しても、
  間隙 (z − LP) / max(|z|, 1) が g を超えたら既定の RENS も 1 回回す。間隙が 0.5 を超える解は「LP の 2 倍より悪い」ので
  素の if にした (間隙の分布は verbose の `RENS_BIGGAP:` の行で、計測の P の結果と合わせて確かめる。まだ見ていない)。
- 手元 (1 スレッド、300 秒): 既存の同じ形の試作 `ENOMOTO_MIP_HEUR4=r` + `ENOMOTO_T_MIP_HEUR4_RENS_GAP=0.5` で、
  trento1 は種 1 で 2.55e7、種 2 で 2.59e7。def は種 2 で 5.01e8、0.1.9 は種 2 で 5.54e7。
  根の暫定解はどちらの種も 9.74e7 (def は 4.70e9〜4.96e9)。
- 4 スレッドでは効かない: 根で暫定解がないとき、並列の「暫定解なしの RENS」(固定率 0.8) が先に回り、ダイブ式 RENS の道を通らない
  (trento1 種 2: def 5.39e6、HEUR4=r 5.19e6。差は木の運)。4 スレッドの trento1 の揺れ (5.19e6〜3.56e7) は、木の中で
  5.2e6 台の解に届くかどうかで決まる (HEURGAP の結論と同じ)。
- 4 スレッドの道へ広げた (51a253fee、親の依頼): 根で並列のサブ MIP の解を受け取った後 (`RENS (more nodes)` の後) も間隙が g を超えるなら、
  既定の RENS を 1 回 (暫定解の値が打ち切り値、1 回の求解で 1 度、`rens_biggap_done`)。cargo test 409 通過・0 失敗。
  trento1 (4 スレッド、600 秒): 種 1・2 とも並列の RENS の解 (5.05e7・4.57e7) の後に間隙 0.85 で発動したが、既定の RENS は約 6 秒で
  解なし (打ち切り値 3.55e7 の下では見つからない)。最終は種 1 1.56e7、種 2 5.29e6 で def の揺れの幅のまま。
