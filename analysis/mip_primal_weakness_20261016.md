# MIP: 暫定解を見つける力 (主側) が HiGHS より弱い原因の調査と対策 (2026-10-16)

## 0. 要約

**原因は主に 3 つ (詳細は 3 節)。そのうち最初の解の遅さを直す変更 (HiGHS と同じ手順の Feasibility Jump、FJ2) を既定にした。**

1. **Feasibility Jump が別物で弱かった** (最初の解が遅い主因)。ENOMOTO の `fj_search` は「違反行を 1 本選び、その行の変数の値の
   候補を全部評価する」簡略版で、comp07-2idx・comp21-2idx・net12・CMS750_4 などで解を見つけられず、最初の解が根のヒューリスティクス
   (局所探索・clique など) の 10〜60 秒後になっていた。HiGHS は同じ問題で FJ (「J」) が 0.2〜1.3 秒で解を出す。
   → HiGHS と同じ手順の FJ を移植した (`src/mip/fj.rs`)。上の問題で 0.05〜0.2 秒で解を見つける。
2. **RENS・RINS が条件に合う列を全部固定し、近傍が狭すぎる**。drayage-25-23 では根の RENS のサブ MIP に 11090 列中 229 列しか
   残らず 0 ノードで実行不能。変更前の診断の 41 問で、根の RENS のサブ MIP の約 1/3 (49 回中 16 回)、カット前の LP 解の RENS の
   3/4 (20 回中 15 回) が 0〜1 ノードで実行不能だった。HiGHS は成功・失敗した固定率から目標の固定率 (初期 0.6) を決めて止める。
   → 固定率の上限 (`ENOMOTO_MIP_FIX_CAP`) を試作したが、93 問では改善と悪化が混ざり (trento1・lotsize は良くなるが rococoC10・
   noswot・10teams などが悪くなる) 採用しなかった。
3. **木の中で暫定解を磨く力が弱い**。木の中の大近傍探索 (ALNS) は経過時間の 2% (最大 10%) の予算で、1 回のサブ MIP の時間も予算の
   残りの 2 倍 (最低 0.3 秒) に抑えるので、大きな問題 (net12・rococoC10・sct2・glass-sc・lotsize) では 50 秒間に 2〜3 回しか呼ばれず、
   1 回のサブ MIP は根も解き終わらない。HiGHS は net12 でヒューリスティクスに LP 反復の 49% (サブ MIP 3 回に 18.9 秒) を使い、
   木の中の「L」(サブ MIP) で暫定解を何度も更新する。→ 予算・時間の上限を広げる設定を試したが (`ENOMOTO_T_MIP_LNS_TIME_MIN`・
   `ENOMOTO_T_MIP_SUBMIP_TIME_FRAC`)、揺れを超える改善は出ず、未解決 (6 節)。

採用した変更 (FJ2、既定。`ENOMOTO_MIP_NO_FJ2` で以前の局所探索) の効果 (93 問、4 スレッド・60 秒、各 2 回の平均):

| 集合 | 主ギャップの和 基準 → FJ2 | 最初の解の時刻 (ずらし 1 の幾何平均) | 解けた数 |
|---|---|---|---|
| A (6 問) | 2.24 → 2.55 | 24.1 → 21.3 秒 | 1 → 1 |
| B (7 問) | 0.074 → 0.051 | 3.0 → 2.5 秒 | 2 → 2 |
| C (27 問) | 6.39 → **5.33** | 6.2 → 4.5 秒 | 0 → 0 |
| 見張り (23 問) | 5.26 → 4.98 | 4.7 → 4.1 秒 | 4 → 4 |
| 既定の 40 問 | 2.16 → **1.63** (SGM 21.60 → 21.26 秒) | 1.57 → 1.16 秒 | 25 → 24.5 |
| 全 93 問 | 14.91 → **13.77 (−7.7%)** | 3.88 → **3.07 秒** | 29 → 28.5 |

目的値の不一致は 0 (解けた問題の目的値をすべて `.solu` と照合。異常終了なし)。同じ基準の 2 回で主ギャップの和が 13.94 / 15.89 と
2.0 動くので、差の大きさは揺れと同程度。それでも C・見張り・40 問がそろって良くなり、最初の解ははっきり早い。A の悪化は
neos-3381206-awhea (解が見つかるかが木の別スレッドのランダム丸めの当たりで決まる。FJ はどちらも見つけない) と dws008-01。
40 問の 0.5 問減は noswot (基準でも 41 秒前後で解ける境目の問題。FJ2 は 2 回中 1 回時間切れ) で、10teams 23.7 → 14.7 秒・
qiu 47.0 → 24.8 秒・binkar10_1 31.7 → 29.4 秒と速くなった問題もある。


## 1. 調べ方

- コード: 変更前の診断は 230c835 (依頼の計測 b38653b の 5 コミット後)。比較の基準は途中で取り込んだ develop (31740cc、のち 7d1d843 の
  implied bound カットの既定化を含む版)。HiGHS 1.15.1 (highspy)。
- マシン: 4 vCPU・メモリ 15 GB のクラウドのコンテナ。**両ソルバーとも 4 スレッド** (HiGHS は `threads=4`、ENOMOTO は
  `solve` の threads と `ENOMOTO_MIP_THREADS=4`)、60 秒、MIPLIB の元の問題 (前処理なし)。1 問ずつ順に解き、計測中は
  ほかの重い処理を走らせない。依頼の計測 (16 スレッド) とはスレッド数が違うので、問題によって結果が違う
  (app1-1 は 4 スレッドでは ENOMOTO も 15.7 秒で最適を示す)。
- 診断: ENOMOTO は `ENOMOTO_MIP_LOG=1` のログに、**暫定解の出どころ** (どのヒューリスティクスか、別スレッドなら木か
  ヒューリスティクス役か) と、並列で解く根のサブ MIP の名前・自由な列の数・所要時間を出すようにした (この調査で追加した計装。
  挙動は変えない)。HiGHS は `output_flag=true` のログの「Src」列 (J = Feasibility Jump、L = サブ MIP (RENS/RINS)、
  R = ランダム丸め、T = 木のノード、H = ヒューリスティクス、C = 中心丸め、S = LP 解) で比べた。
- 主ギャップは |z - ref| / max(|z|, |ref|) (解なしは 1)、参照値は `miplib2017-v31.solu`。
- ログ: 診断の実行 (変更前、41 問) の要約は付録 A。

## 3. 原因の分類

| 分類 | 内容 | 該当する問題 | 対策 |
|---|---|---|---|
| (1) FJ が弱い | 簡略化した局所探索で、大きな問題で解を見つけられない | comp07-2idx・comp21-2idx・net12・CMS750_4・rococoB10・supportcase18・b1c1s1・app1-1 | **FJ2 (採用)** |
| (2) 近傍の固定しすぎ | RENS・RINS が合う列を全部固定し、サブ MIP が 0 ノードで実行不能 | drayage-*・ns1830653・net12・comp07/21・istanbul・traininstance2 ほか (RENS のサブ MIP の約 1/3) | FIX_CAP (不採用、6 節) |
| (3) 木の中の改善が弱い | 大近傍探索の予算 (経過時間の 2%) と 1 回の時間の上限が小さく、大きな問題で呼べない・解き切れない | net12・rococoC10・sct2・glass-sc・lotsize・snowy・C の大半 | 未解決 |
| (4) 丸め系の連続部分の LP の反復上限 | 根で 2000 反復まで。連続変数の多い問題で整数の丸めが成功しても解にならない | trento1・istanbul・lotsize | RR_HIGHS (不採用) |
| (5) 根のヒューリスティクスの時間 | Pump・ダイビングに時間の上限がなく、大きな問題で 1 回 10〜45 秒。その間、別スレッドのサブ MIP の解も受け取れない | trento1・comp07・istanbul・net12・traininstance2 | 随時受け取り (POLL) は不採用。時間の上限 (`ENOMOTO_T_MIP_ROOT_DIVE_TIME_FRAC`) は試作のみで未計測 |
| (6) 下界側 | 根のカットで下界が上がらず、LP 解が整数解から遠い | neos-3381206-awhea・net12 (HiGHS 130、ENOMOTO 80〜93)・drayage | 範囲外 (develop の 7d1d843 で awhea は改善) |
| (7) FJ の早い解の副作用 | 質の悪い暫定解があると、根の暫定解なし用のヒューリスティクス (局所探索など) が回らず、木の中の改善も弱い | nexp-150-20-8-5・ns1830653 | FJ2 の続行 (採用)、KEEP_NOINC (不採用) |


## 4. HiGHS との手法・使い方の違い

| 項目 | HiGHS 1.15.1 | ENOMOTO (変更前) |
|---|---|---|
| Feasibility Jump | Luteberget & Sartor の FJ (跳び先の値・増分のスコア・良い変数の標本 25 個・重みの更新)。前処理後の問題で根の LP の前に回す。手間の上限 1024·nnz、改善のない間 256·nnz | 違反行の変数の候補を全部評価する簡略版。手間 50·nnz・3 秒。並列ではカットのループの終わりまでしか回さない |
| (参考) FJ の負の係数 | HiGHS の写しには、負の係数で割ったときの区間の入れ替え (参照実装の `if (cell.coeff < 0.) std::swap`) がない | 移植では参照実装どおり入れ替えた |
| RENS | LP を解き直しながら、整数値の列を目標の固定率 (成功・失敗から決める、初期 0.6) まで段ごとに固定。実行不能なら深さを半分・固定率を半分にしてやり直す | 整数値の列を全部固定 (整数列の 5 割以上が整数値のときだけ)。暫定解がないときだけダイビング式 (固定率 0.8) |
| RINS | 同じくダイビング式。分数の列のうち暫定解の側へ丸められるものも固定に加える (RINS 近傍の拡張)。木では待ち行列から取ったノードごとに、予算の範囲で毎回 | 一致する列を全部固定 (5 割未満なら根だけ補う)。木では ALNS の腕の 1 つとして 50 ノードおき・時間の予算の範囲 |
| サブ MIP の設定 | 今の LP (カットつき、効いていない行を除く) と根の基底を渡す。葉 500・ノード 200 + ノード数/20・停滞 12 ノード (推定値が打ち切り値以上のノードが続いたら止める)。強分岐の信頼度 0、ヒューリスティクスの手間 0.8、絶対ギャップ feastol × max(ギャップ, 1000) | 元の行だけ。ノード 500、時間は残りの 7% (最大 6 秒)、木の中は予算の残りの 2 倍 (最低 0.3 秒) |
| ヒューリスティクスの予算 | LP 反復の 5% (+ 序盤 1 万)。サブ MIP の反復は (1 − 固定率) 倍に割り引いて数え、総反復にも足す。木の重みが小さい間は予算を前倒し | 時間の 2% + 8%·成功率 (木の大近傍探索)。ランダム丸めなどは LP 反復の 1/20 + 1 万 |
| ランダム丸め | lock を見て丸め (上向きの lock がなければ切り上げ…)、連続部分の LP を max(1 万, 最初の根の LP の 2 倍) 反復まで | 丸めの閾値は 1 回目 0.5、後は乱数。連続部分の LP は 2 × ノードの平均 (根では 2000) まで |
| 中心丸め | 解析的中心を計算し、中心と LP 解を結ぶ線上で丸める | 内点丸め (似た考え)。41 問で解を出していない |
| 並列 | 今回の 4 スレッドでも「Using 1 max workers. Parallel search off」(木は 1 本) | 木 4 本 + ヒューリスティクス役 (条件つき) + 根の並列のサブ MIP |

## 7. 追記: サブ MIP の停滞による打ち切りと基底の引き継ぎ (採用)、ダイビング式の RINS (不採用) (2026-10-17)

6 節の残った課題 1〜3 のうち、HiGHS のサブ MIP の使い方に合わせる 3 つを実装した。

- **停滞による打ち切り** (`ENOMOTO_T_MIP_SUBMIP_STALL`、既定 12): サブ MIP の中で、暫定解があり、待ち行列から取ったノードの推定値が
  打ち切り値以上のことが 12 回続いたら止める (HiGHS の RENS・RINS・rootReducedCost のサブ MIP の `mip_max_stall_nodes` = 12)。
- **根の基底の引き継ぎ** (既定。`ENOMOTO_MIP_NO_SUBMIP_BASIS` で使わない): サブ MIP の根の LP を、呼び出し側の LP の基底 (列の状態) から
  始める (HiGHS の `rootbasis`)。前処理は列の番号を保つので列の状態はそのまま使え、行の状態は論理変数で埋めて修復する。
- **ダイビング式の RINS** (`ENOMOTO_MIP_RINS_DIVE`、不採用): LP 解が整数値で暫定解と同じ値の列 (なくなったら丸めると暫定解の値になる
  分数の列) を、目標の固定率まで段ごとに固定して LP を解き直し、残りをサブ MIP にする。RENS は既存のダイビング式

## 9. 追記: pk1 の揺れの原因と、カットの保護・共有の待ち行列の変更 (採用) (2026-10-18)
