# 試作 `ENOMOTO_MIP_PROBE_REPRESOLVE` (prr) の害の調べと直し (2026-11-06)

bench に使う環境変数: 既定 (def) は `ENOMOTO_MIP_THREADS=4` だけ、prr は加えて `ENOMOTO_MIP_PROBE_REPRESOLVE=1`。どちらも 4 スレッド
(`--threads 4`)。調べの回は `ENOMOTO_MIP_LOG=1` も付けた (`run1.py`)。直した prr の新しいつまみ `ENOMOTO_T_MIP_PRR_MIN_FIXED` (既定 1)・
`ENOMOTO_T_MIP_PRR_MIN_ROW_FRAC` (既定 0.1) は既定値のまま。

生データは `analysis/prr_harm_20261106/` (`bench58.jsonl`・`long600.jsonl`・`dray*.jsonl`・`logs/`・`pre/`)。

## 1. momentum1 の `not_solved` (34 秒で止まる)

### 事実

- 既定 (`mom_def.log`): 根の LP (二段解法) が 54 秒で終わらず時間切れ (60 秒、28422 反復)。既定でも 60 秒では根の LP が解けない問題。
- prr (`mom_prr.log`): プロービングが 90 列を固定・境界を 636 本締め、かけ直した前処理が行を 24303 -> 14953 (−38%) に減らす。根の LP は
  19.6 秒・44999 反復で `Error`、内点法 + クロスオーバーの解き直しも `Error` で、`root LP failed (Error)` -> `finish NotSolved` (24 秒)。
  60 秒の残りがあるのに諦めて `not_solved` (暫定解・下界なし) を返す。
- `ENOMOTO_DEBUG_EXT_ITERS=1` (`mom_prr_dbg2.log`): 二段解法は `refactorize returned None (singular basis)` で 12 回投げ出し、
  `x_B inconsistent ... rel 1.3e3` で摂動を掛け直し、与えた基底からの解き直しも全スラック基底からの解き直しも失敗する。数値の破綻。
- 前処理の LP による固定の基底 (かけ直す前の問題のもの) を渡さなくても (`ENOMOTO_MIP_NO_LP_PROBE=1`、`mom_prr_nolpp.log`) 9.4 秒で同じ `Error`。
  基底の受け渡しが原因ではない。
- かけ直しを 1 回にしても (`ENOMOTO_T_MIP_PROBE_REPRESOLVE_MAX=1`) 同じ。クリーク行の拡張を止めると (`ENOMOTO_MIP_NO_CLIQUE_EXTEND=1`)
  破綻せず 53 秒で時間切れ (既定と同じ止まり方)。
- 前処理の後の問題を書き出して (`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED`) LP 緩和を解くと、HiGHS は既定・prr とも 0.3 秒 (約 2000 反復)、
  ENOMOTO の LP の経路 (LP の前処理あり) も 0.3 秒で解ける。prr の問題には幅 0 < 幅 < 1e-6 の行が 19 本ある (既定の問題は 0 本。
  既定の問題には幅 < 1e-6 の列が 233 本あり、prr はこれを固定している)。係数は 1.3e-9〜10。

### 推測

- 壊れるのは整数最適化の根の LP (`TwoStageLp`、拡張したクリーク行つき) の数値の扱いで、かけ直した問題 (+ クリーク行の拡張) がたまたま
  特異な基底に入りやすい形になった。幅の極めて狭い行 19 本が疑わしいが確かめていない。根の LP の失敗で諦める作りは既定の経路にもある
  (既定では momentum1 で起きないだけ)。

### 直し (prr の経路の中だけ)

`solve_problem` (外側の求解) で、prr が有効で、かけ直しを実際にした (`PRR_APPLIED`) のに外側の最初の根の LP が二段解法でも内点法でも
解けずに諦めた (`ROOT_LP_FAILED`、`solver.rs` の `root LP failed` で立てる) ときだけ、かけ直しを止めて (`PRR_OFF`) 残りの時間で解き直す
(暫定解があれば `RESTART_SOL` で引き継ぐ)。解き直しの前処理は既定とまったく同じになる (下の `prr_active`)。

- 直した prr (`mom_prrfix.log`・`logs/mom_fix_prr_momentum1_1.log`): 28 秒の残りで解き直し、既定と同じく根の LP の途中で 60 秒の時間切れ。

## 2. drayage-25-23 (既定 6.7 秒 -> prr で時間切れ)

### 事実 (`dray.jsonl`、60 秒 5 回ずつ)

| 回 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| def | 7.0 | 6.9 | 6.6 | 6.6 | 6.3 |
| prr (直す前) | 7.2 | 33.8 | 時間切れ (58.9) | 12.6 | 20.6 |

- **系統的** (bench28 の 3 回 6.2・6.7・6.4 -> 25.9・時間切れ・27.6 秒とも合う)。
- 既定は 5 回とも同じ道筋: 最初の根で clique のサブ MIP が 104549 を見つけ、再スタートの判定で「根の被約費用で新しく固定 184 ≥ 閾値 110」で
  再スタート (3 回)。
- prr は前処理のプロービングが列を 0 本固定・連続列の境界を 8 本締めるだけなのにかけ直し、行は 752 -> 732 (−2.7%)、列は 1 本しか減らない。
  ところが根のヒューリスティクスの道筋が変わり (根の被約費用・LP 面のサブ MIP が 51 ノードで実行不能 -> 500 ノードで打ち切り、clique の
  サブ MIP は解なし)、再スタートの判定の時点の暫定解が 105714 と悪く、新しく固定 65 < 110 で再スタートしない。木は下界 101208 で止まり、
  最適 101282.6 を閉じるのに 13〜60 秒かかる (rep 1 だけは RINS の後の早めの再スタートで 7.2 秒)。
- **既定の `ENOMOTO_MIP_SUBMIP_HIGHS` (`p` を含む) では、サブ MIP の前処理にも `submip = false` が渡る**。そのため prr の「サブ MIP では
  かけ直さない (`ENOMOTO_MIP_PROBE_REPRESOLVE_SUBMIP` がなければ)」判定が効かず、サブ MIP の中でもかけ直していた。根の被約費用の
  サブ MIP が同じ 5290 列の入力でも既定と別の結果になっていたのはこのため (下の直しで既定と同じ「51 ノードで実行不能」に戻った)。
  FJ だけに渡す問題の前処理 (`fj_p3_problem`) でもかけ直していた。
- prr の下では `probe_equiv_fix` (同値な 0-1 列の代入まで進むか) も常に偽になる (既定では 2 巡目の同値の組が多いと真)。

### 原因 (推測を含む)

かけ直しの得 (行 −2.7%) はほぼないのに、本体とサブ MIP の問題がわずかに変わることで根のヒューリスティクスの当たり外れが変わり、
再スタートの判定 (暫定解の質に頼る根の被約費用の固定の数) を外す。かけ直しの時間 (0.3〜0.4 秒) や固定の数が直接の原因ではない。

## 3. かけ直しが効く条件と、効かないときにかけ直さない形

### 事実 (`pre/`・`prestats.txt`・`prestats2.txt`: prr で前処理だけを走らせた最初のかけ直し)

- 58 問のうち最初の前処理でかけ直すのは 11 問だけ (ほかはプロービングが何も締めない)。かけ直しは再スタートの前処理でも起きる。
- 行が大きく減るのは momentum1・traininstance6 (38〜43%)。それ以外は 0〜4% (piperout は 9〜13%)。

### 試作 (prr の中、既定は変えない)

1. プロービングが列を `ENOMOTO_T_MIP_PRR_MIN_FIXED` 本 (既定 1) より少なくしか固定しなければかけ直さない (境界を締めただけのとき)。
2. かけ直した結果、行が `ENOMOTO_T_MIP_PRR_MIN_ROW_FRAC` (既定 0.1) の割合より減らなければ結果を捨て、かけ直さない問題 (既定と同じ問題)
   を使う。捨てるときは、かけ直しの中のプロービングが置いた同値な組 (`PROBE_EQUIV`・`PROBE_EQUIV_FORCE`) を戻す。
3. prr が効くかを `prr_active` にまとめた: 環境変数があり、安全網の解き直し (`PRR_OFF`) でも FJ_P3 の前処理でもなく、サブ MIP の前処理
   (`PRESOLVE_IN_SUBMIP`、`solve_problem_inner` が `params.submip` で立てる) なら `ENOMOTO_MIP_PROBE_REPRESOLVE_SUBMIP` もあるとき。
   `represolve_after_probe` と `probe_equiv_fix` の両方がこれを見るので、効かない所の前処理は既定と同じになる。

- drayage-25-23 (`dray_fix.jsonl`): 直した prr 7.4・7.6・7.3・7.4・7.6 秒、同じ時の既定 7.2・6.5・6.5 秒。道筋は既定と同じ
  (再スタート 3 回、サブ MIP の結果も同じ)。残りの 0.4〜0.6 秒は再スタート 3 の後の、捨てるかけ直し 1 回 (プロービングが 5 列固定、
  行 508 -> 493) と見ている (推測)。
