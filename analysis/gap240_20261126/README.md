# 他のソルバーに負けている問題の型分けと、改良の的の見積り (2026-11-26、親の依頼)

combo2 第 2 段 (MIPLIB 240 問・600 秒) の当方の結果を、既存の SCIP・HiGHS の 600 秒の結果と並べた。
当方が負けている問題を原因の型に分け、型ごとに SGM への効きを見積もって、改良の候補を値打ちの順に並べた。
大きな新しい計測はしていない。足りない数だけを、19 問で 1 回ずつ取った (3 節)。

## 3. 原因の型 (classify.txt)

- **過去の調べ**: docs/improvement_history.md と analysis/ の記録から、問題ごとの既知の原因と取り下げた案を集めた (4 節の「過去」)。

## 4. 型ごとの見積りと改良の候補 (値打ちの順)

効きは、主な型の問題で当方の時間を相手の時間まで縮めたときの、186 問の SGM の比 (1 より小さいほど縮む。解けない回は 600 秒で数えるので下限)。
「c2c の後」は、c2c を既定にしたうえで残る差。

| 型 | 問題 | 効き t1 | 効き t4 | c2c の後 t1 / t4 |
|---|---|---:|---:|---|
| 解 (1 スレッド) | 30n20b8、CMS750_4、bnatt400、neos-1171448 | 0.972 | 1.000 | 0.968 / 1.000 |
| ノード数 (分枝) | dano3_5、mcsched、swath1 | 0.987 | 1.000 | 0.988 / 1.000 |
| 根の下界 (前処理・カット) | istanbul-no-cutoff、neos-873061、net12 | 0.991 | 0.995 | 0.992 / 0.995 |
| ノードあたり | fhnw-binpack4-4、rocI-4-11 (1 スレッド) | 0.987 | 1.000 | 0.997 / 1.000 |
| 根の再スタート・縮小 | uccase12、satellites2-40、satellites2-60-fs | 1.000 | 0.997 | 1.000 / 0.997 |
| 木を閉じる (最後の 1 段) | csched008、sct2 | 1.000 | 0.995 | 1.000 / 0.995 |
| 4 スレッドだけ・根の手間 | neos859080、tbfp-network | 1.000 | 0.998 | 1.000 / 0.997 |
| 計 | 19 問 | 0.938 | 0.984 | 0.946 / 0.984 |

### 候補 1. 1 スレッドの解探し (4 問 + 従の型で 3 問、t1 で約 0.97)

- **問題と構造**: 30n20b8・bnatt400・CMS750_4 は precedence (順序) の行 + 0-1 (set_partitioning・invariant_knapsack・binpacking)。
  csched008 (t1 は解なし)・satellites2・neos-873061 も、最初の解が 159〜185 秒と遅い。
- **相手の手**: SCIP は木の途中のダイビングで解を得る (linesearchdiving 88 秒、木の LP 24 秒、locks 1 秒)。
  当方は 4 スレッドなら並列の解探し (FJ+Local-MIP・並列のサブ MIP) で 1〜8 秒に解を得るが、1 スレッドではそれが回らない。
- **過去**:
  - `ENOMOTO_MIP_T1MIX=1` (1 スレッドで FJ+LMIP を時分割) は CMS750_4 を解くが、P の 1 スレッドで +6.5% のため不採用 (t1gap_20261121 6 節)。
  - `HEUR1T` は効かず。
  - c2c (HEUR_ADAPT・FP_STAGE3_LS) で 30n20b8・bnatt400 は 1 スレッドで解ける (489・597 秒、上限ぎわ)。
- **案**: T1MIX を「暫定解がない・改善が止まった時間 (作業量)」のシグモイドで絞る形にする (常時の時分割で P を遅くしたのが取り下げの理由)。
  木の中のダイビング (目的つき・linesearch) を、暫定解がないときに強める。
- **値打ち**: いちばん大きい。ただし利く問題は 1 スレッドに限られる。

### 候補 2. 分枝 (ノード数、3 問 + 30n20b8 の従、t1 で約 0.987)

- **問題と構造**: mcsched・30n20b8 (precedence・set_partitioning)、dano3_5 (variable_bound・cardinality)、swath1。
  根の下界は並び、秒/ノードは同じか当方のほうが短いのに、木が 2.5〜34 倍大きい。
- **相手の手**: SCIP の relpscost (強分枝の子で締まった境界を probingbounds で使い、衝突・推論の得点を混ぜる)。
  pscost にすると SCIP 自身も 5〜7 倍遅い (treegap_20261121・20261123)。
- **過去**:
  - `SB_PROBEBD=1` (c2c に入っている) は swath1 で 1.8 倍速いが、30n20b8 は悪化。
  - `SB_ADAPT=1` (dano3_5・mcsched が解ける) は 4 スレッドの P で外れ。
  - `CONFLICT_WEIGHT=0.01`・cfx2 は他の問題を遅くして不採用。
  - 双対退化のノードで強分枝を省くのが 30n20b8 の分枝の 94%。
- **案**: 退化のノードで強分枝を省く判定を、退化の度合いの連続関数にする。強分枝の子の境界・衝突の得点を、信頼度つきで混ぜる (relpscost に寄せる)。
  SB_ADAPT の 4 スレッドの外れの原因を切り分けてから組み直す。

### 候補 3. 根の下界 (前処理・カット、3 問、t1 約 0.991・t4 約 0.995)

- **istanbul-no-cutoff** (aggregations・variable_bound・knapsack): SCIP は probing と linear の係数の締めを交互に回し、
  集約の多い cMIR (maxaggrsroot = 6) で根 129。
  - 過去: `PATH_STARTS` (解けた数 −2、不採用)、`PRR_TIGHT`・`ENUM_ADAPT` で 82〜84 (cutgap_20261123)。
- **net12** (set_packing・cardinality・invariant_knapsack): HiGHS の Enumeration の前処理 (8 列以下の 0-1 行を列挙) で根の LP 128。
  - 過去: `ENUM_PRESOLVE=all` で根 130。適応形 `ENUM_ADAPT=1s` は c2c に入っているが、net12 は c2c でも解けない (ノードの LP が重い)。
- **neos-873061** (precedence・variable_bound、17.5 万列): HiGHS は根で 6 回再スタートし、4558 列まで縮めて根 113.4。当方は木に入るまで 500 秒。
  - 過去: `TAB_HIGHS_RULES` (根 109〜111、30n20b8 を下げて不採用)、`ROOTLP_PRESOLVE=d` (根の LP は速くなるが全体は変わらず)。
- **案**: 前処理の後半で、probing と係数の締めの繰り返しを足す (固定 0 本でも係数が変われば回す)。
  cMIR の集約の段数を、行の長さのシグモイドで深くする。ENUM の適応の閾値を見直す (net12 は根は上がるのに解けない。候補 4 と組みになる)。

### 候補 4. ノードあたりの時間 (2 問、t1 約 0.987、c2c の後は 0.997)

- fhnw-binpack4-4 (LP の行が平均 1759 対 SCIP 約 570) と rocI-4-11 (1 スレッドの秒/ノードが SCIP の 2.6 倍)。
- c2c の `NODEROWS_ADAPT=r0k23` で fhnw は 82 → 24 秒、rocI-4-11 は 1 スレッドで 222 秒 (SCIP 207 秒) になり、**c2c を既定にすればほぼ埋まる**。
- 残りは LP の 1 反復の速さ (uccase12・bnatt400 で相手の 2.8〜5 倍遅い、lpgap_20261126)。`LU_TINY_HS=1` (1 反復 −21%) の P の確かめが次。

### 候補 5. 根の再スタートと縮小 (HiGHS 型、3 問 + 従で 4 問、t4 約 0.997)

- **問題と構造**: uccase12 (aggregations・precedence・variable_bound、連続列が多い)、satellites2 (set_partitioning・packing・cardinality)、
  csched008・sct2・neos-873061 も従の型。
- **相手の手**: HiGHS は根で被約費用・解析的中心による固定が一定の割合を超えると再スタートし、繰り返す (uccase12 は 25 回で 39970 → 11594 列)。
- **過去**: `HO4_ACFIX=d` (+`SB_NO_DEGEN_SKIP`・`SB_BUDGET_HIGHS`) で satellites2-60-fs は 500 秒で解けたが、その組 (protoscreen の hso) は P で外れ。
  `TC=i` (木の中の再スタート) は csched008 に効かず。
- **案**: 根の再スタートの判定 (今は固定の割合の閾値 16) を、固定の数と根の LP の重さの連続関数にして繰り返せるようにする。
  ACFIX は再スタートの前の固定の手段の 1 つとして、大きい 0-1 の問題だけに効くよう絞る。
- **値打ち**: 4 スレッドの SGM への効きは小さい (HiGHS 自身も揺れて解けない回がある)。ただし、大きい問題での秒/ノードも縮むので、解けた数に効く。

### 候補 6. 木を閉じる最後の 1 段 (2 問、t4 約 0.995)

- csched008・sct2 は、根の下界が並ぶか当方が上でも、最後の 1 段 (下界 172・−231.047) が上がらない。
- **過去**: `TC=i/g`、潜りの深さ、`CHILD_HIGHS`、衝突を長く持つ形、`CONFLICT_PROOF_EXPLAIN` (既定化済み) のどれでも閉じない (treeclose_20261114、treeclose2_20261117)。
- HiGHS の回し直しでは csched008 も時間切れで、相手の運の分もある。**値打ちは低い (後回し)**。

## 5. まとめ

- 負けの 19 問の半分 (a1 の 8 問 + b の 3 問) は **当方の 1 スレッドの弱さ**で、4 スレッドなら解けるか SCIP 並み。
  4 スレッドどうしで HiGHS に負ける 7 問は、HiGHS の根の再スタートと前処理 (Enumeration) の差。そのうち 3 問は HiGHS 自身も揺れて解けない回がある。
- 値打ちの順:
  1. 1 スレッドの解探し (T1MIX の絞り込み)
  2. 分枝 (退化のノードの強分枝の判定、relpscost 寄りの得点)
  3. 根の下界 (probing と係数の締めの繰り返し、cMIR の集約の段数、ENUM)
  4. ノードあたり (c2c の既定化でほぼ埋まる。残りは LP の反復)
  5. 根の再スタート (HiGHS 型)
