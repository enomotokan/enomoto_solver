# Local-MIP の手間の数え違い (`ENOMOTO_MIP_LMIP_SCORE_TICKS`) の確かめ (2026-11-25、親の依頼)

analysis/comboharm_20261124/app1-1.md で見つけた数え違いの続き。
- Local-MIP は 1 手の手間を見当 `step_work` = (行の平均の長さ + 列の平均の長さ + 1) × 見る列の数で数える。
- 候補の列は違反行の非零から選ぶので、密な列があると実際の重さ (列の長さに比例) を大きく下回る。
- 試作 `ENOMOTO_MIP_LMIP_SCORE_TICKS=1` (既定オフ) は、列の走査 (`St::for_col`) で見た非零を手間に足す。

依頼の 3 つ: (1) 早めの FJ・Local-MIP が効く問題と密な列のある問題で比べる、(2) P で比べる、(3) 同じ形の見積りがほかにないかをコードで探す。

## 3. 同じ形の見積り (1 手の手間を平均の長さで数える) がほかにないか (コードを読んで)

| 所 | 手間の数え方 | 判定 |
|---|---|---|
| src/mip/localmip.rs `LocalMip::run` の `step_work` | (行の平均 + 列の平均 + 1) × 見る列 64。16 手ごとに `16 × step_work` を手間に足し、`work_cap` の判定 (`step × step_work + lift_work`) にも使う | **同じ形** (今回の数え違い)。直しは手間にだけ足しており、`work_cap` の判定は見当のまま |
| src/mip/heuristics.rs `subheur_local_mip` (試作 `ENOMOTO_MIP_SUBMIP_HEUR` の `l`、既定では使わない) | 予算 `200 × nnz` を同じ式の `step_work` で割った手数で止める | **同じ形**。密な列のある問題では予算より多く回る (時間の期限は別に見る) |
| src/mip/tpre.rs (試作 `ENOMOTO_MIP_TPRE` の `pl`、既定では使わない) | `step_cap` = min(10 万手, 2e9 / nnz)、`w`・`g` の形で `work_cap` 5e6 (`LocalMip::run` の見当で判定) | **同じ形** (`work_cap` の判定が見当を使う) |
| src/mip/localmip.rs `chain_move` (連鎖の手) | 実際に見た候補の数 (`effort += loc.len()`) × `ENOMOTO_T_MIP_CHAIN_EFFORT_TICKS` (4) | 実数。app1-1 では連鎖の手ありで実時間 3.99 秒・手間 2.79 秒と合う |
| src/mip/localmip.rs `lift_sweep` | 見た非零 `lift_work` (門の付いたスレッドだけ手間に足す) | 実数。app1-1 では lift はほとんど回らず、門のないスレッドで足しても変わらなかった |
| src/mip/fj.rs (FJ 本体) | `reset_moves` で列の長さ、行の更新で行の長さ、`select_variable` で見た候補の数 (≤ 25) を `effort` に足す | 実数 (HiGHS の FJ と同じ数え方) |
| src/mip/heuristics.rs の局所探索 (根の `local search`、1391〜1506 行・1766 行) | 行・列の長さ、目的の行は n、重みの更新は m + 1 を `work` に足す | 実数 |
| src/mip/heur_shift.rs (shifting・int shifting など) | 列・行の長さを `work` に足す | 実数 |
| src/mip/localmip/swap.rs (集合分割の入れ替えの手、既定で使う) | `St::score2` → `St::for_col` を通る | 見当には入らないが、直し (`col_work`) では数える |

- 平均の長さの見当で数えるのは、Local-MIP の `step_work` とそれを写した 2 か所 (どちらも既定では使わない試作) だけ。
- 直しを既定にするなら、`work_cap` の判定 (localmip.rs 727 行、TPRE の `w`・`g` だけが使う) と `subheur_local_mip` の手数の上限も、同じく実数 (`col_work`) で数えるのが筋 (未実装)。
