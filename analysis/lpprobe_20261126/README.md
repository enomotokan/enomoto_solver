# lpprobe: 根の前処理の LP プロービングを速くする (2026-11-26、親の依頼)

背景: analysis/rootpar_ph_20261126 の診断 (根の重い 37 問・4 スレッド) で、前処理は計 105 秒・CPU 平均 1.99 本。LP プロービングは 32.9 秒
(cod105 21.9 秒、CPU 2.83)、プロービング (同値の巡まで) は 28.8 秒 (mzzv42z 8.7・supportcase7 5.0・30n20b8 3.8)。
プロービングの並列 (`PROBE_PAR`) は analysis/rootpar_20261122 3 節で閉じた (含意を使うプロービングは 1 回の試しが 0.2 ミリ秒前後と軽く、
窓の写しの分だけ遅くなる。速くするなら繰り返しを減らす方がよい、という見立て)。

## 0. LP プロービング ([`lp_probe`]、src/mip/mod.rs) の中身

1. **最初の LP**: 前処理の後の問題の LP 緩和を基底なしで解く (4 スレッドなら単体法と内点法の同時実行)。上限は手間
   (`ENOMOTO_MIP_PRESOLVE_WORK`、反復 × (行 + 列 + 非零) が 1.25e9) と安全網の時間。止まったら固定を試さずに終える (基底は捨てる)。
2. **子の LP**: 最初の LP の解で分数の整数列を、分数部分が 1/2 に近い順に並べ、列ごとに上の子 (x ≥ ⌈v⌉) と下の子 (x ≤ ⌊v⌋) を
   最初の LP の最適基底から双対単体法で解く (温め: 基底・LU・DSE 重みの写しを持つ状態を保存し、子ごとに戻す)。
   1 本の反復の上限 `per_lp` = 最初の LP の反復 / 4 (200〜2000)。**実行不能になった子だけが結果を生む** (反対側に締める。両方なら実行不能)。
   最適・反復の上限で終わった子からは何も得ない (打ち切り値による固定はしない)。
3. **打ち切り**: 固定が 0 のまま 8 列 (`PRESOLVE_WORK_LP_GIVEUP_COLS`) を試すか、子の反復が「最初の LP の反復 + 2e7 / (行 + 列)」を
   越えたらやめる。固定が出たら最大 3 巡。4 スレッドでは候補の窓を塊に分けて写しの LP で並べて解く (`PREPAR` の `l`、結果はスレッドの数によらない)。
4. 固定が出たら前処理をかけ直す。最初の LP の基底は「固定が出た」か「最初の LP が重い」ときだけ根の LP に渡す。

### 1.4 子の LP 1 本の手間の内訳 (`ENOMOTO_MIP_XPROF` の区間計時、cvs16r128-89・physiciansched6-2、1 スレッド、窓なし `ENOMOTO_MIP_PREPAR=pe`)

- 子の LP は反復によらず 1 本に固定の手間がかかる: cvs16r128-89 (4633 行) は 14 反復で 0.13 秒、physiciansched6-2 (12095 行) は 21 反復で 0.07 秒。
- 区間を分けると (cvs16r128-89、子 8 本): 主ループ 1.20 秒、**厳密な DSE 重みの作り直し 0.97 秒** (主ループの前の重みの初期化、
  1 本 0.12 秒)、LU の写し 0.07 秒。physiciansched6-2: 主ループ 0.12 秒、DSE 重み 0.33 秒。
- 理由: 子は保存した状態 (最初の LP の最適基底) に戻してから解く。その LU は FT 更新が 64 回を超えているので `mip_lp` は使わず
  (`n_upd64`)、引き継いだ DSE 重みは既定では使わない (`ENOMOTO_WARM_DSE` は閉じた)。そこで `ENOMOTO_MIP_DSE_INIT` の `u` (既定) の
  「温めた始動で重みが渡らなければ、その基底の厳密な重み (m 回の BTRAN) から始める」に毎回入る。**どの子も同じ基底・同じ LU から
  同じ重みを m 回の BTRAN で作り直している** (無駄の型: 同じものの作り直し)。

### 1.5 無駄の大きい所 (まとめ)

| 型 | どこで | 大きさ |
|---|---|---|
| 同じものの作り直し | 子の LP ごとの厳密な DSE 重み (同じ基底・同じ LU) | 子の LP の時間の 3〜7 割 (cvs16r128-89 0.97 / 2.4 秒、physiciansched6-2 0.33 / 0.5 秒) |
| 結果の出ない子 | 反復の上限まで走る子 (P で 41 本・11441 反復、cod105 で 7 本・11 秒)。結果を生む子 (実行不能) は `per_lp` の 0.55 倍以内で終わる | P 1.2 秒、cod105 11 秒 |
| 結果の出ない列 | 55 問中 50 問は固定 0 (8 列試してやめる) | P の子の時間の大半 (10.7 秒中) |
| 捨てる最初の LP | 止まった最初の LP の基底を捨て、根で一から解き直す (ns1116954 6.8 + 13.0 秒、cod105 1 スレッド 36.4 秒) | 問題による (`ROOTCAP p` で渡す形は逆効果で閉じている) |

## 2. 試作 `ENOMOTO_MIP_LPPROBE_FIX` (既定オフ、src/mip/mod.rs・src/simplex/slope_intercept_dual.rs)

### 2.1 `d` (結果を変えない): 子の LP の厳密な DSE 重みを使い回す

- 中身: [`lp_probe`] の子の LP の間 (`lpprobe_dse_scope`、窓の写しは塊ごと) だけ、厳密な DSE 重み (`DseState::from_basis`) を
  (行列の場所, 行の数, 基底) ごとに覚え、LU の更新が 0 回の同じ基底なら覚えた重みを返す。同じ LU からの重みはビット単位で同じ。
  決定的な手間の時計 (`crate::ticks`) は、作り直したときと同じだけ進める (作り直したときの差を覚えて足す)。
  期限で途中まで作った重みは覚えない。
- 確かめ:
  - 検査の形 (`ENOMOTO_MIP_LPPROBE_DIAG=dsecheck`: 使い回すときも作り直して比べる): cvs16r128-89 で食い違い 0。
  - `check_default.py ENOMOTO_MIP_LPPROBE_FIX=d`: 6 問一致。
  - 1 スレッドの手間の時計: noswot・cvs16r128-89・physiciansched6-2 で子の手間が既定と同じ (時計を足す前は少なく数え、
    4 スレッドの noswot で道筋が変わっていた)。
- cvs16r128-89 1 スレッド: LP プロービング 4.90 → 3.55 秒、ノード・下界・暫定解は同じ。
- P (`wide/`、58 問 × 種 1〜3、60 秒、`res_s0.jsonl`。この計測は時計を足す前の版):
  - 1 スレッド: **両方解けた 123 組でノード数がすべて同じ** (道筋が同じ)。比 0.999 [0.997, 1.001]、解けた 124 → 123
    (pk1 種 2: 既定 59.6 秒、d は 60 秒で時間切れ)。
  - 4 スレッド: 比 1.008 [0.976, 1.040]、解けた 138 → 139。1.25 倍超の遅れは physiciansched6-2 (1.56)・noswot (1.55)。
    解き直し (`shards_rep.json`、各 2 回): physiciansched6-2 は既定も 49 秒の回があり揺れ。noswot は 4 スレッドの最初の LP の同時実行で
    既定どうしでも道筋が変わる (最初の LP の反復 80・81)。
- 見立て: P では LP プロービングの子は全体の時間の 1% 未満なので、全体の比は動かない。子の LP の重い問題 (cvs16r128-89・
  physiciansched6-2・cod105 のような行の多い・密な問題) で効く。

### 2.2 `c` (結果が変わりうる): 子の反復の上限を効き目のシグモイドで縮める → 効かない

- 中身: 子の上限 `per_lp` に 2σ(L)、L = ln((固定 + 1) / (試した列 − 固定 + 1)) = 2 (固定 + 1) / (試した列 + 2) を掛ける (1 で頭打ち)。
- 確かめ (`diag3.sh` → `res_diag3.jsonl`、1 スレッド・種 1、d と dc): 固定は 12 問とも同じ (nubu 1・neos-860300 3・dcmulti 3 ほか) だが、
  手間はほぼ変わらない。**4 スレッドの窓と同じく 1 スレッドでも最初の窓 (あきらめまでの 4〜8 列) をまとめて解くので、窓の始めの
  「まだ何も試していない」値 (1) がそのまま使われる**。neos-860300 は子が安くなって反復の予算が余り、試した列が 36 → 67 に増えた。
- 固定のない問題で手間をほぼ 0 にするには、試す前に「固定が出そうか」を見分ける手がかりが要る。子の目的値の上がり方
  (縮退して 0 のまま・大きく上がる) では、固定の出る 5 問と出ない 50 問を分けられなかった。

### 2.3 (イ)・(ロ) の見込み (未試作)

- (イ) 窓をやめて列を 1 本ずつ試し、効き目のシグモイドで次の列の予算を絞る: 固定の出た 5 問の最初の固定は 1〜7 列目
  (nubu は 5〜6 列目、子の反復の累計で最初の LP の 0.5 倍)。nubu を落とさない絞り方では、固定 0 の問題でも 5〜6 列は試すことになり、
  手間は今の 1/3〜1/2 ほどにしかならない見込み。4 スレッドでは窓の並列をやめる分だけ遅くなりうる。
- (ロ) 問題の外の手がかり (前処理のプロービングの固定・含意の数など) で強さを決める: 1.2 節のデータでは手がかりを確かめていない。
- どちらも、P で子の LP が全体の 1% 未満なので、取り返せる分は小さい。

## 3. 結び (2026-11-26、親の判断)

- **LP プロービングはここで区切る。**
- `d` は結果を変えない直しとして、既定の候補に利用者へ諮る (親)。
- `c` は既定オフのまま残す (効かない: 窓の始めの値が使われる。逆効果: 余った予算で試す列が増える)。
- cod105 の 1 スレッドの最初の LP (クロスオーバーの再分解が多すぎて 36 秒で止まる) は、LP の部品の「いつ再分解するか」の判断の問題として
  HJZ2 の担当に回した (親)。(b) の「クロスオーバーに期限を付ける」形は新しい閾値になるので作らない。前処理の順の入れ替え
  (対称性を LP プロービングの前に) は LP_PROBE_AFTER_EXT の負けの記録があるので見送る。
