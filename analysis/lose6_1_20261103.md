## 1. 結論

事実:

1. **h80x6320d の差は「一定の手間」(根で待つ時間) と木の始めの強分岐**。根の下界は ENOMOTO のほうが高い (再スタートの後 6352〜6359 対 HiGHS 6341)。

     **7.6〜8.9 秒待つ** (26〜27 ラウンド、伸びは 1 ラウンド 0.5 前後で窓の判定に当たらない)。再スタートは 38〜42 秒、木の始めは 49〜56 秒。

## 2. 試作 (既定・`=0` では今までと同じ。既定の経路は変えていない)

src/mip/solver.rs のみ。

- **`ENOMOTO_MIP_LOSE6_1_STOP`** (`lose6_1_stop()`): 根のヒューリスティクスで早めの再スタートが決まったら、並列のサブ MIP の結果を受け取る
  (`join_submips(0)`) 前に `ENOMOTO_T_MIP_LOSE6_1_GRACE` 秒 (0.5) だけ待ち、まだ走っているものに止めの合図を送る (`SubmipCtl::abort` を足した。
  サブ MIP の `time_up` が真になり、その時点の解を時間切れとして返す)。値に `w` を含むと、早めの再スタートが決まった根では裏のカットを待つのを
  `ENOMOTO_T_MIP_LOSE6_1_BGWAIT` 秒 (2) までにする (再スタートの後の小さい問題でカットを回し直すので)。
  ログ `MIP: ENOMOTO_MIP_LOSE6_1_STOP: stopping 2 of 2 running parallel sub-MIPs after the early restart`。
- **`ENOMOTO_MIP_LOSE6_1_RINS`** (`lose6_1_rins()`): RINS にも「解なし」の印 (`failed_heurs`) を付け、再スタートの前に解を出さなかったら再スタートの後の根で回さない
  (今の既定では RINS は `heur_bit` の一覧になく、毎回回る)。
- **`ENOMOTO_MIP_LOSE6_1_LIGHT`** = f (`lose6_1_light()`): 暫定解があり、再スタートで新たに固定された整数列が整数列の f 未満なら、再スタートの後の根では
  軽いヒューリスティクス (`light_root_heur`: 丸め・shift-and-propagate) だけを回す (`skip_heurs` を全部立てる。RINS も飛ばす)。
  ログ `MIP: ENOMOTO_MIP_LOSE6_1_LIGHT: 8 of 64 newly fixed (< 0.2); only light root heuristics after the restart`。
- 既存の試作も組み合わせた: `ENOMOTO_MIP_EARLY_RESTART_JOIN` (並列のサブ MIP の解で暫定解が良くなったときも早めの再スタートの判定をする。
  analysis/cand_slow_neos-2978193-inde_20261031.md)、`ENOMOTO_MIP_PAR_SB` (主だけのときの強分岐を LP の複製で並列に解く。analysis/tree_parallel_profile_20261013.md)、
  `ENOMOTO_MIP_MC11FIX2=b` (analysis/mc11_wait2_20261103.md)。
- scripts/run_miplib_benchmark.py: `ENOMOTO_BENCH_HIGHS_LOG=1` で HiGHS のログを出す (調べるとき用)。

設定の名前 (`cfgs.json`): `s` = STOP=1、`sb` = s + MC11FIX2=b、`p` = PAR_SB、`sp` = s + p、`sw` = STOP=w、`swp` = sw + p、`r` = RINS、
`j` = EARLY_RESTART_JOIN、`srj` = s + r + j、`jl` = j + LIGHT=0.2、`all` = sw + j + LIGHT=0.2、`allp` = all + p。
