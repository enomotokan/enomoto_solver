# lpiter: 単体法の 1 反復の速さ (木のノードの LP) (2026-11-23、親の依頼)

依頼: 複数の負けに共通する土台の弱点として「単体法の 1 反復の速さ」を調べる。材料は bnatt400 (analysis/bnatt_20261123: 当方 約 250 µs/反復
対 SCIP 約 90 µs、行は 5400 対 4500)、fhnw-binpack4-4 (analysis/nodespeed_20261123: NODE_CLEANUP=q でも 2.84 万反復/秒 対 SCIP 5.5 万)、
neos-873061 (analysis/highsonly_20261123: ノードの LP とカットの LP が重い)。

## 0. 道具

- perf は入っておらず、入れることも許可されなかった。代わりに単体法の主ループの段階別の計時 `ENOMOTO_PROF_PHASES_EXT` (BTRAN・PRICE・
  chuzr・chuzc1・BFRT・FTRAN・x_B 更新・DSE 更新・双対更新・FT 更新・再分解と原因別の回数) と、区間計時 `ENOMOTO_MIP_XPROF` を使う。
- `dump.sh <問題> <秒> <何回に 1 回> [K=V ...]`: 1 スレッド・種 1 で解き、木のノードの最初の LP を `ENOMOTO_MIP_NODELP_DUMP` で基底・DSE 重みごと
  書き出す (30 本まで、`dumps/` はコミットしない)。ログは `logs/<問題>_dump.log.gz`。
- `cmp.py <問題> [名札] [K=V;...]`: 書き出した LP を同じ出発の基底から当方 (`cut_lp_debug` テスト、計時つき、既定は重みを引き継ぐ) と
  HiGHS (analysis/node_lp_20261106/highs_warm.py、1 スレッド・前処理なし・双対単体法) で解き直し、`res_<問題>.jsonl` に書く。
- 計測は 1 本ずつ (他と並べない)。

## 1. bnatt400 (1 スレッド 300 秒で書き出し、ノードの LP 30 本、4198〜5259 行)

木の中 (`MIP: nodelp`): 潜りの子 301 反復・54.5 ms (181 µs/反復)、兄弟 403 反復・73.2 ms (181 µs)、待ち行列 547 反復・106 ms (194 µs)、
LP の行 5250 前後 (うちカット 1290)。

同じ基底からの解き直し (30 本の合計、`res_bnatt400.jsonl`):

| | 反復 | 時間 | 1 反復 |
|---|---:|---:|---:|
| 当方 | 9593 | 1.844 秒 | **192 µs** |
| HiGHS 1.15.1 | 9039 | 1.632 秒 | **181 µs** |

当方の主ループの内訳 (1 反復 175 µs、再分解は LP 1 本あたり 0.93 回):

| 段階 | µs/反復 | 割合 |
|---|---:|---:|
| FTRAN (入る列) | 61.0 | 34.8% |
| x_B の更新 | 42.2 | 24.1% |
| BTRAN (`rho_p`) | 25.5 | 14.5% |
| FT 更新 | 11.1 | 6.3% |
| PRICE | 8.2 | 4.7% |
| DSE 更新 | 6.5 | 3.7% |
| 再分解 | 4.5 | 2.6% |
| chuzr | 4.1 | 2.3% |
| BFRT | 2.9 | 1.7% |

- FTRAN の結果の密度は平均 0.735 (行の 7 割以上が非零)、主実行不能な行のプールは平均 606 行。LP の行は元の行もカットも 1 行あたり非零 3〜4 個で
  まばら (node49: 元の行 4.2、カット 224 本 4.3、node1599: カット 1269 本 3.0) なので、密なのは基底の逆の性質 (bnatt400 の構造)。
- **事実: bnatt400 の木の LP では、当方の 1 反復も反復の数も HiGHS とほぼ同じ** (1 反復 +6%、反復 +6%)。SCIP の 90 µs との差は、単体法の
  作りではなく、LP の大きさと中身 (行 5250 対 4500、基底の逆の密さ) の差とみる (推測。SoPlex で同じ LP を解いてはいない)。

## 2. fhnw-binpack4-4 (`ENOMOTO_MIP_NODE_CLEANUP=q`、1 スレッド 120 秒、13.3 秒で実行不能を示した)

木の中: ノードの LP 7418 本・23.0 万反復 (31.0 / LP)・6.75 秒 (平均 686 行)。潜りの子 25.6 反復・0.78 ms、待ち行列 43.1 反復・1.16 ms。

同じ基底からの解き直し (30 本の合計、`res_fhnw-binpack4-4.jsonl`):

| | 反復 | 主ループの時間 |
|---|---:|---:|
| 当方 (重みを引き継ぐ、`q`) | 905 | 31.9 ms (35 µs/反復、温まると 16〜17 µs) |
| 当方 (厳密な重みから、`exact`) | 873 | 25.4 ms |
| HiGHS (既定) | **560** | (1 本 1〜3 ms、準備込み) |
| HiGHS (費用の摂動なし) | 560 | |
| HiGHS (Dantzig の価格付け、`simplex_dual_edge_weight_strategy=0`) | 792 | |

- **事実: 反復が HiGHS の 1.6 倍**。DSE 重みの出発 (引き継ぎか厳密か) では変わらない。HiGHS を Dantzig 式にすると当方に近づく (792) ので、
  当方の離基行・入る列の選び方が HiGHS の DSE ほど反復を減らせていない (原因は未特定。比率テスト (BFRT・Harris) か、二段法の点数 `Score2` か)。
- 1 反復の時間は小さい: 主ループは温まれば 16〜17 µs/反復 (計時の漏れ 1 割)。
- **LP 1 本ごとの外回りが重い** (`ENOMOTO_MIP_XPROF`、120 秒の 1 回、`logs/fhnw-binpack4-4_xprof.log.gz`):
  主ループ (`main`) 2685 ms に対し、外回りは準備 `s_*` 321 ms・`setup1` 80 ms・出発の LU `w_lu` 422 ms・`w_d` 68 ms・`outside` 98 ms・
  `impl_drop` 35 ms・`finish` 112 ms・`polish` 290 ms・行の追加と削除 42 ms で合わせて約 1.5 秒 (主ループの 55%)。LP 1 本あたり約 0.19 ms で、
  反復にして 10〜15 回分。
- LP の外では、伝播 (`m_proof` の区間: 目的・双対証明・リテラルの衝突・カットプールの伝播) が 1783 ms と大きい (nodespeed のカットプールの伝播
  1.47 秒と同じもの)。
