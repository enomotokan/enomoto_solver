# lpiter: 単体法の 1 反復の速さ (木のノードの LP) (2026-11-23、親の依頼)

依頼: 複数の負けに共通する土台の弱点として「単体法の 1 反復の速さ」を調べる。材料は bnatt400 (analysis/bnatt_20261123: 当方 約 250 µs/反復
対 SCIP 約 90 µs、行は 5400 対 4500)、fhnw-binpack4-4 (analysis/nodespeed_20261123: NODE_CLEANUP=q でも 2.84 万反復/秒 対 SCIP 5.5 万)、
neos-873061 (analysis/highsonly_20261123: ノードの LP とカットの LP が重い)。

## 0. 道具

- perf は入っておらず、入れることも許可されなかった。代わりに単体法の主ループの段階別の計時 `ENOMOTO_PROF_PHASES_EXT` (BTRAN・PRICE・
  chuzr・chuzc1・BFRT・FTRAN・x_B 更新・DSE 更新・双対更新・FT 更新・再分解と原因別の回数) と、区間計時 `ENOMOTO_MIP_XPROF` を使う。
- `dump.sh <問題> <秒> <何回に 1 回> [K=V ...]`: 1 スレッド・種 1 で解き、木のノードの最初の LP を `ENOMOTO_MIP_NODELP_DUMP` で基底・DSE 重みごと
  書き出す (30 本まで、`dumps/` はコミットしない)。ログは `logs/<問題>_dump.log.gz`。
- `cmp.py <問題> [名札] [K=V;...]`: 書き出した LP を同じ出発の基底から当方 (`cut_lp_debug` テスト、計時つき、既定は重みを引き継ぐ) と
  HiGHS (analysis/node_lp_20261106/highs_warm.py、1 スレッド・前処理なし・双対単体法) で解き直し、`res_<問題>.jsonl` に書く。
- 計測は 1 本ずつ (他と並べない)。

## 1. bnatt400 (1 スレッド 300 秒で書き出し、ノードの LP 30 本、4198〜5259 行)

木の中 (`MIP: nodelp`): 潜りの子 301 反復・54.5 ms (181 µs/反復)、兄弟 403 反復・73.2 ms (181 µs)、待ち行列 547 反復・106 ms (194 µs)、
LP の行 5250 前後 (うちカット 1290)。

同じ基底からの解き直し (30 本の合計、`res_bnatt400.jsonl`):

| | 反復 | 時間 | 1 反復 |
|---|---:|---:|---:|
| 当方 | 9593 | 1.844 秒 | **192 µs** |
| HiGHS 1.15.1 | 9039 | 1.632 秒 | **181 µs** |

当方の主ループの内訳 (1 反復 175 µs、再分解は LP 1 本あたり 0.93 回):

| 段階 | µs/反復 | 割合 |
|---|---:|---:|
| FTRAN (入る列) | 61.0 | 34.8% |
| x_B の更新 | 42.2 | 24.1% |
| BTRAN (`rho_p`) | 25.5 | 14.5% |
| FT 更新 | 11.1 | 6.3% |
| PRICE | 8.2 | 4.7% |
| DSE 更新 | 6.5 | 3.7% |
| 再分解 | 4.5 | 2.6% |
| chuzr | 4.1 | 2.3% |
| BFRT | 2.9 | 1.7% |

- FTRAN の結果の密度は平均 0.735 (行の 7 割以上が非零)、主実行不能な行のプールは平均 606 行。LP の行は元の行もカットも 1 行あたり非零 3〜4 個で
  まばら (node49: 元の行 4.2、カット 224 本 4.3、node1599: カット 1269 本 3.0) なので、密なのは基底の逆の性質 (bnatt400 の構造)。
- **事実: bnatt400 の木の LP では、当方の 1 反復も反復の数も HiGHS とほぼ同じ** (1 反復 +6%、反復 +6%)。SCIP の 90 µs との差は、単体法の
  作りではなく、LP の大きさと中身 (行 5250 対 4500、基底の逆の密さ) の差とみる (推測。SoPlex で同じ LP を解いてはいない)。

## 2. fhnw-binpack4-4 (`ENOMOTO_MIP_NODE_CLEANUP=q`、1 スレッド 120 秒、13.3 秒で実行不能を示した)

木の中: ノードの LP 7418 本・23.0 万反復 (31.0 / LP)・6.75 秒 (平均 686 行)。潜りの子 25.6 反復・0.78 ms、待ち行列 43.1 反復・1.16 ms。

同じ基底からの解き直し (30 本の合計、`res_fhnw-binpack4-4.jsonl`):

| | 反復 | 主ループの時間 |
|---|---:|---:|
| 当方 (重みを引き継ぐ、`q`) | 905 | 31.9 ms (35 µs/反復、温まると 16〜17 µs) |
| 当方 (厳密な重みから、`exact`) | 873 | 25.4 ms |
| HiGHS (既定) | **560** | (1 本 1〜3 ms、準備込み) |
| HiGHS (費用の摂動なし) | 560 | |
| HiGHS (Dantzig の価格付け、`simplex_dual_edge_weight_strategy=0`) | 792 | |

- **事実: 反復が HiGHS の 1.6 倍**。DSE 重みの出発 (引き継ぎか厳密か) では変わらない。HiGHS を Dantzig 式にすると当方に近づく (792) ので、
  当方の離基行・入る列の選び方が HiGHS の DSE ほど反復を減らせていない (原因は未特定。比率テスト (BFRT・Harris) か、二段法の点数 `Score2` か)。
- 1 反復の時間は小さい: 主ループは温まれば 16〜17 µs/反復 (計時の漏れ 1 割)。
- **LP 1 本ごとの外回りが重い** (`ENOMOTO_MIP_XPROF`、120 秒の 1 回、`logs/fhnw-binpack4-4_xprof.log.gz`):
  主ループ (`main`) 2685 ms に対し、外回りは準備 `s_*` 321 ms・`setup1` 80 ms・出発の LU `w_lu` 422 ms・`w_d` 68 ms・`outside` 98 ms・
  `impl_drop` 35 ms・`finish` 112 ms・`polish` 290 ms・行の追加と削除 42 ms で合わせて約 1.5 秒 (主ループの 55%)。LP 1 本あたり約 0.19 ms で、
  反復にして 10〜15 回分。
- LP の外では、伝播 (`m_proof` の区間: 目的・双対証明・リテラルの衝突・カットプールの伝播) が 1783 ms と大きい (nodespeed のカットプールの伝播
  1.47 秒と同じもの)。

### 2.1 同点の比率テスト (fhnw-binpack4-4 は目的がすべて 0)

- fhnw-binpack4-4 は目的がすべて 0 の実行可能性の問題 (木の LP の最適値 0) で、被約費用がすべて 0。比率テストの候補はすべて比 0 で同点になる。
  当方の BFRT は比の順の累計が `w_r` を超えた位置 `k_star` から**手前向きにだけ** |alpha| 最大を探す (Harris のパス 2)。同点の並びの先頭で
  超えると `k_star = 0` で、|alpha| によらずその列でピボットする (平均の窓の大きさ 1.07)。
- 既存の切り替えで確かめた (30 本の合計、当方だけ): 既定 905、`ENOMOTO_SIMPLEX_BFRT_GROUP=gz` (同点を組で扱う) **790**、`HARRIS2=t` 905、
  `HARRIS_WIDE=1` 905、`TINY_SKIP=1` 905、許容誤差 `ENOMOTO_T_ROW_INFEAS_TOL=1e-7` (HiGHS と同じ) 878。HiGHS 560 との残りの差は未特定。
- 木の中で既存の試作 `ENOMOTO_MIP_NODELP_BFRT_GROUP=1` (木のノードの LP だけ `gz`) を使った (`NODE_CLEANUP=q` に足す、1 スレッド):
  LP 1 本の反復 31.0 → **22.7** (SCIP 24)、ノードの LP の時間 6.56 → 5.99 秒。ただしノードが 13303 → 16881 に増え、全体は 12.8 → 13.4 秒。

## 3. neos-873061 (1 スレッド 600 秒、木のノードの LP 14 本、93460 行)

木の中: 潜りの子 13 本・平均 4286 反復・7.4 秒 / LP (深さ 11〜13 は 7169〜26657 反復で時間か反復の上限)。1 反復しない LP も 0.28 秒。

同じ基底からの解き直し (`res_neos-873061.jsonl`):

- HiGHS は深さ 5 以降の LP で 1.3 万〜6 万反復 (当方は 2〜3213 反復) で、渡した基底をほぼ使えていない (理由は未確認) ので、反復の数は比べられない。
- 1 反復: 長い LP で当方 1.5〜1.8 ms (FTRAN 約 500 µs・PRICE 約 370 µs・BTRAN 約 260 µs・双対の更新 約 140 µs、FTRAN の結果はまばら)、
  HiGHS 1.1〜2.0 ms で同程度。
- LP 1 本の固定費: 0〜2 反復の LP で当方 0.23〜0.25 秒、HiGHS 0.09 秒 (2.5 倍)。
- **決め手は LP の大きさ**: HiGHS (h1 のログ) は根の下界 112.95・L で 113.67 (55 秒) からギャップ 0.63% で「88.3% inactive integer columns」の
  再スタート (90817 行 → 10158 行、さらに 9286 行) をして、小さな LP で 7645 ノード (1 ノード約 44 ms) を解く。当方は根の下界 106.35・暫定解
  121.6 (ギャップ約 13%) で被約費用の固定が起きず、9 万行のまま木に入る。差は単体法の速さではなく、根のカット (下界) と暫定解の質。

## 4. まとめ

| 問題 | 1 反復 (当方 対 HiGHS、同じ LP・同じ基底) | 反復の数 | 主な差 |
|---|---|---|---|
| bnatt400 | 192 µs 対 181 µs | 9593 対 9039 | なし (SCIP との差は LP の大きさと中身とみる) |
| fhnw-binpack4-4 | 主ループ 16〜17 µs (木の中は外回り込みで 28 µs、SCIP 23 µs) | 905 対 560 | 同点の比率テスト (目的 0)、LP 1 本ごとの外回り |
| neos-873061 | 1.5〜1.8 ms 対 1.1〜2.0 ms | (比べられない) | LP の大きさ (HiGHS は根の固定で 9 分の 1 にする)、LP 1 本の固定費 2.5 倍 |

- **事実: 3 問とも、当方の単体法の 1 反復は HiGHS と同程度** (同じ LP・同じ基底)。「1 反復の速さ」は共通の弱点ではない。
- 差が出ているのは、(1) LP の大きさ・中身 (bnatt400 の SCIP との差、neos-873061 の再スタートの差)、(2) 目的 0 の同点の扱い (fhnw、既存の試作で
  反復は SCIP 並みになるが道筋が変わる)、(3) LP 1 本ごとの固定費 (fhnw で主ループの 55%、neos-873061 で HiGHS の 2.5 倍)。

## 5. LP 1 本ごとの固定費 (親の依頼 (a)、fhnw-binpack4-4 `NODE_CLEANUP=q`)

区間計時 `ENOMOTO_MIP_XPROF` に印を足した (`nl_start`・`nl_pre`・`nl_post` (木のノードの LP の前後)、`pol_cost`・`pol_d`・`pol_xb` (仕上げの段の中)、
どれも計時を有効にしたときだけ動く)。書き出した LP の解き直しでも `CUTLP_XPROF=1` で同じ計時が出る (`cut_lp_debug`)。

### 5.1 木全体 (1 スレッド 120 秒、13.3 秒で実行不能を示した、`logs/fhnw-binpack4-4_x2.log.gz`)

| 区間 | 合計 | 中身 |
|---|---:|---|
| 主ループ (`main`) | 2647 ms | 反復 (約 23 万) |
| 出発の LU (`w_lu`) | 420 ms | 作り直し約 2600 回: 更新 64 回到達 1210・標準形の作り直し (行の追加と削除) 713・キャッシュなし 704・基底が違う 39 |
| 仕上げの段 (`polish`) | 297 ms | 下の 5.2 |
| 準備 (`s_*`・`setup1`・`w_d`・`s_alloc`) | 約 470 ms | 価格付け・x_B・被約費用の用意など |
| `finish`・`outside`・`impl_drop`・`duals` | 約 260 ms | |
| 合計の固定費 | **約 1.45 秒** | LP 1 本あたり約 0.18 ms (全体 13.3 秒の約 11%) |

LP の外の木の処理では、伝播 (`m_proof`) 1737 ms が固定費より大きい。

### 5.2 仕上げの段 (書き出した LP 2 本、温まった回)

主ループの後に必ず通る仕上げの段 (`polish_with_true_bounds`) は、HiGHS と同じ形の費用の摂動 (`perturb_costs`) をかけた有界の双対単体法で、
入口で摂動した費用の被約費用を全部の列について計算し直し (`pol_d` 約 40 µs)、`x_B` を解き直し (`pol_xb` 約 30 µs)、終わりに真の費用で
もう一度 BTRAN と全部の列の被約費用を計算して双対実行可能を確かめる (`polish` の残り 47〜93 µs)。fhnw では仕上げの段のピボットは 0 回
(主実行不能な行 0)。入口の摂動した被約費用は、主実行不能な行が 0 なら使われないので省ける (1 本約 50 µs、木全体で 0.1 秒弱)。
終わりの真の費用での確かめは、HiGHS が最適で終わるときに主と双対を計算し直すのと同じ種類の仕事で、省くのは安全でない。

### 5.3 既存の調整値

- `ENOMOTO_T_MIP_LU_MAX_UPD=1000` (既定 64): 出発の LU 427 → 163 ms に減るが、更新の列が長くなり主ループが 11.8 → 13.5 µs/反復に重くなって
  打ち消される。全体 13.3 → 12.8 秒 (ノード 13303 → 12089 で道筋も変わる)。

### 5.4 見立て

- 固定費は fhnw で全体の約 11%。うち最大の出発の LU (3%) を大きく減らすには、行の追加・削除のときに LU を作り直さず延ばす・縮める仕組みが要る
  (HiGHS は行の追加で分解を延ばす。現状の当方は行が変わると標準形と LU を作り直す)。大きな実装の割に、得られるのは全体の数 % の見込み。
- neos-873061 は木のノードの LP が 14 本だけで、固定費 (1 本 0.23〜0.28 秒) は 600 秒のうち約 4 秒。決め手ではない (3 節)。
