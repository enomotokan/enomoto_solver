# HiGHS は根でほぼ解き切るのに ENOMOTO は木が要る問題の根の比べ (rootgap、2026-11-16)

親の依頼 (調べ A)。対象は cand1118 の M (600 秒・4 スレッド、`analysis/cand1118_20261116/res_M_s*.jsonl`) で、HiGHS が根 (1〜6 節点) で解き、
当方が木を要するか遅い 5 問。

## 2. 差の元の切り分け

### 2.1 前処理 (HiGHS の規則を 1 つずつ外す、`presolve_rule_off`)

HiGHS の前処理の大半は、Enumeration presolve (規則 16) とプロービングの係数の持ち上げ (規則 15) で行う。
`logs/highs_presolve_mzzv11.log` によると、Enumeration presolve は何十回も回り、プロービングは 3 回で行 1101・列 1440 を消して非零 53423 個を持ち上げる。

| HiGHS の設定 | mzzv11 根の LP / 根の終わり | mzzv42z 根の終わり |
|---|---|---|
| 全部 | −22419 / −21764 | −20684 |
| 列挙を外す | −22631 / −21786 | −20676 |
| プロービングを外す | −22652 / −21876 | −20680 |
| 両方を外す | **−22840** / **−21884** | **−20688** |
| 当方 | −22841 / −22007 | −20723 |

- 両方を外した HiGHS の根の LP は、当方とほぼ同じ (−22840 対 −22841)。
- 前処理の分は、mzzv11 で根の終わりに約 120 (−21884 → −21764)、mzzv42z ではほぼない。
- 当方の全行の列挙 (`ENOMOTO_MIP_HO3_ENUM=1`・`ENUM_EDGES=1`) は、衝突の組・同値の組を足すだけで、下界は変わらない (−22008・−20782)。
  行の削除・係数の持ち上げはしない。

### 2.2 カット (当方の鍵を切り替える、`ENOMOTO_MIP_DEBUG_SEPPROF` で分離器ごとに集計)

当方の分離器の 1 ラウンドあたりの候補 / 採用 (mzzv11、既定):
- 表 (Gomory 系) 460 / 8.4、implied bound 29 / 29、経路の集約 2.2 / 0.3、元の行 1.5 / 0.4。
- zerohalf とクリークは回っていない。

| 当方の設定 | mzzv11 根の下界 | mzzv42z 根の下界 |
|---|---|---|
| CAND1118 | −22007 | −20723 |
| 1 ラウンドの上限 200 (`ENOMOTO_T_MIP_ROOT_MAX_CUTS`) | −22007 | −20768 |
| HiGHS 流のカット管理 (`ENOMOTO_MIP_HIGHS_CUTMGMT=1`) | −22007 | −20730 |
| 表の行を増やす (`ENOMOTO_T_MIP_TAB_ROWS_FRAC=1`) | −22007 | −20723 |
| zerohalf を回す (`ENOMOTO_MIP_NO_ZEROHALF=0`) | −21996 | −20711 |
| **クリークのカットを根で回す (`ENOMOTO_MIP_CLIQUE_CUTS=root`)** | **−21887** | **−20690** |

- クリークのカットを根で回すと、HiGHS の「列挙とプロービングを外した形」(−21884・−20688) とほぼ同じ下界になる。
  カットの分の差は、クリークのカット (既定 `fallback` の自動の判定で、この 2 問では使わない側) でほぼ説明がつく。
- ただし根の秒は延びる (node_limit 1 の回で mzzv11 84 → 155 秒、mzzv42z 114 → 95 秒)。木の全体の時間への効きは未確認。

### 2.3 ほかの 3 問

- **irp**: HiGHS は前処理で列を 945 本消す (当方は 0)。カットの後の下界も 12142.3 で、当方の 12139.1 より強い。
  そのあと被約費用による固定で列が 70% 減るたびに再スタートし (3 回)、根で解き切る。当方は RENS の解の後に早めの再スタートを 1 回。
- **hypothyroid-k1**: どちらも根で解く。HiGHS は根の終わりで最適値 −2851 に届き、当方は −2871.7 で止まる (別の手で閉じる)。
- **tbfp-network**: 最適値 24.163 に対し、当方の根の下界は 23.758。M の HiGHS は 1 節点・250〜290 秒で解く。
  この計測の HiGHS (1.16、`mip_max_nodes=1`) は 58 秒からずっと LP の中で、600 秒で 23.50 と再現しない。
  ノード上限なしの HiGHS 1.15.1 のログが要る。

## 3. 次の改善候補

1. **クリークのカットの自動の判定** (`clique_cuts_mode` の `fallback`・`clique_auto`): mzzv11・mzzv42z では根の下界を約 120・33 上げる
   (HiGHS の前処理なしの形と同じ)。判定の条件を見直す。まず 58 問と Mittelmann の数問で、根で回す形 (`root`) と既定を比べる。
2. **プロービングの係数の持ち上げと列挙の前処理** (HiGHS の規則 15・16 に当たる。行の削除・係数の強め): mzzv11 で根の下界を約 120 上げる。
   当方の前処理のプロービングにない部分。実装の手間が大きい。
3. **irp の前処理の列の削除** (HiGHS は 945 本、当方 0): 優越列・双対の固定の類。何の規則かを HiGHS の規則の記録で確かめる。
4. **tbfp-network**: HiGHS 1.15.1 のノード上限なしの根のログを取り、根の下界の推移を見る。
