# 裏のカットのスレッドから主に DSE 重みを返す試作 `ENOMOTO_MIP_BG_RETURN_DSE` (2026-11-02)

bench17 に使う環境変数: `ENOMOTO_MIP_BG_RETURN_DSE=1` (試作の側。比べる既定の側は何も付けない)

## 何をしたか

- 裏のカットのスレッド (`CutJob`) は終わるとき、最後の LP のカットの行と最終基底を主に返していた。主はカットの行を置き換えてその基底を
  `set_basis` で入れ、LP を解き直すが、DSE 重みは渡していないので単位に近い重みから解き直していた。
- 試作 `ENOMOTO_MIP_BG_RETURN_DSE=1` (既定では使わない。既定の経路は変えない):
  - 裏のスレッドは基底と一緒に `dse_snapshot()` ((変数番号, 重み)) を `CutJob::dse` に入れる。
  - 主はカットの行を置き換え、返された基底を入れた後に、重みの数 = 行の数で番号がすべて `n + 行の数` 未満なら `set_dse_vars` で当てはめ、
    置き換えた後の LP の解き直しだけ `WARM_DSE_ONCE` を立てる。合わなければ今まで通り。
  - 行の並び: 写しの LP は主と同じ元の行 (0..m) の後にカットの行が並ぶ。主は自分のカットの行 (m..) を全部消してから返されたカットの行を
    同じ順で `add_cut_rows` (= `lp.add_rows`、選別なし) で末尾に足すので、行 i は同じ番号になる。基底の大きさの確かめ
    (`b.row.len() == num_rows`) が通れば番号はそのまま使える。ログでも、当てはめた全回で「重み k / k の基底変数が一致」(例: mzzv42z
    10717 / 10717) だった。重みが取れなかった (`not available`)・合わなかった (`not applied`) 回は 0。
- ログ (`ENOMOTO_MIP_LOG=1`): `MIP: background cuts: returned DSE weights applied (…)`、`LP solve time with the replaced cuts …s (returned DSE used)`
  (時間の行は既定でも出る)。

## 判断

- 狙いの所は効いている: 置き換えた後の LP の反復が大きい問題で減る。physiciansched6-2 1243〜6345 → 690 反復、neos-957323 782 → 356 反復
  (時間は 0.6 → 0.3 秒)。mzzv42z は 1 回増え (357 → 1093) 2 回減った (713/932 → 229/183)。他の問題は元から 1〜3 反復で差がない。
- ただし節約は 1 回の LP で最大でも数秒 (physiciansched6-2 の 6345 反復の回で 4 秒) で、60 秒の求解の結果を変えるほどではない。
- 気になる点: seymour1 は rd の 3 回とも暫定解が 411.402 (def は 411.124〜411.177) とそろって悪い。置き換えた後の LP は 1〜2 反復だが、
  重みが変わると後の LP の経路 (退化した頂点の選び方) が変わり、ヒューリスティクスの出発点が変わったと思われる (ノード数 38〜54 → 63〜78)。
  mzzv42z も rd の 2 回で暫定解が悪い。6 回ずつでは振れとの区別はつかない。
- 既定にはしない。bench17 (58 問・Mittelmann) で、`ENOMOTO_MIP_BG_RETURN_DSE=1` が全体で害がないか (特に seymour1 の暫定解) を見てから決める。

## 再現手順

```
pip install -q highspy==1.15.1 maturin
maturin build --release -o /tmp/whl && pip install -q --force-reinstall --no-deps /tmp/whl/*.whl
cd analysis/bg_return_dse_20261102
python run.py def,rd 3 0            # 7 問 × 2 設定 × 3 回、logs/<問題>_<設定>_<回>.log と res.jsonl
python agg.py > table.md            # 回ごとの表 (run 99 は動作確認の回で除く)
```
