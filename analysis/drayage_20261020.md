# drayage-25-23・drayage-100-23 を HiGHS がほぼ一瞬で解く理由の調査 (途中までで中断、2026-10-20)

- 環境: クラウドのコンテナ、**CPU 4**。コミット develop bc89ad1 (ブランチ inv/drayage、ビルドなし。親が入れた bc89ad1 の
  ビルドを使用)。HiGHS 1.15.1 (highspy)。時間上限 60 秒。
- **調査は親の指示で途中で打ち切った** (別のセッションに引き継ぎ)。ENOMOTO の 4 スレッドの実行は途中 (約 6 秒・根の
  ヒューリスティクスまで) で止めた。試作はしていない。
- 実行のスクリプトとログ: `analysis/drayage_runs/` (highs_run.py・eno_run.py・classify.py・presolve_dump.py、ログ)。

## 問題の構造 (確かめた事実)

drayage-25-23: 4630 行・11090 列 (0-1 が 11025、連続 65、目的関数は 0-1 列だけ)。行は
- 210 本: 割当の等式 (係数 ±1、右辺 1)
- 4160 本: `a x_i - 60000 x_k - t_u + t_v >= rhs` の形の big-M の時間の行 (0-1 が 2 本以下・連続 2 本)
- 65×4 本: 連続変数 (時刻) 1 本の時間窓などの行。連続変数の元の境界は [0, +inf)

つまり時間窓つきの配車 (MTZ 型の big-M) で、LP の値は big-M の行がほとんど効かない割当の緩和で決まる。

## HiGHS (確かめた事実)

| | drayage-25-23 | drayage-100-23 |
|---|---|---|
| 前処理後 | 732 行・7745 列 (0-1 7710、連続 35) | 686 行・7716 列 |
| 根の LP | 99718.79 | 103333.87 (= 最適値) |
| カット後の根 | 100121.99 (カット 1399 本、LP に 139 本) | 103333.87 |
| 最初の解 | 0.2 秒 FJ 264620 (4 スレッドでは 0.3 秒) | 0.2 秒 FJ 299137 |
| 改善 | 2.3 秒 サブ MIP「L」101344 → 再スタート (整数列の 24% が固定済み) → 3.0 秒「H」101282.65 で最適を証明 | 1.0 秒「H」103333.87 で最適 |
| ノード | 1 | 1 |

drayage-25-23 は 1 スレッド (1thr/) と 4 スレッドでほぼ同じ (HiGHS は 4 スレッドでも木は 1 本)。**drayage-100-23 の列は 1 スレッドの値** (4 スレッドは未実行)。

- HiGHS の前処理は 2 段目で 3251 行 (ENOMOTO の前処理後と同じ数) まで減らし、**3 段目で 732 行まで減らす**。前処理後の
  モデル (`presolve_dump.py`) を見ると、連続変数 (時刻) の境界が [0, inf) から幅 7200 程度の区間 (例 [22225, 29425]) に
  締まり、big-M の時間の行 4160 本のうち残るのは連続 2 本の 65 本と連続 1 本の 457 本だけ。時刻の境界が締まったことで
  big-M の行の大半が冗長 (最小の活動量でも成り立つ) になって消えたと見られる。
- drayage-100-23 では根の LP 値が最適値で、HiGHS は根のカットの後のヒューリスティクス「H」で LP 値と同じ解を見つけて終わる。

## ENOMOTO (4 スレッド、根まで。確かめた事実)

drayage-25-23 (`ENOMOTO_MIP_LOG=1`、約 6 秒で中断):
- 前処理: 4630 行 → 3251 行 (係数の強化 4054 個) → LP probing の後 **3212 行・7775 列** (1.80 秒)。HiGHS の 732 行の 4.4 倍。
- 根の LP 99718.79 (HiGHS と同じ)。
- **根のカット 6 ラウンド (585 本、平均の非零 2、毎ラウンド分離に 0.74〜1.03 秒) で下界が 99718.79 から全く動かない**
  (HiGHS は 100121.99)。カットのループに 5.9 秒。
- 最初の解: 3.76 秒に並列の FJ で 304636 (HiGHS は 0.2〜0.3 秒)。
- 根の RENS: 自由な列 280 (11090 列中) のサブ MIP が 0 ノードで実行不能 (0.02 秒)。locks のサブ MIP は 976825、
  LP face は 7710 列中 2150 列しか固定できず空振り。
- 以前の調査 (mip_primal_weakness_20261016.md、4 スレッド・旧版): 下界は 99718.79 から木でも動かず、最適値には 20〜27 秒に
  別スレッドの RINS で届くが証明できない。

## 考えられる主因 (推測を含む)

1. **前処理で連続変数 (時刻) の境界を締めていない → big-M の行が消えない** (事実: 行数 3212 対 732。推測: 境界の締め付けと
   冗長な行の削除の不足)。LP が 4 倍以上大きく、カットの分離 (0.8〜1 秒/ラウンド) も LP も遅い。さらに時刻の境界が [0, inf)
   のままだと big-M の係数の強化・フローカバー/MIR が弱く、カットが効かない一因と考えられる。ENOMOTO の probing は
   「2210 bounds tightened」と出るので境界の一部は締めているが、行の削除には結び付いていない (要確認)。
2. **根のカットが下界を上げない** (事実: 99718.79 → 99718.79、HiGHS は 100121.99。ギャップ 1564 のうち HiGHS は 26% を根で閉じる)。
   HiGHS の最後の「H」の時点で下界が最適値まで一気に上がるのは、再スタート後の (打ち切り値つきの) 縮小と、締まった
   時刻の境界での伝播が効いていると推測 (未確認)。
3. **最初の良い解が遅い**: HiGHS は根のカットの後のサブ MIP (RENS、自由な列が多い) で 2.3 秒に 101344。ENOMOTO の根の RENS は
   LP で整数値の列を全部固定して 280 列しか残らず即座に実行不能 (前回の調査と同じ)。下界が動かないことと合わせ、
   drayage-100-23 (LP 値 = 最適値) でも 60 秒で最適解を見つけられない。

## 次にやること (引き継ぎ)

- ENOMOTO の前処理後の連続変数の境界を出し、HiGHS の前処理後 (`d25_pre.mps`) と比べる。時刻の境界の伝播 (行 1 本の
  連続変数の行と big-M の行からの活動量の伝播) を前処理の不動点まで回し、最小の活動量で成り立つ行を消す、で 732 行近くまで
  減るかを試す (`ENOMOTO_MIP_...` で切り替え)。
- 時刻の境界が締まった問題で、根のカットが下界を上げるか (HiGHS の 100122 に届くか) を見る。
- 根の RENS を目標の固定率まで (ダイビング式 `ENOMOTO_MIP_RENS_DIVE`、または FIX_CAP) にしたとき、drayage-100-23 で
  LP 値と同じ解が出るか。
- 4 スレッドの ENOMOTO の 60 秒の通しの数値 (暫定解の推移・ノード数・下界) は取れていない。
