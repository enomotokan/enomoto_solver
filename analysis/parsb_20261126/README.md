# 強分枝の並列化 `ENOMOTO_MIP_PARSB` (2026-11-26、利用者の指示・親の依頼)

狙い: 主のスレッドがノードで強分枝をしている間、空いているスレッドに候補の子の LP を解かせる。まず木が分かれる前 (木の最初のノード (根) の強分枝。
4 スレッドの木の段のスレッド秒の 4.2% の遊び、analysis/paridle_20261126 1.1 節) を狙い、木の中でも待っているスレッドがあれば使う。
決定性: どの列で分枝するかは主のスレッドが今と同じ規則と順序で決め、子の LP の結果は候補の順に当てはめる。**既定はオフ。**

## 1. 今の強分枝の作り (src/mip/solver.rs `select_branch_inner`、SCIP の relpscost に倣う)

- 候補 (分数の列) を擬似費用の点数の順に並べ、観測の数が閾値 (1〜5、予算の残りで変わる) に満たない候補 (信頼できないもの) を順に強分枝する。
- 候補ごとに両方の子の LP: 分けた列の境界を置く (下の子は対称性の軌道の列も 0 に) → `lp.solve(limits_k(sb_iter_limit))` → `restore_state(saved)`。
  - 反復の上限 `sb_iter_limit` = 4 × ノードの LP の平均の反復 (10〜500)、打ち切り値 (`prune_limit`) は上限 (`SolveLimits::cutoff`) に入る。
  - 候補の間では LP に触れない (片側が切れたときの固定は定義域にだけ置く)。
- 打ち切りの規則 (候補ごとに、その候補の前に判定): 改善のない候補が lookahead (9 × (1 + 信頼できない割合)) 本続く、評価した候補が `max_tried` (100)、
  強分枝の反復の予算 (25000 + 0.125 × ノードの反復) を使い切る、時間切れ。
- 順序に依存する所:
  - (a) 子の LP 解が整数なら `try_lp_solution` で暫定解が良くなり、後の候補の打ち切り値が変わる (根の解発見スレッドからの解も同じ)。
  - (b) 両側切れで刈り、片側切れで定義域の固定 (5 個たまると解き直し)。
  - (c) `SB_PROP`・`SB_PROBEBD` (c2c の部品) では、子ごとに LP の前に定義域で伝播し、締まった境界も LP に渡す (前の候補の固定が後の候補の入力に効く)。
- 既存の取り下げた試作 `ENOMOTO_MIP_PAR_SB` は、候補をまとめて LP の複製で並列に解くが、まとめ始めの打ち切り値を使う・整数の子の連続列を解き直さない・
  `SB_PROP` と併用できない、ので逐次と道筋が変わった (tree_parallel_profile_20261013)。

## 2. 作り (`ENOMOTO_MIP_PARSB`、`parsb_flags`・`parsb_batch`・`parsb_prop`)

投機 + 当てはめでの確かめ:
- 逐次の繰り返しで信頼できない候補に来たら、その候補から、逐次でも強分枝するはずの候補 (同じ信頼度の判定) を空いたスレッドの数まで集め、子の LP を並列に解く。
  - 空いたスレッドの数: 木が分かれる前 (`pool` なし) はスレッド数、木の中では待っている木のスレッドの数 + 1。
  - 子の伝播 (c2c) のときは、主が今の定義域で衝突を作らずに伝播して LP に渡す境界の並びを求める (`parsb_prop`)。
- 主は今の逐次の繰り返しをそのまま回し、候補の順に、子の「入力」(打ち切り値のビット、分けた列の定義域、下の子の軌道、子の伝播の境界の並び) が
  先に解いたときと全く同じときだけ結果を使う。違えば逐次で解く。子の LP 解が整数のとき (暫定解の候補) も逐次で解き直す。
  使わなかった結果 (打ち切りで止まった後の候補) は捨てる。選び方・打ち切りの判定は逐次と同じ順で同じ値を見る。
- 先に解いた結果を当てはめるときは、逐次の求解の後と同じ処理 (擬似費用の観測、打ち切り、証明 `sb_child_proof_y`、反復の累計) をする。

### 2.1 結果をビットで同じにするために要ったこと (`v` = 確かめの形: 先に解いた結果を使わず逐次でも解き、状態・反復・目的値・解・双対を比べる)

1. 最初の形 (各スレッドの LP の複製で、逐次と同じく「境界を置く → 解く → `restore_state`」) では、状態・反復・目的値はビット一致したが、解が 1e-12 程度違う子が多かった
   (h80x6320d 154/314、mc11 245/300)。c2c では反復の数も違う子があった (eil33-2 17 回)。
   - `restore_state` は LP の中の全てを戻さず、子の結果が同じ LP で前に解いた子に左右される (逐次で同じ子を 2 回続けて解くと一致するが、
     複製で前の子が違うと違う。複製を主のスレッドで順に解いても違った)。
   → `PARSB` では子の LP をどれも (逐次で解くときも) 強分枝の前の LP の複製から解く形にした。主の逐次の求解も複製から解く (既定の逐次とは、この下の桁の分だけ違う)。
2. それでも別のスレッドの子は少し違った (c2c の eil33-2 18/577)。複製を主のスレッドで解くと 0。原因はスレッドごとの LP の印
   (`slope_intercept_dual::tl_flags`: DSE 重みの引き継ぎ・ポートフォリオの設定)。主の印を作業のスレッドに持ち込む (次の 1 回だけの印は除き、当てはめで下ろす)。
3. 子の LP の中の並列 (FTRAN の 2・3 本の同時、`x_B` の更新の区間分け。`rayon::current_num_threads() > 1` で入る) は、作業のスレッドを 1 本ずつの rayon の池
   (求解の間使い回す) で回して切った。毎回新しいスレッドで中の並列も使う形 (`p`) は、1 子あたり逐次の約 3 倍遅かった (スレッドの取り合いと、新しいスレッドの作業領域)。

確かめ (`ENOMOTO_MIP_PARSB=v`、4 スレッド、種 1): 不一致 0 (状態・反復・目的値・解・双対/Farkas の射線の全て)。
h80x6320d 220 回・roll3000 368 回・mc11 300 回・eil33-2 298 回 (既定)、eil33-2 598 回 (c2c)。

結果を同じにできない所 (記録):
- 逐次の既定 (`PARSB` なし) とは、子の LP を「前の子を解いた後に状態を戻した LP」で解くか「強分枝の前の LP の複製」で解くかの違いで、解の下の桁
  (と c2c では反復の数) が違いうる。`PARSB` の中では、スレッドの数・先に解いたかどうかによらず同じ。
- 次の 1 回だけの LP の印 (2・4) が強分枝の始めに立っていると、逐次では最初に解く子だけが使う。先に解いた子には持ち込まない (当てはまるときは入力が同じでも
  結果が違いうる)。確かめでは不一致 0。
- 4 スレッドの根の段は時間による判定で道筋が変わる (根の強分枝に入る前に違う) ので、`PARSB` の有無で木の最初のノードの選びを比べることはできない。確かめは同じ回の中で行った。

## 5. まとめ

- 強分枝の子の LP を空いたスレッドで先に解き、入力が逐次と同じときだけ使う形で、`PARSB` の中では結果がビットで同じ (スレッドの数・先に解いたかによらない)。
  そのために、子の LP をどれも強分枝の前の LP の複製から解く (既定の逐次とは解の下の桁が違いうる)、スレッドの LP の印を持ち込む、作業のスレッドは 1 本の
  rayon の池で回す、の 3 つが要った。
- 根の強分枝は 1.7〜2.5 倍速く、P の 4 スレッドで 0.981 [0.966, 0.995]、解けた数は同じ、食い違い 0。採用の目安を満たす (既定は変えていない)。
- 木の中の強分枝: 待っている木のスレッドがあればその数だけ使う (今の作り)。木のスレッドが全部働いているときは使わない。各スレッドが自分のノードで強分枝する
  ときにほかのスレッドを借りる形は、借りたスレッドの木の探索が止まるので、木の段の遊びが少ない (1〜2%) 今の 4 スレッドでは得が小さいと見て作っていない。
