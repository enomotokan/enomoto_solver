# divebudget (2026-11-27): 木の中のダイビングの LP 反復の上限を SCIP の式にし、種類を UCB1 で選ぶ試作

試作 `ENOMOTO_MIP_DIVEBUDGET`・`ENOMOTO_MIP_DIVESEL` (どちらも既定は切。既定の道筋は変わらない)。

背景: Fnaw の LSDIVE の調べで、木の中のダイビングの時間が SCIP よりずっと少ない (既定では木の時間の 0.4% 前後) ことが分かった。
SCIP は種類ごとに上限を持つが、当方は全種類で 1 つの上限を共有し、見つからないと上限が 0 に向かって縮む。

## 1. 中身

### 1.1 上限の式 (`ENOMOTO_MIP_DIVEBUDGET=1`、`db`)

SCIP の `heuristics.c` の `getDivesetIterLimit` と `heur.c` の SolSuccess をそのまま移した (種類ごと)。

```
上限 = maxlpiterquot (0.05) × (SolSuccess + 1) / (NCalls + 1) × NNodeLPIterations + maxlpiterofs (1000) − その種類の NLPIterations
SolSuccess = 10 × nbestsolsfound + nsolsfound   (当方は成功 1 回を 11 と数える: 見つけた解はその時点の最良解なので両方に入る)
```

- **MINLPITER = 10000** (SCIP の `heuristics.c` の定数、`DIVE_MINLPITER`)。1 回のダイビングの上限は max(残り, 使った分 + 10000)、
  LP 1 回の上限は max(残り, 10000) (SCIP の `solveLP`)。当方の今の LP 1 回の最低 1000 の代わり。
- **lpsolvefreq = 0、lpresolvedomchgquot = 0.15** (SCIP の既定値): 固定のたびに LP を解き直さず、変数の 15% を超えて範囲が縮んだら解き直す。
  当方の LineSearch の複数固定 (`ls_multi`) と同じ形なので、`dive_scip` のとき全種類でそれを使う。
- 新しい閾値は作っていない (3 つとも SCIP の既定値)。ダイビングを続ける条件 (深さ < 10・候補の減り・反復 < 上限 かつ 目的値 < 探索の上限) は移していない。
- 選び方は今の巡回のまま (上限に余裕のある最初の種類)。

記録の誤りの訂正: DIVEQUOTA の `s` の式 (1 + 10 × (成功 + 1)/(呼んだ数 + 1)) は SCIP と違う (SCIP は (10 × 最良解 + 解 + 1)/(呼んだ数 + 1)、「1 +」はない)。
LSDIVE の README の式は最良解の重み 10 が抜けている。

### 1.2 種類の選び方 (`ENOMOTO_MIP_DIVESEL`)

- `u`: 種類を UCB1 で選ぶ (ALNS-CP と同じ形)。まだ呼んでいない種類は無限大 (1 回ずつ試す)。平均は 100 回までは単純平均、その後は 0.9 / 0.1 の指数平均。
  利得 = 相対改善 (z0 − z1)/max(|z0|, 1) / (1 + 使った反復 / ノードの平均反復)。暫定解がなかったときに見つければ相対改善は 1。
  上限は今の共有のまま。暫定解がない間の巡回のダイビングの枠 (NOINC_BANDIT が切のとき) も、6 種類から UCB1 で選ぶ。
  `ENOMOTO_MIP_LSDIVE` が付いていれば LineSearch も候補にする。
- `b`: 種類ごとの上限 (1.1 と同じ)。`ub` は UCB1 で、上限に余裕のある種類の中から選ぶ。
- `g` (`ubg`): 上限の割合 0.05 にギャップの係数 2·laplace(gap, その種類の呼んだ数) を掛ける。
  - laplace(x, n) = (x·n + 1)/(n + 2) (src/mip/adapt.rs。T1PRIMAL v2 の s = 0.25·σ(logit h + logit f + logit g) と共通)。
    項が 1 つなので σ(logit(·)) は値を変えず、省いた (HsTC の指摘)。
  - gap = (z − lb)/max(|z|, |lb|, 1) を [0, 1] に収めたもの (`Solver::gap_frac`)。暫定解なし・下界なしは 1。
  - 情報がないとき (n = 0) は 1 (ub と同じ)、上は 2 未満 (振り切れない)。MINLPITER の最低保証は残す。

### 1.3 DIVEQUOTA との違い

| | DIVEQUOTA `s` / `e` (objdive_20261121) | DIVEBUDGET / DIVESEL `b` |
|---|---|---|
| 上限の式 | `s`: (1 + 10 × (成功 + 1)/(呼んだ数 + 1)) × 0.05 × ノードの反復 + 1000 (SCIP と違う)。`e`: 使った手間で割る独自の式 | SCIP の getDivesetIterLimit そのまま (最良解の重み 10) |
| LP 1 回・1 回のダイビングの最低 | 今の 1000 | SCIP の MINLPITER 10000 |
| LP の解き直し | 固定ごと | lpsolvefreq 0・domchgquot 0.15 (複数固定) |
| 選び方 | 巡回 | `b` は巡回、`ub` は UCB1 (反復あたりの改善) |
| 割合の調整 | `ENOMOTO_T_MIP_DIVEQUOTA_FRAC` | なし (`g` はギャップと回数だけで決まる係数) |

### 4.3 まとめ

- SCIP の式の上限にすると、木の中のダイビングの反復が 30〜40 倍になる (木の時間の 0.4% 前後 → 10〜50%)。
  CMS750_4・30n20b8・trento1 のように、解を早く見つける問題はある。
- ただし P では 1・4 スレッドとも sgm(1) が約 5% 悪くなり、1 スレッドでは解けた数が 5〜6 減った。
  UCB1 で選んでも (ub)、ギャップで絞っても (ubg) ほとんど変わらない。
- 当方の木はノードの LP が SCIP より重いので、反復を同じ割合でダイビングに回すと、ノードを解く時間が足りなくなると見ている。
  どれも既定にはしない (試作として残す。既定は切)。
