# neos-2978193-inde: 「根のカットが LP に残るから木が大きい」の確認 (2026-10-20、2 回目)

- 環境: Linux x86_64、**CPU 4** (専用コンテナ、計測中は他の重い処理なし)、ブランチ `inv/neos2978193-r2-20261020`
  (develop 0542795 + 前の調査の試作 02372a3 を取り込み + このメモの試作。どれも既定では無効なので既定の動作は 0542795 と同じ)、
  highspy 1.15.1 (パッチなし)
- 計測: **4 スレッド** (ENOMOTO `ENOMOTO_MIP_THREADS=4` + `solve(..., 4)`、HiGHS `threads=4`、`mip_rel_gap=0`)、時間上限 300 秒、
  打ち切り値なし。数字は `solve` の呼び出しの実時間とノード数 (全スレッドの合計)。ソルバーは同時に 1 つだけ。
- ログ・スクリプト: `work_r2/` (`*.out` と結果。木のログ `*.err` は大きいので追跡しない) (`exp.sh` 1 回の実行、`summ.py` 結果と葉の LP の行数、`run_highs.py` HiGHS 1 回、`batch*.sh` 計測の並び)。
  葉の LP の行数は `ENOMOTO_MIP_TREE_LOG` の `ENODE ... rows=` (主スレッドの分だけ)

## 結論

- **推測「根のカットが LP に残るため木が大きい」は、ENOMOTO でも HiGHS でも成り立たない** (事実、下の 1・2)。
  - ENOMOTO: カットを LP から早く外すほど木は**大きく**なる。HiGHS と同じ年齢の付け方 (試作 `ENOMOTO_MIP_CUT_AGE_HIGHS`) で
    木の LP を HiGHS 並み (葉の中央値 470〜490 行) にすると 21000〜36000 ノード・2 回は 300 秒で時間切れ (既定 8859〜23307 ノード)。
    根のカットなしも 22769〜30415 ノード。
  - HiGHS: `mip_lp_age_limit=32767` (根のカットを年齢で外さない) でも木は崩れない (種 0/1/2 で 1787/1046/926 ノード、既定 1720/7570/3637)。
    前の調査で「ノードでの分離を止めると崩れる」(`mip_allow_cut_separation_at_nodes=false`) は、根のカットが残るためではなく、
    ノードでの分離そのもの (プールのカット・衝突カットを LP に戻す、新しいカットを作る) が止まるためと見るのが自然 (推測)。
- 再スタートのカットを問題の行にしない既存の `ENOMOTO_MIP_RESTART_CUTS_TO_POOL` は、この問題では 6 回 72.7〜114.2 秒 (中央値 88.5、
  既定と同等の 13 回は 77.7〜174.1 秒・中央値 106.3) とやや良いが、木の LP の行はほとんど減らない (再スタート後の根のカットのループが
  入れ直す) ので「行が減ったから」ではない。再スタートする他の問題で悪化する (mik-250 約 2 倍、mas76 1.5 倍、neos-911970 の gap 悪化。§5) ので
  既定にする候補ではない。
- 毎ノードの分離 (`ENOMOTO_MIP_NODE_CUTS`) は木を約半分 (4631〜9973 ノード) にするが、LP の行が増え (葉の中央値 1180〜1430、最大 1900)
  1 ノードが重くなり、時間は縮まない (86〜160 秒)。
- **直す試作で効いたものはない**。原因 (木の差) は特定できていない。

- 再スタート: どの設定でも 1 回 (8 列固定)。既定は再スタートでカット約 400 本を問題の行にし、再スタート後の問題は 799〜863 行。
  TO_POOL / READD でも、再スタート後の根のカットのループが 440〜460 本を LP に入れ直すので、木の LP の行はほとんど変わらない (1110〜1190 行)。
- 既定の年齢の付け方では木の LP は 700 行より下がらない: 上限を 10 にしても、論理変数が非基底のカットは**双対値が 0 でも**年齢 0 に戻る。
  この問題は双対退化が強く (退化の係数約 31、前の調査)、退化して効いているだけのカットが外れない。HiGHS は非基底で双対値が 0 なら年齢を
  変えない (`HighsLpRelaxation::performAging`、下の 3)。HiGHS と同じにすると (試作) 行は 400〜600 行に下がるが、木が大きくなる。
- 毎ノードの分離の時間 (`ENOMOTO_MIP_LOG` の `node diag`、主スレッド): 既定 3081 ノード・分離 11 回・ノードの LP 43.6 秒 (平均 1061 行、

  行が増えた LP が重い。NODE_CUTS の行は既定の年齢では外れず 2000 行近くまで増える (上と同じ理由)。
- 木の形 (既定、主スレッドの分): 葉は深さ 16〜21 が中心 (HiGHS は前の調査で 13〜15)。終わり方は LP の目的値 61%、伝播 39%。

## 2. HiGHS: 根のカットを LP に残す (4 スレッド、300 秒、`mip_rel_gap=0`)

| 設定 | 種 0 | 種 1 | 種 2 |
|---|---|---|---|
| 既定 | 31.5 秒 / 1720 | 114.4 秒 / 7570 | 58.6 秒 / 3637 |
| `mip_lp_age_limit=32767` (年齢で外さない。上限 32767) | 32.7 / 1787 | 25.7 / 1046 | 18.4 / 926 |

- 注意: 最初に `mip_lp_age_limit=1000000` を与えた回は上限 32767 を超えて**設定が拒否され** (`checkOptionValue: ... above upper bound`)、
  既定と同じ木になった。上の表は 32767 でやり直したもの。
- HiGHS は年齢の上限を変えても木の大きさは種の揺れ (1720〜7570) の中。根のカットが残ること自体は HiGHS の木を崩さない。

## 3. HiGHS 1.15.1 のカットの年齢 (ソースで確認した事実)

- `HighsLpRelaxation::performAging(deleteRows)`: カットの行ごとに、論理変数が基底なら年齢 +1 (`deleteRows` でなければ年齢が 0 でないものだけ)、
  非基底で |双対値| > 双対の許容誤差なら 0 に戻す、非基底で双対値 0 なら変えない。外すのは `deleteRows` のとき (分離のラウンドの後
  `HighsSeparation::separationRound` と、分離しないノード) だけで、上限 `mip_lp_age_limit` (既定 10) を超えたもの、`agelimit/2` 回に 1 回。
- 木の中の分離 (`HighsSeparation::separate`) は待ち行列から取り出したノードで、目的値が伸びる間ラウンドを繰り返す
  (プールのカット = 衝突カットを含む、を LP に戻すのもここ)。

## 6. 推測 (確かめていない)

- ENOMOTO の LP では根のカットが木で効いている (外すと木が大きくなる)。HiGHS の LP ではカットの有無で木がほぼ変わらない (前の調査:
  分離器を全部止めても 389〜1058 ノード)。HiGHS の木を小さくしているのは LP の強さではなく、衝突カット (双対証明から作る短いカット) の
  伝播とノードでの分離 (前の調査の 1)。ENOMOTO で証明を短くし CMIR で強めても (前の調査の試作) 木は変わらなかったので、残る違いは
  (a) 伝播の仕方 (HiGHS はカットプールと衝突プールの伝播を行の伝播と同じ不動点で回す。ENOMOTO の証明のプールの伝播
  `apply_dual_proofs` が同じ締め付けを出すか)、(b) 分枝の列の選び方 (HiGHS のスコアはほぼ衝突スコア)、のどちらかと見る。
  同じノード (同じ境界) で両者の伝播の結果を並べるのが次の一手。
- 4 スレッドの実時間は既定で 78〜174 秒と 2 倍以上揺れる。2 回ずつの比較では 20〜30% の差は判別できない。
