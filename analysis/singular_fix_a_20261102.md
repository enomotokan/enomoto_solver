# 渡した基底が特異なとき、特異の原因の列だけをスラックに差し替えて warm start する試作 (singular_fix_a、2026-11-02)

analysis/basis_nb_diag_20261102.md の 2〜4 節: warm start で渡した基底の LU が特異だと `warm_start_basis` が失敗し、全スラック基底
(crash) から解き直している (共有の待ち行列のノードの 36%、再スタートの後の根の 89%、前処理の LP の基底からの根の 69%、サブ MIP の根の 82%)。
並列の 3 つのうちの A として、どこから来た基底にも効く汎用の修復を src/simplex 側に入れて試した (B: 共有の待ち行列のノードの基底を受け取る側、
C: 前処理の基底からの根・再スタートの根の基底の元の直し。src/mip/solver.rs は触っていない)。

- 土台: `base_commit.txt` (4f3428162 + このブランチの src/simplex の変更。flbgx の既定化 89e721bbc の前)。既定・試作とも同じバイナリで環境変数だけを変えた。
- 生データ・台本: analysis/singular_fix_a_20261102/

## 1. 何をしたか

`ENOMOTO_SIMPLEX_WARM_SING_REPAIR` (既定 0 = 今まで通り。既定の経路は変えない):

| 値 | 振る舞い |
|---|---|
| 1 | 渡した基底の LU が特異なら、既存の部品 `basis_kernel::factorize_basis_repair` (HiGHS の rank deficiency の扱い。稠密切替なしの疎な Markowitz 分解でピボットの取れなかった列を、取れなかった行のスラックに差し替える) で基底を直し、残りの基底で warm start する。外れた列は非基底になり、今の warm start の規則 (被約費用の符号の側。希望 `WARM_NB` があればその側) で置かれる。修復もできなければ今まで通り crash |
| 2 | 1 と同じだが、差し替えた基底で非基底列を置いたとき費用のずらしが 1 列でも要るなら諦めて crash (差し替えた基底が双対実行可能なときだけ使う) |
| 3 | 1 と同じだが、差し替える列が `ENOMOTO_T_WARM_SING_REPAIR_MAX` (既定 100) 列を超えるなら諦めて crash |

場所: src/simplex/slope_intercept_dual.rs の `warm_start_basis` (正則な基底では `refactorize` と同じ分解で、何も変わらない)。

診断:

- `ENOMOTO_MIP_NB_DIAG` の行に `n_rep` (差し替えて使った LP)・`sum_rep` (差し替えた列の和)・`it_rep`/`t_rep`、特異で捨てた LP の `it_noeff`/`t_noeff` を足した (src/simplex/nb_diag.rs)。
- `ENOMOTO_SIMPLEX_WARM_SING_AB=1`: 渡した基底が特異な求解を、crash と差し替えた基底 (=1) の両方で解き、反復・時間・目的関数値・
  差し替えた基底の費用のずらしの数・主実行不能な基底変数の数を `SING_AB` の行に出す (返すのは差し替えた側)。同じ LP での比べ用。

- 差し替えた基底は、主実行不能な基底変数が m の 2〜6 割あり、費用のずらしの要る列も多い。**特異な基底は差し替える列だけが悪いのではなく、
  全体が今の LP に合っていない** (B・C の調べた元の壊れ方。受け取る側の行の食い違い、列の状態だけの基底) ので、差し替えても crash より
  遠いことがある。特に差し替える列が数百〜数千の前処理の基底からの根は大きく損。

  数十列以下、前処理の基底からの根で数百〜数千列ときれいに分かれたので、=3 (100 列で切る) を作った。

## 5. LP の答え

netlib.org にはこの環境から届かない (プロキシで 403) ので、HiGHS のリポジトリの check/instances にある Netlib の 15 問 (25fv47・80bau3b・
adlittle・afiro・e226・etamacro・greenbea・israel・perold・scrs8・shell・stair・standata・standgub・standmps、ほかに woodinfe・forest6・gas11) を
既定と =1 (いちばん広く効く設定) で解いた (`lp_check.py`・`lp_check.jsonl`)。15 問とも目的関数値は既定と =1 で同じで HiGHS と相対 1e-6 で一致。
woodinfe (実行不能) も同じ。forest6・gas11 は既定・=1 とも同じ結果 (HiGHS と食い違うが、この試作の前からのもの)。純粋な LP では
特異な基底からの warm start はほとんど起きない。

## 6. 判断

- **既定にはしない**。=3 は 10 問で -12.4% (3 回) だが 58 問では -1.1% (1 回) で揺れの範囲を出ず、pk1・misc07 のように遅くなる問題もある。
- 差し替えそのものは正しく働き (特異で捨てた LP がほぼ 0、目的関数値の食い違いなし)、同じ LP では反復が減る問題 (neos-911970 -40%、noswot -25%) と
  増える問題 (swath1 4 倍、neos5 1.3 倍、前処理の基底からの根 1.1〜8 倍) がある。差がつくのは渡す基底の質で、**特異になるほど壊れた基底は
  直しても crash より遠いことが多い**。B (共有の待ち行列のノードの基底を非特異に、`ENOMOTO_MIP_POOL_BASIS_FIX`) と C (`ENOMOTO_MIP_ROOT_BASIS_FIX`) が
  元を直したあとで、残った特異の受け皿として =3 を重ねるのがよいと考える (元が直れば差し替えは数列で済み、得の側に寄る見込み)。
- 次に試すなら: B・C の試作と =3 を重ねた計測。=3 の閾値 100 列は 10 問から決めた値で、m に比例させるかは未検討。
