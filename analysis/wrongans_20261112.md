## 4. 続き: 実行不能な小さな MIP を「最適 -5」と答える (OBJINT が見つけた seed14、既定の動き)

台本・生データは `analysis/wrongans_20261112/seed14/`。例は `analysis/objint_20261112/wrong_seed14.py` (34 列・4 行、HiGHS は Infeasible)。

### 結論

- 誤りは 2 つ重なっていた (事実)。どちらか一方を直せばこの例は正しく実行不能になる (単体テストで両方とも確かめた)。
  1. **前処理: 費用 0 のスラック列の消去 (`src/presolve/slackcol.rs`) が、区間の空な範囲制約 (`L > U`) の行の組から列を消して、
     実行不能な行を実行可能な行に変える**。範囲制約 `L <= r + a x_j <= U` を 2 本の `<=` (符号を反転した組) で持つとき、
     `x_j` を消して `r <= U - mn`・`r >= L - mx` に緩める。`L <= U` なら正しいが、`L > U` でも `a x_j` の値域 `[mn, mx]` が広ければ
     緩めた 2 本は満たせてしまう。この例では `x32 - x33 >= 2` (3 行目) と `x33 - x32 >= 6 x13` (2 行目) から、伝播で 0-1 列が 0 に
     固まった後に `x32 - x33 ∈ [2, 0]` (空) の組が残り、x33 (費用 0、伝播で有限の境界) を消して行が消えた。
  2. **安全網: 前処理なしの解き直しが、前処理した問題で作った対称性の控え `SYM_ORIG` を消さずに使う**。後処理した点が元の問題で
     実行不能なので前処理なしで解き直す (正しい) が、`SYM_ORIG` (前処理した問題。列の数は元と同じ 34) が残っていて、木の
     `try_incumbent` がその問題で実行可能な点を「対称性の行にだけ反する解」とみなし (`ENOMOTO_MIP_SYM_ORIG_CUT`)、打ち切り値に
     使った。解き直しの根の LP は実行不能と分かるが、`finish` が `orig_best` を答えにして「最適 -5」を返した
     (ログ `MIP: returning the solution feasible only without the symmetry rows`)。
- 「行にも目的にも出ない 17 列を外すと正しい」は、`ENOMOTO_MIP_THREADS` の違い (fuzz_objint.py は 1 を置く) によるもので、
  1 スレッドなら 17 列を外しても誤る。2 スレッドでは 1. は同じく起きるが、2. が起きずに正しく実行不能になる (理由は追っていない)。
  縮めた最小の形は 3 列 (0-1 の x1 (費用 -5)・x32 ∈ [1, 58]・x33 ∈ [-4, inf)) と 2 行 (`x33 - x32 >= 0`・`x32 - x33 >= 2`)。
- 切り分け: `ENOMOTO_DBG_SKIP=<縮約>` で縮約を 1 つずつ飛ばすと、`slackcol` を飛ばしたときだけ前処理が実行不能を返す。

### 直し (既定、`=0` で以前の形)

- `ENOMOTO_PRESOLVE_SLACK_COL_RANGE` (src/presolve.rs `slack_col_range_on`、src/presolve/slackcol.rs): 反転した 2 行の組では、列を消す前に

## 5. 根の緩和が非有界で終わる問題を実行不能と非有界に分ける (`ENOMOTO_MIP_UNB_FEAS`、cand1113 の fuzz_slack seed 240)

台本・生データは `analysis/wrongans_20261112/unbfeas/`。例は `analysis/cand1113_20261112/slack240.py` (束 cand1113 で `ENOMOTO_MIP_HNFPRE=0` のとき
HiGHS の Infeasible に対して `infeasible_or_unbounded`)。作業は別の作業ツリー (`git worktree`) で、58 問の計測のビルドは動かさずにした。

### 事実

- slack240 は `ENOMOTO_MIP_HNFPRE=0` のとき前処理の後の根の LP が非有界 (`Root LP: no finite optimum`) で、`resolve_unbounded_root` が区別を
  求められていない (`Model.solve` の `distinguish_infeasible_unbounded` の既定は偽) ので、そのまま `InfeasibleOrUnbounded` を返していた。
  区別を求められたときにだけ、切片問題 (論文の式 (8)、緩和は下に有界) を整数に制限して目的 0 で解き、整数解があれば非有界・なければ実行不能と
  していた。
- 整数解がないのは、等式 `7.5 x1 - 4.5 x2 - 7.5 x4 - 7.5 x5 - x8 = 7` の合同式と境界・ほかの行の組み合わせ (x8 = 1 なら
  `5 x1 - 3 x2 - 5 x4 - 5 x5 = 4` で gcd は 1、整数解そのものはある)。等式 1 本の gcd の検査だけでは見つからず、HNF (`bounds`) が要る。
- 切片問題 (目的 0) を前処理ありで解くと、目的が全部 0 の問題で働く早めの FJ/Local-MIP (`ENOMOTO_MIP_FEAS_FJ_EARLY`、時間の上限がなければ
  10 秒) が整数解のない問題で 10 秒空回りしていた (slack240 で 10.1 秒、木は 0.06 秒で実行不能を示していた)。

### 直し (既定、`=0` で以前の形)

- `ENOMOTO_MIP_UNB_FEAS` (src/mip/solver.rs `unb_feas_on`・`resolve_unbounded_root`): 区別を求められていなくても、根の緩和が非有界なら
  実行可能性の問題を解く。暫定解があれば非有界。切片問題が作れない (基底の情報がない) ときは目的 0 にした元の問題を解く (以前は
  `InfeasibleOrUnbounded`)。この実行可能性の問題を解く間 (`UNB_CHECK`、src/mip/mod.rs) は:
  - 早めの FJ/Local-MIP を飛ばす。
  - `ENOMOTO_MIP_HNFPRE=0` でも HNF を `bounds` で使う (src/mip/hnf.rs `mode`)。合同式で実行不能が分かる問題を、上限のない整数列の木の探索に
    任せると終わらないことがある (親の指摘)。
  - 区別を求められていないときは時間を `ENOMOTO_T_MIP_UNB_FEAS_SECS` (既定 60 秒) までにし、結論が出なければ以前どおり
    `InfeasibleOrUnbounded` にする (区別を求められたときは今までどおり残りの時間を全部使い、時間切れは `TimeLimit`)。
- 回帰テスト `mip::tests::unbounded_root_relaxation_is_split_into_infeasible_or_unbounded` (前処理なしで解く。slack240 の 12 列 → Infeasible
  (前処理ありでも)、右辺を 6 にした形 → Unbounded、`2 x - 2 y = 1` (上限のない整数 2 本、目的 -x) → Infeasible かつ 30 秒以内)。
  既定と `ENOMOTO_MIP_HNFPRE=0` で通り、`ENOMOTO_MIP_UNB_FEAS=0` (と `HNFPRE=0`) で落ちる。

### 58 問・Mittelmann に非有界の問題はあるか (事実)

- 58 問 (`analysis/cbcimpl_20261029/probs.py`): solu では全部 `opt`。非有界・実行不能の問題はない。
- Mittelmann (`analysis/cbcimpl_20261029/mitt_parts.json` の 186 問): 非有界はない。実行不能が 5 問 (bnatt500・cryptanalysiskb128n5obj14・
  fhnw-binpack4-4・neos-3988577-wolgan・neos859080)。これまでの記録 (analysis/ 以下の jsonl) で `infeasible_or_unbounded` を返したのは
  hnfcut_20261107 の MIPLIB の非有界の問題 (solu が `unbd`) 10 問と gas11 だけで、58 問・Mittelmann にはない。直しは根の LP が非有界のとき
  だけ働くので、58 問・Mittelmann の速さには影響しない見込み。
- MIPLIB の非有界の問題 4 問 (1 スレッド・120 秒、HNF・上限の直しの前の版): menik・maipo・linge は根の LP が 120 秒で終わらず (直しは働かない)。
  kolva は 8.5 秒で根の緩和が非有界になり、切片問題を残りの時間で解いても整数解が見つからず時間切れ (直す前 (`UNB_FEAS=0`) は 19.2 秒で
  infeasible_or_unbounded)。60 秒の上限を入れた最後の版では 9.1 秒で根が非有界、切片問題は 69.1 秒で時間切れ、80.7 秒で
  infeasible_or_unbounded (`unbd_def2_kolva.log.gz`)。こうした問題 (整数解が見つけにくい非有界の問題) では、以前より最大 60 秒ほど遅く
  同じ答えになる (上限は `ENOMOTO_T_MIP_UNB_FEAS_SECS` で変えられる)。
