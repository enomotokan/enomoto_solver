# 80bau3b 目的関数値不一致(rel 1.55e-3)の原因分析

- 日付: 2026-09-21
- 対象: NETLIB `80bau3b`(n=9799, m=2262, nnz=21002、等式行 0 / `<=` 35 / `>=` 2227、単項行 158)
- 症状: `ours_obj=988755.5438361148` vs `highs_obj=987224.1924090902`(相対誤差 1.551e-3)。ours の解は元問題に対して実行可能(境界違反 2.7e-12、行違反 4.9e-12)だが最適でない(目的値が高い)。
- 分類: **正答性バグ(presolve の縮約が不正)**。398aed9 の postsolve 統合や extended_dual の変更ではなく、**7baad18 で `dualpropagate` に追加された「dominated column」列固定**が誤った固定を行っている。悪条件・退化・ピボット選択・初期基底・postsolve 復元順は無関係。

## 1. 結論

ボトルネックとなっている正答性バグは `src/presolve/dualpropagate.rs:215-227`(双対箱の制約行 t-row 生成)と `:283-294`(列固定の読み出し)、およびそれを適用する `src/presolve.rs:571-574` にある。

`dualpropagate::run` は「列 j の現在の上界 `ub[j]` が元境界 `orig_ub[j]` より狭い(= propagate が導いた implied bound)なら、j は元の境界に張り付けないので reduced cost `r_j >= 0`」という双対制約を立てる(下側は対称に `r_j <= 0`)。しかし直前の `propagate::propagate`(`src/presolve.rs:509` → `src/presolve/propagate.rs:182`)は、**その implied bound を導いた行自身を「冗長」として行集合から落としている**(80bau3b では多項行 2079 本のうち 58 本)。落とされた行の制約内容は tightened bound という形でしか残らないため、現在の行集合上では当該境界は implied ではなく「本物の制約」であり、最適解でその境界に乗った列の reduced cost は非零になる(乗数が落とした行から境界へ移る)。従って `r_j >= 0` は現在の双対空間の**すべての**最適双対解で偽になり、双対箱は最適双対解を1つも含まない。その箱から区間演算で「`r_j` が全域で正」と判定された列(TE1CNU1W 等)が誤って下界に固定され、最適値が押し上げられる。

round 1 で 106 列、round 3 で 1 列が固定され、そのうち少なくとも 15 列は HiGHS の最適解と矛盾する(TE1CNU1W/2W/5W/8W は HiGHS では上界に乗り reduced cost が -27〜-45)。

### 2.2 固定列の検証(HEAD 計測ビルド、`DPFIX` 出力 107 件)

- round 1: `implied_equalities=371 fixed_columns=106`、round 3: `fixed_columns=1`。
- 107 件中 15 件で HiGHS の最適解が固定先の境界に乗っていない。うち 4 件(TE1CNU1W=8262, TE1CNU2W=8263, TE1CNU5W=8264, TE1CNU8W=8265)は HiGHS では上界に乗り reduced cost が -27.1/-45.2/-5.3/-10.0 と強く負。dualpropagate はこれらに `r_j ∈ [0.67, 1.00]`(8262)等、全域正と判定して `lb=0` に固定した。
- 残り 11 件(RU*BR1.N 等)は HiGHS で内点(rc=0)。目的値の差 1531.35 はこれら固定の総和。

### 2.3 双対箱が最適双対解を含まないことの直接検証

計測ビルドで round 1 の `dualpropagate::run` に渡された系(P1: G行 2021 本、A行 0 本、列 9799、コスト・境界はスケール後)と t-row 8482 本(kind 0: `ub=inf` 1432、kind 1: implied ub 4713、kind 3: implied lb 316、kind 4: G行の符号 2021)、伝播後の箱をダンプし、以下を確認した。

1. **P1 は元問題と等価**: P1 を HiGHS で解くと 987224.1924090905(反復 2987)。P1 に round-1 の固定 106 件を加えて解くと **988755.543836115** = ours_obj と一致。つまり固定が唯一の原因。
2. **`propagate::propagate` 自体は正確**: Rust 実装を Python で再現し、ダンプされた箱と全成分一致。さらに t-row 系上で `min r_8262(d)` を HiGHS で LP として解くと 0.6733 で、区間演算の下限 0.6733 に一致(箱は t-row 系の正確な緩和であり、伝播に不具合はない)。
3. **t-row のうち kind 1/3 が P1 の双対空間で偽**: P1 の最適双対解 d1(HiGHS の row_dual の符号反転)で t-row を検査すると 288 本が違反(kind 1: 171、kind 3: 117、kind 0/2/4: 0)。違反 288 本すべてで、ソース列は P1 最適解でその "implied" bound にちょうど乗っており、reduced cost が非零。
4. **`r_8262 >= 0.67` を支えている制約は 6 本**(LP の双対乗数が非零のもの): kind 0 ×4、kind 4 ×1、kind 1 ×1(t-row 2210、ソース列 5306 RU1NN1.E)。列 5306 の tightened ub 132.54(スケール後、元境界は +inf)は **現在の行集合 + 元境界のもとでは implied ではない**(`max x_5306` が Unbounded)。TE1CNU8W(8265)についても同様に kind 1 の t-row 2881(列 6027 RU8NN1.N、tightened ub 11.10、Unbounded)が唯一の非自明制約。
5. **P1 の行集合 + 元境界(P2)の最適値は -6.57e7**: 落とされた 58 行は冗長ではなく、tightened bound の形でのみ制約が残っている。

具体例(列 5306 RU1NN1.E、MPS 境界 [0, +inf)、コスト 1.291):
- 元行 523 `LU1NN..E`: `-RU1NN1.E + ZU1NN..E >= 0`。propagate はここから `ub(RU1NN1.E) = ub(ZU1NN..E)` を導き、その直後に行 523 を最大活動 ≤ rhs として**削除**(`propagate.rs:182`)。
- 元問題の最適解では行 523 は活性(activity 0)で双対値 y=33.97、x_5306=102.7 は内点(rc=0)。
- P1 の最適解では x'_5306 = 132.542 = ub'(境界に張り付き)、rc' = -26.32。行が無いので乗数は境界に移る。
- dualpropagate は `orig_ub=inf > ub'` を見て kind 1 の t-row「`r_5306 >= 0`」を立てる(`dualpropagate.rs:219-221`)。これは P1 のすべての最適双対解で偽。
- この偽制約が箱を狭め、TE1CNU1W(行 1845 `MU1E1...` で列 5306 と同居)の `r_8262` の区間下限を 0.67 に押し上げ、`rlo > TOL` で lb=0 に固定(`dualpropagate.rs:290-291`、適用は `presolve.rs:571-574`)。真の最適解では TE1CNU1W は上界 9.877 に乗る。

### 2.4 HiGHS との比較

| | ours (HEAD) | HiGHS |
|---|---|---|
| 総時間 | 0.45-0.58s | 0.12-0.15s |
| presolve 後サイズ | 8677 cols / 1823 rows(列固定無効化時 8805/1806) | 8427 cols / 1640 rows / nnz 18635 |
| 反復回数 | 2900(extended_dual 主ループ) | 3097 |
| 目的値 | 988755.5438361148(誤り) | 987224.1924090902 |

時間差は「1反復が重い」分類(反復数は同程度)だが、本件の主題は正答性であり、時間の分析は行っていない。HiGHS の HPresolve は implied bound をモデル境界に書き戻さず別配列(`implColLower/Upper` と `colLowerSource/Upper`)に保持し、implied bound を根拠にした双対符号制約をその行自身の双対境界計算には使わない(筆者の理解、要確認)。本ソルバでは `propagate` が tightened bound を `lb/ub` に書き戻したうえで導出元の行を削除するため、同じ論法が成立しない。

## 3. 機序のまとめ

1. `presolve.rs:509` の `propagate` が行 R から列 j の implied bound を導出し `lb/ub` に書き込む。
2. 同じ `propagate` 内(`propagate.rs:182`)で、R が tightened bound のもとで冗長になったとして `real_rows` から落とす。この時点で「R の制約」は「j の境界」に置き換わっている。
3. `dualpropagate.rs:219/224` は `orig_ub > ub`/`orig_lb < lb` を見て「j は境界に乗らないから `r_j` の符号が定まる」という t-row を立てる。現在の行集合では j の境界は本物の制約なので、この t-row は最適双対解で偽。
4. 偽の t-row を含む系を `propagate`(正確)で伝播した箱は最適双対解を含まず、区間演算(`dualpropagate.rs:275-289`)が他列の `r_j` の符号を誤判定して固定(`:290-293`)。
5. 固定列は `presolve.rs:571-574` で `lb=ub` にされ、以降の全パスと解法はその誤った問題を正しく解くので、実行可能だが最適でない解が返る。

なお t-row の元境界比較は「`propagate` が tightened bound を書き戻す」設計と、「その導出元の行を落とす」設計の**組み合わせ**で破綻する。どちらか一方だけなら論法は成立する。

## 4. 改善候補(効果の見積もりとリスク)

1. **kind 1/3 の t-row 生成をやめる**(`dualpropagate.rs:219,224` の `|| orig_ub[j] > ub[j] + TOL` / `|| orig_lb[j] < lb[j] - TOL` を外し、`ub==+inf` / `lb==-inf` のみを使う)。最も安全。80bau3b では列固定無効化と同等の結果になる見込み(検証済みの列固定無効化ビルド: 目的値一致、時間 0.53s vs 0.45s、反復 3013 vs 2900、presolve 後 8805/1806)。副作用は縮約力の低下(implied bound 由来の implied equality / 固定が減る)。他問題への時間影響は 93 問スイープで要計測。
2. **implied bound の導出元行を落とさない、または落とした列を t-row 生成から除外する**。`propagate` が「行 R を落としたときに R が境界を更新した列」を記録し、dualpropagate でその列の kind 1/3 t-row を生成しない。縮約力を保てるが `propagate` の内部状態追跡が必要で、round をまたいだ伝播(前 round で落とした行由来の境界)も追う必要があり、実装リスク中。
3. **HiGHS 方式: tightened bound をモデル境界に書き戻さず implied bound として別管理する**。根本対策だが presolve 全体の設計変更で影響範囲が大きい。
4. 7baad18 のメッセージに同じ「既存バグ」として挙がる **bnl2 / czprob(および greenbea の偽 infeasible)** が同じ機序でないか、`ENOMOTO_DEBUG_DUALPROPAGATE=1` と本分析の列固定無効化ビルドで確認する(未検証、仮説)。
5. 運用: 「以前は一致していた」の根拠は該当コミットを実ビルドして得ること。今回は JSON 記録(別系統のソースで計測)とコミットの対応が取れておらず、原因コミットの誤認(398aed9)につながった。また共有 `CARGO_TARGET_DIR` で複数 worktree を順にビルドすると再ビルドされず同一バイナリになる(本分析中に発生、md5 で検出)ので、worktree ごとに target dir を分ける。
