# 内点法の双対による被約費用の固定 (IPMRC、2026-11-11)

XOLAZY (analysis/xolazy_20261111.md) の派生。根の LP (最初・再スタートの後) の同時実行で内点法の点が手に入ったら、クロスオーバーの前の
内点法の双対からラグランジュ下界と被約費用を作り、被約費用による固定に使う。内点法の点は厳密な相補性に近く、頂点の双対で 0 になる
(双対退化の) 被約費用が 0 にならないので、固定が増えると見込んだ。

環境変数 (どれも既定では使わない):

- `ENOMOTO_MIP_XOLAZY_LOG=1` (診断、振る舞いは変えない): XOLAZY の行に、根の終わり (再スタート・木に入る直前) の打ち切り値と根の LP の時点の
  大域的な境界で固定できる整数列の数を、最適な頂点の双対 `fix_opt`・内点法の双対 `fix_ipm`・両者の和集合 `fix_union`・止められた
  二段解法の途中の基底の双対 `fix_simplex` ごとに出す。`fix_*_new` はそのうち実際にはまだ固定されていない列 (実際の固定に足される分)。
- `ENOMOTO_MIP_IPMRC_WAIT=1` (診断、採る結果は変えない): 二段解法が先に最適で終わっても、内点法の点が届くまで待ってから止める (待った秒 `t_wait`)。
- `ENOMOTO_MIP_IPMRC` (試作): `u` 内点法の双対のラグランジュ下界と被約費用を被約費用による固定 (`t4_rc_extra`、`root_redcost_fixing`) に足す。
  `w` 二段解法が勝っても内点法の点を待つ (`IPMRC_WAIT` と同じ)。

正しさ: どの行の双対 `y` でも `L(y) = b·y + Σ_j min_{l_j <= x_j <= u_j} (c - A^T y)_j x_j` は LP の下界で、各列の項を最小の側の境界に置くので
`c·x >= L(y) + |d_j| (x_j - 境界)` が LP の境界の中のすべての `x` で成り立つ (頂点の双対の弱双対の不等式と同じ形)。近似の双対でスラック列
(片側だけ有限の境界) の符号が逆になる分は、行の双対をスラックの被約費用が 0 になる値に射影して直し (射影した `y` でも `L` は正しい下界)、
浮動小数の和の誤差の余裕 (項の絶対値の和の 1e-9 倍 + 値の 1e-9 倍) を引く。`L` が根の LP の値を越えたら使わない。
作り: `src/simplex/mip_lp.rs` (`lagrange_std`・`xolazy_duals`・待ち)、`src/simplex/crossover.rs` (内点法の双対を `XO_STAMP` に置く)、
`src/mip/xolazy.rs` (`ipmrc_store`・固定の数え)。

## 結論 (先に)

- **固定は大きく増えるが、解く時間は良くならない。既定候補にならない。**
  - 診断: 内点法の双対で実際の固定に足される整数列は 58 問 (60 秒・種 1・2) で 1710 本、Mittelmann の重い 36 問 (600 秒) で 210 本
    (最適な頂点の双対では 58 本・2 本)。
  - 58 問 × 種 1・2 の既定と `uw` の対 (4 分担、同じ問題・種の対は同じ機械): SGM 17.23 → 17.57 (+1.9%、95% 区間 [−1.2%, +5.6%])、解けた回
    84 → 82 (既定だけ 2)。区間の上限が基準 (+5%) を越え、解けた回も 2 減る。
  - 揃った害: neos-911970 (10.2・14.4 → 23.7・26.9 秒)。
- 害の形 (推測): 固定が増えると再スタートの判断が早く・多くなり (fiber・qnet1・khb05250 で再スタートの回数が増えた)、道が変わる。
  neos-911970 は最初の再スタートで新たに固定された列が 78 → 16 に減っていて、固定が早くたまって再スタートが早まり、
  根で固定しきる前に再スタートしたとみられる。
- 止められた二段解法の途中の基底の双対は、足される分が 84 本・1 本で効き目は小さい (下界の差 16〜1e6 が多い)。

## 1. 診断 (`ENOMOTO_MIP_IPMRC_WAIT=1`、58 問 60 秒・種 1・2 `p58w.jsonl` → `summ_p58w.txt`、Mittelmann 36 問 600 秒・種 1 `res_s*.jsonl` → `summ_m36.txt`)

| | 根の終わり (内点法の双対あり) | 固定: 最適 | 内点法 | 和集合 | 途中の基底 | 実際の新しい固定 | 足される: 最適 | 内点法 | 途中の基底 | 待った秒 (全体の割合) |
|---|---|---|---|---|---|---|---|---|---|---|
| 58 問 | 137 (114) | 5799 | 4237 | 7602 | 4382 | 22638 | 58 | **1710** | 84 | 10.2 (0.37%) |
| 36 問 | 26 (24) | 9561 | 9613 | 10517 | 8303 | 15750 | 2 | **210** | 1 | 14.3 (0.10%) |

- 「固定」は根の LP の時点の境界と根の終わりの打ち切り値で数えた数。「足される」はそのうち実際にはまだ固定されていない列。
- 足される分が大きい問題: neos-3083819-nubu (333)・mzzv42z (189・186)・blp-ar98 (157)・exp-1-500-5-5 (61〜74)・fiber (52〜57)・qnet1・mzzv11
  (内点法 859 本対 最適 285 本、`fix_*_new` の数えを足す前の版の分担)・neos-960392 (22)。
- 内点法の下界と主の目的値の差は 1e-11〜1e-2 (多くは 1e-4 以下)。khb05250 は 0.24 (最適な双対でも 0.26、係数が大きく余裕が大きい)。
- 途中で直したこと: 初めは下界の差の基準を最適な双対の `L` にしていて、内点法の下界が LP の値を越えて見える例があった (khb05250、−0.05)。
  基準を主の目的値 (`c·(x - shift)`) にしてからはすべて正 (`chk.jsonl`)。

## 2. 試作 `uw` と既定の対 (58 問 × 種 1・2、60 秒・4 スレッド、`shards58.json` の 4 分担 → `res58_s*.jsonl`、`cmp.py` → `cmp58.txt`)

事実:

- SGM 17.23 → 17.57 (+1.9%)、95% 区間 [−1.2%, +5.6%]、符号反転の p=0.29。解けた回 84 → 82 (既定だけ 2・`uw` だけ 0)。
- 揃った差 (2 種とも 0.3 (log) 超): neos-911970 +0.46 ×2 (遅い)。
- 時間切れの最終ギャップ (log10) +0.107 [+0.008, +0.264] (`uw` が少し悪い)。根の下界・初めの解の時刻は差なし。
- 誤答・暫定解と下界の矛盾 (既知の最適値と比べて) 0 件 (232 行)。最大 RSS の比 1.006。`uw` で内点法の双対を足した根の LP 162 本。
- 固定は実際に増えた: 根の終わりの最初の出来事の新しい固定の和 21600 → 21697、neos-3083819-nubu の 2 回目の再スタートで 617 → 950 本。
  `uw` では内点法の双対で足せる列 (`fix_ipm_new`) が 0 になる (取り込まれている)。
- 時間: neos-3083819-nubu 4.7・5.7 → 4.9・4.8 秒、exp-1-500-5-5 6.5・8.7 → 6.3・7.2、qnet1 3.6・4.7 → 3.7・3.2、fiber 1.9・1.7 → 2.0・2.2、
  mzzv42z・blp-ar98 は両方時間切れ。
- 誤答検査 (`ENOMOTO_MIP_IPMRC=uw`): `fuzz_tiny.py 400 0` bad 0 (`fuzz/fuzz_tiny_uw.log`、400 問とも内点法の双対を使った)、
  `mip_fuzz_vs_highs.py 300` bad 0 (`fuzz/fuzz_vs_highs_uw.log`)。`cargo test --release --lib` 400 通過。

推測:

- 足した固定の多くは、木の中の被約費用による固定 (カットのループの後の LP の双対、ノードの LP) でもいずれ締まる列で、60 秒の問題では
  時間の差にならない。差が出たのは再スタートの時機が変わった問題 (neos-911970・fiber・qnet1) で、道の変化による揺れと害が混ざる。

## 次の手 (案)

- 既定候補にはしない。試作と診断は残す (既定では何もしない)。
- 続けるなら: (1) 再スタートの判断には使わず、木に入った後の固定だけに使う (再スタートの時機を変えない) 形、(2) 固定の多い Mittelmann の重い問題
  (mzzv11・mzzv42z) で 600 秒の対を測る、のどちらか。どちらも 60 秒の 58 問で効き目が見えていないので、優先度は低い。

## 3. 案 (1) `utw`: 再スタートの判断には使わず、木に入るときに足す (58 問 × 種 1・2、`shards58t.json` → `res58t_s*.jsonl`、`cmp.py` → `cmp58t.txt`)

`ENOMOTO_MIP_IPMRC=utw`: 内点法の双対の固定 (`u`) を根の LP の直後には足さず、主が木に入るとき (再スタートの判断の後) に `t4_rc_extra` に足して締める
(`ipmrc_tree_start`)。木の中の再スタートの判断には効く。

事実:

- SGM 17.05 → 16.80 (−1.5%)、95% 区間 [−5.7%, +2.3%]、符号反転の p=0.48。解けた回 84 → 86 (既定だけ 1・`utw` だけ 3)。揃った差 (0.3 超) なし。
- 時間切れの最終ギャップ (log10) −0.047 [−0.112, −0.000] (`utw` が少し良い)。根の下界・初めの解の時刻は差なし。
- 誤答・暫定解と下界の矛盾 0 件 (232 行)。最大 RSS の比 0.992。
- 木に入るときに足した回 72、そこで新たに固定した整数列の和 1052 (9 問)。
- 問題ごと: neos-911970 19.3・14.0 → 25.3・19.1 秒 (2 種とも遅いが 0.3 未満。`uw` でも遅かった)、neos-3083819-nubu 4.0・7.5 → 3.6・7.1、
  fiber 1.4・1.9 → 1.4・1.4、exp-1-500-5-5 5.3・5.9 → 5.0・5.6、qnet1 4.1・5.1 → 4.6・5.7。
- 誤答検査 (`utw`): `fuzz_tiny.py 400 0` bad 0、`mip_fuzz_vs_highs.py 300` bad 0 (小さい問題は木に入らないので、木に入るときに足す経路は
  通っていない。足す仕組み (`t4_rc_extra`) は `uw` の検査で通っている)。`cargo test --release --lib` 400 通過。

読み方: `uw` の害 (再スタートの時機が変わる) は消えた。取り込みの基準 (docs/backlog.md の冒頭) は満たす: 区間の上限 +2.3% ≤ +5%、解けた回は減らない、
揃った害なし、誤答 0、余分なメモリなし。余分な時間は内点法の点を待つ分 (`w`、58 問で全体の約 0.4%) で、時間の計測に含まれている。
効き目は区間が 0 をまたぐ程度で小さい。neos-911970 の小さな遅れは 2 つの形 (`uw`・`utw`) とも同じ向き。
