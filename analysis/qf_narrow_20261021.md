# Qf の絞り込み: どこで悪くなり、どう絞るか (2026-10-21)

環境: 4 CPU のクラウドのコンテナ (ソルバーは同時に 1 本だけ)。ブランチ `inv/qfnarrow-20261021` (b375bf1 = gfrsplit の試作 +
develop) に診断と試作を足したビルド。**計測はすべて 4 スレッド・60 秒**、`m.solve(None, False, 60.0, None, None, 4, log=True)`、
`ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_THREADS=4 ENOMOTO_MIP_DEBUG_FACETIME=1`。MPS は miplib.zib.de が 503 のため
`origin/inv/mps-cache-20261021` から展開した。台本とログは `analysis/qf_narrow/` (`erun.sh <問題> <設定> <回>`、設定は `cfg.sh`、
表は `python3 table.py [問題...]`、全部の表は `table_all.txt`、結果の行は `b1.txt`〜`b4.txt`)。

略号: G = `ENOMOTO_MIP_IMPLBD_GENINT=1`、R = `ENOMOTO_T_MIP_CUT_LP_RETRY=4`、F = `ENOMOTO_MIP_FACE_SEP=off`、
X = `ENOMOTO_MIP_RESTART_REF=1`。Qf = `ENOMOTO_MIP_GR_AUTO=2 ENOMOTO_MIP_FACE_SEP_FC=off ENOMOTO_MIP_RESTART_REF=1`。
QfnoX (= P1) = Qf から X を外したもの。

## 結論

1. **悪化の仕組みは 2 つ** (どちらもログで確かめた事実):
   - **X × 再スタートの増加 (qnet1)**: G・F で根の下界が上がり (15706 → 15814)、被約費用の固定が増えて再スタートが 1 → 2〜3 回に
     なる。X のもとでは再スタート後の求解が「前の暫定解より悪い解」を暫定解にしないので、暫定解なしのまま根のヒューリスティクス
     (局所探索 2.6〜2.9 秒 ×2、フィージビリティポンプ) が走る。既定はポンプの 16942 を暫定解にしてすぐ木に入る。
     X を外す (QfnoX) と 3.4〜5.3 秒で既定 (4.3〜4.9 秒) 並み。X だけ (4.1〜4.3 秒) も既定並み。
   - **F で根の頂点が変わり、根のヒューリスティクスが外れる (h80x6320d・nursesched-sprint02)**: 根の RINS・RENS・LP face の
     近傍が変わり、良い暫定解が出ない回がある。すると最初の再スタートで固まる列が大きく減り (h80x6320d 4473〜5126 → 996 本、
     nursesched 7000 本前後 → 853〜1382 本)、2 回目以降の再スタートと大きな木が要って遅くなるか時間切れになる。
2. **mc11・mzzv42z の効果に X は要らない**: mc11 は QfnoX 3 回とも解ける (26.4〜32.2 秒)、mzzv42z は QfnoX -20190〜-20540
   (Qf -20310〜-20520、既定 -17240〜-18784)。
3. **前回の計測で悪化と出た h80x6320d・noswot は、今回は Qf で悪化を再現しなかった**: noswot は Qf 6 回全部 28.6〜36.8 秒
   (既定 6 回は 33.4〜56.4 秒と時間切れ 1 回)。h80x6320d は Qf 6 回で 31.3〜56.9 秒と時間切れ 1 回 (既定 39.7〜47.8 秒) で、
   揺れが大きくなる (上の 2 つ目の仕組み)。
4. **絞った試作 P3** = `ENOMOTO_MIP_GR_AUTO=2 ENOMOTO_MIP_FACE_SEP_FC=off ENOMOTO_T_MIP_FACE_SEP_FC_MAXCOLS=5000 ENOMOTO_T_MIP_GR_AUTO_MIN_FRAC=0.01`
   (X なし)。固定費用型の F は 5000 列 (前処理の後) までの問題に、GR_AUTO は一般整数が固定されていない列の 1% 以上ある問題に限る。
   mc11 9 回中 7 回解ける (P2・QfnoX・Qf の合計。P3 は mc11 では P2 と同じ経路)、mzzv42z -19400〜-20500、h80x6320d は既定の
   経路 (39.9〜46.0 秒)、nursesched-sprint02 は既定の経路 (31.4〜33.5 秒)、qnet1 は既定並み。
   **ただし 2 つの閾値はどちらも、効く問題 1 つと崩れる問題 1 つの間に引いたもの** (5000 列は mc11 3034 列と h80x6320d 12640 列の間、
   1% は mzzv42z 2.0% と nursesched 0.2% の間)。仕組みから決めた値ではない。
5. 誤った最適値は今回の 60 秒のログ 234 本で 0 回。

## 3. 仕組みの詳細 (事実)

### 3.1 qnet1 (X × 再スタート)

`logs/qnet1_{def,Qf}_1.log`: 既定は根 15705.6 → 背景のカット 15736.6、再スタート 1 回 (238 列)、再スタート後のポンプが 16942 を出して
2.1 秒で木。Qf は根 15813.9 → 15852.4、再スタートが 3 回 (331・84・115 列)。前の暫定解 (最適解 16029.69) は再スタート後の問題では
打ち切り値による固定で実行不能になり、X では参照解に回るだけ (`kept as the RINS reference`)。再スタート後は暫定解がなく、
局所探索が 2.86 秒・2.61 秒走る。木に入るのが 4.2 → 10.6 秒、ノードはどちらも 5。

### 3.2 h80x6320d (F で根のヒューリスティクスが外れる)

最初の根のヒューリスティクスの後の暫定解と、最初の再スタートで新たに固まった列:

| 設定 | 暫定解 (再スタート前) | 固まった列 | 結果 |
|---|---|---|---|
| 既定 ×6 | 6388.3〜6417.6 | 4473〜5126 | 39.7〜47.8 秒 |
| X ×3 | 6400.9 | 4643 | 39.5〜41.2 秒 |
| Qf ×6 | 6383.6 ×2 / 6397.9 ×2 / 6644.8 ×2 | 5263 / 5102 / 996 | 31.3・32.9 / 46.5・44.6 / TL・56.9 |
| QfnoX ×3 | 6644.8 ×3 | 996 | 54.0〜55.6 秒 |

F の根は下界が良い (6313.8〜6320.2、既定 6251.6〜6277.5) が、その頂点の近傍の RINS は 9 回中 5 回 6644.8 止まり。そうなると固まる列が
996 本で 2 回目の再スタートが要り、最後の根の下界が 6347〜6349 (既定 6354〜6356) で木が 229〜341 ノード (既定 11〜131)。
再スタート後の根では固定費用型の判定が外れて面の分離が戻ることがある (例 `h80x6320d_Qf_1` の再スタート 1: 面 3.45 秒)。

### 3.3 nursesched-sprint02 (F で根のヒューリスティクスが外れる)

根のヒューリスティクスの後の暫定解 / 最初の再スタートで固まった列: 既定 58 ×5・62 (4021)、GR 58・65 (2929)・67 (2344)、
P1 59・59・71 (1382)・66 (2642)・72 (1179)・63 (3631)、F 63 (3631)・73 (853)・73 (853)、P3 58 ×3。
時間切れの 2 回 (P1) と遅い 2 回 (F 59.4・50.3 秒) は、どれも暫定解 71〜73・固まる列 853〜1382 の回。

### 3.4 mc11 と h80x6320d の違い (F を止める条件の候補)

| | mc11 既定 | mc11 F | h80x6320d 既定 | h80x6320d F |
|---|---|---|---|---|
| 列 (元) | 3040 | | 12640 | |

- **面の分離が分離の時間に占める割合では分けられない**: mc11 65%、h80x6320d 60〜65% (roll3000 64%、timtab1 62%、mzzv42z 82%、
  neos-1456979 92%、qnet1 27%、rout 34%、30n20b8 26%)。依頼の案「面の分離が 1 ラウンドの大半を占めるときだけ止める」は mc11 と
  h80x6320d を分けない。
- **背景のカットが伸び続けるか**も両方で伸びる (ラウンドが 2〜3 倍、下界も上がる)。違いは伸びが効くか (mc11 は最適 11689 の
  手前まで閉じる、h80x6320d は木の大きさが根のヒューリスティクスと再スタートで決まる) で、ループの中では分からない。
- 手前の根のループ: mc11 はラウンドの上限 (25) で止まり、h80x6320d は根のカットの時間の上限で止まる。F は h80x6320d ではラウンドを
  増やし、mc11 では時間を減らす。ただしこれで分けても理由づけはできていない (推測の段階)。
- 再スタートの有無は分ける (mc11 なし、h80x6320d あり) が、h80x6320d の害は最初の再スタートの前 (根のヒューリスティクス) で
  起きているので、再スタートで切り替えても間に合わない。
- 残ったのが問題の大きさ。試作では列数の上限にした (5000)。

### 3.5 mzzv42z と noswot・qnet1・nursesched の違い (G+R+F の条件の候補)

- noswot・qnet1 は X を外せば Qf で悪化しない (noswot は Qf 6 回とも既定より速いか同じ、QfnoX は揺れの範囲)。
  一般整数の割合で GR_AUTO を外す必要はこの 2 問にはない。
- 崩れたのは nursesched-sprint02 (一般整数 20 / 10250 列 = 0.2%、全部整数) で、mzzv42z (235 / 11717 = 2.0%、全部整数) と型が近い。
  「連続変数がない」では分けられない。一般整数の割合で分けた (1%)。G のカットの本数は数えていない (ログに出していない)。
- 30n20b8 は元の問題では 0.3% だが、前処理の後の固定されていない列で数えると 1% 以上になり、P3 でも GR_AUTO が働く
  (P3 の根も面の頂点 0 個)。60 秒では既定・Qf・P3 のどれも解なしで、根の下界は P3 140.1 > 既定 138.3。

## 4. 試作 (既定は変えない、`src/mip/`)

- `ENOMOTO_MIP_DEBUG_FACETIME` (診断): 根・背景のカットのループごとに `FACETIME root|bg restarts k rounds n: sep (face, vertices), LP, loop, obj`
  を出す (`Solver::face_secs`・`face_used`)。
- `ENOMOTO_T_MIP_FACE_SEP_FC_MAXCOLS` (既定 上限なし): `FACE_SEP_FC=off` を、前処理の後の列がこの数以下の問題に限る (separation.rs)。
- `ENOMOTO_T_MIP_GR_AUTO_MIN_FRAC` (既定 0): `GR_AUTO` を、一般整数の列が固定されていない列のこの割合以上ある問題に限る (mod.rs
  `implbd_genint_for`)。G・R・F (GR_AUTO=2) のすべてに効く。
- `cargo test --release --lib`: 308 件通過 (17 件は無視の印)。

計測に渡す形:
- **P3 (推す形)**: `ENOMOTO_MIP_GR_AUTO=2 ENOMOTO_MIP_FACE_SEP_FC=off ENOMOTO_T_MIP_FACE_SEP_FC_MAXCOLS=5000 ENOMOTO_T_MIP_GR_AUTO_MIN_FRAC=0.01`
- P1 (X を外しただけ): `ENOMOTO_MIP_GR_AUTO=2 ENOMOTO_MIP_FACE_SEP_FC=off`

P3 が働く問題 (今回の計測から): F (固定費用型) は mc11・gr4x6・rout (gr4x6 は面の頂点がもともと 0、rout は一般整数でも当たる)。
GR_AUTO は 40 問の一般整数の 12 問 (30n20b8 を含む) と mzzv42z・roll3000 で、nursesched-sprint02・hypothyroid-k1 (1 列) は外れる
はず (hypothyroid-k1 は P3 で測っていない。neos-950242 は 4.2% で働く。P1 で既定並み)。

## 5. うまくいかなかったこと・確かでない点

- 面の分離の時間の割合、背景のカットの伸び、連続変数の有無はどれも mc11/h80x6320d、mzzv42z/nursesched を分けなかった (3.4・3.5)。
- 2 つの閾値は各 1 組の問題の間に引いた。固定費用型 18 問 (beasleyC1-3・mc7/8・h50x2450・sp150x300d など) と、一般整数が少しだけ
  ある問題での確認がない (今回のキャッシュは 55 問だけ)。beasleyC3 は今のビルドでは固定費用型と判定されない (vb 行 852 / 1453)。
- F の害 (根の頂点が変わって根のヒューリスティクスが外れる) は、F が働く問題ならどこでも起こりうる。今回 mc11・mzzv42z 以外で
  F が働く問題で害が見えなかったのは、根のヒューリスティクスの当たり外れで経路が決まる問題でなかったからと見ている (推測)。
- 前回の 40 問計測 (rQFb) の h80x6320d・noswot の時間切れは、F の当たり外れ (h80x6320d) と揺れ (noswot) と見ている。
  10teams・uccase12・beasleyC3 の差は Qf の G・R・F が働かない問題なので、X (再スタートがあれば働く) か揺れ。X を外した P1・P3 では
  これらの問題は既定と同じ経路になるはず (確かめていない)。
- mc11 の F の経路でも、手前の根が 11099.2 (713 本) に着く回は背景のカットが 11587 で止まり解けない (9 回中 2 回)。
