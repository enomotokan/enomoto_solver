## 1. 結論

- ns1116954 は**目的関数の係数が全部 0** の実行可能性問題 (131991 行・12648 列、0-1 7482・連続 4446)。実行可能解を 1 つ見つければ最適。
- **HiGHS は根の LP を解かずに終わる**: 前処理 1.2〜1.6 秒 → 前処理直後の Feasibility Jump (種 0) が 2.1〜2.4 秒で解 → 根のノードは
  LP 反復 0 で下界 0 (目的関数が 0 なので自明) → 1 ノードで最適 2.5〜3.0 秒。ただし**種 0 の当たり**: `random_seed=1・2・3`、
  `presolve=off`、FJ を切った形はどれも 60 秒で解なし (根の LP だけで 14〜48 秒)。HiGHS の手法として ENOMOTO に足りないのは
  「前処理の直後・根の LP の前に FJ を回し、見つかれば自明な下界で終える」順番だけで、カット・木・サブ MIP は関係ない。
- **ENOMOTO の既定の 27〜33 秒の内訳** (3 回 + 診断 1 回): 前処理 約 17 秒 (うち**LP による固定 10.9〜13.2 秒で固定 0**、プロービング
  2.7〜2.9 秒・同値の検出 1.0 秒で何も減らない) → 根の LP 11.7〜12.6 秒 (LP による固定の基底は、後のクリーク行の拡張で行が変わり
  列の状態だけになって効かず、反復は前処理の LP より多い 3892) → FJ のスレッドは根の LP の途中 (約 8 秒) で解を見つけているが、
  主は根の LP が終わるまで受け取らない → カットのループのクリークの分離 3.0〜3.3 秒 (何も足さない) → 根で終える判定で最適 (MIP の
  時計 14.9〜15.8 秒)。**時間のほぼ全部が「解の要らない LP」**。
- 試作 `ENOMOTO_MIP_FEAS_FJ_EARLY=1`: 前処理後の目的関数が全部 0 なら、LP による固定の前に種を変えた FJ2 を 4 スレッド並べて回し
  (上限 0.1 x 時間上限 = 6 秒)、見つかれば残りの前処理・根の LP・木を飛ばして最適で終える。**ns1116954 は 3 回とも 2.7〜3.2 秒** (既定
  29.9〜32.8 秒)、種を変えても 5 回とも 0.8〜6.4 秒で最適。HiGHS (種 0 で 2.5〜4.8 秒、ほかの種では解なし) より頑健。
- 損の出やすい 6 問 (neos-960392・physiciansched6-2・h80x6320d・qiu・10teams・n5-3) では早めの FJ は一度も動かない (目的関数が
  0 でない)。時間の違いは揺れ。58 問で最適値 0 の問題は ns1116954 だけなので、58 問で変わるのは ns1116954 だけのはず。

## 3. 原因 (ENOMOTO だけが無駄にしている処理)

1. **FJ を回す順番**: ENOMOTO の FJ は根の LP と並べて別スレッドで始まり (src/mip/solver.rs の FJ のスレッド)、その前に前処理の全部
   (LP による固定を含む約 17 秒) が終わっている。HiGHS は前処理の直後・根の LP の前に FJ を回す。目的関数が 0 の問題では FJ の解が
   そのまま最適解なので、前処理の LP・根の LP・カットは全部無駄。
2. **FJ の解を根の LP の途中で受け取れない**: FJ のスレッドは約 8 秒で見つけているが、主は根の LP (12 秒) が終わるまで受け取らない。
   さらに受け取った後もカットのループのクリークの分離 (3 秒) を回してから終える判定をする (判定はループの各ラウンドの頭と終わり)。
3. **前処理の LP による固定の基底が効かない** (この問題に限らない): `lp_probe` は最初の LP が 1 秒を越えると基底を根に渡すが、その後の
   クリーク行の拡張 (`extend_clique_rows`) が行を変えると行の状態が捨てられ、列の状態だけの基底は根の LP の反復を減らさない
   (3892 反復 > 前処理の LP 3225 反復)。この問題では 11〜13 秒の LP が丸ごと捨てられている。
4. FJ_P3 の前処理 (FJ のスレッド、3.1〜4.8 秒) も何も減らさない (主と CPU を取り合う)。

HiGHS の手法で足りないもの: 上の 1 (前処理直後の FJ) と、目的関数から出る自明な下界で根を LP なしで閉じること。カット・木・
サブ MIP の差ではない。HiGHS の 4.8 秒は種 0 の運に頼っており、ENOMOTO の既定は (遅いが) 毎回解けている点では強い。

## 4. 試作 `ENOMOTO_MIP_FEAS_FJ_EARLY` (src/mip/mod.rs、既定では使わない)

- `presolve_mip_depth` の LP による固定の直前で、最初の求解 (サブ MIP・再スタートでない) かつ前処理後の目的関数が全部 0
  (`heuristics::fj_feas_extend`) なら `feas_fj_early` を呼ぶ: スレッドの数 (`MipParams::threads`) だけスレッドを立て、それぞれ種を変えた

  前処理の期限 (`PRESOLVE_DEADLINE`) も見る。種は `ENOMOTO_T_MIP_FEAS_FJ_EARLY_SEED` (診断用) でずらせる。

## 5. 既定にする候補か・58 問で確かめる形の提案

- `ENOMOTO_MIP_FEAS_FJ_EARLY`: **候補**。動くのは前処理後の目的関数が全部 0 の問題だけで、58 問では最適値 0 の問題は ns1116954 だけ
  (`analysis/highs_vs_20261101/highs.jsonl`。pk1・markshare_4_0 は最適値が正なので目的関数は 0 でない)。したがって 58 問の確かめは
  「ns1116954 が速くなり、ほかの 57 問の動きが変わらない」ことを見るだけでよい: 既定と試作を 58 問 x 2 回 (今までの bench と同じ組)、
  SGM・解けた数を比べる。Mittelmann の組にも実行可能性問題 (目的 0) があれば、そちらで見つからない場合の損 (最大 0.1 x 時間上限) を
  確かめたい。
- 見つからないときの損を減らす形 (未試作): 早めの FJ は短く (例 2 秒) して、見つからなければ FJ のスレッドに任せる。または FJ の
  スレッドが解を見つけた時点で、目的関数が 0 なら根の LP を止めて終える (原因 2。根の LP の止めの合図が要る)。
- 原因 3 (前処理の LP の基底がクリーク行の拡張で効かなくなる) は ns1116954 以外にも当たりうる。消えた行の状態を捨て、拡張された行は
  状態を引き継ぐ形で行の状態を写す、あるいは基底を渡すときはクリーク行の拡張の後の行で LP を解き直す、などが考えられる (未試作)。
- 原因 4 (FJ_P3 の前処理が何も減らさないのに 3〜5 秒) も別に見る価値がある。
