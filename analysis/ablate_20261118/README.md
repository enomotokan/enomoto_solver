# 既定の機能の二極化の洗い出し (2026-11-18、段階 1 は計測なし)

利用者の案: 既定にしている機能のうち、問題によって効き目が二極化していて「場合分けして一部の問題では切る」方がよいものを探す。

- 段階 1 (この節まで、新しい計測なし): 既定にしたときの対の計測 (res*.jsonl) を読み直し、機能ごとに
  「全種で 1.25 倍超遅い問題 (slow)」「全種で 0.8 倍未満速い問題 (fast)」「片方だけ解けた種のある問題 (one)」を拾う。
  遅い問題は「同じ種での全種一致の遅れか」と「1 スレッドで同じ道でも遅いか」で本物だけを残す。
- 段階 2 (まだ回さない): 有望なものについて、遅い・速い問題と特徴で分けた組で「既定 対 その機能を切ったもの」を未使用の種で測る分担表。

## 道具

- `pairs.py 名前 'res のグロブ' 機能ありの設定 機能なしの設定 [tl]`: 比 = (あり + 10) / (なし + 10) (時間切れは tl) を同じ (問題, 種, tl) で
  対にする (同じ組が複数の計測にあれば幾何平均)。両方とも時間切れの種は全種一致の判定から外す (残りが 2 種以上のときだけ判定)。
  機能ありの設定を含むファイルだけを読む (同じ場所の別の計測の既定を混ぜない)。
- `features.txt`: 調べた機能と計測の場所 (名前|グロブ|あり|なし)。`pairs.jsonl` はその全部の出力
  (`while IFS='|' read -r n g on off tl; do python pairs.py "$n" "$g" "$on" "$off" $tl; done < features.txt`、analysis/ から)。
- `feat.py 問題 ...`: 元の MPS から行・列・非零・整数列・2 値列・連続列の割合 (`feat.jsonl`)。
