# 既定の機能の二極化の洗い出し (2026-11-18、段階 1 は計測なし)

利用者の案: 既定にしている機能のうち、問題によって効き目が二極化していて「場合分けして一部の問題では切る」方がよいものを探す。

- 段階 1 (この節まで、新しい計測なし): 既定にしたときの対の計測 (res*.jsonl) を読み直し、機能ごとに
  「全種で 1.25 倍超遅い問題 (slow)」「全種で 0.8 倍未満速い問題 (fast)」「片方だけ解けた種のある問題 (one)」を拾う。
  遅い問題は「同じ種での全種一致の遅れか」と「1 スレッドで同じ道でも遅いか」で本物だけを残す。
- 段階 2 (まだ回さない): 有望なものについて、遅い・速い問題と特徴で分けた組で「既定 対 その機能を切ったもの」を未使用の種で測る分担表。

## 道具

- `pairs.py 名前 'res のグロブ' 機能ありの設定 機能なしの設定 [tl]`: 比 = (あり + 10) / (なし + 10) (時間切れは tl) を同じ (問題, 種, tl) で
  対にする (同じ組が複数の計測にあれば幾何平均)。両方とも時間切れの種は全種一致の判定から外す (残りが 2 種以上のときだけ判定)。
  機能ありの設定を含むファイルだけを読む (同じ場所の別の計測の既定を混ぜない)。
- `features.txt`: 調べた機能と計測の場所 (名前|グロブ|あり|なし)。`pairs.jsonl` はその全部の出力
  (`while IFS='|' read -r n g on off tl; do python pairs.py "$n" "$g" "$on" "$off" $tl; done < features.txt`、analysis/ から)。
- `feat.py 問題 ...`: 元の MPS から行・列・非零・整数列・2 値列・連続列の割合 (`feat.jsonl`)。

### 遅い問題の確かめ (本物の遅れか)

1 スレッドの確かめは `t1/runs.jsonl` (既定の種、手元 4 コアで 4 本並べた)。

- **FOLD の physiciansched6-2 (1.43・1.43)**: 当時 (2026-11-10) は細分化に 20.6 秒かかっていた。今の版 (`rinq`) では 1.69 秒で畳む
  (`t1/physiciansched6-2_fold.log`、111827 → 67576 列)。1 スレッドで既定 24.2 秒・`ENOMOTO_MIP_FOLD=0` 23.5 秒 (どちらも根で最適、節点 0)。
  → 細分化が速くなって遅れは消えている。
- **FOLD の neos-860300 (規則 2 の前の b58v2 で 1.56〜1.98 × 4 種)**: 規則 2 (列がまとまらない畳みはしない) で畳まなくなった。1 スレッドで
  既定 21.1 秒・`FOLD=0` 20.5 秒 (どちらも節点 0)。→ 遅れは消えている (b58v3 では slow に出ない)。roll3000 も同じ。
- **DOMCOL の supportcase33**: domrev の記録で、この問題では固定する列が 0 本 (同じ道)。→ 4 スレッドの揺れ。
- **cand1119 の部品 (A: 4 問 × 種 1〜3 × 部品を 1 つずつ抜いた設定)**: 全種一致の遅れはない。目立つのは
  - SYM_TWINS で CMS750_4 が 1.24〜1.43 倍 (3 種)。ところが CMS750_4 では双子が 1 組も見つからず、対称性も「none」
    (`t1/CMS750_4_sym.log`)。1 スレッド 900 秒では既定・`SYM_TWINS=0` とも時間切れで、目的値 509・下界 250・節点 67416 / 68526 と同じ。→ 揺れ。
  - csched008: 同じ cand1119 対 def で、M (種 1・2) では def だけ解き (1.30・1.78)、A では両方とも全種で時間切れ。→ 揺れ (同じ種で一致しない)。
  - シグモイド (`CLIQUE_CUTS=sigmoid`) で supportcase33 が 1.13〜1.27 倍 (3 種、全種 1.25 は超えない)。1 スレッド 900 秒では既定・
    `CLIQUE_CUTS=fallback` とも時間切れ (目的値 −340 / −345、下界 −390 / −410。下界は既定が良く、解は fallback が良い)。→ 決め手なし。
- **cand1108zd の hypothyroid-k1・mzzv42z**: 束の中の zerohalf を切ったこと (`ENOMOTO_MIP_NO_ZEROHALF=1`) が元 (docs/improvement_history.md の
  2026-11-09 の節)。zerohalf を問題で使い分ける試作 `ENOMOTO_MIP_CUTMIX=z` (全部整数・係数が小さい行の割合で入れる) は
  analysis/vsscip_slow_20261118/cmz で、入る 20 問の SGM 1.228 と悪く、遅くなる nw04・air03・eil33-2 と得をする seymour を分ける特徴が
  見つかっていない。→ 本物だが、根だけで分ける特徴は既に探して見つかっていない。

### 片方だけ解けた・速い問題の向き

速い側はどの機能も「その機能が実際に働く問題」(g1 の VUB 集約が効く neos-787933、DOMCOL が列を固定する rail507・fast0507、FOLD が畳む
neos-960392・neos-957323 など) に集まり、遅い側は上の確かめで揺れか、既に直ったものだけだった。片方だけ解けた種 (`one`) は
noswot・neos-933966・traininstance6・tbfp-network・mzzv11 など、どの機能でも両向きに出る揺れの大きい問題がほとんど。

### 特徴 (`feat.jsonl`)

遅い側に残る問題が実質ないため、遅い・速いを分ける特徴は作れない (CMS750_4 は連続列 38%、supportcase33・mzzv42z・hypothyroid-k1 は
全部 0-1 列と、まとまった性質もない)。

## 段階 1 のまとめ

- 最近既定にした機能 (TREE_SHARE_CUTS・cand1119・PROP_RELTOL_CONT・AGG_PIVOT_COL・SEP_FAST・g1・can・seq・clqprb・rfs30・drevmf・FOLD・SYMDYN) は、
  「同じ種での全種一致の遅れ」と「1 スレッドで同じ道でも遅いか」を通すと、本物の遅れの問題が 1 つも残らない。どれも、働かない問題では同じ道を
  通り、働く問題で速いだけの形 (効き目は二極化ではなく「中立か速い」)。
- 本物の遅れが残るのは cand1108zd の zerohalf を切ったこと (hypothyroid-k1・mzzv42z) だけで、使い分けの特徴は既に cmz で探して見つかっていない。
- 弱い候補として clique カットのシグモイド (cand1119) が残る。1 回の計測では遅れが全種 1.25 を超えないが、rootgap_20261116/clq の M4 でも
  irp が 4 種とも 1.08〜1.42 倍遅く (速いのは mzzv11・neos-933966・neos-1456979)、向きが揃っている。

### A. clique カットのシグモイド (`ENOMOTO_MIP_CLIQUE_CUTS`、既定 `sigmoid` 対 以前の `fallback`)

- 遅い側: irp・supportcase33 (+ 確かめに csched008)。速い側: mzzv11・neos-933966・neos-1456979・mzzv42z。
- 分ける特徴の見当: シグモイドの入力そのもの (根の点数、clique の行の割合 sp・`s`)。irp は sp 1.0・s 0.57 で f 0.6、速い側の mzzv11 は根の
  clique の伸びが大きい。遅い側が「sp が高いのに clique カットで根が伸びない」問題なら、`sigmoid_a` (根の 3 ラウンド目で clique カットだけの
  伸びを測る適応の形、試作済み) で分けられる見込み → 設定は {def, fb (`ENOMOTO_MIP_CLIQUE_CUTS=fallback`), sa (`=sigmoid_a`)}。
- 種: 5・6・7 (cand1119 の M・A は種 1〜3、rootgap の M4 は 1〜4 で使用済み)。600 秒・4 スレッド。
- 回数: 7 問 × 3 種 × 3 設定 = 63 回、最大 10.5 時間 → **9 分担** (各 7 回、約 70 分)。同じ (問題, 種) の 3 設定は同じ分担に続けて置き、
  順は種で入れ替える (cand1119_20261117/run.py の分け方と同じ)。
