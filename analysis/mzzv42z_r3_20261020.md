## 結論

1. **双対側 (前の調査の結論は今の develop でも成り立つ)**: 既定の根のカット後の下界は -21246 (14.1 秒、2+2 ラウンド)。G+F で -20852〜-20969
   (7 秒前後)、HiGHS は前処理の後の根で -20738 (23.6 秒)。差の大半は一般整数の含意の implied bound カットの有無と、面の頂点の分離の時間。
2. **主側の主因は、根の LP が弱いことで根の RENS の近傍が崩れること**: 既定では暫定解なし用の RENS (ダイビング式、目標の固定率 0.8) が
   途中で LP が実行不能になって 1 段戻り、**固定率 0.35〜0.43 (6000〜7000 列が自由) のサブ MIP が 15〜18 秒で時間切れ** (0〜1 ノード、
   -17834 か解なし)。既定・p5s の 4 回と 120 秒の 1 回はすべてこの形。G+F では 24 回中 21 回が固定率 0.78〜0.84 で止まり、2100 列前後のサブ MIP が
   3〜9 秒で -19770〜-20540 を出す (1 回は実行不能) (HiGHS は根のカットの直後のサブ MIP (`L`) で -20540、23.6 秒)。
   **p5s で悪くなる点はこれ** (p5s1 は時間切れのサブ MIP が解を返さず、並列の locks の -13112 からの RINS で -17320)。p5s 固有の原因ではなく、
   既定でも同じ形で揺れる (既定・p5s とも RENS は固定率 0.36 で時間切れ)。
3. **(新しく分かったこと) 再スタートで暫定解を失う**: G+F で根の暫定解 (-20080〜-20540) ができると、根の目的値の探り・被約費用固定が
   打ち切り値 (暫定解より目的の刻み以上良いこと) で列を固定して再スタートし、**再スタート後の問題では前の暫定解が実行不能になって捨てられる**
   (`the start solution is not feasible in the presolved problem; dropped`)。再スタート後の求解は暫定解なしとして動き、
   - Feasibility Pump に 10〜29 秒、暫定解なし用の RENS (カット前の LP) のサブ MIP に 10〜29 秒を使い (60 秒のうち)、木は 0 ノードで終わる
   - 打ち切り値より悪い解 (FJ の -680、RINS の -5770 など) を暫定解として受け取り、それを RINS の相手にする
   - 暫定解がないまま終わると下界を -inf と報告する (G+F の 60 秒は 3 回とも -inf)

## 3. 再スタートで暫定解を失う (事実)

G+F の 1 回 (`logs/e_gf1.log`、時刻は再スタート後は再スタートからの秒):
- 14.3 秒に根の RINS で -20460。根の目的値の探り (打ち切り値 -20461.98) の後、394 列が新たに固定されて再スタート (15.2 秒)。
- 再スタート後の前処理で前の暫定解が実行不能になり捨てられる。根の LP を最初から 43285 反復 (9.5 秒) 解き直す。
- 根のヒューリスティクスは「再スタート前に失敗したもの」を飛ばすが、Feasibility Pump は再スタート前は暫定解があったので回っておらず、
  暫定解なしとして 10.2 秒回る (`gfr1` では 29 秒)。同時に暫定解なし用の RENS (カット前の LP) のサブ MIP が 10〜29 秒かかって実行不能。
- 54.6 秒 (絶対) に木に入り、0 ノードで時間切れ。下界は「暫定解がないと目的値の定数のずれが分からない」(`mod.rs`) ので -inf。
- 外側は良い方の解を採るので最終の暫定解は -20460 のまま (誤った答えにはならない)。

打ち切り値より悪い解を暫定解にする件 (`logs/e_gfrd1.log`): 再スタートの打ち切り値 -19873.98 (前の暫定解 -19872) なのに、
再スタート後の求解が FJ の -680、RINS の -5770 を `new incumbent` にした (`try_incumbent` は暫定解がなければ打ち切り値を見ない)。
`logs/e_gfrn2.log` でも暫定解 -20540 の再スタートの後に -20500、2 回目の再スタートの後に -19990 を暫定解にしている。
枝刈りは打ち切り値 (`prune_limit` は `params.cutoff` との小さい方) で行うので木は正しいが、RINS などの相手と暫定解なし用の
ヒューリスティクスを止める判断が悪い解で決まる。

## 4. 試作: `ENOMOTO_MIP_RESTART_REF=1` (既定では使わない)

内容 (再スタート後の求解 (`params.restarts > 0`) だけで働く):
1. 再スタート前の暫定解が再スタート後の前処理後の問題で実行不能なら、捨てずに「参照解」(`solver::REF_SOL` → `Solver::ref_sol`) として渡す。
2. 根の RINS は暫定解がなければ参照解を相手にする (境界の中にある値だけ固定。サブ MIP は打ち切り値を引き継ぐ)。
3. 参照解があれば暫定解なし扱いにしない (`noinc_like` が偽、暫定解なし用の RENS (カット前の LP) を回さない) ので、Feasibility Pump・
   ダイビング・暫定解なし用の RENS に時間を使わない。
4. 暫定解がないとき、打ち切り値に届かない解を暫定解にしない (`try_incumbent`)。
5. 前の暫定解 (元の行を満たす) から前処理の前後の目的値のずれを求め、再スタート後の求解が暫定解なしで終わっても下界を報告する (`mod.rs`)。

変えたところ: `src/mip/mod.rs` (`solve_problem` の始めの解の受け渡しと、下界の報告)、`src/mip/solver.rs` (`REF_SOL`・`ref_sol`・
根の RINS の条件・暫定解なし用の RENS の条件・`noinc_like`・`try_incumbent`)、`src/mip/heuristics.rs` (`rins_inner` が参照解を使う。
ほかに、ダイビング式の近傍の LP が最適でないときの理由を出すログ (`neighbourhood dive: LP ...`) を足した)。

mzzv42z (60 秒):

| G+F+R (8 回: R1〜R5・RD1〜RD3) | -20330 / -20500 / -20480 / -20540 / -20430 / -20440 / -20490 / -20090 | -inf (R1、2 回目の再スタートの後の木で時間切れ) / -20735 / -20752 / -20765 / -20745 / -20780 / -20785 / -20767 |

## 5. 既定にする候補か

- **R は既定にする候補** (働くのは再スタートで前の暫定解が外れる問題だけ。40 問では 3 問で、どれも差がない)。ただし mzzv42z では
  G+F と組み合わせないと 60 秒以内に再スタートが起きず、効果が見えない (既定では 60 秒で再スタートしない)。16 問 (highsonly16) で働くかは
  見ていない。R の 4. (打ち切り値に届かない解を暫定解にしない) と 5. (下界の報告) は再スタートの扱いの直しなので、それだけ切り出してもよい。
- G (一般整数の含意のカット) は前の調査どおり副作用 (neos-1456979・roll3000 が悪化気味) が残る。F (`FACE_SEP=off`) は全部の問題の
  根の分離を変えるので、40 問で測らないと判断できない (この調査では測っていない)。mzzv42z を解くには G と F の両方が要る
  (G だけ、F は既定の 1 回は根のカット後 -21071、RENS が固定率 0.42 に崩れて -19130)。

## 6. うまくいかなかった試み

- `ENOMOTO_MIP_RENS_DIVE_KEEP` (書いて捨てた): 近傍のダイビングの LP が反復の上限で止まったときに段を戻さない。調べると戻る理由は
  実行不能だったので意味がなく、消した。
- `ENOMOTO_MIP_RENS_DIVE_RETRY=k` (書いて捨てた): 段の LP が実行不能なら段を戻し、1 段の割合を半分にし列の順を混ぜ直して続ける。
  既定の根では固定率 0.81 まで進むが、その近傍のサブ MIP は 0.11 秒で実行不能 (`logs/e_dv2.log`、暫定解は RINS の -6620 止まり)。
  弱い根の LP 解のまわりの 0.8 の近傍には解がない。G+F では戻りが起きず (RD1〜RD3) 働かない。効果がないのでコードから外した。
- `ENOMOTO_MIP_ROOT_WIDE_SUBMIP` (develop にある) を G+F に足した 1 回 (gfw1): RINS (wide) が 29.6 秒に -20450 を出すが、
  その後の再スタートで暫定解を失い (R なし)、-20450 のまま下界 -inf。

## 7. 確かでない点

- G+F+R の 60 秒の暫定解は 8 回で -20090〜-20540 と揺れる。主な原因は根の RENS のサブ MIP (2100 列、ノード上限 18〜121 ノードで止まる
  ことが多い) と見ているが、サブ MIP の中 (`ENOMOTO_MIP_SUBMIP_VERBOSE`) はまだ見ていない。HiGHS のサブ MIP は 21 回で合計 4.25 秒。
- 120 秒の比較は 1 回ずつ。
- 下界の差 (G+F+R の 60 秒 -20735〜-20785、HiGHS の 2 回目の再スタートの後 -20672、HiGHS は 1 ノードの強分枝で -20540 まで閉じる) の
  中身は見ていない。ENOMOTO は再スタート後の根の LP を最初から解き直し (3.8〜9.5 秒)、木の強分枝が重い (1 ノード目に 4〜15 秒)。
- R の 5. の目的値のずれは「前処理は元の行を満たす点で目的値を定数だけずらす」ことを前提にしている (前の暫定解は再スタート後の
  問題の行を満たすが、打ち切り値による境界は満たさない)。
- R の 1 回 (R1) は下界が -inf: 2 回目の再スタートの後、木の 2 ノード目で時間切れになり、木の下界の集計が「-」になっている。
  再スタートの扱いとは別の報告の問題と推測 (未確認)。
