## 2. neos-1445765: 等式 1 本にだけ現れる整数列 (事実)

- 元の問題: 0-1 列 y_k (費用つき 1000 本・費用なし 1150 本)、連続列 18467 本、行 `y_k − Σ x = 0` など。当方の前処理 (TREE2_FORCEQ) は
  連続列を 0-1 列に置き換え、2146 列・1001 行になる。費用つきの y_k (1000 本) は、それぞれ等式 `Σ_{S_k} x_j − y_k = 0` の 1 本にだけ現れる。
- SCIP の前処理 (`scip_pre.py`): 当方の前処理後の問題でも 0.08 秒で 1134 列・929 行。決め手は setppc の集約 1000 列 (y_k を Σx で置き換え、
  費用を x に移す)。元の問題からだと前処理に 24.6 秒 (probing の集約 18444 列 = 連続列、setppc 998 列)。
- SCIP の前処理後の問題を当方で解くと 183.8 → 47.8 秒 (1 スレッド)、根の下界 −18698.9 → −18226 (SCIP の根は −18607)。
- 当方の列シングルトンの消去 (`presolve/colsingleton.rs`) は整数最適化の前処理で整数列を消さない (復元値が整数になる保証がないため)。

### 試作 `ENOMOTO_MIP_INTSING=1` (既定では使わない、`colsingleton.rs`)

- 整数列でも、等式 1 本にだけ現れ、その係数が ±1 で、行の他の列がすべて整数列・係数が整数・右辺が整数なら消す
  (復元値 `(rhs − Σ) / ±1` は整数。列の境界は残りの項の範囲の行になる。費用は行の他の列へ移す。連続列の消去と同じ処理)。
- neos-1445765 (1 スレッド): 前処理後 2146 → 1146 列、**183.8 → 27.0 秒・165 ノード** (SCIP 49.9 秒・145 ノード)。
- 確かめ: cargo test 409 通過 (既定・試作とも)、fuzz 7 本 bad 0、狙った fuzz (`fuzz_intsing.py`) は 5000 問で試作による誤り 1 件
  (seed 1155) → 3 節の既存の不具合が表に出たもの。直し (`ENOMOTO_MIP_TIGHTEN_INTBOUND=1`) と組で bad 0。

## 3. 既存の誤答: カットの係数の締め付け (事実、既定でも起きる)

- 狙った fuzz で、既定 (環境変数なし) でも 5000 問中 2 件 (seed 3006・3103) が誤り (SCIP で確かめて HiGHS が正しい。seed 5226 は HiGHS の誤りで
  SCIP・当方が一致)。seed 3103 は MPS (`wrong/fz3103.mps`、12 列・9 行、SCIP の最適解 `wrong/fz3103.sol`) で 1・2・4 スレッドとも再現:
  当方 −10.95 を最適と返す (正しくは −14)。`ENOMOTO_MIP_NO_CUTS=1` か `ENOMOTO_MIP_NO_CUT_TIGHTEN=1` なら −14。
- 原因 (デバッグ解 `ENOMOTO_MIP_DEBUG_SOL` と、足した診断で確かめた): `finish_cut` の係数の締め付け (HiGHS の `tightenCoefficients`) は
  「整数列 x_j がその境界になければ境界から 1 以上離れる」ことに頼るが、カットの整数列 (`cut_int`) は暗黙の整数の連続列を含み、その境界は
  丸められていない。seed 3103 では列 7 (元は連続、下限 0.532 まで締まっている) の係数 −5 を −4.34 に締め、右辺を `(5 − 4.34) × 0.532` だけ
  動かしたカットが最適解 (x7 = 1) を切った。
- 直し `ENOMOTO_MIP_TIGHTEN_INTBOUND=1` (今は既定では使わない、`separation.rs`): 使う境界 (c > 0 なら上限、c < 0 なら下限) が整数のときだけ締める。
  seed 3103・1155 とも正しくなり、狙った fuzz 5000 問 (既定・INTSING とも) で食い違い 0 (HiGHS の誤り seed 5226 を除く)。
  cargo test 409 通過・fuzz 7 本 bad 0 (`INTBOUND=1` + `INTSING=1`)。**誤答の直しなので既定にすることを勧める** (親の判断待ち)。
- 診断を足した: デバッグ解があるとき、締め付けの前は満たし後で破るカットの列・係数・境界を出す (`MIP_DEBUG_SOL: CUT_TIGHTEN ...`)。
