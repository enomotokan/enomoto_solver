## 3. 既存の誤答: カットの係数の締め付け (事実、既定でも起きる)

- 狙った fuzz で、既定 (環境変数なし) でも 5000 問中 2 件 (seed 3006・3103) が誤り (SCIP で確かめて HiGHS が正しい。seed 5226 は HiGHS の誤りで
  SCIP・当方が一致)。seed 3103 は MPS (`wrong/fz3103.mps`、12 列・9 行、SCIP の最適解 `wrong/fz3103.sol`) で 1・2・4 スレッドとも再現:
  当方 −10.95 を最適と返す (正しくは −14)。`ENOMOTO_MIP_NO_CUTS=1` か `ENOMOTO_MIP_NO_CUT_TIGHTEN=1` なら −14。
- 原因 (デバッグ解 `ENOMOTO_MIP_DEBUG_SOL` と、足した診断で確かめた): `finish_cut` の係数の締め付け (HiGHS の `tightenCoefficients`) は
  「整数列 x_j がその境界になければ境界から 1 以上離れる」ことに頼るが、カットの整数列 (`cut_int`) は暗黙の整数の連続列を含み、その境界は
  丸められていない。seed 3103 では列 7 (元は連続、下限 0.532 まで締まっている) の係数 −5 を −4.34 に締め、右辺を `(5 − 4.34) × 0.532` だけ
  動かしたカットが最適解 (x7 = 1) を切った。
- 直し `ENOMOTO_MIP_TIGHTEN_INTBOUND=1` (2026-11-19 に既定にした (d7a8e2567)、`=0` で以前の動き。`separation.rs`。7 節): 使う境界 (c > 0 なら上限、c < 0 なら下限) が整数のときだけ締める。
  seed 3103・1155 とも正しくなり、狙った fuzz 5000 問 (既定・INTSING とも) で食い違い 0 (HiGHS の誤り seed 5226 を除く)。
  cargo test 409 通過・fuzz 7 本 bad 0 (`INTBOUND=1` + `INTSING=1`)。**誤答の直しなので既定にすることを勧める** (親の判断待ち)。
- 診断を足した: デバッグ解があるとき、締め付けの前は満たし後で破るカットの列・係数・境界を出す (`MIP_DEBUG_SOL: CUT_TIGHTEN ...`)。

  前処理後の問題で 1 回判定する):
  - 主側の規則: 等式行 `a_j x_j + Σ a_k x_k = b` で、他の列がすべて (暗黙の) 整数、`a_k / a_j` と `b / a_j` が整数。整数列が整数なら
    **すべての実行可能解で** x_j は整数。

### 7.1 丸め (SEP_ROUND_IMPLINT) は正しさに要るか (理屈の確かめ、2026-11-19)

PR の比べで丸める既定が約 2% 遅かったので、丸めていない境界を受ける 10 か所が「整数列の境界は整数」を前提にした導出をしているかを読んだ。

| 所 | 境界の使い方 | 前提にするか |
|---|---|---|
| `finish_cut` の係数の締め (4 か所の呼び出し・並列の分離・並列の生成の中) | 「境界でなければ境界から 1 以上離れる」 | **する** (3 節の不具合。`TIGHTEN_INTBOUND` で境界が整数のときだけ締める) |
| `finish_cut` の小さい係数の吸収・GAP4 の非零の削り | `c × 境界` を右辺に移す | しない (どんな正しい境界でも妥当) |
| ゼロ半分 (`zerohalf_cuts`) | 整数列を境界で補って偶奇をとる | 前提にするが**自分で確かめている**: 下限・上限とも整数でない列は使わない (`is_integral` で外し、その列を含む行も使わない)。丸めないとカットが減るだけ |
| hnfcut の `map_rows` (合同式の写し) | `z_range` で `(境界 − r)/g` を切り上げ・切り下げ | 既定では使わない (`ENOMOTO_MIP_HNFCUT` 未設定で `f` をそのまま呼ぶ)。使うときも自分で丸める |
| 整数の変数上下限 `add_int_vbs` (既定の MUSHAGG=cover で作る) | 含意の値を整数に丸めて、境界で `min`/`max` | しない: 境界で切り詰めた値は弱くなるだけで、含意として正しい。使う側 (被覆の上がり) も正しい含意しか要らない |
| `VB_IMPL`・暗黙の境界のカット | 連続列 (`p.is_int` でない) の大域の境界と 0-1 列の含意 | しない (どんな正しい境界でも妥当) |
| `gen_cuts_parallel` の生成そのもの | `CutVars` (もともと丸め済み) | — |

結論: 正しさのために丸めが要るのは係数の締めだけで、それは `TIGHTEN_INTBOUND` が受け持つ。`SEP_ROUND_IMPLINT` は「カットを変える」変更
(丸めた境界でゼロ半分に入る列・締められる係数が増える) で、正しさの直しではない。既定を `0` に戻すのが筋 (判断は親・利用者)。

確かめ (`TIGHTEN_INTBOUND` 既定 + `SEP_ROUND_IMPLINT=0`、ビルド b6762abe3 相当、`fix2/`): fuzz_intsing 4000 問 bad 0、mip_fuzz_vs_highs 300 bad 0、
fuzz 7 本すべて bad 0 (締めの直しだけの d7a8e2567 でも同じく全部 0、cargo test 409 通過)。締めの直しだけで十分。

### 13.1 試作 (`ENOMOTO_MIP_INTSING` に `o`、既定はオフ。試作は `1go`。`src/presolve/colsingleton.rs` の `INTSING_HOLD`、`src/mip/mod.rs` の `presolve_mip`)

## 14. 等式でずらした費用 c' = c − λᵀA_E で固定が増えるか (数えるだけ、2026-11-19。既定の動作は変えない)

### 14.1 正しさと理屈
- 正しさ: 実行可能な点はどれも A_E x = b_E を満たすので c'x = cx − λᵀb_E (定数の差)。実行可能な点の目的の順位は c と c' で同じで、最適解の集合も同じ。
  よって「c' で最適解の 1 つを残す」固定は c でも最適解の 1 つを残す。前処理の途中の問題でも、その問題の等式の行を使う限り同じ (固定を順にかけるとき、
  各段の問題で c と c' の最適解の集合が一致するので、ほかの固定と混ぜても正しい)。λ は等式の行だけに使う (不等式の行の λ は目的を定数でなく変える)。
- 双対固定 (費用の符号と錠の向き) は c' で増えない: c'_j ≠ c_j になるのは等式の行に出る列だけで、その列は等式で両向きに錠がかかり、もともと双対固定の対象でない。
- 優越の固定 ([`dominated_binary_fixings_with`]) の費用の比べ `s_j c_j ≤ s_k c_k` も変わらない: 等式の行では文字の係数が等しい (`s_j a_ij = s_k a_ik`) ことが
  支配の条件なので、λ の分 `s_j λᵀA_j = s_k λᵀA_k` が両辺で打ち消し合う。変わりうるのは符号だけの条件 (予測の境界の (c) の `s_k c_k ≥ 0`) だけ。

### 14.2 数え上げ (診断 `ENOMOTO_MIP_DIAG_COSTSHIFT`、`scan_cs.py` → `scan_cs.jsonl`・`scan_cs_1g.jsonl`、前処理だけ 1 スレッド)
支配の固定の段で、元の費用 (base) と、λ = 根の LP の双対値の等式の分 (root)、λ = LP `min Σ_{0-1 列で等式に出る j} max(0, −c'_j)` の解 (lam) で固定の数を数えた。
- 既定の費用 (INTSING なし、P 58 問・M 32 問 = 90 問、支配の固定の段まで来た 76 問): **固定が増える問題 0**。lam は負の費用をほぼ 0 にする
  (rout 285 → 0、atlanta-ip 114 → 2、neos-1445765 1000 → 456、mzzv42z 42 → 0、sing326 46 → 0) が、固定の数は変わらない
  (air03 2297・nw04 3440・atlanta-ip 517・rail01 4500・satellites2-40 1200・mzzv42z 125 のまま。root は nw04 で 3429 に減ることもある)。
  LP の手間: lam は多くの問題で 1 秒未満、satellites2-40 46 秒・rail01 36 秒、root は rail01・cod105 で 60 秒の上限に届く。
- 1g の後の問題 (INTSING が前処理を変える 36 問): air03 160 → lam 514、nw04 451 → lam 993 と増えるが、air03 は `o` (§13.4) で 2297 に戻っていて、
  nw04 は自由な列の 10% (8745) に届かず捨てられる。INTSING が等式を範囲の行に変えた分 (§11.1 の add1) は λ で扱えないので、`o` の代わりにはならない。
- 意見: **試作に進む価値はない**。14.1 のとおり比べの部分は λ で変わらず、符号の条件で増える問題も 76 問で 0。λ が効くのは「等式が崩れた後に費用が負になった」
  場合だけで、それは `o` (固定を先にかける) で既に扱った。

## 15. 暫定解の目的の行での伝播を λ で強める (数えるだけ、2026-11-20。既定の動作は変えない)

### 15.1 診断 `ENOMOTO_MIP_DIAG_OBBT=U` (`src/mip/solver.rs` の `diag_obbt`) と `scan_obbt.py` → `scan_obbt.jsonl`・`obbt_summary.txt`
根の被約費用の早めの記録の直後 (根のカットの後の LP) で、U = 最適値 (解けなかった問題はいちばん良い暫定解) として数える。
