# 小さい問題でのプロービングの無駄な手間 (SCIP-PROBE、2026-11-20)

親の依頼: air03・neos8・irp で、SCIP より遅い差の元になっているプロービングの手間を減らす。PROBE_USELESS (analysis/scipslow_20261119 の 3・5・9・10 節、
1 回のプロービングの中で役に立たない試しが続いたら打ち切る) は不採用だったので、同じ失敗をしない形として
(a) 前の周の成果に応じた次の周の手間、(b) CLQPRB の `g` のやり直しを省く条件、(c) 再スタートの後のプロービングの手間、を考える。

- 台本: `one.sh <札> <種> <秒> <スレッド> <問題> [K=V ...]` (当方を `ENOMOTO_MIP_LOG=1` で回し、ログ → `logs/`、結果 → `res_one.jsonl`)、
  `prbscan.py` (P・M の走査 → `prbscan.jsonl`)、`fuzz.sh`、計測の `cfg.py`・`plan.py`・`run.py`・`summ.py` (scipslow_20261119 の写し)。
- `res_one.jsonl` の札: `def`・`def2` は試作の前のビルド、`pw1` は 1 版目 (下の 2 節)、`def3`・`pw` は 2 版目のビルド (マージの後) の既定と試作。

## 1. 原因 (今の HEAD、1 スレッド・種 1)

- **irp** (34.9 秒): プロービングは 4 回 (根 1.62 + 再スタートの後 1.21・1.25・1.14 秒) で、どれも固定・締め付け・同値な組が 0。
  毎回「何も見つからない間の手間の上限」`ENOMOTO_T_MIP_PRESOLVE_WORK_PROBE0` (1.15e9、問題の大きさによらない値) で止まる。
  slowm_20261119 の記録の「固定 419・21・2 本」は今の版では出ない。再スタートの問題は `from_rows` で作り直すので含意 (`conflict_edges`) を引き継がず、
  毎回 100〜180 万本を集め直している。
- **air03** (4.6 秒、`ENOMOTO_MIP_DEBUG_PRETIME=stop` で前処理 3.5 秒): プロービングは 1 回だけ (1.93 秒、8342 列中 752 列、成果 0、同じ上限で止まる)。
  ほかに clqext 0.47・支配の固定 0.40 秒。周回も再スタートもないので (a)・(c) は効かない。1 回の中の打ち切りは PROBE_USELESS と同じ話で、
  含意 (air03 は 97% が行の上限で衝突グラフから落ちた組、scipslow 14 節) を減らすことになる。手を入れない。
- **neos8** (6.4 秒、前処理 5.9 秒): CLQPRB `g` の既定の形 2.08 秒 → 含意の形 2.03 秒 → かけ直しの中 0.64・0.32 秒。(b) は analysis/clqprbg_20261119 で
  「ρ = (含意の形の成果) / (既定の形の成果) には両方の形を最後まで回す必要があり、判定を変えずに 1 周目を省けない。puriri は `g` の判定が要る」と
  結論済み。条件で予測して省く形は puriri との切り分けを 1 問に合わせることになるので作らない。
- (a) の周回 (プロービングの後の前処理のかけ直し) は「固定 > 0」のときしか起きないので、成果 0 に近い周の後の周という形がほとんど無い
  (neos8 の最後の周 0.32 秒のみ)。
- **害の確かめ** (PROBE_USELESS で遅くなった 4 問、1 スレッド・種 1): roll3000 は根のプロービングの成果が 0 なのに、再スタートの後
  (カット 320 行を足した問題) では 12 列を固定する (0.04 秒)。「前の回の成果が 0 なら次を省く」は害になる。drayage-25-23・physiciansched6-2・
  neos-827175 はプロービング 1 回が 0.01〜0.5 秒と軽く、再スタートの後に重い回は無い。

## 2. 試作 `ENOMOTO_MIP_PRBWORK` (src/mip/mod.rs の `probe`・`prbwork_*`、src/mip/solver.rs の再スタート、既定では使わない)

- **1 版目** (コミット 940c9fc2e の前、札 `pw1`): 「何も見つからない間の上限」を 1 回ごとでなく求解全体の持ち分にし、成果 0 の回の pwork を引く。
  neos-860300 で 27.7 → 44.3 秒・根の下界 3200.2 → 2668.8 と害が出た。成果 0 でも候補を最後まで試した回 (かけ直しの中の 1216 of 1216) まで持ち分から引いたため、
  捨てられたかけ直しの後のやり直しのプロービングが 144 列で切られ、含意が 55.9 万 → 6.1 万本に減った。また再スタートの後に固定が 7・9・6 本出ていた。
  (1 版目では、サブ MIP (親と同じ前処理で解くもの) のプロービングまで止めていて irp の再スタート 1 の前から道が変わったので、
  `PRESOLVE_IN_SUBMIP` の中では使わないように直した。2 版目も同じ。)
- **2 版目** (今の形): プロービングが固定・締め付け・同値な組を 1 つも得ないまま、何も見つからない間の上限 (手間か時間の安全網) で
  **打ち切られた**ら印を付け、その求解の再スタートの後のプロービングを回さない。そのときは再スタートの問題に前の求解の含意を渡し、
  再スタートの前処理で引き継ぐ (再スタートの問題は前の問題を狭めたものなので含意はそのまま成り立つ。`ENOMOTO_MIP_KEEP_IMPLICATIONS` と同じ引き継ぎ)。
  後のプロービングが何か得れば印を消す。候補を最後まで試して成果 0 の回 (roll3000 の根、neos-860300 のかけ直し) は印を付けない。
  閾値は無い (印は「打ち切られたか」の真偽だけ)。値 `f` は確かめ用 (成果 0 なら打ち切りによらず印を付ける。fuzz で省く道を通すため)。

## 3. 働く問題の数え上げ (`prbscan.py`、`prbscan.jsonl`)

- P 58 問 + M (P と重ならない 145 問) を 1 版目・1 スレッド・種 1・60 秒で回し、プロービングの各回 (列・固定・締め付け・含意・秒・pwork) と再スタートを拾った。
  203 問すべて止まった (optimal 60・infeasible 1・time_limit 142、crash 0)。
- 2 版目が働きうるのは「成果 0 のまま上限 (pwork ≥ 1.15e9) に届いた回がある」問題で、P 5 問 (air03・eil33-2・hypothyroid-k1・ns1116954・nw04)、
  M 21 問。そのうち 60 秒・1 スレッドで再スタートまで行き実際に省いたのは irp (4 回)・n2seq36q (3 回)・nursesched-sprint02 (1〜2 回) の 3 問だけ。
  ほかは再スタートが無く、既定と同じ計算になる (4 スレッド・600 秒では再スタートが起きうるので M の計測には含める)。
- 小さな型: 成果 0 で 1 秒前後使うプロービングを再スタートの度にやり直す問題は少ない。得は 1 問あたり数秒、4 スレッドではさらに小さい見込み。
