# 根・再スタートの後の根に渡す基底が特異になる元を直す試作 (2026-11-02、C)

analysis/basis_nb_diag_20261102.md の 3 節「サブ MIP の根・写し・再スタート・前処理の基底が重い問題」の続き。
前処理の LP の基底からの根 (root_probe) と再スタートの後の根 (restart) で、渡した基底が特異になって全スラック基底から
解き直している元を調べ、`ENOMOTO_MIP_ROOT_BASIS_FIX=1` で入る試作にした (既定の経路は変えない)。

  計測は rebase 前の土台どうしの比べ)。
- 台本・ログ: analysis/singular_fix_c_20261102/ (`run.py` が解いて `logs/<設定>/<問題>_r<回>.log`、`table.py` が `tables.md`)。

## 1. どこで作られ、なぜ特異になるか

### root_probe (src/mip/mod.rs の `lp_probe` → `solver::ROOT_BASIS`)

- `lp_probe` は前処理の途中で LP を解き、その基底 (列と行の状態) と行の指紋 (`rows_fingerprint`) を渡す (既定の
  `ENOMOTO_MIP_LP_PROBE_FINISH`)。
- ところが `lp_probe` の後もプロービング・**クリーク行の拡張 (支配される行の削除を含む)**・対称性の行などで行が変わる。
  根では指紋が合わないので「the rows changed after LP probing; the row statuses are not used」となり、**列の状態だけ**を
  `set_basis` に渡す。
- `set_basis` の修復 (`repair_basis`) は足りない基底変数を行 0, 1, 2, ... の論理変数で埋める。前の基底で論理変数が
  基底だった行とは無関係なので、ほぼ必ず特異になり、warm start をやめて全スラック基底から解いていた。
  - ns1116954: 前処理の LP の後のクリーク行の拡張で 6882 行を拡張・4206 行を削除。
  - mzzv42z: プロービングで 355 列固定 + クリーク行の拡張 1270 行・削除 139 行。

### restart (src/mip/solver.rs の再スタート → `RESTART_BASIS` → `restart_basis_for`)

- 再スタートの直前の LP の列の状態と、各行の中身・論理変数の状態を渡し、行は中身 (`row_key`) で照らし合わせる。
- 再スタートの後の前処理は**固定した列を行から消す** (列の番号は保つ) ので、その列を含む行は中身が合わず、合わない行の
  論理変数はすべて基底に入る。基底変数が多すぎる分は `repair_basis` が後ろの構造列から外す。
- 加えて、前の基底で基底だった列が今の LP では**空の列** (どの行にも現れない) になり、そのまま基底に残る。空の列が
  基底にあれば必ず特異。mzzv42z は 9351 行中 4065 行しか合わなかった。

## 2. 試作 (`ENOMOTO_MIP_ROOT_BASIS_FIX=1`)

src/mip/solver.rs の `root_basis_rebuild`。前の LP の列の状態・行 (中身と状態)・解 `x` から、今の LP の特異でない基底
(基底変数がちょうど行の数) を MIP 側で作り、行の状態も入れて `set_basis` に渡す (修復は何もしない)。

1. 構造列: 基底だった列のうち空の列は外す (非基底は解の値に近い側)。固定の列は基底に残す (双対実行可能なまま双対単体法が外す。
   値 `f` で外す形も試せる。mzzv42z で外すと根の LP が 40775 反復 51 秒、残すと 1652 反復 0.9 秒)。
2. 行: 前の行から今の LP に現れない列を除いてから中身で照らし合わせる。合わない行 (拡張したクリーク行・新しい行) は、前の解 `x`
   での行の活動が境界にあれば非基底 (その側)、なければ論理変数を基底にする (値 `a` で常に基底にする形。mzzv42z で 12783 反復)。
3. 基底変数の数を行の数に合わせる (多ければ合わない行の論理変数から外し、少なければ非基底の行の論理変数を足す)。
4. 疎な LU (`crate::simplex::lu::rank_deficient_remainder`、呼ぶだけで simplex 側は変えていない) でピボットの取れない列を、
   残りの行の論理変数に差し替える (4 回まで)。

- root_probe: `lp_probe` が行の中身・状態・解を `ROOT_BASIS_SAVED` に置き、根で指紋が合わないときだけ作り直す (合えば今まで通り)。
  DSE 重みは使わない。
- restart: 再スタートの直前に解 `x` も `RESTART_X` に置く。照らし合わせた行が 9 割未満 (`ENOMOTO_T_MIP_ROOT_BASIS_FIX_MATCH`) か、
  外した列が行の 2% (`ENOMOTO_T_MIP_ROOT_BASIS_FIX_DROP`) を超えれば基底を渡さない (全スラック基底から)。値 `r` なら常に渡す。
  mzzv42z の再スタートは、照らし合わせを 75〜78% まで増やしても作った基底に主実行不能な基底変数が 4580 個あり、双対単体法が
  bfrt_exhausted の繰り返し・特異な再分解の巻き戻しを重ねて 1 万反復 20 秒で終わらず、全スラック基底に戻っていた
  (既定は全スラック基底から 1.1〜1.8 万反復 5〜8 秒)。これは単体法側の振る舞いなので C では基底を渡さない形に留めた。
- 試す形の文字 (`ENOMOTO_MIP_ROOT_BASIS_FIX` の値に含める): `f` 固定の列も外す、`a` 合わない行は常に基底、`n` 上限・下限の
  置き場所も渡す (`set_basis_nb`)、`k` 現れない列を除かずに照らし合わせる、`r` 再スタートで常に渡す。計測は `1`。

## 4. 判断

- 「渡した基底が特異で丸ごと捨てられる」こと自体は、元 (行の状態の欠落・固定して消した列・空の列) で直せた。root_probe・restart
  とも特異は 0 になり、根の LP の反復は大きく減る。
- しかし全体の時間は良くならない (58 問 1 回で +5.1%)。損の見込みだった ns1116954 の 12 秒は、前処理の LP と根の LP が別の LP
  (クリーク行の拡張で締まる) になっているためで、基底を写しても取り戻せなかった。ほかの問題の根の LP は 1〜2 秒しかなく、
  反復が減っても数秒の得で、根の頂点が変わることによる経路の揺れ (neos-960392・physiciansched6-2 で根の RENS・カットの道が
  変わる) の方が大きい。
- **既定にはしない**。試作は残す (`ENOMOTO_MIP_ROOT_BASIS_FIX`)。
- 次に試すなら:
  - ns1116954 型: 前処理の LP を解く時点を、行を変える前処理 (クリーク行の拡張) の後にずらすか、行の変化が大きいときは前処理の
    LP の基底を渡すのをやめる (渡しても得がなく、特異な基底の分解の手間だけかかる)。
  - restart だけ試作を入れる形 (再スタートの後の根の LP は 58 問で 6.6 → 1.3 秒。neos-960392・physiciansched6-2 の揺れは
    root_probe 側の頂点の変化による)。今回は分けて計っていないので、`r`/root_probe を分ける切り替えを足して 58 問で確かめる。
  - mzzv42z の再スタートの基底 (主実行不能が多い基底で双対単体法が bfrt_exhausted を繰り返す) は単体法側 (A) の話。
