# カットプールの伝播を既定にする (2026-10-28)

ブランチ `inv/cutpool-prop-20261028`。試作のまま既定で使っていなかったカットプールの伝播 (`propagate_cut_pool`、HiGHS の
`HighsDomain::CutpoolPropagation` に当たる) を、HiGHS と同じ差分評価に作り直し、効かない問題では止めるようにして既定にした。
あわせてノードの伝播の不動点 (`PROP_FIXPOINT`) も既定にした。

## まとめ

1. **遅くなる原因は伝播の手間** (事実)。以前の試作は毎ノードでプールの全カットを走査していた。1 スレッド・60 秒で
   timtab1 は 23 秒 (11395 回、プール 1 万本)、misc07 は 8 秒、rout は 9.4 秒、neos-860300 は 343 回で 6 秒 (締めた境界 0) を
   これに使っていた。差分評価にした後は rout・misc07 で既定より良くなり (§2)、手間を除いた伝播そのものの副作用は小さいと見る
   (推測寄り。timtab1 は差分評価でも 60 秒の下界がやや悪い)。
2. HiGHS は (a) カットの最小活動量を境界の変更ごとに差分で持ち、(b) 活動量が変わり、余裕が capacity threshold
   (`max |a_j| × 幅`) 未満のカットだけを伝播し、(c) 巻き戻した変更の理由のカットに印を付け直す。同じ形にした
   (`propagate_cut_pool_incr`、`CutPropState`)。時間は timtab1 23 -> 3.5 秒、neos-860300 6 -> 0.18 秒、misc07 8 -> 1.1 秒、
   rout 9.4 -> 1.2 秒。
3. 差分でも候補が減らない問題がある: pk1 は候補が毎回プールの半分 (2 千本) で、1 スレッド 120 秒中 81 秒かけて 1 本も締めない。
   **1000 回呼んで「締めた境界 + 刈ったノード × 10」が呼び出しの 1% 未満なら、その求解では止める**ようにした。
4. 計測 (4 スレッド・60 秒、交互に各 2 回): MIPLIB 40 問 SGM 20.45 / 20.57 -> **18.90 / 19.61 秒** (解けた数 25 / 26 -> 26 / 26)、
   負けている 21 問 18.63 / 15.78 -> **17.18 / 15.97 秒** (18 / 19 -> 20 / 19)、最適値の食い違い 0。

## 2. 差分評価版 (`propagate_cut_pool_incr`)

- `Domain` に「前回から境界が変わった列」の 3 本目の記録 (`take_changed_for_cutpool`、`track_cutpool` を呼ぶまでは数えない) を足した。
- `CutPropState`: 列ごとの (カット, 係数) の索引、活動量に入れた境界、カットごとの最小活動量 (有限部分と無限の項の数)、
  `cap` (取り込んだときの大域的な境界での `max |a_j| × 幅`。連続列は幅に `1 - CONT` を掛ける)。
- 呼び出しごとに、変わった列の項だけ活動量を直し、その列を含むカットに印を付ける。印の付いたカットのうち、余裕が `cap` 未満
  (またはちょうど 1 項が無限) のものだけを今の境界で計算し直して伝播する。
- 前回と同じ境界に戻っただけの列は飛ばす (ダイビングなどで変えて戻した列。neos-860300 の手間の大半)。その代わり、前回の後に
  境界を締めたカット (`fired`) は必ず見直す (締めた境界が巻き戻されたとき。HiGHS は巻き戻した変更の理由のカットに印を付ける)。
- 作り直し: 最初、プールの追い出し (`evict_pool`) の後、512 回ごと (`ENOMOTO_T_MIP_CUTPOOL_PROP_REFRESH`、誤差の蓄積を消す)。
- 確認 (`ENOMOTO_MIP_DEBUG_CPP_CHECK`): 差分の活動量は計算し直したものと一致 (不一致 0)。候補から漏れて締まるカットは、
  PROP_FIXPOINT ありでまれに 1 本 (同じ列の別のカットの締め付けが後で巻き戻され、活動量に効かない側の境界だけが緩む場合)。
  HiGHS も同じ場合は印を付けないので、そのままにした。
- 以前の全走査は `ENOMOTO_MIP_CUTPOOL_PROP_FULL` で残す。

差分評価版 (1 スレッド・60 秒、伝播の時間): timtab1 3.5 秒 (12097 回、30 秒)、misc07 1.1 秒、rout 1.2 秒、neos-860300 0.18 秒、
qiu 0.9 秒。rout は cpfx で 41.6 -> 18.8 秒。

## 3. 効き目で止める

pk1 (1 スレッド・120 秒): cp は伝播に 81 秒 (78653 回、締めた境界 0、候補 1.7 億本・非零 85 億)、ノード 155366 -> 78677。
差分にしても、毎回プールの半分が「余裕 < cap」を満たす。`ENOMOTO_T_MIP_CUTPOOL_PROP_TRIAL` (1000) 回ごとに、
「締めた境界 + 刈ったノード × 10」が呼び出しの `ENOMOTO_T_MIP_CUTPOOL_PROP_MIN_RATE` (0.01) 倍未満なら止める。
pk1 は 1000 回 (0.04 秒) で止まり、qiu (1.9%)・misc07・timtab1・rout は止まらない。

## 6. 残り (HiGHS との差)

- HiGHS は連続列を幅の 0.3 倍以上縮むときだけ締める (`adjustedUb`)。こちらは 0.1 倍 (`ENOMOTO_T_MIP_CUTPOOL_PROP_CONT`)。試していない。
- `cap` は大域的な境界で一度だけ計算する上界。HiGHS は伝播のたびにノードの境界で計算し直す (pk1 のように候補が多い問題で効くはず)。
- カットプールで締めた境界は衝突解析では「外からの変更」(決定と同じ扱い) で、カットまで遡らない。HiGHS は `Reason::cut` から
  衝突を作る。
- timtab1 (HiGHS 7k ノードで証明) はこれだけでは解けない。
