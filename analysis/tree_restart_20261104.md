# 木の中の再スタートの試作を 1 つにまとめる (2026-11-04)

生データ: `analysis/tree_restart_20261104/`
- `res.jsonl`, `logs/`: 600 秒・5 問
- `res58.jsonl`, `run58.log`: 58 問・60 秒
- `run1.py`, `run58.py`, `q*.sh`: 計測用
- `summ.py`: 表を出す

**既定の動きは変えていない。** 新しい試作は `ENOMOTO_MIP_TREE_RESTART` が `1` か `force` のときだけ動く。木の重みの記帳 (`wtree`) も、この試作が切れているときは何もしない。

## 1. まとめ方

前の 2 つの試作は、どちらも HiGHS の木の大きさの見積もりを使って再スタートを決めていた。

| | 前の書き方 | 違い |
|---|---|---|
| `TREE1_RESTART` (tree_close1) | 主スレッドだけで判定する | `=f` で `force_restart` |
| `TREE4_RESTART` | 別の判定関数 `tree4_restart_due` と `t4r_*`、`maybe_restart` の中の `t4_force` | `=force` で固定数の閾値を外す |

これを次のように 1 つにした。

- 判定は `tree_restart_due` の 1 つだけにした。
  - 呼び出しの塊も 1 つで、流れは「判定 → `join_workers` → `force_restart` で `maybe_restart` → 断られたら主スレッドだけで続ける」。
  - `maybe_restart` の強制の道も `force_restart` の 1 本だけにした。
- 環境変数は `ENOMOTO_MIP_TREE_RESTART` にまとめた。

  | 値 | 動き |
  |---|---|
  | `1` | 試作。新しく固定された列が閾値に満たなければ見送る |
  | `force` | 閾値を見ない |
  | `inc` | 以前この名前で入っていた、暫定解を起点にする試作 |
  | `0` / `off` / 未設定 | 既定 (切) |

- 古い名前は別名として残した。
  - `ENOMOTO_MIP_TREE1_RESTART=f` は `1` に、それ以外の値は `force` になる (前の `=1` は閾値を外していたため)。
  - `ENOMOTO_MIP_TREE4_RESTART=force` は `force` に、それ以外の値は `1` になる。
  - ログは `ENOMOTO_MIP_TREE_RESTART_LOG` と `ENOMOTO_MIP_TREE1_RESTART_LOG` のどちらでも出る。

調整用の環境変数:

| 名前 | 既定値 | 意味 |
|---|---|---|
| `ENOMOTO_T_MIP_TREE_RESTART_FIRST` | 1000 | 判定を始める全体のノード数 |
| `ENOMOTO_T_MIP_TREE_RESTART_EVERY` | 100 | 判定の間隔 (全体のノード数) |
| `ENOMOTO_T_MIP_TREE_RESTART_MIN_FIX` | 1 | 新しく固定された列の最小本数 |
| `ENOMOTO_T_MIP_TREE_RESTART_FIX_FRAC` | 0.01 | 新しく固定された列の最小割合 (根で自由な整数列に対して) |
| `ENOMOTO_T_MIP_TREE_RESTART_MIN_LEFT` | 0.1 | 残り時間が制限時間のこの割合を切ったら再スタートしない |

## 2. 固定数の閾値 (試作の既定)

見積もりで「木が大きすぎる」が必要な回数続くと、新しく固定された整数列の本数を数える。
- 本数が `max(1, 0.01 × 根で自由な整数列の本数)` に満たなければ、再スタートしないで続ける。
  - ログには `TREER: ... skipped: newly fixed ...` と出す。
  - 見積もりの起点 `(done, q, ub, lb)` は今の点に置き直す。続けて毎回見送らないようにするため。
- `force` のときはこの検査をしない。そのときも `maybe_restart` の中の閾値 (1 回目 1%、2 回目から 2.5%) は `force_restart` で外れる。
- 前の版では固定 0 本でも再スタートしていた。今の版では、csched008・fiball・kasai に木の中の再スタートが一度も起きない (見送りが 9〜39 回)。

## 3. 木の重みの二重数えを直す

前の版でも、ほかのスレッドの開いたノードの重み (`wopen`) は `publish_tree_weight` で 16 ノードごとにしか更新していなかった。そのため次の 2 つの数え違いが起きていた。

- 共有の待ち行列に渡したノードが、渡した側の `wopen` と共有の待ち行列の両方で数えられる (二重数え)。
- 共有の待ち行列から受け取ったノードは、次の更新までどこにも数えられない (数え漏れ)。

これを次のように直した。

- 重みを記帳する欄 `ThreadSlot.wtree` を新しく設けた。
  - `wopen` はヒューリスティクス役の起動の判定 (既定で入) が読むので、そちらには触らない。
  - 試作が入っているときだけ記帳する。
- 渡すとき・受け取るときに、共有の待ち行列の錠の中で同じだけ `wtree` を動かす。
  - 渡す側 (`pool_donate*` の 4 か所) は引く。
  - 受け取る側 (`pool_acquire`、`pool_balance`、pool2/pool3、`tree1_pool_take`) は足す。
  - `pool_acquire` の待ちに入るときは 0 に戻す。
- 判定では「主の待ち行列 + 潜っている節」と、錠の中で読む「共有の待ち行列 + ほかのスレッドの `wtree`」を足す。

## 7. 結論

- 試作は 1 つの判定と 1 つの環境変数 (`ENOMOTO_MIP_TREE_RESTART`) にまとまった。
  - 古い 2 つの名前は別名として残した。
  - 固定数の閾値 (自由な整数列の 1%、少なくとも 1 本) が試作の既定。
- **効き目:** swath3 (600 秒で解けなかったのが 150〜420 秒で解ける) の 1 問だけ。固定 0 本の無駄な再スタートはなくなった。
- **害:** 58 問の 60 秒で SGM +1〜3%。主に eil33-2 (固定 170 本の再スタートで解けなくなる)。
- 既定で入れるには、eil33-2 のように固定数が足りても損になる場合を見分ける条件がまだない。今は既定で切のままにする。
- 次に試すなら、次の 2 つの案がある。
  - 再スタートの後にかかりそうな根の費用 (1 回目の根の時間) と残り時間を比べる。
  - 1 回目の木の中の再スタートは、ノード数が `FIRST` の数倍になるまで待つ。
- `cargo test --release --lib`: 339 通過・失敗 0・無視 18 (3 版)。
