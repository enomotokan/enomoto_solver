# mzzv42z: HiGHS の前処理のどの手順が根の LP に効くか (2026-10-24)

環境: 4 CPU のクラウドのコンテナ (`nproc` = 4)。ソルバーは同時に 1 本。土台は inv/mzzcmp-20261023 に
claude/enomoto-solver-heuristic-survey-xjlnol の 9b31391 (mixoc が既定) を merge したもの。HiGHS 1.15.1 (highspy)。
台本・ログは `analysis/mzzpre_20261024/`:
- `hrule_lp.py <mps> [キー=値]` (HiGHS の前処理をオプションつきでかけ、前処理後の大きさと LP 緩和の値)、`hrule_batch1.sh` (規則を 1 つずつ切る)
- `hdiff.py` (消えた列を、前処理後の LP 解 6 個を後処理で戻して「固定」と「代入」に分ける)、`hbounds.py` (締まった境界を元の問題に当てる)、
  `hcoef.py`・`hcoef_apply.py` (係数の変わった行・それを元の問題に写す)、`hsubs.py` (同値な列の組を探して足す)、
  `hrowdiff.py` (元の問題の LP 解が前処理後のどの行を破るか)、`hclq_apply.py` (列が足された集合詰め込み行だけを元の問題に写す)、`fixmps.py`
- ENOMOTO: `run_cfg.sh <問題> <秒> <名前> [環境変数]`、`batch1.sh`〜`batch4.sh`、`batch3_scan.sh` (55 問の洗い出し、`logs/scan.tsv`)、
  `summarize.py`、`check_opt.py` (「最適」を benchmarks/*.json の HiGHS の最適値と照合、`logs/check_opt.tsv`)

略号: rf = `ENOMOTO_MIP_CLIQUE_EXTEND_ROWS_FIRST=1` (この調査の手当て)、eq = `ENOMOTO_MIP_PROBE_EQUIV_FIX=1`、rfeq = 両方。

## 結論

1. **HiGHS の前処理で根の LP を上げているのは「クリークの統合 (runCliqueMerging)」** (事実、規則を切った値と HiGHS のソースから)。
   probing と Enumeration presolve はどちらも最後に `finaliseProbing` を呼び、そこで集合詰め込み行にクリーク表の文字を足す
   (ログの "lifted nonzeros")。だからどちらか一方を切っても根の LP は -21424 のまま、両方切ると -21623 (前処理なしと同じ) になる。
   固定 (831 列)・締めた境界 (43 本)・係数の強化 (38 行) を元の問題に当てても LP は -21623 のまま動かない。
   列が足された集合詰め込み行 674 本 (3072 非零) だけを元の問題に写すと -21462。
2. **ENOMOTO も同じ手順 (`extend_clique_rows`) を持っているが、プロービングの含意が多いと効かない** (事実)。`ENOMOTO_MIP_NO_PROBING=1` だと
   根の LP は -21423.67 (HiGHS のプロービングなしの前処理後とまったく同じ値)、既定 (プロービングあり) は -21534。原因は 2 つ:
   (a) 衝突グラフに含意の辺が多い (行から 205346 辺、含意 1186997 本) と、番号順の貪欲が LP に効かない文字を先に取り、行から作る辺での拡張を塞ぐ。
   (b) プロービングで 0 に固定された列は前処理をかけ直すまで行に残り、その列を含む行は集合詰め込み行と見られない。
3. **手当て `ENOMOTO_MIP_CLIQUE_EXTEND_ROWS_FIRST` (既定は変えない)**: (a) まず行から作る衝突グラフだけで文字を足し、その後に含意を含むグラフで
   足せるだけ足す。(b) 0 に固定された列を行にないものとして見る (値 `fix0` は (b) だけ)。根の LP は -21534 → **-21424**
   (`fix0` だけなら -21489 で、eq と同じ値)。HiGHS の既定の前処理後の問題は -21414。
4. **効果 (60 秒 3 回ずつ、証明はどの設定も 0 回)**: 根のカット後の下界は既定の -21009〜-20925 から -20835〜-20824 (rf) に上がる。
   60 秒の下界の平均は 既定 -20792 / rf -20723 / rfeq -20744 / eq -20737。値の平均は 既定 -20240 / rf -20360 / **rfeq -20427** / eq -20270。
   **根の RENS は rf だけでは崩れる** (3 回中 2 回が固定率 0.35)。**rfeq では 3 回とも崩れない** (固定率 0.66〜0.73、サブ MIP は 9〜12 秒で -20360〜-20420)。
5. **既定にする候補か: rfeq は候補**。ただしもう少し確かめてから: 副作用 (60 秒 1 回ずつ) は neos-960392 の値 -228 → -206 (rf)・-237 (rfeq)、
   roll3000 は rfeq で 43.2 秒で証明 (既定は 60 秒で 12890・下界 12617.7)、physiciansched6-2 は値・下界とも良くなる。
   ほかの 50 問はクリーク行の拡張が変わらない。誤った最適値 (HiGHS と違う「最適」) は 0 回 (59 件を照合)。

## 1. HiGHS の前処理の規則を 1 つずつ切る (前処理後の LP 緩和、`logs/hrule_batch1.log`)

| 設定 | 前処理 (秒) | 行 | 列 | 非零 | LP 緩和 |
|---|---|---|---|---|---|
| 既定 | 18.5 | 6139 | 6980 | 80276 | -21414.2 |
| probing なし (`presolve_rule_off=32768`) | 2.0 | 9539 | 10781 | 132359 | -21423.7 |
| Enumeration なし (65536) | 13.4 | 6172 | 7033 | 80195 | -21423.7 |
| probing・Enumeration なし (98304) | 0.2 | 10316 | 11422 | 150451 | -21623.0 |

| `mip_lifting_for_probing` = 0 / 1 / 2 | 17〜18 | 6139 | 6980 | 80276 | -21414.2 |

| Sparsify なし / Parallel なし / Aggregator なし / Doubleton なし | 17〜21 | 6100〜6630 | | | -21421〜-21424 |

- -21623 → -21424 は probing か Enumeration (どちらか一方で足りる)。-21424 → -21414 は規則の組み合わせ (Sparsify・平行な行と列・
  Aggregator・Doubleton のどれを切っても -21421〜-21424 に戻る) で小さい。
- HiGHS のソース (v1.15.1 `HPresolve::finaliseProbing`): `cliquetable.runCliqueMerging(domain)` の後、拡張の文字を行に足し
  (`liftedNonZeros`)、含まれるクリーク行を消し、固定を外し、`applyConflictGraphSubstitutions` で同値な列を代入する。
  Enumeration (`enumerateSolutions`) も probing も最初に `prepareProbing` (行からクリークを取り出す) を呼び、最後に `finaliseProbing` を呼ぶ。

## 6. 次の手 (推測を含む)

- rfeq を既定にする前に、mzzv42z の回数を増やし (5 回以上)、neos-960392・roll3000・physiciansched6-2 を 3 回ずつ流す。
  eq は `ENOMOTO_MIP_PROBE_EQUIV_FIX` の前の評価 (physiciansched6-2 などの副作用) と合わせて見る。
- 貪欲の改善: HiGHS は拡張の候補を乱数で並べ替える (`randgen.shuffle`)。ENOMOTO は番号順。行から作るグラフを先に使う手当ては、
  含意の辺だけで足せる文字を塞ぐことがある (physiciansched6-2 の非零が減る)。LP の解の値で候補を並べる (分数値の大きい文字を先に) と
  両方に効くかもしれない。
- RENS が崩れない理由の残り (代入で列が減ること) と、証明に要る再スタートの連鎖 (前の調査 mzzcmp_20261023 の (b)・(c)) は残る。
