# ns1688926 の停滞の原因と対処: `x_B` のずれに応じた主実行不能の許容誤差 (2026-10-03)

対象: Mittelmann ns1688926 (32,768 行 × 16,587 列、1.7M 非零)。論文の計測では ENOMOTO・HiGHS は 600 s で打ち切り、
CLP は 18.5 s。前回 (`analysis/large_problems_20261002.md` §3) は「8,192 行を消す強制列の前処理を入れても双対単体法が
退化で進まない」とした。今回は退化ではなく、数値誤差の雑音を主実行不能と見て追い続けていたことが原因だと分かった。
base = `52d1879` (`/home/user/venv_base2`)、計測機は 4 CPU。

## 1. 症状

- `ENOMOTO_DEBUG_EXT_TRACE` で 2,000 反復ごとに実行不能行のプールを見ると、約 14,000 反復で本物の実行不能はほぼ無くなる
  (目的関数の増分は 3.3808238e6 から動かない) が、逸脱 1e-9〜2e-5 の行が 7,000 行前後、出たり消えたりし続ける。
  27 万反復でも終わらない。
- 判定の許容誤差 (`LEX_REL_TOL` = 1e-9 の絶対値) を 1e-7・1e-8 に広げても終わらない (1e-7〜1e-5 の行が 3,000 行残る)。
  1e-5 にすると主ループは 14,348 反復で終わる (CLP は 14,598 反復で双対を終える) が、その後の polish
  (`PRIMAL_FEAS_TOL * max(1, |x|)` = 1e-7 相対) が同じ行を追って終わらない。
- 残る行の `|x_B|` は 1e-5 程度で、逸脱は `|x_B|` に比例しない (相対許容誤差では救えない)。

## 2. 原因: 右辺の桁と `x_B` の増分更新の誤差

- 問題は L1 回帰型 (等式行 8,192 本に係数 1〜77,870 の密な 202 列、自由列 `y_k`、`e_k ≥ ±y_k`)。前処理の伝播が自由列
  `y_k` に [−5.3e8, 5.9e9] (スケール後) という緩い上下限を付け、標準形への平行移動 (有限な側を 0 に) で右辺が 5.7e8 になる
  (元の右辺は 5.3e6)。`x_B` は 5.7e8 の桁の量の差なので、1 ULP でも 1e-7 の桁。
- 周期的な再分解で、増分更新で保った `x_B` と解き直した `x_B` を比べると、全行で最大 3.6e-3、実行不能な行だけでも
  1e-5〜5e-5 ずれている。実行不能と判定した行の 1〜2 割は、解き直すと実行可能 (1e-9 以下)。つまり逸脱の大きさが
  `x_B` 自身の誤差より小さく、どちらに転ぶかは雑音で決まる。
- CLP は同じ状況で `ClpDualRowSteepest::pivotRow` の許容誤差に主残差 `largestPrimalError` (上限 1e-2) を足すが、CLP の
  主残差は 2e-9 と小さい (スケール後の右辺は 5e4〜7e4 で、ENOMOTO より 4 桁小さい)。CLP も最後の 300 反復で 6,471 行・
  合計 0.02 の微小な実行不能を抱えるが、そこから抜けている。

## 3. 試したこと

| 案 | 結果 |
|---|---|
| 許容誤差を主残差 `‖b − A x‖∞` 連動に (CLP と同じ量) | 主残差は再分解直後で 1e-8〜1e-6 と小さく、終わらない |
| 伝播で付いた、元は無限の側の大きい暗黙の上下限を無限に戻す (`|bound| > 1e7`) | 右辺 5.7e8 → 1.5e8。終わらない |
| 上に加え、箱型列を 0 に近い側の境界へ寄せる (反転) | 右辺 → 1.5e7、逸脱の最大 2e-5 → 2e-6。それでも 1e-7 超が 5,000 行残り終わらない |
| 上 2 つ + 許容誤差 1e-6 固定 | 164 s で最適 (polish が長い) |
| **許容誤差を `x_B` のずれ連動に (下)** | **約 20 s で最適** (上の 2 案は不要) |

## 4. 対処 (採用)

`src/simplex/slope_intercept_dual.rs`:

1. 周期的な再分解 (`need_refactor`) の `resync_x_b` で、上書き前の `x_B` と解き直した `x_B` の相対的なずれ
   `err = max_i |Δx_i| / max(1, |x_i|)` を測る (段階 B のみ。ピボットの不一致の後や段階の移行の後の再同期では測らない:
   その差は雑音の大きさではない。bnl1 で数値的破綻の後の差 2.7 を拾って経路が変わった)。
2. 候補の許容誤差 `ROW_INFEAS_TOL (1e-9) + min(ROW_ERR_CAP (1e-5), ROW_ERR_MULT (1) * err)` を、実行不能な行の過半
   (`ROW_ERR_POOL_FRAC` = 0.5) がその候補以下の逸脱しか持たない、つまり残りがほぼ雑音だけのときにだけ採る
   (`noise_gated_row_tol`)。そうでなければ基準値 1e-9。この条件を付けないと square41 (ずれ最大 8e-7) で経路が変わり
   反復が 17,927 → 23,771 (+33%) に増えた。dfl001 も経路が変わった。条件付きでは Netlib 93 問・square41・dfl001 は
   base と反復数が同じ。ns1688926 では 13,651 反復で初めて条件が成り立つ (プール 7,849 行のうち 7,699 行が雑音水準)。
3. 許容誤差は `RowBounds::tol` に持ち、主ループの逸脱判定 (`deviation_flat`・`deviation_core`・`refresh_row`・
   `xb_update_par`) はそれを読む。`thread_local` に置いて毎回読むと、拡張モジュールでは関数呼び出しになり Netlib の
   幾何平均が +0.7% 遅くなった。
4. polish (`row_deviation_plain`) の許容誤差も、主ループの最後の値を下回らない。

ns1688926: 打ち切り → 19.9 s、目的関数値 262.135785 (CLP 262.135841、相対 2.2e-7)。
