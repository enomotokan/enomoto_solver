# Linf_520c (Mittelmann) の内点法 + クロスオーバーが収束しない件 (2026-10-14)

`root_solver="ipm_crossover"`、develop `f5f3ce6` (irish-electricity の対策の後)。4 コアの計算機で、16 スレッドは
`max_threads` の上限を手元だけ外して計測した (コミットしていない)。最適値 0.19886847 (CLP)。

## 1. 結果: 直っていない (スレッド数にもクロスオーバーにも依らない)

| 版 | 結果 |
|---|---|
| irish の対策前の既定、16 スレッド | 1,200 秒で打ち切り (クロスオーバー後の二段解法が 6.4 万反復、実行不能行 3.4 万前後のまま) |
| 今の既定、16 スレッド | 同じ (900 秒で 4.2 万反復、実行不能行 4.3 万前後) |

- 内点法は 1・4・16 スレッドで反復の経路がまったく同じ (時間だけが違う: 695・227・239 秒)。
- 内点法が 200 反復の上限で止まり、最良の点の相対残差は (主 30、双対 0.57、ギャップ 9.99e7) 倍。ギャップの受理の倍率
  `IPM_ACCEPT_GAP_REL` = 1e8 のためクロスオーバーに渡され、基底は主実行不能 18,452 (修復の上限 1,569 を超えるので修復なし)、
  仕上げの二段解法が終わらない。irish の対策 (主単体法の比率テスト、修復した基底の再利用) はこの経路に関わらない。

## 2. 内点法が止まる仕組み

- 費用のある列は 2 本 (目的の変数 t)。反復 10 までに t (列 62368) が 1.2e6、≥ 行のスラック列 1,712 本が 1.2e6 になる
  (最適値は内部の単位で 1e-3 程度)。
- そのスラック列の双対残差はすべて 5.84e-4 (≈ 1/1712: t の費用 1 が 1,712 行に均等に配られた形)。必要な乗数は
  z = 5.84e-4 で符号は実行可能だが、s = 1.2e6 では s·z が μ (1e-9) と合わず z が 1e-16 につぶれ、s を 0 近くへ戻す歩幅が
  取れないので抜けられない。双対残差は反復 12 から 200 まで 5.84e-4 のまま。
- 発端は初期点: Mehrotra 型の一律の持ち上げで、最小二乗解の少数の列の境界違反 (約 2e4) に合わせて全ての s, z が
  約 4.7e4 になる (初期の主残差 4.68e4、μ 2.4e9)。境界の近くにあるべきスラック列まで 4.7e4 から始まり、x と s の差を
  埋める過程で t とスラック列が 1e6 へ押し上げられる。

## 3. 試した案 (いずれも 200 反復で未収束、200 反復時点の値)

| 案 | 目的値 (内部) | 双対残差 | ギャップ |
|---|---|---|---|
| 既定 | 3.52e6 | 5.84e-4 | 3.52e6 |
| 近接中心の毎反復更新 / 正則化の下げ方 0・3 / Gondzio 2 回 | 2.5e6〜3.5e6 | 5.84e-4 | 同程度 |
| 正則化の下限をギャップに比例 (1e-2) | 3.3e5 | 1.24e2 | 5.4e10 |
| μ の下げすぎの保護 `ENOMOTO_T_IPM_INFEAS_GUARD` = 1・10・100 (新設) | 3.3e6〜3.5e6 | 5.84e-4 | 同程度 (反復 10 までに崩れている) |
| 列ごとの初期点 `ENOMOTO_T_IPM_INIT_LOCAL` θ = 0.01 (新設) | 3.34e4 | 5.84e-4 | 3.34e4 |
| 同 θ = 1 | 4.46e-3 | 4.3e-6 | 4.9e-3 |
| 同 θ = 10 | 3.05e-3 | 7.0e-8 | 3.3e-3 |
| θ = 1 + 保護 K = 10 / θ = 1 + Gondzio 2 回 | 4.4e-3 / 4.0e-3 | 4.6e-6 / 5.3e-6 | 5.0e-3 / 4.3e-3 |

列ごとの初期点 (θ ≥ 1) で 1e6 への押し上げはなくなり、目的値は 3 桁以上改善するが、ギャップが目的値とほぼ同じ大きさ
(3〜5e-3) のまま縮まない (双対の目的値が 0 付近から伸びない) 別の停滞が残る。二つの新しい調整項目は試験用で、既定は無効
(既定の動作は変わらない)。

## 4. 残り

- θ ≥ 1 の後の停滞 (ギャップが縮まない) の原因の調査。
- 列ごとの初期点を既定にするかは、Netlib・Kennington・Mittelmann での比較が要る (初期点は全ての問題の経路を変える)。
- 粗い点 (ギャップ 1e8 倍) をクロスオーバーに渡す受理の条件の見直し。ただし Linf_520c は二段解法でも 600 秒で解けない
  (CLP は Idiot + 主単体法で 30〜90 秒、`analysis/fable_mitt_b_20261004.md`)。
