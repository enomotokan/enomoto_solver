  `logs/b1/` は 1 版目 (内点法の時間を根のカットの時間の上限に数えていた版)、`logs/b7/` はゲートの判定を分離の前に移した版。

## 1. 試作 (環境変数。既定は変えない)

`src/mip/separation.rs` の `root_cut_loop` にある。

| 環境変数 | 意味 |
|---|---|
| `ENOMOTO_MIP_INOUT_SEP=1` (`ipm`) | ループの始めに、根の LP (今のカット込み) を内点法 (費用つき、`interior_point(false, …)`) で 1 回だけ解き、最適面の中心付近の点 x_c を得る。各ラウンドで x(α) = x_lp + α (x_c − x_lp) を [`separate`] (点から行を集約する分離: 行ごとの MIR・被覆・フロー被覆、zerohalf、implied bound、経路集約、tableau 行の集約) にかける。x_lp を切るカットとほぼ平行 (0.99) なものを除いたうえで、別枠 (`ENOMOTO_T_MIP_INOUT_MAX_CUTS`、既定 50 本、既定の選択 `select_cuts`) で選び、x_lp のカットと一緒に LP に入れる。x(α) で破れる候補がなければ x_c ← x(α) とする (Ben-Ameur & Neto の更新)。 |
| `=face` | 毎ラウンド (`ENOMOTO_T_MIP_INOUT_RECENTER`、既定 1)、今の LP (カット込み) を内点法で解き直して中心を取り直す (x_c は常に今の最適面の中心付近)。 |
| `=ac` / `=inc` | 費用 0 の内点法 (実行可能領域の中心) / 暫定解を中心にする (計測していない) |
| `ENOMOTO_T_MIP_INOUT_ALPHA` | α (既定 0.5) |
| `ENOMOTO_T_MIP_INOUT_IPM_FRAC` | 1 回のループで内点法に使う時間の合計の上限 (時間上限 × 0.05)。内点法の時間は根のカットの時間の上限に数えない (その分だけ上限を延ばす) |
| `ENOMOTO_MIP_INOUT_NO_BG` | カットを強める求解 (根のヒューリスティクスの間に別スレッドで回すループ) では使わない |
| `ENOMOTO_T_MIP_INOUT_GATE=r` | 最初のラウンドで、x(α) の分数の整数列の数が x_lp の r 倍に満たなければ (最適面が狭い)、そのループでは止める。判定は x(α) の分離の**前**に行う。分離は経路集約の始点などの状態を進めるので、後で判定すると止めた回の経過が既定からずれる (batch5 の timtab1 で根 495812。既定は 597k) |
| `ENOMOTO_MIP_INOUT_EQ2_ONLY` | 同値の代入 (`ENOMOTO_MIP_EQUIV2_CUTS` が働く求解) でだけ使う |

x(α) での分離のため、`separate` は行の活動量を LP からではなくその点から計算するようにした (`Solver::sep_point_act`)。
tableau 行の集約も、行そのもの (B⁻¹ の行と LP の行の組み合わせ) はどの点でも有効な等式なので、x(α) で MIR をかけてよい。
加えたカットはどれも大域的な境界から作る有効不等式で、正しさは変わらない。
`cargo test --release --lib` は既定・`INOUT_SEP=face`・`INOUT_SEP=1` のどれも 308 件通過 (18 件は無視の印。`cargo_test.txt`。
pyo3 のため `RUSTFLAGS="-L /usr/lib/x86_64-linux-gnu -C link-arg=-lpython3.13"`)。全計測で、最適と返した値は既知の最適値と一致し
(neos-911970 54.76、mc11 11689、roll3000 12890、beasleyC3 754、h80x6320d 6382.099、noswot −41 など)、下界が最適値を超えた回はない
(physiciansched6-2 は 49324 にちょうど届く)。

## 2. 結論

1. **根の下界は、最適面が広い問題で大きく上がる。ほかのカットを増やしても、この伸びは出ない**:
   - neos-911970: 既定 47.26 (3 回とも、19 ラウンドで止まる) → `face` 52.02 (3 回とも、25 ラウンド。HiGHS は 38 ラウンドで 52.1)、`io` 52.08。
     1 ラウンドの上限を 100 本にする対照 (`mc100`) では 47.26 のまま。
   - physiciansched6-2 (代入あり `e2`): 既定 49199 (3 回とも 10 ラウンド) → `e2io` 49324 (= 最適値。batch2 では 3 回ともラウンド 11〜13、22〜27 秒で届いた)。
     ただし後の batch では同じ働きの設定 (`e2iog`・`e2ioeq`、どちらも代入のある求解では `e2io` と同じ) で 49141〜49324 とばらつき、6 回中 49324 は 1 回。`e2face` は 49099〜49324。対照の `e2mc100` は 49047。
   - 代入なしの physiciansched6-2: 根のループは 1〜2 ラウンドしか回らない (時間の上限) が、48587 → 48684〜48822、bg の後は 48957 (既定 48587)。
   - roll3000 12305〜12379 → `face` 12433〜12481、misc07 1534 → 1555、beasleyC3 717〜744 → 729〜751、neos5 13.44 → 13.51。
2. **60 秒の結果は良くならない**。根の 1 ラウンドが重くなり (x(α) での分離がもう 1 回、`face` はさらに毎ラウンド内点法)、bg のラウンドが減って、
   bg の後の根の下界はかえって下がる問題が多い。表は batch2・3 (既定と交互に回した回):

   | 問題 | 既定 | `face` | `io` |
   |---|---|---|---|
   | neos-911970 | 3/3 解ける 32〜42 秒 | 2/3 (37・39 秒) | 1/3 (41 秒) |
   | mc11 | 2/3 (47・55 秒) | 0/3 (下界 11636〜11648) | 0/3 |
   | roll3000 | 0/3 | 0/3 (1 版目で 1 回 52 秒) | 0/3 |
   | mzzv42z | 0/3 | 0/3 | 0/3 |
   | physiciansched6-2 (e2) | 0/3、暫定解なし | 0/3 (1 回 49524) | 0/3、暫定解なし |
   | h80x6320d | 3/3 36〜45 秒 | **0/3** | |
   | qnet1 | 3/3 2.6〜3.9 秒 | 3/3 8.3〜10.5 秒 | |
   | mik-250-20-75-4 | 3/3 4.9〜7.2 秒 | 3/3 11.3〜12.5 秒 | |
   | timtab1 | 1/3 | 0/3 | |
   | beasleyC3 | 2/3 | **3/3** 29〜35 秒 | |
   | noswot | 0/3 | **2/3** 51〜53 秒 | |
   | 10teams | 3/3 | 3/3 | |
   | misc07・rout・neos5 | 同じ (rout はやや遅い) | | |

   親の 40 + 16 問 (d00d9b7、`io`) でも 40 問 25 → 23 問、16 問 11 → 7 問で、10teams・neos-911970・beasleyC3・mc11・neos-960392 が落ちたとのこと。
3. **最適面の広さで効き方が分かれる**。最初のラウンドの x_c と x_lp の違い (`face`、`MIP: cut round 0: in-out point:` の行):

   | 問題 | 値の違う列 / 列 | 分数の整数列 x_lp → x(α) | 根の下界の伸び |
   |---|---|---|---|
   | neos-911970 | 864 / 888 | 60 → 840 | 大 (47.26 → 52.0) |
   | physiciansched6-2 | 5024 / 111827 | 1782 → 5031 (代入あり 852 → 4080) | 大 (49199 → 49324) |
   | neos-960392 | 58529 / 59376 | 228 → 58529 | 動かず (−238) |
   | 10teams | 825 / 2025 | 147 → 825 | 動かず (924 = 最適) |
   | noswot | 120 / 128 | 26 → 95 | 動かず (−43) |
   | misc07 | 48 / 260 | 16 → 48 | 中 (1534 → 1555) |
   | roll3000 | 192 / 1166 | 207 → 263 | 中 |
   | h80x6320d | 113 / 12640 | 120 → 189 | 下がる (6283 → 6232) |
   | timtab1 | 87 / 397 | 102 → 124 | 根は伸びる (597k → 611k) が木で悪い |
   | beasleyC3 | 122 / 2500 | 148 → 162 | 中 |
   | mc11 | 20 / 3040 | 363 → 365 | 根は伸びる (11069 → 11274) |
   | qnet1 | 11 / 1541 | 49 → 53 | 少し下がる |
   | mik-250-20-75-4 | 0 / 270 | 75 → 75 | 下がる (最適面が 1 点) |

   最適面が狭い問題では、x(α) で選んだカットはほとんど x_lp も切る (`face` の mc11: 入れた 393 本中 390 本、qnet1 169 本中 169 本)。
   つまり in-out ではなく、1 ラウンドの上限を 50 本増やしただけになる。mc11 の根の伸び (11069 → 11274) は、対照の
   `mc100` (100 本、11483、2/2 解ける) より小さい。広い問題 (neos-911970 の `io`: 入れた 1802 本中 x_lp も切るのは 259 本) では、
   x_lp を切らないカットが入り、最適面を削っている。
4. **中心の取り方**: `io` (最初の点を使い続ける) は、x_c が後のカットで切られた点になり (目的値は最初の根の LP の値のまま)、
   x(α) で破れる候補が毎ラウンド数百本ある (中心は一度も動かない)。入るカットのうち x_lp も切るのは 1〜3 割。
   `face` は x_c が今の最適面にあり、選ばれたカットのほぼ全部が x_lp も切る。
   根の下界は neos-911970 では同程度、physiciansched6-2 (代入あり) では `io` の方が良い (49324 × 3 対 1/3)、mc11・roll3000 では `face` の方が良い。
   内点法は mzzv42z (10460 行) でよく失敗する (`face` の取り直しの 2 回目以降・再スタート後、`facenb` は 3 回とも最初から)。
5. **bg で使わない (`NO_BG`) は効かない**: mc11 は `facenb` / `ionb` でも 0/3、neos-911970 は `facenb` 1/3、`ionb` 0/3。
   physiciansched6-2 (代入なし) では、bg で in-out が下界を 48957 まで上げていた分がなくなる (48791)。
6. **ゲート `ENOMOTO_T_MIP_INOUT_GATE=2` (分数の列の比)** は、狭い問題 (mc11・qnet1・mik・h80x6320d・timtab1・roll3000・beasleyC3) で
   in-out を止める。判定を分離の前に移した版 (batch7) では、止めた回の根のループは既定と同じ経過になる (timtab1 598412、mik −54556.9、
   qnet1 15813.9、mc11 11069.4。残る違いは最初の内点法 1 回分 (0.03〜0.3 秒) だけ)。ただし **10teams・neos-960392・noswot・misc07 は広い側に入り、
   止まらない**。このうち 10teams・neos-960392 は、親の計測で `io` が落とした問題 (こちらの 60 秒の 2〜3 回ずつでは、10teams は既定でも 2/3〜3/3、
   neos-960392 は既定でも解けず、差は見えなかった)。neos-911970 も広い側に入るが、60 秒では既定より悪い。**ゲート 2 だけでは、親の 40 + 16 問で
   落ちた 5 問のうち 3 問 (beasleyC3・mc11 は止まる側。10teams・neos-911970・neos-960392 は止まらない) しか戻らない見込み**。
7. **主側は動かない**: physiciansched6-2 (代入あり) で下界が 49324 に届いても、根の RENS (30 秒前後) は解を出さず、暫定解は出ないか 49524 (FP) で、
   木に入らない (0 ノード)。

## 3. 既定にするか

**既定にはしない** (全問に掛けると 60 秒の結果が悪い。§2.2)。根の下界の伸びは本物で、最適面が広い問題 (neos-911970・physiciansched6-2) に限られる。

ゲート案の推奨:
- **使うなら `ENOMOTO_MIP_INOUT_SEP=1 ENOMOTO_MIP_INOUT_EQ2_ONLY=1`** (同値の代入がある求解だけ。55 問では physiciansched6-2 だけが当たる。
  ほかの問題は経過が既定と同じ: neos-911970 `ioeq` は根 47.26・2/2 解ける)。ただしこれ単独では 60 秒で解けない。
  主側の手当て (`EQUIV2_FJ`、根のサブ MIP の改善) と組み合わせてはじめて意味がある。下界が 49324 に届くのは `io` 系 9 回中 4 回 (残りは 49141〜49253。既定 `e2` は 3 回とも 49199)。
- 分数の列の比のゲート (`GATE=2`) は、狭い問題を既定に戻すには十分。ただし広い問題 (10teams・neos-960392・neos-911970・noswot・misc07) では
  60 秒が良くならず、ゲートの基準 (最適面の広さ) が「伸びて、かつ速く解ける」とは結びつかない。既定にする候補にはしない。
- 根の下界を上げて木を小さくする方向で続けるなら、x(α) の分離の手間 (1 ラウンドの分離が 2〜3 倍) を減らすこと (経路集約・tableau 行を除いた軽い分離
  `ENOMOTO_MIP_INOUT_LIGHT`、未計測) と、bg のラウンド数を落とさないことが先。
