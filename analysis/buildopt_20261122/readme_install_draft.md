## README.md

(「Installation」の `pip install enomoto-solver` のコードの直後)

```markdown
The wheels on PyPI are built with link-time optimization (LTO) and profile-guided optimization (PGO).
The x86-64 wheels (Linux, Windows, macOS on Intel) contain two builds of the Rust core: one for any x86-64 CPU and one for x86-64-v3 CPUs (AVX2, FMA, BMI2 and so on; most CPUs since about 2015).
At import time, the package checks the CPU and loads the x86-64-v3 build if the CPU supports it.
To force one of them, set the environment variable `ENOMOTO_CORE` to `base` (the build for any x86-64 CPU), `v3`, or `auto` (the default).
The arm64 wheels (Linux aarch64, macOS on Apple silicon) contain one build.
```

(「Building from source」の「Always build with `--release`. …」の直後)

````markdown
A build from source contains one build of the Rust core, without LTO or PGO, for any CPU of the target architecture.
To build for the CPU of the machine you are on, set `RUSTFLAGS` (the result may not run on other machines).

```sh
RUSTFLAGS="-C target-cpu=native" maturin develop --release
```

To build a wheel in the same way as the wheels on PyPI (LTO, PGO, and on x86-64 also the x86-64-v3 build), use `scripts/build_dist_wheel.sh` (bash; on Windows, Git Bash).
It needs the `llvm-tools` component of Rust (`rustup component add llvm-tools`).
The script does the following.

1. It builds an instrumented wheel.
2. It installs that wheel in a temporary virtual environment and solves the problems generated by `scripts/pgo_train.py` to record a profile.
3. It builds the wheel again with the profile and, on x86-64, a second time for x86-64-v3.
4. It merges the two wheels with `scripts/make_dual_wheel.py`.

```sh
pip install maturin
rustup component add llvm-tools
bash scripts/build_dist_wheel.sh      # the wheel is written to dist/
pip install dist/enomoto_solver-*.whl
```

This takes several times longer than `maturin develop --release` (about 25 minutes on 4 cores).
Set `PGO=0` to skip PGO and `DUAL=0` to skip the x86-64-v3 build.
Pass further `maturin build` arguments in `MATURIN_ARGS` (for example `MATURIN_ARGS="--features pyo3/abi3-py39"`, as on PyPI).
To merge two wheels you built yourself, run `python scripts/make_dual_wheel.py BASE_WHEEL V3_WHEEL OUT_DIR`.
The two wheels must have the same version and tag; the second is built with `-C target-cpu=x86-64-v3`.
````

## README.ja.md

(「インストール」の `pip install enomoto-solver` のコードの直後)

```markdown
PyPI の wheel は，リンク時最適化(LTO)とプロファイルに基づく最適化(PGO)をかけてビルドしています．
x86-64 の wheel(Linux，Windows，Intel の macOS)には，Rust の本体が 2 つ入っています．どの x86-64 の CPU でも動くものと，x86-64-v3 の CPU(AVX2，FMA，BMI2 などを持つもの．おおむね 2015 年ごろ以降の CPU)向けのものです．
読み込むときに CPU を調べ，x86-64-v3 に対応していればそちらを使います．
環境変数 `ENOMOTO_CORE` に `base`(どの x86-64 の CPU でも動くもの)，`v3`，`auto`(既定)を与えると，どちらを使うかを決められます．
arm64 の wheel(Linux の aarch64，Apple シリコンの macOS)には本体が 1 つだけ入っています．
```

(「ソースからビルドする場合」の「必ず `--release` を付けて…」の直後)

````markdown
ソースからビルドすると，Rust の本体は 1 つで，LTO・PGO はかかりません．その CPU の種類のどの機種でも動く形になります．
手元の CPU に合わせてビルドするには，`RUSTFLAGS` を与えます(できたものは，ほかの機械では動かないことがあります)．

```sh
RUSTFLAGS="-C target-cpu=native" maturin develop --release
```

PyPI の wheel と同じ形(LTO，PGO，x86-64 では x86-64-v3 向けの本体も)の wheel を手元で作るには，`scripts/build_dist_wheel.sh`(bash．Windows では Git Bash)を使います．
Rust の `llvm-tools`(`rustup component add llvm-tools`)が必要です．
この台本は次のことを順に行います．

1. 計測用の wheel をビルドする．
2. それを一時的な仮想環境に入れ，`scripts/pgo_train.py` が作る問題を解いてプロファイルを取る．
3. プロファイルを使ってもう一度ビルドする．x86-64 では x86-64-v3 向けにもビルドする．
4. `scripts/make_dual_wheel.py` で 2 つの wheel を 1 つにまとめる．

```sh
pip install maturin
rustup component add llvm-tools
bash scripts/build_dist_wheel.sh      # wheel は dist/ にできる
pip install dist/enomoto_solver-*.whl
```

`maturin develop --release` の数倍の時間がかかります(4 コアで約 25 分)．
`PGO=0` で PGO を，`DUAL=0` で x86-64-v3 向けのビルドを省けます．
`maturin build` に渡す引数は `MATURIN_ARGS` で足せます(PyPI と同じにするなら `MATURIN_ARGS="--features pyo3/abi3-py39"`)．
自分でビルドした 2 つの wheel をまとめるには `python scripts/make_dual_wheel.py BASE_WHEEL V3_WHEEL OUT_DIR` を使います．
2 つの wheel は版とタグが同じで，2 つ目は `-C target-cpu=x86-64-v3` を付けてビルドしたものにします．
````
