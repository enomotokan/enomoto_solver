# 初回の再スタートの閾値 (2026-10-31)

依頼: 初回の再スタートが、ごく少ない固定でも起きる (`ENOMOTO_T_MIP_RESTART_FIRST_FAC` 既定 0) のを見直す。
土台は既定にする候補の hs_pi0_bgw_r (`ENOMOTO_MIP_SUBMIP_HIGHS=-s ENOMOTO_MIP_SUBMIP_PC_INHERIT=1 ENOMOTO_T_MIP_SUBMIP_RELIABLE=0 ENOMOTO_MIP_BG_CUTS_WAIT=1 ENOMOTO_MIP_SUBMIP_HIGHS_TRIM=r`、
以下 `r`)。あわせて def に足した形も見る。

計測は全部この機械 (4 コア) で、4 スレッド・60 秒、ソルバーは 1 本ずつ、問題ごとに設定の順を回で逆にした。コードは `b020509b`。
台本・ログは `analysis/restart_thr_20261031/` (`run.py`・`bench.py`、ログは `logs/`・`blogs/`、集計は `summ.py`・`summ_bench.py`・`restarts.py`)。

## 1. HiGHS の規則と、こちらの規則

- HiGHS (`HighsMipSolverData::evaluateRootNode`、master のソースで確かめた):
  - 根の LP の直後と、カットのラウンドの間: 固定率 10% 以上なら再スタート。
  - 根の最後: `fixingRate >= 2.5 || (fixingRate > 0 && numRestarts == 0)`。**初回は固定が 1 本でもあれば再スタートする**。
    「HiGHS と同じ」というコメントは正しい。
  - ただし固定率 (`percentageInactiveIntegers`) は、前処理の後の模型の整数列に対する割合で、クリーク表の代入も数える。
- こちら (`Solver::maybe_restart`): 新たな固定 / 全部の整数列 (`p.nint`) を見る。初回は `ENOMOTO_T_MIP_RESTART_FIRST_FAC` (0)、2 回目以降は `ENOMOTO_T_MIP_RESTART_FAC` (0.025)。
  早めの再スタート (`proto_restart_ok`) も、同じ FIRST_FAC を使う。
- physiciansched6-2 の `p.nint` は 109346 本だが、根の始めに自由な整数列は 4421 本しかない。
  - 固定 18〜46 列は、全体の 0.02〜0.04%、自由な列の 0.4〜1.0%。
  - HiGHS の数え方に近い分母 (自由な列) だと「ごく少ない」とは言えない。

- 足した試作 `ENOMOTO_MIP_RESTART_FIRST_LPW` (既定では使わない):

### 3.1 physiciansched6-2: 再スタートを止めても解けない

- 3 設定とも 1/8。解けた回は、どれも裏のカットが根の下界を 49324 まで上げた回 (`obj 4.8857e4 -> 4.9324e4`)。
- 再スタートしない回 (r_f001・r_lpw の 16 回) の様子:
  - 根の後に木に入る。木に入るのは 23〜54 秒。根の強分枝も重い (r_lpw の 1 回目では 16 秒)。
  - 下界は 48684〜48724 (裏のカットが止まった回) のまま、60 秒で数ノードしか進まない。
  - 49324 を持っていても証明が間に合わない。
- 49324 を時間切れの時点で持っていた回: r 3/8、r_f001 4/8、r_lpw 7/8。
  - どの回も、49324 は再スタートの判定より前に、最初の根の RINS が出している (15〜20 秒)。判定がここに影響することはないので、差は RINS の揺れ。
  - 再スタートした回 (r の 5 回) では、前処理が打ち切り値で 49324 の解を捨てるが、最後には前の暫定解として返すので、上界は変わらない。
- 根の LP はこの機械では 2.4〜3.2 秒 (前回の記録の 14.8 秒は再スタート後の根の LP の解き直し)。
- つまり physiciansched6-2 の揺れは、前回の記録 (§3) のとおり、裏のカットの止まる時刻で決まる。再スタートの閾値では変わらない。

## 6. 判断

- **提案: `ENOMOTO_T_MIP_RESTART_FIRST_FAC=0.01` (初回の再スタートは、新たな固定が全部の整数列の 1% 以上のときだけ)。形は今の判定のままで、値だけを変える。**
  - 58 問 2 回: SGM 20.20 → 20.13 (−0.3%)、解けた数 82 → 83 (+1、roll3000)。
  - 判定が変わるのは 58 問中 5 問。うち 3 問 (roll3000・p0201・drayage-100-23) が速くなり、2 問は両方とも時間切れ。残りの 53 問は同じ (19.74 → 19.73)。
  - def に足しても同じ向き (roll3000・p0201)。
- 0.005 と 0.01 の違い: 判定が分かれるのは固定 0.5〜1% の問題だけ。58 問では blp-ar98 (107 / 15806 = 0.68%) の 1 回で、どちらも時間切れ。
  roll3000 (0.4%)・p0201 (0.497%) は 0.005 でも止まる。前の記録 (roll3000_r3) と揃えて 0.01 とする。
  0.002 (highstree_phys の hpgc) では roll3000 の 3 / 738 = 0.41% を止めない。
- `FIRST_LPW` (根の LP の重さを見る形) は採らない:
  - 働くのは physiciansched6-2 だけで、そこでは再スタートを止めても解けた数が変わらない (1/8)。
  - roll3000 のような根の LP が軽い問題には働かない。
  - FIRST_FAC=0.01 で physiciansched6-2 の再スタートも止まる。
- physiciansched6-2 (依頼の動機) は、閾値では解けるようにならない。
  - 解けない回は、裏のカットが根の下界を上げる前に止まる回。再スタートしなくても、木の下界が 48724 から動かない。
  - 効く見込みがあるのは裏のカットの側。別のセッションの `ENOMOTO_MIP_BG_CUTS_PROOF_STOP` の記録では、P_r が 5/8 → 7/8。
- 既定は変えていない。既定にするなら、`maybe_restart`・`proto_restart_ok` の `tunable!("ENOMOTO_T_MIP_RESTART_FIRST_FAC", 0.0, f64)` の既定値を 0.01 にする。
  - 「HiGHS と同じ」というコメントも直す。HiGHS は前処理後の自由な整数列に対する割合で数えるので、分母が全部の整数列のこちらでは、0 は HiGHS より再スタートしやすい。
