# neos-4722843-widden の誤答 (既定・4 スレッドで稀に誤った最適) の調べと直し (2026-11-17)

## 事象

analysis/slow2_20261117/res_MSW_s0.jsonl で、既定 (環境変数なし、4 スレッド、種 1、600 秒、c6599c8ed を含むビルド) が
neos-4722843-widden を optimal・目的値 25153.884488 (下界も同値) で返した。既知の最適値は 25009.662227 (MIPLIB)、
同じ実行の sw 設定・HiGHS は 25009.6634。

## 結論

- **原因はノードの LP の「際どい実行不能」の誤判定**。カット・伝播・前処理・共有カット・対称性は無罪。
- widden は係数が 1/101 刻みで、最適解も 1e-8 程度の誤差つきでしか実行可能でない。温め始動の双対単体法が、
  許容誤差の範囲で実行可能な LP を、余裕の極めて小さい Farkas の射線 (yb = −1.0e−7 対 0、射線の最大 8〜160) で
  「実行不能」と判定し、ノードを刈る。そのノードが最適解を含むと誤答になる。
- 修正 (558d7a4ce): ノードの LP が Infeasible のとき、元の空間で Farkas の隙間が FEASTOL·(Σ|y_i| + Σ|(yᵀA)_j|) 以下
  (= どの行・列も 1e−6 まで破ってよいなら埋まる) なら実行不能を信用せず、全論理変数基底から解き直し、それでも際どければ
  LP が解けないものとして扱う (既存の「LP 値なしで分枝」、正しさは保たれる)。
  `ENOMOTO_MIP_NO_LPINF_CHECK` で以前の動き、`ENOMOTO_MIP_LPINF_LOOSE` で解き直しの結果をそのまま使う (試作の比べ用)。
- 修正後: widden を 120 回 (デバッグ解つき、2 本並走) 誤答 0・デバッグ解の喪失 0、cargo test 419 通過、fuzz 7 本 bad 0。

## 2. 原因の特定

1. デバッグ解: 前処理 (対称性の行の後、`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED3`) の問題を HiGHS で解いた最適 (mkdbg.py、
   widden_pre_s1.sol.gz)。前処理後の問題の最適は 25009.6634 で、前処理・対称性の行は最適を残している。前処理は種によらず同一
   (種 1・2・5 の書き出しの md5 が一致)。
2. 誤答の回 (dbgB 種 10) の診断: `MIP_DEBUG_SOL lost at node 171 (helper thread): node LP Infeasible` — デバッグ解を含むノードの
   LP が実行不能と判定されて刈られた。LP に足したカットの行の既存の検査 (debug_check_cut_rows) は何も出さなかった。
3. 診断 `ENOMOTO_MIP_DEBUG_ROWS_ALL` (ノードの LP を解くたびに LP の全部の行をデバッグ解で確かめる): 78 回で違反 0。
   LP の行 (元の行・カット・共有カット) は正しい。
4. 診断 `ENOMOTO_MIP_DEBUG_LPINF` (ノードの LP が実行不能と出るたびに、LP の列境界と定義域の食い違い、同じ行・境界で一から
   作った LP の結果、Farkas の射線の確かめを出す): 例 (種 1、thread 0、node 106、行 14254):
   - 列境界と定義域の食い違い 0、内部の標準形を作り直しても b の差 1.7e−13 (同期漏れではない)。
   - Farkas の射線は内部の確かめ (std_farkas_ok) を通る: `yb −1.03e−7, zlo −1.2e−22, zhi 0, ymax 8〜128, mag 1.0e−7, tol 1e−9`。
     許容 tol が項の大きさ (mag) に比例するだけなので、隙間 1e−7 が射線の大きさに比べて小さくても通る。
   - 一から作った LP は Optimal (目的値 25649.78 < 打ち切り値 25846.1)、その解の行の違反は相対 1.0e−9 (許容誤差ちょうど)。
   - 全論理変数基底から解き直しても同じく際どい実行不能 (温め始動だけの問題ではない)。
   つまり LP は 1e−8 程度だけ実行不能で、許容誤差の範囲では実行可能。この種の LP の判定は解き方次第で揺れ、最適解
   (1e−8 程度の誤差つきで実行可能) を含むノードで「実行不能」側に振れると誤答になる。

## 3. 直し (src/mip/solver.rs)

- `Solver::lp_infeasible_marginal`: 射線 y (元の行の向き) から z = yᵀA、行の活動の組 yᵀr の範囲 [rlo, rhi] (行の境界) と
  zᵀx の範囲 [zlo, zhi] (列の境界) を作り、隙間 max(rlo − zhi, zlo − rhi) が FEASTOL·(Σ|y_i| + Σ|z_j|) 以下なら際どい
  (各行・各列を FEASTOL まで破ると隙間が埋まりうる)。射線がない・範囲が開いているときも際どいとみなす。
- ノードの LP が Infeasible で際どければ、全論理変数基底から解き直す。解き直しても際どい実行不能なら `LpStatus::Error`
  (既存の「LP 値なしで分枝」) にする。Farkas の証明 (add_farkas_proof) もこのときは作らない。
- ログに `MIP: marginal node LP infeasibility (all threads, cumulative): re-solved from the slack basis N, still marginal after that M`。
- widden では 1 回あたり平均 75 回 (最大 446) 発動し、ほぼすべてが解き直しても際どい。

## 6. 確かめを根の LP・強分枝の子・LP のプロービングにも広げる (ec54d0cb0)

親の依頼で、同じ判定 (`lp_farkas_marginal`、自由関数にした) を次にも入れた。`ENOMOTO_MIP_NO_LPINF_CHECK=1` で全部まとめて以前の動き。

| 箇所 | 際どい実行不能のときの扱い |
|---|---|
| ノードの LP | 全論理変数基底から解き直し、それでも際どければ LP 値なしで分枝 (3 節) |
| 根の LP | 全論理変数基底から解き直し、それでも際どければ結論なし (Error) として既存の安全網 (尺度の二段解法・内点法 + クロスオーバー) へ |
| 強分枝の子 (並列・逐次・旧経路 select_branch_old) | 解き直さず不明: 切らない、増分 0 (子の値は親の値)、Farkas の証明・衝突も作らない |
| 強分枝の固定の後の解き直し | Resolve (呼び出し側がノードの LP として解き直し、ノードの LP の確かめを通る) |
| LP のプロービング (lp_probe_cutoff = GAP1・TREEFIX、objprobe_round) | 固定・「打ち切り値より良い解はない」の結論に使わない |
| 前処理の LP プロービング (mod.rs の lp_probe、既定で動く) | 最初の LP: 固定せずに終える (問題を実行不能にしない)。片側の LP: 切らない。固定の後の解き直し: 実行不能にしない |

- 潜り (ヒューリスティクス) の LP は実行不能でも潜りを終えるだけで正しさに関わらないので入れていない。試作 (既定外) の
  tighten_vubs も入れていない。
- 目的値の打ち切り (ObjectiveBound) で刈る場合は対象外 (打ち切り値に許容があり、今回の誤りの形ではない)。
- 統計の行: `MIP: marginal LP infeasibility (all threads, cumulative): node LPs re-solved A branched without the LP B strong branching children unknown C root and LP probing D`
  (ログ ENOMOTO_MIP_LOG のときだけ。全スレッド・サブ MIP 込みの累計)。widden 種 1 では [95, 95, 5, 0]。

## 8. rocI-4-11 の時間切れと、一から作った LP での確かめへの変更

- 事象 (親の計測): a9d7bae3d (ノードの確かめ入り) の既定で rocI-4-11 種 1 が時間切れ (以前は 174〜335 秒)。
- 切り分け (roc.sh、ec54d0cb0 系のビルド、600 秒、res_one.jsonl):

| 設定 | 種 1 | 種 2 |
|---|---|---|
| 既定 (旧方式) | 時間切れ (暫定 −5020203、下界 −11070466、lpinf [46675, 46608, 728, 2]) | 時間切れ (lpinf [23055, 22980, 707, 2]) |
| NO_LPINF_CHECK=1 | 276.8 秒で最適 | 215.2 秒で最適 |
| PROP_RELTOL_CONT=0 | 時間切れ (lpinf [38643, 38576, …]) | (新方式のビルドで) 122.2 秒で最適 |

  原因は確かめ: 全論理変数基底から解き直しても際どいままの実行不能が数万回出て、LP 値なしの分枝が連鎖し下界が根から動かない。rtc は無関係。
- 証明の「実行可能になるのに要る最小の一様な破り幅」r = 隙間 / (Σ|y_i| + Σ|z_j|) の分布 (診断、ログの `LP infeasibility certificates` の行):
  rocI は 1e-7〜1e-6 の帯に 7.6 万件 (しきい値 1e-6 のすぐ下)。widden を確かめなし + LPINF 診断で 6 回 (rep_lr.out) 回すと、
  誤判定 (一から解くと実行可能) の r は 1.7e-10 か証明として無効 (−inf)、本物の実行不能は 6e-5 以上か −inf。
- 新方式 (cc78f70da): ノード・根の LP が際どく実行不能なら、同じ行・境界・費用で LP を一から作って
  (`L::new`) 解く。実行不能なら信用する (ただし際どい射線から Farkas の証明は作らない)。最適ならその基底をノードの LP に移して解き直す。
  どちらでもなければ結論なし (ノードは LP 値なしで分枝、根は安全網)。一から作った LP が最後の判定なので、しきい値 r ≤ 1e-6 は確かめの回数だけを決める (据え置き)。
- 新方式の rocI-4-11 (既定、600 秒): 種 1 = 309.1 秒、種 2 = 166.3 秒で最適 (lpinf [1519, 0, 1358, 2, 0]・[599, 1, 834, 2, 0]。
  第 1 欄 = 一から確かめた数、第 2 欄 = 結論なし、第 5 欄 = 一から作った LP が実行可能だった数)。
