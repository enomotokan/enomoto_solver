## 1. 結論

1. **遅くなるのは閾値 0 (強分枝なし) のせいで、擬似コストの引き継ぎのせいではない**。ただしこの機械で回をまたいで遅くなったのは neos17 だけ。
   pk1・qnet1・exp-1-500-5-5 は 4 設定の差が揺れの範囲で、前の計測の損は再現しなかった。
2. neos17 の仕組み: 根の RENS のサブ MIP が、閾値 0 では根の解 (0.1592) のまま 50 ノードよくならず、**成果連動の打ち切り
   (`submip_outcome_stop`、最小 50 ノード) で 54 ノードで止まる**。強分枝ありなら 63 ノード目で最適値 0.15000 を見つける。
   根のサブ MIP は親の擬似コストがほぼ空のうちに出るので、引き継ぎだけ (hs_pi) では何も変わらない。
3. 閾値 0 は得の元でもある。h80x6320d・binkar10_1 の得は、強分枝が重いのに何も見つけないサブ MIP が速く終わる分。qiu の得は hs そのもので、pi0 とは関係ない。
4. 手当ての試作 3 つ (既定は変えない):
   - **成果連動の打ち切りを 150 ノードに広げる (hs_pi0_om150、既存の `ENOMOTO_T_MIP_SUBMIP_OUTCOME_MIN_NODES`)**: neos17 は 21 → 15 秒、
     binkar10_1・h80x6320d の得は残る。コードは要らない。
   - 強分枝の時間をサブ MIP の経過時間の 0.25 倍までにする (hs_pi_sbf25、新しい `ENOMOTO_T_MIP_SUBMIP_SB_TIME_FRAC`): neos17 は hs 並み
     (13 秒) に戻るが、binkar10_1 で損 (10 → 18 秒) が出て、h80x6320d の得も一部消える。
   - 閾値 0 を、引き継いだ観測のある列だけに使う (hs_pi0_inh、新しい `ENOMOTO_MIP_SUBMIP_RELIABLE_INHERITED`): ほぼ hs に戻り、得も消える。
5. 45 問 × 2 回では、3 つとも SGM は変わらない (hs_pi0_bgw 8.26 (86)、hs_pi0_om150_bgw 8.28 (85)、hs_pi_sbf25_bgw 8.30 (88))。
   損の問題を消す手当てとしては om150 が一番よいが、全体の得にはならない。どれも既定にしない。

## 3. 仕組み (ログ、`ENOMOTO_MIP_DEBUG_SUBMIP_STOP`)

新しい診断 `ENOMOTO_MIP_DEBUG_SUBMIP_STOP` は、サブ MIP がノードの上限・停滞 (`ENOMOTO_T_MIP_SUBMIP_STALL`)・成果連動のどれで止まったかと、
そこまでのノード・強分枝の LP の回数・反復・秒・ノードの反復・最後に解がよくなったノードを出す。

### neos17 (回 1)

| | hs | hs_r0 |
|---|---|---|
| 根の並列のサブ MIP (RENS) | 131 ノード、強分枝 596 LP (0.28 秒)、成果連動で停止、63 ノード目に 0.15000 | 54 ノード、強分枝 0、成果連動で停止、最後の改善はノード 0 (根の入れ子のサブ MIP の 0.1592) |
| 根の並列のサブ MIP (root reduced cost) | 98 ノード、48 ノード目に 0.15000 | 59 ノード、0.15945 |
| 直列の RENS (more nodes)・RINS | 各 0.7 秒、67 ノード | 各 2.2〜2.4 秒、54 ノード |
| 根のヒューリスティクスの終わり | 5.29 秒 (暫定解 0.15000) | 7.83 秒 (暫定解 0.15925) |
| 最適値を見つけた時刻 | 3.8 秒 (RENS) | 再スタートの後の木 (再スタート後の時計で 12.7 秒、tree randomized rounding) |
| 全体 | 12.4 秒 | 20.8 秒 |

- サブ MIP の中の時間の大部分は、その根のヒューリスティクス (入れ子のサブ MIP、各 0.3〜0.9 秒) で、強分枝はサブ MIP の時間の約 10%。
- 閾値 0 ではサブ MIP の木が根の解を 50 ノードの間よくできず、成果連動の打ち切りに掛かる。最適値が根で見つからないので、
  再スタートの後も根のヒューリスティクスをもう一度回し (5 秒)、木で見つけるまで待つ。
- 打ち切りを 150 ノードにすると (om150)、根の RENS は 452 ノードまで進んで 0.15031 を見つけ、最適値は再スタート後の木で見つかる (再スタート後の時計で 9.0 秒、全体 14.6 秒)。

### h80x6320d (回 0、得の側)

- hs: 根の並列の root reduced cost のサブ MIP が 50 ノードに強分枝の LP 990 回 (25326 反復、4.5 秒。ノードの反復 1696 の 15 倍) を使い、
  10 秒かけて何も見つけない (6618。親はその間に LP face で 6382 を見つけている)。主はこれを待つので、根のヒューリスティクスが 15.8 秒で終わる。

- ただし根で解けるかは回で分かれる (hs_r0 は 20.9 / 48.5 / 21.4 秒。48.5 秒の回は木に進む)。

## 4. 手当ての試作

コード (`src/mip/solver.rs`、どれも既定では使わない):

- `ENOMOTO_T_MIP_SUBMIP_SB_TIME_FRAC` = f (> 0): サブ MIP では、強分枝の時間 (`sb_secs`) がサブ MIP の経過時間の f 倍を超えたら強分枝しない。
  neos17 のサブ MIP では強分枝が約 10%、h80x6320d の root reduced cost のサブ MIP では 47% なので、f = 0.25 で分けられると見た。
- `ENOMOTO_MIP_SUBMIP_RELIABLE_INHERITED`: サブ MIP の閾値 (`s`・`ENOMOTO_T_MIP_SUBMIP_RELIABLE`) を、親から引き継いだ擬似コストに観測のある列だけに使い、
  観測のない列は親と同じ閾値 (1〜5) にする。
- `ENOMOTO_MIP_DEBUG_SUBMIP_STOP`: 上の診断。

既存の調整値 `ENOMOTO_T_MIP_SUBMIP_OUTCOME_MIN_NODES` (成果連動の打ち切りの最小ノード数、既定 50) も試した。

## 5. 判断と次

- どれも既定にしない。hs_pi0_bgw の損 (neos17) を消すなら om150 (`ENOMOTO_T_MIP_SUBMIP_OUTCOME_MIN_NODES=150`) を足すのがよい
  (得の binkar10_1・h80x6320d を残す)。ただし 45 問の SGM は変わらない。
- 成果連動の打ち切りのノード数を、強分枝のないサブ MIP (閾値 0) のときだけ広げる形にすれば、既定の形 (強分枝あり) には触れずに済む。
  今の hs_pi0 ではサブ MIP はすべて閾値 0 なので、調整値を変えるのと同じになる。
- 次: hs_pi0_om150_bgw を 58 問の残りと Mittelmann で確かめる。neos17 の残りの 2〜3 秒 (根の RENS が最適値の手前で止まる) は、
  打ち切りをノード数でなく時間で決める形 (強分枝のないノードは軽い) で縮むかを見る。
