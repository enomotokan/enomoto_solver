# 誤答 seed 3470 (と seed 7545) の調査と直し (2026-11-14)

ブランチ ccr-1beed81b-ex0uhq。台本・問題・ログは `analysis/wrong3470_20261114/`。

## 結論

- **seed 3470 は ENOMOTO の誤り** (HiGHS の解は元の問題で残差 1e-15 以下、`repro.py`)。原因は前処理の空行の判定:
  プロービングの「幅の小さい列の固定」が連続列 x10 を真値から 1.18e-9 ずれた値に固定し、その後の整数どうしの二項等式の代入で
  行が `0 = −1.18e-9` の空行になり、foldfixed の判定 (許容誤差 `1e-9 (1 + |右辺|)`。代入で元の右辺 13.8 の大きさを失い ≈ 1e-9)
  が実行不能とした。
- 直し 1 (9b839dd1、既定): foldfixed の空行の判定の許容誤差に下限 **1e-7** (主実行可能性の許容誤差。HiGHS `HPresolve` の空行の判定、
  こちらの rowsingleton のクランプ `ROWSINGLETON_CLAMP_TOL` と同じ) を入れる。`ENOMOTO_T_EMPTY_ROW_FEAS_TOL` (既定 1e-7、0 で従来)。
  診断用 `ENOMOTO_DEBUG_EMPTY_ROW` (下限で初めて通った空行を出す)。
- 広い fuzz (`mip_fuzz_vs_highs.py` の seed 0〜19999) で同じ根の誤答がもう 1 種あった: **seed 7545** (HiGHS −317.41 に対し −314.54 を
  「最適」)。同じく幅の小さい列の固定の誤差 1.2e-9 が `8 x8 + 8 x15 = 24.0000000025` を作り、整数どうしの二項等式の消去が比・右辺を
  「整数 (相対 1e-9 以内)」と判定しながら丸めずに `x15 = 3.0000000003 − x8` と代入、`4 x15 + … <= 26` が整数行の正規化
  (`floor(b + 1e-9)`) で `<= 17` (正しくは 18) になって最適解を切った。
- 直し 2 (既定): 整数どうしの二項等式の消去で、整数と判定した比と右辺を丸めた値で代入する (src/presolve/doubleton.rs)。
  `ENOMOTO_PRESOLVE_NO_INT_DOUBLETON_SNAP` で従来。
- 途中で別の重大な不具合を見つけて直した (7917d993): af29a20a (robust2 の ORDINV `c`) の
  `if let (Some((_, cp)), Some(x)) = (&canon, r.x.take())` が、canon が None (既定) でも `r.x.take()` を評価して解を捨て、
  **既定のまますべての MIP が「最適・目的値なし」を返していた** (x + y <= 3.5 の 2 変数でも)。入れ子の `if let` にした。
- 報告の版 (724b1814) はこのリポジトリに見当たらず、手元は 149c806b から始めた。こちらの版では `ENOMOTO_MIP_NO_PRESOLVE`・
  `ENOMOTO_MIP_NO_PROBE_EQUIV`・`ENOMOTO_MIP_NO_PROBING`・`ENOMOTO_PRESOLVE_NO_INT_DOUBLETON` のどれでも直る
  (報告では NO_PRESOLVE・NO_PROBE_EQUIV でも実行不能のまま。版の違いと見ているが確かめていない)。

## 2. 実行不能と判断した場所 (事実)

`ENOMOTO_MIP_LOG=1`: 前処理 → プロービング (同値な 0-1 の組 3 つ、幅の小さい列の固定 1 本) → かけ直し → 2 回目のプロービング →
同値な組の等式を足した前処理 (`substitute_probe_equiv`) が実行不能を返す。

- `ENOMOTO_MIP_DEBUG_DUMP_PROBE` で組の等式を足した問題 `dmp_q0.mps` を書くと、HiGHS は最適 (−209.532 + 定数 28.325 = −181.207)、
  ENOMOTO は単独でも実行不能 (`scripts/enomoto_mip_cli.py dmp_q0.mps`)。`ENOMOTO_PRESOLVE_NO_INT_DOUBLETON=1` で最適。
- `shrink.py` (行・列を落として HiGHS 最適・ENOMOTO 実行不能のままの最小を探す) の結果は 3 列 3 行:

  ```
  3 x2 − 3 x11 + 6 x17 = 2.9999999988162678   (元は x6・x18・x10 を含む行。x10 = 0.18373255366794583 に固定済み)
  x2 + x11 = 1,  x2 + x17 = 1                  (プロービングの同値な組)
  ```

  x11 = 1 − x2、x17 = 1 − x2 を代入すると 1 行目は `0 = −1.18e-9`。
- x10 の真値は行 `6x17 + 3x2 − 3x11 + 4x18 + 7x6 − x10 = 13.816267445148322` から 14 − 13.8162674… = 0.1837325548516784。
  固定値との差 1.18e-9。固定は `fix_tiny_width_columns` (src/mip/mod.rs、プロービングの後) で、伝播が 1e-9 だけ緩めて入れた
  幅の小さい区間の下限に固定する。等式の行の予算 `1e-9 (1 + |b|)` = 1.5e-8 の内なので固定は許される。
- 実行不能の判定は `foldfixed::fold_fixed_columns` の空行 (等式) の `|残差| <= 1e-9 (1 + scale)`、scale = max(|右辺|, |固定項|)。
  二項等式の代入 (`doubleton::rewrite_row`) で項が全部消えた行は右辺が残差そのもの (1.18e-9) で、scale も 1.18e-9 になる。

## 3. 直し (事実)

| 直し | 場所 | 既定 | 戻す環境変数 |
|---|---|---|---|
| 空行の判定の許容誤差の下限 1e-7 | src/presolve/foldfixed.rs、src/params.rs `EMPTY_ROW_FEAS_TOL` | 入 | `ENOMOTO_T_EMPTY_ROW_FEAS_TOL=0` |
| 整数どうしの二項等式の比・右辺を丸めて代入 | src/presolve/doubleton.rs | 入 | `ENOMOTO_PRESOLVE_NO_INT_DOUBLETON_SNAP=1` |
| 解を捨てる if let (af29a20a) | src/mip/mod.rs `solve_mip` | — | — |

- 空行の下限は「前処理が単体法より厳しい基準で実行不能を宣言しない」ため (rowsingleton のクランプと同じ考え方)。落とした行は
  最終の解で最大 1e-7 破れうるが、最終の解の確かめ (`is_feasible(x, 1e-6)`) と HiGHS の基準 (1e-7) の内。
- 丸めは、比・右辺が `is_integral` (相対 1e-9) を通ったときだけ。整数解ではこの等式は整数の値で成り立つので、丸めは許容誤差内の
  ずれを消すだけ。後処理 (`x_elim = (rhs − a_keep x_keep) / a_elim`) も丸めた値で整数になる。
- 7545 は直し 2 だけで直る (直し 1 を切っても直る。直し 2 を切ると再発)。3470・7100・8278 は直し 1 で直る。
