## 7. 型 A の試作: 列挙を縮みの効率で続ける (`ENUM_ADAPT` の `z`) と、境界で満たされる行の掃除 (`ROWCLEAN`) (2026-11-28、親の依頼)

版: dc6c06b4b (先端 7d43fcdac 以降を取り込み。DUALEQ・RSTLOOSE・PRR_TIGHT=o が既定)。check_default は全部一致。どちらの試作も既定オフ。

### 7.1 試作の中身 (src/mip/mod.rs)

- **`ENOMOTO_MIP_ENUM_ADAPT=z`** (`enum_adapt_z`): 既存の `ENUM_ADAPT` (列挙の前処理・列挙とプロービングの繰り返し) の判定を、時間でなく**縮みの効率**で行う。
  - 得 = 列挙が固定した列の数。2 周目からは、繰り返しのプロービングが固定した列も足す。締め付け・同値な組・衝突の組は数えない。
    neos8 では、プロービングの同値な組が得に数えられて、何も固定しない繰り返しが続いていた (protoscreen_20261124 の 9.3 節)。
  - 手間 = 列挙した行の、固定されていない列の延べ本数 (`ENUM_Z_WORK`)。
  - s = log10(得 / 手間) を既存のシグモイド f = σ(a (s − b)) (a = 8、b = −0.09、`ENUM_ADAPT` の係数のまま) に通す。
    得があれば続け、次の列挙では行の f の割合を列挙する。得が 0 なら止める (既存の規則)。
  - 列挙の途中でも、16 行ごとに同じ f を見る。中立の点 1/2 (既存の途中の止め `s` の下限と同じ) を下回るか、得がまだ 0 なら止める。
  - この求解の最初の列挙は、上限つき (400 行・空振り 6 回、`ENUM_PRESOLVE=1` と同じ) で回す。全部の行 (`all`) に広げるのは 2 回目から。
  - 締め付けでの前処理のかけ直しの判定は、既定の規則のまま (`ENUM_ADAPT` のシグモイドの上書きを使わない)。
  - 時間を使わないので、機械や回の速さで判定が揺れない。新しい閾値はない。
- **`ENOMOTO_MIP_ROWCLEAN=1`** (`drop_redundant_rows`): クリーク行の拡張の直後に、列の境界だけで両辺が満たされる行を落とす。
  - 落とすのは、全部の列が固定された行と、活動の範囲が行の範囲の内に入る行 (許容 1e-9 (1 + |端|))。
  - 実行可能な点は変わらないので、後処理は要らない。全部の列が固定されて破れている行は残す。
  - 最後のプロービング・列挙の固定の後には前処理をかけ直さない。そのため ex9 では、自由な列 196 本に対して 13727 行が根の LP に残っていた。

### 7.2 ex9・ex10 (種 1、600 秒。`solve.jsonl`・`others.jsonl`)
