# 再スタートで pseudocost を前処理の後の列へ写す試作 (案 a、2026-10-31)

`analysis/diag_hsletters_20261031.md` によると、hs_pi0_bgw (`ENOMOTO_MIP_SUBMIP_HIGHS=-s ENOMOTO_MIP_SUBMIP_PC_INHERIT=1
ENOMOTO_T_MIP_SUBMIP_RELIABLE=0 ENOMOTO_MIP_BG_CUTS_WAIT=1`) の損の主な仕組みは、再スタート後の根で重いサブ MIP を回し直すこと。
再スタートでは新しいソルバーの pseudocost が空から始まるので、再スタート後の根のサブ MIP に「引き継ぐ」観測がほぼないのではないかと考えた。
そこで、再スタート前の pseudocost を新しい問題の列へ写して引き継ぐ形を試した。

- 機械: 4 CPU。4 スレッド・60 秒、ソルバーは同時に 1 つだけ。`ENOMOTO_MIP_LOG=1`。HiGHS (highspy) は 1.15.1。
- ビルド: `b0339d9`。ほかのセッションの `0db049c` (`ENOMOTO_MIP_SUBMIP_HIGHS_RESTART`、既定では使わない) を取り込んだ後のもの。
- 台本・ログは `restart_pc_20261031/`:
  - `run.py 設定,... 問題,... 回数 [最初の回]`: 1 本ずつ回し、`logs/<問題>_<設定>_<回>.log` と `res.jsonl` に書く。
  - `summ.py [問題,...] [設定,...] [-v]`: 時間の表 (`summ.txt`)。`-v` (`summv.txt`) はログごとに次を出す。
    - 再スタートの回数
    - 根のヒューリスティクスが終わった時刻 (区間ごと。再スタートで時計が戻る)
    - 外側から出したサブ MIP の時間の和
    - 再スタート時の pseudocost の観測 (両向きの観測のある列 / 観測の総数)
    - 最終の暫定解を最初に出した区間・時刻・出どころ
  - `sgm.py`: 損の 4 問・得の 5 問の SGM (`sgm.txt`)。
  - 回 90 のログは、診断を確かめるために取り込みの前のビルドで回したもの。表には入れていない。
- 表の数字は秒、T は時間切れ。最適値の食い違い・crash はない。`cargo test --release --lib` は 330 件通過。

## 1. 結論

1. **再スタートの時点で pseudocost は空** (観測のある列 0、観測 0、ノード 0)。9 問 × 5 設定 × 3 回で起きた再スタート 110 回のすべてでそうだった。
   - 根での再スタート (`solver.rs` の `maybe_restart`) は、根のカット・ヒューリスティクスの後、最初の分枝の前に呼ばれる。
   - pseudocost に観測を入れるのは分枝 (強分枝とノードの結果) だけで、根のサブ MIP の中の観測は親に戻らない。
   - したがって「再スタート前にも根の強分枝の観測がある」という見込みは外れで、観測は構造上 0 になる。
   - 写して意味があるのは木の中の再スタート (`ENOMOTO_MIP_TREE_RESTART`、試作で既定では使わない) だけ。
2. そのため、写し (hs_pi0_bgw_pc) は hs_pi0_bgw と同じ動きになる。
   - 再スタート後の根のヒューリスティクスの時間も、解の出どころも同じ。差は揺れの範囲。
   - **再スタート後の根のサブ MIP は軽くも良くもならない**。
   - 再スタート後の根のサブ MIP は閾値 0 (強分枝なし) なので、pseudocost が効くのは分枝の列の選び方だけ。
     重い部分は diag_hsletters の `c` (サブ MIP の根のカット 25 ラウンド) と `h` (中の RENS) で、pseudocost では変わらない。
3. 損と得の比較 (3 回):

   | 問題 | hs_pi0_bgw | + `TRIM=r` | + 写し |
   |---|---|---|---|
   | binkar10_1 | 9.6〜9.8 | **6.6〜6.8** | 9.7〜10.4 |
   | swath1 | 37〜42 | **22〜25** | 33〜41 |
   | mik | 6.9〜8.1 | **3.0〜5.2** | 7.1〜8.6 |
   | physiciansched6-2 | 2/3 | 2/3 | 1/3 |
   | h80x6320d | 24〜27 | **21〜24** | 26〜29 |
   | qiu | 3/3 | 1/3 | 2/3 |

   - 写しは損を消さない。`TRIM=r` は損の 3 問を def 並みに戻す。
   - 写しは得も変えない。physiciansched6-2・qiu は解けない回が出るが、どの設定でも初めの解・木の揺れで決まり、写しのせいではない (2 節)。
4. 余裕分の形 hs_pir_bgw_pc は、最初の根のサブ MIP を強分枝ありにし、再スタート後の根のサブ MIP だけ閾値 0 にしたもの
   (新しいスイッチ `ENOMOTO_MIP_SUBMIP_RELIABLE_RESTART_ONLY` + 写し)。
   - 損は減らない (binkar10_1 は 12 秒でかえって遅い)。
   - h80x6320d の得を失う (24〜27 → 42〜47 秒)。最初の根のサブ MIP の閾値 0 が得の元だからで、diag_pi0 の結論と合う。
   - physiciansched6-2 は 3/3・qiu も 3/3 で解けた。ただし physiciansched6-2 は回の揺れが大きく、3 回では決まらない。
5. **案 a は効かない**。写しと `RELIABLE_RESTART_ONLY` は既定にしない (残すが使わない)。
   再スタート後の根の損に手を打つなら、サブ MIP の形 (`c`・`h`) を変える `TRIM=r`、またはほかのセッションの `SUBMIP_HIGHS_RESTART` の方向がよい。

## 4. 試作のコード (どれも既定では使わない)

- `ENOMOTO_MIP_RESTART_PC` (`mod.rs` `restart_pc_on`・`RESTART_PC`、`pseudocost.rs` `remap_for_restart`、`solver.rs` `maybe_restart`・`run`):
  - 再スタートで今の pseudocost を退避し、前処理の後の問題の列へ写して、再スタート後の求解の初めの pseudocost にする。
  - 前処理は列の番号を保ち、尺度 d を掛ける (x = d x')。そこで、残った列 (前処理の後に幅のある列) は単位あたりの値に d を掛けて、観測の数ごと写す。
    前処理で消えた列・固定された列の観測は捨てる。全体の平均は残った列から数え直す。
  - 前処理が何も減らさないときは、そのまま写す。再スタートのたびに同じことをするので、繰り返しても続けて写る。信頼の閾値は新しい求解の設定のまま。
- `ENOMOTO_MIP_SUBMIP_RELIABLE_RESTART_ONLY` (`heuristics.rs` `submip_r0_on`・`SUBMIP_R0`、`solver.rs` の信頼の閾値):
  - `ENOMOTO_T_MIP_SUBMIP_RELIABLE` を、外側の求解の再スタート後の根で作ったサブ MIP と、その中の入れ子だけに効かせる。
  - 並列のサブ MIP には、`submip_r0` で印を渡す。
- 診断 (`ENOMOTO_MIP_LOG=1` のとき): 再スタートのたびに、次の 1 行を出す。
  - `MIP: restart k: pseudocost observations: columns up/down/both …; observations up/down …; nodes …`
  - 写しを使ったときは、写した後の量も出す。

## 判断と次の手

- 案 a (pseudocost の写し) は、根での再スタートでは写すものがない。再スタート後の根のサブ MIP を軽くも良くもしない。既定にしない。
- 再スタート後の根の損に効くのは、サブ MIP の形 (`c`・`h`) を戻すこと (`TRIM=r`)。
  - この 9 問の 3 回では、損の 4 問の SGM を 9.5 → 6.5 にする。
  - 得の 5 問は 14.5 → 17.8。qiu の時間切れ 2 回と、physiciansched6-2 の時間切れ 1 回が乗っている。どちらも揺れの大きい問題。
- pseudocost を再スタート後に生かしたいなら、根のサブ MIP の中の観測を親に戻す形が要る (HiGHS もしない)。
  - ただし再スタート後の根のサブ MIP は閾値 0 で強分枝がなく、重さの元は分枝ではないので、時間の得は見込みにくい。試さない。
