# 解を 1 つも見つけないサブ MIP を止める試作 `ENOMOTO_MIP_SUBMIP_NOSOL_STOP` (2026-11-01)

問い: `submip_where_20261101.md` で、今の既定のサブ MIP の時間の 43% (深さ 1 で 261 本・180.8 秒、58 問 1 回) は解を 1 つも
見つけないサブ MIP だった。成果連動の打ち切り (`submip_outcome_stop`) は解を見つけた後にしか効かない。解なしのサブ MIP だけを
途中で止めれば、得の問題を残したまま時間を返せるか。一律にノード上限を下げる形 (`halve_submip_20261030.md` の bench8) は
10teams・h80x6320d を遅くして採らなかった。

- 機械: 4 CPU。4 スレッド・60 秒、ソルバーは同時に 1 つだけ。HiGHS (highspy) は 1.15.1。`ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_SUBMIP_VERBOSE=1`。
- 問題: 損 (n5-3・neos-1582420・neos-2978193-inde)、得 (h80x6320d・qiu・mc11・physiciansched6-2)、見張り (10teams・binkar10_1・blp-ar98・mas76)
  の 11 問を各設定 3 回。回 → 問題 → 設定の順に回した。
- ビルドは 2 つ:
  - 1 回目 (`92b80fd` + 試作の最初の形、ノード数だけで止める): def・n200・n100・n50。
  - 2 回目 (別のセッションの RENS の試作 `b0e7b3e`・`469aec0` を取り込んだ木 + ノード数と時間の両方で止める形 `aff054c` の時点):
    def2・t10・t20。取り込んだ試作は既定では通らないが、同じビルドで既定 (def2) も回し直した。
- 台本・ログは `submip_nosol_stop_20261101/`:
  - `run.py [回数] [問題,...] [設定,...]`: 1 本ずつ解いて `logs/<設定>/<問題>_r<回>.log.gz`、結果の行を `results.jsonl` に足す。設定は `CFGS`。
    親の `ENOMOTO_` の環境変数は全部外してから設定を入れる。経過は `run.out` (1 回目のビルド)・`run2.out` (2 回目)。
  - `summ.py`: 下の表 (`summ.txt`)。平均の表は `avg.txt`。
- `cargo test --release --lib` (`CARGO_TARGET_DIR=target/test-py RUSTFLAGS="-C link-arg=-lpython3.13"`): 330 件通過 (18 件は ignored)。
- **最適値の食い違いはない**: 231 回のうち「最適」で終わった回の目的値は問題ごとに 1 つ (h80x6320d は全部 6382.09905)。
  別のセッションの ns250s (`submip_nodes_20261101.md` の 3.4 節) で出た h80x6320d の 6386.09905 (再スタート 2 の前処理の誤った実行不能の判定) は、
  ここの 7 設定 × 3 回では一度も出なかった。ただし同じ道 (LP face が 6386 を出し、続くサブ MIP が解なしで切られ、暫定解 6386 で
  再スタート 2 に入る) はこの試作でも開きうるので、前処理の誤り (`presolve_infeasible_20261101.md`) が直るまでは既定にしない。

## 1. 試作 (既定では使わない)

`src/mip/solver.rs` の `Solver::submip_nosol_stop` (木のループの、ノード上限の判定の直後で呼ぶ)。サブ MIP (`params.submip`) が
まだ暫定解を持っていなければ、**ノード数と経過秒の両方**が閾値を超えたら止める (片方を 0 にすればもう片方だけ。両方 0 なら止めない)。

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `ENOMOTO_MIP_SUBMIP_NOSOL_STOP` | なし | 立てると試作を使う |
| `ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES` | 100 | 深さ 1 のノード数の閾値 |
| `ENOMOTO_T_MIP_SUBMIP_NOSOL_TIME_FRAC` | 0 | 深さ 1 の経過秒の閾値 (サブ MIP の時間の上限に対する割合) |
| `ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES_DEEP`・`_TIME_FRAC_DEEP` | 深さ 1 と同じ | 深さ 2 以上 (入れ子の RENS など) |
| `ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES_NOINC` | 0 (止めない) | 刈り込みの上限が無限のとき (下) のノード数。時間では止めない |

- 根 (ノード 0) のカットのループ・根のヒューリスティクスは止めない。サブ MIP の解の多くはノード 0 で出る (`submip_where` の 2 節)。
- 止めたときの状態は `TimeLimit`。`NodeLimit` で返すと、RENS のノード上限 4 倍のやり直し (`RENS (more nodes)`) が同じ所まで回り直すので避けた
  (別のセッションの `ENOMOTO_MIP_RENS_MORE_NODES_REAL` を立てなくても、止めた RENS はやり直さない)。
- 「深さ」はサブ MIP の中の `SUBMIP_DEPTH` (外側の根・木から出したもの、別スレッドの並列のものが 1、その中の入れ子の RENS が 2)。
  外側の木の中の大近傍探索のサブ MIP も深さ 1 として同じ値を使う (時間の上限が 0.3〜1.4 秒と小さいので、時間の割合の条件は
  ほとんど同じ割合の秒になる)。
- **外側に暫定解がまだないときは除く (`_NOINC` の既定 0)**。判定はサブ MIP の刈り込みの上限 (`prune_limit`: 自分の暫定解・打ち切り値
  `params.cutoff`・外側から渡り続ける上限 `SubmipCtl::outer_best` の小さい方) が無限かどうか。無限なら、外側にも呼び出し側にも解がなく、
  そのサブ MIP は「最初の解を見つけること」自体が目的で、ここで止めると最初の解が遅れる・なくなる。例: physiciansched6-2 は
  Local-MIP が解を出さない回に、打ち切り値なしの根の RENS が 163〜252 ノードかけて 49324 を見つける (`ENOMOTO_T_MIP_SUBMIP_NOINC_GAP` の注釈)。
  解なしの時間の無駄は、ほとんどが外側に解があるとき (打ち切り値で切られて何も見つからない) なので、除いても取り分は小さい。
- LP 反復の割合の条件は入れていない。木のループのノードごとの LP 反復はノード数と経過秒にほぼ比例し、「1 ノードの重いサブ MIP だけを
  切る」には経過秒の条件で足りた (2 節の 10teams と 30n20b8 の比べ)。

## 2. 値の決め方: ノード数だけでは 10teams を切る

`submip_where_20261101/logs` (58 問 1 回) を読み直すと (`submip_where` の集計のやり直し):

- 深さ 1 で「最初の解を木 (ノード > 0) で見つけ、外側を良くした」サブ MIP は **10teams の 1 本だけ** (LP face、233 ノード・4.0 秒で 924)。
  深さ 2 以上では blp-ar98 の RENS (more nodes) の 1 本 (256 ノード・2.2 秒、時間の上限 6 秒)。ほかの外側を良くしたサブ MIP は全部ノード 0 で最初の解を持つ。
- 深さ 1 の解なしの重いもの: 30n20b8 の根の被約費用 (500 ノード・32.1 秒)・RENS (14.5 秒)、supportcase26 の RENS (more nodes) (27.4 秒)・
  RENS (18.9 秒)・RINS (10.7 秒)、neos-1456979 の根の被約費用 (18.2 秒)・RENS (11.0 秒)、h80x6320d の RENS (9.3 秒)、eil33-2 の根の被約費用 (5.1 秒)。

1 ノードあたりは 10teams 17 ms、30n20b8 64 ms、neos-1456979 36 ms、h80x6320d 19 ms と大差なく、ノード数の閾値は 10teams の 233 を
下回ると必ず切る。時間の割合の条件を重ねると、根のサブ MIP の時間の上限 (`t` で残り時間 ≈ 55〜58 秒) の 0.1 で約 5.5 秒・0.2 で約 11 秒になり、
10teams の 4 秒は残り、上の 10〜30 秒のものは 5.5〜11 秒で切れる。

### 読み

1. **ノード数だけで止める形 (n200・n100・n50) は 10teams を毎回遅くする** (既定 4.8〜5.2 秒 → 9 回とも 6.6〜37 秒)。予想どおり、根の被約費用・LP face の
   サブ MIP が 233 ノード目に出す 924 を失い、外側の木で 924 を見つけるまで 2000〜4000 ノードかかる (`logs/n100/10teams_r1.log.gz`)。
   n200 の 1 回目は根の被約費用・LP face のサブ MIP が出ない道 (下の 5 節の def2 の 39 秒の回と同じ) で、11 秒。
2. **ノード数だけの形は h80x6320d も遅くする** (22.9 → 26.7〜29.3)。止めたのは並列のスレッドの RENS (500 ノード・7.4 秒・解なし) で、
   解を失ったのではない。止めた後、再スタート後の根の LP face のサブ MIP が既定では 6382.099 (最適) を出すのに、試作では 6652 にとどまり、
   最適解は外側の木で 30 ノード目になる (`logs/def/h80x6320d_r1`・`logs/n100/h80x6320d_r2`)。並列のサブ MIP の終わる時刻が変わり、
   再スタート後の根の道が変わる。別のセッションの ns250 (並列のサブ MIP にもかける) が h80x6320d を遅くしたのと同じ仕組み
   (`submip_nodes_20261101.md` の 3.2 節。あちらは並列のサブ MIP を除く `_SERIAL` で避けた)。
3. **時間の条件を重ねると (t10・t20) 10teams は 6 回とも 4.9〜5.0 秒のまま**。t20 は h80x6320d も 22.6〜23.5 秒で既定と同じ
   (h80x6320d の RENS は 7.4 秒で、t20 の約 11 秒に届かず切らない)。t10 は h80x6320d を 3 回中 2 回 30〜31 秒にする (RENS を 5.5 秒で切る)。
4. 損の 3 問は戻らない。neos-1582420 の解なしのサブ MIP は 1 本 2〜4 秒で t10・t20 の閾値に届かないものが多く、改善は 34.4 → 33.3・31.6 秒
   (揺れの中)。n5-3 は解のあるサブ MIP が重い型で、この試作は効かない (`cand_slow_neos-1582420` の nosol と同じ)。neos-2978193-inde は
   ビルド間でも 38 → 52 秒と揺れ (def と def2)、試作の効きは読めない。
5. qiu の n200・n100・n50・def2 の時間切れ・40 秒の回は、最適解を持ったまま証明が届かない回で、各設定 1 回ずつ出る揺れ。physiciansched6-2 も
   どの設定でも 3 回中 0〜2 回時間切れになる (下界が 49324 に届くかの揺れ、`cand_slow_neos-1582420` の 5 節)。
6. 11 問の範囲では、t20 の得は blp-ar98 (時間切れのまま) の解なしの時間を半分にするくらいで、ほかは既定と同じ。効くはずの問題
   (30n20b8・supportcase26・neos-1456979 の 10〜30 秒の解なしのサブ MIP) は 11 問に入っていないので、58 問で確かめる。

## 4. 58 問で確かめる値

**t20** (1 つ):

```
ENOMOTO_MIP_SUBMIP_NOSOL_STOP=1 ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES=100 ENOMOTO_T_MIP_SUBMIP_NOSOL_TIME_FRAC=0.2
```

(深さ 2 以上も同じ値。外側に暫定解がないときは止めない。`_NODES=100` は既定値なので省いてもよい。)

- 理由: 11 問で既定より遅くなった問題がなく (10teams・h80x6320d を守る)、解なしのサブ MIP の時間を減らす。根の 10〜30 秒の解なしのサブ MIP
  (30n20b8・supportcase26・neos-1456979・eil33-2 の型) を 11 秒前後で切るのが狙い。
- 2 つ目を回すなら t10 (`... _TIME_FRAC=0.1`) だが、h80x6320d を遅くする回があるので優先度は低い。
- 別のセッションの ns250s (`ENOMOTO_T_MIP_SUBMIP_NOSOL_CAP=250 ENOMOTO_MIP_SUBMIP_NOSOL_CAP_SERIAL=1 ENOMOTO_MIP_RENS_MORE_NODES_REAL=1`) とは狙いが重なる
  (あちらはノード数 250 で、並列のサブ MIP を除く。こちらは並列も含め、時間の条件で重いものだけ)。n5-3 の得は real から来るので、
  58 問で t20 が良ければ t20 + `ENOMOTO_MIP_RENS_MORE_NODES_REAL=1` も比べるとよい。

## 5. 注意

- 3 回ずつの計測で、問題ごとの揺れ (qiu・physiciansched6-2・neos-2978193-inde・10teams の道の違い) は試作の効きより大きいことが多い。
  例えば def2 の 10teams の 39 秒の回は、根の被約費用・LP face のサブ MIP がそもそも出ない道 (Local-MIP の解の時刻の違い) で、試作とは関係ない。
- `summ.txt` の「うち解なしの打ち切り (TimeLimit)」の列は、状態が `TimeLimit` でノード上限より前に終わった解なしのサブ MIP の数で、
  本当の時間の上限 (深さ 3 の RENS など、既定でも出る) を含む。試作が止めた本数そのものではない。
- 前処理の誤った実行不能の判定 (`presolve_infeasible_20261101.md`) が直るまでは、どの解なしの打ち切りも既定にしない (0 項)。
