# neos-3627168-kasai の nra の害 (2026-11-26、親の依頼)

親の依頼: c2c の kasai で、nra (NODEROWS_ADAPT) をつけると 1 ノードが 1.3 ms → 3.4 ms に重くなる (analysis/par4_20261126 §11 の見立て) ので、
原因を突き止めて直しの試作 (既定オフ) を作る。nra は採用候補の `r0k23p` の形で測る。

台本: `run.py` (設定 def・c2cp・c2cp-nra・c2cp-sbpb・c2cp+環境変数。stderr はまるごと `logs/` に残し、`ENOMOTO_PROF_TREE_PAR` と
`ENOMOTO_MIP_NRA_TRACE=2000` をつける。どちらも解き方は変えない)。c2cp = analysis/combo2_20261125/cfg.py の C2 + SB_PROBEBD=1、nra は `r0k23p`。

## 1. 1 ノードの重さ (4 スレッド、種 1〜3、600 秒、`res.jsonl`、版 a76530529 = 新しい既定 ROOTPAR_CUT・PARIDLE・UNIFY_FIX を取り込んだもの)

1 ノードの CPU 時間 = 最後の求解の 4 スレッドの (終わり − 待ち) の和 / ノード数 (`ENOMOTO_PROF_TREE_PAR` の行から)。
潜りの LP = 潜り・兄弟のノードの最初の LP の平均の反復数と時間。

| 設定 | 種 | 秒 | ノード | 1 ノードの CPU 時間 | 潜りの LP |
|---|---|---:|---:|---:|---|
| def | 1 | 54.2 | 9423 | 13.60 ms | 21.2 it・6.32 ms |
| def | 2 | 46.2 | 29897 | 4.26 ms | 8.1 it・1.31 ms |
| def | 3 | 61.1 | 11508 | 12.15 ms | 18.6 it・5.68 ms |
| c2cp | 1 | 84.7 | 64394 | 4.48 ms | 8.5 it・1.36 ms |
| c2cp | 2 | 54.7 | 12022 | 11.85 ms | 19.1 it・5.26 ms |
| c2cp | 3 | 75.3 | 56172 | 4.46 ms | 9.5 it・1.51 ms |
| c2cp-nra | 1 | 41.0 | 37955 | 3.94 ms | 9.8 it・1.37 ms |
| c2cp-nra | 2 | 57.6 | 49918 | 3.90 ms | 8.8 it・1.37 ms |
| c2cp-nra | 3 | 74.6 | 59519 | 4.04 ms | 8.2 it・1.28 ms |

- **nra で 1 ノードが重くなる形はない**。1 ノードの重さは設定によらず 2 つの型に分かれる。
  - 軽い型: 約 4 ms、潜りの LP は約 9 反復・1.3 ms。ノードが多い。
  - 重い型: 約 12〜14 ms、潜りの LP は約 20 反復・5〜6 ms。ノードが少なく、全体はむしろ速い。
  - 既定 (nra なし) でも両方の型が出る (種 2 は軽い型、種 1・3 は重い型)。
- LP の行の数 (`NRA_TRACE` の lp_rows) は、どの回も 1700〜2900 行で、型による差はない。
- par4 §11 の「1.3 → 3.4 ms」は、取り込み前の版で経過時間をノード数で割った値で、この 2 つの型の違いを見ていた。仕組みの害の根拠にはならない
  (同じ版の def が重い型、c2c が軽い型だっただけ)。
- 秒の幾何平均: def 53.4、c2cp 70.4、c2cp-nra 55.6。c2cp の遅れはノード数の違い (道筋) で、nra を抜いて戻るのは種 1 だけ (種 2・3 は同じ)。
