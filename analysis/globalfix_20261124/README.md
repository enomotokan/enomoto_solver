# globalfix: 根・衝突で分かった大域的な固定を大域的な境界に入れる試作 (2026-11-24、親の依頼、利用者の承認あり)

監査 (analysis/globalaudit_20261124) の A1・A2・C1 を直す試作。**既定は変えない** (`ENOMOTO_MIP_GLOBALFIX` を付けたときだけ働く)。新しい閾値は作らない
(`b` の伝播の繰り返しの上限は FIXMORE の既存のつまみ `ENOMOTO_T_MIP_FIXMORE_ROUNDS` (既定 50) をそのまま使う)。

## 1. 中身

値の文字で部品を選ぶ (`=abc` で全部。`k` は計測の途中で足した、`c` を整数列だけにしたもの (4.3 節))。

- `a` (監査の A1、src/mip/solver.rs の `globalfix_root`): 根のノード (深さ 0、分枝の変更なし。再スタートの後の根も含む。主の求解だけで、サブ MIP・木の写しの従では
  使わない) を分枝する時点で、定義域が大域的な境界より締まっている**整数列**の境界を `tighten_global` で大域的な境界に入れる。根のノードの記録はまだ
  巻き戻していないので、`tighten_global` は大域的な境界をその場で締め、今の定義域には次に根へ戻ったときに置く (`pending_global`)。
  - 大域的な境界に入るので、再スタートの判定の数え (`newly_fixed_ints`)・ほかのスレッド (`sync_global_bounds`、64 ノードおき)・再スタートの後の問題
    (`maybe_restart` は大域的な境界で作る) にもそのまま入る。判定を呼ぶ時点は変えない (根の終わりの判定は根のノードの前に済んでいるので、
    `a` の固定が数えられるのは木の中の判定 (暫定解の改善のとき) から)。
  - 連続列は入れない: analysis/objprobehull_20261124 の 1.2 節で、連続列の締めを LP に入れると根の下界と木が悪くなる形があった。
    `b` を併せれば、整数列の固定から行を通して締まる連続列の境界は、根へ戻ったときの伝播で入る。
- `b` (A2、src/mip/domain.rs の `reset_to_root`・`globalfix_propagate`): `reset_to_root` が保留中の大域的な締め付けを置いたとき、伝播の待ち行列を
  捨てずに根で伝播し切り (行と含意。手間の上限で打ち切られたら続けて最大 50 回、FIXMORE の `propagate_all` と同じ)、結果を `commit_root` で
  大域的な境界にする (整数列・連続列とも)。伝播が矛盾したら (打ち切り値より良い解がない) 記録を巻き戻して `root_dead` を立て、以後の根への戻りで
  毎回矛盾にする (残りのノードは全部刈られ、木は今の暫定解で閉じる)。
  - サブ MIP の定義域でも働く (定義域の中の処理なので区別しない。サブ MIP の中でも同じ理屈で正しい)。
  - FIXMORE (保留、analysis/fixmore_20261112.md) の `p` は、根の終わり (再スタートの判定の前) に 1 回だけ、新しい定義域を作って大域的な境界から
    閉包を取り、整数列と目的の列を大域にするもの。`b` は同じ「大域的な境界からの行の伝播の閉包」を、大域的な締め付けを置くたび (主に暫定解の改善で
    根の被約費用の固定をかけ直したあと) に、今の根の定義域の上で差分だけ (置いた締め付けの行から) 取る。FIXMORE の 58 問の計測 (+1.4%) の主な部品は
    内点法の双対の固定 `u` で、`p` 単独の計測はない。
- `c` (C1、solver.rs の `add_lit_conflict`): 大域的に成り立つリテラルを除いて長さ 1 になったリテラルの衝突は、そのリテラルの否定を `tighten_global` で
  大域的な境界に置く。否定は衝突のプールの伝播 (src/mip/conflict_pool.rs の「否定」) と同じ形 (`x <= v` の否定は整数列 `x >= floor(v) + 1`、
  連続列は緩めて `x >= v`)。プールにもこれまでどおり入れる (ほかの振る舞いは変えない)。ほかのスレッドから取り込んだ衝突にも当てる。
- 数え: `ENOMOTO_MIP_DIAG_GLOBALAUDIT=1 ENOMOTO_MIP_LOG=1` で、終わりに `MIP: GLOBALAUDIT globalfix:` (部品ごとの回数・締めた数・固定の数) と、
  監査の診断 (捨てた数) を出す。`a` を付けたとき、監査の `GLOBALAUDIT root` の行は `a` の後に数える (大域にない残りを出す)。

## 2. 正しさの理屈

「打ち切り値より良い解 (暫定解が無ければ全ての実行可能解) をどれも捨てない」締め付けは、木の全ノード・全スレッドに置いてよい。根の被約費用の固定
(`root_redcost_fixing`) と同じ根拠で、打ち切り値が後で良くなっても成り立ったまま (残す解の集合が小さくなるだけ)。

- `a`: 根のノードの定義域の変更 (記録の理由) は、行の伝播 (全ての実行可能解で成り立つ)、双対証明・リテラルの衝突・カットのプールの伝播 (どれも大域的に
  成り立つ制約・衝突の伝播)、ノードの被約費用の固定・強分枝の片側の打ち切り・目的の伝播 (打ち切り値より良い解だけを残す。深さ 0 では全ての解が
  根のノードの下にある)、根の打ち切り値つきプロービングが足した含意 (同じ)。オービトープの固定 (対称性) は、対称性の扱いが木全体で同じ群を使う限り
  根のノードの部分木 = 木全体で成り立つ (再スタートした後の問題は「最適解を含む」ことが保たれる)。そもそも根のノードの LP の値を子の下界にしているのは、
  根のノードの定義域が (打ち切り値より良い) 全ての解を含むという同じ前提。
- `b`: 根の定義域 (記録が空) は大域的な境界そのもの。置いた締め付けも大域的に成り立つので、そこからの行・含意の伝播も大域的に成り立つ。矛盾 =
  大域的な境界 (打ち切り値つき) の中に解がない = 打ち切り値より良い解がない。
- `c`: リテラルの衝突は「全てのリテラルが同時には成り立たない」で、衝突解析の理由 (行・証明・カット) は大域的に成り立ち、決定・外からの変更は葉として
  リテラルに残る。大域的に成り立つリテラルを除いた後に 1 つ残れば、その否定は全ての (打ち切り値より良い) 解で成り立つ。プールの伝播はすでにこの衝突を
  どのノードでも使っているので、新しい前提は足していない。

### 4.3 =k (=c を整数列だけに)

`k` = `c` を整数列だけにしたもの (連続列は大域にせずプールだけに入れる。`a` が連続列を除くのと同じ理由。新しい閾値はない)。pk1 (1 スレッド、種 1) では
大域の締め付けが 8 本になり、既定と同じ 52.6 秒で解けた (=c は時間切れ)。ただし種 1〜5 では上の表のとおり pk1 1.05・noswot 1.17 (1 スレッド) で、害は消えなかった。
P の本計測 (`plan_k.py` → shards_k.json、res_k1〜k4.jsonl。既定は 4.1 節と同じ res_s*.jsonl):

| スレッド | 回 | 比 | 95% 区間 | 解けた数 既定 → =abk | 食い違い | 1.25 倍超の問題 |
|---|---:|---:|---|---|---|---|

| 4 | 174 | 1.015 | [0.993, 1.038] | 139 → 139 | 0 | 10teams 1.79、noswot 1.26 |

=abk は =abc より良くない。

- noswot (1 スレッド、種 2、既定 16 秒・=abk 時間切れ) の中身: 既定は 6.6 秒 (11200 ノード) で木の大きさの見積もりによる木の再スタート
  (`MIP: TREE restart: 0 newly fixed integer columns`) をして 18 秒で解ける。=k は長さ 1 の衝突から整数列の大域の固定を 140 回置き、8900 ノードの
  時点の見積もりが既定と違って (est 19 万 → 42 万) 再スタートをせず、時間切れ。固定そのものが重いのではなく、再スタートの判定という不安定な分かれ目で
  悪い側に転んだ形。

### 4.4 まとめ

- 正しさ: 食い違い 0 (P の 1044 行 + 切り分け 174 行)、fuzz 7 本誤答 0、cargo test 通過。
- 速さ: =abc・=abk とも P では全体で中立 (1 スレッド 0.999・1.003、4 スレッド 1.008・1.015)。捨てていた情報 (qnet1 の 329 本など) を大域に入れても、
  この 58 問・60 秒では速さに出ない。害は noswot・10teams (短い問題で再スタートや木の進み方がずれるもの) で、4 スレッドでは種のばらつきの範囲と区別しにくい。
- 既定にはしない。=a・=b は 1 スレッドで中立なので、目的の伝播 (OBJ_PROP)・objprobehull のように大域の固定を増やす部品と組み合わせたときの土台として残す
  (objprobehull の子が =abc・=abc+OG・=abc+OG+OBJ_PROP を測る)。=c・=k は長さ 1 の衝突がもともとプールで全ノードに効いているので、大域にする得が小さく、
  再スタートの判定などの分かれ目を揺らす分だけ損になりやすい。
