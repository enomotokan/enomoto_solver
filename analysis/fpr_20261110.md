## 文献

- Salvagnin, Roberti, Fischetti (2025)「A fix-propagate-repair heuristic for mixed integer programming」, Math. Prog. Comp. 17(1), 111–139。
  本文 (の preprint) は arxiv.org・optimization-online.org に見つからず (arXiv の API で著者・題名を引いても出ない)、Springer・著者の頁は許可外で、
  **論文そのものは読めていない**。
- 代わりに、論文を HiGHS に移した Spoorendonk (2026)「Presolve heuristics in HiGHS: implementation and computational study」(arXiv 2609.22938)
  の 2.2 節・Algorithm 2 と、その公開の実装 (github.com/spoorendonk/mip-heuristics の `src/fpr.cpp`・`fpr_core.cpp`・`repair_walk.cpp`・
  `fpr_strategies.h`・`fpr_val_select.cpp`・`docs/PARAMETERS.md`。論文の節・図・表を引いたコメントつき) を読んだ。そこに書かれた論文の中身
  (移植者による引用・言い換えで、論文の原文での確認ではない):
  - 枠組み: 整数列を順 σ・値の規則 ν で決める深さ優先探索で、形 m が伝播・repair・後戻りを入り切りする。`dfs` (伝播・後戻り)、`dfsrep` (伝播・repair・後戻り)、
    `dive` (伝播なし、repair は最後だけ、後戻りなし)、`diveprop` (伝播・repair・後戻りなし)、`repairsearch` (論文の図 5)。兄弟はもう一方の端 (0-1 列は 1 − v)。節点は n + 1 まで。
  - 最初に自明に丸められる整数列 (片方の lock が 0) を固定する (論文 6 節)。
  - repair (論文 5 節、RepairWalk): **部分割り当て** (今の定義域) の上で、行の活動量の範囲 [m, M] と行の範囲の距離を違反とする。違反行を一様に選び、
    その行を満たす最小のずらし (整数列は丸め、元の境界に収まるよう切る) で列の**定義域を平行移動**する。違反を減らさない列は除く。被害は他の行の違反の
    **増えた分** (減った分は数えない。論文は「違反の数」と「違反の量」の両方を書いており、移植は量を採った)。被害 0 の手は貪欲、なければ雑音 **0.75**
    で無作為。タブーは直近 **3** 手、**10** 手ごとに最良の状態へ戻す、1 回 **200** 手まで。repair は伝播を使わない。
  - 整数列を全部決めたら残りを埋め (費用のある連続列は良い向きの端、費用 0 は 0、無限の端は ±1e5)、違反が残れば全列の点の上の WalkSAT (200 手、雑音 0.75)。
  - 列の順: LR (定式化の順)・type (0-1・整数・連続)・random (型の中で無作為)・locks (型の中で max(上 lock, 下 lock))・typecl (0-1 列のクリーク被覆を先に)・
    cliques・cliques2 (LP を使う)・domainsize (節点ごとに最も狭い列)。値: up・random・goodobj・badobj (費用 0 は下限)・loosedyn (今の定義域の活動量で数えた lock の
    少ない向き)・LP 系 (zerocore・zerolp・core・lp。lp は小数部分の確率で切り上げ)。名前つきの組が 14 通り (論文 表 3)。
  - LP を使わない初めの 8 通り (論文 6.3 節の Class 1、移植の `kInitialFprConfigs`): (typecl, badobj, dfs)・(locks, loosedyn, dfs)・(locks, loosedyn, dive)・
    (LR, loosedyn, dfsrep)・(typecl, badobj, dfsrep)・(typecl, random, diveprop)・(LR, loosedyn, repairsearch)・(domainsize, loosedyn, dfs)。2 回目からは順の先頭 30% を混ぜる。
  - 移植の結果 (mipfeas 233 問、HiGHS 1.15.1): 単独で FPR は 136 問で解を出し、109 問で最初 (FJ 146・107、LocalMIP 160・116)。ただし解の質は低く
    (最良の解のギャップの中央値 FPR 0.448、FJ 0.099、LocalMIP 0.182。両方が解く問題で FJ が FPR より良いのは 81 問、悪いのは 24 問)。FJ → FPR → LocalMIP の順に
    つないだ設定で、最初の解の出どころは FJ 114 問・FPR 16 問・LocalMIP 5 問、600 秒の最良の解は FPR 2 問だけ。LP を使う FPR (`fpr_lp`、木の中のダイビングで使う)
    は 49 問で解を 1 つも採られず、既定では切ってある。
- 検索の抜粋で分かっていたこと: MIPLIB 2017 の 240 問のうち 189 問でポートフォリオが数秒で解を出す。Xpress に入れて少し縮んだ。弱みは repair が伝播を使わず循環しやすいこと。

## 実装 (`src/mip/fpr.rs`、既存のファイルの差分は小さく)

- `fpr_run`: 1 回の FPR。列を順に決め、決めるたびに `Domain::propagate`。矛盾したら、その固定を戻したうえで列はその値に決めたまま、
  **全列の点** (決めた列はその値、まだ決めていない列は今の定義域に収めた仮の値) の上で WalkSAT 風の repair をする:
  違反行を無作為に 1 つ選び、その行の列 (長い行は 64 本まで) について違反を直す向きにずらした値 (整数列は丸め、最初の伝播の後の定義域に収める) を候補にし、
  確率 0.1 (`ENOMOTO_T_MIP_FPR_NOISE`) で無作為、それ以外は重みつきの違反の増減 (被害) が最小のもの (まだ決めていない列を少し好む。タブー 3〜10 手) を選ぶ。
  行き詰まったら (最良の手でも良くならない) 違反行の重みを 1 増やす (FJ 流)。全行を満たせば、その点を解として返す。満たせなければ
  (手数の上限 200 + 10 × 違反行数)、値の変わった最初の決定まで定義域を巻き戻して固定・伝播をやり直し、やり直しで矛盾した列は「まだ決めていない」に戻して
  repair の値の近くから決め直す (各列 3 回まで)。
  - 最初の実装は「決めた列の値 + まだ決めていない列の定義域」で行の活動量の範囲を見る repair だったが、伝播の矛盾は連鎖で起きるので違反行として見えず、
    repair が何もしなかった (neos-3216931-puriri で 0 手)。全列の点の上の repair に変えた。
- 列の順: 番号順・無作為・非零の多い順・定義域の狭い順・LP 解の整数に近い順。値: 目的の良い端・lock の少ない端・無作為・LP 解の丸め・0 に近い値。
  LP を使わない 8 通り (`LP_FREE`) と LP 解を使う 4 通り (`WITH_LP`) をポートフォリオで回す。
- 使う場所 (`ENOMOTO_MIP_FPR` の文字、`1` で全部):
  - `t`: FJ と同じ問題 (対称性の行を足す前) で、根の LP の前に別スレッドで LP を使わない 8 通りを回す (時間上限の 0.1 倍、最大 10 秒。全列の解を見つけたら
    1 周だけ回して止める。主が暫定解を持ったら止める)。連続列で行き詰まったら整数列の割り当てを主に渡し、主が整数列を固定して LP で仕上げる。
    解は根のカットのループの各ラウンドなど (`poll_lmip_thread`) で受け取る。
  - `r`: 根のヒューリスティクス (ランダム丸めの後、暫定解がなければ)。8 回、時間上限の 0.02 倍・最大 2 秒。整数列だけ決め、連続部分は LP (`fix_and_propagate`)。
  - `b`: 暫定解がない間の木の中の腕 (`NOINC_FPR_ARM`)。バンディットなし: RENS → FP → ダイビング → FPR を回す。バンディット `ENOMOTO_MIP_NOINC_BANDIT` の腕にもなる。

- **論文に寄せた核 `ENOMOTO_MIP_FPR=p`** (`src/mip/fpr_paper.rs`、11-10 の後半に足した): 上の移植の記述に合わせ、`dfs`・`dfsrep`・`dive`・`diveprop` の形、
  兄弟への後戻り (節点 n + 1 まで)、自明な丸め、部分割り当ての上の RepairWalk (活動量の範囲・定義域の平行移動・被害は増えた分・雑音 0.75・タブー 3・
  10 手ごとに最良へ・200 手)、最後の埋めと WalkSAT、Class 1 の 8 通りを入れた。違い: (1) ENOMOTO の `Domain` は境界を締めることしかできないので、repair が
  決めた列の値を変えたら最初から固定し直して伝播する (失敗ならその試みは終わり)。固定し直した後は前の兄弟に戻らない。(2) typecl のクリーク被覆はなく型の順だけ。
  (3) `repairsearch` は `dfsrep` で代えた。(4) LP を使う組み合わせ (主のスレッドの `r`・`b`) は論文の Class 2・3 の正確な組が分からず、移植の `typecl/lp` に形を
  組み合わせた 4 通り (未確認)。最初の版 (`1`) の repair は全列の点の上の WalkSAT で、論文の repair とは違う (FJ に近い)。

## 事実と推測

事実:
- FPR の別スレッドは、多くの問題で MIP 前処理の後 0.01〜0.6 秒で全列の実行可能解を出す (cod105・mzzv11・mzzv42z・satellites2-60-fs・neos-873061・neos-1456979・10teams)。
  連続列や等式の多い問題 (neos-4722843-widden・csched008・tbfp-network・physiciansched6-2・neos-3216931-puriri) では出せない。
- その解は質が低いことが多く (neos-873061 2.58e5 対 主の 125.9、air03 711196 対 340160)、解き終わる時間はほとんど変わらない (58 問の SGM の区間は 0 をまたぐ)。
- 最初の解の時刻の差は小さい問題が多い。外側の時刻の大部分は前処理と、主のスレッドが受け取るまでの時間 (根の LP)。
- 論文の本文は読めていない (arXiv・optimization-online に無い。Springer・著者の頁は許可外)。repair の細部は HiGHS への移植 (arXiv 2609.22938 と公開の実装) で確かめた。

推測:
- 論文の 240 問中 189 問・数秒という結果と比べて ENOMOTO で効き目が小さいのは、ENOMOTO にはすでに FJ + Local-MIP のスレッドがあり、最初の解の多くをそれが出すため
  (既定の最初の解は 58 問の多くで「Local-MIP」)。Xpress に入れて少し縮んだという報告も、同種の LP を使わない局所探索の有無で差が変わると思われる。
- repair を「全列の点の上の WalkSAT」にした最初の版は FJ にかなり近い。論文寄りの repair (部分割り当ての上、定義域の平行移動) にしても良くはならなかったので、
  ENOMOTO で効き目が小さいのは repair の形ではなく、FJ + Local-MIP と役が重なること (と ENOMOTO の伝播が締めることしかできず、repair の後に固定し直す手間) によると見る。
