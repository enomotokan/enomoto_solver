- 機械: 4 CPU のコンテナ。ソルバーは同時に 1 つ (1. の途中で 1 回 cargo build を重ねた: gen-ip054 か pk1 の実行中。どちらも 0.1 秒台で暫定解が出る問題で表には効かないとみる)。
- 土台: develop 1540290。ブランチ `inv/fjrepair-20261023`。
- 台本・ログ: `analysis/fjrepair_20261023/` (`run_cfg.sh`・`eno_run.py`・`table.py`・`batch1.sh`・`batch3.sh`、`logs/`)。表: `table_stats.md` (1.)、`table_def.md`・`table_fjr3.md` (3.)。
- 4 スレッド・60 秒。

## 足したもの (既定は変えない)

| 環境変数 | 中身 |
|---|---|
| `ENOMOTO_MIP_FJ_STATS=1` | 診断。別スレッドの FJ の最良の点 (違反の行の数が最も少ない点) を記録し、`MIP: FJ best point: ...` (違反行の数・違反量・暫定解の有無) を出す。根のヒューリスティクスの後に、出どころ別の最良の点 (`MIP: infeasible point pool: ...`) を出す |
| `ENOMOTO_MIP_FJ_REPAIR=1` | 試作 (FJ 修復)。下記 |
| `ENOMOTO_T_MIP_FJ_REPAIR_MAXVIOL` (20) | 修復を始める違反行の数の上限 |
| `ENOMOTO_T_MIP_FJ_REPAIR_MAXFREE` (2000) | 1 回目に自由にする整数列の上限 (違反行の列はこれを超えても全部自由)。回ごとに 2 倍 |
| `ENOMOTO_T_MIP_FJ_REPAIR_ROUNDS` (4) | 近傍を広げてやり直す回数 |
| `ENOMOTO_T_MIP_FJ_REPAIR_TIME_FRAC/_MAX` (0.25 / 15 秒)、`_NODES` (2000) | サブ MIP の時間・ノードの上限 (今の Repair は 7%・6 秒・500 ノード) |
| `ENOMOTO_MIP_FJ_REPAIR_NOCUTS` | サブ MIP の根のカットをサブ MIP の既定 (5 ラウンド) に戻す (既定の試作は `fc_submip` の設定で 25 ラウンド・停滞 10) |
| `ENOMOTO_MIP_FJ_REPAIR=2` | 暫定解があっても試す (打ち切り値つき、近傍は 1 回だけ) |

FJ 修復の手順 (`heur_scip.rs` `spawn_fj_repair`・`fj_repair_problems`・`pool_repair`、`solver.rs` `join_fj_thread`・`poll_fj_repair`):
1. FJ のスレッドが終わったとき (根のカットのループの途中)、暫定解がなく FJ の最良の点の違反行が MAXVIOL 本以下なら、別スレッドでサブ MIP を解き始める。
   受け取りは根のカットの各ラウンド・根のヒューリスティクスの後・木の各ノードで (待たない)。
2. サブ MIP: 違反行の整数列 + そこから 1 段の行 (短い行から) の整数列を MAXFREE 本まで自由にし、ほかの整数列を点の値に固定。連続列は全部自由。**元の目的関数・元の制約**。
3. 実行不能なら同じ固定で違反量の合計の最小化 (今の Repair と同じ形)。違反 0 なら解。残れば、その点から段を 1 つ増やし MAXFREE を 2 倍にして 2. へ (ROUNDS 回まで)。
4. 利用者の追加案: 暫定解がない間、FJ・Feasibility Pump の各回の丸めた点・randomized rounding の目標の点・局所探索の違反最小の点・`try_incumbent` で落ちた点 (simple rounding など) を、出どころごとに「違反行の数、同じなら違反量」が最小のものを記録する (`note_point`)。根のヒューリスティクスの後 (Repair の前) にまだ暫定解がなく、前の修復が終わっていれば、まだ使っていない最良の点から 2.〜3. を始める。

## 既定にする候補か

- 当たる問題は 55 問中 neos-1456979 の 1 問 (最初の暫定解 44〜60 秒 → 3.7 秒)。働かない問題では、FJ の最良の点を残す手間 (違反の行が 200 本以下になるたびの点の写し) と、暫定解がない間の `note_point` (点ごとに全部の行の違反を数える) だけ。
- 1 問だけの効果なので、**既定にするなら 40 問 + 16 問を 2 組回して悪くならないことを確かめてから**。今の形 (暫定解がなく FJ の点の違反が 20 行以下のときだけ動く) なら、動く問題が少なく害も小さいとみる。
- Pump・丸めの点の記録 (`note_point`) は効果が見えないので、既定にするなら FJ・局所探索の点だけで足りる。
