- 事実: 時間の差は roll3000・mik-250 で種によって向きが入れ替わり、他はほぼ同じ。2 種で揃って動くのは unitcal_7 の根の下界だけ
  (0.1・0 で +4 万、2 種とも)。誤答なし。
- 事実 (ログ): 今の既定では MIN_REL を使わない経路が多い。sp150x300d・p200x1188c は固定費用ネットワーク型の判定に掛かり
  `ENOMOTO_T_CUTSEL_FC_MIN_REL` (0) で選ぶ。nu25-pr12 は選び方の下見 (CUTSEL_PROBE) が pool を選び HiGHS の点数で選ぶ。
  misc07 は根の候補がほぼ全部 0.5 × 最良を超える。10 月の記録の差 (misc07 36 → 11 秒、sp150x300d 60 秒切れ → 1.4 秒、p200x1188c 6.5 → 12.5 秒) は
  その後の既定の変更 (固定費用型の緩めた選択・CUTSEL_PROBE など) でほぼ吸収されている (推測)。
- 特徴の候補: 閾値を超える候補の割合 (DEBUG_CUTSEL の呼び出しの平均。サブ MIP とノードを含む) は unitcal_7 が 0.06〜0.07、他は 0.26〜0.91 で、
  閾値を下げて得をする唯一の問題 (unitcal_7) は分けられる。ただし 1 問だけで、時間の得はまだ見えていない (120 秒では根の下界だけ)。

## 判断

- 「効く側と損する側の逆向き」は今の既定の上では再現しない。シグモイドの試作 (3) には進まない。
- 続けるなら、超える割合が小さいとき (例 < 0.15) だけ閾値を下げる案になるが、これは既存の `ENOMOTO_T_CUTSEL_FILL_FRAC` (少なすぎれば上位半分まで足す) と
  ほぼ同じ働き。先に unitcal_7 (と M で根の候補が多い問題) を 600 秒で `ENOMOTO_T_CUTSEL_MIN_REL=0.1` / `FILL_FRAC` と比べ、時間の得があるかを見るのが順。
