# cutlen: 根のカットのループの長さを特徴の関数にする (featconst_20261118 の 3、2026-11-18)

BRIEF.md の 3 (`ENOMOTO_T_MIP_CUT_TIME_FRAC`・`ENOMOTO_T_MIP_CUT_ROUNDS`) の担当。共通の約束の (1)・(2) までの記録。

## 道具

- `src/mip/solver.rs` に診断の行 `MIP: root LP work: <手間> tick-s (...)` を足した (記録だけ、振る舞いは変えない)。
- `one.sh` (slow2 の写し、4 スレッド・ログつき)、`feat.py` (ログから r などを拾う)、`batch1.sh` (下の計測)。ログは `logs/*.log.gz`。
- r = 1 ラウンドの手間 ÷ 根の LP の手間。外側の最初の根のループの「時間の上限の判定」の時計 (ループの始めからの手間、TICKS `w`) を
  判定の回数で割り、根の LP の手間で割る。手間はスレッドごとの数えなので、種によらずほぼ同じ値になる (表の r は種 1)。

## (1) 今の既定での測り直し (ログを残した版は 44eb237f3 の上、4 スレッド・60 秒、種 1・2)

設定: def = 既定、r8 = `CUT_ROUNDS=8`、r8h = r8 + `SUBMIP_HC_CUT_ROUNDS=25` (サブ MIP は既定のまま)、r50 = `CUT_ROUNDS=50`・`CUT_TIME_FRAC=0.2`。秒 (種 1 / 種 2)。

| h80x6320d | 3.63 | 26.5 / 32.4 | 20.8 / 24.8 | 23.7 / 27.1 | 55.3 / 40.3 |
| neos-3381206-awhea | 2.80 | 4.0 / 3.7 | 14.1 / 18.2 | 3.8 / 3.7 | 4.2 / 3.5 |
| neos-911970 | 2.27 | 39.3 / 12.1 | 32.1 / 18.3 | - | 49.7 / 17.5 |
| exp-1-500-5-5 | 1.34 | 8.6 / 5.7 | 5.3 / 8.2 | - | 9.0 / 8.7 |
| p200x1188c | 0.75 | 3.1 / 3.3 | 2.8 / 3.2 | - | 4.2 / 5.0 |

- **r は両側をきれいに分ける**: 「長い方が良い」とされた 4 問は r = 1.3〜3.6、「短い方が良い」4 問は 0.39〜0.75 (境目 ≈ 1)。
- **ただし今の既定の上では、逆向きは記録より弱い**:
  - 延ばす (r50) と得をする問題はない。h80x6320d は ×1.6 遅く (上限に当たるまで 48〜55 ラウンド)、短い側も ×1.2〜1.5 遅い。
  - 縮める (r8) と、短い側は得 (qnet1 ×0.47、neos17 ×0.85、p200x1188c ×0.94、fiber 同じ)。
  - 長い側で r8 の損に見えた neos-3381206-awhea (×4) は、**外側の根ではなくサブ MIP の根のラウンド数**から来ていた
    (`SUBMIP_HC_CUT_ROUNDS` の既定が `CUT_ROUNDS` を引き継ぐ。外側のループは r8 でも 24 ラウンド回っていて
    (「動かないので本数を広げる」で上限が 100 ラウンドに延びる)、r8h では既定と同じ 3.8 秒)。
  - h80x6320d は記録 (timedep §6.2、手間の上限 6 で ×2.64) と逆に、8 ラウンドで速い (×0.79。根の閉じた割合は 0.95 → 0.77 に下がるが、木が軽い)。
  - neos-911970・exp-1-500-5-5 は種の揺れの方が大きい (39.3 / 12.1 など)。neos-911970 は r8 で根の閉じた割合が 0.75 → 0.30 に下がる。
- 外側のループの長さは `CUT_ROUNDS` だけでなく、本数を広げると +100 ラウンド (`CUT_WIDEN`)、強いカットなら第 2 段階 +60 ラウンド (`CUT_STRONG_AUTO`、
  exp-1-500-5-5・p200x1188c 種 2 は 85 ラウンド)、伸びが続けば +25 (adapt) でも決まる。時間の上限 (全体の 1 割の手間) に当たったのは r50 の h80x6320d だけ。

## (2) 見込み

- 特徴 r は分かれるが、効く向きは「r が小さい問題ではラウンドを 8 前後に縮める」の片側だけで、「r が大きい問題で延ばす」側の得は今の既定では見えない。
- 試作の案: 外側の根だけ (サブ MIP の `SUBMIP_HC_CUT_ROUNDS` は 25 のまま固定して切り離す) の上限を
  `rounds = 8 + 17 × σ(k (ln r − ln r0))` (r0 ≈ 1、k ≈ 4) にする。r が大きい問題は今と同じ 25、小さい問題は 8。
  延ばす向き (r50) と時間の上限 (`CUT_TIME_FRAC`) は変えない。
- 懸念: 8 問のうち得は qnet1 が主で、neos-911970 (r 2.3) は縮めると根が弱くなるが、r が大きいので守られる。h80x6320d (r 3.6) は縮める方が速いので、
  関数では取りこぼす。58 問全体で r < 1 の問題に縮めて損をするものがあるかは P で確かめる必要がある。

## (3) 試作 `ENOMOTO_MIP_CUTLEN` (既定では使わない、src/mip/separation.rs)

- 外側の根の主のループ (サブ MIP・裏のカット・続きのループでは使わない) で、1 ラウンド目から 8 ラウンド目の始めまでの時計 (時間の上限と同じ時計、
  既定では手間) から r を数える。0 ラウンド目は選び方の比べなどで重いので除く (始めの 3 ラウンドで数えた初版は、qnet1 の r が 2.8 と出て効かなかった)。
- 上限 = `LO + (HI − LO) × σ(K (ln r − ln R0))`。LO 8 (`ENOMOTO_T_MIP_CUTLEN_LO`)、HI = `ENOMOTO_T_MIP_CUT_ROUNDS` (25)、R0 1、K 4、数える所 `ENOMOTO_T_MIP_CUTLEN_AT` (8)。
  下げるだけで上げはしない。本数を広げる・第 2 段階などの延長は今のまま。上限がもうそのラウンドに届いていれば、そのラウンドを回さずに止める。
- 再スタートの後の根でも同じく数える (r はふつう小さくなる)。

代表 8 問 × 種 1・2 (`batch2.sh`、秒、def は (1) の表):

| 問題 | 8 ラウンド目の r → 上限 | def | cl |
|---|---|---|---|
| h80x6320d | 2.0 → 24、再スタート後 1.1 → 18 | 26.5 / 32.4 | 23.4 / 31.5 |
| neos-3381206-awhea | 2.5 → 25 | 4.0 / 3.7 | 4.0 / 4.1 |
| neos-911970 | 2.4 → 25 | 39.3 / 12.1 | 20.4 / 20.8 |
| exp-1-500-5-5 | 1.1 → 18 | 8.6 / 5.7 | 5.0 / 5.5 |
| p200x1188c | 0.7〜1.0 → 11〜16、再スタート後 9〜12 | 3.1 / 3.3 | 2.1 / 3.0 |
| fiber | 0.7 → 11、再スタート後 8 | 0.9 / 0.9 | 0.9 / 0.9 |
| neos17 | 0.73 → 12 | 5.2 / 5.1 | 4.8 / 4.3 |
| qnet1 | 0.47 → 9、再スタート後 8 | 3.1 / 2.9 | 2.7 / 3.8 |

- qnet1 は小さく道に敏感で、種 1〜3 を足しても K 8 (いつも 8) で 2.1 / 1.9 / 4.3 秒、r8h で 1.7 / 2.0 / 2.0 秒とばらつく。r8 (2 種で 1.2 / 1.6) ほどの得は安定しない。
- 群 3 (session_01HrNYnGtTw7QyKEbYQadiGY) から「延ばす向き」の例として受けた mc11・beasleyC3 (`batch3.sh`、種 1 / 種 2):

| 問題 | r | def | cl | r50 |
|---|---|---|---|---|
| mc11 | 0.4〜0.6 (→ 8) | 33.2 / 28.4 | 22.3 / 25.2 | 23.8 / 23.8 |
| beasleyC3 | 0.4〜0.6 (→ 9〜10) | 21.4 / 15.2 | 17.8 / 17.3 | 12.5 / 20.0 |

  どちらも r は小さく (1 ラウンドが軽い)、縮めても延ばしても既定より速い回があって、向きは種の揺れに埋もれる。SCIP が 86〜103 ラウンド・約 5000 本を回して根で
  閉じるのは、1 ラウンドの本数 (当方は最大 50 本) と根の再スタートの組み合わせで、r の大小とは別の軸と見る (この試作では扱わない)。

誤答の確かめ (`fuzz.sh`、要約は `fuzz.txt`): `CUTLEN=1` と、いつも 8 に縮める `CUTLEN=1 R0=100` の 2 組 × fuzz_tiny 400・mip_fuzz_vs_highs 300・
fuzz_objint 1000・fuzz_slack 1000、**bad / mismatch 0**。`cargo test --release --lib` は既定・`CUTLEN=1` とも 419 passed、0 failed。
