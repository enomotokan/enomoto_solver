## 2. 良い値の seed (81) を別の方法で確かめた

- 2 値の全列挙 (2^7 点) と連続列を 1e9 倍した LP: 厳密な最適値 −10.95、許容誤差 1e-6 (2e-9 以上) の最適値 −37.53 (ENOMOTO の値)。
- ENOMOTO の解: 行 `Σx + Σy ≤ 1 − 2e-9` を Σx = 1 で 2e-9 破る。HiGHS (既定) に全列を固定して与えると `Optimal −37.53`、つまり HiGHS は
  自分の許容誤差でこの解を受け付けるのに、自由に解くと −30.36 (その解は 4e-9 破る) を最適と答える。
- HiGHS を厳しくする (1e-10、前処理なし) と −10.95 (厳密な最適値) になる。HiGHS の答え −30.36 はどの許容誤差の最適値でもない。
- 判定: 1e-6 の約束では ENOMOTO が正しく HiGHS が誤り。148・260・324・350 も同じ形。

## 3. 後処理の修復の下界 (試作 `ENOMOTO_MIP_FZ3_REPAIR_BOUND=1`)

### 3.1 何をしたか (src/mip/mod.rs)

- `solve_problem_inner` の修復の後: 既定は `r.best_bound += z(xn) − z_pre(xr)` (xn は直した解)。試作では
  `r.best_bound += p.objective(x) − prob.objective(xr)` (x は後処理した直す前の解。前処理後の問題と元の問題の目的値の定数の差だけを
  足す。実行可能な場合の枝と同じ式) にし、さらに `best_bound = min(best_bound, z(xn))` (直した解は実行可能なので最適値はその値以下)。
- ログ (`ENOMOTO_MIP_LOG`) に `MIP: postsolve repair: bound shift ... (at the postsolved point ..., at the repaired point ...)` を
  出す (既定でも出す。値は変えない)。
- `repair_postsolved` の LP の期限: 試作では `Duration::try_from_secs_f64` と `checked_add` で、時間の上限なしなら期限なしにする
  (既定は panic のまま。既定の動きは変えない約束のため)。

### 3.2 確かめたこと

- `cargo test --release --lib`: 333 件通る (18 件 ignored)。
- `fuzz_tiny.py 400 0`: 既定 13/400、試作 13/400 で同じ seed・値 (`fuzz_tiny_400_default.txt`・`fuzz_tiny_400_fz3.txt`)。fuzz_tiny では
  修復は一度も起きない (`ENOMOTO_MIP_LOG=1` で `postsolve repair` 0 行)。`scripts/mip_fuzz_vs_highs.py 300` も 0 行 (食い違い 0)。
- `fuzz_mixtiny.py 300` (`mixtiny_scan.py`、panic でも止めない): 既定は seed 58・189・230 が panic、204 が以前からの差 (0.2016604 対
  0.2016557)。試作では 3 件とも解ける (`repair_seeds.txt`):

### 3.3 下界が最適値を越える例

- 作れなかった (事実)。fuzz_tiny・mip_fuzz_vs_highs では修復が起きず、fuzz_mixtiny の 3 件は木が閉じて下界が解の値に置き換わる。
  修復が起きる小さな問題を作る生成 `fuzz_repair.py` (小さい係数の連続列を代入で消させる) も 300 問で修復 0 回だった。
- 越えるには (式の読み): (1) 時間切れ (状態が最適だと一番上で下界は解の値になる)、(2) 木の下界が最適値から Δ 以内、(3) 修復で目的値が
  Δ より大きく上がる、(4) 一番上の `min(下界, 解の値)` で消えない (= 返す解が下界より悪い) が重なること。uccase12 の修復の Δ は 1e-3 程度
  (記録の 560 秒の回で 11507.40374 → 11507.40644、下界は 2.7e-3 上がる) で、下界と最適値の間 (0.035) よりずっと小さく、今の時間では起きない。
- 状態が最適のときは下界は問題にならないが、別の問題がある: 木が閉じたときの直した解は最適とは限らない (直す前の解だけが最適で、
  直すと値が上がる) のに「最適」と答える (`analysis/uccase12_mem3_20261103.md` §0 の「誤答の芽」と同じ)。試作はこれを直さない。
