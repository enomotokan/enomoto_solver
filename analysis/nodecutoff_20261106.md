# ノードの LP の打ち切り値による途中停止の効き目と、共有の最良値の読み直しの試作 (2026-11-06)

bench に使う環境変数: `ENOMOTO_MIP_THREADS=4` (全部の回)、計数の回は `ENOMOTO_MIP_NODECUT_STAT=1`、試作の回は `ENOMOTO_MIP_NODECUT_LIVE=1`
(読み直しの間隔 `ENOMOTO_T_MIP_NODECUT_LIVE_EVERY`、既定 32 反復)。害の比べ (plain / plainlive) は `STAT` なし。

生データ: `analysis/nodecutoff_20261106/` (`run1.py` 1 回の計測、`run58.py` 58 問、`summ.py` 表、`stat_table.md` 計数の表)。

## 今の仕組み (コードで確かめたこと)

- `src/simplex/slope_intercept_dual.rs` の `ext_check`: 段階 B で 8 反復ごと (と進みの判定で下界を計算した回) に、今の基底の双対から
  下界 (`lower_bound_from_basis`。近道では基底解の目的値) を求めて `ExtControl::cutoff` と比べ、越えたら `ExtStop::ObjectiveBound` で止める。
  段階 A では比べない。
- 打ち切り値は `Solver::limits()` → `prune_limit()` (自分と共有の暫定解の良い方、刻み `obj_step`、ギャップ、根のサブ MIP の外側の上限)。
  `SolveLimits` は LP を解き始める前に作り、解いている間は変わらない。
- `lower_bound_from_basis` は、境界が無限の列の被約費用の符号が逆 (|d| > 1e-9 (1 + max|y|)) だと -inf を返す (比べられない)。
- ノードの LP が最適で終わると、`node_obj >= prune_limit()` (その時点の値で読み直す) で刈る (`solver.rs` のノードのループ)。

## 足したもの (既定の動きは変えない)

- 診断 `ENOMOTO_MIP_NODECUT_STAT=1`: `limits_k(反復, 種類)` (種類: ノードの LP / 強分枝の子 / 潜り・丸めなどのヒューリスティクスの LP) で
  打ち切り値を読み直す関数 (`Solver::nodecut_fn`、`prune_limit` と同じ式 `prune_limit_of` で、共有の最良値と外側の上限だけを読み直す) を
  スレッドローカルに置き、`TsLp::solve_inner` が打ち切り値がビット単位で同じ求解だけで使う。双対単体法は 32 反復ごとに読み直した値を
  記録だけし (下げない)、段階 B の比べの回に、読み直した値を越えた最初の反復も記録する。終わりに `MIP: nodecut <種類>: ...` を出す。
  数えるもの: ObjectiveBound で止まった回数・反復、最適で終わって出発の打ち切り値以上だった回数・反復 (途中で止められたはずの分の上限)、
  そのうち段階 B に入らなかった回数、最後の下界が -inf だった回数、-inf の列を飛ばした値 (正しい下界ではない) なら越えていた反復の見積もり、
  最適で終わって出発の値未満・終わりに読み直した値以上 (読み直していれば刈れた) 回数・反復・途中で止められた反復の見積もり。
- 試作 `ENOMOTO_MIP_NODECUT_LIVE=1`: 上と同じ口で、読み直した値が今の打ち切り値より小さければ `ExtControl::cutoff` を下げる
  (木の従のスレッドの LP でも同じ。読み出しは `Portfolio::best()` のアトミック 1 個 + 根のサブ MIP のとき 1 個、32 反復に 1 回)。
  刻み・ギャップは `prune_limit` と同じ式。自分の暫定解は LP を解いている間に変わらないので出発のときの値を使う。

強分枝の子・潜りの LP も同じ傾向 (解いてから刈る LP は全体の反復の 0〜1.7%、ほとんど 10 反復未満の短い LP)。

読み取り (推測を含む):
- 打ち切り値で途中で止める仕組みは働いている (neos-1445765 でノードの LP の反復の 9%、neos-911970 で 21%、mzzv42z で 19% が止まった LP の分)。
- 最適まで解いてから刈った LP は少なく、ほとんどは 8 反復の間隔の中で越えた短い LP (neos-911970 の追跡 `ENOMOTO_MIP_NODECUT_TRACE=1` で、
  多くは 4〜13 反復、最後に比べたのは 0 か 8 反復目)。省ける反復は 1 回あたり数反復 (事実: 間隔 8 より短い)。
- 段階 A のまま越えていた LP は、どの問題でも 0 (warm start のノードの LP は段階 B から始まる)。
- 共有の最良値を読み直していれば刈れた LP はどの問題でも 0〜3 回 (省ける反復の見積もり 0〜222)。解いている間にほかのスレッドが良い解を
  見つける回数自体が少なく (読み直した値が下がった LP は 0〜15 回)、下がっても双対の目的値が新しい打ち切り値を越えるのは最後の方。
- neos-911970 では長い LP (数百〜千反復) で下界が -inf になり比べられないものがあった (境界が無限の列の被約費用の符号が逆。費用のずらしの
  せいと推測)。ただし -inf の列を飛ばした値 (上から見た見積もり) でも越えたのは終わり近くで、省ける反復は 1641 / 47.5 万 (0.3%)。
  その回の最適値は多くが暫定解と同じ値 (54.76) で、双対の目的値が打ち切り値 (暫定解 - 5e-8) を越えるのは最適の直前。
