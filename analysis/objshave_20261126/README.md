# 目的の下界を LP 以外で押し上げる部品 (CP-SAT の objective shaving・core) の調べと試作 (2026-11-26、親の依頼)

## 0. 資料 (CP-SAT、ソースのコメントから。論文 Perron・Didier・Gay CP 2023 は取得できず)

- objective shaving (`use_objective_shaving_search`、既定は切) は専用のワーカーとして動く。
  - 目的の値を固定したモデルを作り直し (仮定で目的を縛るのではない)、前処理あり・probing なしで解く。
  - 1 回の試しの予算は `shaving_search_deterministic_time` (0.1)。
  - δ の決め方と、実行不能のときの処理は、読めた範囲では確認できなかった。
- lb_tree_search: 下界を上げるためだけの MIP 型の木 (開いたノードの全一覧)。
  - 矛盾した枝の下界を無限大にし、親へ伝える。木の半分超が共有の下界より下なら木を捨てる。
- core (`CoreBasedOptimizer`): 目的の項を仮定に置いて core を取り出す。
  - core の中の最小の重みだけ下界を上げる。core は伝播で最小化する。
  - 重みは 90% 分位で層に分ける (stratification)。
  - 「目的の項が多いときだけ効く」とコメントにある。

## 1. 候補の問題 (`objform.py`・`objform.jsonl`・`pick.py`・`pick.txt`)

- 元にしたのは analysis/gap240_20261126/gap.json (combo2 第 2 段の既定、600 秒)。
  - 記録にあるのは根の下界と最後の下界だけで、途中の推移は無い。
  - 既知の最適値は scripts/miplib2017-v31.solu から取った。
- 既定 t4 で時間切れは 132 問。
  - 解が既知の最適値と同じで、下界だけが残るのは 22 問。そのうち、根から最適までの差を木で 2 割も縮められないのは 11 問。
- 目的が整数値を取り、0-1 の項が 8 割以上の時間切れは 27 問。
  - 下界から最適値までが数段 (gcd 単位) なのに、下界が根からほとんど動かない問題が多い。
  - 例: chromaticindex1024-7 は 1 段、nexp-150-20-8-5 は 1 段、supportcase10 は 3 段、glass-sc は 4 段、square41 は 5 段、lectsched-5-obj は 9 段。

## 2. shaving の効きの見積り (`shavetest.py`・`shavetest.jsonl`)

- 手順: 候補 18 問に「目的 ≤ L」の行を足し、当方 (4 スレッド・種 1・120 秒、HEAD 808d6c570) で解く。
  - L は既定 t4 の 600 秒後の下界。最適値は L より大きいので、答えは実行不能になる。
  - 実行不能を示せれば、下界を L + gcd に上げられる。

- 時間切れの 13 問: chromaticindex1024-7・neos-5052403-cygnet・nexp-150-20-8-5・supportcase10・sorrell3・neos-1354092・square41・netdiversion・satellites2-40・satellites2-60-fs・seymour・cvs16r128-89・comp21-2idx。
- 見立て:
  - 「目的 ≤ L」の行は、値 L + gcd の解を持っているときの打ち切りと同じ働きをする。
    - 子の刈り、目的の伝播 (OBJ_PROP)、打ち切りつきの probing が、楽観的な打ち切り値で効く。
  - 4 問は、既定が 600 秒で超えられなかった下界を、1〜2 分で 1 段上げられた。ただし 1 回の証明で上がるのは 1 段だけ。
    - net12 は 118 段のうちの 1 段。glass-sc は 4 段のうちの 1 段。
  - 残りの 13 問は、行を足した問題も 120 秒では閉じない。下界の側が本当に難しい。
  - 伝播と衝突だけ (LP なし) の shaving では、これ以上は見込みにくい (推測)。
    CP-SAT そのもので比べたかったが、ortools の導入は権限で止められた。
