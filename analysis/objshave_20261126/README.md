# 目的の下界を LP 以外で押し上げる部品 (CP-SAT の objective shaving・core) の調べと試作 (2026-11-26、親の依頼)

## 0. 資料 (CP-SAT、ソースのコメントから。論文 Perron・Didier・Gay CP 2023 は取得できず)

- objective shaving (`use_objective_shaving_search`、既定は切) は専用のワーカーとして動く。
  - 目的の値を固定したモデルを作り直し (仮定で目的を縛るのではない)、前処理あり・probing なしで解く。
  - 1 回の試しの予算は `shaving_search_deterministic_time` (0.1)。
  - δ の決め方と、実行不能のときの処理は、読めた範囲では確認できなかった。
- lb_tree_search: 下界を上げるためだけの MIP 型の木 (開いたノードの全一覧)。
  - 矛盾した枝の下界を無限大にし、親へ伝える。木の半分超が共有の下界より下なら木を捨てる。
- core (`CoreBasedOptimizer`): 目的の項を仮定に置いて core を取り出す。
  - core の中の最小の重みだけ下界を上げる。core は伝播で最小化する。
  - 重みは 90% 分位で層に分ける (stratification)。
  - 「目的の項が多いときだけ効く」とコメントにある。

## 3. 試作 `ENOMOTO_MIP_OBJSHAVE` (既定オフ、src/mip/solver.rs の `spawn_objshave`・`objshave_loop`)

- 形: 木を分け合う並列 (2 スレッド以上) の主が、木に入るところで下界の専任スレッドを 1 本起こし、木のスレッドを 1 本減らす。
  - 対象は、目的が整数の刻みを取る問題だけ (`MipProblem::objective_step`)。連続の目的では、δ の単位を新しい閾値なしに決められないため。
- 専任スレッドの手順:
  - 主の根の写し (`TreeSnapshot`、根のカット・大域の境界・擬似費用) を、打ち切り値 C = off + (m0 + k − ½)·刻み で解く (`solve_snapshot`)。
    off + m0·刻み は、今の下界を格子に切り上げた点。
  - 実行不能 (または C 未満の解なしで最適) なら「C 未満の解はない」ので、下界を off + (m0 + k)·刻み に上げ、k を 2 倍にする。
  - 時間切れなら k を半分にする。k = 1 なら、1 回の時間を 2 倍にする。
  - 1 回の時間の最初の値は、解探索のスレッドと同じ配分 (残りの 0.3 倍、20 秒まで)。新しい閾値は作っていない。
  - 今の下界には、自分が示した値・主が知らせる下界 (`Portfolio::publish_lb`)・木に入るときの下界の最大を使う。
- 主への受け渡し:
  - 示した値は原子変数で主に渡す。主は既存の `bisect_lb` (目的値の二分探索と同じ置き場) に入れる。
  - `bisect_lb` が打ち切りの値に届けば最適として閉じ、時間切れのときは下界の報告に入れる。
- 正しさの扱い (誤りが許されない所):
  - 写しの求解は、主と何も共有しない独立の求解 (共有の待ち行列・Portfolio なし)。打ち切り値 C から導いたカット・衝突・固定は、その求解の中だけに残り、主には戻らない。主に戻すのは値だけ。
  - C は写しの `valid_below` (写しの大域の固定が成り立つ範囲 = 写しを作ったときの主の打ち切りの値) を超えない。
    双対の縮小・対称性による固定は最適解を 1 つ残すので、「C 未満の解の集合が空か」の判定を崩さない。
  - 作りの途中で見つけた誤り (直した):
    - 写しを「ノードなし」で作ると、写しの求解は根の代わりに写しのノードだけを探索するので、待ち行列が空のまま、すぐ「実行不能」を返した。
    - net12 で 0 ノード・3 秒で下界 213 を「示した」(最適値 214 と矛盾しなかったのは、C を valid_below の下に抑えていたための偶然)。
    - 今は、変更なしの根のノード 1 つ (写しの大域の境界の全体) を入れる。
  - 写しの求解は相対ギャップ 0 で解く。暫定解 z が C の少し上にあると、相対ギャップの分だけ C より下で刈りうるため
    (|z| が刻みの 5000 倍を超える問題で起こりうる)。
  - 示した値を取るのは、探索を終えた求解からだけ。時間切れ・止めた求解の下界は使わない。
  - LP の途中の打ち切りの合図 (`with_halt`) は使わず、止めるのはノードの区切りだけ (`FIND_STOP`)。中断した LP を実行不能と取り違えないため。
  - 並列の木の終わりで、従の下界との min を取るときに `bisect_lb` を落としていた。そこに `bisect_lb` を足した
    (試作を使わなければ `bisect_lb` は -inf なので、既定は変わらない)。
- fuzz 7 本 (`fuzz.sh`、`fuzz.out`、4 スレッド・OBJSHAVE=1): どれも誤答 0。
  - fuzz_tiny 0/400・0/400、fuzz_highs 0/300、fuzz_objint 0/1000・0/1000、fuzz_slack 食い違い 0 (1000・1000 回)。
  - 小さい問題は根で解けることが多く、専任スレッドが実際に動いた数は数えていない。
- cargo test は、取り込んだ後の版で 425 件通過。

## 4. 24 問の下界の推移 (`run.py`・`res.jsonl`・`summ.py`・`summ.txt`、4 スレッド・種 1・300 秒、同じビルド)

- 対象: 2 節の 4 問と、「解は最適で下界だけが残る」22 問 (重なり 2) の計 24 問。
  - 600 秒では 8 時間かかるので 300 秒にした。
  - 試作が働かない問題 (目的が整数の刻みを取らない) は既定と同じ設定なので、既定は回していない。
- 試作が働いたのは 8 問。下界の積分 (dual integral、g(t) = (最適 − 下界) / max(|最適|, |下界|, 1) の時間の積分、秒) で比べた:

| 問題 | 下界: 既定 → shave | 積分: 既定 → shave | 証明の回数 |

| lectsched-5-obj | 15 → 16 | 136.5 → 108.5 | 1 |
| net12 | 90 → 92 | 221.4 → 209.0 | 2 |
| glass-sc | 18 → 18 | 107.3 → 95.7 | 2 |

- 積分の比 (shave / 既定、幾何平均) は 0.925。良くなったのは 4 問、悪くなったのは 1 問 (n3div36)。
  - n3div36 は最後の下界は上がったが、途中は木のスレッドが 1 本少ない分だけ遅れた。

## 6. まとめ (2026-11-26)

- 効くのは、目的が整数の刻みを取り、下界が LP の側で止まっている問題の一部だけ。下界の積分は 8 問で 0.925 倍。
- 1 回の証明で上がるのは 1 段で、時間切れの問題が解けるようにはならない。
- P の害は小さい (−0.9% [−9.7%, +6.4%]) が、解けた数が 1 対減った (mzzv42z の種 3)。採用基準の「解けた数を減らさない」は満たしていない。
- 伝播と衝突の学習だけの CP-SAT 型 (LP なし) は作っていない。2 節の見積りの通り、効いている中身は打ち切り値による LP の刈りと被約費用の固定。

## 7. 結論 (2026-11-26、利用者の判断: 試作のまま残して区切る)

- コードは既定オフのまま残す (`ENOMOTO_MIP_OBJSHAVE=1` で使う)。
- 効いた問題 (4 スレッド・300 秒):
  - lectsched-5-obj (下界 15 → 16)、net12 (90 → 92)、glass-sc (同じ 18 に早く着く)、seymour (412 → 413)。
  - n3div36 は最後の下界が 124400 → 125400 に上がったが、下界の積分は悪くなった。
- 効いた中身: 伝播と衝突の学習ではない。楽観的な打ち切り値 C による LP の刈りと、被約費用による固定 (根と木のノードで C を使う) が効いている。
  2 節の見積り (「目的 ≤ L」の行を足した問題で、刈りが値 L+1 の解を持つときと同じに効く) と同じ。
- 続ける場合の 2 案:
  1. 下界の専任スレッドを、木が止まりかけた問題 (下界の伸びが止まり、間隙が残る) にだけ回す。働く問題を絞り、木のスレッドを 1 本減らす害を避ける。
  2. 専任スレッドが C 未満で見つけた解を主に渡す (今は捨てている)。写しの問題は主と同じ空間なので、解探索のスレッドの受け渡し (`FIND_OUT`) が使える見込み。
