# neos-960392 の時間切れ (2026-10-23)

環境: 4 CPU のクラウドのコンテナ (`nproc` = 4、ソルバーは同時に 1 本)、土台は inv/heur-ls-20261023 の 7f0d7c3、
作業ブランチ inv/neos960392-20261023。4 スレッド・60 秒。HiGHS 1.15.1 (4 スレッド、mip_rel_gap 0)。
ログは `analysis/heur_ls_20261023/logs/neos-960392_e_*.log` (ENOMOTO) と `analysis/neos960392_20261023/highs_*.log` (HiGHS)。
HiGHS の台本は `analysis/neos960392_20261023/run_highs.py`。

## 結論

- **原因 (事実)**: 前処理の最後の「LP による固定」([`lp_probe`]、`src/mip/mod.rs`) の最初の LP には期限
  `ENOMOTO_T_MIP_LP_PROBE_TIME_FRAC` × 時間上限 = 0.05 × 60 = **3.0 秒**がある。neos-960392 のこの LP は **2.8〜3.0 秒**かかるので、
  間に合うかどうかが回ごとに変わる。
  - 間に合った回 (経路 A): 基底が根の LP に渡り (`ROOT_BASIS`、最初の LP が 1 秒以上なので固定 0 でも渡す)、根の LP は 7447 反復の頂点に着く。
    根の暫定解なし用の RENS (`fj_poor_bg_rens`、11586 列のサブ MIP) が **0 ノード・5〜6 秒で −238 (最適値)** を出し、28〜32 秒で最適を証明する。
  - 間に合わなかった回 (経路 B): LP は `TimeLimit` で終わり、基底を渡さない。根で同じ LP を一から解き直し (約 2.9 秒の損)、
    7184 反復の**別の頂点**に着く。そこからの RENS (11471 列) は **189 ノード・13.5 秒で時間切れ、−237 止まり**。
    根の RINS (513 列) は 0 ノードで時間切れ。木の根の強分枝 (102 LP) に 18 秒かかり、残り 9 秒で 1 ノードのまま時間切れ。
- 依頼文の推測 (「良い最初の解が出ると質の悪い解と判定されず RENS が回らない」) は、この機械の 26 回では**当てはまらなかった**:
  最初の暫定解は既定で FJ の −2、mixoc で Local-MIP の −35 で、どの回も「質の悪い FJ の解」と判定されて RENS が回っている。
  時間切れを分けているのは RENS が回るかどうかではなく、**RENS の出発点の LP の頂点** (経路 A/B)。mixoc かどうかとは関係しない。
- **手当て**: `ENOMOTO_MIP_LP_PROBE_FIRST_FULL=1` (既定では使わない)。`lp_probe` の最初の LP の期限だけを
  `ENOMOTO_T_MIP_LP_PROBE_FIRST_MULT` (既定 4) 倍に延ばす (固定を試す手間の上限は今までどおり 3 秒)。
  どのみち根で解く LP なので、延ばしても時間は失わない (間に合わない回の解き直しの分だけ得をする)。
  合わせて、最初の LP が間に合わなかったときにログに `MIP: LP probing: the first LP ended ...; the root LP is solved again` を出す
  (`ENOMOTO_MIP_LOG=1` のとき。既定の動作は変えない)。
- **効果** (neos-960392、4 スレッド・60 秒):

| 設定 | 回数 | 最適を証明 | 時間切れ | 経路 B (最初の LP が間に合わない) | 時間 (解けた回) |
|---|---|---|---|---|---|
| 既定 | 6 | 4 | **2** (−237・−237) | 2 | 28.5・29.6・30.6・31.9 |
| 既定 + FIRST_FULL | 3 | **3** | 0 | 0 | 29.0・29.3・29.4 |
| mixoc | 6 | 5 | **1** (−237) | 1 | 28.5・28.8・28.8・29.8・31.8 |
| mixoc + FIRST_FULL | 3 | **3** | 0 | 0 | 28.4・28.5・29.9 |

  経路 B を確実に起こす (`ENOMOTO_T_MIP_LP_PROBE_TIME_FRAC=0.04` = 2.4 秒) と、2 回ずつで:

| 設定 | 結果 |
|---|---|
| 既定 + FRAC 0.04 | −237 時間切れ / −237 時間切れ (どちらも経路 B) |
| 既定 + FRAC 0.04 + FIRST_FULL | 30.6 秒 / 38.9 秒で最適 (経路 A) |
| mixoc + FRAC 0.04 | −237 時間切れ / −237 時間切れ (経路 B) |
| mixoc + FRAC 0.04 + FIRST_FULL | 29.0 秒 / 29.5 秒で最適 (経路 A) |

  経路 B の回はすべて時間切れ (6/6)、経路 A の回はすべて 60 秒以内に最適 (20/20)。
- 目的値の不一致はなし (どの回も「最適」は −238)。
- `cargo test --release --lib`: 313 件通過、18 件無視。

## 1. 時間切れの回の内訳 (事実、`neos-960392_e_def_3.log`。経路 A は `e_def_1.log`)

時刻はソルバーの時計 (前処理の後から。前処理は約 6.2 秒)。

| | 経路 A (e_def_1) | 経路 B (e_def_3) |

## 3. 推測

- 経路 B の頂点から RENS が −238 を出せないのは、固定率 0.8 で残る 11471 列の近傍に −238 の解がない (または 13.5 秒で見つからない)
  ためと見られる (未確認)。どちらの頂点が良いかはこの問題に限った運で、FIRST_FULL が一般に良い頂点を選ぶわけではない。
  FIRST_FULL の一般的な利点は「最初の LP が期限に間に合わない問題で、根の LP を 2 回解かない」こと。
- 同じ形 (前処理の最初の LP が 3 秒の期限で打ち切られ、根で解き直す) は physiciansched6-2 にもある
  (前処理の LP が 3.00 秒で期限切れになり、根の LP を解き直す)。ただし下の確認では、根の LP までの時刻は浮かなかった。
- mzzv42z・uccase12 は最初の LP が 3 秒より速いので変わらない見込み。

## 4. 副作用の確認 (physiciansched6-2、2 回ずつ)

| 設定 | 1 回目 | 2 回目 | 前処理の最初の LP |
|---|---|---|---|
| 既定 | 51029 (61.9 秒) | 51029 (60.9 秒) | 2 回とも 3.00 秒で期限切れ (新しいログ行で確認) |
| 既定 + FIRST_FULL | 51029 (60.8 秒) | 解なし (60.5 秒) | 3.5 秒前後で最適、基底を渡す |
| mixoc | 50725 (61.6 秒) | 50826 (62.3 秒) | 2 回とも期限切れ |
| mixoc + FIRST_FULL | 50725 (60.5 秒) | 51029 (61.6 秒) | 最適、基底を渡す |

- 事実: FIRST_FULL で前処理の最初の LP は期限切れにならなくなるが、根の LP までの時刻はほぼ同じ
  (既定: 前処理 3.86 秒 + 根の LP 5.87 秒、FIRST_FULL: 4.38 秒 + 5.20 秒。根の LP は渡した基底からでも 5 秒前後かかる。
  前処理の LP はプロービング・クリークの前の問題なので、基底がそのままは合わないと見られる (推測))。
- 最終の値は 2 回とも同じ向きの差がない (FIRST_FULL の 1 回の「解なし」は、既定でも多い解なしの回と同じ揺れの範囲と見る)。
  つまり physiciansched6-2 では良くも悪くもならない (2 回ずつでは差が見えない)。超過 (60.5〜62.3 秒) は依頼 A の対象。

## 5. 既定にする候補か

- 候補になる。変えるのは「前処理の最初の LP が 0.05 × 時間上限に間に合わない問題」だけで、その問題では根で同じ LP を解き直す時間が浮く。
  neos-960392 では時間切れ (既定 2/6・mixoc 1/6) が 0/3・0/3 になり、経路 B を強制しても 4/4 で最適。physiciansched6-2 は変わらない。
  ただし根の頂点が変わるので、経路が変わる問題の良し悪しは揺れ次第 (頂点の良し悪しは運)。既定にするかは親の 40 問 + 16 問で判断する。
- 40 問 + 16 問のうち、この切り替えで動くのは「前処理の最初の LP が 3 秒を超える問題」だけ。既存のログで当たるのは neos-960392
  (2.8〜3.0 秒、境目) と physiciansched6-2 (3 秒超) の 2 問。ほかの問題は最初の LP が 3 秒より速く、動作は同じ (推測。全部は確かめていない)。
