## 測り方 (run.py・plan.json → res.jsonl、集計 summ.py → summ.txt)

## 並列にする案と見積り (アムダール、4T の根 256 秒・全体 668 秒に対して)

1. **分離の並列 (`ENOMOTO_MIP_SEP_PARALLEL`、既にある試作)**: cut は 4T の根の 38% (97 秒)。1 ラウンドの時間の大半は分離
   (h80x6320d で 1 ラウンド 0.35 秒のうち分離 0.30 秒)。候補は逐次と同じ順につなぐので決定的。仮に分離の半分が並列になって 2 倍速くなれば
   cut は 97 → 約 70 秒、根 −10%、全体 −4%。**作らずに測れるので最初に試す**。
2. **RINS (と残りの根のヒューリスティクス) を空いているスレッドで並走**: RENS と同じ並列のサブ MIP の形で RINS を出し、決まった所 (木に入る前など)
   で待って結果を受け取る。heur の 4T 86 秒のうち RINS 43 秒が隠れれば根 −17%、全体 −6%。決定性: サブ MIP は 1 スレッド・手間の上限で
   決定的にし、受け取る所を固定すれば 4 スレッドの再現も保てる (時間で打ち切る形 (TIMEDEP) は避ける)。1 スレッドの動きは変えない。
3. **プロービングの並列**: pre は 22% (56 秒)、その多くがプロービングと含意の同値の検出。2 値の列を塊に分けて並列に調べ、固定・含意を決まった順に
   合わせる。固定が次の列の調べに効く (逐次の依存) ので、塊ごとの結果を合わせ直す手間がかかる。得は大きくて pre の半分 (根 −11%)。作るのは重い。
4. **裏のカットの待ち (post 11 秒、根の 4%)**: 待つ所を木の最初の数ノードの後にずらす、などで隠せる。小さい。

まとめ: 4 スレッドの根では約 2 本が空いている。主のスレッドで逐次に動いているのは、カットのループ (分離の一部・LP の解き直し)・RINS・
プロービング。試作は 1 → 2 → 3 の順を提案 (1 は計測だけ、2 は RENS の並列の形を写せる、3 は作りが重い)。

## 3. プロービングの並列化 (2026-11-23、利用者の判断)

### 今の作り (src/mip/mod.rs の `probe`)

- 0-1 列の候補を順に、x_j = 0・1 で伝播 (`Domain::propagate`) して比べる。片側が矛盾すれば固定し (定義域が変わる)、両側が成り立てば
  含意 (衝突の組)・含意による境界・同値な組・両側で締まる境界を集める。固定・締め付けは後の候補の伝播に効く (逐次の依存)。
- **既に並列 (既定)**: `ENOMOTO_MIP_PREPAR` は既定 `ple` (コメントの「既定では使わない」は古い)。`p` は投機的な窓: 先の候補の窓
  (4 つの塊、塊の大きさは使われ方で 2〜32 に増減) を、窓を作った時点の定義域の写しで塊ごとにほかのスレッドで試す。定義域が変われば
  (`ver`、固定・締め付け) 窓の残りを捨てて作り直す。窓・塊の大きさは数えた量だけで決まるので、結果はスレッドの数・順序によらず逐次と同じ。
  `e` は同値な組の巡、`l` は LP による固定の試しを並べる。
- **並列にならない所**: (1) 窓の外の主のスレッドの処理 (結果の取り込み・含意の表・同値な組・終わりの集計)、(2) 含意を伝播に使う形
  (`want_pclique`: `ENOMOTO_MIP_CLQPRB` の `g` で 2 回目に含意を使う形でやり直すとき、`ENOMOTO_MIP_PROBE_CLIQUE`・`GAP4` の `q`・`PRB_TABLE`)
  では、試すたびに含意を定義域に足す (`add_implications`) ので窓を使わない (`par` の条件の `!want_pclique`)。
- mzzv42z (4 スレッド、種 1) の前処理では、プロービングが 6 回 (2.0・3.6〜4.2・1.1・0.7 秒、再スタートの後に 1.2・0.6 秒)。窓を使うのは
  最初の 1 回だけ (544 窓、11941 回のうち 11077 回が窓から)。最初の回でも、窓の秒は 1 スレッド 1.39 秒 → 4 スレッド 0.78 秒 (1.8 倍) で、
  窓の外が 0.8〜1.3 秒残る (全体 2.21 → 2.04 秒)。2 回目 (含意を使う形、3.6〜4.2 秒) が一番重く、これは逐次。

### 設計と試作 `ENOMOTO_MIP_PROBE_PAR` (既定オフ)

- 含意を使う形でも窓を使う。塊は窓を作った時点の定義域 (含意の表を含む) の写しで試すので、同じ窓の前の候補が足した含意は使わない
  (逐次より弱いことがあるが、含意はどれも大域的に成り立つので正しい)。取り込みでは逐次の道と同じく含意を詰め、定義域に足す。
  窓・塊の大きさは数えた量だけで決まるので、結果はスレッドの数・順序によらない (4 スレッドでも同じ種で同じ結果)。
- 1 スレッドの動きは変えない (`par_threads > 1` のときだけ。1 スレッドでも窓は使うが、含意を使う形の窓は 2 スレッド以上だけ)。
  `PRB_TABLE` の `a` とは使わない。
- mzzv42z 種 1 (4 スレッド) で: 2 回目のプロービングが窓を使うようになった (1035 窓、20707 回のうち 18179 回) が、**4.00 → 6.76 秒と遅くなった**。
  窓に入れた候補は 34753 回で、使われたのは 18179 回 (約半分が固定で捨てられた)。固定が多い (926) ので窓がすぐ崩れ、塊が 2〜8 候補と小さく、
  1 候補あたりの窓の秒 (0.15 ミリ秒) が逐次の 1 回 (0.19 ミリ秒) とほとんど変わらない。3・4 回目は 1.19 → 0.94・0.75 → 0.79 秒。
