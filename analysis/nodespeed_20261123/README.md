## 1. 1 ノードあたりの時間の内訳 (事実、1 スレッド)

| | 当方 (既定) | SCIP 10.0.2 |
|---|---:|---:|
| 全体 | 63.2 秒 (木の始まりは 2.5 秒) | 10.4 秒 |
| ノード | 10977 | 10500 (3 runs、再始動 2 回) |
| ノードの LP | 6054 回・784088 反復 (**129.5 / LP**) | 6601 回・158444 反復 (**24.1 / LP**) |
| LP の時間 | **55.2 秒** (1 反復 70 µs、約 1.4 万反復 / 秒) | 3.6 秒 (約 4.4 万反復 / 秒) |
| ノードの LP の行 | **平均 1759 行** (元 510 行、終わり 1857) | 約 570 行 (ログの rows 欄) |
| 伝播 (カットプール) | 1.47 秒 | 0.06 秒 |
| 衝突解析 | 0.18 秒 | — |
| 双対証明 | 48 本 (ほぼ使われない) | — |
| ノードの分離 | 0.49 秒 | 0.79 秒 (aggregation) |

- 木の時間 (約 60 秒) のほぼ全部がノードの LP。伝播・衝突・双対証明・分離・ヒューリスティクスは合わせて数秒。
- LP が重いのは、行が SCIP の約 3 倍あり、1 回の反復も 1 LP の反復も多いため。取り出したノードの最初の LP は 195 反復 / LP (2137 回)、
  それ以外も 94.8 反復 / LP。
- 行が増える仕組み: 根の終わりの LP は 773 行。木では、待ち行列から取り出したノードごとにプールの破られたカットを 10 本ずつ戻す
  (`pool_cut_round`)。外すのは年齢 (効いていない LP の回数) が上限を超えたときだけで、上限は元の行の数の半分 (232) で、20 ノードごと。
  そのため別の部分木で戻したカットが LP に溜まり、上限 m + 2000 近くまで膨らむ。
- SCIP は木の中で加えた行を、加えたノードの部分木の LP にだけ置き、別の部分木へ移るときに外す。そのため LP は根の行 + 今の道筋の分にとどまる。
- 既存の切り替えで確かめた (事実):
  - プールから戻さない (`ENOMOTO_MIP_NO_POOL_CUTS=1`): 24.2 秒・平均 1045 行・69.4 反復 / LP。
  - 年齢の上限 10 (`ENOMOTO_T_MIP_CUT_AGE_LIMIT=10`): 14.3 秒・742 行・46.9 反復 / LP。
  - どちらも既定にできる形ではない。年齢 10 は binkar10_1 で効くカットまで外れることが記録済み (`remove_aged_cuts` の説明)。

## 2. 試作 `ENOMOTO_MIP_NODE_CLEANUP` (既定では使わない、新しい閾値なし)

`Solver::node_cleanup_rows`。保存した基底を置いた直後に、木の中で LP に加えたカットのうち、置いた基底で基底にある行を LP から外す。
対象は、番号が木の始まり以降のもの (プールから戻したもの・ノードの分離で作ったもの)。基底にある行とは、親の LP で効いていなかったか、保存の後に加わった行。
外したカットはプールに残り、破られればまた戻る。基底の行だけを外すので、置いた基底はそのまま使える。

- 文字:
  - `q`: 待ち行列から取り出したとき。
  - `s`: 兄弟へ戻ったときも。
  - `a`: 行を外したノードでは、プールのラウンドで破られたカットを本数の制限 (既定 10 本) なしに戻す。兄弟・潜りの途中でもこのラウンドを回す。
- 最初に「分枝する前に、このノードで加えて効いていない行を外す」(SCIP の lp/cleanuprows) 形も試したが、外せる行は 0 本で効かなかった。
  加えた時点では全部効いていた (4421 本)。

  1 スレッドでは早めの FJ/Local-MIP は 1.6 秒で止まる。4 スレッドの残りの差はこの 20 秒で、ノードの速さとは別の型 (hang_20261117 の 14 節の rfs30 と同じ所)。

### 2.2 他の問題 (事実、1 スレッド・種 1・120 秒、1 回ずつ。`side_t1.jsonl`)

| 問題 | 既定 | qs | qa | qsa |
|---|---|---|---|---|
| binkar10_1 | 14.1 (3774) | **106.5 (32903)** | 21.2 (3999) | 24.0 (6065) |
| mik-250-20-75-4 | 14.2 (6333) | 22.4 (25137) | 17.0 (5981) | 34.0 (24558) |
| neos-911970 | 23.7 (7981) | **時間切れ** (下界 52.16) | 28.2 (7975) | |
| neos5 | 時間切れ | **91.0 (213373)** | 時間切れ | |
| mas76 | 26.2 | 24.5 | 32.1 | |
| pk1 | 53.1 | 59.0 | 52.3 | |
| misc07 | 5.1 | 5.0 | 5.2 | |
| nw04 (0 ノード、試作は効かない) | 18.8 | 18.9 | 22.1 | |

- 答えはどれも既定と同じ (最適値・実行不能)。nw04 は木がないので、差の 3 秒は揺れの目安になる。
- qs は、外したカットが取り出したノードで 10 本ずつしか戻らない。そのため最適化の問題で木が弱くなる (binkar10_1 はノード 8.7 倍、neos-911970 は時間切れ)。
- qa はノード数が既定並みに戻る。ただし外して戻す出し入れの手間で、binkar10_1 +50%・mas76 +23%・neos-911970 +19%・mik-250 +20%。fhnw-binpack4-4 は −48%。
- 読み (推測): 実行不能の証明 (目的なし) の木では、別の部分木のカットはほぼ効かず、外すほど速い。下界を詰める木では、別の部分木のカットも効いている。
  SCIP のように道筋ごとに行を持つ形でないと、外す・戻すの手間が出る。

## 3. 次 (案)

- P・M の計測 (親がまとめて回す) は、`ENOMOTO_MIP_NODE_CLEANUP=qa` (害の小さい方) と `q` (fhnw-binpack4-4 で最も速い) の 2 つ。
- 本筋の直しは、行を「加えたノードの部分木」に結びつける形 (SCIP の道筋ごとの行)。待ち行列のノードに、親の道筋で加えたカットの番号を持たせる。
  移るときは共通の祖先より下で加えた行だけを外し、新しい道筋の行を戻す。今の年齢の仕組みと保護 (`ENOMOTO_MIP_PROTECT_QUEUE_CUTS`) の作りに手が入る。
- 4 スレッドの早めの FJ/Local-MIP の 20 秒 (実行不能の実行可能性問題で使い切る) は別に扱う。
