# hs_pi0_bgw の得はどの部分から来るか (2026-10-31)

`analysis/halve_submip_20261030.md` の bench6 で hs_pi0_bgw (`ENOMOTO_MIP_SUBMIP_HIGHS=-s ENOMOTO_MIP_SUBMIP_PC_INHERIT=1
ENOMOTO_T_MIP_SUBMIP_RELIABLE=0 ENOMOTO_MIP_BG_CUTS_WAIT=1`) が速くした 5 問 (h80x6320d・qiu・misc07・nu25-pr12・physiciansched6-2) について、
得が hs・pi0・bgw のどこから来るかを切り分けた。損の側の調査 (`diag_hsletters_20261031.md`・`diag_pi0_20261031/`) と合わせて、組み合わせを提案する。

- 機械: 4 CPU。4 スレッド・60 秒、ソルバーは同時に 1 つだけ。`ENOMOTO_MIP_LOG=1`。
- ビルド: 1〜4 節は `fdcae94`。5 節のうち TRIM を使う設定と損の 4 問の全設定は `e85b7ae` (`ENOMOTO_MIP_SUBMIP_HIGHS_TRIM` の試作 `0835251` を含む。既定は同じ)。
- 台本・ログは `diag_gain_20261031/`:
  - `run.py 設定,... 問題,... 回数`: 1 本ずつ回し、`logs/<問題>_<設定>_<回>.log` と `res.jsonl` に書く。設定は名前か `名前=変数=値;変数=値`。
  - `summ.py`: 問題 × 設定の表 (`summ1.txt`〜`summ3.txt`)。`sgm.py`: 得の 5 問・損の 4 問の SGM (`sgm.txt`)。
  - `logstat.py`: ログから、最終の解を最初に出したヒューリスティクスと時刻、根の RINS・LP face のサブ MIP の結果、裏のカットのラウンド数と下界、
    再スタートの回数を抜き出す (`logstat.txt`)。
- 表の数字は秒、T は時間切れ。括弧は解けた回 / 回数。最適値の食い違い・crash はない。

## 2. 仕組み (ログ、`logstat.txt`)

### physiciansched6-2: 最初の根の RINS のサブ MIP が最適解 49324 を出せるか

- どの設定でも、最初の解は Local-MIP で 6〜9 秒 (49424〜51026、回で変わる)。その解で根の RINS のサブ MIP を作る。
- **def・pi0**: RINS のサブ MIP は 3 回とも、ノード 0 のまま 3 秒の上限で時間切れになる (`status TimeLimit, nodes 0, 2.99〜3.07s`)。
  その後、再スタートの後の根では「解がない」ので、ヒューリスティクスの多くを飛ばす。そのまま 49424〜49724 で時間切れになる。
- **hs**: 同じ近傍の RINS のサブ MIP が 0 ノード・1.2〜3 秒で 49324 を出し (`status Optimal, nodes 0`)、そのまま 21 秒前後で証明が終わる。
  - `ENOMOTO_MIP_SUBMIP_VERBOSE=1` (`physiciansched6-2_hsV_0.log`) で中を見た:
    - hs のサブ MIP は根の LP が 49324 で、中の feasibility pump が 0.37 秒で 49324 を見つける。
    - def (`defV`) のサブ MIP は feasibility pump 1.28 秒・fractional diving 1.25 秒で何も出さず、3 秒の上限に当たる。
      ただし defV の回は初めの解が 51026 で近傍が違い、根の LP は 49423.67 だった。
- hs で解けない回 (hs_2・hs_pi0_2・hs_pi0_bgw_1・hs_bgw_0) は、RINS のサブ MIP が 12〜24 秒・100〜270 ノードかけて 49424・49524 止まりで、再スタートに入る。
  hs の `t` (サブ MIP の時間の上限を残り時間にする) で長く走れる分、外れの近傍で時間を使う。
- pi0_bgw の 2 回は別の道で解ける: 再スタートの後の根の feasibility pump が 49324 を出す (39 秒)。

文字の切り分け (各 1 回、`summ2.txt`。`Hx` は `SUBMIP_HIGHS=x` だけ、`Xx` は hs から x を抜いた形 `-sx`):

| | p | c | g | t | i | h | f |
|---|---|---|---|---|---|---|---|
| その文字だけ (Hx) | 38 (再スタート後の FP) | T | T | 50 (RINS 269 ノード・30 秒) | T | T | T |
| hs から抜く (Xx) | 26 | 25 | T (RINS 95 ノード・27 秒) | 21 | 21 | T (RINS 前に解なし) | 26 |

1 文字だけでは RINS の速い解は出ない。抜く側では `p`・`c`・`t`・`i`・`f` は抜いても解ける。`g`・`h` を抜いた回は解けないが、Xh は初めの解がなく RINS が
走っていないので、1 回だけでは `h` が要るとは言えない (初めの解しだいの揺れが大きい)。

### h80x6320d: 最初の根の LP face のサブ MIP の解の質 (`c`)

- 根の LP face のサブ MIP (592 列、ノード上限 77〜81 で止まる) の答えは設定ごとに決まっていて、回で変わらない:

| 設定 | LP face のサブ MIP |
|---|---|
| def・Hg・Ht・Hi・Hf | 6666.09 (77 ノード) |
| pi0・pi0_bgw | 6865.52 (57 ノード) |
| hs_pi0・hs_pi0_bgw | 6392.71 (50 ノード) |
| hs・hs_bgw | **6382.10 = 最適** (20 ノード) |
| Hc | **6382.10** (5 ノードで最適) |
| cgh_bgw | **6382.10** (16 ノードで最適) |

- **`c` (サブ MIP の根のカットを親と同じだけ回す) 1 文字で最適解が出る** (Hc は 28 秒)。良い解が最初の根にあると、
  再スタートで被約費用により 5000 列以上を固定できる (def は 6666 で 813 列)。
- その後の時間 (20〜50 秒の差) は再スタート後の木で決まる。bgw の待ちで下界が上がる (6349〜6350 で再スタート) と速い回が多い。
  - hs_pi0_bgw の速い回は、再スタート後の根で同じ解をわずかに良い値で拾い直し、2 回目の再スタートで 211 列を固定していた。
  - `t` を入れた cght_bgw_r は 50 秒と遅い (diag_hsletters でも、hs から `t` を抜くと 31 → 24 秒)。

### misc07: 裏のカットの待ち (bgw) で根の下界が上がる

- 最適解 2810 はどの設定でも 2〜4.5 秒で木 (他スレッドの木・local branching・randomized rounding) が見つける。差は証明の側。
- bgw なしは、裏のカットが 3〜5 ラウンドで止められ、下界は 1480 → 1488〜1498 (def の 1 回だけ 12 ラウンド・1530 で 17 秒)。
  bgw ありは 14〜67 ラウンド・1529〜1580 まで上がり、7〜11 秒で解ける。サブ MIP の形 (hs・pi0) は関係しない。

### qiu: 木の証明の揺れ

- 最適解 −132.87 は、どの設定でも木の randomized rounding で 9〜20 秒に見つかる。差は証明で、def は回によって下界が −164 で止まり時間切れ。
- hs の形では根の RINS のサブ MIP が `t` で 5〜6 秒走り、根が 9.7 秒まで延びるが、その後の木は 9 回とも 15 秒前後で閉じる。仕組みは特定できていない。
  pi0 を (hs なしで) 入れると 1/3 に落ちる。
- diag_hsletters によると、深さ 2 のサブ MIP も hs の形であることが要る (`TRIM=d` で得が消える) が、`c`・`h`・`t` を抜いても得は残る。
  5 節の cgh_bgw・cgh_bgw_r・cght_bgw_r も 4 回とも 18〜20 秒。

### nu25-pr12: 根の並列サブ MIP の待ち時間

- def では根の「root reduced cost」の並列サブ MIP が 280 ノード・2.95 秒かかり、根がそれを待って 3.7 秒になる (最適解 53905 もこのサブ MIP が出す)。
- pi0 (強分枝なし) ではサブ MIP がノード上限に早く着き、根は 0.6〜1.2 秒で抜ける。得は 2〜3 秒。

## 3. 損の側との突き合わせ

- 損の文字 (diag_hsletters): binkar10_1 は `h`、dcmulti・mik は `c`、swath1 は `c`・`t`・`i`。仕組みは、重いサブ MIP を再スタート後の根でも回し直すこと。
  手当ての `TRIM=r` (再スタート後の根のサブ MIP は既定の形) で binkar10_1・swath1・mik が戻る。
- neos17・pk1 は bench6 で pi0 が損の原因とされた。neos17 は pi0 を外すだけで def 並みに戻る (5 節: hs_bgw 13 秒、hs_pi0_bgw 23 秒)。
- **得と損は同じ文字から来る**:
  - `c`: h80x6320d の得 ⇔ dcmulti・mik の損
  - `h`: physiciansched6-2 の得 (たぶん) ⇔ binkar10_1 の損
  - `t`: physiciansched6-2 の最初の根の RINS ⇔ swath1・h80x6320d の損
  - pi0: nu25-pr12 の 2 秒 ⇔ neos17 の +10 秒

## 判断と次の手

- 得の出どころ:
  - physiciansched6-2・qiu・h80x6320d は hs (サブ MIP の形)。h80x6320d は `c` 1 文字で決まる。
  - misc07 は bgw。
  - nu25-pr12 は pi0 (と hs)。
  - pi0 は nu25-pr12 の 2〜3 秒のほかに得がなく、neos17 の損 (+10 秒) の元なので外してよい。
- **提案する最小の組み合わせは `ENOMOTO_MIP_SUBMIP_HIGHS=cgh` + `ENOMOTO_MIP_BG_CUTS_WAIT=1` (pi0 なし)**。
  - 得の 5 問は 2 回とも全部解け (SGM 15.7、hs_pi0_bgw 14.6)、損の 4 問は 21.9 → 20.2。
  - `p`・`i`・`f`・`t` は得の 5 問で要らない。
  - 損を最も小さくするなら `TRIM=r` を足す (損 17.4) が、physiciansched6-2 の得を失う。
  - どちらも 2 回だけなので、58 問 (bench6 の組) で確かめるまで既定にはしない。
- 残る損は binkar10_1 (`h`、def 7〜8 秒 → 18 秒) と dcmulti 型 (`c`)。
- 次の手:
  - `TRIM=r` を RINS だけ外す形 (再スタート後の根でも RINS のサブ MIP は hs の形のまま) を試す。physiciansched6-2 の 2 回目の道を残しつつ、binkar10_1・swath1 の損を抑えられるかもしれない。
  - physiciansched6-2 の `g`・`h` が本当に要るかは、初めの解 (Local-MIP) の揺れが大きく、1 回ずつでは決まらなかった。回数を足して確かめる。
