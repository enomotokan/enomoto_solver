# cand で neos-1582420 が遅くなる理由の切り分け (2026-10-31)

依頼: `halve_submip_20261030.md` の bench7 で、既定にする候補 cand
(`ENOMOTO_MIP_SUBMIP_HIGHS=-s ENOMOTO_MIP_SUBMIP_PC_INHERIT=1 ENOMOTO_T_MIP_SUBMIP_RELIABLE=0 ENOMOTO_MIP_BG_CUTS_WAIT=1

## 1. 結論

1. **遅さは安定している** (8 回ずつ、平均 def 32.4 秒・cand 49.7 秒)。ただし回ごとの時間は「根の道」A/B (下) で大きく分かれ、
   bench7 の 26.1 → 59.3 秒は「def が道 A・cand が道 B」を引いた回だった。同じ道どうしでも cand は遅い (道 A +8.5 秒、道 B +18.6 秒)。
2. **原因は hs の文字 `t`** (根のサブ MIP の時間の上限を残り時間にする)。`t` だけを抜く (c-t、`ENOMOTO_MIP_SUBMIP_HIGHS=-st`) と
   6 回平均 27.3 秒で、def (32.4) より速くなる。`c`・`h` を抜いても戻る (31.8・38.1 秒) が、どちらも得の出どころ (`diag_hsletters_20261031.md`)。
   ほかの部品 (pi・r0・bgw・trim・ff・ps・p・g・i・f) はどれを抜いても戻らない。
3. 仕組み: `c` (根のカット 25 ラウンド) と `h` (サブ MIP の中の RENS) でサブ MIP の 1 本が重く、`t` で時間の上限がなくなると、
   - 解を見つけないサブ MIP が 500 ノードの上限まで走る (成果連動の打ち切りは、解を 1 つも見つけていないサブ MIP には効かない)。
     neos-1582420 の道 B では根の root reduced cost のサブ MIP が 12.8 秒、RENS のやり直し 6.9 秒、RINS 6.6 秒で、
     **根のヒューリスティクスが def の 13 秒から 29〜35 秒に延び**、どれも解を出さない。
   - 解を見つけて 50 ノードで成果連動で止まるサブ MIP も、中の入れ子の RENS (深さ 2) が「親のサブ MIP の残り時間の 0.3 倍」をもらうので、
     `t` で延びた分だけ重くなる (n5-3: 入れ子の RENS が 0.5 秒 → 6.0 秒で時間切れ、外側 1 本 2.3 秒 → 9〜12 秒、根のヒューリスティクス 16 → 40 秒)。
4. **手当て: cand から `t` を抜く (`ENOMOTO_MIP_SUBMIP_HIGHS=-st`)**。コードは要らない。各 3 回で、遅い 3 問は全部戻り、得の問題の得も残る
   (h80x6320d は 3 回中 1 回 38.5 秒、mc11 は cand より +2.7 秒ほど。下の表)。58 問・Mittelmann での確かめはしていない (次の手)。
5. 試作 `ENOMOTO_MIP_SUBMIP_HIGHS_NOSOL` (解のないうちのサブ MIP だけ `t` のない上限で止める) は neos-1582420 を戻す (34.2 秒) が、
   n5-3 (解のあるサブ MIP が重い型) は直さない (3 回とも時間切れ)。`t` を抜く形より弱いので、既定にはしない。

## 2. 根の道 A/B (揺れの元)

neos-1582420 は、根の LP (目的値はどちらも 87.576) の最適頂点が回で変わり、そこからカットのループが 2 通りに分かれる。
根の LP は二段解法と内点法 + クロスオーバーの同時実行 (`TwoStageLp::solve_race`) で、勝つ側で頂点が変わると見られる (勝った側は記録していない)。

| 道 | カットの選び方の探り (6 ラウンド) | カットのループの終わり | 裏のカット | 根の下界 |
|---|---|---|---|---|
| A | 既定 63 本・プール 37 本 | 89.251 | 37 ラウンド → 89.813 | 89.81〜89.91 |
| B | 既定 67 本・プール 40 本 | 89.261 | 26 ラウンド → 89.501 | 89.50〜89.59 |

最適値は 91 なので、道 A の方が木が小さい。設定で道の出やすさは変わらない (def 5A/3B、cand 3A/5B、全体で A 約 6 割)。
`summ.py` は最初のカットのループの終わりの値で道を分ける。

## 4. 手当ての試作 `ENOMOTO_MIP_SUBMIP_HIGHS_NOSOL` (既定では使わない)

`heuristics.rs` の `solve_submip_problem` と `solver.rs` の `SubmipCtl::nosol_deadline`・`Solver::time_up`。
`t` で時間の上限を残り時間にした根のサブ MIP に、`t` がないときの時間の上限の `ENOMOTO_T_MIP_SUBMIP_HIGHS_NOSOL_MULT` (1) 倍を
「解のないうちの上限」として持たせ、その時刻までにサブ MIP が解を 1 つも見つけていなければ止める。解を見つけたサブ MIP は今まで通り
(残り時間まで、成果連動の打ち切りで止まる)。h80x6320d の得 (LP face のサブ MIP が 7 秒かけて最適解を出す) を残し、
neos-1582420 の道 B (何も見つけないサブ MIP が 500 ノード走る) だけを切るつもりで作った。

- neos-1582420: 4 回平均 34.2 秒 (道 B の根のヒューリスティクスは 13 秒に戻る。道 A は 18 秒のまま)。
- n5-3 は直らない (60 秒・時間切れ 3 回)。解のあるサブ MIP の中の入れ子が重い型には効かない。
- 得の問題は cand と同じ程度 (下の表)。

## 6. 判断と次の手

- cand (= 今の既定) の neos-1582420・n5-3・neos-2978193-inde の損は、hs の `t` が `c`・`h` の重いサブ MIP の時間の上限を外すことから来る。
  **`t` を抜く形 (今の既定では `ENOMOTO_MIP_SUBMIP_HIGHS=-st`) を既定の候補にする**。ここでは 7 問だけなので、
  既定にする前に 58 問 2 回と Mittelmann (bench7 と同じ組) で確かめる。
- 試作 `ENOMOTO_MIP_SUBMIP_HIGHS_NOSOL` は既定にしない (n5-3 に効かない)。`t` を残したい問題が 58 問で見つかったときの代わりとして残す。
- physiciansched6-2 の「裏のカットが 49324 に届いたのに使われない」(not above) は別の問題として調べる (`bg_proof_stop_20261031.md` の続き)。
