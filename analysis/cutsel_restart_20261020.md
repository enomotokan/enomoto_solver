## 1. 試作 (どれも既定では使わない)

| 環境変数 | 中身 (src/mip/separation.rs `root_cut_loop`) |
|---|---|
| `ENOMOTO_MIP_CUTSEL_VIOL=1` (新規、(a)) | 選択の枠 (質の閾値の基準 = 枠の中の最良のスコア) を、今の LP 解を切る (違反 > 1e-6(1+\|rhs\|)) 候補だけにする。面の頂点の候補のうち今の解を切るものは効き目を今の解で測り直して同じ枠に入れ、切らないものは別枠で `ENOMOTO_T_MIP_CUTSEL_VIOL_FACE_MAX` (5) 本まで採る (採ったカットとほぼ平行 (0.99) なものは除く)。今の解を切るカットを 1 本も採れないラウンドでループを止める。サブ MIP と `ENOMOTO_T_MIP_FACE_MAX_CUTS > 0` では使わない |
| `ENOMOTO_MIP_CUT_STALL_MOVE=1` (新規、(b)) | 停滞の数え方: 今の解を切るカットを採って LP の解が動いた (どれかの列が 1e-6(1+\|x\|) 超動いた) ラウンドは、目的値も分数の列の数も動かなくても 2 回分と数えない (1 回分)。サブ MIP では使わない |
| `ENOMOTO_MIP_CUTSEL_HIGHS=1` (既存、(c)) | HiGHS の選択 (違反量 / (効いている非零の数 × 効いている列のノルム)、最良の一定割合以上、平行度 0.1) |
| `ENOMOTO_T_MIP_CUT_ROUNDS=100` (既存) | 根のラウンドの上限 25 → 100 |
| `ENOMOTO_MIP_RESTART_CUTS_READD=1` (既存、3) | 再スタートで効いているカットを問題の行にせず、新しい求解の根の LP の前にカットの行として足し直す (木の中で年齢で外せる。プールにも入る) |
| `ENOMOTO_MIP_RESTART_CUTS_TO_POOL=1` (既存、3) | 再スタートで LP のカットとカットプールを全部新しい求解のプールに渡す (行にしない。根の最初の 5 ラウンドはプールで違反するものも候補にする) |

(c) の「効き目 + 目的との平行度 + 整数の列の割合」は既定の `select_cuts_hybrid` のスコア (`cut_quality`) そのもので、
HiGHS のスコアは上の違反量 / (非零の数 × ノルム) なので、比べたのは既存の `ENOMOTO_MIP_CUTSEL_HIGHS` と既定。

## 2. 原因の切り分け (事実)

### neos-911970

- 既定の選択 (1 スレッド相当の主スレッドのログ、`ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_DEBUG_CUTSEL=1`、`logs/neos-911970_dbg_def.log`):
  ラウンド 15〜21 で目的値は 47.0292 のまま。毎ラウンド候補 830〜930 本のうち 35〜130 本が質の閾値を超え、10〜21 本を採る。
  **採ったカットは今の解を切っている** (効き目 0.2〜0.3) のに LP の値が動かない (LP 90〜195 反復)。LP の行の数は 196〜208 で
  ほぼ一定 (毎ラウンド同じくらいの本数が `remove_inactive_cuts` で外れる)。roll3000 の「面の頂点のカットが基準を上げて今の
  解を切るカットが落ちる」形ではない。
- 停滞の判定を緩めても (`STALL_MOVE` + 100 ラウンド、`logs/neos-911970_dbg_mv100.log`) 25 ラウンド目まで 47.0292 のまま
  (根のカットの時間の上限で止まる)。年齢で外す (`ENOMOTO_T_MIP_ROOT_CUT_AGE=10`) と 44.87 で、むしろ下がる。
- HiGHS の選択でも最初の根は **46.86** で止まる (ラウンド 10〜17 で動かない)。HiGHS の選択が効くのは再スタートの後で、
  ログ (`logs/neos-911970_dbg_hs100.log`) では:
  - 1 回目の再スタートで固定された整数列が **49 本** (既定は 22 本)。暫定解はどちらも RENS の 62.3〜62.95 で大差ない。
    固定の差は根の LP の双対 (被約費用固定など) の差と見られる (推測)。
  - 再スタート後の根の LP が **カットを足す前に 51.92** (既定は 47.03 のまま)。その後 52.0 → 53.0 → 54.1 と再スタートが続く。
  - つまり neos-911970 で HiGHS の選択が効くのは「最初の根のカットが強い」からではなく、「その LP で固定が多く出て、
    再スタート後の LP が上がる」から。
- 既定の再スタート後の根は 7 ラウンドで止まり 47.03 のまま (`logs/neos-911970_dbg_def.log`)。カットが問題の行になったまま
  同じ平坦な所に戻る (前の調査の推測どおり)。READD・TO_POOL でも再スタート後の根は 47.03 / 45.38 で上がらない。

### roll3000

- 前の調査の主因 (面の頂点のカットが質の閾値の基準を上げ、今の解を切るカットが落ちて停滞) に対し、`CUTSEL_VIOL` は
  基準を今の解を切る候補だけで決めるので同じ形の停滞は起きない。ただし `VIOL` だけでは停滞の 2 回分の数え方で止まる回があり
  (根 12077)、`STALL_MOVE` と組むと 2 回とも 25 ラウンド回って 12380〜12403 → 再スタート後 12505〜12512 になる。

- neos-911970: HiGHS の選択を使う設定 (`hs`・`hs100`・`hs100readd`・`hs100pool`) だけ下界が 54.7 台に上がる。VIOL・STALL_MOVE
  は下界が既定より悪い (52.4〜52.7。STALL_MOVE を付けると再スタートが起きなくなり、根が 47 台のまま木に入る)。
- roll3000: 根は VIOL + STALL_MOVE で既定より 290 上がり (12218 → 12508)、HiGHS + 100 + READD で 12563。60 秒の下界は
  HiGHS + 100 + READD が最良 (12723・12727、2 回とも)。どの設定でも解けない。
- mzzv42z: 根の処理 (前処理・根の LP・カット・ヒューリスティクス) に 30〜40 秒かかり、木は 4〜160 ノード。カットの選択では
  根の下界は動かない (-21395 → -21299〜-21454 の揺れ)。HiGHS の選択で暫定解が良くなる (-17590 → -19175〜-19340) が、
  カットで根の LP 解が変わってヒューリスティクスの当たりが変わったためと見る (推測)。
- neos-2978193-inde: 根の下界はすべて -2.41852 で、どの設定でも木の下界はほぼ動かない。根のカット・再スタートのカットの扱いは
  効かない (前の調査の「再スタートでカットを問題の行にすると木が大きくなる」推測は、READD・TO_POOL で 60 秒の下界が
  変わらないので、少なくとも 60 秒の範囲では確かめられない)。
- 再スタートのカットの扱い (3): 既定の選択と組むと READD・TO_POOL は効かない (neos-911970 で再スタート後の根が 47.03 / 45.38、
  下界は既定より悪い)。HiGHS の選択 + 100 ラウンドと組むと READD は roll3000 で良い (12725 対 hs100 の 12605)。

## 5. 推測 (確かめていない)

- neos-911970 の 47 の平坦な所: 箱の対称性のため LP の最適面が大きく、今の解を切るカットを足しても同じ目的値の別の頂点に
  移るだけになる。HiGHS は最初の根で 52.1 まで上がるので、カットの生成 (候補の種類・強さ) か、カットの行の扱い (毎ラウンド
  効いていないカットを外すこと) の違いが残っている。年齢で外すだけでは上がらなかった。
- HiGHS の選択で再スタート時の固定が増える仕組み (どの固定が増えたか: 被約費用固定か、プロービングか) は調べていない。
