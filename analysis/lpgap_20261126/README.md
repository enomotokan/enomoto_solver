# 当方の LP (双対単体法) が HiGHS より遅い原因: アルゴリズムか実装か (2026-11-26)

親の依頼 (利用者「LP のアルゴリズム自体に問題があるわけではないと思うが、そのへんまで含めてはっきりさせてほしい」)。
先端 6e78c5d90 (7d839da81 を含む) でビルド、1 スレッド、冷えた始動 (基底なし)。HiGHS は highspy 1.15.1 の双対単体法
(`solver=simplex`・`simplex_strategy=1`・`threads=1`)。

## 0. 台本

- `mklp.py`: 比べる LP を `.lpgap_cache/` (gitignore) に MPS で書き出す。`dano3_3_fix` = dano3_3 の整数列 69 本を当方の 1 スレッドの最適解
  (576.34463303) の値で固定した LP、`*_rel` = 整数を外した LP 緩和。
- `one.py {ours|highs|highs_pre} LP名`: 当方 (`lp_solver="simplex"` = 傾き・切片双対二段解法、`threads=1`) か HiGHS (前処理なし / あり) で解く。
  当方の内訳は `ENOMOTO_PROF_PHASES_EXT=1` (主ループの段ごとの時間)。
- `highs_opt.py LP名 キー=値 ...`: HiGHS のオプションを変えて解く (摂動・価格付け・尺度の効き目)。

## 1. 出発点の「dano3_3 の固定 LP で当方 58.7 秒」は再現しない

| 解き方 | 反復 | 秒 | µs/反復 |
|---|---|---|---|
| 当方 LP (`lp_solver="simplex"`) | 52305 | 18.3 | 349 |
| HiGHS 前処理なし | 57076 | 19.9 | 348 |
| HiGHS 前処理あり (2892 行 12259 列、当方の前処理の後 2893 行 12256 列とほぼ同じ) | 30397 | 10.5 | 345 |
| HiGHS 前処理なし・摂動なし (`dual_simplex_cost_perturbation_multiplier=0`) | 1175527 で 600 秒の時間切れ | — | — |
| 当方 MIP (整数を残して境界で固定した MPS) の返す解の研磨 (同じ LP を基底なしで解く) | 52305 | 17.7 | 374 |
| 当方 MIP の根の LP (LP プロービングの最初の LP) | 8384 (単体法の分) | 5.6〜6.3 | — |

- 当方の LP の経路は HiGHS の前処理なしと同じ速さ (反復 0.92 倍、1 反復 1.00 倍)。HiGHS の前処理ありより 1.7 倍遅いのは反復の差 (30397 対 52305)。
  前処理の後の大きさは同じなので、差は前処理後の LP の形 (行・列の並び、尺度) から来る反復の違い。
- 58.7 秒は当方の 1 スレッドの冷えた LP では出ない。4 スレッドで他のスレッドと CPU を分け合った研磨の LP (nattai 6 節の 16〜17 秒の LP) を測った数と思われる。
- MIP の根の LP が 8384 反復で済むのは単体法が良いからではない: 1 スレッドでも根の最初の LP は内点法 → クロスオーバー → 単体法
  (`TwoStageLp::solve_seq_ipm`、gdb で確かめた) で解いていて、8384 はクロスオーバーの後の単体法の反復。5.6 秒のうち主ループは 1.85 秒で、残りは内点法。
- 研磨の LP (整数を固定した LP) は基底なしの単体法だけで解くので 17.7 秒かかる。MIP 全体 24.3 秒のうち 73% が研磨。

## 3. dano3_3_rel の反復の差の切り分け

当方の主ループの内訳 (164188 反復、39.4 秒): FTRAN 27.4%・x_B 更新 13.0%・価格付けの行 11.0%・再分解 11.0%・chuzc 8.5%・BTRAN 7.5%・BFRT 6.4%。
特定の段が重いのではなく、反復が多い。

`ENOMOTO_DEBUG_PROGRESS=1` で見ると、主実行不能の行が 1800 前後のまま 13 万反復進まず、14 万反復目から減り始める (停滞)。

| 試したこと | 当方 反復 | 秒 |
|---|---|---|
| 既定 | 164188 | 39.4 |
| `ENOMOTO_DSE_REFRESH_ON_REFACTOR=1` (再分解のたびに DSE 重みを厳密に作り直す) | **96982** | 45.0 (作り直しが重い) |
| `ENOMOTO_DSE_WEIGHT_CHECK=1` (選んだ行の重みを確かめて選び直す) | 151237 | 36.7 |
| `ENOMOTO_SIMPLEX_BFRT_GROUP=gz` (HiGHS 式の BFRT のまとめ) | 119036 | 39.9 (1 反復が重くなる) |

| HiGHS の設定 (dano3_3_rel、前処理なし) | 反復 | 秒 |
|---|---|---|
| 既定 (DSE・摂動・尺度あり) | 58320 | 23.0 |
| 摂動なし | 41593 | 16.7 |
| 尺度なし | 40592 | 15.4 |
| 尺度なし・摂動なし | 62407 | 25.4 |
| **Dantzig の価格付け (`simplex_dual_edge_weight_strategy=0`)** | **670710** | 224.0 |

- HiGHS でも DSE を外すと 11.5 倍の反復になる。この LP は行の選び方の質で反復が決まる。
- 当方は重みを再分解ごとに厳密に作り直すだけで反復が 41% 減る → **保持している DSE 重みが再分解の間にずれている** (アルゴリズムの実装の正しさの問題)。
  作り直した後でも HiGHS の 1.7 倍あるので、ずれ以外の何か (BFRT の同点の扱い・傾き・切片の辞書式の行の比べ) も残る。

| 当方の設定 (dano3_3_rel) | 反復 | 秒 |
|---|---|---|
| `ENOMOTO_T_PERTURB_FACTOR=0` (費用の摂動なし) | **75534** | **25.9** |
| `ENOMOTO_T_PERTURB_FACTOR=10` | 156338 | 38.4 |
| `ENOMOTO_SIMPLEX_HARRIS2=0` | 164188 (同じ道) | 43.9 |
| `ENOMOTO_SIMPLEX_STABLE_TIE=1` | 402780 で解けず (240 秒) | — |

- DSE 重みのずれは主因ではない: `ENOMOTO_PROF_PHASES_EXT_WORK=1` で選んだ行の保持している重みを真の値 ‖ρ‖² と比べると、
  dano3_3_rel で 99.5%、dano3_3_fix で 99.8% が 1% 以内 (164187 回・52304 回)。`DSE_REFRESH_ON_REFACTOR` の 97k は選ばれない行の重みが変わった道筋の違いと見る。
- 費用の摂動を外すと当方も 2.2 倍減る (164188 → 75534)。HiGHS も摂動を外すと減る (58320 → 41593)。ところが dano3_3_fix では HiGHS は摂動なしで
  117 万反復でも終わらない (摂動ありは 57076)。退化の強い LP で、摂動の有無・大きさ・列の並びで反復が数倍変わる道筋の運の問題。
- HiGHS が前処理した LP (`getPresolvedLp` を書き出したもの、`*_hpre`) を両方で解くと:

| LP | 当方 反復・秒・µs | HiGHS 反復・秒・µs |
|---|---|---|
| dano3_3_fix_hpre | 49700・18.5・372 | 30397・11.2・368 |
| dano3_3_rel_hpre | 81127・25.4・313 | 59126・23.2・391 |

  同じ LP・同じ並びでも当方の反復は 1.4〜1.6 倍。1 反復は同じか速い。
