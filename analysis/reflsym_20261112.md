# REFLSYM: 列の反転を含む対称性と、前処理の後に畳む量の数え上げ (2026-11-12)

診断だけで、解く側は変えていない。bench に使う環境変数: 診断 `ENOMOTO_MIP_REFLSYM_COUNT` (src/mip/reflsym.rs。`stop` 前処理の後で数えて終える、
`r` 再スタートの後も数えて解き続ける)、`ENOMOTO_T_MIP_REFLSYM_TIME` (検出 1 回の時間の上限、既定 20 秒)。畳み量は既存の `ENOMOTO_MIP_FOLD=<値>c`
(解かずに畳むだけ) で、値 `ri` (今の既定と同じく元の問題を畳む) と `riP` (前処理 → 畳む) を比べた。wheel はどちらも 220bd75e。

## 結論

- 反転 (x → l + u − x、0-1 なら補完) を含む符号つき置換で数えても、前処理の後の 203 問 (58 問と Mittelmann) で対称性が増えるのは 12 問、
  反転を含む生成元があるのは 8 問だけ。58 問では sp150x300d (動く列 326 → 334) と timtab1 (0 → 2) の 2 問で、どちらも小さい。
  置換で 0 から増えるのは neos-5107597-kakapo (1437 生成元、どれも反転を含む)・fhnw-binpack4-48・neos-4338804-snowy・graphdraw-domain・
  supportcase33 で、どれも 58 問の外。
- 再スタートの後 (uccase12 の 2 回、neos-1582420 の 1 回) も反転を含む生成元は 0。ほかの 9 問は 300 秒で再スタートしなかった。
- 前処理の後に畳むと、畳み量が大きく増える問題がある (239 問で、畳めたのは前 35・後 31、後だけ 11): physiciansched6-2 37.5% → 95.6%、
  supportcase12 6.0% → 89.3%、physiciansched3-3 11.8% → 81.4%、neos-5093327-huahum 4.7% → 55.0%、academictimetablesmall 2.2% → 30.8%、
  後だけで brazil3 71.5%・cryptanalysiskb128n5obj14/16 49.1%・supportcase33 69.7%・icir97_tension 55.3%・piperout-08 43.2%・rail01 21.6%。
  逆に前処理の後では畳めなくなる問題もある (widden 18.8%・neos-1582420 63.2%・atlanta-ip 24.0%・bnatt400/500 33%・gmu-35-40/50・seymour・swath)。
- 判断: (a) 符号つき置換を lex-leader・orbitope に使う道は、当たる問題が少なく 58 問にほぼ無いので見込みが薄い。(b) 前処理の後 (または前と後の
  良い方) に畳む道の方が見込みがある。ただし数は「畳む段階で列がいくつ減るか」で、畳んだ後に前処理をかけた最後の大きさや解く速さは比べていない。
  試作はまだしない。

## 1. 前処理の後の符号つき置換 (`count_a.jsonl`・`count_b.jsonl`、`summ.py` → `summ.txt`)

  可能性はある (cryptanalysis は打ち切られても反転を含む生成元が 48)。

## 2. 前処理の前と後に畳む量 (`count_fold.jsonl` = `ri`、`count_foldP.jsonl` = `riP`、`summ_fold.py` → `summ_fold.txt`)
