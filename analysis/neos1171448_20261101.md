### trim3 で何が起きたか (VERBOSE の 4 本、`SMT` の行)

- **外側 (深さ 1) の RENS のやり直し・継続は def でも trim3 でも起きない**。並列の根の RENS (161 / 2457 列が自由) は 500 ノードの上限の手前 (def 62〜71、trim3 57)
  で停滞・成果連動の打ち切りで止まる。trim3 は `RENS (more nodes) skipped: the parallel sub-MIP stopped at 57 of 500 nodes` (REAL の場合分け)。def は
  やり直しの印 (`rens_node_limited`) は立つが、根の後の差が −307.5 で 0.49% (≤ 0.5%) なのでやり直しに入らない。
- **RESUME はこの問題では一度も働かない**: 一時停止 (`paused=1`)・継続 (`SMT resume`・`resuming the paused`)・捨てた一時停止 (`dropped`) はどのログにも 0 本
  (ノード上限まで進んだ RENS が無いので、一時停止の条件に入らない)。
- **深さ 3 の RENS はどの回も作られない** (def でも `depth=3` の `SMT begin` は 0 本)。`RENS (LP before cuts)` もどのログにも無い。
  つまり `ENOMOTO_MIP_RENS_MAX_DEPTH=2`・`ENOMOTO_MIP_RENS_LPBC_MAX_DEPTH=1` (d2lp1) もこの問題では働かない。
- **違いは REAL の場合分けが深さ 2 (サブ MIP の中の RENS) で効くこと**だけ。def では次の道を通る (VERBOSE 2 本とも同じ):

  | | def | trim3 |
  |---|---|---|
  | 深さ 1 の RENS (並列) の中の深さ 2 の RENS | 88 / 500 ノードで止まり −307 | 同じ (88 / 500、−307) |
  | その深さ 2 の `RENS (more nodes)` | **走る** (2000 ノードの上限、223 ノード、0.8〜1.0 秒) で −307.5 | 省く (`the sub-MIP stopped before its node limit`) |
  | 深さ 1 の RENS の結果 | −307.5 (1.5〜2.0 秒) | −307 (0.6〜0.7 秒) |
  | 根の RINS (161 列が自由) の中の深さ 2 の RENS | 383 / 500 ノードで −307 | 120 / 500 ノードで **−308.000001758** |
  | その深さ 2 の `RENS (more nodes)` | **走る** (383 ノードで同じ所で止まる空回り、1.2〜1.4 秒) | 省く |
  | 根の RINS の結果 | −307 (2.8〜3.1 秒、外側を良くしない) | −308.000001758 (0.9〜1.2 秒、外側を良くする) |
  | 根の後の暫定解 | −307.5 | −308.000001758 |

  RINS の固定は暫定解と LP 解の一致で決まるので、深さ 1 の RENS の値 (−307.5 か −307 か) が変わると RINS のサブ MIP の中身が変わり、RINS の中の RENS の道も
  変わる。trim3 の根が 2.2 秒早く終わるのは、この 2 本のやり直し (計 2.0〜2.4 秒) を省くため。
- 木では、どちらの形も −309 を見つけるのは熱心なヒューリスティクスのスレッドの ALNS (mutation・crossover・RINS) の 1 回で、木に入ってから 15〜30 秒かかる。
  def は木に入った 11 回中 8 回、まず木の RINS が −307.50000153 (根の −307.50000000067 より 1.5e-6 良いだけの別の解) を見つけ、2〜5 秒後に mutation・crossover が
  −309 を見つける。trim3 は根の暫定解が −308.000001758 で、木の RINS が最初に暫定解を更新するのは 12 回中 3 回だけ、多くは mutation が −308 から直接 −309 を見つける。
  時間切れの 2 回は、木の 38〜40 秒の間に暫定解が一度も更新されない (−308.000001758 のまま)。暫定解の値の違いが ALNS の腕の選び方 (改善した腕に報酬) や
  mutation の固定の元を変えていると思われるが、熱心なスレッドのサブ MIP は `ENOMOTO_MIP_LOG=1` でも行を出さないので、ここでは確かめていない。

### 見立て

- **RESUME のせいではない**。RESUME (一時停止・継続) はこの問題で一度も働かず、深さ 3 の RENS を止める d2lp1 も働かない。trim3 の根の道を def から変えるのは、
  REAL (RESUME も含む、ノード上限の手前で止まった RENS のやり直しを省く) が**深さ 2 で** 2 本のやり直しを省くことだけ。2 節の real・real+d2lp1 (RESUME なし) も
  6 回に 2 回ずつ時間切れになり、3 節の resume の時間切れの値も同じ −308.000001758 で、この見立てと合う。RESUME を外しても neos-1171448 は直らない。
  (2 節の「real は根の道を変えていない」は外側 (深さ 1) の話で、深さ 2 では上の表の通り変わる。3 節の終わりの推測を VERBOSE で確かめた形。)
- **揺れか**: どちらの形も「−309 を木のヒューリスティクスが見つける時刻」の籤で、解けた回の時間は同じくらい (中央 46.4 秒どうし)。ただ、REAL の入った形
  (trim3・real・real+d2lp1) はこの速さの機械で 24 回中 6 回時間切れ、def は 12 回中 0 回 (片側 p = 0.07、bench を含めて 8/26 対 1/17 で p = 0.05)。
  def は根の後の −307.5 の解から木の RINS → mutation・crossover と進んで −309 に早めに届くことが多く、REAL の道 (根の −308.000001758) は外れの裾が重い。
  REAL が無駄な仕事を省いた結果、深さ 2 の値の違いから根の暫定解が決まった形で入れ替わり、その下流の木のヒューリスティクスの当たりやすさが変わった
  (仕組みとして損をする部品ではなく、道が変わったことによる偏り) とみる。60 秒の境目の上にある問題なので、この偏りが解けた数にそのまま出る。
  3 節の遅い機械では def も 0/4 なので、機械の速さの方が大きく効く。
- **trim3 を既定にしてよいか**: neos-1171448 だけを理由に止める必要はないと考える。損の出どころは RESUME でも d2lp1 でもなく REAL の道の入れ替わりで、
  REAL の得 (58 問・Mittelmann の空回りのやり直しを消す、`rens_resume_20261101.md` 1.1 節) と引き換えになるのはこの 1 問の 1/4〜1/6 の時間切れの率。
  bench9・bench10 の合計 (58 問 −2.4%・+5、Mittelmann ±0、neos-1171448 の −1 を含む) で判断してよい。
  - **RESUME を外すべきか**: この問題を理由に外す必要はない (外しても REAL が残る限り同じ)。RESUME の要否は、本当にノード上限まで進んだ RENS がある問題
    (ran14x18-disj-8・supportcase26 など) の得で決めるのがよい。
  - 気になるなら、120 秒の上限で def・real の「−309 までの時刻」を比べるか、熱心なスレッドの ALNS の腕と結果をログに出して、根の暫定解の値で
    木の当たりがどう変わるかを確かめる (別の手。振る舞いは変えない)。

  - d2lp1 は木に入るのが平均 1.4 秒遅く、解けた回の時間も 2 秒ほど長い (4 回ずつで、揺れの内)。
  - 結論: neos-1171448 の時間切れは、real・d2lp1 のどちらの部品でも 2/6 の率で起きる。RESUME の関与は、同じ数の trim3 (と既定) の回と比べないと決まらない
    (別のセッションの既定と trim3 の比べの結果を待つ)。どの形でも木の中のヒューリスティクスの 1 回に頼っているので、形の比べはこの問題 1 つでは揺れが大きい。

## 3. resume・d2lp1

- 機械: 4 CPU。4 スレッド・60 秒、ソルバーは同時に 1 つだけ、`ENOMOTO_MIP_LOG=1` (サブ MIP の中の行は出ない)。HiGHS (highspy) 1.15.1。
- ビルド: ブランチ `ccr-1beed81b-ex0uhq` の `5e66bc28` (計測中は取り込み直していない)。
- 形: resume = `ENOMOTO_MIP_RENS_RESUME=1` (REAL の場合分けを含む)、d2lp1 = `ENOMOTO_MIP_RENS_MAX_DEPTH=2 ENOMOTO_MIP_RENS_LPBC_MAX_DEPTH=1`。
  resume → d2lp1 の順に交互に各 6 回。そのあと、この機械の速さを見る対照として既定 (def) を 4 回 (交互ではなく続けて)。
- 台本・ログ: `analysis/neos1171448_20261101/resume/`
  - `run.py 回数 [ログのディレクトリ] [設定の並び]` (ログは `logs/<設定>/neos-1171448_r<回>.log`、`run.out` は 1 回ごとの結果の行)
  - `summ.py`: ログから下の表の値を拾う (`summ.txt`)。

### 見立て

- **この機械では既定 (def) も 4 回とも時間切れ**で、bench の機械 (def 41〜53 秒、最初の解の時刻 4.3〜5.7 秒) より遅い
  (ここの最初の解の時刻は 5.2〜7.9 秒、1 回目は 7〜8 秒と特に遅い)。neos-1171448 はこの機械では 60 秒の境目の上にあり、resume 1/6・d2lp1 2/6・def 0/4 の差は
  この回数では揺れと区別がつかない。**resume・d2lp1 のどちらか一方が時間切れの原因、という形は見えない**。
- 解ける回は 3 回とも、木の熱心なヒューリスティクスのスレッド (`1 of 4 tree threads take the heuristic role`) が 50〜55 秒に
  crossover・RINS で −308 → −309 を続けて見つけて終わる (主のスレッドのノード 258〜275)。根の終わりの主の値や RENS の値はそれを左右して
  いない (根で −308 を持っていた resume 3・5、def 2 も、−304〜−305 の回も解けない)。木に入ってから −309 に届くまでが 25〜30 秒かかる、
  時刻の競争になっている。
- resume は REAL の場合分けで根の `RENS (more nodes)` を 6 回とも省いた (根の RENS は 48〜60 ノードで停滞・成果連動の打ち切り、継続は 0)。
  木に入るのは平均 25.2 秒で 3 つの中で一番早く、ノードも一番多い (1067)。それでも −309 の解には届かないことが多い。つまり resume は
  この問題でやり直しの時間を削ってはいるが、損の原因ではない。継続 (一時停止の再開) はこの問題では一度も起きない (根の RENS がノード上限まで進まない)。
- d2lp1 は根の深さ 1 の振る舞いを変えない (やり直しは差 > 0.5% のときに def と同じく走る。1・5 回目)。違いはサブ MIP の中の深さ 2 以下だけで、
  `ENOMOTO_MIP_LOG=1` では見えない。RENS の値の分布 (−307.5 が 4/6) は def (2/4) と似ている。
- bench9・bench10 の trim3 の 2 回の時間切れが同じ値 −308.000001758 で止まったことは、ここの resume 3・5 と同じ (根の RENS −307 → 根の RINS
  −308.000001758)。resume・trim3 の RENS のサブ MIP の中は REAL の場合分けで def と違う道を通るので、この −307 → −308.0000018 の道に
  入りやすいのかもしれない。ただ、ここでは −308 を根で持つ回 (def 2 も) が解けないだけで、そこから木が −309 を見つけるかは 25 秒以上の
  時刻の競争で、道の違いだけでは決まらない。
- 2 節 (別のセッション、別の機械) と比べると、あちらは木に入るのが 18.5〜22.7 秒・解けた回 41〜48 秒で、ここ (20.7〜34.1 秒) より速い。
  あちらでも real 4/6・real+d2lp1 4/6 で、−309 を木のヒューリスティクスのスレッドが見つけるかの籤という見立ては同じ。
- 次の手: 切り分けには bench と同じ速さの機械で回すか、時間の上限を延ばして (例 120 秒) −309 に届く時刻を比べるのがよい。
  60 秒・この機械の回数を増やしても、def が解けないので部品の効きは測れない。
