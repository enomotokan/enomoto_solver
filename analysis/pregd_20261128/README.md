# PREGD: 前処理の型 G (支配される列の一般化) と型 D (余った行・列を消す) (2026-11-28〜、親の依頼)

背景は analysis/presize240_20261127/README.md の型 G・型 D。試作は既定オフの `ENOMOTO_MIP_PREGD` (文字の組み合わせ)。

| ファイル | 中身 |
|---|---|
| `highs_rules.py` → `hlog/` | HiGHS 1.15.1 の前処理のログ (規則の記録つき、presize240 の写し) |
| `solve.py` → `solve.jsonl`・`logs/` | 1 問を最後まで解く (種 1、前処理の後の大きさと時間) |
| `fuzz_domcol.py` | 支配列を狙った乱数の MIP で HiGHS と最適値を突き合わせる fuzz (2 節) |

## 1. 何が差か (HiGHS のログから)

- **nw04**: HiGHS は `Fixed 36777 dominated columns` で 87482 → 46189 列。行はすべて等式なので、HiGHS の支配は
  「係数が全く同じ列で費用の安い方が残る」と同じ。同じ列の組は 46190 組で、HiGHS とほぼ一致する。
  当方の 0-1 の支配列 (`ENOMOTO_MIP_DOMCOL`) は衝突グラフの隣を候補にするので 3440 本しか見つけず、
  さらに「固定が自由な列の 1 割未満なら捨てる」で捨てていた。
- **seymour1**: 集合被覆 (行はすべて Σ x ≥ 1、費用はすべて 1)。1372 列のうち 921 列が [0,1] の連続列。HiGHS は 202 + 11 本を固定する。
  当方の支配列は 0-1 列しか見ないので、連続列が丸ごと対象外だった。
- **supportcase7**: HiGHS は 4209 本の支配列を固定する。
- **swath1**: 列の数はほぼ同じ (当方 6262、HiGHS 6260)。差は非零 (31722 対 25480) で、HiGHS のログに支配列の行はない。支配列とは別の原因 (未調査)。
- **rocI-4-11**: HiGHS のプロービングが「deleted columns」で 308 + 35 + 30 列を消す (行ではなく列。プロービングでの置き換え)。型 D の本体はこちら。

## 2. 試作 `ENOMOTO_MIP_PREGD`

- `p` ([`identical_col_fixings`]): 係数が全く同じで型の同じ列の組で、費用の安い列 x_j を残し、ほかを下限に固定する。
  x_j を上げられるのは、上限が無いときか、両方 0-1 で同時に 1 にできない (ある行で 2 本とも 1 にすると最小活動でも破れる) とき。
- `g`: 0-1 の支配列の固定 ([`dominated_binary_fixings_with`]) を、両側に有限の境界を持つ一般の整数・連続の列にも広げる。
  文字は y = x − l か y = u − x、幅 w = u − l。整数の列が連続の列を支配することは使わない (HiGHS と同じ)。
- 新しい閾値は作っていない (固定を捨てる既存の判定 `ENOMOTO_T_MIP_DOMCOL_MIN_FRAC` 0.1 はそのまま)。

| seymour1 | 1150 (334.7 秒) | `g`: 928 (166.6 秒) | 890 |

- seymour1 で「固定を捨てる判定」だけを外す (`ENOMOTO_T_MIP_DOMCOL_MIN_FRAC=0`、62 本を固定) と 457.4 秒で、かえって遅い。
  `g` は連続列も調べるので 189 本になり、1 割を越えて捨てられない。

### 誤答の確かめ

- fuzz 7 本 (release019 の fuzz.sh の組) を `PREGD=pg` で: 誤答 0。
- `fuzz_domcol.py` (支配列を狙う。元の列に「同じ列」と「係数を支配の向きにずらした列」を、型・有限の境界・費用を変えて足す):
  - 種 0〜5999 で、既定にも `PREGD=pg` にも共通の食い違いが 4 件出た。どれも PREGD の誤りではない。
    - **種 1399 は当方の既定の誤り** (実行可能なのに実行不能)。原因は幅の小さい列の固定の予算で、直した (docs/improvement_history.md の 2026-11-28)。
      0.2.0 (PyPI) では同じ仕組みで種 4631 が誤る (直しを当てると正しくなる)。直した版では、既定・`PRR_TIGHT=0`・`PREGD=pg` で種 0〜5999 の当方の誤りは 0。
    - 種 2880・6174 は HiGHS 1.15.1 の前処理の誤り (HiGHS を前処理なしで解くと当方と一致)。
    - 種 6532 は許容誤差の差。
  - **今後の誤答の確かめの組に加える候補**: `fuzz_domcol.py` は支配列・同じ列・有限の境界の連続列を多く含み、既存の fuzz 7 本では
    出なかった誤答 (種 1399) を見つけた。`ENOMOTO_MIP_REL_GAP=1e-9 python3 analysis/pregd_20261128/fuzz_domcol.py 6000 0` (約 2 分)。
    HiGHS の前処理の誤り (種 2880・6174) と許容誤差の差 (種 6532) が bad に数えられるので、これらは既知として除いて読む。

## 3. P (`PREGD=pg`、174 問 × 種 3、1・4 スレッド、`pgp/`)

19766cd86 のビルドで、4 つの分担に分けて回した (分担 0 はここで、1〜3 は他の作業者)。696 回すべて終わり、crash 0。集計は `pgp/summ.txt`。

| スレッド | 比 (pg/既定) | 95% 区間 | 解けた数 既定 → pg | 食い違い | 効いた (< 0.8) | 害 (> 1.25) |
|---|---:|---|---|---:|---|---|
| 1 | 0.988 | [0.967, 1.010] | 124 → 124 | 0 | nw04 0.53 | なし |
| 4 | 0.989 | [0.958, 1.020] | 141 → 141 | 0 | nw04 0.45 | 10teams 1.27 |

- nw04 は種 3 つとも速い (1 スレッドで 31.0・28.0・50.8 秒 → 16.8・14.3・11.9 秒)。
- 4 スレッドの「全種 1.25 倍超の遅れ」は neos-3083819-nubu (1.35・1.25・1.29) だけ。ただし既定で 1.8〜2.1 秒の小さな問題で、遅れは 0.5 秒ほど (節点 19〜21 → 31〜49)。1 スレッドでは 5.7・5.9・5.1 秒 → 7.0・6.7・4.8 秒で、はっきりした遅れはない。
- 10teams の 4 スレッドは種による (7.5・17.9・15.1 秒 → 18.3・44.6・6.3 秒)。並列の揺れと見分けがつかない。1 スレッドは既定・pg とも 60 秒で解けない。
- seymour1・supportcase7 は P の組 (60 秒の打ち切り) に入っていない、または解けないので、1 節の 600 秒の結果が効き目の証拠になる。
- 全体では中立 (区間が 1 をまたぐ)。目に見えて効くのは同じ列の多い問題 (nw04) と、連続列の支配列が多い問題 (seymour1・supportcase7)。

## 4. 型 D (rocI-4-11 の列の差)

新しい既定 (55c7060b1 以降) でも rocI-4-11 の前処理の後は 2806 行・1343 列 (HiGHS 2589 行・1062 列)。内訳を数えると:

| | 0-1 列 | 一般の整数列 | 連続列 | 計 |
|---|---:|---:|---:|---:|
| HiGHS | 585 | 164 | 313 | 1062 |
| 当方 既定 | 719 | 311 | 313 | 1343 |
| 当方 `TREE2_INTAGG=1` | 673 | 167 | 315 | 1155 |
| 当方 `PREGD=d` + `TREE2_INTAGG=1` | | | | 1065 |

- HiGHS の「probing ... 308 deleted columns」は当方の「308 equivalent binary pairs」と同じもので、既定で既に消えている。
- 当方の前処理の後の問題 (`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED3`) に HiGHS の前処理をかけると 1340 -> 1038 列。規則を 1 つずつ切ると、効いているのは
  aggregator (規則 12) だけ。残る等式行は 3 列の行 (`x734 = 2 + x206 + x295`、整数 [2,4] と 0-1 2 本など) が 344 本。当方の整数列の消去
  (`ENOMOTO_MIP_TREE2_INTAGG`、既定 `d`) は「残りが全て 0-1 列で、消す列の出る行が 2 本まで」に限っている。`=1` (0-1 列も消す) で 1155 列。
  (`=1` は tree_close2_20261104 で h80x6320d の根を下げたので既定にしていない)
- `TREE2_INTAGG=1` の後に HiGHS の前処理をかけると、今度はプロービング (規則 15) で 1132 -> 1055 列。当方の最後のプロービングは同値な 0-1 列の組を
  90 組見つけているのに、境界を締めただけ (固定 0 本) なので [`represolve_after_probe`] が「skipped (probing fixed 0 columns)」で早く戻り、
  組を代入しないまま捨てていた。
- 試作 `PREGD` の `d` ([`prr_early_return`]): かけ直しの判定で早く戻るときも、同値な組があれば代入する ([`substitute_probe_equiv`]、回数の上限は既存の
  `ENOMOTO_T_MIP_PROBE_EQUIV_ROUNDS`)。新しい閾値は無い。`TREE2_INTAGG=1` と合わせて 1065 列で、HiGHS (1062) とほぼ同じになる。
- ただし 60 秒の時点の下界は、どの設定でも −1108 万 (HiGHS も 90 秒で −1107 万) で、大きさの差は下界に効いていない。rocI-4-11 は下界の証明が
  難しい問題で、大きさの差が遅さの原因ではない。
