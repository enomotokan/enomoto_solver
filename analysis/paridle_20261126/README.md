# 4 スレッドの「遊び」と「重複探索」(2026-11-26、親の依頼)

背景: analysis/par4_20261126 の診断で、スレッドの遊びは平均 8.6% (木の短い問題で大きい)、4T のノードは 1T の 0.785 倍 (全体の重複は少ない) が、
neos-1582420 のように 21 倍になる問題がある (treeclose 9.77: 共有の頻度を上げても減らない)。
仕事: (1) 遊びの時期・重複の中身を数字で示す、(2) 原因に合わせた試作 (`ENOMOTO_MIP_PARIDLE`、既定オフ)、(3) P の 4 スレッドで既定と比べる。

### 1.1 遊びの時期

木の段 (主が木に入ってから終わるまで) のスレッド秒 = スレッド数 × 木の段の壁時計を分母にして、遊びを次の 4 つに分けた。

| 時期 | 中身 | 全問の合計 (スレッド秒の重み) |
|---|---|---:|
| A 分かれる前 | 主が木の最初のノード (根) を処理していて、従がまだいない (`workers start` − `tree start`) × 3 | **4.2%** |
| B1 写しの準備 | 従が始まってから最初に待ち行列を見に来るまで (`ready`) | 1.1% |
| B2 最初の待ち | 準備を終えた従が最初のノードを受け取るまで (主が渡すのを `TREE_HOLD_SECS` = 1 秒か `TREE_START_NODES` = 8 個まで控える) | **3.5%** |
| C 途中の待ち | 共有の待ち行列が空で待った (主も含む) | 1.0% |
| D 終わりの待ち | 最後に仕事が尽きた (`tail`) | 0.2% |
| 計 | | **9.9%** |

(木の段に入った 38 問、木の段のスレッド秒の計 2625。問題ごとの割合の平均は 29.5% で、木の短い問題ほど大きい。)

- **A は木の最初のノードの強分枝**: `TREEPAR: spawn` の行の `sb` (強分枝の秒) が A の長さとほぼ同じ。h80x6320d 6.0 秒 (214 LP)・eil33-2 4.5 秒 (280 LP)・
  roll3000 3.2 秒 (582 LP)・mc11 3.0 秒 (200 LP)。従は根を分枝して待ち行列が 2 個になってから始まる (`TREE_SPAWN_NODES` = 2) ので、その間 3 本が空く。
  A の割合の大きい問題: h80x6320d 67%・roll3000 26%・eil33-2 24%・mc11 15%・cvs16r128-89 12%・rout 10%・mzzv42z 10%。
- **B2 は主の控え**: 従の準備 (B1) は短い (多くは 0.0〜0.2 秒) のに、主は 1 秒か 8 ノードまで渡さない。B2 の大きい問題: neos-3083819-nubu 54%・p0201 42%・
  nu25-pr12 39%・neos17 27%・misc07 21%・mzzv42z 18%・rout 16%・binkar10_1 14%・cvs16r128-89 14%・qiu 13%・swath1 13%。
- 途中 (C)・終わり (D) の遊びは小さい (eil33-2 の C 33% が例外)。同期の待ちは小さい (`sync` は木の段の 1% 未満)。
- 長い木 (noswot・pk1・mas76・neos5・gen-ip*) は遊び 1% 以下。

### 1.2 重複探索

両方とも最適で終えた 22 問のノード 4T / 1T の幾何平均は 0.646 (4T の方がノードが少ない)。時間切れの問題の 2.7〜3.7 倍は同じ 60 秒で 4 本が処理した数で、重複ではない。
両方とも最適で 4T の方がノードの多い問題:

| 問題 | ノード 1T → 4T | lb>=opt 1T → 4T | 最後の暫定解の時刻 (全体の割合) 1T → 4T | 読み |
|---|---|---|---|---|
| noswot | 17457 → 41382 (2.37) | 0 → 0 | 0.17 → 0.03 | 4T の方が早く最適解を見つけ、刈れたはずのノードは 0。木の形 (分枝の選び方) が違う |
| neos17 | 1507 → 2769 (1.84) | 0 → 1164 | 0.50 → 0.99 | 4T は最適解を最後に見つけた。1164 ノードは最適値が分かっていれば刈れた |
| graph20-20-1rand | 1972 → 3197 (1.62) | 78 → 498 | | 同上の型 (小さい) |
| timtab1 | 19604 (時間切れ) → 22406 | 3120 → 12304 | 0.42 → 0.94 | 同上 |

- `lb>=opt` は最適値 (か最後の暫定解) 以上の下界のノードの数で、上界が初めから分かっていれば刈れた。
- 上界 (打ち切り値) は全スレッドが毎ノード読む (共有の `Portfolio`) ので、届く遅れは 1 ノード分。4T の水増しは「上界の届く遅れ」ではなく、
  (a) 探索の順の違いで最適解を見つけるのが遅れた回 (neos17・timtab1)、(b) 分枝の選び方 (擬似コストの共有は 16 ノードおき) で木の形が違う回 (noswot)。
- 同じ部分木を 2 本が解くことは作りの上で無い (ノードは共有の待ち行列か各スレッドの手元のどちらか一方にある。木の再スタートの後は作り直す)。
- neos-1582420 (P の外) は今の版では 1T 59.5 秒・1304 ノード、4T 31.3 秒・2954 ノード (2.3 倍、種 1)。par4 の 21 倍は再現しない。
  4T の木の段 11.4 秒のうち、最初のノードの強分枝が 2.8 秒 (A)。

### 1.3 試作の方向

遊びの 9.9% のうち A (4.2%) と B2 (3.5%) が大きく、どちらも木の始まりにある。重複は上界の共有の遅れではないので、上界の即時共有は作らない。

## 2. 試作 `ENOMOTO_MIP_PARIDLE` (既定オフ、src/mip/solver.rs `paridle`)

| 文字 | 中身 | 狙う遊び |
|---|---|---|
| `h` | 主の控え (`TREE_HOLD_SECS` = 1 秒・`TREE_START_NODES` = 8 個まで渡さない) を、準備を終えて共有の待ち行列で待っている従がいれば (既存の渡す判定と同じ `idle > len`) 終える | B2 最初の待ち (3.5%) |
| `e` | 従を木の最初のノード (根) の前に始める (`TREE_SPAWN_NODES` の 2 の代わりに 1)。従の写しの準備が根の強分枝と重なり、ヒューリスティクス役 (4 スレッドの tid 3) は暫定解があれば強分枝の間に役を始める。ノードは根を分枝してから渡す | A 分かれる前 (4.2%)・B1 写しの準備 (1.1%) |

- 新しい閾値はない (`h` は既存の判定 `idle > len`、`e` は既存の始める数を 1 にするだけ)。
- どちらも木を分け合うとき (2 スレッド以上) だけ働く。1 スレッドの道筋は変わらない: `check_default.py ENOMOTO_MIP_PARIDLE=eh` で 6 問とも基準と一致。
- 誤答の確かめ (`fuzz.sh eh4 ENOMOTO_MIP_PARIDLE=eh ENOMOTO_MIP_THREADS=4`): fuzz 7 本とも誤答 0 (fuzz_tiny 0/400・fuzz_highs 0/300・fuzz_objint 0/1000・
  fuzz_slack 0・fuzz_tiny2 0/400・fuzz_objint2 0/1000・fuzz_slack2 0)、cargo test 424 通過・失敗 0。
- 手元の当たり (種 1、4 スレッド、診断の回と比べて): 従の始まる時刻は木の始まりと同じになった (h80x6320d 12.12 → 6.88 秒、roll3000 8.20 → 3.44 秒、
  木の始まりはそれぞれ 6.06 → 6.89・5.02 → 3.44 秒)。全体の秒は 1 回ずつでは揺れの範囲 (h80x6320d 30.0 → 33.1、neos17 5.8 → 6.2、roll3000 34.8 → 36.5)。
