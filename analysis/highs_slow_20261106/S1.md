# S1: HiGHS より遅い 3 問 (physiciansched6-2・hypothyroid-k1・neos-860300) の調べ (2026-11-06)

bench に使う環境変数: `ENOMOTO_MIP_S1_RINSWIDE=2 ENOMOTO_MIP_S1_IPMFIND=1 ENOMOTO_T_MIP_CLIQUE_FB_RATIO=0.1`
(3 つまとめて `s1all`。問題ごとの効き目は下の表。どれも既定では使わない。`CLIQUE_FB_RATIO` は既存のつまみ (既定 0.5) で、コードの変更はない)

- 機械: 4 CPU (`nproc` = 4)。ソルバーは同時に 1 つだけ動かした (当たりつけの exp1 の 1〜5 回目は `cargo check` と重なった)。
- ENOMOTO は 4 スレッド・上限 300 秒 (3 問とも 75 秒以内に解けるので 600 秒と同じ扱い)、`ENOMOTO_MIP_LOG=1`、種は `ENOMOTO_T_MIP_SEED`。
  HiGHS は highspy 1.15.1、4 スレッド、`mip_rel_gap=0` (`scripts/run_miplib_benchmark.py` の `--worker-highs`、`ENOMOTO_BENCH_HIGHS_LOG=1` でログ)。
- 台本: `S1/run1.py` (1 回)、`S1/base.sh`・`exp1.sh`〜`exp3.sh`・`main3.sh` (並び)、`S1/summ.py` (集計)、`S1/bench58.py` (58 問)。
  結果は `S1/res.jsonl`、ログは `S1/logs/<タグ>_<問題>_s<種>.log` (HiGHS は `highs_<問題>_s<回>.log`)。
- ENOMOTO のログの時刻は MIP の時計 (前処理の後から) なので、`solve returned` の全体の時間より 3.5〜4.6 秒小さい。

## 2. physiciansched6-2

### 事実 (ログ)

| | HiGHS | ENOMOTO 既定 |
|---|---|---|
| 前処理の後 | 8861 行 × 4608 列 (1.1 秒) | 9872 行 × 4981 列 (プロービングの同値 1084 組を代入した後) |
| 根の LP | 47410.8 (2.6 秒) | 48583.1 (1.75 秒) |
| 根の下界 | 49324 (7.7 秒、最適値) | 49324 (カットのラウンド 3、9.1 秒)。その後ラウンド 11 まで動かずに回る (13.2 秒) |
| 暫定解 | 8.5 秒にサブ MIP (`L`、解のない根なので RENS) が 49324 | Local-MIP 49624〜49925 → 根の RENS 49424 (15 秒、自由列 1069 のサブ MIP が 0 ノードで「最適」) → 根の RINS は固定率 0.88 (自由列 1069) で 0.2 秒で実行不能 (近傍に 49424 より良い解なし) → **木の RINS (202 ノード目、自由列 1472〜1527) が 49324 (51〜60 秒)** |
| 木 | 1 ノード | 根の強分岐 5 秒、木の開始 20.6 秒、全ノードの下界が 49324 のまま約 200 ノード |
| 全体 | 8.5 秒 | 56〜73 秒 |

- 既定の速い 1 回 (`m_def` 種 3、22.0 秒) は、カットのループ中に Local-MIP が 49424 を出し、根の RINS の固定率が **0.71** (自由列 1794) になって 3.2 秒で 49324 を見つけた回。
  固定率 0.88 だと外れ、0.68〜0.71 だと当たる (下の試作の回も同じ)。
- 既存の試作の当たりつけ (1 回ずつ): `HO1_ROLEEARLY` 44.1 秒 (木の local branching が 40 秒に 49324)、`ROBUST_STALL=rw` 69.8 秒、`ROOTLP_BOTH` 55.4 秒。
  前の調べ (`analysis/physprimal_20261024.md`) の頃は根の RINS が時間切れで解を出さなかったが、今の既定では RINS は 0.2 秒で終わり、近傍に解がないのが原因。

### 試作 `ENOMOTO_MIP_S1_RINSWIDE=k` (`src/mip/heuristics.rs` の `rins`)

根 (サブ MIP でない、ノード 1 以下) の RINS が解を出さず短く (`ENOMOTO_T_MIP_S1_RINSWIDE_SECS` 秒、既定 1.0 未満で) 終わったら、近傍に良い解がないと見て、
暫定解と LP 解で一致する列の固定を乱数で `ENOMOTO_T_MIP_S1_RINSWIDE_DROP` (既定 0.25) × 回 の割合だけ外し (近傍を広げ)、最大 k 回やり直す。
前の回が 1 秒以上かかったらやめる (近傍を広げるほど重くなるので)。

| 回 | 既定 (6 回) | RINSWIDE=2 |
|---|---|---|
| 時間 | 56.0・60.8・67.4・59.7・73.1・22.0 | 25.9・20.1 (当たりつけ)、24.7・19.9・20.7 (本計測) |
| 49324 を出したもの | 木の RINS (5 回)、根の RINS (1 回) | 根の RINS: 1 回目のやり直し (外す 0.25、0.3〜0.7 秒) 3 回、2 回目 (外す 0.5、固定率 0.68、自由列 1921、5.3〜5.7 秒) 2 回 |

### 残り (推測を含む)

- HiGHS は解のない根の RENS 1 回で 49324 を出す (根の LP の頂点が違うので近傍が違う、推測)。ENOMOTO の RENS (自由列 1069) の近傍の最良は 49424。
- カットのラウンド 4〜11 は目的値が 49324 のまま約 4 秒回る (目的値は整数刻みのはずだが、整数刻みでの停滞の判定 `CUT_INTOBJ_STALL` に掛かっていない。理由は未確認)。
- 根の強分岐 5 秒と、木の 1 ノードの LP (最初の LP 9447 反復/10 ノード) は重いが、解が出れば 1 ノードで閉じるので今回は効かない。

## 3. hypothyroid-k1

### 事実 (ログ)

| | HiGHS | ENOMOTO 既定 |
|---|---|---|
| 前処理の後 | 5189 行 × 2595 列 (1.4 秒) | 5190 行 × 2596 列 (LP プロービングの根の LP 3.1 秒を含む) |
| 根の LP | −2902.85 (5.0 秒までに) | −2902.85 |
| 根のカット | (下界の表示は解が出たときに −2851) | 20 ラウンド、11.4 秒 (1 ラウンド 0.45〜0.6 秒、分離 0.3〜0.4 秒で候補 2500 本から 1〜2 本)、−2902.85 → −2886.50 |
| 暫定解 | 5.0 秒に randomized rounding −2692、10.2 秒にサブ MIP (`L`) −2851 (最適) | FJ・Local-MIP の −1〜−5 だけ → カットの後に解発見スレッド (11.6〜12.6 秒に開始) → **主スレッドの内点法の丸め (7.2〜7.6 秒、解なし) が終わった直後** (19.1〜20.3 秒) に −43 と −2851 を取り込む |
| 証明 | −2851 と同時に閉じる (1 ノード) | 根の目的関数のプロービング (4 秒) で証明 (23.7〜24.6 秒) |
| 全体 | 10.2〜10.7 秒 | 27.9〜29.3 秒 |

- 解発見スレッドの解は、主スレッドが根のヒューリスティクスの合間に `poll_find_thread` で取り込む。内点法の丸めは止めの合図を時刻でしか見ないので、
  その間は取り込まれない。3 回とも「内点法の終わり ≈ 取り込みの時刻」(12.06 + 0.2 + 7.2 ≈ 19.07 など)。
- カットのラウンドの上限を 5 にする (`ENOMOTO_T_MIP_CUT_ROUNDS=5`) と **39.5・39.8 秒に悪化**: 解発見スレッドは 4.0 秒に始まるが取り込みは内点法 (9.0 秒) の後の 13.3 秒、
  さらに裏のカットのスレッドが 33 ラウンド続け、決定的な待ち (`background cuts: determ: waited 15.83s`) が入る。主のループを早く止めても、時間は裏のカットの待ちに移る。

### 試作 `ENOMOTO_MIP_S1_IPMFIND=1` (`src/mip/solver.rs` の根の interior rounding、`src/simplex/mip_lp.rs` の `with_ipm_abort`)

解発見スレッドが走っている間は、根の内点法の丸めの内点法に「解発見スレッドの出力が空でなくなったら止める」条件を渡す (内点法の見張りのスレッドが 5 ミリ秒ごとに
時刻と一緒に確かめる)。止まった内点法は「失敗」と同じ扱いで、次のヒューリスティクスの前に解を取り込む。

| | 既定 (6 回) | IPMFIND (5 回) |
|---|---|---|
| 時間 | 28.3・29.3・29.1・28.1・27.9・28.8 | 23.6・24.0 (当たりつけ)、23.8・24.4・23.6 |
| 内点法 | 7.2〜7.6 秒 (解なし) | 1.1〜1.3 秒で打ち切り |
| −2851 の取り込み | 19.1〜20.3 秒 | 13.2〜13.8 秒 |

### 残り (推測を含む)

- 根のカットの 11 秒 (目的値の大きさに比べて伸びが小さいが、相対変化 1e-4 を越えるラウンドが混じり停滞と数えられない)。主のループだけ早く止めると裏のカットの待ちに移るので、
  裏のカットも一緒に止める形が要る。
- 目的関数のプロービングでの証明 4〜5 秒。HiGHS は −2851 が出た時点で下界も −2851 (被約費用の固定・伝播で閉じる、推測)。
- 解発見スレッドがカットのループの後にしか始まらない (始まってから約 1.5 秒で −2851)。

## 4. neos-860300

### 事実 (ログ)

| | HiGHS | ENOMOTO 既定 |
|---|---|---|
| 前処理の後 | 568 行 × 1219 列 (前処理 3.6 秒、その中のサブ MIP を含む) | 594 行 × 1381 列 (係数の締め 177152 個) |
| 根の LP | 2091.9 | 2210.3 (LP プロービングの後) |
| 根のカット | → 3050.0 (7.0 秒、カット 92 本・LP に 66 本) | 25 ラウンド (ラウンドの上限) で → 2694.7、クリークの判定 (fallback) は g_c 2.19e-2・g_d 1.80e-1 で使わない |
| 暫定解 | 7.0 秒にサブ MIP 3201 (最適) | 根で 4307 → 再スタート後 4070 → 木で 3900・3479・3201 (木の開始から約 5 秒) |
| 再スタート | 被約費用の固定で 8 回 (1219 → 22 列)、1 ノードで閉じる (11.2 秒) | 1 回 (57 列固定)、2 回目の根 2706 → 2769、木 230〜480 ノード |
| 全体 | 11.2〜11.3 秒 | 17.2〜21.7 秒 |

- 既存のクリークカットの使い方を変えると、どれも 0 ノードで解ける (1 回ずつ): `CLIQUE_CUTS=auto` 10.0 秒 (最初の LP でクリークを試して 2210 → 2305 で使う、
  根のループで 3019)、`=root` 12.1 秒、`=1` 12.3 秒、`CLIQUE_FB_RATIO=0.1` 11.8 秒。
  クリークなしでカットを増やす形は効かない: `CUT_STRONG_FRAC=0.1` 21.3・21.6 秒、`CUT_PHASE2_AT_CAP` 27.8 秒、`CUT_ROUNDS=60` 27.2 秒。
- 前の調べ (`analysis/drayage_clique_20261020.md` §2) で fallback の比の閾値 0.5 が neos-860300 を落とすことは書かれていた (「比の閾値次第 (未調整)」)。
  その表の値では、比 0.1 にしても 30n20b8 (g_c/g_d 0.0045)・timtab1 (0.0045)・misc07 (0.0013)・beavma (0.0013)・dcmulti (0.0003) は使わないまま (推測、測ったのは neos-860300 だけ)。
