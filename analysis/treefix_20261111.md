# TREEFIX: 木の中で暫定解が良くなったら、大域的な伝播・打ち切り値つきのプロービングで範囲を締める仕事 (2026-11-11)

bench に使う環境変数: `ENOMOTO_MIP_TREEFIX=pcu` (本命の形。`1` は `pcur`)。比べた形は `pcurR`・`pcuR`・`pcu`。
計測: 58 問 (analysis/cbcimpl_20261029/probs.py)、60 秒・4 スレッド・種 1〜2 (`ENOMOTO_MIP_THREADS=4 ENOMOTO_T_MIP_SEED=s`)、
既定 (cand1108zd + DRCR、6787e9cd の wheel) と対。スクリプトは analysis/treefix_20261111/ (run.py・summ.py)。

## 結論 (先に)

- `pcu` (仕事だけ、`r`・`R` なし) は 58 問で SGM 17.74 → 17.65 秒 (-0.5%)、95% 区間 [-4.0%, +3.1%]、解けた回 81 → 83、
  種をまたいでそろって遅い問題なし、矛盾 0。取り込みの基準 (1)〜(4) は満たす。(5) の余分な時間は主のスレッドには出ないが、
  ヒューリスティクス役のスレッドの時間を mc11 で最大 7.9 秒 (LP のプロービング 463 回、固定 0) 使う (1 回あたりの平均 0.2 秒)。
- `R` (固定がたまったら木の中の再スタートの判定に渡す) は害: 主の暫定解が良くなるたびに `inc` の判定 (ノード数の上限なし) を立てるので、
  仕事が 0 回の qnet1 でも木の中で再スタートし 3.2〜3.6 → 4.9〜5.2 秒 (2 種とも、ENOMOTO_MIP_LOG で確かめた)。
  `pcuR` は +0.2% [-5.5%, +5.0%] (区間の上が基準の境目)、`pcurR` は +2.7% [-1.5%, +7.4%] で基準 (1) を満たさない。
- 効き目は小さい (推測ではなく数の上で): 締まるのは csched008 (1 回 25〜41 本固定、死んだ未処理ノード 370〜581)・10teams・neos17
  (LP のプロビングで 41〜44 本固定)・eil33-2・neos-911970・neos-3083819-nubu など。時間が 2 種そろって縮んだ問題はない。
- 未処理のノードに共通する範囲 (4、`o`) は作っていない (下の「作らなかったもの」)。

## 作り (事実)

- 本体は src/mip/treefix.rs (solver.rs の子モジュール)。solver.rs への差分は呼び出しの数行と、既存の 2 関数の切り出し
  (`ho2_global_obj_prop` の本体を `global_obj_prop(all, tag)`、`gap1_lp_probe` の本体を `lp_probe_cutoff(tmax, max_gap, itlim, tag)`。
  既定の振る舞いは変えない)。`root_redcost_fixing` の本体には手を入れていない (RCSTRONG と範囲を分けた)。
- 起動: 木を分け合う探索で、番号の最も大きい従 (ヒューリスティクス役を受け持つスレッド、`heur_role_count` が 1 以上) が、共有の最良値が
  前に見た値より下がったら、潜りの子がないとき (木のループのヒューリスティクス役の判定の前) か ALNS の合間に 1 回だけ回す。
  木に入って最初に見た値では回さない。仕事の時間の合計は木の始まりからの経過時間の `ENOMOTO_T_MIP_TREEFIX_FRAC` (0.2) 倍まで。
- 文字:
  - `p`: 締めた大域的な範囲での行の伝播と、打ち切り値による目的関数の行 (`global_obj_prop` の本数を問わない形)。
  - `c`: 根の定義域とカットの行で LP を解き直し (反復 5 万まで)、被約費用で締める。
  - `u`: 打ち切り値つきの LP プロービング (GAP1 の `u`)。1 回 `ENOMOTO_T_MIP_TREEFIX_PROBE_SECS` (時間上限の 0.02 倍)、相対ギャップ
    `ENOMOTO_T_MIP_TREEFIX_PROBE_MAX_GAP` (0.01) 超なら試さない。子の LP の反復は根の解き直しの反復の 0.5 倍 (最低 100)。
  - `r`: RCUNION (根のカットの各ラウンドの LP の被約費用) を集め、主の `root_redcost_fixing` が当てる (`ENOMOTO_MIP_TREE4_RCUNION` と同じ)。
  - `R`: 仕事で新たに固定した列があれば主に `TREE_RESTART=inc` の判定を頼み、主のノード数の上限を外す。
- 配り方: 締めた範囲は自分の大域的な範囲と共有の範囲に入れ、ほかのスレッドは既存の 64 ノードおきの `sync_global_bounds` (決まった点) で取り込む。
  取り込んだ後、手元の待ち行列で大域的な範囲に反する分枝を持つノード (取り出せばすぐ刈られる) を数える (「死んだノード」、数えるだけ)。
- 根で矛盾 (伝播の矛盾・LP が打ち切り値以上) したら、主が次の木のループの頭で最適として終える。
- 集計は主の `join_workers` で `TREEFIX: summary` の 1 行。`ENOMOTO_MIP_TREEFIX_LOG` で仕事ごとの行も出す。

## 考え (推測)

- 各ノードはすでに打ち切り値の伝播を自分で行うので、大域的に締めた分の節約は「死んだノードを刈る」ことに限られ、刈れたのも
  csched008・10teams・mc11 の数百ノード程度。backlog の見込みどおり小さい。
- `R` の害は再スタートの判定が粗い (固定の割合だけで、木の進み具合を見ない) ことによる。`TREE_RESTART=1` (HiGHS 式) の判定に
  固定の数を渡すだけにすれば害は消えると思うが、`TREE_RESTART` 自体が単独で負けている。
- ヒューリスティクス役の大近傍探索の時間を削る分は、平均 0.2 秒 (60 秒 × 1 スレッドの 0.3%)。mc11 のように固定の出ないプロービングを
  繰り返す問題があるので、「プロービングで固定 0 なら次からは回さない」などの手当てをすれば (5) の余分も 1 秒程度に収まる見込み。

## 作らなかったもの

- (4) 未処理のノードに共通する範囲 (`tighten_by_open_nodes`): 複数スレッドでは、ノードが共有の待ち行列と各スレッドの手元の間を
  移る途中のものを漏らさず数える仕組み (受け渡しの錠の中で各スレッドの箱を広げるなど) が要り、漏らすと誤答になる。効き目の見込みが
  小さい (締まっても主に再スタートで効く) ので後回しにした。
- 58 問で当たらなかったので、Mittelmann の 47 問は測っていない。
