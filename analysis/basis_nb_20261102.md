# 保存した基底の上限・下限の置き場所を次の求解に渡す試作 `ENOMOTO_MIP_BASIS_NB` (2026-11-02)

`Basis` (src/simplex/mip_lp.rs の `basis()`) は非基底の列・行が上限・下限のどちらにあるかを持つが、`set_basis` は基底に入る列の集合だけを使い、
解き始めの置き場所は `nb_hint()` (直前に解いた点 `self.x` からの推し量り) で決めている。保存した置き場所を、打ち切られた求解の続き
(`resume_nb`) と同じ形の希望 (-1 / +1) として次の求解の `sid::set_warm_nb` に渡す試作を入れ、木の大きい問題などで測った。
置き場所の食い違いの量そのものは、別のセッションの analysis/basis_nb_diag_20261102.md (58 問の上限の見積もり) にある。

- 土台: 421913d6 + e1a3eb94 (この試作は 9dd449d4・58d95d63)。4 スレッド・60 秒、ソルバーは同時に 1 つ、`ENOMOTO_MIP_LOG=1`、クラウドの 4 コアの機械。
- 台本・ログ・集計: analysis/basis_nb_20261102/ (`run.py` が解いて `logs/<問題>_<設定>_<回>.log` と `res.jsonl`、`summ.py` が表を作る。
  `summ_main.txt` (6 設定 × 12 問 × 2 回)、`summ_w.txt` (5 問の追加の回を含む)、`summ_all.txt`)。

## 1. 試作 (既定では使わない)

- `TwoStageLp::set_basis_nb(b, skip)` (src/simplex/mip_lp.rs): `set_basis(b)` に加え、`b` の Lower → -1、Upper → +1 (行は σ を見てスラックの
  下限 -1 / 上限 +1 に直す) を `basis_nb` に覚える。`skip` の列 (分枝で締めた列)、Basic の列 (修復で基底から外れた列を含む)、修復の後に基底に
  入った列は 0 (今の推し量りのまま)。求解のとき (`solve_inner`) に `nb_hint()` を作ってから、希望の側の境界が有限で固定 (下限 = 上限) でない列、
  等式でない行 (スラックの上限側は幅が有限のときだけ) について希望で上書きして `set_warm_nb` に渡す。希望は次の求解 1 回で使い切り、行・解が
  変わったら捨てる (`clear_memo`)。列の境界の変更 (ノードの分枝の積み直し) では捨てず、求解のときの境界で上の判定をする。
- 試作を使うときは `compute_basis` が、範囲行でスラックが上限 (行の幅) にある行を反対の側として返す (既定はスラック 0 の側とだけ返す)。
- 切り替え `ENOMOTO_MIP_BASIS_NB` (`1` で全部、カンマ区切りで場所を選ぶ):

  | 場所 | 呼び出し元 | 渡すもの |
  |---|---|---|
  | `t` | 木のノードの基底の復元 (`restore_node_basis`、兄弟ノード・待ち行列のノードとも) | 列と行。`skip` = ノードの根からの分枝の列 |
  | `s` | サブ MIP の根の初めの基底 (`SUBMIP_BASIS`) | 列だけ (行は空で修復に任せる) |
  | `b` | 裏のカットの写しの根 (`BG_ROOT_BASIS`。解探索のスレッドの根も同じ道) | 列と行 |
  | `w` | `b` を、主の根の LP が `ENOMOTO_T_MIP_BG_CUTS_BASIS_X_SECS` (1 秒) 以上の問題の裏のカットの写しだけに (`ENOMOTO_MIP_BG_CUTS_BASIS_X=lpw` と同じ条件) | 列と行 |
  | `r` | 再スタートの後の根 (`RESTART_BASIS`) | 列と、照らし合わせた行 |

- 診断の行 (既定でも `ENOMOTO_MIP_LOG=1` で出る。振る舞いは変えない): 終わりに
  `MIP: basis nb diag: tree first LPs restored … others …; root LPs: submip … bgcopy … find … restart … main …; nb hints applied …`。
  木 (サブ MIP の外、全スレッド) のノードの最初の LP を「基底を復元した直後」と「それ以外 (潜りの子など)」に分けた回数・反復、根の LP の
  種類ごとの回数・反復・時間、希望を使った求解の数・有効だった希望の数・推し量りから変えた数。プロセス全体の累計。

### 2.2 場所ごとの見立て

1. **裏のカットの写し (`b`) だけがはっきり効く**: 写しの根の LP は、主の基底の集合だけを渡す既定では physiciansched6-2 で 6368〜15503 反復
   (5〜9.5 秒)、neos-1171448 で 3540 反復、h80x6320d で 5 反復、binkar10_1 で 3.7 反復のところが、すべての回で **1 反復**になった
   (列の値を渡す `ENOMOTO_MIP_BG_CUTS_BASIS_X` と同じ効き。値を渡さず置き場所だけで足りる)。
2. **ただし条件なしの `b` は h80x6320d で損をする** (`BASIS_X=1` の mc11 と同じ、道が変わる損): 4 回とも 44〜56 秒・245〜369 ノード
   (def は 33〜42 秒・93〜139 ノード)、再スタートの後の根の LP が 4 回の合計で 5 → 8 回、うち 1 回は時間切れ。根の LP が 0.1 秒程度の問題では写しの解き直しは元から
   軽く、主と同じ頂点から始めると裏のカットの選ぶ道が変わる。mc11 も `b` で 25.7 → 33.0 秒だが、写しを動かさない `w` でも 32.0 秒・`t` で 26.5 秒、
   def の 4 回が 15〜31 秒と揺れが大きく、この回数では mc11 の損は言い切れない。
3. **`w` (根の LP が 1 秒以上の問題だけ `b`) は h80x6320d の損を避ける** (`summ_w.txt`、4 回): h80x6320d 4/4・38.9 秒・119 ノード (写しには
   渡らない)、neos-1171448 3/4・50.1 秒 (写しの LP 3540 → 1)、physiciansched6-2 2/4・40.5 秒 (写しの LP → 1)、mc11 4/4・32.0 秒 (写しには渡らない)。
   `tw` (t と w): neos-1171448 4/4・44.2 秒、physiciansched6-2 2/4、h80x6320d 4/4・39.6 秒、mc11 4/4・30.2 秒。
4. **木のノードの復元 (`t`) は揺れの範囲**: 復元直後の LP の 1 回あたりの反復は n5-3 415 → 299、h80x6320d 544 → 466、qiu 77 → 67 と減る問題も
   あるが、neos-1171448 2010 → 2226・mc11 395 → 430・eil33-2 32 → 40 と増える問題もあり、木に触れない `b` でも 0.91 倍になる揺れの中に収まる。
   推し量りから変えた数は 1 求解あたり 25〜60 (n + m の 1% 未満) で、そのうち warm start が実際に希望の側に置く (被約費用の符号がはっきりしない)
   列はさらに少ない。analysis/basis_nb_diag_20261102.md の見積もり (保存した側に置き直せる列は 1 LP あたり 1 列以下、反復の差の大半は
   「遠いノードの基底」から) と合う。
5. **サブ MIP の根 (`s`) は効かない**: 希望で変えた数は 1 求解あたり 0〜5 (サブ MIP では多くの列を固定し、固定した列は推し量りのまま)、
   根の LP の反復は 1.04 倍。analysis/basis_nb_diag_20261102.md の通り、サブ MIP の根は 82% が修復の後の基底が特異で捨てられており、そちらが先。
6. **再スタート (`r`)**: 再スタートのある 3 問で、再スタートの後の根の LP の反復は変わらない (mas76 89・binkar10_1 592・h80x6320d 889)。
7. physiciansched6-2 の `all` の 0/4 と `s` の 0/2: 解けた・解けないの分かれ目は、既定と同じく根のカットのループの道 (500 本で 49057 に着く道か、
   600 本で 49224 に着く道か) と、Local-MIP・RINS が 49324 を見つけるか。`all_2` は暫定解のない RENS のサブ MIP が 36 秒かかって (根の LP は 317 反復、
   置き場所とは別の所) 暫定解なしで終わった。`all` が 4 回とも解けないのは目立つが、`b`・`t` それぞれでは def と並ぶので、`s` を含む組み合わせの
   害かどうかはこの回数では分けられない (`s` 単独の 2 回も解けない)。58 問で確かめるなら `s` は入れない。
8. 10teams の `all`・`t`・`b`・`r` の 0 ノード (5〜6 秒) は、def でも 4 回中 3 回が 0 ノード (6 秒) で、根のヒューリスティクスで最適値が
   出るかの揺れ。試作の効き目ではない。

## 3. 58 問・Mittelmann で確かめる形の提案

- 候補は **`ENOMOTO_MIP_BASIS_NB=w`** (裏のカットの写しの根だけ、主の根の LP が 1 秒以上の問題)。`ENOMOTO_MIP_BG_CUTS_BASIS_X=lpw` と同じ所に
  同じ条件で効き、列の値を写しに渡さない (写しの LP は主の基底から 1 反復で済み、写しの `x` は写し自身の解になる) 点だけが違う。
  bench13 で `bgx` (`BASIS_X=lpw`) を確かめているなら、`w` は `bgx` と比べて差がないか (同じ効きか) を見る形でよい。
- 形: 今の既定 (def) と `w` を 58 問 (bench12 の組) × 2 回 + Mittelmann。見る所: physiciansched6-2・neos-1171448・neos-960392 (写しの LP が重い問題)
  の解けた数と時間、写しの根の LP の反復 (`MIP: basis nb diag` の `bgcopy`)、根の LP が 1 秒前後の問題で道が変わって損をしていないか。
- `t` は 58 問で測るほどの差が見えない。続けるなら、analysis/basis_nb_diag_20261102.md の 4 節の通り、共有の待ち行列のノードやサブ MIP の根で
  修復の後の基底が特異になって捨てている分を先に手当てする。`s`・`r` は入れない。
