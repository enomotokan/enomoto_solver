# neos-2978193-inde: 木が HiGHS より大きい理由の調査 (2026-10-20、木の比較)

- 環境: Linux x86_64、**CPU 4** (専用コンテナ)、ブランチ `inv/neos2978193b-20261020` (develop bc89ad1 + 9 つの調査の試作、c346265) +
  このメモの試作 (どれも既定では無効なので既定の動作は c346265 と同じ)、highspy 1.15.1、HiGHS 1.15.1 を計測用パッチでビルドしたもの
- 計測: ENOMOTO `ENOMOTO_MIP_THREADS=4` + `solve(..., 4)` (「4 スレッド」)、HiGHS `threads=4`。時間上限 300 秒 (一部 60 秒)。
  木の比較は「木だけ 1 スレッド」= `ENOMOTO_MIP_THREADS=4` + `solve(..., 1)` で、**打ち切り値に最適値を与えた証明だけの比較**
  (ENOMOTO `ENOMOTO_MIP_CUTOFF=-2.38805`、HiGHS `objective_bound=-2.38805`)。ソルバーは同時に 1 つだけ
- ログ・スクリプト: `work_tree/` (`exp.sh` 1 回の実行、`tree_stats.py` 葉の終わり方・分枝した列・深さ、`depth_lp.py` 深さごとの LP 値、
  `replay_lp.py` HiGHS の分枝を固定した LP、`side.sh` 副作用の確認)。HiGHS の計測用パッチは `scripts/highs_instrument_tree.patch`
  (使い方は `scripts/highs_instrument.md` の最後の節)
- 新しい診断: `ENOMOTO_MIP_TREE_LOG` (ノードごとに `ENODE d= r=終わり方 lp= rows=`、分枝ごとに `EBR d= col= val= lp= rows=`、
  プールのカットを LP に戻したとき `EPOOL`)

## 結論

**HiGHS の木が小さいのは、双対証明から作る「衝突カット」(`HighsCutGeneration::generateConflict`) のため** (事実、下の 1)。
HiGHS は木のノードの LP に連続列の局所的な境界を渡さない (`flushDomain` が `removeContinuousChangedCols`) ので、LP の双対は
容量制約の行を通して施設の 0-1 列 y に乗り、証明は y だけの短いもの (平均 27 列、連続列 0) になる。これを CMIR で強めた
カット (平均 18 列) をカットプールに入れ、伝播とノードの分離で使う。
ENOMOTO は閉じた施設の x (324 列ずつ) を LP の境界で 0 に固定するので、証明はその x の被約費用に乗り平均 5300〜5500 列、
密すぎ・局所的で、ほとんど働かない。

ただし、ENOMOTO で証明を HiGHS と同じく短くし (試作 1・2)、CMIR で強めてカットプールにも入れても (試作 3・4)、
木は 5800〜12000 ノード (1 スレッド、打ち切り値あり) で HiGHS (635〜4361) との差は縮みきらなかった。4 スレッドの終わるまでの時間も
既定の揺れの範囲 (既定 8 回 中央値 115 秒、試作 9 回 中央値 111 秒)。**残る差の原因は特定できていない** (推測は最後の節)。
副作用の確認では binkar10_1 が 25〜29 秒 → 15〜19 秒と良くなり、mas76 が 11 秒 → 13.5 秒とやや遅くなった (§5)。既定にする候補ではない。

## 1. HiGHS の何を外すと木が大きくなるか (HiGHS、打ち切り値あり、種 0/1/2、300 秒)

| HiGHS の設定 | ノード数 (種 0 / 1 / 2) | 時間 [秒] |
|---|---|---|
| 既定 | 635 / 4361 / 1171 | 9.4 / 53.3 / 16.3 |
| 衝突スコアなし (`HIGHS_CONF_W=0`) | 7795 / 1914 / 2522 | 94.6 / 29.4 / 35.0 |
| **衝突カットを作らない** (`HIGHS_NO_GENCONF`) | **22588 / 22324 / 22739 (3 回とも時間切れ)** | 300 |
| **ノードでの分離なし** (`mip_allow_cut_separation_at_nodes=false`) | **26023 / 26449 / 28730 (3 回とも時間切れ)** | 300 |
| 分離器を全部止める (`HIGHS_SKIP_SEP=012 HIGHS_NO_IMPLB HIGHS_NO_CLQ`: 根のカットもなし、プールの衝突カットだけ) | **389 / 1058 / 772** | 12.4 / 16.8 / 12.9 |
| 退化した基底変数の双対を使わない (`HIGHS_NO_BDD`: `computeBasicDegenerateDuals` を飛ばす) | 1904 / 722 / 4100 | 29.5 / 15.6 / 61.8 |

- 衝突カット: 種 0 で 240 本作る (`HGC ok`)。元の証明は平均 27 列 (3〜14 列のものが多い)、**連続列は全部で 0**、カットは平均 18 列。
  定義域の矛盾 (葉) の理由はほとんどカットプール (`HINF cutpool=87`、全 97 のうち)。衝突カットを作らないと cutpool=0 になる。
- 分離器を全部止めた回は根のカットがなく、葉の LP は 396〜403 行 (衝突カットは LP にほとんど入っていない)。つまり衝突カットは
  主に**伝播**で効いている。ノードでの分離を止めた回は、根のカット 236 本が年齢で外れずに LP に残り続け、葉の LP はいつも 632 行
  だった (衝突カットの本数・長さは既定と同じ: 60 秒で 1719 本、平均 18 列)。なぜこちらが崩れるかは確かめていない (推測は最後)。
- 衝突スコア (分枝スコアの衝突の項。退化係数が約 40 なので HiGHS のスコアはほぼこの項): 外すと中央値で約 2 倍。主因ではない。
- HiGHS の葉の終わり方 (種 0): 葉 302 = LP の目的値の打ち切り 223 + 定義域の矛盾 79。深さ 13〜15 が中心。分枝は 64 列のうち 48 列。
  子はほぼ常に上 (y = 1、施設を開ける) へ進む。

## 4. 試作 (どれも既定では無効)

1. `ENOMOTO_MIP_LP_INT_BOUNDS` (src/mip/solver.rs `sync_lp`、`lp_int_bounds`、局所的な被約費用の固定の後の解き直しの判定):
   HiGHS と同じく、木のノードの LP には連続列の大域的な境界だけを渡す (伝播で締まった連続列の境界は定義域にだけ置く)。
   LP の値は (行と整数列の境界から導かれる限り) 変わらない。証明が連続列の被約費用に乗らなくなる。
2. `ENOMOTO_MIP_PROOF_SIDE_REDUCE` (src/mip/solver.rs `add_proof_from`、`proof_side_reduce_mode`): 証明の列を大域的な境界で右辺に
   移す条件を「ノードの境界が大域と同じ」から「最小活動量を決める側 (係数が正なら下限、負なら上限) が大域と同じ」に広げる
   (このノードでの破れの幅は変わらない)。1 との組み合わせで、LP では x が [0, 1] のまま被約費用が正になるので証明から外れる
   (1 だけでは定義域の x の上限が 0 なので外れない)。`=1` は常に、`=dense` は「移さないと密すぎて捨てる証明」か「移すと 1/10 未満に
   縮む証明」だけ作り直す。常に移すと証明が大域的に弱くなり (移した列は他のノードでその列の境界が締まっても効かない)、
   mas76 が 11 秒 → 35 秒に悪化したので `=dense` を作った (mas76 13.5 秒、担当の問題の証明は平均 8.8 列のまま)。
3. `ENOMOTO_MIP_PROOF_CMIR` (src/mip/solver.rs `add_proof_cmir`): 受け入れた証明を HiGHS の `generateConflict` と同じく CMIR で強めた
   カット (大域的な境界、丸めの基準はノードの最小活動量の点を証明の超平面まで縮めた点) を、右辺を固定した行として証明のプールにも足す。
   60 秒で 364 本試して 364 本作れた。
4. `ENOMOTO_MIP_PROOF_CMIR_POOL`: 3 のカットをカットのプールにも入れる (待ち行列から取り出したノードで破れていれば LP に戻る)。
   プールから LP に戻すラウンドは 5078 ノード中 91 回、1 回 1〜3 本だった (`EPOOL`)。
5. `ENOMOTO_MIP_HIGHS_CONFLICT_SCORE` (src/mip/domain.rs `analyze_multi_bumps`、src/mip/pseudocost.rs `bump_conflict`): 衝突スコアを
   HiGHS と同じく、解析で説明に使った境界の変更全部の列で上げる (作れた衝突のリテラルでは上げない)。`ENOMOTO_T_MIP_CONFLICT_WEIGHT`
   と併用しないと分枝に効かない。効果なし。
6. `ENOMOTO_MIP_PROOF_FIXPOINT`: ノードの伝播で、証明の締め付け → 行の伝播で境界が変わる間、証明を調べ直す (HiGHS は行・カット・
   衝突を 1 つの伝播の不動点まで回す)。効果は揺れの範囲。
7. `ENOMOTO_MIP_CHILD_HIGHS` (`=up` で常に上): HiGHS の子の選び方 (`kHybridInferenceCost`)。効果なし。
- 診断: `ENOMOTO_MIP_TREE_LOG`、`ENOMOTO_MIP_DEBUG_PROOF` で受け入れた証明の長さ (`PROOF ok len`) と CMIR (`PROOF cmir`)、
  `ENOMOTO_MIP_LOG` で `proof CMIR cuts: tried / added`。

## 6. 失敗・取り下げたもの

- 衝突スコアを分枝に使う (`ENOMOTO_T_MIP_CONFLICT_WEIGHT`): 既定の証明では 9622/11277 → 7061〜7735 (1 回ずつ) と少し良く見えたが、
  証明を短くした上では 5797 → 12235 / 10295 と悪化。HiGHS でも外して 2 倍程度。主因ではない。
- 子の選び方を HiGHS に合わせる: 効果なし。
- 証明を不動点まで伝播: 揺れの範囲。
- 証明の側別の短縮を常に行う (`SIDE_REDUCE=1`): mas76 で 4 倍遅い。`=dense` に絞った。
- 「木の後の待ち」(上の §3 の注意): 見誤り。サブ MIP の中止 (`join_submips` の前に止める合図) と研磨の LP の時間の上限を試作したが、
  待ちは存在しなかったので取り下げた (コミットしていない)。

## 7. 推測 (確かめていない)

- ENOMOTO の残りの差は、**LP に残る根のカット**と関係していると見る。HiGHS でもノードの分離を止めて根のカットが LP に残り続けると
  (632 行固定) 3 回とも 26000 ノード超で崩れ、カットを全部止めると 389〜1058 ノードで既定より良い。ENOMOTO は再スタートでカット 486 本を
  問題の行にし、木の LP は 950〜1340 行。カットで LP の頂点が変わり (y が 0.509… のような値)、分枝の候補と証明の形が HiGHS と違う。
  ただし ENOMOTO で根のカットをなくすと (前の調査・上の表) 木は大きくなるので、「カットを外す」だけでは足りない。HiGHS の
  「カットなし + 短い衝突カットの伝播」の組み合わせを ENOMOTO で再現できていない理由 (証明のプールの伝播の仕方、衝突のプール、
  分枝の選び方の違い) は分からない。
- 次に調べるなら: (a) HiGHS の分離器なしの設定と ENOMOTO の根のカットなし + 試作 1〜3 の木を、分枝した列と深さで並べる
  (どちらも LP は 396 行前後で比べやすい)、(b) ENOMOTO の証明のプールの伝播 (`apply_dual_proofs`) が HiGHS のカットプールの伝播と
  同じ締め付けを出すかを、同じノードで比べる。
