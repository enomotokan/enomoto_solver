# 時間の上限の超過 (60 秒の上限で 61〜67 秒で返る回) の原因と試作 `ENOMOTO_MIP_OVERRUN3` (2026-11-03)

- 機械: 4 CPU。ソルバーは同時に 1 つだけ動かした。highspy 1.15.1。4 スレッド・60 秒、`ENOMOTO_MIP_LOG=1`。
- 土台: ブランチ `ccr-1beed81b-ex0uhq` の `925975ae` (canddet + p の今の既定)。
- 秒は `run_miplib_benchmark.py --worker-ours` の `time` (`m.solve` だけ。MPS の読み込み・モデルの組み立ては含まない。壁時計はさらに 1〜4 秒長い)。
- 台本・生データは `mittelmann_ready_20261103/overrun/`:
  - `count.py` (出力 `count.txt`): bench14〜20 の jsonl から超過を数える。
  - `watch.sh 問題 上限 回数 接頭辞 [環境変数]`: `overrun_crypt_20261101/watch.sh` と同じ (上限 + 1.5 秒 (壁時計) を過ぎたら gdb で全スレッドのスタック)。
    **壁時計は MPS の読み込み (2〜4 秒) を含むので、最初のスタックは期限の少し前になる。また gdb で止める分だけ時刻が伸びる** (下の 2 節の表は gdb なし)。
  - `watch_at.sh 問題 上限 開始秒 接頭辞 [環境変数]`: 開始秒 (壁時計) から終わるまでスタックを取り続ける。`stk.py` はスタックを 1 行ずつにまとめる。
  - `ab.py 接頭辞 回数 設定 問題...`: 今の既定 (off) と `ENOMOTO_MIP_OVERRUN3=設定` (on) を交互に gdb なしで回す (`AB_TIME_LIMIT`・`AB_CFGS` で上限・片方だけ)。
    `summ.py 接頭辞` が表にする。
  - `logs/`: `base_*` 今の既定 3 回ずつ (gdb あり)、`at1_*`・`at2_*`・`zilt_*` 期限の直後のスタックと試作の途中、`ab*`・`same*`・`long600*` 比べ (gdb なし)。
    `ab2` の app1-2 は 3 回とも回の番号 0 で回したので、ログは最後の 1 回だけ残る (結果は jsonl に 3 回分)。

## 2. 原因 (今の既定、`base_*` の 3 回ずつと期限の直後のスタック)

| 問題 | 今の既定 (gdb あり、秒) | どこで超えるか |
|---|---|---|
| radiationm40-10-02 | 65.14・61.71・61.29 | **裏のカットのスレッドの zerohalf の分離** (`zerohalf_cuts_with` の mod 2 の消去、1 回 数秒) が止めの合図・期限を見ない。主は `BgCuts::finish` で待つ (`background cuts: no result (waited 4.86s)`) |
| sorrell3 | 61.85・62.20・62.25 | (a) 根の LP が期限で止まった後、**双対単体法が「特異基底の破綻」として解き直し** (`solve_slope_intercept_dual_retrying`) を始め、最初の LU 分解 (`warm_start_basis` → `factorize_flat_markowitz`) に数秒。(b) その後 FJ のスレッドを待つ間に受け取った Local-MIP の解の **twoopt** (既定、期限を見ない) と oneopt (0.5 秒) |
| app1-2 | 60.06・60.57・60.88 | **根の局所探索** (`local_search_heur`) の時間の枠 (上限の 5% = 3 秒) が期限までの残りで切られず、期限の 1 秒前に始めて 2 秒越える |
| supportcase42 | 60.24・60.43・61.79 | 根の LP (双対単体法と内点法の競争) が期限を 0.5〜1.8 秒過ぎて止まる。期限の手前のスタックは双対単体法の定期の LU 分解 (`refactorize` → `FtLu::new`) |
| uccase12 | 60.28・60.37・60.57 | 根の LP の後の解き直しの LP が期限を 0.2 秒過ぎる程度。この 3 回は 1 秒を超えない |
| snp-02-004-104 | 60.74・60.43・60.39 | この 3 回は 1 秒を超えない (前回の調べ `overrun_crypt_20261101.md` では根の並列サブ MIP の LP) |

- 期限の後の「特異基底の破綻」は sorrell3 だけでなく uccase12・snp-02-004-104 の LP でも期限の後に出る (試作のログの
  `MIP: OVERRUN3: dual simplex singular-basis bailout after the deadline`)。期限で止めた後の後始末で特異基底の印 (`SINGULAR_BAILOUT`) が立ち、
  既定では安全モードで同じ基底・スラックの基底から解き直す (どちらも期限ですぐ止まるが、最初の LU 分解の分だけ遅れる)。印が立つ道筋そのものは調べていない。
- `bgdsecap` の 84〜97 秒は採らなかった試作の形 (裏のカットのスレッドの根の LP を厳密な重みで解く) なので、今回は見ていない。

## 3. 試作 `ENOMOTO_MIP_OVERRUN3` (既定では使わない。文字で選ぶ)

| 文字 | 直し | 場所 |
|---|---|---|
| `z` | zerohalf の分離に求解の期限を渡し、mod 2 の消去・カットの組み立ての列ごとに見て、過ぎていればカットなしで戻る (逐次の分離・並列の分離の両方) | `src/mip/zerohalf.rs` (`with_zh_deadline`)・`src/mip/separation.rs` |
| `i` | 期限を過ぎてから受け取った解は twoopt・連続変数の解き直し・被約費用の固定をしない (oneopt はする。`o` は oneopt もしない) | `src/mip/solver.rs` (`try_incumbent`) |
| `l` | 双対単体法の 1 回目が破綻で終わったとき、期限 (`ExtControl` の時刻の上限・スレッドの期限) を過ぎているか止めの合図が立っていれば解き直さず、期限で止まったものとして返す | `src/simplex/slope_intercept_dual.rs` |
| `h` | 根の局所探索の時間の枠を期限までの残りで頭打ちにする (並列の形も) | `src/mip/heur_scip.rs` (`ls_time_cap`) |
| `d` | 求解の後の木の待ち行列 (`WorkPool`、開いたノードの写し `SnapNode`) の片付けを裏のスレッドに回す (5 節) | `src/mip/solver.rs` (`solve_with`) |
| `r` | 期限までの残りが max(1 秒, 根の LP の 2 倍) 未満なら再スタートしない (4.5 節) | `src/mip/solver.rs` (`maybe_restart`) |
| `t` | 診断用: `try_incumbent` の各手順の秒をログに出す | |

- どれも期限を過ぎた後 (`h`・`r` は期限の直前、`d` は求解の後) だけ効くので、時間内に解ける問題の道は変わらない。例外は、木の探索が終わって主が止めの合図を出した後の
  従のスレッドの LP (`l` が止めの合図でも効く): 解き直さずに戻るので、終わりが少し早くなるだけ (下の 4.3)。

## 5. 上限 300・600 秒のときの超過 (`long600`・`long300`・`long300d`・`at300`)

| 問題 | 上限 | 形 | 求解の秒 | 超過 | 最大の常駐メモリ |
|---|---|---|---|---|---|
| sorrell3 | 600 | 今の既定 | 600.25 | 0.25 | |
| radiationm40-10-02 | 600 | 今の既定 | **462 秒で OOM で落とされた** (cgroup の上限約 14 GB、RSS 14.0 GB、ノード 3103・開いたノード 1000) | | 14.0 GB |
| radiationm40-10-02 | 300 | 今の既定 | 304.73 | 4.73 | 11.7 GB |
| radiationm40-10-02 | 300 | `zilh` | 302.76 | 2.76 | (同じ程度) |
| radiationm40-10-02 | 300 | `zilh` (gdb あり、`at300`) | 304.99 | 4.99 | |
| radiationm40-10-02 | 300 | `zilhd` | **300.97** | 0.97 | 11.8 GB |

- 長い上限では、60 秒のときの原因 (根の手順) はもう走っておらず、超過は**木の探索の終わり**で起きる:
  - 主が期限に気づくのはノードの区切り (0.3〜0.6 秒遅れ)。従のスレッドの合流は 0.03〜0.25 秒の回と 2.1〜4.0 秒の回がある (`long300` の既定・`zilh`:
    `tree thread 1 joined 2.142s after the stop signal`。従が何を回していたかは、スタックを取った回 (`at300`) では再現しなかったので未確認)。
  - **求解の後の片付け**: `at300` の期限の後のスタックは 5 秒の間ずっと `drop_glue::<Solver>` → `Arc<WorkPool>::drop_slow` → `SnapNode` の解放
    (`free`・`munmap`)。待ち行列の開いたノードの写しが数 GB あり、その解放が `solve` の中で走る。`d` で裏に回すと 304.7〜305.0 → 300.97 秒。
- 見積もり: 根の手順の超過 (60 秒で 1〜6 秒) は上限によらず 1 回の手順の長さで決まるので、上限 600 秒でも同じ大きさ (上限の 1% 未満)。木の探索の
  終わりの超過 (従の合流 + 片付け) は待ち行列の大きさに比例し、radiationm40-10-02 では 300 秒で 3〜5 秒。600 秒では待ち行列が 2 倍近くになるので、
  `d` なしでは 5〜10 秒程度と見込む (ただしこの問題は 600 秒ではメモリが先に尽きる)。`d` を入れると片付けの分は消え、残りは従の合流 (0〜4 秒)。
- **メモリ**: radiationm40-10-02 は 300 秒で 11.7 GB、600 秒の途中 (462 秒) で 14 GB に達して OOM。並列のセッションの記録
  (`long_b.md`) でも uccase12 が 600 秒の上限で 325 秒・13.6 GB で OOM、最大 RSS は HiGHS の 3〜21 倍。**時間の上限よりメモリの方が
  Mittelmann の長い上限で問題になる**。開いたノードの写し (`SnapNode`) を減らす・捨てる手当てが要る (今回の範囲の外)。

## 6. 判断と残り

- 6 つの直し (`z`・`i`・`l`・`h`・`d`・`r`) はどれも期限の後 (局所探索・再スタートは直前、片付けは求解の後) だけ効く短い直しで、60 秒の上限の
  1 秒以上の超過を、既定の 18 回中 6 回 → `zil` で 4 回、ab2 の 11 回中 2 回 → `zilh` で 0 回に減らし、上限 300 秒の超過を 4.7 秒 → 1.0 秒にし、
  時間内に解ける 8 問の最適値を変えない。全部入り (`zilhd`・`zilhdr`) の 1 秒以上の超過は 8 回中 2 回 (uccase12 の再スタート → `r` で手当て、
  supportcase42 の LU 分解)。**`ENOMOTO_MIP_OVERRUN3=zilhdr` を既定にしてよい候補** (既定にする前に 58 問・Mittelmann の bench で 1 回は回し、
  解けた数・SGM が変わらないことを確かめる。`h`・`r` は期限の直前の振る舞いを変えるので、境目の問題で揺れが出うる)。
- `o` (期限の後の oneopt もしない) は使わない: sorrell3 では oneopt が -1 を -11 にし、0.04〜0.5 秒で終わる。
- 残り:
  - 双対単体法の LU 分解 (大きな問題で 1 回 0.5〜1.5 秒) は途中で期限を見ない。supportcase42 の根の LP は 0.5〜1.4 秒越える (`zil` の 61.47 秒)。
    LU の途中で止めると数値の失敗として扱われるおそれがあるので、今回も手を付けていない (`overrun_crypt_20261101.md` の 4 節と同じ)。
  - 期限の後の特異基底の印が立つ道筋 (2 節) は調べていない。`l` で解き直しは止まるが、印が立つこと自体が数値の扱いの穴かもしれない。
  - `try_incumbent` の twoopt は期限を見ない。時間内でも大きな問題で数秒かかりうる (sorrell3 で 1〜4 秒)。
