# サブ MIP はどこで良い解を見つけているのか (2026-11-01)

問い: サブ MIP (RENS・RINS・LP face・根の被約費用・locks・入れ子の RENS など、`src/mip/heuristics.rs`) の解は、分枝限定法の木で
見つかっているのか、サブ MIP の根の軽いヒューリスティクス (丸め・入れ子の RENS など) で見つかっているのか。

- 機械: 4 CPU。4 スレッド・60 秒、ソルバーは同時に 1 つだけ。HiGHS (highspy) は 1.15.1。
- ビルド: ブランチ `ccr-1beed81b-ex0uhq` の `6289ec0` + 下のログの行 (今の既定 = `analysis/cand_default_20261031.md` の cand、
  `ENOMOTO_MIP_SUBMIP_HIGHS` の既定 `-s` などは環境変数なしで入っている)。
- 問題: `analysis/cbcimpl_20261029/probs.py` の 58 問を 1 回ずつ。`ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_SUBMIP_VERBOSE=1`。
- 台本とログは `analysis/submip_where_20261101/`:
  - `run.py [問題,...] [ログのディレクトリ 変数=値 ...]`: 1 問ずつ回して `logs/<問題>.log` に書く (gzip 済み)。
  - `analyze.py [ログのディレクトリ]`: 下の表を全部出す (`summ.txt`。5 節の形は `summ_nocut.txt`、5 節の 18 問だけの既定は `summ18_default.txt`)。
  - `cmp_nocut.py`: 5 節の比べ (`cmp_nocut.txt`)。

## 0. 足したログ (振る舞いは変えない)

これまでのログでは、並列のサブ MIP (根のヒューリスティクスの間に別スレッドで 3 本まで走る) の中の行が混ざり、どのサブ MIP の中の行か・
入れ子の深さが分からなかった。`ENOMOTO_MIP_SUBMIP_VERBOSE` のときだけ、次の行を足した (`SUBMIP_TAG`・`SUBMIP_CHILD`・
`submip_trace_begin`、`src/mip/heuristics.rs`。`spawn_submip`・`take_submip`・`try_incumbent`、`src/mip/solver.rs`)。

- `SMT begin id=… parent=M/3 depth=2 kind=[RENS] caller_node=… free=…/… node_limit=… time_limit=… parallel=… T=…`:
  サブ MIP に番号を振り、呼び出し側の道筋 (`M` は外側の求解、`M/3` は 3 番のサブ MIP の中) と種類 (呼び出し側の `heur_label`) を出す。
- `SMT end id=… status=… nodes=… objective=… secs=…`、`SMT acc id=… accepted=0|1`: 終わりと、呼び出し側が解を受け入れて
  暫定解が良くなったか。
- `SMT inc tag=M/3/7 z=… node=… src=[…] child=…`: 暫定解が良くなったとき、どの求解の中か (道筋)、そのノード数、ヒューリスティクスの名、
  サブ MIP の解ならその番号 (`child`)。外側の暫定解から `child` をたどれば、入れ子の一番下で解が出た場所が分かる。

道筋はスレッド局所の変数で持ち、並列のサブ MIP のスレッドは出した側の道筋を受け継ぐ。

## 6. 問いへの答え

1. **木は要る。** 外側を良くした深さ 1 のサブ MIP 66 本のうち、葉で数えて 38 本 (58%) は木のノード (深さ 1 の木 20 本、入れ子の RENS の木 18 本) で
   見つかった。最終解をサブ MIP が出した 18 問でも 8 問は木 (5〜320 ノード目) で、そのうち 3 問は入れ子の RENS の木。木のヒューリスティクスの
   主役は tree randomized rounding (深さ 1・入れ子あわせて 20 本)。根の軽いヒューリスティクス (と LP が整数) だけで足りたのは 28 本 (42%)、
   最終解では 10 問。
2. **ただし深い木は要らない。** 深さ 1 の木の改善は 1〜100 ノード目に 17/20、101 ノード目以降は 3 本 (10teams の 233 ノード目など)。入れ子の RENS の木では blp-ar98 の 320 ノード目がある。
   ノード 0 で最後の改善をしたのに 11〜100 ノード回したものが 26 本・11.6 秒ある。成功したサブ MIP の「最後の改善の後」の無駄は合計 12.9 秒で、
   それより **解を 1 つも見つけないサブ MIP (深さ 1 で 261 本・180.8 秒)** の方がずっと大きい。特に根の被約費用 (解なし 8 本・62 秒)・
   RENS (21 本・54 秒)・RENS (more nodes) (12 本・39.7 秒、成功 0)。
3. **入れ子の RENS は効いている (深さ 2 まで)。** 深さ 2 の RENS は 236 本・66 秒で外側に 21 本の解を届け、最終解の 5 問 (drayage-100-23・
   physiciansched6-2・mas76・blp-ar98・dcmulti) の出どころになった。
   深さ 3 の RENS は 135 本のうち 1 本しか解を出さない (4.4 秒と安い)。深さ 2 の RENS (LP before cuts) は 41 本・16.4 秒で外側に届いたものなし。
4. **カット (`c`) はサブ MIP の解をノード 0 側に寄せる。** カットを抜くと、成功の数は同じでも木で見つける割合が増え、解なしのサブ MIP の時間が
   1.8 倍になり、h80x6320d・drayage-100-23・neos-960392・swath1 で最終解か終わりが遅れた。

ノード上限の目安: 4 節の木の葉のノード (5・17・20・52・54・65・233・320) から、ノード上限 500 × 0.2 = 100 では 10teams (233)・blp-ar98 (320、入れ子) を、
× 0.1 = 50 ではさらに fiber・mas76・neos-3083819-nubu を失う恐れがある (同じ近傍で別の解の道があるかは見ていない)。

## 8. 注意

- 1 回ずつの計測。並列のサブ MIP・FJ・Local-MIP の早さで近傍が変わるので、問題ごとの数は揺れる。
- 「ノード」はそのサブ MIP の求解のノード数 (`Solver::nodes`)。ノード 0 は根 (カットのループと根のヒューリスティクスを含む)。
- 「LP が整数」は暫定解の名が `[tree]` のもの (固定した整数の LP で連続列を直した解 (`fixed-integer LP`) を含む)。
- 外側の再スタートの後は外側の求解の `nodes` が 0 に戻る。外側の再スタート後の根で同じ解を受け直すと `[tree]` の行が出るが、
  4 節は最終の目的値を最初に持った時刻で数えるので影響しない。
- 解の目的値はサブ MIP の中 (前処理の後) の値で、`acc` と `child` でつなぐので、値の空間の違いは集計に効かない。
