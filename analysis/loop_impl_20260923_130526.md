## 各対処法の詳細

### L1 融合 FTRAN の U 段 2 本同時 axpy — 不採用

- 実装: `pair_r_u_permute` の U 段で `(a≠0, b≠0)` のとき 1 回の eta 走査で両ベクトルへ axpy
  (`HybridVec` の sparse/dense 両アーム)。fingerprint は 93/93 問でビット同一。
- A/B (対 base, 19 問): d2q06c **+11.0%**、25fv47 +9.5%、80bau3b +8.6%、pilot.we +8.5% …
  pilot87 −1.1%、fit1p −5.3%、合計 +3.7%。再計測 (対照として無変更ビルドも用意): d2q06c +5.4%、
  25fv47 +6.3%、pilot +4.4% (無変更ビルドは base と ±2% 以内)。
- callgrind (25fv47): 命令数は −1.7% 減るのに wall は増える。変形 (dense アームのみ融合、
  nnz ≥ 8 の eta のみ融合、両ロードを先に行って 4K エイリアシングを避ける) も試したが、いずれも
  +1〜5% で改善しなかった。U 段の支配コストは eta 値のロードではなく書き込み先の散在アクセスと
  見られ、2 本の散在ストアを同じループに混ぜると不利になる。コードは元に戻した。

### L4 BFRT FTRAN の融合 + flip 反映と x_B 更新の統合 — 採用

- (a) BFRT combined-flip の rhs が dense 経路に回り、かつ DSE の融合 FTRAN を使う反復では、
  base チャネルの FTRAN を後回しにし、入列 FTRAN + τ と同じ 1 回の L/R/U 走査で 3 本目として解く
  (`FtLu::solve_into_triple_capture` / `solve_sparse_into_triple_capture`、ベクトルごとの演算列と
  合成クロックの tick は分離版と同一)。flip の反映も入列 FTRAN の後に移した (入列 FTRAN は
  x_B/InfeasibleRows を読まないので不可視)。(a) 単独ではビット同一で、fit2p −1.7%、fit1p −3.9%、
  dfl001 ±0% にとどまった。
  U 段の 3 本は L1 の結果に合わせてベクトルごとの axpy のまま (L 段と R 段だけを共有)。
- (b) flip の x_B 反映 (`for i in 0..m` + `refresh_row`) を入列ステップの x_B 更新ループに統合。
  行ごとの算術は同一 (x −= flip 分、次に x −= α·θ) で、θ は行 r の flip 後の値から計算する。
  `refresh_row` は行ごとに 1 回になる。fit2p では flip 反映パス (約 60 µs/反復、1 回あたり行の
  約半分で InfeasibleRows の出入りが起きる) がほぼ消え、bfrt 410 ms → 30 ms、xb_update
  375 → 469 ms。InfeasibleRows 内の行順が変わるので経路は変わりうる (実際に変わったのは
  93 問中 dfl001 のみ)。
- (c) 付随する修正: (b) で dfl001 の経路が変わると、polish → primal cleanup の `run_phase` が
  |α| = 1.2e-9 の pivot を選び、`try_update` が拒否、再分解は特異で失敗して `None` になる。
  extended dual 全体が from-scratch の別経路にフォールバックし、dfl001 が **+110% (32 s)** になった。
  `run_phase` の比率テストの足切りを `TOL` (1e-9) から `FT_MIN_PIVOT` (1e-7) に上げた
  (HiGHS の primal `alpha_tol` と同じ水準)。これで dfl001 はフォールバックせず 15.0 s。
  この修正だけでは他の 92 問の経路は変わらない (fingerprint で確認; primal cleanup に入る 53 問を
  含む)。(b) を安全に入れるための前提条件なので、L4 の一部として評価した。
- A/B (L4 = a+b+c 対 base、全 93 問): **fit2p −14.4%**、fit1p −8.8%、degen3 −8.4%、greenbea −8.3%、
  25fv47 −7.5%、fit2d −7.2%、pilot87 −4.5%、合計 −3.21%。10% 超の退行は afiro +17.3% のみで、
  これは経路同一の 0.4 ms 問題なので再計測したところ +0.8% (ノイズ)。dfl001 −1.0%。
- A/B 用のスイッチ: `ENOMOTO_FUSED_BFRT_FTRAN=0` で (a) を、`ENOMOTO_MERGE_FLIP_XB=0` で (b) を、
  `ENOMOTO_PRIMAL_RATIO_PIVOT_TOL_OLD=1` で (c) を元に戻せる。

### L7 ドリフト検査 rhs の増分管理 — 採用 (ユーザー判断で境界採用)

- `b − N x_N(M)` を BFRT flip (combined rhs をそのまま減算) と基底交換 (入列の項を戻し、出る変数の
  項を足す) で増分管理し、5 反復ごとの `compute_rhs_affine` (O(nnz(A)) と Vec 確保 2 本) を
  廃止。全再同期の箇所では毎回 `compute_rhs_affine` の値に戻す。経路が変わったのは pilot.ja のみ。
- A/B (L4+L7 対 L4): 18 問の部分集合で 80bau3b −10.3%、ship12l −8.2%。全 93 問では ship12l
  −9.9%、greenbea −9.3%、80bau3b −9.2%、degen3 −9.0%、合計 **−4.99%**。再計測 (6 ラウンド) では
  80bau3b −9.8%、ship12l −8.2%。10% 超の退行候補 kb2 +17.2% は再計測で −2.1%。
- 3 回の計測のうち 10% を超えたのは 1 回だけ (−10.3%) なので、当初は基準未達として不採用とした。
  合計では −5% の改善で退行がないことから、**ユーザー判断で境界採用**となった。
  `claude/practical-tesla-s52fnq` の `7f35875` (presolve P1/P2/P6 + L4 マージ済み) の上に L7 だけを
  適用した (L13 は入れていない)。適用後に `cargo test --release` を通し、全 93 問で status・目的関数を
  HiGHS と照合した (相対 1e-6) 結果は後述の「L7 追加適用後の確認」のとおり。
  A/B 用のスイッチ `ENOMOTO_XB_RHS_INCREMENTAL=0` で従来の全再計算に戻せる。
  (`loop_impl_20260923_130526_rejected_L7_L13.patch` は評価時のコードの記録。L13 部分は不採用のまま。)

### L14 primal cleanup の増分化 — 未実装 (上限見積もりで基準未達)

- 実装前に上限を測った。polish → primal handoff の `run_phase` の wall を
  `ENOMOTO_PROF_PHASES_EXT` 下で出力する計測を追加 (`PROF_HANDOFF run_phase=…ms`、この計測
  コードは採用状態に残してある)。handoff する 53 問での solve に占める割合は etamacro 10.7%、
  nesm 7.9%、pilot87 4.6%、scsd1 3.1%、その他は 3% 未満。
- run_phase を丸ごと消しても 10% を超えうるのは etamacro だけ。増分化で消せるのはその一部
  (resync と BTRAN 分) なので、どの問題でも 10% には届かない。M 規模の書き換えに見合わないため
  実装しなかった。

### L9 CHUZC1 の直接書き込み + 部分ソート — 未実装 (前提が解消済み)

- 現行コードでは、非 bland 経路の候補は stopper (幅無限の最小候補) で数十件に刈り込まれてから
  `BinaryHeap` に積まれ、BFRT が必要な先頭だけを pop する。全ソート (`candidates.sort()`) は
  `bland_mode` のときだけ走る。レポートの前提「毎反復フルソート」は成り立っておらず、残りは
  数十要素の extend 1 回だけ (1 反復あたり数十 ns)。10% には届かないので実装しなかった。

### L13 polish の摂動付き d の遅延計算 — 不採用

- A/B (L4+L13 対 L4、小問題 25 問): sc50b −27.8%、boeing2 −16.3% と出たが、再計測 (300 回 × 6
  ラウンド) では sc50b −2.7%、boeing2 −0.5%、sc50a +0.2%、lotfi 0.0% だった。A/B の数値は sub-ms の
  ノイズ。不採用。

### L12 τ FTRAN の削減 (経路変更) — 不採用

- (b) 合成クロック係数 (`ENOMOTO_SYNTH_CLOCK_FACTOR`、既定 16) を 8/12/24 で試した (L4 ビルド):
  pilot は 8 で −2.9%、12 で +27.6%、24 で +5.6%。pilot87 は 8 で +7.2%。fit2p は 12/24 で +5〜7%。

  pilot87 +94〜576%、d2q06c +244〜259%、degen3 +108〜129%。DSE 重みが粗くなって反復数が大きく増える。
  実験コードは入れていない。
