# uccase12 が候補の組 (CAND) で 902356 になる件 (2026-10-23)

ブランチ inv/uccase12-20261023 (acaa6fa から)。4 スレッド・60 秒。ログは `analysis/heur_ls_20261023/logs/uccase12_u12*` ほか
(名前の `z` は `_` の置き換えの誤り。例: `u12add_lpzprobezfirstzfull` = LP_PROBE_FIRST_FULL を足したもの)。

## 1. 切り分け (各 2 回)

CAND = WORKER_HALT=1 LATE_NO_RESOLVE=1 LP_PROBE_FIRST_FULL=1 GR_RESTART=1 FJ_NOSOL_EXTEND=1 CUT_STRONG_WIN5=nofc CUT_INTOBJ_STALL=1

| 組 | 最終の値 (2 回) | 最初の解の時刻 |
|---|---|---|
| 既定 | 11507.9040 / 11507.9043 | 14〜15 秒 |
| CAND | 902356.79 / 902356.79 | 60.2 秒 |
| 既定 + LP_PROBE_FIRST_FULL だけ | **838610.52 / 838610.52** | 60.1 秒 |
| 既定 + ほかの 6 つ (1 つずつ) | 11507.902〜11507.904 (12 回とも) | 14〜15 秒 |
| CAND − LP_PROBE_FIRST_FULL | **11507.9040 / 11507.9023** | 13.9 秒 |
| CAND − ほかの 6 つ (1 つずつ) | 902356.79 または 838610.52 (12 回とも) | 60.1 秒 |

原因は **LP_PROBE_FIRST_FULL だけ** (事実)。ほかの 6 つは足しても外しても変わらない。

## 2. 何が起きるか (事実、ログ `uccase12_u12cand_1.log`)

- 前処理の LP による固定 (`lp_probe`) の最初の LP は、既定では期限 3 秒で打ち切られる (`the first LP ended TimeLimit (3.04s of 3.00s)`)。
  根の LP は基底なしで二段解法と内点法 + クロスオーバーの競争で解かれ、内点法が 5〜9 秒で勝つ。
- FIRST_FULL では期限が 12 秒になり、最初の LP が 8.8 秒 (内点法 + クロスオーバー) で解ける。最初の LP に 1 秒以上かかったので
  基底を根に渡す (`ENOMOTO_T_MIP_LP_PROBE_BASIS_SECS`)。渡すのは**列の状態だけ** (`lp.basis().col`)。
- 根では `set_basis(Basis { col, row: [] })` → `repair_basis` (src/simplex/mip_lp.rs) が、足りない基底の分を**行 0, 1, 2, … の
  論理変数で順に埋める**。どの行が効いているかを見ないので、88,586 行の最適基底とはかけ離れた基底になる。基底があるので
  内点法との競争もなく、単体法だけで解く。根の LP が残りの 40 秒で終わらず (`Root LP` の行が出ない)、解は並列の FJ の
  902356 / 838610 だけ (FJ_NOSOL_EXTEND の有無で FJ の解が変わるだけ)。
- 前の計測 (a261791) で CAND でも 11507.90 だった理由は確かめていない (推測: その回は最初の LP が 12 秒に間に合わなかったか、
  内点法の順番が違った。最初の LP は 8.8 秒で期限 12 秒とは余裕が小さい)。

## 3. 手当て 1: `ENOMOTO_MIP_LP_PROBE_ROW_BASIS` (行の状態も渡す)

- `lp_probe` が列の状態と一緒に行の状態と行の指紋 (列番号と係数のハッシュ、`rows_fingerprint`) を渡す (`solver::ROOT_BASIS_ROWS`)。
- 根の LP の始めの行の指紋が合えば行の状態も使い、後から加わった行 (対称性の行など) の論理変数は基底に入れる。合わなければ
  今までどおり列の状態だけ (`root LP: the rows changed after LP probing` を出す)。
- 効果 (uccase12): FIRST_FULL + ROW_BASIS で根の LP が普通に進み 11507.94 (1 回)。CAND + ROW_BASIS + POSTSOLVE_REPAIR で
  11507.4101 / 11507.4109。
- 触れる経路: 56 問を CAND + 2 つの手当てで 20 秒ずつ流した (`*_sweep20_1.log`)。`lp_probe` が基底を渡したのは 11 問で、行の状態を
  使ったのは uccase12 と flugpl だけ。残り 10 問 (app1-1・neos-960392・mzzv42z など) は LP による固定の後の前処理のかけ直しなどで
  行が変わっていて、今までどおり (列の状態だけ)。flugpl は 60 秒で CAND / CAND + 手当て とも 2 回とも 1201500 で最適 (HiGHS と一致)。
- 目的値の不一致はなし (56 問の 20 秒の「最適」はどれも HiGHS の最適値と一致。pk1 の 11 は HiGHS が時間切れで 17 のもの)。

## 4. 後処理で実行不能になる件 (既定でも起きる)

既定でも、再スタート後の解 11507.41 前後が捨てられ、最終の値が 11507.90 に戻っている (u12def_1 ほか)。

### どこで見つかり、どこで捨てられるか (`uccase12_u12def_1.log`)

| 時刻 (各段の時計) | 出来事 |
|---|---|
| 10.6 秒 | 並列の FJ が 902356 |
| 19.0 / 23.5 秒 | randomized rounding 11507.906、RENS 11507.904 |
| 26.2 秒 | Restart 1 (584 列固定)。暫定解は再スタート後の前処理で実行不能として捨てる (`the start solution is not feasible in the presolved problem; dropped`) |
| (再スタート 1 の段) 15.3 / 16.2 秒 | randomized rounding 11507.42、RINS 11507.41 |
| 17.5 秒 | Restart 2 (277 列固定)。同じく暫定解を捨てる |
| (再スタート 2 の段) 9.3 秒 | randomized rounding 11507.409 |
| 時間切れ | 再スタート 2 の段の前処理の後処理は通る。再スタート 1 の段の最良の解 (再スタート 2 の段の 11507.409) を再スタート 1 の段の前処理の後処理で戻すと、再スタート 1 の問題 (外側の前処理後の問題 + カット) で実行不能 → `solving without presolve` (根の LP だけで時間切れ、解なし) |
| 最後 | 外側は自分の暫定解 11507.904 を返す |

LATE_NO_RESOLVE では前処理なしの解き直しを省くだけで、捨てる点は同じ (どちらでも 11507.90)。

### 何が破れるか (`ENOMOTO_MIP_DEBUG_POSTSOLVE=1` の診断、`uccase12_u12diag_1.log`・`u12diag2_1.log`)

- 段: 再スタート 1 回目の問題の前処理 (後処理の手順 583、すべて代入 `Sub`。平行列・強制列はなし)。
- 前処理後の解は前処理後の問題で 1e-6 では実行可能、1e-9 では実行不能。
- 元の (再スタート 1 回目の) 問題で破れるのは **行ではなく列の境界だけ**: 代入で消した連続列 74〜106 本が下限 0 を
  −5e-6〜−1.2e-5 だけ下回る (列 13097〜13107 など。上限 3600〜5400、尺度 1)。行の破れは 0 本。
- 例: 列 13101 = 5280 − Σ (83 項)。項の列 26099 (前処理後も残った連続列、境界 [0, 300]) が 290.000006261 で、この 6.26e-6 がそのまま
  13101 の −6.26e-6 になる。項の列はどれも前処理後の境界の中 (境界からの外れの合計は 1e-13 程度)。つまり「Σ ≤ 5280」は前処理後の
  問題に 1 本の行としては残っておらず、ほかの行の組み合わせで含意されるだけで、各行の許容誤差 1e-6 が積み重なって 6e-6 になる (推測)。
- `ENOMOTO_KEEP_IMPLIED_BOUND_ROWS=1` (列シングルトン・二項等式で、含意される境界を保つ行を省かない) では直らない
  (2 回とも同じく実行不能、手順の数も 583 で変わらない)。前処理のどの手順が「Σ ≤ 5280」を落としたかは特定できていない。

### 手当て 2: `ENOMOTO_MIP_POSTSOLVE_REPAIR` (整数列を固定した LP で直す)

- 後処理した解が実行不能なら、整数列をその値に固定し、その段の問題の LP を LP の前処理つき (`solve_lp`、研磨と同じ経路) で解いて
  連続列を直す。直れば (1e-6 で実行可能) その解を採り、前処理なしで解き直さない。期限は残り時間と
  `ENOMOTO_T_MIP_POSTSOLVE_REPAIR_SECS` (既定 2 秒) の大きい方 (時間切れの後でも試す)。
- 最初は前処理なしの LP (`TwoStageLp`) で試したが、8.8 万行で 2 秒に収まらなかった (`u12rep_1`、64.9 秒)。前処理つきでは 0.20〜0.24 秒。
- LATE_NO_RESOLVE と一緒でも働く (修復は時間切れでも試し、解き直しは省く)。

| 組 | 最終の値 (2 回) | 時間 |
|---|---|---|
| 既定 | 11507.9040 / 11507.9043 | 61.07 / 60.92 |
| 既定 + REPAIR | **11507.4087 / 11507.4084** | 61.03 / 60.90 |
| 既定 + REPAIR + LATE_NO_RESOLVE + WORKER_HALT | **11507.4095 / 11507.4084** | 60.54 / 60.34 |
| CAND + ROW_BASIS + REPAIR | **11507.4101 / 11507.4109** | 60.73 / 60.45 |
| mixoc + CAND (FJ_NOSOL_EXTEND=2, HEUR_MU_ROLE_OBS=1) + ROW_BASIS + REPAIR | 11507.4095 / 11507.9026 | 60.53 / 60.27 |

- HiGHS の 60 秒の値 11507.41、最適値 11507.405。下界は 11507.369 前後で最適値より下 (矛盾なし)。
- mixoc + CAND の 2 回目が 11507.90 なのは、再スタート 1 の段の根の LP に 29 秒かかって (二段解法が先、内点法が遅れた) 解が出ないまま
  時間切れになったため。後処理・修復の経路は通っていない (事実)。根の LP が遅れた理由は調べていない。
- 56 問の 20 秒の流しでは、uccase12 のほかに修復の経路 (後処理で実行不能) を通った問題はない。

## 5. 推測と残り

- 既定にする候補: ROW_BASIS は候補 (列の状態だけを渡すのは明らかに損で、行が変わったときは今までどおり)。FIRST_FULL を既定に
  するなら ROW_BASIS は必須。REPAIR も候補 (実行不能のときしか働かず、uccase12 では 0.2 秒で解を救う)。ただし 40 問 + 16 問の 60 秒
  2 回では測っていない。
- サブ MIP の基底 (`SUBMIP_BASIS`) も列の状態だけを渡して行を論理変数で埋めている。同じ損があるかもしれない (調べていない)。
- LP による固定で前処理をかけ直した問題 (app1-1 など) では、行の状態を新しい行に写せないので使っていない。
- 後処理の破れの出どころ (前処理のどの手順が行を落とすか) は未特定。診断 `ENOMOTO_MIP_DEBUG_POSTSOLVE` を残した。
- ログの `the postsolved solution is infeasible …; solving without presolve` は REPAIR で直ったときも出る (直ったかは次の
  `postsolve repair:` の行で分かる)。
