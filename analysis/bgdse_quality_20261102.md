bench に使う環境変数: `ENOMOTO_MIP_BG_CUTS_LP_WORK=1` (`ENOMOTO_MIP_BG_CUTS_DSE=q`・`=qa`・`=1q`・`=1qa` は採らない)

# 裏のカットの写しの DSE の重み: 標本でずれを測って厳密な重みにするか決める (`ENOMOTO_MIP_BG_CUTS_DSE=q` ほか) (2026-11-02)

## 結論

- **標本のずれ (`=q`) は、厳密な重みが効く問題と害になる問題を分けられない。**
  - 害になる mc11・roll3000 は、LP の始めのずれがむしろ大きい方です。4 倍を超えてずれた行の割合は 0.44〜0.56 と 0.91 でした。
  - 効く neos-960392・neos-933966・comp07-2idx・atlanta-ip・physiciansched6-2 は 0.44〜0.69 です。
  - `=q` は 9 問中 7 問で厳密な重みにします。mc11・roll3000 は 3 回とも時間切れで、`LP_WORK=1` だけなら 3 回とも最適で解けます。
- **両者を分けるのは LP の長さ。**
  - mc11・roll3000 の最初のカットの LP は 229・93 反復です。厳密な重みで反復は少し減りますが、着く頂点が変わり、写しの道筋 (ラウンド数・下界) と主の探索まで変わります。
  - 効く方の問題は 886 反復以上です。
- **`=qa` (500 反復目で確かめる) は安全だが、ほとんど効かない。**
  - mc11・roll3000 では確かめる前に LP が終わるので、`LP_WORK=1` と同じ道筋になります (3 回とも最適)。
  - neos-960392 では 500 反復目に厳密にしても、その LP は 5345 反復でした (`LP_WORK=1` は 5176)。始めから厳密にしたときは 1059 反復です。途中で直しても、それまでの 500 反復で外れた側へ進んだ分は取り戻せません。
  - physiciansched6-2 では、厳密にした後の 5 本目の LP が反復の上限で外れました (2 回とも 6326 反復)。時間も 25 s から 30〜33 s に延びています。
- **主の重みを渡す形 (`=1q`・`=1qa`) は不可。**
  - 元の行の重みはほぼ厳密 (標本のずれ 0) で、厳密な重みを計算する判定にはまず掛かりません。
  - それでも重みを渡すこと自体が道筋を変え、roll3000 は 3 回とも時間切れ、mc11 も 52〜54 s に延びました (`=1qa` の 3 回のうち 2 回)。
- **時間の上限の確かめ**: neos-4763324-toguru・uccase12 は `q`・`qa`・`1qa` のどれも 60.2〜60.4 s で、上限 60 s を大きく超えません。
  - toguru の `q` では厳密な重みの計算を 4.7 s で止め、その LP は時間の上限で外れましたが、全体の時間は延びていません。
- **したがって bench は `LP_WORK=1` だけにする。**
  - 「重みがどれだけずれているか」は、厳密な重みが得か損かの原理的な条件になりません。損得を決めるのは、その LP が長く続いて価格付けの質が反復数に効くかどうかです。
  - その長さは LP を始める前には分かりません。分かったとき (500 反復目) には遅すぎます。
  - 残る手は次のとおりです (この記録では作っていません)。
    - 写しの根の LP や主のカットの LP の反復から、最初のカットの LP の長さを前もって見積もる。もう片方のセッションの `=g` に近い考えです。
    - 厳密な重みの計算を、mc11・roll3000 で道筋を変えない形にする (例えば同じ頂点に着くよう、ずれた行だけ直す)。

既定の道筋・`=r`・`=rw` は変えていません。新しい形は `ENOMOTO_MIP_BG_CUTS_DSE` の値 `q`・`1q`・`qa`・`1qa` を指定したときだけ動きます。

## 作ったもの

`ENOMOTO_MIP_BG_CUTS_DSE` の値は次のとおりです。

| 値 | 確かめる時点 | 主の重み |
|---|---|---|
| `q` | 写しの最初のカットの LP の始め | 渡さない |
| `1q` | 写しの最初のカットの LP の始め | 渡す (`=1` と同じ) |
| `qa` | その LP が `ENOMOTO_T_MIP_BG_CUTS_DSE_AFTER` 反復 (既定 500) 続いたとき | 渡さない |
| `1qa` | 同上 | 渡す |

確かめ方は次のとおりです (src/simplex/slope_intercept_dual.rs `dse_sample_check`)。

- 標本は次の 2 つです。乱数は固定の種 (splitmix64) を使います。
  - 基底の行から `ENOMOTO_T_MIP_BG_CUTS_DSE_SAMPLE` 行 (既定 32)
  - 主実行不能な行から同じ数
- 標本の各行について、BTRAN で厳密な重み ‖e_iᵀB⁻¹‖² を計算し、今の重みとの比 r を取ります。
- 記録する統計は次のとおりです。判定には `ENOMOTO_T_MIP_BG_CUTS_DSE_STAT` で 1 つを選びます。
  - 0: 全体の |ln r| の中央値
  - 1: ばらつき (|ln r − 中央値 ln r| の中央値。重みを一様に何倍しても DSE の選び方は変わらないので、一様なずれを除いた値)
  - 2: 主実行不能な行のばらつき
  - 3 (既定): 全体の 4 倍を超えてずれた行の割合 (|ln r| > ln 4)
  - 4: 主実行不能な行の同じ割合
- 判定値が `ENOMOTO_T_MIP_BG_CUTS_DSE_DEV` (既定 0.1) を超えたときだけ、全部の行の厳密な重みを計算します (`DseState::from_basis_stoppable`)。
  - 32 行ごとに期限・取り消し・止めの合図を確かめます (`=rw` と同じ)。
  - `qa` で計算したときは、CHUZR の候補表・ヒープを作り直します。
- 1 つの LP の解き方は単体法の関数を何度も呼ぶので、`qa` の「何反復目か」はスレッドごとの反復の累計 `EXT_ITERS` で数えます。この状態はスレッドローカルの `DSE_SAMPLE_LATE` に持たせ、呼び出しをまたいで残します。
- `ENOMOTO_MIP_BG_CUTS_LOG=1` を付けると、`MIP: cut round N: background DSE sample: …` の 1 行に次を出します。
  - 標本の統計、判定値、確かめた反復
  - 標本にかかった秒数
  - 厳密な重みを計算したか (computed / stopped / not computed) と、その秒数
  - LP が確かめる前に終わったときは `not taken`

**標本の費用**は、64 回の BTRAN で 0.001〜0.05 s です (neos-4722843-widden・neos-873061 が 0.03〜0.05 s で、他は 0.01 s 以下)。全部の行の厳密な重みは次のとおりです。

| 問題 | 全部の行の厳密な重み |
|---|---|
| neos-960392 | 0.1 s |
| neos-933966 | 0.3〜0.45 s |
| physiciansched6-2 | 0.4〜0.75 s |
| comp07-2idx | 1.5 s |
| atlanta-ip | 4.0 s |
| neos-4722843-widden | 0.9〜1.8 s で、止めの合図により中止 |
| neos-4763324-toguru | 4.7 s で中止 |

- LP の始めの割合は、悪化する 2 問と得をする問題とで重なります (0.44〜0.91)。この割合に閾値を置いても分けられません。

```sh
pip install -q highspy==1.15.1 maturin
maturin build --release -o /tmp/whl && pip install -q --force-reinstall --no-deps /tmp/whl/*.whl
cd analysis/bgdse_quality_20261102
P=neos-960392,neos-933966,neos-4722843-widden,neos-873061,comp07-2idx,atlanta-ip,physiciansched6-2,mc11,roll3000

```

- 使い方は `python run.py 問題,... 設定,... 回数 [初めの回]` です。
