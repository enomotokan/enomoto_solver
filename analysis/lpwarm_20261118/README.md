## 0. 道具 (足したもの、既定の動きは変えない)

- 診断 `ENOMOTO_DEBUG_EXT_ITERLOG=1` (`slope_intercept_dual.rs`): 双対単体法の主ループの反復ごとに、出る行 `r`・出る変数・入る列 `q` (構造列 / スラック)・
  ピボット `alpha`・主の歩み `theta`・入る列の被約費用 `dj`・行 `r` の値・フリップの数 (累計)・反復の後の主実行不能の行の数・`w_r` を 1 行 (`ITERLOG`) 出す。
- 試作 `ENOMOTO_SIMPLEX_BFRT_GROUP=<文字>` (既定では使わない、`1` は `gz`): 双対の比のテスト (主ループの chuzc) を変える。
  - `g`: BFRT を HiGHS (`HEkkDualRow::chooseFinal`) と同じく Harris の組ごとに進める。組 = まだ見ていない候補のうち比が
    `theta_max = min (比 + Td / |alpha|)` 以下のもの (`Td` = `ENOMOTO_T_SIMPLEX_BG_TD`、既定 1e-7)。組を丸ごとフリップしても `w_r` に届かなければ
    丸ごとフリップして次の組へ、届く (または幅が無限の候補を含む) 組を最後の組とし、その中の |alpha| 最大を入れる列にする (最後の組の他の候補はフリップしない)。
    最後の組で飛ばした候補の被約費用の符号の誤り (高々 `Td` 程度) は、既存の `ENOMOTO_SIMPLEX_HARRIS2` と同じく費用をずらして 0 に戻す (`harris2_skip`)。
  - `z`: 自由な非基底列 (`Zero`、比 0) が候補にあるとき、最小添字でなく |alpha| 最大の列を入れる。
  - スレッド局所の印 `BFRT_GROUP_SCOPE` (1 = `gz`、2 = 使わない) も置いた (まだどこからも使っていない)。
- 台本: `run1.py`・`run58.py` (analysis/node_lp_20261106 の写し。設定 `plain`・`gz`、`PROBS`・`TL`・`RUN1_THREADS` 環境変数)、`summ58.py` (同じもの)、
  `fuzz.sh` (release019 と同じ fuzz 7 本を試作の値で回す)。ノードの LP の書き出しと単独の解き直しは既存の `ENOMOTO_MIP_NODELP_DUMP` と
  `cut_lp_debug` テスト、HiGHS の解き直しは `analysis/node_lp_20261106/highs_warm.py`。根の LP の書き出しは既存の `ENOMOTO_MIP_ROOTLP_SIMPLEX_DIAG=<prefix>`
  + `ENOMOTO_MIP_ROOTLP_DUMP_ONLY=1`。

### 1.1 反復の中身 (`ITERLOG`、node89・摂動なし・既定)

```
it=0 q=18441 col alpha=-8.598e-2 theta=-5.785e0 dj=3.4e-16 flips=0 inf=4
it=1 q=18461 col alpha=-1.204e-3 theta= 1.470e2 dj=-1.8e-16 flips=0 inf=131
...
it=12 ...                                            flips=63 inf=2433
it=15 ...  alpha=2.529e-2 theta=1.143e5             flips=64 inf=3570
```

- 出発の主実行不能は 1 行なのに、1 回目のピボットで 4 行、2 回目で 131 行、十数回で 3500 行に広がり、900 反復かかる。入る列の被約費用はどれも 0 に近い
  (この LP は費用 0 の連続列が大半で、双対退化が非常に強い)。
- 原因 (コードで確かめたこと): 比のテストの候補は `(比, 列番号)` の順に並べ (`Cand` の `Ord`)、BFRT は比の小さい順に候補を 1 本ずつ足して `w_r` に届いた位置で止まり、
  Harris のパス 2 はそこから**後ろ向きにだけ**窓 (比の差 1e-7) を見て |alpha| 最大を選ぶ。比 0 の同点が大量にあると、
  (a) 同点の中の列番号の小さい列で止まり、それより |alpha| の大きい同点の候補を見ない (node89 の 1 回目は |alpha| 0.086 で歩み 5.8)。
  (b) 同点の中の箱型の列を列番号順に何十本もフリップする (node14 は 1 回目で 38 本、主実行不能 1 → 1575 行)。比 0 のフリップは双対の目的値を
  良くしないので、主の値を壊すだけになる。HiGHS は Harris の組ごとにしかフリップせず、最後の組 (= 比 0 の同点の組) の中では |alpha| 最大を選んで
  その組はフリップしない。
- 既存の前向きの Harris (`ENOMOTO_SIMPLEX_HARRIS2=1`) は (a) を直すが (b) は直さない: node89 917 → 4、node14 235 → 286、node9 72 → 65。
  木の LP で今使っている `ENOMOTO_MIP_NODELP_PERTURB` の `h` は `HARRIS2=t` (数値のトラブルのときだけ) なので、この LP では効いていない。

## 2. 根の LP (事実)

- 根の LP を書き出して単独で解くと木の中と同じ 22692 反復を再現する (`cut_lp_debug`、`CUTLP_COLD=1`)。中身 (`ENOMOTO_DEBUG_EXT_ITERS`):
  511 反復目に `x_B` と `rho^T (b - N x_N)` の不一致 (数値の破綻) → 安全モード + 全部の費用の摂動で解き直し → 主ループ 12618 反復 + 仕上げ 9557 反復。
  再分解 267 回で時間の 52% (検算の失敗で 133 回)。
- 破綻の元 (`ITERLOG`): 連続列の多くが自由列 (前処理の後に境界のない列) で、全スラック基底から始めると非基底の自由列は `Zero` に置かれる。
  候補に `Zero` 列があると BFRT をせずに**最小添字**の `Zero` 列を入れる規則 (論文 3.1 節 (iii)) なので、|alpha| = 1e-8〜1e-9 の列を入れて歩みが
  1e9〜1e14 になり、数十反復ごとに条件数の悪い基底を作る。
- 始めの基底 (crash) は全スラック基底 + 被約費用の符号で置き場所を決めるだけ (`crash`)。価格付けは DSE (単位重みから)。摂動は破綻の後の解き直しで全部の費用。
- HiGHS 1.15.1 (`highspy`、整数性を外した元の問題、1 スレッド、双対単体法): 前処理あり 46525 反復・60.5 秒、前処理なし 129629 反復・212 秒、
  前処理なし + 尺度なし (`simplex_scale_strategy=0`) **1300 反復・1.0 秒**、DSE なし (Dantzig) 84270 反復。HiGHS もこの LP は尺度をかけると桁で遅い。
  当方の根は係数の幅 4.2e3 で `ENOMOTO_MIP_ROOTLP_SCALE` (幅 1e4 以上) に当たらず尺度なしで解いている (`ROOTLP_SCALE: ... applies false`)。

## 7. 過去に BFRT・Harris の周りで試して不採用だった記録と、今回の違い

- `HARRIS_RATIO_TOL` の行ごとの尺度版 (`r_i + tol / |alpha_i| >= r_stop`、docs/improvement_history.md の「定数 HARRIS_RATIO_TOL」): Netlib で時間 +9.7%、
  `cycle` で**誤った最適値**のため戻した。理由として「飛ばした候補の符号の誤りの大きさを抑える向きと逆に、置き換える候補の |alpha| で窓を広げていた」と
  書かれている。今回の `g` は HiGHS の `chooseFinal` と同じく、組の上限 `theta_max = min (比 + Td / |alpha|)` を**飛ばしうる全部の候補**の最小で決めるので、
  飛ばした候補の被約費用の符号の誤りは高々 `Td` (1e-7) で、それも双対の更新の後に費用をずらして 0 に戻す (仕上げが真の費用で直す)。Netlib 93 問で
  目的値の不一致 0 (`cycle` を含む)。
- 試作 `ENOMOTO_SIMPLEX_HARRIS2` (前向きの Harris、analysis/rootlp_simplex_fail_20261105.md 7.1 節): `Td` に敏感 (1e-8 でだけ supportcase42 が解ける)、
  いつも使うと neos-873061 が時間切れ・uccase9 +19% で、安全モードのときだけ (`r`) に絞った。違い: `HARRIS2` は BFRT の歩進 (列番号順に 1 本ずつ足して
  `w_r` に届いた位置で止まる) をそのままにして、止まった位置から先だけを広げる。同点の中の箱型の列を列番号順にフリップする (b) は残り、
  止まる位置も同点の中の列番号で決まる。`g` は歩進そのものを組単位にし、最後の組 (同点の組) はフリップしない。上の表で neos-873061・uccase9 は悪くならない。
- analysis/fable_mitt_a_20261004.md の対処案 Q5 (前向き Harris 窓 + 費用シフト、HiGHS `chooseFinal`) は案のまま実装されていなかった。今回の `g` がその実装に当たる。
- `Zero` 列を最小添字で入れる規則 (論文 3.1 節 (iii)、improvement_history の BFRT の節) を変えた記録はない。`z` は同じ比 0 の `Zero` 列の中で
  |alpha| 最大を選ぶだけで、BFRT をしないこと (比 0、フリップなし) は同じ。
