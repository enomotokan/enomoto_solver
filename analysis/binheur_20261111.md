## 結論

- 案 1 の試作 `ENOMOTO_MIP_LMIP_SWAP=1` (集合分割の行の中で 1 を立てる列を入れ替える組の手を Local-MIP に足す) は、58 問 × 種 1〜2 で

  解けた数が減らない・同じ問題がそろって遅くならない) は満たす。効き目は小さく、区間は 0 をまたぐ。
- 効き目が小さい理由 (事実): 既定では Local-MIP は根の FJ のスレッドで FJ と時間を分け、主が暫定解を持つか根が終わるまでの数秒しか回らない。

  ROLE_LMIP → ROLE_LMIP+SWAP は +6.7% (区間 [−0.2%, +20.5%])、どちらも解けた 8 → 7。悪く出たのは neos-911970 の種 2 が両方とも
  時間切れになったため (種 3〜6 では 4 回とも解ける)。それを除くとそれぞれ −1.4%・+0.4% で差はない。良くなった回もある

- **取り込みの基準: SWAP 単独 (`ENOMOTO_MIP_LMIP_SWAP=1`) は満たす** (58 問 × 種 2 で区間の上端 +3.1% ≤ +5%、解けた数は減らない、

  見立て「時間がかかる原因の多くは下界の証明の側」は 60 秒では当たっている。

  案 2 (個数の制約) が多いのは graph20-20-1rand・physiciansched6-2 だが、どちらも解の側は遅れていない。案 3 (集合被覆) の行が多い

### 案 1 の試作 (`ENOMOTO_MIP_LMIP_SWAP`、run_b.py → b_hit.jsonl・b_p58.jsonl、summ_b.py → b_hit.txt・b_p58.txt)

作り: 等式・0-1 列だけ・係数がすべて同じで右辺/係数 = 1 の行 (集合分割の行) を集め (`SwapIdx::build`、なければ何もしない)、
Local-MIP の 1 歩ごとに違反行 (目的の行を含む) を `ENOMOTO_T_MIP_LMIP_SWAP_ROWS` (2) 本選び、その列を `_COLS` (16) 本まで見る。
列 j の tight move が 0-1 の反転で j が集合分割の行 q にあれば、j を 0 → 1 なら q で今 1 の列を 1 → 0 に、j を 1 → 0 なら q で今 0 の列
(乱数で `_PARTNERS` (4) 本) を 0 → 1 にする組を `score2` で評価し、今の最良の手より良ければ置き換える。localmip.rs の差分は 24 行。

19.0 → 14.9 秒。eil33-2・nw04 はほぼ変わらない。

## 推測

- 案 1 (等式の 0-1 行の中で 1 を立てる列を入れ替える動き) が効くとすれば eil33-2・nw04・bppc4-08 (品物を別の箱へ移す)・
  neos-1456979。ただし eil33-2・nw04 は 15〜30 秒で解けており、最適解を早く持っても木が刈れる分だけしか縮まない
  (最良優先に近い探索なら下界が最適値に届くまでの木はほぼ変わらない)。
- 58 問全体の SGM への効き目は、当たる問題が 50 回中 13 回・その半分は時間切れのままなので、出ても小さいと見る。

- SWAP の効き目が小さいのは Local-MIP の回る時間が短いため。根の後も Local-MIP を回す `ENOMOTO_MIP_PRECHAIN=ebiR` (RESTCHAIN) や
  `ENOMOTO_MIP_ROLE_LMIP` と重ねれば効く問題が増えるかもしれない (下の 組み合わせ で確かめる)。
