## 4. 研磨がなぜ重いか・同時実行は走っているか (利用者の問い、2026-11-27)

診断 `ENOMOTO_MIP_POLISH_STATS` に文字を足した (解き方は変えない): `b` 写した基底の出発の点の主の実行不能、`s` 研磨の LP の大きさと、整数を固定した後に
自由な連続列が 0・1 本の行の数、1 本の行を列の境界にして外すことを繰り返した残り (前処理の見積り)、`r` 同時実行の記録 (`ENOMOTO_MIP_XOLAZY_LOG` と組) と
1 反復の秒、`e` 基底を捨てて基底のない入口 (`solve_cold_entry`) で解く。1 スレッド・種 1・上限 120 秒 (kasavu は 60 秒) の回。

### 4.1 研磨の LP (B&B の問題 = MIP の前処理の後の問題、整数を固定、カットなし)

| neos-5049753-cuanza | 320520 | 8304 / 234432 | 6408・228096 (73%) | 39852・33360 | 39251・42.8 秒・1.09 ms |
| neos-873061 | 93292 | 87644 / 87610 | 0・87610 (94%) | 2340・2488 | 64859・163 秒・2.51 ms |

- **重さの元は「前処理なしの大きな LP を単体法で一から解く」こと**。研磨の LP は B&B の問題 (MIP の前処理の後) に整数の固定を置いただけで、LP の前処理をしない。
  thor50dday・neos-873061 は行ごとに連続列が 1 本 (整数を固定すると各行が 1 列の境界になる) で、LP の前処理なら行が 0・2340 本に減るのに、
  単体法で 1.5〜6.5 万反復を回している。cuanza・kasavu も 7 割の行がこの形。
- **温めた基底は効いていない**: cuanza では、基底を写す (既定)・基底なし (`c`)・基底のない入口 (`e`) の 3 つとも 39251 反復で同じ。整数の固定で
  基底から外れる整数列 (2735〜3899 本) とカットの行 (293〜2298 本) を外すと、基底の変数が行の数に足りず (317988 / 320520)、修復した基底は
  出発の点として使えない (`b` の診断で分解できない `None`。neos-873061 だけは主の実行不能 2 で使える形だが、それでも 6.5 万反復)。
- dano3_5・snp-02-004-104 は別の型: LP は小さめで前処理で減らない (1 本の行が 4% 未満)。反復が多いのは LP そのものの縮退 (rootpar_ph の dano3_3 と同じ)。

### 4.2 内点法 + クロスオーバーと双対単体法の同時実行 (問い (a))

- 1 スレッド: 同時実行は走らない (`cold_race_threads()` が 1)。`j` の形 (温めた単体法に反復の上限 G5SEQ_C × (行 + 列) = 0.5 × 56 万 = 28 万) で、
  上限には当たらない (cuanza 3.9 万反復) ので、内点法には回らない。dano3_5 だけ上限 (8512) に当たり基底のない入口へ (1 スレッドでは二段解法 → 内点法の G5SEQ)。
- 4 スレッド (cuanza、`POLISH_STATS=r`): 求解の終わり (従のスレッドは止まっている) で `solve_race_warm` (`j`、同時実行のスレッド数 4) が**走る**。
  勝ったのは単体法 (66.3 秒、44306 反復)。内点法は 25.5 秒で終わり、押し出しが 52.2 秒、仕上げ (クロスオーバーの単体法) は 66.3 秒までに終わらなかった。
  単体法側の 1 反復は 1.50 ms で、1 スレッド (1.09 ms) より 4 割遅い (同時実行のスレッドとの取り合い)。研磨は 1 スレッドの 42.8 秒より長い 66〜79 秒。
- `cancel::current()` が立っている場面 (サブ MIP の中など) と `jcap` が切の形では同時実行しない。求解の終わりの研磨はどちらでもない。

### 4.3 (s) の候補の見積り (問い (c))

1. **整数を固定した後に LP の前処理をかける**: 効く問題では大きい。thor50dday は前処理だけで解ける (残り 0 行)、neos-873061 は 93292 → 2340 行、
   cuanza は 320520 → 39852 行 (1/8)、kasavu は 954422 → 102087 行 (1/9)。単体法の反復は行の数に強く依るので、cuanza でも数秒、neos-873061・thor50dday はほぼ 0 秒と見込む。
   dano3_5・snp には効かない。既存の LP の前処理 (`solver::solve_lp` の LP の経路、`simplex::solve_lp_dual_with`) を、研磨の LP (`MipProblem` + 整数の固定) に
   かける形が作りやすい (研磨の採り方・漏れの評価は今のまま、元の空間の解に戻してから)。新しい閾値は要らない。
2. **温め方を良くする** (前処理した空間の最適基底を元の問題へ写す、など): 今の温めは効いていない (4.1) ので、写す基底が良くなれば効く。
   ただ 1. の前処理をかけるなら、前処理後の小さな LP を一から解くので温めは要らない (1. が先)。
3. **1 スレッドでも内点法 + クロスオーバーを使う (G5SEQ の形)**: cuanza の 4 スレッドの記録では内点法が 25.5 秒・押し出し 52 秒で、単体法 (1 スレッドで 42.8 秒)
   より遅い。この型の LP (行ごとに連続列 1 本、退化) では得にならない見込み。dano3_5・snp の縮退の型には効くかもしれないが、上限 (G5SEQ_C) に当たってから回る今の形で十分。

## 5. (s) の試作 `ENOMOTO_MIP_POLISH_PRESOLVE` (2026-11-27、利用者の承認 (p+s)・親の依頼)

- 最後の研磨の LP (整数を固定した B&B の問題) を、温めた単体法の前に LP の前処理 + 単体法で解く (既存の `polish_in_problem` と同じ解き方、
  `crate::solver::solve_lp`。src/mip/mod.rs `polish_presolved`)。`1` = 時間切れで終わるときだけ、`a` = いつも。解けなければ今の温めた単体法へ。
  新しい閾値はない。期限は今の研磨と同じ (`g` では期限なし、`OVERRUN240=p` と組めば求解の期限)。
- この経路は双対値を返さないので、許容の漏れの上界 W (`POLISH_TOL_LEAK`) は 0 にする。W は「最後の研磨で上がった幅が許容を越えたら最適と言わない」
  判定の許容に入るので、0 は厳しい側 (最適と言う回が減りうるだけで、誤って最適と言うことはない)。`1` では時間切れで終わる回だけなので関わらない。
- 元の空間への戻しの誤りは、戻した解の違反を元の問題で測る採り方の判定 (違反が増えず目的値が悪くならない、か違反が真に減る) で捨てられる。
- ビルド: (p) の計測と重ならないよう別の作業ツリー (/home/user/es_ovr) で `cargo build --release` し、`PYTHONPATH` でその作業ツリーの python/ を先に読ませて回した
  (計測の本体の enomoto_solver は変えない)。(p) の計測と同じ機械で同時に回したので、秒は取り合いの分だけ大きめ。

### 10.1 読み

**前処理で縮む問題** (kasavu・cuanza・neos-873061・thor50dday)
- どの設定でも、越えは 0.2〜6.9 秒に収まる。
- ただし、R (同時の研磨) は D より 1〜3 秒多く越える。
  - 例: kasavu 2T の race P は 3.5〜4.9 秒、前処理つきの研磨だけなら 1.7〜2.4 秒。
  - 温めた研磨と CPU を取り合うためとみる。縮む型では、同時に回す得はない。
- kasavu は、どの設定でも 1918.5 を返した。
  - 8 節 (2d6a85396) では 1551 だった。このビルドで暫定解の道筋が変わったため。研磨の前後の値は、まだ確かめていない。

**前処理でほとんど縮まない問題** (dano3_5・snp)
- (δ) の門は通る。前処理の後に少しだけ小さくなるため。
  - 例: dano3_5 は 2645 行・10751 列・59871 非零。
- その結果、D は前処理つきの研磨 (14〜29 秒) に入る。A (温めた研磨) と同じくらいか、それより多く越える。
  - 1 スレッド 120 秒: A +28.2・+14.2、D +25.2・+18.2。
  - 1 スレッド 600 秒: A +16.4・+15.3、D +29.5・+19.9。
- R では温めた研磨が勝つが、それでも 10.8〜16.1 秒かかる。A と同じくらい越える。
- 裏の研磨の結果を使えた回 (bg) は、越えが 0.0〜1.2 秒になった。
  - Ri: dano3_5 2・8T、snp 2・4T。
  - Rw: dano3_5 2T、snp 4T・600 秒。
- 使えなかった回は、R と同じく 11〜16 秒越える。
- w で働いているスレッドが取ったのは、2 回だけ (snp 2T で 1、4T で 2)。
  - その 2 回とも、返す解の研磨が間に合わず、使えなかった。

**まとめ** (利用者の判断の材料)
- 1 スレッド:
  - 縮む型は、A でも D でも直る。
  - 縮まない型 (dano3_5・snp) は、A でも D でも 14〜30 秒越える。D の門は、この型を見分けられない。
- 2 スレッド以上:
  - 縮まない型を直せるのは、裏の研磨だけ。結果を使えた回だけ直る。
  - 同時の研磨 (r) は、縮む型で 1〜3 秒遅く、縮まない型では温めた研磨と変わらない。
- w は、i と比べてほとんど効いていない。働いているスレッドが取った回が少ない。11 節で a (いつも取る) と比べる。
