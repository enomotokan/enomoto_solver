  rococoB10-011000 も同じ形 (720 行、規則 12 を切ると 810 行・一般整数 90 列)。

- 残る一般整数 (C10 の 82 本など) は容量の列 z で、2 行にだけ出る: 定義の等式 `z − Σ c_k y_k = 0` (y は 0-1、c は 2048・27856・34000 などの整数)
  と容量の行 `Σ d x − z ≤ 0`。HiGHS の Aggregator は z を代入で消して容量の行を 0-1 だけのナップサック行 `Σ d x − Σ c y ≤ 0` にする。
- こちらの Aggregator (v2) は整数最適化の前処理で整数列を候補から外す (未実装ではなく、意図して外している。条件が狭い)。整数列も消す試作
  `ENOMOTO_MIP_TREE2_INTAGG` は既にあった (analysis/tree_close2_20261104.md、ピボット行の残りが全て整数列で係数・右辺がピボットの係数の整数倍の
  ときだけ)。`=1` は 0-1 列も消して h80x6320d を壊し、`=g` (一般整数だけ) は neos-3083819-nubu の流量の保存式 (等式 4〜5 本に出る一般整数の流量
  31 本) を消して根が弱くなり遅い (7.9 → 12.5 秒、cand1114 でも 3.1 → 7.7 秒・ノード 50 → 3000)。
- 平行な行 (規則 13) の分は、`d` で集約すると 577 行になるので、こちらの平行な行の検出で足りている (集約の後の平行な行が消える)。

- 親の手がかり (平行な整数列 `ENOMOTO_PRESOLVE_PARALLEL_INT=1`、平行な行・列だけの畳み `ENOMOTO_MIP_FOLD=rinpq`) を cand1114 の上で試した
  (rococoC10、前処理の後の大きさだけ、1 スレッド): どちらも 741 行・2566 列で変わらない。`d` に `PARALLEL_INT` を足しても 577 行・2443 列で同じ。
