## 結論

事実 (下の表、58 問 + mushroom-best のうちギャップのある 56 問):

- 閉じたギャップの割合の平均: **ENOMOTO の既定の根 55.4%**、HiGHS の根 60.4%、**CG 閉包の見積もり 23.4%** (cg・mod-2・mod-k の回の最大)、
  mod-2 閉包 9.0%、mod-k 閉包 (k = 2, 3, 5, 7) 10.9%。CG 閉包は前処理なしの元の模型の LP から、1 問 1 設定 300 秒まで (分離 MIP 1 回 20 秒) で
  近似したもの (下からの見積もり。連続列は係数 0 に落とす射影 CG)。
- CG 閉包の見積もりが ENOMOTO の既定の根を 5 点より大きく上回るのは **4 問だけ**: flugpl (58.5% 対 17.5%)、**neos-1456979 (mod-2 で 36.4% 対 4.5%)**、
  qiu (14.3% 対 1.6%)、**eil33-2 (mod-k で 16.0% 対 7.5%)**。1〜5 点上回るのが blend2 (24.2 対 21.0)・gen-ip054 (5.3 対 3.9)。
  ほかの 50 問は既定の根がすでに見積もりと同じか上 (多くは既定の根が大きく上。カットの種類が多いのと前処理の効き目)。
- この 6 問で、上回る分が mod-k (分母 2, 3, 5, 7) で取れるか:
  - **mod-2・mod-k で取れる**: neos-1456979 (mod-2 36.4%、cg の回は 6.8%)、eil33-2 (mod-k 16.0%・mod-2 13.0%、cg の回 13.1%、900 秒でも 12.8%)。
  - **mod-k では取れない (分母の大きい重みか 1 以上の重みが要る)**: flugpl (mod-k 0%、mod-16・mod-64 でも 2.0%、cg 58.5%)、qiu (mod-k 0%、cg 14.3%)、
    blend2 (mod-k 0%、cg 24.2%)、gen-ip054 (mod-k 1.4%、cg 5.3%)。この 4 問は整数にできない行 (実数の係数・連続列を含む行) を 1 以上の重みで
    使うカット (flugpl では 2 本の行を重み 3.5・1.4 などで足して連続列を消すもの) で、MIR に近い形。
- mushroom-best (HiGHS の mod-k が根の下界を上げる問題): CG 閉包の見積もりは 0.8% (ENOMOTO 28.6%、HiGHS 53.5%)。mod-2 は 0%、mod-k の分離 MIP は
  終わらなかった。`analysis/mushroom_cuts_20261106.md` のとおり、HiGHS の z の式は mod-k で見つけた行の組を変数上下限で置き換えて lifted cover に
  したもので、射影 CG の閉包には入らない (連続列・一般整数列の上下限の置き換えが要る) ことと合う。
- HiGHS の根が ENOMOTO を 5 点より大きく上回る 15 問のうち、CG 閉包の見積もりで説明できそうなのは neos-1456979 (一部)・qiu・blend2・p0201・
  qnet1・neos-860300 だけ。bppc4-08 (29.1%)・graph20-20-1rand (57.1%)・cvs16r128-89 (25.8%) は HiGHS の下界が目的値の刻みに切り上げた値
  (52・-21・-120) で、CG 閉包の見積もりは 0%。hypothyroid-k1・assign1-5-8・neos-911970・supportcase26 も CG 閉包の見積もりは 0%。

推測:

- **「CG カット (mod-k を含む) の探し方を良くする」方向の伸びしろは、58 問ではごく一部の問題に限られる**。CG 閉包の見積もりは下からの
  見積もりで時間の上限で止まっているものが多いが、既定の根との差は 1 問あたり平均で数点にとどまり、大きいのは neos-1456979・eil33-2 (mod-k で
  取れる)、flugpl・qiu (mod-k では取れない) の 4 問。Smith 標準形などで mod-k を一般化しても、分母の大きい重みが要る問題 (flugpl・qiu・blend2) は
  整数の行の mod-k の枠の外 (1 以上の重み・実数の行) で、取れるとすれば集約 + MIR 側の改良。
- 一番手の届きそうな候補は **neos-1456979**: mod-2 のカット 30 本のうち 29 本が「等式の行 1 本 + 大きな M (500) の行 2 本を 1/500 にしたもの」の
  3 本の組で、2 本の大きな M の行は連続列 2 つ (x6 − x106 と −x6 + x106) が打ち消し合う。ENOMOTO の zerohalf は整数列だけの行しか使わない
  (`src/mip/zerohalf.rs` の冒頭) ので、連続列を含む行はそもそも使えない。HiGHS の根は 77.3% で、別のしかけ (経路集約の CMIR など) で取っている
  と思われる (確かめていない)。
- eil33-2 (集合分割) は mod-k の閉包がまだ上がり続けている (300 秒で止まった) ので、伸びしろはもっと大きいかもしれない。

## 1. 方法

### 1.1 分離 MIP (Fischetti–Lodi 2007)

元の模型 (前処理なし) を highspy で読み、次の形に直す (`cgclosure.py` の `Model`)。

- 列: `x = d + σ x'`、`x' ≥ 0`。整数列は下限があれば下限から、なければ上限から測る (下限・上限は整数に丸める)。両方ない列は自由列
  (整数なら `α_j = uA_j` が整数、連続なら `uA_j = 0` を課す)。上下限の幅が 1e6 以上なら無限とみなす (roll3000 の 1e9 で分離 MIP が壊れた)。
- 行: ≤ の形 (等号・両側の行は 2 本)。整数列の係数を有理数として通分し (分母 1000 まで、通分の積 1e6 まで)、整数列の係数の最大公約数で割る。
  **整数列だけ・整数係数の行は右辺を切り下げ、乗数 u ∈ [0, 1 − δ]** (δ = 0.01、Fischetti–Lodi のとおり)。整数にできない行・連続列を含む行は
  整数列の最小の係数が 1 になるように割り (最大の係数が 1e4 を超えるなら 1e4 に。ran14x18-disj-8 の大きな M で 1e9 になって壊れた)、
  **u ∈ [0, 10]** (近似。[0, 1) では flugpl・gen-ip002 などで何も取れない)。整数列の上限 `x'_j ≤ u_j − l_j` も行にする。
- 連続列: Fischetti–Lodi・射影 CG (Bonami–Cornuéjols–Dash–Fischetti–Lodi 2008) のとおり、`uA_j + v_j ≥ 0` (v_j ≥ 0 は連続列の上限の行の乗数) を
  課し、カットでは係数 0 で落とす。MIR 閉包 (Dash–Günlük–Lodi 2010) には切り替えていない (分離 MIP が大きく複雑になるため)。**連続列を含む
  問題では、この閉包は MIR 閉包よりかなり弱い** (pk1・markshare・mas74・mas76 で 0%)。
- 分離 MIP: `max Σ_{j: x'*_j > 0} α_j x'*_j − β − ε Σ u_i`、`α_j ≤ uA_j`、`β ≥ ub + Σ v_j W_j − 1 + δ`、α・β 整数 (ε = 1e-5)。
  `x'*_j = 0` の整数列の α は持たない (Fischetti–Lodi の工夫。カットでは ⌊uA_j⌋ を後で計算する)。使う行は LP 点での余裕で絞らない
  (余裕 1 未満に絞ると p0201 で 13.5% → 全部の行で 36.6% 以上と大きく取りこぼした)。余裕の小さい順に 2 万本まで。
  HiGHS の `objective_bound` で違反 1e-3 未満の解を切り、`mip_improving_solution_save` で改善解を全部カットにする。
- mod-k: `u_i = t_i / k`、t_i ∈ {0, ..., k − 1} の整数 (行の種類によらない)。`mod2` は k = 2 だけ、`modk` はラウンドごとに k = 2, 3, 5, 7 を全部
  解いて全部足す (HiGHS の mod-k と同じ k)。`modK16` などは k を 1 つ (分母 16 まで、2・4・8 を含む)。
- カットは乗数から浮動小数で作り直し (`floor(uA_j + 1e-9)`)、LP 点で違反 1e-3 以上のものを LP に足して解き直す。ラウンド 30 回・300 秒まで
  (長い回は分離 MIP 60 秒・900 秒まで)。カットは捨てない。
- 正しさの確かめ: 全てのカットを MIPLIB 2017 の既知解 (`miplib.zib.de/downloads/solutions/<名前>/1/`) で検査した。違反 0 本 (許容誤差 1e-5 (1 + ‖c‖₁)。
  1e-6 では binkar10_1 で 3 本が 7e-6〜2e-5 だけ違反した。既知解の整数列が 7.4e-6 ずれているためで、誤りではないと判断)。

### 1.2 注意 (事実)

- **下からの見積もり**: 多くの回が時間 (300 秒) で止まった (表の「cg の止まり方」が `tmax`)。分離 MIP が 20 秒で解を見つけられずに止まった回
  (`nocut/Time limit reached`) もあり、そのときは閉包を過小に見ている。`nocut/Optimal`・`nocut/Infeasible` は「その点を切る違反 1e-3 以上の
  カットはない」ことを分離 MIP が示した (閉包に届いた) もの。
- cg の回 (u が連続) は分離 MIP が重く、1 ラウンドに数本しか出ない。mod-2・mod-k のカットも CG カットなので、表の「CG 見積もり」は 3 つの回の最大。
  10teams は cg の回 28.6% に対し mod-2 100% で、cg の回だけでは大きく過小になる。
- 前処理なしの LP から測るので、前処理・プロービングの効き目は含まない。ENOMOTO・HiGHS の根は前処理と全てのカット (と目的値の刻みの切り上げ) を含む。
  つまり「既定の根 − CG 閉包の見積もり」が負でも、CG カットを足して根が上がらないとは言えない (既定の根の LP に CG 閉包を重ねた測定はしていない)。
- ENOMOTO の `root_bound` は暫定解の目的値で上から切り詰めた値 (根で最適になった drayage-100-23 などは 100%)。HiGHS は 1 ノードで最適を示せば最適値。
- 閉じたギャップの割合は最小化の向きで `(下界 − LP) / (最適値 − LP)`。LP = 最適値の 3 問 (neos-827175・neos-960392・ns1116954) は「—」。

| gen-ip054 | 3.9 | 4.2 | **5.3** | 0.0 | 1.4 | EXT_GEN | 大半は取れない |

- 長い回で neos-1456979 の cg・mod-k・mod-16 が短い回の mod-2 より低いのは、重みの空間が広いほど分離 MIP が重くなり、時間の中で回るラウンドが
  減るため (mod-2 は 1 回 0.3〜1 秒、mod-k は 4 つの k で 1 ラウンド 60 秒前後)。重みの空間を広げても、時間を区切った近似では良くならない。

### 3.2 カットの形 (事実、`--dump` の書き出し)

- **neos-1456979 (mod-2)**: `dump_neos-1456979_mod2.jsonl` の 30 本のうち 29 本が 3 本の行の組 (残り 1 本は 22 本)。例 (1 本目): 等式の行 R0151
  (0-1 列 44 本) を −1 倍、大きな M の行 R4526 `x6 − x106 + 500 y451 ≤ 490` と R5746 `−x6 + x106 + 500 y2641 ≤ 489` を 1/500 にしたもの、
  それぞれ重み 1/2。2 本の大きな M の行を足すと連続列 x6・x106 (どちらも上下限の内側) が消え、`y451 + y2641 ≤ 1.958` (→ 1) になる。
  mod-2 はこれと等式の行を合わせて違反 0.968 のカットを作る。カットの係数は 0-1 列に ±1 (34 本)、右辺 0。
- **flugpl (cg)**: 1 本目は行 STD6 (係数 50 の倍数、1/50 にしたもの) を −1 倍して重み 3.53、行 UEB6 (1/20) を重み 1.41 で足し、`−12 STM6 + 7 ANM6 ≤ −848`。
  重みが 1 を超え、分母も 2, 3, 5, 7 ではない。2 ラウンド目以降も重み 9・10 の行 (ANZ*、係数 10 の倍数) を使うものが多い。
- cg の回のカットの重みの分母 (各カットの非零の u を分母 64 までの有理数に近づけた最大の分母) は、カットを出した 50 問のうち 39 問で 7 割以上が 20 以上。
  ただし u が連続の分離 MIP の解は `uA_j ≥ α_j` のぎりぎり (u = α / a) に寄るので、分母は行の係数で決まり、「その分母が要る」ことは示さない。
  「要るか」は mod-k の回と cg の回の閉包の差 (上の表) で見る。

### 3.3 推測

- neos-1456979 は「連続列を打ち消す 2 本の行の和 + 整数の行」の mod-2。ENOMOTO の zerohalf は連続列を含む行を使わないので、zerohalf の前に
  「連続列が打ち消し合う行の組を足した行」(MUSHAGG の行の組と同じ考え) を候補の行に加えるか、連続列を上下限で置き換えた空間の行を
  mod 2 に入れる (`ENOMOTO_MIP_MODKVB` と近い) と取れる見込み。
- eil33-2 は集合分割の行 (32 本、整数列だけ) の mod-k (k = 3, 5, 7 のカットが多い: mod-k の回の 276 本のうち k = 7 が 107 本)。ENOMOTO の
  zerohalf (mod 2 だけ) では取れない分がある。
- flugpl・qiu・blend2・gen-ip054 は実数の係数の行を 1 以上の重みで足すカットで、mod-k の一般化 (Smith 標準形を含む) の枠の外。集約 + MIR
  (δ の選び方・集約する行の選び方) の側。flugpl は小さく既定で一瞬で解ける (伸びしろがあっても速さには効かない)。

## 4. 次の一手 (推測)

1. neos-1456979 で「連続列を打ち消す行の組の和」を zerohalf の候補の行に足す診断 (根の下界 4.5% → mod-2 閉包の 36% にどこまで近づくか)。
   別のセッションの `ENOMOTO_MIP_MODKVB` (変数上下限で置き換えた空間の mod-k) がこの形を拾うかを先に確かめる。
