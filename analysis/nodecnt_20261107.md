# HiGHS に負ける問題でノード数が 10〜100 倍になる原因 (2026-11-07〜08、調査と試作 `ENOMOTO_MIP_NODECNT`)

bench に使う環境変数: `ENOMOTO_MIP_LOG=1 ENOMOTO_MIP_THREADS=4 ENOMOTO_T_MIP_SEED=s ENOMOTO_MIP_TREE4_TRACE=10` (4 スレッド、TRACE は診断の出力だけ)。
設定 (`bench.py` の `CFG`): `h` = `ENOMOTO_MIP_NODECNT=h`、`p` = `ENOMOTO_MIP_NODECNT=p`、`nc` = `ENOMOTO_MIP_NODECNT=1` (= `d`)、`htp` = `h` + `ENOMOTO_MIP_TREE1_POOL=1`、
`t1*` は 1 スレッド (`ENOMOTO_MIP_THREADS=1`・`--threads 1`)。刈り込みの理由は `NC_TREELOG=1` の回だけ (`ENOMOTO_MIP_TREE_LOG=1` の `ENODE` 行)。
HiGHS は highspy 1.15.1 (`hrun.py`、4 スレッド・`mip_rel_gap=0`、ログは `logs/H_<問題>_<設定>.log`)。生データは `analysis/nodecnt_20261107/`。

## 結論 (先に)

1. **HiGHS で効いている部品は「ノードでの分離」**(事実、HiGHS のオプションで止めた比べ): 木で閉じる 4 問 (kasai・csched008・unitcal_7・tr12-30)
   のどれも、`mip_allow_cut_separation_at_nodes=false` で HiGHS も時間内に解けなくなり、下界は ENOMOTO の 600 秒と同じ程度で止まる
   (kasai 150 秒で 981726・25032 ノード、tr12-30 450 秒で 130452.6・105988 ノード)。強分枝 (`mip_pscost_minreliable=0`) は効かないか逆
   (tr12-30 は止めると 389 → 197 秒)、木の中の再スタートは csched008 だけで決め手、ヒューリスティクス・対称性はノード数に効かない。
   neos-957323 はどのオプションでも 101〜222 ノードで、差の元はオプションの範囲では特定できなかった。
   (HiGHS を計装してソースからビルドする手は、この環境で外のコードのビルドが拒まれたので使っていない。`highs_nodecnt.patch` は記録として置いた)
2. **ENOMOTO のノードの分離には、固定費用ネットワーク型の判定に当たらない問題で経路集約がない**(事実、コード): 既定のノードの分離 (`light`) は、
   判定 (`fixed_charge_network_for_nodes`: 変数上限のある連続列が 9 割以上など) に当たらなければ経路集約の始点が 0 本。kasai (変数上限のある連続列 462/924)
   はこれに当たり、HiGHS がノードで毎回回す経路集約を ENOMOTO はノードで一度も回さない。kasai の 1 スレッド・120 秒で、処理した 9074 ノードのうち
   8210 を分枝し、LP の値で刈れたのは 59 (HiGHS は同じ程度のノード数で 36% が葉)。
3. **試作 `ENOMOTO_MIP_NODECNT=h` (ノードでも経路集約を、HiGHS の移植も含めて使う) で kasai が良くなる** (neos-1456979 は旧ビルドでは良く見えたが、新しいビルドでは揺れの範囲、9.4 節)(事実、600 秒・種 1・2):
   kasai は種 1 で **455 秒で最適** (既定は時間切れ、ギャップ 4.9e-3)、種 2 はギャップ 4.0e-3 → 4.7e-4。neos-1456979 は 2 回とも下界 162・165 → 168、
   暫定解 → 最適値 176。csched008・tr12-30・sct2・unitcal_7・rococoC10 は解けず、差は揺れの範囲 (csched008 は暫定解が悪い)。
   csched008・tr12-30・unitcal_7 で HiGHS のノードの分離のどの部品が効くのか (経路集約以外: 含意の境界・tableau・プールから戻すこと) は未特定。
4. **害**: 58 問 (60 秒・種 1・2) で SGM +3.1% (95% 区間 −0.8%〜+8.0%)、解けた回 84 → 83。揃って遅いのは noswot (34 秒 → 2 回とも時間切れ。ただし
   後の確かめでは既定が時間切れで揺れが大きい)、ほかに qiu・binkar10_1 (1.4〜1.8 倍)。速いのは neos5・misc07・timtab1 (各 1 回)。
   **既定にはしない**。経路集約の採られた割合で絞る `g` は効く問題と効かない問題を分けられなかった。
   根で採った経路集約のカットの本数で絞る `hr` (9 節) は、kasai の効き目を保ち (種 1 は 553 秒で最適)、58 問の害を +1.5%・解けた回 84 → 84 に減らした。
5. 4 スレッドの木の別の弱さ (事実): kasai の既定 (4 スレッド) では、全体の下界 = 共有の待ち行列の最小で、共有の待ち行列に 1.3 万〜2.8 万ノードが溜まり、
   各スレッドは手元の待ち行列 (約 1000 ノード、下界は最適値の近く) ばかり処理する。600 秒でも 120 秒の下界から動かない。`h` + 既存の試作
   `ENOMOTO_MIP_TREE1_POOL=1` (下界最小を取る番に共有の待ち行列から取る) で 120 秒の下界 985701 → 987039。1 スレッドの `h` (987472) の方が高い。
6. 試作 `d` (HiGHS の `computeBasicDegenerateDuals` に倣う、基底にあって境界に張り付いた整数列の被約費用による固定) は、kasai・neos-957323 で
   固定は起きる (kasai 1 スレッド 120 秒で 12791 本) が、下界・ノードは変わらないか重さで悪い。効き目は見えない。
7. 誤答の検査 (`dh`): fuzz_tiny 400 (既定と同じ既知の 13 件・同じ種)、mip_fuzz_vs_highs 300 (0 件)、固定費用の乱数の問題 300 (`fuzz_fc.py`、0 件)。
   `cargo test --release --lib` は 375 件通過 (19 件 ignored)。

次の一手 (推測を含む):
- ノードの経路集約を「効く問題」だけに絞る条件を、根の情報で作る (例: 根で経路集約のカットが下界の伸びに占める割合、変数上限のある連続列の割合の閾値を 9 割から下げる)。
  時間で絞るなら、ノードの経路集約の始点の数 (`ENOMOTO_T_MIP_NODE_FC_PATH_STARTS` = 1000) を小さくする形も試す価値がある。
- csched008 (連続列なし)・tr12-30・unitcal_7 で HiGHS のノードの分離の中のどの部品が効くかは、HiGHS の計装 (ビルドが許される環境で `highs_nodecnt.patch`
  に部品ごとの切り替えを足す) が要る。ENOMOTO の `light` が止めているもの (含意の境界の連続列・tableau の行数 50・mcf・clique) を 1 つずつ戻す試しも候補。
- 4 スレッドの共有の待ち行列の飢え (5) は `h` と独立に効くので、`TREE1_POOL` と合わせた評価。

## 0. 方法と制約

- HiGHS v1.15.1 を計装してソースからビルドする手 (`highs_nodecnt.patch`: 刈り込みの理由の内訳・退化した双対の固定の数・ノードの選び方の数、
  環境変数で衝突解析・退化した双対・ノードの被約費用の固定を止める) は、**この環境で外のコードのビルドが拒まれた**ので使っていない。
  パッチは記録として置いた。HiGHS の部品の切り分けは highspy のログとオプション (`mip_pscost_minreliable`・`mip_allow_restart`・
  `mip_heuristic_*`・`mip_detect_symmetry`・`mip_allow_cut_separation_at_nodes`) の範囲にとどめた。止められない部品 (衝突解析・
  ノードの伝播・退化した双対) は ENOMOTO 側に足して確かめる。

## 4. 試作 `ENOMOTO_MIP_NODECNT` (既定では使わない)

値の文字で部品を選ぶ (src/mip/solver.rs `nodecnt`):

- `p`: 木の中の分離 (`tree_sep`) で、固定費用ネットワーク型の判定に当たらない問題でも経路集約 (従来の実装、始点は
  `ENOMOTO_T_MIP_NODE_FC_PATH_STARTS` = 1000) を使う (`Solver::tree_sep_fc` を真にする)。既定では判定に当たる問題だけノードで経路集約を使い、
  ほかはノードの経路集約の始点が 0 本。
- `h`: `p` に加え、ノードでも HiGHS の経路集約の移植 (`path_aggregation_highs`) を使う (既定ではノードでは従来の実装だけ)。
- `d` (`1` と同じ): ノードの LP で基底にあって境界に張り付いた整数列に、双対単体法の 1 歩の比の判定で被約費用を与え、被約費用による固定をする
  (HiGHS の `HighsLpRelaxation::computeBasicDegenerateDuals` に倣う、`Solver::degen_dual_fixing`)。1 ノードの候補は
  `ENOMOTO_T_MIP_NODECNT_MAXC` (既定 100) 本まで。双対の符号が許容誤差を越えて食い違う候補は使わない。

ノードの分離をする・しないの判定 (`tree_sep_start`) と回数・時間の予算は既定のまま。分離の中身だけを変える。

## 5. 既定の ENOMOTO と HiGHS の並べ (600 秒・4 スレッド・種 1、`e600.jsonl` の def の回、HiGHS は `hres.jsonl` の def と過去の記録)

ENOMOTO の下界は全体の下界 (`TREE4` の行の `glb`、主の経過の行の `lb` は主の手元の待ち行列の値で全体の下界ではない)。
「共有」は共有の待ち行列の大きさと最小の下界。強分枝は主のスレッドの数 (`branching:` の行)、衝突は主のスレッドの数。
