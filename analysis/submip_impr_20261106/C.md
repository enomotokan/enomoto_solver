## 1. 試作の中身 (`src/mip/heur_subfix.rs`、既定では使わない)

`ENOMOTO_MIP_SUBFIX=<文字>` (値 `1` は `ritc`):

| 文字 | 中身 |
|---|---|
| `r` | 外側の根の RENS (暫定解があるとき。既定は LP で整数値の列を全部固定する `rens_old` を並列のサブ MIP で) を **ダイブ** ([`Solver::subfix_dive`]) にする。暫定解のない根の RENS (既定のダイビング式、目標 0.8) は変えない |
| `i` | 外側の根の RINS (既定は `rins_highs`: 一致する列を全部伝播しながら固定) を同じダイブにする (一致する列を固定)。既定の `S4_RINSRATE` (固定率 0.5 未満ならサブ MIP にしない) も当てる |
| `t` | 木の中の RINS (ALNS の RINS の腕) を同じダイブにする |
| `h` | 外側の根で RINS を呼ばない (HiGHS の `evaluateRootNode` は根で RENS だけ。`r` と合わせる) |
| `c` | 根の被約費用のサブ MIP (既定で固定率 0.3 未満はやらない) の固定率と結果も共通の記録に入れる |

ダイブ (HiGHS v1.15.1 の `HighsPrimalHeuristics::RENS`・`RINS` に倣う):

1. 自由な整数列を lock の積 ((ε + 下) × (ε + 上)) の大きい順 (同点は乱数) に並べる (HiGHS の `setupIntCols`)。
2. 目標の固定率 = HiGHS の `determineTargetFixingRate` (初め 0.6、実行不能だった固定率の平均 × 0.9 を上の端、解を見つけた固定率の平均の 0.9〜1.1 倍を
   含む範囲の乱数)。記録は**外側の求解の全スレッドで共通** (静的な `STATS`、外側の求解の始めに消す)。RENS・RINS・被約費用 (`c`) で共通。
3. 段: 今の LP 解で、RENS は列を [切り下げ, 切り上げ] に締め (整数値なら固定)、RINS は LP 解と暫定解が一致する列を固定する。1 列ごとに伝播し、
   固定率が `min(目標, 1 − (1 − 今の率) × 0.9)` (残りの自由な列の 1 割) に達したら段を終えて LP を解き直す。
4. 締める列が尽きたら (RINS は固定率 0.25 未満のときだけ)、分数の列を `getFixVal` (根の LP 解からの変化 ≥ 0.4 ならその向き、でなければ費用の悪くなる向き、
   費用 0 なら近い整数) で、丸め幅の小さい順に丸め幅の和 0.5 まで固定する。根の LP 解は外側の根で RENS・RINS を呼んだときの LP 解 (共通の記録に置く)。
5. 段の LP が実行不能か打ち切り値以上なら、その段の固定を捨てて段の幅を半分にする (10 回まで)。伝播の矛盾は最後の 1 列だけ戻す。
   (HiGHS は最後の分枝を逆にする深さ優先の戻り。ここは簡略化。)
6. 目標の固定率に達したら (固定率 < 0.1 ならサブ MIP にしない。HiGHS は深さ優先の探索 10 回)、その定義域でサブ MIP (ノード上限 500、時間・停滞・成果連動の
   打ち切りは既定のまま) を解く。
7. **空振りのやり直し**: サブ MIP が 1 ノード以下で実行不能なら、目標を「達した固定率 × 0.5」にし、ダイブの深さ (締めた回数) の半分まで戻って 3 から
   やり直す (深さの半分 ≤ 1 か `ENOMOTO_T_MIP_SUBFIX_TRIES` (既定 5) 回でやめる)。
8. やり直しにはサブ MIP の結果が要るので、**根の RENS・RINS のサブ MIP は主のスレッドで解く** (既定の根の RENS は別スレッドの並列のサブ MIP)。

ログ: `MIP:   SUBFIX <RENS|RINS|tree RINS> try k: target …, fixing rate …, depth …, … free integer columns …, status …, nodes …, accepted …` と、
終わりの `MIP: SUBFIX summary: dives … sub-MIPs … accepted … root-infeasible retries … ; success … (mean rate …), infeasible … (mean rate …)`
(木のスレッドの分も数える。木の RINS の 1 行ずつのログは主のスレッドの分だけ)。

チューニングの変数: `ENOMOTO_T_MIP_SUBFIX_RATE0` (初めの目標 0.6)、`ENOMOTO_T_MIP_SUBFIX_TRIES` (5)、`ENOMOTO_T_MIP_SUBFIX_ITERS_MULT` (ダイブの LP 反復の上限、
ノードの平均の 20 倍 + 1 万)。

## 4. まとめ

事実:

- 試作 `ENOMOTO_MIP_SUBFIX` (既定では使わない) は、HiGHS と同じく RENS・RINS を「LP を解き直しながら 1 割ずつ固定し、目標の固定率 (初め 0.6、共通の統計で動く)
  で止めるダイブ」にし、サブ MIP が根で実行不能なら目標を半分にして深さの半分まで戻ってやり直す。
- 8 問 (300 秒・2 回): neos-933966 (既定 3379・388 → fix 1337・最適 159 秒、fixh 3370・最適 139 秒)、thor50dday (86020・190078 → 72621・76015)、
  physiciansched6-2 (根の後 49324 が 4 / 4 回。既定は 1 / 2 回)、fiball (143 → 142) が良くなる。cod105 は遅くなる (154〜164 秒 → 176〜262 秒)。
  nexp-150-20-8-5・trento1・drayage-25-23 は揺れの範囲。
- やり直しは physiciansched6-2 で効く (0.60〜0.66 で 0 ノードで実行不能 → 0.31〜0.34 で最適値 49324)。他の 7 問では根で実行不能のサブ MIP はほぼ出なかった
  (`SUBFIX summary` の root-infeasible retries は physiciansched6-2 の 3 本だけ)。
- 58 問 (60 秒・2 回): fixh は既定と同じくらい、fix は少し悪い (3 節)。
- `cargo test --release --lib`: 346 通過・0 失敗 (試作を入れた後)。既定の動きは変えていない (環境変数がなければ新しい分岐に入らない。
  `note_fix_rate` の共通の記録への書き込みも `ENOMOTO_MIP_SUBFIX` があるときだけ)。

推測・次にやること:

- 既定にするなら fixh の形 (`rtch`) が候補だが、58 問で得がなく、8 問の得 (neos-933966・thor50dday) は 300 秒の長い回のもの。600 秒の Mittelmann の集合で
  確かめる価値はある。
- 害の元は根のサブ MIP を主のスレッドで解くこと。cod105 (自由な整数列 409・密な行) では RENS のダイブのサブ MIP が 26 秒で解なし、thor50dday では 286 秒
  主を止めた (その代わり良い解)。HiGHS のサブ MIP は 200 ノードで止まり時間では止めない。(a) 1 回目は並列のサブ MIP のまま出し、根で実行不能と分かったときだけ
  やり直しを主で解く、(b) 根のサブ MIP のノード上限を HiGHS と同じ 200 にする、を試すとよい (担当 A の打ち切りの試作と合わせる必要がある)。
- 木の RINS のダイブ (`t`) は 1 本 0.3〜6 秒で、大近傍探索の時間の予算の中で回る。木で解を出したのは neos-933966 の 2 本だけ。

## 5. 続き (2026-11-06 夜〜11-07、親のセッションの依頼): 根をふさぐ害を減らす形 `n`・`p` と、担当 A の `SUBA_RATE=n` との比べ

### 5.1 足したつまみ (`ENOMOTO_MIP_SUBFIX` の文字、既定では使わない)

| 文字 | 中身 |
|---|---|
| `n` | SUBFIX のサブ MIP のノード上限を HiGHS と同じ `200 + 外側のノード数 / 20` にする (既定の 500 の代わり。`ENOMOTO_T_MIP_SUBMIP_NODES_MULT*` の倍率はそのまま掛かる) |
| `p` | 根の RENS のダイブの 1 回目のサブ MIP は既定どおり**並列のサブ MIP** (別スレッド) で出す。受け取ったときに 1 ノード以下で実行不能なら印を付け、根の並列のサブ MIP を全部受け取った後 (`join_submips(0)` の直後、ヒューリスティクス名 `RENS (SUBFIX retry)`) に、目標を「達した固定率 × 0.5」にした新しいダイブを主のスレッドで解く (深さの半分まで戻る代わりに今の LP 解からダイブし直す) |

### 5.3 推測

- `p`・`n` はどちらも cod105・thor50dday の根をふさぐ害を減らさない。害の元は「根のサブ MIP に残り時間をまるごと与え、根の終わりに全部を待つ」既定の仕組み
  (`SUBMIP_HIGHS` の `t`、`join_submips(0)`) で、固定の仕方ではない。これは別のセッションの `ENOMOTO_MIP_SUBCAP*` (重いサブ MIP のノード数の上限) と
  担当 A の止め方の範囲。
- 固定の仕方としては、SUBFIX の `rtch` (LP を解き直すダイブ + 根で実行不能ならやり直し) が `suban` より thor50dday で良く、physiciansched6-2 で同じくらい、
  neos-933966 と cod105 は揺れの中。以下の Mittelmann 600 秒は `fixh` (`rtch`) で測る。

## 7. 既定にする価値があるか (判断)

事実のまとめ:

| 集合 | fixh (`rtch`) と既定の差 |
|---|---|
| 8 問 (300 秒・2 回、2 節) | 良い: neos-933966・thor50dday・physiciansched6-2。悪い: cod105 (+10〜20 秒)。ほかは揺れ |
| 58 問 (60 秒・2 回、3 節) | SGM −0.4% / +0.1%、解けた数 43 / 41 (既定 42 / 42)、主ギャップの和 同じくらい |
| Mittelmann 20 回 (600 秒、6 節) | 良い 9 回・悪い 5 回 (うち trento1 は無関係の揺れ)・同じ 6 回 |

判断 (推測を含む):

- **今のままでは既定にしない**。58 問で得がなく (揺れの範囲)、600 秒の得は「根の RENS を目標 0.6 で止めたダイブ」が当たる一部の問題
  (physiciansched6-2・neos-933966・thor50dday・neos-4722843-widden) に限られる。害も 1 回ずつで出ている (sing326 は根の RINS をやめたため、swath3 種 1・cod105)。
  swath3・neos-4722843-widden・neos-933966 は同じ設定でも種で数倍変わるので、1〜2 回では言い切れない。
- 効いているのは**根の RENS のダイブ** (`r`) で、根の RINS をやめる `h` は sing326 で害、根の RINS もダイブにする `i` は 58 問で悪い (`fix`)。次の候補は
  **`rtc` (根の RENS のダイブ + 木の RINS のダイブ、根の RINS は既定の形のまま)**。これは測っていない。
- 根のサブ MIP が根をふさぐ害は、既定でも起きている (thor50dday・cod105 の根の終わり)。`p`・`n` では減らない (5 節)。直すなら根のサブ MIP の時間の上限か
  根の終わりの待ち方で、別のセッションの `ENOMOTO_MIP_SUBCAP*` の範囲。
- 採るとしても、Mittelmann の残りの問題 (根で暫定解のある問題) を含む 2〜3 回の計測で、`rtc` と `rtch` を既定と比べてから。
