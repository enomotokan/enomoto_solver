# RELPS: 分枝の得点を SCIP の relpscost に寄せる (2026-11-27、親の依頼・利用者の承認済み)

背景 (analysis/gap240_20261126 4 節の候補 2):
- mcsched・swath1・dano3_5 は、根の下界が SCIP と並び、1 ノードあたりの秒も同じか短い。それなのに木が 2.5〜34 倍大きい。
- 過去の試み:
  - SB_PROBEBD: swath1 は効いたが、30n20b8 が悪化した。
  - SB_ADAPT: dano3_5・mcsched が解けたが、P の 4 スレッドで外れた。
  - CONFLICT_WEIGHT=0.01・cfx2: 不採用。
  - SBDEGEN: 4 スレッドで 1.032 で、閉じた。

進め方:
1. SB_ADAPT の 4 スレッドの外れを切り分ける (1 節)。
2. SCIP の branch_relpscost.c と当方の違いを表にする (2 節、`scip_compare.md`)。
3. 違いから試作する (3 節、既定オフ)。
4. 5 問 (mcsched・swath1・dano3_5・30n20b8・mc11) を 1・4 スレッドで比べる (4 節)。良ければ P を回す。

既定は変えない。

### 1.2 今のビルドで部品を外す (ビルド e834070ec。既定と既定 + `ENOMOTO_MIP_SB_ADAPT=1`、種 1・60 秒)

SB_ADAPT の中身は 2 つの強さでできている (analysis/sbadapt_20261124 1 節)。
- f_A = σ(5.05 (cpn − 1.7)): 強分枝の予算を HiGHS の大きさへ寄せ、双対退化のノードでも確率 f_A で強分枝する。
- f_B = σ(11.9 (0.185 − deg)): 強分枝の子の伝播 (SB_PROBEBD) を確率 f_B で使い、衝突の重みの床を 0.01 f_B にする。

部品は tunable で外した。
- `_nofa`: `ENOMOTO_T_MIP_SBAD_AB=100` で f_A ≈ 0 にする。
- `_nofb`: `ENOMOTO_T_MIP_SBAD_BB=-10` で f_B ≈ 0 にする (子の伝播と床の両方が止まる)。
- `_nocw`: `ENOMOTO_T_MIP_SBAD_CW=0` で床だけ外す。
- `_np`: `ENOMOTO_MIP_PARSB=0` で強分枝の子の投機を切る。

表の値は「秒 / ノード数 / 強分枝の LP の回数」。強分枝の LP は「MIP: branching:」の行の値で、4 スレッドでは主のスレッドの分。

分かったこと:
- **外れの元は f_A の側 (強分枝の予算を HiGHS の大きさに寄せ、退化のノードでも強分枝する) で、強分枝の量が増えたことによる。**
  - f_A だけ止めると (`_nofa`)、3 問とも強分枝の量が既定並みに戻る。4 スレッドでは既定よりわずかに速い (27.3・18.5・4.5 秒)。
  - f_B を止めても (`_nofb`) 量は減らず、遅いまま。
- f_A は 200 ノードごとの診断では 0.002〜0.02 で、ほぼ働かないように見える。それでも強分枝は 2〜4 倍に増えた。
  - cpn = 衝突の数 ÷ (ノード数 + 1) は、木の始め (ノードが少ないとき) に大きくなる。そこで f_A が 1 に近づき、予算が大きく開くとみている (推測。始めの f_A の値は出していない)。
  - 4 スレッドで目立つのは、主のスレッドが木の上のほうを受け持ち、始めの強分枝の量の増えがそのまま全体の遅れになるため (推測)。
    graph20-20-1rand は 1 スレッドでも遅い (13.7 秒、既定 8.0 秒)。
- 強分枝の子の投機 (PARSB、2026-11-26 に既定) は主因ではない。切っても強分枝の量は変わらない (mc11 は差が縮む)。
- まとめ:
  - mc11・eil33-2・graph20-20-1rand は**強分枝の量** (f_A)。
  - neos-960392 は**道筋** (enum と重なる)。
  - neos-911970 は**揺れ**。
  - スレッドの取り合いの証拠は見つからなかった。
- RELPS への含意:
  - 強分枝の予算を大きくする向き (SB_BUDGET_HIGHS・SBDEGEN・SB_ADAPT の f_A) は、4 スレッドで強分枝の手間として遅れに出る。
  - そのため、まず予算を増やさずに情報の使い方を変える部品から試す (3 節)。

## 2. SCIP の relpscost と当方の違い (`scip_compare.md`)

SCIP master の branch_relpscost.c・branch.c・var.c などを読み、当方の `select_branch_inner` (src/mip/solver.rs)・src/mip/pseudocost.rs と比べた。
計測の相手の 10.0.2 のタグとも差分を見た。詳しい表は `scip_compare.md` に、ソースで確かめたことと推測を分けて書いた。要点:

| 点 | SCIP (既定) | 当方 (既定) | 違い |
|---|---|---|---|
| 信頼度の閾値 | 1〜5、予算の残りで動かす (prio の式) | 同じ式 | 予算の大きさが違う (下の行) ので、当方は閾値が早く 1 に下がる |
| 反復上限で止まった強分枝の子 | 途中の値で擬似費用を更新し、回数も数える | 数えない (`PCL=a` の試作だけ一部) | **違う** |
| 統計で強分枝を省く (`skipbadinitcands`) | 有効。観測 2 回以上の候補を、強分枝の最良と比べて検定で飛ばす | なし | **違う** |
| 強分枝していない信頼できない候補 | 強分枝した候補が 1 本でもあれば選ばない (bestuninit の規則) | lookahead・予算で止まった後、事前の点数 (観測のない向きは全体の平均) で選べる | **違う** |
| 子の伝播と probingbounds | どちらも有効。片側が切れたときも、残った子の境界をノードに置く | 既定でオフ (`SB_PROBEBD` が近い。両方の子が残ったときだけ和を置く) | 違う |
| 点数の混ぜ方 | 擬似費用 + 衝突 0.01 + 推論 1e-4 + 打ち切り 1e-4 (動的な重み)、積の形 eps 1e-6 | 式の形は同じ。衝突の重みは CW_RAMP (始め 200 ノードは 0、その後 0〜0.1) | 衝突の始めの重み |
| 予算 | 10.0.2: 0.5·x + 100000 (+ 根の強分枝の反復)。master: 再スタート 2 回までその 0.25 倍 | 0.125·x + 25000。根の強分枝の反復も中に数える | 大きさと根の扱い |
| 子 1 本の反復上限 | 平均の 2 倍 (10〜500) | 平均の 4 倍 (10〜500) | 小さな違い |

注意 (ソースで確かめた):
- 今の `select_branch_inner` は `pc.min_reliable` (`ENOMOTO_T_MIP_MINREL`) を信頼度の判定に使っていない。信頼度は上の 1〜5 の閾値 (`thr_of`) で決まる。
  - `ENOMOTO_T_MIP_MINREL` が効くのは、擬似費用と全体の平均の混ぜ方 (pseudocost.rs の `w`) だけ。
  - treegap_20261123 3 節の「強分枝なし (`ENOMOTO_T_MIP_MINREL=0`)」は、強分枝を止めていなかった。
    そのため「当方の強分枝は木を小さくしていない」という結論の根拠は崩れる。
  - 強分枝を本当に止めるなら `ENOMOTO_T_MIP_SB_MAXCAND=0` などが要る。

## 3. 試作 `ENOMOTO_MIP_RELPS` (既定オフ、src/mip/solver.rs `relps_has`・`select_branch_inner`)

値の文字で部品を選ぶ。どれも主の木だけで働く (サブ MIP では使わない)。強分枝の予算は増やさない (1 節の含意)。

- **`u`** (強分枝していない信頼できない候補を、信頼度つきで弱める):
  - 強分枝をしたノード (このノードで 1 本以上強分枝した後) に限って、強分枝していない信頼できない列の事前の点数に重み w = n / (n + thr) を掛ける。
    n はその列の観測の少ない方の回数、thr は信頼度の閾値 (1〜5、既存の `thr_of`)。
  - w は ln(n / thr) のシグモイド。観測 0 回なら 0 で、SCIP の bestuninit の規則 (選ばない) と同じ。観測が閾値に近づくと 1/2 に近づく。新しい閾値はない。
  - 信頼できる列と、強分枝をしていないノード (予算切れ・退化など) の点数は変えない。
- **`c`** (反復上限で止まった強分枝の子も観測に数える): 子の途中の値 (双対単体法なので下界) で擬似費用を更新し、回数も数える。SCIP と同じ。
- **`r`** (根の強分枝の反復を予算に数えない): 深さ 0 の強分枝の反復を、木の強分枝の予算 (`sb_iters`) から外す。SCIP と同じ。
- 診断: `ENOMOTO_MIP_RELPS_DIAG=1` (または `RELPS` を付けた回) で、終わりに 1 行出す。
  - 書式: 「MIP: RELPS: selections with strong branching …, picked an unreliable column without strong branching …, capped children observed …, root sb iters not counted …」
  - 「強分枝をした選びのうち、強分枝していない信頼できない列を選んだ数」は、試作がなくても数える。
- 試していない残りの候補 (`scip_compare.md` 7 節):
  - skipbadinitcands に当たるもの
  - 予算を SCIP 10.0.2 の大きさにする (1 節の含意から後回し)
  - 片側が切れたときの子の境界

## 4. 5 問の 1・4 スレッド (`run5.py`・`res5.jsonl`・`logs5/`、ビルド 8fda04043、種 1・300 秒)

時間は秒、ノードは木のノード数。RELPS の数えは「強分枝をした選び / そのうち強分枝していない信頼できない列を選んだ数 / 止まった子を観測に入れた数 / 予算から外した根の反復」。

| 問題 | スレッド | 既定 | `u` | `ucr` |
|---|---|---|---|---|
| swath1 | 1 | 最適 46.9 秒・2904 | 最適 45.5・2904 | 最適 43.5・2170 |
| mc11 | 1 | 最適 57.8・3111 | 最適 47.4・2933 | 最適 105.5・5058 |
| 30n20b8 | 1 | 時間切れ・暫定解 402 | 時間切れ・453 | 時間切れ・**暫定解なし** |
| mcsched | 1 | 時間切れ・下界 195833 | 時間切れ・196641 | 時間切れ・195638 |
| dano3_5 | 1 | 時間切れ・暫定解 577.27 | 時間切れ・579.68 | 時間切れ・578.28 |
| swath1 | 4 | 最適 22.1・217 | 最適 21.6・223 | 最適 23.2・221 |
| mc11 | 4 | 最適 15.2・1289 | 最適 28.2・2436 | 最適 26.5・3050 |
| 30n20b8 | 4 | 最適 255.4・2397 | 最適 116.4・4003 | 最適 110.0・2665 |
| mcsched | 4 | 最適 176.1・94535 | 最適 159.3・86111 | 最適 170.1・91724 |
| dano3_5 | 4 | 時間切れ (下界 576.395) | 時間切れ (576.377) | 最適 300.0 |

- `u` は狙いどおりに働いた。強分枝していない信頼できない列を選んだ数は、既定の 14→2 (swath1 1T)・7→0 (mc11 1T)・90→3 (mcsched 1T)・15→0 (mc11 4T) に減った。
  ただし、強分枝をした選び自体が木のノードの 1〜10% と少ないので、道筋への効き目は小さい (swath1 1T はノード数が同じ)。
- 1 スレッド (決定的) では `u` は mc11 で 18% 速く、他は同じか揺れの範囲。4 スレッドは種 1 回だけで、mc11 は遅く 30n20b8・mcsched は速い。どちらも揺れと分けられない。
- `ucr` は 1 スレッドの mc11 が 1.8 倍遅く、30n20b8 は 300 秒で暫定解が出なかった (既定 402)。30n20b8 は「悪化しないこと」の問題なので、`ucr` は今のままでは使えない。
  `c` と `r` のどちらが効いたかは分けていない。`r` は根の強分枝の反復 (6000〜19000) をそのまま木の予算に回すので、SB_ADAPT の f_A と同じく強分枝を増やす向き (1 節) になる。
- このため、P では `u` だけを既定と比べる (5 節)。

## 5. P の `u` と既定 (`prun.py`・`prun.jsonl`・`psumm.py` → `psumm.txt`、ビルド 29f47dc7c、60 秒)

- 測ったのは 1 スレッド (決定的、種 1) と 4 スレッド (種 1)。4 スレッドの種 2 は、2 つの結果で向きがはっきりしたので回していない。
- 時間の比は SGM (u / 既定、shift 1 秒、時間切れは 60 秒) と、問題単位のブートストラップ 95% 区間。

| | 問題 | SGM (u / 既定) | 解けた数 u / 既定 | 強分枝していない信頼できない列を選んだ問題 (既定 → u) |
|---|---|---|---|---|
| 1 スレッド・種 1 | 58 | **+4.0%** [−0.0%, +9.5%] | 42 / 42 | 21 → 11 |
| 4 スレッド・種 1 | 58 | +1.0% [−1.9%, +4.3%] | 47 / 47 | 15 → 9 |

- 目的値の食い違い・落ちた回はなし。
- 1 スレッドで 1.25 倍超遅いのは noswot 2.58・rout 2.05・roll3000 1.42 (60 秒で解けず)・graph20-20-1rand 1.34・neos-911970 1.34。速いのは mc11 0.80 だけ。
  - noswot・rout・roll3000 は、`u` で強分枝をした選びが 1.6〜4 倍、ノード数が 1.4〜2.4 倍に増えた。
    強分枝していない列を避けた結果、別の列を選んで道筋が変わり、木が大きくなった (推測。どの列を選んだかは見ていない)。
- 4 スレッドの 1.25 倍超は、遅い側が dcmulti 1.59 (3 ノード、1〜3 秒の揺れ)・mas76 1.35・rout 1.32、速い側が qiu 0.61・10teams 0.79・noswot 0.80。
- 結論: `u` は SCIP の bestuninit の規則を信頼度つきで真似たものだが、当方では速くならない。1 スレッドでは悪化の側にある。
  当方の強分枝は、選び全体の 1〜10% のノードでしか起きず、強分枝していない信頼できない列を選ぶのもその一部 (P で 21 問、1 問あたり数回)。
  このため、効く場面が少ないうえ、効いたときは道筋を変える揺れとして出る。
