# beasleyC3・mc11: 固定費用型の木のノードの分離を既定にできるか (2026-10-20)

環境: CPU 4 (nproc=4、専用コンテナ。ソルバーは同時に 1 つだけ)、コミット bc89ad1 (develop) + 本ブランチの試作
(`ENOMOTO_MIP_FC_NODE_SEP2`、bdc3512 の `..._ADAPT` を含む)、HiGHS 1.15.1。**計測はすべて 4 スレッド**
(ENOMOTO は `ENOMOTO_MIP_THREADS=4`・`solve(..., 4)`、HiGHS は `threads=4`)、時間上限 60 秒。前のセッションの 1 スレッドの
数値 (前版のこのメモ) は使わず、すべてやり直した。ログは `runs/logs_4t_20261020.tar.gz` (展開すると `runs/logs/`、
`runs/summ.sh <log>` で前処理後の大きさ・根・暫定解の推移・最後の行を出す)、実行は `runs/go.sh`・`runs/batch_*.sh`。

木の下界は表の行 (`time nodes open best bound incumbent gap`) の大域的な値で比べる。`MIP: ... nodes ... lb` の行の lb は
主スレッドの待ち行列だけの値で、問題によっては大きく違う (ran14x18-disj-8 で 3622.7 対 大域 3563.5) ので使わない。

## 0. 要約

- 事実
  - **(a) `ENOMOTO_MIP_FC_NODE_SEP` (557090f) と `..._ADAPT` (bdc3512) は、ノードの分離がほとんど走っていない**。
    待ち行列から取り出したノードでは、先にカットプールのラウンド (`pool_cut_round`、違反カットを 10 本まで戻す) が
    `resolves += 1; continue` で解き直し、その後のノードの分離の条件 `resolves == 0` が偽になる。プールに違反カットが
    あるノード (ほぼ全部) で分離が飛ばされ、60 秒で分離した回数は主スレッドで beasleyC3 39 回 (994 ノード)、mc11 6 回
    (2198 ノード)。ADAPT は 4・5 回。だから重さの問題ではなく、効果がほぼなく揺れの範囲 (下の表)。既定にできない理由は
    これで、判定 (`fixed_charge_network_for_nodes`) そのものは問題ない。
  - **試作 `ENOMOTO_MIP_FC_NODE_SEP2`**: 取り出したノードではプールのラウンドの後でも分離し、LP の値が伸びる間
    5 ラウンドまで繰り返す (HiGHS の `HighsSeparation::separate` の 1.01 倍の基準)。時間はノードの分離 (解き直しを含む)
    が経過時間の 0.1 倍まで。保存した基底の行数が合わない (効いていたカットの行が消えた) ときは今の基底のまま解く。
    - beasleyC3: 既定・FC_NODE_SEP・ADAPT は 60 秒で解けない (大域の下界 746.9・748.2・746.8) が、SEP2 は
      0.1 の版で 3 回とも解けた (19.6・29.2・52.2 秒)。0.3 の版も 6 回中 5 回 (22.8〜56.5 秒)。HiGHS 25.9 秒。
    - mc11: 解けない (HiGHS 48.0 秒) が、下界 11463〜11466 (既定 2 回) → 11489〜11493 (0.1 の版 2 回)、
      暫定解 11712・11747 → 11716・11729。
  - 副作用 (判定に当たる他の問題、ソルバーの中の時間): rout 6.5・7.5 秒 → 9.0・9.1 秒 (0.3 の版では 15.9・20.9 秒)、
    h80x6320d 15.7・16.5 秒 → 18.8・25.5 秒、ran14x18-disj-8 は 60 秒の下界 3557.1・3558.0 → 3563.5・3567.0 (良くなる)、
    gr4x6・beavma は根で解けて変わらない。
  - **(b) HiGHS との残りの差**: 打ち切り値に最適値を与えても (`ENOMOTO_MIP_CUTOFF=11689.5`、HiGHS は
    `objective_bound`)、HiGHS は mc11 を 28.5 秒・209 ノードで証明するが、ENOMOTO は 60 秒で下界 11456.7 (既定)・
    11517.9 (SEP2 の 0.3 の版)。mc11 の差は主側だけでなく木の下界の伸び (ノードあたりの強さ) にもある。
    - ノードの LP の反復: HiGHS は全体で mc11 135718 反復のうち強分岐 97293、分離 8269、ヒューリスティクス 9450 で、
      ノードの LP は約 2 万反復 (675 ノード、1 ノード約 30)。beasleyC3 も 1 ノード約 60。ENOMOTO の主スレッドは
      取り出したノードの最初の LP が 1 回 350〜460 反復 (既定、beasleyC3 494 回で 22.8 万、mc11 589 回で 20.4 万)。
      SEP2 で基底の修復のまま (今の基底にしない) だと mc11 で 1 回 1400 反復 (118 回、うち行数の不一致 36)。
    - LP のカットの行: ENOMOTO は木の中で 2000 本前後に増える (beasleyC3 の LP の行 1980 → 3300、元の行 1153)。
      HiGHS は 434〜1000 本。年齢の上限は `ENOMOTO_T_MIP_CUT_AGE_PER_ROW` 0.5 × 行数を [30, 300] に収めた値で、
      どちらの問題も 300 (HiGHS は 10)。
- 推測
  - beasleyC3 は SEP2 で HiGHS と同程度になった。解けるまでの時間の揺れ (20〜56 秒) は 754 を見つける時刻
    (13〜53 秒) でほぼ決まる (主側)。HiGHS は根の部分 MIP で 756 を 1.9 秒に見つける。
  - mc11 の残りの差は、(1) 取り出したノードの LP の反復の多さ (ノードの数が稼げない)、(2) 根のヒューリスティクス
    (HiGHS は根で 11743、ENOMOTO は根で 12070〜12168)、(3) 強分岐の量 (HiGHS は反復の 7 割が強分岐) のどれか。
    切り分けていない。

## 2. 試作 `ENOMOTO_MIP_FC_NODE_SEP2` (既定では使わない)

`src/mip/solver.rs`:
- `Solver::fc_sep2` (新しい欄): `ENOMOTO_MIP_FC_NODE_SEP2` があり、`fixed_charge_network_for_nodes` に当たるとき
  (`fc_node_sep` も真になる)。
- ノードの LP のループ (`solve_node` 相当、`node_cuts_due` を呼んでいた所): `fc2_rounds / fc2_first / fc2_last` を持ち、
  取り出したノード (`node.depth > 0 && plunge_depth == 0`) では `resolves` に関係なく分離する。分離して加わらなければ
  そのノードでは打ち止め。ラウンドは `ENOMOTO_T_MIP_FC_SEP_ROUNDS` (5) まで、2 ラウンド目からは
  「LP の値 − 最初の値 > 1.01 × (前の値 − 最初の値)」の間だけ。ノードの分離の時間が経過時間の
  `ENOMOTO_T_MIP_FC_SEP2_TIME_FRAC` (0.1) 倍を超えている間は行わない。SEP2 では `node_cuts_due` (深さの規則) は使わない。
- `restore_node_basis`: SEP2 では、保存した基底の基底変数の数が合わない (効いていたカットの行が消えた) とき、修復した
  基底を置かずに今の基底のまま解く (`ENOMOTO_MIP_RESTORE_KEEP_CURRENT` と同じ扱い。`ENOMOTO_MIP_FC_SEP2_REPAIR` で従来の修復)。
- 効き目の統計 (`fc_record`、ログの `fc_sep calls / gain_ema`) は SEP2 でも取る。

`src/mip/separation.rs`:
- `separate`: `ENOMOTO_MIP_FC_NODE_PATH_HIGHS` なら、固定費用型のノードの分離でも HiGHS の経路集約の移植を使う
  (既定のノードの分離は従来の経路集約だけ)。beasleyC3 では同程度、mc11 では悪い (下界 11455.1) ので SEP2 には入れていない。

`cargo test --release --lib` (PyO3 のため `RUSTFLAGS="-C link-arg=-L/usr/lib/x86_64-linux-gnu -C link-arg=-lpython3.13"`
`CARGO_TARGET_DIR=target/testbuild`): 既定 mip 28 件、`ENOMOTO_MIP_FC_NODE_SEP2=1` で全体 302 件通過。

## 3. 失敗した・効かなかった試み

- `ENOMOTO_MIP_FC_NODE_SEP` / `..._ADAPT`: 上の通り分離がほぼ走らない。ADAPT の効き目のしきい値 (0.05) は確かめられない
  (calls 4〜6)。SEP2 の効き目の移動平均は beasleyC3 0.06〜0.28、mc11 0.02〜0.07、rout 0.11〜0.38、h80x6320d 0.16〜0.49、
  ran14x18-disj-8 0.16〜0.40 で、遅くなった rout・h80x6320d の方が高い。効き目で絞っても副作用は避けられない見込みなので
  ADAPT の方向は捨てた。
- SEP2 + 時間 0.3: beasleyC3 は解けるが、rout 2〜3 倍、mc11 の主スレッドのノードが 1/5。
- SEP2 + ノードで HiGHS の経路集約の移植: beasleyC3 同程度、mc11 悪い。
- SEP2 + 年齢の上限 50 (`ENOMOTO_T_MIP_CUT_AGE_LIMIT=50`): mc11 で LP の行は減らず (3770)、下界 11485.5。
- SEP2 + 1 ラウンド: beasleyC3 39.9 秒、mc11 11476.2 で、複数ラウンドより弱い。

## 4. 既定にするか / 残り

- SEP2 (0.1) は判定に当たる問題だけに効く。beasleyC3 が解けるようになり、mc11・ran14x18-disj-8 の下界も上がる。
  rout (+2 秒)・h80x6320d (+3〜10 秒) は遅くなるが、どちらも 60 秒で解ける。判定に当たらない問題は変わらないはず
  (`fc_node_sep` が偽なら SEP2 の分岐は通らない。40 問の全体の計測はしていない)。既定にする候補。
- 確かでない点: 各設定 1〜3 回で、beasleyC3 の時間は 754 を見つける時刻で 20〜56 秒と揺れる。rout・h80x6320d の遅れが
  分離そのものか経路の揺れかは切り分けていない。40 問の全体で判定に当たる問題はこの 7 問という前回の確認 (bc89ad1 の
  ログ) によるもので、MIPLIB の他の問題は見ていない。
- 次の手: (1) mc11 の取り出したノードの最初の LP の反復 (既定で 1 回 350 前後、HiGHS は 30 前後) の原因 (基底の復元・
  DSE の重み・カットの行の数) を見る。(2) mc11 の根のヒューリスティクス (HiGHS は根の部分 MIP で 11743)。
