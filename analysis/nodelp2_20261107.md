## 0. 方法の制約 (事実)

- 計装した HiGHS v1.15.1 のビルド (cmake) はこの環境で拒まれた (外のコードのビルド)。用意した計装 (`highs_nodelp2.patch`: 前回の
  `NLP` の行に、基底を戻したか (`rst`: 0 親の続き・1 兄弟/戻り・2 待ち行列 (前の潜りの最上位の基底)・3 待ち行列 (行が合わない古い基底)) を足し、
  `HIGHS_LPOPT` で MIP の LP の内側の Highs の設定を変える) は置いておくが、測っていない。HiGHS の数は highspy のログの終わりの表
  (ノード・LP の反復の内訳) と、オプションの切り替えと、ソースを読んだ事実に限る。
- highspy で `simplex_*`・`dual_simplex_cost_perturbation_multiplier` を変えても、MIP のノードの LP には届かない
  (`HighsLpRelaxation` の内側の `Highs` は既定の設定で作られ、MIP から渡すのは許容誤差と乱数の種だけ: `HighsLpRelaxation.cpp` の構築子)。
  だから HiGHS の双対単体法の部品 (摂動・DSE) を止めて比べることは highspy ではできない。

## 1. 同じ 120 秒・4 スレッドの並べ (事実、`e.jsonl` の `diag`・`h.jsonl` の `def`、種 1、1 回)

### 1.2 HiGHS のソースで確かめたこと (v1.15.1)

- ノードの LP の双対単体法は、出発点が「摂動なしで双対実行可能で、主実行不能が 1000 行未満かつ最大 1e-3 未満」(near optimal) のときだけ
  費用の摂動を省く (`HEkkDual::solve`)。分枝した子は境界が 0.1 以上動くので、木のほぼ全部の LP を摂動した費用で解く。摂動の量は列ごとに
  固定の乱数 (`numTotRandomValue`) で、`(1 + r)(|c_j| + 1) * 5e-7 * max|c|` (max|c| > 100 なら 4 乗根)。ENOMOTO の `perturb_costs` は同じ式。
- 待ち行列のノードは基底を持たない (`installNode` は `nodeBasis` を空にする)。潜りが終わったとき (`openNodesToQueue`) に、潜りの一番上の
  ノードの基底 (行の数が合えば) を LP に戻し、次に取り出したノードはその基底から解く。兄弟 (`backtrack`) は親の基底を、非基底の上限・下限の
  区別まで含めて戻す (`HighsBasis`)。
- 潜りの間は LP の行を消さない (`performAging(false)` は年齢を進めるだけ。消すのは分離のラウンドの `performAging(true)`)。兄弟に戻す基底は
  必ず行の数が合う。
- 強分枝は `Playground` で親の状態 (基底・重み) を保存して戻し、終わりに親の LP を 0 反復で解き直すので、子の LP の仕事を肩代わりしない。
- ノードの LP の反復の上限は max(10000, 10 x 平均, 1.5 x 最初の根の LP) で、反復を抑える仕組みではない。

## 2. HiGHS の部品を止める (highspy のオプション、120 秒、`h.jsonl`、途中)

`nosepnodes` = `mip_allow_cut_separation_at_nodes=false`、`age100` = `mip_lp_age_limit=100` (既定 10)、`rel0` = `mip_pscost_minreliable=0`
(強分枝なし)、`noheur` = `mip_heuristic_effort=0`、`norestart` = `mip_allow_restart=false`、`cut` = `objective_bound` に既知の最適値 + 余裕。
数は ノード / ノードの LP の反復/ノード / 全体の反復/ノード。

| 問題 | def | cut | nosepnodes | age100 | rel0 | noheur | norestart |
|---|---|---|---|---|---|---|---|
| supportcase33 | 824 / 63.3 / 257 | 351 / 98.9 / 539 | 744 / 65.9 / 262 | 525 / 74.8 / 350 | 2348 / 32.9 / 65 | 729 / 82.6 / 295 | 671 / 64.2 / 295 |
| ns1830653 | 4890 / 66.5 / 158 | 3951 / 92.5 / 203 | 12596 / 40.9 / 69 | 3825 / 79.9 / 183 | 5762 / 64.4 / 103 | 5390 / 62.2 / 143 | 5373 / 56.0 / 130 |

- 1 ノードの LP の反復を増やすのは LP の行を増やす向き (年齢の上限 10 → 100 で +12〜20%) で、木の中の分離を止めると ns1830653 では
  0.6 倍に減る (下界は 13004 → 12622 と悪い)。強分枝・ヒューリスティクス・再スタートを止めても 1 ノードの LP はほぼ同じ。
  HiGHS の MIP の側の部品では、ENOMOTO との 3〜10 倍の差は出ない。差の元は LP の解き方 (双対単体法の部品) と LP の大きさの側にある (推測)。
- highspy では MIP の LP の内側の設定 (摂動・DSE) を変えられない (0 節) ので、その部品の効きは ENOMOTO の側で HiGHS に寄せて測る (3 節)。

## 3. ENOMOTO の側で HiGHS に寄せる (120 秒・種 1、`e.jsonl`、途中)

注意: 最初の `diag` (ns1830653 1716 ノード) は古い wheel (他のセッションの変更の取り込み前)。その後の回は取り込み後の wheel で、
同じ既定の回 (`diag` 種 2) を計画 C で測り直す。

supportcase33 (スレッド 0 の待ち行列のノード、出発の主実行不能の内訳 構造列/元の行/カットの行):

| 設定 | ノード | 待ち行列 反復/LP | 出発の主実行不能 (内訳) | 兄弟 反復/LP | 兄弟の主実行不能 |
|---|---|---|---|---|---|
| 既定 (cut の回) | 5916 | 802 | 443 (85 / 308 / 51) | 307 | 44 (18 / 22 / 4) |
| bnt (保存した置き場所) | 7132 | 619 | 149 (39 / 89 / 21) | 238 | 22 (13 / 7 / 1) |
| rnever (戻さない、HiGHS の待ち行列と同じ) | 7115 | 695 | 915 (152 / 693 / 70) | 245 | 324 (57 / 241 / 27) |

- 待ち行列のノードでは、保存してから戻すまでにカットの行が平均 53 行足され 16 行消える (`rdiag`、RESTDIAG)。足された行の論理変数は基底に入り、
  親の頂点で破られるカットの分がカットの行の実行不能 (約 51 行) になる。
- 置き場所を保存どおりにすると (`bnt`) 出発の主実行不能は 1/3 になるが反復は 0.77 倍、戻さないと (`rnever`) 主実行不能は 2 倍でも反復は 0.87 倍。
  **出発の主実行不能の数は反復の決め手ではない** (事実)。
