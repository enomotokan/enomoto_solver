# neos-3216931-puriri の根のカットの LP が根の最適基底から遅い原因 (2026-11-06)

bench に使う環境変数: 試作 `h1` = `ENOMOTO_MIP_CUT_HARRIS2=1`、組み合わせ `h1mv` = `ENOMOTO_MIP_CUT_HARRIS2=1 ENOMOTO_MIP_HO4_CUT0=moved`
(既定の動きは変えていない。`ENOMOTO_MIP_CUT_HARRIS2` を付けなければ経路は前と同じ)。

生データは `analysis/puriri_cutlp_20261106/` (書き出した LP `cutlp_r0_TimeLimit.mps.gz` と基底 `cutlp_r0_TimeLimit.bas`、
ENOMOTO の単独の求解 `v_*.txt`・`base_*.txt`、HiGHS の求解 `highs_*.txt`、MIP のログ `logs/`、58 問 `bench58.jsonl`)。

## 結論 (短く)

- 原因は LU の実装の遅さではなく、**双対単体法の比の判定 (BFRT のパス 2、Harris の窓) が条件数の悪い基底へ入っていく**こと。
  根の最適基底 (条件数の見積もり 4.5e6) から既定の規則で進むと、10 反復で 2e6、50 反復で 1.2e8、100 反復で 3e11 になる。
  HiGHS は同じ基底から出発して 1.2 万反復まで 6e6〜1.4e8 に収まる。悪い基底では FTRAN の解が 1e6〜4e9 の大きさになり、
  PRICE の値と FTRAN の値が合わなくなる (照合の不一致)。再分解の直後 (更新 0 回) でも相対 50% 以上ずれることがある。
- 照合の判定 (相対 1e-7) は HiGHS の `updateVerify` と同じで、厳しすぎるのではない (ずれは本物の数値誤差)。LU は後退安定
  (残差は解の大きさに比べて小さい)。
- 前向きの Harris (既存の試作 `ENOMOTO_SIMPLEX_HARRIS2`、HiGHS 流に緩めた比 `ratio + Td/|alpha|` の範囲で |alpha| 最大を選ぶ) にすると、
  書き出した LP は根の最適基底から **23644 反復・15.8 秒で最適** (既定は 40 秒で打ち切り)、照合・悪条件の再分解は 0 回。
- 試作 `ENOMOTO_MIP_CUT_HARRIS2` (根のカットのループの LP だけ前向きの Harris) を足した。MIP では puriri のカットの LP は反復の上限
  (進みの判定) で先に止められるので、それだけでは根の下界は変わらない。上限で止めたら続けて解く既存の試作 `ENOMOTO_MIP_HO4_CUT0=moved`
  と組むと、0・1 ラウンド目のカットが入る (結果は下の表)。
- 害: 58 問 (60 秒・2 回) では解けた数 44→43、SGM +3.3%。前向きの Harris でカットの LP の着く頂点が変わり、分離されるカットが変わる
  (nw04 は根で閉じなくなり 10.7→47.4 秒)。既定にはしない。効かせる場面を絞るのが次の手 (4 節)。

## 2. 再分解の多発の原因

### 2.1 照合の不一致は本物の誤差

`ENOMOTO_DEBUG_D_DRIFT_EXT=1` の `VERIFY_FAIL` の行 (15 秒、`v_vf.txt`。更新の回数 `upd` と、どの判定に落ちたかを足した):

| 更新の回数 | 大きな不一致 (相対 > 0.5、悪条件の数に入る) | 特異の検査 | 照合 (相対 > 1e-7) |
|---|---:|---:|---:|
| 0 (再分解の直後) | 66 | 0 | - (更新 0 回では照合しない) |
| 1〜4 | 11 | 0 | 177 |
| 5〜19 | 6 | 1 | 53 |
| 20〜59 | 4 | 2 | 18 |
| 60 以上 | 8 | 2 | 7 |

- 照合の相対誤差は 1e-7〜1 に広く散らばる (最初の 10 秒の 227 回で 1e-7 台 56、1e-6 台 42、1e-5〜1e-4 台 39、1e-3〜1 で 90)。照合に落ちた軸の |alpha| は多くが 0.1〜10 の普通の大きさ
  (最初の 10 秒の 227 回のうち 176 回)。|alpha| が 1e-9 前後の小さい軸は 26 回。
- 再分解の直後 (更新 0 回) でも PRICE の値と FTRAN の値が相対 50% 以上ずれる。更新の積み重ねではなく、その基底での解そのものが不正確。
- 試作の診断 `ENOMOTO_DEBUG_VERIFY_RESID=1` (`v_resid.txt`): 照合に落ちた軸で、今の LU (更新込み) と一から分解し直した LU の
  FTRAN・BTRAN の残差を測った。`|B^-1 a_q|` は 2e6〜4e9、`|rho|` は 1〜3e6。残差は FTRAN 1e-8〜6e-5、BTRAN 1e-14〜2e-6 で、解の大きさに比べて
  小さい (後退安定)。一から分解し直しても 2 つの値の食い違いは同じ程度に残る (例: `x_r = 7.3e-12`、`rho.a_q = 5.6e-11`)。
  → **LU の精度の問題ではなく、基底が悪条件** (条件数 1e10 前後では 1e-16 の丸めが 1e-6 の相対誤差になる)。
- 照合の判定 (`UPDATE_VERIFY_TOL` 1e-7、尺度の下限 `FT_MIN_PIVOT` 1e-7) は HiGHS の `updateVerify` (1e-7、更新 1 回以上で再分解) と同じ。
  緩めても悪条件の基底を通ること自体は変わらない (推測。悪条件の基底での照合を緩めると、x_B のずれの検査や特異の検査で同じだけ止まる)。

### 2.2 道筋の基底の条件数

途中の反復で基底を書き出し (`CUTLP_ITERS=k CUTLP_DUMP_BASIS=...`、ENOMOTO は `ENOMOTO_MIP_LP_RESUME=1` で止まった基底を残させる。HiGHS は
`simplex_iteration_limit=k` の後 `getBasis`)、`cond_basis.py` (scipy の `splu` と `onenormest`) で 1 ノルムの条件数を見積もった:

| 反復 | ENOMOTO (既定) | HiGHS |
|---:|---:|---:|
| 0 | 4.5e6 | 4.5e6 |
| 10 | 2.2e6 | - |
| 20 | 1.5e7 | - |
| 50 | 1.2e8 | - |
| 75 | 1.9e10 | - |
| 100 | 3.3e11 | 5.2e6 |
| 200 | 2.1e9 | 2.4e6 |
| 300 | 3.2e9 | 1.0e7 |
| 500 | 2.9e7 | 6.2e6 |
| 700 | 6.6e10 | - |
| 1000 | 4.4e9 | 1.8e7 |
| 2000 | 2.1e10 | 1.0e8 |
| 4000 | 2.0e9 | 4.4e7 |
| 8000 | - | 6.8e7 |
| 12000 | - | 1.4e8 |

- ENOMOTO は最初の 100 反復で条件数が 5 桁悪くなる。その 100 反復に |alpha| < 1e-3 の軸は無い (`pivlog`: 最初の 300 反復の |alpha_r| は
  1e-3〜1e2)。小さすぎる軸 (1e-9) ではなく、普通の大きさの軸の選び方が積み重なって悪くなる (推測: 比の判定で、比が同じくらいの候補の中から
  |alpha| の小さいものを選び続けている)。
- 基底の構造列は ENOMOTO 1276 → 1550 (4000 反復)、HiGHS は 1265〜1360。LU の非零も ENOMOTO の道は 9〜11 万、HiGHS の道の基底を ENOMOTO で
  分解した値は測っていない。

### 2.3 比の判定の違い

- ENOMOTO の既定 (`slope_intercept_dual.rs` の BFRT のパス 2): パス 1 の止まった候補 `k*` から**後ろ向きにだけ**、比が
  `ratio(k*) - HARRIS_RATIO_TOL` (1e-7、比の絶対値) 以上の窓の中で |alpha| 最大を選ぶ。被約費用が 1e4 程度 (費用 50〜65 万) の問題では
  比の 1e-7 の窓は比の丸めの程度でしかない (推測)。
- HiGHS (`HEkkDualRow::chooseFinal`): 緩めた比 `(d_j + Td)/|alpha_j|` の最小までの候補 (前向きも含む) から |alpha| 最大を選ぶ。|alpha| が小さい
  候補は緩めた比が大きくなるので選ばれにくい。
- 既存の試作 `ENOMOTO_SIMPLEX_HARRIS2` (analysis/rootlp_simplex_fail_20261105.md 7.1 節) がこの HiGHS 流の前向きの Harris。

| 設定 (根の最適基底から、40 秒の上限) | 結果 | 反復 | 時間 | 再分解 (照合 / 悪条件) | 1 回の再分解 |
|---|---|---:|---:|---|---:|
| 既定 | 打ち切り | 8498 | 40.1 s | 792 (466 / 217) | 44 ms |
| `ENOMOTO_SIMPLEX_HARRIS2=1` (いつも) | **最適** | 23644 | **15.8 s** | 93 (0 / 0) | 19 ms |
| `HARRIS2=1`、Td=1e-7 | 最適 | 27546 | 18.8 s | 104 (0 / 0) | 20 ms |
| `HARRIS2=r` (解き直しの安全モードだけ) | 最適 | 21410 | 15.7 s | 79 (0 / 0) | 23 ms |
| `HARRIS2=t` (数値の不調 5 回の後) | 最適 | 24360 | 17.4 s | 99 (2 / 0) | 22 ms |
| `HARRIS2=t`、不調 1 回の後 | 最適 | 62360 | 31.2 s | 238 (0 / 0) | 11 ms |
| `ENOMOTO_T_HARRIS_RATIO_TOL=1e-6` (後ろ向きの窓を広げる) | 打ち切り | 13253 | 40.4 s | 980 (530 / 289) | 33 ms |
| `ENOMOTO_T_HARRIS_RATIO_TOL=1e-5` | 打ち切り | 51700 | 40.0 s | 927 (111 / 250) | 13 ms |
| `ENOMOTO_SIMPLEX_HARRIS_WIDE=1` | 打ち切り | 8530 | 41.6 s | 811 (476 / 225) | 45 ms |
| `ENOMOTO_SIMPLEX_GROW_TA=1` (HiGHS の Ta) | 最適 (1536 反復目で x_B の照合に落ち、安全モードの解き直しも特異で落ち、全スラックから) | 40920 | 22.2 s | - | - |
| `ENOMOTO_SIMPLEX_TINY_SKIP=1` | 打ち切り | 6533 | 40.4 s | 654 (390 / 216) | 54 ms |

- 後ろ向きの窓を広げるだけ・小さい軸を外すだけでは効かず、前向きに |alpha| 最大を選ぶことが効く。
- `HARRIS2=1` で再分解は 93 回 (時計 83) になり、残りの 1 反復 0.67 ms のうち FTRAN 36%・BTRAN 16%・x_B の更新 12%・再分解 11%。
  全スラックからの道 (0.41 ms) より重いのは、道の基底が密 (LU の非零 6.7〜7.5 万、全スラックからの道は 3.7 万) なため (事実は非零の数まで)。

### 2.4 LU の側 (閾値・列の最大値・探索の上限)

| 設定 | 結果 | 時間 | 再分解 | 1 回の再分解 | ピボットの探索 | LU の非零 |
|---|---|---:|---:|---:|---:|---:|
| 既定 | 打ち切り | 40.1 s | 792 | 44 ms | 12.5 s | 11.1 万 |
| `ENOMOTO_PIVOT_SEARCH_LIMIT=8` (HiGHS の値) | 打ち切り | 41.0 s | 836 | 44 ms | 5.1 s | 15.2 万 |
| `ENOMOTO_REUSE_PIVOT_ORDER=0` | 打ち切り | 41.2 s | 1033 | 30 ms | - | - |
| `HARRIS2=r` | 最適 | 15.7 s | 79 | 23 ms | 0.6 s | 7.5 万 |
| `HARRIS2=r` + 探索の上限 8 | 最適 | 12.9 s | 67 | 19 ms | 0.2 s | 7.9 万 |
| `HARRIS2=r` + `ENOMOTO_LU_LAZY_COLMAX=0` | 最適 | 15.8 s | 79 | 24 ms | 0.6 s | 7.5 万 |

- ピボットの閾値 0.25 → 0.5 の引き上げは、既定の道で 1 回起きる (分解の失敗からの巻き戻しの段 (2)、`slope_intercept_dual.rs` の
  `escalate_pivot_threshold`)。求解の中では下げない。HiGHS も `reinvertOnNumericalTrouble` で 0.1 から 5 倍ずつ上げ (上限 0.5)、求解の中では
  下げない (docs/lu_comparison_enomoto_vs_highs.md 2.4 節)。`HARRIS2` の道では引き上げが起きない (0.25 のまま)。
- 列の最大値はすでに遅延の数え直し (古い列だけ、候補として要るときだけ)。既定の道で 4.6 億要素を数え直すのは、再分解の回数 (792) と悪条件の
  基底の LU の大きさのため。HiGHS は列の値も列の向きに持つ (`mc_value`) ので数え直しは連続した読み出し、ENOMOTO は列の写しが添字だけで値を
  行から探す (`row_get`)。増分にする余地はあるが、再分解が 1/10 になれば効き目は小さい (`LAZY_COLMAX=0` との差 1%)。
- 探索の上限 (既定 64 列) を HiGHS の 8 列にすると、既定の道では埋まり (fill) が増えて悪く、`HARRIS2` の道では 18% 速い (1 回だけの計測)。
- 1 回の再分解の重さ (既定の道 44 ms) は、悪条件・密な基底の LU (非零 11 万) と、照合に落ちた後の特異の検査の試し分解
  (`pivot_makes_singular`、|alpha_r| < 1e-7 のとき) の分も含む。再分解の直後 (更新 0 回) の大きな不一致でも分解し直す (同じ基底なので同じ LU に
  なり、その軸を禁止して選び直すだけで足りるはず。66 回) のは無駄 (直していない)。

## 3. 試作 `ENOMOTO_MIP_CUT_HARRIS2`

- `src/mip/separation.rs`: 根のカットのループ (サブ MIP でないもの、裏のカットの写しも) のラウンドの LP を解くあいだ、スレッドの
  `HARRIS2_SCOPE` (`slope_intercept_dual.rs`) に値を置く。双対単体法は `ENOMOTO_SIMPLEX_HARRIS2` が無ければその値を使う。値は
  `ENOMOTO_SIMPLEX_HARRIS2` と同じ (`1` いつも、`t` 数値の不調の後、`r` 安全モードだけ)。ラウンドの終わりに元に戻す。
- 主実行不能が大きければ全スラックへ切り替える判定は作らなかった: 出発の基底の主実行不能はカットの 50 行 (和 1.25) だけで小さく、
  実行不能の行は解いているあいだに 3000 行に増える。出発の時点では見分けられない。

(結果は 4 節)

2 回とも同じ向きに大きく動いた問題 (秒、2 回の平均):

  (カットの LP の比の判定) から来る。
- 事実 (nw04 を取り直したログ `logs/nw04_{def,h1mv}_60.log`): カットの LP の反復は同じくらい (round 0 で 41 対 71) だが、別の最適の頂点に着き、

  「カットの LP が上限で止まる問題」にだけ効かせる (例: 1 回目が進みの判定で止まった後の解き直しの時だけ前向きの Harris にする) のが
  害を減らす筋と思われる (試していない)。
- 気になる点 (確かめていない): nw04 の h1mv の 1 回目は `root_bound` が 16866.37 で最適値 16862 を超えている。再スタートが 1 回あり、
  再スタートの後の根の値を記録している可能性がある。正しさの問題かは調べていない。
