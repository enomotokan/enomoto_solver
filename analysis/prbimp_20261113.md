# PRBIMP: プロービングの含意を、害を避けて使う (2026-11-13)

課題: 含意を集めるプロービング ([`probe`]、src/mip/mod.rs) は既定では含意の本数を非零数の 10 倍までに制限し、見つけた含意を後の列の伝播に使わない。
使う形 `ENOMOTO_MIP_CLQPRB` (analysis/clqprb_20261112.md) は mzzv11・mzzv42z・neos8 で効くが、roll3000・cbs-cta・neos-3216931-puriri で悪化して
束 cand1114 から外した (analysis/cand1114_20261113/README.md)。(1) 悪化の原因を調べ、(2) 害を避けて含意を使う形を試作し、(3) cand1114 と比べる。

- ビルド: ブランチ ccr-1beed81b-ex0uhq (このファイルを足したコミット)。同じ機械 (4 CPU) で 1 度に 1 つ (前処理の見比べの一部を除く)。
- 台本・生データ: `analysis/prbimp_20261113/`
  - `cfg.py`: 設定。`c14` = cand1114 (cand1114_20261113/cfg.py の `CAND1114`)、`c14clq` = c14 + `CLQPRB=1d` (cand1113 と同じ形)、
    `c14clqn` = c14 + `CLQPRB=1dn`、`c14clqg` = c14 + `CLQPRB=1dg`。
  - `one.py`: 1 回解いてログ (`logs/`、`ENOMOTO_MIP_LOG=1`) を残す → `res_one.jsonl`。`batch1.sh` (roll3000・cbs-cta、種 1・2、150 秒)。
  - `pscreen.py`: 根の LP の大きさの行が出るまで回し、プロービングの行・根の LP の前の大きさ・時間を取る → `pscreen.jsonl`。
  - `run.py` (cand1114_20261113/run.py の写し)・`shards_*.json`・`res_*_s*.jsonl`: 対の計測。`summ.py`: 対の集計。

## 結論 (先に)

1. **悪化 3 問の原因** (§1): roll3000・cbs-cta はプロービングの時間ではなく、含意を使っても何も固定・締め付けできない問題で、増えた含意・implied bound・
   同値な組 (cbs-cta の 3 組) が後の流れだけを変える型。neos-3216931-puriri は、c14 の唯一の解の出どころ (根のヒューリスティクスの後の locks の sub-MIP、
   350〜400 秒) が、含意で増えた固定・締め付けで外れる型 (4 種とも同じ。同値な組を止めても同じ)。
2. **試作 `CLQPRB` の `g`** (§2): 既定の形で何か得られたときだけ含意を使う形でやり直す。roll3000・cbs-cta の害は消える (判定が入らず c14 と同じ前処理)。
   判定が入るのは P の 58 問のうち 14 問、M の 48 問のうち 17 問。誤答 0 (fuzz 4 種・cargo test 415 通過)。
3. **計測** (§3): mzzv11 は 4 種とも時間切れ → 307〜340 秒で解け、istanbul-no-cutoff も 2 種とも解ける。mzzv42z・neos-4738912-atrato も速い。
   一方、timtab1 (1.58・2.20 倍)・neos-4722843-widden (1.30・1.25 倍)・neos-860300 (P、4 種で 1.03〜1.20 倍) が種をまたいで遅く、puriri は 4 種とも解を失う。
   M で判定が入る問題の SGM は +13.3% [−11.8%, +53.0%] (T を足して +0.4% [−20.5%, +32.8%])。
4. **判断: `g` は採用基準 (種をまたいで一貫して遅い問題なし、区間上限 ≲ +5%) を満たさないので、既定にも束にも入れない**。コードは環境変数の形で残す (既定は変えない)。
   効きも害も「含意で固定・締め付けが増えること」そのものから来ていて (puriri と mzzv11 は既定の形の得た量で分けられない)、
   プロービングの段で判定を工夫しても分けられない見込み。次に試すなら、含意で増えた固定を root のヒューリスティクス (locks など) の固定率の計算から外す、
   のような後段の側の手当て (推測。まだ試していない) で、puriri・timtab1・widden を個別に調べてから。

## 1. 悪化 3 問の原因

### roll3000・cbs-cta: プロービングの時間ではなく、何も得られない含意の差で後の流れが変わる型 (事実)

`res_one.jsonl`・`logs/` (c14 と c14clq、種 1・2、150 秒) と `pscreen.jsonl` (58 問の前処理):

| 問題 | 設定 | プロービング | 含意 | 同値な組 | 根の LP の前 | 時間 (種 1・2) |
|---|---|---|---|---|---|---|
| roll3000 | c14 | 624 列、固定 0・締め付け 0、0.03 秒 | 8840 | 0 | 1588×878 | 40.9・76.6 |
| roll3000 | c14clq | 同じ、0.03 秒 | 9902 | 0 | 1588×878 | 54.8・108.4 |
| cbs-cta | c14 | 2467 列、固定 0・締め付け 0、0.03 秒 | 6 | 0 | 9964×8214 | 77.7・12.1 |
| cbs-cta | c14clq | 同じ、0.02 秒 | 9 | **3** | 9964×8211 | 14.4・7.7 |

- どちらもプロービング自体は 0.03 秒で、含意を伝播に使っても 1 本も固定・締め付けできない。変わるのは、含意を伝播に使って見える変化が増えた分の
  (a) 含意 (= クリークのグラフの辺。roll3000 は 4775 → 4951 辺)、(b) implied bound、(c) 同値な組 (cbs-cta の 3 組。代入されて列が 3 本減り、
  根の LP の基底が使えず 200 → 5106 反復) だけ。根の LP の値は同じで、その後の分離・ヒューリスティクスの流れが変わる。
- roll3000 は cand1113 の P で 4 種そろって 1.32〜1.55 倍 (cand1114/summP.txt)、ここでも 2 種とも 1.34・1.42 倍 (根の下界は c14clq の方が 12498 → 12652 と良いが、
  木で 30 秒に再スタートが入る)。cbs-cta はこの機械では逆に 2 種とも c14clq が速い (cand1113 の loo2 では 4 種とも遅い)。cbs-cta は目的 0 の解を
  見つけるだけの問題で、ゆらぎが大きい。
- **判断**: 害は「含意で何も得られない問題で、得られない含意の差が流れだけを変える」型。プロービングの時間の問題ではない。
  58 問のうち、含意を使って前処理の結果 (根の LP の前の大きさ) が変わるのは mzzv42z・neos8・30n20b8 の 3 問だけ (下の表)。

含意を使う形 (c14clq) で根の LP の前の大きさが変わる問題 (残りの 55 問は大きさ・根の LP が同じ):

|---|---|---|---|

| neos8 | 5591×1128、固定 0、同値な組 602・740・459 | 4457×560、固定 0、同値な組 **2431**・1152 | **同値な組** (固定ではない) |

  (clqprb §結論 6) はこれと含意の増え (`d` で対処) による。

### neos-3216931-puriri: 根の 350 秒の後の 1 回の locks の sub-MIP に頼る問題で、その 1 回が外れる型 (事実 + 解釈)

`logs/neos-3216931-puriri.{c14,c14clqg}.s1.log.gz` (600 秒、種 1):

| | c14 | c14clqg |
|---|---|---|
| プロービング | 固定 304・締め付け 40・同値な組 16 (0.44 秒) | 既定の形の後に含意を使う形でやり直し: 固定 354・締め付け 171・同値な組 113 (1.02 秒) |
| 根の LP の大きさ | 5927×3078、非零 97340 | 5051×2768、非零 **103739** (同値な組の代入で増える) |
| 根の LP | 58939.7、26518 反復、11.9 秒 | **60402.8**、48642 反復、**22.7 秒** |
| feasibility pump・3 つの diving | 79・55・35・28 秒、どれも解なし | 133・59・52・56 秒、どれも解なし |
| locks の sub-MIP (根のヒューリスティクスの後、350・422 秒) | 固定率 0.68 (1087 列が自由)、5.2 秒・49 節点で **81380 を見つける** | 固定率 0.75 (805 列が自由)、すぐ実行不能 |
| 600 秒の時点 | 解 81380、下界 59440 | 解なし、下界 60470 |

- どちらも根のヒューリスティクスに 350〜420 秒かけて何も見つからず、c14 の解は locks の sub-MIP の 1 回だけ (種 2 も 370 秒)。
  含意を使う形では固定・締め付けが増えて locks の固定率が上がり、その 1 回が実行不能になる。根の LP も重く (非零が増える)、ヒューリスティクスが全体に遅い。
- 下界は含意を使う形が良い (59440 → 60470)。この問題は 600 秒では両方とも解けない。
- **判断**: プロービングの時間の害ではなく、ほぼ唯一の解の出どころが外れる型。「解けた数」は変わらない (どちらも時間切れ) が、解なしは利用者には悪化。
  種 3・4 でも同じ (計測 T2: c14 は 4 種とも 352〜396 秒で解、c14clqg は 4 種とも解なし)。
- 同値な組の代入が原因かの切り分け (`ENOMOTO_MIP_NO_PROBE_EQUIV=1`、種 1、600 秒、`res_one.jsonl`): c14clqg でも同値な組なしで **解なし** のまま
  (根の LP 60272.3、19.9 秒、非零 106223。locks の固定率 0.73 ですぐ実行不能)。c14 は同値な組なしでも 377 秒に locks で 81490。
  mzzv11 は c14clqg + 同値な組なしで 321.6 秒で最適 (効きは固定による)。→ 害の元は同値な組ではなく、含意で増える固定・締め付けそのもの。
  puriri (既定の形で固定 304・締め付け 40) と mzzv11 (固定 336・締め付け 113) は、既定の形の得られた量では分けられない。

## 2. 試作

### `ENOMOTO_MIP_CLQPRB` の `n` (捨てた)

含意を使う形で回して何も固定・締め付けられなければ、既定の形でやり直す。neos8 は固定 0 (効きの元は同値な組) なので効きが消え、
何も得られない問題では両方の時間がかかる。捨てた (コードには残す)。

### `ENOMOTO_MIP_CLQPRB` の `g` (本命)

- まず既定の形でプロービングを回す。固定・締め付け・同値な組が `ENOMOTO_T_MIP_CLQPRB_G_MIN` (既定 1) 個以上出たときだけ、問題を元に戻して
  含意を使う形 (CLQPRB) でやり直す。一度切り替えたら、その求解の後のプロービング (前処理のかけ直し・再スタート) でも判定せずに使う
  (neos8 は 2 回目のプロビングで既定の形では同値な組 0、含意を使うと 1152 組)。
- 何も得られない問題 (58 問のうち 44 問) では既定とまったく同じ前処理になり、余分な時間もかからない。roll3000・cbs-cta・air03・nw04 はここに入る。
- 得られた問題 (58 問のうち 14 問) では c14clq と同じ前処理 (neos8 4457×560、mzzv42z 6475×7808、mzzv11 5496×6741、puriri 5051×2768、30n20b8 491×4455) で、
  既定の形の分の時間 (並列なので 0.03〜1.4 秒) が余分にかかる。
- 判定が入る 14 問: drayage-100-23・drayage-25-23・mzzv42z・neos-860300・neos-960392・neos8・physiciansched6-2・misc07・blend2・30n20b8・beavma・blp-ar98・
  timtab1・graph20-20-1rand。
