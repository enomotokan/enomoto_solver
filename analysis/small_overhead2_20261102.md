# 小さい問題の手間 2: drayage-100-23・drayage-25-23・neos8・air03 (2026-11-02)

HiGHS が 1〜6 秒で解く小さい問題で ENOMOTO が負けている件の調査 (並列 3 セッションのうちの 2)。担当の 4 問で、ENOMOTO の時間の内訳を
ログの時刻から拾って HiGHS と並べ、問題の小ささに見合わない手間を特定し、環境変数で入る試作 2 つ (既定では使わない) を入れて測った。

## 要点

- **「証明済みなのに止まらない」形はない**が、近い形がある: air03・neos8 は**根のカットのループが終わった時点で LP の解が最適解
  (下界 = 最適値)** なのに、主が FJ のスレッドの終わりを 0.7〜1.4 秒待っていた。FJ のスレッドは、FJ に渡す問題を作る前処理 (FJ_P3、
  プロービングを含む) の最中で、その前処理は止める合図を見ない (見るのは求解の時間の上限だけ)。
  → 試作 **`ENOMOTO_MIP_SMALL2_FJSTOP=1`**: FJ_P3 の前処理に FJ のスレッドの止める合図を渡す。air03 4.26 → 3.50 秒、neos8 7.61 → 5.85 秒
  (各 3 回の中央値)。58 問では働くのは 6 問だけで、ほかの問題の経路は変わらない。**既定にしてよいと考える** (5 節)。
- drayage-25-23 は、根の被約費用 (root reduced cost) と LP face の 2 本の並列サブ MIP (自由な列 5272、前処理後は同じ問題) が、サブ MIP の
  根の分数ダイビング (深さ 595)・係数ダイビングなどで 1.2 秒使って何も見つけず、主は 2 本の終わりを 2.2 秒待っていた (2 本とも結果は
  実行不能)。→ 試作 **`ENOMOTO_MIP_SMALL2_SUBLIGHT=1`**: どのサブ MIP でも根の Feasibility Pump とダイビングを使わない。drayage-25-23
  7.20 → 5.47 秒、drayage-100-23 4.71 → 1.65 秒 (FJSTOP と合わせて)。ただし **binkar10_1 6.0 → 9.9 秒・qnet1 3.0 → 4.9 秒と遅くなり、
  58 問の SGM は変わらない**。並列のセッション 3 の `ENOMOTO_MIP_SMALL3_SUBMIP_LIGHT` (同じ手順、深さ 1 だけ) も 58 問で悪かった
  (analysis/small_overhead3_20261102.md)。**既定にはしない**。
- 残る差の多くは前処理 (neos8 のプロービング 3 周で 4.5 秒・air03 のプロービング 1.6 秒) と再スタートの繰り返し (drayage-25-23 は 3 回、
  HiGHS は 1 回)。neos8・air03 は HiGHS も前処理に 4.35 秒・2.01 秒かけている。drayage-100-23 は根の LP がもう最適値で、解を見つけるのが
  運 (根の RENS が当たれば 1.6 秒、外れると木で 3〜4 秒)。

## 1. 計測の条件

- ビルド: ブランチ ccr-1beed81b-ex0uhq (a7531eb7 の上) + 試作。環境変数なしなら既定と同じ経路。
- ENOMOTO: 4 スレッド・60 秒 (`ENOMOTO_MIP_THREADS=4`・`--threads 4`)、`ENOMOTO_MIP_LOG=1`、各 3 回。ソルバーは同時に 1 つ (CPU 4 のコンテナ)。

## 4. 特定した手間と直し方の見当

1. **FJ のスレッドの FJ_P3 の前処理が止める合図を見ない** (air03 0.7〜1.0 秒、neos8 1.4〜1.5 秒、drayage-25-23・swath1 0.1〜0.3 秒)。
   主はカットのループの終わりに `join_fj_thread` で FJ のスレッドに止める合図を出して待つが、FJ のスレッドが FJ_P3 の前処理 (本体の前処理を
   もう一度かけ、プロービングも回す) の中にいると、その前処理は求解の時間の上限 (`with_presolve_deadline`) しか見ない。
   → 試作 `ENOMOTO_MIP_SMALL2_FJSTOP` (5.1 節)。
2. **根の並列サブ MIP の根のダイビング** (drayage-25-23 で 2.2 秒の待ち)。→ 試作 `ENOMOTO_MIP_SMALL2_SUBLIGHT` (5.2 節)。悪くなる問題がある。
   ほかの見当: 前処理後に同じ問題になるサブ MIP (root reduced cost と LP face) を 1 本にまとめる (未試作)。
3. **前処理のプロービングの繰り返し** (neos8: 同値の対が出るたびに前処理をかけ直してプロービングを最初からやり直す、3 周 4.5 秒、
   固定 0)。2 周目以降は変わった列の近くだけ調べる、または前処理全体のプロービングの時間を根の LP の時間などで頭打ちにする。HiGHS も
   この問題の前処理に 4.35 秒かけているので、取れても 1〜2 秒。未試作。
4. **対称性** (neos8 0.62 秒・drayage 0.3 秒)、**クリークのグラフ作り・クリーク行の拡張** (air03 計 0.9 秒)。どれも 1 回 1 秒未満で、
   単独では小さい。
5. **再スタートの繰り返し** (drayage-25-23 3 回、HiGHS 1 回)。セッション 1 (analysis/small_overhead1_20261102.md) も同じ形を挙げている。

## 5. 試作と結果

### 5.1 `ENOMOTO_MIP_SMALL2_FJSTOP=1` (src/mip/solver.rs、FJ のスレッドの中)

FJ_P3 の前処理 (`fj_p3_problem`) を `crate::cancel::with_halt(Some(stop2))` で包み、前処理の重い手順 (プロービング・同値の検出・クリーク行の
拡張・再帰) が見る `presolve_stop()` が FJ のスレッドの止める合図でも真になるようにする。前処理の後に合図が立っていたら FJ を始めずに抜ける
(途中で打ち切った前処理の結果は使わない)。合図は主の `join_fj_thread` でしか立たないので、合図の前の動きは変わらない。

- 担当 4 問: air03 4.26 → 3.50 秒、neos8 7.61 → 5.85 秒 (FJ の待ち 0.91・1.38 秒 → 0.05〜0.12 秒・0.05 秒未満)。drayage 2 問は待ちが
  0.1 秒ほどで差は揺れの中。
- 58 問 1 回 (`bench58.py`、問題ごとに 3 設定を続けて): 合図で FJ_P3 の前処理を打ち切ったのは air03・drayage-100-23・drayage-25-23・
  mzzv42z・neos8・swath1 の 6 問だけ。ほかの 52 問は経路が同じ。

| 設定 | 解けた | SGM (シフト 10 秒、解けない回は 60 秒) |
|---|---:|---:|
| 既定 | 44 | 16.58 |
| FJSTOP | 43 | 16.12 |
| FJSTOP + SUBLIGHT | 43 | 16.55 |

- FJSTOP の解けた数の 1 減は noswot (既定 33.6 秒 → 60 秒で下界 -43)。noswot では FJSTOP は働いておらず (FJ_P3 は合図の前に終わる)、
  揺れ (noswot は HiGHS も解けない、時間の揺れが大きい問題)。
- 1 回の計測で FJSTOP が遅く見えた問題 (exp-1-500-5-5 3.8 → 5.7、fiber 0.7 → 1.5、qnet1 3.0 → 5.0 (2 回目)) はどれも FJSTOP が働いていない。
  exp-1-500-5-5・fiber を既定・ダミーの環境変数 (`ENOMOTO_MIP_SMALL2_DUMMY=1`)・FJSTOP で交互に 4 回ずつ解き直すと、平均 4.35・4.45・4.39 秒、
  1.12・1.21・1.23 秒で差はない (その前の交互 4 回では 3.93 対 4.63 と開いたが、根のカットのループの randomized rounding の当たり外れで、
  LP による固定の反復数の時点からもう回ごとに違う)。
- 注: 58 問の計測の途中 (neos-960392 のあたり、bench58.out の 34〜36 行目) で cargo check が 1 分ほど重なった。

### 5.2 `ENOMOTO_MIP_SMALL2_SUBLIGHT=1` (src/mip/solver.rs、根のヒューリスティクス)

サブ MIP (深さ 1 以上、打ち切り値によらず) の根で Feasibility Pump とダイビング 3 つを使わない (`ENOMOTO_MIP_SUBMIP_LIGHT_HEUR` の形を
打ち切り値が有限のサブ MIP にも広げる)。rebase のときにセッション 3 の `ENOMOTO_MIP_SMALL3_SUBMIP_LIGHT` (打ち切り値が有限のサブ MIP、
値 `1` は深さ 1 だけ、`all` は入れ子も) と同じ場所でぶつかったので、両方を残して論理和にした。

- 担当 4 問 (FJSTOP と合わせて): drayage-25-23 7.20 → 5.47 秒 (並列サブ MIP 2 本 2.2 秒 → 0.8 秒)、drayage-100-23 4.71 → 1.65 秒
  (3 回とも根で最適解。ただしこの問題はもともと運の揺れが大きい)、neos8・air03 は FJSTOP だけと同じ。
- 悪くなる問題 (各 2 回、FJSTOP だけ → FJSTOP + SUBLIGHT): binkar10_1 6.13 → 9.93 秒、qnet1 4.00 → 4.90 秒 (既定 3.03)、
  physiciansched6-2 は 58 問の 1 回で 60 秒の時間切れ (49724 で止まる)、測り直しの 2 回は 30.4・29.8 秒 (既定 40.6・28.4)。
  サブ MIP の根のダイビングが外側に良い解を早く返している問題がある。58 問の SGM は 16.12 → 16.55 秒 (FJSTOP だけと比べて)。

## 6. 判断

- **`ENOMOTO_MIP_SMALL2_FJSTOP` は既定にしてよい**と考える。働くのは主が FJ のスレッドに止める合図を出した後だけで、その後の FJ の結果は
  もともと受け取れない (主は合図の後の FJ の解を待っているだけ) ので、失うものがない。58 問で働いた 6 問のうち 2 問で 0.8〜1.8 秒速く、
  ほかの問題の経路は同じ。既定にするなら、念のため Mittelmann の問題で時間の上限の超過が減る向きにしか効かないことを確かめる
  (analysis/overrun_crypt_20261101.md の cryptanalysiskb128n5obj14・16 は期限で打ち切る形で直っているが、合図でも打ち切れる)。
- **`ENOMOTO_MIP_SMALL2_SUBLIGHT` は既定にしない**。drayage には効くが、binkar10_1・qnet1・physiciansched6-2 を悪くし、58 問では差なし。
  セッション 3 の SMALL3_SUBMIP_LIGHT も 58 問で +5.7% だった。小さいサブ MIP の根のダイビングが効く問題と、大きい (自由な列が多い) サブ MIP
  のダイビングが空回りする問題を分ける条件 (例: ダイビングの予算を自由な列の数で決める、2 本のサブ MIP が前処理後に同じ問題ならまとめる) は未検討。
- 前処理のプロービングの繰り返し (neos8) と再スタートの繰り返し (drayage-25-23) は、この調査では試作していない。
