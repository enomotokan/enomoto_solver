## 3. 計測で見えた主要な非効率 (file:line は HEAD 8cc4303)

### 3.1 5 反復ごとのドリフト検査 `‖A_B x_B − rhs‖` が総時間の 4.3% (今までタイマ外)
- 場所: `src/simplex/extended_dual.rs:4900-5016` (`since_check >= XB_CHECK_INTERVAL` → `residual_norm_affine`
  :1405-1466 = 2 本の `O(m)` fill + `O(nnz(A_B))` 蓄積 + `O(m)` 差、100 反復ごとに `fresh_d_into` :2011 = BTRAN + `O(nnz(A))`)。
  `XB_CHECK_INTERVAL = super::FT_CHECK_INTERVAL = 5` (:601)、古典ループは `5 × RESIDUAL_CHECK_MULTIPLIER(20) = 100` 反復ごと。
- 計測 (計測ビルド `drift_check` タイマ): 93 問合計 843 ms = 主ループ wall の 4.3%。dfl001 368 ms (4.5%)、pilot87 136 (3.1%)、
  fit2p 96 (6.2%)、d2q06c 67 (5.1%)、maros-r7 38 (5.1%)、pilot 29 (3.5%)、greenbeb 21 (5.3%)、80bau3b 18 (6.8%)、degen3 12 (6.1%)、
  greenbea 7 (5.3%)、ship12l (5.5%)、scfxm3 (5.1%)。callgrind fit1p: `residual_norm_affine` 2.2% + `residual_norm_slope` 0.7%。
- `XB_CHECK_INTERVAL` のドキュメント (:590-601) は「間隔を緩めると cycle/degen3 が偽 Infeasible」と記すが、その後
  「更新済み因子分解から Infeasible を結論しない (先に再分解)」ガード (:3704-3723, :3873-3892) が入っており、失敗様式は
  別経路で塞がれている。実測 (`ENOMOTO_XB_CHECK_INTERVAL=20`、全 93 問): 誤答 0、bailout 0、反復 −0.6% (経路変化 10 問:
  dfl001 −2.6%、fit2p −2.7%、d2q06c −1.9%、pilot +6.1%、pilot87 +1.2%、greenbea の primal 反復 18→62)、drift 起因の再分解は
  減る (pilot87 61→50、greenbea 17→11、perold 17→12)。時間 −3.3% (ノイズ込み)。

### 3.2 polish → primal `run_phase` handoff: pilot87 8.4%、48 問で発火し 36 問は固定列由来の空振り
- 場所: `extended_dual.rs:5557-5631` (polish 終了時に真のコストで `true_d` を BTRAN+`O(nnz(A))` で計算し、
  `true_dual_feasible` を **絶対 `TOL = 1e-9`** で判定 :5570-5575、失敗なら `super::run_phase` :5611 へ)。
  `run_phase` (`src/simplex.rs:1772-2213`) は毎反復 `recompute_basics` (:1821 = `compute_rhs` `O(nnz(A))` + 密 FTRAN)、
  `solve_transpose_into` で y (:1893)、全列 pricing、入列 FTRAN (:1976)、SE 重みの BTRAN ×2 (:2138-2139) を行う。
- 計測: handoff 48 問、合計 428 ms。pilot87 405〜487 ms = **総時間の 8.4〜10%** (277 primal 反復、1.46 ms/反復 = 双対反復
  0.65 ms の 2.3 倍; 真の双対非実行可能列 107 本 (固定列除く)、最大 1.9e-2 = コスト摂動 (`perturb_costs` :1646、
  `5e-7 × max|c|^(1/4) × (|c_j|+1)` ≈ pilot87 で 1e-2) を外した分)。nesm 4.4 ms (5.4%、25 反復)、cycle 2.4 ms (7.1%、19 反復)、
  greenbea 5.2 ms (3.1%、18 反復)、d2q06c 5.2 ms (0.4%、12 反復)、etamacro 0.6 ms (5.6%)、scsd1 0.2 ms (5%)、scsd6 0.3 ms (3%)。
- **固定列の混入**: `d[j]` は PRICE が固定列 (`lb == ub`) を飛ばすため更新されず (:2617、d ドリフト検査も :4995 で除外)、
  polish の判定だけが固定列を含む。結果、dfl001 (772 本、最大 4.1e4)、greenbea (127 本のうち 125 本)、degen3/d6cube/greenbeb/
  woodw/pilot.we/wood1p/scsd8/… で**固定列だけが「双対非実行可能」となり handoff**。48 問中 36 問は固定列を除くと 0 本で、
  primal 1 反復 (= FTRAN+BTRAN+全列 pricing + `Tableau`/`SteepestEdgeState::new` 生成 :5595-5597) を空振りしている
  (合計 3.2 ms、dfl001 0.76、degen3 0.25、d6cube 0.23、greenbeb 0.22、woodw 0.13、wood1p 0.10、scsd8 0.09 ms)。
  `ENOMOTO_POLISH_DUAL_TOL=1e-7` の実験で handoff が 1 問も減らないのはこのため。固定列を除き 1e-7 (HiGHS の
  `dual_feasibility_tolerance`) で判定すると 48 → 10 問 (pilot87, greenbea, d2q06c, nesm, cycle, bnl2, etamacro, 25fv47,
  pilot.ja, fffff800) に減る (`nonfixed_bad_1e7` の集計)。

### 3.3 α・ρ・τ が疎でも `0..m` を走査する密ループ (xb_update / DSE 更新 / PRICE の ρ 走査)
- 場所: xb_update `extended_dual.rs:4536-4604` (`for i in 0..m` で `alpha_full[i]`、`combined_alpha_base[i]` を読む)、
  DSE `src/simplex.rs:2680-2703` (`w.iter_mut().zip(alpha).zip(tau)` 全 m 行 + `wp_old = Σ ρ²` の `O(m)`)、
  PRICE `extended_dual.rs:3536-3552` (`for i in 0..m { if rho[i].abs() <= TOL {continue} ...}`)。FTRAN/BTRAN は nnz を
  数えて返す (`permute_out` `lu.rs:4332`) が添字リストは出さない。
- 計測 (`WORK` スイープ、1 反復平均): alpha/m ≤ 0.12 かつ xb_update の比率: stocfor2 0.12 / **27.6%** (m=1072、16 µs/反復)、
  sctap3 0.08 / 10.2%、sctap2 0.08 / 6.6%、80bau3b 0.03 / 6.4% (m=1977)、ship12l 0.03 / 5.1%、ship08l 0.04 / 5.9%、
  ship12s 0.06 / 6.7%、sierra 0.02 / 6.2%、czprob 0.03 / 5.7%、nesm 0.18 / 10.3%、bnl2 0.18 / 11.2%、cycle 0.18 / 11.1%。
  同じ問題群で dse_update 2.5〜5.2% (80bau3b 4.6%、ship12l 4.0%、scfxm3 3.7%、cycle 5.2%)、ρ/m ≤ 0.05 で PRICE の
  `0..m` 走査が PRICE 時間の主成分 (ship12l ρ=10.5/686、80bau3b 44/1977、fit2p 18/3000、stocfor2 11/1072)。
  これらの問題で 1 反復あたり HiGHS の 1.3〜2.6 倍 (§2.2) — HiGHS は α/ρ/τ を index list 付き `HVector` で持ち、
