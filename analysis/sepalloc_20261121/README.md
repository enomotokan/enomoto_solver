# 伸びの取り分で手間を配る・同じ物差しで止める (P2-INF、2026-11-21)

analysis/sepeff_20261120/ の続き。根のカットのループで、分離器の種類ごとの伸び (|双対値| × 違反での按分) と手間をその求解の中で測る。
1 ラウンドの手間の枠は今のまま、伸びの取り分に比例して配る (`a`)。ループを止める判断も、手間あたりの伸びで行う (`s`)。
試作は `ENOMOTO_MIP_SEPALLOC` (src/mip/sepalloc.rs) で、既定では使わない。

## 0. 結論

**判断 (2026-11-21、利用者): `a` (配る)・`s` (止める) とも既定にせず閉じる。** 通しの計測 (§5) は回さない。
スイッチ `ENOMOTO_MIP_SEPALLOC` は既定オフのまま残す (LPFACE・FACECUT と同じ閉じ方)。理由は次の 2 つ。

- `s`: 伸びが次第に鈍る道のりでは、最初の窓で必ず止まる。
- `a2`: 同じ手間では伸びるが、最後の下界が既定を下回る。

以下は判断の材料。

- **止める `s` は閉じる。**
  - 狙いの 4 問のうち、伸びたのは binkar10_1 (49.3% → 63.4%) だけだった。
  - nu25-pr12 (99.7% → 85.1%)・neos-1456979 (36.9% → 15.5%)・neos-3083819-nubu (88.6% → 80.8%) は早く止まりすぎた。
  - 203 問では、閉じた割合が 0.1% 超で良い 7 問・悪い 98 問。
  - 「直近の窓の速さ < 根の LP からの全体の速さ」で止める判定は、伸びが次第に鈍る (凹な) 道のりではほぼ必ず早く止まる (§3)。
- **配る `a` (候補なしのやり直しを入れた a2) は、同じ手間では伸びるが、最後の下界は既定より少し低い。**
  - 同じ手間での比べは良い 64 問・悪い 18 問、手間は幾何平均で 0.85 倍。
  - 最後の閉じた割合は良い 30 問・悪い 64 問 (中央値 0、平均 −1.3 ポイント)。
  - 手間を減らした分だけループが早く (停滞の判定で) 終わり、下界の高さに変わらない。
  - 解く時間への効き目は根だけでは分からない。通しの計測の台本と分担表は用意した (§5)。回すかどうかは親が決める。
- 誤答の fuzz (`as`) は 0 件。cargo test は 419 件通過 (§4)。

## 1. 作り (src/mip/sepalloc.rs)

### `a` (配る)

- **対象**: zero-half・path_highs・path・tableau。
- **伸び G_k と手間**: `ENOMOTO_MIP_SEPSTAT` と同じ計測 (根の累積) から取る。手間は診断の手間を含む決定的な手間。
- **枠 B**: Σ u_k。u_k は、倍率 1 で直近に動いたときの 1 回の手間。
- **取り分 s_k = G_k / ΣG**:
  - 伸びが 0 の種類にも、伸びのある種類の中で一番小さい取り分を残し、割り直す。
  - 手間が付いていない種類 (既定で切ってある zero-half) は取り分を持たない。
- **倍率 f_k = s_k B / u_k**:
  - f_k ≥ 1 なら、上限 (tableau の行の数・path の始点の数・zero-half の本数) に倍率を掛ける。
  - 2 回目からは、前の手間が枠に合うように倍率を掛け直す。
  - f_k < 1 なら f_k を貯め、1 以上になったラウンドだけ動かす。
- **今の配り方のまま (全部 1 倍) のとき**: 1 ラウンド目と ΣG = 0 の間。伸びは目的値の 1e-9 倍 (数値の誤差) 以下を 0 と見る。
- **候補なしのやり直し**: 飛ばした分離器があって候補が 1 本もないラウンドは、全部を 1 倍で分離し直す (a2 で追加)。
  - a では、候補なしで止まる問題が 9 → 35 問に増えた。a2 では 10 問に戻った。
- 新しい閾値は置いていない。

### `s` (止める)

- 根の LP 1 回分の手間を窓にする。
- 窓の伸びの速さ M と、全体の速さ A = (今の下界 − ループの始めの下界) / (根の LP の手間 + ループの手間) を比べ、M < A で止める。
- 窓に満たない間と、下界が一度も動いていない間は、今の判定のまま。

## 3. 止める判定が早すぎる理由

- 道のりが凹 (伸びが次第に鈍る) なら、直近の窓の速さは、始めからの平均の速さより必ず小さい。
- そのため M < A は、窓が満ちた最初の判定でほぼ成り立つ。ループの長さが根の LP の手間 1〜2 回分で切れる。
  - misc07 は 2 ラウンド目で止まった (7.8% → 0.7%)。
- binkar10_1 が伸びたのは、既定の停滞の判定 (10 回) が「下界が動かない」ことで止まるのに対し、こちらは下界が動いている限り続けたため。
  - 判定の物差しの良さではない。
- 同じ物差しで「止める」なら、比べる相手は平均の速さではなく、「その手間を木に回したときの伸び」になる。これは根の中だけでは測れない。

## 6. 注意

- **手間の付け方**:
  - 診断の手間 (zero-half・clique・implbd) の重み (`ENOMOTO_T_TICKS_W_DIAG`=2) は、時間に合わせた較正ではない。
  - 並列の分離の手間は数えていない。
- **伸びの按分は雑音が多い**: |双対値| × 違反で按分している。
- **取り分の下限**: 伸びが 1 種類だけのときは、下限 (一番小さい取り分 = 1) のせいで伸びのない種類も同じ取り分になる。
  - p0201 の 4 スレッドの試しで、path_highs が tableau と同じ枠を持った。
  - 下限の決め方は親の指示 (伸びが 0 の種類にも最小の取り分) のままにした。
- **倍率を上げても手間は増えない場合がある**: tableau の倍率を上げても、分数の行が足りなければ手間は増えない。
  - 倍率の掛け直しで倍率だけが上がる (p0201 で 1.91 → 7.73)。上限が効かないだけで害はない。
