## 1. 入れたもの (`ENOMOTO_MIP_LMIP3=文字`、`src/mip/localmip.rs`)

| 文字 | 中身 | 場所 |
|---|---|---|
| `s` | 2 段のスコア (本家 v2 `progress`): 行が 違反 → 満たす = +2w、満たす → 違反 = −2w、違反のまま減る = +w・増える = −w、違反のまま反対の側へ越える = 0 (本家は両側の行・等式を 2 本の不等式に分けるので +2w −2w で 0)。暫定解の後は目的を、目的の行が違反しているかに関わらず、下がれば +2w0・上がれば −2w0 で数える。連鎖の手 (`chain_move` の `contrib`) も同じ数え方 (`ChainView::contrib` を足した。FJ 側は今までどおり) | `St::contrib_t2`、`St::score`・`score2` |
| `a` | スコアと breakthrough bonus が同点なら、最後に動かした手数 (age) の古い列を選ぶ (本家 v2 は `max(最後に増やした手数, 最後に減らした手数)` の小さい方)。random walk の同点も | `St::last` (`St::apply` で記録)、`run` の `better` |
| `t` | 満たされた行からの tight move (本家 `explore_sat_mtm`): 実行可能解を見つけた後、違反行からの手 (と `LMIP2` の `b`) が正でなければ、満たされた行 (等式でない) を乱数で `ENOMOTO_T_MIP_LMIP3_SAT_ROWS` 本 (既定 3) 選び、その行の列 (`SAMPLE_COLS` = 64 本まで) をその行の余裕を使い切る端まで動かす手を候補に足す (両側の行は両方の端。整数列は行を満たしたままの向きに丸める)。タブーは見る | `St::sat_tight_value`、`run` |
| `o` | 確かめ用: 目的の行の重みは、ほかに違反行がないときだけ上げる (本家 v2 `monotone`)。セッション 2 の `ENOMOTO_MIP_LMIP2` の `w` と同じもの (リベースで同じ分岐にまとめた) | `run` の重みの更新 |

- 既定 (`ENOMOTO_MIP_LMIP3` なし) の動きは変えていない (`St::last` の記録が増えただけ。`base2` = 既定の 2 回目で、55 問中 49 問が
  3 秒の値まで同じ、違う 6 問は時間で切る探索の揺れ)。
- **歯止め**: `t` で、上限 (下限) のない向きへ 1e6 を超えて動かす手は採らない。入れる前は gen-ip002 (一般整数、上限なし) の `sato` で、
  余裕の大きい行を使い切る手が上限のない列を次々に大きくし、値が 1e307 まで膨らんで左辺が NaN になり、lift の掃引
  (`while s.lift_sweep(..) > 0 {}`) が止まらなくなった (時間の上限を見ないので 60 秒で打ち切られた)。`t` を含む 4 組は歯止めの後に
  回し直した (前の記録は `analysis/lmip3_score_20261105/logs/old_noguard/`)。

- **最初の解の時刻は、どの組でも変わらない** (幾何平均 0.010〜0.012 秒。ほとんどの問題で Local-MIP は 0.01 秒以内に最初の解を出す)。
  変わるのは暫定解の後の改善。
- **`s` だけは害がはっきり** (悪い 32 問 vs 良い 13 問)。例: fiber 533468 → 1251580、drayage-25-23 106885 → 159073、
  gt2 21166 → 26990、physiciansched6-2 49900 → 解なし (違反 1 行)、app1-1 −1 → 解なし (違反 3 行)。一方で
  **roll3000 は既定で解なし (違反 4 行) → `s` を含む組で解が出る** (`s` 23845、`so` 24780、`sato` 25141)。
  - 推測: ENOMOTO は暫定解の後、目的の行が違反している間はいつも目的の重み w0 を上げる (重みの更新のたびに違反行の重みを +1、
    目的の行も含む)。`s` は目的をいつも ±2w0 で数えるので、育った w0 が制約を直す手 (目的を少し悪くする手) を抑え、
    目的の行の下に入った後に実行可能に戻りにくい。本家は w0 を「違反行が目的の行だけ」のときにしか上げない (`o`)。
    `o` を足すと `s` の害は減り (`so`: 悪い 27・良い 16)、`t` も足すと既定より少し良い (`sato`: 良い 24・悪い 20、0.455)。
    本家のスコアは本家の重みの上げ方と組で働くもので、スコアだけ入れると害になる、と読める。
- **`a` (age) は効き目が見えない** (良い 20・悪い 21)。ENOMOTO はタブーの手数が本家 v1 と同じで、同点の多くが既にタブーで

- **`t` (満たされた行からの手) は少し良い** (良い 20・悪い 17、0.459)。良くなった例: qiu 1653 → 932、misc07 3065 → 2865、

  neos-911970 131.7 → 212.6、neos-960392 −35 → −3。1 回ずつの計測なので、この差 (3 問) は揺れと区別できない。
- `sato` の良い例: qiu 1653 → 437、neos-2978193-inde 42.0 → 13.0、markshare_4_0 56 → 10、supportcase26 2202 → 1918、

## 4. まとめ

- 本家のスコア (`s`) をそのまま入れると害になる (55 問で悪い 32・良い 13)。目的の重みを本家の上げ方 (`o` = セッション 2 の `w`) と
  組にすると害は消え、満たされた行からの手 (`t`) も足した `sato` は 55 問で既定より少し良い (良い 24・悪い 20)。roll3000 は
  `s` を含む組でだけ 3 秒で解が出る。
- age (`a`) は効き目が見えない。`t` 単独は 55 問で少し良い (良い 20・悪い 17) が、58 問ではわずかに悪い (SGM 17.24 vs 16.89、
  解けた数 −1 (physiciansched6-2))。
- 58 問の全体では、どの組も既定と差がない (揺れの範囲)。**既定は変えない**。
- 次に試すなら: `s` はセッション 2 の `w` (目的の重み) と組にしてだけ使う。roll3000 のように `s` で解が出る問題を混ぜる形
  (`fj_lmip_mix`) の上で確かめる。55 問・58 問とも 1 回ずつなので、良さそうな `sato` は種を変えた複数回で見直す。
