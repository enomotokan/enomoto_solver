# 内点法の Clarabel との比較: 遅さの原因と高速化の実装策 (2026-10-06)

対象: `src/interior_point/boxed.rs` (PIQP 型の近接内点法 IP-PMM、Newton 系は `src/interior_point/kkt.rs` の正規方程式
Cholesky (faer、AMD、既定は逐次分解) または拡大系 LDLᵀ) と、Clarabel 0.11.1 (pip の `clarabel`、Rust 製。等質自己双対埋め込み、
拡大系 (準定値 KKT) の LDLᵀ を QDLDL または faer で分解) の比較。ブランチ `claude/confident-faraday-0cj5gq` (HEAD `338c0b4`)、
**src は変更していない**。試験的な切り替えと問題の書き出しは別の worktree (スクラッチ、下記) で行った。
計測は 4 コア (Intel Xeon 2.80 GHz) / 15 GB の計算機。時間の計測は `benchmarks/crossover/ab14/` の比較が終わってから行い、
反復数だけを見る調査 (CPU 1 スレッド、nice 19) は並行して行った。

## 0. 要約

- **enomoto の内点法は Clarabel より遅い。原因の大半は「反復数」ではなく、反復数と 1 反復の手間の両方で、しかも
  性質の違う 2 つの要因に分かれる。**
  1. **反復数**: 既定 (Netlib の小さな 60 問、§2.1) で enomoto は Clarabel の **1.14 倍** の反復を使い、perold・pilot4 は 200 反復で
     収束しない。原因は正則化 (近接項) の初期値と下限 (§3): `RHO0 = DELTA0 = 0.1` は PIQP の既定 (`rho_init = 1e-6`,
     `delta_init = 1e-4`) より 3〜5 桁大きく、序盤〜中盤で Newton 方向を歪めて中心性を失わせ (ship04s: 7 反復目で
     `min(sz)/μ = 7e-3`、歩幅 0.05〜0.2 が 30 反復続く)、一方で下限 `1e-10` (PIQP は収束間際に `1e-13` へ下げる) は終盤に
     残差の床 `δ‖λ − y‖ ≈ 1e-9` を作って、目的値で測るギャップが `1e-7` で止まる (stair、bnl1)。
     **初期値 1e-4・下限 1e-13 に替えるだけで 60 問すべて収束し反復数は 0.79 倍 (Clarabel の 0.94 倍)、Gondzio の補正子 2 回を
     加えると 0.69 倍 (Clarabel の 0.82 倍)** になる (§3.3、worktree での実測)。
  2. **1 反復の手間**: §2.2 (計測後に記入)。
- **推奨する実装策** (§5、効果の見込みの大きい順): (1) 正則化の初期値・下限の変更 (`params.rs` の `RHO0`/`DELTA0`/`RHO_MIN`/
  `DELTA_MIN`、PIQP の finetune 相当の「残差が許容値内なら下限を 1e-13 へ」)、(2) Gondzio の多重中心性補正子を既定で有効化
  (既存の `ENOMOTO_T_IPM_GONDZIO`)、(3) 1 反復の手間 (§5 の 3 以降)。

## 1. 計測の方法

### 1.1 同じ問題を両方に解かせる

前処理後の問題 (内点法に渡す `A, b, c, l, u`: 固定列を除いた後、大きさの正規化 `β, γ` の前) をファイルに書き出す手段は無かった
ので、スクラッチの worktree (`<scratchpad>/wt`、HEAD から分岐) の `solve_box_lp_warm` に `ENOMOTO_DUMP_IPM_DIR` (バイナリ: `p, n, nnz`、
CSR、`b, c, l, u`) を足し、同じ worktree に `ENOMOTO_DEBUG_IPM` の出力へ求解回数・反復改良の回数・三角求解の時間を加えた
(`IPM solves=... refine_steps=... plain_solve_time=...`)。それ以外の経路は HEAD と同じ。双対化 (`ENOMOTO_T_XO_DUALIZE=1`、既定) で
内点法が双対 LP を解く問題では、書き出されるのも双対 LP である (Clarabel も同じものを解く)。

Clarabel には `min c^T x, A x = b (ZeroCone), -x_j + s = -l_j, x_j + s = u_j (NonnegativeCone)` として渡す
(`scripts/run_clarabel.py`)。許容誤差は enomoto の `EPS_ABS = EPS_REL = 1e-8` に合わせて `tol_feas = tol_gap_abs = tol_gap_rel = 1e-8`、
`max_iter = 200`。それ以外は Clarabel の既定 (Ruiz 平衡化 10 回、静的正則化 1e-8、動的正則化 ε = 1e-13 / δ = 2e-7、反復改良
最大 10 回 reltol 1e-13、presolve あり、`max_step_fraction = 0.99`)。線形ソルバは `qdldl` (1 スレッド) と `faer` (1 / 4 スレッド) を
記録した (Clarabel の `auto` は `flops / nnz(L) < 40` なら QDLDL、そうでなければ faer の超節点)。

- enomoto 側の時間は `ENOMOTO_DEBUG_IPM=1` の `IPM profile total` (記号分解 + 全反復。クロスオーバーを含まない)。
- Clarabel 側は `DefaultSolver(...)` の構築 (`t_setup`、KKT の組み立てと記号分解) と `solve()` (`t_solve`) の実時間。表の
  「時間」は `t_solve` (記号分解は Clarabel では `solve()` の中の `setup` に含まれる)。
- スクリプト: `<scratchpad>/scripts/{driver.py, run_enomoto.py, run_clarabel.py, ipmdump.py, summarize.py, variants_table.py,
  main_bench.sh}`。結果は `<scratchpad>/results/*.jsonl`。`<scratchpad>` =
  `/tmp/claude-0/-home-user-enomoto-solver/62f8f2eb-f61f-5117-b0a2-bc33ce60d30a/scratchpad`。

## 3. 反復数で負ける原因: 正則化 (近接項) の初期値と下限

### 3.1 症状

ship04s (既定): 7 反復目で相補積の広がりが `min(sz)/μ = 7e-3`、`max(sz)/μ = 98` になり、歩幅 `α = 0.05〜0.2` のまま μ が
`1e-4` 付近で 30 反復停滞する (Clarabel は 20 反復、歩幅 0.35〜0.9)。adlittle も同じ (8 反復目から歩幅 0.03〜0.5)。

```
IPM it=  7 alpha_p=1.83e-1 alpha_d=8.17e-2 mu=9.22e-5 sigma=4.37e-1 min(sz)/mu=7.0e-3 max(sz)/mu=9.8e1
IPM it= 19 alpha_p=3.04e-2 alpha_d=5.30e-2 mu=5.26e-5 sigma=8.24e-1 min(sz)/mu=7.5e-3 max(sz)/mu=3.4e2
IPM it= 28 alpha_p=4.26e-1 alpha_d=5.15e-1 mu=4.29e-5 sigma=2.43e-1 min(sz)/mu=2.7e-3 max(sz)/mu=1.1e2
```

このとき ρ, δ は `1e-2 〜 1e-5` で μ と同じ桁か大きい。IP-PMM の Newton 系は元の KKT 系ではなく近接項 `ρ(x − ξ)`、`δ(λ − y)`
を加えた系なので、ρ, δ が μ に比べて大きいうちは方向が元の問題の中心パスから外れ、中心性が壊れる。ρ, δ は相補性の相対減少率
`r` に比例してしか下がらない (`(1 − r)` 倍、停滞中は `(1 − 0.666 r)` 倍) ので、中心性を失って r が小さくなると ρ, δ も
下がらず、悪循環になる。

### 3.2 PIQP・Clarabel の既定との差

| | enomoto (`params.rs`) | PIQP (`settings.hpp`) | Clarabel |
|---|---|---|---|
| 初期 ρ (主の近接項) | `RHO0 = 1e-1` | `rho_init = 1e-6` | 静的正則化 `1e-8` (固定) |
| 初期 δ (双対の近接項) | `DELTA0 = 1e-1` | `delta_init = 1e-4` | 同上 |
| 下限 | `RHO_MIN = DELTA_MIN = 1e-10` | `reg_lower_limit = 1e-10`、残差が許容値内で更新が 7 回止まったら `reg_finetune_lower_limit = 1e-13` | ― |
| 停止のギャップ | `\|c·x + b·y + h·z\|` (相対 1e-8) | 既定では残差だけ (`check_duality_gap` は任意) | `\|pcost − dcost\|` (相対 1e-8) |
| 初期点 | `W = 1 + δ` の KKT を 1 回解く (PIQP 式) | 同じ | 等質埋め込みの標準初期化 |

enomoto の `RHO0 = DELTA0 = 0.1` は親モジュール (`interior_point.rs`) から引き継いだ値で、PIQP の既定より 3〜5 桁大きい。

### 3.3 終盤の床: 下限 1e-10 とギャップの停止判定

初期値を小さくすると (`ENOMOTO_T_IPM_REG0=1e-4`)、ship04s は 15 反復、adlittle 17 反復になるが、stair・bnl1 が 200 反復で
失敗する。trace を見ると 20〜27 反復目で `pres = 1e-9`、`dres = 1e-13` まで収束したあと、`gap = 3.6e-7` (stair)、`1.7e-7` (bnl1) が
一定のまま μ だけが `1e-300` まで潰れる。

```
stair (REG0=1e-4):
IPM it= 20 pres=1.09e-9 dres=3.08e-14 gap=1.95e-7 rho=1.0e-10 delta=1.0e-10
IPM it= 29 pres=1.09e-9 dres=5.33e-15 gap=3.61e-7 rho=1.0e-10 delta=1.0e-10   (以後 200 まで同じ)
```

主残差が `1.09e-9` で止まるのは、近接項のせいで Newton 方向が `A x − b = −δ(λ − y)` に収束するため (床 ≈ `δ‖λ − y‖`、
δ = 1e-10、‖λ − y‖ ≈ 10)。目的値で測るギャップ `c·x + b·y + h·z` には `r_p·y` の分 (1e-9 × ‖y‖ ≈ 300) が乗って 1e-7 となり、
`bnd_g ≈ 1e-8 × max(|c·x|, |b·y|, |h·z|)` を下回れない。既定の `0.1` から始めると、停滞中に `(1 − 0.666 r)` で下がる ρ, δ が
ちょうど収束の頃に 1e-10 に達するので、この床が見えにくかっただけである (perold・pilot4 の失敗の一因でもある)。

下限を PIQP の finetune と同じ `1e-13` にすると床は `1e-12` になり、stair 21、bnl1 30、tuff 24 反復で収束し、**perold (76)・
pilot4 (33) も収束する**。

## 4. 1 反復の手間

§2.2 のとおり、中〜大の問題では 1 反復の時間は enomoto の方が短く (Kennington で Clarabel の 1/2〜1/7)、1 反復の手間で負けているのは
小さな問題 (1 反復 5 ms 以下) だけである。内訳は次のとおり。

### 4.1 系の次元と因子の大きさ (enomoto が速い理由)

enomoto は境界のスラック・乗数を消去した `p` 次元の正規方程式 `A D^{-1} A^T + δI` を正定値 Cholesky (faer、AMD、逐次) で解く。Clarabel
は変数 `x` (n)、等式乗数 (p)、境界の不等式 (n_lo + n_up、enomoto なら `Σ` に畳み込まれる) をすべて持つ準定値 KKT 系を LDLᵀ で解くので、
次元が `n + p + n_lo + n_up` になる (pds-20: enomoto 8,928、Clarabel 約 25 万。osa-60: 10,209 対 約 50 万)。等式が少なく列が多い
LP (Kennington 全部、Netlib の fit、ship、osa) では正規方程式が圧倒的に有利で、これが Clarabel に対する 3〜7 倍の差になっている。
Clarabel が LP でも拡大系を使うのは円錐計画一般 (QP の P、二次錐など) に同じ経路を使うためで、LP 専用の設計ではない。

### 4.2 分解・求解・その他の比率

| 問題 | 反復 | 内点法 (s) | 分解 | 求解 (改良含む) | 残り | 1 反復 (ms) | Clarabel 1 反復 (ms) |
|---|---|---|---|---|---|---|---|
| stocfor2 | 25 | 0.180 | 0.086 | 0.059 | 0.035 | 7.2 | 2.6 |
| scfxm3 | 29 | 0.113 | 0.021 | 0.065 | 0.027 | 3.9 | 2.8 |
| wood1p | 31 | 0.279 | 0.053 | 0.086 | 0.140 | 9.0 | 6.0 |
| fit2p | 24 | 0.442 | 0.067 | 0.251 | 0.124 | 18.4 | 15.4 |
| osa-60 | 55 | 5.086 | 0.423 | 2.482 | 2.181 | 92.5 | 692 |
| cre-b | 53 | 2.046 | 0.839 | 0.621 | 0.586 | 38.6 | 128 |
| pds-20 | 102 | 26.654 | 21.425 | 3.549 | 1.680 | 261 | 1834 |
| ken-18 | 51 | 14.988 | 11.533 | 2.043 | 1.412 | 294 | 521 |

- **分解が重い問題** (pds-20、ken-18、pilot87、dfl001) では分解が 70〜80 %。faer の逐次 Cholesky は AMD 順序で、pds の格子状の構造では
  nested dissection の方が fill-in が数倍少ないのが通例 (前回の報告 §3.4)。並列分解 (`ENOMOTO_T_FACTOR_SEQ=0`) は §2.3 の計測で
  改めて比べる (第 2 回の比較では逐次の方が速かった)。
- **横長の問題** (osa-60、cre-b、fit2p) では「求解」と「残り」が大きい。求解の中身は三角求解 (`plain_solve_time`、osa-60 で 0.1 秒
  程度) ではなく、`A D^{-1} r_x`・`A^T dy` の行列ベクトル積 (`csr_mat_t_vec_into` は逐次) と反復改良の残差計算 `K·x` (osa-60 で
  111 求解中 42 回の改良)。「残り」は残差・停止判定・右辺・ステップ長などの rayon ループ 20 本あまり。
- **小さな問題** では rayon の `par_iter` の join の手間 (1 本 10〜50 µs × 20 本 × 反復) と `dot`/`norm_inf` の集計が 1 反復 1〜3 ms を占め、
  Clarabel (逐次、QDLDL) の 2〜3 ms と同程度になる。stocfor2 では分解 0.086 秒 (25 回、1 回 3.4 ms、nnz(L) = 53k) 自体も Clarabel の
  1 反復全体 (2.6 ms) より長く、faer の simplicial Cholesky の 1 回の手間が QDLDL より重い可能性がある (要確認: 同じ行列で
  faer と QDLDL を比べる計測はしていない)。

### 4.3 反復改良

正規方程式は `δ` が 1e-10 まで下がり `D^{-1}` の桁が開くと精度が落ちるので、反復改良 (`REFINE_STEPS = 3`、残差が半分未満にならなければ
打ち切り) が入る。収束する問題では改良は 0〜0.3 回/求解だが、収束しない問題では 1 回/求解を超える (greenbea 500/399、perold 390/401、
pilotnov 245/323、d6cube 379/400)。改良は「対称」ではなく、方向の精度が出ない状態 (正規方程式の条件数が `D` の比に比例して悪化) を
示している。§3.4 の `REG0=1e-4` + 拡大系で stair が収束したこと、`REFINE=0` で反復数が変わらないこと (改良が効いていない) から、終盤の
精度は改良の回数より系の選択 (拡大系か正規方程式か) と正則化の床で決まる。

## 5. 推奨する実装策 (効果の見込みの大きい順)

### 5.1 正則化 (近接項) の初期値と下限を PIQP に合わせる

- **変更箇所**: `src/params.rs` `interior_point::{RHO0, DELTA0, RHO_MIN, DELTA_MIN}`、`src/interior_point/boxed.rs` (`rho`, `delta` の初期化と
  下限の適用 `delta = delta.max(delta_min)` の箇所)。
- **既定値の候補**: `RHO0 = DELTA0 = 1e-4` (§3.4 で最も良かった値。PIQP の `rho_init = 1e-6, delta_init = 1e-4` は bnl1 で失敗)。下限は
  `1e-13` (PIQP の `reg_finetune_lower_limit`)。より PIQP に忠実にするなら、下限は `1e-10` から始め、主残差・双対残差が許容値内に
  なった (または近接中心の更新が 7 回続けて止まった) 時点で `1e-13` に下げる (PIQP の finetune)。§3.4 の計測は単純に下限 `1e-13` で
  60 問すべて収束したので、まず単純な版でよい。
- **効果の見込み**: Netlib 小 60 問で反復数 0.79 倍、Clarabel の 0.94 倍。perold・pilot4 が収束する。中〜大の問題 (§2.3) で
  確かめる。
- **退行の危険**: (a) 初期点の系 (`W = 1 + δ`) の正則化も小さくなる。`REG0 = 1e-6` 以下では stair が初期点から発散した (μ = 1.4e5)。1e-4
  なら 60 問で問題なかったが、初期点の系だけ `0.1` で解く選択肢 (`ENOMOTO_T_IPM_INIT_REG`) も worktree にある (効果は無かった)。
  (b) 正則化が小さいと正規方程式の Cholesky が破綻しやすい (`factorization failed` → 正則化を 100 倍に戻す経路が既にある)。
  (c) 近接中心を使う Farkas 判定 (`at_floor && stall >= 2`) は `rho_min`/`delta_min` を見ているので、下限を変えても条件は同じ。
  (d) 内点法の経路が全問で変わるので、クロスオーバーの時間 (基底の質) も変わる。109 問の比較 (`benchmarks/crossover/ab*/`) で
  判定するのがよい。
- **PIQP との残る差**: PIQP は停止判定にギャップを使わない (`check_duality_gap` 任意)。enomoto の `gap = |c·x + b·y + h·z|` は残差 × 乗数の
  雑音 (§3.3) を含むので、下限 1e-13 でも大きな乗数の問題では床が残りうる。代替は相補性 `s·z` をギャップとして使う (Clarabel も
  `|pcost − dcost|` だが、残差を 1e-13 まで追い込むので床が見えない)。

### 5.2 Gondzio の多重中心性補正子を既定で有効にする (`ENOMOTO_T_IPM_GONDZIO=2`)

- **変更箇所**: `boxed.rs` の `gondzio_max` の既定値 (`tunable!("ENOMOTO_T_IPM_GONDZIO", 0usize, usize)` → 2)。実装は既にある。
- **効果の見込み**: 5.1 と組み合わせて反復数 0.69 倍 (Clarabel の 0.82 倍)。1 回の補正は分解なしの求解 1 回 (反復改良込み) なので、
  分解が反復の 70 % 以上の問題 (pds、ken-18、pilot87、dfl001) では反復数の減少がそのまま時間になる。横長の問題 (osa) では求解が
  重いので得は小さい。
- **退行の危険**: 第 1 回の比較で単独では大きめの問題で遅くなった (補正 1 回あたり求解 + 行列ベクトル積の手間)。歩幅が
  十分 (`α ≥ 0.999`) なら補正しない条件は入っている。既定にするなら `dim` か `nnz(L) / nnz(A)` の比で「分解が求解より十分重い」
  ときだけ有効にする (Gondzio & Colombo 2008 の `K = floor(factor/solve の比)` 方式)。

### 5.3 小さな問題の rayon の手間を減らす

- **変更箇所**: `boxed.rs` の `par_iter_mut().with_min_len(PAR_MIN_LEN)` 群、`dot`/`det_sum`/`norm_inf`、`kkt.rs` の
  `NormalKkt::solve_in_place` の並列ループ、`sparse.rs` の `csr_mat_t_vec_into` (逐次)。
- **直し方**: `n + p` が閾値 (2〜4 万) 未満なら逐次版に切り替える (前回の報告 §2.10 (c))。`csr_mat_t_vec_into` は `NormalKkt` が
  持つ `col_ent` (CSC) で列ごとに並列化できる。
- **効果の見込み**: Netlib 小の内点法 20〜40 % (1 反復 1〜3 ms)。Clarabel と同程度の 1 反復になる。中〜大では効かない。
- **退行の危険**: 加算順を揃えればビット一致。

### 5.4 分解の手間 (大きな問題)

- **順序付け**: faer の AMD だけ。pds・ken のような構造では nested dissection で fill-in が数倍減る見込み (HiGHS IPX は AMD、
  MOSEK・Clarabel (faer の `SymmetricOrdering::Amd`) も AMD なので、ここは enomoto だけが不利な点ではない)。純 Rust の ND は無く、
  METIS のバインディングが要る。見込みは pds-20 の分解 21 秒 → 数秒だが、実装の手間が大きい。
- **並列分解**: `ENOMOTO_T_FACTOR_SEQ=0` (faer の並列) は §2.3 で再計測。
- **超節点の閾値**: faer は `flops / nnz(L) > 40` で超節点に切り替える (Clarabel の `auto` も同じ閾値で QDLDL ↔ faer)。
  変える余地は小さい。

### 5.5 ギャップの停止判定と停滞の検出

- `gap` を `s·z` (相補性) で測るか、残差が許容値内で `gap` が 10 反復改善しなければ「許容値の数倍以内」として受理する
  (クロスオーバーは `IPM_ACCEPT_GAP_REL` で既に緩く受理している)。stair・bnl1 型の 100 反復以上の無駄を消す。5.1 で下限を
  1e-13 にすれば頻度は下がるが、保険として要る。
- 発散の検出: `REG0 = 1e-8` の stair のように主残差が 1e4 に発散しても `worst` が有限なので 200 反復回る。`res_new` が `res` の
  1e3 倍を超えたら最良点に戻して打ち切る。

### 5.6 その他 (効果は小さいか未検証)

- 拡大系への自動切り替え (`ENOMOTO_T_IPM_SWITCH_AUG`) は第 13 回で不採用。5.1 で終盤の精度の問題が減れば不要。
- Ruiz 平衡化は前処理 (`RUIZ_ITERS = 10`) で済んでおり、Clarabel の `equilibrate` と同等。
- 双対化 (`ENOMOTO_T_XO_DUALIZE`、第 14 回の比較中) は ex10 型 (`p ≫ n`) の問題の系の次元を減らす。
