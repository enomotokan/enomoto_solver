# 裏のカットの写しのカットの LP の上限を反復で決める (`ENOMOTO_MIP_BG_CUTS_LP_WORK`) と、厳密な DSE 重みを列の値を渡す問題に絞る (`ENOMOTO_MIP_BG_CUTS_DSE=rw`) (2026-11-02)

bench に使う環境変数: `ENOMOTO_MIP_BG_CUTS_LP_WORK=1` (第 1 候補)、`ENOMOTO_MIP_BG_CUTS_LP_WORK=1` + `ENOMOTO_MIP_BG_CUTS_DSE=rw` (第 2 候補)

- 発端: 裏のカットの写しの中のカットの LP は、1 回の時間の上限 `max(0.02 × time_limit, 1.0)` 秒に当たると外され、2 回外すとループを抜ける。
  上限が秒なので、機械の速さ・重みの質で結果が変わる (遅い機械の physiciansched6-2 で写しが 0 ラウンド (analysis/bgx_check1_20261102.md)、
  単位重みの neos-960392・neos-933966 (analysis/bgx_check2_20261102.md))。厳密な DSE 重みの `=r` は bench16 で mc11・roll3000 の道を変え、
  行の多い問題で時間の上限を大きく超えた (analysis/halve_submip_20261030.md の bench16)。利用者の方針は「裏のカットの運の要素を設計で取り除く」。
- 並列のもう 1 つのセッションが裏のカットの止め方 (`ENOMOTO_MIP_BG_CUTS_DETERM`、solver.rs 側) を作っている。こちらは separation.rs 側の
  写しのカットの LP の上限と失敗の扱い。
- 土台: 228517e9 + 試作 (commit 2141b41d、既定では働かない)。4 スレッド・60 秒、ソルバーは同時に 1 つ、`ENOMOTO_MIP_LOG=1`・`ENOMOTO_MIP_BG_CUTS_LOG=1`。
  `cargo test --release --lib` (PyO3 のため `RUSTFLAGS="-C link-arg=-L/usr/lib/x86_64-linux-gnu -C link-arg=-lpython3.13"`) 333 件通過。

## 1. 試作 (既定では使わない。既定の経路は変えない)

- `ENOMOTO_MIP_BG_CUTS_LP_WORK` = `f[h]` (`src/mip/separation.rs` の根のカットのループ、写し (`job.is_some()`) だけ):
  - カットの LP 1 回の反復の上限を `max(f × 主の根の LP の反復 (BG_ROOT_ITERS、最低 100), ENOMOTO_T_MIP_BG_CUTS_LP_WORK_MIN (既定 2000),
    ENOMOTO_T_MIP_CUT_LP_WORK_PREV (既定 5) × このループで最適まで解けたカットの LP の反復の最大)` にする。
    これまでの写しの反復の上限は写し自身の根の LP の反復から決めていて (列の値を渡すと 1 反復なので 11000)、実際には効いていなかった。
  - 時間の上限は今の上限 (`ENOMOTO_T_MIP_BG_CUTS_LP_CAP_SECS`・`ENOMOTO_MIP_BG_CUTS_LP_CAP` を含む) の `ENOMOTO_T_MIP_BG_CUTS_LP_WORK_TIME_MULT` 倍
    (既定 5、60 秒の問題で約 5 秒) にして、安全網としてだけ残す。
  - 末尾に `h` (`h` だけなら f = 1): 写しのカットの LP が上限 (反復・時間) に当たったら、失敗と数えずにカットを外して以後の本数の上限を半分にして
    続ける (`ENOMOTO_MIP_CUT_LP_HALVE` と同じ形。`ENOMOTO_T_MIP_CUT_LP_HALVE_MIN` (既定 20) 本以下で当たったら失敗と数える。止めの合図の後は半分化しない)。
  - 表示: `background cut LP work cap: N iters (f .., main root LP .. iters)`、0・1 ラウンド目の `background cut LP time cap ..s, iteration cap N`。
- `ENOMOTO_MIP_BG_CUTS_DSE=rw` (`src/mip/solver.rs`・`src/simplex.rs`・`src/simplex/slope_intercept_dual.rs`): `=r` (写しの根の LP を厳密な DSE 重みから解く) を
  - 列の値を渡す問題 (`lpw` が働く問題、主の根の LP が 1 秒以上) だけにかける (渡さない問題は既定と同じ)。
  - 厳密な重みの計算 (行ごとの BTRAN) で、32 行ごとに LP の期限・取り消し・主の止めの合図 (`CutJob::stop`、写しのスレッドの
    `DSE_EXACT_STOP` に置く) を見て、当たったら計算をやめて単位重みで続ける (`exact DSE weights stopped by the deadline or the stop signal`)。
  - `=r` は変えていない (`DSE_EXACT_STOP` がないと今までの `from_basis`)。

## 2. 結論

1. **`LP_WORK=1` で、写しのカットの LP の失敗が秒の上限から来ている 4 問すべてで失敗 0 になり、写しの道が回ごとにそろう**。
   既定は neos-960392・neos-933966・comp07-2idx が 3/3 で 0・1 ラウンド目を外して 2 ラウンドで抜け、atlanta-ip も 3/3 で 2 回外す。
   `w1` は 4 問とも 9 回すべて失敗 0 (atlanta-ip 12〜13 ラウンド・3/3 で使う・写しの下界 81.27〜81.37 → 81.40〜81.43、comp07-2idx は写しが 3.67 → 6 まで上げる、
   neos-933966 7〜8 ラウンド)。写しのカットの LP の反復の並びは回をまたいで同じ (neos-960392 は 3 回とも 5176・1701、neos-933966 は 1917・972・825・…、
   comp07-2idx は 1093・1183・1249・…、physiciansched6-2 は 1402・1118・1141・978・…)。
2. **遅い機械の真似 (`ENOMOTO_T_MIP_BG_CUTS_LP_CAP_SECS=0.6`、physiciansched6-2) で、手間の上限に変えた形は結果が変わらない**:
   既定 (`def_s06`) は 3/3 で 0・1 ラウンド目が 0.61 秒の上限に当たって写し 0 ラウンド、**0/3 で時間切れ**。`w1_s06` は失敗 0 で **3/3 で最適** (22.7〜29.1 秒、
   普通の速さの `w1` と同じ反復の並び 1402・1118・1141・… の回もある)。安全網の時間の上限 (0.6 × 5 = 3 秒) には当たらない。
   `w1h_s06` は 2/3 (時間切れの 1 回は写しが 12 ラウンド・49324 で使われた後の木の側。`w1` 普通の速さの時間切れ 1 回も同じ形)。
3. 結果 (状態・時間) は既定と揺れの範囲で区別できない: 最適まで行くのは neos-960392 (どの形も 3/3、25.6〜28.8 秒)・physiciansched6-2 (def 3/3、w1 2/3、
   w1h 3/3、rw 3/3)・mc11 (どの形も 3/3) だけで、ほかは時間切れ。physiciansched6-2 の時間切れ 1 回 (w1) は写しが 12 ラウンドで 49324 を出して使われた
   後で、写しの失敗とは関係ない (分枝の側の揺れ。bgx_check1 の群 C と同じ形の暫定解 49424)。
4. **半分化 (`h`) はほとんど働かず、得は見えない**: 半分化が起きたのは atlanta-ip の 1 回だけで、そこでは 59 本でも 28 本でもカットの LP が
   1 万反復 5 秒 (安全網) に当たって効かなかった (この回は写しの LP が他の回の 10 倍の反復。主の FJ の解が悪く写しのスレッドが 1 本の回もあり、
   atlanta-ip の w1h は 1/3 しか写しを使えなかった)。f = 1 の反復の上限は atlanta-ip では 13823 と緩く、ここでは安全網の時間の上限が実際の
   上限になる (機械の速さの影響が残るのはこの形)。値で選べる形のまま残し、bench には `h` なしを勧める。
5. **`=rw` は時間の上限の超過を直す**: `=r` の neos-4722843-widden 96.8 秒・uccase12 77.6 秒 (止めの合図の後の待ち 54.5・54.8 秒。bench16 の 92.7・84.1 秒と
   同じ形) が、`rw` では 60.5・60.2 秒 (待ち 0.11・0.6 秒)、`LP_WORK=1h` + `rw` も 60.4・60.3 秒。neos-4722843-widden は 112876 行の BTRAN が 7.9 秒で
   止めの合図に当たってやめ、写しは 0 ラウンド (既定も 2 回外して 0)。uccase12 は 1 回目の写しは列の値を渡さないので `rw` はかからず、再スタート後の
   写し (列の値を渡す) の BTRAN が 0.79 秒で止めの合図に当たってやめた。neos-4763324-toguru は列の値を渡さない (主の根の LP 0.15 秒) ので `rw` はかからない
   (bench16 の 96.8 秒は `=r` が渡さない問題にもかかったため)。mc11 も渡さない問題で、`rw` は既定と同じ道 (51 ラウンド・11666、3/3 最適)。
6. **`=rw` 単独は写しの失敗を半分しか直さない**: neos-933966 は 3/3 で 7 ラウンド失敗 0、neos-960392 は 2/3 (1 回は 0・1 ラウンド目が 1.01 秒の上限に当たる)、
   comp07-2idx は 3/3 とも最初の LP だけ通って 1・2 ラウンド目が上限に当たる (写し 4.29)、atlanta-ip は根の BTRAN に 3.8 秒かかり 1 回は 0 ラウンド。
   重みの質を上げても秒の上限が残る限り運の要素は残る。`LP_WORK` と重ねる形 (`w1h_rw`) は 3 問の時間の確かめでしか測っていない。
7. 判断: **`ENOMOTO_MIP_BG_CUTS_LP_WORK=1` を 58 問・Mittelmann の bench に出す** (写しの失敗を手間で決め、遅い機械の真似でも結果が変わらない)。
   `=rw` は時間の上限の超過がなくなったので、`LP_WORK=1` と重ねた形を第 2 候補とする。どちらも 60 秒の結果への効きは今回の 6 問では見えない
   (写しの結果を主が使うのは atlanta-ip・physiciansched6-2・mc11 だけ)。

## 4. 注意・次

- f = 1 は行の多い問題 (atlanta-ip 13823 反復) で緩く、写しの LP が遅い道に入ると時間の安全網 (約 5 秒) が実際の上限になる。上限に当たった LP は
  止めの合図を見ないので、主はその終わりを最大で安全網の分だけ待つ (今回の待ちは最大 1.3 秒)。bench で時間の上限の超過が出たら f を 0.5 に
  下げるか、写しのカットの LP にだけ止めの合図を見させる (ただし止めた LP の解き直しが `TimeLimit` になると写しは結果を返さない
  (`cut_ok` が偽) ので、外す前の状態に戻す (`ENOMOTO_MIP_CUT_FAIL_RESTORE`) 形と組にする必要がある)。
- `rw` の BTRAN は行の数に比例して重く (atlanta-ip 3.8 秒、neos-4722843-widden 11 万行で 8 秒以上)、その間写しはラウンドを回さない。行の多い問題では
  厳密な重みの代わりに主の重み (`=1`) を渡すなどの形も候補。
- 計測の途中で `git rebase` を走らせると、台本の出力 (`run1.out`) が書き換えられて後半が失われた (結果は `res.jsonl` に残る)。`run1.out` は `res.jsonl` から作り直した。
