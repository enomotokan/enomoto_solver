# uccase12・ns1116954: HiGHS が 1 ノードで解き ENOMOTO が解けない理由の調査 (2026-10-20)

- 環境: 専用のクラウドコンテナ、CPU 4 (`nproc` = 4)。ソルバーは同時に 1 つだけ、ビルドとも重ねていない。HiGHS 1.15.1 (highspy)。
- コミット: ブランチ `inv/ucc-ns2-20261020` (develop bc89ad1 + 9 つの調査の試作) に、この調査の試作 3 つを足したもの。
  試作はどれも既定では使わないので、「既定」の計測は統合ブランチの既定の動作。
- **計測はすべて 4 スレッド** (ENOMOTO `ENOMOTO_MIP_THREADS=4` + `solve(..., 4, log=True)`、HiGHS `threads=4`)、時間上限 60 秒
  (HiGHS の uccase12 の切り分けは 120 秒)。
- ログ・スクリプト: `work_ucc/` (`run_eno.py` / `run_highs.py` / `batch.sh <名前> <mps> <秒> [ENV=VAL...]` / `side.sh` /
  `highs_sol.py`)、ログは `work_ucc/logs/` (`e_*` ENOMOTO、`h_*` HiGHS、`side/` 副作用の 10 問)。

## 1. 結論

| 問題 | HiGHS が 1 ノードで解く理由 | ENOMOTO が解けない理由 | 試作の効果 |
|---|---|---|---|
| ns1116954 | 目的関数が**全部 0** の実行可能性問題。前処理直後の FJ が 2.8 秒で解を出す (LP 反復 0)。ただし**種 0 の当たり**: `random_seed=1〜5` では 5 回とも 60 秒で解なし (根の LP だけで約 42 秒) | FJ2 は 1 回 (2.6 秒、違反 1〜2 行で止まる) しか回らない。見つかっても根のカット・ヒューリスティクスを最後まで回す | FJ を種を変えて続ける + 根で下界が暫定解に届いたら終える: 6 種中 5 種で 16.6〜22.6 秒で最適 |

## 2. ns1116954 (事実)

問題: 131991 行、12648 列 (0-1 7482、連続 4446)、目的関数の係数はすべて 0。前処理後 131865 行 11928 列 (両者ほぼ同じ)。

| | HiGHS 種 0 (2 回) | HiGHS 種 1〜5 (各 1 回) | ENOMOTO 既定 (2 回) |
|---|---|---|---|
| 前処理 | 1.6〜1.8 秒 | 1.6 秒 | 4.3〜4.8 秒 (前処理の LP 3.0 秒を含む) |
| 根の LP | 解かない | 3.3 → 45.1 秒 (12456 反復) | 約 10〜11 秒 (3225 反復、終わりの時刻 14.5〜16.5 秒) |
| 最初の解 | FJ 0 (2.8 秒) | なし | なし |
| 結果 | 最適 3.0 / 3.3 秒、1 ノード | 5 回とも時間切れ・解なし | 時間切れ・解なし |

- ENOMOTO の FJ (`fj_search`、別スレッド): FJ2 1 回目は 2.62 秒・413939 歩で「改善のない手間の上限」で止まり、最後の違反は
  `>= 1` の被覆の行 2 本 (長さ 20・38)。時間上限 (`min(0.05 T, 5)` = 3 秒) の残りは旧来の局所探索に使われ、種を変えた FJ2 は回らない。
- ENOMOTO の根の LP は HiGHS (42 秒) より速い。前の調査で疑った「根の LP が遅い」は主因ではない (HiGHS も LP では解いていない)。
- 既定ではカットのループの LP が 2 ラウンドとも時間切れ (`LP status TimeLimit, removed the cuts`)、内点法の丸めが 17〜18 秒、
  RENS が 9.5 秒で時間切れ。
- 試作 `ENOMOTO_MIP_FJ_FEAS_EXTEND` のみ (1 回): FJ2 の 9 回目 (13.1 秒) で 0 を見つけるが、根のカット・ヒューリスティクス・裏の
  カットを回し続けて 52.0 秒で最適。→ 根で終える判定が無いことも原因の一部。

試作 2 つ (`ENOMOTO_MIP_FJ_FEAS_EXTEND` + `ENOMOTO_MIP_ROOT_GAP_EXIT`) を種を変えて (`ENOMOTO_T_MIP_FJ_SEED`):

| 種 | FJ2 の回数 (見つけた時刻、FJ のスレッドで) | 結果 |
|---|---|---|
| 0 (2 回) | 9 回 (12.1 秒) | 最適 18.4 / 22.6 秒 |
| 1 | 16 回 (19.8 秒で止められる) | 時間切れ・解なし |
| 2 | 1 回 (1.2 秒) | 最適 16.6 秒 |
| 3 | 1 回 (2.0 秒) | 最適 17.1 秒 |
| 4 | 6 回 (7.9 秒) | 最適 17.2 秒 |
| 5 | 8 回 (11.2 秒) | 最適 16.9 秒 |

FJ が早く見つけても、主のスレッドが根の LP (14〜16 秒) を終えてカットのループで受け取るまで終われない (16〜17 秒が下限)。

## 3. uccase12 (事実)

問題: 121161 行、62529 列 (0-1 9072)。前処理後 HiGHS 88217 行 40240 列、ENOMOTO 88584 行 40371 列 (同程度)。

| | HiGHS 既定 (2 回、種 1・2 も同様) | ENOMOTO 既定 (2 回) | ENOMOTO + `BG_CUTS_BASIS` (3 回) |
|---|---|---|---|
| 前処理 | 2.2 秒 | 3.7 秒 (前処理の LP 2.9 秒を含む) | 同 |
| 根の LP | 11507.2914 (5.6 秒までに) | 11507.2914 (8.6 秒、内点法 + クロスオーバーが先) | 同 |
| カット後の根 | 11507.3690 | 11507.3518 (2 ラウンド、1 ラウンドの分離 4 秒) | 裏のカットで 11507.3690 |
| 最初の解 | R 12360.1 (5.6 秒) | ランダム丸め 11622.8 (22.4〜24.3 秒) | 同 |
| 暫定解の推移 | C 11626.7 (12.9 秒) → L 11507.4053 (25.8〜28.7 秒) | RENS 11507.95 (30.3 秒) → RINS 11507.90 (32.8 秒) で止まる | RINS 11507.90 (約 31 秒) → 再スタート → ランダム丸め・RINS 11507.41 (再開後約 11 秒) |
| 結果 | 最適 23.2〜28.7 秒、1 ノード (ギャップ 3e-6、許容 1e-4) | 時間切れ 0 ノード (ギャップ 4.8e-5) | **最適 48.7 / 49.5 / 49.3 秒**、0 ノード (2 回目の再スタートの前処理で実行不能) |

- 既定の ENOMOTO の時間の内訳 (1 回目): 前処理 3.7 → 根の LP 8.6 → カット 2 ラウンド 16.8 → 自明な解 4.0 秒 (固定して LP を 4 回)
  → ランダム丸め 3.4 秒 → 内点法の丸め 2.9 秒 (失敗) → RENS・RINS 30.3〜32.8 秒 → **裏のカットの終わりを 23.3 秒待つ** → 56.1 秒。
- 待つ理由 (`ENOMOTO_MIP_BG_CUTS_LOG` で裏の求解のログを出して確認): 裏のカットの求解は写し (`TreeSnapshot`) から始め、写しは
  根の基底を持たないので、88600 行の根の LP を基底なしで解き直す。主が 4 本並列で 5 秒かかる LP が、他のスレッドと CPU を取り合い
  38 秒たっても終わらない。LP は止めの合図 (`CutJob::stop`) を見ないので、主は `BgCuts::finish` の join で LP の時間切れまで待つ。
- 基底を写しに渡すだけ (1 段目) では、裏の根の LP は 0.52 秒 (281 反復) になり 4 ラウンド回るが、主がカットの行を置き換えた後の
  LP が 25 秒かけて時間切れになった (全部のカットの行を消すと効いていたカットの分だけ基底列が余り、`repair_basis` で構造列を外した
  基底から解き直しになる、と推測)。裏の LP の最後の基底も受け取って置き換え後の LP に入れると (2 段目) 95〜104 反復・0.2 秒。
- `ENOMOTO_MIP_REL_GAP=1e-4` だけ (既定の上): 裏のカットの待ちで時間切れのまま。`ENOMOTO_MIP_NO_BG_CUTS=1`: 待ちは消えるが
  再スタート後の根の LP を基底なしで解き直し (6.9 秒) 時間切れ。
- HiGHS の切り分け: `mip_heuristic_effort=0` も `mip_heuristic_run_rins=false mip_heuristic_run_rens=false` も 24.6〜26.1 秒・
  同じ解 (根の L は止まらない)。`presolve=off` は 8.5 秒で 11507.925 (C)。`mip_rel_gap=0` は 120 秒で時間切れ (下界 11507.3756)。
  → HiGHS の決め手は**相対ギャップ 1e-4** と、根の LP の値がすでにその範囲にあること。前処理・カットは決め手ではない。

## 4. 試作 (どれも既定では使わない)

1. `ENOMOTO_MIP_BG_CUTS_BASIS` (src/mip/solver.rs): 裏のカットの求解を始めるとき主の根の LP の基底を `BG_ROOT_BASIS` (スレッド
   局所) で渡し、写しの根の LP の前に `set_basis`。裏の求解は終わるとき最後の LP の基底を `CutJob::basis` に置き、主はカットの行を
   置き換えた後にそれを入れる。行の数が合わなければ使わない。診断用に `ENOMOTO_MIP_BG_CUTS_LOG` (裏の求解のログ) と、置き換えの
   前後の LP の反復数のログ (`ENOMOTO_MIP_LOG`) を足した。
2. `ENOMOTO_MIP_ROOT_GAP_EXIT` (src/mip/solver.rs `root_gap_closed`、src/mip/separation.rs `root_cut_loop`): 根で、根の LP の値
   (`cur_lb`) が暫定解の打ち切り値 (`prune_limit`) に届いたら、カットのループを抜け、根のヒューリスティクス・裏のカットを回さずに
   最適で終える。判定はカットのループの各ラウンドの頭と、ループの後 (FJ のスレッドを受け取った後)。
3. `ENOMOTO_MIP_FJ_FEAS_EXTEND` (src/mip/heuristics.rs `fj_search`・`fj_feas_extend`、solver.rs の FJ のスレッドを始める所):
   目的関数が全部 0 のとき、FJ のスレッドの時間上限を `ENOMOTO_T_MIP_FJ_FEAS_FRAC` (0.5) x 時間上限にし、旧来の局所探索を
   飛ばして種を変えた FJ2 を見つかるまで繰り返す (見つかれば最適なのですぐ返す)。FJ は根のカットのループの後で止められる。
   診断用に `ENOMOTO_T_MIP_FJ_SEED` (FJ の種をずらす) を足した。

効果 (担当の問題): 上の表。3 つ全部を有効にした uccase12 は 47.8 秒で最適 (1 回)。

## 6. 推測と確かでない点

- **uccase12 の「最適」の値**: ENOMOTO は 11507.4073〜11507.4120 を最適と報告するが、HiGHS の解 11507.4051 の方が良い
  (相対 1.7e-7〜6e-7)。2 回目の再スタートの「根で固定 + 前処理で実行不能」で終わっている。打ち切り値 11507.406 で 120 秒
  回しても、解も実行不能の証明も出ず判定できなかった。HiGHS の解を `ENOMOTO_MIP_START_FILE` で渡すと最初の前処理の後で
  「前処理後の問題で実行可能でない」と捨てられる (前処理が連続列を置き換えるので、この確かめ方では判定できない)。
  内部のどこかの相対 1e-6 程度の許容によるものか、再スタートの固定・前処理が解を落としているのかは未確認。
- uccase12 の比較は許容ギャップの違いが大きい。HiGHS (1e-4) と同じなら、試作 1 で ENOMOTO も 33 秒。rel_gap 0 では HiGHS も
  120 秒で解けず、ENOMOTO (試作 1) の 49 秒の方が速い。
- ns1116954 は FJ の種の運。HiGHS も種 0 以外では解けないので、「HiGHS が解ける問題」と数えるのは種 0 の当たりのため。
  試作 3 で 6 種中 5 種になるが、種 1 では FJ が 16 回で止められて外れる。
- 置き換え後の LP が 25 秒かかった理由 (`repair_basis` 後の基底) は推測。
- 残っている時間の無駄 (未対処): uccase12 の自明な解 4 秒 (固定して LP を 4 回)、1 ラウンド 4 秒の分離 (下界は 5e-6 しか動かない)、
  再スタート後の根の LP を基底なしで解き直す (6.9 秒)、ns1116954 の内点法の丸め 17 秒・カットの LP の時間切れ。打ち切り値付きの
  uccase12 では Feasibility Pump が 58.9 秒かかった。

## 7. 既定にする候補か

- `ENOMOTO_MIP_BG_CUTS_BASIS`: **候補**。裏のカットは既定で使っており、基底なしで解き直すのは単純な抜けに近い。40 問での確認が要る
  (neos-1456979・10teams の揺れを見る)。
- `ENOMOTO_MIP_ROOT_GAP_EXIT`: **候補** (軽い。根で下界が暫定解に届いたときしか動かない)。
- `ENOMOTO_MIP_FJ_FEAS_EXTEND`: 候補 (目的関数が全部 0 の問題でしか動かない。40 問には当たる問題がないと見るが確かめていない)。
- 許容ギャップ (既定 0、HiGHS・SCIP 1e-4) を揃えるかは方針の判断。ベンチマークの比較では揃えないと uccase12 型の問題で不公平。
