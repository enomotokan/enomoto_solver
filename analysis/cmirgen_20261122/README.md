**利用者の判断 (2026-11-22): `d` は閉じた (既定オフのまま)。`f` を P (58 問 × 種 1〜3) で確かめる (分担 6 本、§6 に集計)。**

aggrsel_20261121 の続き。根の下界の差のうち、neos-1582420 は SCIP の 1 行だけの cmir (集約なし) でも 89.87 に届き、当方は 89.06 だった。
当方の CMIR (src/mip/cuts.rs の `cmir_terms`) と SCIP 10.0 の `SCIPcutGenerationHeuristicCMIR` (cuts.c) を同じ項で並べ、差の場所を調べた。

## 0. 結論

**同じ項で比べると、差は 2 か所にあった。どちらも neos-1582420 の根の差の元ではなかった。**

1. **f0 の上限 (当方 0.995、SCIP の maxfrac 0.999)**
   - f0 は右辺 / δ の小数部。mc11 の 5000 行で、効き目の和が 206.7 → 353.4 になる (670 行で良く、悪い行なし)。p200x1188c は 2.67 → 3.49。
   - 例 (mc11): 係数 −212 の 0-1 の項と右辺 −1 の行は、δ = 212 で f0 = 0.9953 になる。当方は捨てて δ = 106 の効き目 0.240 のカットを作り、SCIP は効き目 0.445 のカットを作る。
2. **δ の候補**
   - SCIP の候補: 境界の内側にある整数の項の係数すべて、係数を全部整数にする倍率からの δ、最大の係数 + 1、1。
   - 当方の候補: 内側の係数を最大 8 個と、それぞれの 1/2・1/4・1/8。
   - 効くのは beasleyC3 (5000 行で 192.5 → 202.6、212 行で良い)。
3. **差がないところ**: 補数の反転の順 (境界からの距離の順)、f0 の下限 (0.005 と 0.05)、大きさの判定。
4. **境界・変数上下限の選び方**: 両者とも近い方を選ぶので同じ。整数の行の余り (スラック) を整数として扱うのも同じ。

**neos-1582420 の根の差 (当方 89.06、SCIP の 1 行だけの cmir 89.87) は、cmir の作り方の外にある。**

- 同じ項での効き目は、当方 1.221、SCIP の規則 1.226 (5000 行のうちカットが出るのは 18 行) とほぼ同じ。
- SCIP は暫定解があると、打ち切り値で抑えた目的の行からも集約を始める (objcmir)。ヒューリスティクスを切ると、SCIP の同じ回は 89.63 になる。これで約 0.23。
- SCIP の前処理の後の問題 (2407 列) を当方に解かせると 89.28。前処理は 0.22 だけ (当方の前処理も 2407 列にしている)。
- 残り約 0.35 の元は、この調査では分からない。

**試作 `ENOMOTO_MIP_CMIRGEN` (既定オフ、新しい閾値なし)**

- `f`: f0 の上限を SCIP の 0.999 にする。
  - 9 問・種 1〜3・4 スレッド・60 秒で 0.983 倍 (95% [0.890, 1.085])、解けた数は 27 / 27。
  - neos-1582420 0.76、p200x1188c 0.84 は良い。mc11 1.31 は悪い (根のループが 25 巡で止まり、第 2 段階に入らなくなる)。

  - 1.084 倍 (95% [0.943, 1.246])。nw04 が全回で 1.69 倍遅い (根で閉じなくなる) ため、勧めない。

## 2. SCIP の SCIPcutGenerationHeuristicCMIR (v10.0.0 の cuts.c) の手順と当方との違い

| 段 | SCIP | 当方 |
|---|---|---|
| 置き換え | 近い境界 (boundswitch 0.5)。連続列は近い変数上下限も使う (aggregation では vartypeusevbds = 2) | 同じ (同点なら項が消える方の変数上下限、HiGHS と同じ) |
| 行の余り | 整数の行の余りは整数の項 | 同じ |
| δ の候補 | 内側の整数の項の係数すべて (境界からの距離の順)、整数にする倍率 s からの 1/s と 1/(s⌊maxfrac/f⌋)、最大 + 1、1 | 内側の係数を最大 8 個 (項の順)、なければ最大の係数。それぞれの 1/2・1/4・1/8 |
| δ を割る | 最良の δ だけ 1/2・1/4・1/8 | 全候補で |
| f0 の範囲 | [0.05, 0.999]、(1/δ)/(1−f0) ≤ 1e6 | [0.005, 0.995]、|右辺/δ| ≤ 1e6 |
| 補数の反転 | 内側の整数の項を、境界からの距離の大きい順に全部 | 整数の項を順に最大 50 個 |
| 効き目 | 置き換えた空間の違反量 / ノルム | 同じ |

## 5. 置き場所と回し方

- コード: src/mip/cuts.rs。
  - `cmirgen`・`max_frac`・`scip_deltas`・`int_scalar`・`small_denom`: 試作。
  - `CMIRDUMP`: 診断。
- `cmp.py`: 同じ項で規則を比べる (dump/ は回せば作れる。下の書き出しのコマンド)。
- `cfg.py`: 設定 def・f・d・fd。
- `root.py`: 根だけを回す。結果は root.jsonl。
- `run.py`・`ci.py`・`shards_L.json`: 通しの計測。結果は res_L_s0.jsonl。
- `plan.py`・`shards_P.json`: 広い計測の分担表 (def 対 f)。回し方は `python run.py P K` (K = 0〜5)、集計は `python ci.py 60 def f res_P_s*.jsonl`。
- `fuzz.sh` (`CMIRGEN=f` で回す)・`fuzz_f.out`: 誤答の確かめと cargo test。
- 書き出しのコマンド (リポジトリの根から):
  `ENOMOTO_MIP_CMIRDUMP=300000 ENOMOTO_MIP_NODE_LIMIT=1 ENOMOTO_MIP_NO_RESTART=1 ENOMOTO_MIP_THREADS=1 python3 scripts/run_miplib_benchmark.py --worker-ours .miplib_cache/mc11.mps --time-limit 120 --threads 1 2>&1 >/dev/null | grep ^CMIRDUMP > analysis/cmirgen_20261122/dump/mc11.txt`
- presolved/ (SCIP の前処理の後の問題) は回して作るだけで、コミットしない。
