bench に使う環境変数: 既定 (`def`、`ENOMOTO_` なし) / `ebi` = `ENOMOTO_MIP_PRECHAIN=ebi` (PRECHAIN の形) /
`ebiR` = `ENOMOTO_MIP_PRECHAIN=ebiR` (RESTCHAIN、`R` は `r` を含む)。ほかに `ebir` = `ENOMOTO_MIP_PRECHAIN=ebir` (PRECHAIN の `r`)。

## 結論 (先に)

- `ebiR` (再スタートをまたいで FJ・Local-MIP を続ける) は、58 問・60 秒・4 スレッド・種 1・2 で既定に対し **SGM +0.7%
  (95% 区間 [−3.9%, +4.5%])、解けた 85 → 85、暫定解と下界の矛盾 0、時間上限の超過 0**。害は見えないが、解く時間への効き目も見えない。
  最初の暫定解が早い (1.22 → 0.89 秒) のは PRECHAIN の部分 (`e`) の効き目。
- 再スタートの起きる 49 回 (問題 × 種) でも解く時間は変わらない (シフト 1 の幾何平均 def 7.31・ebi 7.39・ebiR 7.41 秒)。再スタートの時点の
  暫定解は主の根のヒューリスティクス (RINS・根の被約費用のサブ MIP など) が見つけたものが多く、連鎖を続けても再スタートの打ち切り値・
  固定できる整数列の数はほとんど変わらない (固定の計 def 27430・ebiR 26197)。見立ての「早い暫定解 → 固定が増える → 再スタートが
  よく縮む」はこの 58 問ではほとんど働いていない。
- 途中で不具合を 2 つ見つけて直した (3.0): サブ MIP の前処理が連鎖をサブ MIP の問題に乗り換えさせていた (`r` にもある)、Local-MIP の
  lift move の繰り返しに上限がなく終わらないことがある (binkar10_1 で止まった)。後者は既定の Local-MIP にも入る直しだが、上限に当たら
  ない限り振る舞いは同じ。
- 取り込みの基準 (docs/backlog.md の冒頭): `ebiR` は (1) 区間の上限 +4.5% ≤ +5%、(2) 解けた回は減らない、(3) 両方の種で 10% 超遅い問題は
  misc07 (4.2/5.2 → 5.4/6.3 秒) の 1 問、(4) 誤答 0 (fuzz_tiny 400・mip_fuzz_vs_highs 300 は bad 0、cargo test 400 通過)・矛盾 0、
  (5) 時間上限の超過なし (メモリは測っていない。問題は読み取り専用で分け合う)。**基準はおおむね満たす** (misc07 の小さな遅れが気になる程度)。
  ただし効き目が見えないので、取り込む利点は「再スタートの多い難しい問題への備え」に限られる。`ebi` は解けた 85 → 81、揺れの大きい問題を
  除くと +2.5% [+0.7%, +5.1%] で、基準を満たさない。
- 次の手 (推測): 効くとすれば根が長く再スタートの後も暫定解が良くなり続ける難しい問題 (Mittelmann の 600 秒) だが、58 問で再スタートの
  打ち切り値が変わらない以上、優先度は低い。決定性 (手間で数える打ち切り) は作っていない。

## 4. `W`: 再スタートの判定の前に Local-MIP で固定を増やす (2026-11-11 に親の依頼で足した)

bench に使う環境変数: `W` = `ENOMOTO_MIP_PRECHAIN=W` (既定 + `W`) / `ebiRW` = `ENOMOTO_MIP_PRECHAIN=ebiRW`。

- 中身 (`Solver::restchain_w`): 根の終わりの被約費用による固定 (`root_redcost_fixing`) の直後 (目的のプロービング・`maybe_restart` の前、
  裏のカットの待ちの後) に、大域的な境界 (固定で締めた範囲) の上で Local-MIP を主の暫定解から回す。暫定解が範囲の外なら範囲に収めた点から
  目的の行だけ締めて探す (`seed_outside`)。秒は根までの時間の 0.1 倍、1 秒と時間上限の 0.02 倍まで (`ENOMOTO_T_MIP_PRECHAIN_W_FRAC`・
  `ENOMOTO_T_MIP_PRECHAIN_W_SECS`)。暫定解が良くなったら被約費用による固定をやり直し、増えた固定も再スタートの判定に入る。再スタートの
  後の根でも同じ位置で回る。連鎖のスレッドとは別に主のスレッドで回す (秒で打ち切るので決定的ではない)。
- 例 (p200x1188c、種 1): 1 回目の `W` (0.4 秒) で暫定解 15568 → 15078 (最適)、新たな固定 713 → 834 列。
- 計測は前の `def`・`ebiR` と同じソース (a3f25705 + 59400a6f の直し) に `W` だけを足したビルドで、`res58.jsonl` に足す (`jobsW.txt`)。
  fuzz_tiny 400・mip_fuzz_vs_highs 300 (`ebiRW`) は bad 0。

(結果は計測の後に書く)

## 1. 今の作り (事実、2026-11-11 にソースで確かめた)

- 再スタート (`Solver::maybe_restart`、`solver.rs`): 根の終わり (被約費用による固定・目的のプロービングの後、木に入る直前) と、木の中
  (早めの再スタート `early_restart_on`・`ENOMOTO_MIP_TREE_RESTART`) で判定する。新たに固定された整数列が整数列の 1% (初回)・2.5% (2 回目以降)
  以上なら、大域的な境界 (`dom.global_lo/up`) を列の境界にした問題 `newp` (`MipProblem::from_rows`、**列の数・番号は同じ**) を作り、
  カット・暫定解 (`RESTART_SOL`)・基底 (`RESTART_BASIS`・`RESTART_X`)・打ち切り値を渡して `solve_problem(&newp, ..)` を入れ子に呼ぶ
  (最大 4 回)。前処理も列の番号を保つので、再スタートの後の根の問題 (`self.p`) も同じ列の空間にある。
- 根の FJ・Local-MIP のスレッド (既定): 根の LP の前に `self.orig` (**最初の求解の問題**。再スタートで作り直さない) で FJ_P3 の問題を
  作ってから回し、根のカットのループの終わり (`join_fj_thread`) で止める。再スタートの後の根でも同じ `self.orig` の元の境界で時刻 0 から
  回り直す (`ENOMOTO_MIP_FJ_RESTART_BOUNDS` は境界だけ重ねる試作で、単独ではほぼ効かなかった)。
- PRECHAIN (`analysis/prechain_20261110.md`) の `e`・`b`・`i`: 前処理の途中で立てたスレッド (4 スレッドなら 3 本) を根で 1 本に減らして続ける。
  `r` (8141fb1a): 根のカットのループの終わりで止めず、再スタートの後の根で**スレッドがまだ生きていれば**、再スタートの前処理で縮んだ問題
  (`self.p`) に乗り換えさせる (再スタートの前処理の途中でも `refresh` で縮んだ問題に乗り換える)。解は列の番号が同じなので、固定された列を
  そろえて実行可能なら写す (`map_to`)。
- `r` の穴 (事実): スレッドの打ち切りは根に入ったときの `max(Local-MIP の秒 (0.1 × 時間上限、10 秒まで), FJ の秒)` (60 秒なら 6 秒、
  主に暫定解がなければ 15 秒まで)。根のカット・ヒューリスティクスがそれより長い問題では、再スタートの時点でスレッドは終わっていて、
  今までどおり `self.orig` で FJ のスレッドを立て直す。木の中の再スタートでも、木に入るときに止めているので同じ。

## 2. 作ったもの (`R`、既定では動かない)

`ENOMOTO_MIP_PRECHAIN` の値に `R` を含めると `r` も含むとして扱い、次を足す (`e`・`b`・`i`・`p`・`r` の振る舞いは変えない。最初の求解は
`ebir` と同じ種・同じ流れ)。PRECHAIN が先に push していた `r` の下書き (8141fb1a、コンパイルのみ・未実行) を消さずに土台にし、
`attach` に立て直しの分岐を足した。

1. **根の後も延ばす**: 根のカットのループの終わり (`join_fj_thread`) で、連鎖の打ち切りを求解の期限まで延ばす (`prechain::extend_to`)。
   木に入る直前 (`maybe_restart` が再スタートしないと決めた後) に止め、受け渡し箱に残った解を受け取る。再スタートすると、その前処理の
   間も古い問題で回り、縮んだ問題ができたら次の区切り (FJ 1 回・Local-MIP 0.2 秒) で乗り換える (`refresh`、PRECHAIN の部品)。
2. **再スタートで立て直す**: 再スタートの後の根 (`attach_prechain`) でスレッドが終わっていれば (木の中の再スタート、打ち切りに達した、
   前処理で立てなかった)、再スタートの前処理で縮んだ問題を根の問題 (版 0) として `ENOMOTO_T_MIP_PRECHAIN_ROOT_KEEP` (1) 本で立て直す
   (`prechain::spawn`、種に再スタートの回数を混ぜる)。打ち切りは今の根の FJ のスレッドと同じ。
3. **境界・暫定解の受け渡し**: 根の終わりの被約費用による固定 (`root_redcost_fixing`) の後にも `post_prechain` を呼び、締まった大域的な
   境界 (`b`、FJ の範囲だけ) と主の暫定解 (`i`、Local-MIP に inject) を渡す。再スタートの後の問題は大域的な境界を列の境界にしたものなので、
   乗り換えた後は被約費用による固定・再スタートで締まった境界がそのまま FJ・Local-MIP の範囲になる。
   - 正しさ: 打ち切り値で締めた範囲 (被約費用による固定) は今の暫定解を外しうる。乗り換えた後は Local-MIP の範囲も締まった問題の
     境界になるが、主の暫定解の inject は `to_sp` (`map_to`) で締まった問題に写せるものだけ (外れる解は inject しない) なので、範囲を破る
     出発点は持ち込まない。主に渡す解は根の問題で実行可能なものだけ (今までどおり主の `try_incumbent` も確かめる)。打ち切り値で締めた問題で
     見つかる解は打ち切り値より良い解だけなので、主の暫定解を失うことはない (主は自分の暫定解を持ち、再スタートでは `RESTART_SOL` で渡す)。
   - 乗り換えでは FJ の重み・Local-MIP の解の集まりは捨て、最良の解 (写せれば) と主の暫定解から出発し直す (PRECHAIN の作りのまま)。

### 作っていないもの

- **決定性** (`BG_CUTS_DETERM` の方針の、手間で数える打ち切り・決まった点だけの受け渡し): PRECHAIN と同じく秒で数え、主は根のカットの
  ループの各ラウンドなど決まった点で受け取るが、届く解はスレッドの進み具合で変わる (今の根の FJ のスレッドと同じ)。
- 前処理の重なりの後処理を順に持つ段: 前処理・再スタートが列の番号を保つので要らない (固定された列をそろえる写しで足りる)。
- 根で残すスレッドの数の作り直し (`ROOT_KEEP` は 1 のまま)。

### 推測 (確かめていない)

- 効くのは「根が長く (6 秒より長い)、再スタートが起き、再スタートの後も暫定解が良くなる」問題。再スタートの時点の暫定解が良いほど
  被約費用による固定が増え、次の再スタートの前処理がよく縮む。根が短い問題では `r` と変わらない。
- 害: 根の後も 1 本が回り続けるので、根のヒューリスティクス (サブ MIP は別スレッド) と CPU を取り合う (4 スレッド)。

## 3. 計測

ビルドは a3f25705 の作業木 (下の 2 つの直しを含む) で、58 問 × 種 1・2 × (`def`・`ebi`・`ebiR`)、60 秒・4 スレッド (`jobs58.txt`、`res58.jsonl`)。

### 3.0 最初の版の不具合 (直した。`res58_v1.jsonl`・`logs_v1/` は直す前の種 1)

最初の版 (9272abd9) の種 1 は `ebiR` が SGM +6.9% (区間 [−1.0%, +18.2%])、解けた 45 → 41 で、binkar10_1 が**止まって** 460 秒で
打ち切られた (`crash`)。gdb で見ると、主は木に入る前に連鎖を止めて待ち (`prechain::stop_current` → `Chain::finish` の join)、連鎖の
スレッドは `LocalMip::run` の中で回り続けていた。原因は 2 つ:

1. **サブ MIP の問題への乗り換え** (`r` にもある): 根の後も連鎖が生きているので、根のヒューリスティクスで主のスレッドが解くサブ MIP
   (RENS など) の前処理が `presolve_mip_depth` の連鎖の位置を通り、`refresh` がサブ MIP の問題 (列の数は同じ) を連鎖に渡していた
   (`submip` の引数はサブ MIP の前処理でも偽のことがある)。サブ MIP の前処理では呼ばないようにした (`PRESOLVE_IN_SUBMIP` を見る)。
2. **Local-MIP の lift move の繰り返しが終わらない**: `while s.lift_sweep(..) > 0 {}` には回数の上限も止める合図の確かめもなく、
   サブ MIP の問題では連続列が少しずつ動き続けて抜けなかった (10 回中 9 回で 1000 回を超えた)。1000 回の上限と止める合図の確かめを
   足した (`localmip.rs`、上限に当たらない限り振る舞いは同じ。既定・`ebi` の binkar10_1 では当たらなかった)。

直した後は binkar10_1 の `ebiR` は 5 回とも 9〜10 秒で最適、上限に当たる回 0。fuzz_tiny 400・mip_fuzz_vs_highs 300 は bad 0、
`cargo test --release --lib` (`ENOMOTO_MIP_PRECHAIN=ebiR`) は 400 件通過 (pyo3 のリンクに `RUSTFLAGS="-L /usr/local/lib -l python3.13"`
と別の `CARGO_TARGET_DIR` が要る)。
