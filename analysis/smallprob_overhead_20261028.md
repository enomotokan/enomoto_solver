## 2. 原因 (コードとログ)

### 2.1 プロービングの後に前処理をかけ直さない (neos8、事実)

- 前処理の流れ (`presolve_mip_depth`): 前処理 → LP による固定 (`lp_probe`) → プロービング (`probe`) → 同値な列の代入。
  プロービングが境界を締めても、`ENOMOTO_MIP_PROBE_REPRESOLVE` (既定では使わない) がなければ前処理をかけ直さない。
- neos8: 診断 `ENOMOTO_MIP_DEBUG_PROBE_PROGRESS` (この調査で追加) で見ると、**最初の 32 本のプロービング (CPU 0.32 秒) で 0-1 列 23035 本の
  うち 21379 本の境界が締まって固定**され、その後の 1264 本は含意を集めるだけ (CPU 9 秒、手間の上限 3e9 に当たるまで)。
  固定された列と行は消されず、46070 行・23039 列のまま根を解く (根で `global fixed integers 21568 of 23228`)。
  LP による固定もその前に同じ大きさで 4.9 秒。HiGHS の前処理は 6496 行・659 列 (2 回目の縮約で 1660 列)。
- `PROBE_REPRESOLVE=1` でかけ直すと 6774 行・1660 列になるが、最初のプロービングの 11 秒と LP による固定の 5 秒は残る (26.4 秒)。

### 2.2 根の並列のサブ MIP の時間と待ち方 (neos17・nu25-pr12・nubu、事実)

- 根のサブ MIP の時間の上限は `min(0.07 x 残り時間, 6 秒)` (`ENOMOTO_T_MIP_SUBMIP_TIME_FRAC`・`_MAX`)、60 秒の上限で約 4 秒。ノード上限 500。
  根に入るまで 1 秒の neos17 でも、根の被約費用・LP face・RENS のサブ MIP がそれぞれ 3.7 秒、続けて「RENS (more nodes)」3.8 秒、RINS 3.2 秒、
  再スタート後の RINS 3.3 秒を使う (計 14 秒で、最適解は見つからない。最適解は木が入ってすぐ 1.1 秒で見つけ、3 秒で証明)。
- 並列のサブ MIP の上限は 3 本 (4 スレッド)。4 本目を出すとき `join_submips(lim - 1)` で**いちばん古いもの**を待つ。
  nu25-pr12 (`ENOMOTO_MIP_SUBMIP_VERBOSE=1` のログ `logs/diag_subverb_nu25-pr12.log`): LP face のサブ MIP は始めて 0.2 秒で最適値 53905 を
  見つけ 0.7 秒で終わったが、主のスレッドは根の被約費用のサブ MIP (4.1 秒で時間切れ) を待ち、53905 を 3.3 秒後に受け取った。
  RENS のサブ MIP (14 行) も 0.03 秒で終わっていたのに「4.11s」と記録される (受け取った時刻)。
- どちらにしても根のヒューリスティクスの最後の `join_submips(0)` で一番遅いサブ MIP を待つので、受け取る順を変えるだけでは時間は縮まない。

### 2.3 再スタートで前のカットを捨てる (p200x1188c、事実)

- `solve_problem_inner` は再スタート前のカットのうち「前処理で新たに固定された列」を含むものを捨てる (代入された列の値は前処理後の境界から
  分からないため)。p200x1188c (固定費用のネットワーク) は再スタートで 0-1 列 764 本が 0 に固定され、その連続列 (x ≤ u y) も前処理で 0 に
  固定されるので **カット 65 本が全部捨てられる** (`0 cuts from before the restart put in the cut pool`)。再スタート後の根の LP は 13396 → 5679 に
  戻り、カットのループ (0.9 秒) をやり直し、カット後の下界も 13229 (前の 13388 より低い)。HiGHS は再スタート後も下界 11710 から続ける。
- 値の決まり方は後処理の手順で分かる: 代入 (`Sub`)・平行列の併合 (`ParallelCol`)・強制列の消去 (`Forcing`) の対象の列だけが後処理で値を書き換え
  られ、それ以外の固定された列の値は前処理後の境界のまま。

### 2.4 そのほか (事実、試作はしていない)

- **drayage**: 大きな M の行が 3159 行残る (HiGHS 686 行、`analysis/drayage_20261020.md` と同じ)。`PROBE_REPRESOLVE=1` で 686 行になるが、
  対称性の lex-leader の行が 799 → 1599 本に増え LP は 2311 行、通しは 6.6 → 5.9 秒・13.7 → 12.3 秒 (各 1 回) で決め手にならない。
  drayage-100-23 は根の LP の値が最適値で、根のカット 7 ラウンド (1.5 秒) は下界を動かさない。最適解は再スタート後の Feasibility Pump で出る
  (最初の根では Local-MIP の解 (差 6.5%) があるので暫定解なし用の Pump が回らない)。HiGHS は RENS の中のダイブ (H) で 0.8 秒。
  drayage-25-23 はクリークの判定が「使う」になると、カットのループを選択の比べ (0.4 秒) から全部やり直す (4.9 秒のうち 2.6 秒)。
- **hypothyroid-k1**: 内点法の丸めが失敗するまで 2.65 秒 (`IPM (cost) failed`)、背景のカットの待ち 1.15 秒、最適の証明は根の目的値の
  プロービング 7.25 秒。既存の試作 `ENOMOTO_MIP_EARLY_RENS=1` は -2851 を 1 秒で見つけ 32.7 → 26.9 秒、`+ ENOMOTO_MIP_EARLY_RENS_PROBE=1` で
  24.3 秒 (各 1 回)。暫定解が最適値でも根のカット (7 秒) とヒューリスティクスは全部回る。
- **neos-827175**: 根の LP を 2 回解く (LP による固定の中で 0.83 秒、クリーク拡張で行が変わり列の状態だけを引き継いだ根で 1.0 秒)。

## 3. 試作 (どれも既定では使わない)

- `ENOMOTO_MIP_PROBE_EARLY_REPRESOLVE` (`quick_probe_fixings`): LP による固定の前に、行の多い 0-1 列から 64 本 (`ENOMOTO_T_MIP_PROBE_EARLY_CANDS`)
  だけ `probe` と同じ規則でプロービングし (含意は集めない)、新たに固定された列が自由な列の 1 割 (`ENOMOTO_T_MIP_PROBE_EARLY_FRAC`) 以上なら
  その境界で前処理をかけ直す (LP による固定・プロービングは小さくなった問題で行う)。少なければ問題は変えない (64 本の手間だけ)。
  neos8: 64 本 0.71 秒で 21400 列を固定 → 6774 行・1660 列、LP による固定 0.19 秒、23.7 → 10.0 秒 (残りは小さい問題のプロービングと同値の
  代入の 3 巡 5.5 秒)。
- `ENOMOTO_MIP_RESTART_CUTS_FIXED`: 再スタートで、後処理が値を書き換えない固定された列を含むカットは残す。p200x1188c は 43 本残り、再スタートの
  周 0.92 → 0.47 秒 (1 回)。
- `ENOMOTO_MIP_ROOT_SUBMIP_REL=k`: 根 (外側の根と再スタート後の根) のサブ MIP の時間の上限を、最初の根のヒューリスティクスに入るまでの秒の
  k 倍 (最小 0.5 秒、`ENOMOTO_T_MIP_ROOT_SUBMIP_REL_MIN`) までにする。暫定解のあるときだけ。
- `ENOMOTO_MIP_SUBMIP_FIRST_DONE`: 並列のサブ MIP を終わった順に受け取る (空き待ちと最後のまとめ受け取りの両方)。
- 診断: `ENOMOTO_MIP_DEBUG_PROBE_PROGRESS` (プロービングの 16 候補ごとの経過)。
