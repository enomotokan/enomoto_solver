# CMIR の割る数 δ の候補を同時ディオファントス近似で作る (試作 `ENOMOTO_MIP_CMIRDELTA`) (2026-11-07)

bench に使う環境変数: 既定 (`def`) はなし。試作は `ENOMOTO_MIP_CMIRDELTA=1` (`cd`、gcd・連続分数・LLL の 3 つ)・`=g` (`cdg`、gcd だけ。
HiGHS の `integralScale` に当たる)・`=c` (`cdc`、連続分数だけ)・`=l` (`cdl`、LLL だけ)。どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_MIP_LOG=1`・
`ENOMOTO_T_MIP_SEED=回`。根だけの比べは `ENOMOTO_MIP_NODE_LIMIT=1`。上限の調整は `ENOMOTO_T_CMIRDELTA_K` (足す候補の数、既定 8)・
`_N` (使う列の数、既定 8)・`_QMAX` (倍率 q の上限、既定 64)・`_SECS` (全スレッドの合計の時間、既定 20 秒)。試作は既定では使わない。

## 結論

- **効く問題ははっきりある**: neos-3083819-nubu は 4 回とも 8.0 → 2.2 秒 (幾何平均、10 秒ずらし。根の下界 6.3038e6 → 6.3072e6、選ばれたカット 59 本のうち 25 本が新しい δ)。
  drayage-25-23 は既定の根の下界が 2 つの値 (100122 / 101283) に分かれて遅い回 (19・46 秒) が出るが、cd は 4 回とも 101283 に届いて 14.0 → 3.9 秒。
  p200x1188c 5.2 → 3.9 秒、qnet1 は根の下界が 4 回とも上がる (15752〜15904 → 16013)、3.5 → 3.1 秒。hypothyroid-k1 も 29.1 → 21.6 秒 (4/4) だが、
  根の下界はむしろ下がっており、新しい δ のカットは 1 本しか選ばれていない (探索の道筋が変わっただけと推測)。
- **58 問では差は揺れの範囲**: 2 回 (種 1・2) で SGM 15.50 → 15.61 (+0.7%、95% 区間 [−4.9%, +6.3%]、p=0.82)、解けた 86 → 84 (片方だけ解けた回: def だけ 3・cd だけ 1、p=0.63)。
  そろった差は neos-3083819-nubu (−0.42×2) だけ。根の下界のずれ (log10) は平均 −0.076 (p=0.23)。
- **代わりに根が遅くなる**: 根だけの比べで根の時間 ×1.067 (同じ回の cdg は ×1.013 なので、δ の候補を足す手間で 5% 前後)。δ の候補を作る時間は全スレッドの合計で
  最大 blp-ar98 の 11.8 秒、58 問の合計 47 秒。候補 1 つあたりの効き目の評価 (行の長さに比例) も増える。
- **作り方では連続分数が主**: 新しい δ が既存の候補より効き目が大きかった 36683 回のうち、連続分数 27212・LLL 8811・gcd 660。効く問題の内訳では、
  neos-3083819-nubu は連続分数 (3.2 秒) と LLL (4.5 秒) の両方が効き、両方 (2.2 秒) が最良。drayage-25-23・hypothyroid-k1・qnet1 は連続分数だけで同じ効き目、
  LLL だけでは出ない。HiGHS 型の gcd (`cdg`) だけでは根の下界はほぼ変わらない (平均 +0.008)。
- **新しい δ のカットは選ばれにくい**: 根で選ばれたカット 25629 本のうち新しい δ から来たものは 1094 本 (4.3%)、その効き目の平均 0.027 は全体 0.138 より小さい。
  選ばれる本数が多いのは p200x1188c (613/3740)・h80x6320d (147/5421)・sp150x300d (67/853)・blp-ar98 (37/545)・supportcase26 (37/588)・neos-3083819-nubu (25/59)。
- 誤答の検査は全部 0 (fuzz_tiny は既定でも出る前からの 13 問だけ)。`cargo test --release --lib` は既定・`ENOMOTO_MIP_CMIRDELTA=1` とも 368 件が通る。
- **既定にはしない**。58 問の平均が動かず根が少し遅くなる。次の一手は「δ の候補を常に足す」ではなく、(1) 係数がそろっていない行 (既存の δ で端数が散らばる行) だけで
  連続分数の候補を足す、(2) 足す数を 2〜3 に減らす、の 2 つで根の時間を戻せるかを見ること (4 章)。

## 1. 今の δ の選び方 (事実、`src/mip/cuts.rs`)

- 既定 (`cmir_terms`): 置き換えた行で、LP 値が境界の内側にある整数列の係数の絶対値 |a_j| (重複を除き最大 8 個) と、その 1/2・1/4・1/8 を候補にし、
  効き目 (y の空間での違反量 / 係数のノルム) が最大の δ を選ぶ。内側の列がなければ |a_j| の最大。`ENOMOTO_MIP_CMIR_DELTA1` で δ = 1 も足す (既定では足さない)。
  δ を決めた後に補変数化の向きを 1 つずつ反転して効き目が上がるか試す (Marchand–Wolsey 2001 の CMIR と同じ手順)。
- `ENOMOTO_MIP_SEP_FAST`・`ENOMOTO_MIP_CMIR_DELTAS_HIGHS` では `cmir_terms_fast` (評価を前計算で速くしたもの。HIGHS は 1/2・1/4・1/8 を最良の δ だけで試す)。
  `ENOMOTO_MIP_CMIR_SEARCH` は log δ 上の局所探索 (40 問で悪化して既定にしていない)。
- HiGHS 1.11 の `HighsCutGeneration::cmirCutGenerationHeuristic` (ソースを読んだ): 整数列で LP 値 > feastol のものの |a_j| を全部 (数の上限なし、|a_j| <= 1e-4 は除く)、
  **連続の項がなく候補が 2 つ以上なら `HighsIntegers::integralScale` (連続分数で分母を出し、すべての係数を整数にする最小の倍率 s) から δ = 1/s** (s <= 1e4 で、
  右辺の端数 f0 が 0.005〜0.995 のとき)、min(1, 初めの尺度) と max|a_j| + min(1, 初めの尺度) を候補にし、最良の δ の 2・4・8 倍も試す。
  つまり HiGHS も「係数を同時に整数にする倍率」を使うが、**すべてを正確に整数にする場合 (gcd) だけ**で、ほぼ整数にする近似は使わない。
- ENOMOTO の既定にはこの gcd の候補がない。今回の `g` がそれに当たる (連続の項があっても使う点は HiGHS と違う)。

## 2. 試作の中身 (`src/mip/cmirdelta.rs`)

基準の係数 r (LP 値が境界の内側の整数列の係数、最大 2 つ) をとり、ほかの整数列の α_j = |a_j| / r (内側の列を先に、係数の大きい順に最大 N = 8 個) に対して、
q α_j が多くの j で同時にほぼ整数になる正の整数 q を探し、δ = r / q を候補に足す (r / δ = q は整数、a_j / δ = q α_j はほぼ整数)。

- `g` (gcd): すべての α_j を 1e-9 の幅で整数にする最小の q (各 α_j の連続分数の分母を掛けていく、q <= 1e4、溢れは i64 の checked で検査)。HiGHS の integralScale と同じ考え。
- `c` (連続分数): α_j (最初の 4 列) の連続分数の近似分数の分母 q (2 <= q <= 64)。r と a_j の 2 列を同時に整数にする。
- `l` (LLL): 格子 {(q ε, q α_1 − p_1, …, q α_n − p_n)} (ε = 0.25/64) の基底を浮動小数点の LLL (Lenstra–Lenstra–Lovász 1982、δ_L = 0.75、Gram–Schmidt は
  Cohen 1993 の入れ替えの更新式) で縮約し、縮約した基底の各ベクトルの q を使う (Lagarias 1985 の同時近似の作り方)。基底の整数の変換行列は i64 で溢れを検査して持ち
  (成分が 2^40 を超えたら諦める)、q は変換行列から正確に取る。q の検算は元の α_j から q α_j の端数を計算し直し、端数 0.05 以内の列が 2 つ以上あるものだけ使う。
  入れ替えは (列の数 + 1) の 20 倍まで。
- 候補は既存の候補と 1e-9 の幅で重ならないものを最大 K = 8 個。効き目の評価と δ の選び方は既存と同じ (新しい候補が勝てばそれを使う)。全体の時間の上限は
  全スレッドの合計 20 秒 (超えたら作らない。58 問の根では最大 11.8 秒で、上限には当たっていない)。
- 診断: 新しい δ が勝った回数・作り方の内訳、その δ で作ったカット (置き換えを戻した生のカット) の指紋を覚え、`finish_cut` を通った候補・根で選ばれたカットを数え、
  根のカットのループの終わりに `SEP cmirdelta: ...` を出す (累計。全スレッド・裏のカットのループを含み、サブ MIP の選択は数えない)。指紋は係数と右辺のビット列なので、
  後で係数が書き換わったカット (クリークの拡張など) は数え漏れる。
- 初めの版は、長い行で係数の重複を除くループが列数の 2 乗になっていた (neos-960392 で 1 回 150 μs、根 40 → 53 秒)。使う数が集まったら止めるよう直し、根の比べは
  直した版でやり直した (前の版の結果は `cmirdelta_20261107/root58_v1.jsonl`)。

## 4. 次の一手 (推測を含む)

1. **足す場面を絞る**: 既存の候補の最良の効き目が小さい行 (または既存の δ で整数列の端数の散らばりが大きい行) だけで連続分数の候補を足す。exp-1-500-5-5 のように
   候補の評価が数百万回ある問題で、ほぼ選ばれない評価を減らす。足す数 K も 8 → 2〜3 で効く問題の効き目が残るか (`ENOMOTO_T_CMIRDELTA_K`) を見る。
2. **連続分数を主にする**: 効く問題の多くは連続分数だけで足りる。LLL は neos-3083819-nubu で上乗せがあるだけなので、列が多く連続分数で足りないときだけにする。
3. HiGHS 型の gcd は ENOMOTO の既定にない候補だが、単独では根の下界をほぼ変えない (`cdg`)。入れるなら 1 と一緒に。
4. 固定費の網の問題 (p200x1188c・sp150x300d・qnet1) で HiGHS が根を閉じる仕組みは δ ではなさそう (推測)。集約の側 (`analysis/mushroom_cuts_20261106.md` の流れ) で見る。
