- **雑音水準** `noise_r = C · eps · sqrt(w_r) · max(‖b‖∞, ‖x_B‖∞, 1)` (C = 10〜100、eps = 2.2e-16)。

  通常時 (`sqrt(w_r) ≤ 1e5`) は `noise_r ≤ 1e-7` 程度で既存の判定を変えない (Netlib は `sqrt(w_r)` が 1e9 を超えない限り経路不変。
  要確認: 93 問の `max sqrt(w)` を一度計測して閾値を決める)。
- 行 r を「実行不能」とみなす条件を `dev > max(現行の判定, noise_r)` にする (chuzr の選択、`Eligible = ∅` の結論、BFRT 到達判定)。
  条件を満たさない行は `noise_feasible`/タブー扱いで外す (既存の 3195-3203 と同じ処理)。
- **悪条件モードの引き金**: `max_i sqrt(w_i) > 1e8` (2,000 反復ごとに O(m) で確認しても十分安い) または数値要因の再分解が
  直近 100 反復に 3 回以上。モードでは (i) 次の再分解で Markowitz 閾値 0.5、(ii) 比率テストで `|alpha_j| < 1e-3 · noise_r/ scale` 級の
  候補を除外 (前回の `ALPHA_NOISE_REL` は行の重みだけで判定して 1e-9 で壊れた; 逸脱の雑音判定と組にすれば除外は雑音行にしか掛からない)、
  (iii) 重み `w_r > W_MAX` (1e20) の行は逸脱が本物でも修復 (行のスラックを基底に入れる、§5 M7) を優先。
- 雑音ピボットは PRICE/FTRAN 照合 (`pivot_values_agree`) では検出できない (e2、§2.5)。`update_count == 0` のとき照合を省く現状の
  設計は、この型には無関係 (照合を掛けても通る)。

読み (§5 の優先順位への反映):
1. M1 (行の雑音判定) は必要条件だが十分ではない。**M1' として比率テストにピボットの雑音判定** `|alpha_j| ≤ C·eps·sqrt(w_r)·‖a_j‖∞`
   (`‖a_j‖∞` は列ノルムを 1 回前計算) を追加し、候補が全滅した行は `stuck_row_taboo` と同じ扱い (3324-3340) にする。
   これが致命ピボット 7 件 (alpha 1e-9〜2.8e-9、sqrt(w_r) 2.6e14〜3.1e18) をすべて弾く。
2. 修復 (M4) は「一度従属になった基底」を健全にはできない (r6/r7/r9: 修復のたびに再特異、`d` の破壊、再分解ループ)。
   修復後に **DSE 重みを再計算し (`from_basis`)、`sqrt(w) > 1e10` の行のスラックを続けて基底に入れる** (M7) までやらないと安定しない。
   irish 型では M7 が本命で、M4 は M7 の実装手段 (行のスラックを基底に入れる操作) と兼ねられる。
3. 誤 `Infeasible` は主ループ外 (polish/finish) からも出る。M2 のガードは polish 側の判定 (5356-5392) にも入れる。
4. pilot87@1e-3 (LU 不安定型) は M5 (閾値引き上げの既定 on) だけで解決。
