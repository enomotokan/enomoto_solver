# HiGHS 風のサブ MIP (hs) のどの文字が遅くするか (2026-10-31)

`analysis/halve_submip_20261030.md` の hs (`ENOMOTO_MIP_SUBMIP_HIGHS=-s`。`s`・`q` 以外の `p c g t i h f` を全部入れる) と hs_pi0_bgw が、
binkar10_1・swath1・dcmulti・mik-250-20-75-4 を回をまたいで遅くする理由を調べた。4 スレッド・60 秒、ソルバーは同時に 1 つだけ (4 コアの機械)。
台本・ログは `diag_hsletters_20261031/` (`run.py` 計測、`summ.py` 表 (`summ.txt`)、`logstat.py` ログの集計)。

## 1. 文字の切り分け (hs から 1 文字ずつ抜く、各 2 回)

`hs-x` は `ENOMOTO_MIP_SUBMIP_HIGHS=-sx` (hs から x を抜く)。秒、全部最適。

| swath1 | 22.7・25.2 | 32.8・32.5 | 31.4・29.2 | 27.0・26.1 | 32.2・31.0 | 23.7・31.8 | 27.5・22.9 | 30.5・30.1 | 40.8・39.8 |

- 回の間の揺れは小さい (hs-t の swath1・hs-i の binkar10_1 を除いて ±1 秒ほど)。2 回で足りるとした。
- 1 文字に決まらない。binkar10_1 は `h` (サブ MIP の中の RENS)、dcmulti は `c` (サブ MIP の根のカット)、mik は `c` (と `h`)。
  swath1 は 1 文字では戻らず、`c`・`t`・`i` が少しずつ効く。`p`・`g` はどの問題でも関係ない。`f` は抜くとかえって遅くなる (swath1・mik)。
- 得の問題 (各 1 回): h80x6320d は hs 31.3 秒 → hs-c 40.0・hs-h 40.7・hs-t 24.2。**得も `c`・`h` から来る** (損と同じ文字)。
  qiu (hs 22.2、def 50.2) と nu25-pr12 (hs 4.1、def 6.5) は `c`・`h`・`t` を抜いても得が残る (この 3 文字以外から来る)。

損の問題はどれも、**根のサブ MIP にかかる時間** (外側から出したサブ MIP の時間の和) が増えている。解を見つけるのが遅れたのでも、前処理が重いのでもない。

`ENOMOTO_MIP_SUBMIP_VERBOSE=1` でサブ MIP の中も見た (`verbose_binkar10_1_hs.log`・`verbose_dcmulti_hs.log`)。

- **1 本が重い**: hs のサブ MIP (深さ 1) は次の 3 つが重なって重い。
  - `c`: 根のカットを 25 ラウンド回す (dcmulti では 1 本 0.2〜0.3 秒、ラウンドごとの伸びは小さいが 1e-4 を超えるので停滞と数えられない)。
  - `h`: 打ち切り値のあるサブ MIP の中で旧来の RENS のサブ MIP (深さ 2) を回す。binkar10_1 では 0.45〜0.52 秒で、さらに「RENS (more nodes)」(ノード 4 倍) のやり直しが 0.39〜0.45 秒かかる。
  - 深さ 2 のサブ MIP にも `c` が効いて、そこでも 25 ラウンド回す。
  - binkar10_1 の深さ 1 の RENS のサブ MIP (50 ノード) は def の 0.4 秒から 1.6〜3 秒になる。
- **良い解 → 再スタートの繰り返し**: 重い分、深さ 1 のサブ MIP は良い解を返す (binkar10_1 の根: hs 6763・6751、def 7038・6948)。
  被約費用で固定される整数列が出て (初回は 1 本でも) 再スタートし、**再スタート後の根でも同じ重いサブ MIP を回し直す**。
  - binkar10_1 は最適値 6742.2 に再スタート 1 回目の根 (4.5 秒) で届くが、その後も 2 回再スタートし、根のヒューリスティクスに 4.3・9.3 秒使う。
  - swath1・h80x6320d・mik も、再スタート後の根のヒューリスティクスが def の 2〜4 倍。
- **得の出どころは最初の根**: h80x6320d は、hs だと最初の根の LP face のサブ MIP が 7.1 秒で最適解 6382.1 を出す (def は最初の根で 6666.1、最適解は再スタート 1 回目の後)。
  その後の根のヒューリスティクス (15 秒まで) と再スタート後の根 (7.6 秒) は、解を良くしていない。
- `t` (根のサブ MIP の時間を残り全部にする) は、swath1 でサブ MIP をノード上限まで回させる (ノードの和 def 55 → hs 679)。

## 3. 手当ての試作 `ENOMOTO_MIP_SUBMIP_HIGHS_TRIM` (既定では使わない)

`heuristics.rs` `hs_trim_off`。サブ MIP を作るときに条件に当たれば、そのサブ MIP (と中の入れ子) を `ENOMOTO_MIP_SUBMIP_HIGHS` の形にせず既定の形で解く
(スレッドごとの印 `SUBMIP_HS_OFF` を立て、`submip_highs` が偽を返す。外側で決める `t`・`g`・`i` も使わない)。

| 文字 | 対象 |
|---|---|
| `r` | 外側の求解の再スタート後の根で作るサブ MIP |
| `d` | 深さ 2 以上のサブ MIP (サブ MIP の中で作るもの) |
| どちらも含まない値 (`1` など) | 両方 |

1 回目は 3 つの形 (hs_trim・hs_trim_r・hs_trim_d) を 8 問で試し、hs_trim_r だけ 2 回目も測った。hs_pi0_bgw (既定にする候補) にも `r` を足して 2 回測った。秒、T は時間切れ。

| 問題 | def | hs | hs_trim (rd) | **hs_trim_r** | hs_trim_d | hs_pi0_bgw | **hs_pi0_bgw_r** |
|---|---|---|---|---|---|---|---|
| binkar10_1 | 5.9・5.5 | 25.5・20.8 | 11.6 | **10.5・10.2** | 23.3 | 9.5・9.1 | **6.5・5.9** |
| swath1 | 22.7・25.2 | 32.8・32.5 | 25.6 | **23.9・23.1** | 32.9 | 31.4・33.1 | **21.4・20.0** |
| dcmulti | 0.8・0.8 | 2.4・2.4 | 2.3 | 2.7・2.2 | 2.1 | 2.2・2.2 | 2.2・2.2 |
| mik-250-20-75-4 | 6.0・6.3 | 8.2・8.2 | 6.6 | **5.7・5.5** | 9.8 | 7.4・6.7 | **4.4・4.3** |
| h80x6320d | 34.4・45.0 | 31.3・30.2 | 37.8 | **26.9・26.0** | 40.7 | 23.3・23.5 | **20.8・22.2** |

- **`r` が効く**:
  - 損の 4 問のうち、再スタートが起きる 3 問は、hs を def 並みかそれより速くする。swath1 は 33 → 23 秒、mik は 8.2 → 5.6 秒。binkar10_1 は 23 → 10 秒で、def (5.7) との差は半分以下になった。
  - hs_pi0_bgw に足すと、binkar10_1・swath1・mik は 2 回とも def 以下になる。
  - 得の 4 問の得は全部残る。h80x6320d は hs より速い (31 → 26 秒、hs_pi0_bgw 23 → 21 秒)。
  - ログでの確かめ: 再スタート後の根のヒューリスティクスが def と同じ程度に戻る (swath1 12.4 + 7.8 → 4.1 + 2.1 秒、binkar10_1 4.5 + 4.3 + 9.3 → 2.2 + 1.5 秒、
    h80x6320d 7.6 → 3.5 秒)。最初の根 (得の出どころ) は変わらない。binkar10_1 は再スタートが 3 → 2 回になる。
- `d` は得を消す (qiu 22 → 51 秒・時間切れ、h80x6320d 31 → 41 秒)。qiu・h80x6320d の得には、深さ 2 のサブ MIP も hs の形であることが要る。
- **dcmulti は直らない** (2.2〜2.7 秒)。再スタートが起きず、損は最初の根で出ている: hs は 0.93 秒で最適解を見つけるが、その後の根の RINS のサブ MIP (`c` の 25 ラウンドと中の RENS) が
  0.9 秒走る。差は 1.5 秒ほど。
- misc07 はどの設定でも再スタートが起きないので、`r` は何も変えない。hs_pi0_bgw (5.3・7.1) と hs_pi0_bgw_r (11.3・9.7) の差は揺れ (def も 9.4・14.7 秒、過去の計測では 9〜35 秒)。
- 最適値の食い違いはない。`cargo test --release --lib` は 330 passed。

## 判断と次の手

- hs の損の主な仕組みは「`c`・`h` でサブ MIP 1 本が重い」×「良い解で再スタートが増え、再スタート後の根でも重いサブ MIP を回し直す」。
  得は最初の根の重いサブ MIP から来るので、文字を抜くのでなく、**再スタート後の根だけ既定の形に戻す (`TRIM=r`)** のがよい。
- hs_pi0_bgw + `ENOMOTO_MIP_SUBMIP_HIGHS_TRIM=r` を 58 問 (bench6 と同じ組) で 2 回確かめる。8 問ではどれも損がない。
- dcmulti 型 (再スタートなし・最適解の後の根の RINS) の残り 1.5 秒は、`c` のサブ MIP のカットのループの止め方 (伸びの小さいラウンドを停滞と数える) で詰められるかもしれない (未試作)。
