# beavma の誤った最適 (383738.6、最適値 383285) (2026-10-20)

- 発端: d492cc5 の newdef の計測 (inv/bench-newdef2-20261020、4 スレッド・60 秒 r1) で beavma が「最適 383738.6」と返り、目的値が一致しなかった。同じ組の olddef と、ほかの 35 回の計測では一致。
- 再現: d492cc5 のビルドで 4 スレッドの beavma を続けて解くと 30 回中 8 回 (並べて負荷をかけると 240 回中 2 回)。`ENOMOTO_MIP_NO_PROBE_EQUIV` では 130 回中 0 回。1 スレッドでは 20 回中 0 回。3b35332 以降のビルドでは 510 回中 0 回 (再スタートの経過が変わり、下の形の問題に当たらないだけで、欠陥は残っていた)。
- 経過: 2 回目の再スタートの後の問題 (前処理で 242 行・138 列) の根の LP が最適値 (383285) に等しいのに、木の最初のノードで探索が終わり、1 回目の解 383738.6 を最適として返していた。再スタートの問題を MPS に書き出すと (診断用に一時的に足したもの)、前処理の前も後も HiGHS では 383285 で、前処理は正しい。こちらは前処理後の問題を単独で解いても (1 スレッドでも、PROBE_EQUIV・対称性なしでも) 「実行不能」と返し、`ENOMOTO_MIP_NO_CUTS` のときだけ正しい。
- 原因: ノードの LP 解が許容誤差 (1e-6) の中で整数 (`fractional` が空) のとき、`try_lp_solution` で暫定解を試し、結果に関係なくノードを捨てていた。この問題では big-M の行 `x17 - 14203 y212 <= 0` で LP が `y212 = 1.06e-10`、`x17 = 1.5e-6` を返し、y212 を 0 に丸めると行が 1.5e-6 破れるので暫定解として捨てられ (整数を固定して連続変数を解き直しても実行不能)、そのままノードも捨てていた。カットで根の LP 解がこの形になったときに起きる (カットなしでは LP 解が別の頂点)。PROBE_EQUIV は再スタートの後の問題の形を変えてこの頂点に当たりやすくしていただけ。
- 修正 (src/mip/solver.rs、ノードの LP の後): 暫定解として採れず、整数列を丸めた解が行に反するときは、ノードを捨てずに、整数からのずれが最大の (固定されていない) 整数列で分枝する (ここでは y212: y212 = 0 の子と 1 の子)。丸めた解が実行可能で暫定解より良くないだけなら、これまでどおり捨てる。
- 確認: 書き出した問題は 1・4 スレッドとも 383285 (154174.3 + 定数 229110.7)。d492cc5 に同じ修正を当てて beavma を 100 回続けて解くと誤りは 0 回 (修正前は 30 回中 8 回)。cargo test --release --lib 308 件通過。
