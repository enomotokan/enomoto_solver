## 1. 結論

事実:

1. **根のカットのループを止めているのは、主に根のカット全体の時間の上限 (時間上限の 10%)。ラウンド 1 の LP の時間切れは、それに重なる 2 つ目の理由。**
   - 根のカット全体の上限: `ENOMOTO_T_MIP_CUT_TIME_FRAC` (0.1) × 残りの時間上限 = 5.6 秒。主のスレッドの CPU 時間で測る。
     今回足したログ (`loop stopped`) では、ループの始めから数えていた。
   - 1 回の LP の上限: `ENOMOTO_T_MIP_CUT_LP_TIME_FRAC` (0.02) × 60 秒 = 1.2 秒 (最低 1 秒)。
     上限で止まると、そのラウンドのカットを外して LP を解き直す。
   - ラウンド 0 は 1 回で約 3.3 秒かかる (`ENOMOTO_MIP_DEBUG_SEPPROF`)。
     - 内訳の 2.3 秒は「面の頂点での分離」の LP 2 本 (`int2`)。どちらも時間切れか、使われないまま (採用 0 本)。
     - 分離そのものは 0.4 秒。カットの LP は 0.6〜0.9 秒。
   - ラウンド 1 の LP:
     - 行 10752 → 11046 (カット 294 本、平均 3 非零)、列 6003。
     - 解けた回は 1591〜1923 反復 (約 1.1〜1.5 秒)。1 反復は約 0.7 ms。
     - 1.2 秒の上限のすぐ近くにあるので、回によって時間切れになる。今回の既定・mixoc の 7 回中 5 回が時間切れ (mixoc のラウンド 0 の時間切れ 2 回も含む)。
   - どちらの場合も、ラウンド 2 の始めで全体の上限 5.6 秒を超えて止まる (`cap clock 6.98s of 5.59s` など)。
     **LP が解けた回でも 2 ラウンドで終わる** (既定 `k_def_2`・`pbdef_1`: 48583 → 48634)。
2. **上限を緩めると、カットは 10〜16 ラウンド回り、根の下界は 48924〜48965 まで上がる。** 診断の 1 回ずつ:

   | 設定 | ラウンド | 根のカットの後 | ループの終わり |
   |---|---|---|---|
   | 既定 | 1〜2 | 48587〜48634 | 13〜15 秒 |
   | 面の分離なし + 全体 0.6 + LP 0.1 + 100 ラウンド (`pbwide`) | 16 (うち 2 回は LP 時間切れ) | 48965 | 41 秒 |
   | 面の分離なし + 全体 0.4 + LP 0.05 + `CUT_DSE_EXACT` (`pbc1`) | 11 | 48817 (ラウンド 7〜10 は動かない) | 31 秒 |
   | 同じで全体 0.25 (`pbc2`) | 7 | 48800 | 22 秒 |
   | 既存の `FACE_ADAPT` / `CUT_EXTEND` / 両方 / + `CUT_DSE_EXACT` | 1〜2 | 48587〜48634 | — |

   - 既存の試作だけでは効かない。`CUT_EXTEND` は 1.2 秒の LP を 3 回続けても終わらない回があり、全体の上限も延びない。
   - `pbwide` では、1 本の LP が 6 秒の上限を超えるラウンドが 2 回あった (前の調査 r5 の「ときどき 5000〜11000 反復」と同じ)。
   - `CUT_DSE_EXACT` (出発の基底で DSE の重みを厳密に計算し直す) を付けると、この時間切れは消えた。代わりに 1 ラウンドが 2.4 秒に延びた。
3. **HiGHS との比較** (この機械の 1 回):
   - 前処理後 8861 × 4608、根の LP 47410.8 (6633 反復、4.7 秒)。
   - 10.2 秒にカットで 49324 (LP の行 375 本、プール 2037 本、分離の LP 計 10447 反復)。
   - 14.5 秒にサブ MIP (`L`) で 49324、1 ノードで最適。
   - ENOMOTO は前処理後の根の LP が 48583 と HiGHS より 1170 高い。それでも 16 ラウンド・約 25000 反復で 48965 までしか上がらない。
     **1 ラウンドあたりの伸びが小さい** (ENOMOTO +20〜+60、HiGHS は 13 ラウンドで +1900)。
   - ENOMOTO のカットは平均 3 非零と短い。ラウンド 0 の候補の内訳 (`SEPPROF`) は、行 1044 本 → 採用 90 本、
     zerohalf 100 → 6.5、path (HiGHS 流) 934 → 40.5、tableau 2543 → 57。
   - HiGHS のログにはカットの種類の内訳が出ない。HiGHS の分離器 (`HighsSeparation`) は 5 種類: implied bound、
     クリーク、tableau、path aggregation (CMIR) と mod-k。ENOMOTO にも同じ種類の分離器がある。
     種類ごとの本数は比べられていない。
4. **手当て `ENOMOTO_MIP_CUT_STRETCH` (試作、既定は不変、§4)** で、6 組 (既定・x1・mixoc・mixoc + x2 と ST の組) の 2 回とも、
   根の下界が上がった (§2)。
   - 既定 → 既定 + ST: 60 秒の下界 48587・48688 → **48957・48929**。暫定解は 51029 のまま。
   - mixoc → mixoc + ST: 48774・48587 → **49041・49216**。暫定解は 49724・50826 → 50826・50425 (向きはそろわない)。
   - mixoc + ST + x2: 下界 49266・48782、暫定解 **49524・49524** (今回の最良。最適は 49324、ギャップ 0.5%)。
   - 根のカットのループは 13〜15 秒 → 19〜38 秒 (`MIP:` の時刻) で終わる。5〜14 ラウンド。
   - 60 秒では 1 回も最適を証明していない (HiGHS は 14.5 秒で最適)。
5. **副作用** (各 1 回、§3):
   - neos-911970・roll3000 では延長が働かず、根は同じ。
   - mzzv42z では根のカットが 6.9 → 9.7 秒に延びた。根の下界は −21071 → −20877 と良くなり、60 秒の暫定解は −20100 → −20390 (揺れの範囲)。
6. 目的値の不一致 (HiGHS の最適値と違う「最適」) は出ていない。最適と報告したのは neos-911970 の 54.76 だけで、これは既知の最適値。

推測:

- 49524 (mixoc + ST + x2 の 2 回とも) は、根のヒューリスティクスの後 (24〜31 秒) に FJ のスレッド (Local-MIP) から来た。
  x2 の延長は根のカットのループの終わりで止まる。そのため ST でループが延びた分、Local-MIP が長く回れたとみる。
  ST が LP の側で直接効いたのではない。
- 下界を 49324 まで上げるには、1 ラウンドの伸びを HiGHS 並みにする必要がある (カットの選び方・種類)。上限を緩めるだけでは、
  60 秒の中では 49000〜49270 で頭打ちになる。
- 回ごとの揺れの主な出どころは、ときどき出る長い LP (4882 反復などで延長の予算を使い切る。`k_mxstx2_2` は 5 ラウンドで 48782)。

## 5. 既定にする候補か

- **今のままでは候補にしない。親の計測に入れるなら、mixoc + x2 と組み合わせた形で。**
- 理由:
  - 根の下界は 2 回とも上がる (+250〜+630)。それでも physiciansched6-2 は 60 秒で解けないので、解けた数は変わらない見込み。
  - 根のカットのループが長くなる問題がほかにもある (mzzv42z +2.8 秒)。
    40 問 + 16 問で根の時間が延びる問題の損得を見る必要がある。
  - 暫定解の改善 (49524) は、x2 の延長が長く回れることによる見込み。ST そのものの効果とは分けて見る必要がある。

## 6. 確かでない点・次の手

- 1 ラウンドの伸びが HiGHS より 1 桁小さい理由は、見ていない。
  - 次の手は、カットの種類ごとに LP 解に効いた本数 (双対値が非零) を数え、HiGHS の前処理後の問題 (r3 で 6 ラウンドで 49324 に届いた) と比べること。
- 面の頂点の分離 (`int2`) は、この問題では 1 ラウンド 2.3 秒を使って採用 0 本。
  - 根の始めの数ラウンドで採用がないときに止める既定の規則があれば、ST がなくても 1〜2 ラウンド多く回る。
  - ただし `FACE_ADAPT` 単独では全体の上限に当たって効かなかった (`pbfa`: 2 ラウンドで 48634)。
- 長い LP (4882 反復など) の原因は、r5 から持ち越し。
- 返り値の `root_bound` が、根のカットの後の値で書き直されない回がある (`pbwide`: 48583 のまま、`best_bound` は 48965)。
  この表では、根の下界はログの `Root cuts` の行から取った。
