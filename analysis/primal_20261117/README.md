## 4. 差の元のまとめ

1. **根の RENS の予算と止め方** (tbfp): HiGHS は暫定解がない間の根の RENS を節点の数で止め、時間で切らない (約 190 秒)。当方は並列の
   サブ MIP を、早い再スタートの合図 (`ENOMOTO_MIP_LOSE6_1_STOP`) で 35 秒目に止める。暫定解の間隙が大きい (locks の解は 7%) 時にも止める。
2. **RENS・RINS の固定率** (satellites): 当方の RENS は目標 0.80 で固定して 0.11 秒で実行不能になり、やり直さない。RINS は暫定解 (間隙
   が大きい) との一致で 94% を固定する。HiGHS は中心丸めの解を種にしたサブ MIP で −16 を得る。
3. **サブ MIP を回す時期** (puriri・873061): HiGHS は根のカットのループの途中 (最初の数ラウンドの後) にサブ MIP を回す。当方は根の
   カットのループが終わってから (puriri 186 秒、873061 130 秒)。
4. **根の被約費用のサブ MIP の長さ** (873061): 175 秒を使い、木に入るのが 572 秒。
5. 良い暫定解が早く出れば、被約費用の固定による再スタートで問題が小さくなる (HiGHS は 4 問すべてで 42〜88% を固定して再スタート)。

## 5. 試作案 (どれも既定は変えない、問題の特徴か仕事量で決める形)

- **C1 (RENS を止めない)**: 早い再スタートで並列のサブ MIP を止めるとき、暫定解の間隙 (暫定解 − 下界) / |暫定解| が g (例 2%) を超える
  間は RENS (と根の被約費用) を止めずに続け、再スタートの後の問題に解を渡す。tbfp で locks の 25.889 (間隙 8%) の後も RENS を回す。
- **C2 (RENS の固定率の引き下げ)**: 根の RENS が LP をほとんど解かずに (例 1 秒未満・0 節点で) 実行不能なら、固定率を 0.8 → 0.6 → 0.4 と
  下げて節点の上限つきでやり直す。RINS は暫定解の間隙が大きい (> 50%) とき、一致による固定を LP の解が整数の列だけに絞る (HiGHS の RENS と
  同じ形)。satellites で RENS・RINS が 0 節点で終わる形を対象にする。
- **C3 (カットのループの途中のサブ MIP)**: 暫定解がない (または間隙が大きい) まま根のカットのループの仕事量が根の LP の k 倍 (例 5 倍) を
  超えたら、その時点の LP の解で RENS を 1 本、並列に起動する。puriri (カットのループ 180 秒) と 873061 (130 秒) を対象にする。
- **C4 (根の被約費用のサブ MIP の上限)**: 根の被約費用のサブ MIP の時間を、根のカットのループの時間か根の LP の仕事量の何倍かで切る
  (873061 の 175 秒)。
- 確かめは、4 問 + これまでの M の重い問題 (rootgap の M4 の 12 問) を種 1〜2 で、既定と各案を同じ分担で並べる形にする。

## 11. 案 2 (列挙の前処理) の確かめ: 既存の試作は HiGHS の規則 16 の忠実な移植、ただし sat_rens の差は列挙ではない (2026-11-17)

## 12. sat_rens の前処理の差の切り分け (HiGHS の規則の組み合わせ、2026-11-17)

HiGHS 1.16 で規則を組み合わせて止めた結果 (`sat_rens_presolve.txt`):

- HiGHS 1.15.1 の源 (`HPresolve::runProbing`・`HighsImplications::runProbing`・`HighsCliqueTable::processNewEdge`) との違い:

## 13. 試作案 (既定は変えない)

## 15. HiGHS の前処理の後の列の突き合わせ (`col_match.py` → `col_match.txt`、2026-11-17)
