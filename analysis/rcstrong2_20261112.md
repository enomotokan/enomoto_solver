# RCSTRONG2: RCSTRONG=irk が rmatr100-p10 を遅くする元 (2026-11-12)

課題: 束 cand1113 の `ENOMOTO_MIP_RCSTRONG=irk` (src/mip/rcstrong.rs、analysis/rcstrong_20261111.md) が rmatr100-p10 を 2 種とも遅くする
(winwhy_20261111.md §6: 既定 36.1・38.7 秒 → 50.5・47.0 秒、ノードの LP に行が足され 1.05 → 1.38 回/ノード)。どの部品が何の行を
いつ足すかを特定し、小さな直しを試す。この機械 4 コア、4 スレッド、ソルバーは同時に 1 つ。

## 結論

- **決定 (親、2026-11-12)**: 束 cand1113 を既定にするときは `ENOMOTO_MIP_RCSTRONG=k` にする (`i`・`r` を外す)。根拠は下の 58 問の対と gen-ip054 の節。

- **遅れの元は `i` の根の大域的な固定だけ。`k` は無害** (rmatr100-p10、120 秒: `k` 38.1・33.8・31.7・33.0 秒、同じ回の既定 36.8・34.4・33.4・29.1 秒、
  ノードの LP は 7260 行のまま)。`i`・`ir`・`irk` は 42〜49 秒。`r` (ノードで切り捨てない) では直らない。
- 仕組み (事実): rmatr100-p10 では TU2 の規則で連続列 7259 本が暗黙の整数になり、根の被約費用の表に 6611 本が入る (既定では連続列は
  この表に入らない)。暫定解が出るたびの根の大域的な固定で、切り捨てによって連続列が大域的に 0 に固定される (根のヒューリスティクスの前に約 100 本、
  後で約 7000 本。従のスレッドは共有の境界から取り込む: 「global bounds taken from other threads」既定 0 → 5000〜7000)。すると
  1. **根の部分 MIP が遅くなる** (遅れの半分以上): 固定された列が部分 MIP の前処理で消え、部分 MIP の根のカットのループが 18〜25 本のカットを足す
     (既定は 0 本)。根の被約費用の部分 MIP の根が 0.5 → 5.9 秒、RENS の部分 MIP が 2.7 → 4.6 秒 (`ENOMOTO_MIP_SUBMIP_VERBOSE`、種 2、
     `logs/submip_verbose.*.log.gz`)。木の始まりは既定 7.1〜7.9 秒 → `i` のどの形でも 12.9〜15.3 秒 (16 回すべて)。部分 MIP の解も悪い
     (根の暫定解 425〜444 → 429)。
  2. **木のノードで tableau 行の CMIR カットが効き始める**: ノードの分離で足す行は全部 tableau 行のカット (`ENOMOTO_MIP_SEPSTAT`、
     既定はノードで候補 0)。木全体で 76〜106 本、1 本平均 129 非零 (元の行は平均 3.0)。ノードの LP が平均 7300〜7320 行、
     LP の解き直しが 1.05 → 1.35〜1.48 回/ノード。**ノード数は減らない** (既定 211〜422、`i` の形 236〜356)。
  - ノードの分離を止めると (`ENOMOTO_T_MIP_TREE_SEP_ROUNDS=0`) 行は足されないが、`ir` は 38.0・38.4 秒 (既定 33.0・27.6) と遅いまま
    (1. の分)。
- **固定はこの問題では効き目がない** (ノード数が減らず、部分 MIP の解も良くならない)。行を足さないと固定の効き目が消える、という関係ではない
  (足さなくても効き目はもともとない)。
- 試した直し (どちらも**効かない**、ソースからは外した。差分は `rcstrong2_20261112/gn_trial.patch`):
  - `g`: 根では切り捨てで境界に固定される列だけ締める → 締め付けのほとんどが 0 への固定なので変わらず、42.6〜47.2 秒・カット 77〜106 本。
  - `n`: カットを作るときの境界 (`separate` の `lo`・`up`) では印の列を前処理の後の境界まで広げる → 41.7〜44.3 秒・カット 85〜104 本。
    カットが効き始めるのは境界ではなく、固定で LP の点 (基底) そのものが変わるためと見る (推測)。部分 MIP の分は (前処理で列が消えるので) 元から防げない。
- 効いた問題での `k` だけの形 (60 秒、種 1・2、下の表) は効き目を保つとは言い切れない:
  - pk1 (120 秒、種 1〜4): 既定 36.3・27.8・31.4・48.5、`irk` 28.8・31.0・35.8・26.4、`k` 45.6・37.0・42.2・39.5。`k` は 4 種とも `irk` より遅い
    (中央値 既定 33.9、`irk` 29.9、`k` 40.9)。pk1 では `i` の根の固定が効いている可能性がある (原因は見ていない)。
  - swath1 (暗黙の整数 0 本、`i` は何もしない): `irk` 41.2・51.3 は既定 31.4・28.7 より遅く、`k` 26.9・27.5 は同じくらい。`irk` と `k` の差は
    `k` の行の伝播の回数 (9775 対 1902) だけで、遅い理由は見ていない。
  - neos-911970: 既定 18.5・20.5、`irk` 60*・17.1、`k` 25.6・25.5。`irk` の種 1 は木の始まりが 2.3 → 4.8 秒 (rmatr と同じ形)。
  - ほか (neos-827175・khb05250・exp-1-500-5-5・h80x6320d・gen-ip054・mas74・physiciansched6-2) は 3 つとも揺れの内。
- **提案**: 束では `i` の根の固定 (連続列の大域的な固定) が rmatr100-p10 を確実に遅くし、`k` だけでは pk1 が遅い (4 種)。2 種・4 種の小さい計測では
  決められないので、58 問 × 種 1〜3 で `irk` 対 `k` の対を取って決めるのがよい (親に依頼)。

## 誤答の検査

ソースは HEAD のまま (試作 `g`・`n` は外した) なので、`k` だけの形 (`ENOMOTO_MIP_RCSTRONG=kc`、wheel は HEAD) で fuzz を回した:
fuzz_tiny 400 で bad 0 (strict 13 は以前の判定の数)、mip_fuzz_vs_highs 300 で bad 0。`cargo test` はソースを変えていないので回していない。
計測の全回 (a〜e、66 回) で解けた回の最適値は既定と一致 (rmatr100-p10 423、pk1 11 など)。

  (設定は run.py の `CFGS`。`RCS2_EXTRA=名前=値,...` で環境変数を足す)。ログは `logs/` (a〜d の一部は名前が重なって上書きされた:
  `logs/rmatr100-p10.<設定>.s<種>.log.gz` は b・c・d のうち最後の回のもの、e 以降は `<出力の名前>.` が頭に付く)。

## 58 問の対 irk 対 k (60 秒、種 1〜3、3 分担、コミット 440d5602、`res_P_s*.jsonl`・`summP.txt`)

- `k` は `irk` に比べて SGM **−1.5%** (95% 区間 −4.7%〜+1.8%、どちらかが解けた 44 問)。解けた回は irk 127・k 125 (174 組)。最適値の食い違い 0、crash 0。
  最大 RSS 1814 MB (irk 1705 MB)。3 種すべてで 1.25 倍より遅い問題・0.8 倍より速い問題はない。
- 差が出た問題 (時間、* は時間切れ。3 種の比の幾何平均):
  - k が速い: neos-911970 (irk 45.2・19.0・21.2 → k 23.7・14.0・25.6、0.78)、physiciansched6-2 (32.2・21.3・* → 33.2・13.9・37.5、0.76)、
    pk1 (36.5・35.4・45.9 → 37.8・30.1・34.7、0.88)、noswot (38.8・*・* → *・17.9・*)。
  - k が遅い: mc11 (*・44.3・21.6 → *・51.0・*、1.46)、10teams (12.2・28.5・10.1 → 37.7・18.6・10.1、1.25)、neos5 (54.6・28.7・48.0 → *・41.3・45.3)。

## gen-ip054 の 600 秒 (種 1・2、`f_genip054.jsonl`、wheel は HEAD 9417ecb2 のソース)

| 設定 | 種 1 | 種 2 |
|---|---|---|

- 6 回とも最適値 6840.97 で解けた。この機械では既定も 2 種とも解ける (WINWHY の res_B の「既定は 2 種とも時間切れ、irk は 523・498 秒」は、
  別の機械・別のビルドの数で、この 2 種では再現しない)。
- gen-ip054 は暗黙の整数が 0 本 (等式行の規則 0、TU2 0) なので `i` は何も締めず、`irk` と `k` は同じ解き方 (違いは `i` の印の計算と数えるだけ)。
  `irk` と `k` の差 (324・398 対 545・358) は 4 本の木のスレッドの揺れで、既定との差も揺れの内 (2 種ずつでは効き目は見えない)。
- したがって「束で `k` だけにする」は gen-ip054 の得を捨てない (得があるなら `k` の行から来る)。
