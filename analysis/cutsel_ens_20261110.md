## 1. 結論 (先に)

確かめた事実:

1. **SCIP の既定の重みそのまま (ens) は ENOMOTO では遅くなる**: 58 問 (4 スレッド・60 秒、種 1・2) で SGM 16.17 → 17.65 (**+9.2%**、95% 区間
   [+2.4%, +17.2%]、符号反転の p = 0.011)・解けた 85 → 84 回。問題ごとに 5% 超の差は速い 3・遅い 17 (p = 0.003)。揃って遅いのは roll3000 (+0.72 log ×2)・
   neos-827175 (+0.44 ×2)・hypothyroid-k1 (+0.43 ×2)、揃って速いのは neos-960392 (−0.43 ×2、時間切れ ×2 → 31.8・39.2 秒) だけ。
   根の下界は平均でやや弱い (最良の既知値とのずれ log10 で +0.126、区間 [+0.004, +0.313])。
2. **本数を既定にそろえ密度を使わない形 (enskd) は中立**: 58 問の種 1 (+ 種 2 の 3 回) で +0.5% ([−5.7%, +7.1%])・解けた 46 → 47、速い 10・遅い 10。効き目はない。
3. **効きそうな 10〜12 問 (a) でも勝つ変種はない**: 既定に対し ens +33.1% ([+10.4%, +63.6%])・ensw +20.5%・ensk +7.5%・ensd +14.6%・enskd +7.0% (§4)。
4. **根の下界が上がっても速くならない問題がある**: neos-860300 で ensd・enskd は根の下界が 3200.21 → 3201 (最適値) に上がるが、時間は 15.9・15.8 → 21.8〜23.8 秒。
   hypothyroid-k1 でも ensd・enskd は根 −2883.9 → −2873.0〜−2875.6 (最適 −2851) と強いが 35 → 36〜42 秒。
5. **既定の選び方との差の中身** (58 問、問題ごとに種を平均した ens / 既定 の比の幾何平均): 根の最初のループで足した本数 ×1.14 (増える 27 問・減る 10 問)、
   ラウンド数 ×0.75、LP に残るカットの非零 ×0.56、根の終わりの時刻 ×1.01。相対の閾値 (既定は最良の 0.5 倍未満を捨てる) がないので、伸びないラウンドで
   本数の上限 (50 → 100 → 200 の `CUT_WIDEN`) まで採り、密度の罰で非零 3〜4 の短いカットを多く採る (hypothyroid-k1: 既定は 158 本・平均非零 1182 → ens 450〜550 本・3〜4)。
6. 誤答の検査: `fuzz_tiny.py 400 0` は試作を入れて bad 0 (strict 13 は前からの値)、`mip_fuzz_vs_highs.py 300` は試作を入れて不一致 0、`cargo test --release --lib` は試作の 2 本を含め 395 通過・2 失敗 (失敗はほかのセッションの `mip::sympre` の 2 本で、この試作とは関係しない)。 58 問の全回 (既定・ens・enskd、290 回) と (a) の全回で暫定解と下界の矛盾なし、解けた回どうしの最適値も一致 (`summ.py`)。

推測:

- SCIP の点数は相対の閾値を持たず「予算まで採る」形で、SCIP 側は LP からカットを積極的に外す (age) ことと組で調整されている。ENOMOTO の根のループは
  1 ラウンドの本数の上限と停滞の判定で止めるので、採る本数が増えるぶん LP が重くなり、伸びは変わらない。
- 密度の罰 (疎の点 0.5、密度 0.425 で捨てる) は、ENOMOTO で効く密なカット (hypothyroid-k1 の 1000 非零級の CMIR など) を落とす。`d` で外すと根は強くなる。
- 論文の 5% は SCIP 8.0.3 (LP は Xpress) で、両方が解けた組だけの値。本文でも点数の重みは SMAC の回ごとにばらばらで、重みが選び方の他の部品 (本数・止め方・age) と
  解く仕組みに依存していると見られるので、そのまま写しても効かない。

既定にする価値: **ない** (ens は有意に遅い、enskd は中立)。47 問 (600 秒) は効き目が見えなかったので回していない。

次の一手 (推測): (1) ensemble の点の並べ方を、既定の閾値 (最良の 0.5 倍) と組にして重みだけ探す (SMAC の代わりに 58 問の部分集合で座標探索)。
(2) 密度で捨てずに、LP の反復の増え (非零の予算) だけを止め方に使う。(3) neos-860300・hypothyroid-k1 のように根が強くなっても遅くなる理由 (木の LP の重さか、
分枝の向きか) を分けて調べる。

## 2. 文献と SCIP のソース

- Turner・Berthold・Besançon "A Context-Aware Cutting Plane Selection Algorithm for Mixed-Integer Programming" (ZIB Report 23-21・arXiv 2307.07322 (2023)、
  Operations Research Proceedings 2023 (2025))。本文 (arXiv の v2 の PDF、2026-11-10 に curl で取得) で確かめた事実:
  - 点数の項: 擬似費用 psc = Σ ψ(x_i) |x_i^LP − α_i (α x^LP − β) / ‖α‖²| (回の最大で正規化、式 (2))、ロック loc = (1/n) Σ (ζ_i^− + ζ_i^+) (回の最大で正規化、
    多いのを良しとするか少ないのを良しとするかを選べる、式 (3))、疎の点 sps = max{maxsps − (maxsps / endsps) ‖α‖_0, 0} (式 (4))。これに効き目・期待される改善・
    目的との平行度・整数台を足した加重和。directed cutoff distance は学習で最適解を読み込むと有利になるので外した。
  - 間引き: 密度で先に捨てる (40% 前後が良いという先行の結果)、平行なものは捨てずに点を下げ、点が 0 を下回ったら外す。
  - 止め方: 1 ラウンドに LP に足す非零の数の上限を LP の列の数の倍数にする。
  - 重み: SMAC を種 1〜5 で 5 回 (40 問の訓練集合、SCIP 8.0.3、LP は Xpress)。訓練集合で 8〜15% 速い設定が出たが、点数の重みは回ごとにばらばらで共通の値がなかった。
    一致したのは「密なカットを 40〜50% で捨てる」「平行なものは捨てずに軽く罰する」の 2 点。最終の設定は SMAC の結果と専門知識を組み合わせて決めた
    (**本文に重みの数値は載っていない**)。
  - 結果: MIPLIB 2017 benchmark (種 1〜5、2 時間) の影響を受けた組 (97%) のうち両方が解けた組で、時間の SGM (ずらし 10 秒) 0.95・ノード 0.92、解けた数 +14 (/668)。
- 著者のコード (GitHub の Opt-Mucca/Context-Aware-Cut-Selection、2023-08-02 の `49f38d1`) の `configuration.txt` が最終の設定: isp 0.45・obp 0.25・eff 0.75・exp 0.1・
  psc 0.75・loc 0.25・sparsity_bonus 0.5・end_sparsity_bonus 0.2・root_budget 4.5・tree_budget 9.5・max_parallel 0.95・parallel_penalty 0.25・max_density 0.425・
  filter_dense_cuts True・filter_parallel_cuts False・penalise_locks True・penalise_obp True。**これは SCIP の `cutsel_ensemble.c` の既定値とすべて一致する**ので、
  この試作の `ENOMOTO_MIP_CUTSEL_ENS=1` は論文で計測した設定そのもの (根では擬似費用の項は SCIP でも 0)。
- 本文とソースの違い: ロックの項は、本文の式 (3) では変数の上下のロックの和、SCIP のソースではカットの係数の向きで上か下のロックだけを数え、非零の数で割る。
  試作はソースに合わせた。
- SCIP のソース `src/scip/cutsel_ensemble.c` (GitHub の master、2026-11-10 に取得) で確かめた事実:
  - 既定の重み: 効き目 0.75、directed cutoff distance 0、目的との平行度 0.25 (**既定では平行度を罰する** `penaliseobjparal = TRUE`、点は 0.25 × (1 − 平行度))、
    整数台 0.45、期待される改善 (効き目 × 平行度) 0.1、擬似費用 0.75 (木だけ)、ロック 0.25 (**既定ではロックの少ないものを良しとする**)、
    疎の点の最大 0.5 (密度 0.2 で 0 になる直線)、数値の点 0。効き目・期待される改善・dcd は (log1p(v) / log1p(最大))^2 で正規化。
  - 間引き: 密度 (非零の数 / LP の列数) が 0.425 を超えるものを先に捨てる。採ったカットと平行度 0.95 を超える残りは点から 0.25 引く (1 なら捨てる)。
    `filterparalcuts` (平行なものを捨てる) は既定で偽。
  - 止め方: 点の下限 0 (相対の閾値はない)、非零の予算は根で 4.5 × LP の列数 (木 9.5)、予算の残りが 1 列ぶん未満になったら残りに収まらない密度のものを捨てる。
    `maxcuts` = 200 (候補がこれを超えると ensemble は選ばず次の選び方に任せる)、変数 50000 まで。
  - **優先度は 7000 で、cutsel_hybrid (8000) より低い**。つまり SCIP の既定ではこの選び方は使われていない (ソースで確認。論文の「次の版に入れる」は
    「入っているが既定ではない」の形で実現している)。

## 3. 実装 (`src/mip/cutsel_ens.rs`、既定では使わない)

- `ENOMOTO_MIP_CUTSEL_ENS=<文字>` (値 `1` で上の SCIP の既定どおり)。外側の根のカットのループ (主・裏のカットの写し) と、根の選び方の比べ
  (`ENOMOTO_MIP_CUTSEL_PROBE`) の既定の側で、`select_cuts` (旧 cutsel_hybrid 相当: 効き目 + 0.1 × 目的との平行度 + 0.1 × 整数台、最良の 0.5 倍未満を捨て、
  平行度 0.3 で捨てる) の代わりに使う。固定費用のネットワーク型 (`fc_relax`) とサブ MIP・木のノードでは使わない (既定のまま)。
- 項: 効き目・期待される改善・目的との平行度 (罰)・整数台・密度の点・ロック (元の行から数えた上下のロック。カットは `a x <= b` なので a > 0 は上、a < 0 は下)。
  擬似費用の項は根では SCIP でも 0 なので入れていない。dcd と数値の点は SCIP の既定で重み 0 なので入れていない。乱数の 1e-6 も入れていない (同点は番号の小さい方)。
- 選択を通さずに入るカット (implied bound の `forced`) で残りを先に罰する (SCIP の forced cuts と同じ)。
- 本数の上限は今の上限 (根 50 本、伸びないラウンドで 100・200… に広げる `CUT_WIDEN`)。文字 `w` で 2000 (SCIP の `separating/maxcutsroot`)。
- 変種の文字: `k` = 本数を既定の選び方が採る本数にそろえる (並べ方だけ ensemble)、`d` = 密度で捨てず密度の点・非零の予算も使わない、
  `f` = 平行なものを罰でなく捨てる、`c` = 候補が 200 本を超えたら既定に戻す (SCIP の `maxcuts`)、`p` = 平行度の罰の値を変数で変える。
- 単体テスト 2 本 (平行なカットを捨てる・密なカットを捨てる)。

  (ほかのセッションの `src/mip/sympre.rs`。この試作は触れていない)。試作の `mip::cutsel_ens::tests` の 2 本は通過 (`check_cargo_test.txt`)。
- 試作はカットの選び方だけを変え、固定・衝突・対称性・暗黙の整数には触れない。それでも (a) と 58 問の全回で、暫定解と下界の矛盾 (最小化に直して下界 > 暫定解) がないこと、
