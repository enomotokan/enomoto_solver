# presym: 負け問題の「前処理・対称性」型の原因の切り分け (2026-11-23、親の依頼)

対象: 30n20b8・traininstance6・CMS750_4・bnatt400・fhnw-binpack4-4 (analysis/losses_20261123 の 6.3 節で「前処理・対称性」型とした 5 問)。
6.3 節の見立ては、相手の最終の下界を根の下界と取り違えていたので取り消した (losses 6.4 節で作り直し)。ここでは根の下界と根の後の差を、
SCIP の部品を 1 つずつ切って調べる。

- 台本: `scipab.py <mps> <秒> <名前> [パラメータ=値 ...]` (analysis/scipsym_20261120/scipab.py の写し + 統計の「First LP value」)。ログは logs/ (コミットしない)。
- SCIP 10.0.2 (pyscipopt 6.3.0)、種 1 (randomseedshift 1)。当方は今のブランチの既定、1 スレッド、ENOMOTO_MIP_LOG=1。

## 2. 30n20b8: SCIP の 151 は根の強分枝から (事実)

- SCIP の部品を切った根の下界 (limits/nodes = 1):
  - 前処理なし (presolving/maxrounds = 0): 最初の LP 43.3・根 133.4。プロービングなし: 最初の LP 43.3・根 151。対称性なし: 151。カットを全部切る (separating/maxroundsroot = 0): 108.7。
  - aggregation (cmir・flow cover・knapsack cover)・zerohalf・implied bounds・knapsack・linear の分離を 1 つずつ・組で切っても 151 のまま。
- SCIP のログ (logs/30n20b8_root.log) の根の行: カットの巡で 108.47 → 126.15 (25 巡、19.1 秒)。そこから**強分枝 24 回 (LP 約 4.5 万反復、8.4 秒)** で 151 に上がる。
  カットの後の根の下界は当方 (141.9) の方が上。
- 当方: プロービングで 3284 列を固定し、最初の根の LP は 122.95 (SCIP の 108.47 より上)。カット 25 巡で 141.9。
- 読み: 前処理・対称性・カットの差ではない。SCIP が根の強分枝で下界を上げ、木を 2069 ノードで閉じるのに対し、当方 1 スレッドは 12248 ノードで時間切れ
  (4 スレッドは 121 秒で解ける)。分枝 (強分枝の使い方) と木の型。

## 6. CMS750_4 の 1 スレッドの解探し (事実と試作、2026-11-23)

- SCIP (1 スレッド、300 秒): 38.0 秒・652 ノードで最適値 252。解の出どころは 1 つではなく、根の locks 746 → Feasibility Pump 278 (4.7 秒) → 目的つきのダイビング・
  ALNS・Crossover で少しずつ良くし、zirounding が 252 (38 秒)。
- 当方 (1 スレッド、200 秒): 主のスレッドの FJ (同期) が 767 (0.02 秒)、根の shifting が 604 (7.5 秒)、その後は 7500 ノード目の tree mutation まで動かず 525 で時間切れ
  (4 スレッドは Local-MIP などの並列の解探しで 245 秒で解ける)。根で Feasibility Pump とダイビングが回っていない。
- 原因の連なり (ログで確かめた):
  1. 根の FP・ダイビングは「暫定解なし」(`noinc_like`) のときだけ回る。質の悪い FJ の解を「なし」とみなす既存の試作 `ENOMOTO_MIP_FJ_POOR_NOINC` は、
     FJ のスレッドの解だけを見る (`inc_only_fj`)。1 スレッドの同期の FJ の解には名札がなく「[tree]」で入るので働かない。
     名札を付けても、根の shifting が 767 → 604 と少し良くした時点で「FJ の解だけ」でなくなる。
  2. FP・ダイビングの予算は「根の LP の反復」に比例するが、根の LP は前処理の LP プロービングの基底から 1 反復で終わる (プロービングの側は 3857 反復)。
     FP の LP が約 1000 反復の予算で 2 回目に打ち切られていた (`FP_STATS: LP stop at pass 1: status IterationLimit`)。既存の試作 `ENOMOTO_MIP_P2RIT` は
     `self.root_lp_iters` だけを変え、FP・ダイビングに渡す局所の `root_iters` は 1 のままだった。
  3. 予算を足しても、当方の FP は 179 回の丸めのすべてで「整数列は全部固定できたが、連続列の LP が実行不能」(FP_STATS の fixed_not_found) で解を出さない。
     SCIP の FP は丸めた点の周りをサブ MIP で直す段 (stage 3) を持つ。当方の FP にはこれがない。
- 試作 (どれも既定オフ):
  - `ENOMOTO_MIP_FJSYNC_LABEL=1` (heuristics.rs の feasibility_jump): 同期の FJ の解にも「feasibility jump」の名札を付ける。
  - `ENOMOTO_MIP_POOR_NOINC=1` (solver.rs の `poor_any`): 根で、暫定解が誰のものでも、根の LP との相対ギャップが既存の基準 (`ENOMOTO_T_MIP_FJ_POOR_GAP` = 0.5) を
    超えていれば、暫定解なし用のヒューリスティクス (FP・ダイビングなど) を回す。新しい閾値は足していない。
  - `ENOMOTO_MIP_P2RIT=a` (solver.rs): FP・ダイビングの予算の物差しも前処理の LP の最初の LP の反復にする。
  - 診断: `ENOMOTO_MIP_FP_STATS` のとき、FP の LP が最適で終わらなかった回の状態と反復を出す。
- CMS750_4 (1 スレッド、200 秒、種 1) の結果: どの組でも時間切れ。暫定解は既定 525、POOR_NOINC 575、P2RIT=a + POOR_NOINC 576、
  RHBUDGET=0 + P2RIT=a + POOR_NOINC 509 (どれも木の中の LNS による)。FP は回るようになったが、3. の理由で解を出さない。**まだ効いていない**。
- cargo test (3 つとも有効にして): 421 通過・0 失敗。
- 次の候補: FP に丸めた点の周りのサブ MIP の段 (SCIP の stage 3、連続列を自由にして整数列を丸めた値の近くに絞る) を足す。

### 6.1 試作 `ENOMOTO_MIP_FP_STAGE3=1` (既定オフ): FP の第 3 段

- `heuristics.rs` の `fp_stage3`: Feasibility Pump が解を出さずに終わったら、LP 解にいちばん近かった丸めの点 r の周りをサブ MIP で探す (SCIP の heur_feaspump の stage 3)。
  元の行はそのまま、目的は r からの 0-1 列の距離 (r = 0 の列は x、r = 1 の列は 1 − x)。暫定解があれば「元の目的値が暫定解より良い」行を足す
  (刻みは目的の整数性が分かればそれ、なければ相対 1e-6)。ノードは 500 まで (他のサブ MIP と同じ)、時間は残りの 0.1 倍・10 秒まで (min relaxation と同じ)。
  得た解は元の問題の解なので暫定解の候補にする。新しい閾値は足していない。
- CMS750_4 (1 スレッド・200 秒・種 1、`FP_STAGE3=1 POOR_NOINC=1 P2RIT=a`): 根で FP の第 3 段が 604 → **362** (23 秒、500 ノードで打ち切り)、
  200 秒で **357** (既定 525、最適値 252)。最適値には届かないが、1 スレッドの暫定解は大きく良くなった。FP は POOR_NOINC がないと回らない。
- 誤答: `bash analysis/presym_20261123/fuzz.sh` (4 つの試作を全部有効にして): fuzz 7 本とも bad 0、cargo test 421 通過。小さい問題では FP の第 3 段まで届くことは少ない。

## 7. bnatt400: 衝突解析が決め手 (事実、p2inf_20261119 4.2〜4.11 節の続き)

SCIP 10.0.2・1 スレッド・300 秒・種 1 (`scipab.py`、logs/bnatt400_*.log):

| SCIP の設定 | 結果 | ノード | 最初の解 |
|---|---|---|---|
| 既定 | 115.4 秒で最適 | 4098 | 21.4 秒 (467 ノード目、木の中の LP) |
| 衝突解析なし (conflict/enable = FALSE) | 時間切れ・解なし | 16960 | なし |
| 分枝の衝突の重みを 0 (relpscost の conflictweight・conflictlengthweight = 0) | 時間切れ | 14459 | 252 秒 |
| 前処理なし | 191.0 秒で最適 | 6671 | 101 秒 |
| 木の中のカットなし (separating/maxrounds = 0) | 111.6 秒で最適 | 7408 | 108 秒 |
| 対称性なし | 120.5 秒で最適 | 4098 | 21.9 秒 |

- 衝突解析が決め手。p2inf は「伝播の矛盾からの衝突 (useprop)」が決め手と示した。今回、**衝突を分枝の得点に使うこと (conflictweight)** も決め手と分かった
  (衝突の制約はあっても、分枝に使わないと 252 秒まで解が出ない)。SCIP の統計: 伝播の衝突の解析 2314 回で衝突 12789 本、大域に 7793 本。
- 当方 (1 スレッド・150 秒、logs/bnatt400_t1.log): 衝突の解析 2240 回で 4216 本を足し、プールに 1393 本 (2823 本は年齢で捨てる)。衝突の重みはノード 200 で
  0 → 0.1 (CW_RAMP)。150 秒で解なし (4151 ノード)。年齢で捨てずプールを 1 万本にしても (`ENOMOTO_T_MIP_LIT_CONFLICT_AGE`・`_POOL`) 解なし (4496 ノード)。
- p2inf 4.5〜4.11 節で、分枝の重み・同点の崩し方・SCIP の分枝の順をなぞる診断などは試してあり、残る差は衝突の中身 (どの変数の組か) と見立てられている。
  ここでは新しい試作は作らない (p2inf の続きの材料: SCIP の決め手は「伝播の衝突」と「その衝突の得点を分枝に使うこと」の組)。

## 8. fhnw-binpack4-4: ノードの LP の反復と速さ (事実)

- SCIP (1 スレッド・120 秒): 7.9 秒で実行不能、約 9000 ノード (3 回の再スタート)。ノードの LP は双対単体法 6601 本・**平均 24.1 反復**・5.5 万反復/秒。
- 当方 (1 スレッド・200 秒、logs/fhnw_t1.log): 57.5 秒で実行不能、10977 ノード。前処理の早めの FJ/Local-MIP は 1.5 秒 (以前の 30 秒の上限はもう使わない)。
  木の中は 10 秒で 2731 ノード・ノードの LP 1531 本・14.0 万反復 (**1 本あたり約 92 反復**、うち最初の解き 12.9 万)・**約 1.5 万反復/秒**。
- 読み: ノード数は同じくらいで、LP 1 本あたりの反復が約 4 倍、1 反復あたりも約 3.7 倍遅い。前者はノードの LP が親の基底から近いところで始まっていない
  (飛び込みでない節点への移り方・基底の受け渡し) 疑いがあり、後者は LP の作り (scipsym 2 節の cod105 でも 1 反復約 30 ミリ秒の遅さが出ている) の担当。
  ここでは試作を作らない (木の担当・LP の担当への材料)。

## 10. heur1t の試作と mcsched (2026-11-23、親の分担の整理の後)

親の整理: presym は CMS750_4・mcsched の 1 スレッドの解探しを受け持つ (bnatt400・fhnw-binpack4-4 は別の子、分枝・木の型は別の子)。

- heur1t の試作 `ENOMOTO_MIP_HEUR1T=nd` (analysis/heur1t_20261123) を CMS750_4 で (1 スレッド・200 秒・種 1、`run1.sh`):
  HEUR1T だけ 525 (既定と同じ)、HEUR1T + 6 節の組 (FP_STAGE3・POOR_NOINC・P2RIT=a) 357 (組だけと同じ)。CMS750_4 には HEUR1T は効かない。
- mcsched (1 スレッド・600 秒・種 1): 既定 519.6 秒、6 節の組 529.9 秒、HEUR1T 523.2 秒。3 つとも 78143 ノードで道筋が同じ。
  根の暫定解 (RENS 220782) と根の LP (19.38 万) の相対ギャップは約 0.12 で、POOR_NOINC の基準 (0.5) にかからず、FP などは回らない。
- mcsched の型 (事実): 当方は最適解 211913 を 223 秒 (40841 ノード目) に出し、その後は下界が 19.4 万 → 19.9 万しか上がらず、ノードを使い切って閉じる。
  SCIP (1 スレッド・400 秒): 243.7 秒・8068 ノード。暫定解の良くなり方は当方と似ている。木の中のカットを切ると (separating/maxrounds = 0)
  **159.0 秒・23244 ノード** で、既定より速い。カットなしの SCIP と当方で 1 ノードの時間はほぼ同じ (約 6.8 ミリ秒) で、ノード数が 3.4 倍違う。
  → mcsched は解探しの型ではなく、分枝 (木の大きさ) の型。分枝・木の型の担当への材料。
