## 2. 問題ごとの原因

### 2.1 ken-18・ken-13: 部分 `tau` (`u_solve_partial`) の依存閉包が実際の非ゼロの 50 倍

ken-18 は `alpha` 118 非ゼロ (m の 0.3%)、`tau` 371 (0.9%)、`rho` 33 と超疎で、1 反復あたりの実演算は数百 flop のはずなのに
FTRAN が 73 µs (45%)。callgrind (主ループ 32.2G 命令、62,375 反復 → 516K 命令/反復) の関数別 (包含):

| 関数 | 命令比 | 内容 |
|---|---:|---|
| `solve_sparse_into_pair_capture_tracked` (融合 FTRAN) | 54.9% | うち `pair_r_u_permute_tracked` 49.4% |
| ├ **`u_solve_partial` (`lu.rs:5337`) 42,398 回** | **23.5%** | 策12 の部分 `tau` |
| ├ `permute_out` (`lu.rs:6530`) 1,844 回 | 5.3% | `tau` の超疎段が失敗した反復の O(m) 置換 (1 回 92 万命令 = 平均反復の 1.8 倍) |
| ├ `u_solve_hyper_heap` 90,181 回 | 5.2% | 超疎 `U` 段 (入る列と、部分 `tau` を使わない反復の `tau`) |
| ├ `apply_r_sparse` | 3.7% | |
| `solve_transpose_unit_work_sparse` (BTRAN) | 9.3% | |
| `refactorize` 46 回 | 8.9% | 1 回 62M 命令 (≈ 20 ms、nnz(LU) 8.5 万) |
| `residual_norm_affine` + `residual_scale_affine` (ドリフト検査、100 反復ごと) | 5.9% | 1 回 1.4M 命令 |
| `memset` | 3.6% | O(m) の `fill` (`clear_after_hyper`・`l_solve_steps_into_clean` の `z.fill(0.0)` など) |

`u_solve_partial` の中の行別 (`cg/cg_ken-18_annot.txt`):

|---|---:|---:|---|

つまり部分 `tau` は毎反復、`alpha` の非ゼロ 118 行が依存する `U` の行を **値によらず構造的に** 1,650 スロットたどり、そのうち値が
非ゼロで演算するのは 35 スロットしかない (閉包は `tau` の非ゼロの約 50 倍、`alpha` の 14 倍)。ken-18 (多品種流) の基底は三角形に
近く、`U` の列の依存の連鎖が深いので、`alpha` の少数の行から逆向きにたどる閉包が大きくなる。一方、通常の超疎 `U` 段
(`u_solve_hyper_queue`、`lu.rs:5271`) は `tau` の `U` 段への入力 (L・R 段の後の非ゼロ、≈ `tau` の非ゼロ数) から順向きに値が非ゼロの
スロットだけをたどるので、超疎な `tau` ではこちらのほうが 50 倍安い。stormG2_1000 (策12 の動機、`tau` 1.3% × m=378K = 5,000 非ゼロ、
`alpha` は数十) では逆で、部分 `tau` が正しい。

CLP (`ClpDualRowSteepest::updateWeights`: `updateColumnFT` + `updateColumn` で `tau` を全部求める) も HiGHS (`HEkkDual::updateFtranDSE`
→ `ftranInScaledSpace`) も `tau` は常に全体の超疎 FTRAN で、「`alpha` の非ゼロ行だけ」という最適化はしていない。

## 3. 対処案

各案は独立に実装・判定できる粒度。「ビット一致」は解・反復経路が現行とビット単位で同じか。

### A. 部分 `tau` の閉包に「入力の大きさに比例した上限」を置き、超えたら通常の超疎 `U` 段に落とす (ken-18 −25%、ken-13 −12%)

- 変更箇所: `src/simplex/lu.rs:5343-5366` (`u_solve_partial` の `limit`)。現在 `limit = U_HYPER_ABORT_FRACTION (0.25) × m`
  (`params.rs:734`) で、閉包の辺数が m の 25% を超えたときだけ諦める。これを
  `min(0.25 m, K × (gb.reach.len() + gb.r_seeds.len() + a_list.len()) + C)` のように、`tau` の `U` 段への入力の非ゼロ数
  (= 通常の超疎段が触る数の下限) と `alpha` の非ゼロ数で決める (K は 4〜8 程度、ken-18 は閉包 1,650 に対し入力 ≈ 400)。
  超えたら `return false` → `pair_r_u_permute_tracked` (`:6449`) が `try_u_hyper` で通常の超疎段を行う経路は既にある。
  `tick` は諦めた側も通常側もそれぞれ既存の数え方のまま (作業 #10 (B) のような移動平均・測り直しは入れない)。
- 期待効果: ken-18 −25% (11.7 → 8.8 s、FTRAN 77 → 38 µs)、ken-13 −12〜14%。Kennington 16 問の 10 秒シフト付き幾何平均で
  約 −3%、131 問で −0.5% 前後。pds-100 (論文 169 s、`tau` 1〜5%、部分 `tau` が最速経路) は閉包が入力に比して大きくないので
  現状維持のはず (要確認)。
- 退行リスク: 中。閉包と入力の比が K 付近の問題で経路が変わる (pds-20 は部分 `tau` なしで +6% なので K を小さくしすぎない)。
  stormG2_1000 (部分 `tau` が必須: 切ると 86 → 319 s) は閉包が入力より小さい側なので K ≥ 2 なら影響しない見込みだが要計測。
  irish-electricity は作業 #10 (B) の取り下げ理由 (移動平均の切り替えで再分解の時期が変わる) が当てはまらない (判定が各反復で
  構造的に決まる) ので再現しない見込みだが、旧前処理の試験は要る。
- 難度: 低 (数行)。
- ビット一致: 閉包が上限内の反復は同じ。上限を超えた反復は `tau` の値は同じだが tick が変わり再分解の時期が動くので、
  ken-18/ken-13 など効く問題では経路が僅かに変わる (ken-18: 反復 +21、目的関数値は最終桁まで同じ)。効かない問題は一致。
- 変種 A': 作業 #10 (B) の `PARTIAL_TAU_ADAPTIVE` をそのまま既定にする (ken-18 −22%、ken-13 −14%、pds-20 +2%)。irish-electricity
  (旧前処理) の 1,800 s 超が現行コード (作業 #9 以降の雑音の許容誤差・特異基底対策) でも起きるかを先に確かめる価値はある。

### B. aggregator の「fill-in 超過 3 連続で打ち切り」を、候補の作り直しなしに続ける形にする (pds-20 −20%)

- 変更箇所: `src/presolve/aggregator.rs:1001-1006` (打ち切り) と `:860-935` (候補の集計)、呼び出し側 `src/presolve.rs:893`。
  案 (i): 打ち切った位置から同じ呼び出しの中で候補の残りを続け、「1 周で消去が 0」になるまで繰り返す (HiGHS が
  `substitutionOpportunities` を持ち越すのと同じ効果を、1 回の呼び出しの中で得る)。候補の fill-in 判定は消去で変わった行
  (`act_a`/`row_max_a` が `None` に戻る行) だけ再計算される既存の仕組みがあるので、2 周目以降は安い。
  案 (ii): 連続失敗での打ち切りをやめ、代わりに「fill-in 判定に使った作業量 (`gross` の計数で触れた要素数) の予算」で打ち切る
  (`ENOMOTO_T_MAX_CONSECUTIVE_FILLIN_FAILURES=1e6` の実験は bnl2 で前処理 19 → 30 ms、25fv47 で反復 +7% と、
  候補走査の延長と出力の変化が出るので、予算が要る)。
- 期待効果: pds-20 −20% (4.94 → 3.94 s、前処理 1.35 → 0.48 s、25 → 3 ラウンド、反復 +1.7%)、cre-d 前処理 −20% (全体 −3%)、
  pds-100 (論文 169 s、`PRESOLVE_ROUNDS` 26 ラウンドで前処理 4.4 s) でも同じ構造なので数秒。pds-06/10 も同方向。
  131 問の幾何平均で −0.5% 前後。
- 退行リスク: 中。前処理の出力が変わる問題 (pds 系は行数 8,928 → 8,859、25fv47 は反復 +7%) で経路が変わる。候補の順序を
  保ち (i) の形にすれば「打ち切りで消し残した候補を同じ順で続ける」だけなので、既定で 1 ラウンドで収束している問題
  (Netlib の大半、`PRESOLVE_ROUNDS_END rounds=2〜5`) の出力は変わらないはず。
- 難度: 中。
- ビット一致: 前処理の出力が変わる問題では不一致 (方針上、前処理の出力の変化による反復数の増減は本質的な退行とみなさない)。

  取り下げられた。ここでの案は O(m) 自体をなくすもので、作業 #10 の (E)(i)(iii) に当たる (未着手)。
- 期待効果: callgrind の命令比から cre-d で `permute_out` 7.5% + `permute_btran_out_capture` 3.9% + `memset` 1.8% = 13%、
  pds-20 で 8.0% + 3.6% + α、ken-18 で 5.3% + 1.4% + 3.6%、25fv47 で 5.9% + 1.5% + 1.8%。一覧経由にすると触れた非ゼロ数に比例
  (cre-d の `tau` 921 / 3,954) になるので、その 7〜8 割が消える: cre-b/d −8〜10%、pds-20 −7%、ken-18 −6%、Netlib 中規模 −4〜6%。
  Kennington 16 問の幾何平均 −5% 前後、131 問で −1〜2%。
- 退行リスク: 低。全走査で `u_seq` のヘッダを O(m) でなめる部分は残る (それは `lu.rs:6455` の `iter().rev()` で、命令比 1.5〜2%)。
- 難度: 中 (一覧の記録を全走査の内側に足す。`a_scan`/`b_scan` 両方で記録が要る)。
- ビット一致: 値・順序とも同じにできる (置換は出力位置の集合が同じなら同じ値。`fill` の省略も同じ)。

### D. 結果が密な問題で再分解の間隔を `U`+`R` の膨張で決める (dfl001・d2q06c・25fv47・greenbea・小問題で 3〜12%)

- 変更箇所: `src/simplex/slope_intercept_dual.rs:444-470` (`synth_clock_should_refactor_density`) と `SynthDensity` の分岐 (`:5808` 付近の
  呼び出し)。既存の `SynthDensity::Dense` (策11、`SYNTH_CLOCK_DENSE_FRACTION`) は「密なら `sqrt(m)` 倍を掛けない」だけで、
  m < 10,000 の Netlib には何も効いていない。案: `alpha` の非ゼロ率の移動平均 (`density_col_aq`、既にある) が 0.3 以上の問題では
  `lu.u_r_nnz()` (`lu.rs:7566`、`ENOMOTO_DEBUG_FT_FILL` が使う) の `U+R` が分解直後の `lu_nnz_baseline()` の 2 倍を超えたら再分解する
  (合成クロックとの OR)。密な結果では FTRAN の手間 ∝ nnz(L+U+R) なので、膨張比はそのまま 1 反復の手間の倍率。
  degen3 のように再分解が高い問題 (1 回 2 ms、分解の tick が大きい) は合成クロックが先に効かない限りそのままになるよう、
  膨張の閾値を「分解の tick / 平均の求解 tick」で補正する。
- 期待効果: `SYNTH_CLOCK_FACTOR=8` の実測 (§2.4: 25fv47 −8%、greenbea −12%、bnl2 −11%、grow22 −3%、cre-d −3%、dfl001 −2%、
  d2q06c +2%、degen3 +15%) の上側を取り、下側 (degen3) を避ける形。Netlib 93 問の幾何平均 −2〜3% (結果が密な 20 問前後で
  5〜10%)、Kennington は pds-20 の `tau` 9% 密に効くかは要計測。10 秒シフト付きでは Netlib の寄与が小さいので 131 問で −0.5% 程度。
- 退行リスク: 中。再分解の時期が変わると経路が変わる (pilot87 の崖の前例)。`SYNTH_CLOCK_FACTOR` の掃引で 24 問に 10% 超の退行が
  無い値を選んだ経緯があるので、新しい条件も同じ掃引 (特に pilot87・dfl001・degen3) が要る。
- 難度: 低〜中。ビット一致: 再分解の時期が変わる問題では不一致 (値は同じ基底の分解なので最終解は同じになることが多い)。

### E. ピボット順の再利用の fill 上限を「結果が密な問題」で締める (`REBUILD_FILL_LIMIT` 1.25 → 1.1 相当)、または再利用の分解を次の再分解で必ず作り直す

- 変更箇所: `src/simplex/lu.rs:2079` (`max_nnz`)、`params.rs:690` (`REBUILD_FILL_LIMIT`)。再利用の採否を「結果の密度」で分ける:
  `alpha` の非ゼロ率が高い (≥ 0.3) 問題では FTRAN が分解の全非ゼロを触るので fill 上限を 1.1 に、疎な問題では 1.25 のまま。
  または、再利用の分解の `fill_baseline` を自分の非ゼロ数にせず前回の通常分解の値を引き継ぐ現行 (`:2088`) を保ったうえで、
  再利用が 2 回続いたら 3 回目は通常分解にする (連鎖で 1.25 倍が積み上がらないようにする既存の意図を強める)。
- 期待効果: `ENOMOTO_REUSE_PIVOT_ORDER=0` の実測 (§2.4: 25fv47 −5%、bnl2 −7%、greenbea −5%、d2q06c −3%、dfl001 −3%、cre-d −2%、
  grow22 ±0、degen3 +4.5%)。全部切ると採用時の計測 (Netlib −1.5%) と逆になるので、密な問題に限って 2〜5%。
- 退行リスク: 中 (再分解の手間が増える問題: degen3)。難度: 低。ビット一致: 分解が変わるので不一致 (基底は同じ)。

### F. ken-18 系で合成クロックの基準行数を膨張に合わせる (`SYNTH_CLOCK_LARGE_REF_M` 2,000 → 8,000、m ≥ 10,000 のみ)

- 変更箇所: `params.rs:271`。作業 #10 (G) で「pds-20 ±0〜−9%、pds-100 +6.6%、fome13 +1.7%、効果が揺れと区別できない」として
  取り下げられたが、ken-18 では今回 −6.5% (再分解 46 → 88 回、FTRAN 77 → 66 µs)、A と併用で −33% (7.81 s)。
  pds-100 +6.6% が揺れか本物かで採否が決まる。A の後に再計測する価値がある (A で FTRAN の固定費が減ると、再分解の
  最適な間隔は短くなる方向)。
- 期待効果: ken-18 −6%、ken-13 ±、pds-20 ±。退行リスク: pds-100・fome13。難度: 定数 1 つ。ビット一致: 不一致 (再分解の時期)。

### G. ドリフト検査 (`residual_norm_affine`・`residual_scale_affine`) を疎な結果の大きな問題で間引く (ken-18 6%)

- 変更箇所: `slope_intercept_dual.rs:1410-1512`、`params.rs:179-186` (`XB_CHECK_CADENCE_LARGE` = 100、`_DIV`)。ken-18 では 100 反復ごとの
  検査 1 回が 1.4M 命令 (平均反復の 2.7 倍) で全命令の 5.9%。作業 #10 (C) は m < 10,000 の間隔 20 → 100 と標本検査が取り下げられた
  (pilot87・irish の経路変化)。ここでは m ≥ 10,000 側で、`x_B` 更新一覧の長さの累計 (更新した要素数) が m に達するまでは
  検査しない (ken-18 は 1 反復の更新が 118 要素なので 340 反復に 1 回になる) 形にする。
- 期待効果: ken-18 −4%、ken-13 −2%、pds-20 −1%。退行リスク: 中 (再分解トリガ drift の発火が遅れる)。難度: 低。ビット一致: 不一致。

### H. 再分解 1 回の手間 (ken-18 20 ms、m=39,832、nnz(LU) 85K = 235 ns/非ゼロ; ken-11 3 ms、m=5,567)

- ken-18 の再分解は命令の 8.9% (46 回)、`factorize_reusing` の中は `RowOwners::push` (`lu.rs:1752-1763`)・列の走査 (`:2185-2240`) が
  分散していて 1 行の突出はない。CLP は ken-18 を 474 反復ごと (≈ 100 回) 再分解しても 1 反復 74 µs に収めているので、
  三角形に近い基底 (ken 系は行・列シングルトンの剥離でほぼ全部が消える) の分解は O(nnz) に近いはず。

  今回は F (間隔) と A の後に残る割合 (A の後は ≈ 12%) を見て判断する。
