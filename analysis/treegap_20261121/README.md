## 5. 当方で直すなら (優先順位つきの案。試作はしない)

1. **ORBPP の対象の条件 (misc07)**: 列の数の下限 10 をやめ、別の条件で分ける。misc07 (79x3、1 個) は効き、neos-911970 (35x3 が 6 個と 35x6) は損。
   候補: オービトープの数 (1 個だけなら静的)、行の数と列の数の比 (79 行 / 3 列 = 26 と 35 / 3 = 12)、分割の行 (= 1) かパッキングの行 (≤ 1) か、
   静的な固定の後の根の下界と再スタートの組み合わせ (neos-911970 は根が 49.64 → 52.18 と上がるのに遅いので、木の側の損)。
   手間が小さく効きが確か (misc07 で 2.3〜2.6 倍)。ほかの問題への害を P・M で測る必要がある。
2. **根の再スタートの回数と条件 (neos-911970・neos-1582420)**: SCIP は 3〜4 回再スタートし、前処理で列を大きく減らす (neos-1582420 10100 → 1197 列)。
   当方は 1 回で、列が減らない。再スタートの判定 (固定の割合の閾値) を見直す。既存の記録 (backlog) でも再スタートの閾値で 23・37 → 8・15 秒の例がある。
3. **根の打ち切り値の利用 (全般)**: SCIP は打ち切り値で根の下界が上がる (swath1 +1.65、misc07 +61)。当方は変わらない。根で暫定解が出た後の被約費用の固定と、それを受けた再スタートが要る。
4. **cmir (集約) の強さ (unitcal_7・neos-911970・neos-1582420)**: SCIP の根の伸びのほぼ全部が aggregation/cmir。当方の根との差 (unitcal_7 0.0046e7、neos-911970 2.6、neos-1582420 0.53) は
   cmir を切った SCIP と同じ程度。経路集約の選び方 (unitcal_7、既存の記録) から当たる。
5. **swath1 の木の伝播**: SCIP で一番効く単独の手 (7 倍) だが、当方に項目別のスイッチがなく切り分けられない。先に当方の木の伝播の内訳 (行・被約費用・含意) の数を
   SCIP の Propagators の表と並べる診断を足す。
6. 10teams は解探しなので木の強さの対象外 (LPFACE の採否は既存の記録どおり)。
