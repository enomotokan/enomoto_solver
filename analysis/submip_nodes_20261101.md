# サブ MIP のノード上限を下げると損の問題が戻るか (2026-11-01)

問い: サブ MIP の良い解は主に根の近くで見つかり、木を深く回すのは無駄ではないか。サブ MIP のノード上限 (多くは 500) を下げると、
得の問題 (h80x6320d・qiu) を残したまま、損の問題 (n5-3・neos-1582420・neos-2978193-inde) が戻るか。
背景は `cand_slow_n5-3_20261031.md`・`cand_slow_neos-1582420_20261031.md`・`cand_slow_neos-2978193-inde_20261031.md`・`diag_gain_20261031.md`、
今の既定は `cand_default_20261031.md`。

- 機械: 4 CPU。4 スレッド・60 秒、`ENOMOTO_MIP_LOG=1`、ソルバーは同時に 1 つだけ。HiGHS (highspy) は 1.15.1。回ごとに設定の順を逆にした。
- コード: `6289ec03` (bench8 の分担表) の上。def は環境変数なし = 今の既定。下の試作 (3 節) は環境変数で入れるだけで、既定の動きは変えない
  (def・nm02・nm01 は試作を入れる前の wheel、ほかは試作を入れた wheel。試作は既定では通らない)。
  push の前に `8ad6ced3` (別のセッションの `ENOMOTO_MIP_SUBMIP_NOSOL_STOP`・RENS の深さ・`ENOMOTO_MIP_RENS_RESUME` の試作などを含む) の上に rebase し、
  `cargo test` が 330 件通ることを確かめた (3.3 節の「名前」)。
- 台本・ログは `submip_nodes_20261101/`:
  - `run.py 設定,... 問題,... 回数 [回の始め]`: 1 本ずつ解いて `logs/<問題>_<設定>_<回>.log` に書く (先頭に使った環境変数)。設定は `CFGS`。
  - `summ.py [-v] [問題,...] [設定,...]`: 1 回ごとの状態・時間、根のヒューリスティクスの終わりの時刻 (再スタートの区間ごと)、
    サブ MIP の本数・時間の和・解を出した本数・解のない本数とその時間・最大ノード。`-v` でサブ MIP を 1 本ずつ (`summ1.txt` は全部の `-v`)。
  - `table.py 設定,... [問題,...]`: 問題 × 設定の時間の表と、根のヒューリスティクスの終わり / サブ MIP の時間の和の表
    (`table1.txt` def・nm02・nm01、`table2.txt` 2 回目まで、`table_all.txt` 全設定、`table_6rep.txt`・`table_final.txt` 回を足した分)。
  - `impnode.py [設定]`: 解を見つけた根のサブ MIP が最後に良くなったノードの推定 (2 節、`impnode_def.txt`)。
  - `run1.out`〜`run7.out`: 計測の経過。`repro/`: 3.4 節の再現の材料 (再スタート 2 の問題、台本、ログ)。
- `cargo test --release --lib` (`CARGO_TARGET_DIR=target/test-py RUSTFLAGS="-C link-arg=-lpython3.13"`) は試作を入れた後で 330 件通過。
- 表の数字は秒 (`run_miplib_benchmark.py` の `time`)、T は時間切れ (平均は 60 として)。crash・60 秒の大きな超過はない。**最適値の食い違いが 1 種類ある**: ns250s の h80x6320d で 2 回 (`h80x6320d_ns250s_5`・`_90`)、
  最適値 6382.09905 ではなく 6386.09905 を「最適」として返した (1 節の 0 項、3.4 節)。ほかの 300 回あまりは全部同じ最適値。

## 1. 結論

0. **ns250s は誤った最適値を返すことがある (正しさの不具合、要調査)**。h80x6320d の ns250s 9 回 (rebase の前後を合わせて) のうち 2 回、
   6386.09905 を最適として返した。2 回とも、再スタート 1 の後の LP face のサブ MIP が 6386.099 を出し、根の RINS のサブ MIP が
   解のないまま試作の上限 250 ノードで切られ、暫定解 6386 のまま再スタート 2 に入り、その解き直しが即座に「これより良い解はない」で終わった。
   def でも同じ道 (LP face が 6386) に入る回はあり (`h80x6320d_def_96`)、そこでは RINS が 318 ノードで 6382 を見つけて正しく終わる。
   つまり試作は「暫定解 6386 で再スタート 2 に入る」道を開くだけで、誤りそのものは既存の前処理 (`run_extended_mip`) が、
   実行可能な再スタート 2 の問題 (HiGHS も前処理なしのこのクレートも 6382.099 を解く) を 0.01 秒で実行不能とすることにある (3.4 節、再現の材料は `repro/`)。
   def の再スタート 2 でも同じ誤った判定は起きているが、暫定解がすでに最適なので結果は正しい。この前処理の誤りを先に直すべきで、
   それまではどの形も既定にしない。
1. **ノード上限を一律に下げても損の 3 問は戻らない**。`ENOMOTO_T_MIP_SUBMIP_NODES_MULT` の 0.2 (nm02、100 ノード)・0.1 (nm01、50 ノード) は、
   9 問 × 3 回で n5-3 47.2 → 46.7・51.2、neos-1582420 31.1 → 36.0・30.4、neos-2978193-inde 43.1 → 46.1・38.0 秒 (揺れの中)。
   得の側は損をする: h80x6320d 22.2 → 27.5・31.7、10teams 4.9 → 8.6・20.7、physiciansched6-2 は nm01 で 3 回中 2 回時間切れ。
   別のセッション群の bench8 (58 問 2 回、4 節) でも nm02 は SGM +3.9%、nm01 は +1.5% で、10teams は 4 回中 3 回 28〜36 秒 (def 5〜6 秒)、h80x6320d は 2 回とも 44 秒〜時間切れ (def 25〜33 秒)。
2. **前提の半分は正しい**: 解を見つけた根のサブ MIP は、最後に良くなるのがほとんど 0〜7 ノード目 (2 節)。ただし今の既定では、
   そういうサブ MIP はすでに成果連動の打ち切り (見つけてから max(k, 50) ノード) で 50〜55 ノードで止まっている。
   500 ノードまで深く回るのは **解を 1 つも見つけないサブ MIP** で、そのうち一部は木を解き切って Infeasible で終わる。例外は
   10teams の根の被約費用のサブ MIP (233 ノードで木を解き切り、そこで最適解) と h80x6320d の根の被約費用 (22 ノード目)。
3. 損の 3 問の重さはノード上限から来ていない:
   - **n5-3**: 根のサブ MIP は 8 本とも解を見つけ、成果連動で 50〜54 ノードで止まる。1 本 7〜10 秒の重さはサブ MIP の中の根
     (`cand_slow_n5-3` の 3 項) と、**RENS の空回りのやり直し** (`RENS (more nodes)`、上限によらず同じ 53 ノード・7 秒)。
     ノード上限を下げても止まり方は同じ。やり直しを止める既存の試作 `ENOMOTO_MIP_RENS_MORE_NODES_REAL` (real) だけで 49.6 → 38.0 秒 (6 回)。
   - **neos-1582420**: 解のないサブ MIP (RENS・LP face・RINS) が 99〜495 ノードで Infeasible まで解き切る。上限で切ると状態が
     `NodeLimit` になり、RENS のやり直し (ノード上限 4 倍) が走るので、上限を下げた分が戻ってくる (nm02 で `RENS (more nodes)` 400 ノード)。
   - **neos-2978193-inde**: 最初の根のくじ (`cand_slow_neos-2978193-inde` の 3 項) と木の揺れ。ノード上限の形では変わらない。
4. **得の問題の得の一部は「解のない長いサブ MIP」の時間に乗っている** (3.2 節):
   - h80x6320d は、根のヒューリスティクスの間に裏のカットが何ラウンド進むかで決まる (19 ラウンド以上で 20〜25 秒、18 ラウンドで 36〜37 秒)。
     解を出さない並列の RENS (500 ノード・7〜8 秒) が根のヒューリスティクスの終わり (`join_submips`) を延ばし、その間に裏のカットが 21〜23 ラウンド進む。
     RENS を 100・50・250 ノードで切ると多くの回で 18〜20 ラウンドになり、再スタートの固定と後の LP face のサブ MIP の結果が変わって遅くなる。
   - physiciansched6-2 の nm01 の時間切れの 1 回は、根の RINS のサブ MIP が 50 ノードの上限で 49424 止まり (最適 49324 に届かない)。
     もう 1 回は最初の解 (Local-MIP) が出なかった回で、ノード上限とは関係ない揺れ。
5. 狙った形の試作 (3 節) のうち、効いたのは **解のないサブ MIP だけを、主のスレッドで逐次に解くものに限って 250 ノードで止め、
   RENS のやり直しを本当にノード上限まで進んだときだけにする** 形 (ns250s:
   `ENOMOTO_T_MIP_SUBMIP_NOSOL_CAP=250 ENOMOTO_MIP_SUBMIP_NOSOL_CAP_SERIAL=1 ENOMOTO_MIP_RENS_MORE_NODES_REAL=1`)。
   6 回 (3.3 節): n5-3 49.6 → **36.1**、neos-1582420 31.0 → 30.0 (道 A の 5 回は 26.7〜29.1、道 B の 1 回 40.9)、
   neos-2978193-inde 40.9 → 38.8 (揺れの中)、h80x6320d 22.8 → 22.7、physiciansched6-2 は 6 回とも解けて 23.0 (def は 6 回中 4 回)、
   qiu 34.6 → 32.6 (どちらも 6 回中 2 回が遅い道)、10teams・binkar10_1・mc11 (3 回) も変わらない。
   損の 2 問 (n5-3・neos-1582420) が戻り、h80x6320d・qiu・10teams・physiciansched6-2 の得は残る。neos-2978193-inde は揺れの中で戻らない。
   n5-3 の得は real (RENS のやり直しの空回りを止める) から、neos-1582420 の得は解のない逐次のサブ MIP (根の RINS など) を 250 ノードで切ることから来る。
   ただし 0 項の誤りがある (h80x6320d の 6 回の時間は誤った回 (回 5、23 秒) も含む)。どれも 9 問・6 回までの確かめで、58 問・Mittelmann では
   確かめていない。**既定は変えない**。再スタート 2 の誤りを直してから、ns250s (と比べに real) を 58 問 2 回で回すのがよい。
6. ほかの形は効かない: 成果連動の最小ノード 50 → 20 (om20)・入れ子のサブ MIP だけ 0.2 倍 (deep02)・外側の木の中のサブ MIP だけ 0.2 倍 (tree02)
   は損の 3 問を戻さない。`t` を抜く形 (st、`ENOMOTO_MIP_SUBMIP_HIGHS=-st`) は n5-3・neos-1582420 を戻すが、
   **physiciansched6-2 を 3 回とも時間切れにする** (根の RINS のサブ MIP が `t` なしの 3 秒の上限で 0 ノードのまま止まり、49324 を出せない。
   `diag_gain_20261031.md` の 2 節と同じ仕組み)。

## 2. サブ MIP の解はどこで見つかるか (def、`impnode_def.txt`)

成果連動の打ち切り (`solver.rs` の `submip_outcome_stop`) は、最後に良くなったノード k から max(k, 50) 進むと止めるので、`NodeLimit` で止まった
ノード数 n から k = n − 50 (50 ≤ n < 100)・k ≈ n / 2 (n ≥ 100) と推定した。`<n?` は 50 ノード未満で止まったもの (停滞の打ち切り・時間など)、
`Opt` / `Tim` は木を解き切った・時間切れのもの (数字はノード数)。解を見つけたサブ MIP だけを、ログに出た順に並べた (回 0)。

| 問題 | 解を見つけたサブ MIP の k |
|---|---|
| 10teams | Opt233 (根の被約費用。233 ノードで解き切る) |
| binkar10_1 | <48? 1 <29? 2 5 0 5 5 0 Opt5 |
| h80x6320d | 0 22 <38? 1 |
| mc11 | Opt17 2 Opt0 0 <23? 上限 (最後は名前の出ない逐次のもの (外側の木の中と見られる)、500 ノード・0.9 秒) |
| n5-3 | 0 Opt0 3 1 3 4 1 Tim50 |
| neos-1582420 | 0 <24? |
| neos-2978193-inde | 7 1 2 Opt27 Tim0 |
| physiciansched6-2 | Opt0 |
| qiu | Opt0 Opt15 Opt15 Opt0 Tim4 |

解を見つけない根のサブ MIP は、def の 27 回で h80x6320d の RENS (500 ノード・7〜8 秒)、neos-1582420 の RENS・LP face・RINS
(99〜495 ノードで Infeasible、道 B では 500 ノード)、10teams の LP face (170 ノードで Infeasible) など。
(別のセッションが同じ問いを、入れ子をたどる診断ログ (`1c2603c1`) で 58 問 1 回について調べている (`submip_where_20261101.md`)。
ここではそれを使わず、この 9 問の終わりのノード数から推した。あちらでは成功するサブ MIP の改善が 233・320 ノード目にもあり、
「無駄の大部分は解を 1 つも見つけないサブ MIP」という見立ては同じ。)

### 3.3 狙った形の試作 (`table_all.txt`・`table_final.txt`)

試作 (環境変数、既定では使わない):

- `ENOMOTO_T_MIP_SUBMIP_NOSOL_CAP` = K (既定 0 = 使わない、`solver.rs` の木のループ): サブ MIP が解 (打ち切り値より良いもの) を
  1 つも見つけないまま K ノード進んだら止める。解を見つけたサブ MIP はノード上限と成果連動の打ち切りのまま。
  - **名前**: 計測のときは `ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES`・`ENOMOTO_MIP_SUBMIP_NOSOL_NODES_ROOT`・`_SERIAL` と呼んでいた (ログの先頭の env の行)。
    push の前の rebase で、別のセッションが同じ時期に入れた試作 `ENOMOTO_MIP_SUBMIP_NOSOL_STOP` (`99fa5098`・`26717a55`、
    `submip_nosol_stop_20261101/`) が `ENOMOTO_T_MIP_SUBMIP_NOSOL_NODES` (既定 100) を別の意味で使っていたので、こちらを `_CAP` に改名した。
    あちらは解のないサブ MIP をノード数と時間で止め、状態を `TimeLimit` で返す (RENS のやり直しが走らない)。外側の暫定解がない (打ち切り値が無限の)
    サブ MIP は既定で止めず、深さ 2 以上の値を分けられる。並列のサブ MIP を除く切り替え (こちらの `_SERIAL`) はない。
  - `ENOMOTO_MIP_SUBMIP_NOSOL_CAP_ROOT`: 外側の根のサブ MIP (成果連動の打ち切りの対象) だけにかける (計測していない)。
  - `ENOMOTO_MIP_SUBMIP_NOSOL_CAP_SERIAL`: 別スレッドで解く並列のサブ MIP (`spawn_submip`) とその中の入れ子を除く
    (スレッドごとの印 `SUBMIP_IN_THREAD` を `spawn_submip` のスレッドで立てる)。
  - 止めたときの状態は `NodeLimit` だが、ノード上限には届いていないので `ENOMOTO_MIP_RENS_MORE_NODES_REAL` ではやり直しをしない。
- `ENOMOTO_T_MIP_SUBMIP_NODES_MULT_ROOT`・`_TREE`・`_DEEP` (既定 1、`heuristics.rs` の `solve_submip_problem`): `ENOMOTO_T_MIP_SUBMIP_NODES_MULT`
  に加えて、外側の根のサブ MIP・外側の木の中のサブ MIP・サブ MIP の中のサブ MIP (入れ子) だけに掛ける倍率。

設定 (`run.py` の `CFGS`): st = `ENOMOTO_MIP_SUBMIP_HIGHS=-st`、real = `ENOMOTO_MIP_RENS_MORE_NODES_REAL=1`、
ns100o = `NOSOL_CAP=100`、ns100 = ns100o + real、ns250 = `NOSOL_CAP=250` + real、ns250s = ns250 + `NOSOL_CAP_SERIAL`、
om20 = `ENOMOTO_T_MIP_SUBMIP_OUTCOME_MIN_NODES=20`、deep02 = `NODES_MULT_DEEP=0.2`、tree02 = `NODES_MULT_TREE=0.2`。

### 3.4 ns250s の h80x6320d の誤った最適値: 前処理が実行可能な再スタートの問題を実行不能とする

**解決 (2026-11-01)**: 原因は伝播の強制行の判定 (余裕の残る行を強制行とみなし、係数の小さい連続列を上限 2e-9 に固定していた)。
`presolve_infeasible_20261101.md` で直し、再現の問題は 6382.09905 で最適になった。h80x6320d の def の約 25 秒の回は、再スタート 2 の解き直しが
この誤りで即座に終わっていた近道で、修正後は 40〜47 秒程度になる。

事実:

1. 誤った 2 回 (`h80x6320d_ns250s_5`・`_90`) は、どちらも再スタート 1 の後の根で LP face のサブ MIP が 6386.099 (42 ノード) を出し、
   根の RINS のサブ MIP が解のないまま 250 ノードで切られた (`_CAP`)。暫定解 6386.099 のまま再スタート 2 (固定 164 本) に入り、
   その解き直しは根の LP のログも出さずに即座に終わって、外側は `Optimal` / `Infeasible` を「暫定解が最適」と読む (`maybe_restart` の終わり)。
   def でも LP face が 6386.099 を出す回はある (`h80x6320d_def_96`) が、RINS が 318 ノードで 6382.099 を見つけるので、暫定解 6382.099 で再スタート 2 に入る。
2. `ENOMOTO_MIP_DEBUG_DUMP_RESTART` で再スタートの問題を書き出す台本 (`repro/rep.sh`) で、20 回目に同じ誤りを再現した
   (`repro/h80x6320d_ns250s_dump.log`、再スタート 2 の問題は `repro/h80x6320d_restart2.mps.gz`、打ち切り値 6386.0990436)。
3. その問題を単独で解くと (`repro/check.py`):
   - HiGHS 1.15.1: 最適 6382.099049 (つまり固定・引き継いだカットは 6382.099 の解を切っていない)。
   - このクレート、前処理なし (`ENOMOTO_MIP_NO_PRESOLVE=1`): 最適 6382.099050 (29 秒)。
   - このクレート、既定: **0.01 秒で infeasible**。前処理の入口 `crate::presolve::run_extended_mip` が `infeasible` を返している
     (`src/mip/mod.rs` の `presolve_mip_depth` の `if pre.infeasible`。各所に印を入れたビルドで確かめた。`ENOMOTO_DBG_SKIP` の 8 つの段を全部外しても同じ)。
4. def の回 (正しく 6382.099 で終わる) の再スタート 2 の問題 (打ち切り値 6382.0990436) も、HiGHS は 6382.099049 (暫定解と同じ値) を見つけ、
   このクレートの前処理は infeasible とする。def ではもともとそれより良い解がないので結果は正しいが、前処理の同じ誤った判定は毎回起きている。

見立て: 誤りは ns250s の試作ではなく、既存の前処理 (`run_extended_mip`) の誤った実行不能の判定 (許容誤差・カットの行の扱いなどが疑わしいが、
段は特定していない)。試作は「暫定解が最適でないまま再スタート 2 に入る」道を開いただけ。ほかの問題・設定でも、再スタートの問題に
同じことが起きれば誤った最適値になる。**これを先に直すべき** (直すのはこの調べの範囲の外として残した)。
