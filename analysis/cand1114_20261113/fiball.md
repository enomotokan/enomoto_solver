# cand1114 で fiball などが遅くなった原因の切り分け (2026-11-13)

問い: Mittelmann 600 秒 (res_M、ビルド 54a057b8) で fiball が def 119/461 秒・cand1113 158/118 秒・cand1114 時間切れ/時間切れになった。
cand1113 → cand1114 の差 (RCSTRONG irk → k、HNFPRE=0・SUBFIX=0・IPMRC=utw・DUALEQ・CLQPRB を外した) と、
衝突の直し (f1c14c30・dfb8186d、analysis/wrongans_blend2_20261113.md) のどれが元か。
ついでに、cand1113 で効いて cand1114 で消えた csched008・ran14x18-disj-8・neos-2978193-inde。

台本は fiball/ (cfg.py の形: "+X" は cand1114 に cand1113 の項目 X を戻した形)。ビルドは 54a057b8。
ただし分担 F だけは、54a057b8 に衝突の直し 2 つを入れたビルド。600 秒、4 スレッド。

## 結論

- **fiball: 1 項目では決まらない (揺れが支配的)**。同じ形でも、種・機械で 35 秒から時間切れまで動く (表 1)。
  - 4 種すべてで解けたのは +RCSTRONG_irk だけ (82・111・73・208 秒)。cand1114 は 341・600・35・時間切れ、cand1113 は時間切れ・179・294・時間切れ。
  - irk の `i` は fiball では 1 列にしか印を付けず、再スタートも起きない (ログ)。なので、irk が効く理由は neos-2978193-inde の型ではなく、木の中の揺れと見る (推測)。
  - CLQPRB を戻すと 2 種とも時間切れ。HNFPRE=0 を戻すと 1 種で時間切れ。
  - 衝突の直しの影響: 直したビルドで cand1114 は 266/413 秒で解けた (分担 F)。直す前のビルドでは 341/600 (分担 0・1)。揺れの中で、害は見えない。
  - M の cand1114 の 2 種とも時間切れは、この揺れの悪い側と読む。どの段でも、決まった差は見つからない (根の下界はどの形も 138 で同じ、最初の解は 0.5〜0.7 秒)。
    差は木で、最適値 138 の解をいつ見つけるかと、下界 138 をいつ閉じるか。
- **neos-2978193-inde: RCSTRONG を k にしたことが元 (根の段)**。irk に戻すと 2 種とも cand1113 並みになる (表 3)。
  - irk の `i` (主側の暗黙の整数、TU2 の規則で 20736 列) が、根の被約費用の固定で切り捨てを使って 17040 列を固定する。それで早い再スタートが起き、
    問題が free columns 20800 → 3752、nonzeros 41600 → 8194 に縮む。木に入るのは 6.2 秒 (k だけでは 16.9 秒)、ノードは 2991 (5817)。
  - RCSTRONG=k は rmatr100-p10 の害 (`i` の切り捨て) を避けるためだったが、`i` を外すとこの再スタートの効きも失う。
    `ik` (ノードの切り捨ても使う) や `irk` のように `i` を残す形と、rmatr100-p10 の害の両方を見て決め直すのがよい。
- **ran14x18-disj-8 (種 1 まで)**: cand1114 は 393 秒で解け、cand1113 は 370 秒。M での「cand1114 で解けない」は、今回の機械では出ない (揺れか機械の差)。
  戻すと遅くなる形がある: +HNFPRE0・+DUALEQ は時間切れ、+CLQPRB は 600 秒。
- csched008 と ran14x18-disj-8 の種 2 は、分担 3〜5 を待っている。
