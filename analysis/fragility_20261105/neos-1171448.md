# neos-1171448 の探索の脆弱性 (2026-11-05)

問い: 小さな違いで経路が分かれ、遅い経路に入ると回復できないのはなぜか。neos-1171448 (最適値 −309) は
`analysis/slow9_20261104/neos-1171448.md` で 40 秒前後か 70 秒前後の二山と分かっている。どこで分かれ、遅い山で何が起きていないかを調べ、
手当ての試作 `ENOMOTO_MIP_ROBUST_STALL` (既定では使わない) を入れて比べた。

この機械 (4 コア)、時間の上限 600 秒、ブランチ ccr-1beed81b-ex0uhq (3c1f4d5c の後)。単発は `neos-1171448/run.sh`
(`ENOMOTO_MIP_LOG=1`、`scripts/run_miplib_benchmark.py --worker-ours`)。ログは `neos-1171448/log_<回>.txt`、要約は
`summ.py` (暫定解の時刻と出どころ・ALNS の呼び出し)・`roles.py` (役に就いた時刻)・`stats.py` (設定ごとの中央値・最悪)。
全ての回で一時の診断 `ENOMOTO_MIP_FRAG_DIAG=1` (全スレッドの ALNS 1 回ごとの腕・時間・結果。従のスレッドは `verbose` が切れていて
既定のログには出ない) と `ENOMOTO_MIP_HEUR_ROLE_VERBOSE=1` を付けた (表示だけで探索は変えない)。
ログの `FRAG: ... t` は木の探索の始まりからの秒数 (全体の時刻 = 木の始まり + t)。

## 2. どこで分かれるか (引き金)

事実:

- 根の再スタートはどの回もない。根の暫定解は −304〜−308 で、回によって違う (Local-MIP・RENS・RINS)。根のどの答えが良いかと、速い山かどうかは
  きれいには対応しない (a2 は根で −308、a3 は −307.5 だがどちらも同じような −309 の見つけ方の候補。c9 は根で −306.5 でも速い)。
- 速い回は全て、**主のスレッド (tid 0) の木の最初の大近傍探索 (ALNS の 1 回目 = tree RINS)** が −309 を見つけている。呼ばれるのは
  ほぼ必ず木の **202 ノード目** (全体 31〜44 秒)。1 スレッドでも 4 スレッドでも同じ 202 で、時刻ではなくノード数で決まっている。
- 遅い回はこの 1 回目の tree RINS が −309 に届かない (改善なし、または −308 / −308.5 止まり)。

202 ノード目の理由 (事実): 木の大近傍探索は、潜り (plunge) の始めのノードでしか呼ばない (`plunge_depth == 0` の条件、
`src/mip/solver.rs` の木の大近傍探索の呼び出し)。この問題は LP の値がどのノードでも −309 のままで (2457 個の 0-1 列、刈れるのは実行不能だけ)、
潜りの打ち切りの条件 (下界 ≤ 全体の下界 + 0.25 (打ち切り値 − 全体の下界)) に必ず入るので、根からの最初の潜りが実行不能の葉に当たるまで
約 200 ノード続く (1 スレッドのログで open = nodes − 1 が 1000 ノード以上続く)。

**引き金**は「木の最初の潜りの終わり (202 ノード目) に 1 回だけ回る tree RINS が −309 を当てるか」。その RINS の中身 (どの列を固定するか) は
根の暫定解とノードの LP 解で決まり、それが根のヒューリスティクスの計時・種の違いで変わる。どちらに転ぶかは今の材料からは読めない (推測: RINS の
サブ MIP は 500 ノード・数秒で打ち切られ、その範囲に −309 が入るかどうかの当たり外れ)。

## 3. 遅い回で何が起きていないか (回復できない弱さ)

### 3.1 主のスレッドの大近傍探索は 1 回きり

- 4 スレッドの既定 14 回のどれでも、木のスレッドの大近傍探索 (`role false`) は **tid 0 の 1 回だけ** (`grep "role false"` で 14 行)。
  tid 1 (木のヒューリスティクスを回してよい 2 本目) は一度も回していない (潜りが長く、始めのノードに来ないためと推測)。
- 1 回目の後、時間の予算 (`ENOMOTO_T_MIP_LNS_TIME_MIN` 0.02 + 0.08 × 成功率、全体の経過時間に掛ける) が尽きる。
  a1 では 3.4 秒使って成功率 1/3 になり、次に呼べるのは全体 72 秒ごろ、a3 は 5.1 秒使って 85 秒ごろ。さらに、ヒューリスティクス役が
  就いている間は木のスレッドは大近傍探索を回さない (`tree_heur_allowed`)。
- 1 スレッドでは役がないので、この予算と潜りの始めの条件だけで決まる。b0: 202・805・1006・1408 ノード目 (全体 45・107・130・168 秒) の 4 回で、
  2〜3 回目は予算の残りに合わせて 1 回 0.3〜0.4 秒に縮められ (`ENOMOTO_T_MIP_LNS_CALL_MIN`)、local branching・proximity は何も返さず、
  4 回目の mutation (0.57 秒) で −309。b2 は 5 回目の crossover (240 秒) で −309。

### 3.2 4 スレッドの回復はヒューリスティクス役を待つだけで、役に就くのが遅い

- 遅い回の −309 は全て、ヒューリスティクス役 (tid 3) の ALNS が見つけている (mutation 7 回、RINS 2 回、proximity 1 回)。役に就いてから
  −309 までは 11〜16 秒 (役の ALNS は自分の数え方で RINS → local branching (5 秒で打ち切り) → proximity (5〜6.7 秒) → mutation (0.1〜1.2 秒) の順に一巡する)。
- 役に就いた時刻は木の始まりから **29.3〜45.4 秒** (既定の遅い回 9 回)。その間、暫定解は −306〜−308 のまま止まり、どのスレッドも大近傍探索を回していない。
- 役に就く判定 (`heur_role_mine` → `heur_trigger_eval` → `mu_worth`) は、木の完了の予測が無限大 (刈れないので進まない) で「停滞」に当たり、
  木の中の大近傍探索の観測が 3 回未満なので主解の側も可。つまり **「温まった」(`warm`) の条件だけ** で待っている:
  木の経過 ≥ `ENOMOTO_T_MIP_HEUR_TRIG_WARM_FRAC` (0.05) × (木の経過 + 残り時間)。上限 600 秒・木の始まり 15〜21 秒なら約 29 秒。
  → **役に就くまでの待ちは時間の上限に比例する** (3600 秒なら約 175 秒待つことになる。推測、測っていない)。
- 29 秒を過ぎても、判定は潜りの終わり (`plunge.is_none()`) でしか呼ばれないので、tid 3 の潜りが終わるまでさらに 0〜16 秒遅れる
  (29.3・30.0・30.0・32.3 秒で就いた回と、39.8〜45.4 秒の回がある)。

### 3.3 まとめ (事実と推測)

- 事実: 遅い回の 70〜80 秒のうち、木の始まり + 30〜45 秒は「暫定解が止まっているのに改善ヒューリスティクスがどこでも回っていない」時間。
  原因は (i) 木の大近傍探索が潜りの始めにしか呼ばれず、この問題の潜りが数百ノード続く、(ii) 主の時間の予算が 1 回で尽きる、
  (iii) ヒューリスティクス役の「温まった」の条件が時間の上限の 5% で、判定も潜りの終わりにしかしない。
- 推測: どれも「暫定解が良くならない間ほどヒューリスティクスを回す」仕組みになっていない (予算は経過時間と成功率、役の起動は時間の上限)。
  下界が根で閉じていて暫定解だけが足りない問題で、根・最初の RINS の当たり外れがそのまま時間になる。

## 4. 試作 `ENOMOTO_MIP_ROBUST_STALL=<文字>` (既定では使わない)

- `r`: 役に就くかの判定を潜りの途中でも `ENOMOTO_T_MIP_ROBUST_ROLE_EVERY` (16) ノードおきに行う (就くときは潜りの子を待ち行列に戻す)。
- `w`: 「温まった」の条件を `ENOMOTO_T_MIP_ROBUST_WARM_SECS` (10) 秒で頭打ちにする (時間の上限の 5% と 10 秒の短い方)。
- `l`: 木の大近傍探索を潜りの途中のノードでも呼べるようにする (予算・50 ノードおきの条件はそのまま)。

役に就いた時刻 (木の始まりから): 既定 29.3〜45.4 秒、r 29.7〜30.4 秒 (潜りの途中で就く)、w 14.0〜23.5 秒、rw 10.3〜11.3 秒 (全て潜りの途中)。

- `r` だけでは効かない (29 秒の「温まった」が先に効く)。`w` だけでは潜りの終わりまで待つ分が残る。両方で役が 10 秒ちょうどに就き、
  最悪が 75.8 → 50.4 秒、中央値 61.3 → 44.4 秒。
- 代わりに既定の速い山 (40 秒前後) はなくなる: 役が先に就くと木のスレッドは大近傍探索を回さないので、202 ノード目の tree RINS が呼ばれない。
  rw の木で解いた回は 39.6〜50.4 秒に集まる (二山が一山になる)。
- rw_7・rw_8・w_8・r_7 (13.7〜19.6 秒、0 ノード) は根の RINS が −309 を見つけた回。試作は根を変えないので、根の計時の揺れによるもの (既定の 14 回では 0 回)。
- `l` は rw にほとんど上乗せしない。rwl_6・rwl_9 (24〜26 秒) は tid 0 の tree RINS が潜りの途中の 50 ノード目 (木の 5 秒) に呼ばれて −309 を当てた回。
  ほかの 8 回は 50 ノード目の RINS が外れ、以後は rw と同じ (tid 0 の大近傍探索は 1 回きり)。

1 スレッドには役がないので `r`・`w` は効かない。1 スレッドの遅い山 (170・243 秒) は予算と潜りの始めの条件で決まっていて、今回は手当てしていない。

## 6. 結論

- **揺れの元**: 並列の計時 (種を固定しても根の Local-MIP の答えが変わる) と種 (1 スレッドでも根の shifting・RENS の答えが変わる) の両方。
  どちらも「木の最初の潜りの終わり (202 ノード目) の 1 回の tree RINS が −309 を当てるか」に集まり、そこで二山に分かれる。
- **回復できない弱さ**: 外れた後、暫定解が止まったまま改善ヒューリスティクスがどこでも回らない時間が 25〜45 秒ある。主の大近傍探索は潜りの
  始めにしか呼ばれず (この問題の潜りは数百ノード) 予算も 1 回で尽き、4 スレッドの回復役 (ヒューリスティクス役) は時間の上限の 5% (ここでは 29 秒) と
  潜りの終わりを待ってから就く。1 スレッドでは回復役がなく、170〜243 秒かかる。
- **試作の効き目**: `ENOMOTO_MIP_ROBUST_STALL=rw` で役が木の 10 秒に就き、10 回の中央値 61.3 → 44.4 秒、最悪 75.8 → 50.4 秒。58 問での害は 5 節。
- 残り: 1 スレッドの遅い山 (役がない場合の予算・潜りの始めの条件)、役の ALNS の一巡の順 (mutation が 4 番目で、RINS・local branching・proximity に 10 秒ほど
  使ってから当たる)、時間の上限が長いときの役の待ち (推測、未計測)。
