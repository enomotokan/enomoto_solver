# MIP の前処理後の問題の大きさ: HiGHS 1.15.1 との 55 問の比較と改善策 (2026-10-25)

環境: 4 CPU のクラウドのコンテナ、基準は develop ae2836c。HiGHS 1.15.1 (pip の highspy)。MPS は `origin/inv/mps-cache-20261021` の
55 問 (MIPLIB 40 問 + HiGHS だけが解く 16 問の重なり分)。

計測 (台本は `analysis/presolve_size/`):
- HiGHS: `hpre.py` で前処理だけをかけ (`presolve()`、1 スレッド)、`writePresolvedModel` で書き出す。
- ENOMOTO: `eone.sh` で 1 スレッド・時間制限 120 秒で解き始め、`ENOMOTO_MIP_DEBUG_DUMP_PRESOLVED2` (クリーク行の拡張の後、根の LP を
  解く問題) が書き出されたところで止める。
- 両方の書き出しを `pstats.py` で読み、行・固定でない列・その非零・型の内訳・**LP 緩和の値** (HiGHS で解く、目的の定数を含む) を出す。
- 表は `table.md` (全 55 問)、元のデータは `sizes_final.jsonl` (HiGHS 側は `sizes.jsonl` と同じ)、試作の比較は `cmp_cfg.md`
  (`e_def.jsonl`・`e_dd.jsonl`・`e_all.jsonl`)。HiGHS の規則ごとの切り分けは `hoff.py <mps> [規則の番号 ...]` (規則を 1 つずつ
  `presolve_rule_off` で止め、前処理後の大きさと LP の値を出す) と `hlog.py` (規則ごとの記録)。列ごとの比較は `cmpcols.py`。

**計測の注意 (事実)**: 最初は時間制限 2 秒で解いて書き出していたが、前処理の結果が時間制限で変わる。LP による固定の時間は
時間制限の 5% (`ENOMOTO_T_MIP_LP_PROBE_TIME_FRAC`)、プロービングには壁時計の上限 (1〜3 秒) がある。2 秒では app1-1 の LP が
−3.99 → −18.75、30n20b8 の列が 4750 → 8033 (プロービングの固定 3283 本が消える) になった。表の数字はすべて 120 秒・書き出しで
止める計測。ベンチマークは 60 秒なので LP による固定は 3 秒まで (この表の 6 秒と違いうる)。neos-860300 は同じ設定でも回によって
1216 列 / 1381 列と揺れる (プロービングが時間の上限に掛かる)。

## 結論

1. **全体 (事実)**: 55 問の合計で HiGHS 319722 行 × 298140 列・非零 3180692、ENOMOTO 328615 行 × 349446 列・非零 3714456。
   問題ごとの比 (ENOMOTO / HiGHS) の幾何平均は行 1.098・列 1.022・非零 1.088。1% 以上大きい問題は行 18 問・列 16 問・非零 22 問、
   小さい問題は行 1 問・列 5 問・非零 6 問。LP 緩和の値は HiGHS が強い 5 問 (30n20b8・beavma・gt2・mzzv42z・nursesched-sprint02)、
   ENOMOTO が強い 9 問 (app1-1・blp-ar98・dcmulti・fiber・neos-860300・neos-950242・physiciansched6-2・roll3000・timtab1)。
   列の差 51306 本のうち 43590 本は nw04 と air03 の 2 問 (同じ列の 0-1 列)。
2. **差の原因は 6 つに分かれる (事実、HiGHS の規則を止めた計測と列の比較から)**:

   | 原因 | 問題 (差) | HiGHS の規則 | ENOMOTO の現状 |
   |---|---|---|---|
   | A. 同じ列の 0-1 列 | nw04 (+41293 列、同じ列 41292 本)、air03 (+2318 列、2297 本) | dominated columns (2202 本固定) | 並列列の併合は整数列を除く。`DOMCOL` (試作) は組の上限 100 万で air03 が 160 本だけ |
   | B. 双対の推論による整数列の境界 | gt2 (LP 13460 → HiGHS 20147)、flugpl (+1 行) | (規則を止めても変わらない基本の縮約) | `dual_bound_tightening` は連続列だけ・既定で使わない・苦しくなる行が 1 本でもあるとやめる |
   | C. プロービングの後のかけ直し・含意 | drayage-25-23・-100-23 (+2476・+2511 行)、mzzv42z (+4182 行・+3713 列)、neos-960392 (+923 行・+2488 列)、physiciansched6-2 | probing (15) | `PROBE_REPRESOLVE`・`PROBE_CLIQUE` (試作、既定で使わない) |

   原因の分からない差: nursesched-sprint02 の LP (54.42 対 56.17、HiGHS は probing と enumeration のどちらか一方があれば 56.17、両方を
   止めると 54.42)、30n20b8 の LP (122.95 対 122.98)。
3. **今回の試作 2 つ (事実)**:
   - `ENOMOTO_MIP_DUAL_BOUND2` (B): gt2 の LP が 13460.2 → 20146.8 (HiGHS と同じ値)、flugpl は 15 → 14 行。55 問で形が変わるのは
     この 2 問だけ。前処理の時間は変わらない。
   - `ENOMOTO_MIP_DUPCOL` (A): nw04 87482 → 46190 列 (HiGHS 46189) を **0.06〜0.10 秒** (HiGHS は前処理全体に 48 秒)、air03
     10755 → 8458 列 (HiGHS 8437)、mzzv42z 10693 → 10572 列、physiciansched6-2 6003 → 5955 列。
   - 2 つ (dd) で列の幾何平均 1.022 → 1.003、非零 1.088 → 1.067。既存の試作も全部入れた all で行 1.020・列 0.986・非零 1.004。
4. **小さくしても速くなるとは限らない (事実)**: `DUPCOL` は nw04 を 3 回とも遅くする (既定 10.5 / 10.5 / 10.1 秒 → 29.2〜31.6 秒、
   4 スレッド)。既定は根のカットの 3 巡で 16862 (最適値) に届いて根で閉じるが、`DUPCOL` では 6 巡で 16814.5 にしか届かず木に入る
   (カットの行の平均の非零 53069 → 22912)。理由は調べきれていない。air03 は 3.5 → 3.3 秒。前の調査でも `g` (C + F) は
   drayage-25-23 を 19〜29 秒 → 時間切れにしている。
5. **改善策 (優先順)**: 下の 5 章。B (`DUAL_BOUND2`) はすぐ 40 + 16 問で測る候補。A (`DUPCOL`) は nw04 の根のカットの違いを
   調べてから。C は `PROBE_REPRESOLVE` だけ (drayage-25-23 で HiGHS と行・列・非零・LP がすべて一致) を切り離して測り直す。
   前処理の打ち切りを時間でなく手間で決める (再現性) のも必要。

## 2. 原因ごとの調べ

### A. 同じ列の 0-1 列 (nw04・air03)

- 元の問題で係数がすべて同じ列: nw04 41292 本、air03 2297 本 (physiciansched6-2 は 30514 本だが、ENOMOTO の既定でも大半は消える)。
  どちらも集合分割 (全行が `= 1`) なので、同じ列の 2 本は同時に 1 にならない。費用の安い方を残して残りを 0 にしてよい。
- HiGHS は dominated columns (Achterberg ら 2020 の 6.4 節) で消す (air03 のログ "Fixed 2202 dominated columns")。等式の行では係数が
  等しいことを求めるので、集合分割では同じ列だけが対象になる (HiGHS の `HPresolve::dominatedColumns` の `checkDominationNonZero`)。
- ENOMOTO: `parallelcols` は整数列を飛ばす (`src/presolve/parallelcols.rs` の `is_int_col`)。`ENOMOTO_MIP_DOMCOL` (試作) は衝突グラフの
  隣を組として調べ、組の上限 `ENOMOTO_T_MIP_DOMCOL_MAX_PAIRS` (100 万) で止まる。air03 は 160 本だけ固定、上限を 10 億にすると
  8458 列 (HiGHS 8437) になるが前処理が 1.3 → 3.3 秒になる。
- **試作 `ENOMOTO_MIP_DUPCOL`** (`duplicate_binary_fixings`): 0-1 列を列の (行, 係数) でハッシュして群に分け、群の 2 本を同時に 1 に
  できない行 (a > 0 で `最小活動 + 2a > 上限`、a < 0 で `最大活動 + 2a < 下限`) があれば、最も安い列 (同じなら番号の小さい列) を
  残して残りを 0 に固定する。前処理の最初 (`presolve_mip_depth` の頭) で境界だけを締め、消すのは既存の縮約に任せる。
  単体テスト `duplicate_binary_fixings_keep_optimum` (6 列・3000 問の総当たり)。

### B. 双対の推論による整数列の境界 (gt2)

- gt2 の 87 列で HiGHS の上限がきつい (`cmpcols.py`)。例: `x...0101` は `dem.01: 50 x101 + 45 x102 + ... >= 200` と
  `avail.01: x101 + ... <= 9` に出て、費用 3595 > 0。HiGHS の上限 4 = ceil(200 / 50)、ENOMOTO は 9 のまま。
  x101 > 4 の解は x101 = 4 にしても dem.01 は x101 だけで満たされ (他の列の下限は 0)、avail.01 は楽になり、目的は下がる。
- ENOMOTO の `dual_bound_tightening` (`ENOMOTO_MIP_DUAL_UB`、既定で使わない) は同じ推論だが、(1) 連続列だけ、(2) x を増やすと
  苦しくなる行 (avail.01) が 1 本でもあるとやめる。(2) の条件は要らない (減らす向きはその行を楽にする)。
- **試作 `ENOMOTO_MIP_DUAL_BOUND2`** (`dual_bound_tightening2`): 費用 `c_j >= 0` の列の上限を「x_j を増やすと楽になる行 (の向き)
  をすべて、他の列の最悪の値でも満たす値」まで下げる (下限は向きを逆に)。整数列は切り上げる。楽になる行の他の列の活動が
  無限なら締めない。締めた境界は次の列の最悪の活動に使う (順に適用して正しい)。前処理の最初で使う。
  単体テスト `dual_bound_tightening2_keeps_optimum` (整数 0..3 の 4 列・片側と範囲の行・3000 問の総当たり)。
- gt2 の LP 13460.2 → 20146.8 (HiGHS と同じ値)、0-1 列 22 → 32 (HiGHS 33)。flugpl 15 → 14 行。55 問のほかの問題は変わらない。

### C. プロービングの後のかけ直し (drayage・mzzv42z・neos-960392)

- drayage-25-23: `ENOMOTO_MIP_PROBE_REPRESOLVE=1` **だけで** 732 × 7745・非零 17051・LP 99718.8 と HiGHS に完全に一致する
  (既定 3208 × 7775)。プロービングが締めた連続列 (時刻) の境界で冗長になった行を、かけ直しで消す。
- mzzv42z・neos-960392: HiGHS で probing を止めると +3400 行 (mzzv42z、前の調査) / +616 行・+3195 列 (neos-960392)。ENOMOTO の
  `PROBE_CLIQUE` + `PROBE_REPRESOLVE` (MAX 6) で mzzv42z は 8975 × 9388・LP −21405.2 (HiGHS −21414.2 より強い)、neos-960392 は
  3446 × 54895 (all)。
- 前の調査 (`presolve_gap_20261022.md`) で、`g` (= `AGG_INT` + `PROBE_CLIQUE` + `PROBE_REPRESOLVE`) は drayage-25-23 を 19〜29 秒 →
  時間切れ、neos-960392 と h80x6320d も悪くした。どの部品が悪くしたかは分けて測っていない。

### D. 疎化 (beavma など)

- beavma: HiGHS で sparsify だけを止めると LP が 217396 → **170489 (ENOMOTO の既定と同じ値)**。疎にした行に、その後のプロービング
  (20 列を消す) と係数の強化が効く。ENOMOTO の `SPARSIFY=highs` だけでは 172199、`PROBE_CLIQUE` + `PROBE_REPRESOLVE` と合わせて 213823。
- assign1-5-8 (非零 3720 → HiGHS 2340)・ran14x18-disj-8 (10277 → 8951) は sparsify を止めると HiGHS も ENOMOTO と同じ非零になる。
  `SPARSIFY=highs` 入りの all で 2195・8948。
- 前の調査 (`twovar_20261020.md`) では `SPARSIFY` の効果は 40 問ではっきりしなかった。

### E・F. 整数列の並列列・aggregator

- p0201 (177 列対 195)・mik-250-20-75-4 (253 対 270)・mas74・mas76 (148 対 150): HiGHS で parallel rows and columns を止めると
  ENOMOTO と同じか近い列の数になる。費用の比が係数の比と同じ整数列は `z = x_j + s x_k` に併合できる (s = ±1 なら整数の z を整数に
  分けられる)。ENOMOTO の `parallelcols` は整数列を対象外にしている。
- blend2: HiGHS で aggregator を止めると 154 × 302 (ENOMOTO 169 × 319)。整数列の代入 (`AGG_INT`) は前の調査の試作で、`PRESOLVE_GI`
  と一緒に保留 (68c007d) になり develop にない。

## 5. 改善策

優先度は「効く問題の数・大きさ」「手間」「悪化の見込み」で付けた。

1. **双対の推論による境界を整数列にも広げて既定に (B、`DUAL_BOUND2`)**: 手間は小さく (前処理の最初の 1 パス、O(非零))、gt2 の
   LP を HiGHS と同じにする。55 問でほかに形が変わる問題はない。既存の `dual_bound_tightening` (`DUAL_UB`・FJ の P3 で使う) を
   置き換えられる (条件が緩いだけで同じ推論)。次は 40 + 16 問の対の計測で既定にするか決める。さらに前処理のラウンドの中
   (伝播で境界が締まった後) でも回すと効く問題が増えうる (未確認)。
2. **同じ列の 0-1 列の固定 (A、`DUPCOL`)**: nw04・air03 の差のほぼ全部を 0.1 秒で消す。ただし nw04 は 3 倍遅くなる。既定にする
   前に、nw04 の根のカットが弱くなる理由 (どの分離器のカットが消えるのか) を調べる。消した列を前処理後も 0 に固定した列として
   カットの分離に見せる・群の代表だけに列を寄せる、などで分けて試す。広げるなら、費用の等しい整数の並列列を `z = x_j + x_k`
   に併合する (E、p0201・mik・mas74/76) のも同じ枠組みでできる。
3. **プロービングの後のかけ直し (C) を部品に分けて測り直す**: `PROBE_REPRESOLVE` だけで drayage 2 問は HiGHS と同じ形になる。
   前の調査で悪化を見た `g` は `AGG_INT`・`PROBE_CLIQUE` も含む組なので、`PROBE_REPRESOLVE` 単独・`PROBE_CLIQUE` 単独で
   drayage-25-23・neos-960392・h80x6320d・uccase12・dcmulti を測り、悪化の元を特定する。
4. **前処理の打ち切りを壁時計でなく手間で決める**: プロービングの時間の上限と LP による固定の時間 (時間制限の 5%) のため、
