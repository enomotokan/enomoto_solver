## 改造 HiGHS (分離器を個別に切る)

highspy 1.15.1 には分離器を切るオプションがない (`mip_*` は symmetry・restart・ヒューリスティクスなどだけ) ので、sdist
(`highspy-1.15.1.tar.gz`) の `highs/mip/HighsSeparation.cpp` に `highsloss2_20261113/hsep.patch` を当て、別の venv に `pip install` した。

- 環境変数 `HSEP_OFF` = 文字の並び: `i` implied bound の分離 (`HighsImplications::separateImpliedBounds`)、`c` clique、`t` tableau、
  `p` path (`HighsPathSeparator`)、`m` mod-k。カットプールからの分離と伝播は切らない。
- `HSEP_LOG=1`: 根 (サブ MIP でない、ノード 0) の `separationRound` ごとに 1 行 (`HSEP round: obj 前 -> 後 pool+ impl .. clq .. tab .. path .. modk ..; to LP ..`、
  分離器ごとにプールに入った本数)。`HSEP step ...` は始めと伝播ごとの LP 値と大域的に固定された列の数 (2 回目のビルドから)。
  `HSEP_DUMP=1` で clique 分離のカットの中身を出す。
- LP 値は HiGHS の前処理後の内部の値 (puriri は表示の値より 830 小さい。表示 = 内部 + 前処理の定数)。

### hypothyroid-k1: 目的関数の上限つきプロービング

改造 HiGHS の `HSEP step` (`logs/hsep_hypothyroid-k1_-_steps.log.gz`):

```
HSEP step start obj -2902.852586 fixed global 0 local 0 ub -2693
HSEP step propagate: 968 bound changes, obj -2851.081103 fixed global 968 local 968
HSEP round: obj -2902.852586 -> -2851.000000 pool+ impl 0 clq 2 tab 0 path 895 modk 160; to LP 8; pool 1057
```

- 1 ラウンド目の始め、`separateImpliedBounds` は **LP で小数の 2 値列のうちまだ試していないものを順にプロービング** する
  (`HighsImplications::runProbing`、HighsImplications.cpp 594〜615 行)。大域の定義域の伝播には目的関数の行 (上限 = 暫定解 −2692 − 1) が入るので、
  x_j = 0 / 1 のどちらかで矛盾すれば固定になる。ここで 968 列が固定され、LP を解き直すと −2851.08 (目的は整数なので −2851 = 最適値)。
  その後の分離器は残りの小数を消すだけ (`c`・`p`・`m` のどれか 1 つで足りる、`cipmt` で全部切ると −2898.6)。
- 上限 −2692 は根の LP の直後の randomized rounding (R、5.7 秒) の解。HiGHS の randomizedRounding は lock の数の順に丸めて 1 列ずつ伝播する。
- `i` だけ切った HiGHS は 40 ラウンドで −2865.0 (`logs/hsep_hypothyroid-k1_i_steps.log.gz`)。こちらの 49 ラウンドで −2870 とほぼ同じ伸び。
  つまりカットの種類の差はほとんどない。clique カットも HiGHS が出すのは長さ 2 の辺 (x9889 + x20371 ≤ 1 など) で、元の LP に足しても
  −2902.85 → −2902.57 しか動かない (確かめ: HiGHS の前処理後の LP にこの 1 本を足して解いた)。
- こちらにも同じ機構 `root_obj_probe` (solver.rs、目的の伝播・カットの行・含意つき) があるが、(1) 根のカットのループ・根のヒューリスティクスの後に
  1 回だけ、(2) 暫定解と LP のギャップが `ENOMOTO_T_MIP_ROOT_OBJ_PROBE_MAX_GAP` (0.05) 以下のときだけ。既定の流れでは根の間の暫定解が
  Local-MIP の 3・−1・−3 と find スレッドの −43 で、ギャップ 98.5% のため飛ばす。根の randomized rounding は解なし (カットの後の LP で 1 回)。
- 確かめ: 診断用 `ENOMOTO_MIP_CUTOFF=-2692` (HiGHS の R の解の値) を与えると、カットの後 (−2881.1、ギャップ 0.78%) に `root_obj_probe` が
  2570 列を試して両側矛盾 = 最適の証明 (141.8 秒、`logs/eno_hypothyroid-k1_cutoff2692.log.gz`)。上限を早く持てば同じ機構で根で閉じる。
  残る差は時間の順: こちらはカットのループ (49 ラウンド・61 秒) と clique fallback の試し (24.7 秒、効かず) の後にしか試さない。
- `ENOMOTO_MIP_CLIQUE_CUTS=root` (clique を根で毎ラウンド): 候補は毎ラウンド約 100 本 (上限) 出るが効き目 0.008 で選ばれず、目的値の推移は既定と同じ。

### rococoC10-001000: 前処理と path

- HiGHS の前処理後は 576 行・2442 列 (全部 2 値、連続も一般整数もない)。こちらは 741 行・自由な列 2566 (一般整数が約 123 列残る)。
  HiGHS の規則を 1 つずつ切ると (`presolve_rule_off`)、規則 12 (Aggregator) で 699 行・一般整数 82 列が残り、規則 13 (ParallelRowsAndCols) で 617 行。
- HiGHS の前処理後の問題を MPS に書いて (`highspy` の `getPresolvedLp`) cand1114 で解くと、根のカットの後が 9969 (自前の前処理では 9153、HiGHS 10158)、
  60 秒の下界 10322 (`logs/eno_rococoC10-001000-hpre_t1.log.gz`)。根の差 (9153 → 10158) の約 8 割は前処理。
- 連続変数がない問題では HiGHS の path separator は「LP で締まった行 (カットの行を含む) 1 本ずつを両向きで `HighsCutGeneration`
  (変数上下限の置き換え・CMIR・持ち上げ被覆)」になる。こちらの移植 (`path_aggregation_highs`) は自前の前処理の問題では 741 本の始点すべてが
  「消す連続変数なし」で、カットは 0 本 (`ENOMOTO_MIP_GAP4_PATHDIAG`、1 ラウンド目)。HiGHS の前処理の問題では 551 本中 32 本が成功する。
- 前処理の件は親経由で (a) の担当に伝えた (caf7db41 で記録済み)。

### neos-3216931-puriri: mod-k と tableau、cand1114 の前処理

- HiGHS は毎ラウンド mod-k が 10〜40 本をプールに入れ、tableau は時々まとめて (119・416 本) 入れる。跳ねる 27〜29 ラウンドは mod-k 21〜38 本・
  tableau 0〜25 本。`m` を切る (19 ラウンドで止まる) か `t` を切る (34 ラウンド) とどちらも跳ねない。`p`・`i` はほぼ関係ない。
- こちらの zerohalf (mod 2、元の行と単純な上下限) は既定で切 (`ENOMOTO_MIP_NO_ZEROHALF` の既定 1)。HiGHS の mod-k に合わせた試作
  `ENOMOTO_MIP_MODKVB=1` (k = 2・3・5・7、変数上下限の置き換え、LP のカットの行も使う。analysis/modkvb_20261107.md) は cand1114 では
  根の 2 ラウンドで 58939.7 → 59331 (時間切れ、下の前処理の件で根の LP がもともと低い)。比べるには cand1113 相当の前処理で回す必要がある (未)。
- **cand1114 は puriri の前処理が cand1113 と違う**: cand1114 は 5315 行・2965 列・根の LP 58939.7 (HiGHS 60272 より下)、cand1113 は 5095 行・2768 列・
  60402.8。cand1114 で外した `ENOMOTO_MIP_CLQPRB=1d` を戻すと cand1113 と同じ前処理になる (`DUALEQ=1`・`HNFPRE=0` は無関係)。親に連絡済み。

### satellites2-60-fs

HiGHS も最初の根は −29 から動かない (カット 1434 本・LP に 262 本でも −29、130 秒)。147 秒 C (central rounding) 94・160 秒 L 25 の後、
「40.3% inactive integer columns」で再スタート (12335 列の 2 値に縮む)、縮んだ問題の根のカットで −28 → −25 (3104 本)。こちらは 75 秒に
被約費用ではなく根の固定 (3447 列) で再スタート、暫定解なしで木に入り (253 秒)、初めの解は 102 秒の 80、600 秒で 22 / −29。
カットの差より先に **解の発見** (b の担当) の差で、良い解の後の再スタートで問題が縮んでからカットが効く。

## 追記: D2 ノードの切り替えの重さの原因 (kasai と 58 問の 10 問)

親からの依頼 (待ち行列から取ったノードの最初の LP が重い原因の特定と直し方)。台本 `highsloss2_20261113/ratio.py` (1 スレッドで解き、
`ENOMOTO_PROF_TREE_PAR` の「最初の LP」の内訳と `ENOMOTO_MIP_RESTORE_DIAG` の 1 本ずつの行を集計、`ratio.jsonl`)。HiGHS 側は改造を足して
(`hsep.patch` の後半、`HighsSearch.cpp`)、`installNode` で待ち行列から入れたノードの最初の LP と、それ以外のノードの LP の反復を数える
(`HSEP_LOG=1` のとき終わりに `HNODE stat` の 1 行)。

### (1)〜(4) の答え

- **(1) 基底の出所**: 子を作るときに親の LP の最適基底 (と行の世代 `basis_epoch`) をノードに付け、取り出したときに戻す (`restore_node_basis`)。
  保存の後に行の追加・削除があれば記録 (`row_log`) で行の並びを直す。基底変数の数が合わない (保存した基底で効いていたカットの行が消えた) ときは、
  既定では木の中の分離 (`tree_sep`、既定で真) の分岐で **戻さずに直前のノードの最適基底のまま** 解く (`ENOMOTO_MIP_TREE_SEP_REPAIR` で修復して使う)。
  根の基底に戻ることはない。
- **(2) 境界の差**: 保存した親の基底を戻せて行の変化がなければ、待ち行列のノードでも 12.4 反復 (kasai、229 本) で潜りの子並み。
  境界の差 (木の中の距離) が効くのは、戻せずに直前のノードの基底から解くときだけ。
- **(3) カットの行の出し入れ** (主因): kasai の 1 スレッド・120 秒の待ち行列のノード (戻したもの) を行の変化で分けると

  | 保存の後の行の変化 | 本数 | 最初の LP の反復 |
  |---|---|---|
  | なし | 229 | 12.4 |
  | 追加 1〜9 | 71 | 18.3 |
  | 追加 10〜99 | 130 | 38.2 |
  | 追加 100 以上 (削除なし) | 63 | 345 |
  | 追加 100 以上 + 削除あり | 51 | 325〜360 |
  | 基底の数が合わない (修復して使った分) | 12 | 486 |

  さらに、基底の数が合わず戻さなかったノードが 809 本 (待ち行列 1899 本の 43%) あり、1 本 **394 反復** (待ち行列の反復の 7 割)。
  復元の試み 3138 回のうち 1534 回 (49%) が不一致。不一致の元は、ノードの分離のラウンドが新しいカットを足す前に「今のノードで効いていない
  (論理変数が基底の) カットを全部外す」(`inactive_cut_mask`) こと。年齢での削除は `ENOMOTO_MIP_PROTECT_QUEUE_CUTS` で守れるが、この一括削除は守らない
  (保護だけ入れても不一致 1863 回)。追加の側は、木のほかの所で足されたカットが保存した点で破れているので、その分の双対単体法の反復が要る。
- **(4) 初期化の費用**: 待ち行列のノードは 273 反復・47 ms (1 反復 0.17 ms)、潜りの子は 13 反復・3.3 ms (0.25 ms/反復)。1 反復の単価は高くなく、
  再因子分解・価格付けの重みの捨て直しは主因ではない (反復の数が問題)。

### HiGHS との比較

| 問題 (1 スレッド) | HiGHS: 待ち行列から入れたノード / それ以外 (反復/LP) | HiGHS: 取り出しの割合 | こちら: 待ち行列 / 潜りの子 (反復/LP) | こちら: 取り出しの割合 |
|---|---|---|---|---|
| neos-3627168-kasai | 867 本 200.8 / 16277 本 5.4 (比 37) | 867 / 11880 ノード = 7% | 1899 本 233 / 1140 本 11.9 (比 20) | 約 50% |
| rout | 128 本 272.0 / 11016 本 25.7 (比 10.6) | 2% | 559 本 212 / 3058 本 51 (比 4.2) | 13% |
| neos-911970 | 162 本 81.7 / 13602 本 8.8 (比 9.3) | 1.8% | 348 本 380 / 2436 本 61.5 (比 6.2) | 12% |
| timtab1 | 124 本 183.7 / 9850 本 20.1 (比 9.1) | 2% | 316 本 140 / 7119 本 38.4 (比 3.6) | 4% |
| neos5 | 532 本 55.9 / 49730 本 10.9 (比 5.1) | 1.2% | 9323 本 48 / 17954 本 16.4 (比 2.9) | 32% |

(HiGHS は 300 秒 (kasai)・60 秒、こちらは 60 秒 (kasai は 120 秒)。こちらのほかの 5 問: misc07 比 1.9・52%、pk1 1.1・23%、mas76 2.4・26%、
noswot 2.1・3%、eil33-2 4.9・16%。neos-1456979 は 188 ノードで待ち行列 2 本。)

- HiGHS は待ち行列のノードに基底を持たせない (`HighsNodeQueue::OpenNode` は境界の変更・下界・推定値だけ)。取り出すと、部分木を待ち行列に戻したときの
  一番上のノードの基底 (`openNodesToQueue`) から解くので、**1 回の切り替えはこちらより重い** (kasai 201 反復、rout 272)。
- 差は回数: HiGHS は待ち行列から 1 本入れると、そのノードの下を最大 100 ノード (`processNodes` の `plungeLimit`) 潜り、終わったら部分木の中の
  一番近い開いた祖先の兄弟に戻る (`backtrackPlunge`、下界の条件は打ち切り値だけ。祖先の擬似費用の点数の方が良ければ待ち行列へ)。
  こちらは潜りの子・兄弟に進む条件が「下界 ≤ 最良の下界 + 0.25 × (打ち切り値 − 最良の下界)」(`ENOMOTO_T_MIP_PLUNGE_QUOT`・`SIBLING_QUOT`) で、
  戻る先も今の潜りの兄弟だけなので、待ち行列に戻る割合が 3〜25 倍。
- こちらは潜りの子の LP も重い (kasai 12 対 5.4、neos-911970 62 対 8.8、rout 51 対 26)。LP の行が多い (kasai 約 3000 対 1650、neos-911970 523 対 231、
  rout 512 対 403)。

### 試し (1 スレッド、3 本同時なので秒は目安)

| 問題 | 既定 | F2 (`ENOMOTO_MIP_PROTECT_QUEUE_CUTS=1` + `ENOMOTO_MIP_HL2_PROTECT_INACTIVE=1`) | HP (`ENOMOTO_T_MIP_SIBLING_QUOT=1e9`・`PLUNGE_QUOT=1e9`) |
|---|---|---|---|
| neos-3627168-kasai (200 秒、`TREEEFF=psh`) | 4601 ノード・下界 986744、待ち行列 273 反復 | 5358 ノード・**987236**、待ち行列 128 反復・不一致 0、行 4131 | 37118 ノード・981007 (悪化)、待ち行列 110 本 |
| rout (120 秒) | 42.1 秒 (4094 ノード)、待ち行列 205 反復 | **26.7 秒** (3654)、待ち行列 70 反復 | **25.0 秒** (5656) |
| neos-911970 (120 秒) | 95.0 秒 (5221) | 114.4 秒 (7876)、行 523 → 656 | 時間切れ (下界 54.673、最適 54.76) |
| neos5 (120 秒) | 下界 14.521 | **14.549**、待ち行列 59 → 23 反復 | 14.063 (悪化) |

- F2 は今回入れた試作 (既定では切): `inactive_cut_mask` (ノードの分離の前の効いていないカットの一括削除) で、待ち行列のノードの保存した基底で
  効いているカット (`ENOMOTO_MIP_PROTECT_QUEUE_CUTS` の保護) を外さない。不一致は 0 になり、4 問中 3 問で良くなったが、LP の行が増え
  (kasai 3000 → 4131、neos-911970 523 → 656) neos-911970 は遅くなった。
- HP (HiGHS のように下界の条件なしで潜る・兄弟に戻る) はノードは安く多くなるが、下界の伸び (最良優先) が崩れて kasai・neos5・neos-911970 で悪化。
  HiGHS が潜りでも下界を保てるのは、木の中のノードの順 (祖先の擬似費用の点数での打ち切り) と 100 ノードの上限によるとみられ、条件を外すだけでは足りない。

### 直し方の案と見込み

| 案 | 中身 | 見込み | 手の大きさ |
|---|---|---|---|
| D2a (F2 を詰める) | 保護を「待ち行列のノードの基底で効いているカット」すべてでなく、下界の良い (取り出されやすい) ノードの分だけにする、または保護したカットの行の数に上限 (例: 元の行の 0.5 倍) | 不一致をほぼ消しつつ行の増加を抑える (neos-911970 の悪化を避ける)。kasai・rout・neos5 の改善を保つ | 小〜中 |
| D2b 不一致のとき消えたカットを足し直す | 取り出したノードの保存した基底で効いていて今の LP に無いカットを、プール (カットの番号) から LP に戻してから基底を置く。木の中では使い終わったら次の分離のラウンドで外れる | 不一致の 394 反復 → 保存した基底からの十数〜数十反復。行の増加は一時的 | 中 (カットの番号からプールの行を引く所が要る) |
| D2c 追加された行の扱い | 保存の後に 100 本以上足されていたら、足されたうち保存した点で破れていないものだけ残して LP を解く (破れているものは解いた後に分離で戻る) | 追加 100 以上の 345 反復を減らす。ただし下界の弱いノード LP になる | 中 |
| D2d 待ち行列に戻る回数 | HiGHS の `backtrackPlunge` に合わせ、潜りの終わりで部分木の祖先の兄弟に (下界の条件を緩めて) 戻る。祖先の擬似費用の点数の比較と、1 回の潜りの上限 100 ノード | 取り出しの割合 13〜50% → 数% にできれば、kasai では LP の反復が半分以下。ただし HP の試しでは下界の伸びが崩れたので、どの条件で戻るかの調整が要る | 大 |

D2a・D2b が先 (小さく、kasai・rout・neos5 で効きが見えた F2 の延長)。58 問の対で害を見る必要がある (neos-911970 のように行が増えて遅くなる問題)。
