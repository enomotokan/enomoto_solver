## 改造 HiGHS (分離器を個別に切る)

highspy 1.15.1 には分離器を切るオプションがない (`mip_*` は symmetry・restart・ヒューリスティクスなどだけ) ので、sdist
(`highspy-1.15.1.tar.gz`) の `highs/mip/HighsSeparation.cpp` に `highsloss2_20261113/hsep.patch` を当て、別の venv に `pip install` した。

- 環境変数 `HSEP_OFF` = 文字の並び: `i` implied bound の分離 (`HighsImplications::separateImpliedBounds`)、`c` clique、`t` tableau、
  `p` path (`HighsPathSeparator`)、`m` mod-k。カットプールからの分離と伝播は切らない。
- `HSEP_LOG=1`: 根 (サブ MIP でない、ノード 0) の `separationRound` ごとに 1 行 (`HSEP round: obj 前 -> 後 pool+ impl .. clq .. tab .. path .. modk ..; to LP ..`、
  分離器ごとにプールに入った本数)。`HSEP step ...` は始めと伝播ごとの LP 値と大域的に固定された列の数 (2 回目のビルドから)。
  `HSEP_DUMP=1` で clique 分離のカットの中身を出す。
- LP 値は HiGHS の前処理後の内部の値 (puriri は表示の値より 830 小さい。表示 = 内部 + 前処理の定数)。

### hypothyroid-k1: 目的関数の上限つきプロービング

改造 HiGHS の `HSEP step` (`logs/hsep_hypothyroid-k1_-_steps.log.gz`):

```
HSEP step start obj -2902.852586 fixed global 0 local 0 ub -2693
HSEP step propagate: 968 bound changes, obj -2851.081103 fixed global 968 local 968
HSEP round: obj -2902.852586 -> -2851.000000 pool+ impl 0 clq 2 tab 0 path 895 modk 160; to LP 8; pool 1057
```

- 1 ラウンド目の始め、`separateImpliedBounds` は **LP で小数の 2 値列のうちまだ試していないものを順にプロービング** する
  (`HighsImplications::runProbing`、HighsImplications.cpp 594〜615 行)。大域の定義域の伝播には目的関数の行 (上限 = 暫定解 −2692 − 1) が入るので、
  x_j = 0 / 1 のどちらかで矛盾すれば固定になる。ここで 968 列が固定され、LP を解き直すと −2851.08 (目的は整数なので −2851 = 最適値)。
  その後の分離器は残りの小数を消すだけ (`c`・`p`・`m` のどれか 1 つで足りる、`cipmt` で全部切ると −2898.6)。
- 上限 −2692 は根の LP の直後の randomized rounding (R、5.7 秒) の解。HiGHS の randomizedRounding は lock の数の順に丸めて 1 列ずつ伝播する。
- `i` だけ切った HiGHS は 40 ラウンドで −2865.0 (`logs/hsep_hypothyroid-k1_i_steps.log.gz`)。こちらの 49 ラウンドで −2870 とほぼ同じ伸び。
  つまりカットの種類の差はほとんどない。clique カットも HiGHS が出すのは長さ 2 の辺 (x9889 + x20371 ≤ 1 など) で、元の LP に足しても
  −2902.85 → −2902.57 しか動かない (確かめ: HiGHS の前処理後の LP にこの 1 本を足して解いた)。
- こちらにも同じ機構 `root_obj_probe` (solver.rs、目的の伝播・カットの行・含意つき) があるが、(1) 根のカットのループ・根のヒューリスティクスの後に
  1 回だけ、(2) 暫定解と LP のギャップが `ENOMOTO_T_MIP_ROOT_OBJ_PROBE_MAX_GAP` (0.05) 以下のときだけ。既定の流れでは根の間の暫定解が
  Local-MIP の 3・−1・−3 と find スレッドの −43 で、ギャップ 98.5% のため飛ばす。根の randomized rounding は解なし (カットの後の LP で 1 回)。
- 確かめ: 診断用 `ENOMOTO_MIP_CUTOFF=-2692` (HiGHS の R の解の値) を与えると、カットの後 (−2881.1、ギャップ 0.78%) に `root_obj_probe` が
  2570 列を試して両側矛盾 = 最適の証明 (141.8 秒、`logs/eno_hypothyroid-k1_cutoff2692.log.gz`)。上限を早く持てば同じ機構で根で閉じる。
  残る差は時間の順: こちらはカットのループ (49 ラウンド・61 秒) と clique fallback の試し (24.7 秒、効かず) の後にしか試さない。
- `ENOMOTO_MIP_CLIQUE_CUTS=root` (clique を根で毎ラウンド): 候補は毎ラウンド約 100 本 (上限) 出るが効き目 0.008 で選ばれず、目的値の推移は既定と同じ。

### rococoC10-001000: 前処理と path

- HiGHS の前処理後は 576 行・2442 列 (全部 2 値、連続も一般整数もない)。こちらは 741 行・自由な列 2566 (一般整数が約 123 列残る)。
  HiGHS の規則を 1 つずつ切ると (`presolve_rule_off`)、規則 12 (Aggregator) で 699 行・一般整数 82 列が残り、規則 13 (ParallelRowsAndCols) で 617 行。
- HiGHS の前処理後の問題を MPS に書いて (`highspy` の `getPresolvedLp`) cand1114 で解くと、根のカットの後が 9969 (自前の前処理では 9153、HiGHS 10158)、
  60 秒の下界 10322 (`logs/eno_rococoC10-001000-hpre_t1.log.gz`)。根の差 (9153 → 10158) の約 8 割は前処理。
- 連続変数がない問題では HiGHS の path separator は「LP で締まった行 (カットの行を含む) 1 本ずつを両向きで `HighsCutGeneration`
  (変数上下限の置き換え・CMIR・持ち上げ被覆)」になる。こちらの移植 (`path_aggregation_highs`) は自前の前処理の問題では 741 本の始点すべてが
  「消す連続変数なし」で、カットは 0 本 (`ENOMOTO_MIP_GAP4_PATHDIAG`、1 ラウンド目)。HiGHS の前処理の問題では 551 本中 32 本が成功する。
- 前処理の件は親経由で (a) の担当に伝えた (caf7db41 で記録済み)。

### neos-3216931-puriri: mod-k と tableau、cand1114 の前処理

- HiGHS は毎ラウンド mod-k が 10〜40 本をプールに入れ、tableau は時々まとめて (119・416 本) 入れる。跳ねる 27〜29 ラウンドは mod-k 21〜38 本・
  tableau 0〜25 本。`m` を切る (19 ラウンドで止まる) か `t` を切る (34 ラウンド) とどちらも跳ねない。`p`・`i` はほぼ関係ない。
- こちらの zerohalf (mod 2、元の行と単純な上下限) は既定で切 (`ENOMOTO_MIP_NO_ZEROHALF` の既定 1)。HiGHS の mod-k に合わせた試作
  `ENOMOTO_MIP_MODKVB=1` (k = 2・3・5・7、変数上下限の置き換え、LP のカットの行も使う。analysis/modkvb_20261107.md) は cand1114 では
  根の 2 ラウンドで 58939.7 → 59331 (時間切れ、下の前処理の件で根の LP がもともと低い)。比べるには cand1113 相当の前処理で回す必要がある (未)。
- **cand1114 は puriri の前処理が cand1113 と違う**: cand1114 は 5315 行・2965 列・根の LP 58939.7 (HiGHS 60272 より下)、cand1113 は 5095 行・2768 列・
  60402.8。cand1114 で外した `ENOMOTO_MIP_CLQPRB=1d` を戻すと cand1113 と同じ前処理になる (`DUALEQ=1`・`HNFPRE=0` は無関係)。親に連絡済み。

### satellites2-60-fs

HiGHS も最初の根は −29 から動かない (カット 1434 本・LP に 262 本でも −29、130 秒)。147 秒 C (central rounding) 94・160 秒 L 25 の後、
「40.3% inactive integer columns」で再スタート (12335 列の 2 値に縮む)、縮んだ問題の根のカットで −28 → −25 (3104 本)。こちらは 75 秒に
被約費用ではなく根の固定 (3447 列) で再スタート、暫定解なしで木に入り (253 秒)、初めの解は 102 秒の 80、600 秒で 22 / −29。
カットの差より先に **解の発見** (b の担当) の差で、良い解の後の再スタートで問題が縮んでからカットが効く。
