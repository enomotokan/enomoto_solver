  `mip_rel_gap=0`・`output_flag=True`)。時間上限 60 秒 (基準)・300 秒 (終わるまで)。「打ち切り値つき」は証明だけの比較で
  ENOMOTO `ENOMOTO_MIP_CUTOFF=-2.38805`。
- ログ・スクリプト: `analysis/neos2978193_r3_work/` (`run.sh` 1 回の実行、`base.sh`・`exp1.sh`〜`exp3.sh`・`side.sh`・`side2.sh`・`screen.sh`・`pp.sh`

## 結論

1. **HiGHS の「4 スレッド」は木を 1 本の CPU で解いている** (事実)。HiGHS 1.15.1 の木の並列 (`getMaxNumWorkers`) は
   `parallel=on` のときだけで、既定 (`choose`) では 1 つの作業者。計測では CPU 時間 27.9 秒 / 実時間 27.6 秒、2 回とも 1720 ノード
   (決定的)。ENOMOTO は CPU 4 本を使い (打ち切り値つきで CPU 294 秒 / 実時間 92 秒、8693 ノード)、それでも実時間で負ける。
   つまり CPU 時間で比べると差は約 10 倍: **ノード数 約 5 倍 × 1 ノードの CPU 時間 約 2 倍**。
2. **1 ノードが重いのは、LP の反復が HiGHS の約 2 倍** (事実)。主スレッドで 1 回のノードの LP は 102〜224 反復 (中央値 約 130)、
   HiGHS は木全体で 1 ノード 64 反復 (木の LP の反復 110823 / 1720 ノード)。1 反復の時間は同程度 (ENOMOTO 主 0.17〜0.25 ms、
   HiGHS は 1 ノード 13 ms / 64 反復 = 0.2 ms 以下)。ENOMOTO の木の LP は 1060〜1230 行 (HiGHS は前の調査で葉 507〜664 行)。
   主スレッドのノードの 56〜66% は待ち行列や兄弟から基底を戻したノード (§2・§3)。
3. **分枝の選び方 (変数・子・ノード) を HiGHS に合わせても木は小さくならない** (事実、下の表)。子の選び方を HiGHS の本体の
   `kRootSol` にしても (試作 `ENOMOTO_MIP_CHILD_ROOTSOL`)、潜りを HiGHS と同じく刈られるまで続けても (既存の
   `ENOMOTO_T_MIP_PLUNGE_QUOT=1 ENOMOTO_T_MIP_SIBLING_QUOT=1`)、ノード数は既定の揺れ (8319〜27671) の中。
   潜りを続ける設定は、1 ノードの LP の反復が減り (待ち行列から取り出す回数が減る) 遅い回がなくなる (打ち切り値つき 5 回で
   既定 中央値 110.8 秒・最大 186 秒 → 中央値 88.6 秒・最大 101 秒、打ち切り値なし 3 回で 72.9/127.4/129.2 秒 → 82.3/95.4/81.7 秒)。
   ただし揺れが大きく 8 回ずつでも有意とは言えない。**副作用の確認では 14 問中 8 問で 15〜45% 速くなるが、暫定解をまだ
   良くする必要がある問題で悪くなる** (neos-911970 が 23〜40 秒で解ける → 60 秒で解けない、neos5・gen-ip002 の gap が悪化。§6)。
   証明の段階に入ってから切り替える試作 (`ENOMOTO_MIP_PROOF_PLUNGE`) は、検出が遅く利点の大半が消えた (§6)。既定にする候補ではない。
- 根: 両者とも根の LP -2.418518、カットで動かない。HiGHS は 3.7 秒にサブ MIP で最適解、約 4 秒で木に入る。ENOMOTO は 5〜9 秒で
  最適解 (乱択丸め・内点丸め・RENS) を持つが、根のヒューリスティクスと再スタートで**木に入るのは実時間 17〜22 秒** (前の調査と同じ)。
  60 秒の上限ではこの 15 秒前後の差も大きい。

## 2. HiGHS と ENOMOTO の分枝の選び方 (ソースで確かめた事実)

| | HiGHS 1.15.1 (本体の木) | ENOMOTO (既定) |
|---|---|---|
| 強分岐 | `HighsSearch::branch`: LP の双対退化の係数 (`computeLPDegneracy`) が 10 以上なら `minreliable=0` (強分岐なし)。この問題は係数 約 30〜40 なので根を含め強分岐しない | 退化 (`dual_degeneracy`) なら根以外で強分岐しない。根では強分岐する (60 秒で 50 LP・5145 反復) |
| 変数のスコア | `getScore`: pseudocost の項 / 退化係数 + 退化係数 × (1e-2 衝突 + 1e-4 (打ち切り + 推論))。この問題ではほぼ衝突スコア | `hybrid`: pseudocost の項 / dynw + dynw × 1e-4 (推論 + 打ち切り)、dynw = (実行不能の葉+1)/(打ち切りの葉+1)。衝突の重みは既定 0 |
| 擬似費用の初期化 | 観測のない列は全体平均 `cost_total` (最初は 0)。再スタートでは `HighsPseudocostInitialization` で引き継ぐ (観測数は上限つき) | 観測のない列は全体平均 (なければ 1)。根の強分岐の観測が入る |
| 子の選び方 | 本体は `kRootSol`: 両側の推論の平均を根の LP 解からの距離で重み付け、大きい方 (同点は上)。`kHybridInferenceCost` はサブ MIP 用 | pseudocost × 小数部の小さい側 |
| 潜り | 刈られるまで潜る。兄弟へ戻る (`backtrackPlunge`) とき、祖先の反対側のスコアの方が高ければ待ち行列へ回す。1 回の潜りの上限は processNodes の plungeLimit | 子の下界が 全体の下界 + 0.25 × (打ち切り値 - 全体の下界) を超えたら潜らず待ち行列へ (`ENOMOTO_T_MIP_PLUNGE_QUOT`)、兄弟へ戻るのも同じ条件 (`SIBLING_QUOT`)。上限 min(1000, ノード数/10) |
| ノードの選び方 | 作業者 1 つでは、待ち行列から取り出す 10 回に 1 回は下界最小、他は「下界と推定値」(`popBestNode` = hybridEstim) | 暫定解があれば 4 回に 1 回は下界最小 (`ENOMOTO_T_MIP_BB_EVERY_INC`)、他は下界と推定値の平均 |

- 前の調査で試した HiGHS 風のスコア (`ENOMOTO_MIP_DEGEN_SCORE`) と衝突スコアの重み (`ENOMOTO_T_MIP_CONFLICT_WEIGHT`) は効果なし。
  前の調査の子の選び方の試作 `ENOMOTO_MIP_CHILD_HIGHS` は `kHybridInferenceCost` (HiGHS のサブ MIP の規則) で、本体の規則ではなかった。
- この問題の ENOMOTO では暫定解のギャップが 1.28% (0.0305) と狭く、潜りの打ち切りの幅は 0.0076。木の LP の値の多くがこの幅を
  超えるので潜りがすぐ切れる: 打ち切り値つきの既定で主スレッドの分枝 709〜3497 回のうち 76〜900 回 (11〜38%) が潜らずに待ち行列へ、
  主スレッドのノードの 56〜66% が基底を戻したノード (兄弟への戻りを含む。潜りを続ける設定では 49〜51%)。

- ノード数はどの設定も既定の揺れの中。潜りを続けると木はやや大きく (中央値 15201 対 11495) なるが、主の反復/LP が下がり実時間は
  そろう。
- 子の選び方を HiGHS の `kRootSol` にしても、この問題の ENOMOTO では下が多いまま (下 = 施設を閉じる。x の上限 324 個が 0 になり

  可能性があるが確かめていない。
- 全候補の強分岐は 1 ノード 約 0.9 CPU 秒かかり、300 秒で終わらず木の大きさの下限の目安にならなかった (失敗)。

## 7. 試作 (既定では無効)

1. `ENOMOTO_MIP_CHILD_ROOTSOL` (src/mip/solver.rs 子ノードを作るところ (`prefer_up`)、`Solver::child_rootsol`・`root_lp_x`、
   src/mip/pseudocost.rs `inference` を公開): HiGHS の本体の木の子の選び方 `ChildSelectionRule::kRootSol` (`HighsSearch::branch`)。
   根 (深さ 0) のノードで分枝するときの LP 解を覚え、両側の推論の平均 + ε に (1 + 今の値 - 根の値) / (1 + 根の値 - 今の値) を掛けて
   大きい方へ潜る (同点は上)。効果なし。
2. 診断 `ENOMOTO_MIP_SB_FULL` (src/mip/solver.rs `select_branch_inner`): 全ノードで全候補を強分岐 (退化・予算・信頼度・先読みを無視)。
3. 診断: `ENOMOTO_MIP_LOG` の終わりの `MIP: sibling backtracks ...` の行と、スレッドごとの `node diag (thread k)` に、潜った子の
   向き (下, 上) と潜りの打ち切りの数を足した (`Solver::child_dir_stats`・`plunge_aborts`)。
4. `ENOMOTO_MIP_PROOF_PLUNGE` (src/mip/solver.rs `proof_plunge`・`proof_phase_flag`、潜りの打ち切りと兄弟への戻りの条件、
   `proof_phase_check` の起動条件): 証明の段階 (検出は `ENOMOTO_MIP_PROOF_SWITCH` と同じ。`ENOMOTO_T_MIP_PROOF_GAP_FRAC` などで調整)
   に入ったら潜りと兄弟への戻りを下界で打ち切らない。`ENOMOTO_MIP_PROOF_SWITCH` の他の効果 (下界最小のノード選択・木の中の
   ヒューリスティクスと役の停止) は `ENOMOTO_MIP_PROOF_SWITCH` のときだけにした (既定の動作は変わらない)。効果は §6。
- `cargo test --release --lib`: 既定で 308 件通る (17 件 ignored)。`ENOMOTO_MIP_CHILD_ROOTSOL=1 ENOMOTO_MIP_PROOF_PLUNGE=1
  ENOMOTO_T_MIP_PROOF_GAP_FRAC=1` でも 308 件通る。

## 8. うまくいかなかった試み

- 全候補の強分岐で木の大きさの下限を見る: 遅すぎて終わらない (§3)。
- 子の選び方を HiGHS の本体の規則に: 効果なし (§3・§4)。
- 潜りの打ち切りをやめる (全体・片方・0.5・証明の段階だけ): 担当の問題と証明だけの問題は速くなるが、暫定解を良くする問題で悪化 (§6)。
- 計測の途中で `run.sh` を書き換えたため、実行中の bash が読み崩れて 1 回分 (打ち切り値つき plq1 の 2 回目) の結果の行が
