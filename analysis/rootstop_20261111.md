# 根の段の打ち切りの基準をそろえる試作 (ROOTSTOP、2026-11-11)

- bench に使う環境変数: 既定 (`def`) はなし (cand1108zd + DRCR、`ENOMOTO_MIP_FOLD=ri` が既定の版)。試作は `ENOMOTO_MIP_ROOTSTOP=文字`:
  `r` (`ENOMOTO_MIP_ROOTSTOP=r`)・`b` (`ENOMOTO_MIP_ROOTSTOP=b`)・`rb02` (`ENOMOTO_MIP_ROOTSTOP=rb ENOMOTO_T_MIP_ROOTSTOP_RATE=0.02`)。
  どれも `ENOMOTO_MIP_THREADS=4`・`ENOMOTO_T_MIP_SEED=種`・`ENOMOTO_MIP_LOG=1`。試作は既定では使わない。既定の動きは変えていない。
- 課題: docs/backlog.md の「根の段 (前処理・ヒューリスティクス・再スタート・カット・根の LP) を打ち切って木に移る基準を 1 つにそろえる」。
  このセッションで作ったのは案 1 (相対の判定) と案 6。案 2 (再スタートの損得)・案 5 (時間の安全弁) はまだ。案 4 (対称性の 2 段) は SASSY・PRECHAIN の領分なので触らない。
- 機械: 4 CPU、ソルバーは同時に 1 つ。計測の wheel は 7620dd5b の前の版 (32462467) に試作だけを入れたもの。
- 生データ: `rootstop_20261111/p58.jsonl` (58 問 × def・r・b × 種 1・2)、`p58v2.jsonl` (def は p58.jsonl の写し + rb02)、`tgt.jsonl` (10teams の種 3〜5)。
  行の `root` は `rootinfo.py` (analysis/cutloop_stop_20261106/B のもの) の出力 (木に入った時刻・再スタート・前景/裏のラウンド)。
  `rs_r` は r で止めた回数、`rs_b_skip` は b で裏のカットを飛ばした回数。回し方 `bench.py`、集計 `summ.py` (出力 `summ_*.txt`)。
  標準エラーの全体は大きいので入れていない。

## 結論

- **b (再スタートが見込まれる根で裏のカットを起こさない) は取り込みの基準を満たす。効き目は小さい。**
  58 問・種 2 つで SGM 15.79 → 15.74 秒 (−0.3%)、対の比の 95% 区間 [−3.5%, +2.9%]、解けた 87 → 87、種をまたいで揃った害なし。
- **r (根のカットを「下界の上がり ÷ LP の反復」の相対の判定で止める) は基準を満たさない。** 割合を 0.02 に緩めて b と合わせた rb02 も同じ
  (SGM −1.1%、区間 [−8.3%, +6.9%]。揺れの大きい 12 問を除くと −2.9% [−5.8%, −0.1%] で速い向きだが、全問の区間の上限が +5% を越える)。
  区間を広げているのは 10teams (根は同じで、既定も種で 6〜30 秒に振れる)。
- 割合 5% の r:
  SGM +0.1% だが区間 [−7.5%, +9.9%] で上限が +5% を越え、時間切れの問題の最終ギャップがやや悪い (log10 で +0.049、p=0.042)。
- 誤答 0 (`fuzz_tiny.py 400 0`・`mip_fuzz_vs_highs.py 300`、どちらも `ENOMOTO_MIP_ROOTSTOP=rb`)、全回 (354 回) で暫定解と下界の矛盾 0、
  `cargo test --release --lib` 400 通過 (既定と `ENOMOTO_MIP_ROOTSTOP=rb` の両方)。

## 試作の中身 (`src/mip/rootstop.rs`、呼び出しは separation.rs・solver.rs に数行)

### r (案 1 の相対の判定)

- 外側の主の根のカットのループだけ (サブ MIP・裏のカットの写し・`ENOMOTO_MIP_BG_CUTS_DETERM` の `c` の続きでは使わない)。
- 手間 = そのラウンドの LP の反復 (時刻は使わない)。基準の速さ = ループの始めから下界が初めて動いたラウンドまでの上がり ÷ その間の反復の和。
  外側の最初の根で決め、再スタートの後の根も同じ基準を使う (再スタートの後の根は持ち越したカットで最初のラウンドの伸びが小さいので、
  その根で決め直すと長く回る。analysis/cutloop_stop_20261106/B.md の mushroom-best の直しと同じ理由)。
- 直近 `ENOMOTO_T_MIP_ROOTSTOP_WIN` (3) ラウンドの上がり ÷ 反復が基準の `ENOMOTO_T_MIP_ROOTSTOP_RATE` (0.05) 倍を下回ったら止める。
  基準が決まった後は SCIP 式の停滞の回数 (10 回) を数えない。ラウンドの上限 (25、強いカットの延長を含む)・時間の上限・目的値が整数刻みの
  判定はそのまま効く。下界が一度も動いていない間は今までの判定のまま。ログ `MIP: cut round k: ROOTSTOP r: rate ... < ... x first ...; stop`。

### b (案 6)

- 裏のカットを起こす直前 (solver.rs の `bg_mode` の決め方) に、新たに固定された整数列 + 今の LP の被約費用と打ち切り値で固定できる
  整数列 (`lose6_3_cut_restart_due` と同じ数え方) が [`maybe_restart`] の閾値 (初回 1%・2 回目から 2.5%) を越えるなら、裏のカットを起こさない。
  ログ `MIP: ROOTSTOP b: newly fixed ... + fixable by reduced costs ... restart (not) expected; background cuts skipped/started`。
- 空いたスレッドを解改善に回す部分 (案 6 の後半) はまだ入れていない (RESTCHAIN のセッションと相談済み。試すなら `ENOMOTO_T_MIP_PRECHAIN_ROOT_KEEP=2` と組み合わせる)。

- noswot は b だけでも速くなっている (32.7・60 → 21.8・50.8 秒) ので、r の効きではなく木の運と見る (推測)。

- r の当たる問題: 前景のラウンドがはっきり減り (fiber 91 → 12〜18、p200x1188c 104〜148 → 12〜16、timtab1 81〜85 → 13〜25、mc11 25〜79 → 19〜23)、
  その分は裏のカットが回す (裏のラウンドが増える)。速くなった: mc11 41.5 → 22.9・32.6 秒、neos5 51.6・59.4 → 24.4・43.8 秒、eil33-2 29 → 28・22 秒、
  dcmulti・khb05250・fiber。遅くなった: neos-911970 9.3 → 23.0 秒 (種 1)、mik-250-20-75-4 3.4 → 6.8 秒 (種 2)、swath1 19.3 → 36.0 秒 (種 2、再スタートが 1 → 3 回)。
- 10teams (r で 8.2・6.5 → 51.9・47.5 秒) は根が同じ (5 ラウンド目で下界 924、r の判定と整数刻みの判定が同じラウンドで止める)。種 3〜5 を足すと
  既定 6.2・21.0・30.1 秒、r 39.1・5.8・13.3 秒で、既定も大きく振れる。木の運の問題と見る (`tgt.jsonl`)。
- b が働いたのは再スタートの後の根だけ (最初の根では、裏のカットを起こす時点で暫定解がなく、新たな固定もまだ 0)。飛ばした回が多いのは
  p200x1188c (3〜4 回、4.3・7.8 → 2.5・3.4 秒)・exp-1-500-5-5・sp150x300d・qnet1・fiber・mik-250-20-75-4。

## 推測・次の手

- r は前景のラウンドを減らして裏のカットに回すので、木に入る時刻は変わらない (中央値 −0.04 秒) が、時間切れの問題の下界は少し悪くなる。
  割合を 0.02 に緩めても区間の上限は下がらなかった。木の速さの見積もり (案 1 の後半) と比べる形にしないと、根の打ち切りとしての得は小さいと見る。
- b は、最初の根では効かない。最初の根でも効かせるには、裏のカットを起こすのを根のヒューリスティクスの後 (暫定解が出た後) まで遅らせるか、
  再スタートを先に判定する流れに変える必要がある (案 2 と合わせて)。
