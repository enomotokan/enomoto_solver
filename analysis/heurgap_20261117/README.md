# HEURGAP: HiGHS 1.15.1 に暫定解の質で負ける問題の解探し (2026-11-17)

0.1.9 の既定と HiGHS 1.15.1 の Mittelmann 600 秒の比べ (analysis/vshighs_20261117/) で、当方の暫定解が HiGHS より悪い問題について、
どの手がいつ解を出したかを両者のログで対応づけ、試作 (既定は変えない環境変数) で手元の効き目を確かめた。
手元・4 コア・4 スレッド・600 秒、ソルバーは同時に 1 つ。

- `list.py` → `list.txt`: 負ける問題の一覧 (主のギャップ = |obj − 最良既知| / max(|obj|, |最良既知|)。28 問)。
- `run.py`: 1 問ずつ解いてログ (`logs/`) と結果 (`res.jsonl`) を残す (analysis/primal_20261117/run.py の写し。`TAG`・`OURS_ENV` で試作を回す)。
- puriri・satellites 系・neos-933966 は他のセッション (TREECLOSE・TIMEDEP) が下界・前処理の側で見ているので、ここでは扱わない。
- サブ MIP の中の解探しの弱さは analysis/subheur_20261117/ が扱っている。

## 4. わかったこと

- **trento1 の大きな差 (1.5e7 と 5.3e6) は、解探しの手でなく木の運**。5.3〜5.6e6 への改善は、どの形でも木そのもの
  (`[tree]`・`[other thread (tree)]`) が 450〜600 秒に出していた。既定でも種 2 では 5.29e6、sm60 は種 2 で 4.5e7 と悪くなる。
  役の長いサブ MIP (gd、local branching 497 秒) は 1.61e7 → 1.58e7 だけ。
- **academictimetablesmall の `g` の改善 (3500 → 2292) は種 1 だけ**。種 2 では役の local branching が 432 秒走って何も出さない
  (gt でも 4301 → 4294)。種 2 は根の RINS も改善せず、Local-MIP の 4301 のまま。
- 共通の弱点: **木の中の近傍探索 (RINS・local branching・proximity) が、上限 (5〜8 秒) の中で解を出せない**。上限を延ばしても
  (sm60・t・g の数百秒) 安定しては出ない。HiGHS は同じ規模の近傍 (サブ MIP) から数秒〜数十秒で解を出しており、
  差は時間の配分より**サブ MIP の中の解探しの速さ**にある (subheur_20261117 の「サブ MIP の根では trivial が最初に解を出し、
  入れ子の RENS・ポンプ・ダイビングが回らない」と同じ方向)。
- `r` の発見 (役のスレッドが根とみなされる) は既定でも起きうる癖。既定の役は短く退くので目立たないが、役に長く居る形を入れるなら直す。

## 5. 判断

- 試作 `g`・`t`・`r`・sm60 は、2 問 × 種 2 つで安定した改善を示さない (種で逆転する)。P・M の対の比べには回さない。
- 次に効きそうなのは、時間の配分でなく、サブ MIP の中で暫定解なし用の手 (入れ子の RENS・ダイビング) を trivial の解があっても回すこと
  (subheur_20261117 の続き)。trento1 の根の RENS (当方 1.6e7、HiGHS の根のサブ MIP 5.5e6) がその試金石になる。

### 6.1 HiGHS の根のサブ MIP を書き出して比べる (記録つきの HiGHS 1.15.1)

HiGHS 1.15.1 のソース (PyPI の sdist) の `HighsPrimalHeuristics::solveSubMip` に、外側の根のサブ MIP を MPS に書き出して固定率・自由な列・結果を
出す記録 (環境変数 `HIGHS_SUBMIP_DUMP`) を足して組み立てた (手元の一時置き場、リポジトリには入れない)。trento1・4 スレッド・40 秒。

- **HiGHS の 12〜14 秒の解は RENS でなく根の被約費用 (root reduced cost) のサブ MIP**: 固定率 0.5 (HiGHS の数え方。整数とみなした連続列 1178 本を分母に含む)、
  自由な整数列 3796、上限 500 葉・200 ノード・停滞 12。種 1 は 5.85 秒 201 ノードで 5506026、種 2 は 8.7 秒 201 ノードで 5385174。
- 近傍を列ごとに比べる (種 2、当方の根の被約費用の部分問題と): どちらも下限 (0) への固定だけ。当方は 0-1 の列 6415 本のうち 3217 本を、
  HiGHS は 2717 本を固定する。共通 2120、当方だけ 1097、HiGHS だけ 597。
- **HiGHS の近傍は当方でも解ける**: HiGHS の近傍をサブ MIP の形 (`ENOMOTO_MIP_DEBUG_AS_SUBMIP`、1 スレッド) で当方に解かせると、
  5.35 秒・0 ノードに入れ子の RENS で 5826356 (種 1 の近傍)・6.13 秒に 6404094 (種 2 の近傍)。`SUBMIP_HEUR=t` でも同じ。
  逆に当方の近傍は HiGHS でも 60 秒で 3.70e7 (6 節)。→ **trento1 の差は近傍 (被約費用でどの列を固定するか) の違い**で、サブ MIP の中の
  探し方ではない。
- 当方の被約費用の固定率を下げても (`ENOMOTO_T_MIP_RRC_RATE=0.4`、自由 3838)、サブ MIP は 4.4e9 しか出さない (150 秒の目的値:
  種 1 6505739・種 2 235911369・種 3 16745831)。固定する数でなく、どの列を固定するか (LP の解・被約費用の違い) が効いている。
- 別件: 4 スレッドの通常の形で HiGHS の近傍を解くと、当方の既定は種 1 の近傍で 60 秒解なし (根のサブ MIP が全部 0 ノードで実行不能、
  暫定解なしの RENS は固定率 0.8 で 1 回きり)。`ENOMOTO_T_MIP_NOINC_RENS_RATE=0.6` か `ENOMOTO_T_MIP_NOINC_RENS_TRIES=4` なら
  14〜22 秒に最初の解、60 秒で 5.29e6 前後 (HiGHS 単独と同じ)。ただしこの直しは暫定解がまだないときだけ効き、trento1 本体では
  Local-MIP が先に解を出すので当たらない (primal_20261117 の 7 節では HiGHS 形の RENS は 4 問で効かず、やり直し 1 回は 30n20b8 で決めた値)。

## 7. まとめ (2026-11-17)

- 親の指示の「サブ MIP の中で trivial の解があっても入れ子の RENS・ダイビングを回す」は、trento1 では差の原因に当たらない
  (HiGHS の近傍なら当方のサブ MIP も 5〜6 秒で解を出す)。P・M の対の比べには回さない。
- trento1 の差は、根の被約費用の近傍の選び方。次の手の候補: 被約費用のサブ MIP が悪い解しか返さないとき、別の近傍 (別の LP の解
  (カットの前・後)・被約費用の同点の崩し方・整数とみなした列を数える HiGHS の固定率) でやり直す。どの列の違いが効くかは、
  当方と HiGHS の根の LP の解・被約費用を列ごとに並べると切り分けられる (前処理の前の LP は 200 秒で解けず、ここでは未着手)。

### 7.1 被約費用の候補の違いの切り分け (親の指示: LP の解の違いか、選び方の規則の違いか)

記録つきの HiGHS に、根の被約費用の候補 (lurking bound) と根の LP の解・被約費用・基底を書き出す記録 (`HIGHS_RRC_DUMP`) を足した (trento1・種 2)。

- HiGHS の候補は **226 本だけ** (当方 5010 本)。HiGHS の `addRootRedcost` は、根の LP を解くたびに (カットのループの各回も) 候補をためて、
  「その固定が正しくなる打ち切り値」(LP の値 + 被約費用) の大きい順に並べる。さらに `computeBasicDegenerateDuals` で、基底にあって境界に張り付いた
  整数列にも双対の値を与える。
- 226 本の内訳 (最後の LP で): 非基底・値 0・被約費用 > 0 が 156、基底・値 0・被約費用 > 0 が 42、基底・値 1・被約費用 < 0 が 19 (1 への固定)、
  その他 9。1 への固定は 20 本で、集合分割の行の伝播で多くの列を 0 に固定し、226 本で固定率 0.5 に届く。
- 当方は非基底の列の被約費用だけを使い (0 への固定だけ)、被約費用の大きい順に 3217 本を固定して 0.5 に届かせる。
- 試作 `ENOMOTO_MIP_HEURGAP=d` (コミット済み、既定は変えない): 当方の根の被約費用の候補に、基底にあって境界に張り付いた整数列を、
  退化した双対の比 θ ([`Solver::degen_thetas`]、ノードの `degen_dual_fixing` と同じ判定) で足す (1 への固定も候補)。trento1 では
  5010 本に 579 本 (うち 1 への固定 14 本) が加わるが、150 秒の目的値は種 1 55684402・種 2 195945342・種 3 55948412 で、
  被約費用のサブ MIP は 4.4e9 か 5.6e7 しか出さず、効かない。
- → **主因は LP の解 (頂点と双対) の違い**: HiGHS の根の LP では値 0 の列の多くが基底にあり被約費用 0 で、被約費用が正の非基底の列は 156 本しかない。
  当方の LP では 5010 本が非基底で被約費用が正で、候補の先頭を占める。退化した双対の候補を足しても、5010 本の並びは変わらない。
  親の指示どおり、ここで区切る (試作 d は P・M に回さない)。
- 次に手を入れるなら: 根の被約費用の近傍を、被約費用の大きさでなく「固定の打ち切り値」の大きい順に少数 (HiGHS の 226 本程度) だけ固定し、
  伝播に任せる形 (固定率の目標を固定する本数でなく伝播の結果で測る)。ただし当方の LP の双対が HiGHS と違う以上、同じ近傍になる保証はない。
