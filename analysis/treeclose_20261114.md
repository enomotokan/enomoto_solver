# TREECLOSE: 木を閉じる力 (2026-11-14、途中)

目的: Mittelmann の組で ENOMOTO (束 cand1114) が HiGHS 1.15.1 に負ける「暫定解は良いのに下界を閉じきれない」型の問題で、
差がどこにあるかを型に分け、手当ての案を出す。

- ソース: a61040b7 以降 (ccr-1beed81b-ex0uhq)。設定は cand1114 (analysis/cand1114_20261113/cfg.py の `CAND1114`) + ログ
  (`ENOMOTO_MIP_LOG=1`・`ENOMOTO_PROF_TREE_PAR=1`・`ENOMOTO_MIP_DEBUG_PRETIME=1`・`ENOMOTO_MIP_TCTRACE=1`、どれも解く側は変えない)。
  HiGHS は highspy 1.15.1 (`mip_rel_gap=0`、ログ付き)。600 秒・4 スレッド・種 1。
- 新しい診断の表示 `ENOMOTO_MIP_TCTRACE` (src/mip/solver.rs の `log`): 経過の行 (`MIP: ...s nodes`) の lb・nodes は主スレッドの
  待ち行列の分なので、全体の下界・全スレッドのノード数・打ち切り値を外側の経過時間 (再スタートをまたいで通しの時刻) で 2 秒ごとに出す。
- 台本 `treeclose_20261114/`: `run.py K [plan]` (分担表 `plan.json` の K 番目、`res_<plan>_sK.jsonl`・`logs/<問題>_<設定>[_s種].log.gz`)、
  `parse.py` (ログから時間ごとの下界・上界・ノード数と終わりの統計)、`summ.py` (問題ごとに並べる)。
- 分担: 0 は手元 (sct2・unitcal_7・neos-3627168-kasai・csched008・fiball)、1・2 は親に依頼 (mushroom-best・neos-933966・mzzv11・
  tbfp-network・net12 / uccase12・rococoC10-001000・traininstance6・mcsched・satellites2-60-fs)。
  前の計測 (analysis/rootcap2_20261113/logs の cand1114、analysis/highsloss_20261113/logs の HiGHS) も合わせて読む。

### sct2

- 根の下界はこちらが上 (−231.047 対 −231.064)。最適解は 73 秒 (HiGHS 251 秒)。
- 2 回目の木の中の再スタート (102 秒) の後、**全体の下界が −231.04739 (再スタートの後の根の LP と同じ値) のまま 500 秒・7 万ノード動かない**。
  開いたノードは 4 万まで増える。前の暫定解は打ち切り値の固定で再スタートの後の問題から外れるので、内側の求解は暫定解なし
  (打ち切り値 −230.98916 だけ) で進み、600 秒まで暫定解を持たない。
- HiGHS も下界は根の値 −231.064 のまま 290 秒動かないが、木の中で 5 回 (固定がほとんど増えない「巨大な木」の判定で) 再スタートし、
  292 秒の再スタートで 30.4% の整数列が外れて根の下界 −231.028、最後の再スタート (367 秒) の後 400 ノードで閉じる。
- こちらの木の中の再スタートの判定 `tree_restart_due` は「暫定解がない」と判定しない (`self.incumbent.is_none()` で戻る) ので、
  再スタートの後の求解が暫定解なしのままだと、それ以降の再スタートが起きない。前の計測 (rootcap2) でも 199〜516 秒の間は同じ。
- ノードの LP: こちら 112 反復/LP (待ち行列から取ったノードは 300〜465 反復)、HiGHS 64 反復/ノード。ノード数はこちらが 3.4 倍。

### neos-3627168-kasai

- 4 スレッドで 10.7 万ノード、HiGHS は 1 本の木で 11880 ノード・97 秒。同じノード数での下界: こちら 9645 ノード (98 秒) で 986100、
  HiGHS 8837 ノードで 987605。4 スレッドの合計のノードあたりの下界の伸びが HiGHS より悪い (1 スレッドではほぼ同等、analysis/highsloss2_20261113.md)。
- 各スレッドで待ち行列からの取り出しが潜りより多い (例 tid 0: 潜り 7082・自分の待ち行列 11125 (153 反復)・共有 421 (337 反復))。D2 の型。
- 強分枝が少ない: 主スレッドで 12714 回の選択に強分枝の LP 2530 本 (106026 反復)。HiGHS は強分枝 116100 反復 (11880 ノード)。

### csched008

- 整数の目的。こちらは 4 回再スタート (固定 0〜12 列、HiGHS も 3 回)。173 を 340 秒に見つけた後、下界 172 のまま 1.3 万 → 4.2 万ノードで閉じない。
  HiGHS は 173 を 153 秒に見つけ、約 8000 ノード・206 秒で証明。
- 各スレッドで処理したノードのうち下界が最適値以上 (`lb>=opt`) のものが 1400〜1600 (暫定解が来る前に処理した分を含む)。

### unitcal_7 (木ではない)

- 根の LP はほぼ同じ (1.9450e7 / 1.9436e7)。根のカットの後: こちら 1.9541e7 (25 ラウンド、カットの平均の長さ 2〜3)、HiGHS 1.9610e7
  (60 秒)。根の段もこちら 147 秒 (根のヒューリスティクス 118 秒) で、暫定解は 19640125 のまま 515 秒まで。
- 木の中の下界の伸びはこちらも悪くない (147 秒 1.9542e7 → 600 秒 1.9615e7) が、HiGHS の根の下界に届くのが 600 秒。根のカット (と ROOTHEUR) の担当。

## 2. 型 (途中)

| 型 | 中身 | 該当 (分担 0 と前の計測) |
|---|---|---|
| A 再スタートの使い方 | 下界が根から動かない木を、再スタート (固定・カットの持ち越し・根のやり直し) で縮めて閉じる。こちらは再スタートの後に暫定解を失い、以降の再スタートが止まる | sct2 (csched008 も再スタートが多い) |
| B ノードあたりの下界の伸び (4 スレッド) | ノードは多いが下界が伸びない。待ち行列への戻り (D2)・強分枝の少なさ・スレッドの分担 | kasai、csched008 |
| C 最後の詰め | 整数の目的で上界 − 下界 = 1 段から閉じない | csched008 |
| D 根 (木ではない) | 根のカット・前処理・根の時間 | unitcal_7、net12、rococoC10-001000 (前の計測) |
| E 解の発見 | 最適解を得た後はすぐ閉じる | fiball、neos-933966 (前の計測) |

## 3. 手当て (試作)

- `ENOMOTO_MIP_TC=i` (既定では使わない): 再スタートの後の求解で暫定解がなくても、打ち切り値があれば木の中の再スタートを判定する
  (`tree_restart_due`)。HiGHS は暫定解を持ったまま何度でも再スタートする。sct2・csched008 の 2 種で確かめ中 (`tc1.json`)。
