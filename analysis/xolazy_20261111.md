# 根の LP のクロスオーバーを後回しにする (XOLAZY、2026-11-11)

案 (利用者): 根の LP (最初・再スタートの後) の同時実行で内点法側はクロスオーバーで頂点と基底を作り切ってから勝つが、再スタートに要るのは
値 (主・双対、被約費用による固定、下界) で基底ではない。再スタートしそうな根の LP ではクロスオーバーを省き、基底が要る段 (カットのループ・木) に
入るときだけ縮んだ問題でクロスオーバーする。

診断 (振る舞いは変えない): `ENOMOTO_MIP_XOLAZY_LOG=1` で stderr に `XOLAZY {...}` の行を出す。

- `"ev":"rootlp"`: 主の根の LP ごと。`winner` (`simplex` 二段解法・`ipm` 内点法 + クロスオーバー・`warm` 基底があり同時実行に入らない)、
  `t_ipm`・`t_push`・`t_xo` (同時実行の始めから、内点法・押し出し・仕上げの単体法の終わり。勝ち負けが決まった時点までに終わったものだけ)、`t_end`。
  内点法が勝ったときは、止められた二段解法の途中の基底の双対 (最後に共有の下界を計算した双対) と内点法の双対 (押し出しの前) の
  ラグランジュ下界の最適値との差 `gap_simplex`・`gap_ipm` (スラック列の符号に射影した双対で計算。どの双対でも正しい下界)。
- `"ev":"restart"`・`"ev":"tree"`: 再スタート・木に入る時刻。直前の根の LP で内点法が勝っていれば、その時点の打ち切り値 `U` と根の LP の
  時点の大域的な境界で、最適な双対・途中の基底の双対・内点法の双対のそれぞれから被約費用で固定できる整数列の数 `fix_opt`・`fix_simplex`・`fix_ipm`
  (`L(y) + |d_j| (x_j - 境界) > U` の判定。実際の固定の数 `newly` はカットのループの後の LP などによるもので別)。

作り: `src/simplex/crossover.rs` (時刻と内点法の双対を `XO_STAMP` に置く)、`src/simplex/mip_lp.rs` (`RaceDiag`・`lagrange_std`)、
`src/mip/xolazy.rs` (固定の数え)、`src/mip/solver.rs` (行を出す)。計測は `xolazy_20261111/bench.py`、集計は `summ.py`。

## 結論 (先に)

- **クロスオーバーを後回しにして省ける時間の上限は小さい。段階 1 には進まない。**
  - 58 問 (60 秒・種 1・2): 省ける上限 3.6 秒 / 全体 2773 秒 (0.13%)。その根の LP の後に再スタートしたものに限ると 0.11 秒 (0.004%)。
  - Mittelmann の根の LP が重い 30 問 (600 秒・種 1): 23.7 秒 / 10675 秒 (0.22%)。再スタートしたものに限ると 2.5 秒 (0.02%)。
- 理由 (事実):
  1. 内点法が勝つ根の LP が少ない (58 問で 188 本中 17 本、30 問で 46 本中 5 本)。重い最初の根の LP の多くは LP プロービングの基底から解く `warm` で、
     同時実行に入らない (satellites2-60-fs 13.8 秒・neos-3216931-puriri 12.4 秒・neos-933966 6.1 秒・mzzv11 4.1 秒)。
  2. 再スタートは根の LP の直後ではなく、カットのループ・根のヒューリスティクスの後に決まる。根の LP から再スタートまで 1〜73 秒
     (mzzv11 25〜73 秒、uccase12 3〜30 秒)。案のとおりにするには、再スタートを見込んだ根でカットのループ (基底が要る) も飛ばす必要があり、
     それはクロスオーバーの省き (1 本あたり 2 秒前後) より大きな変更になる。
  3. クロスオーバーで一番重いのは、再スタートしない根の LP (rail01 の最初の根: 内点法 14.6 秒・押し出し 5.7 秒・仕上げ 11.9 秒) で、
     その後はカットのループに入るので基底が要る。
- **別の発見: 内点法の双対 (クロスオーバーの前) は、最適な頂点の双対より被約費用による固定がずっと多い** (mzzv11、下の 3 節)。
  内点法の点は厳密な相補性に近く、頂点の双対で 0 になる (双対退化の) 被約費用が 0 にならないためと推測する。新しい課題の候補 (docs/backlog.md の XOLAZY)。

## 3. 止められた二段解法の途中の基底と内点法の双対 (親の追加の観点、`dual60.jsonl`・`dual200.jsonl`)

内点法が勝った根の LP で、ラグランジュ下界の最適値との差と、根の終わりの打ち切り値で固定できる整数列の数:

| 問題 (種) | 根の LP | gap 途中の基底 | gap 内点法 | 固定: 最適な双対 | 途中の基底 | 内点法 | 実際の新しい固定 `newly` |
|---|---|---|---|---|---|---|---|
| mzzv11 (1) | 再スタート 1 回目の後 (8.0 秒) | 1.0e6 | 1.2e-4 | 265 | 0 | **1005** | 337 |
| mzzv11 (1) | 再スタート 2 回目の後 (5.3 秒) | 9.4e5 | 5.2e-5 | 37 | 0 | **85** | 38 |
| cvs16r128-89 (1) | 最初 (0.69 秒) | 16 | 8.7e-11 | 0 | 0 | 0 | 0 |
| mc11 (1) | 最初 (0.04 秒) | 28.5 | 3.1e-8 | 0 | 0 | 0 | 297 |
| neos-1445765 (1) | 最初 (0.27 秒) | 6660 | 1.4e-9 | 0 | 0 | 0 | 0 |
| neos-911970 (1・2) | 再スタートの後 (0.03 秒) | なし | −∞ (境界が無限の構造列の符号が逆、推測) | 20・8 | 0 | 0 | 37・8 |

事実:

- 止められた二段解法の途中の基底の双対は、内点法が勝つ時点ではまだ遠い (下界の差 16〜1e6、段階 A の途中が多い)。固定は 0。
  同時実行の共有の下界 (`gap_shared`) も最適値に届いておらず (差 0 は内点法が勝った後に二段解法が書いた値ではなく、最適値そのものを書いた
  クロスオーバーの仕上げの値とみられる)、途中の基底を被約費用の固定に使う効き目は見えない。
- 内点法の双対のラグランジュ下界は最適値との差 1e-11〜1e-4 (相対 1e-8 以下) で、余裕を取らなくてもほぼ最適な下界になる。
- mzzv11 では内点法の双対だけで固定できる整数列が最適な頂点の双対の 3.8 倍 (1005 対 265)、実際の固定 (カットのループの後の LP などによる 337) の 3 倍。
- 被約費用の向きの確かめ: 最適な双対から作った被約費用と `lp.reduced_costs()` の差は 1e-12 以下 (`rc_diff`)。

推測:

- 内点法の点は最適面の相対的な内部にあり、被約費用が厳密な相補性を満たす (最適面のどの頂点でも境界にある列の被約費用がすべて正)。
  頂点の双対は双対退化で多くの被約費用が 0 になるので、固定が少ない。HiGHS などが頂点の双対だけで固定しているなら、内点法の双対は
  ほかのソルバーにない固定の材料になりうる。
- ただし 1 問 (mzzv11) だけの観察で、内点法が勝つ根の LP は少ない。内点法が負けた根の LP でも内点法を最後まで回して双対を取れば材料は増えるが、
  その分の手間がかかる。
