- 機械: 4 CPU (`nproc` = 4)。ソルバーは同時に 1 つだけ動かした (ビルド・テストは計測の合間)。
- 土台: `inv/physcmp-20261023` (`ad1e0d3`) に `claude/enomoto-solver-heuristic-survey-xjlnol` (`9b31391`、mixoc が既定) を merge。
  作業ブランチ `inv/physprimal-20261024`。
- 計測は 4 スレッド・60 秒、`analysis/physprimal_20261024/run_cfg.sh` (`ENOMOTO_MIP_LOG=1`)。既定 = mixoc (FJ_LMIP_MIX・SYM_ORIG_CUT)。
  AGG = `ENOMOTO_MIP_CUT_AGG=1`。HiGHS は 1.15.1。
- 「サブ MIP の書き出し」= `ENOMOTO_MIP_SUBMIP_DUMP` で書いた根のサブ MIP の MPS。手元での解き直しは 1 スレッド
  (`highs_sub.py`、ENOMOTO は今回の診断 `ENOMOTO_MIP_DEBUG_AS_SUBMIP=1` + `ENOMOTO_MIP_CUTOFF=<外の暫定解>` で根のサブ MIP と同じ形)。
- 台本とログは `analysis/physprimal_20261024/` (§6)。

## 1. 結論

事実:

1. **60 秒での証明は、どの形でもできなかった** (今回の 9 回 + 診断の回。最良の暫定解は 49624、根の下界の最高は 49324)。
2. **RENS が解を出さないのは、近傍に解がないから** (伝播や ENOMOTO のサブ MIP の不具合ではない)。
   - 根の RENS (LP で整数値の列を全部固定、自由な整数列 1808) のサブ MIP は、HiGHS でも 0.09 秒で実行不能 (LP 緩和は 48674 で解ける)。
     固定率を 0.6 に止めて伝播しながら積む形 (`ENOMOTO_MIP_FIX_CAP`、根の下界 49224 の回、自由な整数列 2151) も HiGHS で 0.59 秒・
     1 ノードで実行不能。locks・clique のサブ MIP も同じく実行不能。
   - 既存の「伝播つきの RENS」(`ENOMOTO_MIP_RENS_PROP`・`FIX_CAP`) では解決しない。
3. **解は RINS の近傍にあり、ENOMOTO はそこで時間切れになる**。書き出した根の RINS のサブ MIP 3 つ:

   | 書き出し | 外の根の下界 | 近傍 | HiGHS (1 スレッド) | ENOMOTO の実際の回 | ENOMOTO を手元で (サブ MIP の形・20 秒) |
   |---|---|---|---|---|---|
   | `d1_3` | 48757 | 既定の RINS (暫定解 50425 と一致する列を全部固定) | 49424 (最適)・1.71 秒・1 ノード | 2.55 秒・0 ノードで時間切れ | 49624 (時間切れ) |
   | `d2_3` | 49224 | `FIX_CAP` (固定率 0.55) | **49324 (全体の最適値)・3.06 秒・1 ノード** | 0.59 秒・0 ノードで時間切れ | 解なし |
   | `av_3` | 48633 | `RINS_FJ_BOOST` (暫定解 49824) | **49324・1.98 秒・1 ノード** | 9.73 秒・0 ノードで時間切れ | 解なし (30 秒でも) |

   - HiGHS はこれらを「前処理で小さくし (`av_3`: 1982 行 × 1151 列。ENOMOTO は 2956 × 1780)、根のカットで下界をサブ MIP の最適値まで
     上げ (`d2_3`: 48924 → 49324、2.8 秒・分離の LP 4019 反復)、中のサブ MIP (`L`) が解を出す」形で解く。
   - ENOMOTO のサブ MIP は、根のカットが 5 ラウンド・時間の 1 割・集約カットの枠なしで 49257 (`d2_3`) で止まり、残りを Feasibility Pump
     (4.3〜5.9 秒) とダイビング (4〜5 秒) に使い、木は強分岐で 1 ノード 2 秒かかる。サブ MIP の中の RENS は既定では使わない。
   - 同じ `av_3` をサブ MIP でない通常の求解 (1 スレッド) で解くと、既定で 20.8 秒、AGG で 6.6 秒 (中の RENS が 5.4 秒に 49324) で最適。
4. **手当て `ENOMOTO_MIP_SUBMIP_CUT_AGG` (今回の試作)**: サブ MIP の根のカットのループにも集約カットの枠を使い、ラウンドの上限を 25、時間の
   上限をサブ MIP の時間の 5 割にする。手元のサブ MIP の形で `d2_3` が **5.7 秒・0 ノードで 49324 (最適)**、`d1_3` が 3.5 秒で 49424 (最適)。
   `av_3` は下界 49324 まで上がるが 30 秒でも解なし。ただし **実際の 60 秒の回では、これを入れても根の RINS は 0 ノードで時間切れのまま**
   (§2。RINS の時間を 9〜10 秒に延ばしても同じ)。
5. **根の揺れの原因: ときどき 1 ラウンドの LP だけが 7000 反復 (5〜6 秒) に膨らみ、目的値は動かず、その時間で根のカットの時間の上限に当たる**。
   - 48757 で止まる回 (`physcmp` の `b_agg_1`、今回の `F_1` など): ラウンド 5 の LP が 7489〜7649 反復 (ふだん 900〜1600)、目的値 48757.3 の
     まま。伸びの判定は通るが 1 段 (3 秒) 延ばしても経過が上限を超えたままで止まる。
   - 48633 で止まる回 (`p1_1`・`A_2`): ラウンド 3 の LP が 6952〜7080 反復で 48633.5 のまま。直近 3 ラウンドの伸び 46 が閾値
     (|目的値| の 1e-3 = 48.6) をわずかに下回り、延ばさずに止まる。
   - 49099〜49324 に届く回は、重いラウンドが出ないか、出ても延長の余裕があるうちに出た回。カットの種類・本数 (毎ラウンド 150 本、
     ラウンド 0〜4 の候補はどの回も 4014〜4233 本) は止まる回と届く回で変わらない。
   - 重い LP は、DSE の重みを厳密に計算し直す (`ENOMOTO_MIP_CUT_DSE_EXACT`) でも、止まった LP の続きから解く (`ENOMOTO_MIP_LP_RESUME`)
     でも出る (4938 反復・3 秒の上限 3 回)。
6. **手当て (今回の試作) `ENOMOTO_MIP_CUT_EXTEND_CATCHUP`・`ENOMOTO_T_MIP_CUT_EXTEND_WIN`**: 延ばした上限が経過に届かなければ経過 + 1 段まで
   延ばす、伸びを見るラウンドの数 (既定 3) を変える。これで重いラウンドの後もループは続く (`F2_1`: 48757 → 48846、ラウンド 9 まで) が、
   3 回の根の下界 48874〜49157 は AGG だけの 3 回 (48814〜49324) と変わらない。
7. 目的値の不一致 (HiGHS の最適値と違う「最適」) は出ていない (最適と報告したのは roll3000 12890、neos-911970 54.76、書き出したサブ MIP の
   49324・49424 で、HiGHS と一致)。

推測:

- 主側の本体は「ENOMOTO のサブ MIP が、HiGHS なら根で解ける近傍を解けない」こと。カットの枠でサブ MIP の下界は HiGHS 並みに上がるので、
  残りは (a) サブ MIP の前処理が弱い (行・列とも HiGHS の 1.5 倍)、(b) 下界が最適値に着いた後の整数解の取り出し (HiGHS は中の RENS、
  ENOMOTO はポンプ・ダイビングで時間を使う) の 2 つとみる。実際の回で手元より遅いのは、時間の上限が短く (0.6〜10 秒) カットの時間
  (その 5 割) も短いこと、根の後半で他のスレッド (FJ・Local-MIP・背景のカット) と CPU を分けることによるとみる (確かめていない)。
- 根の揺れは、カットの選び方ではなく LP の重い回の出方で決まる (同じ候補・同じ本数で分かれる)。重い LP はカットを足した LP の双対単体法の
  反復の膨らみで、`lp_hang_20261021.md` の「重みを正しく引き継いでも 4000〜7000 反復の回がある」と同じものとみる。直すなら単体法の側
  (HiGHS は同じ LP を 2000 反復前後で解く) で、根のカットの時間の継ぎ足しでは揺れの幅が変わるだけ。

### 2.1 根のヒューリスティクスの時刻 (下界 49324 に届いた回、`physcmp` の `b_mixagg50rh_2`)

根のカットのループが 37.6 秒に 49324 (= 最適値) に届き、39.7 秒に終わった後:

| ヒューリスティクス | 結果 | 時間 |
|---|---|---|
| simple rounding・ZI round・randomized rounding | なし | 0.00・0.00・0.04 秒 |
| interior rounding | IPM (cost) が失敗、なし | 2.81 秒 |
| root reduced cost | なし | 0.00 秒 |
| LP face | 整数列 5443 のうち 129 しか固定できず、なし | 0.00 秒 |
| RENS (並列、旧来の全部固定、自由な列 2277) | サブ MIP が実行不能 | 0.35 秒 |
| locks (固定率 0.65)・clique (0.93) | サブ MIP が実行不能 | 0.31・0.28 秒 |
| vbounds | 固定率 0、なし | 0.00 秒 |
| RINS (暫定解 51029、自由な列 2875) | サブ MIP が 0 ノードで時間切れ | 0.93 秒 |

43.8 秒に根のヒューリスティクスが終わり、背景のカットの後 56.0 秒に木に入って時間切れ。HiGHS (元の問題) は 8.86 秒に下界 49324、
12.65 秒に根のサブ MIP (`L`) で 49324、12.7 秒に最適。

再スタートの後に届いた回 (`physcmp` の `b_mixagg_1`・今回の `AGG_1`): 再スタートの後の根は前の暫定解を持たず (打ち切り値だけ)、
前の根で失敗したヒューリスティクスを全部飛ばし (「skipped (no solution before the restart)」)、RENS (カット前の LP) は実行不能、
Feasibility Pump が 13.4 秒使って解なし。`ENOMOTO_MIP_RESTART_ALL_HEURS` + `ENOMOTO_MIP_RESTART_REF` (F3) で RINS は回るが、
0 ノードで時間切れ (F3_1、2830 列)。

## 5. 既定にする候補か

- **どれも候補にしない。**
  - 60 秒の証明は 0 回のまま、暫定解・根の下界も AGG だけと変わらない (§2)。
  - F2 は neos-911970 が 12.7 → 32.0 秒、F3 は neos-911970 が時間切れ・mzzv42z が −16110 (§3)。
- 次に効きそうなもの (推測):
  - サブ MIP の前処理 (HiGHS の 1.5 倍の行・列が残る。`physcmp` §3.1 の Probing・Enumeration の差と同じ所) と、下界が着いた後の整数解の
    取り出し (サブ MIP の中の RENS をカットの後の LP から) を、手元の 3 つの書き出し (`subgz/`) で HiGHS の 2〜3 秒に近づけること。
    手元で速くなれば、実際の回の RINS (2〜10 秒) に乗る。
  - 根の揺れは単体法の重い回 (同じ LP を HiGHS は 2000 反復前後) を直す方が筋がよい。
